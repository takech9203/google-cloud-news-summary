🧠 AlloyDB AI の事前登録 Gemini モデル刷新

google_ml_integration 1.6.5 — Gemini 3.x / 4 世代への移行と semantic-ranker-512 の追加
📅 リリース日: 2026-10-29

📝 概要

AlloyDB AI は google_ml_integration 拡張機能 バージョン 1.6.5 以降で、事前登録 (pre-registered) される Gemini モデルのラインナップを刷新しました。 gemini-3.1-flash-lite、gemini-3.5-flash、gemini-3.5-flash-lite、gemini-3.6-flash、gemini-3.7-flash、gemini-3.8-flash、gemini-4-argon の 7 モデルが新たに事前登録され、手動登録なしで SQL から直接呼び出せるようになりました。

デフォルトの Gemini モデルは gemini-3.5-flash-lite に変更され、旧世代の gemini-2.0/2.5 系 5 モデルは事前登録リストから削除されました。 さらに、リランキング用モデル semantic-ranker-512 の事前登録サポートも追加されています。

❌ Before (アップデート前の課題)

  • 事前登録モデルは Gemini 2.0 / 2.5 世代が中心で、3.x / 4 世代を使うには google_ml.create_model() による手動登録が必要
  • 新世代モデルを試すたびに登録・権限設定などの運用作業が発生
  • リランキング用の事前登録モデルの選択肢が限られ、semantic-ranker-512 には個別対応が必要

✅ After (アップデート後の改善)

  • Gemini 3.1〜3.8 Flash 系 + gemini-4-argon の 7 モデルが事前登録され、モデル ID 指定だけで ai.generate() などから即呼び出し可能
  • デフォルトモデルが gemini-3.5-flash-lite になり、ID 省略時も新世代モデルを使用
  • semantic-ranker-512 が事前登録され、ai.rank() での再ランク付けに追加登録作業が不要
🤖 対象ユーザー: ai.generate()、ai.if()、ai.rank() などの AlloyDB AI 関数でデータベース内 LLM を活用しているユーザー。旧 2.x 系モデル ID をクエリにハードコードしている場合は移行対応が必要です。

拡張機能を 1.6.5 に更新すると、SQL から登録作業なしで呼び出せる事前登録モデルが Gemini 3.x / 4 世代に入れ替わり、デフォルトモデルも gemini-3.5-flash-lite に変わります。

🚀 主要機能

1️⃣ Gemini 3.x / 4 世代モデルの事前登録サポート

→gemini-3.1-flash-lite、gemini-3.5-flash、gemini-3.5-flash-lite、gemini-3.6-flash、gemini-3.7-flash、gemini-3.8-flash、gemini-4-argon の 7 モデルを追加
→手動登録ステップが不要。修飾モデル名 (qualified name) を model_id に指定するだけで呼び出せる

2️⃣ デフォルト Gemini モデルの変更

→バージョン 1.6.5 でデフォルトの Gemini モデルが gemini-3.5-flash-lite に設定
→モデル ID を明示しない AI 関数呼び出しは、この新しいデフォルトモデルで実行される

3️⃣ 旧世代モデルの事前登録リストからの削除

✗gemini-2.0-flash、gemini-2.0-flash-lite、gemini-2.5-flash、gemini-2.5-flash-lite、gemini-2.5-pro が事前登録モデルから削除
→これらのモデル ID をハードコードしているクエリは、拡張機能更新後に新世代モデルへの移行が必要

4️⃣ リランキングモデル semantic-ranker-512 の事前登録サポート

→ai.rank() 関数の model_id に semantic-ranker-512 を直接指定して検索結果を再ランク付け可能
→ベクトル検索結果の並び替え精度を向上させる RAG (Retrieval-Augmented Generation) 用途に有効

ステップ 1: 拡張機能のバージョン確認と更新

SQL google_ml_integration の更新 
-- 現在のバージョンを確認
SELECT extversion FROM pg_extension WHERE extname = 'google_ml_integration';

拡張機能を 1.6.5 以降に更新すると、新しい事前登録モデルが利用可能になります。

ステップ 2: 新しい Gemini モデルを SQL から呼び出す

SQL 事前登録済み Gemini 3.5 Flash でテキスト生成 
-- 事前登録済みの Gemini 3.5 Flash でテキスト生成
SELECT ai.generate(
  model_id => 'gemini-3.5-flash',
  prompt   => 'この製品レビューを 1 文で要約してください: ...');

手動のモデル登録は不要で、修飾モデル名を指定するだけで呼び出せます。

ステップ 3: semantic-ranker-512 で検索結果を再ランク付けする

SQL ai.rank() による再ランク付け 
SELECT index, score
FROM ai.rank(
  model_id      => 'semantic-ranker-512',
  search_string => 'おすすめのデザート',
  documents     => ARRAY['レビュー 1', 'レビュー 2', 'レビュー 3'],
  top_n         => 2);

ベクトル検索の初期結果を ai.rank() で再ランク付けすることで、RAG の検索品質を向上できます。

⚠️ デメリット・制約事項

🚧 制限事項

✗新しい事前登録モデルの利用には google_ml_integration 拡張機能 1.6.5 以降が必要
✗gemini-2.0-flash、gemini-2.0-flash-lite、gemini-2.5-flash、gemini-2.5-flash-lite、gemini-2.5-pro は事前登録リストから削除されるため、これらの ID を直接指定しているクエリは 1.6.5 への更新後に動作しなくなる可能性がある
✗Agent Platform モデルのサポートは、Agent Platform のモデルバージョニングとライフサイクルのガイドラインに従う (モデルの提供終了スケジュールに注意)

🤔 考慮すべき点

→拡張機能の更新前に、既存のクエリ・ストアドプロシージャ・アプリケーションコードで旧 2.x 系モデル ID をハードコードしている箇所を洗い出し、新モデルへの置き換え計画を立てる
→デフォルトモデルの変更 (gemini-3.5-flash-lite) により、モデル ID を省略している処理の出力品質・レイテンシ・コストが変わる可能性があるため、更新後に動作検証を行う
→リランキングモデルの利用には Discovery Engine API の有効化と IAM 権限の付与が別途必要

SQL 2 段階検索 (ベクトル検索 + 再ランク付け) 
WITH initial_ranking AS (
  SELECT id, description, ROW_NUMBER() OVER () AS ref_number
  FROM product
  ORDER BY embedding <=> google_ml.embedding(
    'gemini-embedding-001', 'フィットネス機器')::vector
  LIMIT 10
),
reranked_results AS (
  SELECT index, score
  FROM ai.rank(
    model_id      => 'semantic-ranker-512',
    search_string => 'フィットネス機器',
    documents     => (SELECT ARRAY_AGG(description ORDER BY ref_number)
                      FROM initial_ranking),
    top_n         => 5)
)
SELECT id, description
FROM initial_ranking, reranked_results
WHERE initial_ranking.ref_number = reranked_results.index
ORDER BY reranked_results.score DESC;

効果: ベクトル検索単独よりも検索クエリとの意味的な関連度が高い順序で結果を返せる。

AlloyDB AI の事前登録モデルが Gemini 3.x / 4 世代へ一新され、semantic-ranker-512 も追加されたことで、最新の生成 AI 機能を SQL から登録作業なしに利用できるようになりました。 一方で旧 2.x 系モデルは事前登録リストから削除されるため、google_ml_integration を 1.6.5 へ更新する前に、既存クエリのモデル ID を棚卸しして新モデルへの移行計画を立てることを推奨します。
