Looker GA (一般提供) AI エージェント連携

📊 Looker-managed MCP サーバーが GA

AI エージェントをミドルウェアなしで Looker のセマンティックレイヤーに安全接続
リリース日: 2026-10-26

📌 概要

Looker-managed Model Context Protocol (MCP) サーバーが一般提供 (GA) になりました。 MCP サーバーが Looker プラットフォームに直接組み込まれ、Gemini CLI、Claude Desktop、Cursor、Copilot などの AI エージェントが、追加のミドルウェアを構築・運用することなく、Looker インスタンスのビジネスデータや LookML モデルと安全に対話できます。Looker がサーバーをホストするため、ユーザー側でのインフラのデプロイ・保守は不要です。

今回の GA は、新しい「Manage OAuth Clients」管理ページによって支えられています。 管理者は Application Library から事前構成済みの統合をすばやく有効化したり、特定のリダイレクト URI と グループベースのアクセス制御を持つカスタム OAuth クライアントを登録したりできます。

🎯 対象ユーザー: Looker を信頼できるセマンティックレイヤーとして AI エージェントに接続したい データチーム・プラットフォーム管理者。AI エージェントからの BI データ活用をガバナンスの効いた形で実現したい組織に重要なアップデートです。

❌ Before: アップデート前の課題

  • AI エージェント接続には MCP Toolbox for Databases などのスタンドアロン MCP サーバーを自前でデプロイ・運用するミドルウェアが必要
  • 外部アプリのアクセス管理に API キー作成や API Explorer が必要で、OAuth クライアントを一元統制する管理画面がなかった
  • AI エージェントごとの OAuth クライアント登録やアクセス制御を集中管理する手段が限られていた

✅ After: アップデート後の改善

  • Looker ホストの組み込み MCP サーバーでミドルウェア不要で接続可能 (エンドポイント: LOOKER_INSTANCE_URL/mcp)
  • 「Manage OAuth Clients」ページで API キー不要のアイデンティティベース OAuth 2.0 アクセスを一元管理
  • Application Library から Cursor、VS Code、Claude Code、Claude Desktop、ChatGPT、Gemini CLI などをワンクリックで有効化
  • カスタム OAuth クライアントを複数リダイレクト URI・グループ ID 制限付きで登録可能

AI エージェントは OAuth 2.1 で認証し、Looker 組み込みの MCP サーバー経由で LookML モデルとビジネスデータに安全にアクセスします。 エージェントは認証したユーザーの Looker ロールと権限を継承し、すべての操作は監査ログに記録されます。

⚙️ 主要機能

🔌 1. Looker-managed MCP サーバー (GA)

  • MCP サーバーが Looker プラットフォームに直接組み込まれ、AI エージェントがビジネスデータと LookML モデルに安全に接続可能
  • Looker がサーバーをホストするため、自前のミドルウェアのデプロイ・保守が不要なプラグアンドプレイ構成
  • サーバー URL は LOOKER_INSTANCE_URL/mcp、認証は OAuth 2.1
  • 接続した AI エージェントは、認証したユーザーの Looker ロールとアクセス権を継承

🔐 2. Manage OAuth Clients 管理ページ

  • Admin パネルの Authentication セクションに配置。API キー作成や API Explorer を使わずアイデンティティベースの OAuth 2.0 アクセスを一元管理
  • Application Library タブ: Looker 管理の事前構成済み OAuth クライアントのカタログを有効/無効スイッチで管理
  • Custom Clients タブ: 独自のカスタム OAuth 2.0 クライアントを、クライアント ID、複数のリダイレクト URI、グループ ID 制限 (Restrict to Group ID) 付きで登録・編集・削除
  • アプリの無効化・削除時にはアクティブな OAuth リフレッシュトークンが即時失効 (アクセストークンも 60 分以内に失効)

Application Library の事前構成済みクライアント:

Cursor VS Code Claude Code Claude Desktop ChatGPT Gemini CLI Cline Windsurf Antigravity Looker Extension for VS Code Connected Sheets Data Studio Tableau Desktop Power BI Microsoft Excel Looker CLI

🧰 3. MCP ツールのきめ細かな管理 (Admin > Platform > MCP)

  • デフォルトではすべてのツールが無効。管理者が許可するツール (例: looker_query、looker_update_project_file) を明示的に有効化
  • 「Enable all tools」トグルによる一括有効化、またはツール単位での個別制御が可能
  • 各ツールに読み取り/書き込みのアクセスレベルが表示され、必要なツールのみの有効化がセキュリティベストプラクティス

🛡️ 4. Looker の既存セキュリティ・ガバナンスの継承

  • ユーザーレベルの権限境界を厳格に適用。AI エージェントは認証ユーザーが閲覧権限を持たないデータ・モデルにアクセス不可
  • Looker (Google Cloud core) では VPC Service Controls 境界、CMEK、IP 許可リストを追加設定なしでそのまま尊重
  • すべての操作は Looker System Activity (History / Event Attribute Explore) と Cloud Audit Logs に記録

gemini mcp add --transport http looker LOOKER_INSTANCE_URL/mcp

または ~/.gemini/settings.json に手動で設定:

JSON ~/.gemini/settings.json 
{
  "mcpServers": {
    "looker": {

      "oauth": {
        "clientId": "CLIENT_GUID"
      }
    }
  }
}

MCP ツールの有効化

  • Looker の Admin メニュー > Platform セクション > MCP を開く
  • AI エージェントに許可するツール (例: looker_query) のトグルを Enabled に切り替える (デフォルトはすべて無効)
  • 必要に応じて「Enable all tools」トグルで一括有効化も可能 (最小権限の観点からは個別有効化を推奨)
2

OAuth クライアントの有効化・登録

  • Admin メニュー > Authentication セクション > Manage OAuth Clients を開く
  • Application Library タブで、接続したい AI クライアント (Cursor、Claude Code、Gemini CLI など) の Enable スイッチをオンにする
  • ライブラリにないツールや別のリダイレクト URI が必要な場合は、Custom Clients タブ > Add New から、クライアント ID (com.looker. で始まる ID は予約済みのため不可)、クライアント名、リダイレクト URI、必要に応じてグループ ID 制限を指定して登録する
3

AI エージェント側の接続設定

  • エージェントの設定で MCP サーバー URL に LOOKER_INSTANCE_URL/mcp を指定する
  • エージェントを起動すると OAuth 認可フローが開始され、Looker のログイン認証情報で認証する
  • ブラウザ内で動作する MCP クライアントが CORS 経由で通信する場合は、そのドメインを Embedded Domain Allowlist に追加する

⚠️ デメリット・制約事項

制限事項

✗Looker ホストのインスタンスのみ対応。顧客ホストの Looker (original) インスタンスでは利用できない (代替としてオープンソースの MCP Toolbox for Databases を利用可能)
✗きめ細かな OAuth スコープは未サポートで、アクセス制御はグローバルなツール許可リストとユーザーの基本権限に依存する
✗ツール許可リストの変更は接続中のクライアントに自動反映されず、クライアントの再接続が必要
✗リダイレクト URI は登録値との完全一致が必要でワイルドカード非対応。動的ポートを使う AI ツール (Claude Code、Cline など) には事前登録された固定ポート (例: Claude Code/Cline は 8080、Gemini CLI は 7777) を使用するか、カスタムクライアントとして登録する
⚠️ 考慮すべき点
  • AI エージェントのツール呼び出しはインスタンスの標準的な管理系・クエリ系 API クォータを消費するため、エージェントの活発な利用は API クォータに影響しうる
  • セキュリティベストプラクティスとして、ユースケースに必要なツールのみを有効化することが推奨される
  • エージェントは認証ユーザーの権限をそのまま継承するため、接続するユーザーの Looker ロール設計が実質的なアクセス制御になる

🎯 ユースケース

💻 ユースケース 1: IDE / CLI からの自然言語データ分析

シナリオ: データアナリストや開発者が、Gemini CLI や Cursor などの AI ツールから自然言語で Looker のガバナンスされた指標に対してクエリを実行したい。

Bash 実装例 
# 管理者: Admin > Platform > MCP で looker_query を有効化
# 管理者: Manage OAuth Clients の Application Library で Gemini CLI を有効化
# ユーザー:
gemini mcp add --transport http looker https://mycompany.looker.com/mcp
gemini   # 対話モードで起動し、OAuth 認証後に自然言語で Looker に質問

効果: SQL や Looker UI の操作を介さずに、LookML で定義された信頼できる指標に基づく分析結果を AI エージェント経由で取得できる。

🏢 ユースケース 2: 社内カスタム AI アプリケーションのガバナンス付き接続

シナリオ: 社内開発の AI アシスタントを Looker に接続したいが、利用者を特定の部門 (Looker グループ) に限定したい。

実装例: Custom Clients タブでカスタム OAuth クライアントを登録し、リダイレクト URI (例: https://mycompany.com/oauth/callback) と「Restrict to Group ID」に対象グループの数値 ID を設定する。

効果: 指定グループのメンバーのみがそのアプリケーション経由で Looker に認証でき、退役時はクライアント無効化によりトークンが即時失効するため、安全なライフサイクル管理が可能。

💰 料金・利用可能リージョン

✅ 追加費用なし: Looker-managed MCP サーバーは追加費用なしで利用できます。 ただし、AI エージェントによるツール呼び出しはインスタンスの標準的な管理系およびクエリ系 API クォータを消費します。 詳細は Looker の料金ページ を参照してください。
🌍 利用可能リージョン: Looker ホストの Looker (Google Cloud core) および Looker (original) インスタンスで利用できます。 リージョン別の提供状況は公式ドキュメントを参照してください。

📝 まとめ

Looker-managed MCP サーバーの GA により、Gemini CLI や Claude などの AI エージェントを、 ミドルウェアなしでガバナンスの効いた LookML セマンティックレイヤーに接続できるようになりました。 新しい Manage OAuth Clients ページとツール単位の許可リストにより、管理者はエージェントのアクセスを一元的かつ安全に統制できます。

🤖 推奨アクション: AI エージェントからの BI 活用を検討している組織は、まず Admin パネルで 必要最小限のツールと OAuth クライアントを有効化し、System Activity での監査を組み合わせた運用から始めることを推奨します。
