🔒 Security Command Center:
Compliance Manager プロジェクトレベル有効化と Standard ティア拡張

Security Command Center GA Compliance Manager
2026-05-11

📋 概要

Security Command Center に2つの重要な変更が加えられた。Compliance Manager のプロジェクトレベル有効化と、組織レベルでの Enhanced Standard ティアのサポートである。

❌ Before (課題)

  • Compliance Manager は組織レベルでのみ有効化可能
  • 特定プロジェクトのみに適用したくても組織全体に影響
  • 新規 Standard ティアは Standard-legacy の機能のみ
  • 拡張機能を使うには手動マイグレーション待ち
  • マルチプロジェクト環境での段階的導入が困難

✅ After (改善)

  • 単一プロジェクトに対して Compliance Manager を有効化可能
  • 組織レベル新規アクティベーションで拡張機能が即利用可能
  • Compliance Manager、DSPM、Vulnerability Assessment が直ちに使える
  • 段階的導入が容易に (試験運用 → 全体展開)

🏗️ アーキテクチャ図

組織レベルでの新規 Standard ティアのアクティベーションは拡張機能をサポートし、Compliance Manager はプロジェクト単位でも有効化可能になった。プロジェクトレベルでの新規 Standard ティアのアクティベーションは引き続き Standard-legacy ティア機能を提供する。

✅ メリット

💼 ビジネス面

✓ 段階的導入の実現: 特定プロジェクトから始めて組織全体に展開、導入リスクを低減
✓ コスト最適化: 必要なプロジェクトのみに適用して運用コストを抑制
✓ コンプライアンス対応の迅速化: プロジェクト単位でのフレームワーク適用で規制対応の初動が早まる

🔧 技術面

✓ スコープの柔軟性: プロジェクト単位でのセキュリティ評価が可能
✓ 拡張機能の即時利用: Compliance Manager、DSPM、Vulnerability Assessment が直ちに利用可能
✓ 自動フレームワーク適用: Security Essentials が自動適用、初期設定の手間を削減

⚠️ デメリット・制約事項

⚠️ 制限事項:
  • プロジェクトレベルでの新規 Standard ティアのアクティベーションは Standard-legacy 機能のみ (Enhanced 不可)
  • Compliance Manager は Customer-Managed Encryption Keys (CMEK) をサポートしない
  • Compliance Manager を有効化した後に無効化することはできない
  • プロジェクトレベルのアクティベーションではデータレジデンシーがサポートされない
🔍 考慮すべき点:
  • 既存の Standard ティアユーザーのマイグレーションタイミングは Google 側で制御される
  • Security Health Analytics と Compliance Manager を同じリソースで有効化すると重複 findings が発生する可能性
  • 組織に Premium ティアがプロジェクトレベルでアクティベートされている場合、Standard ティアの自動マイグレーション対象外

🎯 ユースケース

🏗️ ユースケース 1: マルチプロジェクト環境での段階的コンプライアンス導入

シナリオ: 複数のプロジェクトを持つ組織で、本番環境プロジェクトから順次コンプライアンス管理を導入したい場合

効果: まず本番環境プロジェクトのみに Compliance Manager を有効化し、Security Essentials フレームワークでセキュリティベースラインを確立。問題なければ他プロジェクトにも順次展開できる。

🆕 ユースケース 2: 新規組織でのセキュリティ基盤構築

シナリオ: 新しく Google Cloud 組織を作成し、セキュリティ対策の基盤を構築したい場合

効果: 組織レベルで Standard ティアを新規アクティベートすることで、追加費用なしで Compliance Manager、DSPM、Vulnerability Assessment for Google Cloud が利用可能。Security Essentials フレームワークが自動適用され、即座にコンプライアンス監視を開始できる。

📋 ユースケース 3: 規制対応が必要な特定プロジェクトの分離管理

シナリオ: 組織全体では Standard-legacy ティアを使用しているが、特定のプロジェクトで規制準拠の証跡が必要な場合

効果: 該当プロジェクトのみに Compliance Manager を有効化し、コンプライアンス状況の可視化と証跡管理を実現。組織全体のアップグレードを待たずに対応可能。
