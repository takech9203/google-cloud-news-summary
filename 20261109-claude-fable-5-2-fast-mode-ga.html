🤖 Claude Fable 5.2 が GA、Claude モデル向け Fast モードも GA

Anthropic の最新 Fable 系モデルを本番利用可能に。"speed": "fast" パラメータ 1 つで出力トークン生成を高速化

📋 概要

Model Garden で Anthropic の最新モデル Claude Fable 5.2 (claude-fable-5-2) が GA になりました。コーディングや金融など技術・科学分野の作業向けに設計され、曖昧な問題への長時間の取り組み、自己検証、サブエージェントのオーケストレーションに対応します。

あわせて、対応 Claude モデル (第一弾は Claude Fable 5.2) 向けの Fast モードが GA になりました。従量課金 (PayGo) のオンライン予測リクエストに "speed": "fast" を指定するだけで、ベースモデルの知能と安全性を維持したまま出力トークン生成を高速化できます。対話型のエージェント的コーディング、ライブプランニング、インシデント対応などレイテンシ重視のワークロードに最適です。

❌ Before (アップデート前)

  • Claude モデルの出力トークン生成は標準のサービング構成のみ。レイテンシ重視のワークロードでも生成速度を選択できなかった
  • 対話型コーディング反復やインシデント対応では、より小型のモデルに切り替えるなどの妥協が必要だった
  • Fable 系の最新モデルは Claude Fable 5.1 までだった

✅ After (アップデート後)

  • "speed": "fast" の追加だけで同一モデル・同一エンドポイントのまま高速化 (ベータヘッダーや別モデルカード有効化は不要)
  • 専用クォータ anthropic-claude-fable-fast により高速/標準トラフィックのレート制限が分離
  • Claude Fable 5.2 が GA。Fast モード、Computer use、Web search、バッチ予測、プロンプトキャッシュ、Function calling、Memory tool をサポート
🎯 対象ユーザー: Google Cloud 上で Claude モデルを使ったエージェントアプリケーションを構築する開発者、human-in-the-loop の対話的ワークフローで応答速度を重視するチーム

同一の公開モデルエンドポイント (claude-fable-5-2) に対して、リクエストボディの "speed" パラメータの有無で標準速度と Fast モードのサービング経路が切り替わり、それぞれ独立したクォータと料金体系で処理されます。

⚡ 主要機能

1️⃣ Claude Fable 5.2 (claude-fable-5-2) の GA 提供

→技術・科学分野 (コーディング、金融など) の作業向けに設計された Anthropic の最新 GA モデル
→曖昧な問題への長時間の取り組み、自己検証、サブエージェントのオーケストレーションに対応
→入力はテキスト・画像・PDF、出力はテキスト。最大入力 1,000,000 トークン / 最大出力 128,000 トークン
→Fast モード、Computer use、Web search、バッチ予測、プロンプトキャッシュ、Function calling、トークンカウント、Memory tool をサポート
→リリース日は 2026 年 11 月 9 日、廃止日は 2027 年 11 月 9 日より前にならない

2️⃣ Fast モード ("speed": "fast") の GA 提供

→オンライン従量課金予測リクエストのトップレベルに "speed": "fast" を設定するだけで出力トークン生成を高速化
→ベースモデルの知能・安全性を維持する高速サービング構成。anthropic-beta ヘッダーや別モデルカードの有効化は不要
→応答の usage.speed フィールド (ストリーミングでは message_start / message_delta イベント) で実際の速度を確認可能
→サポートロケーションは global / us / eu。リージョナルエンドポイントは非対応

3️⃣ Fast モードのライフサイクルポリシー

→Fast モードは対応モデルファミリーの最新バージョンで提供。新バージョン公開後、旧バージョンには 30 日間の移行期間
→移行期間終了後、旧バージョンへの "speed": "fast" リクエストは HTTP 400 (INVALID_ARGUMENT) を返す (標準速度は引き続き動作)

ステップ 1: Fast モードで予測リクエストを送信する (REST)

Bash rawPredict エンドポイントへの送信 
curl -X POST \
  -H "Authorization: Bearer $(gcloud auth print-access-token)" \
  -H "Content-Type: application/json; charset=utf-8" \
  -d @request.json \
  "https://aiplatform.googleapis.com/v1/projects/PROJECT_ID/locations/global/publishers/anthropic/models/claude-fable-5-2:rawPredict"
⚠️ 注意: エンドポイント URL には必ずベースモデル ID (claude-fable-5-2) を指定します。claude-fable-5-2-fast を URL に指定すると HTTP 404 になります。

ステップ 2: Python (Anthropic Vertex SDK) から Fast モードを使用する

Python anthropic[vertex] SDK での利用例 
from anthropic import AnthropicVertex

client = AnthropicVertex(project_id="PROJECT_ID", region="global")
message = client.messages.create(
    model="claude-fable-5-2",
    max_tokens=1024,
    extra_body={"speed": "fast"},  # Fast モードを有効化
    messages=[{"role": "user", "content": "..."}],
)

anthropic[vertex] SDK では extra_body={"speed": "fast"} を渡します。応答の usage.speed で実際の速度を検証できます。

ステップ 3: Fast モードが利用できない場合のフォールバックを実装する

💡 推奨: Agent Platform は Fast モードリクエストを暗黙的に標準速度へダウングレードしません。BadRequestError のエラーメッセージを判定して標準速度で再試行する、または次のモデルバージョンの Fast モードへ切り替えるフォールバックをアプリケーション側で実装することが推奨されます。

💡 メリット

💼 ビジネス面

✓対話型エージェント体験の向上: トークン生成の待ち時間が短縮され、human-in-the-loop のコーディング反復やライブプランニングでコンテキストスイッチを減らせる
✓段階的な導入が容易: リクエストパラメータ 1 つで有効化でき、既存のモデル有効化・IAM・組織ポリシー設定をそのまま利用できるため導入コストが低い
✓最新 Fable モデルの本番利用: GA ステータスにより、技術・科学分野の高度なタスクに Claude Fable 5.2 を本番ワークロードで利用できる

⚙️ 技術面

✓クォータの分離: Fast モードは専用の anthropic-claude-fable-fast クォータを使用するため、高速トラフィックが標準トラフィックのレート制限を圧迫しない (逆も同様)
✓可観測性: Cloud Monitoring で model_user_id="claude-fable-5-2-fast" によって Fast モードのリクエスト数・トークン使用量・レイテンシを標準速度と分けて監視できる
✓モデル品質の維持: Fast モードはベースモデルの知能と安全性を維持する高速サービング構成であり、モデルを変えずに速度だけを選択できる

⚠️ デメリット・制約事項

🚫 制限事項

✗Fast モードは Provisioned Throughput に非対応。常に従量課金 (PayGo) となり、ベースモデルの Provisioned Throughput 注文があっても消費・スピルオーバーしない
✗Fast モードのロケーションは global / us / eu のみ。リージョナルエンドポイントへの "speed": "fast" リクエストは HTTP 400 (FAILED_PRECONDITION)
✗X-Vertex-AI-LLM-Request-Type: dedicated ヘッダー付きの Fast モードリクエストは HTTP 429 (RESOURCE_EXHAUSTED) でスロットル (ヘッダーを省略するか shared を指定)
✗Claude Fable 5.2 自体も Provisioned Throughput は非対応 (Shared Model Lineage Quota のみ)
✗Fast モードのトークン料金は標準速度の 2 倍 (全トークンタイプ)

🤔 考慮すべき点

⚠️新バージョンのモデル公開後、旧バージョンの Fast モードは 30 日で廃止される。廃止後は HTTP 400 となるため、標準速度へのフォールバックまたは次バージョンへの移行処理を実装しておく必要がある
⚠️Fast モードリクエストは暗黙にダウングレードされないため、可用性エラーのハンドリングはアプリケーション側の責務
⚠️Claude Fable 5.2 は Advanced AI Safety Addendum の対象であり、不正利用監視の目的で全プロンプト・レスポンスが最大 30 日間保存される
⚠️claude-fable-5-2-fast はモニタリング用のメトリクスラベルであり、呼び出し可能なモデル ID ではない点に注意

🎯 ユースケース

💻 ユースケース 1: 対話型エージェントコーディング

シナリオ: 開発者が human-in-the-loop のコーディングエージェントで、複数ステップのリファクタリングやデバッグを反復する。応答待ちが長いとコンテキストスイッチが発生し生産性が落ちる。

Python 実装例 
message = client.messages.create(
    model="claude-fable-5-2",
    max_tokens=4096,
    extra_body={"speed": "fast"},
    messages=[{"role": "user", "content": "このモジュールをリファクタリングして..."}],
)

効果: 出力トークン生成が高速化され、開発者が対話のテンポを維持したまま反復作業を進められる。

🚨 ユースケース 2: インシデント対応の高速トリアージ

シナリオ: 本番アラートの発生時に、エージェントがアラート内容と運用コンテキストを集約し、根本原因の分析と緩和手順を生成する。推論のターンアラウンドタイムが対応速度に直結する。

効果: Fast モードによりトリアージと修復手順の生成が高速化され、MTTR (平均復旧時間) の短縮に寄与。レイテンシ非依存のバッチ分析は標準速度 (1x 料金) に振り分けることでコストも最適化できる。

🔬 ユースケース 3: 技術・科学分野の高度なエージェントワークロード

シナリオ: 複雑なコーディング、数学、金融分析などの長時間タスクを、サブエージェントのオーケストレーションと自己検証を活用して自律的に処理する。

効果: GA となった Claude Fable 5.2 の 100 万トークン入力と Memory tool・Computer use などの機能により、大規模コードベースや長大なドキュメントを扱う本番エージェントを構築できる。

💰 料金

Claude Fable 5.2 は従量課金 (pay-as-you-go) で、トークン数に基づいて課金されます。Fast モードの料金は以下のとおりです。

項目料金
トークン (入力 / 出力 / 5 分・1 時間キャッシュ書き込み / キャッシュヒット)標準速度のトークン料金の 2 倍
Web search ツール呼び出し標準 (1x) 料金で課金
課金の計上ベースモデルの Google Cloud SKU に Fast モードのラベル付きで計上
Provisioned Throughput利用不可 (Fast モードは常に PayGo)
💡 コスト最適化のヒント: Fast モードは対話型・時間クリティカルな処理に限定し、レイテンシ非依存のバッチ処理は標準速度 (1x) に振り分けるのが効果的です。具体的なトークン単価は Agent Platform の料金ページを参照してください。

📝 まとめ

Claude Fable 5.2 の GA と Fast モードの GA により、Google Cloud 上で最新の Fable 系モデルを本番利用しつつ、"speed": "fast" パラメータ 1 つでレイテンシ重視のエージェントワークロードを高速化できるようになりました。

Fast モードは料金が標準の 2 倍かつ PayGo 限定のため、対話型・時間クリティカルな処理に限定して適用し、バッチ処理は標準速度と使い分けるのが効果的です。導入時は、モデルバージョン更新に伴う 30 日の Fast モード廃止ウィンドウを踏まえたフォールバック実装を推奨します。
