📋 概要

Looker 26.8 は、CI (継続的インテグレーション) 機能の GA 化を中心に、AI エージェント連携、データベース統合、ダッシュボード UX 改善など多岐にわたる機能強化を含む大型リリースです。

特に注目すべきは、Looker マネージド MCP サーバーの Preview 提供開始により、Gemini CLI や Claude Desktop などの AI エージェントから Looker インスタンスへのセキュアな接続が可能になった点です。

🤖 AI 連携のハイライト: Conversational Analytics の強化 (Development Mode 対応、オブザーバビリティメトリクス、Agentic Workflows) により、Looker の AI 活用がさらに進化しています。

🔄 Before / After

❌ Before (アップデート前)

  • LookML の変更検出に標準的な自動テスト手段が限定的 (CI は Preview)
  • AI エージェント接続に独自ミドルウェアの構築が必要
  • BigQuery Graph / Snowflake Semantic Views と Looker セマンティックレイヤーの統合方法がなかった
  • Conversational Analytics は本番データのみ、開発モードでテスト不可
  • ダッシュボードタイルのサイズ調整が粗い単位

✅ After (アップデート後)

  • Looker CI が GA に昇格、PR ごとの自動バリデーション
  • マネージド MCP サーバーでミドルウェア不要の AI 接続
  • sql_analytic_model_name で BigQuery Graph / Snowflake を LookML から参照
  • Development Mode で Conversational Analytics のクエリ実行をサポート
  • Granular Dashboard Sizing でピクセル単位のレイアウト調整

🚀 主要機能

GA 1. Looker Continuous Integration

LookML プロジェクトに対する自動テスト機能が一般提供に昇格。4 種類のバリデーターで品質を自動検証します。

📝 PR 送信
→
🔍 CI トリガー
→
✅ バリデーション
→
📊 結果レポート
  • SQL Validator / Assert Validator / Content Validator / LookML Validator
  • GitHub App 連携で PR 送信時に自動トリガー
  • CI スイートでバリデーターの組み合わせを定義
  • 有効化時に 10 個の Looker CI ユーザーが自動作成

Preview 2. Looker マネージド MCP サーバー

Model Context Protocol (MCP) サーバーを Looker プラットフォーム内にビルトインで提供。AI エージェントから直接接続可能に。

  • Gemini CLI、Claude Desktop、Cursor、Copilot などが直接接続
  • OAuth 認証によるセキュアな接続 (ユーザーの Looker ロールを継承)
  • 管理者が個別ツールの有効/無効をきめ細かく制御
  • 別途ミドルウェアのデプロイ・運用が不要

Preview 3. Analytic Models 統合

BigQuery Graph および Snowflake Semantic Views との連携機能。sql_analytic_model_name パラメータで既存の分析モデルを LookML ビューの基盤として参照。

  • BigQuery: <project>.<dataset>.<analytic_model_name> 形式
  • Looker と他の BI ツール間でセマンティック定義の一貫性を維持

Preview 4. Agentic Workflows

自然言語で Conversational Analytics データエージェントに指示し、条件ベースの通知ワークフローを作成。

  • 通知先: Email、Slack、Looker モバイルアプリ
  • 監視頻度: 月次 / 週次 / 日次 / 時間単位 / 15 分単位
  • Gemini powered key driver analysis による原因分析 (オプション)

Preview 5. Conversational Analytics: Development Mode

Development Mode でクエリを実行する機能を新たにサポート。LookML 開発者が開発中のモデル変更を AI アシスタント経由でテスト可能に。

Preview 6. Conversational Analytics オブザーバビリティ

エンゲージメントおよびトークン使用量データを含む拡張オブザーバビリティメトリクス。AI 機能の利用状況と費用を可視化。

Preview 7. Granular Dashboard Sizing

ダッシュボードタイルのサイズとレイアウトをピクセル単位で変更可能。ダッシュボードエディターが Labs 設定から有効化。

🔧 技術仕様

Looker CI の構成要素

項目 詳細
SQL Validator Explore のディメンションがデータベースに対して正しく実行されるか検証
Assert Validator LookML データテストを実行し、全ての失敗とエラーを報告
Content Validator Looks とダッシュボードのコンテンツバリデーションを実行
LookML Validator LookML 構文エラーをチェック
自動作成ユーザー数 10 (CI 有効化時に自動作成)
GitHub 連携 CI GitHub App のインストールが必要 (PR トリガー利用時は必須)

MCP サーバー仕様

項目 詳細
認証方式 OAuth 2.0
対応インスタンス Looker (Google Cloud core)、Looker (original) ホスト型
非対応 カスタマーホスト型 (オンプレミス) インスタンス
ツール制御 管理者による個別ツールの有効/無効切替
アクセス権限 認証ユーザーの Looker ロールを継承

Analytic Models 対応

項目 詳細
対応データベース BigQuery、Snowflake
BigQuery モデル BigQuery Graph (Property Graph)
Snowflake モデル Semantic Views
LookML パラメータ sql_analytic_model_name
スコープ形式 <database>.<schema>.<analytic_model_name>

⚠️ 制約事項・注意点

制限事項
  • ✕ Looker CI は Public IP 構成のインスタンスのみ (Private/Hybrid 非対応)
  • ✕ Looker CI は CMEK 有効インスタンスでは利用不可
  • ✕ CI データの一部は米国に保存 (データレジデンシー要件に注意)
  • ✕ MCP サーバーはカスタマーホスト型 (オンプレミス) では利用不可
  • ✕ Agentic Workflows は複雑なカスタムメトリクス、ディメンション、テーブル計算の監視に非対応
💡 考慮すべき点
  • CI 有効化時の 10 CI ユーザーには access_grant 用のユーザー属性値設定が必要
  • MCP ツール変更時は AI クライアント側の再接続が必要
  • Looker CI は FedRAMP High/Moderate、DoD IL5 の認可境界には含まれない
  • Preview 機能はサポートが限定的 - 本番ワークロードでの使用は慎重に検討

💡 ユースケース

🔄 ユースケース 1: LookML 開発の CI/CD パイプライン

シナリオ: 大規模 LookML プロジェクトを複数開発者が共同開発。手動レビューだけでは品質担保が困難。

実装: Looker CI 有効化 → GitHub App インストール → CI スイート作成 (SQL + LookML + Content Validator) → PR 送信時に自動トリガー

効果: プロダクション環境へのデプロイ前に SQL エラーやコンテンツの破損を自動検出し、エンドユーザーへの影響を未然に防止。

🤖 ユースケース 2: AI エージェントによるセルフサービス分析

シナリオ: 営業チームが Looker 操作に不慣れ。AI アシスタントを通じて自然言語でデータにアクセスしたい。

実装: MCP サーバー有効化 → ツール (looker_query 等) 有効 → AI エージェントを OAuth クライアント登録 → 各メンバーが接続

効果: 「先月の地域別売上を教えて」と AI に尋ねるだけで、Looker のセマンティックレイヤーに基づいた正確なデータを取得可能。

📈 ユースケース 3: データ異常の自動検知と通知

シナリオ: EC サイトの売上データを監視し、異常な落ち込みを即座に通知したい。

実装: Conversational Analytics で売上 Explore エージェントを開く → 「日次売上が前日比20%以上減少したら Slack に通知して」と自然言語で指示

効果: 非技術者でも高度な監視ルールを自然言語で構築可能。Gemini key driver analysis で原因の示唆も自動提供。
