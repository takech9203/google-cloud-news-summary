🗄️ Bigtable: list_hot_tablets MCP ツールが GA に

Cloud Bigtable GA MCP
2026-07-14

📋 概要

Bigtable のリモート MCP サーバーで提供される list_hot_tablets ツールが一般提供 (GA) になりました。 AI エージェントが Model Context Protocol (MCP) を通じて Bigtable クラスタのヘルスを問い合わせ、 リソース集約型のタブレット (ホットタブレット) や過負荷状態のノード CPU をプログラム的に検出できます。

🤖 MCP とは: 大規模言語モデル (LLM) や AI アプリケーションが外部データソースに接続するための標準プロトコル。Gemini CLI、Claude、ChatGPT などから直接 Bigtable のクラスタヘルス情報を取得可能。

🎯 対象ユーザー

🔧 SRE エンジニア 🗄️ データベース管理者 ⚙️ DevOps エンジニア

🔄 Before / After

❌ Before (アップデート前)

  • ホットタブレット検出に手動 gcloud CLI や Admin API 呼び出しが必要
  • AI エージェントからクラスタヘルス情報へ直接アクセスする標準的方法がない
  • パフォーマンス問題の検出・対応に人手が介在し MTTR が長い

✅ After (アップデート後)

  • AI エージェントが MCP 経由で直接ホットタブレット情報をクエリ
  • 自動化されたパフォーマンス監視・障害検知パイプラインの構築が容易
  • AI 駆動の自律的なトラブルシューティングが可能に

⚡ 主要機能

🔍 list_hot_tablets MCP ツール

  • ノード CPU 使用率の高い順にホットタブレットを返却
  • 最大 48 時間の時間範囲でクエリ可能 (過去 14 日以内)
  • 読み取り専用ツール (Read Only Hint: true) で安全に使用可能

🌐 リモート MCP サーバー統合

  • エンドポイント: bigtableadmin.googleapis.com/mcp
  • HTTP トランスポートによるリモート接続
  • OAuth 2.0 + IAM による認証・認可
  • Bigtable API を有効化するだけで自動的に利用可能

🤖 AI エージェント互換性

  • Gemini CLI、Claude、ChatGPT、カスタムアプリケーションに対応
  • JSON-RPC 2.0 プロトコルによる標準的な通信
  • ページネーション対応で大量結果にも対応

🛠️ 設定方法

📋 前提条件:
  • Google Cloud プロジェクトで Bigtable API が有効化されていること
  • roles/mcp.toolUser (MCP ツール呼び出し権限) が付与されていること
  • roles/bigtable.admin または bigtable.viewer 権限を含むロールが付与されていること

Step 1: IAM ロールの付与

Bash IAM ロール設定 
# MCP ツールユーザーロールの付与
gcloud projects add-iam-policy-binding PROJECT_ID \
  --member="serviceAccount:AGENT_SA@PROJECT_ID.iam.gserviceaccount.com" \
  --role="roles/mcp.toolUser"

# Bigtable 閲覧者ロールの付与 (ホットタブレットの一覧に必要)
gcloud projects add-iam-policy-binding PROJECT_ID \
  --member="serviceAccount:AGENT_SA@PROJECT_ID.iam.gserviceaccount.com" \
  --role="roles/bigtable.viewer"

Step 2: MCP クライアントの設定

JSON MCP クライアント設定ファイル 
{
  "mcpServers": {
    "bigtable": {
      "url": "https://bigtableadmin.googleapis.com/mcp",
      "transport": "http",
      "auth": {
        "type": "oauth2",
        "scope": "https://www.googleapis.com/auth/bigtable.admin"
      }
    }
  }
}

Step 3: ツールの呼び出しテスト

Bash curl によるテスト呼び出し 
curl --location 'https://bigtableadmin.googleapis.com/mcp' \
  --header 'content-type: application/json' \
  --header 'accept: application/json, text/event-stream' \
  --header "authorization: Bearer $(gcloud auth print-access-token)" \
  --data '{
    "method": "tools/call",
    "params": {
      "name": "list_hot_tablets",
      "arguments": {
        "projectId": "my-project",
        "instanceId": "my-instance",
        "clusterId": "my-cluster"
      }
    },
    "jsonrpc": "2.0",
    "id": 1
  }'

🔬 技術面

📐標準プロトコル準拠 - MCP で特定ツールに依存しない実装が可能
🔎細粒度の監視 - 1 分単位のホットタブレット情報で短時間のホットスポットも発見可能
📊クラスタレベルの可視性 - テーブル横断で CPU 使用状況を把握

⚠️ 制約事項・注意点

制限事項:
  • テーブルのデータ量がクラスタあたり 1 GB 未満の場合、ホットタブレット情報は利用不可
  • テーブルが 1 GB に達してから利用可能になるまで最大 1 時間のラグ
  • 検索可能な時間範囲は最大 48 時間、過去 14 日以内に限定
  • 15 分間隔内で同一タブレットが複数回ホットと判定された場合、最も CPU 使用率の高いもののみ返却
🔒 セキュリティ考慮事項:
  • IAM ロールは最小権限で bigtable.viewer を推奨 (bigtable.admin は過剰)
  • API キー認証は不可、OAuth 2.0 による認証が必須
  • エージェント用の専用サービスアカウントを作成しアクセスを監視
  • Model Armor の有効化でプロンプトインジェクション等のリスクを軽減

🚨 UC1: AI 駆動の自動パフォーマンストリアージ

シナリオ: SRE チームが AI エージェントを使用して Bigtable クラスタのパフォーマンス問題を自動トリアージ

効果: 定期的にホットタブレットを監視し、CPU 使用率が閾値超えで自動的に PagerDuty チケットを作成。影響テーブルとキー範囲を含むレポートを自動生成。

効果: 単調増加する行キー (タイムスタンプベースなど) によるホットスポットを自動検出し、キーのソルティングやハッシュ化などの改善策を提案。

📋 UC3: マルチテーブルクラスタの問題テーブル特定

シナリオ: 複数テーブルを含むクラスタで、CPU リソースを過剰消費しているテーブルを AI エージェントが自動判別

効果: テーブル横断分析で問題テーブルを迅速に特定し、テーブル単位のスケーリングやトラフィック分散の判断を支援。
