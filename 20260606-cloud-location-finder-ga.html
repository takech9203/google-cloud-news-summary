📋 概要

Cloud Location Finder が一般提供 (GA) となりました。5つのクラウドプロバイダーにまたがるリージョンとゾーンのロケーションを、近接性（レイテンシ）、地理的位置（テリトリーコード）、カーボンフットプリント（CFE%）に基づいて特定・フィルタリングできる公開 API です。

💡 ポイント: 2025年6月のパブリックプレビューを経て約1年間の運用実績を積み、SLA 保証付きの本番利用が可能になりました。REST API v1 エンドポイントが安定版として利用可能です。

Cloud Location Finder はクライアントからのリクエストを受け付け、内部のロケーションリポジトリを参照して5つのプロバイダーのロケーション情報を返却します。

⚡ 主要機能

📍 近接性検索 (Proximity Search)

ネットワークレイテンシ (RTT) に基づいて、ソースロケーションから最も近いクラウドロケーションを検索。クラウドプロバイダーをまたいだ比較が可能。

🗺️ テリトリーコードフィルタリング

ISO 3166-1 alpha-2 コードによる国・地域ベースのフィルタリング。データレジデンシーやコンプライアンス要件に対応。

🌱 カーボンフリーエネルギー (CFE%) ソート

Google Cloud ロケーションのカーボンフリーエネルギー使用率に基づくソート。サステナビリティ目標に合致した選定を支援。

🗄️ マルチクラウドリポジトリ

GCP, GDC, AWS, Azure, OCI のロケーションを統合管理。24時間ごとに自動更新で常に最新情報を提供。

🔒 VPC Service Controls 対応 (Preview)

セキュリティ境界内での Cloud Location Finder の利用が可能。機密性の高い環境での利用を支援。

フィルタリングオプション

フィルタフィールド 説明 例
carbon_free_energy_percentage CFE% でフィルタ (Google Cloud のみ) > 75
cloud_location_type ロケーションタイプ (REGION, ZONE 等) = CLOUD_LOCATION_TYPE_REGION
cloud_provider クラウドプロバイダー = CLOUD_PROVIDER_GCP
territory_code ISO 3166-1 alpha-2 国コード = "JP"
latency レイテンシ (ms 単位の RTT) < 50
containing_cloud_location 親ロケーション リソース名で指定

🛠️ 設定方法

1. API 有効化
→
2. IAM ロール付与
→
3. 検索実行

ステップ 1: API の有効化

Bash 
gcloud services enable cloudlocationfinder.googleapis.com --project PROJECT_ID

ステップ 2: IAM ロールの付与

Bash 
gcloud projects add-iam-policy-binding PROJECT_ID \
  --member user:myemail@example.com \
  --role roles/cloudlocationfinder.viewer

ステップ 3: 近接性検索の実行

Bash 
# 最も近い Google Cloud ゾーンを検索
gcloud cloudlocationfinder cloud-locations search \
  --source-cloud-location=aws-us-east-1 \
  --query="cloud_provider=CLOUD_PROVIDER_GCP AND cloud_location_type=CLOUD_LOCATION_TYPE_ZONE" \
  --limit=1

ステップ 4: テリトリーコードによるフィルタリング

Bash 
# 日本国内のリージョンを検索
gcloud cloudlocationfinder cloud-locations list \
  --filter="territory_code=\"JP\" AND cloud_location_type=CLOUD_LOCATION_TYPE_REGION"

🎯 ユースケース

🔄 ユースケース 1: マルチクラウド DR サイト選定

シナリオ: AWS us-east-1 で稼働するアプリの DR サイトを Google Cloud に構築する際、最もレイテンシが低い Google Cloud ゾーンを特定。

Bash 
gcloud cloudlocationfinder cloud-locations search \
  --source-cloud-location=aws-us-east-1 \
  --query="cloud_provider=CLOUD_PROVIDER_GCP AND cloud_location_type=CLOUD_LOCATION_TYPE_ZONE" \
  --limit=3

効果: 手動でのネットワークテスト不要で、RTT データに基づく最適な DR サイト候補を即座に特定。

🏛️ ユースケース 2: データレジデンシー対応

シナリオ: GDPR 対応のため、EU 域内のみにデータを保持する必要があるマルチクラウド環境で、利用可能な全プロバイダーのリージョンを一覧化。

Bash 
gcloud cloudlocationfinder cloud-locations list \
  --filter="territory_code=\"DE\" AND cloud_location_type=CLOUD_LOCATION_TYPE_REGION"

効果: 複数プロバイダーのドキュメントを個別調査する手間を省き、コンプライアンス要件を満たすロケーションを一括確認。

🌱 ユースケース 3: サステナブルなクラウド利用

シナリオ: サステナビリティ目標に基づき、CFE% が 75% 以上の Google Cloud リージョンを特定。

Bash 
gcloud cloudlocationfinder cloud-locations list \
  --filter="cloud_provider=CLOUD_PROVIDER_GCP AND cloud_location_type=CLOUD_LOCATION_TYPE_REGION AND carbon_free_energy_percentage > 75"

効果: サステナビリティ KPI に直結するロケーション選定を自動化し、環境報告にも活用可能。

✓レイテンシベースの最適化: RTT データに基づく客観的評価

⚠️ 制限事項・注意点

制限事項:
  • CFE% データは Google Cloud ロケーションのみで利用可能。サードパーティの CFE データは非提供
  • サードパーティクラウドのロケーションデータは公開情報に基づき、正確性は保証されない
  • VPC Service Controls 対応は現在 Preview 段階
💡 考慮すべき点:
  • レイテンシデータはネットワーク条件により変動するため、定期的な再評価を推奨
  • 大規模クエリでは API クォータに注意
  • GDC connected ロケーション検索には GDC Hardware Management API の有効化と roles/gdchardwaremanagement.reader が追加で必要
