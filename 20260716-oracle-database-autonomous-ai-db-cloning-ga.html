📋 概要

Oracle Database@Google Cloud において、Autonomous AI Database のクローニング機能が一般提供 (GA) となりました。既存の Autonomous AI Database から新しいデータベースインスタンスを作成でき、ソースデータベースに影響を与えることなくデータやメタデータの複製が可能になります。

gcloud CLI および Oracle Database@Google Cloud API を使用して、フルクローン、メタデータクローン、リフレッシャブルクローンの 3 種類のクローンを作成できます。

🔄 Before / After

❌ Before (アップデート前)

  • 手動でのエクスポート/インポートやバックアップからのリストアが必要
  • 構造のみの複製に標準的な手段がなかった
  • テスト/レポーティング環境と本番データの定期同期が困難
  • 運用負荷が高く、環境構築に数日を要する

✅ After (アップデート後)

  • gcloud CLI / API で簡単にクローン作成が可能
  • 用途に応じた 3 種類のクローンを選択可能
  • リフレッシャブルクローンで増分同期が可能
  • バックアップからのクローンで特定時点データを復元可能

⚡ 主要機能: 3 種類のクローン

📦 フルクローン (Full Clone)

  • 全データおよびメタデータの完全コピー
  • インスタンスまたはバックアップからクローン可能
  • クローン後は独立した読み書き可能なDB
  • 本番データの完全複製が必要なシナリオに最適

🏷️ メタデータクローン (Metadata Clone)

  • メタデータ (ユーザー、ロール、テーブル構造) のみ複製
  • 実データなしのため高速に作成可能
  • スキーマ検証、CI/CD パイプラインに最適
  • バックアップからのメタデータクローンも可能

🔄 リフレッシャブルクローン (Refreshable Clone)

  • ソースDBの読み取り専用コピー
  • 増分リフレッシュで効率的にソースと同期
  • 独立したコンピュート/ストレージで動作
  • 手動/自動リフレッシュモード選択可能
  • レポーティング/分析ワークロードに最適

🛠️ 設定方法

前提条件

✓ クローンのソースとなる既存の Autonomous AI Database が必要
✓ roles/oracledatabase.autonomousDatabaseAdmin IAM ロールが付与されていること
✓ Oracle Database@Google Cloud の環境セットアップが完了していること

フルクローンの作成 (gcloud CLI)

Bash 
gcloud oracle-database autonomous-databases create CLONE_ID \
  --project=PROJECT_ID \
  --location=REGION \
  --admin-password=ADMIN_PASSWORD \
  --database=CLONE_NAME \
  --display-name=DISPLAY_NAME \
  --properties-license-type=LICENSE_TYPE \
  --properties-compute-count=COMPUTE_COUNT \
  --properties-db-version=DATABASE_VERSION \
  --properties-db-workload=WORKLOAD_TYPE \
  --properties-data-storage-size-gb=STORAGE_SIZE \
  --properties-mtls-connection-required \
  --source-config-autonomous-database="projects/PROJECT_ID/locations/REGION/autonomousDatabases/SOURCE_DATABASE_ID" \
  --source-config-type="CLONE_DATABASE" \
  --source-config-clone-type="FULL"

メタデータクローンの作成 (gcloud CLI)

Bash 
gcloud oracle-database autonomous-databases create CLONE_ID \
  --project=PROJECT_ID \
  --location=REGION \
  --admin-password=ADMIN_PASSWORD \
  --database=CLONE_NAME \
  --display-name=DISPLAY_NAME \
  --properties-license-type=LICENSE_TYPE \
  --properties-compute-count=COMPUTE_COUNT \
  --properties-db-version=DATABASE_VERSION \
  --properties-db-workload=WORKLOAD_TYPE \
  --properties-data-storage-size-gb=STORAGE_SIZE \
  --properties-mtls-connection-required \
  --source-config-autonomous-database="projects/PROJECT_ID/locations/REGION/autonomousDatabases/SOURCE_DATABASE_ID" \
  --source-config-type="CLONE_DATABASE" \
  --source-config-clone-type="METADATA"

リフレッシャブルクローンの作成 (REST API)

Bash 
curl -X POST \
  -H "Authorization: Bearer $(gcloud auth print-access-token)" \
  -H "Content-Type: application/json" \
  "https://oracledatabase.googleapis.com/v1/projects/PROJECT_ID/locations/REGION/autonomousDatabases/CLONE_ID" -d \
  '{
    "name": "projects/PROJECT_ID/locations/REGION/autonomousDatabases/CLONE_ID",
    "database": "CLONE_NAME",
    "displayName": "DISPLAY_NAME",
    "properties": {
      "licenseType": "LICENSE_TYPE",
      "computeCount": COMPUTE_COUNT,
      "dbVersion": "DATABASE_VERSION",
      "dbWorkload": "WORKLOAD_TYPE",
      "dataStorageSizeTb": STORAGE_SIZE,
      "mtlsConnectionRequired": true
    },
    "sourceConfig": {
      "sourceType": "CLONE_TO_REFRESHABLE",
      "autonomousDatabase": "projects/PROJECT_ID/locations/REGION/autonomousDatabases/SOURCE_DATABASE_ID",
      "cloneType": "FULL",
      "refreshableMode": "MANUAL"
    }
  }'
💡 ヒント: refreshableMode を AUTOMATIC に設定すると自動リフレッシュも可能です。

⚠️ デメリット・制約事項

制限事項
  • クローンは同一 Google Cloud プロジェクト内でのみ作成可能
  • スタンバイデータベースインスタンスからのクローン作成は非対応 (プライマリDBのみ)
  • 複数のクローンの同時作成は非対応 (順次実行が必要)
  • リフレッシャブルクローンのソースDBでは暗号化キーの変更が非対応
考慮すべき点
  • ストレージサイズ: 0.02 TiB ~ 384 TiB (DW は 1 TiB ~ 384 TiB)
  • クローン名: 英字で始まり、最大 30 文字の英数字、OCI テナンシ内で一意
  • 管理者パスワードの設定が必須 (リフレッシャブルクローンは不要)
  • ソースDBの完全なリソースパスの指定が必要

🎯 ユースケース

🧪 ユースケース 1: 開発/テスト環境の迅速な構築

シナリオ: 開発チームが本番データを使用した統合テストを実施する必要があるが、本番DBへの直接アクセスはセキュリティポリシーで禁止されている。

効果: テスト環境の構築時間を数日から数分に短縮し、本番同等のデータでの品質検証が可能になる。

📊 ユースケース 2: レポーティング/分析ワークロードのオフロード

シナリオ: BI チームが本番データに対してリアルタイムに近い分析クエリを実行したいが、本番DBの OLTP パフォーマンスへの影響を回避したい。

効果: リフレッシャブルクローンにより、本番環境のパフォーマンスに影響を与えず、独立したコンピュートリソースで重い分析処理を実行可能。

🔄 ユースケース 3: CI/CD パイプラインでのスキーマ検証

シナリオ: データベーススキーマの変更を本番適用する前に、自動テストでマイグレーションスクリプトの正当性を検証したい。

効果: メタデータクローンにより、データベース構造のみを高速に複製し、CI/CD パイプラインに容易に組み込める。

💰 料金情報

Oracle Database@Google Cloud の料金は Oracle Cloud Infrastructure (OCI) のリソース使用量に基づいて課金されます。

料金モデル 説明
パブリック (従量課金) 標準のオンデマンド料金。OCPU 時間とストレージ GB 単位で課金
プライベート Oracle 営業チームとのカスタム料金交渉。長期契約による割引が可能
💡 課金の仕組み:
  • クローンされたDBは独立したリソースとして課金 (コンピュート + ストレージ)
  • メタデータクローンはデータなしのため、ストレージ課金が最小限
  • リフレッシャブルクローンは独自のリソースで動作し、それぞれ課金対象
  • Google Cloud の請求書に Oracle サービスの使用量が一元表示

🔗 関連サービス・機能

🛡️ Oracle Data Guard

Autonomous AI Database のスタンバイ構成。クローンはプライマリデータベースからのみ作成可能。

🔄 Oracle GoldenGate

異なるデータベース間のリアルタイムデータレプリケーション。クローンと組み合わせた高度なデータ移行パターンに利用可能。

💾 Zero Data Loss Autonomous Recovery Service

データベースのバックアップと復旧サービス。バックアップからのクローン作成機能と連携。

🔑 Google Cloud IAM

クローン操作の権限管理に使用。roles/oracledatabase.autonomousDatabaseAdmin ロールが必要。

📊 BigQuery

Oracle GoldenGate との統合により、クローンデータベースから BigQuery への分析データ連携が可能。
