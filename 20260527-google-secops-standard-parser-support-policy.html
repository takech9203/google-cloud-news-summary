🔒 Google SecOps: Standard Parser Support Policy

Google SecOps (SIEM) Policy Announcement
2026-05-27

📋 概要

Google SecOps は、Standard パーサーに対する集中的なサポートポリシーを導入しました。プラットフォームの安定性、予測可能なパフォーマンス、高品質なデータ正規化のスケーリングを目的とし、パーサーを Premium / Standard / Community の3階層に分類します。

さらに、Important UDM Fields を通じてコアセキュリティデータを優先的に処理する仕組みと、ロングテールパーサーをコミュニティ主導で管理するモデルを確立しました。

🔄 Before / After 比較

❌ Before (課題)

  • すべてのパーサーに一律のサポートレベルが適用
  • 高優先度データソースへのリソース集中が困難
  • パーサーリクエストの優先度付けが不明確
  • ロングテールパーサーによるメンテナンスコスト増大
  • 重要 UDM フィールドの基準が不明確

✅ After (改善)

  • Premium / Standard / Community の明確な階層化
  • サポートティア別のリクエストトリアージ体系化
  • Important UDM Fields による優先処理
  • GitHub リポジトリへの移行でコミュニティメンテナンス実現
  • 予測可能なサポートレベルの提供

⚡ 主要機能

1. パーサーサポートティアの構造化

✓Premium パーサー: 最も広く使用されている高ボリュームデータソース向け。リクエストは通常数日以内に処理
✓Standard パーサー: その他のサポート対象データソース向け。ベストエフォートでのサポート
✓Community パーサー: 使用率の低いロングテールパーサー。GitHub リポジトリで管理

2. 顧客サポートティア別のトリアージ

✓Standard サポート: 基本的な SLO に基づくリクエスト処理
✓Expert / Expert+ サポート: 強化された SLO と優先的なリクエスト処理
✓サポートティアに応じた明確な優先度付け

3. Important UDM Fields による品質基準

✓コアセキュリティデータの正規化を優先する基準を設定
✓Curated Detections、Indexing、Threat Hunting ごとに重要フィールドを定義
✓Important UDM Fields への正確なマッピングを推奨

4. コミュニティ主導のメンテナンスモデル

✓低使用率パーサーを専用 GitHub リポジトリに移行
✓パートナーおよび Google SecOps コミュニティによる管理
✓Google のリソースを高優先度パーサーに集中

⚠️ デメリット・制約事項

制限事項
✗Community パーサー (GitHub 移行後) は Google による直接サポートが終了。問題発生時のレスポンスが不確実
✗Standard パーサーのフィールドマッピング追加は Feature Request として処理され対応時期が不確定
✗Custom パーサーおよび Extensions には Google からのサポートが提供されない
💡 考慮すべき点
  • 現在使用中のパーサーが Community 移行対象かどうかの確認が必要
  • Community パーサーへの移行後は、パートナー契約またはコミュニティ参加がメンテナンスに必要
  • Important UDM Fields の変更に伴い、既存の Detection Rules への影響確認が推奨

🎯 ユースケース

🏢 ユースケース 1: 高ボリュームデータソースの運用

シナリオ: 大規模 SOC チームが、ファイアウォール、EDR、クラウドサービスなど主要セキュリティツールからのログを大量に取り込んでいる

効果: Premium パーサーとして最優先でサポート。パーサーの問題やフィールドマッピング追加リクエストが数日以内に処理。Expert/Expert+ ティアでさらに迅速な対応。

🔬 ユースケース 2: ニッチなデータソースへの対応

シナリオ: 特定業界固有のアプリケーションや使用率の低いセキュリティツールのログを取り込む必要がある

効果: Parser Extensions や Auto-extract を活用したセルフサービスで即時対応が可能。GitHub リポジトリのコミュニティパーサーも利用・カスタマイズ可能。

🤝 ユースケース 3: パートナーによるパーサー提供

シナリオ: MSSP やセキュリティパートナーが顧客向けにカスタムパーサーを開発・管理

効果: GitHub リポジトリでコミュニティにパーサーを公開・共有。Important UDM Fields の基準に沿った開発で Curated Detections との統合品質を確保。

🔗 関連サービス・機能

☁️Google SecOps SIEM: パーサーが動作する基盤プラットフォーム。ログ取り込みから UDM 正規化、脅威検知までの一連の処理を担う
🛡️Curated Detections: Important UDM Fields に正確にマッピングされたデータを利用する、Google マネージドの脅威検知ルールセット
🔧Parser Extensions: プリビルトパーサーに追加マッピングを定義し、データ取り込みをカスタマイズするセルフサービス機能
🤖Auto-extract: 追加フィールドの自動抽出機能で、Standard パーサーの即時ニーズに対応

📝 まとめ

Google SecOps の Standard Parser Support Policy は、パーサーエコシステムの持続可能な成長に向けた重要な構造改革です。

  • Premium / Standard / Community の明確な階層化で高ボリュームデータソースへの優先対応を実現
  • ロングテールパーサーのコミュニティ主導での維持管理が両立
  • セキュリティ運用チームは利用中パーサーの分類を確認し、必要に応じてセルフサービス対応を検討すること
