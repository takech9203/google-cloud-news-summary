🤖 Gemini Enterprise: Workflow Agents

Gemini Enterprise GA with allowlist
2026-06-18

📋 概要

Gemini Enterprise にワークフローエージェント機能が GA with allowlist として追加されました。設定されたトリガーに基づいて一連のステップやアクションを実行するエージェントを、Gemini Enterprise Web アプリ上で作成・インポート・更新・利用できるようになります。

🤖 ポイント: AI による自動化と人間の介入を組み合わせた処理フローを構築でき、業務プロセスの自動化に活用できます。ノーコード・ローコードで構築可能。

🔄 Before / After 比較

❌ Before (アップデート前)

  • 単一ステップエージェント・マルチステップエージェントのみ利用可能
  • トリガーベースのワークフロー実行に非対応
  • AI 自動化と人間の承認を組み合わせるには外部ツールとの連携が必要
  • イベント駆動型のエージェント実行は実現不可

✅ After (アップデート後)

  • トリガーに基づくワークフローエージェントが自動起動
  • AI 自動処理と人間の介入を同一ワークフロー内で組み合わせ可能
  • ワークフローの作成・インポート・更新が Web アプリ内で完結
  • ビジュアルフローキャンバスで視覚的に編集可能

⚡ 主要機能

🎯 トリガーベースの実行

設定されたトリガー条件に基づいてワークフローエージェントが自動起動。従来のスケジュール実行に加え、イベント駆動型の実行が可能に。

🤝 AI 自動化と人間の介入のミックス

ワークフロー内の各ステップを AI 自動処理または人間の介入として定義可能。人間が必要な判断・承認を挟みながら、全体のプロセスは自動で進行。

📦 ワークフローエージェントの作成・インポート・更新

Gemini Enterprise Web アプリ内で新規作成、外部からのインポート、既存エージェントの設定更新が全て完結。

🎨 Agent Designer との統合

ノーコード・ローコードの Agent Designer プラットフォーム上で構築。ビジュアルフローキャンバスによる視覚的編集やチャットペインを使った自然言語での構成調整が可能。

⚙️ 設定方法

📋 前提条件: Gemini Enterprise ライセンスの保有、Google Cloud プロジェクトの許可リスト追加、Gemini Enterprise Admin ロールを持つ管理者が必要です。

許可リストへの追加依頼

Google アカウントマネージャーに連絡し、Google Cloud プロジェクトを Workflow Agents の許可リストに追加依頼

Agent Designer の有効化

Gemini Enterprise Web アプリの機能管理設定ページで「Enable agent designer」トグルをオンに設定

ワークフローエージェントの作成

ナビゲーションメニューから「+ Create agent」をクリックし、ワークフローエージェントのタイプを選択して構築

テストと公開

Preview タブでテストし、問題なければ「Create」をクリックして公開

ビジネス面

✓ 業務プロセスの自動化促進: 定型的な業務フローを AI と人間の協調作業として自動化し、生産性が向上
✓ コンプライアンス対応: 人間の承認ステップを必須ポイントとして組み込み、ガバナンス要件を満たしながら自動化を実現
✓ ノーコードでの構築: 技術者でない業務担当者でも自然言語やビジュアルキャンバスでワークフローを構築可能

技術面

✓ トリガー駆動型アーキテクチャ: イベントベースのエージェント起動でリアクティブな自動化パイプラインを構築可能
✓ Agent Designer との統合: 既存のエコシステム (データソース接続、サブエージェント構成) をワークフローエージェントでも活用可能
✓ インポート・エクスポート対応: 外部で開発したワークフローエージェントの取り込みが可能で既存資産を再利用

⚠️ デメリット・制約事項

制限事項:
  • GA with allowlist のため、すべての組織がすぐに利用できるわけではない (アカウントマネージャーへの連絡が必要)
  • 管理者による「Enable agent designer」の有効化が必須であり、個別ユーザーが自律的に開始することはできない
  • 具体的なトリガー種別や利用可能なアクションの詳細は、許可リスト追加後にドキュメントで確認が必要
考慮すべき点:
  • 人間の介入ステップではレスポンス待ちが発生するため、ワークフロー全体の完了時間は人間の応答速度に依存
  • 機密データを扱うワークフローでは、各ステップでのデータアクセス権限を適切に設計する必要あり
  • スケジュール実行では 14 日ごとに認証の更新が必要な既知の制限があり、ワークフローエージェントでも同様の制約の可能性

💡 ユースケース

📄 経費精算承認ワークフロー

シナリオ: 従業員が経費精算を提出した際に、AI が自動でレシート内容を確認・分類し、規定額以上の場合は上長の承認を求めるワークフロー。

効果: 手動での経費確認作業を削減しつつ、高額支出には人間による承認を維持しコンプライアンスを確保。

🎧 カスタマーサポートエスカレーション

シナリオ: 顧客からの問い合わせに対し、AI が一次回答を生成。回答の信頼度が閾値を下回る場合や顧客が不満を示した場合に人間のサポート担当者にエスカレーション。

効果: 定型的な問い合わせは AI が即座に対応し、複雑なケースのみ人間が介入することで対応速度と品質を両立。

📝 コンテンツ公開レビューフロー

シナリオ: マーケティングコンテンツの作成をトリガーに、AI が自動でブランドガイドライン準拠チェック・SEO 最適化を行い、最終承認を担当者に求めるワークフロー。

効果: コンテンツ品質チェックの大部分を自動化しつつ、最終判断は人間が行うことで品質とスピードを両立。
