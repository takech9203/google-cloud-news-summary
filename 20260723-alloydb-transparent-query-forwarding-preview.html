📋 概要

AlloyDB for PostgreSQL に Transparent Query Forwarding (透過的クエリ転送) 機能が Preview として追加されました。プライマリノードが読み取り専用クエリをインターセプトし、Read Pool インスタンスに自動転送することで、アプリケーション変更なしで読み取り負荷分散を実現します。

🔄 Before / After 比較

❌ Before (従来)

  • Read Pool 活用にはアプリ側でリーダー/ライターエンドポイントの使い分けリファクタリングが必要
  • モノリシックアプリでは接続先切り替えが困難で Read Pool の恩恵を受けにくい
  • プライマリノードに読み取りクエリが集中し書き込みレイテンシに影響
  • トラフィックスパイク時に手動でクエリルーティング調整が必要

✅ After (TQF 導入後)

  • アプリコード変更なしでプライマリが自動的に読み取りクエリを Read Pool に転送
  • read-your-writes 一貫性が保証され、転送後もプライマリ実行と同等の結果
  • SQL コマンド 1 行で有効化、セッション/DB レベルで制御可能
  • 負荷が高い場合に自動で Read Pool へオフロード、書き込みレイテンシ影響を低減

🏗️ アーキテクチャ図

プライマリノードが全クエリを受信し、読み取り専用かつコスト条件を満たすクエリのみを Read Pool インスタンスに転送します。転送されたクエリは read-your-writes 一貫性を維持した状態で実行されます。

⚠️ デメリット・制約事項

Preview 段階のため SLA 保証がなく、サポートも限定的です。

制限事項

✗PostgreSQL 17 / 18 互換クラスタのみ (16 以前は非対応)
✗volatile 関数やユーザー定義関数を含むクエリは転送対象外
✗SELECT ... FOR UPDATE のようなロック取得クエリは転送不可
✗一時テーブル、UNLOGGED テーブル、カタログテーブルは除外
✗HA ホットスタンバイ / セカンダリクラスタへの転送は非対応

考慮すべき点

  • インデックススキャンの軽量クエリは転送オーバーヘッドが大きいため通常プライマリで実行
  • スナップショット復元等のオーバーヘッドがあり、全クエリがパフォーマンス向上するわけではない
  • マルチステートメントトランザクション内 SELECT は限定的サポート
  • CURRENT_DATE や USER 等の SQL 値関数を含むクエリは転送されない

💡 ユースケース

🛒 ユースケース 1: HTAP ワークロードにおける負荷分離

シナリオ: EC サイトでトランザクション処理と分析クエリが同一 DB 上で実行。分析クエリがプライマリに負荷をかけ、書き込みレイテンシが悪化。

SQL 
-- DB レベルで有効化
ALTER DATABASE ecommerce_db SET alloydb.enable_query_forwarding = ON;

-- 重い分析クエリが自動的に Read Pool に転送される
SELECT category, SUM(amount), COUNT(*)
FROM orders
WHERE order_date >= NOW() - INTERVAL '30 days'
GROUP BY category;

効果: 重い分析クエリが Read Pool にオフロード、プライマリの書き込みレイテンシが安定。アプリ変更ゼロで実現。

🏢 ユースケース 2: モノリシックアプリの段階的モダナイゼーション

シナリオ: レガシーなモノリシック Web アプリが単一接続文字列を使用。リーダー/ライター分離リファクタリングに数ヶ月必要だが、読み取り負荷増加に早急に対応が必要。

効果: リファクタリングを待たずに Read Pool のキャパシティを活用して読み取り負荷を分散。将来のアーキテクチャ刷新までの暫定対策として機能。

📈 ユースケース 3: 予測不可能なトラフィックスパイクへの対応

シナリオ: SaaS アプリで月末レポート生成やキャンペーン中に読み取りトラフィックが急増。スパイクのタイミングが不規則で事前スケーリングが困難。

効果: Read Pool のオートスケーリングと組み合わせ、トラフィックスパイク時にプライマリ負荷を自動分散しサービス安定性を維持。

🌍 利用可能リージョン

AlloyDB for PostgreSQL が利用可能な全リージョンで Transparent Query Forwarding を使用できます。ただし、クエリの転送先は同一リージョン内の Read Pool インスタンスに限定されます。

詳細なリージョン情報は AlloyDB のロケーションページ を参照してください。
