📋 概要

Google Distributed Cloud (software only) for bare metal のパッチバージョン 1.35.700-gke.124 がダウンロード可能になりました。 本バージョンは Kubernetes v1.35.8-gke.100 上で動作します。 リリース後、GKE On-Prem API クライアント (Google Cloud コンソール、gcloud CLI、Terraform) でのインストールやアップグレードに利用可能になるまで、約 7〜14 日かかります。

本リリースの中心は、信頼を失効した eMudhra (emSign) および AAA Certificate Services ルート CA の削除というセキュリティ強化と、 クラスタ運用の安定性に関わる複数の重要なバグ修正です。特に、コントロールプレーンノードのリセット/削除時に IP アドレスのプレフィックス一致により誤った etcd メンバーが削除される問題や、 ノード削除時にローカル PersistentVolume リソースが孤立する問題など、 オンプレミスクラスタの運用担当者に直接影響する修正が含まれています。

💡 ストレージ利用者向け: サードパーティのストレージベンダーを使用している場合は、本リリースの認定を通過済みかどうかを ストレージパートナー一覧 で確認してください。

❌ アップデート前の課題

  • 失効した eMudhra (emSign) / AAA Certificate Services ルート CA が残存し、侵害された eMudhra 中間 CA を拒否できていなかった
  • ノード削除時にローカル PersistentVolume が GC されず孤立したまま残っていた
  • コントロールプレーンノードのリセット/削除時、IP プレフィックス一致 (例: 10.201.0.2 と 10.201.0.26) で誤った etcd / etcd-events メンバーが削除され、ノードが NotReady になりアップグレードが停止
  • イメージ展開中のノード再起動で containerd の状態が破損することがあった
  • アップグレード/ロールバック中に構成ドリフトヘルスチェックが「version not supported」エラーで失敗
  • audit-proxy が恒久的エラーに対しても監査ログエクスポートを無限リトライし、過剰なトラフィックを発生
  • プリフライトヘルスチェックが管理クラスタの全 Namespace をスキャンし、無関係なクラスタの古い reconciling リソースでアップグレードが失敗

✅ アップデート後の改善

  • システムコンポーネントとコンテナベースイメージから失効ルート CA を削除し、侵害された eMudhra 中間 CA を拒否
  • ノード削除時にローカル PV が自動でガベージコレクションされる (アップグレード後に作成された PV に適用。既存の孤立 PV は手動削除が必要)
  • IP プレフィックス一致による誤った etcd メンバー削除が解消され、コントロールプレーンノードのリセット/削除が安全に
  • イメージ展開中のノード再起動に対する containerd の耐性が向上
  • アップグレード/ロールバック中の構成ドリフトヘルスチェックの誤検知が解消
  • Vulnerability fixes に記載の脆弱性を修正

🔧 バグ修正 (Fixed)

🛡️ 1. 脆弱性修正

Vulnerability fixes に記載された脆弱性を修正。

💾 2. ノード削除時のローカル PersistentVolume の孤立

ノードをクラスタから削除した際にローカル PV リソースが GC されず残存していた問題を修正。本修正は 1.35.700-gke.124 へのアップグレード後に作成されたローカル PV に適用され、既存の孤立 PV は手動で削除する必要があります。

🗳️ 3. etcd / etcd-events メンバーの誤削除

コントロールプレーンノードのリセット/削除時に、別ノードの IP アドレスが同じプレフィックスを共有する場合 (例: 10.201.0.2 と 10.201.0.26) に誤ったメンバーを削除していた問題を修正。この問題により影響ノードが NotReady となり、クラスタアップグレードが停止していました。

📦 4. containerd の状態破損への耐性向上

コンテナイメージの展開 (unpack) 中にノードが再起動した場合の、containerd の状態破損に対する耐性を改善。

🩺 5. 構成ドリフトヘルスチェックの誤検知

クラスタのアップグレードまたはロールバック進行中に、定期的な構成ドリフトヘルスチェックが「version not supported」エラーで失敗していた問題を修正。

📝 6. audit-proxy の無限リトライ

恒久的なエラーに対して監査ログエクスポートを無限に再試行し、過剰な監査ログトラフィックを発生させていた問題を修正。

🔍 7. プリフライトヘルスチェックのスキャン範囲

Kubernetes プリフライトヘルスチェックが対象クラスタの Namespace ではなく管理クラスタの全 Namespace をスキャンし、無関係なクラスタの古い reconciling リソースによってアップグレードが失敗していた問題を修正。

🎯 ユースケース

🔁 ユースケース 1: コントロールプレーンノードの安全な入れ替え

シナリオ: 3 ノード HA 構成のコントロールプレーンで、ハードウェア保守のためノードをリセット・再追加する。ノード IP が 10.201.0.2、10.201.0.20、10.201.0.26 のようにプレフィックスを共有している。

効果: 従来は誤った etcd メンバーが削除されてノードが NotReady になりアップグレードが停止するリスクがあったが、本バージョンでは正しいメンバーのみが削除され、安全にノードの入れ替えができる。

📉 ユースケース 2: ワーカーノードのスケールダウンとストレージ管理

シナリオ: ローカル PV (LVP share / LVP node mounts) を使用するクラスタで、需要減に応じてワーカーノードを削除する。

効果: 本バージョン以降に作成されたローカル PV はノード削除時に自動でガベージコレクションされ、孤立 PV の棚卸しや手動削除の運用負荷が軽減される。
