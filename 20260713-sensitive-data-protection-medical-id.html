🔒 Sensitive Data Protection: MEDICAL_ID infoType の動作変更

Sensitive Data Protection Breaking Change 90日間移行期間
2026-07-13

📋 概要

Sensitive Data Protection (旧 Cloud DLP) の MEDICAL_ID infoType に MEDICAL_RECORD_NUMBER が統合されました。 InfoType.version を未設定または stable に設定している場合、 スキャン結果に MEDICAL_RECORD_NUMBER の検出結果が MEDICAL_ID タイプとして含まれるようになります。

⚠️ 破壊的変更: 2026年5月11日に latest として導入された機能が stable に昇格。従来の動作を維持するには version: "legacy" の設定が必要ですが、90日間 (2026年10月11日頃まで) のみ利用可能です。

❌ Before (変更前)

  • MEDICAL_ID と MEDICAL_RECORD_NUMBER は別々に検出
  • 包括的スキャンには両方の個別指定が必要
  • 設定漏れによる検出抜けリスク
  • General infoType に医療記録番号が未含有

✔️ After (変更後)

  • MEDICAL_ID 指定のみで MEDICAL_RECORD_NUMBER も自動検出
  • General infoType の包括性が向上
  • 設定の簡素化 (infoType 数削減)
  • 医療関連データ保護がより確実に

⚡ 主要機能

1. MEDICAL_RECORD_NUMBER の MEDICAL_ID への統合

→ MEDICAL_RECORD_NUMBER の検出結果が MEDICAL_ID タイプとしてスキャン結果に含まれる
→ MEDICAL_ID は医療記録番号を含むより包括的な医療識別子検出器として機能
→ MEDICAL_RECORD_NUMBER は感度レベル SENSITIVITY_HIGH に分類

2. InfoType.version によるバージョン管理

→ stable (またはデフォルト/未設定): 新しい動作 (MEDICAL_RECORD_NUMBER を含む)
→ legacy: 従来の動作 (MEDICAL_RECORD_NUMBER を含まない) - 90日間のみ
→ latest: 新しい動作 (2026年5月11日から利用可能)

3. 90日間の移行期間

→ 2026年7月13日 ~ 2026年10月11日頃まで legacy バージョンで従来動作を維持可能
→ 移行期間終了後は legacy オプションが削除され、新しい動作のみに
