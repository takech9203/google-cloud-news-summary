☸️ GKE 2026-R48 バージョンアップデート
リリースチャネル更新とセキュリティ修正

リリース日: 2026-11-13
Google Kubernetes Engine GA (Generally Available) 2026-R48 Security Update

📌 概要

GKE の 2026-R48 バージョンアップデートが実施され、 Rapid / Regular / Extended / No channel の各チャネルに新しいパッチバージョンが追加された。 新規クラスタの作成と、既存クラスタのコントロールプレーン・ノードの手動アップグレードに利用できる (Stable チャネルは今回新規リリースなし)。

新バージョンには更新済みの Container-Optimized OS (COS) イメージが含まれ、 前回リリース以降の累積的なセキュリティ修正が適用される。 新パッチは自動アップグレードターゲット化の少なくとも 1 週間前に利用可能になるため、 手動アップグレードや accelerated patch auto-upgrades で先行適用できる。

❌ アップデート前の課題

  • 前回リリース (2026-R47) 以降に COS で修正された脆弱性が既存 GKE バージョンに未反映
  • 各チャネルの既存パッチバージョンに最新のバグフィックス・セキュリティ修正が未収録
  • 旧 Alpha バージョン (1.38.0-gke.3229000+preview) は 1.38 系の最新修正を含まず

✅ アップデート後の改善

  • 各チャネルに最新セキュリティ修正を含む新パッチが追加され、新規作成・手動アップグレードで利用可能
  • 更新済み COS イメージ (cos-121-18867-652-29 / cos-133-19999-44-193 / cos-dev-138-20162-0-0) により累積的なセキュリティ修正を適用
  • Alpha が 1.38.0-gke.5166000+preview に更新され、次期 1.38 の最新ビルドを検証可能

Kubernetes アップストリームから GKE 各リリースチャネルへのバージョン伝搬フローと、 2026-R48 の新規バージョンに更新済み COS イメージのセキュリティ修正が同梱されてクラスタへ提供される流れ。

⚙️ 主要なアップデート内容

⚡ 1. Rapid チャネルの新規バージョン

  • 新規利用可能: 1.34.12-gke.1776000、1.36.5-gke.2370000、1.37.2-gke.1325000
  • Alpha バージョン 1.38.0-gke.5166000+preview が GKE Alpha クラスタ向けに提供開始
  • 旧 Alpha バージョン 1.38.0-gke.3229000+preview は利用不可に

⚖️ 2. Regular チャネルの新規バージョン (本番推奨)

  • 新規利用可能: 1.34.12-gke.1539000、1.35.9-gke.1505000、1.36.5-gke.1982000
  • 一般的な本番ワークロード向け推奨チャネルで最新セキュリティ修正を含むパッチが選択可能に

🛡️ 3. Stable チャネル

  • 今回の 2026-R48 では新しいリリースなし

🕐 4. Extended チャネルの新規バージョン

  • 新規利用可能: 1.32.13-gke.3070000、1.33.13-gke.2398000
  • 長期サポートが必要な環境向けに 1.32 系・1.33 系の最新セキュリティパッチを継続提供

🚫 5. No channel (非推奨) の新規バージョン

  • 新規利用可能: 1.34.12-gke.1776000、1.36.5-gke.2370000、1.37.2-gke.1325000
  • 新規ノードバージョン: 1.32.13-gke.3070000、1.33.13-gke.2398000、1.34.12-gke.1776000、1.36.5-gke.2370000、1.37.2-gke.1325000
  • No channel 構成自体は非推奨で 2027-06-14 に削除予定。リリースチャネルへの移行を推奨

🔒 6. セキュリティ更新 (Container-Optimized OS)

  • 更新された COS イメージを使用する新しい GKE バージョンを含む
  • イメージは累積的で、前回の GKE リリース以降のすべての COS セキュリティ修正を取り込む
  • 解決された個別の脆弱性は各 COS イメージの Security release notes で確認可能

🛠️ 設定方法

前提条件

✓Google Cloud プロジェクトで GKE API が有効化されていること
✓gcloud CLI がインストールされ、認証が完了していること
✓Kubernetes Engine Cluster Admin 以上の IAM 権限を持つこと

ステップ 1: 現在のクラスタバージョンとチャネルを確認

Bashクラスタ一覧とチャネルの確認
gcloud container clusters list \
    --project PROJECT_ID \
    --format="table(name,location,currentMasterVersion,releaseChannel.channel)"

ステップ 2: 利用可能なバージョンを確認

Bashチャネルごとの利用可能バージョン一覧
gcloud container get-server-config \
    --location LOCATION \
    --format="yaml(channels)"
⚠️ 注意: ロールアウトは複数日かけて全ゾーンに展開されるため、リリースノート公開時点では一部のゾーンで新バージョンが未提供の場合がある。

ステップ 3: 手動でバージョンをアップグレードする場合

Bashコントロールプレーン → ノードプールの順にアップグレード
# コントロールプレーンのアップグレード
gcloud container clusters upgrade CLUSTER_NAME \
    --location LOCATION \
    --master \
    --cluster-version VERSION

# ノードプールのアップグレード
gcloud container clusters upgrade CLUSTER_NAME \
    --location LOCATION \
    --node-pool NODE_POOL_NAME \
    --cluster-version VERSION

ステップ 4: セキュリティパッチを早期適用 (accelerated patch auto-upgrades)

Bashパッチ自動アップグレードの加速設定
gcloud container clusters update CLUSTER_NAME \
    --location LOCATION \
    --patch-update accelerated

パッチバージョンが自動アップグレードターゲットに設定される前に、利用可能になった時点で自動アップグレードを受け取れる。 セキュリティパッチを可能な限り早く適用したい場合に有効。

💡 メリット

💼 ビジネス面

  • セキュリティリスクの低減: 累積的な COS セキュリティ修正を含む新バージョンにより、既知の脆弱性リスクを迅速に低減
  • 運用負荷の軽減: リリースチャネル登録クラスタはメンテナンスポリシーに従って自動アップグレードされ、手動のバージョン管理を最小化
  • 計画的なパッチ適用: 自動アップグレード化の 1 週間以上前に利用可能になるため、検証環境での先行確認と計画的な適用が可能

🔧 技術面

  • Kubernetes 1.38 最新ビルドで検証可能: Alpha が 1.38.0-gke.5166000+preview に更新され、次期マイナーバージョンを GKE Alpha クラスタで検証
  • 幅広いマイナーバージョンへのパッチ提供: 1.32 系から 1.37 系まで最新パッチを追加。Extended チャネルの長期サポート環境でも修正を受領
  • パッチの早期利用: 手動アップグレードや accelerated patch auto-upgrades で、自動アップグレードを待たずに先行適用

⚠️ デメリット・制約事項

制限事項

  • Rapid チャネルのバージョンは GKE SLA 対象外であり、本番環境での使用は推奨されない
  • Alpha バージョン 1.38.0-gke.5166000+preview は GKE Alpha クラスタ専用。旧 Alpha バージョン 1.38.0-gke.3229000+preview は利用不可に
  • ロールアウトは公開時点で進行中であり、全ゾーンへの展開完了まで複数日かかる場合がある
  • Stable チャネルには今回新しいリリースがなく、新バージョンの選択肢は変わらない

考慮すべき点

🚫 No channel は非推奨: リリースチャネル未登録構成は 2027 年 6 月 14 日に削除予定。該当クラスタはリリースチャネルへの移行計画を策定すること。
⏰ 自動アップグレードに備える: 今回のパッチは今後自動アップグレードターゲットに設定される見込み。メンテナンスウィンドウ/除外の設定を確認し、ビジネスクリティカルな時間帯での自動アップグレードを回避すること。
🔍 脆弱性詳細の確認先: セキュリティ修正の内容は GKE リリースノートには個別記載されず、各 COS イメージの Security release notes で確認が必要。

🎯 ユースケース

🔒 ユースケース 1: セキュリティパッチの迅速な適用

シナリオ: セキュリティ要件が厳しい環境で、COS のセキュリティ修正を含む新バージョン (例: Regular の 1.36.5-gke.1982000) を自動アップグレードターゲットになる前に適用したい。

Bash即時適用または加速自動アップグレード
# 方法 1: 手動アップグレードで即時適用
gcloud container clusters upgrade prod-cluster \
    --location us-central1 \
    --master \
    --cluster-version 1.36.5-gke.1982000

# 方法 2: accelerated patch auto-upgrades を有効化
gcloud container clusters update prod-cluster \
    --location us-central1 \
    --patch-update accelerated

効果: パッチが利用可能になった時点でアップグレードでき、COS の累積セキュリティ修正を通常の自動アップグレードスケジュールより早く適用できる。

🧪 ユースケース 2: Kubernetes 1.38 最新 Alpha ビルドの先行検証

シナリオ: プラットフォームチームが次期 Kubernetes 1.38 の新機能や API 変更を事前検証したい。Rapid チャネルの GKE Alpha クラスタで最新 Alpha バージョンを使用。

Bash1.38.0 preview の Alpha クラスタ作成
gcloud container clusters create alpha-test-cluster \
    --location us-central1 \
    --enable-kubernetes-alpha \
    --release-channel rapid \
    --cluster-version 1.38.0-gke.5166000+preview

効果: 1.38 系が一般提供される前にアルファ機能ゲートを含む最新ビルドの挙動を検証でき、マイナーバージョンアップグレードへの準備期間を確保できる。

📜 ユースケース 3: Extended チャネルで長期バージョン保持とパッチ適用を両立

シナリオ: 規制要件によりマイナーバージョンアップグレードに社内監査プロセスが必要な環境で、1.32 系・1.33 系を長期維持しつつ、最新セキュリティパッチ (1.32.13-gke.3070000 / 1.33.13-gke.2398000) は適用したい。

効果: Extended チャネルの長期サポートで監査プロセスの時間を確保しながら、cos-121-18867-652-29 の累積セキュリティ修正を含むパッチレベルの更新を適用してクラスタの安全性を維持できる。

🌍 利用可能リージョン

GKE のリリースチャネルバージョンアップデートは、GKE が利用可能なすべてのリージョンおよびゾーンに適用される。 ただし、ロールアウトはリリースノート公開時点で進行中であり、全ゾーンへの展開完了まで複数日かかる場合がある。

🔗 関連サービス・機能

🚀 GKE リリースチャネル

クラスタのバージョン管理ポリシーを定義する機能。Rapid、Regular、Extended、Stable の 4 つのチャネルから選択可能。

🖥️ Container-Optimized OS

GKE ノードのデフォルト OS イメージ。Google が管理するセキュリティ強化済みの OS で、今回のセキュリティ更新の対象。

🗓️ GKE メンテナンスウィンドウと除外

自動アップグレードの実行時間帯を制御する機能。ビジネスクリティカルな時間帯を避けてアップグレードをスケジュール可能。

🔔 GKE クラスタ通知

バージョンの更新やアップグレードイベントに関する通知を Pub/Sub 経由で受信できる機能。

🧪 GKE Alpha クラスタ

Kubernetes のアルファ機能ゲートと Alpha API を有効化した検証用クラスタ。Rapid チャネルの Alpha パッチバージョンを利用可能。

📝 まとめ

  • 2026-R48 により Rapid / Regular / Extended / No channel に累積的な COS セキュリティ修正を含む新パッチバージョンが追加された (Stable は今回新規リリースなし)
  • Rapid の Alpha が 1.38.0-gke.5166000+preview に更新され、次期マイナーバージョンの最新ビルドで検証が可能に
  • 今後自動アップグレードターゲット化される見込みのため、セキュリティ要件が厳しい環境では手動アップグレードや accelerated patch auto-upgrades による先行適用を検討し、メンテナンスウィンドウの設定を確認すること
  • No channel 構成のクラスタは 2027 年 6 月の削除に向けてリリースチャネルへの移行を計画すべき
