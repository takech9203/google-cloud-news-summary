🔒 Assured OSS Premium: リモート (プロキシ) Artifact Registry リポジトリがリージョン / マルチリージョンに対応

Assured Open Source Software 一般提供 (Feature) Premium ティア 📅 リリース日: 2026-11-06

📌 概要

Assured OSS Premium ティアのリモート (プロキシ) Artifact Registry リポジトリが、 Google Cloud の複数リージョンおよびマルチリージョンをサポートしました。 Assured OSS は、Google が自社利用と同じプロセスでビルド・スキャン・署名した OSS パッケージ (Java / Python / Go / JavaScript・NPM) を提供するサービスで、SLSA レベル 3 準拠のビルド、署名付きプロベナンス、SBOM を備えています。

これまで Premium ティアのプロキシリポジトリは us (米国) のみの対応でしたが、今回のアップデートで アジア、オーストラリア、ヨーロッパ、北米の各リージョンと europe / us マルチリージョンを選択できるようになり、 データレジデンシー要件やレイテンシの観点で米国以外のロケーションからパッケージを配信したい組織に対応します。

❌ Before: アップデート前の課題

  • Premium ティアのプロキシリポジトリは us (米国) のみサポート。ヨーロッパやアジアなどのロケーションを選択できなかった
  • データレジデンシー要件を持つ組織 (特に EU 圏) が、パッケージ取得経路を自地域内に収めることが難しかった
  • 米国から離れたリージョンの CI/CD パイプラインでも、パッケージ取得は米国エンドポイント経由だった

✅ After: アップデート後の改善

  • リモート (プロキシ) リポジトリを 11 リージョン + 2 マルチリージョン (europe / us) に配置可能に
  • europe マルチリージョンや各国リージョンの選択で、データレジデンシー要件に沿った配信構成が可能に
  • JFrog Artifactory / Sonatype Nexus から https://LOCATION-maven.pkg.dev/... のようにロケーション指定で接続可能に

Premium ティアのリモート (プロキシ) リポジトリを任意のサポート対象リージョン / マルチリージョンに配置し、 開発者やリポジトリマネージャーがそこを経由して Google 管理の Assured OSS パッケージを取得する構成です。

⚙️ 主要機能

🌍 1. リモート (プロキシ) リポジトリのマルチロケーション対応

Premium ティアのリモート (プロキシ) Artifact Registry リポジトリが、複数の Google Cloud リージョンおよびマルチリージョンをサポート。 対応ロケーションはアジア (asia-southeast2)、オーストラリア (australia-southeast1 / australia-southeast2)、 ヨーロッパ (europe-north1 / europe-north2 / europe-west1〜west4)、 北米 (northamerica-northeast1 / northamerica-northeast2)、マルチリージョン europe / us。

🔗 2. ロケーションを指定したエンドポイント

リモートリポジトリへの接続 URL は https://LOCATION-maven.pkg.dev/PROJECT_ID/assuredoss-java のようにロケーションを含む形式 (Python / NPM / Go も同様のパターン)。JFrog Artifactory や Sonatype Nexus のリモートリポジトリ設定でこの URL を指定して利用します。

⚠️ 3. セキュリティメタデータは us マルチリージョンに限定

パッケージ本体の配信はマルチロケーション対応ですが、セキュリティメタデータ (SBOM、VEX など) のサポートは us マルチリージョンに限定される点に注意が必要です。

🛠️ 設定方法

📋 前提条件

✓ Assured OSS Premium ティアの利用 (Security Command Center Premium または Enterprise の組織レベル有効化が必要)
✓ Assured OSS と Security Command Center の統合、および利用するサービスアカウントの接続検証が完了していること

🚀 手順 (JFrog Artifactory の例)

ステップ 1: リモートリポジトリの作成
リポジトリマネージャーで Maven / PyPI / npm / Go タイプのリモートリポジトリを作成し、Remote Storage URL にサポート対象ロケーションを含むエンドポイントを指定します。

https://LOCATION-maven.pkg.dev/PROJECT_ID/assuredoss-java

ステップ 2: 認証情報の設定

Text 認証情報

Password: (サービスアカウント JSON キーを 1 行の Base64 文字列にしたもの)
💡 補足: Go の場合は Advanced Settings で「Bypass HEAD Requests」を有効にします。 Python の場合は pip の index-url 用に URL 末尾へ /simple を付与します。

💡 メリット

💼 ビジネス面

✓ データレジデンシー対応: europe マルチリージョンや各国リージョンの選択で、パッケージ配信経路に関する地域要件 (EU のデータ所在地要件など) に対応しやすくなる
✓ コンプライアンス姿勢の強化: サプライチェーン保護 (SLSA レベル 3、SBOM、署名付きプロベナンス) と地域要件への対応を両立できる

⚙️ 技術面

✓ 既存ワークフローとの統合: JFrog Artifactory / Sonatype Nexus などの既存リポジトリマネージャーからロケーション指定のエンドポイントに接続するだけで利用可能
✓ 地理的に近いロケーションの選択: CI/CD パイプラインやビルド環境に近いリージョンを選択できる

⚠️ デメリット・制約事項

🚧 制限事項

✗ 本機能は Premium ティア (Security Command Center Premium / Enterprise 契約が前提) が対象
✗ セキュリティメタデータのサポートは us マルチリージョンに限定される
✗ サポートされるのは 11 リージョン + 2 マルチリージョンであり、すべての Google Cloud リージョンに対応しているわけではない (例: 日本リージョンは現時点で対象外)

🤔 考慮すべき点

⚠️ 注意: セキュリティメタデータ (SBOM / VEX など) を利用するワークフローがある場合は、 メタデータ取得が us に依存する点を設計時に考慮する必要があります。
📅 Enterprise ティアの終了予定: Security Command Center Enterprise ティアは 2027 年 5 月 21 日に終了が予定されており、Enterprise 利用組織は Premium ティアに自動移行されるとドキュメントに記載されています。
