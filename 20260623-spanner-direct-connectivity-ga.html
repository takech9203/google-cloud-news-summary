Cloud Spanner: Direct Connectivity GA

Cloud Spanner GA
2026-06-23

📋 概要

Cloud Spanner の Direct Connectivity (直接接続) 機能が一般提供 (GA) になりました。この機能を有効にすると、アプリケーションのトラフィックが Google Front End (GFE) サーバーをバイパスし、Spanner サーバーに直接ルーティングされます。これにより、全体的なレイテンシを削減できます。

レイテンシに敏感なワークロードを Compute Engine または GKE 上で実行しているユーザーに特に有益です。

❌ Before (従来)

  • 全てのリクエストが GFE を経由し追加レイテンシが発生
  • GFE レイヤーでのレイテンシをバイパスする手段がない
  • TLS 終端処理によるオーバーヘッド

✅ After (Direct Connectivity)

  • GFE をバイパスしレイテンシ削減
  • 環境変数 1 つで簡単に有効化
  • クライアントメトリクスでモニタリング可能
  • GA で本番 SLA 対象

🏗️ アーキテクチャ図

Direct Connectivity を有効にすると、アプリケーションのトラフィックは GFE をバイパスし、Spanner API フロントエンド (AFE) に直接ルーティングされます。AFE は引き続き認証・認可・クォータチェックを実行するため、セキュリティは維持されます。

⭐ 主要機能

⚡ GFE バイパスによるレイテンシ削減

アプリケーショントラフィックが GFE を経由せず、直接 Spanner サーバーにルーティング。GFE レイヤーで発生していた TLS 終端処理などのレイテンシを排除し、エンドツーエンドのレイテンシが改善されます。

🔧 簡単な有効化方法

環境変数 GOOGLE_SPANNER_ENABLE_DIRECT_ACCESS=true の設定、またはクライアントライブラリの API 設定で有効化可能。アプリケーションコードの大幅な変更は不要です。

📊 クライアントサイドメトリクス

directpath_enabled ラベルで有効状態、directpath_used ラベルで実際の使用状況をモニタリング。レイテンシ削減効果を operation_latencies および gfe_latencies メトリクスで確認可能。

⚙️ 技術仕様・前提条件

項目 要件
実行環境 Compute Engine または Google Kubernetes Engine (GKE)
エンドポイント グローバルエンドポイント (spanner.googleapis.com)
ネットワーク構成 Egress: 34.126.0.0/18 および 2001:4860:8040::/42
Java クライアント バージョン 6.111.0 以降
Go クライアント バージョン 1.88.0 以降
IAM 権限 spanner.databases.get

📝 有効化方法

方法 1: 環境変数

Bash 
export GOOGLE_SPANNER_ENABLE_DIRECT_ACCESS=true

方法 2: Java クライアントライブラリ

Java 
SpannerOptions options = SpannerOptions.newBuilder()
    .setEnableDirectAccess(true)
    .build();

方法 3: Go クライアントライブラリ

Go 
client, err := spanner.NewClientWithConfig(ctx, db,
    spanner.ClientConfig{
        EnableDirectAccess: true,
    })

方法 4: JDBC ドライバー

JDBC 
jdbc:cloudspanner:/projects/PROJECT/instances/INSTANCE/databases/DB?enableDirectAccess=true

ビジネス面

✔ GA によるエンタープライズ利用の安心感 (SLA 対象)

技術面

✔ ネットワークホップの削減によるリクエストパスの短縮
✔ 環境変数一つまたはクライアント設定の変更だけで有効化
✔ 透過的なフォールバック (条件を満たさない場合は自動的に従来パスに)
✔ クライアントサイドメトリクスで使用状況を可視化

⚠️ 制限事項・考慮点

制限事項
  • ✗ Compute Engine / GKE 上のアプリのみ対象 (Cloud Run, App Engine は非対象)
  • ✗ グローバルエンドポイント使用時のみ有効 (リージョナルは不可)
  • ✗ 対応クライアントは Java (6.111.0+) と Go (1.88.0+) のみ
  • ✗ 特定 IP レンジへの Egress 許可が必要
  • ✗ spanner.databases.get IAM 権限が追加で必要
💡 考慮すべき点
  • GFE の DDoS 保護レイヤーをバイパスするが、AFE が引き続き認証・認可を実施
  • VPC Service Controls やファイアウォールポリシーとの互換性を事前に確認
  • 有効化後は directpath_used ラベルで実際の使用をモニタリング

🎯 ユースケース

💰 レイテンシクリティカルなトランザクション処理

金融系のリアルタイムトランザクション処理システムが GKE 上で稼働。数ミリ秒のレイテンシ削減がビジネスインパクトを持つ環境。GFE ホップの排除により、P99 レイテンシの改善が期待できます。

Bash 
# GKE Pod の環境変数として設定
kubectl set env deployment/transaction-service \
  GOOGLE_SPANNER_ENABLE_DIRECT_ACCESS=true

🎮 ゲームバックエンドのセッション管理

Compute Engine 上で動作するゲームサーバーが Spanner をセッションストアとして使用。プレイヤーのアクション応答速度がゲーム体験に直結するため、Direct Connectivity によりセッション読み書きのレイテンシが短縮され、応答性が向上します。
