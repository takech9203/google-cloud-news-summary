📞 telephony_disable_voice_processing で
音声認識をオフにして DTMF 専用モードへ

リリース日: 2026-10-19

📝 概要

Dialogflow CX のテレフォニー統合で、セッションパラメータ telephony_disable_voice_processing を true に設定すると、 音声認識 (Speech-to-Text) を無効化し、以降のセッションでは DTMF (電話キーパッド) 入力のみを受け付けられるようになりました。 設定後の次の会話ターンから音声入力は無視され、設定はセッションの残りの期間、有効であり続けます。 false に戻せば音声認識を再度有効化できます。

騒がしい環境からの着信に対応する IVR (音声自動応答) システムで特に有効で、 背景雑音による no-match イベントの誤発火や DTMF 入力の打ち切りを回避し、 ノイズ環境下での会話完遂率を向上させます。

❌ Before: アップデート前の課題

✗背景雑音が発話として誤って文字起こしされ、no-match イベントが誤発火
✗キーパッドで DTMF 数字を入力中に、雑音の誤認識で入力が途中で打ち切られる
✗セッション途中で音声認識を無効化して DTMF 専用に切り替える手段がなかった

✅ After: アップデート後の改善

✓パラメータを true にするだけで次ターンから音声入力を無視し DTMF のみ処理
✓設定はセッション中維持され、false に戻せば音声認識を再有効化できる柔軟な制御
✓no-match / no-input ハンドラ + パラメータプリセットで DTMF 専用モードへ自動フォールバック
💡 Google の推奨: 会話の開始時点ではなく、フォールバックとして使用すること。 例えば no-match / no-input イベントが 2 回連続でトリガーされた場合に true に設定し、 キーパッドの使用を促すプロンプトを再生する使い方が想定されています。

騒音環境で no-match イベントが連続発生した際に、フルフィルメントのパラメータプリセットで telephony_disable_voice_processing を true に設定し、 以降のターンを DTMF 専用モードに切り替えるフォールバックフローです。

⚡ 主要機能

🔇 1. セッション単位での音声認識の無効化

→telephony_disable_voice_processing を true に設定すると、次の会話ターンから音声入力を無視し、DTMF 入力のみを処理
→設定はセッションの残りの期間、有効であり続ける (セッション単位のステートフルな制御)

🔄 2. 音声認識の再有効化

→パラメータを false に設定すれば音声認識を再度有効化できる
→会話の状況に応じて音声モードと DTMF 専用モードを動的に切り替え可能

🛟 3. フォールバックとしての利用 (推奨パターン)

→会話の開始時点ではなく、フォールバックとしての使用が推奨
→例: no-match / no-input が 2 回連続した後、パラメータプリセットで true に設定しキーパッド使用を案内
→エンドユーザーが提供するパラメータで DTMF が有効になっていることを確認する必要あり

🔢 DTMF 入力の処理仕様 (既存機能)

✓DTMF 入力は通常形式 (例: 123#) と DTMF 固有形式 (例: dtmf_digits_123pound) の両方でエンティティマッチング
✓DTMF 入力が終了条件 (最大桁数または終了桁) を満たすまでエージェントは入力を待機
✓音声と DTMF の両方が検出された場合、音声入力は破棄され DTMF 入力のみが考慮される

🛠️ 設定方法

✅ 前提条件

✓テレフォニー統合 (Dialogflow CX Phone Gateway など) を使用するエージェントであること
✓エンドユーザーが入力するパラメータに対して DTMF が有効化されていること (エージェント / フロー / ページ / パラメータレベルで設定可能)

📌 手順

  1. DTMF を有効化する
    Dialogflow CX コンソールで Agent settings の「Speech and IVR」タブを開き、「Enable DTMF」をオンにして Finish digit や Max digits などを設定。フォームパラメータで使用する場合は、パラメータ設定で DTMF を有効化。
  2. フォールバック用のイベントハンドラを構成する
    no-match / no-input の組み込みイベントハンドラを構成し、連続発生 (例: 2 回) した場合のルートを用意。
  3. パラメータプリセットで DTMF 専用モードへ切り替える
    ルートのフルフィルメントで telephony_disable_voice_processing を true に設定し、「キーパッドで入力してください」といった案内メッセージを再生。
  4. (必要に応じて) 音声認識を再有効化する
    DTMF での入力収集が完了し、音声での会話に戻したい場合は、フルフィルメントでパラメータを false に設定。

🎯 メリット

💼 ビジネス面

✓コールの完遂率向上: 騒音環境 (屋外、車内、工場など) からの着信でも、DTMF 専用モードへの切り替えで入力エラーによる離脱やオペレーター転送を削減
✓顧客体験の改善: 音声認識の誤動作による聞き返しの繰り返しを回避し、確実な入力手段をエンドユーザーに提供

⚙️ 技術面

✓追加コンポーネント不要: セッションパラメータの設定のみで実現。Webhook やインフラの追加実装なしでエージェント設計 (パラメータプリセット) だけで完結
✓動的かつ可逆的な制御: セッション途中で切り替えられ、false で音声モードへ復帰できる柔軟な会話設計
✓既存の DTMF 機能との統合: 既存の DTMF 設定 (最大桁数、終了桁、正規表現パターン) をそのまま活用可能

⚠️ デメリット・制約事項

🚧 制限事項

✗テレフォニー統合でのセッションを対象とした機能である
✗設定が反映されるのは次の会話ターンからであり、設定したターンの音声入力には適用されない
✗DTMF 専用モードの間は音声入力が完全に無視されるため、キーパッド入力で表現できない自由発話 (問い合わせ内容の説明など) は収集できない

🤔 考慮すべき点

⚠️会話の開始時点での使用は非推奨。no-match / no-input の連続発生後のフォールバックとしての使用が推奨されている
⚠️収集対象のパラメータで DTMF が有効になっていないと、DTMF 専用モードに切り替えても入力を収集できない
⚠️DTMF 専用モードに切り替える際は、キーパッドの使用を明確に案内するプロンプトを用意する必要がある

💼 ユースケース

🚗 ユースケース 1: 騒音環境からの着信に対するフォールバック

シナリオ: 屋外や車内など騒がしい環境から電話をかけたエンドユーザーの発話が背景雑音により正しく認識されず、no-match イベントが連続して発生している。

実装例:

Plaintext フォールバック実装の流れ 
1. no-match イベントハンドラで連続発生回数をカウント (例: session パラメータで管理)
2. 2 回連続で no-match が発生したルートのフルフィルメントで
   パラメータプリセット: telephony_disable_voice_processing = true
3. 応答メッセージ: 「お電話が聞き取りづらいようです。
   以降はキーパッドで入力してください。会員番号を入力し、最後に # を押してください」
4. 会員番号パラメータは DTMF 有効 (Max digits: 10, Finish digit: #) に設定

効果: 雑音起因の認識エラーによるループや離脱を回避し、確実に必要情報を収集してセルフサービスを完遂できる。

🔐 ユースケース 2: 機密性の高い数値情報の確実な収集

シナリオ: IVR で暗証番号やカード番号などの数値情報を収集する際、周囲の雑音で入力が途切れる、または復唱による聞き返しが発生するのを避けたい。

効果: 該当セクションで DTMF 専用モードに切り替えることで、背景雑音により DTMF 入力が途中で打ち切られる事象を防ぎ、数値入力の確実性を高められる。収集完了後は false に戻して音声対話に復帰できる。

🔗 関連サービス・機能

→Dialogflow CX Phone Gateway: Google がホストする電話番号をエージェントに接続するテレフォニー統合。本パラメータが対象とする代表的な電話経由のセッションを提供

→組み込みイベントハンドラ (no-match / no-input): 認識失敗や無入力を検知するイベント。DTMF 専用モードへのフォールバックのトリガーとして使用
→Speech-to-Text (phone_call モデル): テレフォニー統合で使用される音声認識。本パラメータで無効化の対象となる処理

✨ まとめ

騒音環境での音声認識の誤動作は、IVR / ボイスボット運用における長年の課題でしたが、 本アップデートによりセッションパラメータ 1 つで DTMF 専用モードへフォールバックできるようになりました。

テレフォニー統合で Dialogflow CX を運用しているチームは、no-match / no-input イベントハンドラと パラメータプリセットを組み合わせたフォールバックルートの追加を検討することを推奨します。 その際、収集対象パラメータの DTMF 設定 (最大桁数・終了桁) が適切に構成されていることを併せて確認してください。
