🔐 IAM Recommender x PAM: グループの過剰権限修正

Security IAM Preview
2026-05-08

📋 概要

IAM Recommender が Google グループの過剰な権限を検出した際に、永続的なロールバインディングを削除し、 Privileged Access Manager (PAM) のオンデマンドエンタイトルメントに移行して修正できるようになりました。 永続アクセスを Just-in-Time (JIT) アクセスモデルに安全に移行することで、最小権限の原則を実現します。

Before

  • 過剰権限の修正手段はロールの削除または縮小のみ
  • 永続的なロール削除は緊急時のタスク実行を阻害するリスク
  • 最小権限と緊急時アクセス確保の両立が困難

After

  • IAM Recommender から直接 PAM エンタイトルメントを作成可能
  • 永続ロールを一時的なオンデマンドアクセスに移行
  • Security Insights / IAM ページから数クリックで修正適用

🏗️ アーキテクチャ図

IAM Recommender による検出から PAM エンタイトルメントの作成、一時的アクセスの付与までの全体フローです。

flowchart TD
    A[IAM Recommender] -->|過剰権限を検出| B[Security Insights / IAM ページ]
    B -->|推奨事項を表示| C{管理者の判断}
    C -->|ロール削除してオンデマンドアクセスを付与| D[PAM エンタイトルメント作成]
    D -->|自動処理| E[永続ロールバインディング削除]
    D -->|エンタイトルメント有効化| F[PAM エンタイトルメント]
    F -->|グループメンバーがアクセス要求| G[Grant リクエスト]
    G -->|承認フロー| H{承認者による審査}
    H -->|承認| I[一時的なロール付与]
    H -->|拒否| J[アクセス拒否]
    I -->|期間終了| K[ロール自動削除]

⚡ 主要機能

🔗
IAM Recommender と PAM の統合ワークフロー
過剰権限検出時に「ロールを削除してオンデマンドアクセスを付与する」オプションを表示。ロールとリソースが自動入力された PAM エンタイトルメント作成フォームを提供。
🛡️
Security Insights ページからの修正
「Top groups with excess permissions」ウィジェットから過剰権限を特定し、推奨事項から直接 PAM エンタイトルメントを作成。
👥
IAM ページからの修正
IAM ページのプリンシパル一覧から Security insights 列を確認し、推奨事項から直接エンタイトルメントを作成。1-2 分でアクセス変更反映。
↩️
推奨事項の取り消し (Revert)
適用した推奨事項の取り消しが可能。元の IAM バインディングが復元され、作成された PAM エンタイトルメントが削除される。

前提条件: Privileged Access Manager が対象リソース (プロジェクト、フォルダ、または組織) でオンボーディングおよび有効化されていること。

Security Insights ページからの修正手順

1. IAM & Admin > Security Insights ページに移動
2. 「Top groups with excess permissions」ウィジェットで対象グループを確認
3. Insights 列のリンクをクリック
4. 「View recommendation」をクリック
5. 「Remove role and grant on-demand access to the role」を選択
6. エンタイトルメントの詳細を入力し「Apply」をクリック

⚖️ メリットと制約事項

✅ メリット

ビジネス面
  • 最小権限の原則を維持しつつ必要時のアクセスを確保
  • 永続ロール削除のリスクなく権限最適化
  • 完全な監査ログによる監査対応の強化
技術面
  • IAM Recommender から PAM まで一貫したコンソール操作
  • ロールとリソースの自動入力で設定ミスを低減
  • 問題発生時に推奨事項の適用を取り消し可能

⚠️ 制約事項・考慮点

制限事項
  • Preview 機能のため限定的なサポート
  • Google グループのプリンシパルのみが対象
  • PAM が事前にオンボーディングされている必要あり
  • アクセス変更の反映に 1-2 分を要する
考慮すべき点
  • オンデマンドアクセス要求への運用フロー変更が必要
  • 承認者設定を適切に行わないと業務遅延の可能性
  • PAM 管理のロールバインディングを手動変更しないこと

💡 ユースケース

🖥️ ユースケース 1: 開発チームの本番環境アクセス制御

シナリオ: 開発者グループに本番環境の Editor ロールが永続的に付与されているが、実際にアクセスが必要なのはデプロイ時やトラブルシューティング時のみ。IAM Recommender が過剰権限として検出。

→ Editor ロールを PAM エンタイトルメントに移行し、デプロイ時にのみ一時的なアクセスを要求させることで、常時の攻撃面を縮小しつつ必要な業務を妨げない。

📋 ユースケース 2: セキュリティ監査対応

シナリオ: セキュリティ監査で複数の Google グループに過剰な権限が付与されていることが指摘。しかし、永続的にロールを削除すると四半期ごとの重要な運用タスクが実行できなくなるリスクがある。

→ PAM への移行により、監査要件である最小権限を満たしつつ、四半期ごとのタスク実行時にオンデマンドでアクセスを取得。承認ログにより監査証跡も確保。

📝 まとめ

IAM Recommender と Privileged Access Manager の統合により、Google グループの過剰権限を安全に修正する新しいワークフローが Preview として利用可能になりました。 永続的なロール削除のリスクを回避しながら最小権限の原則を実現できます。

推奨アクション:
  • Privileged Access Manager のオンボーディングを完了する
  • Security Insights ページから過剰権限のあるグループを確認する
  • 重要度の高いグループから段階的に PAM への移行を実施する
