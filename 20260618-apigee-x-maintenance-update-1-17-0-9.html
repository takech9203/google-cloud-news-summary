📋 概要

メンテナンスウィンドウを設定している Apigee インスタンスに対して、バージョン 1-17-0-apigee-9 への自動アップデートが開始されました。 対象は現在のバージョンが 1-17-0-apigee-9 未満のインスタンスで、7 日から 21 日以内にアップデートが適用されます。

バージョン 1-17-0-apigee-9 は 2026 年 6 月 8 日にリリース済みで、SSRF 対策のセキュリティ修正や OpenTelemetry トレースエクスポートパイプラインの可観測性メトリクス追加などが含まれています。

🔄 Before / After

❌ アップデート前の課題

  • メンテナンスウィンドウ設定済みインスタンスは手動対応なしには最新化されない
  • SSRF 攻撃 (リンクローカルアドレスへのリクエスト) がブロックされない
  • OpenTelemetry トレースエクスポートの可観測性が限定的
  • フォワードプロキシ経由の認証が失敗する

✅ アップデート後の改善

  • 指定した曜日・時間帯に自動的にバージョンアップ
  • Script ポリシーにおける SSRF 攻撃がブロック
  • OTel メトリクス (スパン数、レイテンシ、バッチサイズ、ドロップ数) が利用可能
  • フォワードプロキシ経由の HTTP トレースエクスポート認証の問題が修正

⭐ 主要機能

🔄 自動アップデート

メンテナンスウィンドウが設定済みかつ現行バージョンが 1-17-0-apigee-9 未満のインスタンスが対象。7-21 日以内にアップデート実施。

🛡️ SSRF セキュリティ修正

Script ポリシーにおける Server-Side Request Forgery をブロック。リンクローカルアドレスへのリクエストを制限します。

Bug ID: 514384893

📊 OpenTelemetry 可観測性強化

トレースエクスポートパイプラインのメトリクスを追加。エクスポート済みスパン数、レイテンシ、バッチサイズ、ドロップされたスパン数を報告。

Bug ID: 512850756

🔧 フォワードプロキシ認証修正

HTTP 経由の OpenTelemetry トレースエクスポートが Basic 認証を要求するフォワードプロキシを通過する際の認証失敗を修正。

Bug ID: 515039499

⚠️ 除外条件

以下のいずれかに該当するインスタンスはアップデート対象外です。

📡 DNS 設定不備

Known Issue 445936920

バージョン 1-16-0-apigee-2 で自動 DNS フォールバック機能が削除されたことにより、DNS 設定の問題が DNS エラーとして表面化する。ランタイムログで DNS 解決エラーを確認することで検出可能。

📦 削除済み Java ライブラリの使用

2025 年 10 月 16 日のリリースノートで記載

deprecated ディレクトリに含まれていた JAR ライブラリが削除されており、Java Callout ポリシーでこれらを使用しているインスタンスは互換性の問題からアップデート対象外。

⚙️ 設定方法

💡 前提条件: Apigee Organization Admin ロール (roles/apigee.admin) または apigee.instances.update 権限が必要です。

ステップ 1: 現在のインスタンス状態を確認

Bash 
AUTH="Authorization: Bearer $(gcloud auth print-access-token)"
curl -H "$AUTH" \
  "https://apigee.googleapis.com/v1/organizations/YOUR_ORG/instances/YOUR_INSTANCE"

ステップ 2: メンテナンスウィンドウの設定例

Bash 
# メンテナンスウィンドウの設定例 (日曜 23:00 UTC, Week 2)
curl -X PATCH \
  -H "$AUTH" \
  -H "Content-Type: application/json" \
  -d '{
    "maintenanceUpdatePolicy": {
      "maintenanceWindows": [
        {
          "day": "SUNDAY",
          "startTime": {
            "hours": 23
          }
        }
      ],
      "maintenanceChannel": "WEEK2"
    }
  }' \
  "https://apigee.googleapis.com/v1/organizations/ORG_ID/instances/INSTANCE_ID?updateMask=maintenanceUpdatePolicy.maintenanceWindows,maintenanceUpdatePolicy.maintenanceChannel"

ステップ 3: メンテナンス通知のオプトイン

1. Google Cloud コンソールで「ユーザー設定 > コミュニケーション」ページに移動
2. 「Apigee, Maintenance window」の行で、Email のラジオボタンを「On」に設定

ステップ 4: 除外対象の回避確認

⚠️ 確認事項:
  • ランタイムログで DNS 解決エラーがないこと (Known Issue 445936920)
  • Java Callout ポリシーで削除済みの Apigee 内部ライブラリを使用していないこと

🔧 ユースケース 2: DNS 設定問題の事前解決

シナリオ: Known Issue 445936920 に該当し、アップデートが適用されないインスタンスがある。

効果: ランタイムログで DNS 解決エラーを確認し、DNS 設定を修正することでアップデート対象に復帰。セキュリティ修正を受けることが可能に。

⚠️ 制限事項

  • メンテナンス中は新規インスタンス作成、環境アタッチ、エンドポイントアタッチメント作成、一部スケーリング操作が実行不可
  • 1 インスタンスにつき 1 つのメンテナンスウィンドウのみ設定可能
  • 同一組織内の複数インスタンスには、少なくとも 12 時間の間隔を空けたウィンドウが必要
  • メンテナンスの所要時間は顧客の構成により異なる (通常は数時間)
  • セキュリティやコンプライアンスの理由から、Google がウィンドウ外でアップデートを実施する場合がある
