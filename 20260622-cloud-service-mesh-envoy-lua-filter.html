Cloud Service Mesh: Envoy Lua Filter

Cloud Service Mesh Preview Rapid Channel
2026-06-22

📋 概要

Cloud Service Mesh の EnvoyFilter API において、Envoy Lua Filter が Preview 機能として Rapid リリースチャネルで利用可能になりました。Envoy プロキシの HTTP フィルターチェーンに Lua スクリプトを挿入し、リクエスト/レスポンスの処理をカスタマイズできます。

Wasm フィルターと比較して、Lua スクリプトはコンパイル不要で迅速に実装できるため、プロトタイピングやシンプルなリクエスト変換に適しています。

💡 ポイント: EnvoyFilter API で利用可能な拡張が LocalRateLimit、GrpcWeb、Compressor に加え、Lua Filter が追加されました。

🔄 Before / After

❌ Before (従来)

  • カスタムロジック実行には Wasm フィルターの開発・コンパイル・デプロイが必要
  • シンプルなヘッダー操作でも本格的なフィルター開発のオーバーヘッド
  • EnvoyFilter API の拡張は LocalRateLimit、GrpcWeb、Compressor のみ

✅ After (今回のアップデート)

  • Lua スクリプトを inline_string で直接記述、コンパイル不要
  • リクエスト/レスポンスヘッダーの動的操作を簡潔に実現
  • Rapid チャネルの TRAFFIC_DIRECTOR で Preview 利用可能

🏗️ アーキテクチャ図

Envoy Lua Filter は EnvoyFilter カスタムリソースとして定義され、TRAFFIC_DIRECTOR コントロールプレーンを経由してサイドカープロキシに配信されます。Lua スクリプトは HTTP フィルターチェーン内で router フィルターの前に挿入されます。

⚡ 主要機能

📝 インライン Lua スクリプト実行

→default_source_code.inline_string フィールドで Lua コードを直接記述
→コンパイルやビルドパイプラインが不要
→リクエスト/レスポンスの両フェーズでスクリプトを実行可能

📦 EnvoyFilter API を通じた宣言的設定

→Kubernetes カスタムリソースとして Lua フィルターを定義
→workloadSelector による適用対象の制御
→INSERT_BEFORE オペレーションで router フィルターの前に挿入

🔒 セキュリティ制約付きサンドボックス実行

→外部呼び出し (httpCall) は使用不可
→ファイル I/O、デバッグライブラリ、FFI は無効化
→スクリプトサイズとパッチ数に上限を設定

🛠️ 設定方法

前提条件

✓Cloud Service Mesh が GKE クラスターにプロビジョニング済み
✓TRAFFIC_DIRECTOR コントロールプレーン実装を使用
✓GKE クラスターが Rapid リリースチャネルに設定済み
✓対象ネームスペースでサイドカーインジェクションが有効

Step 1: ネームスペースの設定確認

Bash 
# Rapid チャネルのリビジョンラベルを確認
kubectl get namespace TARGET_NAMESPACE -o jsonpath='{.metadata.labels.istio\.io/rev}'
# "asm-managed-rapid" であることを確認

Step 2: Lua フィルターの EnvoyFilter リソース作成

YAML 
apiVersion: networking.istio.io/v1alpha3
kind: EnvoyFilter
metadata:
  name: custom-lua-filter
  namespace: TARGET_NAMESPACE
spec:
  workloadSelector:
    labels:
      app: TARGET_APP
  configPatches:
  - applyTo: HTTP_FILTER
    match:
      context: SIDECAR_INBOUND
      listener:
        filterChain:
          filter:
            name: "envoy.filters.network.http_connection_manager"
            subFilter:
              name: "envoy.filters.http.router"
    patch:
      operation: INSERT_BEFORE
      value:
        name: envoy.filters.http.lua
        typed_config:
          "@type": type.googleapis.com/udpa.type.v1.TypedStruct
          type_url: type.googleapis.com/envoy.extensions.filters.http.lua.v3.Lua
          value:
            stat_prefix: custom_lua
            default_source_code:
              inline_string: |
                function envoy_on_request(request_handle)
                  request_handle:headers():add("x-custom-header", "processed-by-lua")
                end
                function envoy_on_response(response_handle)
                  response_handle:headers():add("x-response-processed", "true")
                end

Step 3: 適用と確認

Bash 
# EnvoyFilter を適用
kubectl apply -f lua-filter.yaml

# ステータス確認
kubectl get envoyfilter -n TARGET_NAMESPACE custom-lua-filter -o yaml

status.conditions で Accepted が True であることを確認します。

🎯 ユースケース

📌 ユースケース 1: リクエストヘッダーの動的追加

シナリオ: マイクロサービス間通信で、リクエスト属性に基づいてカスタムヘッダーを付加し、下流サービスでのルーティング判断やログ記録に活用

Lua 
function envoy_on_request(request_handle)
  local path = request_handle:headers():get(":path")
  if string.find(path, "/api/v2") then
    request_handle:headers():add("x-api-version", "v2")
  end
end

効果: アプリケーションコードを変更せずに、メッシュレベルでリクエストメタデータを付加可能

📌 ユースケース 2: レスポンスヘッダーのサニタイズ

シナリオ: バックエンドが返すデバッグ用ヘッダーやサーバーバージョン情報を、外部クライアントに露出しないよう削除

Lua 
function envoy_on_response(response_handle)
  response_handle:headers():remove("x-debug-info")
  response_handle:headers():remove("server")
end

効果: サービスメッシュのエッジでセンシティブなヘッダーを確実に除去しセキュリティ強化

📌 ユースケース 3: カスタムメトリクス用のタグ付け

シナリオ: 特定のリクエストパターンを識別するためのヘッダーを付加し、Envoy の統計情報やアクセスログでの分析を容易にする

効果: stat_prefix と組み合わせて Lua フィルター経由の処理に関するメトリクスを収集し、オブザーバビリティを向上

✅ メリット

ビジネス面

✓迅速なプロトタイピング: Wasm のビルドサイクルなしに即座にカスタムロジックをテスト可能

✓宣言的管理: EnvoyFilter CR として GitOps に統合可能
✓セキュリティサンドボックス: 外部呼び出し・ファイルアクセス制限で安全実行

⚠️ デメリット・制約事項

⚠️ 注意: Preview 段階のため、本番環境での使用は推奨されません (Pre-GA Offerings Terms が適用)。

制限事項

✕Rapid リリースチャネルでのみ利用可能 (Regular/Stable では未対応)
✕httpCall が使用できないため、外部サービスへの呼び出し不可
✕スクリプトサイズの上限が厳しい (単一 50KB、全体 100KB)
✕クラスター内の Lua EnvoyFilter パッチ数は最大 10 に制限
✕TRAFFIC_DIRECTOR コントロールプレーンでのみサポート (istiod では非対応)

考慮すべき点

→複雑な Lua スクリプトはパフォーマンスに影響を与える可能性がある (十分なリソーステストが必要)
→サポート範囲は「設定がワークロードに伝播されること」に限定 (スクリプト自体の正確性はサポート対象外)
→不正な設定はメッシュを不安定化させる可能性がある

📝 まとめ

Cloud Service Mesh で Envoy Lua Filter が Preview として利用可能になったことで、Wasm フィルターの開発コストをかけずにデータプレーンのカスタマイズが可能になりました。

💡 今後の展望: 現時点では Rapid チャネル限定かつ Preview のため本番利用には注意が必要ですが、ヘッダー操作やリクエスト変換などのシンプルなユースケースにおいて、迅速なプロトタイピングや軽量な拡張を実現する有効な選択肢です。GA 昇格に向けて Regular/Stable チャネルへの展開が期待されます。
