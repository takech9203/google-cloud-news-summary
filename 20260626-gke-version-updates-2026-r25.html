📄 概要

GKE 2026-R25 バージョンアップデートでは、全リリースチャンネル (Rapid、Regular、Stable、Extended) にわたる包括的なバージョン更新が実施されました。Kubernetes 1.36.0 の最新パッチバージョンが Rapid チャンネルで利用可能になり、Regular チャンネルでも 1.36.0 が初めて利用可能になりました。

❌ アップデート前の課題

  • Rapid デフォルト: 1.36.0-gke.2684000 (セキュリティ修正未適用)
  • Regular/Extended デフォルト: 1.35.5-gke.1000000 (旧パッチ)
  • Container-Optimized OS に累積的セキュリティ修正が必要
  • 一部の旧バージョンにセキュリティ脆弱性が存在

✅ アップデート後の改善

  • Rapid で 1.36.0-gke.3302001 が利用可能に
  • 各チャンネルのデフォルトが最新セキュリティ修正版に更新
  • Container-Optimized OS イメージが更新済み
  • 旧バージョンの非推奨化で移行を促進

⚡ 主要機能

Rapid Kubernetes 1.36.0 最新パッチ

  • 1.36.0-gke.3070003 が新しいデフォルトバージョンに設定
  • 1.36.0-gke.3302001 が新規利用可能バージョンとして追加
  • 1.35 から 1.36.0-gke.3070003 への自動アップグレードが可能
  • 旧バージョン (1.36.0-gke.2684000、1.36.0-gke.3009002 など) の非推奨化

Regular 1.35.5 デフォルト化と 1.36.0 導入

  • 1.35.5-gke.1057002 が新しいデフォルトバージョンに設定
  • 1.36.0-gke.2684000 が Regular チャンネルで初めて利用可能に
  • 1.34 から 1.35.5-gke.1057002 への自動アップグレードが可能

Stable 安定版の更新

  • 1.34.7-gke.1499000 が新しいデフォルトバージョンに設定
  • 1.35.5-gke.1000004 が Stable チャンネルで新規利用可能
  • 1.34.8-gke.1000000 も利用可能に

Extended 幅広いバージョンサポート

  • 1.35.5-gke.1057002 が新しいデフォルトバージョンに設定
  • 1.30.14 から 1.36.0 まで幅広いマイナーバージョンをサポート
  • 新しいノードバージョン: 1.30.14-gke.2710000、1.31.14-gke.2116000 など

🔒 セキュリティ更新: Container-Optimized OS イメージ

  • 全チャンネルで更新された Container-Optimized OS イメージを使用
  • 累積的なセキュリティ修正が適用済み
  • 最新の COS バージョン: cos-129-19506-120-64 (Rapid/1.36.0 向け)

✅ メリット

💼 ビジネス面

  • セキュリティコンプライアンスの維持: 最新の COS イメージでセキュリティ監査要件を満たしやすく
  • サポート期間の確保: 標準サポート期間 (14 か月) を最大限活用可能
  • 運用コストの削減: 自動アップグレード機能で手動管理工数を削減

🛠 技術面

  • Kubernetes 1.36 の新機能: Rapid チャンネルで最新機能を早期検証・活用可能
  • セキュリティ強化: COS の累積修正でノードレベルの脅威を軽減
  • 柔軟なアップグレードパス: 複数のターゲットで段階的移行が可能

⚠ デメリット・制約事項

🚨 制限事項:
  • ロールアウトは全 Google Cloud ゾーンへの展開完了に数日かかる場合がある
  • リリースチャンネルの自動アップグレードはメンテナンス除外や非推奨 API 使用により遅延する場合がある
  • Rapid チャンネルのバージョンは GKE SLA の対象外 (既知の回避策のない問題が含まれる可能性)
💡 考慮すべき点:
  • Kubernetes 1.36 は Stable チャンネルにはまだ到達していない
  • No Channel (非推奨) 設定は 2027 年 6 月 14 日に廃止予定。未登録クラスタは Stable チャンネルに自動登録
  • 非推奨バージョンは 90 日以内に削除されるため、早期のアップグレード計画が必要
  • containerd の重大な脆弱性 (GCP-2026-037) は別途パッチ (1.36.0-gke.3545000 以降) で対応が必要

🏭 ユースケース 1: 本番環境の計画的アップグレード

シナリオ: Regular チャンネルを使用する本番クラスタで、1.34.x から 1.35.5 への計画的マイナーバージョンアップグレードを実施

Bash 
# メンテナンスウィンドウを設定 (深夜帯に実行)
gcloud container clusters update production-cluster \
  --zone=asia-northeast1-a \
  --maintenance-window-start=2026-06-28T18:00:00Z \
  --maintenance-window-end=2026-06-28T22:00:00Z \
  --maintenance-window-recurrence="FREQ=WEEKLY;BYDAY=SA"

# コントロールプレーンを手動アップグレード
gcloud container clusters upgrade production-cluster \
  --zone=asia-northeast1-a \
  --master \
  --cluster-version=1.35.5-gke.1057002

効果: Regular チャンネルのデフォルトバージョンへの更新で、安定性とセキュリティのバランスが取れた最新環境を維持

🔬 ユースケース 2: Kubernetes 1.36 の検証

シナリオ: 開発/ステージング環境で Kubernetes 1.36 の新機能を検証し、本番環境への導入を計画

Bash 
# Rapid チャンネルで 1.36 のテストクラスタを作成
gcloud container clusters create k136-test \
  --zone=asia-northeast1-a \
  --release-channel=rapid \
  --cluster-version=1.36.0-gke.3070003 \
  --num-nodes=3

効果: 本番導入前に Kubernetes 1.36 の動作検証が可能。Rapid チャンネルにより最新パッチも自動適用

🏦 ユースケース 3: 長期サポートが必要なワークロード

シナリオ: 金融系システムなど、変更を最小限に抑えたいワークロードで Extended チャンネルを活用

Bash 
# Extended チャンネルでクラスタを作成
gcloud container clusters create fintech-cluster \
  --zone=asia-northeast1-a \
  --release-channel=extended \
  --cluster-version=1.31.14-gke.2116000 \
  --num-nodes=5

効果: 最大 24 か月のサポート期間を活用し、安定した環境を長期間維持しながらセキュリティパッチのみを受領
