📝 概要

Google Cloud の生成 AI セキュリティサービス Model Armor の画像スクリーニング機能が 一般提供 (GA) になりました。スタンドアロン画像に加え、 PDF / Word / Excel / PowerPoint に埋め込まれた画像を自動抽出してスクリーニングできます。 あわせて課金が開始され、画像サイズをトークンに換算するテキストと統一されたトークンベースの料金体系が適用されます。

画像に埋め込まれたプロンプトインジェクションや機密情報は、テキストのみの検査では見逃されるリスクでした。 本アップデートにより、ドキュメント内のテキストと画像の両方を単一のサニタイズ処理でカバーでき、 マルチモーダルな AI ワークロードのセキュリティ境界を強化できます。

❌ アップデート前の課題

✗画像内に埋め込まれたテキスト (インジェクション指示や機密情報) はテキストのみのスクリーニングでは検出できなかった
✗ドキュメントのスクリーニングはテキスト抽出が中心で、埋め込み画像に潜むリスクは未カバー
✗画像スクリーニングの正式な料金体系が未確定で、本番導入時のコスト見積もりが困難

✅ アップデート後の改善

✓ドキュメントから埋め込み画像 (最大 5 枚) を自動抽出し、ビジュアルスキャン + OCR の両方でスクリーニング
✓MODALITY_TEXT と MODALITY_IMAGE の両方を有効化すれば、テキストと埋め込み画像を 1 回のリクエストで検査
✓画像サイズベースのトークン換算式が確定し、テキストと同一レート・同一無料枠でコスト予測が可能

Model Armor がドキュメントからテキストと埋め込み画像を抽出し、ビジュアルスキャンと OCR の 2 系統でフィルタ検査を行うデータフロー。問題がなければ LLM に渡し、違反検出時はブロックまたは検出結果を返します。

⚙️ 主要機能

📄 1. ドキュメント埋め込み画像の抽出とスクリーニング (GA)

→テンプレートで MODALITY_IMAGE を有効にすると、PDF (PDF)、Word (WORD_DOCUMENT)、Excel (EXCEL_DOCUMENT)、PowerPoint (POWERPOINT_DOCUMENT) のサニタイズ時に埋め込み画像を最大 5 枚まで自動抽出してスクリーニング
→MODALITY_TEXT と MODALITY_IMAGE の両方を有効にすると、ドキュメントのテキストと埋め込み画像の両方を検査

🔍 2. 2 系統の画像検査手法

→ビジュアルスキャン: 高度な Sensitive Data Protection フィルタで、画像内の機微なオブジェクトや被写体 (オブジェクト infoType、画像コンテキスト infoType) を検出
→OCR: 画像からテキストを抽出し、責任ある AI の安全性カテゴリ、プロンプトインジェクション / ジェイルブレイク検出、悪意のある URL、SDP infoType の各フィルタで検査

💰 3. 画像サイズベースのトークン課金の開始

→処理した画像を「5,000 トークン + 1 MB あたり 1,000 トークン (MB 単位で切り上げ)」の式でトークンに換算
→画像トークンはテキストトークンと同一レートで課金され、同じトークン使用量・ティア枠にカウント
→OCR で抽出したテキストは画像トークンに含まれ、別途テキストトークンとして課金されない

🧩 テンプレート設定 (モダリティの指定)

REST API では templateMetadata.modalities フィールドでスキャン対象のモダリティを指定します。

JSON モダリティ指定 
{
  "templateMetadata": {
    "modalities": ["MODALITY_IMAGE", "MODALITY_TEXT"]
  }
}
設定スキャン対象
MODALITY_TEXT のみテキスト文字列とドキュメント内テキスト (埋め込み画像は無視)
MODALITY_IMAGE のみスタンドアロン画像とドキュメント内の埋め込み画像 (ドキュメントの平文テキストは無視)
両方指定テキストと画像の両方をスキャン
未指定 / 空テキストのみスキャン (従来どおり)

💼 ビジネス面

🔧 技術面

✓単一リクエストでの一括検査: 両モダリティを有効にすれば、ドキュメント 1 件のサニタイズでテキストと埋め込み画像の両方を検査でき、アプリ側での画像抽出処理が不要
✓OCR とビジュアルスキャンの併用: 画像内テキストへのフィルタ適用 (インジェクション検出、悪意ある URL、SDP) と、視覚的な機微オブジェクト検出の両方を 1 つの機能で実現

⚠️ デメリット・制約事項

🚧 制限事項

✗画像スクリーニングは us と eu のマルチリージョンでのみ利用可能。非対応エンドポイントに画像を送ると invocationResult が FAILURE になる
✗ドキュメントは合計 4 MB 以下・埋め込み画像 5 枚以下が条件。超過するとファイル全体のスキャンがスキップされる (部分スキャンは行われない)
✗スタンドアロン画像は 1 リクエスト 1 枚のみ。テキストと画像を組み合わせたスタンドアロンプロンプトは非対応
✗ストリーミングメソッド (StreamSanitizeUserPrompt など) は画像・ファイルに非対応
✗画像モダリティ有効時のリッチテキストドキュメントでは、SDP の de-identify (秘匿化) は非対応 (inspect テンプレートのみ使用可能)

🤔 考慮すべき点

⚠️入力が初期検証を通過した場合、フィルタが EXECUTION_SKIPPED を返しても (例: 4 MB 以下だが解析できない画像ペイロード) トークンは課金される
⚠️非画像ファイル (ZIP、CSV など) を byteDataType: IMAGE で送信すると、フィルタがスキップされてもスタンドアロン画像のトークン計算で課金される
⚠️データレジデンシー準拠を無効化しても、画像モダリティは us / eu マルチリージョンに制限されたまま
⚠️課金対象のモダリティはテンプレート設定に依存。MODALITY_IMAGE のみの場合はドキュメントテキストは課金されず、両方有効の場合はテキストトークンと画像トークンの合計が課金される

💰 料金

Model Armor はテキスト・スタンドアロン画像・リッチテキストドキュメントにまたがる統一トークンベースの料金体系を採用しており、 画像トークンはテキストトークンと同一レートで課金されます。スタンドアロン版の場合、月 200 万トークンまで無料、 超過分は 100 万トークンあたり $0.10 です (SCC Premium / Enterprise サブスクリプションには月 30 億トークンが含まれます)。

🧮 画像のトークン換算式:
1 画像あたりのトークン数 = 5,000 + (1,000 × 画像サイズ [MB、切り上げ])
  • OCR で抽出されたテキストは画像トークンに含まれ、別途課金されない
  • 初期検証前に拒否・スキップされた入力 (空入力、サイズ・画像数の上限超過など) は課金されない
  • リッチテキストドキュメントは有効なモダリティに応じて課金される (テキストのみ / 画像のみ / 両方の合計)
