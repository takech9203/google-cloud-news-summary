📋 概要

Gemini Enterprise において、SharePoint フェデレーテッドデータストア向けフィルター機能の GA 化と、インド (IN)・シンガポール (SG) リージョンの追加が発表されました。

SharePoint フィルターにより、管理者は検索対象に含めるサイトやパスを細かく制御でき、機密情報の保護と検索精度の向上を両立できます。インド・シンガポールリージョンの追加は、アジア太平洋地域のデータレジデンシー要件を持つ組織にとって大きな進展です。

Before (アップデート前)

  • SharePoint フィルターはプレビュー段階で本番利用に制約あり
  • APAC のユーザーはデータレジデンシー要件を満たすリージョンで利用不可
  • インド・シンガポールの規制要件を持つ企業は US/EU へのデータ転送が必要

After (アップデート後)

  • SharePoint フィルターが GA、本番ワークロードで安定利用可能
  • インド・シンガポールで at-rest DRZ と MLP が利用可能
  • Gemini 3.5 Flash モデルがリージョン内処理として利用可能
  • APAC の規制要件 (データローカライゼーション) への準拠が容易に

🔑 主要機能

🔍 SharePoint フィルター (GA)

→Inclusion フィルター (admin_filter): 特定サイトやパスのみを検索対象に含める
→Exclusion フィルター (admin_exclusion_filter): 特定サイトやパスを検索対象から除外
→レガシーフィルター (structured_search_filter): 既存 API との後方互換性維持

🌍 インド・シンガポールリージョン

→at-rest データレジデンシー (DRZ) のリージョン内保証
→機械学習処理 (MLP) のリージョン内実行
→Gemini 3.5 Flash モデルのリージョン内利用

🎯 細粒度フィルターキー

→Site フィルター: SharePoint サイト URL レベルでのフィルタリング
→Path フィルター: サブサイト、フォルダー、ファイルレベルでの制御
→フィルターの組み合わせ (サイト全体を含めつつ特定パスを除外) が可能

⚙️ 技術仕様

フィルタータイプと動作

フィルタータイプ パラメータ名 用途
Inclusion フィルター admin_filter 検索対象の包含指定
Exclusion フィルター admin_exclusion_filter 検索対象からの除外指定
レガシーフィルター structured_search_filter 既存コネクタとの互換性

フィルターキー

フィルター名 キー URL 形式
Site Site https://{tenant}.sharepoint.com/sites/{site-name}
Path Path https://{tenant}.sharepoint.com/sites/{site-name}/Documents/

フィルター組み合わせの動作

組み合わせ 動作
Path (Inclusion) + Site (空) Path inclusion フィルターのみ適用
Site (Inclusion) + Path (空) Site inclusion フィルターのみ適用
Site (Inclusion) + Path (Exclusion) サイト全体を含めつつ特定パスを除外
Path (Inclusion) + Site (Inclusion) 両フィルターの交差部分のみ含む
Site (Exclusion) + Path (Exclusion) いずれかに一致するパスを全て除外

🛠️ 設定方法

前提条件

1.Gemini Enterprise のサブスクリプション (Standard 以上推奨)
2.Microsoft Entra ID での OAuth 2.0 アプリケーション登録済み
3.Discovery Engine Editor ロール (roles/discoveryengine.editor) の付与
4.Microsoft SharePoint の API パーミッション設定 (Sites.Search.All, AllSites.Read)

フィルター設定例 (API)

JSON Inclusion + Exclusion フィルター設定 
{
  "params": {
    "admin_filter": {
      "Site": [
        "https://contoso.sharepoint.com/sites/engineering",
        "https://contoso.sharepoint.com/sites/product"
      ]
    },
    "admin_exclusion_filter": {
      "Path": [
        "https://contoso.sharepoint.com/sites/engineering/Confidential/"
      ]
    }
  }
}

API によるフィルター追加・更新

Bash curl コマンドによるフィルター設定 
curl -X PATCH \
  -H "Authorization: Bearer $(gcloud auth print-access-token)" \
  -H "Content-Type: application/json" \
  -H "X-Goog-User-Project: PROJECT_ID" \
  "https://ENDPOINT_LOCATION-discoveryengine.googleapis.com/v1alpha/projects/PROJECT_ID/locations/LOCATION/collections/COLLECTION_ID/dataConnector?updateMask=params" \
  -d '{
    "params": {
      "admin_filter": {
        "Site": [
          "https://contoso.sharepoint.com/sites/engineering"
        ]
      },
      "admin_exclusion_filter": {
        "Path": [
          "https://contoso.sharepoint.com/sites/engineering/Confidential/"
        ]
      }
    }
  }'
💡 ヒント: ENDPOINT_LOCATION には us, eu, または global を指定します。インド・シンガポールリージョンの利用には、事前に Google アカウントチームへ連絡し allowlist への追加を依頼する必要があります。

⚠️ デメリット・制約事項

制限事項
  • インド・シンガポールリージョンは GA with allowlist (Google アカウントチームへの連絡が必要)
  • インド (IN) リージョンでは Gemini 2.5 Pro モデルが利用不可
  • インド (IN) リージョンでは Model Armor の MLP が非対応
  • CMEK (顧客管理暗号鍵) はインカントリーリージョンでは利用不可
  • Dynamic facets / Grounding with Google Search はグローバルリージョンでのみ利用可能
  • Web Grounding for Enterprise はインカントリーリージョンでは at-rest DRZ / MLP 非対応
考慮すべき点
  • Inclusion/Exclusion 切り替え時は不要フィルターを明示的に空に設定する必要あり
  • フィルター更新時は既存設定も含めた全フィルターをリクエストボディに含める
  • フェデレーテッド検索ではクエリ文字列が Microsoft API に送信される (Microsoft 側のプライバシーポリシーも確認)
  • LLM によるクエリ書き換えでセッション履歴の一部が Microsoft API に送信される可能性

💡 ユースケース

UC1: 部門別情報アクセス制御

シナリオ: 大手企業で人事部門の機密情報を全社検索から除外しつつ、技術文書サイトのみを検索対象としたい

効果: エンジニアリングチームは必要な技術ドキュメントに素早くアクセスでき、機密性の高い人事情報は検索結果から完全に除外される

UC2: インドでのデータレジデンシー準拠

シナリオ: インドに拠点を持つ金融サービス企業が、インド準備銀行 (RBI) のデータローカライゼーション規制に準拠しつつ Gemini Enterprise を活用

効果: 顧客データの at-rest 保存と ML 処理がインド国内で完結し、RBI 要件を満たしながら全機能を活用可能

UC3: APAC 拠点でのレイテンシー最適化

シナリオ: シンガポールを APAC ハブとする多国籍企業が従業員向け AI アシスタントのレスポンス時間を改善

効果: シンガポールリージョンにより APAC 地域の従業員は低レイテンシーで利用でき、Gemini 3.5 Flash による高速レスポンスを体験
