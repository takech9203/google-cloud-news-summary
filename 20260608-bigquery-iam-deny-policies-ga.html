🔒 BigQuery: IAM Deny Policies GA

BigQuery IAM GA
2026-06-08

📋 概要

BigQuery における IAM deny policies (拒否ポリシー) が一般提供 (GA) となりました。付与されたロールに関係なく、特定のプリンシパルの権限を確実にブロックできる「ガードレール」型のアクセス制御が本番環境で正式にサポートされます。

💡 ポイント: Deny policies は Allow policies より先に評価されます。拒否ルールに該当した場合、どんなロールが付与されていてもアクセスはブロックされます。

❌ Before (従来)

  • Allow policies のみでは意図しないアクセスが発生する可能性
  • 上位階層で付与されたロールを下位で制限する手段が限定的
  • 「絶対に許可しない」制約には複雑なカスタムロール設計が必要
  • Preview 段階で SLA なし、本番利用困難

✅ After (GA リリース後)

  • Deny policies で特定アクションを明示的にブロック可能
  • 組織・フォルダ・プロジェクトレベルで設定、階層全体に継承
  • CEL による条件付き拒否ルールで柔軟なポリシー設計
  • GA により SLA 対象、本番環境で安心して利用可能

⚡ 主要機能

🚫 明示的な権限拒否

Allow policies で付与された権限があっても deny policies が優先。tables.getData や datasets.delete など多数の権限が対象。

📂 階層型ポリシー継承

組織、フォルダ、プロジェクトにアタッチ可能。上位リソースの deny policy は配下全リソースに自動継承。

🎯 条件付き拒否ルール

CEL を使用して条件付き拒否を定義。リソースタグ (例: env:prod) に基づく条件分岐が可能。

👤 例外プリンシパル

拒否対象から特定のプリンシパルを除外可能。管理者グループや認可済みリソースを例外指定できる。

🌐 権限グループによる一括拒否

ワイルドカード (bigquery.googleapis.com/tables.*) でテーブル関連の全権限を一括拒否。将来追加される新しい権限も自動的にカバー。

Deny Policy の構造

JSON 
{
  "displayName": "BigQuery データ保護ポリシー",
  "rules": [
    {
      "description": "機密データセットの削除を全ユーザーに対して拒否",
      "denyRule": {
        "deniedPrincipals": [
          "principalSet://goog/public:all"
        ],
        "exceptionPrincipals": [
          "principal://iam.googleapis.com/projects/-/serviceAccounts/admin@project.iam.gserviceaccount.com"
        ],
        "deniedPermissions": [
          "bigquery.googleapis.com/datasets.delete",
          "bigquery.googleapis.com/tables.delete"
        ],
        "denialCondition": {
          "expression": "resource.matchTag('123456/env', 'production')"
        }
      }
    }
  ]
}

🛠️ 設定方法

前提条件: iam.denypolicies.create / iam.denypolicies.update 権限が必要。gcloud CLI を最新バージョンにアップデートしてください。

Step 1: Deny Policy の JSON ファイルを作成

JSON 
{
  "displayName": "BigQuery テーブル削除防止ポリシー",
  "rules": [
    {
      "description": "本番環境のテーブル削除を拒否",
      "denyRule": {
        "deniedPrincipals": ["principalSet://goog/public:all"],
        "deniedPermissions": [
          "bigquery.googleapis.com/tables.delete",
          "bigquery.googleapis.com/datasets.delete"
        ],
        "denialCondition": {
          "expression": "resource.matchTag('YOUR_ORG_ID/env', 'production')"
        }
      }
    }
  ]
}

Step 2: Deny Policy を作成

Bash 
gcloud iam policies create my-bq-deny-policy \
  --attachment-point=cloudresourcemanager.googleapis.com/projects/my-project \
  --kind=denypolicies \
  --policy-file=policy.json

Step 3: Deny Policy の確認

Bash 
gcloud iam policies get my-bq-deny-policy \
  --attachment-point=cloudresourcemanager.googleapis.com/projects/my-project \
  --kind=denypolicies \
  --format=json

Step 4: Terraform による管理 (オプション)

HCL 
resource "google_iam_deny_policy" "bq_protection" {
  provider     = google-beta
  parent       = urlencode("cloudresourcemanager.googleapis.com/projects/${var.project_id}")
  name         = "bq-table-protection"
  display_name = "BigQuery テーブル保護ポリシー"

  rules {
    deny_rule {
      denied_principals  = ["principalSet://goog/public:all"]
      denied_permissions = ["bigquery.googleapis.com/tables.delete"]
    }
  }
}

⚠️ デメリット・制約事項

制限事項
  • 変更反映は結果整合性 (eventually consistent) - 即座に反映されない場合がある
  • BigQuery キャッシュ結果 (24時間) に対しては tables.getData の deny だけではブロック不可、jobs.create の deny も必要
  • 認可済みリソース (authorized views/routines/datasets) は通常の deny では制御不可、特別なプリンシパル指定が必要
  • リソースあたり deny policies は最大 500、deny rules 合計も最大 500
考慮すべき点
  • 過度に広範な deny rule は正当なアクセスもブロックする可能性がある
  • 条件 (denialCondition) はリソースタグ関数のみサポート、他の条件属性は使用不可
  • 既存のデータセットサブスクリプションは deny policies の影響を受けない場合がある
  • デバッグには Policy Troubleshooter や Policy Analyzer の活用を推奨

🎯 ユースケース

📦 ユースケース 1: 本番データセットの誤削除防止

シナリオ: 大規模な分析チームで複数のエンジニアが BigQuery を利用しており、本番環境のデータセットやテーブルが誤って削除されるリスクがある。

実装: env:production タグ付きリソースの delete 権限を全ユーザーに対して拒否し、platform-admins グループのみ例外指定。

効果: 管理者グループ以外の全ユーザーが本番データを削除できなくなり、誤操作による本番データの喪失を防止。

🔐 ユースケース 2: 機密データへのアクセス制御強化

シナリオ: PII (個人識別情報) を含むテーブルに対し、特定の部署以外からのデータ読み取りを組織レベルで禁止したい。

実装: sensitivity:pii タグ付きテーブルの tables.getData を全ユーザーに拒否、data-privacy-team のみ例外。

効果: PII データへのアクセスが data-privacy-team に限定され、データプライバシー規制への準拠が強制される。

🛡️ ユースケース 3: IAM ポリシーの不正変更防止

シナリオ: プロジェクト内の BigQuery データセットの IAM ポリシーが無断で変更されることを防ぎ、セキュリティチームのみが権限管理を行えるようにしたい。

実装: datasets.setIamPolicy を全ユーザーに拒否し、セキュリティチームのみ例外指定。

効果: 権限エスカレーション攻撃のリスクが大幅に低減される。

💰 料金・リージョン情報

料金: IAM deny policies の利用自体には追加料金は発生しません。BigQuery の通常の料金体系 (ストレージ、クエリ処理) がそのまま適用されます。
利用可能リージョン: IAM deny policies はグローバルリソースであり、BigQuery が利用可能な全てのリージョンで使用できます。deny policy は組織、フォルダ、またはプロジェクトにアタッチされ、リージョンに依存しません。

📝 まとめ

BigQuery における IAM deny policies の GA リリースは、エンタープライズ環境でのデータガバナンスを大幅に強化する重要なアップデートです。Allow policies だけでは実現困難だった「確実な拒否」が可能になり、誤操作や権限エスカレーションからの保護が組織レベルで実装できます。

推奨アクション: データセキュリティ要件の厳しい組織では、既存の allow policies と組み合わせて deny policies を導入し、多層防御アーキテクチャを構築することを推奨します。
