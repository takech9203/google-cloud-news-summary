📋 概要

Looker 26.10 は、ダッシュボード体験の刷新、ビジュアライゼーション機能の強化、AI/Gemini 統合の拡張、開発者向け CI/CD ワークフローの改善を含む大規模なリリースです。

特に注目すべきは、KPI (Single Value) ビジュアライゼーションの Preview 導入、フィルターをタイルとしてキャンバスに配置できる機能、Google Maps の大幅なエンハンスメント、そして Conversational Analytics の可観測性メトリクスです。

⚠️ 破壊的変更: Gemini Enterprise インスタンス更新時のデータエージェント非公開化

Looker に接続されている Gemini Enterprise インスタンスを更新すると、以前の Gemini Enterprise インスタンスに公開していたデータエージェントが全て非公開になります。新しい Gemini Enterprise インスタンスに再公開しなければ、Gemini Enterprise でエージェントとチャットできなくなります。

対応手順:

  1. 更新前に公開済みデータエージェントの一覧を確認
  2. 更新後、各データエージェントの Publish settings から Gemini Enterprise 設定を再度有効化
  3. ユーザーへの Gemini Enterprise User IAM ロール付与を再確認

🔄 Before / After

❌ Before (26.10 以前)

  • import_locale_defs: yes でロケール統合
  • 説明文 2,000 文字に拡張
  • API でオーナーシップをプログラマティック変更

🖥️ ダッシュボード & ビジュアライゼーション

📊 KPI (Single Value) ビジュアライゼーション Preview

既存の Single Value チャートを置き換える新しい KPI チャートオプション。

✓セカンダリビジュアライゼーション: スパークライン (Area chart) またはバーチャート表示
✓比較表示の強化: 任意のメジャーに対する比較 (1行目/2行目/最終行/合計行)
✓スタイリング: タイル背景色、値の配置 (左/中央/右) カスタマイズ
有効化: Admin > Preview Features > KPI Visualization トグルをオン

🔲 Filters as Tiles Preview

ダッシュボードフィルターをキャンバス上のドラッグ可能なタイルに変換。

✓関連するビジュアライゼーションタイルの近くにフィルターを配置可能
✓ビューアーが特定タイルに適用されているフィルターを確認可能 (Show Filters)
✓フィルターバーとキャンバスの間で自由に移動可能
✓LookML ダッシュボードでもサポート
注意: 無効化するとキャンバスに配置済みのフィルタータイルは空白タイルとして表示されます。

🌐 Model Localization for Imported Projects Preview

インポートされたプロジェクトのロケール定義をインポート元プロジェクトの定義と統合可能に。

LookML 
# manifest.lkml (インポート元プロジェクト)
project_name: "my_project"

localization_settings: {
  default_locale: en
  localization_level: permissive
  import_locale_defs: yes
}

優先順位: インポート元プロジェクトのキーが常に優先。インポート順序で重複を解決。

💡 ユースケース

🎯 エグゼクティブ KPI ダッシュボードの刷新

シナリオ: 経営陣向けダッシュボードで売上・利益率・顧客数などの KPI を表示。トレンド把握に別タイル参照が必要だった。

実装: KPI チャートにスパークラインを追加し過去 12 ヶ月トレンドを表示。比較表示で前年同期差分を自動計算。フィルターを KPI グループ近くにタイル配置。

効果: 1 つのタイルで KPI 値、トレンド、比較が完結。ダッシュボードの情報伝達力が大幅に向上。

🔄 LookML プロジェクトの品質自動監視

シナリオ: 複数開発者が LookML を変更する環境で、本番環境のデータ品質を定期的に検証したい。

実装: CI スイートで SQL/Content/Assert Validator を設定。Daily トリガーを早朝に設定。本番リポジトリの検証を毎日自動実行。

効果: データ品質の劣化やコンテンツ破損を早期発見し、業務影響を最小化。

🌐 多国籍企業でのローカライゼーション統合

シナリオ: 共通データモデルプロジェクトをインポートし、各国向けにローカライズ。インポート元の新ラベルが反映されなかった。

実装: manifest.lkml に import_locale_defs: yes を追加。

効果: 共通プロジェクトのロケール定義が各国プロジェクトに自動統合。翻訳の一貫性が向上。
