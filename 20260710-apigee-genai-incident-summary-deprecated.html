Apigee Advanced API Security:
GenAI Incident Summary の廃止

Apigee Deprecated Preview
2026-07-10

📋 概要

Apigee Advanced API Security の Abuse Detection 機能に含まれていた GenAI Incident Summary (generative AI Insights) が、2026年7月9日をもって廃止およびシャットダウンされました。

この機能は Google Cloud の生成 AI 大規模言語モデル (LLM) を活用し、セキュリティインシデントに対して自動要約と緩和ガイダンスを提供するものでした。2024年6月に Preview としてリリースされ、約2年間の提供期間を経て GA に移行せず廃止が決定されました。

⚠️ 重要: この廃止は GenAI Incident Summary のみに影響します。Abuse Detection の中核機能 (ML ベースの異常検知、インシデントクラスタリング、セキュリティアクション) は引き続き利用可能です。

🚫 廃止される機能

🔴 GenAI Incident Summary

Abuse Detection が検出したセキュリティインシデントの自動要約生成。LLM による自然言語説明とインシデント影響範囲の解説。

🔴 AI ベースの緩和ガイダンス

インシデントに対する推奨対策の自動生成。セキュリティアクション (deny, flag) の提案と対応優先度の AI 判定。

📝 ステータス: Preview (Public Preview) のまま廃止。GA (一般提供) には移行せずに終了となりました。

✅ 引き続き利用可能な機能

🤖 Abuse Detection (中核機能)

  • ML ベースの異常検知とクラスタリング
  • セキュリティインシデントの自動検出
  • リスクレベル評価 (Severe / Moderate / Low)
  • インシデント属性情報 (IP, 国, プロキシ, ルール)

🛡️ Security Actions

  • deny / flag / allow アクション
  • IP, CIDR, API キー, User Agent による条件指定
  • プロキシ固有のセキュリティアクション

📊 Security Reports

  • カスタムレポートの生成
  • 国別、IP 別の悪意あるリクエスト分析

💪 Risk Assessment v2 (GA)

  • API 構成のセキュリティスコア評価
  • セキュリティプロファイルに基づく改善推奨

💡 代替アプローチ

方法 1: Incidents API による詳細情報取得

Incidents API でインシデントの詳細データをプログラム的に取得し、独自の分析パイプラインで処理します。

Bash 
# Incidents API でインシデント一覧を取得
curl -X GET \
  "https://apigee.googleapis.com/v1/organizations/{ORG}/environments/{ENV}/securityIncidents" \
  -H "Authorization: Bearer $(gcloud auth print-access-token)"

方法 2: Security Reports API によるカスタム分析

カスタムレポートを作成してインシデント分析を自動化します。

Bash 
# Security Reports API でカスタムレポートを作成
curl -X POST \
  "https://apigee.googleapis.com/v1/organizations/{ORG}/environments/{ENV}/securityReports" \
  -H "Authorization: Bearer $(gcloud auth print-access-token)" \
  -H "Content-Type: application/json" \
  -d '{
    "displayName": "Incident Analysis Report",
    "dimensions": ["ax_resolved_client_ip", "ax_geo_country"],
    "metrics": ["message_count", "error_count"],
    "filter": "ax_security_incident_id != \"\"",
    "timeRange": "last7days"
  }'

方法 3: Cloud Monitoring によるアラート設定

セキュリティアラート機能を活用し、インシデント検出時に自動通知を設定することで、迅速な手動対応を実現します。

🎯 ユースケース

🤖 ユースケース 1: Vertex AI を活用した独自の要約パイプライン

GenAI Incident Summary に代わり、Incidents API + Vertex AI (Gemini) で独自のインシデント要約システムを構築。カスタマイズ可能な形で同等の機能を再構築できます。

Python 
from google.cloud import aiplatform
import requests

# 1. Incidents API からインシデント詳細を取得
incidents = get_security_incidents(org, env)

# 2. Vertex AI (Gemini) でインシデント要約を生成
for incident in incidents:
    prompt = f"""
    以下のセキュリティインシデントを要約し、緩和策を提案してください:
    - リスクレベル: {incident['risk_level']}
    - 検出ルール: {incident['detection_rules']}
    - 影響プロキシ: {incident['affected_proxies']}
    - ソース IP: {incident['source_ips']}
    """
    summary = generate_with_gemini(prompt)

🛡️ ユースケース 2: Security Actions による自動対応

AI 要約なしでも、検出されたインシデントに対して自動的にセキュリティアクション (deny/flag) を適用。人手を介さない即時対応によりインシデント影響の最小化を実現します。

⚖️ メリット・デメリット

🟢 影響が限定的な理由

✓中核機能は維持: ML ベースの検出、クラスタリング、セキュリティアクションは引き続き動作
✓API アクセス可能: Incidents API と Security Stats API でプログラム的アクセスを維持
✓Preview 段階: GA 未到達のため、本番依存が少ないと想定

🔴 影響・制約事項

✗GenAI による自動要約がなくなり、インシデント分析に人手が必要に
✗セキュリティチームの少ない組織では、インシデント対応の初動が遅れる可能性
✗AI ベースの緩和ガイダンスがなくなり、対策立案に専門知識がより必要に
✗依存ワークフロー構築済みの場合、代替手段への移行計画が必要
💡 推奨: AI 要約パイプラインが必要な場合は、Vertex AI / Gemini API を使った独自パイプラインの構築を検討してください。

📝 まとめ

Apigee Advanced API Security の GenAI Incident Summary は Preview のまま廃止となりましたが、Abuse Detection の中核機能 (ML ベースの検出、セキュリティアクション、レポート) は引き続き利用可能です。

AI ベースのインシデント要約が必要な場合は、Incidents API + Vertex AI (Gemini) を組み合わせた独自パイプラインの構築を推奨します。影響を受けるユーザーは、手動分析ワークフローへの移行、または代替の AI 分析基盤の構築を早期に計画されることをお勧めします。
