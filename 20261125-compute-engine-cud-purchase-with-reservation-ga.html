💳 予約作成時の確約利用割引 (CUD) 同時購入が GA

オンデマンド予約作成時のハードウェアリソースベース コミットメント同時購入
📅 リリース日: 2026-11-25

📝 概要

Google Cloud コンソールでオンデマンド予約を作成する際に、一致するハードウェアリソースベースのコミットメントを同時に購入・アタッチできる機能が GA になりました。コミットメントが有効化されると、対象リソース使用量に基づいて確約利用割引 (CUD) が適用されます。

「キャパシティの確保 (予約)」と「コスト削減 (CUD)」という 2 つの操作を、「予約を作成」ページ内の単一ワークフローで完結できます。Compute Engine が予約の合計リソース (vCPU、メモリ、GPU、Local SSD ディスク) に一致するようにコミットメントのリソースを自動設定するため、手動でリソース数を揃える際の設定ミスを防げます。

🎯 対象ユーザー: 安定稼働するワークロード向けにゾーン内のキャパシティを確保しつつ、1 年または 3 年のコミットメントで割引を受けたいインフラ管理者・FinOps 担当者

❌ Before: アップデート前の課題

  • 予約の作成とコミットメントの購入は別々のワークフロー。「確約利用割引」ページ (または gcloud CLI / REST) から購入し、予約を作成・アタッチする必要があった
  • GPU やほとんどの Local SSD ディスクでは、コミットメントと予約のリソース数を正確に一致させる手動での整合性確認が必要だった
  • コミットメントのアタッチ忘れ、リソース量の不一致といった運用上のリスクがあった

✅ After: アップデート後の改善

  • 「予約を作成」ページから、予約の作成とコミットメントの購入を1 つのフローで同時に実行できる
  • Compute Engine が vCPU、メモリ、GPU、Local SSD ディスク (適用除外の local Titanium SSD を含む) を予約の合計リソースに自動的に一致させ、手動調整が不要に
  • VM プロパティの直接指定に加え、インスタンステンプレートや既存 VM ベースの予約でも同時購入が可能
  • 有効化後は対象リソースの使用量に応じて CUD が自動適用

従来は予約とコミットメントを別々のページで作成しリソース数を手動で一致させる必要がありましたが、GA となった本機能では「予約を作成」ページの単一フローで両方を同時に作成でき、リソースの一致は Compute Engine が自動的に保証します。

⚡ 主要機能

1️⃣ 予約作成フローへのコミットメント購入の統合

  • 「予約を作成」ページの「Maximize savings with a committed use discount」セクションから「Purchase a commitment」をクリックして構成
  • 単一プロジェクト予約 (Local) と共有予約 (Shared) の両方に対応
  • VM プロパティの直接指定、インスタンステンプレート、既存 VM のいずれをベースにした予約でも利用可能

2️⃣ リソースの自動マッチング

  • コミットメントの vCPU、メモリ、GPU、Local SSD ディスク (適用除外の local Titanium SSD ディスクを含む) を予約の合計リソースに完全一致するよう自動設定
  • コミットメント構成 (per-VM / 合計) は読み取り専用サマリーとして表示され、サポートされるマシンファミリーでは推定コストも確認できる

3️⃣ ドラフトコミットメントと不一致検出

  • 「Attach commitment」クリックでドラフトとして保存。「Create」をクリックするまで購入・課金は発生しない
  • ドラフト追加後にリージョン、マシンタイプ、vCPU、メモリ、VM 数、GPU、Local SSD を変更すると、インラインの不一致エラーが作成をブロック。「Edit」で更新または「Remove」で削除して解決

4️⃣ コミットメントの条件設定

  • プランは 1 年または 3 年を選択。開始日は翌日の午前 0 時 (米国・カナダ太平洋時間) に自動設定
  • カスタム終了日の指定による期間延長や、期間終了時の自動更新 (Auto-renew) も設定可能

🛠️ 設定方法

✅ 前提条件

✓予約の作成とコミットメントの購入は同一プロジェクト・同一リージョンで行う
✓予約に GPU または Local SSD ディスクが含まれる場合は、自動削除 (Enable auto-delete) を無効にする
✓共有予約の場合は、compute.sharedReservationsOwnerProjects 組織ポリシーでオーナープロジェクトを許可リストに登録し、各プロジェクトのクォータを確認する。コンシューマープロジェクトで CUD を受けるには、Cloud Billing アカウントで CUD 共有を有効にし、全コンシューマープロジェクトが同一の Cloud Billing アカウントに属している必要がある

📝 手順

1

予約を構成する

  1. Google Cloud コンソールで「予約」ページに移動し、「予約を作成」をクリック
  2. 名前、リージョン、ゾーン、共有タイプ (Local / Shared) を設定
  3. 「リソースの詳細」セクションで VM インスタンス数を入力し、マシンタイプの指定・インスタンステンプレート・既存 VM のいずれかで VM 構成を指定
2

コミットメントを購入する

  1. 「Maximize savings with a committed use discount」セクションで「Purchase a commitment」をクリック
  2. コミットメント名を入力し、期間 (1 年 / 3 年) を選択。必要に応じてカスタム終了日や自動更新を設定
  3. 読み取り専用のマシン構成・コミットメント構成サマリーで、VM あたりおよび合計の確約リソースと推定コストを確認
  4. 「Attach commitment」をクリックしてドラフトとして保存
3

作成を確定する

  1. 「Disclosures」セクションで料金、割引の適用条件、利用規約を確認
  2. 同意のチェックボックスを選択して「Create」をクリック
  3. 予約とコミットメントが同時に作成され、コミットメントは翌日午前 0 時 (太平洋時間) に有効化。予約の詳細ページまたは「Linked commitment」列でアタッチ状況を確認できる

💡 メリット

💼 ビジネス面

✓コスト削減の確実な適用: キャパシティ確保と同時に CUD を購入するため、予約リソースに割引を適用し忘れるリスクを低減できる
✓購入前のコスト可視化: サポートされるマシンファミリーでは、購入確定前に推定コストをサマリーで確認できる

⚙️ 技術面

✓リソース不一致の防止: GPU や Local SSD で求められる「コミットメントと予約のリソース数の完全一致」を Compute Engine が自動的に保証する
✓ワークフローの簡素化: 従来 2 つのページにまたがっていた操作が単一フローに統合され、ドラフト保存と不一致検出により安全に構成を変更できる
✓柔軟な構成指定: インスタンステンプレートや既存 VM をベースにした予約でも利用でき、既存環境の構成を流用しやすい

⚠️ デメリット・制約事項

🚫 制限事項

✕コンソール限定: gcloud CLI や REST API からは利用できない (プログラムからのアタッチは「確約利用割引」ページ相当のワークフローを使用)
✕新規予約 1 件 + 新規コミットメント 1 件のみ: 既存予約のアタッチ、複数予約のアタッチ、予約と異なる vCPU / メモリ量のコミットメントには対応しない (その場合は「確約利用割引」ページから購入する)
✕非対応のマシン構成: 共有コアマシンタイプなどリソースベース CUD に対応しない構成では「Purchase a commitment」ボタンが利用できない。拡張メモリを使用するカスタムマシンタイプにもアタッチ不可
✕一部マシンシリーズで失敗の可能性: A3 Mega、H4D、M4、M4N、X4、X5、Z4D など複数のコミットメントタイプを持つマシンシリーズや、Virtual Workstation GPU をアタッチした場合は、コミットメント不一致エラーで作成が失敗することがある (この場合は「確約利用割引」ページから購入する)

🤔 考慮すべき点

  • コミットメントは購入後にキャンセルできず、使用の有無にかかわらず期間終了まで毎月課金される
  • コミットメントは購入したプロジェクトとリージョンに紐づく。Compute Engine はコミットメントを購入したリージョンごとにプロジェクトへのリーエン (lien) を保持する
  • 共有予約でコミットメントのプロジェクト外から CUD を受けるには、同一 Cloud Billing アカウント内のプロジェクトとのみ予約を共有し、CUD 共有を有効にする必要がある

🎯 ユースケース

🏭 ユースケース 1: 本番ワークロードのキャパシティ確保とコスト最適化の同時実行

シナリオ: 特定ゾーンで常時稼働する本番 VM 群 (例: n2-standard 系 20 台) のキャパシティを確実に確保しつつ、1 年コミットメントで割引を受けたい。

実装例: コンソールの「予約を作成」ページで VM 数とマシンタイプを指定し、「Purchase a commitment」で 1 年プランを選択して予約とコミットメントを同時作成する。

効果: ゾーン内のキャパシティ確保と CUD によるコスト削減が 1 回の操作で完了し、リソース量は自動一致するため設定ミスがない。

🔄 ユースケース 2: 既存 VM 構成をベースにした予約 + コミットメント購入

シナリオ: すでに稼働中の VM と同じ構成でキャパシティを追加確保し、その分を長期コミットメントでカバーしたい。

効果: 「既存 VM を使用」で予約を構成すれば、マシンタイプや GPU 構成を手動転記することなく、一致するコミットメントを同時に購入できる。

💰 料金

本機能自体に追加料金はなく、購入するコミットメントに対して通常のリソースベース CUD の料金体系が適用されます。

  • コミットメントは期間中、リソースの使用有無にかかわらず毎月課金される
  • 割引後の価格は、コミットメント有効化日のオンデマンド価格に基づいて算出され、期間終了まで固定される
  • ハードウェアコミットメントの割引率の目安 (公式ドキュメントより):
    • vCPU / メモリ: ほとんどのマシンタイプで最大 55% オフ、一部 (メモリ最適化など) で最大 70% オフ
    • GPU: ほとんどの GPU タイプで最大 55% オフ、一部で最大 65% オフ
    • Local SSD ディスク: 最大 55% オフ
  • 3 年プランは 1 年プランより高い割引率が適用される
  • カスタムマシンタイプをコミットメントで利用する場合は、コミットメント価格に 5% のプレミアムが加算される
💡 詳細: リージョン・リソースごとの 1 年 / 3 年コミットメント価格は Compute Engine の料金ページを参照してください。

🔗 関連サービス・機能

📋 オンデマンド予約 (Reservations)

特定ゾーンでの Compute Engine リソースのキャパシティ確保機能。本アップデートの対象。

💳 確約利用割引 (CUD) ページ

既存予約のアタッチ、複数予約のアタッチ、予約と異なるリソース量でのコミットメント購入など、より柔軟な購入ワークフローを提供 (コンソール / gcloud CLI / REST)。

🤝 CUD 共有 (CUD sharing)

同一 Cloud Billing アカウント内の全プロジェクトでリソースベース CUD をプールして適用する機能。2026 年 6 月 16 日以降に作成された Cloud Billing アカウントではデフォルトで有効。

🤖 Vertex AI

GPU VM の予約を Vertex AI のカスタムトレーニングジョブや予測ジョブから利用するよう共有設定が可能。

🎓 まとめ

✅ 予約作成とコミットメント購入が単一のコンソールワークフローに統合され、キャパシティ確保とコスト最適化を同時かつ安全に実行できるようになりました。

安定稼働するワークロードで予約を利用している場合は、新規予約作成時に本ワークフローでの CUD 同時購入を検討してください。

⚠️ 注意: コンソール限定であり、複数予約のアタッチや A3 Mega / X4 など一部マシンシリーズでは従来の「確約利用割引」ページからの購入が必要です。
