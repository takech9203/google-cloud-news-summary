✅ GA 昇格 (本番利用推奨)

🔐 Compute Engine: Post-Quantum Key Exchange

GA

🤖 GKE: Agent Sandbox

GA

gVisor ベースのサンドボックス環境で AI エージェントが生成するコードを安全に実行。SandboxWarmPool による事前ウォーミングでコールドスタートを最小化。

GA

NCC Gateway spokes が GA に昇格。HYBRID_INSPECTION プリセットトポロジによる統合的なトラフィック検査が利用可能に。

🛡️ Network Security: Secure Access Connect

GA

Symantec Cloud SWG、Palo Alto Networks Prisma Access との統合が GA。NCC Gateway と連携した統合セキュリティアーキテクチャの本番運用が可能に。

🛠️ 設定方法

ステップ 1: Cloud SDK のアップデート

Bash 
# Cloud SDK を 570.0.0 にアップデート
gcloud components update --version=570.0.0

# バージョン確認
gcloud version

ステップ 2: GKE Agent Sandbox の有効化

Bash 
# 新規 Autopilot クラスタで有効化
gcloud container clusters create-auto my-cluster \
  --location=us-central1 \
  --enable-agent-sandbox

# 既存クラスタで有効化
gcloud container clusters update my-cluster \
  --location=us-central1 \
  --enable-agent-sandbox

ステップ 3: Cloud Run SSH 接続

Bash 
# SSH フラグ付きでデプロイ
gcloud run deploy my-service \
  --image=us-docker.pkg.dev/project/repo/image \
  --ssh

# カスタムドメイン付きでデプロイ
gcloud run deploy my-service \
  --image=us-docker.pkg.dev/project/repo/image \
  --domain=api.example.com

GKE Agent Sandbox 設定例

YAML 
apiVersion: agents.x-k8s.io/v1alpha1
kind: Sandbox
metadata:
  name: my-agent-sandbox
spec:
  replicas: 1
  podTemplate:
    spec:
      runtimeClassName: gvisor
      automountServiceAccountToken: false
      securityContext:
        runAsNonRoot: true
      nodeSelector:
        sandbox.gke.io/runtime: gvisor
      tolerations:
        - key: "sandbox.gke.io/runtime"
          value: "gvisor"
          effect: "NoSchedule"
      containers:
        - name: agent-runtime
          image: your-agent-image:latest
          securityContext:
            capabilities:
              drop: ["ALL"]
          resources:
            limits:
              cpu: "500m"
              memory: "1Gi"

ビジネス面

🛡️ハイブリッドセキュリティの統合: Secure Access Connect GA により、Palo Alto/Symantec と Google Cloud のネイティブ統合が本番レベルで実現

技術面

⚡認証キャッシュの効率化: RAB データのネイティブ統合で、マルチリージョン環境での認証オーバーヘッドが削減
🔍暗号ライブラリの最新化: cryptography 46.0.7 への更新で、最新の TLS/SSL 標準に対応し脆弱性リスクを低減
🔄開発者ループの短縮: Cloud Run の SSH/domain フラグと対話型プロンプトで、デプロイ設定の試行錯誤が大幅に削減

⚠️ デメリット・制約事項

⚠️ 制限事項
  • Windows PuTTY は v0.81 にリバートされているため、v0.82 以降の機能は利用不可
  • GKE Agent Sandbox は GKE バージョン 1.35.2-gke.1269000 以降が必要
  • Secure Access Connect は現時点で Symantec Cloud SWG と Palo Alto Networks Prisma Access のみをサポート
💡 考慮すべき点
  • Linux バンドル Python 3.14.5 へのアップデートにより、古い Python スクリプトとの互換性に注意が必要
  • Post-Quantum Key Exchange は自動適用されるため、ネットワーク監視ツールの暗号スイート検出に影響する可能性あり
  • メジャーアップデート前に、既存の CI/CD パイプラインでの動作検証を推奨
