🔥 Google Distributed Cloud for VMware: ファイアウォール許可リストへの us.gcr.io 追加必須化

Breaking Change Google Distributed Cloud VMware
2026-06-15
v1.33.0-gke.799+

📋 概要

Google Distributed Cloud (software only) for VMware の バージョン 1.33.0-gke.799 以降 において、 Advanced クラスターの作成またはアップグレードを行う際に、ファイアウォール許可リストに us.gcr.io を追加することが 必須 となりました。

⚠️ 重要: 対応を行わない場合、クラスターの作成やアップグレードが失敗します。バージョン 1.33 ではクラスターアップグレード時にデフォルトで Advanced クラスターへの自動変換が行われるため、多くのユーザーが影響を受ける可能性があります。

対象: オンプレミス環境で Google Distributed Cloud for VMware を運用しており、プロキシサーバーやファイアウォールを介してインターネットアクセスを制御している組織

🔄 Before / After 比較

❌ Before (v1.32 以前)

  • us.gcr.io がなくてもクラスター操作が可能
  • 地域別 Container Registry エンドポイントへの明示的アクセス不要
  • 既存のファイアウォールルールで管理が機能

✅ After (v1.33.0-gke.799+)

  • 米国リージョンの Container Registry から直接イメージ取得可能
  • イメージ取得パスの明確化でネットワーク透明性が向上
  • 必要エンドポイントが公式ドキュメントで明文化

⚙️ 主要機能

🔐 us.gcr.io ファイアウォール許可リスト要件

バージョン 1.33.0-gke.799 以降で Advanced クラスターを作成/アップグレードする際に必須。us.gcr.io への HTTPS (ポート 443) アクセスをファイアウォールで許可する必要がある。プロキシ使用時はプロキシの許可リストにも追加が必要。

🔄 Advanced クラスターへの自動変換との関連

v1.32 から v1.33 へのアップグレード時、クラスターはデフォルトで Advanced クラスターに変換される。v1.33 では非 Advanced 維持オプションがあるが、v1.34 では必ず Advanced に変換される。

📋 既存ファイアウォール要件との統合

従来から gcr.io、oauth2.googleapis.com、storage.googleapis.com が必須。今回 us.gcr.io が明示的に追加。プライベート Docker レジストリ使用時はこの要件は不要。

Step 1: 現在のファイアウォール許可リストを確認

grep -i "gcr.io" /etc/squid/squid.conf

Step 2: us.gcr.io をファイアウォール許可リストに追加

Bash 
# プロキシサーバー (Squid) の場合、squid.conf に追加:
acl gdc_allowlist dstdomain us.gcr.io
http_access allow gdc_allowlist

# 設定を反映
systemctl reload squid

Step 3: 接続性を確認

Bash 
# 管理ワークステーションから us.gcr.io への接続を確認
curl -v https://us.gcr.io/v2/ 2>&1 | grep "HTTP/"

# DNS 解決を確認
nslookup us.gcr.io

# gkectl を使用した事前検証チェック
gkectl diagnose cluster --kubeconfig ADMIN_CLUSTER_KUBECONFIG

Step 4: クラスターのアップグレードを実行

Bash 
# Admin クラスターのアップグレード
gkectl upgrade admin \
  --kubeconfig ADMIN_CLUSTER_KUBECONFIG \
  --config ADMIN_CLUSTER_CONFIG

# User クラスターのアップグレード
gkectl upgrade cluster \
  --kubeconfig ADMIN_CLUSTER_KUBECONFIG \
  --config USER_CLUSTER_CONFIG

💡 ユースケース

🔄 ユースケース 1: バージョン 1.32 から 1.33 へのアップグレード

企業がオンプレミスの VMware 環境で Google Distributed Cloud 1.32 を運用しており、1.33 へのアップグレードを計画。アップグレード時に Advanced クラスターへの自動変換が行われるため、事前にファイアウォール許可リストの更新が必要。

Bash 
# 1. 接続確認
curl -s -o /dev/null -w "%{http_code}" https://us.gcr.io/v2/

# 2. gkectl のバージョンを確認
gkectl version
# 出力: 1.33.0-gke.799 であることを確認

# 3. プリフライトチェック
gkectl diagnose cluster --kubeconfig /path/to/kubeconfig

# 4. アップグレード実行
gkectl upgrade admin --kubeconfig /path/to/admin-kubeconfig \
  --config /path/to/admin-config.yaml

効果: ファイアウォール許可リストの事前更新により、アップグレードがブロックされることなくスムーズに完了

🆕 ユースケース 2: 新規 Advanced クラスターの作成

新たにオンプレミス環境に Google Distributed Cloud for VMware を導入し、バージョン 1.33 以降で Advanced クラスターを新規作成するシナリオ。
