🛡️ Dataform: BigQuery ガバナンス制御の自動保持

Dataform BigQuery GA (一般提供) データガバナンスタグは Preview
リリース日: 2026-10-14
preserveGovernanceControls

📌 概要

Dataform で preserveGovernanceControls オプションを有効化すると、Dataform の実行をまたいで BigQuery のデータポリシーとデータガバナンスタグ (Preview) を自動的に保持できるようになりました。

Dataform がワークフローアクションでオブジェクト (標準テーブル、ビュー、フルリフレッシュ時の増分テーブルなど) を再作成する際、 BigQuery では CREATE OR REPLACE ステートメントが生成されます。BigQuery のデフォルト動作では、このテーブル置換により 既存の列レベルアクセス制御メタデータ (データポリシーや、外部データガバナンスシステムが適用したタグ) が 自動的に削除されてしまいます。本アップデートで、タグなし (tagless) データポリシーを含むこれらのメタデータを ワークフロー実行をまたいで自動保持できます。

💡 誰に重要? 機密データを扱う ELT パイプラインを Dataform で運用し、BigQuery の列レベルセキュリティや データマスキングを併用しているデータエンジニアリングチーム・データガバナンスチームにとって重要なアップデートです。

❌ Before: アップデート前の課題

  • テーブル再作成 (CREATE OR REPLACE) のたびに、データポリシー・データガバナンスタグが削除されていた
  • 外部データガバナンスシステムで適用したタグも、ワークフロー実行のたびに失われていた
  • セキュリティポリシー維持には、実行後に再適用する運用上の工夫が必要だった

✅ After: アップデート後の改善

  • preserveGovernanceControls: true の設定だけで、データポリシー (タグなしを含む) とガバナンスタグを自動保持
  • テーブル単位 (SQLX config) とリポジトリ全体 (workflow_settings.yaml) の両方で設定可能、個別オーバーライドも対応
  • 中間ステージングテーブルへのポリシー再適用とアトミックなテーブルスワップで安全に置換

従来はテーブル置換時に列レベルアクセス制御メタデータが失われていましたが、本機能を有効化すると、 メタデータのバックアップ → ステージングテーブルへのポリシー再適用 → データ投入 → アトミックスワップ という順序で実行され、ガバナンス制御が保持されます。

⚙️ 主要機能

1️⃣ データポリシー・データガバナンスタグの自動保持

✓BigQuery データポリシー (タグなしデータポリシーを含む) とデータガバナンスタグ (Preview) を、ワークフロー実行をまたいで自動保持
✓外部データガバナンスシステムによって適用されたタグも保持対象

2️⃣ 安全な置換シーケンス

有効化すると、Dataform は実行時に次の順序で処理します。

  1. 📋 INFORMATION_SCHEMA.COLUMNS ビューから既存の列メタデータをバックアップ
  2. 🗂️ 中間の空ステージングテーブルを作成
  3. 🔒 ステージングテーブルにセキュリティポリシーを再適用
  4. 📥 テーブルにデータを投入
  5. 🔄 アトミックなテーブルスワップで元のテーブルを置換

3️⃣ 柔軟な設定スコープ

✓テーブル・増分テーブル・ビュー単位: SQLX 定義ファイルの config ブロックで設定
✓リポジトリ全体: workflow_settings.yaml でプロジェクト全体のデフォルトとして設定
✓グローバル有効化時も、個別テーブルの config ブロックで false を設定してオーバーライド可能

🔬 技術仕様: 要件と保持対象

項目詳細
必要な Dataform core バージョン3.0.62 以降
対象オブジェクトテーブル、増分テーブル、ビュー
保持されるものBigQuery データポリシー (タグなしデータポリシーを含む)、データガバナンスタグ (Preview)
保持されないもの行アクセスポリシー (post_operations での再適用が必要)、レガシーポリシータグ
設定スコープテーブル単位 (SQLX config)、リポジトリ全体 (workflow_settings.yaml)

🛠️ 設定方法

📋 前提条件: ① Dataform core 3.0.62 以降を使用していること / ② Dataform のリポジトリと開発ワークスペースが作成済みであること
1

個別テーブルで有効化する

開発ワークスペースの Files ペインで definitions/ を展開し、SQLX テーブル定義ファイルの config ブロックに preserveGovernanceControls: true を追加します。

SQLX テーブル定義で有効化 
config {
  type: "table",
  preserveGovernanceControls: true
}
SELECT customer_id, email, phone_number FROM ${ref("raw_customers")}
2

リポジトリ全体で有効化する (任意)

workflow_settings.yaml に追加すると、すべてのテーブル・増分テーブル・ビューに対するプロジェクト全体のデフォルト動作として有効化できます。

YAML workflow_settings.yaml 
defaultProject: my-gcp-project-id
defaultDataset: my_dataform_dataset
defaultLocation: US
defaultAssertionDataset: my_dataform_assertions
dataformCoreVersion: 3.0.62
preserveGovernanceControls: true

グローバルに有効化した場合でも、特定のテーブルの config ブロックで preserveGovernanceControls: false を設定すれば、そのテーブルのみ保持を無効化できます。

3

行アクセスポリシーを post_operations で再適用する (必要な場合)

本機能は列レベルのメタデータを保護しますが、行アクセスポリシーは自動復元されません。オブジェクト置換により行レベルセキュリティルールは削除されるため、SQLX の post_operations ブロック内に SQL DDL を定義して、テーブル作成後に再適用します。

SQLX 行アクセスポリシーの再適用 
config {
  type: "table",
}
SELECT bike_id, start_time, duration FROM ${ref("raw_trips")}

post_operations {
  CREATE ROW ACCESS POLICY my_policy
  ON ${self()}
  GRANT TO ('serviceAccount:sa-name@example-gcp-project.iam.gserviceaccount.com')
  FILTER USING (bike_id LIKE 'US-%');
}

⚖️ メリットと制約事項

💼 ビジネス面のメリット

✓ガバナンスとコンプライアンスの維持: 機密列のマスキングやアクセス制御がパイプライン実行のたびに失われるリスクを排除し、継続的なコンプライアンスを担保
✓運用負荷の削減: 実行のたびにポリシーを手動または独自の仕組みで再適用する必要がなくなる

🔧 技術面のメリット

✓宣言的な設定: config ブロックまたは workflow_settings.yaml に 1 行追加するだけで有効化
✓アトミックなテーブルスワップ: ポリシー再適用後にデータを投入し、アトミックに置換するため安全
✓外部ガバナンスシステムとの親和性: 外部システムが適用したデータガバナンスタグも保持

🚧 制限事項

✗Dataform core 3.0.62 以降が必要
✗行アクセスポリシーは自動保持されない (post_operations での再適用が必要)
✗レガシーポリシータグは保持できない (公式ドキュメントは、列レベルセキュリティにはポリシータグではなく BigQuery データガバナンスタグ (Preview) の使用を推奨)

🤔 考慮すべき点

⚠️保持対象であるデータガバナンスタグ自体は Preview 段階の機能であり、Pre-GA 利用規約が適用される
⚠️有効化すると実行シーケンスにメタデータのバックアップ、ステージングテーブル作成、ポリシー再適用のステップが追加される

🎯 ユースケース

📧 ユースケース 1: 機密データを含む ELT パイプラインでの列レベルセキュリティ維持

シナリオ: 顧客のメールアドレスや電話番号を含むテーブルを Dataform で日次再構築しており、BigQuery のデータポリシーでマスキングを適用している。従来は再構築のたびにポリシーが失われていた。

SQLX 実装例 
config {
  type: "table",
  preserveGovernanceControls: true
}
SELECT customer_id, email, phone_number FROM ${ref("raw_customers")}

効果: 日次実行後もデータポリシーとデータガバナンスタグが維持され、機密列のマスキングが途切れなく適用され続ける。

🏢 ユースケース 2: リポジトリ全体でのガバナンス統制の標準化

シナリオ: 多数のテーブル定義を持つ Dataform リポジトリで、ガバナンス制御の保持をチーム標準として一括適用したい。

効果: workflow_settings.yaml に preserveGovernanceControls: true を 1 行追加するだけで全テーブル・ビューに適用され、個別テーブルで false によるオーバーライドも可能なため、柔軟に統制を標準化できる。

🔗 関連サービス・機能

🔒 BigQuery データポリシー

列レベルのデータマスキングやアクセス制御を実現する仕組み。本機能の保持対象 (タグなしデータポリシーを含む)。

🏷️ BigQuery データガバナンスタグ Preview

Resource Manager タグの一種で、機密列に付与してデータポリシーと組み合わせることで条件付きアクセスを実現する。本機能の保持対象。

🚪 BigQuery 行アクセスポリシー

行レベルのセキュリティルール。本機能では自動保持されないため、Dataform の post_operations で再適用する。

📝 まとめ

Dataform の preserveGovernanceControls オプションにより、テーブル再作成のたびに BigQuery のデータポリシーとデータガバナンスタグが失われるという長年の運用課題が解消されます。

✓機密データを扱う Dataform パイプラインを運用しているチームは、Dataform core 3.0.62 以降へ更新のうえ、workflow_settings.yaml または対象テーブルの config ブロックで本オプションの有効化を検討
✓行アクセスポリシーは保持対象外のため、post_operations での再適用を併せて設計することを推奨
