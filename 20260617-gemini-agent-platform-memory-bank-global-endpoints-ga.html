📋 概要

Gemini Enterprise Agent Platform の Memory Bank および Sessions が、 マルチリージョナルエンドポイントとグローバルエンドポイントに対応し GA (一般提供) となりました。

エージェントの長期記憶管理とセッション管理を、特定のリージョンに縛られることなく グローバルまたはマルチリージョン (US / EU) で運用できるようになります。

🧠 Memory Bank とは: エージェントに長期記憶を提供するサービス。会話から重要な情報を抽出・統合・保存し、複数のセッションにわたってパーソナライズされた応答を実現。
💬 Sessions とは: ユーザーとエージェント間のインタラクション履歴を管理し、会話の文脈を維持するサービス。

🔄 Before / After

❌ Before

  • 個別のリージョナルエンドポイントでのみ利用可能
  • グローバル展開エージェントでは複数リージョンの管理が煩雑
  • Preview 段階 (2026年5月19日~) で SLA 保証なし
  • グローバルエージェントとの統合にロケーション制約が障壁

✅ After

  • グローバル / マルチリージョナルエンドポイントが GA
  • 本番ワークロードで SLA 付きで利用可能
  • リージョンを意識せずに記憶・セッション管理
  • US/EU 内でのデータ処理保証 + 高可用性

⚡ 主要機能

エンドポイント対応

🌐 グローバルエンドポイント

ロケーションを global に設定。リージョンを指定せずに Memory Bank と Sessions を利用可能。Gemini Deep Research Agent との統合対応。

🇺🇸🇪🇺 マルチリージョナルエンドポイント

ロケーションを us または eu に設定。管轄区域内でのデータ処理を保証しつつ高可用性を実現。

Memory Bank の機能 (GA)

🧠 メモリ生成

LLM を使用した会話からの情報抽出・統合。マルチモーダルコンテンツからのテキスト知見抽出にも対応。

🔍 類似検索

エンベディングモデルによるスコープベースの記憶検索。関連する記憶を効率的に取得。

⏱️ TTL 設定

メモリの自動有効期限管理。デフォルト TTL と操作別 TTL の設定が可能。

📜 メモリリビジョン

メモリの変遷履歴を自動管理。記憶がどのように更新されてきたかを追跡。

Sessions の機能 (GA)

💬 セッション作成・再開

ユーザーとエージェント間の会話状態の管理。会話の文脈を維持。

📝 イベント管理

会話内容やエージェントのアクション (関数呼び出し等) の記録。

🗂️ ステート管理

現在の会話に関連する一時データの保持。デフォルト TTL は 365 日。

🔧 技術仕様

エンドポイント構成

エンドポイントタイプ ロケーション設定 ホスト名 CMEK
グローバル global aiplatform.googleapis.com ✗ 不可
マルチリージョナル (US) us aiplatform.us.rep.googleapis.com ✓ 可能
マルチリージョナル (EU) eu aiplatform.eu.rep.googleapis.com ✓ 可能
リージョナル 各リージョン名 {region}-aiplatform.googleapis.com ✓ 可能

必要な IAM ロール

roles/aiplatform.user (Agent Platform User)
GKE や Cloud Run からリクエストする場合は、サービスアカウントに上記権限が必要。Agent Runtime からのアウトバウンドリクエストには、Reasoning Engine Service Agent が既に必要な権限を保持。

Memory Bank インスタンスの作成

Python 
from vertexai.types import (
    ReasoningEngineContextSpecMemoryBankConfig as MemoryBankConfig,
    ReasoningEngineContextSpecMemoryBankConfigSimilaritySearchConfig as SimilaritySearchConfig,
    ReasoningEngineContextSpecMemoryBankConfigTtlConfig as TtlConfig,
)

memory_bank_config = MemoryBankConfig(
    similarity_search_config=SimilaritySearchConfig(
        embedding_model="projects/my-project/locations/global/publishers/google/models/text-embedding-005"
    ),
    ttl_config=TtlConfig(
        default_ttl="2592000s"  # 30日
    )
)

✅ メリット

ビジネス面

🌍 グローバル展開の簡素化

単一のグローバルエンドポイントで世界中のユーザーにパーソナライズされたエージェント体験を提供。リージョンごとの個別管理が不要に。

📋 コンプライアンス対応

マルチリージョナルエンドポイント (US/EU) により、データ処理の地理的境界を保証しながら高可用性を実現。

🏢 本番環境対応

GA となったことで SLA が適用され、エンタープライズワークロードでの採用が可能に。

技術面

🔒 高可用性

グローバル/マルチリージョナルエンドポイントは、単一リージョンよりも高い可用性と信頼性を提供。

🔗 統合の柔軟性

ADK、LangChain、LlamaIndex、Agent2Agent など多様なフレームワークとの統合においてエンドポイントの選択肢が増加。

📈 スケーラビリティ

グローバルに分散したエージェントが同一の Memory Bank インスタンスにアクセスでき、セッション間の記憶共有が容易。

⚠️ デメリット・制約事項

❌ グローバルエンドポイントの制限:
  • CMEK (Customer-Managed Encryption Keys) が利用不可
  • データレジデンシーやリージョン内 ML 処理を保証しない
  • 対応 Google エージェントは現時点で Gemini Deep Research Agent (Preview) のみ
⚠️ マルチリージョナルエンドポイントの制限:
  • Private Google Access が非対応。Private Service Connect エンドポイントの構成が必要
💡 推奨事項:
  • データレジデンシー要件が厳格 → リージョナル/マルチリージョナルエンドポイントを選択
  • CMEK が必須要件 → リージョナル/マルチリージョナルエンドポイントを使用

🎯 ユースケース

🌐 ユースケース 1: グローバルカスタマーサポートエージェント

世界中の顧客にサービスを提供する企業が、顧客の過去の問い合わせ履歴や製品選好を記憶するカスタマーサポートエージェントをデプロイ。

効果: リージョンごとに Memory Bank インスタンスを管理する必要がなくなり、運用コストを削減しながら一貫した顧客体験を提供。

🇪🇺 ユースケース 2: EU データ保護規制準拠のエージェント

EU 内のユーザーデータを EU 内で処理する必要がある GDPR 準拠のエージェントを構築。location="eu" で初期化。

効果: 単一リージョンに比べて高い可用性を実現しながら、EU 内でのデータ処理要件を満たすことが可能。

🔬 ユースケース 3: Deep Research Agent との統合

Gemini Deep Research Agent をグローバルエンドポイントで利用し、リサーチ結果をセッション間で記憶として蓄積。

効果: 複数の調査セッションにわたって知見を蓄積し、過去のリサーチ結果を踏まえた深い調査を継続的に実行。
