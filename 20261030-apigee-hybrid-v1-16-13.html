📋 概要

2026 年 10 月 30 日、Apigee hybrid ソフトウェアの更新バージョン v1.16.13 がリリースされました。パッチリリースのため、コンテナイメージは Helm チャートに統合されており、Helm チャートのアップグレードだけでイメージも自動更新されます。

最重要の修正は、エグレスに HTTP フォワードプロキシを必須とするクラスタで apigee-connect-agent が HTTPS_PROXY を無視し、コントロールプレーンへの tether (接続) を確立できなくなるリグレッション (既知の問題 578314600) の解消です。影響バージョンでは管理プレーン操作が no connections available from the Apigee connect agent(s) エラーで失敗します。

さらに、侵害された emSign ルート証明書のトラストストアからの削除、x-envoy-decorator-operation ヘッダーの上流転送の修正、VerifyAPIKey / VerifyAccessToken ポリシーにおける apiproduct.operation.llmTokenQuota.* フロー変数の修正、多数の CVE 対応が含まれています。

❌ Before (v1.16.12 以前の影響バージョン)

  • overrides.yaml で httpProxy を設定しても apigee-connect-agent が HTTPS_PROXY を無視し直接接続 → フォワードプロキシ必須環境で接続タイムアウト、管理プレーン操作が失敗 (578314600)
  • 侵害された emSign ルート証明書とクロス署名用 Comodo AAA Services ルートがトラストストアに残存 (576707253)
  • apigee-ingressgateway が Envoy 内部ヘッダー x-envoy-decorator-operation を上流にそのまま転送 (573622417)
  • VerifyAPIKey / VerifyAccessToken がマッチしていない LLM オペレーションからも apiproduct.operation.llmTokenQuota.* を設定し、意図しない値が参照されるおそれ (492041991)
  • apigee-asm-ingress や apigee-envoy などに多数の未修正 CVE が存在

✅ After (v1.16.13)

  • apigee-connect-agent が HTTPS_PROXY (プロキシ認証情報を含む) を尊重し、HTTP/2 keepalive ping を使用。フォワードプロキシ経由でも tether を確立可能に
  • 侵害された emSign ルートとクロス署名 Comodo AAA Services ルートをトラストストアから削除し、サプライチェーンリスクを低減
  • x-envoy-decorator-operation ヘッダーを上流に転送せず、内部実装情報の漏えいを防止
  • apiproduct.operation.llmTokenQuota.* はリクエストにマッチした LLM オペレーションからのみ設定
  • 多数のコンテナで CVE を修正し、セキュリティ態勢を改善

🛠️ 設定方法 (アップグレード手順)

💡 前提条件:
  • Apigee hybrid v1.16.x (または v1.16 へのアップグレード要件を満たす旧バージョン) が稼働していること
  • アップグレード前に Helm チャートディレクトリと Cassandra データベースのバックアップを取得していること

ステップ 1: v1.16.13 の Helm チャートを取得

Bash Helm チャートの取得 
export CHART_REPO=oci://us-docker.pkg.dev/apigee-release/apigee-hybrid-helm-charts
export CHART_VERSION=1.16.13

helm pull $CHART_REPO/apigee-operator --version $CHART_VERSION --untar
helm pull $CHART_REPO/apigee-datastore --version $CHART_VERSION --untar
helm pull $CHART_REPO/apigee-env --version $CHART_VERSION --untar
helm pull $CHART_REPO/apigee-ingress-manager --version $CHART_VERSION --untar
helm pull $CHART_REPO/apigee-org --version $CHART_VERSION --untar
helm pull $CHART_REPO/apigee-redis --version $CHART_VERSION --untar
helm pull $CHART_REPO/apigee-telemetry --version $CHART_VERSION --untar
helm pull $CHART_REPO/apigee-virtualhost --version $CHART_VERSION --untar

Google Artifact Registry から v1.16.13 の Helm チャート一式を取得します。パッチリリースのため、コンテナイメージはチャートに統合されており手動でのイメージ指定は不要です。

⚖️ メリット・制約事項

💼 ビジネス面のメリット

✓サービス継続性の確保: フォワードプロキシ必須のエンタープライズ環境で管理プレーン操作 (プロキシのデプロイなど) が失敗する重大な問題が解消され、運用停止リスクが低減
✓コンプライアンス / セキュリティ態勢の改善: 侵害された CA ルートの削除と多数の CVE 修正により、脆弱性管理・監査対応の負担が軽減

🔧 技術面のメリット

✓プロキシ環境での確実な tether 確立: HTTPS_PROXY (認証情報付きプロキシを含む) が正しく機能し、HTTP/2 keepalive ping により接続の健全性も維持
✓情報漏えいの防止: Envoy 内部ヘッダーがバックエンドに転送されなくなり、内部実装の露出を防止
✓LLM トークンクォータの正確性向上: AI/LLM API プロダクトのクォータ制御がオペレーション単位で正確に機能
✓適用の容易さ: Helm チャートのアップグレードのみでパッチを適用可能

⚠️ 制限事項・考慮すべき点

  • v1.16.12 は使用禁止。すでに適用済みの場合は速やかに v1.16.13 へアップグレードが必要
  • 既知の問題 578314600 は v1.16 系だけでなく hybrid 1.14.9、1.15.8、1.15.9、1.17.1、1.17.2 にも影響。これらのバージョンでフォワードプロキシを使用している場合も対処が必要 (v1.17 系は v1.17.3 へ)
  • アップグレード前に Helm チャートディレクトリと Cassandra のバックアップ取得を推奨
  • 各 Helm コマンド実行前に --dry-run=server での検証を推奨
  • v1.17 系への移行を計画している場合は、同じ修正を含む v1.17.3 (2026-10-29 リリース) を使用

🎯 ユースケース

🏦 ユースケース 1: フォワードプロキシ必須の規制産業環境での復旧

シナリオ: 金融機関などで、Kubernetes クラスタからのアウトバウンド通信がすべて HTTP フォワードプロキシ経由に制限されている。影響バージョン (例: 1.16.11 や 1.16.12) で apigee-connect-agent が tether を確立できず、API プロキシのデプロイなど管理プレーン操作が no connections available from the Apigee connect agent(s) で失敗している。

YAML overrides.yaml (フォワードプロキシ設定の例) 
# overrides.yaml (フォワードプロキシ設定の例)
httpProxy:
  scheme: HTTP
  host: 10.12.0.47
  port: 3128

効果: v1.16.13 の Helm チャートでアップグレードすることで、apigee-connect-agent が HTTPS_PROXY を尊重してプロキシ経由で tether を確立。管理プレーン操作が正常化し、プロキシ認証情報を使用する構成にも対応。

🤖 ユースケース 2: LLM API プロダクトのトークンクォータ制御の正常化

シナリオ: Apigee hybrid 上で LLM API を API プロダクトとして公開し、オペレーションごとに LLM トークンクォータを設定している。VerifyAPIKey / VerifyAccessToken の評価時に、リクエストにマッチしていないオペレーションの apiproduct.operation.llmTokenQuota.* 値が設定され、意図しないクォータ値が後続のフローで参照されるおそれがあった。

効果: v1.16.13 では、リクエストに実際にマッチした LLM オペレーションからのみフロー変数が設定されるため、オペレーション単位のトークンクォータ制御が設計どおりに機能する。

🔍 ユースケース 3: 定期的な脆弱性対応としてのパッチ適用

シナリオ: セキュリティチームのコンテナイメージスキャンで、apigee-asm-ingress や apigee-envoy などの Apigee hybrid コンポーネントに多数の CVE が検出され、SLA 内での修正が求められている。

効果: v1.16.13 への Helm チャートアップグレードのみで、対象コンポーネントの CVE 修正済みイメージが自動適用され、侵害された CA ルートの削除も同時に反映。脆弱性スキャンの指摘事項を一括で解消できる。
