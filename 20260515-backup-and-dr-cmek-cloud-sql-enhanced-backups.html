🔐 Cloud SQL Enhanced Backups CMEK サポート

Backup and DR Service GA
2026-05-15

📋 概要

Backup and DR Service が Cloud SQL の Enhanced Backups において、顧客管理暗号鍵 (CMEK) のサポートを開始しました。バックアップデータをソースインスタンスと同じ Cloud KMS 鍵で保護できるようになり、暗号化の一貫性が確保されます。

本機能の最大の特徴は、IAM 権限の「分離 (decoupled)」設計です。CMEK の暗号化・復号化権限は Backup and DR Service のサービスエージェントに紐付けられ、Cloud SQL のサービスアカウントとは独立して管理されます。

💡 対象ユーザー: 金融機関、医療機関、政府機関など、データの暗号化に対して厳格な管理を求められる組織。Enhanced Backups の高度な機能 (最大 10 年保持、強制保持期間、柔軟なスケジューリング) を CMEK と組み合わせて利用可能に。

⚡ 主要機能

🔑 同一 KMS 鍵による暗号化

Cloud SQL インスタンスで使用されている CMEK と同じ鍵でバックアップデータを保護。鍵の無効化・破棄でバックアップへのアクセスも同時に制御。

🛡️ 分離された IAM 権限

Backup and DR Service のサービスエージェントに KMS 権限を付与。Cloud SQL のサービスアカウントとは独立した権限管理で最小権限の原則を実現。

📅 Enhanced Backups 全機能との統合

最大 10 年間の保持期間、時間/日/週/月/年単位のスケジューリング、プロジェクト削除後のバックアップ維持、強制保持期間による不変性保証。

⚙️ 設定方法

前提条件

1. Cloud SQL インスタンスが CMEK で暗号化されていること
2. Cloud KMS に対象の鍵が作成済みであること
3. Backup and DR Service API が有効化されていること
4. 適切な IAM 権限 (backupdr.admin または同等) を持つユーザーであること

Step 1: サービスエージェントに KMS 権限を付与

Bash 
# Backup and DR サービスエージェントに CryptoKey Encrypter/Decrypter ロールを付与
gcloud kms keys add-iam-policy-binding KEY_NAME \
  --location=KMS_LOCATION \
  --keyring=KEY_RING \
  --member=serviceAccount:service-VAULT_PROJECT_NUMBER@gcp-sa-backupdr.iam.gserviceaccount.com \
  --role=roles/cloudkms.cryptoKeyEncrypterDecrypter

Step 2: CMEK 対応の Backup Vault を作成

Bash 
# CMEK を有効化した Backup Vault の作成 (作成時のみ設定可能)
gcloud backup-dr backup-vaults create VAULT_NAME \
  --location=LOCATION \
  --backup-min-enforced-retention=RETENTION_PERIOD \
  --encryption-key=projects/PROJECT_ID/locations/LOCATION/keyRings/KEY_RING/cryptoKeys/KEY_NAME
⚠️ 注意: CMEK は Backup Vault 作成時にのみ設定可能です。既存の Vault に対して後から CMEK を有効化・無効化・変更することはできません。

Step 3: バックアッププランの作成と適用

Bash 
# バックアッププランを作成し、CMEK 対応 Backup Vault を指定
gcloud backup-dr backup-plans create PLAN_NAME \
  --location=LOCATION \
  --backup-vault=VAULT_NAME \
  --resource-type=cloudsql.googleapis.com/Instance

✅ メリット

ビジネス面

📜 コンプライアンス要件の充足 - HIPAA、PCI DSS、GDPR など厳格な規制に対応。バックアップ含む統一的な暗号化ポリシーを証明可能。
🌍 データ主権の確保 - 暗号鍵のライフサイクルを完全に制御。鍵を無効化すればバックアップへのアクセスも即座に遮断。
📦 長期保持とセキュリティの両立 - 最大 10 年間の保持と CMEK を組み合わせ、長期アーカイブ要件とセキュリティ要件を同時に充足。

技術面

🔗 暗号化の一貫性 - ソースとバックアップで同一 KMS 鍵を使用し、鍵管理を簡素化。
🛡️ 権限分離によるセキュリティ強化 - 最小権限の原則を実現。Cloud SQL 運用担当者がバックアップ暗号鍵に直接アクセス不要。
🔄 鍵ローテーションの自動対応 - Cloud KMS の自動鍵ローテーション機能と連携し、新バックアップは最新鍵バージョンで暗号化。

⚠️ デメリット・制約事項

制限事項:
  • CMEK は Backup Vault 作成時のみ設定可能。後からの有効化・無効化・変更は不可
  • KMS 鍵は Backup Vault と同一リージョンに存在する必要がある
  • Enhanced Backups 使用インスタンスではディザスタリカバリ (DR) レプリカの作成不可
  • KMS 鍵が無効化・破棄された場合、バックアップからのリストアが不可能に
考慮すべき点:
  • KMS 鍵の可用性がリストア可否に直接影響 - 鍵管理ポリシーを慎重に設計
  • 既存の非 CMEK Vault は新規 Vault 作成とプラン再構成が必要
  • Cloud KMS の追加コスト (鍵バージョンあたり月額 $0.06~) が発生
  • 組織全体で統一的な鍵管理ポリシーの事前策定を推奨

💡 ユースケース

🏦 金融機関におけるデータベースバックアップの暗号化統制

シナリオ: PCI DSS 要件に基づき、全データ (バックアップ含む) を顧客管理鍵で暗号化。監査のためバックアップを 7 年間保持する規制要件あり。

Bash 
# 7 年間の強制保持期間を持つ CMEK 対応 Backup Vault を作成
gcloud backup-dr backup-vaults create finance-vault \
  --location=asia-northeast1 \
  --backup-min-enforced-retention=2555d \
  --encryption-key=projects/my-project/locations/asia-northeast1/keyRings/finance-ring/cryptoKeys/finance-key

効果: PCI DSS のデータ暗号化要件と長期保持要件を同時に充足。鍵の監査ログにより暗号鍵の使用履歴を完全にトレース可能。

👥 マルチチーム環境での権限分離

シナリオ: 大規模組織で、データベース運用チーム、セキュリティチーム、バックアップ管理チームが分離されている環境。

効果: Backup and DR サービスエージェントへの KMS 権限分離により、DB 運用チームは KMS 鍵へのアクセスなしに日常運用が可能。セキュリティチームは KMS 鍵管理に集中し、バックアップ管理チームはプラン運用に注力できる。

💰 料金情報

Enhanced Backups の料金は Backup and DR Service の料金体系に基づきます。CMEK 使用時は追加で Cloud KMS 料金が発生します。

項目 月額料金 (概算)
Cloud KMS ソフトウェア鍵 (1 鍵バージョン) $0.06
Cloud KMS HSM 鍵 (1 鍵バージョン) $1.00 ~ $2.50
Cloud KMS 暗号化オペレーション (10,000 回) $0.03
Backup and DR ストレージ Backup and DR 料金表に準拠

🌐 利用可能リージョン

Cloud KMS 鍵と Backup Vault が同一リージョン (またはマルチリージョン) に存在する必要があります。Cloud SQL インスタンスがサポートされているすべてのリージョンで利用可能ですが、Backup Vault のサポート対象ロケーションとワークロードロケーション互換性を確認してください。

💡 ポイント: マルチリージョン Vault の場合は同一マルチリージョンの KMS 鍵が必要です。

🔗 関連サービス・機能

🔑 Cloud KMS - 暗号鍵のライフサイクル管理。CMEK 鍵の作成、ローテーション、無効化、破棄を制御。
🗄️ Cloud SQL - CMEK で暗号化されたデータベースインスタンスのソースワークロード。
💾 Backup and DR Service - バックアップ一元管理、Backup Vault による不変性保証、強制保持期間の提供。
🤖 Cloud KMS Autokey - CMEK 鍵の自動プロビジョニングと割り当てを簡素化 (HSM 保護レベル)。
👤 IAM - サービスエージェントへの権限付与と分離を実現。

📝 まとめ

今回の CMEK サポートにより、Cloud SQL Enhanced Backups は企業レベルのセキュリティ要件を完全に満たすバックアップソリューションとなりました。分離された IAM 権限設計により、最小権限の原則に基づいたセキュアな運用が可能です。

推奨アクション: CMEK による暗号化制御が必要な組織は、新規 CMEK 対応 Backup Vault の作成とバックアッププランの構成を検討してください。
