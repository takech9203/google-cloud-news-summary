💰 Compute flexible CUD が G2 / G4 GPU マシンシリーズで GA

支出ベースの柔軟なコミットメント割引が NVIDIA L4 (G2) / RTX PRO 6000 (G4) の GPU にも適用可能に

📋 概要

Compute flexible committed use discounts (CUDs) が、 G2 / G4 GPU アクセラレータ最適化マシンシリーズで一般提供 (GA) になりました。 対象リソースは vCPU・メモリ・ローカル SSD・GPU で、 Compute Engine、GKE、Cloud Run にまたがる対象支出に適用される支出ベース (spend-based) の CUD です。

GPU 容量の確保が難しい状況でも、対象マシンシリーズ (G2 ⇔ G4) やリージョンをワークロードの必要に応じて切り替えながら、 同一のコミットメントで割引を受け続けられる点が大きな特徴です。 さらに、これらのマシンシリーズの GPU では予約 (リザベーション) のアタッチが不要です。

❌ Before (アップデート前の課題)

  • Compute flexible CUD は GPU 非対応。対象は vCPU・メモリ・ローカル SSD のみ
  • GPU の CUD 割引はリソースベース CUD のみで、特定のリージョン・マシン構成に紐づくため、容量に応じた移動で割引を活用しきれないリスク
  • Compute Engine / GKE / Cloud Run にまたがる GPU を含む支出を単一の支出ベースコミットメントでカバーできない

✅ After (アップデート後の改善)

  • G2 / G4 の GPU (NVIDIA L4 / RTX PRO 6000) が対象リソースになり、vCPU・メモリ・ローカル SSD と合わせて支出ベース割引を適用
  • GPU 容量が確保できない場合も、別のロケーションや G2 ⇔ G4 の切り替えで同じコミットメントの割引を継続
  • GPU 容量が全く無い場合も vCPU・メモリや GKE・Cloud Run の支出に充当でき、未消化リスクを低減
  • G2 / G4 の GPU では予約のアタッチが不要

Cloud Billing アカウント単位で購入する単一の Compute flexible コミットメントが、 Compute Engine (今回 GA となった G2 / G4 の GPU を含む)、GKE、Cloud Run の対象支出を横断的にカバーします。 G2 / G4 間やリージョン間を移動しても割引が追従します。

⭐ 主要機能

1️⃣ G2 / G4 マシンシリーズの GPU が Compute flexible CUD の対象に (GA)

✓対象リソースは vCPU、メモリ、ローカル SSD ディスク、GPU
✓G2 (NVIDIA L4 GPU) と G4 (NVIDIA RTX PRO 6000 Blackwell Server Edition GPU) が対象
!GPU が対象になるのは G2 / G4 マシンシリーズのみ。他のマシンシリーズは従来どおり vCPU・メモリ・ローカル SSD のみ

2️⃣ ロケーションとマシンタイプの柔軟な切り替え

✓希望するゾーン・リージョンで容量が確保できない場合、別のロケーションにデプロイしても同じコミットメントで割引を適用
✓同一コミットメントを G2 / G4 のどちらにも適用可能。一方の GPU マシンタイプの容量がない場合、もう一方で消化できる
✓GPU 容量が利用できない場合は、vCPU・メモリなどの他の対象リソースや GKE・Cloud Run の対象支出に充当可能

3️⃣ 予約 (リザベーション) のアタッチが不要

✓リソースベースのコミットメントと異なり、予約のアタッチをサポートせず、必要ともしない
!予約アタッチに伴う容量保証は提供されない。G2 / G4 GPU の容量を確保したい場合はスタンドアロン予約を別途作成
✓同一 Cloud Billing アカウントの共有予約から容量を消費する場合も、その使用量に割引が適用される

⚠️ デメリット・制約事項

🚫 制限事項

✗GPU が対象になるのは G2 / G4 マシンシリーズのみ。A シリーズなど他の GPU マシンシリーズの GPU は対象外
✗Compute flexible コミットメントは Cloud Billing アカウント レベルでのみ購入可能
✗Spot VM / プリエンプティブル VM には適用されない
✗予約アタッチによる容量保証はない。容量を確実に確保するにはスタンドアロン予約が別途必要
✗購入後のキャンセルは不可。実際の使用量にかかわらず期間中は毎時のコミットメントフィーを支払う

🤔 考慮すべき点

⚠️ 割引の適用順序: 割引は排他的に適用され、同一リソースにリソースベース CUD と Compute flexible CUD を重複適用できません。リソースベース CUD → Compute flexible CUD → オンデマンド (SUD 適用可) の順で消化されます。
  • G2 / G4 の割引率 (1 年: 21% / 16%、3 年: 43% / 42%) は汎用マシンシリーズ (28% / 46%) と異なるため、コミットメント額の設計時に考慮が必要
  • 毎時のコミットメントフィーを超えた使用分 (オーバーエージ) はオンデマンド料金で課金され、未消化分の繰り越しはない
  • 安定して特定リージョン・特定構成で稼働するワークロードには、割引率の高いリソースベース CUD (最大 55〜70%) の方が有利な場合がある

🎯 ユースケース

💡 ユースケース 1: GPU 容量の変動に強い推論基盤のコスト最適化

シナリオ: NVIDIA L4 (G2) で推論サービスを運用しているが、リージョンによっては GPU 容量が逼迫することがあり、リージョン固定のリソースベース CUD では割引を活用しきれないリスクがある。

効果: Compute flexible コミットメントの購入で、容量状況に応じて別リージョンや G4 インスタンスに切り替えても割引が継続。GPU が確保できない時間帯も、同じコミットメントを vCPU・メモリや GKE・Cloud Run の支出に充当でき、コミットメントの消化率を最大化できる。

💡 ユースケース 2: Compute Engine / GKE / Cloud Run 混在環境の一括コミットメント

シナリオ: G4 インスタンスでのモデルチューニング、GKE 上のバッチ処理、Cloud Run のアプリケーションが混在しており、サービスごとに支出が変動する。

効果: Cloud Billing アカウント単位の単一の Compute flexible コミットメントで、G4 の GPU を含む Compute Engine の支出と GKE・Cloud Run の対象支出を横断的にカバー。サービス間で支出の比率が変わっても割引が適用され続ける。

💵 料金

Compute flexible CUD は、1 年または 3 年の期間にわたり時間あたりの最低支出額を確約する支出ベースの割引です。 コミットメントフィーは実際の使用量にかかわらず期間中毎時支払い、対象リソース・サービスには割引後の価格が直接適用されます。 毎時の対象支出がコミットメントフィーに達するまで割引価格で消化され、超過分はオンデマンド料金で課金されます。
