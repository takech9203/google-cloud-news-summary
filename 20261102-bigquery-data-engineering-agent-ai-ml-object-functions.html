📊 BigQuery: Data Engineering Agent が
AI・ML・オブジェクト関数の生成に対応

BigQuery 🤖 Data Engineering Agent ✅ GA (一般提供) 📅 リリース日: 2026-11-02

💡 概要

BigQuery / Dataform の Data Engineering Agent が、生成する Dataform SQLX パイプラインおよびエージェント指示ファイルにおいて、BigQuery の AI 関数・ML 関数・オブジェクト関数をサポートするようになりました (GA)。

Data Engineering Agent は、自然言語プロンプトから BigQuery のデータパイプラインを構築・修正・トラブルシューティングできる Gemini ベースのエージェントです。今回のアップデートにより、AI.GENERATE_TEXT などの生成 AI 関数、ML.GENERATE_TEXT / ML.PREDICT といった BigQuery ML 関数、OBJ.MAKE_REF などの ObjectRef 関数を含むパイプラインを、自然言語指示だけで生成できます。

🎯 対象ユーザー: BigQuery 上で ELT パイプラインを構築するデータエンジニアや、非構造化データ (画像・音声・ドキュメント) を含むマルチモーダル処理を SQL パイプラインに組み込みたいチーム。生成 AI による要約・分類・埋め込み生成を、手書きの SQLX を介さずにパイプラインへ統合できます。

❌ Before: アップデート前の課題

  • エージェントが生成する SQLX は通常の SQL 変換が中心で、AI / ML / オブジェクト関数の生成は未サポート
  • 生成 AI 分類・ML 推論を組み込むには、生成された SQLX を手動編集して AI/ML 関数を追記する必要があった
  • 指示ファイル (GEMINI.md) に AI/ML 関数のルールを書いても、エージェントが対応していなかった

✅ After: アップデート後の改善

  • 自然言語プロンプトから AI.GENERATE_TEXT・ML.PREDICT・OBJ.MAKE_REF などを含む SQLX パイプラインを自動生成
  • 指示ファイルに AI/ML/オブジェクト関数の利用ルールを定義し、組織全体で一貫した AI 対応パイプラインを生成
  • 非構造化データを扱うマルチモーダルパイプラインの構築がエージェントとの対話のみで完結

自然言語プロンプトとエージェント指示ファイルをもとに、Data Engineering Agent が AI・ML・オブジェクト関数を含む Dataform SQLX パイプラインを生成し、BigQuery 上で Vertex AI のモデル呼び出しや Cloud Storage の非構造化データ処理を実行する流れ

⚙️ 主要機能

1️⃣ ✨ AI 関数を含む SQLX パイプラインの生成

AI.GENERATE_TEXT などの BigQuery 生成 AI 関数を含むパイプラインコードを自然言語プロンプトから生成。テキスト分類、感情分析、要約、画像キャプション生成、音声の文字起こしをパイプラインに組み込めます。

2️⃣ 🧠 ML 関数・ステートメントのサポート

ML.GENERATE_TEXT や ML.PREDICT などの BigQuery ML 関数、リモートモデルを参照するステートメントを含むコードを生成可能。Vertex AI 上の Gemini モデル・パートナーモデル・オープンモデルを使った推論処理をパイプライン化できます。

3️⃣ 🖼️ オブジェクト関数による非構造化データ処理

OBJ.MAKE_REF などの ObjectRef 関数やオブジェクトテーブルで、Cloud Storage 上の画像・音声・ドキュメントを参照するパイプラインを生成。構造化データと非構造化データを組み合わせたマルチモーダル変換を実現します。

4️⃣ 📝 エージェント指示ファイルでの利用

GEMINI.md 形式の指示ファイル内で AI/ML/オブジェクト関数のルール (使用モデル、出力形式、命名規則など) を定義可能。組織のスタイルガイドと同様に AI 関数の利用ポリシーを一元管理し、生成パイプラインの一貫性を確保できます。

🛠️ 設定方法

✅ 前提条件

✓プロジェクトで Gemini in BigQuery が有効化されていること
✓Gemini Data Analytics API (geminidataanalytics.googleapis.com)、Gemini for Google Cloud API (cloudaicompanion.googleapis.com)、BigQuery API (bigquery.googleapis.com) が有効であること
✓IAM ロール: Dataform Code Editor (roles/dataform.codeEditor)、BigQuery Job User (roles/bigquery.jobUser)、Gemini Data Analytics Stateless Chat User (roles/geminidataanalytics.dataAgentStatelessUser)
✓AI/ML 関数の実行には、Vertex AI エンドポイントを参照する BigQuery ML リモートモデルと BigQuery 接続 (Connection) が必要
1

必要な API を有効化する

Bash 
gcloud services enable geminidataanalytics.googleapis.com --project=PROJECT_ID
gcloud services enable cloudaicompanion.googleapis.com --project=PROJECT_ID
gcloud services enable bigquery.googleapis.com --project=PROJECT_ID

Data Engineering Agent の利用に必要な API を有効化します。

2

エージェントに AI 関数を含むパイプラインを依頼する

BigQuery コンソールのパイプライン UI または Dataform ワークスペースで「Ask Agent」をクリックし、自然言語で依頼します。

Text 
raw.customer_reviews テーブルのレビュー本文を AI.GENERATE_TEXT で
ポジティブ / ネガティブに分類し、結果を reporting.review_sentiment
テーブルに格納するパイプラインを作成してください。

エージェントが AI 関数を含む SQLX ファイルの草案を生成するので、各パイプラインノードの SQLX を確認し、「Apply」で適用します。

3

エージェント指示ファイルにルールを定義する (任意)

「Ask agent」配下の「Pipeline instructions」から GEMINI.md を作成し、AI/ML 関数の利用ルールを記述します。

Markdown 
## AI 関数の利用ルール
- テキスト分類には AI.GENERATE_TEXT を使用し、リモートモデルは
  `mydataset.gemini_model` を参照すること
- 非構造化データは ObjectRef 列を介して参照すること

組織共通のルールは外部の Dataform リポジトリに格納し、複数パイプラインから参照することもできます。

🚀 メリット

💼 ビジネス面

✓AI パイプライン開発の民主化: 生成 AI・ML を組み込んだパイプラインを自然言語だけで構築でき、専門知識の少ないメンバーでも AI 活用を推進できる
✓開発リードタイムの短縮: AI/ML 関数の構文やリモートモデル参照の記述をエージェントに任せられ、手動コーディングと検証の工数を削減
✓ガバナンスの強化: 指示ファイルで AI 関数の利用ポリシーを一元管理し、組織全体で一貫した品質のパイプラインを生成

⚡ 技術面

✓マルチモーダルデータ処理の統合: オブジェクト関数により、Cloud Storage 上の画像・音声・ドキュメントを構造化データと同じ SQLX パイプラインで処理
✓コード検証の自動化: 生成コードのコンパイルエラーを自動で検証・修正するため、AI 関数を含む複雑な SQLX でも動作するパイプラインが得られる
✓Dataform ネイティブな管理: 生成コードは Dataform リポジトリで Git 管理され、レビュー・バージョン管理など通常の開発フローを適用可能

⚠️ デメリット・制約事項

🚧 制限事項

✗Data Engineering Agent はパイプラインを実行できない (レビュー・実行・スケジュール設定はユーザーが行う)
✗ノートブックおよびデータ準備 (Data preparation) ファイルに対する自然言語コマンドは未サポート
✗エージェントはプロンプトや指示ファイル内の Web リンク・URL を検索できない
✗Lakehouse ランタイムカタログ管理の Apache Iceberg テーブルに対しては、書き込み系ステートメント (INSERT、UPDATE、MERGE など) や DDL を生成できない
💭 考慮すべき点
  • AI 関数の実行には Vertex AI のリモートモデル呼び出しが発生するため、BigQuery のコンピューティング料金に加えて Vertex AI (Gemini など) の推論料金を考慮する必要がある
  • エージェントによるデータサンプリング・プロファイリングは BigQuery リソースを使用し、BigQuery の料金が適用される
  • 生成 AI 技術の一般的な制限が適用されるため、生成された SQLX (特に AI 関数のプロンプト部分) は必ずレビューしてから適用・実行する

🎯 ユースケース

📈 ユースケース 1: カスタマーレビューの感情分析パイプライン

シナリオ: EC サイトのレビューデータを日次で取り込み、生成 AI で感情分類した結果をダッシュボード用テーブルに格納したい。

プロンプト例 
「raw.customer_reviews のレビュー本文を AI.GENERATE_TEXT で
 'positive' / 'negative' / 'neutral' に分類し、
 reporting.review_sentiment テーブルを作成してください。
 リモートモデルは mydataset.gemini_model を使用してください。」

効果: AI 関数の構文を覚えることなく感情分析パイプラインを構築でき、Dataform のスケジュール実行で日次の自動分類が実現。

📄 ユースケース 2: 非構造化ドキュメントのメタデータ抽出

シナリオ: Cloud Storage に蓄積された商品画像や PDF ドキュメントから、説明文やカテゴリ情報を抽出して BigQuery の商品マスタに付与したい。

効果: ObjectRef 関数とオブジェクトテーブルを使ったマルチモーダル処理をエージェントが SQLX として生成するため、非構造化データの ETL を手書きコードなしで整備できる。

🏢 ユースケース 3: 組織標準の AI パイプラインルールの適用

シナリオ: 複数チームが Data Engineering Agent を利用しており、使用するリモートモデルや出力テーブルの命名規則を統一したい。

効果: 中央の Dataform リポジトリにエージェント指示ファイル (GEMINI.md) を配置して各ワークスペースから参照することで、AI/ML 関数の利用ルールを組織全体で統一できる。

🔗 関連サービス・機能

→Dataform: エージェントが生成する SQLX パイプラインの管理基盤。リポジトリ・ワークスペースでのバージョン管理とスケジュール実行を提供
→BigQuery ML: CREATE MODEL によるリモートモデル定義と ML.PREDICT / ML.GENERATE_TEXT などの推論関数を提供
→Vertex AI: AI 関数・ML 関数が参照する Gemini モデルやパートナーモデルのホスティング基盤
→Cloud Storage / オブジェクトテーブル: ObjectRef 関数で参照する非構造化データの格納先
→Knowledge Catalog (Dataplex): エージェントがテーブル解決やメタデータ付与に利用するカタログ。生成パイプラインのメタデータを自動同期
→Gemini in BigQuery: Data Engineering Agent を含む BigQuery の AI 支援機能群

📝 まとめ

Data Engineering Agent が AI・ML・オブジェクト関数の生成に GA 対応したことで、生成 AI を組み込んだマルチモーダルなデータパイプラインを自然言語だけで構築できるようになりました。BigQuery 上で生成 AI 活用を進めるチームは、まずレビュー分類やドキュメント要約などの小規模なパイプラインで試し、エージェント指示ファイルによる組織標準ルールの整備を進めることを推奨します。
