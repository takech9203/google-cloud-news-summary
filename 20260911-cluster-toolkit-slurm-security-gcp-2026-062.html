📋 概要

Google は、Cluster Toolkit に影響する Slurm の複数のセキュリティ脆弱性に対応し、 セキュリティ情報 GCP-2026-062 として公開しました。 特定のイメージバージョンを参照するブループリントに影響し、Slurm の slurmstepd デーモン、 RPC リクエスト処理、アカウンティングデータベースに関連する問題が含まれます。重要度は High です。

対処方法として Cluster Toolkit v1.103.0 以降へのアップグレードが提供され、 Slurm が 25.11.8 に更新されるとともに、ブループリント内の固定 (ピン留め) イメージ参照が更新されています。

⚠️ 重要: 稼働中のクラスタへの再デプロイだけでは実行中の VM は更新されません。 パッチ適用には VM またはクラスタの破棄と再作成が必要です。

🔄 Before / After

❌ アップデート前の課題

  • 旧イメージ参照のクラスタは slurmstepd、RPC 処理、アカウンティング DB に関する複数の脆弱性 (High) の影響を受けていた
  • 旧バージョンのブループリントは脆弱な Slurm イメージへの固定参照を保持
  • 稼働中クラスタへの直接再デプロイでは VM が更新されず、バージョン不整合の恐れ

✅ アップデート後の改善

  • v1.103.0 以降で Slurm 25.11.8 へ更新、固定イメージ参照も更新され 8 件の CVE を解消
  • 更新済みブループリントの新規デプロイは自動的にパッチ適用済みイメージを使用
  • GCP-2026-062 で影響範囲と対処手順 (破棄・再作成) が明確化

⬆️ 1. Slurm 25.11.8 へのアップグレード

  • slurmstepd デーモン、RPC リクエスト処理、アカウンティングデータベースに影響する複数の脆弱性を修正

  • 更新済みブループリントを使用する新規デプロイメントは自動的にパッチ適用済みイメージを使用

📌 前提条件

  • Cluster Toolkit (gcluster) の実行環境が構成されていること
  • 既存クラスタを破棄・再作成できること (ジョブの退避、データのバックアップなどの事前準備)

ステップ 1: Cluster Toolkit を v1.103.0 以降に更新

Bash Cluster Toolkit の更新 
# Cluster Toolkit リポジトリを最新化してビルド
cd cluster-toolkit
git checkout main && git pull
make
./gcluster --version  # v1.103.0 以降であることを確認

v1.103.0 以降に更新すると、ブループリントの固定イメージ参照がパッチ適用済みバージョンになります。

ステップ 2: 既存クラスタの破棄

Bash ノードのドレインとデプロイメント破棄 
# 静的ノードをドレインして電源オフ (Slurm コントローラ上で実行)
scontrol update NodeName=NODES_TO_UPDATE State=POWER_DOWN_ASAP

# 既存デプロイメントを破棄
./gcluster destroy DEPLOYMENT_FOLDER_NAME --auto-approve
🚫 注意: 稼働中のクラスタへの直接再デプロイでは実行中の VM が更新されないため、必ず破棄・再作成を行います。

ステップ 3: 更新済みブループリントで再デプロイ

Bash クラスタの再作成 
# 更新済みブループリントからデプロイメントフォルダを再作成
./gcluster create BLUEPRINT_NAME -w

# 新しいクラスタをデプロイ
./gcluster deploy DEPLOYMENT_FOLDER_NAME
✅ 完了: 新しいデプロイメントは Slurm 25.11.8 を含むパッチ適用済みイメージを自動的に使用します。

⚖️ メリットと制約事項

👍 メリット

  • セキュリティリスクの低減: High の 8 件の CVE に一括対処し、HPC / AI 基盤のコンプライアンス要件を維持
  • 明確な対処手順: セキュリティ情報として影響範囲と手順が公開され、対応計画を立てやすい
  • パッチ適用の自動化: 更新済みブループリントの新規デプロイは自動的にパッチ適用済みイメージを使用
  • バージョン整合性: Slurm 本体とイメージ参照が同時更新され、不整合を防止

⚠️ 制約・考慮点

  • 稼働中クラスタへの再デプロイだけではパッチが適用されない (実行中 VM は更新されない)
  • VM またはクラスタの破棄・再作成が必須で、クラスタの停止時間が発生
  • 破棄前に実行中ジョブの完了または退避が必要
  • ./gcluster destroy は不可逆的な操作。ブループリントやデータ (Filestore など) の保全を事前確認
  • カスタムイメージ使用時は、パッチ適用済みベースイメージでの再ビルドが必要になる可能性

💡 ユースケース

🧪 ユースケース 1: 稼働中の HPC クラスタの計画的なパッチ適用

シナリオ: Slurm ベースの HPC クラスタで研究計算ワークロードを常時実行している組織が、重要度 High の脆弱性に対応する必要がある。

Bash メンテナンスウィンドウでの実施例 
# 1. ジョブの新規受付を停止しドレイン
scontrol update NodeName=ALL State=DRAIN Reason="GCP-2026-062 patching"

# 2. メンテナンスウィンドウでクラスタを破棄・再作成
./gcluster destroy my-hpc-deployment --auto-approve
./gcluster create my-hpc-blueprint.yaml -w
./gcluster deploy my-hpc-deployment

効果: 計画的なメンテナンスウィンドウ内で 8 件の CVE を解消し、Slurm 25.11.8 ベースの安全なクラスタへ移行できる。

🤖 ユースケース 2: 新規 AI トレーニングクラスタの安全なデプロイ

シナリオ: GPU クラスタを Cluster Toolkit で新規構築する予定のチームが、脆弱なイメージバージョンの使用を避けたい。

効果: Cluster Toolkit v1.103.0 以降の更新済みブループリントを使用するだけで、自動的にパッチ適用済みイメージが選択され、脆弱な構成のデプロイを防止できる。

💰 料金と利用可能リージョン

💵 料金: Cluster Toolkit 自体はオープンソースのツールで無料。このセキュリティ修正に伴う追加料金はありません。 ただし、クラスタ再作成時にデプロイされる Compute Engine、Filestore などのリソースには通常の料金が適用されます。 (Compute Engine の料金)
🌏 リージョン: このセキュリティ修正は特定リージョンに限定されず、Cluster Toolkit でデプロイされた すべての Slurm クラスタが対象です。

🎯 まとめ

GCP-2026-062 は、Cluster Toolkit でデプロイされた Slurm クラスタの slurmstepd、RPC 処理、 アカウンティングデータベースに影響する重要度 High の脆弱性 (CVE 8 件) を修正するセキュリティ情報です。 稼働中のクラスタへの再デプロイだけではパッチが適用されないため、Cluster Toolkit v1.103.0 以降の 更新済みブループリントを使用して、速やかに VM またはクラスタの破棄・再作成を計画してください。
