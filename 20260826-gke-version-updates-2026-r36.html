📌 概要

GKE の全リリースチャネル (Rapid, Regular, Stable, Extended, No channel) でクラスタバージョンが更新された。 Rapid チャネルのデフォルトは 1.36.3-gke.1640000 に、Regular / Extended / No channel のデフォルトは 1.35.7-gke.1027000 に更新。 Rapid チャネルには Kubernetes 1.35.8 系の新パッチが初登場し、アルファクラスタ向けに 次期マイナーバージョン 1.37 のアルファ版 3 バージョンが利用可能になった。

あわせてセキュリティアップデート (2026-R36) として、前回リリース以降の累積的なセキュリティ修正を含む Container-Optimized OS イメージ (cos-117 / cos-125 / cos-129) を使用する新しい GKE バージョンがリリースされた。 GKE クラスタを運用するすべてのプラットフォーム管理者・インフラエンジニアに影響する。

❌ アップデート前の課題

  • 前回 (2026-R35) までのバージョンには、直近の Container-Optimized OS セキュリティ修正が含まれていなかった
  • Regular / Extended / No channel のデフォルトは旧パッチ (1.35.6 系) のままで、最新の修正が新規クラスタに標準適用されていなかった
  • Kubernetes 1.37 系を試験できるアルファ版は 1.37.0-gke.1173000+preview のみで、より新しいアルファパッチは提供されていなかった

✅ アップデート後の改善

  • Rapid のデフォルトが 1.36.3-gke.1640000 に更新され、新規クラスタに 1.36 系の新パッチが標準適用
  • Regular / Extended / No channel のデフォルトが 1.35.6-gke.1710000 から 1.35.7-gke.1027000 に引き上げ
  • 1.35.8 系新パッチと 1.37.0 アルファ版 3 バージョンが追加され、次期バージョンの事前検証が可能に
  • 累積セキュリティ修正を含む COS イメージ (cos-117 / cos-125 / cos-129) が適用され、ノード OS の脆弱性リスクを低減

GKE のリリースチャネルは、Rapid で導入されたバージョンが検証を経て Regular、Stable へと段階的に展開されるパイプラインとして機能する。 今回は Regular / Extended / No channel のデフォルトが 1.35.7 系に引き上げられ、Rapid チャネルには Kubernetes 1.37 のアルファ版が登場。 新しい Container-Optimized OS イメージによるセキュリティ修正が各バージョンに組み込まれた。

🔒 セキュリティアップデート (2026-R36)

新しい GKE バージョンでは、更新された Container-Optimized OS イメージが使用される。 これらのイメージは前回の GKE リリース以降のセキュリティ修正を累積的に含む。

GKE バージョン Container-Optimized OS バージョン
1.31.14-gke.2630000💿 cos-117-18613-675-56
1.34.10-gke.1328000💿 cos-125-19216-532-123
1.35.8-gke.1026000💿 cos-125-19216-532-123
1.37.0-gke.2034000+preview💿 cos-129-19506-299-82

解決された個別の脆弱性は、各 Container-Optimized OS イメージのセキュリティリリースノートで確認できる。

⭐ 主要な変更点

1️⃣ Regular / Extended / No channel のデフォルトが 1.35.7-gke.1027000 に更新

前回デフォルトの 1.35.6-gke.1710000 は Regular / Extended で提供終了、No channel では 1.35.6-gke.1641000 が非推奨化。新規クラスタは 1.35.7 系が標準に。

2️⃣ Rapid チャネルのデフォルトが 1.36.3-gke.1640000 に更新、1.35.8 系パッチが初登場

前回デフォルトの 1.36.3-gke.1537000 は Rapid では提供終了 (Regular / Extended では新規追加)。新パッチ 1.34.10-gke.1328000 / 1.35.8-gke.1026000 / 1.35.8-gke.1036000 / 1.36.3-gke.1767000 が追加。

3️⃣ Kubernetes 1.37 アルファ版が Rapid チャネルで利用可能に 🧪

アルファクラスタ向けに 1.37.0-gke.2034000+preview / 1.37.0-gke.2048000+preview / 1.37.0-gke.2074000+preview が追加。旧アルファ版 1.37.0-gke.1173000+preview は提供終了。

4️⃣ Stable チャネルに 1.34.9-gke.1655001 を追加、1.34.9-gke.1322001 が非推奨化

非推奨バージョンは 90 日後、またはサポート終了時のいずれか早い時点で削除される。

5️⃣ Container-Optimized OS のセキュリティ修正を累積適用 🔒

cos-117 (M117) / cos-125 (M125) / cos-129 (M129) の 3 マイルストーンのイメージを更新。1.31 / 1.34 / 1.35 系の新バージョンおよび 1.37 アルファ版にそれぞれ適用。

⚙️ 技術仕様: バージョンロールアウトの注意点

→リリースノート公開時点でロールアウトは進行中であり、全ゾーンへの展開完了まで数日を要する場合がある
→非推奨バージョンは 90 日後、またはサポート終了時のいずれか早い時点で削除される
→Rapid チャネルのバージョンは GKE SLA の対象外
→アルファ版 (1.37.0-gke.xxx+preview) はアルファクラスタ専用であり、本番環境では使用できない
→No channel (リリースチャネル未登録) 構成は非推奨であり、2027 年 6 月 14 日に削除予定

🛠️ 設定方法

✅ 前提条件

✓Google Cloud プロジェクトで GKE API が有効であること
✓gcloud CLI がインストール・認証済みであること
✓クラスタに対する適切な IAM 権限 (container.admin ロールなど) を保持していること

ステップ 1: 現在のクラスタバージョンとチャネルを確認

Bashクラスタ一覧の確認
gcloud container clusters list \
  --format="table(name,location,currentMasterVersion,releaseChannel.channel)"

ステップ 2: 利用可能なバージョンを確認

BashRegular チャネルの有効バージョン確認
gcloud container get-server-config \
  --flatten="channels" \
  --filter="channels.channel=REGULAR" \
  --format="yaml(channels.channel,channels.defaultVersion,channels.validVersions)" \
  --location=asia-northeast1

ステップ 3: 手動アップグレード (必要な場合)

Bashコントロールプレーンとノードプールのアップグレード
# コントロールプレーンのアップグレード
gcloud container clusters upgrade CLUSTER_NAME \
  --master \
  --cluster-version=1.35.7-gke.1027000 \
  --location=LOCATION

# ノードプールのアップグレード
gcloud container clusters upgrade CLUSTER_NAME \
  --node-pool=NODE_POOL_NAME \
  --cluster-version=1.35.7-gke.1027000 \
  --location=LOCATION

⚖️ メリットと制約事項

👍 メリット

  • セキュリティリスクの低減: 累積的なセキュリティ修正を含む COS イメージへの更新で、ノード OS の脆弱性露出時間を短縮
  • 運用コストの削減: 自動アップグレードにより手動でのバージョン管理・パッチ適用作業が不要
  • 最新パッチの標準適用: Regular / Extended / No channel のデフォルトが 1.35.7-gke.1027000 に更新され、新規クラスタに標準適用
  • 次期バージョンの事前検証: Kubernetes 1.37 アルファ版で互換性検証を早期に開始可能
  • 累積的なセキュリティ修正: 途中のパッチをスキップしても最新のセキュリティ状態に到達可能

⚠️ 制約事項・考慮点

  • ロールアウトは段階的で、一部ゾーンでは新バージョンが未提供の場合がある
  • コントロールプレーンのマイナーバージョンのスキップアップグレードは不可 (1 バージョンずつ順次)
  • Extended チャネルの拡張サポート期間中はセキュリティパッチのみ (新機能追加なし)
  • 1.37 アルファ版はアルファクラスタ専用で SLA 対象外・本番利用不可
  • Stable の 1.34.9-gke.1322001 使用中の場合、90 日以内の削除に備え移行計画を早期に策定
  • Extended では 1.31.14 / 1.32.13 / 1.33.13 系の旧パッチ 5 バージョンが一斉に非推奨化
  • Rapid の 1.35 系は 1.36.3-gke.1640000 への自動アップグレード対象 — 1.36 の非推奨 API 対応を事前確認
  • Extended の 1.30 系 → 1.31.14-gke.2543000、1.31 系 → 1.32.13-gke.2231000 が自動アップグレード対象
  • バージョンスキューポリシー (コントロールプレーンとノードの差は最大 2 マイナーバージョン) に注意

🎯 ユースケース

🔒 ユースケース 1: セキュリティ修正の迅速な適用

シナリオ: セキュリティポリシーにより、ノード OS の脆弱性修正を速やかに適用する必要があるプロダクションクラスタを運用している。

BashCOS 更新済みバージョンへの手動アップグレード
# 該当ノードプールを COS 更新済みバージョンへ手動アップグレード
gcloud container clusters upgrade my-prod-cluster \
  --node-pool=default-pool \
  --cluster-version=1.34.10-gke.1328000 \
  --location=asia-northeast1

効果: cos-125-19216-532-123 の累積セキュリティ修正が適用されたノードイメージに更新され、脆弱性の露出時間を最小化できる。

🧪 ユースケース 2: Kubernetes 1.37 の事前検証

シナリオ: 次期マイナーバージョン 1.37 で自社ワークロードの互換性を早期に確認したい。

Bashアルファクラスタでの 1.37 アルファ版検証
# Rapid チャネルでアルファクラスタを作成し 1.37 アルファ版を検証
gcloud container clusters create test-137-cluster \
  --enable-kubernetes-alpha \
  --release-channel=rapid \
  --cluster-version=1.37.0-gke.2074000 \
  --location=us-central1 \
  --no-enable-autorepair \
  --no-enable-autoupgrade

効果: 1.37 系が一般提供される前に非推奨 API や挙動変更の影響を検証でき、本番環境のアップグレード計画を前倒しで策定できる。

📅 ユースケース 3: 非推奨バージョンからの計画的移行

シナリオ: Stable チャネルで 1.34.9-gke.1322001 を使用しており、90 日以内の削除に備えて移行が必要。

BashStable チャネル後継パッチへのアップグレード
# Stable チャネルの後継パッチへアップグレード
gcloud container clusters upgrade my-cluster \
  --master \
  --cluster-version=1.34.9-gke.1655001 \
  --location=us-central1

効果: 削除期限前に計画的にアップグレードすることで、強制アップグレードによる予期しない業務影響を回避できる。
