Gemini Enterprise GA (一般提供)

🚪 Antigravity Enterprise Gateway サポート

Antigravity のモデル推論トラフィックを組織運用のゲートウェイ経由でルーティング
📅 リリース日: 2026-10-20

📝 概要

Antigravity Enterprise Gateway が一般提供 (GA) になりました。Antigravity アプリ / CLI / IDE 拡張からのモデル推論リクエストを、組織が運用する一元的なエンタープライズゲートウェイ経由で Google Cloud に転送できます。開発者のワークステーションは Google に直接接続せず、ゲートウェイと通信するため、組織はモデルトラフィックの検査・監査、カスタムセキュリティポリシーやネットワーク Egress ポリシーの適用が可能になります。

開発者は個々の Google アカウントサインインを行わず、ゲートウェイが発行する API キーで認証します。ゲートウェイは一元管理された Google Cloud サービスアカウントでリクエストを Gemini Enterprise Agent Platform に転送し、課金は PAYG (従量課金) ベースで行われます (シートベースのサブスクリプションクォータは消費しません)。

🎯 対象ユーザー: 規制業界などで厳格なネットワーク制御を運用しており、開発者ワークステーションからの直接のインターネット接続や対話型のブラウザベース Google サインインを許可できない組織の管理者・セキュリティアーキテクト

❌ Before (アップデート前の課題)

  • 開発者ごとの対話型 Google アカウントサインイン (ブラウザベース) が必要で、外部直接接続やブラウザサインインを禁止する厳格なネットワーク環境では利用が困難
  • モデル推論トラフィックがワークステーションから Google に直接送信され、組織が自前のゲートウェイで検査・監査したり、独自のセキュリティ / Egress ポリシーを適用したりできなかった

✅ After (アップデート後の改善)

  • Antigravity アプリ / CLI / IDE 拡張の推論リクエストを組織運用のエンタープライズゲートウェイ経由でルーティング可能に
  • ゲートウェイ上でトラフィックの検査・監査、カスタムセキュリティ / Egress ポリシーの適用が可能に
  • ゲートウェイ API キー認証で Google アカウントサインインが不要に (MDM で admin_settings.json を配布すれば開発者側の設定作業も不要)
  • 一元管理サービスアカウントで認証し、PAYG 使用量を組織の Gemini Enterprise 契約に帰属可能に

Antigravity の各クライアントはゲートウェイ API キーで企業内のエンタープライズゲートウェイに接続し、ゲートウェイがトラフィックの検査・監査とポリシー適用を行ったうえで、一元管理されたサービスアカウントとして Gemini Enterprise Agent Platform API にリクエストを転送します。

⚡ 主要機能

🔀 1. エンタープライズゲートウェイ経由のルーティング

→Antigravity アプリ、CLI、IDE 拡張のモデル推論リクエストを、組織運用のゲートウェイ経由で Google Cloud に転送
→ゲートウェイ上でモデルトラフィックの検査・監査、カスタムセキュリティ / ネットワーク Egress ポリシーの適用が可能
→Apigee のようなマネージド API ゲートウェイでも、Envoy / LiteLLM など自社インフラ上のゲートウェイでも構築可能

🔑 2. ゲートウェイ API キーによる開発者認証

→組織のゲートウェイが発行する API キーで認証し、個別の Google アカウントサインインは不要
→API キーは Authorization ヘッダーの Bearer トークンとして送信 (Google Cloud の認証情報や OAuth トークンは取得しない)
→開発者ごとのキー発行も可能 (admin_settings.json から gateway.apiKey を省略し、各ワークステーションで AGY_LLM_GATEWAY_API_KEY を設定)

💰 3. PAYG 課金と契約への使用量帰属

→一元管理サービスアカウントを使用し、Gemini Enterprise Agent Platform を通じた従量課金 (PAYG) で請求
→シートベースサブスクリプションクォータ (Standard / Plus の月間利用枠など) は消費しない
→属性ヘッダー (User-Agent、X-Goog-Api-Client) をゲートウェイが保持・転送することで、使用量が組織の既存の Gemini Enterprise 契約として認識される

📦 4. MDM による一元的な設定配布

→Jamf、Microsoft Intune、Ansible、Google Workspace MDM などで admin_settings.json をワークステーションに配布可能
→設定の優先順位は「管理者設定ファイル > 環境変数 (AGY_LLM_GATEWAY_*) > ユーザー設定ファイル」で、管理者設定は開発者が上書き不可
→コンテナ、リモート SSH ホスト、CI/CD パイプラインなど非管理環境では環境変数で設定可能

⚙️ 主な設定項目 (admin_settings.json)

項目詳細
gateway.enabledtrue でゲートウェイルーティングを有効化。全推論リクエストがゲートウェイに送信され、Google アカウントサインインを要求しない
gateway.urlエンタープライズゲートウェイの HTTPS エンドポイント
gateway.apiKeyゲートウェイが発行する API キー。Authorization ヘッダーの Bearer トークンとして送信
gateway.wireProtocolgenai (デフォルト、Gemini API プロトコル) または openai (OpenAI Chat Completions プロトコル)。JetBrains IDE / Zed の ACP サーバーは genai のみ対応
gateway.customHeadersコストセンターなどを付与するカスタム HTTP ヘッダー
caCertPath社内ルート CA バンドルの絶対パス (ゲートウェイの内部 TLS 証明書を信頼させる)
models.defaultModelId / models.listデフォルトモデルと、開発者が選択できる承認済みモデルのリスト

📄 設定例

JSON admin_settings.json 
{
  "gateway": {
    "enabled": true,
    "url": "https://gateway.cymbal.com",
    "apiKey": "GATEWAY_API_KEY",
    "wireProtocol": "genai",
    "customHeaders": {
      "X-Cost-Center": "Platform-Engineering",
      "X-Corporate-BU": "DevTools"
    }
  },
  "caCertPath": "/etc/ssl/certs/cymbal-root-ca.pem",
  "models": {
    "defaultModelId": "gemini-3.8-flash",
    "list": [
      { "modelId": "gemini-3.8-flash" },
      { "modelId": "gemini-3.7-flash" },
      { "modelId": "gemini-3.1-pro-preview" }
    ]
  }
}

🛠️ 設定方法

📋 前提条件

✓Gemini Enterprise Agent Platform (旧 Vertex AI) にアクセスでき、Gemini Enterprise Agent Platform API (aiplatform.googleapis.com) が有効な Google Cloud プロジェクト
✓roles/aiplatform.user IAM ロールを付与した Google Cloud サービスアカウント (ゲートウェイが Google Cloud への認証に使用)
✓課金帰属を Cloud Logging で検証するための、Gemini Enterprise Agent Platform API に対するデータアクセス監査ログの有効化
✓サポート対象バージョンの Antigravity クライアント
1

API の有効化とサービスアカウントの作成

Bash gcloud CLI 
gcloud services enable \
    aiplatform.googleapis.com \
    secretmanager.googleapis.com \
    --project=PROJECT_ID

gcloud iam service-accounts create agy-gateway-sa \
    --project=PROJECT_ID \
    --display-name="Antigravity Enterprise Gateway"

gcloud projects add-iam-policy-binding PROJECT_ID \
    --member="serviceAccount:agy-gateway-sa@PROJECT_ID.iam.gserviceaccount.com" \
    --role="roles/aiplatform.user"

ゲートウェイが Gemini Enterprise Agent Platform API を呼び出すためのサービスアカウントを作成し、必要な API を有効化します。

2

ゲートウェイ API キーの生成と Secret Manager への保存

Bash API キー生成と保存 
openssl rand -base64 32 | tr -d '\n' | gcloud secrets create agy-gateway-api-key \
    --project=PROJECT_ID \
    --data-file=-

gcloud secrets add-iam-policy-binding agy-gateway-api-key \
    --project=PROJECT_ID \
    --member="serviceAccount:agy-gateway-sa@PROJECT_ID.iam.gserviceaccount.com" \
    --role="roles/secretmanager.secretAccessor"

生成した API キーを Secret Manager に保存し、ゲートウェイのサービスアカウントに読み取り権限を付与します。ゲートウェイはこのキーを検証し、有効なキーを持たないリクエストを拒否するよう構成します。長いストリーミングレスポンスが途切れないよう、リクエストは最低 60 分間実行できるようにします。

3

ゲートウェイの直接テスト

Bash curl によるストリーミングテスト 
curl -N -X POST "https://gateway.example.com/v1beta/models/MODEL_ID:streamGenerateContent?alt=sse" \
    -H "Authorization: Bearer GATEWAY_API_KEY" \
    -H "Content-Type: application/json" \
    -H "User-Agent: antigravity/1.2.15 (aidev_client; auth_method=gateway)" \
    -d '{"contents": [{"role": "user", "parts": [{"text": "Reply with PONG"}]}]}'

ワークステーション配布前に、ネットワークルーティング、TLS 証明書検証、認証、バッファリングなしの SSE ストリーミングが機能することを確認します。

4

MDM による admin_settings.json の配布

admin_settings.json を以下のパスに MDM (Jamf、Microsoft Intune、Ansible、Google Workspace MDM など) で配布します。

  • macOS: /Library/Application Support/Antigravity/admin_settings.json
  • Linux: /etc/antigravity/admin_settings.json
  • Windows: %ProgramData%\Antigravity\admin_settings.json

ファイルは管理者アカウント所有とし、開発者は読み取りのみ可能にします。配布後に Antigravity を再起動すると、ステータスバーに Connected: Enterprise Gateway と表示されます。

5

Cloud Logging で課金帰属を確認

Text Logs Explorer クエリ 
resource.type="aiplatform.googleapis.com/Endpoint" OR protoPayload.serviceName="aiplatform.googleapis.com"

Logs Explorer で上記クエリを実行し、protoPayload.requestMetadata.callerSuppliedUserAgent に antigravity/VERSION (aidev_client; auth_method=gateway) が含まれることを確認します。

✅ メリット

💼 ビジネス面

✓規制業界での Antigravity 導入が可能に: 外部直接接続やブラウザサインインを禁止する厳格なネットワーク統制下でも、エージェント型 AI 開発ツールを展開できる
✓コスト配賦の可視化: customHeaders によるコストセンター / 部門ヘッダー付与で、ゲートウェイログや SIEM 上でチーム別の使用量を追跡できる
✓契約への使用量帰属: 属性ヘッダーの転送により、モデル使用量が未契約の生 API 消費ではなく、組織の既存の Gemini Enterprise 契約として課金される

⚙️ 技術面

✓トラフィックの集中検査・監査: プロンプト、コンテキストファイル、レスポンスが組織のゲートウェイを通過するため、監査とポリシー適用が一元化できる
✓モデルガバナンス: models.list で開発者が利用できるモデルを承認済みリストに制限できる
✓柔軟なゲートウェイ実装: Apigee などのマネージド API ゲートウェイのほか、Envoy や LiteLLM を自社インフラに展開する構成も選択可能。ワイヤプロトコルも Gemini API (genai) と OpenAI Chat Completions (openai) から選択できる
✓ローカル保護は維持: ゲートウェイ経由でもターミナルコマンド実行やファイル変更は Antigravity のローカルサンドボックス内で実行され、破壊的操作前の人間による承認 (Human-in-the-loop) も維持される

⚠️ デメリット・制約事項

🚫 制限事項

✗ゲートウェイ利用と Google アカウントサインインは同時に使用できない。シートベースサブスクリプションの利用枠を使いたい場合は、ゲートウェイを無効化して Google アカウントでサインインする必要がある
✗ゲートウェイ経由の利用は PAYG 従量課金となり、Gemini Enterprise のシートベースサブスクリプションクォータ (Standard / Plus の月間利用枠) は適用されない
✗Web 版 Antigravity はゲートウェイルーティング非対応 (対話型 Google サインインが必須)
✗JetBrains IDE / Zed (ACP サーバー) は genai ワイヤプロトコルのみサポート。また ACP サーバーはユーザー設定ファイル (~/.antigravity/settings.json) を読み込まない

🤔 考慮すべき点

🔐 API キーの管理: API キーは admin_settings.json または環境変数から平文で読み込まれるため、ゲートウェイを社内ネットワークに限定公開し、キーを Secret Manager で管理して定期的にローテーションすることが推奨されます。開発者単位の帰属が必要なら開発者ごとに個別キーを発行します。
🚨 認証レイヤーの競合: ゲートウェイを Cloud Run の IAM invoker チェックや Identity-Aware Proxy など、Authorization ヘッダーを自ら解釈する認証レイヤーの背後に配置してはなりません (ゲートウェイ API キーが Google 署名付き ID トークンと誤認され、リクエストが拒否されます)。
🌐 ネットワーク構成: ゲートウェイは公開エンドポイントを持たせず、Cloud VPN / Cloud Interconnect 経由の内部アプリケーションロードバランサなどで社内ネットワークからのみ到達可能にします。
🏷️ 属性ヘッダーの転送: ゲートウェイは属性ヘッダー (User-Agent、X-Goog-Api-Client) を必ず保持・転送する必要があります。転送しない場合、使用量が Gemini Enterprise 契約ではなく未契約の生 API 消費として課金されるおそれがあります。
⏱️ タイムアウト: 長いストリーミングレスポンス対応のため、ゲートウェイのリクエストタイムアウトは 60 分以上に設定します。

💰 料金

Antigravity Enterprise Gateway 経由のリクエストは、一元管理された Google Cloud サービスアカウントを使用し、Gemini Enterprise Agent Platform を通じた従量課金 (PAYG) で請求されます。

→このデプロイモデルでは、Gemini Enterprise のシートベースサブスクリプションクォータ (Standard / Plus の月間利用枠など) は使用されない
→ゲートウェイのデプロイ自体に請求書払いの Cloud Billing アカウントは不要
→Agent Platform の PAYG にはデフォルトの Standard PayGo のほか、Priority PayGo、Flex PayGo などのオプションがある
→PAYG 使用コストは Gemini Enterprise の「Usage & Spending」ページの「Billing」タブで確認可能 (「AI developer tools (such as Antigravity)」として表示)
💡 詳細: 単価はモデルごとに異なるため、Gemini Enterprise Agent Platform の料金オプションを参照してください。
