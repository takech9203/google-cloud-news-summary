Apigee Edge for Private Cloud GA (LTS リリース) Breaking Changes

🚀 Apigee Edge for Private Cloud
4.54.00 リリース (LTS)

📅 リリース日: 2026-10-15

📋 概要

Apigee Edge for Private Cloud 4.54.00 がリリース。 長期サポート (LTS) リリースとして、18 ヶ月のフルサポート + 18 ヶ月のメンテナンス期間が提供される。 Java 8 → Java 17/21 への移行、Classic UI と apigee-sso の削除、 バンドルコンポーネント (Cassandra / Postgres / OpenLDAP / ZooKeeper / Qpid Broker-J / Nginx / Consul) の一括更新を含む、 プラットフォーム基盤の大規模な刷新である。

⚠️ 後方互換性なし: Java 8 の置き換え、Classic UI / apigee-sso の削除、バンドルコンポーネント更新は後方互換性がない。 オンプレミスで Apigee Edge を運用するチームは、アップグレード前に破壊的変更の影響範囲を必ず評価すること。

❌ Before (〜4.53.x) の課題

  • プラットフォームが Java 8 上で動作し、新しい Java のパフォーマンス・セキュリティ改善を利用できない
  • SSO にはスタンドアロンの apigee-sso + Apache Tomcat 9.0.x の運用が必要
  • New Edge UI へのサインインに IdP (SAML/OIDC/Apigee SSO) の構成が必須で、簡易なサインイン手段がない
  • インストール前に環境構成の問題を自動検出する仕組みがなく、インストール後に問題が顕在化し得た
  • Message Processor に useG1GC / useStringDeduplication がデフォルト未設定

✅ After (4.54.00) の改善

  • Java 17 / 21 ベースの実行基盤に刷新。コンポーネントアップグレードで複数の脆弱性を修正
  • SSO が apigee-openldap 統合の OIDC アイデンティティブローカーに一本化。Tomcat 運用が不要に
  • New Edge UI に Basic 認証 (GA) が追加され、IdP なしでサインイン可能
  • apigee-setup / apigee-service に自動プリフライト検証チェック (GA) を追加
  • MP のデフォルト GC が G1GC に、TLS 1.3 がデフォルト有効化 (JEP 332)

⭐ 主要機能

1️⃣ LTS リリース指定とサポートライフサイクル

  • 18 ヶ月のフルサポート (2028 年 4 月終了) + 18 ヶ月のメンテナンス (2029 年 10 月終了)
  • 2029 年 10 月以降はソフトウェアアップデート、セキュリティ緩和策、テクニカルサポートの対象外
  • 後続の 4.54 系マイナーリリース・パッチを適用してもサポート期日は変わらない

2️⃣ プラットフォーム基盤の刷新 (後方互換性なし)

  • Java 8 を Java 17 / Java 21 に置き換え (Oracle JDK / OpenJDK 両対応、JDK 8 はサポート終了)
  • Classic UI (edge-ui) と apigee-sso コンポーネントを削除
  • Cassandra、Postgres、OpenLDAP、ZooKeeper、Qpid Broker-J、Nginx、Consul のバンドルバージョンを一括更新

3️⃣ New Edge UI への全面移行

  • New Edge UI (edge-management-ui) が 唯一の管理 UI としてデフォルトでインストール
  • デフォルトポートが 9000 → 3001 に変更 (conf_uebe_port で変更可能)。ファイアウォール・LB の更新が必要
  • Classic UI のカスタムプロパティは自動では引き継がれない (アップグレード前に New Edge UI へ移行必須)
  • Basic 認証が GA。IdP なしでサインイン可能 (SAML/OIDC/Apigee SSO も引き続きサポート)

4️⃣ SSO アーキテクチャの刷新 (Breaking)

  • apigee-openldap 統合の OIDC アイデンティティブローカーが、スタンドアロン apigee-sso + Tomcat 9.0.x を置き換え
  • 既存の apigee-sso 構成は自動では移行されない。完全かつ検証済みの LDAP バックアップが必須
  • Apigee SSO を使用していないデプロイメントは対応不要

5️⃣ 運用性・ランタイムの改善

  • apigee-setup / apigee-service に自動プリフライト検証チェック (GA)。インストール前に環境構成の問題を検出
  • Edge Router の Nginx を 1.30.0 にアップグレード (1.20.x からの場合は変更一覧の確認を推奨)
  • MP のデフォルト GC を G1GC に変更 (useG1GC=true、useStringDeduplication=true)
  • コンポーネントアップグレードにより複数のセキュリティ脆弱性を修正

🔒 Message Processor の TLS デフォルト変更 (Java 21 暗号ベースライン)

項目詳細
TLS バージョン TLS 1.3 がデフォルトで有効 (JEP 332)。アウトバウンドのバックエンド接続で TLS 1.3 を優先し、TLS 1.2 にフォールバック
無効化される暗号スイート 前方秘匿性のない静的 RSA 鍵交換スイート (TLS_RSA_*) が無効化
対応不要なケース ターゲットサーバー・LB が TLS 1.3、または前方秘匿性のある (ECDHE) 暗号スイートで TLS 1.2 をネゴシエートできる場合
障害が発生するケース conf_http_HTTPTransport.ssl.cipher.suites.whitelist または conf_message-processor-communication_local.http.ssl.ciphers を静的 RSA スイートのみでオーバーライドしている場合、バックエンド呼び出しが no cipher suites in common で失敗し、Router が MP と TLS ハンドシェイクを完了できない
修復方法 TLS_RSA_* エントリをモダンな暗号スイートに置き換え、MP を再起動 (Legacy TLS remediation)

⚙️ 設定方法 (アップグレード手順)

📝 前提条件

  1. 4.54.00 へは 4.53.00 または 4.53.01 からの直接アップグレードがサポートされる
  2. すべての Edge コンポーネントをアップグレードする (複数バージョン混在構成はサポート外)
  3. アップグレードは Edge を最初にインストールした人物、または root 権限で実行
  4. Java 17 と Java 21 の両方を事前にインストール (ブートストラップ時の自動インストールなし)
  5. Classic UI 利用中の場合、アップグレード前に New Edge UI へ移行
  6. Apigee SSO 有効環境では、完全かつ検証済みの LDAP バックアップを取得

🔁 アップグレードフロー

ステップ 1: 事前確認 (Pre-read) 📖

以下の公式ドキュメントを確認する。

  • Changes in Edge for Private Cloud 4.54.00 — TLS・JavaCallout の事前準備が必要な変更
  • New Edge UI / Migrate to the New Edge UI
  • Apigee SSO の新アーキテクチャ
  • Nginx 1.30 changes
  • Known issues

ステップ 2: 影響評価と準備 🔍

  • カスタム JavaCallout ポリシー・カスタムリソース JAR の Java 21 互換性を確認 (非互換の場合はメンテナンスウィンドウ方式、または 4.53.x MP と 4.54.00 MP を併存させるゼロダウンタイム移行戦略)
  • MP の暗号スイートのオーバーライド (conf_http_HTTPTransport.ssl.cipher.suites.whitelist など) に TLS_RSA_* のみが設定されていないか確認
  • ポート 9000 を参照するファイアウォールルール・LB ターゲットポートを 3001 (または conf_uebe_port の設定値) に更新する計画を立てる
  • Apigee SSO 有効環境では LDAP の完全バックアップを取得・検証

ステップ 3: アップグレードの実行 🚀

Update Apigee Edge 4.53.00 or 4.53.01 to 4.54.00 の手順に従う。注意点:

  • 4.54.00 ではコンポーネントのアップグレード順序が従来から変更 (Order of machine update を参照)
  • Apigee のアップグレードと OS のメジャーバージョンアップグレードは同時に行わない
  • Cassandra のメジャーアップグレードを含むため、データセンターごとに 1 つずつアップグレードすることを推奨
  • 新規インストールは New installation overview を参照

⚖️ メリットとデメリット・制約事項

👍 メリット

  • ビジネス面
  • ✓ サポートライフサイクルの明確化: フルサポート 2028 年 4 月 / メンテナンス 2029 年 10 月まで明示され、中長期の運用・移行計画が立てやすい
  • ✓ セキュリティリスクの低減: Java 8 からの脱却と複数の脆弱性修正でセキュリティ態勢が向上
  • 技術面
  • ✓ モダンな Java ランタイム: TLS 1.3 (JEP 332)、G1GC + 文字列重複排除がデフォルト有効
  • ✓ 運用の簡素化: SSO の一本化で apigee-sso + Tomcat 運用が不要。Basic 認証で IdP なしサインインも可能
  • ✓ インストール品質の向上: 自動プリフライト検証で環境構成の問題を事前検出

👎 制限事項

  • ✗ 後方互換性なし: Java 8 置き換え、Classic UI / apigee-sso 削除、バンドルコンポーネント更新
  • ✗ Oracle JDK 8 / OpenJDK 8 はサポートされない
  • ✗ Classic UI のカスタムプロパティは New Edge UI へ自動では引き継がれない
  • ✗ 既存の apigee-sso 構成は自動では移行されない
  • ✗ 4.54 系マイナーリリース・パッチを適用してもサポート期日 (2028 年 4 月 / 2029 年 10 月) は延長されない

🤔 考慮すべき点

  • カスタム JavaCallout / カスタムリソース JAR: Java 21 上で動作しなくなる可能性。アップグレード前の互換性検証が必須
  • TLS 設定のオーバーライド: 静的 RSA スイート (TLS_RSA_*) のみの指定は no cipher suites in common で失敗。モダンな暗号スイートへの置き換えと MP 再起動が必要
  • UI ポート変更: 9000 → 3001 に伴うファイアウォールルール・LB ターゲットポートの更新が必要
  • LDAP バックアップ: Apigee SSO 有効環境では完全かつ検証済みのバックアップ取得が必須
  • アップグレード順序の変更: 4.54.00 ではコンポーネントのアップグレード順序が従来から変更
  • Cassandra メジャーアップグレード: データセンター単位で 1 つずつの実施を推奨
  • OS アップグレードとの分離: Apigee と OS のメジャーアップグレードは同時に実施しない

💼 ユースケース

📈 ユースケース 1: 4.53.x からの LTS 移行計画の策定

シナリオ: 4.53.01 でオンプレミス API 基盤を運用中の企業が、サポート継続のため 4.54.00 LTS への移行を計画する。

  1. Changes in 4.54.00 / Known issues を確認し、影響評価を実施
  2. カスタム JavaCallout・リソース JAR の Java 21 互換性をテスト環境で検証
  3. TLS 暗号スイートのオーバーライド設定を棚卸し (TLS_RSA_* のみの設定を是正)
  4. Classic UI 利用中なら New Edge UI へ事前移行、ポート 9000 → 3001 のネットワーク変更を準備
  5. SSO 有効環境は LDAP の完全バックアップを取得・検証
  6. 変更後の順序に従い、データセンターごとにアップグレードを実行
✅ 効果: 2028 年 4 月までのフルサポート、2029 年 10 月までのメンテナンスを確保し、計画的な次期 LTS 移行までの運用継続性を担保できる。

🔄 ユースケース 2: Java 21 非互換の JavaCallout を抱える環境のゼロダウンタイム移行

シナリオ: ミッションクリティカルな本番環境で、Java 8 と Java 21 の両方で同時に動作させられない JavaCallout を使用している。

✅ 効果: 公式ドキュメントの移行戦略 (新しい環境を用意し、4.53.x Message Processor には Java 8 互換プロキシ、 4.54.00 Message Processor には Java 21 互換プロキシをデプロイして、ロードバランサーで段階的にトラフィックを切り替える方式) に従うことで、 ダウンタイムなしで 4.54.00 へ移行できる。

🎯 まとめ

Apigee Edge for Private Cloud 4.54.00 は、Java 17/21 への移行、 New Edge UI への一本化、SSO アーキテクチャの刷新を含む 後方互換性のない大型 LTS リリースであり、2029 年 10 月までのサポートライフサイクルが明示された。

💡 推奨アクション: オンプレミスで Apigee Edge を運用するチームは、 カスタム JavaCallout の Java 21 互換性検証、TLS 暗号スイート設定の棚卸し、 UI ポート変更 (9000 → 3001) への対応、SSO 環境での LDAP バックアップ取得を含む アップグレード計画の策定に早期に着手することを推奨する。
