Container-Optimized OS 🛡️ Security Patch COS 133 LTS

🐧 Container-Optimized OS
cos-133-19999-44-174 セキュリティパッチ

📅 リリース日: 2026-10-30

📋 概要

COS 133 LTS 系の新パッチイメージ cos-133-19999-44-174 がリリースされました。 主要コンポーネント (Kernel COS-6.18.55 / Docker v29.4.3 / Containerd v2.4.1) は前リリース (cos-133-19999-44-159、2026-10-22) から据え置きで、6 件の CVE 修正を中心としたセキュリティパッチです。

修正対象は google-osconfig-agent (3 件)、app-admin/sudo、 app-arch/brotli (1.0.10 へ更新)、Linux カーネルの各 CVE で、あわせて fs.epoll.max_user_watches や kernel.threads-max、net.ipv4.tcp_mem などのランタイム sysctl 値が微調整されています。

❌ Before (cos-133-19999-44-159 以前)

  • ゲスト管理エージェント google-osconfig-agent に CVE-2026-42508 / CVE-2026-39830 / CVE-2026-39833 の脆弱性が残存
  • app-admin/sudo に CVE-2026-82474、app-arch/brotli (1.0.10 未満) に CVE-2026-111497、Linux カーネルに CVE-2026-98432 が存在

✅ After (cos-133-19999-44-174)

  • google-osconfig-agent、sudo、brotli、Linux カーネルの計 6 件の CVE が修正され、ノード OS のセキュリティ態勢が改善
  • app-arch/brotli が 1.0.10 に更新
  • ランタイム sysctl のデフォルト値 (epoll/inotify/fanotify のウォッチ上限、スレッド上限、TCP/UDP メモリ、各種 namespace 上限など) を微調整
💡 ポイント: COS は GKE ノードのデフォルト OS イメージです。ノード自動アップグレード有効な環境では自然に適用されますが、 イメージバージョンを固定している環境では sudo・カーネルの CVE 修正を含むため計画的な更新を推奨します。

⭐ 主要機能 (アップデート内容)

🤖 1. google-osconfig-agent のセキュリティ修正

→CVE-2026-42508、CVE-2026-39830、CVE-2026-39833 を修正
→OS Config エージェントはパッチ管理や OS インベントリ収集を担うゲストエージェントであり、全インスタンスに影響する修正

🔑 2. sudo / brotli / カーネルの CVE 修正

→app-admin/sudo の CVE-2026-82474 を修正
→app-arch/brotli を 1.0.10 に更新し、CVE-2026-111497 を解消
→Linux カーネル (COS-6.18.55) の CVE-2026-98432 を修正

🛠️ 設定方法

✅ 前提条件

✓Compute Engine で COS を使用している場合: イメージファミリー cos-133-lts (x86) または cos-arm64-133-lts (Arm) を参照していること
✓GKE の場合: ノードイメージに Container-Optimized OS (containerd) を使用していること

1️⃣ ステップ 1: 最新イメージの確認 (Compute Engine)

Bash 
gcloud compute images describe-from-family cos-133-lts \
    --project cos-cloud

イメージファミリーの最新イメージが cos-133-19999-44-174 になっているかを確認します。

2️⃣ ステップ 2: GKE ノードプールのアップグレード

Bash 
# 自動アップグレードが有効なら新バージョンのロールアウトを待つだけでよい
# 手動で適用する場合:
gcloud container clusters upgrade CLUSTER_NAME \
    --node-pool NODE_POOL_NAME \
    --zone ZONE
✅ 推奨: GKE ではノード自動アップグレードを有効にしておくことで、COS のセキュリティパッチが段階的に自動適用されます。

💪 メリット

💼 ビジネス面

✓セキュリティコンプライアンスの維持: sudo やカーネルなど広く使われるコンポーネントの CVE が解消され、脆弱性スキャンの指摘事項を低減できる
✓運用負荷の軽減: GKE ノード自動アップグレードを有効にしていれば追加作業なしでパッチが適用される

⚙️ 技術面

✓ゲストエージェントの堅牢化: パッチ管理を担う google-osconfig-agent 自体の脆弱性が修正され、管理プレーン経由のリスクが低減
✓LTS の安定性: Kernel / Docker / Containerd のメジャーバージョンは据え置きであり、互換性リスクを抑えつつセキュリティ修正のみを取り込める

⚠️ デメリット・制約事項

⚠️ 考慮すべき点
  • イメージバージョンを固定 (ピン留め) している環境では自動適用されないため、手動での更新計画が必要
  • ランタイム sysctl のデフォルト値が微減しているため、epoll/inotify のウォッチ数やスレッド数を上限近くまで使うワークロードでは、念のため実効値を確認するのが望ましい (変動幅はごくわずか)
  • 本リリースは COS 133 LTS 系のパッチであり、他のマイルストーン (COS 121/125/129 LTS など) には別途それぞれのパッチが提供される

🎯 ユースケース

☸️ ユースケース 1: GKE ノードの定期セキュリティパッチ適用

シナリオ: GKE クラスタのノードイメージに COS を使用しており、セキュリティパッチを継続的に適用したい。

Bash 
# リリースチャンネル + ノード自動アップグレードを有効化しておく
gcloud container clusters describe CLUSTER_NAME \
    --zone ZONE \
    --format="value(releaseChannel.channel)"

効果: COS のセキュリティ修正がロールアウトに合わせて自動的にノードへ反映され、CVE 対応の運用負荷を最小化できる。

🖥️ ユースケース 2: Compute Engine 上のコンテナホストの脆弱性対応

シナリオ: Compute Engine インスタンスで COS を直接利用してコンテナを稼働させており、sudo / カーネルの CVE 指摘に対応する必要がある。

効果: インスタンステンプレートのイメージを cos-133-lts ファミリー参照にしておき、インスタンスを再作成 (ローリング更新) することで最新パッチ cos-133-19999-44-174 を適用できる。
