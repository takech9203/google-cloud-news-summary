⚡ 主要機能アップデート

🎫 ServiceNow (v66.0) - 参照フィールド更新サポート

Update Incident アクションに参照フィールド (reference fields) の更新サポートが追加されました。

→ 他テーブルのレコードへのリンク (assigned_to, caller_id, cmdb_ci) を自動化ワークフロー内で設定可能
→ プレイブック内でインシデントの担当者変更、CI アイテムの関連付け、グループ割り当てをより柔軟に自動化
→ Custom Fields パラメータと組み合わせて高度なインシデント管理ワークフローを構築可能

📊 Google Chronicle (v83.0) - ルールタイプフィルタリング

Chronicle Alerts Connector にルールタイプ (rule type) によるアラートフィルタリング機能が追加されました。

→ ルールタイプの例: SINGLE_EVENT、MULTI_EVENT
→ 既存フィルタキー (Rule.severity, Rule.ruleName, Rule.ruleID, Rule.ruleLabels) に加え、ルールタイプによる絞り込みが可能
→ 大量のアラート環境で、特定のルールタイプのみを SOAR に取り込む運用が容易に

💻 Tanium (v20.0) - パートナーヘッダー追加

すべての API リクエストにパートナーヘッダーが追加されました。

→ Tanium 側で Google SecOps からのリクエストを識別・追跡可能に
→ API 利用状況のモニタリングやトラブルシューティングが容易に

🔧 コードリファクタリング (4 コネクタ)

以下のコネクタでコードがリファクタリングされ、安定性とパフォーマンスが向上しました。

→ AlienVault USM Appliance (v27.0): Get PCAP Files For Events アクション
→ Protectwise (v6.0): Get Pcap アクション
→ Service Desk Plus (v9.0): Create Alert Request アクション
→ Service Desk Plus V3 (v9.0): Create Alert Request アクション

💡 ユースケース

🎫 ユースケース 1: ServiceNow インシデントの自動エスカレーション

シナリオ: Google SecOps で高重要度のアラートが検出された場合、ServiceNow のインシデントを自動的に作成し、適切な担当者 (参照フィールド) を設定する

JSON 
{
  "action": "Update Incident",
  "parameters": {
    "Incident Number": "INC0012345",
    "Custom Fields": "{\"assigned_to\": \"sys_id_of_security_analyst\", \"assignment_group\": \"sys_id_of_soc_team\", \"cmdb_ci\": \"sys_id_of_affected_server\"}"
  }
}

効果: 参照フィールドの自動設定により、エスカレーション時の手動操作が不要になり、MTTR (平均修復時間) の短縮に貢献
