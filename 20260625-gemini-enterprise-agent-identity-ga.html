📋 概要

Gemini Enterprise において、管理者がエージェントの詳細ページでエージェントの SPIFFE ID を直接確認できる機能が一般提供 (GA) となりました。

SPIFFE (Secure Production Identity Framework For Everyone) は、分散システムにおけるワークロード間の安全な認証を実現するための標準規格です。各エージェントに一意の SPIFFE ID が割り当てられ、暗号学的に証明可能な ID として機能します。パブリッシャーが SPIFFE ID を公開していない場合は、代替として Agent Registry のリソース ID が表示されます。

💡 対象ユーザー: Gemini Enterprise の管理者。組織内で運用されるエージェント (Google 製、サードパーティ製、内部チーム製) の ID 管理とセキュリティガバナンスを強化できます。

🔄 Before / After 比較

❌ Before

  • SPIFFE ID の確認に API や CLI が必要
  • ID 情報へのアクセスが容易でない
  • IAM ポリシー設定時に ID 確認に手間がかかる
  • エージェントの身元確認と監査に追加手順が必要

✅ After

  • コンソールのエージェント詳細ページで SPIFFE ID を直接確認
  • SPIFFE ID 未公開時も Agent Registry リソース ID がフォールバック表示
  • IAM ポリシーの principal 識別子を容易に取得可能
  • 常にエージェントを一意に識別可能

⚡ 主要機能

🆔 SPIFFE ID の表示

エージェント詳細ページで SPIFFE ID を直接確認可能。フォーマット:

spiffe://TRUST_DOMAIN/resources/SERVICE/RESOURCE_PATH

🔄 リソース ID フォールバック

パブリッシャーが SPIFFE ID を公開していない場合、Agent Registry リソース ID を自動表示。常に一意な識別を保証。

🔗 IAM Principal 連携

SPIFFE ID から IAM allow policy で使用する principal 識別子を容易に特定可能。

principal://TRUST_DOMAIN/resources/SERVICE/RESOURCE_PATH

💻 IAM ポリシー設定例

エージェントの SPIFFE ID を使用して、特定リソースへのアクセス権限を付与する例です。

JSON

  "bindings": [
    {
      "role": "roles/storage.objectViewer",
      "members": [
        "principal://agents.global.org-123456789012.system.id.goog/resources/discoveryengine/projects/9876543210/locations/global/collections/default_collection/engines/my-agent"
      ]
    }
  ]
}

🎯 ユースケース

🏢 ユースケース 1: マルチエージェント環境のアクセス制御

組織内で複数のカスタムエージェントが稼働しており、各エージェントがアクセスできる Cloud Storage バケットを制限したいケース。

Bash 
# エージェント詳細ページから取得した SPIFFE ID を使用
gcloud storage buckets add-iam-policy-binding gs://my-bucket \
  --member="principal://agents.global.org-123456789012.system.id.goog/resources/discoveryengine/projects/9876543210/locations/global/collections/default_collection/engines/sales-agent" \
  --role="roles/storage.objectViewer"

効果: 各エージェントに最小権限の原則を適用し、セキュリティリスクを最小限に抑制

🔍 ユースケース 2: エージェントの監査とコンプライアンス

セキュリティチームが組織内で稼働するすべてのエージェントの ID を確認し、適切なアクセス権限が付与されているかを監査する必要があるケース。

効果: SPIFFE ID を Cloud Audit Logs と照合し、各エージェントのアクティビティを追跡可能

🌐 ユースケース 3: サードパーティエージェントの信頼性検証

Agent Registry から A2A エージェントをインポートした際に、そのエージェントの ID が正しく割り当てられているかを確認するケース。

効果: エージェント詳細ページで SPIFFE ID の存在と形式を確認し、正しく ID システムに登録されていることを検証可能

⚠️ 制限事項・注意点

制限事項:
  • ⚠️SPIFFE ID はパブリッシャーが公開している場合のみ表示される
  • ⚠️SPIFFE ID 未公開時の Agent Registry リソース ID は SPIFFE ID と同等のセキュリティ機能を持たない
  • ⚠️Agent Identity auth manager は現時点で Preview ステータス
考慮すべき点:
  • 💡X.509 証明書は 24 時間で有効期限切れ。自動更新が正常動作していることが前提
  • 💡組織の Trust Domain 設定が正しく構成されている必要がある
  • 💡VPC Service Controls でのエージェント ID の使用は Preview 段階
