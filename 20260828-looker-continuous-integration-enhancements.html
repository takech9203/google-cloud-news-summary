📊 Looker: Continuous Integration の機能強化

dbt Cloud CI 連携 + GitLab CI / Bitbucket Pipelines / GitHub Actions からのトリガー対応

📋 概要

Looker 26.14 リリースの一部として、Looker Continuous Integration (CI) に 2 つの機能強化が登場しました。 1 つ目は dbt Cloud CI 連携で、dbt Cloud の CI ジョブ完了をトリガーに Looker の CI スイートを自動実行し、 dbt モデルの変更が Looker Explore で SQL エラーを引き起こさないかをデプロイ前に検証できます。 2 つ目は 外部 CI/CD ワークフローからのトリガー対応で、Looker API と公式 Python SDK (looker-sdk) を使って GitLab CI / Bitbucket Pipelines / GitHub Actions から Looker CI を起動できるようになりました。

🔍 Looker CI を構成する 4 つのバリデータ

🗄️ SQL Validator
Explore の SQL エラーを検出
🧪 Assert Validator
LookML データテストを実行
📈 Content Validator
ダッシュボード等の参照切れを検出
📝 LookML Validator
LookML の構文・参照を検証

🔄 Before / After

❌ Before (アップデート前)
  • CI の自動トリガーは LookML の pull request とスケジュール実行のみ。dbt モデルの破壊的変更は本番デプロイ後でないと検出できなかった
  • dbt 側の変更による Looker への影響確認は、手動の CI 実行か本番エラーで気付く運用になりがち
  • GitLab CI や Bitbucket Pipelines など既存 CI/CD 基盤から Looker CI を呼び出す公式な手順が案内されていなかった
✅ After (アップデート後)
  • dbt Cloud CI ジョブの完了をトリガーに CI スイートが自動実行され、Explore への影響をデプロイ前に検証可能
  • dbt Cloud の一時スキーマを自動識別し、ユーザー属性を上書きして検証。カラム削除・テーブル名変更をマージ前に検出
  • Looker API + looker-sdk で GitLab CI / Bitbucket Pipelines / GitHub Actions からトリガー可能に (公式手順・サンプルあり)

⚡ 主要機能

1️⃣ dbt Cloud CI ジョブ完了時の CI スイート自動実行 Feature
✓CI スイートの作成・編集時に 「Trigger on pull requests from dbt Cloud」 トグルを有効化して設定
✓トリガー対象の dbt Cloud Job (CI ジョブタイプのみ対応) と、スキーマ名を保持する Schema user attribute を指定
✓スイート保存時に、Looker が dbt Cloud アカウントへジョブ完了を待ち受ける Webhook を自動登録
2️⃣ 一時スキーマの動的識別とユーザー属性の上書き
✓dbt Cloud の実行ごとに作成される一時スキーマを Looker が動的に識別
✓CI 実行の間だけユーザー属性 (接続のスキーマ属性など) を一時スキーマ名で上書きしてバリデータを実行。完了後は CI ユーザーの標準値に復帰
✓カラム削除やテーブル名変更のような破壊的変更を dbt の本番マージ前に検出
3️⃣ 外部 CI/CD ワークフローからのトリガー対応 Change
✓GitLab CI / Bitbucket Pipelines / GitHub Actions の各ワークフローから Looker CI をトリガー可能なことが明確化
✓Looker API と公式 Python SDK (looker-sdk) を使用
✓設定手順とサンプルスクリプトは Admin settings - Continuous Integration ドキュメントで案内

🔧 技術仕様

Looker CI の利用要件

項目詳細
インスタンスLooker がホストするインスタンスで、CI が有効化されていること
Looker (Google Cloud core) の制約Public 接続構成のみサポート。CMEK 有効インスタンス、Private / Hybrid 接続構成では非サポート
CI ユーザーCI 有効化時に Looker CI Users グループ (Looker CI Users ロール) の CI ユーザーが 10 個自動作成される
権限スイートの作成・設定には manage_ci、手動実行・再実行には see_ci 権限が必要
バリデータSQL Validator / Assert Validator / Content Validator / LookML Validator
データ所在CI は一部データを米国に保存するため、データ所在地要件があるインスタンスでは有効化しないこと

dbt Cloud 連携の Admin 設定 (Continuous Integration Admin ページ)

設定項目内容
dbt Cloud Host URLdbt Cloud アカウントの URL
dbt Cloud API Keydbt Cloud のサービスアカウントトークン
Test ConnectionLooker が dbt Cloud への接続を検証し、dbt Cloud Account ID を取得
User AttributesCI 実行時に上書き可能なユーザー属性と CI 実行用の値のペアを登録 (dbt Cloud の一時スキーマを指すために使用)

🛠️ 設定方法

✅ 前提条件

  1. CI の利用要件を満たす Looker インスタンスで、Admin メニュー → Platform → Continuous Integration ページから CI が有効化されていること
  2. dbt Cloud 連携の場合: dbt Cloud アカウントとサービスアカウントトークンを用意し、Admin ページで dbt Cloud Configuration (Host URL / API Key) を設定済みであること
  3. CI スイートを設定する Looker ユーザーが manage_ci 権限を持つこと

ステップ 1: Admin ページで dbt Cloud 連携とユーザー属性を設定

Continuous Integration Admin ページの dbt Cloud Configuration セクションで dbt Cloud Host URL と API Key (サービスアカウントトークン) を入力し、 Test Connection で接続を検証して Save をクリック。あわせて User Attributes セクションで、 CI 実行時に上書きするユーザー属性 (スキーマ名を保持する属性) と CI 実行用の値を登録します。

ステップ 2: CI スイートで dbt Cloud トリガーを有効化

Looker IDE の Continuous Integration アイコン → Suites タブから、スイートの作成/編集画面で 「Trigger on pull requests from dbt Cloud」 トグルを有効化して以下を設定します。

✓dbt Cloud Job: トリガーとなる dbt Cloud CI ジョブを選択 (CI ジョブタイプのみ表示。手動実行は非対応)
✓Schema user attribute: スキーマ名を保持する Looker ユーザー属性を選択 (Admin パネルで CI 用に有効化された属性のみ表示)
✓スイート保存で Webhook が自動登録。Enable email alerts で結果 (Failed / Error / Passed / Cancelled) のメール通知も設定可能

⚙️ 手順: 外部 CI/CD ワークフローからのトリガー

💡 ポイント: GitLab CI、Bitbucket Pipelines、GitHub Actions からは、Looker API と公式 Python SDK (looker-sdk) を使用して CI をトリガーします。 具体的な設定手順とサンプルスクリプトは Admin settings - Continuous Integration ドキュメントを参照してください。

💡 メリット

💼 ビジネス面
  • 本番障害の未然防止: dbt モデルの破壊的変更 (カラム削除、テーブル名変更など) がダッシュボードや Explore を壊す前に検出でき、レポートの信頼性が向上
  • データチームと BI チームの連携強化: データ変換レイヤー (dbt) とセマンティックレイヤー (LookML) の整合性検証が自動化され、手動確認コストを削減
⚙️ 技術面
  • 一時スキーマ検証の自動化: 一時スキーマの動的識別とユーザー属性の上書きにより、検証環境の手動セットアップが不要
  • 既存 CI/CD 基盤への統合: GitLab CI / Bitbucket Pipelines / GitHub Actions から API 経由で起動でき、標準パイプラインに Looker 検証を組み込める
  • Webhook の自動登録: スイートの保存だけで完了。dbt Cloud 側での手動 Webhook 設定は不要

⚠️ デメリット・制約事項

🚫 制限事項

✗dbt Cloud トリガーが対応するのは CI ジョブタイプのみ。手動の dbt Cloud 実行はサポートされない
✗dbt Cloud トリガーの CI 実行は本番 LookML ブランチに対して実行されるため、Content Validator と LookML Validator は開発ブランチ上のエラーを検証しない
✗Looker (Google Cloud core) では Public 接続構成のみサポート。CMEK 有効インスタンスや Private / Hybrid 接続構成では利用不可
✗CI は一部データを米国に保存。データ所在地要件があるインスタンスでは有効化すべきでない。FedRAMP High / Moderate、DoD IL5 の認可境界に含まれない

🤔 考慮すべき点

⚠️Looker CI はレガシーのスタンドアロン Spectacles サービスがベース。スタンドアロン Spectacles は 2026 年 11 月 30 日以降に廃止開始。既存 Spectacles ユーザーは Looker CI への移行を計画すること
⚠️dbt Cloud 連携にはサービスアカウントトークンが必要。トークンの管理・ローテーション運用を検討する
⚠️Looker (original) で IP 許可リストを使用中の場合、CI 用 IP アドレスの手動追加が必要 (IP アドレスはサポートに問い合わせ)

🎯 ユースケース

📌 ユースケース 1: dbt モデル変更のマージ前検証

シナリオ: アナリティクスエンジニアが dbt リポジトリに pull request を作成し、既存モデルのカラム名を変更。 この変更が Looker の Explore やダッシュボードを壊さないかをマージ前に確認したい。

  1. dbt リポジトリへの PR 作成で dbt Cloud の CI ジョブが起動し、一時スキーマに変更後のモデルを構築
  2. ジョブ完了の Webhook を受けて Looker CI スイートが自動実行され、スキーマ属性を一時スキーマ名で上書き
  3. SQL Validator が Explore のディメンションを一時スキーマに対して検証し、参照切れのカラムを検出
  4. 検証結果 (Failed) を確認して、dbt の変更マージ前に LookML 側の修正を計画
✅ 効果: dbt の破壊的変更による Looker 側の SQL エラーを本番デプロイ前に検出でき、ダッシュボード障害を未然に防止。
📌 ユースケース 2: 既存 CI/CD パイプラインへの Looker 検証の組み込み

シナリオ: 組織の標準 CI/CD 基盤が GitLab CI で、データ関連リポジトリのパイプラインの一部として Looker の検証を実行し、 結果をパイプラインの成否に反映させたい。

✅ 効果: Looker API と looker-sdk を使ったスクリプトをパイプラインのジョブとして実行することで、 Looker CI を既存パイプラインに統合でき、Looker IDE を開かずに検証を自動化。GitHub Actions や Bitbucket Pipelines でも同様に構成可能。

🔗 関連サービス・機能

🔧 dbt Cloud

dbt モデルの CI ジョブが Looker CI スイートのトリガーとなる。連携には dbt Cloud のサービスアカウントトークンが必要。

🐙 GitHub / GitLab / Bitbucket

LookML リポジトリのホスティングと、外部 CI/CD ワークフロー (GitHub Actions / GitLab CI / Bitbucket Pipelines) からの Looker CI トリガーに使用。LookML の pull request トリガー (CI GitHub app) はクラウド版 GitHub のみ対応。

🐍 Looker API / Looker Python SDK (looker-sdk)

外部 CI/CD ワークフローから CI をトリガーするためのインターフェース。

🧪 LookML データテスト (Assert Validator)

CI スイート内で LookML の data tests を実行し、失敗とエラーを報告。

📝 まとめ

Looker CI は dbt Cloud CI ジョブの完了を起点とした自動検証と、 GitLab CI / Bitbucket Pipelines / GitHub Actions からの API ベースのトリガーに対応し、 データ変換からセマンティックレイヤーまでを貫く品質ゲートとして CI/CD パイプラインに組み込みやすくなりました。

✓dbt Cloud と Looker を併用しているチームは、CI スイートの dbt Cloud トリガーを有効化して破壊的変更のマージ前検出を導入することを推奨
✓レガシー Spectacles を利用中のチームは 2026 年 11 月 30 日以降の廃止開始に備えて Looker CI への移行を計画
