Cloud Service Mesh の AgentGateway リソースタイプに対応
Cloud Asset Inventory Cloud Service Mesh 一般提供 (Publicly Available)
📅 リリース日: 2026-10-13
🏷️ 新規リソースタイプのサポート

📌 概要

Cloud Asset Inventory で、Cloud Service Mesh の networkservices.googleapis.com/AgentGateway リソースタイプが主要な API 群 (ExportAssets、ListAssets、BatchGetAssetsHistory、QueryAssets、Feed、Search API の SearchAllResources / SearchAllIamPolicies) を通じて一般公開されました。

🤖 AgentGateway とは: AI エージェント、MCP (Model Context Protocol) サーバー、ツールへの接続をガバナンス (統制) するための Cloud Service Mesh のリソースです。Google マネージドのデプロイモードに加え、既存の Application Load Balancer や Secure Web Proxy にアタッチするセルフマネージドモードをサポートします。

今回のアップデートにより、組織内に作成された AgentGateway リソースを Cloud Asset Inventory の各種 API で 一元的に棚卸し・検索・履歴追跡できるようになりました。 AI エージェント基盤を Google Cloud 上で運用する組織にとって、エージェントゲートウェイの構成をガバナンス・セキュリティ監査・コンプライアンスの観点から可視化できることは重要です。主な対象ユーザーはクラウド管理者、セキュリティチーム、SRE です。

😣 Before (アップデート前の課題)

  • AgentGateway は Cloud Asset Inventory の対象外で、組織・フォルダ・プロジェクト横断での棚卸しができなかった
  • 構成変更履歴を履歴 API で追跡できず、監査時には個別に Network Services API を照会する必要があった
  • SearchAllResources や QueryAssets で他のリソースと合わせた横断検索ができなかった

😀 After (アップデート後の改善)

  • ExportAssets で AgentGateway を含むアセットを BigQuery / Cloud Storage へ一括エクスポート可能に
  • BatchGetAssetsHistory で構成変更履歴を取得可能に
  • Feed で変更を Pub/Sub でリアルタイムに監視可能に
  • SearchAllResources / SearchAllIamPolicies / QueryAssets で組織横断の検索・SQL 分析が可能に

Cloud Service Mesh の AgentGateway リソースが Cloud Asset Inventory に取り込まれ、エクスポート・一覧・履歴・フィード・検索の各 API から利用できるようになった構成を示しています。

⚙️ 主要機能

📡 対応 API

✓ ExportAssets: BigQuery / Cloud Storage へのアセット一括エクスポート
✓ ListAssets / QueryAssets: アセットの一覧取得と SQL によるクエリ
✓ BatchGetAssetsHistory: 指定期間におけるアセットの構成変更履歴の取得
✓ Feed: Pub/Sub を介したアセット変更のリアルタイム通知
✓ Search API (SearchAllResources / SearchAllIamPolicies): 組織・フォルダ・プロジェクト横断のリソース / IAM ポリシー検索

🆕 追加されたリソースタイプ

Cloud Service Mesh: networkservices.googleapis.com/AgentGateway

🤖 AgentGateway リソースの概要 (Cloud Service Mesh / Network Services API)

✓ AI エージェント・MCP サーバー・ツールへの接続を統制するゲートウェイリソース
✓ デプロイモード: Google マネージド (googleManaged) またはセルフマネージド (selfManaged、既存の Application Load Balancer / Secure Web Proxy にアタッチ)
✓ ガバナンス対象のアクセスパス: AGENT_TO_ANYWHERE (エージェントから宛先への接続) / CLIENT_TO_AGENT (エージェント・ツールへの接続の保護)
✓ Agent Registry (agentregistry.googleapis.com) との連携、PSC-Interface 経由の Egress や DNS ピアリングなどのネットワーク構成をサポート

💻 検索・エクスポートの例

Bash gcloud asset コマンド例 
# 組織内の AgentGateway リソースを横断検索
gcloud asset search-all-resources \
  --scope="organizations/ORG_ID" \
  --asset-types="networkservices.googleapis.com/AgentGateway"

# AgentGateway を含むアセットを BigQuery へエクスポート
gcloud asset export \
  --organization="ORG_ID" \
  --content-type=resource \
  --asset-types="networkservices.googleapis.com/AgentGateway" \
  --bigquery-table="projects/PROJECT_ID/datasets/DATASET/tables/TABLE" \
  --output-bigquery-force

✅ メリット

💼 ビジネス面: AI エージェント基盤のガバナンス強化

エージェントゲートウェイの配置状況を組織横断で可視化でき、シャドー IT 的なエージェント接続経路の検出に役立つ。

💼 ビジネス面: 監査・コンプライアンス対応の効率化

構成変更履歴 (BatchGetAssetsHistory) により、監査時のエビデンス収集を Cloud Asset Inventory に一本化できる。

🔧 技術面: 一元的なインベントリ管理

他の Google Cloud リソースと同じツール (gcloud asset、BigQuery エクスポート、SQL クエリ) で AgentGateway を扱える。

🔧 技術面: リアルタイム変更検知

Feed + Pub/Sub により、AgentGateway の作成・変更・削除を検知して自動対応 (通知、ポリシーチェックなど) を組める。

⚠️ デメリット・制約事項

⚠️ 考慮すべき点:
  • 今回のリリースノートで公開が明記されたのは networkservices.googleapis.com/AgentGateway の 1 タイプのみ。各アセットタイプの API 対応状況 (分析 API での利用可否など) はサポートされているアセットタイプ一覧で最新情報を確認すること
  • AgentGateway リソース自体の作成・管理は Cloud Service Mesh (Network Services API) 側の機能であり、Cloud Asset Inventory は読み取り (棚卸し・検索・履歴) のみを提供する

💡 ユースケース

🗂️ ユースケース 1: AI エージェントゲートウェイの組織横断棚卸し

シナリオ: 複数プロジェクトで AI エージェントや MCP サーバーを運用している組織が、どのプロジェクトにどの AgentGateway が存在するかを定期的に棚卸ししたい。

Bash 実装例 
gcloud asset search-all-resources \
  --scope="organizations/ORG_ID" \
  --asset-types="networkservices.googleapis.com/AgentGateway" \
  --format="table(name, location, createTime)"

効果: プロジェクトごとに Network Services API を照会する必要がなくなり、1 コマンドで組織全体の AgentGateway を把握できる。

🔔 ユースケース 2: AgentGateway 構成変更のリアルタイム監視

シナリオ: セキュリティチームが、エージェント接続のガバナンスポイントである AgentGateway の構成変更 (作成・変更・削除) を即時に検知したい。
