☁️ Managed Service for Apache Airflow
開発モード環境 & ハイバネーションが GA 🎉

リリース日: 2026-10-13 | Google Cloud Managed Service for Apache Airflow (旧 Cloud Composer)
GA (一般提供) Managed Airflow (Gen 3) Airflow 3 コスト最適化

📋 概要

Managed Airflow (旧 Cloud Composer) で開発モード環境 (Development mode environments) と 環境ハイバネーション (Environment hibernation) が一般提供 (GA) になりました。 Airflow 3 を使用する Gen 3 環境を開発モードで作成し、本番公開前の DAG のテスト・開発に利用できます。

開発モード環境は不要なときにハイバネーション (休止) でき、休止中は Airflow コンポーネントが完全に停止して 環境コストの大部分がゼロになります。必要になったら再開 (Resume) するだけで、環境の再作成なしに開発を続行できます。

💡 Apache Airflow は DAG の強力な分離機構を提供しないため、本番とは別のテスト・開発用環境の維持が公式に推奨されています。 本アップデートで「使うときだけ起動し、使わないときはほぼゼロコストで保持する」運用が GA 機能として可能になりました。

❌ Before (アップデート前の課題)

✗開発用環境でも、未使用時間帯にスケジューラーや Web サーバーが稼働し続けコストが発生
✗コストを抑えるには環境の削除・再作成しかなく、設定や接続情報の復元に手間
✗GA でなかったため、本番を支える開発フローへの正式採用がためらわれるケースも

✅ After (アップデート後の改善)

✓Gen 3 + Airflow 3 の環境を開発モードで作成し、本番公開前の DAG テストに利用可能 (GA)
✓ハイバネーションで Airflow コンポーネントを停止し、コストの大部分をゼロに (休止中は保存分の DCU のみ消費)
✓Console のボタン / gcloud beta composer environments hibernate・resume / API で簡単に休止・再開
✓スナップショットの保存・読み込みで、他の環境と DAG やデータを転送可能

⚡ 主要機能

🧪 1. 開発モード環境 GA

→開発用途専用の環境タイプ。Managed Airflow (Gen 3) + Airflow 3 で作成
→Small 環境サイズのプリセットと標準レジリエンスモードで動作し、低コストで開発・テスト環境を用意
→スナップショットの保存・読み込みに対応し、DAG やデータを他の環境と相互に転送可能

💤 2. 環境ハイバネーション GA

→開発モード環境を使用しない期間に休止させる機能
→休止中は Airflow コンポーネントが稼働せず、DAG 実行の作成・キュー・スケジュールは行われない。環境バケットからの DAG のパース・同期も停止
→composer-user-workloads 名前空間の Pod も停止
→休止した環境コンポーネントの保存分の DCU のみを消費し、環境コストの大部分がゼロに

🖱️ 3. 簡単な休止・再開操作

→Google Cloud コンソールの環境詳細ページから「Hibernate」「Resume」ボタンで操作可能
→gcloud beta composer environments hibernate / resume コマンド、または Cloud Composer API (v1beta1 の environments:hibernate / environments:resume) でも操作可能

ステップ 1: 開発モード環境の作成

Bash --enable-development-mode フラグを指定して作成 
gcloud beta composer environments create ENVIRONMENT_NAME \
  --location LOCATION \
  --enable-development-mode

ステップ 2: 環境のハイバネーション

Bash 環境を休止 (Console では「Hibernate」ボタン) 
gcloud beta composer environments hibernate ENVIRONMENT_NAME \
  --location LOCATION
HTTP Cloud Composer API (v1beta1) 
POST https://composer.googleapis.com/v1beta1/projects/PROJECT/locations/LOCATION/environments/ENVIRONMENT:hibernate

ステップ 3: 環境の再開

Bash 環境を再開 (Console では「Resume」ボタン、API は environments:resume) 
gcloud beta composer environments resume ENVIRONMENT_NAME \
  --location LOCATION

💼 ビジネス面

✓開発環境コストの大幅削減: 夜間・週末などに休止することで環境コストの大部分をゼロに。削除・再作成が不要なため運用負荷も削減
✓GA による正式サポート: 本番の開発フローに安心して組み込める

⚙️ 技術面

✓本番と分離した安全な DAG 開発: 専用の開発モード環境でテストし、本番 DAG への干渉を防止
✓迅速な休止・再開: Console ワンクリック / gcloud / API で操作でき、環境の状態 (DAG やデータ) は保持
✓スナップショットによるデータ移行: 開発モード環境と本番環境の間で DAG やデータを転送可能

⚠️ デメリット・制約事項

🚧 制限事項

✗Managed Airflow (Gen 3) + Airflow 3 の組み合わせのみ対応
✗環境サイズは Small プリセット固定で、Airflow コンポーネント数やリソース上限は変更不可
✗レジリエンスモードは標準のみ (高レジリエンスは利用不可)
✗既存の環境を開発モードに切り替えることはできない (新規作成時に指定が必要)
✗ハイバネーション中は環境の更新・アップグレードができない
✗開発専用であり、本番用途での使用は非推奨

🤔 考慮すべき点

⚠️ 注意:
  • DAG のスケジュールとキャッチアップ設定はハイバネーション期間を考慮する必要がある。キャッチアップ設定時は、再開後にハイバネーション期間分の DAG 実行が作成される可能性がある
  • ハイバネーション中でも、メンテナンスウィンドウ内の自動アップグレードが実行される場合がある
  • hibernate / resume コマンドは現時点で gcloud beta トラックで提供

🎯 ユースケース

🕐 ユースケース 1: 業務時間のみ稼働する DAG 開発環境

シナリオ: データエンジニアリングチームが平日の業務時間だけ DAG の開発・テストを行う。夜間や週末は開発環境が不要。

Bash 実装例 
# 業務終了時に休止
gcloud beta composer environments hibernate dev-airflow --location asia-northeast1

# 翌営業日に再開
gcloud beta composer environments resume dev-airflow --location asia-northeast1
✅ 効果: 環境を削除せずに非稼働時間のコストの大部分をゼロにでき、再開後は DAG や設定がそのまま利用できる。

🚦 ユースケース 2: 本番公開前の DAG 検証パイプライン

シナリオ: 新しい DAG や Airflow 3 向けに書き換えた DAG を、本番環境に影響を与えずに検証したい。

✅ 効果: 開発モード環境で DAG をテストし、スナップショットを活用して検証済みの DAG やデータを本番環境へ転送できる。Airflow の DAG 分離の弱さに起因する本番への干渉リスクを回避。

💰 料金

Managed Airflow の料金は DCU (コンピュートユニット) ベースの従量課金です。開発モード環境は Small 環境サイズのプリセットで動作します。

💡 ハイバネーション中は、休止した環境コンポーネントの保存分の DCU のみを消費し、環境コストの大部分がゼロになります (公式ドキュメントより)。具体的な単価は料金ページを参照してください。

📝 まとめ

開発モード環境とハイバネーションの GA により、Managed Airflow (Gen 3) で「使うときだけ稼働し、使わないときはほぼゼロコスト」の DAG 開発環境を正式に運用できるようになりました。 本番とは別の開発環境を常時稼働させているチームは、開発モード環境への移行とハイバネーション運用の導入を検討することで、環境コストを大幅に削減できます。 導入時は、Airflow 3 / Small プリセット固定などの制約と、再開後のキャッチアップ実行の挙動に注意してください。
