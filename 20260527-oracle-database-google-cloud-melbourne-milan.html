🗄️ Oracle Database@Google Cloud: メルボルン・ミラノリージョン新規追加

Oracle Database@Google Cloud GA 新リージョン追加
2026-05-27

📋 概要

Oracle Database@Google Cloud において、Exadata Database Service on Exascale Infrastructure、Base Database Service、Goldengate の3つのサービスに、オーストラリアのメルボルンとイタリアのミラノが新たに追加されました。

Oracle と Google Cloud のパートナーシップによるマルチクラウド戦略の一環として、エンタープライズ顧客がグローバルに Oracle データベースワークロードを展開するための選択肢が拡大されました。

⚡ 主要機能

🔷 Exadata Database Service on Exascale Infrastructure

→メルボルン (australia-southeast2-a-r2) で Exascale VM Clusters と Storage Vaults の作成が可能に
→ミラノ (europe-west8-b-r1) で同様のリソース作成が可能に
→従来の Exadata に比べてより柔軟なスケーリングが可能な次世代インフラストラクチャ

🔷 Base Database Service

→メルボルン (australia-southeast2-a-r2) で DB System リソースの作成が可能に
→ミラノ (europe-west8-b-r1 および europe-west8-a-r1) の2つのゾーンで利用可能に
→シングルノードまたは2ノードの RAC 構成のデータベースシステムを提供

🔷 Goldengate

→メルボルン (australia-southeast2-a-r2) で Goldengate デプロイメント作成が可能に
→ミラノ (europe-west8-b-r1 および europe-west8-a-r1) の2つのゾーンで利用可能に
→リアルタイムデータレプリケーションとデータ統合をこれらの新リージョンで実行可能

🛠️ 設定方法

📋 前提条件: Oracle Database@Google Cloud のオーダー完了、OCI アカウント連携 (オンボーディング) 完了、ODB Network が対象リージョンに設定されていること。

ステップ 1: ODB Network の作成

Bash 
# Google Cloud CLI を使用して ODB Network を作成
gcloud oracle-database odb-networks create my-odb-network \
  --location=australia-southeast2 \
  --project=my-project \
  --cidr=192.168.1.0/24

ステップ 2: Exascale VM Cluster の作成

Bash 
# メルボルンリージョンで Exascale VM Cluster を作成
gcloud oracle-database exascale-vm-clusters create my-exascale-cluster \
  --location=australia-southeast2 \
  --zone=australia-southeast2-a-r2 \
  --project=my-project \
  --odb-network=my-odb-network

ステップ 3: DB System の作成 (Base Database Service)

Bash 
# ミラノリージョンで DB System を作成
gcloud oracle-database db-systems create my-db-system \
  --location=europe-west8 \
  --zone=europe-west8-b-r1 \
  --project=my-project \
  --odb-network=my-odb-network

✅ メリット

ビジネス面

🏛️データレジデンシーの確保: オーストラリアおよびイタリアのデータ主権要件に対応。GDPR や Privacy Act への準拠が容易に
🌍グローバル展開の加速: メルボルンとミラノに拠点を持つ企業が Oracle ワークロードを現地で運用可能に
💰コスト最適化: 最寄りリージョン利用により、クロスリージョンのデータ転送コストを削減

技術面

⚡低レイテンシ: 地理的に最も近いリージョンの利用でネットワークレイテンシが大幅に改善
🛡️高可用性構成の強化: ミラノの複数ゾーン (europe-west8-b-r1 / europe-west8-a-r1) でのディザスタリカバリ構成が可能
🔄Goldengate レプリケーション: 新リージョン対応により、グローバルなデータレプリケーションのトポロジー設計が柔軟に

⚠️ デメリット・制約事項

制限事項:
  • Exascale Infrastructure はミラノで europe-west8-b-r1 のみ対応 (europe-west8-a-r1 は Base DB と Goldengate のみ)
  • 料金は Oracle が設定しており、リージョンによって異なる可能性あり
  • リソース作成には事前に ODB Network の設定が必要 (同一リージョン・ゾーン内でのみ通信可能)

考慮すべき点

⏱️新リージョンでの初期利用時は一部リソースの provisioning に時間がかかる場合あり
🤖Autonomous AI Database Service は今回のアップデートに含まれない
📝Private Offer 利用時は新リージョンの利用条件について Oracle セールスへの確認を推奨

💡 ユースケース

🏦 ユースケース 1: オーストラリア金融機関のデータベース移行

シナリオ: メルボルンに本社を置く金融機関が、オンプレミスの Oracle DB を Google Cloud に移行。オーストラリア国内にデータ保持が必要。

Bash 
# メルボルンリージョンで Base Database Service を使用
gcloud oracle-database db-systems create finance-db \
  --location=australia-southeast2 \
  --zone=australia-southeast2-a-r2 \
  --project=finance-prod \
  --odb-network=finance-network \
  --shape=VM.Standard.E4.Flex \
  --node-count=2

効果: オーストラリアのデータレジデンシー要件を満たしつつ、Google Cloud 上で Oracle DB を運用。レイテンシ最小限。

🏭 ユースケース 2: ヨーロッパ圏でのデータレプリケーション

シナリオ: イタリアに拠点を持つ製造業企業が、ロンドン本社 DB からミラノへのリアルタイムデータレプリケーションを必要としている。

Bash 
# Goldengate をミラノで展開してレプリケーション設定
gcloud oracle-database goldengate-deployments create eu-replication \
  --location=europe-west8 \
  --zone=europe-west8-b-r1 \
  --project=manufacturing-prod \
  --odb-network=eu-network

効果: ロンドン - ミラノ間のリアルタイムデータレプリケーション実現。GDPR 準拠のデータ配置とヨーロッパ圏内での低レイテンシ同期が可能。

💳 料金情報

Oracle Database@Google Cloud の料金は Oracle が設定しており、利用形態に応じて2つのオファータイプがあります。

オファータイプ 概要 課金方式
Public (Pay-As-You-Go) 標準のオンデマンド料金モデル OCPU 時間、ストレージ GB 単位で従量課金
Private 長期契約やカスタム価格モデル Oracle セールスとの個別交渉による固定料金またはコミット割引

料金構成要素

リソース 課金単位 備考
OCPU 時間あたり サービスタイプにより単価が異なる
ストレージ GB あたり Exascale Storage Vault の容量に基づく
データ転送 GB あたり リージョン間転送に適用
