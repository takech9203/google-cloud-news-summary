🔒 VPC Service Controls が App Optimize API との統合を Preview でサポート

コスト・使用率データをサービス境界の内側で安全に扱える時代へ
📅 リリース日: 2026-10-29
機能: App Optimize API 統合の Preview サポート

📋 概要

VPC Service Controls が App Optimize API (appoptimize.googleapis.com) との統合を Preview としてサポートしました。 サービス境界 (Service Perimeter) の制限対象サービスに App Optimize API を追加し、境界による保護の対象にできます。 Preview 段階ながら既知の制限事項はなく、境界内で API を通常どおり利用できます。

App Optimize API は、Google Cloud リソースのコストと使用状況を把握・監視・最適化するためのプログラマティックな API です (API 自体も Preview)。 プロジェクトや App Hub アプリケーション単位で、金額コスト、CPU / メモリ使用率 (平均・95 パーセンタイル)、リソース割り当てなどを SQL クエリ結果に似た表形式で取得でき、 カスタムダッシュボード構築、BigQuery への定期エクスポート、デプロイパイプラインへのコストチェック組み込みなどの FinOps ユースケースに利用されます。

💡 なぜ重要か: コストデータは組織の支出状況を示す機密性の高い情報です。データ境界による保護を必須とする金融・公共などの規制業種では、VPC Service Controls 対応が API 採用の前提条件になることが少なくありません。今回の統合で、サービス境界を運用する組織でもデータ漏洩リスクを抑えながらコスト最適化ワークフローを構築できます。

😣 Before: アップデート前の課題

  • ❌ App Optimize API は VPC Service Controls の統合対象外。Restricted VIP (restricted.googleapis.com) や Private Service Connect (vpc-sc バンドル) 環境からのアクセスがブロックされていた
  • ❌ 境界内プロジェクトではコンソールからの Gemini Cloud Assist 有効化がエラーになり、gcloud CLI での回避が必要だった
  • ❌ 機密性の高いコスト・使用状況データなのに、境界によるデータ漏洩 (Exfiltration) 対策を適用できなかった

😊 After: アップデート後の改善

  • ✅ 制限対象サービスに appoptimize.googleapis.com を追加し、境界による保護を構成可能に
  • ✅ コスト・使用率レポートの生成と読み取りをデータ境界の内側で完結できる
  • ✅ 既知の制限事項なし。Ingress / Egress ルールやアクセスレベルによるきめ細かなアクセス制御を適用できる

サービス境界に appoptimize.googleapis.com を追加すると、境界内のワークロードからのレポート生成・読み取りは通常どおり動作し、 境界外からの未許可アクセスはブロックされます。境界外からのアクセスが必要な場合はアクセスレベルや Ingress ルールで明示的に許可します。

⚡ 主要機能

🛡️ 1. サービス境界による App Optimize API の保護 (Preview)

→サービス境界の制限対象サービスに appoptimize.googleapis.com を指定可能に
→境界外からの未許可アクセスをブロックし、コスト・使用率データの漏洩リスクを低減
→統合に既知の制限事項はなく、境界内では API を通常どおり利用可能

📊 2. 保護対象となる App Optimize API の機能

→レポート生成 (reports.create): プロジェクト、個別リソース、SKU、期間、App Hub アプリケーション / サービス / ワークロードなどのディメンションで集計したコスト・使用率レポートを非同期生成
→レポート読み取り (reports.read): 金額コスト、CPU / メモリ使用率 (平均・95 パーセンタイル)、CPU コア / メモリの使用量と割り当てを表形式で取得
→CEL (Common Expression Language) によるフィルタリング、AI アプリケーション向けリモート MCP サーバーも提供

🔑 3. VPC Service Controls の標準機能との組み合わせ

→Ingress / Egress ルールにより、境界をまたぐアクセスを ID・送信元・メソッド単位で制御可能
→Access Context Manager のアクセスレベル (IP サブネットワーク、地理的リージョン、デバイスポリシー) と組み合わせたコンテキストアウェアなアクセス制御が可能

🛠️ 設定方法

📌 前提条件:
✓組織で Access Context Manager のアクセスポリシーが作成済みで、サービス境界を構成・更新する権限 (Access Context Manager Editor など) があること
✓保護対象プロジェクトで App Optimize API が有効化されていること
1

App Optimize API を有効化する

レポートを作成・管理するプロジェクトで App Optimize API を有効化します。

gcloud services enable appoptimize.googleapis.com --project=PROJECT_ID
2

サービス境界の制限対象サービスに追加する

既存のサービス境界の制限対象サービスに appoptimize.googleapis.com を追加します。適用前に Dry-run モードで影響を確認することを推奨します。

gcloud access-context-manager perimeters update PERIMETER_NAME \
  --add-restricted-services=appoptimize.googleapis.com \
  --policy=POLICY_ID
3

必要に応じて Ingress / Egress ルールを構成する

境界外のクライアント (社内ネットワークの FinOps ダッシュボードなど) から App Optimize API にアクセスする必要がある場合は、アクセスレベルや Ingress ルールで許可する ID と送信元を明示的に構成します。

✨ メリット

💼 ビジネス面

✓規制業種での採用障壁の解消: データ境界による保護を必須とする組織でも、コスト最適化 API をコンプライアンス要件を満たしながら利用できる
✓コストデータの漏洩リスク低減: 組織の支出状況や使用率という機密性の高いデータへのアクセスを境界で制御し、未許可の外部持ち出しを防止できる

⚙️ 技術面

✓境界内での FinOps ワークフロー完結: Cloud Run + Cloud Scheduler による定期レポートエクスポートやカスタムダッシュボードを、サービス境界の内側で構築できる
✓制限事項なしの統合: Preview ながら既知の制限事項がなく、他の対応サービスと同じ運用モデル (Ingress / Egress ルール、アクセスレベル) で管理できる
✓Gemini Cloud Assist との関係改善: 境界内プロジェクトでのコンソールからの有効化エラー (App Optimize API の VPC Service Controls 未サポートに起因する既知の制限) の前提条件を解消する方向のアップデート

⚠️ デメリット・制約事項

🚧 制限事項

▲統合は Preview 段階であり、Pre-GA Offerings Terms が適用される。「現状のまま」提供され、本番環境向けの完全サポートではない
▲App Optimize API 自体も Preview (v1beta) であり、API の仕様変更の可能性がある
▲生成されたレポートは 24 時間後に自動削除されるため、長期保存には外部へのエクスポートが必要 (エクスポート先も境界設計に含める必要がある)

🤔 考慮すべき点

→制限対象サービスに追加すると、境界外からの既存のアクセス (例: 社外の分析ツールからの API 呼び出し) が拒否される。Dry-run モードで影響範囲を確認してから適用するべき
→App Optimize API は Cloud Billing、Cloud Monitoring、App Hub のデータを参照する。権限チェックやデータ取得が境界をまたがないよう、関連サービスと対象プロジェクトを同一境界内に収める設計が望ましい
→レポートデータを BigQuery などに取り込む場合は、取り込み先サービスも境界の制限対象・VPC accessible services の設計に含める必要がある

🚫 ユースケース 2: 未許可クライアントからのコストデータ取得のブロック

シナリオ: 組織のコストデータへのアクセスを社内ネットワークと特定のサービスアカウントに限定したい。境界外の端末や不正に取得された認証情報による API 呼び出しをブロックしたい。

効果: appoptimize.googleapis.com を制限対象サービスに追加することで、境界外からの呼び出しは IAM 権限があってもブロックされる。正当なアクセスは IP サブネットワークや地理的リージョンに基づくアクセスレベルと Ingress ルールで明示的に許可でき、認証情報漏洩時のコストデータ流出リスクを低減できる。

💰 料金

✅ 追加料金なし: VPC Service Controls でのサービス境界の構成に伴う App Optimize API 側の追加料金はありません。App Optimize API は Preview 期間中、レポートの作成・読み取り・メタデータ取得を含めて追加料金なしで利用できます。

ただし、App Optimize API にデータを提供する以下のサービスには、それぞれの料金が適用される場合があります。

→Cloud Billing の料金
→App Hub の料金
→Cloud Monitoring の料金

🔗 関連サービス・機能

→App Optimize API: 今回 VPC Service Controls の保護対象に加わった、コスト・使用率レポート生成 API。プロジェクトと App Hub アプリケーション単位の分析が可能
→Access Context Manager: サービス境界とアクセスレベルを管理するサービス。境界外からの正当なアクセスを許可する際に使用
→App Hub: App Optimize API がアプリケーション単位のコスト集計に使用するアプリケーション管理サービス
→Cloud Billing / Cloud Monitoring: App Optimize API のコストデータと使用率メトリクスのデータソース
→Gemini Cloud Assist: コンソールからの有効化時に App Optimize API を要求するサービス。境界内プロジェクトでの有効化エラーの既知の制限と関係が深い

📝 まとめ

VPC Service Controls が App Optimize API を Preview でサポートしたことで、サービス境界を運用する組織でもコスト・使用率データをデータ境界の内側で安全に扱えるようになりました。 既知の制限事項がない統合であり、FinOps ワークフローをセキュアに構築する土台が整います。

🚀 サービス境界を利用中でコスト最適化の自動化を検討しているチームは、Dry-run モードで影響を確認しつつ、appoptimize.googleapis.com の制限対象サービスへの追加を試してみることをおすすめします。
