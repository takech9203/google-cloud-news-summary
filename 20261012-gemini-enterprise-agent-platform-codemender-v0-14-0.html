📝 概要

Gemini Enterprise Agent Platform 上で提供される AI コードセキュリティエージェント CodeMender が v0.14.0 にアップデート。 CodeMender はコードベースの脆弱性をスキャン (cm find)、検証 (cm verify)、修正 (cm fix) する自律型エージェントで、 推論は Google Cloud 側でホスト、コードの読み取りや PoC 実行はローカルの cm CLI サンドボックス内で行う ローカルファースト設計を採用している。

→
✅ cm verify
検証

🔧 cm fix
修正

v0.14.0 では cm find --diff が削除されたセキュリティ制御を検知可能になり、 --diff-job-timeout によるタイムアウト調整、--deep / --diff スキャンの 単一セッション統合、cm verify によるコード移動の自動追跡など、 スキャンから検証までのワークフロー全体の精度と使い勝手が向上した。 CI/CD の PR ゲートや定期監査に CodeMender を組み込むチームにとって、誤検知の削減と運用の簡素化につながるアップデートである。

❌ Before (アップデート前の課題)

  • cm find --diff はセキュリティ制御の「削除」の検知が不十分
  • 大きなファイルのスキャンがタイムアウトしやすく、調整手段がなかった
  • --deep / --diff がセッション管理上は別々で、横断的な把握がしづらい
  • スキャン後にコードが移動すると cm verify が Finding の位置を見失うことがあった
  • 未アクティベート時はエラー終了のみで、ユーザーが自分でページを探す必要があった
  • ネストされたシンボリックリンクでのスキャン失敗、存在しないファイルへの Finding、過剰マージの不具合

✅ After (v0.14.0 での改善)

  • 削除されたセキュリティ制御を検知し、PR での「保護の後退」を見逃しにくく
  • --diff-job-timeout で大きなファイルの処理時間を設定可能
  • cm session list / cm report / cm stats で単一セッションとして統合表示
  • cm verify が移動したコードを追跡し、Finding の位置を自動更新
  • アクティベーションページを自動で開き、完了を待機するガイド付きフロー
  • 新フラグ --deep-max-turns / --enable-bash を追加
  • Finding 分離精度の向上、弱いハッシュ・乱数生成の CWE 分類が正確に

💡 ポイント: v0.14.0 では --diff と --deep の両スキャンが単一セッションとして統合管理され、 cm verify がコード移動後も Finding の位置を正しく追跡できるようになった。 推論は Gemini Enterprise Agent Platform 側で、コードの読み取りや検証はローカルサンドボックスで実行される。

⚡ 主要機能

1. 🔍 プルリクエストスキャンの強化 (cm find --diff)

  • 削除されたセキュリティ制御を検知。従来の「追加されたコードの脆弱性検知」に加え、変更によって既存の防御が取り除かれる「後退」も捕捉
  • 大きなファイルにはより長い処理時間が与えられ、--diff-job-timeout フラグでタイムアウトを設定可能

2. 📒 セッションの統合 (Unified sessions)

  • --deep と --diff のスキャンが cm session list、cm report、cm stats 上で単一セッションとして表示
  • スキャンモードをまたいだ Finding の確認・集計・レポート出力が一元化され、運用の見通しが向上

3. 🎯 cm verify でのコード移動追跡

  • cm find の実行後にリファクタリング等でコードが移動していても、移動先を特定し Finding の位置情報を更新
  • スキャンと検証の間に開発が進んでも、Finding が「迷子」にならない

4. 🚀 ガイド付きアクティベーション

  • 未アクティベート状態で cm を実行すると、エラー終了する代わりにアクティベーションページを自動で開き、完了を待機

5. 🚩 cm find の新フラグ

  • --deep-max-turns: --deep スキャンにおけるファイルごとの探索ステップ数を制限
  • --enable-bash: スキャン中のシェルコマンド実行を許可

6. 📈 検知精度の向上

  • ファイルごとに、より明確に分離された Finding を生成
  • 脆弱なハッシュ (weak hashing) と乱数生成 (randomness) に対する CWE 分類がより正確に

7. 🐛 バグ修正

  • ネストされたシンボリックリンク経由で到達するリポジトリのスキャン失敗を修正
  • 存在しないファイルに対する Finding と、過剰にマージされた Finding を修正
  • cm verify が生成するシェルスクリプトが実行可能 (executable) に

🚩 cm find の主要フラグ (v0.14.0 時点)

フラグモード説明
--diff[=REF]Diff対象リファレンス (例: origin/main) との差分をスキャン
--diff-job-timeoutDiff大きなファイルのスキャンジョブのタイムアウトを設定 (v0.14.0 新規)
--stagedDiffステージ済みの変更のみを対象 (pre-commit 用)
--fail-on SEVERITIESDiff指定した重大度の検出時に終了コード 1 を返す (既定: CRITICAL,HIGH)
--deepDeepリポジトリ全体の網羅的スキャン

--model MODEL_NAME共通使用する Gemini モデル (gemini-3.8-flash / gemini-3.8-flash-cyber)

⚙️ 設定方法

📋 前提条件

✓Vertex AI API (aiplatform.googleapis.com) と Cloud Resource Manager API (cloudresourcemanager.googleapis.com) の有効化
✓IAM ロール Vertex AI User (roles/aiplatform.user) の付与
✓CodeMender は Public Preview のため、利用には対象顧客としてのアクセスが必要

ステップ 1: CodeMender CLI のインストール (Linux x86_64 の例)

Bash Artifact Registry から CLI を取得 
gcloud artifacts generic download \
  --project=cmoc-prod \
  --location=us \
  --repository=codemender-cli-production \
  --package=cm \
  --version=stable \
  --name=cm-linux-amd64.zip \
  --destination=./

unzip cm-linux-amd64.zip
chmod +x cm
sudo mv cm /usr/local/bin/cm

CLI バイナリは Artifact Registry でホストされている。v0.14.0 からは、未アクティベート時に cm がアクティベーションページを自動で開き、完了を待機する。

ステップ 2: プルリクエストの Diff スキャンを実行

Bash PR ブランチの差分スキャン 
# PR ブランチを main と比較してスキャンし、SARIF で出力
cm find . --diff=origin/main --format=sarif --output=results.sarif \
  --fail-on=CRITICAL,HIGH

# 大きなファイルが多いリポジトリではジョブタイムアウトを調整 (v0.14.0)
cm find . --diff=origin/main --diff-job-timeout=<TIMEOUT>

ステップ 3: Deep スキャンと検証

Bash Deep スキャン・統合セッション・検証 
# ファイルごとの探索ステップを制限しつつ Deep スキャン (v0.14.0)
cm find . --deep --deep-max-turns=<MAX_TURNS>

# 統合セッションを確認
cm session list
cm report
cm stats

# Finding を検証 (コードが移動していても位置を自動更新)
cm verify FINDING_ID

💪 メリット

💼 ビジネス面

✓プルリクエストゲートの信頼性向上: セキュリティ制御の削除という「静かな後退」を自動検知でき、レビュー漏れによるセキュリティ劣化のリスクを低減
✓運用負荷の軽減: ガイド付きアクティベーションとセッション統合により、CLI 導入時・運用時の手間が減り、チームへの展開が容易に

🛠️ 技術面

✓検証ワークフローの堅牢化: cm verify がコード移動を追跡するため、スキャンと検証の間に開発が進む実際のワークフローでも Finding を正確に扱える
✓スキャンの制御性向上: --diff-job-timeout と --deep-max-turns により、リポジトリの特性に応じて実行時間とコスト (トークン消費) を調整可能
✓精度向上による誤検知削減: Finding の分離精度向上と CWE 分類 (弱いハッシュ・乱数) の精緻化、過剰マージ・存在しないファイルへの Finding の修正により、ノイズの少ないレポートを実現

⚠️ デメリット・制約事項

🚧 制限事項

✗CodeMender は Preview (Pre-GA) であり、限定された顧客向けの提供。商用・本番目的での利用は不可で、テスト・評価目的に限定
✗解析対象は、自身が所有または利用を許可されたコード、もしくは OSI 承認ライセンスで配布される OSS に限られる
✗Diff スキャンは PR の影響範囲のみを解析し、変更されていない部分の既存脆弱性は検出しない。Git リポジトリとベースリファレンスへのアクセスが必要
✗Deep スキャンは実行時間が長くトークン消費も多いため、PR をブロックする同期チェックには不向き

🤔 考慮すべき点

→--enable-bash はスキャン中のシェルコマンド実行を許可するフラグであり、サンドボックス設定 (sandbox.enabled、ネットワークプロファイル、protected_files) と合わせてセキュリティポリシーを検討する必要がある
→Pre-GA 製品のため、重大なエラーが修正できない状況では使用せず、人間による監督のもとで利用することが求められる

🎯 ユースケース

🔀 ユースケース 1: プルリクエストでのセキュリティ制御削除の検知

シナリオ: リファクタリングの PR で、入力バリデーションや認可チェックが意図せず削除された。従来の差分スキャンでは「追加されたコードの脆弱性」が中心で、削除による防御の後退は見逃されやすかった。

Bash CI/CD (GitHub Actions / Cloud Build) で PR ごとに実行 
cm find . --diff=origin/main --format=sarif --output=results.sarif \
  --fail-on=CRITICAL,HIGH

効果: 削除されたセキュリティ制御が Finding として報告され、マージ前にブロックできる。SARIF 出力により GitHub Code Scanning のアノテーションとしても確認可能。

🌙 ユースケース 2: 夜間 Deep スキャンと日中の検証の連携

シナリオ: 夜間に cm find --deep でリポジトリ全体を監査し、日中に開発者が cm verify で Finding を検証する運用。日中の開発でコードが移動すると、従来は Finding の位置がずれる問題があった。

📌 まとめ

CodeMender v0.14.0 は、PR スキャンでの「セキュリティ制御の削除」検知、 --deep / --diff セッションの統合、 cm verify によるコード移動の追跡など、 CI/CD と日常運用の両面で実用性を高めるアップデートである。

→PR ゲートには --diff スキャン (必要に応じて --diff-job-timeout を調整) を組み込む
