🗄️ Cloud SQL for MySQL: 8.0.46 サポート開始

Cloud SQL MySQL GA

📋 概要

Cloud SQL for MySQL が MySQL 8.0.46 マイナーバージョンのサポートを開始。MySQL コミュニティによる 2026年4月21日リリースから約2か月で Cloud SQL でのサポートが実現された。セキュリティ修正、バグ修正、パフォーマンス改善を含む重要なアップデート。

❌ Before (アップデート前)

  • 8.0.46 のバグ修正・セキュリティパッチを利用できない
  • InnoDB FTS インデックス構築時のメモリ使用量が最適化されていない
  • OpenSSL 3.5.5 のセキュリティ強化が未適用
  • SQL パーサーが大きな IN 句で大量メモリ消費

✅ After (アップデート後)

  • MySQL 8.0.46 の全バグ修正とセキュリティパッチが利用可能
  • FTS インデックス構築時のメモリ使用量が最適化
  • OpenSSL 3.5.5 で最新セキュリティ修正が適用
  • SQL パーサーのメモリ管理改善で大規模クエリ処理効率向上

🏗️ アップグレードフロー

Cloud SQL for MySQL 8.0 インスタンスを 8.0.46 にアップグレードする際のフロー。手動アップグレードではステージング環境でのテストとレプリカの事前アップグレードが推奨され、自動アップグレード (8.0.35 以降) ではメンテナンスウィンドウ内で自動的に適用される。

⚡ 主要な改善点

🔒 セキュリティ修正

→監査ログ: gzip ファイル処理の問題を修正
→同梱 zlib ライブラリを 1.3.2 にアップグレード
→OpenSSL を 3.5.5 にアップデート

🗃️ InnoDB 改善

→FTS インデックス構築時のメモリ使用量最適化
→マルチバリューインデックスの問題を修正
→パラレルリーダーの問題を修正
→undo テーブルスペース truncate 操作の修正
→--innodb_parallel_read_threads 高設定時のディスク容量枯渇問題を修正

🧠 オプティマイザ改善

→プリペアド DELETE/UPDATE の最適化問題を修正
→セミジョインマテリアライゼーションの不正結果を修正
→const テーブルの条件が範囲推定に一貫反映されない問題を修正
→EXPLAIN 拡張クエリのジョイン順序ヒント構文を修正

📝 SQL パーサー改善

→大量の IN 句を含む非常に大きなクエリのメモリ消費を改善

🔧 設定方法

📋 前提条件: Cloud SQL for MySQL 8.0 インスタンスが稼働 / 対象バージョンが現行より新しい / Cloud SQL Admin API が有効

Step 1: アップグレード可能なバージョンの確認

Bash 
gcloud sql instances describe INSTANCE_NAME

出力の upgradableDatabaseVersions に MYSQL_8_0_46 が含まれていることを確認。

Step 2: ステージング環境でのテスト

Bash 
# 本番インスタンスのクローンを作成
gcloud sql instances clone INSTANCE_NAME STAGING_INSTANCE_NAME

# ステージングインスタンスをアップグレード
gcloud sql instances patch STAGING_INSTANCE_NAME \
  --database-version=MYSQL_8_0_46

Step 3: リードレプリカのアップグレード

Bash 
# リードレプリカを先にアップグレード
gcloud sql instances patch REPLICA_INSTANCE_NAME \
  --database-version=MYSQL_8_0_46

Step 4: プライマリインスタンスのバックアップとアップグレード

Bash 
# バックアップの作成
gcloud sql backups create --instance=INSTANCE_NAME

# プライマリインスタンスのアップグレード
gcloud sql instances patch INSTANCE_NAME \
  --database-version=MYSQL_8_0_46

⚠️ デメリット・制約事項

⚠️ 重要: MySQL 8.0 はダウングレードに対応していないため、一度アップグレードすると以前のバージョンに戻すことはできません。

制限事項

✗アップグレード中はディスクサイズやメモリの同時変更不可
✗自動マイナーバージョンアップグレードは 8.0.35 以降のインスタンスのみ
✗一度有効化した自動アップグレードは無効化不可

考慮すべき点

→本番環境前に必ずステージング環境でワークロードテストを実施
→Enterprise エディションではインスタンス再起動に伴うダウンタイムが発生
→リードレプリカはプライマリインスタンスより先にアップグレードが必要
→アップグレード後にアプリケーションの動作確認を行うこと

🎯 ユースケース

🔍 大量データの全文検索を行うアプリケーション

シナリオ: 大規模テーブルに対して FTS インデックスを構築・更新するアプリケーションで、インデックス構築時のメモリ消費が問題になっている場合。

効果: InnoDB FTS インデックス構築のメモリ最適化により、大規模テーブルのインデックス構築時のメモリ使用量が削減され、OOM のリスクが低減。

📊 複雑な分析クエリを実行するデータパイプライン

シナリオ: 大量の IN 句や複雑なサブクエリを含む分析クエリを定期実行しているバッチ処理で、メモリ消費やクエリ結果の正確性が懸念される場合。

効果: SQL パーサーのメモリ管理改善とオプティマイザのバグ修正により、大規模クエリの安定した実行と正確な結果取得が期待できる。
