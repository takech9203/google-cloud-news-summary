⚠️ Beam Java オペレーターが JAVA_TOOL_OPTIONS 設定時にデッドロックする既知の問題と解決策

🌬️ Managed Service for Apache Airflow (旧 Cloud Composer) 🐛 既知の問題 + 緩和策 📅 2026-11-26
CVE-2026-114938 緩和策の副作用として Beam Java タスクが停止 — パッチ版では JAVA_TOOL_OPTIONS の自動設定を廃止、回避用プラグインも提供

📌 概要

Apache Beam Java オペレーター (BeamRunJavaPipelineOperator / DataflowCreateJavaJobOperator) を使用する Airflow タスクが、CVE-2026-114938 の緩和策としてワーカーに JAVA_TOOL_OPTIONS 環境変数が設定されている場合に応答しなくなる、またはデッドロックする既知の問題が公開されました。11 月 19〜20 日に展開された CVE 対応 (緩和用環境変数の自動設定を含む) の副作用です。

原因は、JAVA_TOOL_OPTIONS 設定時に OpenJDK が起動メッセージ (Picked up JAVA_TOOL_OPTIONS: ...) を stderr へ出力する一方、apache-airflow-providers-apache-beam の Beam フックが stdout を排出する前に stderr を EOF まで読み切る実装になっているためです。Java プロセスが stdout に 64 KB 超を書き込むと OS のパイプバッファが満杯になりデッドロックします。出力が少なくても、タスクログのストリーミングと Dataflow ジョブ ID の検出がサブプロセス終了まで停止します。

対応として、2026 年 11 月 25 日以降、パッチ適用済み OpenJDK 21 を含むビルドでは JAVA_TOOL_OPTIONS が自動設定されなくなりました。解決策はパッチ版へのアップグレード (推奨)、またはすぐにアップグレードできない場合の回避用プラグイン beam_pipe_deadlock_fix.py の導入です。

❌ Before: 問題の発生状況

  • JAVA_TOOL_OPTIONS="-XX:+IgnoreUnrecognizedVMOptions -XX:UseAVX=2" が自動・手動で設定された環境で、Beam Java タスクが running のまま無期限に停止 (デッドロック)、またはサブプロセス終了までログが流れない
  • 影響範囲: 手動設定環境、11/20 より前の Gen 3 ビルド、11/20 ビルドでも 11/26 より前に作成・更新された環境
  • 未パッチ版で環境変数を空にしたり削除しても、OpenJDK は起動メッセージを出力し続け、CVE 緩和も失われるため安全な回避手段がなかった

✅ After: 解決策の提供

  • 11/25 以降、パッチ適用済み OpenJDK 21 を含むビルド (Gen 3: 3.3.1-build.10 / 3.2.2-build.14 / 2.11.1-build.27 以降、Gen 2: composer-2.18.2-airflow-2.11.1 以降) で自動設定を廃止。アップグレードで根本回避が可能に
  • 回避用プラグイン beam_pipe_deadlock_fix.py を GitHub で公開。stderr を stdout にマージして単一リーダーで排出し、CVE 緩和を維持したままデッドロックを防止
  • プラグインは DAG 変更・環境再起動が不要。バケットの plugins/ フォルダへのアップロードだけで適用

💡 主要なポイント

1️⃣ 既知の問題: Beam Java オペレーターのデッドロック

BeamRunJavaPipelineOperator と DataflowCreateJavaJobOperator を使用するタスクが、JAVA_TOOL_OPTIONS 設定時に応答しなくなる、またはデッドロックします。Beam フックが stdout の排出前に stderr を EOF まで読む実装のため、Java プロセスが stdout に 64 KB を超えて書き込むとデッドロック。64 KB 以下でも、ログのストリーミングと Dataflow ジョブ ID の検出がサブプロセス終了まで停止します。

2️⃣ パッチ版ビルドで JAVA_TOOL_OPTIONS の自動設定を廃止 (11/25 以降)

パッチ適用済み OpenJDK 21 を含むビルドでは自動設定が廃止されました。Gen 3: composer-3-airflow-3.3.1-build.10 / 3.2.2-build.14 / 2.11.1-build.27 以降、Gen 2: composer-2.18.2-airflow-2.11.1 以降。OpenJDK 自体がパッチ済みのため、環境変数なしでも CVE-2026-114938 への対応は維持されます。

3️⃣ 解決策 1 (推奨): パッチ版へのアップグレード

パッチ版バージョンへアップグレードし、手動設定した JAVA_TOOL_OPTIONS を削除します。11/20 ビルドを実行中でも、環境の作成・更新が 11/26 より前の場合は、環境の更新オペレーション (例: 環境変数の追加・更新) を 1 回実行すると自動設定された変数がワーカーから削除されます。

4️⃣ 解決策 2 (暫定): beam_pipe_deadlock_fix.py プラグイン

GitHub (GoogleCloudPlatform/python-docs-samples) で公開された回避用プラグインを plugins/ フォルダにインストール。Beam フックの run_beam_command を置き換え、stderr を stdout にマージして単一リーダーで排出することでデッドロックを防ぎます。CVE 緩和は維持され、DAG 変更・環境再起動も不要です。

5️⃣ 注意: 未パッチ版で環境変数を空にしたり削除したりしない

JAVA_TOOL_OPTIONS を空文字に設定しても OpenJDK は起動メッセージを stderr に出力するため問題は解消しません。未パッチ版で削除すると CVE-2026-114938 の緩和が失われます。

ステップ 1: 影響の有無を確認する

ワーカーのタスクログに以下の行が含まれるかを確認します。

Log ワーカーのタスクログ 
Picked up JAVA_TOOL_OPTIONS: -XX:+IgnoreUnrecognizedVMOptions -XX:UseAVX=2

この行が出力されており、Beam Java オペレーターのタスクが running のまま停止する、またはログがサブプロセス終了まで流れない場合は、この既知の問題に該当します。

ステップ 2 (解決策 1・推奨): パッチ版へアップグレードし、手動設定の環境変数を削除する

Bash パッチ版へのアップグレードと環境変数の削除 
# アップグレード可能なバージョンを確認
gcloud composer environments list-upgrades ENVIRONMENT_NAME \
  --location LOCATION

# パッチ版へアップグレード (Gen 2 の例)
gcloud composer environments update ENVIRONMENT_NAME \
  --location LOCATION \
  --image-version composer-2.18.2-airflow-2.11.1

# 手動で設定した JAVA_TOOL_OPTIONS を削除
gcloud composer environments update ENVIRONMENT_NAME \
  --location LOCATION \
  --remove-env-variables JAVA_TOOL_OPTIONS
💡 補足: 既に 11 月 20 日ビルド (3.3.1-build.10 / 3.2.2-build.14 / 2.11.1-build.27) を実行中で 11 月 26 日より前に作成・更新した環境では、環境変数の追加・更新などの環境更新オペレーションを 1 回実行すると、自動設定された JAVA_TOOL_OPTIONS がワーカーから削除されます。
⛔ 注意: 未パッチ版では JAVA_TOOL_OPTIONS を空文字にしたり削除したりしないでください。空でも OpenJDK は起動メッセージを stderr に出力し、削除すると CVE-2026-114938 の緩和が失われます。

ステップ 3 (解決策 2・アップグレードできない場合): 回避用プラグインをインストールする

Bash 回避用プラグインのダウンロードとインストール 
# GitHub からプラグインをダウンロード
curl -O https://raw.githubusercontent.com/GoogleCloudPlatform/python-docs-samples/main/composer/workflows/beam_pipe_deadlock_fix.py

# 環境のバケットの plugins/ フォルダにアップロード
gcloud composer environments storage plugins import \
  --environment ENVIRONMENT_NAME \
  --location LOCATION \
  --source beam_pipe_deadlock_fix.py
✅ ポイント: DAG の変更や環境の再起動は不要です。JAVA_TOOL_OPTIONS による CVE-2026-114938 の緩和は有効なまま維持されます。

ステップ 4: アップグレード後のクリーンアップ

影響を受けないバージョン (手動の JAVA_TOOL_OPTIONS オーバーライドなし)、または apache-airflow-providers-apache-beam の上流修正を含むバージョンへアップグレードした後は、プラグインを削除します。

Bash プラグインの削除 
gcloud composer environments storage plugins delete \
  --environment ENVIRONMENT_NAME \

⚖️ メリットとデメリット・制約事項

👍 メリット

💼 ビジネス面

  • データパイプラインの停止リスクの解消: Beam Java オペレーターを使うワークフローの無期限停止を解消し、Dataflow を使った日次バッチなどの遅延・滞留を防げる
  • セキュリティと可用性の両立: 回避用プラグインで CVE-2026-114938 の緩和を維持したままデッドロックを回避できる

🔧 技術面

  • 根本対応と暫定対応の 2 つの解決パス: アップグレード (根本対応) と plugins/ へのファイル配置だけの回避用プラグイン (暫定対応) から選択可能
  • 導入コストの低い回避策: プラグインは DAG 変更・環境再起動が不要で、provider 5.5〜6.3.2+ と Airflow 2/3 の両方に対応

👀 デメリット・制約事項

🚧 制限事項

  • プラグイン導入中は Beam サブプロセスの stderr 出力が WARNING ではなく INFO レベルで記録される
  • 未パッチ版では JAVA_TOOL_OPTIONS を空文字化・削除できない (問題が解消せず、CVE 緩和も失われる)
  • Managed Airflow バージョンのダウングレードはできないため、アップグレードは計画的に実施する必要がある

🤔 考慮すべき点

  • 11/20 ビルド実行中でも 11/26 より前に作成・更新した環境は自動設定変数が残っている可能性があるため、ワーカーログを確認し、必要に応じて環境の更新オペレーションを実行する
  • パッチ版へのアップグレード後は、手動設定した JAVA_TOOL_OPTIONS を忘れずに削除する
  • 回避用プラグインは恒久対応ではないため、アップグレード完了後の削除までを運用手順に含める

シナリオ: CVE-2026-114938 対応で JAVA_TOOL_OPTIONS を手動設定した Gen 2 環境で Beam Java オペレーターを使用しており、デッドロックの再発リスクを根本的に排除したい。
