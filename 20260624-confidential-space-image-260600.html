🔒 Confidential Space イメージ 260600

コンテナワークロードのグレースフルシャットダウン対応

2026-06-24
Announcement Security

📋 概要

Confidential Space イメージ 260600 がリリースされ、電源ボタンイベント (ACPI power button event) 発生時にコンテナワークロードをグレースフルにシャットダウンする機能が追加されました。

VM の停止・削除・プリエンプション発生時に、ワークロードが処理中のデータを安全に保存し、リソースを適切に解放してから終了できるようになります。

💡 Confidential Space とは: 複数の当事者が機密データを安全に処理するための信頼された実行環境 (TEE: Trusted Execution Environment) を提供するサービス。Confidential VM 上で動作する強化された OS イメージの中で、単一のコンテナワークロードを実行します。

🔄 Before / After 比較

❌ Before (イメージ 260600 以前)

  • VM 停止/削除時にコンテナが即座に強制終了
  • 処理中のデータが失われる可能性
  • Spot VM プリエンプション時にチェックポイント保存の猶予なし
  • ACPI シグナルをコンテナが受信不可
  • シャットダウンスクリプトによるクリーンアップ不可

✅ After (イメージ 260600 以降)

  • ACPI G2 Soft Off シグナルが適切に伝搬
  • コンテナが SIGTERM を受信しクリーンアップ可能
  • チェックポイント保存の時間を確保
  • リソースの適切な解放が可能
  • データ整合性と運用信頼性が向上

🏗️ アーキテクチャ図: グレースフルシャットダウンフロー

電源ボタンイベント発生時のシグナル伝搬とグレースフルシャットダウンの流れを示します。

sequenceDiagram
    participant GCE as Compute Engine
    participant CS as Confidential Space Image
    participant CL as Container Launcher
    participant WL as Workload Container

    Note over GCE,WL: 通常運用中
    GCE->>CS: 電源ボタンイベント (ACPI G2 Soft Off)
    CS->>CL: シャットダウンシグナル検知
    CL->>WL: SIGTERM 送信
    Note over WL: グレースフルシャットダウン処理開始
    WL->>WL: チェックポイント保存
    WL->>WL: リソース解放
    WL->>WL: 接続クローズ
    WL->>CL: 正常終了 (exit 0)
    CL->>CS: コンテナ停止完了
    CS->>GCE: シャットダウン完了
    Note over GCE: VM 状態: TERMINATED

Compute Engine からの ACPI シグナルが Confidential Space イメージを経由して Container Launcher に伝わり、最終的にワークロードコンテナが SIGTERM を受け取ってクリーンアップ処理を実行します。

⚡ 主要機能

1. 電源ボタンイベントの検知とシグナル伝搬

✓ Confidential Space イメージが ACPI G2 Soft Off シグナルを検知
✓ Container Launcher がシグナルを SIGTERM としてワークロードに伝搬
✓ VM の停止、削除、プリエンプションなど全シャットダウンシナリオに対応

2. コンテナワークロードのグレースフル終了

✓ SIGTERM を受信しアプリケーションレベルでクリーンアップ処理を実行可能
✓ トランザクション完了、一時ファイル削除、ネットワーク接続クローズを実行
✓ タイムアウト後は SIGKILL で強制終了 (VM シャットダウン完了を保証)

3. 既存のリスタートポリシーとの統合

✓ tee-restart-policy メタデータ変数 (Never / Always / OnFailure) と連携
✓ グレースフルシャットダウン後のコンテナ再起動動作を制御可能
✓ 本番環境とデバッグ環境の両方で利用可能

💻 実装例: SIGTERM ハンドラ

ワークロードコンテナで SIGTERM を受信してクリーンアップ処理を実行する Python の実装例です。

Python 
import signal
import sys

def graceful_shutdown(signum, frame):
    """SIGTERM ハンドラ: クリーンアップ処理を実行"""
    print("Graceful shutdown initiated...")
    # チェックポイントの保存
    save_checkpoint()
    # リソースの解放
    release_resources()
    # 接続のクローズ
    close_connections()
    sys.exit(0)

# SIGTERM ハンドラの登録
signal.signal(signal.SIGTERM, graceful_shutdown)
⚠️ 重要: Dockerfile で ENTRYPOINT を exec 形式 (JSON 配列) で指定し、アプリケーションプロセスを PID 1 として実行することで、SIGTERM を直接受信できます。
Dockerfile 
FROM python:3.11-slim

COPY app.py /app/app.py

# SIGTERM を PID 1 に直接送信するため exec 形式を使用
ENTRYPOINT ["python", "/app/app.py"]

🎯 ユースケース

🤖 ユースケース 1: マルチパーティ ML 推論パイプラインでの安全な停止

複数の組織が機密データを持ち寄り、Confidential Space 上で共同 ML 推論を実行。Spot VM でコスト最適化しつつ、プリエンプション発生時に中間結果を安全に保存。

Python 
import signal
from google.cloud import storage

def save_intermediate_results(signum, frame):
    """プリエンプション時に中間結果を暗号化して保存"""
    client = storage.Client()
    bucket = client.bucket("secure-results-bucket")
    blob = bucket.blob(f"checkpoint/{job_id}/intermediate.enc")
    blob.upload_from_string(encrypt(intermediate_data))
    sys.exit(0)

signal.signal(signal.SIGTERM, save_intermediate_results)

効果: Spot VM のプリエンプション時にも中間結果が保存され、新しい VM での処理再開が可能。コストを 60-91% 削減しつつデータの完全性を維持。

🏦 ユースケース 2: 機密データのクリーンルーム分析での安全なセッション終了

金融機関間でのデータクリーンルーム分析において、VM 停止時に暗号化キーのメモリからの消去と監査ログの書き込みを確実に実行。

効果: グレースフルシャットダウンにより、暗号化キーの安全な消去と完全な監査証跡の記録が保証され、コンプライアンス要件を満たすことが可能。

⚠️ 制約事項・注意点

制限事項:
  • Spot VM のプリエンプション時のグレースフル期間は最大 30 秒に限定 (複雑なクリーンアップには不十分な場合あり)
  • VM 再起動時にディスクが新しいエフェメラルキーで暗号化されるため、ローカルディスクへのチェックポイント保存は永続化されない
  • グレースフルシャットダウン中も VM の課金は継続される
考慮すべき点:
  • ワークロードが PID 1 として実行されない場合 (シェルスクリプトラッパー使用時など)、SIGTERM が適切に伝搬されない可能性
  • チェックポイント保存先に Cloud Storage を使用する場合、ネットワーク遅延を考慮したタイムアウト設計が必要
  • tee-restart-policy=Always 設定時、グレースフルシャットダウン後のコンテナ再起動との相互作用を考慮
