Compute Engine GA (一般提供)

🖥️ ストレージ最適化 Z4M マシンシリーズが一般提供 (GA)

📅 リリース日: 2026-10-15

📋 概要

Compute Engine のストレージ最適化マシンファミリーに属する Z4M マシンシリーズが一般提供 (GA) になりました。 第 5 世代 Intel Xeon Scalable プロセッサ (Emerald Rapids)、DDR5 メモリ、Titanium オフロードプロセッサを搭載し、 大容量ストレージを必要とするワークロード向けに設計されています。

主な対象ワークロード:

✓AI/ML ワークロードを支える並列ファイルシステム
✓SQL、NoSQL、ベクトルデータベースなどの I/O 集約型ワークロード
✓チェックポインティングや分散 Key-Value (KV) キャッシュなどの AI/ML トレーニング・推論ワークロード

❌ Before (アップデート前の課題)

  • ローカル Titanium SSD は Z3 で最大 72,000 GiB、Z4D で最大 84,000 GiB にとどまり、より大規模なストレージ密度を必要とするワークロードには容量が不足する場合があった
  • AI/ML のチェックポインティングや分散 KV キャッシュのような、超大容量・低レイテンシのローカルストレージと広帯域ネットワークの両方を要求するワークロードに最適化された GA のマシンシリーズがなかった

✅ After (アップデート後の改善)

  • 1 インスタンスあたり最大 168,000 GiB の Titanium SSD を持つマシンシリーズが GA となり、本番ワークロードで利用可能に
  • 2 枚の物理 NIC により最大 400 Gbps + Cloud RDMA をサポートし、並列ファイルシステムや分散キャッシュのノード間通信性能が向上
  • CUD、Flexible CUD、Spot VM (ベアメタルを除く)、予約などの割引・消費オプションが利用可能に

Z4M はネットワークとストレージの処理を Titanium オフロードプロセッサに委譲することでホスト CPU をワークロードに専念させ、 大容量 Titanium SSD と Cloud RDMA 対応の広帯域ネットワークで I/O 集約型・AI/ML ワークロードを支えます。

⚡ 主要機能

1️⃣ Compute Engine 最大のローカル Titanium SSD 容量

全マシンタイプにローカル Titanium SSD (14,000 GiB 単位) が自動的にアタッチされ、最大構成では 168,000 GiB を提供。Titanium SSD は Titanium I/O オフロード処理に基づくカスタム設計のローカル SSD で、従来のローカル SSD と比較してセキュリティ・性能・管理性が強化されています。

2️⃣ Titanium + Cloud RDMA による高性能ネットワーク

物理 NIC 1 枚構成で最大 200 Gbps、2 枚構成で最大 400 Gbps のネットワーク帯域をサポート。Cloud RDMA により、より高いレベルのネットワーク性能・分離・セキュリティを実現します。

3️⃣ AI/ML ワークロードへの最適化

CPU での AI/ML 推論・トレーニングを高速化する Intel Advanced Matrix Extensions (AMX) をサポート。拡張されたクラスタ管理機能により AI Hypercomputer と組み合わせて利用可能。NUMA アーキテクチャに最適化され、安定した一貫性のあるパフォーマンスを提供します。

4️⃣ 柔軟な消費・割引オプション

リソースベース確約利用割引 (CUD)、Flexible CUD、Spot VM (ベアメタルを除く)、予約をサポートします。

👍 メリット

💼 ビジネス面

✓本番利用が可能に: GA に到達したことで、SLA のもとで本番ワークロードに Z4M を採用できる
✓コスト最適化オプション: CUD、Flexible CUD、Spot VM、予約など複数の割引・消費オプションに対応し、ワークロード特性に応じたコスト管理が可能

🔬 技術面

✓圧倒的なストレージ密度: 1 インスタンスで最大 168,000 GiB の Titanium SSD を提供し、Compute Engine で最大のローカルストレージ容量を実現
✓広帯域・低レイテンシネットワーク: 2 枚の物理 NIC で最大 400 Gbps、Cloud RDMA 対応により分散ストレージ・分散キャッシュのスケールアウトに適する
✓ホスト CPU のオフロード: Titanium によりネットワーク・ストレージ処理をホスト CPU から分離し、ワークロードに計算リソースを集中できる
✓データ保持機構: メンテナンス時も Titanium SSD データが保持され、大容量ローカルデータの再構築コストを低減できる

⚠️ デメリット・制約事項

🚫 制限事項

✗Z4M インスタンスは一部のゾーン・リージョンでのみ利用可能
✗GPU は利用不可
✗インスタンスのサスペンド (一時停止) は不可
✗カスタムマシンタイプは作成不可
✗ライブマイグレーションは、アタッチされた Titanium SSD が 42,000 GiB 以下のインスタンスのみサポート。それより大きいインスタンスは、メンテナンス時に Titanium SSD データ保持を伴って終了する
✗Cloud RDMA を有効化したインスタンスはライブマイグレーション非対応 (ホストメンテナンスポリシーは「終了」を選択する必要がある)
✗Windows OS イメージは非サポート

🤔 考慮すべき点

  • Titanium SSD はローカルストレージであり、容量はマシンタイプに固定で紐付く (z4m-highmem-16 でも 14,000 GiB が付属するため、小容量用途ではコスト効率に注意)
  • 大型マシンタイプ (z4m-highmem-192 / 192-metal) はメンテナンス時に終了または再起動となるため、アプリケーション側での可用性設計 (レプリケーション、チェックポイントなど) が必要

🎯 ユースケース

🤖 ユースケース 1: AI/ML トレーニングのチェックポインティング基盤

シナリオ: 大規模なモデルトレーニングにおいて、チェックポイントの書き込み・読み込みがトレーニング全体のスループットのボトルネックになっている。

効果: z4m-highmem-192 の 168,000 GiB の Titanium SSD (書き込み最大 57,600 MiBps) と Cloud RDMA 対応の 400 Gbps ネットワークにより、チェックポイントの保存・復元を高速化し、GPU/TPU クラスタの待機時間を削減できる。

🔍 ユースケース 2: ベクトルデータベース・分散 KV キャッシュのホスティング

シナリオ: RAG (検索拡張生成) 基盤のベクトルデータベースや、LLM 推論の分散 KV キャッシュで、大容量かつ低レイテンシのローカルストレージが必要。

効果: 1 ノードあたりのストレージ密度が高いため少ないノード数で大規模データを保持でき、Titanium SSD の高 IOPS (最大 1,560 万読み取り IOPS) により低レイテンシの検索・キャッシュ応答を実現できる。

🗂️ ユースケース 3: AI/ML 向け並列ファイルシステム

シナリオ: AI/ML ワークロードに学習データを供給する並列ファイルシステム (ストレージノード群) を構築したい。

効果: 大容量 Titanium SSD と 2 枚の物理 NIC による広帯域・RDMA 対応ネットワークにより、高スループットの並列ファイルシステムのストレージノードとして利用できる。

🔗 関連サービス・機能

💾 Google Cloud Hyperdisk

Z4M は Titanium により高性能なブロックストレージとして Hyperdisk を利用可能。永続データは Hyperdisk、ホットデータは Titanium SSD という使い分けができます。

🌐 Cloud RDMA

Z4M がサポートする低レイテンシの RDMA ネットワーキング。分散ストレージやキャッシュのノード間通信を高速化します。

🤖 AI Hypercomputer

Z4M は拡張クラスタ管理機能をサポートし、AI Hypercomputer と組み合わせて AI/ML インフラの一部として利用できます。

🗄️ Z4D / Z3 マシンシリーズ

同じストレージ最適化ファミリーの既存シリーズ。Z4D は最大 3 TB メモリ・84,000 GiB Titanium SSD、Z3 は最大 1.5 TB メモリ・72,000 GiB Titanium SSD を提供し、ワークロード要件に応じて選択できます。

📝 まとめ

Z4M マシンシリーズの GA により、Compute Engine 最大となる 168,000 GiB のローカル Titanium SSD と 最大 400 Gbps の Cloud RDMA 対応ネットワークを本番ワークロードで利用できるようになりました。

AI/ML の並列ファイルシステム、チェックポインティング、分散 KV キャッシュ、大規模なデータベース基盤を検討している場合は、 Z4D / Z3 との容量・性能・コストの比較を行い、利用可能ゾーンを確認した上で Z4M の採用を評価することをおすすめします。
