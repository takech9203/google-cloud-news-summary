🔍 CREATE AI INDEX で実現する自然言語検索

エンベディング管理不要のセマンティック検索が SQL 1 文で
リリース日: 2026-11-19

📝 概要

BigQuery に CREATE AI INDEX ステートメントが Preview として追加されました。 AI インデックスをテーブルに作成すると、AI.SEARCH 関数でテーブルの列に対する 自然言語検索 (セマンティック検索) を実行できます。 最大の特徴は、エンベディング (埋め込みベクトル) の生成やエンベディングモデルの管理をユーザーが手動で行う必要がない点です。

列の選択 (AUTO COLUMNS 指定時)、インデックスの最適化、継続的なメンテナンスを BigQuery が自動管理。 データウェアハウス上のテキストデータに対して、セマンティック検索・RAG・レコメンデーションを手軽に実現したい データエンジニアやアナリストに有用なアップデートです。

❌ Before (アップデート前の課題)

  • Cloud リソース接続の作成、エンベディングモデル (例: text-embedding-005) の指定、AI.EMBED によるエンベディング列の生成など、複数の構成要素を手動でセットアップ
  • エンベディング列やベクトルインデックスの設計 (対象列、インデックスタイプ) をユーザー自身が判断・管理
  • モデルやインデックスの継続的なメンテナンスの考慮が必要

✅ After (アップデート後の改善)

  • CREATE AI INDEX を 1 文実行するだけで、エンベディング生成やモデル管理なしに自然言語検索の準備が完了
  • AUTO COLUMNS 指定で、BigQuery がインデックス対象の列 (最大 50 列) を自動選択
  • 列選択・最適化・メンテナンスを BigQuery が自動管理
  • INFORMATION_SCHEMA.AI_INDEXES / AI_INDEX_COLUMNS でカバレッジや対象列を監視可能

CREATE AI INDEX の実行後は、列選択・最適化・メンテナンスを BigQuery が自動管理し、 ユーザーは AI.SEARCH に自然言語クエリを渡すだけで検索結果を取得できます。

⚡ 主要機能

1️⃣ CREATE AI INDEX ステートメント

→テーブルに AI インデックスを作成する DDL ステートメント
→AUTO COLUMNS を指定すると、対象となり得る列から最大 50 列を BigQuery が自動選択
→列の明示指定も可能 (タイトルなど情報量の多い列を先頭に置くことを推奨)

2️⃣ エンベディング・モデル管理が不要な自然言語検索

→手動でのエンベディング生成やエンベディングモデルの管理が不要
→AI.SEARCH 関数にベーステーブル (またはクエリ) と検索文字列を渡すだけでセマンティック検索を実行
→結果は distance (距離) 付きで返却、top_k で取得件数を制御可能

3️⃣ INFORMATION_SCHEMA によるモニタリング

→AI_INDEXES: カバレッジ率 (coverage_percentage)、未インデックス行数、論理バイト数などのメタデータ
→AI_INDEX_COLUMNS: インデックス対象列の確認 (AUTO COLUMNS の選択結果の検証に有用)
→JOBS: ジョブ ID が gc_ で始まるメンテナンスジョブのスロット消費 (total_slot_ms) や課金バイト数 (total_bytes_billed) を追跡

4️⃣ DROP AI INDEX によるインデックス削除

→DROP AI INDEX IF EXISTS index_name ON dataset.table でインデックスのみを削除可能
→テーブルを削除するとインデックスも自動的に削除される

ステップ 1: AI インデックスの作成

SQL CREATE AI INDEX 
-- 列を自動選択する場合 (最大 50 列を BigQuery が選択)
CREATE AI INDEX products_ai_index
ON mydataset.products(AUTO COLUMNS);

-- 列を明示指定する場合 (情報量の多い列を先頭に)
CREATE AI INDEX products_ai_index
ON mydataset.products(name, description);

ステップ 2: インデックスのカバレッジを確認

SQL INFORMATION_SCHEMA.AI_INDEXES 
SELECT table_name, index_name, coverage_percentage, unindexed_row_count
FROM my_project.my_dataset.INFORMATION_SCHEMA.AI_INDEXES;
💡 ポイント: インデックス作成が完了するまで検索結果は不完全になるため、coverage_percentage を確認してから検索を実行します。

ステップ 3: AI.SEARCH で自然言語検索を実行

SQL AI.SEARCH による自然言語検索 
SELECT base.id, base.name, base.description, distance
FROM AI.SEARCH(
  TABLE mydataset.products,
  'shoes that keep your feet dry in the rain',
  top_k => 5)
ORDER BY distance;

ステップ 4: 不要になったインデックスの削除

SQL DROP AI INDEX 
DROP AI INDEX IF EXISTS products_ai_index ON mydataset.products;

🤔 考慮すべき点

→AUTO COLUMNS は作成後に追加された列を対象にしないため、スキーマ変更時はインデックスの削除・再作成が必要
→インデックス作成は非同期であり、coverage_percentage が 100 になるまで検索結果が不完全になる
→バックグラウンドのメンテナンスジョブ (gc_ プレフィックス) のスロット消費・課金バイト数を INFORMATION_SCHEMA.JOBS で監視し、コストを把握しておくことが望ましい

🛒 ユースケース 1: EC サイトの商品カタログ検索

シナリオ: 商品名と説明文を持つ商品テーブルに対し、「雨の日でも足が濡れない靴」のような自然言語クエリで商品を検索したい。

SQL 実装例 
CREATE AI INDEX products_ai_index
ON mydataset.products(name, description);

SELECT base.id, base.name, base.description, distance
FROM AI.SEARCH(
  TABLE mydataset.products,
  'shoes that keep your feet dry in the rain',
  top_k => 5)
ORDER BY distance;

効果: キーワード完全一致に依存しないセマンティックな商品検索を、エンベディングパイプラインなしで実現できる。

📚 ユースケース 2: 社内ナレッジ・問い合わせログの横断検索

シナリオ: サポート問い合わせログや社内ドキュメントのテキスト列が多数あるテーブルに対し、どの列が検索に有効か判断せずに検索基盤を作りたい。

効果: AUTO COLUMNS により BigQuery が対象列を自動選択するため、スキーマの事前分析なしに複数列を横断した自然言語検索を開始できる。AI_INDEX_COLUMNS ビューで選択結果を後から検証できる。

🔗 関連サービス・機能

🔍 AI.SEARCH 関数

AI インデックスを利用した検索の実行インターフェース。セマンティック検索に加え、ベクトルインデックス構成によってはハイブリッド検索やリランキング (rerank => TRUE) にも対応。

🗂️ ベクトルインデックス (CREATE VECTOR INDEX)

エンベディング列に対する従来型のインデックス。モデルや列を細かく制御したい場合の選択肢 (AI インデックスとは同一テーブルで併用不可)。

🤖 自動エンベディング生成 (Autonomous Embedding Generation)

AI.EMBED を使った生成列によるエンベディング自動更新の仕組み (AI インデックスとは同一テーブルで併用不可)。

📅 BigQuery Reservations

100 万行を超えるテーブルへのインデックス作成に必要な BACKGROUND ジョブタイプの予約割り当て。
