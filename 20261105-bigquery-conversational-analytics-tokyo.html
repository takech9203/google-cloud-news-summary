☁️ BigQuery Feature: 東京対応 Change: ページ廃止
📅 リリース日: 2026-11-05

💬 Conversational Analytics が東京リージョン (asia-northeast1) に対応

あわせて「Metadata curation」コンソールページは廃止され、ガバナンス タスクは Knowledge Catalog に統合

📌 概要

2026 年 11 月 5 日、BigQuery に関する 2 つのアップデートが発表されました。

1️⃣ Conversational Analytics の asia-northeast1 (東京) 対応 Feature

自然言語でデータに質問すると、データエージェントが SQL を生成・実行して回答やグラフを返す Conversational Analytics (会話型分析) が、東京リージョンで利用可能になりました。これまでは US / EU マルチリージョン、北米の一部リージョン、Global に限られていましたが、エージェントや会話リソースを日本国内に保持したまま利用でき、データレジデンシー要件を持つ日本企業にとって大きな前進です。

2️⃣ 「Metadata curation」コンソールページの削除 Change

BigQuery の「Metadata curation」ページが削除されました。Cloud Storage の検出スキャン (discovery scan) のスケジュール設定、データプロファイリング、データ品質管理などのガバナンス タスクは、今後 Knowledge Catalog で実施します。機能自体の廃止ではなく、入口が Knowledge Catalog に一本化された形です。

❌ Before (アップデート前の課題)

  • エージェント・会話リソースの保存先と ML 処理のロケーションとして日本 (asia-northeast1) を選択できなかった
  • データレジデンシー要件のある日本企業は Global や US/EU のエンドポイントを使わざるを得ず、国内利用のハードルになっていた
  • ガバナンス機能の管理画面が「Metadata curation」ページと Knowledge Catalog に分かれ、導線が分散していた

✅ After (アップデート後の改善)

  • エージェントと会話リソースを asia-northeast1 (東京) に配置でき、日本国内でのデータ保持と ML 処理が可能に
  • 東京リージョンの BigQuery データセットに対して、低レイテンシかつデータレジデンシーに配慮した会話型分析を実現
  • 検出スキャン・プロファイリング・データ品質などの入口が Knowledge Catalog に統一され、管理導線がシンプルに

ユーザーが自然言語で質問すると、データエージェントが BigQuery に対する SQL を生成・実行し、回答やグラフを返します。今回のアップデートにより、この一連の処理 (エージェント・会話リソースの保存と ML 処理) を東京リージョン内で完結できるようになりました。

⚡ 主要機能

🗾 Conversational Analytics の asia-northeast1 (東京) 対応 Feature

→エージェントと会話リソースの保存先、および ML 処理のロケーションとして東京を選択可能に
→自然言語の質問から SQL 生成・実行・可視化までをエージェントが実施
→エージェント作成時にロケーションを選択可能 (保存後は変更不可)

🤖 データエージェントの構成要素

→ナレッジソース: テーブル、ビュー、グラフ、UDF など (最大 100 個)
→検証済みクエリ (verified queries): ユーザーの質問にマッチした場合に実行される確定的な SQL
→用語集 (グロッサリー): 列とビジネス用語を紐付けるセマンティック コンテキスト
→エージェント指示: 会計年度の定義やフォーマット ルールなどの自然言語ルール

📂 Metadata curation コンソールページの削除 Change

→BigQuery コンソールの「Metadata curation」ページが削除された
→Cloud Storage 検出スキャンのスケジュール設定、データプロファイリング、データ品質管理などは Knowledge Catalog で実施
→検出スキャンで作成された BigLake テーブルは引き続き BigQuery で管理・クエリ可能

🛠️ 設定方法

✅ 前提条件

✓BigQuery データセットが asia-northeast1 (東京) または対象ロケーションに存在すること
✓Gemini for Google Cloud / Conversational Analytics API の利用が有効化されていること
✓データエージェントの操作に必要な IAM 権限 (例: cloudaicompanion.topics.* 関連権限) があること

ステップ 1: データエージェントの作成 (東京ロケーションを選択)

BigQuery コンソールの Agent Catalog タブからデータエージェントを作成し、ナレッジソース (テーブルやビュー) を追加します。エージェント作成時にロケーションとして asia-northeast1 を選択できます (保存後は変更不可)。

ステップ 2: Cloud Storage 検出スキャンの管理 (Knowledge Catalog)

Bash gcloud で検出スキャンを作成する例 (東京リージョン) 
# gcloud で検出スキャンを作成する例 (東京リージョン)
gcloud dataplex datascans create data-discovery SCAN_ID \
  --location=asia-northeast1 \
  --data-source-resource=gs://YOUR_BUCKET

従来 BigQuery の Metadata curation ページで行っていた検出スキャンのスケジュール設定は、Knowledge Catalog のコンソールまたは gcloud / REST API から実施します。

👍 メリット

💼 ビジネス面
  • 日本企業のデータレジデンシー要件に対応: エージェント・会話リソースを東京に配置できるため、データの国内保持を求める規制・社内ポリシーに対応しやすくなる
  • データ民主化の促進: SQL を書けないビジネス ユーザーも自然言語で BigQuery のデータに質問でき、分析の裾野が広がる
⚙️ 技術面
  • 低レイテンシ: 東京リージョンの BigQuery データセットと同一リージョンで処理が完結し、応答性が向上する
  • ガバナンス導線の一元化: 検出スキャン・プロファイリング・データ品質の管理が Knowledge Catalog に統一され、運用がシンプルになる

⚠️ デメリット・制約事項

🚧 制限事項
  • エージェントのロケーションは保存後に変更できない
  • 1 エージェントに追加できるナレッジソースは最大 100 個
  • Conversational Analytics の既知の制限 (クエリ、会話、可視化に関する制約) が適用される
🤔 考慮すべき点
  • Metadata curation ページを利用していた運用手順書やブックマークは Knowledge Catalog ベースに更新が必要
  • エージェントのスコープを広げすぎると指示の競合や出力のあいまいさが発生しやすいため、用途ごとにエージェントを分割することが推奨される
  • コスト管理のため、プロジェクト / ユーザー / クエリ単位の支出上限 (例: big_query_max_billed_bytes) の設定を検討する

シナリオ: 東京リージョンの BigQuery に売上データを保持する国内小売企業が、データレジデンシー要件を満たしつつ、ビジネス部門にセルフサービス分析を提供したい。

🗄️ ユースケース 2: Knowledge Catalog によるデータレイクのガバナンス運用

シナリオ: Cloud Storage 上のデータレイクに対して検出スキャンを定期実行し、BigLake テーブルとして BigQuery に公開しつつ、データ品質スキャンで品質を監視している。

効果: Metadata curation ページ廃止後も、Knowledge Catalog を単一の入口として検出スキャンのスケジュール、プロファイリング、データ品質管理を一元的に運用できる。

💰 料金

Conversational Analytics では、データエージェントの作成時およびエージェント / データソースとの会話時に実行されるクエリに対して、BigQuery のコンピューティング料金 (分析料金) が課金されます。エージェント自体の料金は Data Cloud Agent の料金体系に従います。

  • BigQuery の料金 (分析料金モデル)
  • Data Cloud Agent の料金
💡 コスト管理: エージェント設定の big_query_max_billed_bytes やプロジェクト / ユーザー / クエリ単位の支出上限を設定できます。

🌏 利用可能リージョン

Conversational Analytics は、us / eu マルチリージョン、northamerica-northeast1、northamerica-northeast2、us-east4、global に加え、今回のアップデートで asia-northeast1 (東京) で利用可能になりました。

最新のロケーション一覧は公式ドキュメントを参照してください。

🔗 関連サービス・機能

🤖 Conversational Analytics API (Gemini Data Analytics)

コンソールで作成したデータエージェントを API 経由で呼び出し、独自アプリケーションに組み込める。

📚 Knowledge Catalog

Metadata curation ページの後継として、検出スキャン・プロファイリング・データ品質などのガバナンス タスクを担う。

🗄️ BigLake

Cloud Storage 検出スキャンにより自動作成されるテーブル形式。BigQuery から SQL でクエリ可能。

📊 Looker / Looker Studio

Conversational Analytics API がサポートするもう 1 つの主要データソース。
