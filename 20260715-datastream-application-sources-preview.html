📋 概要

Google Cloud の CDC (Change Data Capture) サービスである Datastream に、新たに 3 つのアプリケーションソースが Preview として追加されました。

ServiceNow、Salesforce Marketing Cloud、Microsoft Dataverse からの変更データレプリケーションが可能になり、SaaS アプリケーションのデータを BigQuery や Cloud Storage にニアリアルタイムで連携できます。

Before / After

❌ Before (従来)

  • サードパーティ ETL ツールやカスタムパイプラインが必要
  • 各 SaaS からのデータ抽出を個別管理で運用負荷大
  • バッチ処理依存でニアリアルタイム CDC が困難

✅ After (今回)

  • サーバーレスで 3 つの SaaS ソースからレプリケーション可能
  • 統一インターフェースで DB ソースと SaaS ソースを一元管理
  • ポーリングベースの増分同期でニアリアルタイム連携

⚡ 主要機能

🔧 ServiceNow ソースレプリケーション

  • ServiceNow REST Table API (V2) を使用したデータレプリケーション
  • キーセットベースのページネーションによる信頼性の高い初期バックフィル
  • sys_updated_on フィールドを使用した増分同期
  • 動的なスキーマ検出とテーブルフィルタリング
  • OAuth 2.0 クライアント認証情報フローまたは Basic 認証に対応

📧 Salesforce Marketing Cloud ソースレプリケーション

  • Salesforce Marketing Cloud REST API を使用
  • Assets、Email definitions、Campaigns、Journeys、Contacts など主要オブジェクトに対応
  • 増分同期対応オブジェクトと定期フルリフレッシュの両方をサポート
  • サーバー間 OAuth 2.0 フローによる認証

🗃️ Microsoft Dataverse ソースレプリケーション

  • Dataverse Web API (OData v9.1) を使用
  • OAuth 2.0 クライアント認証情報フロー (Azure AD 経由) による認証
  • /EntityDefinitions エンドポイントによる動的スキーマ検出
  • modifiedon フィールドを使用したタイムスタンプベースの増分同期
  • 標準テーブルとカスタムテーブルの両方をサポート

🛠️ 設定方法

📌 前提条件: Google Cloud プロジェクトで Datastream API が有効化されていること、各アプリケーションソースへの管理者アクセス権限が必要です。

ステップ 1: ソースの設定 (ServiceNow の例)

ServiceNow の場合、OAuth 2.0 プラグインを有効化し、クライアント認証情報を生成します。テーブルの ws_access=true 設定も必要です。

Bash 
# ServiceNow インスタンスで Web Services Access を有効化し、
# OAuth 2.0 を設定後、Datastream 接続プロファイルを作成
gcloud datastream connection-profiles create servicenow-profile \
    --location=us-central1 \
    --type=SERVICENOW \
    --display-name="ServiceNow Production"

ステップ 2: ソースの設定 (Microsoft Dataverse の例)

Azure AD でアプリケーションを登録し、Client ID、Tenant ID、Client Secret を取得します。Dataverse 環境でアプリケーションユーザーを作成し、必要なテーブルへの読み取り権限を付与します。

Bash 
# Azure AD でアプリケーション登録後、Dataverse 接続プロファイルを作成
gcloud datastream connection-profiles create dataverse-profile \
    --location=us-central1 \
    --type=DATAVERSE \
    --display-name="Dataverse Production"

ステップ 3: ストリームの作成

ストリーム作成時にポーリング間隔を設定し、データフレッシュネスの要件に合わせます。

Bash 
# BigQuery を宛先としたストリームの作成
gcloud datastream streams create my-stream \
    --location=us-central1 \
    --source=servicenow-profile \
    --destination=bigquery-profile \
    --display-name="ServiceNow to BigQuery"

✅ メリット

💼 ビジネス面

✓ データサイロの解消: ServiceNow、Salesforce MC、Dataverse のデータを BigQuery に統合し、組織横断分析が可能
✓ 迅速な分析: ニアリアルタイムのレプリケーションで最新データに基づく意思決定
✓ 運用コスト削減: カスタム ETL パイプラインの構築・運用が不要

🔧 技術面

✓ サーバーレス: インフラ管理不要、データ量に応じて自動スケール
✓ 統一管理: DB ソースと SaaS ソースを同一コンソールで管理
✓ Knowledge Catalog 連携: データリネージの追跡が容易

⚠️ デメリット・制約事項

⚠️ Preview ステータス: SLA の対象外であり、本番環境での使用は推奨されません。GA までに仕様変更の可能性があります。

制限事項

✗ 3 つのソース全てで削除イベントの検出は非対応
✗ ServiceNow: 内部プラットフォームテーブル (ts_、v_、imp_ プレフィックス等) は自動的に除外
✗ Salesforce MC: Marketing Cloud Account Engagement および Agentforce Marketing との統合は非対応。SOAP 専用オブジェクト (Lists、Subscriptions、Links) は非対応
✗ Microsoft Dataverse: 仮想テーブルとプライベートテーブルは非対応。Delta Link ベースの変更追跡は非サポート

考慮すべき点

! ポーリング間隔の設定がデータフレッシュネスと API クォータ消費のトレードオフ
! 各ソースの API クォータ制限 (特に Salesforce の 24 時間ローリングウィンドウ) を事前に確認

🎯 ユースケース

🔧 IT サービス管理データの分析基盤構築

シナリオ: エンタープライズ企業が ServiceNow のインシデント管理、変更管理、サービスリクエストのデータを BigQuery に集約し、IT 運用のトレンド分析や SLA 遵守状況のダッシュボードを構築する。

効果: リアルタイムに近いデータで IT 運用の可視化が実現し、問題の早期発見とプロアクティブな対応が可能に。カスタム ETL パイプラインの構築・運用コストも削減。

📊 マーケティングキャンペーン効果のクロスチャネル分析

シナリオ: マーケティングチームが Salesforce Marketing Cloud のメールキャンペーン、SMS、プッシュ通知のデータを BigQuery に連携し、他チャネルデータと統合して ROI 分析を実施。

効果: キャンペーンパフォーマンスをニアリアルタイムで追跡し、チャネル横断の顧客ジャーニー分析が可能に。

🤖 ビジネスアプリケーションデータの統合データウェアハウス

シナリオ: Microsoft Dynamics 365 を使用する組織が Dataverse のビジネスデータ (顧客、商談、注文) を BigQuery に連携し、Vertex AI と組み合わせて予測分析を実施。

効果: Dataverse のビジネスデータと他ソースを統合し、売上予測や顧客離脱予測などの高度な分析が実現。

💰 料金

Datastream は宛先にストリーミングされたデータ量 (GB) に基づいて課金されます。

項目 詳細
課金単位 宛先にストリーミングされたデータ量 (GB)
無料枠 Google Cloud ソース (AlloyDB, Spanner) の CDC データは月 100 GiB まで無料
追加費用 BigQuery や Dataflow を宛先として使用する場合、各サービスの料金が別途発生
💡 注意: アプリケーションソース (ServiceNow、Salesforce Marketing Cloud、Microsoft Dataverse) への無料枠の適用有無については、公式料金ページを確認してください。

🔗 関連サービス

→BigQuery: Datastream の主要な宛先。CDC データをリアルタイムにロードし、分析クエリを実行
→Cloud Storage: Avro/JSON 形式でイベントストリームを保存する宛先オプション

📝 まとめ

Datastream へのアプリケーションソース (ServiceNow、Salesforce Marketing Cloud、Microsoft Dataverse) のサポート追加は、Google Cloud のデータ統合エコシステムを大幅に強化するアップデートです。サーバーレスで SaaS データのニアリアルタイムレプリケーションを実現し、従来カスタム開発が必要だったデータパイプラインを大幅に簡素化します。

💡 推奨: 現在 Preview 段階のため、まずは開発環境での検証から始め、GA を待って本番環境への導入を計画することを推奨します。
