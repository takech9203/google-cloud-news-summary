⚡ Node.js 26 & Python 3.15 ランタイムが GA

サーバーレス基盤 (App Engine / Cloud Run / Cloud Run functions) で最新言語ランタイムが一斉に一般提供
📅 リリース日: 2026-11-23

📋 概要

Google Cloud のサーバーレス実行基盤である App Engine (フレキシブル / スタンダード環境)、 Cloud Run、Cloud Run functions で、 Node.js 26 と Python 3.15 ランタイムのサポートが GA になりました。サーバーレス基盤を横断するランタイムの一斉アップデートです。

両ランタイムは Ubuntu 24.04 ベースの google-24 スタック (デフォルト) および google-24-full スタック上で提供され、ランタイム ID はそれぞれ nodejs26、python315 です。本番ワークロードが GA レベルのサポート対象となり、 セキュリティ アップデート ポリシーに基づく定期的な修正が適用されます。

❌ Before (アップデート前の課題)

  • Node.js 26 / Python 3.15 は Preview 段階で、本番ワークロードで GA レベルのサポートを受けられなかった
  • Cloud Run functions では Preview ランタイムのデプロイに gcloud beta functions deploy が必要だった
  • GA の最新ランタイムは Node.js 24 (非推奨予定: 2028-04-30) / Python 3.14 (非推奨予定: 2030-10-10) で、言語の最新バージョンを GA サポート付きで使えなかった

✅ After (アップデート後の改善)

  • Node.js 26 / Python 3.15 を全サーバーレス基盤で GA サポート付きで利用可能に
  • セキュリティ アップデート ポリシーに従った定期的なセキュリティ修正・バグ修正の対象に
  • 破壊的変更は原則実装されず、実施時はリリースノートで事前告知される運用が適用
⚠️ 注意: Python 3.15 は Cloud Run functions でのみ利用可能で、Cloud Run functions (第 1 世代) ではサポートされません。

Node.js 26 / Python 3.15 は Ubuntu 24.04 ベースの google-24 スタックとして提供され、 App Engine、Cloud Run、Cloud Run functions の各サーバーレス基盤に共通のランタイムとしてデプロイできます。 Python 3.15 のみ Cloud Run functions (第 1 世代) では利用できません。

🔧 主要機能

🟢 1. Node.js 26 ランタイムの GA

→App Engine フレキシブル環境、スタンダード環境、Cloud Run、Cloud Run functions で一般提供
→ランタイム ID: nodejs26 / 実行環境: Ubuntu 24.04 (google-24 / google-24-full スタック)

🐍 2. Python 3.15 ランタイムの GA

→App Engine フレキシブル環境、スタンダード環境、Cloud Run、Cloud Run functions で一般提供
→ランタイム ID: python315 / 実行環境: Ubuntu 24.04 (google-24 / google-24-full スタック)
✕Cloud Run functions (第 1 世代) では非サポート

🛡️ 3. GA ランタイムとしてのライフサイクル サポート

→ランタイム コンポーネントにセキュリティ修正・バグ修正が定期的に適用
→更新はワークロードのセキュリティ アップデート ポリシーに従って適用
→非推奨 (Deprecation) 到達の 90 日前から Google Cloud コンソールで通知

⚙️ 設定方法

前提条件

✓Google Cloud プロジェクトと gcloud CLI のセットアップ
✓デプロイ対象サービス (App Engine / Cloud Run / Cloud Run functions) の有効化

ステップ 1: App Engine で新ランタイムを指定

YAML app.yaml (Node.js の場合) 
runtime: nodejs26
YAML app.yaml (Python の場合) 
runtime: python315

app.yaml の runtime にランタイム ID を指定し、gcloud app deploy でデプロイします。

ステップ 2: Cloud Run functions で新ランタイムを指定

Bash Cloud Run functions のデプロイ 
gcloud functions deploy my-function \
  --runtime=nodejs26 \
  --trigger-http \
  --region=REGION
💡 ヒント: GA となったため、Preview 時に必要だった gcloud beta functions deploy ではなく、 通常の gcloud functions deploy コマンドでデプロイできます。Python の場合は --runtime=python315 を指定します。

⚖️ メリットと制約事項

💼 メリット (ビジネス面)

✓本番利用可能なサポートレベル: GA レベルのカスタマーサポートとランタイム サポートの対象となり、本番ワークロードへ安心して採用できる
✓長期的なランタイム戦略: 最新バージョンへの早期移行で、既存ランタイム (Node.js 22: 2027-04-30 非推奨、Python 3.13: 2029-10-10 非推奨など) の廃止対応を先取りできる

🔩 メリット (技術面)

✓最新の言語バージョン: Node.js 26 / Python 3.15 の最新機能・改善をサーバーレス環境で利用できる
✓基盤間での一貫性: 全基盤で同一のランタイム ID・スタック (google-24) が使え、サービス間の移行・併用が容易
✓安定性の担保: 破壊的変更は原則実装されず、変更時はリリースノートで事前告知

🚧 制限事項

✕Python 3.15 は Cloud Run functions (第 1 世代) ではサポートされない
✕Node.js 26 / Python 3.15 の非推奨・廃止スケジュールは現時点で未定 (今後ドキュメントで告知)

🤔 考慮すべき点

→新ランタイムは Ubuntu 24.04 ベースの google-24 スタックで動作するため、古いスタック (google-22 など) 向けのシステムパッケージ依存がある場合は動作確認が必要
→依存ライブラリ (npm / pip パッケージ) が Node.js 26 / Python 3.15 に対応しているか事前に検証する

🎯 ユースケース

📈 ユースケース 1: 旧ランタイムからの計画的アップグレード

シナリオ: Node.js 20 (非推奨: 2026-04-30 到達済み) や Python 3.10 (非推奨: 2026-10-04 到達済み) で稼働中の App Engine / Cloud Run functions アプリケーションを、サポート期限の長い最新ランタイムへ移行する。

YAML app.yaml を変更して再デプロイ 
runtime: python315  # 旧: python310

効果: 非推奨ランタイムの再デプロイブロックのリスクを回避し、最も長いサポートウィンドウを確保できる。

🧩 ユースケース 2: 複数サーバーレス基盤での統一ランタイム採用

シナリオ: フロントエンド API を Cloud Run、イベント処理を Cloud Run functions、既存アプリを App Engine で 運用しているチームが、全サービスのランタイムを Node.js 26 に統一する。
