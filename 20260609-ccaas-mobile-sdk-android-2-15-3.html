📋 概要

Google Cloud Contact Center as a Service (CCaaS / CCAI Platform) の Android 向け Mobile SDK バージョン 2.15.3 パッチがリリースされました。Web フォームのコールバック処理、チャットメッセージの表示順序、セッション管理、およびタイムアウトメッセージのカスタマイズに関する 4 つのバグ修正 を含む品質改善リリースです。

🔄 Before / After 比較

❌ Before (v2.15.2)

  • UjetWebFormCallback のメソッド不足でフォームデータ受け渡し不可
  • チャットメッセージが時系列順に表示されない
  • セッション終了後に新規セッション開始不可 (再起動必要)
  • タイムアウトメッセージのカスタマイズ不可

✅ After (v2.15.3)

  • コールバックメソッド追加で正常にデータ受け渡し可能
  • メッセージが正しい時系列順で表示
  • セッション終了後に即座に新規セッション開始可能
  • タイムアウトメッセージの自由なカスタマイズが可能

🔧 修正内容 (4 件)

📝

UjetWebFormCallback メソッド追加

onEvent(formDataEvent) および onError() コールバックが正常動作。HMAC-SHA256 署名付きフォームデータを正しく処理可能に。

💬

メッセージ表示順序修正

チャットメッセージとコンテンツカード (リッチメッセージ) が送信時刻に基づいて正しい時系列順で表示されるように。

🔄

セッション再開修正

SessionEnded イベント後、Ujet.start() で新規セッション開始可能。Ujet.getStatus() が正しく UjetStatus.None を返却。

⏱️

タイムアウトメッセージカスタマイズ

待機時間超過時のメッセージテキストをカスタマイズ可能に。ブランドガイドラインに沿った表現や多言語対応が実現。

Step 2: UjetWebFormCallback の実装確認 (Web フォーム利用時)

Kotlin 
class UjetWebFormListenerImpl : UjetWebFormListener {
    override fun ujetWebFormDidReceive(
        event: Map<String, Any?>,
        callback: UjetWebFormCallback
    ) {
        try {
            val smartActionId = event["smart_action_id"]
            val externalFormId = event["external_form_id"]
            val formUri = generateFormUri(externalFormId)

            val data = mapOf(
                "external_form_id" to externalFormId,
                "smart_action_id" to smartActionId,
                "uri" to formUri
            )
            val signature = generateHmacSha256(data)
            val formDataEvent = mapOf(
                "type" to "form_data",
                "signature" to signature,
                "data" to data
            )
            callback.onEvent(formDataEvent)
        } catch (e: Throwable) {
            callback.onError()
        }
    }
}

// SDK にリスナーを登録
Ujet.setUjetWebFormListener(UjetWebFormListenerImpl())

⚠️ 制約事項・注意点

制限事項:
  • 本パッチは Android SDK のみが対象 (iOS SDK には適用されない)
  • minSdkVersion は引き続き API レベル 25 (Android 7.1.1) が最低要件
  • Web フォーム連携には HMAC-SHA256 署名の実装がサーバー側で必要
💡 考慮すべき点:
  • 後方互換性のあるパッチリリースだが、Web フォーム関連の実装がある場合はコールバック動作変更を確認すること
  • チャット表示順序修正により、既存のカスタム UI 実装がある場合はレイアウトへの影響を確認

💡 ユースケース

🏦 ユースケース 1: カスタマーサポートアプリでの Web フォーム連携

シナリオ: 金融機関がモバイルアプリ内のカスタマーサポート機能で、本人確認フォームをチャット中に表示してデータを収集する

効果: v2.15.3 の修正により、フォームデータが確実に SDK 経由でバックエンドに送信され、エージェントが本人確認情報をリアルタイムで受け取れる

🛒 ユースケース 2: 連続サポートセッション

シナリオ: EC サイトのアプリで、ユーザーが注文に関する問い合わせを終えた後、続けて返品に関する別の問い合わせを開始したい

効果: 最初のセッション終了後にアプリを再起動せずに新しいチャットセッションを開始可能。ユーザーの離脱防止とサポート完了率向上

🌐 ユースケース 3: 多言語対応のタイムアウトメッセージ

シナリオ: グローバル展開企業が、ユーザーの言語設定に応じてタイムアウトメッセージを各言語で表示したい

効果: タイムアウトメッセージのカスタマイズにより、日本語・英語・中国語などユーザーのロケールに合わせたメッセージ表示が可能
