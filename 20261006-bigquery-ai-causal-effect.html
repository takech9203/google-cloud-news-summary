💬 会話型分析で AI.CAUSAL_EFFECT をサポート

自然言語の質問だけで「施策の因果効果」を統計的に定量化

リリース日: 2026-10-06
Google Cloud アップデート

📌 概要

BigQuery の会話型分析 (Conversational analytics) が AI.CAUSAL_EFFECT 関数をサポートしました (Preview)。 AI.CAUSAL_EFFECT は、時系列データに対する特定の介入 (インターベンション) がもたらした影響を、 介入がなかった場合の反実仮想 (counterfactual) の予測値と実測値を比較して定量化する関数です。

データエージェントとの自然言語チャットの中で因果効果分析を実行できるようになり、たとえば 「2020 年 3 月 11 日の COVID-19 パンデミック宣言がタクシーの 1 日あたりの乗車数に与えた影響を定量化して」と質問するだけで、 エージェントが SQL を生成し、統計的に有意な効果かどうかを含めて回答します。

🎯 主要な価値提案: SQL や統計モデリングの専門知識を持たないビジネスユーザーからデータサイエンティストまで、 施策の効果測定を自然言語ベースで民主化できます。

❌ Before (アップデート前の課題)

  • AI.CAUSAL_EFFECT の構文を理解して SQL を自分で記述するか、ARIMA_PLUS モデルを自前で構築して反実仮想予測と実測値を比較する必要があった
  • 会話型分析の時系列分析は予測 (AI.FORECAST)、異常検知 (AI.DETECT_ANOMALIES)、トレンド/季節性分析などに限られ、因果の問いには自然言語で答えられなかった
  • p 値の解釈など統計の専門知識が必要で、ビジネスユーザーが自力で実施するのは難しかった

✅ After (アップデート後の改善)

  • データエージェントや直接会話の中で、自然言語の質問から AI.CAUSAL_EFFECT による因果効果分析を実行できる
  • 介入前後のデータ分割、ARIMA_PLUS による反実仮想ベースライン予測、絶対効果・相対効果・p 値の算出までエージェントが自動実行
  • 検証済みクエリ (verified query) に組み込み、定型的な効果測定レポートを自動化できる

ユーザーが自然言語で介入効果について質問すると、データエージェントが AI.CAUSAL_EFFECT を含む SQL を生成し、 介入タイムスタンプを境にデータを分割、ARIMA_PLUS による反実仮想予測と実測値を比較して効果の大きさと統計的有意性を回答します。

⚡ 主要機能

💬 1. 自然言語による因果効果分析

✓データエージェントとの会話や、データソースとの直接会話で「〇月〇日の施策がメトリクスに与えた影響を定量化して」といった質問が可能
✓エージェントが AI.CAUSAL_EFFECT を使った SQL を生成し、結果の解釈 (reasoning) とチャートを含めて回答
✓検証済みクエリ (verified query) に組み込むことで、定期的な効果測定レポートを標準化・自動化

🧮 2. AI.CAUSAL_EFFECT 関数の分析機能

✓時系列セグメンテーション: 指定した介入タイムスタンプでデータを介入前/介入後に自動分割し、絶対効果・相対効果・統計的有意性を計算
✓並列処理: id_cols 引数で複数の時系列を 1 回の呼び出しで並列分析可能
✓単変量時系列モデリング: ARIMA_PLUS 予測で反実仮想ベースラインを構築。コントロール系列や外部共変量が不要で、実験のスピルオーバー効果によるバイアスを防げる

🎛️ 3. 柔軟な出力制御

✓デフォルトでは時系列ごとに 1 行のサマリービュー (p 値、因果効果の確率、絶対効果、相対効果) を返す
✓output_time_series => TRUE でタイムスタンプごとの実測値・予測値・予測区間 (上限/下限) を含む詳細ビューを出力
✓num_post_intervention_points で分析対象とする介入後のデータポイント数を制御可能

🔧 技術仕様

📥 AI.CAUSAL_EFFECT 関数の引数

引数必須/任意詳細
TABLE / query_statement必須介入前後のデータを含むテーブルまたは GoogleSQL クエリ
data_col必須分析対象の時系列値の列名 (INT64 / NUMERIC / BIGNUMERIC / FLOAT64)
timestamp_col必須タイムスタンプの列名 (TIMESTAMP / DATE / DATETIME)
intervention_timestamp必須介入が発生した時点。この時刻でデータを介入前/介入後に分割
id_cols任意複数時系列を識別する列名の配列 (STRING / INT64)。並列分析に使用
confidence_level任意予測区間の信頼水準 [0, 1)。デフォルトは 0.95
output_time_series任意TRUE で時系列の詳細ビューを出力。デフォルトは FALSE (サマリービュー)
num_post_intervention_points任意分析に含める介入後のデータポイント数。未指定時は末尾まですべて使用

📤 出力 (サマリー統計)

列詳細
p_value介入後期間全体に対する帰無仮説の両側 p 値 (ARIMA_PLUS の標準誤差ベースで保守的に算出)
prob_causal_effect因果効果が存在する確率 (1 - p_value)
absolute_effect介入後期間の SUM(実測値 - 期待値)
relative_effectSUM(実測値 - 期待値) / SUM(期待値)
status予測ステータス (成功時は空。データ不足時は "The time series data is too short" 等のエラー文字列)

💻 使用例

SQL COVID-19 パンデミック宣言がタクシー乗車数に与えた影響の分析 
SELECT pickup_date, trip_count, predicted_trip_count, lower_bound, upper_bound
FROM AI.CAUSAL_EFFECT(
  (
    SELECT DATE(pickup_datetime) AS pickup_date, COUNT(*) AS trip_count
    FROM `bigquery-public-data.new_york_taxi_trips.tlc_yellow_trips_2020`
    WHERE EXTRACT(YEAR FROM pickup_datetime) = 2020
    GROUP BY pickup_date
  ),
  data_col => 'trip_count',
  timestamp_col => 'pickup_date',
  intervention_timestamp => '2020-03-11',  -- WHO が COVID-19 をパンデミックと宣言
  num_post_intervention_points => 120,
  output_time_series => TRUE);

会話型分析では、同じ分析を次のような自然言語プロンプトで実行できます。

💬 "Quantify the impact of the COVID-19 pandemic declaration on March 11, 2020 on daily taxi trips."

🛠️ 設定方法

✅ 前提条件

✓Gemini in BigQuery (会話型分析) が利用可能なプロジェクトであること
✓必要な IAM ロール: roles/geminidataanalytics.dataAgentCreator (データエージェント作成)、roles/cloudaicompanion.user (ステートフルなチャット)、roles/bigquery.user (BigQuery データへのアクセス)
✓時系列データに介入前・介入後の両方の期間が含まれ、予測に十分な履歴 (最低 3 データポイント以上) があること

📋 手順

1

データエージェントまたは直接会話を開始

BigQuery Studio で、分析対象テーブルを知識ソースとするデータエージェントを作成するか、データソースとの直接会話を開始します。

2

自然言語で因果効果分析を依頼

「2026 年 9 月 1 日に開始したキャンペーンが日次売上に与えた影響を定量化して」

エージェントが AI.CAUSAL_EFFECT を含む SQL を生成し、効果の大きさと統計的有意性を回答します。

3

(任意) 検証済みクエリとして登録

定期的に実施する効果測定は、AI.CAUSAL_EFFECT を使った SQL を検証済みクエリ (verified query) として登録することで、回答の精度と再現性を高められます。

⚖️ メリットと制約事項

👍 メリット

  • 効果測定の民主化: キャンペーン、価格変更、障害、外部イベントなどの影響を、SQL や統計の専門知識なしに自然言語で定量化
  • 意思決定の高速化: p 値付きの統計的な裏付けのある回答が即座に得られる
  • コントロール群が不要: 単変量モデリングで反実仮想ベースラインを構築するため、コントロール系列や外部共変量が不要。スピルオーバーによるバイアスも回避
  • スケーラブルな並列分析: id_cols で店舗別・商品別など複数の時系列を 1 クエリで分析
  • 保守的な有意性判定: ARIMA_PLUS の標準誤差ベースの p 値で偽陽性が少ない

⚠️ 制限事項・考慮点

  • Preview 機能であり、Pre-GA Offerings Terms が適用される (サポートが限定的で、仕様変更の可能性)
  • 最低 3 データポイント以上の履歴が必要 (不足すると "The time series data is too short" エラー)
  • 単変量モデリングのため、介入と同時期に発生した別の要因の影響を分離できない
  • Gemini の回答は誤りを含む可能性があるため、重要な意思決定の前には生成 SQL と結果の検証を推奨
  • 介入タイムスタンプの指定が結果を大きく左右するため、正確な発生時点の把握が必要
  • 会話型分析のジョブには ca-bq-job: true などのラベルが付与されるため、コスト管理・監査に活用可能

💡 ユースケース

🛒 1. マーケティングキャンペーンの増分効果測定

シナリオ: 小売企業が特定の日に開始した広告キャンペーンについて、「キャンペーンがなかった場合」と比較した増分売上を測定したい。

SQL 店舗別のキャンペーン効果分析 
SELECT *
FROM AI.CAUSAL_EFFECT(
  TABLE `project.dataset.daily_sales`,
  data_col => 'sales_amount',
  timestamp_col => 'sales_date',
  intervention_timestamp => '2026-09-01',
  id_cols => ['store_id']);

効果: 店舗ごとの絶対効果・相対効果と p 値が 1 クエリで得られ、統計的に有意な効果を持った店舗を特定できる。会話型分析では「9 月 1 日のキャンペーンの店舗別の効果を教えて」という質問だけで実行可能。

💰 料金・利用可能リージョン

💵 料金: AI.CAUSAL_EFFECT は内部的に ARIMA_PLUS 予測を使用する BigQuery の AI/ML 関数であり、 クエリの実行はエディション (スロット) またはオンデマンド (処理バイト数) で課金されます。 会話型分析の利用には Gemini in BigQuery が必要です。Preview 期間中の正確な料金は 公式料金ページ (BigQuery ML pricing) を参照してください。
🌐 利用可能リージョン: 公式ドキュメントではリージョンごとの提供状況が明示されていません。 Gemini in BigQuery のデータ処理ロケーションについては Where Gemini in BigQuery processes your data を参照してください。

🔗 関連サービス・機能

💬 Gemini in BigQuery / Conversational Analytics API

会話型分析の基盤。データエージェントの作成、ステートフルなチャット、検証済みクエリの管理を提供。

📈 AI.FORECAST / AI.DETECT_ANOMALIES

会話型分析がサポートする他の時系列分析関数。予測 → 施策実施 → 効果測定という一連のサイクルを BigQuery 内で完結できる。

📉 ML.TREND / ML.SEASONALITY / ML.DETECT_CHANGE_POINTS

トレンド分析・季節性分析・変化点検知。介入の影響を多角的に裏付ける補完的な分析手法。

🔍 AI.KEY_DRIVERS

期間間のメトリクス変化の主要因を特定する関数。因果効果の「大きさ」に加えて「要因」を掘り下げる際に併用できる。

🤖 ARIMA_PLUS (BigQuery ML)

AI.CAUSAL_EFFECT が反実仮想ベースラインの構築に使用する時系列予測モデル。

📝 まとめ

「施策は本当に効いたのか」という因果の問いに、BigQuery の会話型分析が自然言語だけで統計的な裏付け付きの回答を返せるようになりました。

✓コントロール群を用意せずに ARIMA_PLUS の反実仮想予測で効果を定量化できるため、A/B テストが難しい全体施策や外部イベントの影響分析に特に有効
✓まずは公開データセットを使ったサンプルプロンプト (COVID-19 のタクシー乗車数への影響分析など) で動作を確認
✓自社の効果測定ワークフローへの組み込み (検証済みクエリによる定型レポート化) を検討するのがおすすめ
