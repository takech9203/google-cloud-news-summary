Google SecOps Marketplace SOAR Feature / Changed

📋 概要

Google SecOps Marketplace で、SOAR プレイブックから利用できる 5 系統 6 インテグレーションが同日にアップデート。 対象は FireEye HX (Trellix Endpoint Security)、Proofpoint Email Protection、Wiz、Microsoft Graph Mail / Delegated、ServiceNow。

更新の中心は インシデント対応の自動化範囲の拡大 (FireEye HX のファイル取得・封じ込め状態確認、Proofpoint の隔離メール操作) と、 外部プラットフォームとの同期・認証の強化 (Wiz の双方向同期ジョブと Gov/FedRAMP 対応、ServiceNow の OAuth 認証対応)。 SOC チームのレスポンスアクションが増え、政府系・FedRAMP 準拠環境などでも利用しやすくなった。

❌ Before: アップデート前の課題

  • FireEye HX: ファイル取得・封じ込め状態確認の専用アクションがなく、Contain Host はエンティティ (IP / ホスト名) 指定のみで Agent ID を直接指定できない
  • Proofpoint: 隔離メールの転送・リリースはコンソールでの手動操作が必要
  • Wiz: 認証 URL を切り替えられず Gov (FedRAMP) 環境対応が困難。Wiz Threats と SecOps ケースの継続同期の仕組みもなし
  • ServiceNow: Sync Incidents Job は Basic 認証 (ユーザー名 / パスワード) のみ

✅ After: アップデート後の改善

  • FireEye HX v26.0: Get File / Check Containment Status を追加。Contain Host / Cancel Host Contain に Agent Id パラメータ追加
  • Proofpoint v11.0: Forward / Release Quarantined Email で隔離メール対応をプレイブックから自動化
  • Wiz v10.0: Authentication URL で Gov (FedRAMP)・カスタム環境対応。双方向同期ジョブでステータス・コメント・重大度を継続同期
  • Graph Mail v46.0 / Delegated v23.0: Wait For Email From User / Search Emails のパラメータ・フィルタ改善
  • ServiceNow v71.0: OAuth 認証 (クライアントクレデンシャル / リフレッシュトークン) に対応

Google SecOps SOAR のプレイブックアクションとジョブが、5 つの外部セキュリティ / ITSM 製品と連携する構成。 今回の更新で アクションの追加 (FireEye HX、Proofpoint)、双方向同期ジョブの追加 (Wiz)、認証方式の強化 (Wiz、ServiceNow) が行われた。

⚡ 主要機能

🖥️ 1. FireEye HX v26.0: 新アクションと Agent Id パラメータ

✓新アクション「Get File」「Check Containment Status」で、対象ホストからのファイル取得と封じ込め状態の確認をプレイブックから実行可能
✓「Contain Host」「Cancel Host Contain」に Agent Id 入力パラメータが追加され、IP / ホスト名エンティティに加えてエージェント ID による直接指定が可能
✗Contain Host / Cancel Host Contain は FireEye HX 側の制約により Linux ホストには非対応

📧 2. Proofpoint Email Protection v11.0: 隔離メール操作アクション

✓「Forward Quarantined Email」: 隔離されたメールを指定先へ転送
✓「Release Quarantined Email」: 誤検知と判断された隔離メールを受信者へ解放
✓フィッシング対応プレイブックにおける隔離メールのハンドリングを自動化

☁️ 3. Wiz v10.0: Gov/FedRAMP 対応と双方向同期ジョブ

✓Authentication URL パラメータの追加で、Gov (FedRAMP) 環境およびカスタム環境の認証エンドポイントを指定可能
✓新ジョブ「Wiz and Google SecOps Bi-directional Sync Job」で Wiz Threats と Google SecOps ケースを継続同期。同期フィールドは Status / Comments / Product Link / Severity から選択 (デフォルトはすべて)
✓ジョブパラメータ: Environment Name、Wiz API Root (デフォルト https://api.us.wiz.io/graphql)、Client ID / Client Secret、Max Hours Backwards (1〜720、デフォルト 24)、Verify SSL、Fields to sync

📬 4. Microsoft Graph Mail v46.0 / Delegated v23.0: 検索・待機アクションの強化

✓「Wait For Email From User」「Search Emails」のパラメータとフィルタリングオプションが更新され、メール検索・待機の条件指定が改善
✓アプリケーション権限版 (Graph Mail) と委任権限版 (Graph Mail Delegated) の両方に同様の更新を適用

🎫 5. ServiceNow v71.0: Sync Incidents Job の OAuth 認証対応

✓「Sync Incidents Job」で OAuth 2.0 認証をサポート
✓クライアントクレデンシャル (Client ID / Client Secret) またはリフレッシュトークンで認証可能。両方設定時はリフレッシュトークンが優先
✗リフレッシュトークンは 90 日で失効する点に注意

🛠️ 設定方法

✅ 前提条件

✓Google SecOps (SOAR 機能が有効) のインスタンスがあること
✓各サードパーティ製品側で API 認証情報を発行済みであること
  • Wiz: サービスアカウントの Client ID / Client Secret と適切な API スコープ (例: read:issues、write:issue_status など。組織ポリシー上問題なければ read:all / write:all / update:all も可)
  • ServiceNow: OAuth 利用時は Client ID / Client Secret またはリフレッシュトークン。Sync Incidents Job の実行には ITIL (itil) ロールが必要

📝 手順

  1. Marketplace でインテグレーションを更新
    Google SecOps コンソールの Marketplace タブから対象インテグレーション (FireEye HX、Proofpoint Email Protection、Wiz、Microsoft Graph Mail、ServiceNow) を最新バージョンに更新する。
  2. インテグレーションパラメータを構成
    各インテグレーションの構成画面で接続情報を設定。Wiz で Gov (FedRAMP) 環境やカスタム環境を使用する場合は、新しい Authentication URL パラメータに環境に応じた認証エンドポイントを指定する。
  3. ジョブを構成 (Wiz / ServiceNow)
    ジョブスケジューラで「Wiz and Google SecOps Bi-directional Sync Job」を新規構成し、Fields to sync を選択。ServiceNow の Sync Incidents Job では「Use Oauth Authentication」を有効にし、クライアントクレデンシャルまたはリフレッシュトークンを設定する。
  4. プレイブックに新アクションを組み込み
    既存のフィッシング対応・エンドポイント封じ込めプレイブックに、新アクション (Get File、Check Containment Status、Forward/Release Quarantined Email など) を追加する。

💡 メリット

💼 ビジネス面

✓対応の迅速化: 隔離メールのリリースやホスト封じ込め状態の確認が自動化され、SOC アナリストの手動作業と平均対応時間 (MTTR) を削減
✓規制対応環境での利用拡大: Wiz の Gov (FedRAMP) 環境対応により、政府系・規制業種の顧客でも同一のプレイブック資産を活用可能
✓セキュリティガバナンスの強化: ServiceNow 連携でパスワードベースの認証から OAuth 2.0 へ移行でき、認証情報管理のリスクを低減

⚙️ 技術面

✓封じ込め操作の精度向上: Agent Id によるホスト指定で、同名ホストや IP 変動環境でも対象を一意に特定した封じ込めが可能
✓双方向同期による状態整合: Wiz Threats と Google SecOps ケースのステータス・コメント・重大度が自動同期され、二重管理やステータス不整合を防止
✓メールトリアージの柔軟性: Graph Mail 系アクションのフィルタリング強化により、承認フローや通知確認などメール駆動のプレイブック条件をより細かく制御可能

⚠️ デメリット・制約事項

🚫 制限事項
  • FireEye HX の Contain Host / Cancel Host Contain アクションは Linux ホストに非対応
  • ServiceNow の OAuth リフレッシュトークンは 90 日で失効するため、ローテーション運用が必要
  • Wiz Bi-directional Sync Job の Max Hours Backwards は 最大 720 時間 (30 日) まで
🤔 考慮すべき点
  • バージョンアップ後は既存プレイブックのアクションパラメータ (特に Graph Mail の Wait For Email From User / Search Emails) が変更されている可能性があるため、動作確認を推奨
  • Wiz の同期ジョブは同期対象フィールド (Status、Comments、Product Link、Severity) を明示的に選択する設計のため、運用ポリシーに合わせた選定が必要
  • ServiceNow でクライアントクレデンシャルとリフレッシュトークンの両方を設定した場合、リフレッシュトークンが優先される

🎯 ユースケース

📧 ユースケース 1: フィッシングメールの誤検知対応の自動化

シナリオ: Proofpoint で隔離されたメールについて、SOC が調査の結果誤検知と判断した場合、従来は Proofpoint コンソールで手動リリースしていた。

実装例: フィッシング対応プレイブックに「Release Quarantined Email」を組み込み、アナリストの承認ステップの後に自動でメールを解放。調査用に「Forward Quarantined Email」で検体をサンドボックス解析用メールボックスへ転送。
