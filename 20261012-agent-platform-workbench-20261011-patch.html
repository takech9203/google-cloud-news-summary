☁️ Agent Platform Workbench Gemini Enterprise Agent Platform ✅ Fixed 🔄 Change (パッチリリース)

📌 概要

Gemini Enterprise Agent Platform のコンポーネントである Agent Platform Workbench (旧 Vertex AI Workbench) のインスタンスイメージに、パッチリリース 20261011.00_p0 が公開されました。リリース候補 (20261011-2130-rc0 / 20261011-2230-rc0) に続くパッチ版です。

本パッチでは、アップストリーム依存パッケージの最新化 (Change) に加えて、pyOpenSSL と cryptography のバージョン不整合が原因で gcloud / gsutil が OpenSSL.crypto の AttributeError により起動 (ロード) に失敗する問題が修正 (Fixed) されました。ノートブックやターミナルから CLI を使う全ユーザーにとって、運用上重要なメンテナンスリリースです。

🔴 アップデート前の課題

  • pyOpenSSL と cryptography のバージョン不整合で、gcloud / gsutil 実行時に OpenSSL.crypto の AttributeError が発生し CLI がロード不能
  • CLI に依存するワークフロー (Cloud Storage へのデータ転送、リソース操作など) が実行できない状態になり得た
  • 回避には利用者側でのパッケージバージョンの手動調整が必要

🟢 アップデート後の改善

  • バージョン不整合が解消され、gcloud / gsutil が正常にロードされるように
  • アップストリーム依存パッケージが最新化され、セキュリティとパッケージ鮮度が維持される
  • 利用者側での手動のパッケージ修復作業が不要に

⚙️ 設定方法 (パッチの適用 = 環境のアップグレード)

🤖 方法 1: 自動アップグレード

インスタンス作成時に「Environment auto-upgrade」を有効化している場合、指定スケジュール (notebook-upgrade-schedule メタデータ、unix-cron 形式・GMT) で新イメージを自動チェック・適用。

→実行中のインスタンスにのみ適用 (停止中は対象外)
→スケジュールはインスタンス詳細ページの「Environment auto-upgrade」セクションから変更可能

🖱️ 方法 2: 手動アップグレード

  1. Google Cloud コンソールの「Instances」ページを開く
  2. 対象インスタンスが停止中なら起動する (実行中のみアップグレード可能)
  3. インスタンス名をクリックし「Instance details」ページで Upgrade をクリック
  4. データのバックアップ取得を確認してから Upgrade を実行
💡 ポイント: アップグレードはブートディスクを新しいイメージに置き換え、データディスク上のデータは保持されます。問題が発生した場合は「Upgrade history」から Rollback で以前のバージョンに戻せます。

📋 アップグレード時に保持されるもの / されないもの

コンポーネント アップグレード結果
ML フレームワーク / プリインストール依存関係 🔄 更新される
/home/jupyter 配下のローカルファイル・ノートブック ✅ 保持される
ユーザーがインストールしたライブラリ ⚠️ 原則再インストールが必要 (pip install --user なら保持)
ユーザーがインストールした OS パッケージ ❌ 保持されない
GPU ドライバ 🔄 更新される

✗アップグレード可能なのはデュアルディスク (ブート + データ) 構成のインスタンスのみ
✗アップグレード後の後方互換性は保証されない
🤔 考慮すべき点
→アップグレード前のデータのコピー (バックアップ) 取得が公式に推奨
→ブートディスクに pip / Conda でインストールしたライブラリは失われるため再インストールが必要 (--user フラグで /home/jupyter/ に保持可能)
→実行中のユーザー操作に影響し得るため、作業時間帯に注意
