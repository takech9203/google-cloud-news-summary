🗺️ Datastream: SQL Server の空間データ型レプリケーションをサポート

Datastream 一般提供 (Feature) GEOMETRY / GEOGRAPHY
📅 リリース日: 2026-10-09

📝 概要

Datastream が SQL Server ソースの GEOMETRY / GEOGRAPHY 空間データ型のレプリケーションをサポートしました。 これまで対象外だった空間データを含むテーブルも、他のカラムと同様に BigQuery などの宛先へストリーミングできるようになります。

SQL Server の空間型は、Datastream の統一型 (unified type) GEOMETRY にマッピングされます。 統一型は WKB (Well-Known Binary) 形式の値 (value)、空間参照系 ID (srid)、ジオメトリの種類 (type) の 3 フィールドで構成され、BigQuery では同じ構造の STRUCT 型として格納されます。

店舗位置・配送エリア・不動産区画などの地理空間情報を SQL Server で管理する企業が、 BigQuery の地理空間分析と組み合わせてニアリアルタイム分析を行うための重要なアップデートです。

❌ Before (アップデート前)

  • GEOMETRY / GEOGRAPHY カラムはレプリケーションされず、空間データを宛先に届けるには別途エクスポート処理や変換パイプラインの構築が必要
  • 空間データを含むテーブルのニアリアルタイム分析 (BigQuery の地理空間関数との組み合わせ) が Datastream 単体では実現できなかった

✅ After (アップデート後)

  • GEOMETRY / GEOGRAPHY カラムが統一型 GEOMETRY としてレプリケーションされる
  • BigQuery では value (WKB)、srid、type をネストした STRUCT として格納され、ロスレスに空間データを転送できる
  • 既存ストリームもラベル enable_sqlserver_spatial_types: true の追加で有効化できる

SQL Server の空間データ型カラムが Datastream の統一型 GEOMETRY (WKB 値 + SRID + ジオメトリ種別) に変換され、 BigQuery では STRUCT 型として格納されるデータフローを示しています。

⚡ 主要機能

1️⃣ SQL Server 空間データ型のレプリケーション

→GEOMETRY 型 (平面座標系) と GEOGRAPHY 型 (測地座標系) の両方に対応
→どちらも Datastream の統一型 GEOMETRY にマッピング

2️⃣ ロスレスな統一型表現

→統一型 GEOMETRY は value (WKB バイト列)、srid (空間参照系 ID)、type (ジオメトリ種類) の 3 フィールドを持つレコード型
→Avro ではカスタムレコード型、JSON ではネストした JSON として出力

3️⃣ 既存ストリームでの有効化オプション

→サポート導入前に作成されたストリームでは空間カラムはデフォルトでレプリケーションされない
→ラベル enable_sqlserver_spatial_types: true の追加で既存ストリームでも有効化可能

🔧 技術仕様

📐 データ型マッピング

GEOMETRY GEOMETRY STRUCT (value: BYTES (WKB 形式), srid: INT64, type: STRING)
GEOGRAPHY GEOMETRY STRUCT (value: BYTES (WKB 形式), srid: INT64, type: STRING)

🌍 他ソースの空間データ型対応状況 (参考)

ソース 空間データ型 Datastream での扱い
SQL Server GEOMETRY / GEOGRAPHY ✅ サポート (今回のアップデート)
MySQL GEOMETRY ❌ UNSUPPORTED
Oracle SDO_GEOMETRY ❌ UNSUPPORTED
PostgreSQL POINT / POLYGON など ❌ UNSUPPORTED
💡 ポイント: 空間データ型のレプリケーションは SQL Server ソースならではの差別化ポイントです。MySQL / Oracle / PostgreSQL の空間型は引き続き未サポートです。

⚙️ 設定方法

既存ストリームでの空間データ型レプリケーションの有効化

空間データ型サポート導入前に作成されたストリームでは、GEOMETRY / GEOGRAPHY カラムはデフォルトではレプリケーションされません。有効化するには、対象ストリームに以下のラベルを追加します。

YAML ストリームに追加するラベル 
# ラベルキー: 値
enable_sqlserver_spatial_types: true
✅ 新規ストリーム: 新規に作成するストリームでは、空間データ型はデフォルトでレプリケーション対象となります。

👍 メリット

💼 ビジネス面

✓地理空間データのニアリアルタイム分析: 店舗・物流・不動産・IoT デバイスの位置情報を BigQuery にストリーミングし、鮮度の高い地理空間分析が可能に
✓パイプライン構築コストの削減: 空間データ専用のエクスポート / 変換処理を別途開発・運用する必要がなくなる

🛠️ 技術面

✓ロスレスな転送: WKB 値に加えて SRID とジオメトリ種別が保持され、座標系情報を失わずに転送できる
✓標準形式 (WKB) での格納: BigQuery の地理空間関数など WKB を扱えるツールでの後続処理と親和性が高い

⚠️ デメリット・制約事項

🚧 制限事項

•サポート導入前に作成された既存ストリームでは、空間カラムはデフォルトでレプリケーションされない (ラベル enable_sqlserver_spatial_types: true の追加が必要)
•ユニークインデックスのないテーブルでは、ラージオブジェクトカラム (GEOMETRY / GEOGRAPHY を含む TEXT、NTEXT、XML、IMAGE など) の CDC は非サポート (ラージオブジェクトカラムをストリームに含めなければ CDC は可能)
•トランザクションログ方式の CDC では、ユニークインデックスのないテーブル、またはユニークな非クラスター化インデックスのみで可変長カラム (VARCHAR、VARBINARY、NVARCHAR、GEOMETRY、GEOGRAPHY) を含むテーブルにおいて、ラージオブジェクトカラムの CDC は非サポート

🤔 考慮すべき点

→トランザクションログ方式では、GEOMETRY / GEOGRAPHY などの値はソースへのポイントインタイム照会 (supplementation) で補完される。短時間に連続する更新や挿入直後の削除では中間の変更がキャプチャされない可能性があり、append-only 書き込みモードでは特に注意
→BigQuery には STRUCT (WKB バイト列) として格納されるため、BigQuery の GEOGRAPHY 型として直接扱う場合は WKB からの変換処理が必要

🎯 ユースケース

📍 ユースケース 1: 店舗・配送エリアデータのニアリアルタイム地理空間分析

シナリオ: 小売・物流企業が SQL Server で店舗位置 (GEOGRAPHY) や配送エリアのポリゴン (GEOMETRY) を管理しており、BigQuery で売上データと組み合わせた商圏分析を行いたい。

効果: ストリームに空間カラムを含めるだけで、位置情報が WKB 形式で BigQuery に継続的に反映され、専用のエクスポートジョブなしで鮮度の高い商圏分析が可能になる。

🔁 ユースケース 2: 既存の SQL Server ストリームへの空間データ追加

シナリオ: すでに Datastream で SQL Server から BigQuery へレプリケーションを行っているが、これまで空間カラムが宛先に反映されていなかった。

YAML 実装例: 既存ストリームへのラベル追加 
# 既存ストリームにラベルを追加して空間データ型のレプリケーションを有効化
enable_sqlserver_spatial_types: true

効果: ストリームを作り直すことなく、既存ストリームで GEOMETRY / GEOGRAPHY カラムのレプリケーションを有効化できる。

🔗 関連サービス・機能

📊 BigQuery

Datastream の主要な宛先。空間データは STRUCT (WKB 形式の BYTES + SRID + 種別) として格納され、BigQuery の地理空間分析機能と組み合わせて活用できる。

🪣 Cloud Storage

Datastream のもう 1 つの宛先。統一型 GEOMETRY は Avro のカスタムレコード型、または JSON のネスト構造として出力される。

🗄️ Cloud SQL for SQL Server

Datastream の SQL Server ソースとして利用できるマネージドデータベース。
