📋 概要

Google SecOps SOAR に新機能Calculated Fields (計算フィールド)がプレビューとして追加されました。セキュリティオペレーションのケースおよびアラート内で、論理的な数式を定義することで既存フィールドの値に基づいた新しいデータポイントを動的に導出できるようになります。

さらに、UDM Searchにおいて相対時間範囲と絶対時間範囲のオプションが追加され、検索結果の取得に必要な期間をより柔軟に定義できるようになりました。

❌ Before (課題)

  • 派生データ (リスクスコアの分類など) を手動で入力する必要があった
  • フィールド値の変更時に派生フィールドが自動更新されず不整合が発生
  • UDM Search の時間範囲指定が限定的
  • テスト環境と本番環境のアラート区別に手動判断が必要

✅ After (改善)

  • 論理式による計算フィールドでデータ導出が完全自動化
  • 依存フィールド変更時にリアルタイムで再評価、常に最新値を保持
  • 相対・絶対時間範囲の両方をサポートし柔軟な検索が可能
  • 自動リスクスコアリングでインシデントトリアージが加速

🏗️ アーキテクチャ図

Calculated Fields の動作フロー: ケースまたはアラートのフィールド値が変更されると、計算エンジンが依存関係を検出し、定義された論理式を評価して結果をターゲットフィールドにリアルタイムで格納します。

⚡ 主要機能

🧮 Calculated Fields

  • 論理式を定義してケースやアラート内の既存フィールドから新しい値を動的に計算
  • IF/THEN/ELSE 構文による条件分岐ロジック
  • 依存フィールド変更時に同期的リアルタイム再評価
  • 計算結果は Free Text 型カスタムフィールドに自動格納

📐 フィールドスコーピング

  • CaseCustom.YourField - ケーススコープ
  • AlertCustom.YourField - アラートスコープ
  • Both スコープ: ケースとアラートで個別ロジック維持可能

🕐 UDM Search 時間範囲

  • 相対時間範囲: 現在時刻から逆算 (秒/分/時/日/週/月/年)
  • 絶対時間範囲: カレンダープリセット、正確な日時選択
  • イベント時間タブ: 特定イベント起点の時間バッファ設定

UDM Search 時間範囲オプション

モード 設定方法 用途
相対時間範囲 数値 + 単位 (Seconds/Minutes/Hours/Days/Weeks/Months/Years) 直近の期間を動的に検索
絶対 - プリセット サイドバーからプリセット範囲を選択 定型的な期間の検索
絶対 - 日付選択 カレンダーで開始日と終了日をクリック 特定期間の精密な検索
絶対 - イベント時間 Event Time タブで日付を選択し時間バッファ設定 イベント前後の調査

数式の構文例

Formula 
IF ([case.priority] == "High") THEN "Urgent" ELSE "Standard"

数式では関数、演算子、フィールド参照を組み合わせて論理式を構築します。IF 条件には括弧が必要で、キーワードは大文字で記述する必要があります。

📝 前提条件: Google SecOps SOAR の Settings メニューおよび Case Data 管理権限を持つ管理者アクセスが必要。ターゲットフィールドとして使用する Free Text 型のカスタムフィールドが事前に作成されていること。

Step 1: カスタムフィールドの作成

Settings > Case Data > Custom Fields に移動し、新しいカスタムフィールドを作成

  • タイプを「Free Text」に設定
  • スコープを Case / Alert / Both に設定
  • フィールドを Active 状態にする

Step 2: Calculated Field の作成

Settings > Case Data > Calculated Fields に移動

  1. 「Add」をクリック
  2. 一意の名前と説明を入力
  3. Target Field エリアで結果を格納するカスタムフィールドを選択
  4. テキストエディタで数式を構築
  5. 「Save」をクリックして保存
Formula Example 
IF ([case.priority] == "High") THEN "Urgent" ELSE "Standard"

Step 3: UDM Search での時間範囲設定

  1. Investigation > SIEM Search に移動
  2. 検索バー横の「Time Range」をクリック
  3. Absolute または Relative を選択
  4. 時間範囲を設定して「Run Search」をクリック

→ 循環依存検出: システムが自動的に循環依存を防止し無限ループ回避
→ 柔軟な時間範囲クエリ: イベントベースのタイムフレームで調査精度向上

⚠️ デメリット・制約事項

⚠️ 制限事項:
  • Preview (Pre-GA) のため、機能の変更や互換性の問題が発生する可能性
  • ターゲットフィールドは Free Text 型に限定 (数値型やブール型は不可)
  • 他の計算フィールドの依存先となっているフィールドはターゲットに使用不可
  • 削除済みまたは無効化されたフィールドには書き込み不可
💡 考慮すべき点:
  • 複雑な数式は構文エラーが発生しやすい (IF 条件の括弧、キーワードの大文字表記に注意)
  • 多数の計算フィールドを定義する場合、依存関係の管理が複雑になる可能性
  • Pre-GA 機能のため、本番環境での使用前に十分なテストを推奨
  • UDM Search の時間範囲機能も Pre-GA で、サポートが限定的な場合がある

🎯 ユースケース

🚨 ユースケース 1: 自動リスクスコアリング

シナリオ: SOC チームがケースの優先度とイベント量に基づいて自動的にリスクレベルを分類し、トリアージを効率化したい。

Formula 
IF ([case.priority] == "Critical" OR [case.priority] == "High") THEN "Urgent - Immediate Response Required" ELSE IF ([case.priority] == "Medium") THEN "Moderate - Review Within 4 Hours" ELSE "Low - Standard Queue"

効果: 高リスクのインシデントが即座に分類され、適切な対応チームに自動エスカレーション。平均応答時間 (MTTR) の短縮に貢献。

🧪 ユースケース 2: テスト環境フィルタリング

シナリオ: テスト環境からのアラートを自動的に識別し、本番環境のアラートと区別することでアナリストのノイズを削減したい。

Formula 
IF (CONTAINS([alert.name], "test") OR CONTAINS([alert.name], "staging")) THEN "Test Environment" ELSE "Production"

効果: テスト環境由来のアラートが自動ラベル付けされ、アラート疲れ (alert fatigue) が軽減。

🔍 ユースケース 3: イベントベースのタイムフレーム検索

シナリオ: 特定のセキュリティインシデント検出時刻の前後30分間のイベントを調査し、攻撃の全体像を把握したい。

効果: 絶対時間範囲のイベント時間タブで、インシデント発生時刻を基準に前後の時間バッファを設定し、関連イベントを漏れなく調査。攻撃の準備段階や横展開の痕跡を捕捉可能。
