⚡ Anthropic Claude Haiku 5.5 が利用可能に

📝 概要

2026 年 10 月 7 日、Anthropic の最新軽量モデル Claude Haiku 5.5 が Gemini Enterprise Agent Platform の Model Garden で GA (一般提供) になりました。 コーディング、サブエージェント、レイテンシに敏感な大規模ユースケース向けに設計された、高性能かつコスト効率の高いモデルです。

Haiku ファミリーとして初めて 100 万トークンの入力コンテキスト と 128,000 トークンの最大出力 に対応。 さらに Computer use と Memory tool もサポートし、上位モデル (Sonnet 5.5 / Opus 5.5) と 同等の機能セットを低コストで利用できます。

😕 Before: Claude Haiku 4.5 まで

  • 入力 200K / 出力 64K トークンに制限され、大規模コードベースや長大ドキュメントは上位モデルが必要
  • Computer use / Memory tool 非対応でエージェント用途に機能面の制約
  • 提供リージョンは us-east5、europe-west1 (+ global) に限定
  • グローバルエンドポイントのクォータは QPM 2,500 / 入力 TPM 2.5M にとどまる
  • 旧世代 Claude 3.5 Haiku は 2026-07-05 にシャットダウン済みで後継選択肢が必要

😀 After: Claude Haiku 5.5

  • 入力 1M / 出力 128K に拡大し、大規模リポジトリや長文を Haiku クラスの価格・速度で処理
  • Computer use、Memory tool、Web search、Batch predictions、Prompt caching、Function calling に対応
  • 米国・欧州マルチリージョン + グローバルエンドポイント、ML 処理は asia-southeast1 にも拡大
  • QPM 3,000 / 入力 TPM 30M / 出力 TPM 3M に大幅引き上げで並列実行に十分
  • Shared Model Lineage Quota と Provisioned Throughput をサポート
🎯 主な対象ユーザー: マルチエージェントシステムのサブエージェント、カスタマーサービスなどのリアルタイム応答、 大量データの並列処理といった「速度とコストが重要なワークロード」を Google Cloud 上で構築する開発者・アーキテクト。

🚀 主要機能

1️⃣ 100 万トークンコンテキストと 128K 出力

→最大入力トークン: 1,000,000、最大出力トークン: 128,000
→Haiku 4.5 (入力 200,000 / 出力 64,000) から大幅拡大、Sonnet 5.5 / Opus 5.5 と同等のコンテキスト長
→大規模コードベースの解析や長文 PDF の処理を軽量モデルの価格帯で実行可能

2️⃣ エージェント向け機能のフルサポート

→Computer use、Memory tool に新たに対応 (Haiku 4.5 では非対応)
→Web search、Batch predictions、Prompt caching、Function calling、Count tokens もサポート
→コーディングサブエージェント、カスタマーサービスエージェントの構築に必要な機能が揃う

3️⃣ マルチモーダル入力

→入力: テキスト、画像、PDF / 出力: テキスト
→画像・PDF の制限事項は Anthropic のドキュメント (Vision、PDF support) に準拠

4️⃣ 提供リージョンとクォータの拡大

→モデル提供: 米国マルチリージョン、欧州マルチリージョン、グローバルエンドポイント
→ML 処理: 米国・欧州マルチリージョンに加え asia-southeast1 (アジア太平洋)
→グローバルエンドポイントで QPM 3,000 / 入力 TPM 30,000,000 / 出力 TPM 3,000,000

1Model Garden でモデルを有効化

Google Cloud コンソールで Model Garden の Claude Haiku 5.5 モデルカードを開き、「Enable」をクリックします。

URL Model Garden モデルカード 
https://console.cloud.google.com/agent-platform/publishers/anthropic/model-garden/claude-haiku-5-5

2Anthropic SDK または curl でリクエストを送信

モデル名に claude-haiku-5-5 を指定して Gemini Enterprise Agent Platform のエンドポイントにリクエストを送信します。

Bash rawPredict リクエスト例 
MODEL="claude-haiku-5-5"
LOCATION="global"
PROJECT_ID="your-project-id"

curl -X POST \
  -H "Authorization: Bearer $(gcloud auth print-access-token)" \
  -H "Content-Type: application/json" \
  "https://aiplatform.googleapis.com/v1/projects/${PROJECT_ID}/locations/${LOCATION}/publishers/anthropic/models/${MODEL}:rawPredict" \
  -d '{
    "anthropic_version": "vertex-2023-10-16",
    "max_tokens": 1024,
    "messages": [
      {"role": "user", "content": "こんにちは、自己紹介をしてください。"}
    ]
  }'
💡 推奨: Anthropic は、モデルの誤用を記録するために、プロンプトと生成結果の 30 日間ロギングを有効にすることを推奨しています。

⚖️ メリットと制約事項

💼 ビジネス面のメリット

✓コスト効率の高い AI 活用: 入力 $0.10 / 100 万トークンの低価格で、無料枠プロダクトや大量トラフィックの UX を経済的に成立
✓スケーラビリティ: 高いクォータ (グローバルで入力 TPM 3,000 万) によりエンタープライズ規模の並列ワークロードに対応
✓モデルの長期利用: 廃止予定日が 2027 年 10 月 7 日以降と明示されており、本番採用の計画が立てやすい

🛠️ 技術面のメリット

✓軽量モデルで 1M コンテキスト: 大規模コードベース・長文ドキュメント処理を上位モデルなしで実現
✓エージェント機能のフルセット: Computer use、Memory tool、Function calling でサブエージェントの実装パターンが広がる
✓マルチリージョン + Provisioned Throughput: 可用性とスループット要件が厳しい本番システムにも適用可能

🚧 制限事項

✗出力はテキストのみ (画像・音声の生成は不可)
✗画像ファイルは最大 5 MB、1 リクエストあたり最大 100 枚 (Anthropic Claude モデル共通の制限)
✗モデル提供は米国・欧州マルチリージョンとグローバルエンドポイントのみ。ML 処理のアジア対応は asia-southeast1 に限られる

🤔 考慮すべき点

⚠️ 入力トークンが 100,000 を超えるリクエストには長文コンテキスト料金 (入力 $0.50 / 出力 $2.50 per 1M トークン) が適用されるため、コンテキスト長に応じたコスト設計が必要
⚠️ 複雑な推論や最高精度が求められるタスクには Claude Sonnet 5.5 / Opus 5.5 の方が適する場合がある
⚠️ Anthropic のリセラーポリシーにより、一部のリセラー管理下の請求先アカウントではモデルを有効化できない

💡 ユースケース

🤖 ユースケース 1: マルチエージェントシステムのサブエージェント

シナリオ: 大規模リファクタリングや移行プロジェクトで、オーケストレーター (Opus 5.5 / Sonnet 5.5) がタスクを分割し、多数の Haiku 5.5 サブエージェントが並列でコードを処理する。

Text 実装例: タスク分割構成 
オーケストレーター (Opus 5.5)
  ├─ サブエージェント 1 (Haiku 5.5): モジュール A のリファクタリング
  ├─ サブエージェント 2 (Haiku 5.5): モジュール B のテスト生成
  └─ サブエージェント 3 (Haiku 5.5): ドキュメント更新
✨ 効果: 1M コンテキストで大きなモジュールを丸ごと渡せるため分割の手間が減り、低価格でサブエージェントを大量並列実行できる。

💬 ユースケース 2: レイテンシ重視のカスタマーサービスエージェント

シナリオ: チャットボットやカスタマーサービスなど、応答速度が重要なリアルタイムアプリケーションに Haiku 5.5 を利用。プロンプトキャッシュで FAQ やポリシー文書のコンテキストを再利用する。

✨ 効果: 高速応答と低コスト (キャッシュヒット $0.01 / 1M トークン) を両立し、大量の同時セッションを経済的に処理できる。

📚 ユースケース 3: バッチでの大量ドキュメント処理

シナリオ: 大量の PDF・画像を含むドキュメントを Batch predictions で一括処理し、分類・要約・抽出を行う。

✨ 効果: バッチ料金 (入力 $0.05 / 出力 $0.25 per 1M トークン) により、オンライン料金の半額で大規模処理が可能。
