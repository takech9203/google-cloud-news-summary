プレリリースノート 6.26

IVR オーバーキャパシティ向けスケジュールコールバック & Salesforce PKCE / リフレッシュトークンローテーション対応
Contact Center as a Service (CCaaS) Prerelease (6.26 で提供予定) 📅 2026-10-23

📋 概要

CCaaS の次期バージョン 6.26 のプレリリースノートが公開されました。目玉は 2 つの新機能です。 1 つ目は IVR キューのオーバーキャパシティ (容量超過) 時のスケジュールコールバック。 キュー容量超過時に発信者がコールバック予約を選択でき、CCaaS が通話を仮想エージェントに引き渡し、仮想エージェントが Callback call API を通じてコールバックを予約します。 2 つ目は Salesforce の PKCE (Proof Key for Code Exchange) / リフレッシュトークンローテーション対応。 Salesforce が新規作成の接続アプリ・外部クライアントアプリで自動有効化するセキュリティ設定を要求するアプリにも、CCaaS を接続できるようになります。

このほか、ブランド発信者 ID ラベルの表示崩れや着信接続遅延をはじめとする多数の不具合修正が含まれます。

⚠️ 重要: 2 つの新機能はいずれもデフォルトで無効です。インスタンスでの有効化には Google Cloud サポートへの連絡が必要です。

❌ Before (アップデート前の課題)

  • IVR オーバーキャパシティのコールバックオプションは「キュー内の順番保持 → 先頭到達時にコールバック」方式のみで、希望日時を指定するスケジュールコールバックは利用不可
  • PKCE とリフレッシュトークンローテーションを必須とする Salesforce アプリには CCaaS を接続できず、新規作成アプリとの連携に支障 (Salesforce は新規アプリで両設定を自動有効化)
  • カナダフランス語でのブランド発信者 ID ラベル切れ、エージェント割り当て後の着信接続遅延などの不具合

✅ After (アップデート後の改善)

  • キュー容量超過時に発信者がコールバックの予約を選択可能に。仮想エージェントが Callback call API 経由で予約を登録
  • 管理者はグローバル / キュー単位で仮想エージェント・グリーティング・データパラメータを設定可能。レポーティングでコールバック登録有無を確認できる
  • PKCE 要求の Salesforce アプリに接続可能に。新しいリフレッシュトークンを保存し、トークン更新後も接続を維持。CCaaS 側の新たな設定手順は不要で、既存アプリは従来通り動作

キュー容量超過時に発信者がコールバック予約を選択すると、CCaaS が通話を仮想エージェントに引き渡し、仮想エージェントが Callback call API を通じてスケジュールコールバックを予約するフローです。

⚡ 主要機能

📅 1. IVR オーバーキャパシティ向けスケジュールコールバック

  • キュー容量超過時のデフレクションオプションとしてスケジュールコールバックが利用可能に
  • 発信者が予約を選択すると、CCaaS が通話を設定済みの仮想エージェントに引き渡し、仮想エージェントが Callback call API でコールバックを予約
  • 管理者は仮想エージェント、任意のグリーティング、引き渡すデータパラメータをグローバルまたはキュー単位で設定可能
  • レポーティングで各発信者のコールバック登録有無 (登録した / 登録せず離脱した) を確認可能
  • 設定場所: グローバルは Settings > Call > Overcapacity Deflection、キュー単位は Settings > Queue > IVR > Edit / View > [QUEUE] > Overcapacity Deflection > Configure

🔐 2. Salesforce: PKCE とリフレッシュトークンローテーション対応

  • PKCE (Proof Key for Code Exchange) とリフレッシュトークンローテーションを要求する Salesforce アプリへの接続が可能に
  • Salesforce は新規作成の接続アプリ (connected apps)・外部クライアントアプリで両設定を自動有効化 → 新規アプリとの連携に対応
  • CCaaS は Salesforce の管理者接続・エージェント接続の認可時に PKCE を使用
  • Salesforce が返す新しいリフレッシュトークンを保存し、以降のトークン更新後も接続を維持
  • これらの設定を使用しない Salesforce アプリは従来通り動作。CCaaS 側に新たな設定手順は不要

🔧 3. 主な不具合修正 (一部抜粋)

  • カナダフランス語環境で Outbound Number セレクタのブランド発信者 ID ラベルが途中で切れる問題を修正
  • エージェントへの割り当て後に着信の接続が大幅に遅延する問題を修正
  • ウィスパーアナウンスの複数回再生、エージェントデスクトップ通話パネルの読み込み遅延を修正
  • ノルウェー・デンマーク・スウェーデンの固定電話番号へのコールバックが誤って +1 プレフィックスでダイヤルされ失敗する問題を修正
  • Auto-Answer 設定のキューでも仮想エージェントのコールバック通話が手動応答を要求する問題を修正
  • このほか Agent Assist 使用時の通話接続安定性、Salesforce ケース作成遅延、レポーティング精度などに関する多数の修正 (詳細はリリースノート参照)

🛠️ 技術仕様

🔌 Callback call API の概要

スケジュールコールバックの予約・キャンセルをプログラムから実行できる API です。認証は Basic 認証を使用します。

操作エンドポイント
コールバックの予約POST https://<subdomain>.<domain>/apps/api/v1/calls
予約のキャンセルPATCH .../apps/api/v1/calls/scheduled/{id}/cancel
複数予約の一括キャンセルPATCH .../apps/api/v1/calls/scheduled/cancel
JSON 予約リクエストの例 
{
  "call_type": "ScheduledCall",
  "menu_id": 12345,
  "end_user_number": "+18005550100",
  "scheduled_at": "2025-09-02T14:30:00Z"
}

成功すると、call ID を含む call オブジェクトが返されます。

📊 オーバーキャパシティデフレクションのオプション

オーバーキャパシティデフレクションは、セッション開始時に推定待ち時間が設定したしきい値を超えた場合にトリガーされます。キュー単位の設定では以下のオプションから選択できます。

オプション動作
Message設定したメッセージを再生して通話を終了
Queue別のキューメニューに転送
Phone Number / SIP指定した電話番号または SIP URI に転送
Voicemailボイスメールの録音に誘導
Callbackキュー内の順番を保持して通話を終了し、順番が来たらコールバック
Keep Waitingそのままキューで待機
Scheduled Callback 6.26 で追加仮想エージェントが Callback call API 経由でコールバックを予約

⚙️ 設定方法

✅ 前提条件

  1. 本機能 (スケジュールコールバック、Salesforce PKCE 対応) はデフォルトで無効のため、Google Cloud サポートに連絡してインスタンスで有効化する
  2. スケジュールコールバックには、コールバック予約を処理する仮想エージェントの設定が必要
  3. オーバーキャパシティデフレクションのメッセージは Settings > Languages & Messages で設定しておく (オプションの追加・削除時は発信者向け案内メッセージの更新も必要)

🌐 ステップ 1: グローバル設定 (全キュー共通)

  • CCaaS ポータルで Settings > Call に移動
  • Overcapacity Deflection でスケジュールコールバックを設定
  • 使用する仮想エージェント、任意のグリーティング、引き渡すデータパラメータを選択

📋 ステップ 2: キュー単位の設定 (特定キューのみ)

  • Settings > Queue に移動
  • IVR (Interactive Voice Response) ペインで Edit / View をクリック
  • 対象キューを選択し Overcapacity Deflection > Configure をクリック
  • スケジュールコールバックのオプションを設定して保存
🔐 ステップ 3: Salesforce PKCE 対応 (該当環境のみ): CCaaS 側の追加設定は不要です。サポートによる有効化後、PKCE とリフレッシュトークンローテーションを要求する Salesforce アプリ (新規作成の接続アプリ・外部クライアントアプリ) との接続が可能になります。

🎯 ユースケース

📈 ユースケース 1: ピーク時間帯の放棄呼対策

シナリオ: 月曜午前などの問い合わせピーク時にサポートキューの推定待ち時間がしきい値を超過し、長時間待たされた発信者が離脱してしまう。

実装例: 対象キューの Overcapacity Deflection でスケジュールコールバックを有効化し、予約対話用の仮想エージェントとグリーティングを設定。発信者は希望に応じてコールバックを予約し、仮想エージェントが Callback call API で予約を登録する。

効果: 発信者は待ち続ける必要がなくなり、放棄呼を削減。レポーティングでコールバック登録率を測定し、デフレクション設定を継続的に改善できる。

🔐 ユースケース 2: Salesforce の新規接続アプリとの安全な連携

シナリオ: Salesforce 側で新規に作成した接続アプリ・外部クライアントアプリは PKCE とリフレッシュトークンローテーションが自動的に有効化されるため、これまで CCaaS との接続に支障があった。

効果: CCaaS が PKCE による認可とリフレッシュトークンの自動保存に対応したことで、追加設定なしで Salesforce の最新セキュリティ要件を満たすアプリと連携でき、トークン更新後も管理者・エージェント接続が維持される。

🔗 関連サービス・機能

  • 🤖 Conversational Agents (仮想エージェント): スケジュールコールバックの予約対話を担当し、Callback call API を呼び出す
  • 🔌 Callback call API: コールバックの予約・キャンセルをプログラムから実行する CCaaS の API
  • 🔄 Salesforce / Zendesk / ServiceNow 連携: Callback call API は各 CRM 連携と組み合わせて利用可能。レコードステータスに応じたコールバック動作を設定できる
  • 💬 Agent Assist: 本リリースで Agent Assist 使用時の通話接続安定性の修正が含まれる

📝 まとめ

CCaaS 6.26 のプレリリースノートでは、IVR キューの容量超過時に仮想エージェントと Callback call API を組み合わせたスケジュールコールバックが追加され、ピーク時の放棄呼対策の選択肢が広がります。

また、Salesforce の PKCE・リフレッシュトークンローテーション対応により、新規作成の Salesforce アプリとの連携も安全に継続できます。

両機能ともデフォルトで無効のため、利用を検討する場合は正式リリース後に Google Cloud サポートへの有効化依頼と、仮想エージェント・デフレクションメッセージの準備を進めることを推奨します。
