🔍 概要

BigQuery Data Transfer Service における Salesforce からのインクリメンタル (差分) データ転送が一般提供 (GA) となりました。毎回全データを転送するのではなく、前回の転送以降に変更されたデータのみを効率的に転送できるようになります。

ウォーターマークカラム (TIMESTAMP 型) を使用して変更を追跡し、Append (追記) または Upsert (更新/挿入) の2つの書き込みモードを選択可能。大規模な Salesforce データを持つ企業において、転送時間の短縮、コスト削減、データ鮮度の向上が実現されます。

⚡ 主要機能

🔄 インクリメンタル転送モード

ingestionType を incremental に指定して有効化。ウォーターマークカラム (TIMESTAMP 型) で変更を追跡し、初回は全量転送、2回目以降は差分のみを転送。

➕ Append 書き込みモード

新しい行のみを宛先テーブルに追加。CreatedDate 等のカラムをウォーターマークとして使用。重複の可能性がある点に注意。

🔁 Upsert 書き込みモード

プライマリキーに基づいて行の更新/挿入を判定。SystemModstamp をウォーターマークとして使用し、宛先テーブルを最新状態に保持。

📦 複数アセットの同時転送

1つの転送設定で複数の Salesforce オブジェクトを指定可能。各アセットに個別のウォーターマークカラムとプライマリキーを設定 (推奨: 最大10アセット)。

🛠️ 設定方法

前提条件

✓Google Cloud プロジェクトで BigQuery Data Transfer Service API が有効化されていること
✓Salesforce Connected App が作成済み (Consumer Key / Secret 取得済み)
✓BigQuery に宛先データセットが作成済みであること
✓ネットワークアタッチメントと Cloud NAT (静的 IP) が設定済みであること
✓Salesforce 側で IP 許可リストが設定済みであること

bq コマンドラインツールでの設定例

Bash 
bq mk --transfer_config \
  --target_dataset=mydataset \
  --data_source=salesforce \
  --display_name='Salesforce Incremental Transfer' \
  --params='{
    "assets": ["Account", "Contact"],
    "connector.authentication.oauth.clientId": "YOUR_CLIENT_ID",
    "connector.authentication.oauth.clientSecret": "YOUR_CLIENT_SECRET",
    "connector.authentication.oauth.myDomain": "YOUR_DOMAIN",
    "ingestionType": "incremental",
    "writeMode": "WRITE_MODE_UPSERT",
    "watermarkColumns": ["SystemModstamp", "SystemModstamp"],
    "primaryKeys": [["Id"], ["Id"]]
  }'
💡 ヒント: インクリメンタル転送では最小15分間隔で実行可能です。大規模データの場合は、前回の転送が完了する十分な時間を確保してスケジュールを設定してください。

⚠️ 制約事項・注意点

制限事項
✗ウォーターマークカラムは TIMESTAMP 型のみ (値は単調増加必須)
✗ソーステーブルの DELETE 操作は同期されない
✗1転送設定はインクリメンタル/フルのいずれか一方のみ
✗初回実行後はアセットリスト・書き込みモード・ウォーターマークカラム・PK の変更不可
✗Salesforce Sales Cloud のみサポート (Marketing Cloud 等は非対応)
✗バイナリフィールドを含むオブジェクト (Attachment, ContentVersion 等) は転送不可
💡 考慮すべき点:
  • Append モードでは重複データが発生する可能性あり
  • 初回実行は全量転送のため、大規模データセットでは時間がかかる
  • 転送設定後のパラメータ変更に大きな制約があるため、事前設計が重要
  • 同時実行数の制限 (10) のため、多数オブジェクトの場合は転送設定の分散が必要

💡 ユースケース

🎯 ユースケース 1: 営業パイプライン分析のリアルタイム化

シナリオ: 大企業の営業チームが Salesforce の商談データ (Opportunity) を BigQuery に転送し、Looker でパイプラインダッシュボードを構築。従来は日次全量転送で最大24時間のデータ遅延が発生。

Bash 
bq mk --transfer_config \
  --target_dataset=sales_analytics \
  --data_source=salesforce \
  --display_name='Opportunity Incremental Sync' \
  --params='{
    "assets": ["Opportunity", "OpportunityHistory"],
    "connector.authentication.oauth.clientId": "CLIENT_ID",
    "connector.authentication.oauth.clientSecret": "CLIENT_SECRET",
    "connector.authentication.oauth.myDomain": "mycompany",
    "ingestionType": "incremental",
    "writeMode": "WRITE_MODE_UPSERT",
    "watermarkColumns": ["SystemModstamp", "SystemModstamp"],
    "primaryKeys": [["Id"], ["Id"]]
  }'
効果: 15分間隔のインクリメンタル転送でダッシュボードがほぼリアルタイム更新。転送データ量が約95%削減。

🎯 ユースケース 2: 顧客マスター統合と CDC

シナリオ: マルチチャネルで顧客接点を持つ企業が、Salesforce の Account/Contact データを BigQuery に集約し、統合顧客マスターを構築。顧客情報の更新をリアルタイムに反映させ、マーケティングオートメーションやカスタマーサクセス施策に活用。

効果: Upsert モードで顧客レコードが常に最新状態。重複のない統合顧客マスターを維持し、カスタム ETL の開発・運用コストを排除。

🎯 ユースケース 3: コンプライアンス監査ログの蓄積

シナリオ: 金融機関が規制対応のため、Salesforce 上の活動履歴 (Task, Event) を BigQuery に蓄積し、監査証跡として保持。

効果: Append モードと CreatedDate ウォーターマークで新規レコードのみを効率的に追加。完全な履歴データが BigQuery に蓄積され、長期保存とコンプライアンス分析に活用可能。

🌍 利用可能リージョン

BigQuery Data Transfer Service はマルチリージョンリソースであり、BigQuery がサポートする全てのリージョンで利用可能です。転送設定は宛先データセットと同じロケーションに自動配置されます。

US (マルチリージョン) EU (マルチリージョン) asia-northeast1 (東京) asia-northeast2 (大阪) その他全ての BigQuery 対応リージョン
⚠️ 注意: ネットワークアタッチメントと VM インスタンスが異なるリージョンにある場合、クロスリージョンのデータ移動が発生する可能性があります。
