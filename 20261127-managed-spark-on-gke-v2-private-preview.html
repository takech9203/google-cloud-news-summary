⚡ Managed Service for Apache Spark on GKE v2

リリース日: 2026-11-27
☁️ Managed Service for Apache Spark ☸️ GKE 🔒 Private Preview

📌 概要

Google Cloud は、次世代の Managed Service for Apache Spark on GKE v2 を Private Preview として発表しました。 フルマネージドな Apache Spark ワークロードを、ユーザー自身の Standard GKE クラスタ上でネイティブに実行できるようになります。

Managed Service for Apache Spark on GKE は、GKE クラスタ上に仮想クラスタをデプロイして Spark ジョブを Pod として実行する仕組みを提供してきました。 GKE を標準のコンピューティング基盤として採用している組織が、Spark ワークロードを同じクラスタ上に統合し、リソース使用率の向上と運用の一元化を図れる点が特徴です。 今回の v2 は、この GKE 統合を「次世代 (next-generation)」として刷新するものです。

🎯 対象ユーザー: GKE 上でデータ処理基盤を統合したいプラットフォームエンジニアリングチームや、 Kubernetes ネイティブな運用 (ノードプール管理、スケジューリング、モニタリング) と Spark のフルマネージド体験を両立させたいデータエンジニアリングチーム
❌ Before (v1 世代の課題)
  • コンソールからの仮想クラスタ作成が非サポート (gcloud CLI / API のみ)
  • Spark エンジンは Spark 3.5 系 (Spark 3.5.1 / Java 11 / Python 3.8.5) にとどまり、サーバーレス版よりランタイム世代が古い
  • 仮想クラスタ作成時に専用ノードプールが作られ、仮想クラスタ削除後もノードプールが残るなどライフサイクル管理に注意が必要
✅ After (v2 での改善)
  • 次世代アーキテクチャにより、Standard GKE クラスタ上で Spark ワークロードを「ネイティブに」実行可能
  • 実行環境・スケーリング・ジョブ管理は引き続き Google がフルマネージドで提供。ユーザーはジョブ投入に集中
  • 既存の Standard GKE クラスタをそのまま活用でき、インフラの二重管理が不要
⚠️ 注: v2 の詳細な技術仕様 (対応 Spark バージョン、API の変更点など) は Private Preview 段階のため一般公開されていません。上記はリリースノートで確認できた内容に基づきます。

Managed Service for Apache Spark on GKE では、Spark のドライバーとエグゼキュータが GKE クラスタ上の Pod として実行され、 Pod のスケジューリングは GKE が管理します。v2 ではこの統合が次世代アーキテクチャとして刷新され、 Standard GKE クラスタ上でのネイティブ実行が可能になります。

🚀 主要機能

1️⃣ Standard GKE クラスタ上でのネイティブ実行
→ユーザーが所有する Standard GKE クラスタ上で、フルマネージドな Apache Spark ワークロードを直接実行できる
→GKE をコンピューティング基盤として標準化している組織が、Spark ワークロードを同一基盤に統合可能
2️⃣ フルマネージドな Spark 実行体験
→Spark の実行管理は Managed Service for Apache Spark が担い、ユーザーはジョブの開発と投入に集中できる
→従来の GKE 統合 (v1) と同様、専用の Spark クラスタ VM (マスター/ワーカー) を個別にプロビジョニングする必要がない
3️⃣ Private Preview としての提供
→利用にはプロジェクトの許可リスト (allowlist) 登録が必要
→登録希望は dataproc-previews@google.com へ連絡する

🔍 参考: 従来の Managed Service for Apache Spark on GKE (v1) の仕組み

v2 の詳細仕様は未公開のため、比較の参考として現行世代の仕組みを記載します。

💡 メリット

💼 ビジネス面
✓インフラの統合によるコスト効率: GKE クラスタを Spark と他のワークロードで共有でき、リソース使用率を高められる
✓運用の一元化: Kubernetes を中心としたプラットフォーム運用 (監視、セキュリティ、ガバナンス) に Spark ワークロードを組み込める
🔧 技術面
✓フルマネージドな Spark 実行: Spark クラスタの構築・管理を Google に任せつつ、実行基盤には使い慣れた GKE を利用できる
✓Kubernetes ネイティブな統合: Pod スケジューリングやノードプール管理など GKE の機能をそのまま活用できる

🎯 ユースケース

🏢 ユースケース 1: GKE 標準化組織での Spark ワークロード統合

シナリオ: 社内のアプリケーションをすべて GKE 上で運用している企業が、データパイプライン (Spark バッチ) だけ別のクラスタ基盤で運用しており、監視・セキュリティ運用が二重化している。

効果: Spark ワークロードを既存の Standard GKE クラスタに統合し、プラットフォーム運用を一元化。アイドルリソースの共有によりコスト効率も向上する。

🛠️ ユースケース 2: Kubernetes ネイティブなデータ基盤の構築

シナリオ: プラットフォームチームが Kubernetes ベースの社内データ基盤を構築しており、Spark の実行管理 (ドライバー/エグゼキュータのライフサイクル、スケーリング) は自前で運用したくない。

効果: Spark の実行管理をフルマネージドサービスに任せつつ、実行環境は自社の GKE クラスタ上に保持できるため、ガバナンス要件と運用負荷軽減を両立できる。
