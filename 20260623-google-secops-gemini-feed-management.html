🛡️ Google SecOps: Gemini Cloud Assist in Feed Management / Ingestion Metrics修正 / siemAlertId フィールド予約

Google SecOps (SIEM / SOAR) GA Feature Change Breaking
2026-06-23

📋 概要

Google SecOps に対する 3 つの重要なアップデートが発表されました。Feed Management への Gemini Cloud Assist 統合、インジェストメトリクスの精度修正、そして siemAlertId フィールドの破壊的変更です。

🔄 Before / After 比較

❌ アップデート前

  • Feed設定に迷った場合、別途ドキュメント検索が必要
  • インジェストメトリクスが過小に報告され、正確な容量把握が困難
  • siemAlertId がカスタムデータ格納に利用可能（非推奨だが制限なし）

✅ アップデート後

  • Feed Management画面内で「Ask Gemini Cloud Assist」で即座にガイダンス取得
  • メトリクスが正確に報告、容量計画の精度が向上
  • siemAlertId が内部アラートID専用に予約、データモデルの一貫性強化
🚨 緊急: 破壊的変更 (Breaking Change)
siemAlertId フィールドが 2026年7月5日より内部予約フィールドとなります。このフィールドにカスタムデータを格納している場合、7月5日以降は自動的に上書きされデータロスが発生します。即座に代替フィールドへの移行が必要です。

🏗️ アーキテクチャ図

Feed Management UI に Gemini Cloud Assist が統合され、Ingestion Pipeline のメトリクス報告が修正されました。siemAlertId フィールドは 7 月 5 日以降、内部予約フィールドとなりカスタムデータは上書きされます。

🤖 主要機能 1: Gemini Cloud Assist in Feed Management

💡 AI アシスタント統合: Feed Management インターフェースに「Ask Gemini Cloud Assist」ボタンが追加され、フィード設定に関する AI アシスタンスが利用可能になりました。

機能概要

✓フィード作成・設定に関する質問への回答を即座に取得
✓ログソースごとのインジェスト前提条件やセットアップ手順のガイダンス
✓一般的なセットアップ問題の解決方法の提示
✗設定変更は自動実行されない（推奨事項の提供のみ、手動適用が必要）

利用フロー

📂 Settings > Feeds
→
🤖 Ask GCA ボタン
→
💬 質問入力
→
✅ 手動で適用

前提条件

項目 詳細
パッケージ要件 Enterprise 以上（Gemini in security operations 含む）
API 有効化 Gemini Cloud Assist API
IAM ロール roles/geminicloudassist.user
アクセス方法 Feed Management UI 内「Ask Gemini Cloud Assist」ボタン

📊 主要機能 2: Ingestion Metrics Reporting 修正

修正内容

ダッシュボードおよび Cloud Monitoring で表示されるインジェストメトリクスの過小報告が解消されました。実際のログインジェスト量に変更はなく、表示の正確性が向上します。

ロールアウトスケジュール

項目 詳細
ロールアウト期間 2026年6月29日 - 7月10日（リージョンごと）
影響 メトリクス表示の一時的スパイク（見かけ上）
実際のログ量 変更なし
過去データ 修正・バックフィルなし
課金影響 なし
⚠️ 注意: 6月29日〜7月10日の間に表示されるスパイクは実際の異常ではありません。Cloud Monitoring のアラートポリシーの閾値再調整が必要な場合があります。

🚨 主要機能 3: siemAlertId フィールド予約 (Breaking Change)

発効日: 2026年7月5日 - このフィールドにカスタムデータを格納している全ての組織は即座に移行を開始してください。

影響範囲

項目 詳細
発効日 2026年7月5日
影響を受ける取り込み方法 Ingestion API, Webhooks, 1st-party connectors, 3rd-party connectors
動作変更 カスタム/ユーザー指定データが内部アラートIDで自動上書き
リスク データロス（移行しない場合）
対応期限 即座（7月5日まで約12日間）

移行タイムライン

今すぐ (6月23日)

使用箇所の特定を開始。Ingestion API、Webhook、コネクタマッピングを監査

~6月28日

代替フィールドへの移行完了。検知ルール・プレイブック・ダッシュボードの参照先更新

~7月2日

検証環境でのテスト完了

7月5日 (発効日)

siemAlertId が内部予約フィールドに。カスタムデータは自動上書き開始

移行手順

ステップ 1: 現在の使用箇所の特定

  • Ingestion API リクエストの JSON ペイロードを確認
  • Webhook 設定のフィールドマッピングを確認
  • サードパーティコネクタの出力フィールド設定を確認

ステップ 2: 代替フィールドへの移行

JSON 
// 移行前 (非推奨 - 7/5以降データロス)
{
  "siemAlertId": "custom-alert-correlation-id-123"
}

// 移行後 (推奨)
{
  "custom_alert_correlation_id": "custom-alert-correlation-id-123"
}

ステップ 3: 下流システムの更新

  • 検知ルール (YARA-L) の参照先を新フィールドに更新
  • SOAR プレイブックのフィールド参照を更新
  • ダッシュボードクエリの更新

💡 ユースケース

🔌 ユースケース 1: 新しいログソースのオンボーディング

シナリオ: SOC チームが新たに CrowdStrike Falcon のログを Google SecOps に取り込みたいが、設定手順に不慣れ。

手順:

  1. Feed Management 画面で「Ask Gemini Cloud Assist」をクリック
  2. 「CrowdStrike Falcon EDR のログを Amazon SQS 経由で取り込むには？」と質問
  3. GCA が前提条件とステップバイステップの手順を提示
  4. 提示された手順に従い、手動でフィード設定を完了

効果: ドキュメント検索の時間を削減し、新規ログソースのオンボーディングを迅速化

🔄 ユースケース 2: siemAlertId 移行の影響確認

シナリオ: SIEM チームが過去に構築した Ingestion パイプラインで siemAlertId をカスタム相関 ID として利用しており、7月5日までに移行が必要。

手順:

  1. 全 Ingestion API リクエスト、Webhook 設定、コネクタマッピングを監査
  2. siemAlertId を参照する YARA-L ルール・プレイブックを洗い出し
  3. 新しいカスタムフィールド名（例: custom_correlation_id）に一括移行
  4. 検知ルール・プレイブック・ダッシュボードの参照先を更新
  5. 7月5日前に検証環境でテスト

効果: データロスを防止し、検知・対応ワークフローの継続性を確保

⚖️ メリット・デメリット

✅ メリット

ビジネス面

✓SOC 運用効率の向上: AI アシストにより新しいログソースのオンボーディング時間を短縮
✓正確な容量管理: 実際のインジェスト量に基づく適切なキャパシティプランニング
✓データモデルの一貫性: 内部アラート ID の信頼性が向上

技術面

✓セルフサービス: フィード設定の問題をドキュメント検索なしに解決可能
✓メトリクスの正確性: Cloud Monitoring アラートポリシーの閾値がより信頼性の高いデータに基づく
✓予測可能なフィールド: siemAlertId が常に内部アラート ID を指すことが保証

⚠️ デメリット・制約

✗Gemini Cloud Assist は設定変更を自動実行しない（推奨事項の提供のみ）
✗メトリクス修正により過去データとの不連続が生じる（バックフィルなし）
✗siemAlertId のカスタム利用が完全に不可能になる（代替フィールドへの移行必須）
✗GCA の回答は AI 生成であり、公式ドキュメントでの確認が必要

🔗 関連サービス・機能

→Cloud Monitoring: インジェストメトリクスのモニタリング・アラート設定。修正により表示値が変更される

📝 まとめ

Gemini Cloud Assist による Feed Management の AI 支援強化とインジェストメトリクスの精度向上が提供されましたが、最も重要かつ緊急性が高いのは siemAlertId フィールドの予約（破壊的変更） です。

🚨 最重要アクション: 現在 siemAlertId をカスタム用途で使用している全ての組織は、即座に代替フィールドへの移行を開始してください。対応期限まで約12日間。Ingestion API、Webhook、全コネクタが影響を受けます。
