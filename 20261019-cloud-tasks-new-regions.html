📬 Cloud Tasks: デリー・トロントリージョンで利用可能に

リリース日: 2026-10-19
☁️ Cloud Tasks Changed (リージョン拡大) 🇮🇳 asia-south2 (デリー) 🇨🇦 northamerica-northeast2 (トロント)

📝 概要

フルマネージドのタスクキューサービス Cloud Tasks が、新たに asia-south2 (インド・デリー) と northamerica-northeast2 (カナダ・トロント) の 2 リージョンで利用可能になりました。 Cloud Tasks は、非同期タスクをキューに登録し、HTTP エンドポイントや App Engine アプリケーションに対して信頼性の高いレートでディスパッチするサービスです。

キューはリージョンリソースであり、キューを作成するロケーションがタスクデータの保存場所を決定します。 今回の拡大により、インド・カナダともに国内 2 リージョン体制となり、データレジデンシー要件を満たしながらワークロードに近いロケーションにキューを配置できる選択肢が広がりました。

❌ Before: アップデート前の課題

  • インドではキューのロケーションは asia-south1 (ムンバイ) のみ。デリー周辺のワークロード・データと同一リージョンにキューを配置できなかった
  • カナダでは northamerica-northeast1 (モントリオール) のみで、国内でリージョンを分けた構成が組めなかった
  • asia-south2 / northamerica-northeast2 で稼働する Cloud Run などのワーカーに対して、キューだけ別リージョンに置くリージョンまたぎ構成が必要だった

✅ After: アップデート後の改善

  • asia-south2 (デリー)、northamerica-northeast2 (トロント) にキューを作成可能に
  • インド・カナダそれぞれで国内 2 リージョン体制となり、国内にデータを保持したままリージョン分散構成を検討できる
  • 同リージョンの Cloud Run / GKE / Compute Engine などのワーカーとキューを同一リージョンに揃えた構成が可能に

Cloud Tasks のキュー配置先としてデリーとトロントが追加され、インド・カナダともに国内 2 リージョンからロケーションを選択できるようになった構成を示しています。

⚡ 主要機能

🇮🇳 1. asia-south2 (デリー、インド) への対応

✓インド国内では asia-south1 (ムンバイ) に続く 2 つ目の Cloud Tasks 対応リージョン
✓デリー (北インド) 周辺のユーザー・ワークロードに近いロケーションでキューを運用可能

🇨🇦 2. northamerica-northeast2 (トロント、カナダ) への対応

✓カナダ国内では northamerica-northeast1 (モントリオール) に続く 2 つ目の Cloud Tasks 対応リージョン
✓カナダ国内でリージョンを分けたキュー配置が可能に

📍 3. キューのロケーションとしての利用

✓Cloud Tasks のキューはリージョンリソースで、作成時にロケーションを指定する
✓HTTP/S エンドポイントをターゲットとする場合、Cloud Tasks がサポートするすべてのリージョンでキューを作成できる
✗App Engine をターゲットとする場合は、プロジェクトの App Engine リージョンでのみタスクを作成できる (従来どおりの制約)

🔧 技術仕様

項目詳細
追加リージョンasia-south2 (デリー、インド)、northamerica-northeast2 (トロント、カナダ)
リソースの単位キューはリージョンリソース (ロケーションはキュー作成時に指定)
ターゲットHTTP/S エンドポイント (全対応リージョンで利用可)、App Engine (App Engine リージョンに依存)
組織ポリシー (リソースロケーション)キュー作成時に適用される (ポリシー設定前に作成済みのキューには適用されない)

🛠️ 設定方法

📋 前提条件

✓Cloud Tasks API が有効化されていること
✓キューを作成する権限 (例: roles/cloudtasks.admin) を持っていること

1️⃣ ステップ 1: 新リージョンにキューを作成

Bash 新リージョンへのキュー作成 
# デリーリージョンにキューを作成
gcloud tasks queues create my-queue \
    --location=asia-south2

# トロントリージョンにキューを作成
gcloud tasks queues create my-queue \
    --location=northamerica-northeast2
💡 ポイント: キューのロケーションは作成時に指定します。既存キューのロケーションは変更できないため、新リージョンを利用する場合は新しいキューを作成します。

2️⃣ ステップ 2: 新リージョンのキューにタスクを作成

Bash HTTP タスクの作成 
gcloud tasks create-http-task \
    --queue=my-queue \
    --location=asia-south2 \
    --url=https://example.com/handler \
    --method=POST

タスク作成時にもキューと同じロケーションを指定します。

💡 メリット

💼 ビジネス面

✓データレジデンシー要件への対応: インド・カナダ国内にタスクデータを保持する要件を持つ組織 (金融、公共など) が、ワークロードの所在に合わせてキューのロケーションを選択しやすくなる
✓国内 2 リージョン体制: インド (ムンバイ/デリー)、カナダ (モントリオール/トロント) それぞれで国内 2 リージョンから選択でき、国内でのリージョン分散構成を検討できる

⚙️ 技術面

✓ワーカーとの同一リージョン配置: asia-south2 / northamerica-northeast2 で稼働する Cloud Run や GKE などのワーカーとキューを同一リージョンに揃えられ、リージョン間のディスパッチを避けられる
✓レイテンシの最適化: タスクを作成するアプリケーションおよびディスパッチ先のワーカーに近いロケーションにキューを配置できる

⚠️ デメリット・制約事項

🚫 制限事項
  • 既存キューのロケーションは変更できないため、新リージョンへ移行する場合は新規キューの作成とアプリケーション側の切り替えが必要
  • App Engine をターゲットとするタスクは、引き続きプロジェクトの App Engine リージョンでのみ作成可能
🤔 考慮すべき点
  • リソースロケーションの組織ポリシーを利用している場合、新リージョンでキューを作成するには許可リストへの追加が必要になることがある
  • 組織ポリシーはキュー作成時に適用され、ポリシー設定前に作成されたキューには遡及適用されない

🎯 ユースケース

🇮🇳 ユースケース 1: 北インドのワークロード向け非同期処理基盤

シナリオ: デリー (asia-south2) の Cloud Run でアプリケーションを運用している企業が、注文処理やメール送信などの非同期タスクを Cloud Tasks で処理したい。従来はキューをムンバイ (asia-south1) に置く必要があった。

Bash 実装例 
gcloud tasks queues create order-queue --location=asia-south2
✅ 効果: アプリケーション・キュー・ワーカーを asia-south2 に揃えた構成が可能になり、リージョンをまたがないシンプルな非同期処理基盤を構築できる。

🇨🇦 ユースケース 2: カナダ国内でのデータレジデンシーを満たすタスク処理

シナリオ: カナダの組織が、タスクデータを国内に保持する要件のもとで、トロントリージョンの既存ワークロードに非同期処理を追加したい。

✅ 効果: northamerica-northeast2 にキューを作成することで、タスクデータをカナダ国内のトロントリージョンに保持したまま、既存ワークロードと同一リージョンで Cloud Tasks を利用できる。

💰 料金

リージョン追加自体による料金体系の変更はありません。Cloud Tasks はタスクの作成・削除などの操作 (オペレーション) 単位で課金され、App Engine ターゲットへのリクエスト送信自体は無料です。 最新の料金は Cloud Tasks の料金ページ を参照してください。

🔗 関連サービス・機能

⏰ Cloud Scheduler

cron 形式のスケジュールでジョブを実行するサービス。asia-south2 / northamerica-northeast2 を含むリージョンに対応しており、Cloud Tasks と組み合わせた定期的なタスク投入に利用できる。

⚡ Cloud Run

Cloud Tasks の HTTP ターゲットとして一般的なワーカー実行環境。asia-south2 / northamerica-northeast2 の両リージョンで利用可能。

🏗️ App Engine

Cloud Tasks のもう一つのターゲット。App Engine ターゲットのタスクはプロジェクトの App Engine リージョンでのみ作成可能。

🛡️ 組織ポリシー (リソースロケーション制約)

キュー作成時にロケーションを制御。新リージョン利用時はポリシーの許可リストを確認。

📌 まとめ

Cloud Tasks がデリー (asia-south2) とトロント (northamerica-northeast2) に対応し、インド・カナダともに国内 2 リージョンでキューを配置できるようになりました。

✓これらのリージョンでワークロードを運用している、またはデータレジデンシー要件を持つ組織は、ワーカーと同一リージョンへのキュー配置を検討する
✓既存キューのロケーションは変更できないため、移行する場合は新規キューの作成が必要
