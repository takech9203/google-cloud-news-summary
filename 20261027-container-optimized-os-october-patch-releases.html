Container-Optimized OS Security Change / Fixed
リリース日: 2026-10-27

📋 概要

COS の 5 つのアクティブマイルストーン (cos-dev-138 / cos-beta-133 / LTS の cos-125・cos-129・cos-121) に新イメージが一斉リリース。 GKE ノードや Compute Engine 上のコンテナワークロードの基盤 OS に広く関係するリリースウェーブです。

特に注目は eMudhra 中間証明書の侵害の影響を受けた証明書の削除 (cos-dev-138: ca-certificates v20260816.3.125 / NSS v3.131.1) と、 IPU E2100 の idpf リセット起因 60 秒障害の修正 (cos-125 / cos-129) です。 ほかにカーネル・Docker・Kubernetes・sudo・glibc・Go・Python などへの多数の CVE 修正、AMD CPUID faulting の KVM サポート、ARM イメージへの nvidia-container-toolkit 追加が含まれます。

❌ アップデート前の課題

  • eMudhra 中間証明書侵害の影響を受けた証明書が証明書ストア (ca-certificates / NSS) に残存
  • カーネル、Docker、Kubernetes、sudo (CVE-2026-82474)、glibc (CVE-2026-5435)、openssl (CVE-2024-4741) など多数の未修正 CVE
  • IPU E2100 で idpf リセット後に PFGEN_RSTAT の誤読により 60 秒間の障害が発生
  • ARM イメージに nvidia-container-toolkit が未搭載
  • KVM 仮想化で AMD CPUID faulting が未サポート

✅ アップデート後の改善

  • eMudhra 侵害の影響を受けた証明書を削除し、侵害された証明書チェーンを信頼するリスクを解消 (cos-dev-138)
  • 各マイルストーンで CVE 修正が適用され、イメージ更新のみでセキュリティ態勢を改善
  • IPU E2100 の idpf リセット起因 60 秒障害を修正 (cos-125 / cos-129)
  • ARM イメージに nvidia-container-toolkit を追加、ARM + NVIDIA GPU 構成が容易に (cos-dev-138)
  • KVM 仮想化で AMD CPUID faulting をサポート (cos-dev-138)

💪 メリット

💼 ビジネス面

✓サプライチェーン / PKI リスクの低減: eMudhra 中間証明書侵害の影響を受けた証明書が削除され、侵害された CA を信頼し続けるリスクを排除できる
✓コンプライアンス対応: sudo、glibc、Docker、Kubernetes などの既知 CVE が修正済みのイメージへ更新することで、脆弱性管理の要件を満たしやすくなる

🔧 技術面

✓可用性の改善: IPU E2100 環境における idpf リセット後の 60 秒障害が解消され、ネットワーク断の影響を受けていたワークロードの安定性が向上 (cos-125 / cos-129)
✓ARM GPU 対応の強化: ARM イメージに nvidia-container-toolkit が追加され、ARM ベースの GPU ワークロード構築が容易に (cos-dev-138)
✓仮想化機能の拡張: KVM での AMD CPUID faulting サポートにより、AMD CPU 上のネスト仮想化ユースケースでの制御性が向上 (cos-dev-138)

⚠️ デメリット・制約事項

🚫 制限事項
  • eMudhra 侵害証明書の削除や新機能 (AMD CPUID faulting、ARM への nvidia-container-toolkit) は今回のリリースでは cos-dev-138 のみに含まれ、LTS 系統の今回のイメージには含まれない
  • cos-dev / cos-beta は開発・検証用であり、本番ワークロードには LTS ファミリーの利用が推奨される
🤔 考慮すべき点
  • 修正の適用にはノード (GKE ノードプールまたは GCE インスタンス) のイメージ更新・再作成が必要
  • 削除された証明書に依存した外部接続 (eMudhra 系列の証明書を提示するエンドポイントへの TLS 接続) がある場合、イメージ更新後に接続が失敗する可能性があるため事前確認が必要
  • LTS のランタイム sysctl 既定値 (fs.epoll.max_user_watches、kernel.threads-max、net.ipv4.tcp_mem など) がわずかに変更されており、limits ぎりぎりで運用しているワークロードは確認が望ましい

🎯 ユースケース

1️⃣ GKE ノードプールのセキュリティパッチ適用

シナリオ: GKE で COS ノードイメージ (cos_containerd) を利用しており、sudo (CVE-2026-82474) や google-osconfig-agent (CVE-2026-33186) の脆弱性指摘に対応したい。

Bash ノード自動アップグレードの有効化 
# ノード自動アップグレードを有効化してパッチを自動適用
gcloud container node-pools update my-pool \
  --cluster my-cluster \
  --location asia-northeast1 \
  --enable-autoupgrade
✅ 効果: GKE のノード自動アップグレードにより、修正済み COS イメージがロールアウトされ、手動対応なしで CVE 修正を取り込める。

2️⃣ IPU E2100 環境のネットワーク安定化

シナリオ: cos-125 / cos-129 ベースのノードで IPU E2100 を利用しており、idpf ファンクションリセット時に約 60 秒のネットワーク断が発生していた。

✅ 効果: cos-125-19216-760-20 または cos-129-19506-578-21 へ更新することで、PFGEN_RSTAT の誤読に起因する 60 秒障害が解消される。

🔗 関連サービス・機能

🚢 Google Kubernetes Engine (GKE)

COS はデフォルトのノードイメージ (cos_containerd)。ノード自動アップグレードで今回の修正を取り込める。

🖥️ Compute Engine

cos-cloud プロジェクトのイメージファミリー (cos-dev / cos-beta / cos-{M}-lts) から COS インスタンスを作成。

⚙️ OS Config (google-osconfig-agent)

今回 CVE 修正が適用されたゲストエージェントの 1 つ。パッチ管理・構成管理に利用。

🛡️ Container Threat Detection / Security Command Center

ノード OS の脆弱性管理と組み合わせてコンテナ環境のセキュリティ態勢を強化。

📝 まとめ

COS の全アクティブマイルストーンに対する定例的なパッチウェーブですが、eMudhra 中間証明書侵害への対応 (cos-dev-138) と IPU E2100 の 60 秒障害修正 (cos-125 / cos-129) は運用影響の大きい修正です。 本番環境で COS LTS を利用している場合は、GKE ノード自動アップグレードの有効化、または該当 LTS イメージへの計画的な更新を推奨します。
