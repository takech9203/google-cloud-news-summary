🔒 Cloud Trace: Observability バケット作成フローにおける組織ポリシーの適用

Cloud Trace GA Organization Policy CMEK
リリース日: 2026-06-02

📋 概要

Cloud Trace の Observability バケット (_Trace) 作成フローにおいて、組織ポリシーの適用が開始されました。リソースロケーション制約、CMEK (顧客管理暗号鍵) の使用要求ポリシー、および暗号鍵プロジェクト制限ポリシーが、バケット作成時に強制されるようになります。

これにより、コンプライアンス要件やデータ主権要件を持つ組織が、トレースデータの保存場所と暗号化方式を組織全体で統一的に管理できるようになりました。規制産業 (金融、医療、政府機関) や GDPR、HIPAA、PCI DSS などのコンプライアンス基準に対応する組織に特に重要なアップデートです。

🔄 Before / After 比較

❌ Before (アップデート前)

  • Observability バケット作成時に組織ポリシーが適用されなかった
  • 意図しないリージョンにトレースデータが保存される可能性
  • CMEK ポリシーがバケットに適用されず、暗号化制御の対象外
  • 組織全体のセキュリティポリシーと一貫性がない

✅ After (アップデート後)

  • resourceLocations 制約で許可リージョンのみにデータ保存
  • restrictNonCmekServices で CMEK なしのバケット作成をブロック
  • restrictCmekCryptoKeyProjects で承認プロジェクトの KMS 鍵のみ使用
  • 組織レベルで統一的なセキュリティガバナンスを実現

⚡ 主要機能

🌍 リソースロケーション制約の適用

constraints/gcp.resourceLocations 制約に基づき、許可されたロケーションにのみ Observability バケットが作成されます。

  • マルチリージョン (eu, us) および 40 以上のリージョンをサポート
  • 組織ポリシーで許可されたロケーションとバケットがサポートするロケーションの交差集合から自動選択

🔐 CMEK ポリシーの強制

constraints/gcp.restrictNonCmekServices Deny ポリシーにより、新規リソースへの CMEK 暗号化が強制されます。

  • CMEK ポリシー設定時は、デフォルト設定で Cloud KMS 鍵の指定が必須
  • デフォルト設定が未構成の場合、バケットのプロビジョニングが失敗

🗝️ KMS 鍵プロジェクト制限

constraints/gcp.restrictCmekCryptoKeyProjects ポリシーにより、暗号化に使用できる KMS 鍵のプロジェクトを制限できます。

  • 承認されたプロジェクトの鍵のみが暗号化に使用される
  • 組織全体の鍵管理ガバナンスを実現

📐 技術仕様

組織ポリシー制約一覧

制約 ID 目的 適用レベル
constraints/gcp.resourceLocations リソース作成可能なロケーションを制限 組織、フォルダ、プロジェクト
constraints/gcp.restrictNonCmekServices CMEK を使用しないリソース作成をブロック 組織、フォルダ、プロジェクト
constraints/gcp.restrictCmekCryptoKeyProjects 暗号化に使用可能な KMS 鍵プロジェクトを制限 組織、フォルダ、プロジェクト

ロケーション決定ルール

組織ポリシーでロケーション制限 デフォルトストレージロケーション設定 バケットロケーションの決定方法
なし なし サポートされるロケーションからシステムが選択
あり なし 組織ポリシー許可ロケーションとサポートロケーションの交差集合から選択
なし あり デフォルト設定のストレージロケーションを使用
あり あり デフォルト設定のロケーションを使用 (ポリシー非許可の場合は作成失敗)

🛠️ 設定方法

💡 前提条件:
  • 組織レベルのリソース管理者ロール (roles/resourcemanager.organizationAdmin)
  • Cloud KMS API が有効化されていること
  • roles/observability.editor および roles/cloudkms.admin が付与されていること
  • CMEK 使用時: 対象ロケーションに Cloud KMS キーリングと鍵が作成済み

Step 1: 組織ポリシーでリソースロケーションを制限

YAML 
constraint: constraints/gcp.resourceLocations
listPolicy:
  allowedValues:
    - in:asia-northeast1-locations
    - in:us-central1-locations
Bash 
gcloud resource-manager org-policies set-policy \
  --organization=ORGANIZATION_ID \
  policy.yaml

Step 2: CMEK ポリシーを設定

YAML 
constraint: constraints/gcp.restrictNonCmekServices
listPolicy:
  deniedValues:
    - observability.googleapis.com
Bash 
gcloud org-policies set-policy cmek-policy.yaml \
  --organization=ORGANIZATION_ID

Step 3: KMS 鍵プロジェクトを制限

YAML 
constraint: constraints/gcp.restrictCmekCryptoKeyProjects
listPolicy:
  allowedValues:
    - projects/my-kms-project

Step 4: Observability バケットのデフォルト設定を構成

Bash 
# デフォルト KMS 鍵を設定 (組織レベル、asia-northeast1)
gcloud beta observability settings update \
  --organization=ORGANIZATION_ID \
  --location=asia-northeast1 \
  --kms-key-name=projects/my-kms-project/locations/asia-northeast1/keyRings/my-keyring/cryptoKeys/my-key

# デフォルトストレージロケーションを設定
gcloud beta observability settings update \
  --organization=ORGANIZATION_ID \
  --location=global \
  --storage-location=asia-northeast1

Step 5: 設定を確認

Bash 
gcloud beta observability settings describe \
  --organization=ORGANIZATION_ID \
  --location=asia-northeast1

✅ メリット

ビジネス面

  • コンプライアンス自動化: GDPR、HIPAA、PCI DSS の要件を組織ポリシーで自動担保
  • データ主権の確保: 特定の国や地域にトレースデータを閉じ込め可能
  • ガバナンスの統一: ログ・メトリクス・トレース全てに統一的ポリシー適用

技術面

  • 自動適用: 個別プロジェクトでの設定漏れがなくなる
  • 階層的継承: 組織 > フォルダ > プロジェクトで管理負荷軽減
  • 既存バケットへの影響なし: 新規バケット作成時にのみ適用

⚠️ デメリット・制約事項

制限事項

  • 組織ポリシーは遡及的に適用されないため、既存バケットが不適切なロケーションにある場合は手動移行が必要
  • CMEK ポリシー設定時、デフォルト設定を事前に構成しないとバケットのプロビジョニングが失敗し、トレースデータが収集不能に
  • 許可ロケーションとサポートロケーションに重複がない場合、バケット作成不可

考慮すべき点

  • Cloud KMS 鍵のローテーション・無効化・削除がトレースデータへのアクセスに影響 (鍵ライフサイクル管理に注意)
  • Cloud Run functions、Cloud Run、App Engine のトレースデータは、バケット未存在時に保存不可 (ポリシー違反時にデータロス発生の可能性)
  • デフォルト設定の変更は新規バケットにのみ適用 (既存バケットの暗号化設定は変更されない)

💡 ユースケース

🇪🇺 ユースケース 1: EU データ主権要件への対応

シナリオ: GDPR に基づきトレースデータを EU 内にのみ保存する必要がある場合

YAML 
# 組織ポリシー: EU リージョンのみ許可
constraint: constraints/gcp.resourceLocations
listPolicy:
  allowedValues:
    - in:eu-locations
Bash 
# デフォルトストレージロケーションを EU に設定
gcloud beta observability settings update \
  --folder=EU_FOLDER_ID \
  --location=global \
  --storage-location=europe-west3

効果: EU フォルダ配下のプロジェクトで自動作成される Observability バケットが必ず EU リージョン内に配置され、GDPR のデータ越境規制に自動準拠。

🏦 ユースケース 2: 金融機関における暗号化制御

シナリオ: すべてのオブザーバビリティデータに自社管理の暗号鍵を使用し、鍵管理を特定セキュリティプロジェクトに集約する場合

Bash 
# CMEK を強制
gcloud org-policies set-policy cmek-policy.yaml \
  --organization=ORGANIZATION_ID

# KMS 鍵プロジェクトを制限
gcloud org-policies set-policy kms-project-policy.yaml \
  --organization=ORGANIZATION_ID

# デフォルト KMS 鍵を設定
gcloud beta observability settings update \
  --organization=ORGANIZATION_ID \
  --location=asia-northeast1 \
  --kms-key-name=projects/security-kms-project/locations/asia-northeast1/keyRings/observability/cryptoKeys/trace-key

効果: トレースデータを含む全オブザーバビリティデータが承認済み KMS 鍵で暗号化され、暗号鍵アクセス監査ログによる不正アクセス検知も実現。

💰 料金情報

Observability バケットの組織ポリシー適用自体には追加料金は発生しません。Cloud Trace の料金はトレースデータの取り込み量に基づきます。

項目 月額料金 (概算)
Cloud Trace 取り込み (最初の 250 万スパン) 無料
Cloud Trace 取り込み (250 万スパン超過分) $0.20 / 100 万スパン
Cloud KMS 鍵 (CMEK 使用時) $0.06 / 鍵バージョン / 月
Cloud KMS 鍵操作 (CMEK 使用時) $0.03 / 10,000 操作
💡 注: CMEK を使用する場合、Cloud KMS の料金が別途発生します。組織ポリシーの設定・適用自体は無料です。

📝 まとめ

今回のアップデートにより、Cloud Trace の Observability バケット作成フローが組織ポリシーを完全にサポートし、トレースデータのロケーション制御と暗号化管理が組織レベルで統一的に行えるようになりました。

推奨アクション:
  • コンプライアンス/データ主権要件がある組織は、Observability バケットのデフォルト設定と組織ポリシーを組み合わせて構成
  • CMEK ポリシー適用時は、事前にデフォルト設定で KMS 鍵を指定してからポリシーを有効化
  • 既存バケットについてはポリシー遡及適用されないため、必要に応じて手動で確認・移行
