🇨🇦 Cloud Logging: "ca" リージョナルエンドポイントの追加

Cloud Logging GA
リリース日: 2026-06-18

📋 概要

Cloud Logging API に logging.ca.rep.googleapis.com (カナダ) リージョナルエンドポイントが追加されました。カナダ国内の Google Cloud リージョン (northamerica-northeast1: Montreal、northamerica-northeast2: Toronto) に対する Logging API リクエストを、カナダ国内で完結させることが可能になります。

💡 ポイント: TLS 終端とルーティングがカナダ国内で行われ、PIPEDA (Personal Information Protection and Electronic Documents Act) をはじめとするカナダの個人情報保護規制への準拠を支援します。

既存の "us" (米国)、"eu" (EU)、"in" (インド)、"sa" (サウジアラビア)、"ch" (スイス) に続く国/地域別マルチリージョナルエンドポイントとして追加されました。

🔄 Before / After 比較

❌ Before (従来)

  • API リクエストがグローバルエンドポイントを経由し、カナダ国外を通過する可能性
  • PIPEDA への完全準拠の証明が困難
  • カナダ全体をカバーする統合エンドポイントがない

✅ After (新機能)

  • logging.ca.rep.googleapis.com で両リージョンをカバー
  • TLS 終端もルーティングもカナダ国内で完結
  • Assured Workloads と組み合わせで完全なデータ居住性を確保

⚡ 主要機能

🌐 カナダ統合リージョナルエンドポイント

→エンドポイント: logging.ca.rep.googleapis.com
→対象: northamerica-northeast1 (Montreal) + northamerica-northeast2 (Toronto)
→国コード "ca" を使用した統合エンドポイント形式

🔒 転送中データの居住性確保

→TLS セッションがカナダ国内で終端
→Standard Tier ネットワーキング使用 - カナダ最寄りのピアリングポイントからのみ IP アドレスをアナウンス
→カナダ国内 ISP ユーザーのトラフィックはカナダ法域内でルーティング

🔗 既存エンドポイントとの併用

→個別リージョンエンドポイント (logging.northamerica-northeast1.rep.googleapis.com) も引き続き利用可能
→"ca" エンドポイントは両リージョンを統合的にカバーする上位の選択肢

エンドポイント形式: logging.LOCATION.rep.googleapis.com
LOCATION にはリージョン名 (例: northamerica-northeast1) または国/地域コード (例: ca) を指定します。

🛠️ 設定方法

前提条件

✓Google Cloud プロジェクトで Cloud Logging API が有効化されていること
✓対象リソースがカナダリージョン (northamerica-northeast1 または northamerica-northeast2) に存在すること

Step 1: gcloud CLI でリージョナルエンドポイントを使用

Bash gcloud CLI でのエンドポイント指定 
# リージョナルエンドポイントを指定して Logging API を呼び出す
gcloud logging read "severity>=WARNING" \
  --project=MY_PROJECT \
  --billing-project=MY_PROJECT \
  --api-endpoint=https://logging.ca.rep.googleapis.com

Step 2: クライアントライブラリでの設定 (Python)

Python Python SDK でのエンドポイント指定 
from google.cloud import logging_v2

# カナダリージョナルエンドポイントを指定
client = logging_v2.LoggingServiceV2Client(
    client_options={
        "api_endpoint": "logging.ca.rep.googleapis.com"
    }
)

Step 3: VPC 内からのアクセス (Private Service Connect)

Bash Private Service Connect エンドポイントの作成 
# VPC 内からリージョナルエンドポイントにアクセスする場合は
# Private Service Connect エンドポイントの作成が推奨される
gcloud compute forwarding-rules create logging-ca-endpoint \
  --region=northamerica-northeast1 \
  --network=MY_VPC \
  --address=RESERVED_IP \
  --target-google-apis-bundle=logging.ca.rep.googleapis.com
⚠️ 注意: VPC Service Controls と併用する場合や Private Google Access を使用する場合は、証明書エラーを防ぐために Private Service Connect エンドポイントの作成が必要です。

ビジネス面

🤝顧客信頼性の向上 - データがカナダ国外に出ないことを技術的に保証し、ステークホルダーへの説明が容易に
🏗️Assured Workloads 統合 - Canada Data Boundary コントロールパッケージと組み合わせた包括的データ主権ソリューション

技術面

⚡レイテンシ最適化 - カナダ国内ルーティングにより API レスポンス時間が安定
🔗統合エンドポイント - 2 リージョンを 1 エンドポイントでカバーし設定を簡素化
🛡️多層セキュリティ - VPC Service Controls との組み合わせで多層的な保護を実現

⚠️ デメリット・制約事項

制限事項

❌リージョナルエンドポイントは対象リージョン内のリソースにのみアクセス可能。他リージョンのログにはアクセス不可
📝ログ書き込み (write) はリージョン制限の対象外。ログが失われないよう、指定ログバケットにルーティングされる
🔧VPC ネットワーク内からのアクセスには Private Service Connect エンドポイントの作成が必要

考慮すべき点

→グローバルエンドポイントからの移行時は既存クライアント設定の変更が必要
→Apigee 等の他サービス連携時は各サービスのリージョナルエンドポイント設定も合わせて変更が必要

🎯 ユースケース

🏦 金融機関のコンプライアンス対応

シナリオ: カナダの金融機関が OSFI ガイドラインに基づき、すべての運用データをカナダ国内に保持する必要がある。

Bash Assured Workloads + Logging 設定 
# Assured Workloads で Canada Data Boundary フォルダを作成
gcloud assured workloads create \
  --organization=ORG_ID \
  --location=northamerica-northeast1 \
  --compliance-regime=CA_DATA_BOUNDARY \
  --display-name="Finance-Logging"

# リージョナルエンドポイントを使用した Logging 設定
gcloud logging settings update \
  --organization=ORG_ID \
  --storage-location=northamerica-northeast1

効果: ログの保存、転送、処理のすべてがカナダ国内で完結し、規制準拠を技術的に証明可能。

🏥 ヘルスケア企業の PHI データ保護

シナリオ: オンタリオ州のヘルスケア企業が PHIPA に基づき、患者の個人健康情報を含むログをカナダ国内に保持する必要がある。

効果: logging.ca.rep.googleapis.com エンドポイントを使用することで、アプリケーションログに含まれる PHI データが転送中もカナダ国内に留まることを保証。
