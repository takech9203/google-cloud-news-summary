Gemini Enterprise Workflow Builder Feature (新機能)

🛠️ Workflow Builder のワークフローが
Confluence / Jira Data Center に接続可能に

📅 リリース日: 2026-10-16
☁️ Google Cloud リリースノート

📝 概要

Gemini Enterprise の Workflow Builder で作成するワークフローを、 Confluence Data Center および Jira Data Center に接続できるようになりました。 Atlassian のセルフホスト版 (Data Center 版) 製品に対して、ワークフローから データの検索やアクションの自動化が可能になります。

Workflow Builder は、Gemini Enterprise Web アプリ内でワークフロー型エージェントを構築する機能です。 トリガーに基づいて一連のステップやアクションを実行するエージェントを、自然言語やビジュアルエディタで作成できます。 これまでのコネクタ (Gmail、Google Drive、Confluence/Jira の Cloud 版、Slack、Salesforce など) に、 今回 Atlassian セルフホスト版の 2 コネクタが加わりました。

❌ Before (アップデート前の課題)

  • ワークフローから接続できる Atlassian 製品はクラウド版が中心で、Confluence / Jira Data Center をワークフローのステップやツールとして利用できなかった
  • Data Center 版利用企業は、データストア経由の検索は可能でも、ワークフローによる横断的な自動化に組み込めなかった

✅ After (アップデート後の改善)

  • Gemini Agent ステップから Confluence / Jira Data Center のデータを検索可能に
  • Jira Data Center への課題の作成・更新・ステータス変更・コメント追加などをワークフローから自動化
  • Google Workspace 系コネクタと Atlassian Data Center 版を 1 つのワークフローで組み合わせた業務自動化が可能に
💡 ポイント: コンプライアンスやデータ主権の要件で Atlassian 製品をオンプレミス / 自社管理環境で運用している企業でも、 既存のナレッジベース (Confluence) や課題管理 (Jira) を Gemini Enterprise のワークフロー自動化に直接統合できます。

ワークフローのトリガー (手動・スケジュール・イベント) により Gemini Agent ステップが実行され、 コネクタ経由で Confluence Data Center / Jira Data Center のデータ検索とアクション実行を行う構成です。 プライベート IP のインスタンスには Private Service Connect で接続します。

⚡ 主要機能

1️⃣ ワークフローからの Confluence / Jira Data Center 接続

✓Gemini Agent ステップの Connected apps に Confluence Data Center / Jira Data Center をコネクタとして追加可能
✓サポートコネクタ一覧 (Gmail、Google Calendar、Google Chat、Google Drive、Confluence、Jira、Microsoft Teams、Notion、OneDrive、Outlook、Salesforce、SharePoint、ServiceNow、Slack) に両コネクタが追加

2️⃣ データ検索 (Federated Search)

✓Confluence Data Center のページコンテンツ・添付ファイル・コメント、Jira Data Center のプロジェクト・課題・ユーザー情報を検索可能
✓クエリは Jira / Confluence Data Center の API に直接送信され、他の接続済みデータソースの結果とブレンドして表示

3️⃣ アクションの自動化

✓Jira Data Center: 課題の作成 (Create issue)・更新 (Update issue)・ステータス変更 (Change Issue Status)・コメント作成/更新・添付ファイルのアップロード/ダウンロード
✓Confluence Data Center: ページへの添付ファイルのアップロード/ダウンロード
✓コネクタごとに検索/データ変更アクションを個別に有効化・無効化でき、「検索のみ許可し、作成・変更は禁止」といった粒度の細かい制御が可能

⏰ ワークフローのトリガー

トリガー 説明
👆 手動トリガー Gemini Enterprise アプリのチャットから @ + ワークフロー名で起動。入力フィールドの定義も可能
🗓️ スケジュールトリガー 分・時間・日・週・月単位、または cron 式で指定した頻度で実行
⚡ イベントトリガー コネクタ内のデータ変更をきっかけに実行 (フィルタ条件を設定可能)

⚙️ 設定方法

✅ 前提条件

✓Gemini Enterprise 管理者が機能管理設定で Workflow Builder の機能トグルを有効化していること
✓必要なデータストアが接続された Gemini Enterprise Web アプリがあること
✓データストア作成ユーザーに Discovery Engine 編集者ロール (roles/discoveryengine.editor) が付与されていること
✓Confluence / Jira Data Center 側で OAuth アプリを登録し、クライアント ID とシークレットを取得していること (シークレットは Secret Manager に保存)
✓プライベート IP の場合、Private Service Connect のプロデューサーサービスを公開していること

🗄️ ステップ 1: データストアの作成

Google Cloud コンソールの Gemini Enterprise ページで、Data stores > Create data store から「Confluence Data Center」または「Jira Data Center」を選択。接続モード (Federated search)、インスタンス URI、OAuth 認証情報、宛先タイプ (Public / Private) を設定します。Federated search では有効化するアクションもこの時点で選択できます。

🔗 ステップ 2: アプリへの接続と認可

作成したデータストアを Gemini Enterprise アプリに接続し、クエリ実行前にユーザー認可 (OAuth) を完了します。

🛠️ ステップ 3: ワークフローへの組み込み

Workflow Builder のキャンバスで Gemini Agent ノードを開き、Connected apps で対象コネクタをオンに切り替えます (必要に応じて OAuth 認可を実施)。Jira を検索専用で使う場合は、Search For Data をオン、Add Or Update Data をオフにする構成が公式ドキュメントで示されています。

⚖️ メリットと制約事項

💼 ビジネス面のメリット

✓セルフホスト環境の活用: コンプライアンスやデータ主権の要件で Data Center 版を利用する企業でも、既存資産をそのままワークフロー自動化に組み込める
✓業務プロセスの自動化: ナレッジ検索 (Confluence) と課題管理 (Jira) をまたぐ定型業務を、AI 自動化と Human-in-the-loop の承認を組み合わせて自動化

🔧 技術面のメリット

✓粒度の細かいアクション制御: コネクタ単位・アクション単位で検索/変更を個別制御、最小権限での運用が可能
✓プライベート接続: Private Service Connect でプライベート IP のオンプレミスインスタンスにも安全に接続
✓CMEK 対応: US / EU ロケーションで Cloud KMS の顧客管理暗号鍵を設定可能

⚠️ 制限事項

•Data ingestion モードは Private Preview (許可リスト登録が必要)。GA は Federated search and actions のみ
•データストアは Global、US、EU ロケーションのみサポート
•既存データストアへの VPC Service Controls 境界の適用は不可 (再作成が必要)
•添付ファイルの最大サイズは 200 MB
•アクション有効の同一コネクタタイプのデータストアを同じアプリに複数関連付けるのは非推奨

🤔 考慮すべき点

•Federated search では検索クエリがサードパーティ API に直接送信され、ユーザー ID と関連付けられる可能性がある (送信後は当該システムの規約に従う)
•精度向上のため LLM がクエリを書き換えることがあり、セッションのクエリ履歴の一部が送信される場合がある
•Jira の課題レベルセキュリティ利用時、データ取り込みモードでは Permission Accessor for Jira Data Center プラグインが必要
•Gemini Agent ステップは Gemini 3.0 以降のモデルのみサポート

🎯 ユースケース

💡 ユースケース 1: 問い合わせ内容に基づく Jira 課題の自動起票

イベントトリガー (例: メール受信などコネクタのデータ変更) でワークフローを起動し、Gemini Agent が Confluence Data Center の社内ナレッジを検索して関連情報を収集したうえで、 Jira Data Center に課題を自動作成します。

Workflow 実装例 (ワークフロー構成) 
1. イベントトリガー: コネクタのデータ変更を検知
2. Gemini Agent ステップ A: Confluence Data Center を検索 (Search For Data: オン / Add Or Update Data: オフ)
3. Gemini Agent ステップ B: Jira Data Center で Create issue アクションを実行
4. Human-in-the-loop ステップ: 担当者が承認
✅ 効果: ナレッジ参照と起票作業を自動化し、対応の初動を高速化。読み取り専用設定により意図しないデータ変更を防止できる。

💡 ユースケース 2: 定期的な課題ステータスの棚卸しと更新

スケジュールトリガーで週次実行するワークフローが Jira Data Center の課題を検索し、 条件分岐 (Condition ステップ) で滞留課題を抽出してコメント追加やステータス変更を行います。

🔗 関連サービス・機能

☁️ Gemini Enterprise コネクタ (Confluence / Jira Cloud 版)

クラウド版 Atlassian 製品向けのコネクタ。今回のアップデートで Data Center 版も含め、ワークフローから利用可能なコネクタが拡充されました。

🔒 Private Service Connect

プライベート IP で運用される Data Center インスタンスへの接続に使用。セルフホストデータソース接続の基盤です。

🔑 Secret Manager

OAuth クライアントシークレットの保管に使用します。

🛡️ Cloud KMS (CMEK) / VPC Service Controls

US / EU ロケーションのデータストアで顧客管理暗号鍵 (CMEK) を利用可能。VPC Service Controls はデータストアのセキュリティ境界の適用に利用できます (新規作成時のみ)。

🎉 まとめ

Atlassian 製品をセルフホスト (Data Center 版) で運用する企業にとって、Gemini Enterprise の Workflow Builder から Confluence / Jira のデータ検索とアクション自動化を直接組み込めるようになる重要なアップデートです。

🚀 推奨アクション: まずは OAuth 認証とデータストアのセットアップを行い、 検索専用の読み取り構成からワークフローへの統合を試すことを推奨します。 プライベート IP 環境では Private Service Connect の構成も合わせて計画してください。
