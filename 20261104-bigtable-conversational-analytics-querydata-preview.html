🗄️ Bigtable: 会話型分析 & QueryData ツール

Bigtable Conversational Analytics QueryData Preview
📅 リリース日: 2026-11-04

📝 概要

Bigtable に、自然言語でオペレーショナルデータを照会できる 2 つの関連機能が Preview として追加されました。

💬 会話型分析 (Conversational Analytics)

テーブルやビューをナレッジソースとするデータエージェントを作成し、コンソールの「Agents」ページから自然言語チャットで Bigtable のデータに質問。「先四半期の売上合計は?」のような質問をフィールド名を知らなくても投げかけられ、回答にはテキスト・コード・グラフに加え推論過程と生成クエリが含まれます。

🛠️ QueryData ツール

Conversational Analytics API の QueryData エンドポイントとして提供されるエージェンティックツール。ADK や LangChain などのエージェントハーネスから呼び出し、自然言語から SQL への変換をプログラマティックに実行。アプリケーション組み込み向けの機能です。

🎯 対象ユーザー: Bigtable 上のオペレーショナルデータをアドホックに分析したいビジネスユーザー・アナリスト (会話型分析) と、顧客サービス自動化や EC ショッピングアシスタントなど自然言語インターフェースを持つデータエージェントアプリを構築する開発者 (QueryData)。

❌ Before: アップデート前の課題

  • 分析には SQL (GoogleSQL) やクライアントライブラリによるクエリ記述が必要で、スキーマやフィールド名を熟知していないユーザーはデータに直接アクセスできなかった
  • 自然言語でデータベースを照会するエージェントアプリでは、Text-to-SQL 変換ロジック (スキーマ解釈・曖昧さ解消・クエリ生成) を自前実装する必要があった
  • 一般的な LLM の Text-to-SQL では、組織固有の用語やビジネスロジックを反映した正確なクエリ生成が難しかった

✅ After: アップデート後の改善

  • コンソールからデータエージェントを作成・公開し、自然言語の会話 (永続化されたチャット) で Bigtable のデータを分析できる
  • QueryData エンドポイントにより、クエリブループリント・ファセット・バリューサーチからなるコンテキストセットを使った高精度なクエリ生成を、ADK / LangChain / Antigravity / MCP Toolbox から利用できる
  • 回答に推論過程と生成クエリが表示され、結果の検証やクエリの再利用が容易

ユーザーはコンソールの会話型分析 (対話的な分析) または QueryData ツール (アプリケーション組み込み) を通じて自然言語で質問し、Conversational Analytics API がコンテキスト情報を使って SQL を生成・実行し、Bigtable のデータから回答を返します。

⚡ 主要機能

1️⃣ 会話型分析のデータエージェント

→テーブルやビューなどのナレッジソースを選択してデータエージェントを作成
→フィールド名のシノニムやビジネス用語、フィルタリング・グルーピングのデフォルトなどのカスタムメタデータと指示を設定可能
→コンソールの「Agents」ページで、自分が作成したエージェントと他ユーザーから共有されたエージェントを管理

2️⃣ 会話 (Conversations)

→データエージェントまたはデータソースとの永続化されたチャット
→「sales」「most popular」のような一般的な用語での複数パートの質問に対応 (フィールド名の指定やフィルタ条件の定義が不要)
→回答はテキスト・コード・グラフで返され、「Show thinking」で推論過程、「See detail」で生成クエリと結果を確認可能
→データソースとの直接会話も可能だが、コンテキストを持つデータエージェントの方が高精度

3️⃣ コンテキスト生成の 2 方式

方式作成場所向いているユーザー
GuidedGoogle Cloud コンソールコードを書かずに利用したいユーザー
AdvancedGemini CLI や IDEエージェント品質を細かく制御したいユーザー (QueryData のコンテキストを再利用)

4️⃣ QueryData ツール

→Conversational Analytics API の QueryData エンドポイントとして提供されるエージェンティックツール
→自然言語から SQL へのクエリ生成をプログラマティックに実行 (スキーマ解釈とクエリ合成を担当)
→エージェントハーネス (Antigravity、ADK、LangChain など) が会話履歴・ユーザー状態・ツールオーケストレーションを管理し、QueryData に自然言語リクエストを送信
→MCP Toolbox または直接の API 呼び出しでアプリケーションと統合

5️⃣ コンテキストセット (QueryData)

構成要素役割
📘 クエリブループリント代表的な自然言語の質問と検証済み SQL のペア。ビジネスインテントと SQL のマッピングを定義
🧩 クエリファセット日付範囲やしきい値などのモジュール化された SQL 述語・フィルタ条件。組み合わせごとのブループリント作成が不要
🔍 バリューサーチ「Bay Area」→「San Francisco」のように曖昧な表現を実際のカラム値に解決 (完全一致・トライグラム類似・セマンティックベクトル埋め込み)
🤖 自動化: コンテキストエンジニアリングエージェントによるコンテキスト作成の自動化にも対応。

ステップ処理内容
1. 値の解決 (Value resolution)バリューサーチクエリを実行し、プロンプト内のエンティティ (名前、都市、カテゴリなど) をデータベースのカラム値にマッピング
2. インテントマッチングと曖昧さ解消リクエストをコンテキストセットのブループリント・ファセットと照合。曖昧な場合は明確化のための質問を返す
3. クエリ合成マッチしたブループリント構造、適用されたファセット、解決された値から完全な SQL クエリを合成
4. クエリ実行生成されたクエリをデータベースに対して実行し結果を返す

項目詳細

🚀 設定方法

📋 前提条件

✓Bigtable インスタンスとクエリ対象のテーブル・ビューが存在すること
✓データエージェント作成・会話に必要な IAM ロールを保有していること (詳細は公式ドキュメントの required roles を参照)

💬 会話型分析でエージェントと会話する

ステップ 1: データエージェントの作成

Google Cloud コンソールの Bigtable ページでインスタンスを選択し、ナビゲーションメニューの「Agents」からテーブル・ビューをナレッジソースとして指定し、データエージェントを作成・公開。必要に応じてシノニムやフィルタリングのデフォルトなどのコンテキストと指示を設定します。

ステップ 2: エージェントとの会話

「Agent Catalog」タブからエージェントカードをクリックしてチャットパネルを開き、「Ask a question」フィールドに質問を入力 (Gemini が提案する質問から開始することも可能)。「Show thinking」で推論過程、「See detail」で生成クエリと結果を確認できます。

✨ メリット

💼 ビジネス面

✓データ活用の民主化: SQL やスキーマの知識がないユーザーでも、自然言語で Bigtable のオペレーショナルデータから洞察を得られる
✓エージェントアプリの開発加速: 顧客サービス自動化 (「注文はどこ?」)、EC ショッピングアシスタント (「100 ドル以下のランニングシューズを見せて」)、フィールドオペレーション (在庫・部品の照会) を短期間で実現
✓Preview 期間中は追加料金なし: 実行されるクエリの Bigtable 料金のみで試用できる

⚙️ 技術面

✓高精度なクエリ生成: 汎用 LLM の知識や生スキーマだけに頼らず、コンテキストセットで組織固有の用語とビジネスロジックを反映
✓透明性と検証可能性: 推論過程と生成クエリが表示されるため AI の回答を検証でき、クエリの再利用も可能
✓柔軟な統合: コンソールでの対話的な利用から ADK / LangChain / MCP Toolbox 経由のプログラマティックな利用まで、同じ Conversational Analytics API 基盤で対応

⚠️ デメリット・制約事項

制限事項

▲両機能とも Preview であり、Pre-GA Offerings Terms (QueryData はさらに生成 AI プレビュー製品の追加規約) が適用される。サポートは限定的で「現状のまま」提供
▲Gemini for Google Cloud は早期段階の技術であり、もっともらしいが事実と異なる出力を生成する可能性があるため、出力の検証が推奨
▲Vertex AI の Dynamic Shared Quota により、高負荷時に一時的な 429 Resource Exhausted エラーが発生する場合がある (短い遅延の後にリトライ)

考慮すべき点

→データソースとの直接会話はデータエージェントより精度が低くなる可能性があるため、精度が求められるケースではデータエージェントの利用を推奨
→エージェント作成前に、自動生成されるコンテキストと指示でまず動作を確認してからカスタマイズすることを推奨
→Gemini for Google Cloud によるデータの取り扱い (データガバナンス) を事前に確認すること

🎯 ユースケース

📊 ユースケース 1: 運用データのセルフサービス分析

シナリオ: EC サイトの注文イベントを Bigtable に保存している企業で、ビジネスアナリストが SQL を書かずに売上傾向やユーザー行動を分析したい。

Text 実装例 
1. コンソールの Bigtable「Agents」ページで注文テーブルをナレッジソースとするデータエージェントを作成
2. 「sales」=「order_amount カラムの合計」などのシノニムとビジネス用語を設定して公開
3. アナリストが「先四半期の売上合計は?」「セッション時間の上位 5 ユーザーを見せて」と自然言語で質問
✅ 効果: データエンジニアへのクエリ作成依頼が不要になり、分析のリードタイムが短縮。生成クエリが表示されるため結果の検証も容易。

🤖 ユースケース 2: 顧客サービスエージェントへの QueryData 組み込み

シナリオ: 「注文はどこ?」「現在の残高は?」といった大量の定型的な問い合わせに自動応答するカスタマーサービスエージェントを、ADK や LangChain で構築したい。

✅ 効果: QueryData のコンテキストセット (検証済み SQL のブループリント、バリューサーチによる曖昧さ解消) により、正確でグラウンディングされた回答を返すエージェントを、Text-to-SQL ロジックを自前実装せずに構築できる。
