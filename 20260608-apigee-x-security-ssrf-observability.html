📋 概要

Google Cloud は Apigee の更新バージョン 1-17-0-apigee-9 をリリースした。本リリースには、Script ポリシーにおける SSRF 脆弱性への対策強化と、OpenTelemetry トレースエクスポートパイプラインのオブザーバビリティメトリクス追加が含まれる。

💡 ポイント: API ゲートウェイのセキュリティ強化と運用可視性の向上という 2 つの重要な側面をカバー。過去のセキュリティバレチン (GCP-2026-010, GCP-2026-034) で報告された攻撃ベクトルへの追加防御層を提供。

❌ Before (アップデート前)

  • Script ポリシーからリンクローカルアドレス (169.254.0.0/16) へのリクエストが可能 (SSRF リスク)
  • OTel トレースエクスポートパイプラインのメトリクスが不足
  • フォワードプロキシ (Basic 認証) 経由の HTTP エクスポートが認証失敗

✅ After (アップデート後)

  • リンクローカルアドレスへのリクエストを自動ブロック (SSRF 攻撃面の大幅縮小)
  • spans_exported, export_latency, batch_size, dropped_spans メトリクス追加
  • Basic 認証付きフォワードプロキシ経由の HTTP エクスポートが正常動作

🔒 セキュリティ修正の詳細

🛡️ Script ポリシーの SSRF ハードニング

Bug 514384893

  • Script ポリシーからリンクローカルアドレスへの SSRF をブロック
  • リンクローカルアドレス (169.254.0.0/16) はクラウド環境のメタデータサーバーへのアクセスに使用
  • SSRF 攻撃により認証情報 (サービスアカウントトークン / P4SA) の漏洩リスクが存在していた
  • GCP-2026-010 で報告された脆弱性に対する追加の防御レイヤー

🏢 Apigee インフラストラクチャのセキュリティ修正

  • インフラストラクチャレベルでの追加のセキュリティ修正が適用
  • プラットフォーム全体のセキュリティ態勢を強化

🚫 SSRF ハードニングの対象アドレス

アドレス範囲 説明 ブロック状態
169.254.0.0/16 リンクローカルアドレス (IPv4) 🛡️ 今回ブロック追加
169.254.169.254 GCE メタデータサーバー 🛡️ 今回ブロック追加
fe80::/10 リンクローカルアドレス (IPv6) 🛡️ 今回ブロック追加 (推定)

📊 OpenTelemetry オブザーバビリティメトリクス

📡 トレースエクスポートのメトリクス追加

Bug 512850756

OpenTelemetry トレースエクスポートパイプラインに以下のメトリクスが追加され、分散トレーシングパイプラインの健全性をモニタリング可能に。

メトリクス名 説明 用途
spans_exported エクスポート成功したスパンの総数 📈 スループット監視
export_latency エクスポート操作のレイテンシ ⏱️ パフォーマンス監視
batch_size エクスポートバッチあたりのスパン数 ⚙️ バッチ効率の最適化
dropped_spans ドロップ (損失) されたスパン数 ⚠️ データ損失の検出

🔧 フォワードプロキシ経由の HTTP エクスポート認証修正

Bug 515039499

Basic 認証が必要なフォワードプロキシを経由した OpenTelemetry トレースの HTTP エクスポートが認証に失敗する問題を修正。エンタープライズ環境でのトレースエクスポートが正常に機能するように。

Cloud Monitoring アラートポリシー例

dropped_spans メトリクスを監視し、トレースデータの損失を早期に検知する設定例。

YAML 
# Cloud Monitoring アラートポリシー (概念例)
alertPolicy:
  displayName: "Apigee OTel Trace Export - Dropped Spans Alert"
  conditions:
    - conditionThreshold:
        filter: 'metric.type="apigee.googleapis.com/trace/dropped_spans"'
        comparison: COMPARISON_GT
        thresholdValue: 100
        duration: "300s"

⚖️ メリット・デメリット

✅ メリット

🔒 セキュリティ面

  • SSRF 攻撃面の縮小
  • 多層防御 (Defense in Depth) の強化
  • マネージド版はゼロアクションで適用

📊 運用面

  • トレースパイプラインの可視化
  • データ損失の早期検出
  • エンタープライズプロキシ対応

⚠️ 制約事項・注意点

  • Script ポリシー内で正当な目的でリンクローカルアドレスにアクセスしていたカスタムロジックが動作しなくなる可能性
  • ブロック対象の詳細なアドレスリストは公式に非公開
  • Apigee Hybrid は手動バージョンアップグレードが必要
  • 新メトリクスは既存ダッシュボードへの手動追加が必要
  • フォワードプロキシ認証修正は HTTP エクスポートのみ (gRPC は対象外)

🎯 ユースケース

👥 UC1: マルチテナント API プラットフォームのセキュリティ強化

シナリオ: 複数チームが共有 Apigee 環境で API プロキシを開発。悪意ある内部ユーザーや侵害されたプロキシが Script ポリシーを通じてメタデータサーバーにアクセスし、サービスアカウントトークンを窃取する攻撃を防止したい。

効果: リンクローカルアドレスへのリクエストが自動的にブロックされ、追加設定なしで SSRF 攻撃が防止される。

📈 UC2: エンタープライズ環境でのトレースパイプライン監視

シナリオ: 大規模 API トラフィックを処理する Apigee 環境で OpenTelemetry を使用した分散トレーシングを Cloud Trace に送信。トレースデータの欠落やエクスポート遅延を早期検知したい。

効果: dropped_spans メトリクス監視により、トレースデータの損失を 5 分以内に検知し、パイプライン問題を迅速に特定・解決可能。

🌐 UC3: プロキシ経由の分散トレーシング設定

シナリオ: セキュリティポリシーにより全アウトバウンド通信がフォワードプロキシ (Squid 等, Basic 認証必須) 経由の環境で、Apigee の分散トレーシングデータを外部バックエンド (Jaeger 等) にエクスポートしたい。

効果: Basic 認証付きフォワードプロキシ経由での HTTP エクスポートが正常動作し、厳格なネットワーク制約下でも分散トレーシングが利用可能。

📝 まとめ

本アップデートは、Apigee のセキュリティとオブザーバビリティの両面で重要な改善を提供する。

  • SSRF ハードニング: リンクローカルアドレス経由のメタデータサーバーアクセスを防止し、GCP-2026-010 / GCP-2026-034 への追加防御層を提供
  • OTel メトリクス: 分散トレーシングパイプラインの運用状況が可視化され、問題の早期検出が可能に
  • マネージド Apigee: 自動適用 (追加アクション不要)
  • Apigee Hybrid: バージョン 1-17-0-apigee-9 へのアップグレードを速やかに計画すること
