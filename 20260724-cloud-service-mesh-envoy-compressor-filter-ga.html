📋 概要

Cloud Service Mesh の Envoy Compressor Filter が Stable リリースチャネルで一般提供 (GA) となりました。すべてのリリースチャネル (Rapid、Regular、Stable) で Envoy Compressor Filter の全フィールドが正式にサポートされ、本番環境での HTTP ボディの圧縮・帯域幅最適化が完全にサポートされた状態で利用可能です。

Envoy Compressor Filter は、HTTP リクエストおよびレスポンスのボディをリアルタイムで圧縮する機能を提供し、gzip などの圧縮アルゴリズムを使用してサービスメッシュ内の通信帯域幅を削減し、アプリケーションのパフォーマンスを向上させます。

❌ Before (アップデート前)

  • ✗ Stable チャネルでは一部フィールドが正式サポート外
  • ✗ 非推奨形式でバリデーション警告・エラー発生
  • ✗ 本番クラスターでのサポート保証が限定的

✅ After (アップデート後)

  • ✓ すべてのチャネルで GA として完全サポート
  • ✓ 全フィールドが Stable チャネルで利用可能
  • ✓ 完全なサポート保証が提供

⚙️ 主要機能

📤 レスポンス方向の圧縮設定

response_direction_config

  • 最小レスポンスサイズの設定
  • 圧縮対象コンテンツタイプ指定
  • ランタイムキーによる動的制御
  • ETag ヘッダー時の圧縮無効化
  • Accept-Encoding ヘッダー除去
  • 圧縮除外レスポンスコード指定

📥 リクエスト方向の圧縮設定

request_direction_config

  • 最小リクエストサイズの設定
  • 圧縮対象コンテンツタイプ指定
  • ランタイムキーによる動的制御

📚 圧縮ライブラリの選択

compressor_library

  • gzip 圧縮アルゴリズムのサポート
  • choose_first による優先アルゴリズム選択

📝 設定方法

前提条件

✓ Cloud Service Mesh が有効化された GKE クラスター (TRAFFIC_DIRECTOR コントロールプレーン)
✓ Stable リリースチャネルを使用中のクラスター
✓ kubectl コマンドラインツール

ステップ 1: 既存の非推奨設定を確認

Bash 
# 非推奨フィールドを使用している EnvoyFilter を特定
kubectl get envoyfilters --all-namespaces -o yaml | grep -A 20 "envoy.filters.http.compressor"

ステップ 2: モダン形式の EnvoyFilter を適用

YAML 
apiVersion: networking.istio.io/v1alpha3
kind: EnvoyFilter
metadata:
  name: compressor-filter-update
  namespace: istio-system
spec:
  configPatches:
  - applyTo: HTTP_FILTER
    match:
      context: GATEWAY
      listener:
        filterChain:
          filter:
            name: envoy.filters.network.http_connection_manager
            subFilter:
              name: envoy.filters.http.router
    patch:
      operation: INSERT_BEFORE
      value:
        name: envoy.filters.http.compressor
        typed_config:
          '@type': type.googleapis.com/envoy.extensions.filters.http.compressor.v3.Compressor
          compressor_library:
            name: gzip
            typed_config:
              '@type': type.googleapis.com/envoy.extensions.compression.gzip.compressor.v3.Gzip
          response_direction_config:
            disable_on_etag_header: true
            remove_accept_encoding_header: true
            common_config:
              min_content_length: 1024
              content_type:
              - "application/javascript"
              - "application/json"
              enabled:
                default_value: true
                runtime_key: "compressor.enabled"

ステップ 3: 設定の検証

Bash 
# EnvoyFilter のステータスを確認
kubectl get envoyfilter -n istio-system compressor-filter-update -o yaml

# レスポンスヘッダーで圧縮が有効であることを確認

✅ メリット

💰 ビジネス面

  • 帯域幅コスト削減: HTTP ボディ圧縮によりデータ転送量を大幅に削減、ネットワーク Egress コストを低減
  • 本番環境での安心運用: Stable チャネル GA により、SLA に基づいたサポート保証、ミッションクリティカルなワークロードで利用可能

🔬 技術面

  • レイテンシ改善: 圧縮ペイロードによりネットワーク転送時間短縮
  • 柔軟な設定制御: リクエスト/レスポンス方向別の独立した圧縮設定、ランタイムキー制御
  • 段階的な移行パス: 非推奨形式からモダン形式への明確な移行パス

⚠️ デメリット・制約事項

制限事項
  • ✗ TRAFFIC_DIRECTOR コントロールプレーン実装でのみサポート (Istiod ベースでは利用不可)
  • ✗ EnvoyFilter API は HTTP_FILTER のみに適用可能 (TCP フィルターなどには適用不可)
  • ✗ 圧縮処理による CPU オーバーヘッドが発生 (CPU バウンドなワークロードでは影響評価が必要)
💡 考慮すべき点
  • 非推奨のトップレベルフィールドは将来的に拒否される可能性あり
  • 小さなペイロードの圧縮はかえってオーバーヘッドになる (最小サイズの設定が重要)
  • 既に圧縮されたコンテンツ (画像、動画など) に対する圧縮は CPU を浪費する

💡 ユースケース

🛒 ユースケース 1: マイクロサービス間の JSON API 通信の最適化

シナリオ: 多数のマイクロサービスが JSON 形式で大量のデータを交換する E コマースプラットフォームにおいて、サービス間の帯域幅を最適化したい。

YAML 
apiVersion: networking.istio.io/v1alpha3
kind: EnvoyFilter
metadata:
  name: json-compressor
  namespace: istio-system
spec:
  configPatches:
  - applyTo: HTTP_FILTER
    match:
      context: SIDECAR_INBOUND
      listener:
        filterChain:
          filter:
            name: envoy.filters.network.http_connection_manager
            subFilter:
              name: envoy.filters.http.router
    patch:
      operation: INSERT_BEFORE
      value:
        name: envoy.filters.http.compressor
        typed_config:
          '@type': type.googleapis.com/envoy.extensions.filters.http.compressor.v3.Compressor
          compressor_library:
            name: gzip
            typed_config:
              '@type': type.googleapis.com/envoy.extensions.compression.gzip.compressor.v3.Gzip
          response_direction_config:
            common_config:
              min_content_length: 512
              content_type:
              - "application/json"
              - "application/grpc+proto"
              enabled:
                default_value: true
                runtime_key: "json_compressor.enabled"
効果: JSON レスポンスが平均 60-80% 圧縮され、ネットワーク帯域幅の使用量が大幅に削減される。

🌐 ユースケース 2: API Gateway での帯域幅コスト削減

シナリオ: Ingress Gateway を通じて外部クライアントにサービスを公開しており、Egress 帯域幅コストを削減したい。

効果: クライアント向けレスポンスの圧縮により、Cloud NAT や外部ロードバランサーを経由するトラフィック量が削減され、ネットワークコストが低減される。
