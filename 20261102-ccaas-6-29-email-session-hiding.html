📝 概要

Google Cloud は 2026 年 11 月 2 日に Google Cloud CCaaS (Contact Center as a Service) バージョン 6.29 をリリースしました。 目玉は Apps API 経由でメールセッションを非表示にできる新機能です。 2 つの新エンドポイントでメールセッションをエージェントアダプターから隠すことができ、非表示セッションはエージェントのリスト・件数カウント・検索結果・スーパーバイザーダッシュボードのライブカウンターから除外されます。

セッション自体は削除されず、ステータスも変更されません。エンドユーザーが非表示セッションに返信すると自動的に再表示され、既存の返信処理ルールに従って処理されます。 あわせて音声転送、チャット、ダッシュボード、CRM 連携など広範囲の約 20 件のバグ修正が含まれ、運用の安定性が大幅に向上しています。

🎯 主な対象ユーザー: 外部のオーケストレーションやワークフローシステムと CCaaS を連携している企業、および大量のメールセッションを扱うコンタクトセンター管理者。

❌ Before: アップデート前の課題

  • 自動化ワークフローやバックオフィス処理の対象メールもエージェントのリスト・件数・ライブカウンターに表示され続け、対応すべき案件を区別しにくかった
  • セッションを視界から外すにはステータス変更 (resolved / closed) か削除しかなく、状態を維持したまま一時的に見えなくする手段がなかった
  • 音声転送のウィスパー音声の言語誤り、無効な発信者 ID のコールループ、ブレンド SMS のトランスクリプト非表示など運用上の不具合が多数存在

✅ After: アップデート後の改善

  • Apps API の 2 つの新エンドポイントで、削除もステータス変更もせずにメールセッションをエージェントアダプターから非表示にできる
  • エンドユーザーが返信すると自動的に再表示され、既存の返信処理ルールに従うため、顧客対応の抜け漏れを防ぎながら表示制御が可能
  • ウィスパー音声の言語、未読チャットバッジの過大表示、ダッシュボードの二重カウント、Salesforce アダプターのサイレント障害など約 20 件の不具合を修正

⚡ 主要機能

1️⃣ Google Cloud CCaaS 6.29 のリリース

→バージョン 6.29 が正式にリリース
→各インスタンスへの適用タイミングは、選択しているデプロイメントスケジュールに依存

2️⃣ メールセッション非表示機能 (Apps API)

→2 つの新しい Apps API エンドポイントで、メールセッションをエージェントアダプターから非表示化
→非表示にすると、エージェントのリスト・件数カウント・検索・スーパーバイザーダッシュボードのライブカウンターから除外
→セッションは削除されず、ステータスも変更されない (非破壊的)
→エンドユーザーが返信すると自動的に再表示され、既存の返信処理ルールに従う
→Apps API 経由でのみ利用可能 (ポータル UI からの操作は不可)
→デフォルトでは無効。有効化には Google Cloud サポートへの連絡が必要

3️⃣ 約 20 件のバグ修正

→音声・チャット・ダッシュボード・CRM 連携など広範囲の不具合を修正 (詳細は下記)

🔧 主なバグ修正の内容

🎙️ 音声・転送関連

  • 言語をまたぐエージェントからキューへの音声転送で、ウィスパー音声と「Selected Language」表示が転送先ではなく転送元の言語になる問題
  • 無効または整形不能な発信者 ID の着信がエージェント側で読み込まれず、発信者が切断するまでエージェント間でコールがループする問題
  • 受信側エージェントのマイク権限が無効な場合に、スーパーバイザーキューへのウォーム転送がサイレントに失敗し繰り返しループする問題
  • 受信側エージェントにマイクまたはデバイスエラーがある場合に、コール転送が即座に再キューイングされない問題
  • Nexmo 番号を使用したコールが、仮想エージェントエスカレーション中のプリセッションデフレクション試行時に切断される問題
  • 仮想エージェントのウェルカムプロンプト再生前に、着信コールで遅延や無音が発生する問題
  • 1 回のコール中にリダクション (情報秘匿) ボタンを複数回クリックした際に、通話録音の一時停止・再開が一貫して動作しない問題

📊 レポート・ダッシュボード関連

  • 「Deflections - Calls」ダッシュボードで、電話番号にリダイレクトされたコールが二重カウントされる問題
  • スーパーバイザーによる通話中エージェントの強制サインアウトで、必須のコールディスポジションが破棄され、レポートに対応結果が記録されない問題
  • 発信者により放棄された未応答の内線・着信コールが「Missed」リストに表示されず、不明なエラーとして誤分類される問題
  • 一部の失敗コールがセッションデータエクスポートで「Failed: ()」と表示され、高度なレポートフィルターから漏れる問題
  • ポストセッションサーベイへの転送直後に発信者が切断した場合、仮想エージェントの通話録音がエクスポートされない問題

💬 チャット・SMS・統合関連

  • リアルタイムリダクション有効時に、仮想エージェントからエスカレーションされたチャットで未読バッジの件数が過大表示される問題
  • ブレンド SMS コールで通話トランスクリプトと SmartActions パネルが読み込まれない問題
  • 必須のセキュリティキーなしでエージェントデスクトップに読み込まれた際に、Salesforce アダプターがエラーログを残さず接続に失敗する問題
  • クライアント認証情報を使用した OAuth セットアップで権限不足の場合に、Microsoft 365 のメールボックス選択ドロップダウンが空になる問題

🧩 その他

  • サインイン後、CCaaS ポータルのキューリストが長時間ローディング状態のままになる問題
  • 営業時間外およびキャパシティ超過時のアナウンス・オプションメッセージを、個々のユーザーおよびチームレベルでカスタマイズできない問題
  • 直接着信コールがコンタクトリストまたはキューにデフレクトされる際に、カスタム SIP ヘッダーが引き継がれない問題

📐 技術仕様

メールセッション非表示機能の仕様

項目詳細
提供方法Apps API のみ (2 つの新エンドポイント)
非表示の影響範囲エージェントのリスト、件数カウント、検索、スーパーバイザーダッシュボードのライブカウンター
セッションへの影響削除されない、ステータスも変更されない
自動再表示エンドユーザーが返信すると自動的に再表示され、既存の返信処理ルールに従う
デフォルト状態無効 (Google Cloud サポートへ有効化を依頼)
認証Apps API は基本認証 (Basic authentication) を使用

関連する既存の Apps API メールエンドポイント

メールセッションを操作する既存の Apps API エンドポイントと組み合わせて利用できます。

エンドポイントメソッド用途
/apps/api/v1/email/sessions/EMAIL_SUPPORT_IDGETメールセッションのサマリーとメッセージ ID 一覧を取得
/apps/api/v1/email/messages/EMAIL_THREAD_IDGET個別メールメッセージの全文を取得
/apps/api/v1/email/update_statusPOST最大 100 セッションのステータスを一括更新
💡 メールセッションのステータス: unopened / active / paused / resolved / closed / reopened の 6 種類。 非表示機能はこれらのステータスに影響を与えません。

✓自動再表示による安全性: エンドユーザーの返信をトリガーに自動で再表示されるため、顧客からの連絡を見落とすリスクがない

⚠️ デメリット・制約事項

制限事項

✗メールセッション非表示機能は Apps API 経由でのみ利用可能で、CCaaS ポータルの UI からは操作できない
✗デフォルトで無効のため、利用には Google Cloud サポートへの有効化依頼が必要
✗バージョン 6.29 の適用タイミングはインスタンスごとのデプロイメントスケジュールに依存するため、即座に利用できるとは限らない

考慮すべき点

⚠️非表示セッションはエージェントの検索からも除外されるため、運用チームには非表示ルールの存在を周知しておく必要がある
⚠️返信による自動再表示の挙動は既存の返信処理ルールに従うため、再表示後のルーティング設計を事前に確認しておくことが望ましい

🎯 ユースケース

📧 ユースケース 1: 自動応答で完結したメールのエージェントリストからの除外

シナリオ: 注文確認や配送通知への自動返信など、外部の自動化ワークフローで処理が完結したメールセッションが、エージェントのリストと件数に残り続けてしまう。

実装例: 外部オーケストレーションシステムが自動処理の完了後に Apps API の非表示エンドポイントを呼び出し、セッションをエージェントアダプターから除外する。顧客が追加の質問を返信した場合はセッションが自動再表示され、通常の返信処理ルールでエージェントに割り当てられる。

効果: エージェントは人の対応が必要なメールだけに集中でき、スーパーバイザーダッシュボードの件数も実態を反映する。

📥 ユースケース 2: バックオフィス処理待ちセッションの一時退避

シナリオ: 返金処理や外部部門への確認など、エージェントの操作を必要としない待機状態のメールセッションがキューの件数を膨らませ、業務量の把握を妨げている。

効果: ステータスを維持したまま非表示にすることで、レポーティングの整合性を保ちながらライブカウンターを実対応件数に近づけられる。顧客からの返信があれば即座に再表示されるため対応漏れも発生しない。

🔗 関連サービス・機能

🔌 Apps API (CCAI Platform)

本機能の提供基盤。メールセッション・メッセージの取得 (GET /apps/api/v1/email/sessions、GET /apps/api/v1/email/messages) や一括ステータス更新 (POST /apps/api/v1/email/update_status) と組み合わせて、メール処理の自動化パイプラインを構築できる。

👤 エージェントデスクトップ / エージェントアダプター

非表示機能の表示制御対象。バージョン 6.9 以降、エージェントデスクトップはメールアダプターをサポートしている。

🤝 Salesforce / Microsoft 365 連携

本リリースで Salesforce アダプターの接続エラーログ出力、M365 メールボックス選択ドロップダウンの不具合が修正され、CRM・メール連携の信頼性が向上した。

Google Cloud CCaaS 6.29 は、Apps API によるメールセッション非表示という自動化・外部連携向けの新機能と、音声転送やダッシュボードなど広範囲の約 20 件のバグ修正を含むリリースです。 メール処理を外部ワークフローで自動化している組織は、Google Cloud サポートに有効化を依頼した上で、エージェントの作業リスト最適化への活用を検討することをおすすめします。 また、自社インスタンスのデプロイメントスケジュールを確認し、6.29 の適用時期を把握しておきましょう。
