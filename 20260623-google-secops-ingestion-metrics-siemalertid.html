📋 概要

Google Security Operations (SecOps) で 2 つの重要な変更が発表されました。

1. siemAlertId フィールドの内部予約化 (Breaking Change)

7月5日以降、siemAlertId は Chronicle SIEM 内部アラート ID 専用に厳密予約されます。カスタムデータを渡した場合、システムが自動的に上書きします。

2. インジェスションメトリクスの過少報告修正

ダッシュボードおよび Cloud Monitoring に表示されるインジェスションメトリクスの過少報告問題を解消。6/29-7/10 の間に段階適用されます。

🔄 Before / After 比較

❌ Before (現在の課題)

  • インジェスションメトリクスが一部過少報告されていた
  • siemAlertId にカスタムデータを格納して運用するユーザーが存在
  • siemAlertId の用途が明確に制限されず、内部/外部用途が混在

✅ After (改善後)

  • メトリクスが正確に報告され、データ可視性が向上
  • siemAlertId の用途が明確化、アラート ID の一貫性保証
  • SOAR 連携のアラート同期が安定化

⚡ 主要変更の詳細

1. インジェスションメトリクス修正

📊ダッシュボード (Data Ingestion and Health) および Cloud Monitoring のメトリクスが対象
📅2026年6月29日 - 7月10日の間に段階的に有効化
📈修正適用時に一時的な「見かけ上のスパイク」が表示される可能性
💰実際のログ取り込み量に変更なし、課金にも影響なし
🕐過去のメトリクスデータは修正されない (修正以降のデータのみ正確)

2. siemAlertId 内部予約化 (Breaking Change)

📅2026年7月5日に適用開始
🔒Chronicle SIEM 内部アラート ID 専用に厳密予約
⚠️カスタムデータはシステムにより自動上書きされる
🌐全インジェスション方法が影響: Ingestion API、Webhook、コネクタ
🚨7月5日前に別フィールドへの移行が必須

3. siemAlertId の正しい用途

システム内部管理用: Google Chronicle Alerts Creator ジョブがサードパーティアラートを SIEM に同期する際に自動付与され、SIEM で生成されたアラートがコネクタ経由で取得される際に自動設定されるフィールドです。ユーザーが手動で設定するものではありません。

💻 移行先フィールドとコードサンプル

方法 1: UDM additional.fields に移行

JSON UDM additional.fields への移行例 
{
  "metadata": {
    "event_timestamp": "2026-06-23T12:00:00Z",
    "event_type": "GENERIC_EVENT"
  },
  "additional": {
    "fields": {
      "custom_alert_id": {
        "string_value": "your-custom-alert-identifier"
      }
    }
  }
}

方法 2: Ingestion Labels に移行

JSON Ingestion Labels への移行例 
{
  "labels": [
    {
      "key": "custom_alert_id",
      "value": "your-custom-alert-identifier"
    }
  ]
}
💡 移行先の選び方:
  • 検索・フィルタリング用途: UDM の additional.fields に移行
  • ラベル・タグ用途: Ingestion labels (labels[]) に移行
  • アラート関連メタデータ: security_result 内のカスタムフィールドに移行

📝 移行手順

  1. 影響範囲の特定: siemAlertId にカスタムデータを渡しているインジェスション設定 (API スクリプト、Webhook フィード、SOAR コネクタ) を洗い出す
  2. 移行先フィールドの選定: カスタムデータの用途に応じて additional.fields、labels[]、security_result から適切なフィールドを選択
  3. インジェスション設定の更新: 移行先フィールドを使用するようにコードまたは設定を更新
  4. 検証: 更新後のデータが正しく取り込まれ、検索・検出ルールで参照可能か確認
  5. 検出ルールの更新: siemAlertId を参照している YARA-L 検出ルールを移行先フィールド参照に更新
