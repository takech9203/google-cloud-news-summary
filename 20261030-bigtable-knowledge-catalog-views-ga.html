🗄️ Bigtable × Knowledge Catalog
ビュー 3 種の検出が GA

承認済みビュー / 論理ビュー / 連続マテリアライズドビューを中央カタログで検索可能に
リリース日: 2026-10-30
Bigtable Knowledge Catalog (Dataplex) GA (一般提供)

📝 概要

Bigtable と Knowledge Catalog (旧 Dataplex Universal Catalog) の統合が拡張され、 承認済みビュー (Authorized Views)、論理ビュー (Logical Views)、連続マテリアライズドビュー (Continuous Materialized Views) を Knowledge Catalog で検出できる機能が 一般提供 (GA) になりました。 Bigtable のインスタンスやテーブルと並べて、より粒度の細かいデータアセットを横断的に検索できます。

Bigtable のメタデータは Knowledge Catalog に自動的に同期されるため、個別のカタログ登録は不要です。 今回の GA により、同期対象がインスタンス、クラスタ、テーブル (列ファミリーの詳細を含む) に加えて、3 種類のビューまで広がりました。

🎯 対象ユーザー: 組織内のデータアセットを一元的に把握したいデータガバナンスチーム、 既存のビューを再利用して分析・アプリケーション開発を行いたいデータエンジニア / アナリスト。 特にマルチテナント構成で承認済みビューを多数運用しているチームに有用です。

❌ Before (アップデート前の課題)

  • 検出できる Bigtable リソースはインスタンス・クラスタ・テーブルまでで、ビューは中央のカタログから検索不可
  • ビューの存在やアクセス状況は Bigtable 側でインスタンスごとに個別確認が必要
  • ビューとテーブル・インスタンスの関係性 (派生元) をカタログ上で追跡できない

✅ After (アップデート後の改善)

  • 3 種類のビューを Knowledge Catalog の中央インベントリで検索・検出可能に
  • どのビューが存在し誰がアクセスできるかを可視化でき、ポリシー・アクセス制御を適用しやすく
  • 承認済みビューとテーブル、論理 / 連続マテリアライズドビューとインスタンスの関連を把握可能
  • アスペクト (カスタムメタデータ) を付与してデータエステート全体の発見性を向上

Bigtable の各リソースのメタデータが Knowledge Catalog に自動同期され、今回の GA でインスタンス・テーブルに加えて 3 種類のビューも検索対象になりました。ビューのメタデータはインスタンスに割り当てられたリージョンに格納されます。

⚙️ 主要機能

1️⃣ 3 種類のビューの自動カタログ化

承認済みビュー・論理ビュー・連続マテリアライズドビューのメタデータが Bigtable から Knowledge Catalog に自動同期。 従来から同期対象だったインスタンス、クラスタ、テーブル (列ファミリーの詳細を含む) に加わる形で、カタログの網羅性が向上します。

2️⃣ 検索述語 (predicate) によるビューの検索

Knowledge Catalog の検索ページで、以下の述語を使ってビューを絞り込めます。ファセット検索 (フィルタ適用) にも対応。

絞り込み対象検索述語
すべてのビューVIEW
承認済みビューtype=cloud-bigtable-authorized-view
論理ビューtype=cloud-bigtable-logical-view
連続マテリアライズドビューtype=cloud-bigtable-materialized-view
リージョンでの絞り込みlocation=us-central1 など

3️⃣ エントリ詳細でのシステムアスペクト表示

ビューのエントリ詳細ページで、概要情報に加えて SQL クエリ (論理 / 連続マテリアライズドビュー) やスキーマ、サブセット定義 (承認済みビュー) などのシステムアスペクトを確認できます。カスタムアスペクトでビジネスメタデータを追加し、組織内での発見性を高められます。

🔬 技術仕様

📍 ビューメタデータのリージョン制約

項目詳細
カタログエントリの格納場所 ビューはグローバルエントリを持たず、インスタンスに割り当てられたリージョン (knowledgeCatalogRegion) にのみ格納
API アクセス時の location 指定 Dataplex API / クライアントライブラリでビューのエントリを取得・管理する際は、リクエスト URL の location にインスタンスの Knowledge Catalog リージョンを指定する必要あり
location=global を指定した場合 NOT_FOUND エラーが返る
リージョンの確認方法 gcloud bigtable instances describe の出力の knowledgeCatalogRegion フィールドで確認

📋 カタログ化される Bigtable のビュー種別

種別構造定義方法書き込み主な用途
👁️ 論理ビュー SQL クエリ結果の仮想テーブル SQL クエリ ❌ 不可 SQL によるデータ共有・再利用
⚡ 連続マテリアライズドビュー ソーステーブルと同期する読み取り専用テーブル SQL クエリ ❌ 不可 事前集計によるクエリ性能向上
🔐 承認済みビュー テーブルのサブセット JSON 定義ファイル ✅ 可 テナントごとのアクセス制御

🛠️ 設定方法

✅ 前提条件

✓Knowledge Catalog を初めて使う場合は Dataplex API を有効化する
✓Bigtable エントリにアクセスするプリンシパルに必要な IAM ロールを付与する (検索には Dataplex Catalog Viewer roles/dataplex.catalogViewer 以上のロールがリクエスト対象プロジェクトで必要)
1インスタンスの Knowledge Catalog リージョンを確認する
Bash gcloud でインスタンス情報を表示 
gcloud bigtable instances describe INSTANCE_ID

出力に含まれる knowledgeCatalogRegion フィールド (例: us-central1) が、ビューのメタデータが格納されるリージョンです。 Dataplex API でビューのエントリを扱う際はこの値を location に指定します。

YAML 出力例 
createTime: '2026-01-15T10:00:00.000000Z'
displayName: my-instance
edition: ENTERPRISE
knowledgeCatalogRegion: us-central1
name: projects/my-project/instances/my-instance
state: READY
type: PRODUCTION
2Knowledge Catalog でビューを検索する
→Google Cloud コンソールで Knowledge Catalog の「検索」ページに移動する
→検索フィールドにビュー名・ID、または検索述語を入力する
Text 検索述語の例 
# 承認済みビューのみを検索
type=cloud-bigtable-authorized-view

# 特定リージョンの連続マテリアライズドビューを検索
type=cloud-bigtable-materialized-view location=us-central1
→検索結果からビュー名をクリックすると、エントリ詳細ページで SQL クエリ、スキーマ、サブセット定義などの属性を確認できます

💡 メリット

💼 ビジネス面

🛡️ ガバナンスの強化

どのビューが存在し誰がアクセスできるかを可視化できるため、ガバナンスチームがポリシーとアクセス制御を組織的に適用できる。

♻️ データの再利用促進

既存のビューを中央インベントリから発見できるため、重複したビューの作成を避け、分析やアプリケーション開発での再利用が進む。

🔧 技術面

🔄 自動同期によるカタログ鮮度の維持

メタデータは Bigtable から Knowledge Catalog に自動同期されるため、手動でのカタログ登録・更新作業が不要。

🔗 関係性の把握

承認済みビューとテーブル、論理ビュー・連続マテリアライズドビューとインスタンスのつながりをカタログ上で確認でき、データリネージ的なコンテキストが得られる。

🏷️ アスペクトによるメタデータ拡充

カスタムのビジネス・技術メタデータをエントリに付与でき、ターゲットを絞った検索が可能になる。

⚠️ デメリット・制約事項

🚧 制限事項

🌐 グローバルエントリなし: ビューはグローバルカタログエントリを持ちません。メタデータはインスタンスに割り当てられたリージョンにのみ格納されるため、 API からのアクセス時は location にそのリージョンを指定する必要があります (global を指定すると NOT_FOUND)。
🔒 アスペクト閲覧の権限要件: データアスペクトの内容を閲覧するには、エントリの閲覧権限に加えて、 ソースアセットのデータ読み取り権限が必要です (権限がない場合、アスペクトの内容は非表示になります)。

🤔 考慮すべき点

👤 IAM ロール: Knowledge Catalog の検索 (SearchEntries) を実行するには、リクエストに使用するプロジェクトで Dataplex Catalog Admin / Editor / Viewer のいずれかのロールが必要です。
📈 検索クォータ: Dataplex API には検索リクエストのクォータ (例: プロジェクトあたり毎分 1,200 件、組織あたり毎分 2,400 件) があるため、 プログラムから大量に検索する場合は考慮が必要です。

🎯 ユースケース

📦 ユースケース 1: マルチテナント環境での承認済みビューの棚卸し

シナリオ: SaaS 事業者が 1 つの Bigtable テーブルに複数顧客のデータを格納し、顧客ごとに承認済みビューでアクセスを分離している。 ビューの数が増え、どの顧客向けにどのビューが存在するか把握しづらくなっている。

Text 実装例 
# Knowledge Catalog 検索で承認済みビューを一覧化
type=cloud-bigtable-authorized-view

# エントリ詳細でサブセット定義 (JSON) を確認し、
# カスタムアスペクトで「担当チーム」「顧客名」などを付与

✅ 効果: 承認済みビューの全体像を中央インベントリで把握でき、ガバナンスチームが不要なビューの削除やアクセス制御の見直しを計画的に実施できる。

📊 ユースケース 2: 分析チームによる既存ビューの発見と再利用

シナリオ: 分析チームが時系列データの集計クエリを作ろうとしているが、他チームがすでに同様の連続マテリアライズドビューを作成している可能性がある。

✅ 効果: Knowledge Catalog で type=cloud-bigtable-materialized-view を検索し、エントリ詳細で SQL クエリとスキーマを確認することで、 既存ビューの再利用判断が即座にでき、重複するビューの作成 (= 追加のストレージ・処理コスト) を回避できる。

💰 料金

Bigtable メタデータの Knowledge Catalog への自動同期そのものに追加の設定は不要です。 Knowledge Catalog はメタデータストレージと API 呼び出しに対して従量課金が発生します。 コンソールでの検索クエリと Search API 呼び出し、カタログメタモデルリソース (エントリ、エントリグループなど) の作成・管理は無料です。

🔗 関連サービス・機能

📚 Knowledge Catalog (Dataplex)

フルマネージドのメタデータ管理サービス。本アップデートの統合先であり、検索・アスペクト管理・ガバナンス機能を提供。なお、旧 Data Catalog は非推奨となっており、Knowledge Catalog への移行が推奨されている。

🗄️ Bigtable 承認済みビュー / 論理ビュー / 連続マテリアライズドビュー

今回カタログ化の対象となった Bigtable のビュー機能。アクセス制御、SQL による仮想テーブル、事前集計をそれぞれ担う。

🔄 Datastream

同日 (2026-10-30) に Knowledge Catalog 統合が GA になっており、Google Cloud のデータサービス全体でカタログ統合が進んでいる。

🔑 IAM (Dataplex Catalog ロール)

カタログエントリの検索・閲覧には roles/dataplex.catalogViewer などの Dataplex Catalog ロールが必要。

🚀 まとめ

Bigtable のビュー 3 種 (承認済み / 論理 / 連続マテリアライズド) が Knowledge Catalog で検出可能になり GA を迎えたことで、 Bigtable の粒度の細かいデータアセットまでを含めた一元的なメタデータ管理が実現しました。

ビューを多用するマルチテナント構成や分析基盤を運用しているチームは、まず gcloud bigtable instances describe で knowledgeCatalogRegion を確認し、検索述語 (type=cloud-bigtable-authorized-view など) を使って ビューの棚卸しから始めることを推奨します。
