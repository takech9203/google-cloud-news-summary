⚙️ 主要修正内容

🔧 CDAP-21219: Dataproc ジョブステータスのレースコンディション修正

正常に完了した Dataproc ジョブが、プログラムの早期キャンセルにより Dataproc コンソール上で誤って失敗とマークされる問題が修正されました。

→ ジョブ完了確認前にキャンセル信号が発行されるタイミング問題を解消
→ Dataproc コンソールと Cloud Data Fusion UI 間でステータスが一貫するように

🔧 CDAP-21241: パイプライン一覧ページのハング修正

内部サービスのレースコンディションによりパイプライン一覧ページがハングする問題が修正されました。

→ 並行処理の競合状態を解消し、Web UI の応答性が改善
→ 大量のパイプラインを持つインスタンスでも安定した一覧表示が可能に

🔒 CDAP-21260: ログダウンロードのセキュリティ脆弱性修正

ログダウンロード機能において、要求されたログパスおよびクエリパラメータに対する厳格なバリデーションが実装されました。

→ パストラバーサル攻撃や不正なクエリパラメータによるアクセスを防止
→ ログファイルへのアクセスが意図されたスコープ内に限定

📈 CDAP-21259: Wrangler ブラウジング制限の拡大

Wrangler のデフォルトブラウジング制限が 2,000 アイテムに増加されました。

→ データソース接続時のファイルやテーブル一覧がより多く表示可能に
→ 大規模データレイクやデータウェアハウス環境でのデータ探索効率が向上

🛠️ 設定方法

⚠️ 前提条件: Cloud Data Fusion インスタンスがバージョン 6.11.1 系であること。アップグレード前にすべての実行中パイプラインを停止し、スケジュールを一時停止すること。

アップグレード手順

  1. 実行中パイプラインの停止とスケジュールの一時停止
  2. パッチリビジョンへのアップグレードコマンドを実行
  3. アップグレードの確認 (patchRevision フィールドが 6.11.1.4 であること)
  4. パイプラインスケジュールとトリガーの再開
Bash 
# パッチリビジョンへのアップグレード
gcloud beta data-fusion instances update INSTANCE_ID \
  --project=PROJECT_ID \
  --location=LOCATION \
  --version=6.11.1 \
  --patch_revision=6.11.1.4
Bash 
# アップグレードの確認
gcloud beta data-fusion instances describe INSTANCE_ID \
  --project=PROJECT_ID \
  --location=LOCATION
💡 ヒント: INSTANCE_ID、PROJECT_ID、LOCATION はそれぞれご自身の環境に合わせて置き換えてください。

⚠️ デメリット・制約事項

制限事項:
  • パッチリビジョンのアップグレードにはダウンタイムが必要 (パイプライン停止・スケジュール一時停止が必須)
  • Wrangler ブラウジング制限拡大により、大量アイテムのデータソースでレスポンス時間が若干増加する可能性
  • 本パッチはバージョン 6.11.1 系のみに適用可能 (それ以前のバージョンには直接適用不可)
考慮すべき点:
  • 計画的なメンテナンスウィンドウでの適用を推奨
  • CDAP-21219 修正前に誤って失敗マークされたジョブは実データ処理結果の確認が必要な場合あり
  • CDAP-21260 により非標準的なログパスやクエリパラメータがブロックされる可能性

💡 ユースケース

🏢 ユースケース 1: 大規模パイプライン運用環境での安定性向上

シナリオ: 数百のバッチパイプラインを運用する企業が、パイプライン一覧ページのハングや Dataproc コンソールでのジョブ誤表示により運用管理に支障をきたしている。

効果: パイプライン一覧ページのハング解消により即座に状態確認可能。Dataproc ジョブステータスの正確な報告で誤った障害アラートが削減され、運用効率が向上。

🔐 ユースケース 2: セキュリティ監査対応

シナリオ: 金融機関がセキュリティ監査でログアクセスの制御に関する脆弱性を指摘され、早急な対応が求められている。

効果: CDAP-21260 の修正によりパストラバーサル防止とクエリパラメータバリデーションが実装。監査指摘事項への対応が完了し、不正アクセスリスクが排除される。

📂 ユースケース 3: 大規模データレイクでの Wrangler 活用

シナリオ: Cloud Storage に数千のファイルを格納するデータレイク環境で、Wrangler を使用したデータ準備時にブラウジング制限により目的のファイルを見つけるのに時間がかかっている。

効果: ブラウジング制限が 2,000 アイテムに拡大し、より多くのファイルやテーブルを一覧表示可能に。データソースへのアクセスが迅速化。
