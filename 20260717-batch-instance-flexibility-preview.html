Cloud Batch: Instance Flexibility

Cloud Batch Preview
2026-07-17

📋 概要

Cloud Batch に Instance Flexibility (インスタンスの柔軟性) 機能が Preview として導入されました。バッチジョブ実行時に複数のマシンタイプを指定し、オプションでランク付け (優先順位) を設定できるようになります。これにより、リソースの取得可能性 (obtainability) が大幅に向上します。

HPC、機械学習、データ処理などのバッチワークロードを実行しており、リソース確保の信頼性向上やコスト最適化を求めるエンジニア・データサイエンティストが対象です。

Before / After 比較

❌ Before (従来)

  • 単一マシンタイプしか指定できない
  • リソース枯渇時にジョブが失敗
  • Spot VM のプリエンプション率を考慮できない
  • 手動でマシンタイプを変更してジョブ再作成が必要

✅ After (Instance Flexibility)

  • 複数マシンタイプを指定して自動選択
  • ランク付けで自動フォールバック
  • プリエンプション率の低いマシンを自動選択
  • 運用介入なしでジョブ継続実行

🏗️ アーキテクチャ図

Cloud Batch がジョブ作成時に Instance Flexibility Policy を評価し、ランク順にリソース可用性を確認してマシンタイプを選択するフローです。

flowchart TD
    A[ユーザー: ジョブ作成] --> B[Cloud Batch API]
    B --> C{Instance Flexibility Policy}
    C --> D[Rank 1: 最優先マシンタイプ]
    C --> E[Rank 2: 次点マシンタイプ]
    C --> F[Rank 3: フォールバック]

    D --> G{リソース可用性チェック}
    E --> G
    F --> G

    G -->|利用可能| H[MIG 作成・VM プロビジョニング]
    G -->|Rank 1 不可| I[次の Rank へフォールバック]
    I --> G

    H --> J[タスク実行]
    J --> K[ジョブ完了]

⚡ 主要機能

📦 複数マシンタイプの指定

  • 最大 200 のマシンタイプを指定可能
  • x86 と Arm アーキテクチャの混在可
  • マシンタイプ ID で簡単指定

🏆 ランクによる優先順位設定

  • 数値が小さいほど高優先度
  • 同一ランク内は同等優先
  • 利用不可時に自動フォールバック

💰 Spot VM との統合最適化

  • 同一ランク内で最もプリエンプション率の低いマシンを自動選択
  • コスト削減と安定性を両立

🔒 予約 (Reservations) との連携

  • ANY_RESERVATION で未使用予約を優先利用
  • ランクと予約の両方を考慮した選択

🔧 技術仕様

項目 詳細
API フィールド instanceFlexibilityPolicy.instanceSelections
マシンタイプ上限 全 instanceSelections 合計で最大 200
ランク値 整数値 (小さいほど高優先)
対応 API バージョン v1alpha (Batch REST API)
マシンタイプ指定形式 マシンタイプ ID のみ (例: n1-standard-16)

⚙️ 設定方法

前提条件

💡 必要な準備:
  • Batch API が有効化されていること
  • IAM ロール: roles/batch.jobsEditor
  • IAM ロール: roles/iam.serviceAccountUser

ステップ 1: Instance Flexibility Policy を含むジョブ定義

JSON ジョブ定義 (job-config.json) 
{
  "taskGroups": [
    {
      "taskSpec": {
        "runnables": [
          {
            "script": {
              "text": "echo Hello from Batch with Instance Flexibility"
            }
          }
        ],
        "computeResource": {
          "cpuMilli": 4000,
          "memoryMib": 8192
        }
      },
      "taskCount": 10
    }
  ],
  "allocationPolicy": {
    "instances": [
      {
        "policy": {
          "instanceFlexibilityPolicy": {
            "instanceSelections": {
              "preferred": {
                "rank": 1,
                "machineTypes": ["c3-standard-4", "c3d-standard-4"]
              },
              "alternative": {
                "rank": 2,
                "machineTypes": ["n2-standard-4", "n2d-standard-4", "n1-standard-4"]
              }
            }
          }
        }
      }
    ]
  }
}

ステップ 2: gcloud CLI でジョブを作成

Bash ジョブの作成と確認 
# ジョブの作成
gcloud batch jobs submit my-flexible-job \
  --location=us-central1 \
  --config=job-config.json

# ジョブの状態確認
gcloud batch jobs describe my-flexible-job \
  --location=us-central1

✅ メリット

📈 ビジネス面

  • ジョブ完了率の向上: リソース枯渇によるジョブ失敗を大幅に削減
  • コスト最適化: コスト効率の高いマシンを優先しつつ代替で継続
  • 運用負荷の軽減: 手動対応が不要に

🔧 技術面

  • リソース取得可能性の向上: 在庫切れの影響を最小化
  • Spot VM の安定性向上: プリエンプション率低いマシンを自動選択
  • 柔軟なアーキテクチャ対応: x86 と Arm の混在可能

⚠️ デメリット・制約事項

⚠️ 制限事項:
  • Preview ステータスのため SLA 対象外
  • v1alpha API を使用する必要がある (GA 版 API では未提供の可能性)
  • マシンタイプの合計数は最大 200 に制限
  • 指定した全マシンタイプ上でアプリケーションの動作確認が必要
💡 考慮すべき点:
  • マシンタイプ間の vCPU/メモリ差異と computeResource 設定の互換性確認
  • ランクを跨いだ選択では Spot VM プリエンプション率最適化よりランク順が優先
  • SPECIFIC reservation 使用時は instanceSelections に予約マシンタイプを含めること

🎯 ユースケース

📊 ユースケース 1: 大規模データ処理パイプライン

シナリオ: 毎日数万タスクのデータ変換ジョブを実行。特定ゾーンでリソース枯渇が頻発しジョブが失敗。

効果: コンピュート最適化マシン (C3, C3D, C2) を優先しつつ、利用不可時に汎用マシン (N2, N2D, N4) にフォールバック。ジョブ完了率が大幅向上。

💰 ユースケース 2: Spot VM コスト最適化バッチ処理

シナリオ: 機械学習前処理パイプラインで Spot VM を活用したいが、プリエンプションによる中断が課題。

効果: 同一ランク内に多数のマシンタイプを配置し、最もプリエンプション率の低いマシンを自動選択。ジョブの安定性を最大化。

🔬 ユースケース 3: HPC ワークロードの信頼性向上

シナリオ: 科学計算シミュレーションで高性能コンピュート最適化マシンが必要だが、需要集中時にリソース確保不可。

効果: 複数世代の C ファミリー (C3, C3D, C2, C2D) を指定し、いずれかが利用可能であれば即実行。研究スケジュール遅延を防止。

💲 料金情報

✅ Instance Flexibility 機能自体には追加料金は発生しません。

実際にプロビジョニングされた VM のマシンタイプに基づき、通常の Compute Engine 料金が適用されます。

項目 料金体系
Instance Flexibility 機能利用料 無料
VM 利用料 選択されたマシンタイプの Compute Engine 標準料金
Spot VM 割引 オンデマンド価格から最大 91% 割引
Committed Use Discounts (CUD) 1 年: 最大 55% 割引 / 3 年: 最大 70% 割引
Sustained Use Discounts (SUD) 月 25% 以上の使用で最大 30% 自動割引

🔗 関連サービス・機能

⚙️ Compute Engine Instance Flexibility (MIG)

Batch の基盤となる MIG の Instance Flexibility 機能。Batch ジョブは内部的に MIG を使用してリソースを管理。

💰 Spot VM

Instance Flexibility と組み合わせることで、コスト削減と安定性を両立。

📅 Dynamic Workload Scheduler

大規模 GPU ワークロード向けのリソーススケジューリング機能。異なるアプローチでリソース確保を支援。

🔒 Compute Engine Reservations

確約済みリソースの予約。Instance Flexibility と連携して予約済みリソースの優先利用が可能。
