📌 概要

Cloud Workstations で、ブースト構成 (Boost Configuration) への自動フェイルオーバー機能が Preview として利用可能になりました。 ワークステーション起動時に Compute Engine 側でデフォルトのマシンタイプの容量が不足 (リソース枯渇) している場合、 Cloud Workstations が自動的にブースト構成のマシンタイプで VM をプロビジョニングします。

特定のマシンタイプの在庫が一時的に不足していても、別のマシンシリーズへ自動的に切り替わるため、 開発者は中断なく作業を開始できます。クラウドベースの開発環境を標準化している組織や、 キャパシティ不足による起動失敗リスクを低減したいプラットフォームチームに有用なアップデートです。

❌ Before (アップデート前)

  • デフォルトのマシンタイプがリソース枯渇で確保できない場合、起動が失敗していた
  • ユーザーが手動でブースト構成を指定して再起動するなどの対応が必要だった
  • リージョン・ゾーンの一時的なキャパシティ不足が、開発者の作業開始を直接妨げるリスクがあった

✅ After (アップデート後)

  • 容量不足時にブースト構成を使用した VM プロビジョニングへ自動的にフェイルオーバー
  • 複数のブースト構成を有効化でき、記載順に成功するまで順次評価
  • リソース枯渇に起因する起動失敗を自動回避し、手動での再試行が不要に

⚡ 主要機能

🔁 1. ブースト構成への自動フェイルオーバー

ワークステーション起動時に Compute Engine がデフォルトのマシンタイプをリソース枯渇によりプロビジョニングできない場合、自動フェイルオーバーが有効なブースト構成を使用して VM のプロビジョニングを自動的に試行します。リージョンまたはゾーンのリソース枯渇に起因する起動失敗を防止します。

📋 2. 複数ブースト構成の順次評価

複数のブースト構成で自動フェイルオーバーを有効にしている場合、ワークステーション構成に記載されている順序で評価され、プロビジョニングが成功するまで順次試行されます。優先度付きの多段フォールバックを構成できます。

⏱️ 3. アクティブセッション限定のフェイルオーバー

自動フェイルオーバーは、そのときのアクティブなワークステーションセッションにのみ適用されます。次回以降の起動では、まずデフォルトのマシンタイプでのプロビジョニングが試行されます。

💡 ブースト構成 (BoostConfig) とは: ワークステーションにオンデマンドで追加のコンピュートリソースを一時的に割り当てる機能です。より大きなマシンタイプ、GPU、大容量ブートディスク、ネストされた仮想化などを指定できます。今回のアップデートにより、この仕組みがキャパシティ不足時のフォールバック先としても活用できるようになりました。

🛠️ 設定方法

📋 前提条件

✓Cloud Workstations のワークステーションクラスタが作成済みであること
✓自動フェイルオーバー用のブースト構成には、デフォルトのマシンタイプとは異なるマシンシリーズのマシンタイプを指定すること

ステップ 1: 自動フェイルオーバーを有効にしたブースト構成付きのワークステーション構成を作成

Bash ワークステーション構成の作成 
gcloud beta workstations configs create WORKSTATION_CONFIG_ID \
  --cluster=WORKSTATION_CLUSTER_ID \
  --region=LOCATION \
  --project=PROJECT_ID \
  --machine-type=e2-standard-4 \
  --boost-config=id=BOOST_CONFIG_ID,machine-type=n2-standard-4,enable-automatic-failover=true

enable-automatic-failover=true を指定すると、デフォルトのマシンタイプ (この例では e2-standard-4) の容量不足時に、 ブースト構成のマシンタイプ (この例では n2-standard-4) へ自動的にフェイルオーバーします。 ブースト構成のマシンタイプは、デフォルトとは異なるマシンシリーズである必要があります。

ステップ 2: ワークステーションを起動

Bash ワークステーションの起動 
gcloud beta workstations start WORKSTATION_ID

ブースト構成を指定せずに起動した場合でも、デフォルトのマシンタイプが確保できないときは自動フェイルオーバーが発動します。 なお、従来どおり --boost=BOOST_CONFIG_ID を指定して明示的にブーストされた VM で起動することも可能です。

⚖️ メリットと制約事項

👍 メリット

💼 ビジネス面
  • 開発者の生産性維持: 一時的なキャパシティ不足があっても開発環境の起動が失敗しにくくなり、作業開始の遅延を防げる
  • 運用負荷の軽減: 起動失敗時の問い合わせ対応や手動での再試行が不要になり、プラットフォームチームの負荷を軽減
⚙️ 技術面
  • リソース枯渇への自動対処: 異なるマシンシリーズへのフォールバックで、特定シリーズの在庫不足の影響を回避
  • 柔軟なフォールバック戦略: 複数のブースト構成を定義順に評価する、優先度付きの多段フォールバックを構成可能

⚠️ 制限事項・考慮点

🚧 制限事項
  • Preview 段階の機能であり、GA 前の利用条件が適用される
  • フェイルオーバー用のブースト構成は、デフォルトと同じマシンシリーズを指定できない (例: デフォルトが E2 の場合、E2 系は不可)
  • アクティブなセッションにのみ適用され、次回以降の起動ではデフォルトのマシンタイプが優先される
🤔 考慮すべき点
  • フェイルオーバー先は異なるマシンシリーズのため、性能特性や時間あたりのコンピュート料金が変わる可能性がある
  • フェイルオーバー先でも容量不足の場合に備え、複数のブースト構成と評価順序を設計しておくことが望ましい

🎯 ユースケース

💡 ユースケース 1: キャパシティ不足が発生しやすいリージョンでの開発環境の安定運用

シナリオ: 特定リージョンで E2 シリーズのマシンタイプを標準とした開発環境を提供しているが、時間帯によってリソース枯渇による起動失敗が発生することがある。

Bash 実装例 (asia-northeast1) 
gcloud beta workstations configs create dev-config \
  --cluster=dev-cluster \
  --region=asia-northeast1 \
  --machine-type=e2-standard-4 \
  --boost-config=id=failover-n2,machine-type=n2-standard-4,enable-automatic-failover=true

効果: E2 シリーズの容量不足時に N2 シリーズへ自動的にフェイルオーバーし、開発者は起動失敗を意識することなく作業を開始できる。

💡 ユースケース 2: 多段フォールバックによる起動成功率の最大化

シナリオ: 開発環境の起動成功率を最大化するため、複数のマシンシリーズをフォールバック先として用意したい。

🔗 関連サービス・機能

⚙️ Compute Engine

ワークステーション VM の基盤。本機能は Compute Engine のマシンタイプ別の容量 (リソース枯渇) を起点にフェイルオーバーを行います。

🚀 ブースト構成 (Boost Configuration)

ワークステーションに大きなマシンタイプや GPU などを一時的に割り当てる既存機能。今回のアップデートでフォールバック先としての役割が追加されました。

📝 まとめ

Cloud Workstations のブースト構成への自動フェイルオーバーにより、Compute Engine のリソース枯渇に起因するワークステーションの起動失敗を自動的に回避できるようになりました。 クラウド開発環境の可用性を高めたい組織は、デフォルトとは異なるマシンシリーズを指定したブースト構成に enable-automatic-failover=true を設定し、 Preview 段階で動作を検証することを推奨します。
