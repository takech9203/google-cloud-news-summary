📋 概要

Google SecOps (Chronicle) の Publisher Agent Version 2.7.0 が全リージョンで利用可能になりました。本バージョンでは Remote Agent に対する 2 つの重要な機能強化が含まれています。

MSSP (Managed Security Service Provider) やエンタープライズ SOC チームにとって、リモート環境でのセキュリティオペレーションの信頼性と柔軟性を大幅に向上させるリリースです。

🔄 Before / After 比較

❌ Before (v2.6.x 以前)

  • Publisher Agent が単一障害点 (SPOF) となり、停止時にリモート通信が途絶
  • リモートエージェント上でファイルのアップロード/ダウンロードが不可
  • GCOM 移行済みエージェントでファイル操作の自動化手段が限定的

✅ After (v2.7.0)

  • セカンダリエージェントが 30 秒以内で自動テイクオーバー
  • プレイブック/SDK でファイルのアップロード/ダウンロードが可能
  • エンドツーエンドの自動化ワークフローにファイル操作を統合

⚡ 主要機能

🔄 高可用性 (High Availability) サポート

→Publisher Agent にアプリケーションレベルの高可用性サポートを追加
→プライマリ障害時、セカンダリが 30 秒 のダウンタイム後に自動テイクオーバー
→タスク実行中にプライマリが失敗した場合、その特定タスクは失敗となるが、保留中の他のすべてのタスクは即座にセカンダリに転送
→プライマリ 1 つに対してセカンダリ 1 つを構成可能

📁 ファイル転送サポート

→GCOM インフラストラクチャに移行済みエージェントでファイルのアップロード/ダウンロードが可能
→プレイブックおよび SDK を通じてファイル操作を実行可能
→インシデント対応時にリモート環境からのエビデンス収集やファイル配布を自動化

🔧 設定方法

💡 前提条件: Publisher Agent v2.7.0 以上がインストール済み、Google Cloud サービスアカウントが構成済み (GCOM 移行済み)、コネクタが高可用性対応バージョンに再デプロイ済みであること。

高可用性の構成

SOAR Settings > Advanced > Remote Agents に移動し、プライマリエージェントの「View more」から「Add secondary agent」をクリック。セカンダリエージェントのセットアップ手順に従いインストール (手動または Docker/Podman)。

エージェントのアップデート

プライマリエージェントを最新バージョンにアップデート。コネクタが古いバージョンの場合は再デプロイを実施。Remote Agents ページの「High Availability」カラムでステータスを確認。

ファイル転送の利用 (GCOM 移行済みエージェント)

エージェントが GCOM に移行済みであることを確認し、プレイブックまたは SDK でファイルアップロード/ダウンロードアクションを構成。リモート実行で統合を有効化。

⚠️ 制約事項・注意点

制限事項:
✗ファイル転送機能は GCOM インフラストラクチャに移行済みのエージェントのみで利用可能
✗高可用性構成ではプライマリ 1 つにつきセカンダリ 1 つまでに限定
✗タスク実行中にプライマリが障害を起こした場合、そのタスクは手動での再実行が必要

考慮すべき点

→GCOM 移行未完了のエージェントではファイル転送機能を利用できないため、移行計画の策定が必要
→高可用性構成時はコネクタの再デプロイが必要な場合がある
→セカンダリエージェント用の追加サーバーリソース (CPU 4 コア / RAM 8 GB 以上) が必要

💡 ユースケース

🦠 ユースケース 1: マルウェアインシデント対応の自動化

シナリオ: SOC アナリストがアラートを受信し、リモート環境のエンドポイントから疑わしいファイルを自動収集する必要がある場合。

効果: プレイブックでファイルダウンロードアクションを使用し、リモートエージェント経由で自動的にマルウェアサンプルを収集。VirusTotal 等の脅威インテリジェンスサービスとの連携も可能になり、対応時間を大幅に短縮。

🏢 ユースケース 2: MSSP マルチテナント環境での高可用性運用

シナリオ: MSSP が複数の顧客環境に Remote Agent を展開し、24/7 のセキュリティモニタリングを提供している場合。

効果: 各顧客環境のプライマリエージェントにセカンダリを追加することで、エージェント障害時も 30 秒以内に自動復旧。SLA 違反のリスクを最小化し、顧客信頼性を向上。

🔍 ユースケース 3: フォレンジックエビデンスの遠隔収集

シナリオ: セキュリティインシデント発生時に、地理的に離れた拠点からログファイルやメモリダンプを収集する必要がある場合。

効果: ファイル転送機能とプレイブックを組み合わせることで、物理的なアクセスなしにエビデンスを自動収集。対応の迅速化とコスト削減を実現。
