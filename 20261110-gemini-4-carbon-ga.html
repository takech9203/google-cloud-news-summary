🚀 Gemini 4 Carbon / Carbon for cyber が一般提供 (GA) に

Google 最上位の推論モデルが本番エージェントワークロードで利用可能に
📅 リリース日: 2026-11-10

📝 概要

Gemini Enterprise Agent Platform で、Google の最上位推論モデル Gemini 4 Carbon (gemini-4-carbon) と、 防御的サイバーセキュリティ向けバリアント Gemini 4 Carbon for cyber (gemini-4-carbon-cyber-permissive) が 一般提供 (GA) になりました。

Carbon はコーディング・金融・法務・サイバーセキュリティ・科学といった複雑な実世界タスク向けのフロンティアモデルで、 難しい問題には思考トークン (thinking tokens) を多く費やして仮説検証やエッジケース確認を行ってから回答を生成します。

😣 Before (アップデート前の課題)

  • GA 前のため、SLA を前提とした本番ワークロードへの最上位推論モデル採用が困難
  • 同期レスポンスの出力が 64K トークン程度で頭打ちになり、長大なコード生成やレポートの一括生成には分割・独自の継続処理が必要
  • 防御的サイバーセキュリティ用途では汎用モデルの安全性フィルタが過剰に働くことがあり、専用のモデル提供形態がなかった

😊 After (アップデート後の改善)

  • gemini-4-carbon が GA となり、Provisioned Throughput 付きで本番エージェントワークロードに利用可能に
  • 統合 1M ウィンドウ + continuation_token で最大 1M トークン規模の長い出力を一括生成
  • 思考レベル (LOW / MEDIUM / HIGH) で品質・レイテンシ・コストをワークロードごとに調整
  • durable caching 対応の暗黙的キャッシュでコストとレイテンシを自動削減
  • Microsoft Office / OpenDocument ファイルを直接入力可能に
  • cyber 専用バリアントが Fairwind Program の allowlist 経由で利用可能に

エンタープライズアプリケーションはプラットフォームのエンドポイント経由で Gemini 4 Carbon を呼び出し、 暗黙的キャッシュと Provisioned Throughput を活用して長時間のエージェントワークフローを実行します。 サイバーセキュリティ向けバリアントの利用には Fairwind Program の allowlist 承認が必要です。

⭐ 主要機能

1️⃣ 統合 1M トークンウィンドウとロングデコード

→入力・思考・出力トークンが 1 つの 1,048,576 トークンウィンドウを共有
→continuation_token で最大 1,048,576 トークン (入力分を除く) までの長い出力を生成
→長大なコードベース生成、詳細な技術文書、数学的証明なども分割なしで一括生成

2️⃣ 設定可能な思考レベル (Thinking Levels)

→LOW / MEDIUM / HIGH の 3 段階で推論の深さを制御
→デフォルトは MEDIUM。複雑なコードやエージェントユースケースを含むほとんどのタスクに推奨
→HIGH は高難度の数学・科学・コーディング向けで、ロングデコードとの組み合わせに最適

3️⃣ 暗黙的コンテキストキャッシュ (durable caching 対応)

→暗黙的キャッシュがデフォルトで有効。キャッシュヒット時にコストとレイテンシを削減
→durable caching によりキャッシュの持続性を強化
→Provisioned Throughput でもキャッシュヒット時にバーンダウンレートの割引が適用

4️⃣ Microsoft Office / OpenDocument ファイル入力

→Word / Excel / PowerPoint と OpenDocument 形式のファイルを直接入力可能
→PDF 変換などの前処理なしに業務ドキュメントをマルチモーダル入力として処理

5️⃣ Provisioned Throughput サポート

→固定料金でスループットを予約し、オンデマンドリクエストより優先的に処理
→本番エージェントワークロードで安定したレイテンシとスループットを確保

6️⃣ Gemini 4 Carbon for cyber (gemini-4-carbon-cyber-permissive)

→脆弱性発見、リバースエンジニアリング、パッチ生成などの防御的サイバーセキュリティ向けバリアント
→Fairwind Program の allowlist による申請・承認制で提供

ステップ 1: モデル ID を指定してリクエストを送信

Bash curl での呼び出し例 
curl -X POST \
  -H "Authorization: Bearer $(gcloud auth print-access-token)" \
  -H "Content-Type: application/json" \
  "https://aiplatform.googleapis.com/v1/projects/PROJECT_ID/locations/global/publishers/google/models/gemini-4-carbon:generateContent" \
  -d '{

      "role": "user",

    }],
    "generationConfig": {
      "thinkingConfig": {"thinkingLevel": "MEDIUM"}
    }
  }'
💡 移行は簡単: 既存の Gemini 4 Argon からの移行は、モデル ID を gemini-4-carbon に変更するだけでリクエストスキーマの変更は不要です。

ステップ 2: ワークロードに合わせて思考レベルを調整

3 つの思考レベル (LOW / MEDIUM / HIGH) すべてで評価を実行し、品質基準を満たす最も低いレベルを選択します。 Carbon は従来モデルより思考に多くのトークンを使うため、maxOutputTokens を明示設定している既存アプリでは 32,768 以上への引き上げが推奨されます。

ステップ 3: (必要に応じて) Provisioned Throughput を購入

本番ワークロードで安定したスループットが必要な場合は、プロジェクト・リージョン・モデル・バージョンの組み合わせに対して Provisioned Throughput を購入します。

⚖️ メリットと制約事項

💼 ビジネス面のメリット

✓本番採用の判断が容易に: GA 化により SLA の対象となり、本番エージェントワークロードに安心して採用可能
✓幅広い業務ドメイン対応: コーディングに加え金融・法務・サイバーセキュリティ・科学の複雑なタスクを単一モデルでカバー
✓コスト最適化の選択肢: 思考レベル調整と暗黙的キャッシュで品質要件に応じたコストコントロール

🔧 技術面のメリット

✓深い検証ループ: ビルドと検証を繰り返すワークフローで根本原因特定とテスト検証をモデル自身が実行
✓長大な出力の一括生成: クライアント側の分割・結合ロジックなしに最大 1M トークンの出力を取得
✓ドキュメント処理の簡素化: Office / OpenDocument 直接入力で変換前処理パイプラインを削減

🚧 制限事項

✗cyber バリアントは allowlist 制で、Fairwind Program への申請と承認が必要
✗明示的コンテキストキャッシュ (cachedContents / caches.create) は非サポート (暗黙的キャッシュへの移行が必要)
✗temperature / top_p / top_k などのサンプリングパラメータは指定しても無視される

🤔 考慮すべき点

⚠️ 注意:
  • Carbon は Argon より 1 ターンあたりの思考トークン消費とレイテンシが大きい。速度重視のタスクでは Argon の継続利用を推奨
  • 思考トークンも出力トークンとして課金される。HIGH の多用はコストに直結するため、評価で必要最小限のレベルを選定
  • 難しいプロンプトでは応答に数分かかる場合がある。HTTP クライアントのタイムアウトを十分長く設定 (またはバックグラウンド実行を使用)

🎯 ユースケース

🐛 ユースケース 1: 大規模リポジトリの根本原因デバッグと自動修正

複雑なマイクロサービス群で発生した障害について、エージェントがログとコードベースを解析し、 根本原因を特定してテストで検証済みの修正パッチを生成する。

Python 思考レベル HIGH での実装例 
response = client.models.generate_content(
    model="gemini-4-carbon",
    contents=[repo_context, failure_logs, "根本原因を特定し、テストに合格する修正を提案してください。"],
    config=GenerateContentConfig(
        thinking_config=ThinkingConfig(thinking_level="HIGH"),
    ),
)
✨ 効果: 深い検証ループにより、仮説の探索・検証・エッジケース確認を経た精度の高い修正案が得られ、手動デバッグの工数を大幅に削減。

📑 ユースケース 2: 金融・法務ドキュメントのマルチモーダル分析

契約書 (Word)、財務モデル (Excel)、提案資料 (PowerPoint) を前処理なしで直接入力し、根拠の明示を伴う分析レポートを生成する。

✨ 効果: Office / OpenDocument ファイルの直接入力と、ソースへの強いグラウンディング (根拠のない主張の削減) により、密度の高い業務ドキュメントに対する正確な知識ワークを自動化。

🛡️ ユースケース 3: 防御的サイバーセキュリティ運用 (cyber バリアント)

セキュリティチームが gemini-4-carbon-cyber-permissive を用いて、脆弱性発見、エクスプロイト検証、 根本原因のパッチ生成といった防御的ワークフローを実行する。

✨ 効果: 汎用モデルでは扱いが難しいセキュリティ専門タスクを、allowlist で統制された環境下で安全に自動化。

🔗 関連サービス・機能

⚡ Gemini 4 Argon (gemini-4-argon)

同じ 1M 統合コンテキストウィンドウとトークン単価を持つ効率重視のフロンティアモデル。Carbon より高速・低トークン消費で、インタラクティブなコーディングや日常タスク向け。

📈 Provisioned Throughput

プロジェクト・リージョン・モデル単位でスループットを予約し、オンデマンドより優先処理する消費オプション。キャッシュヒット時はバーンダウンレートが割引される。

⚡ コンテキストキャッシュ

暗黙的キャッシュでプロンプトの共通プレフィックスを自動キャッシュし、コストとレイテンシを削減。

🤖 CodeMender

Gemini Enterprise Agent Platform のセキュリティエージェント。cyber 系モデルと組み合わせた脆弱性修正に利用される。

📊 Cloud Monitoring

aiplatform.googleapis.com/PublisherModel リソースのメトリクスで Provisioned Throughput の使用状況 (dedicated / spillover / shared) を監視可能。

💡 まとめ

Google の最上位推論モデル Gemini 4 Carbon が GA となり、1M トークンの統合ウィンドウ、ロングデコード、 思考レベル制御、Provisioned Throughput を備えた本番グレードのエージェント基盤が整いました。

  • まず MEDIUM 思考レベルで既存ワークロードを評価する
  • Argon との使い分けを設計する (速度重視は Argon、推論深度重視は Carbon)
  • cyber バリアントの利用には Fairwind Program への早めの申請が必要
