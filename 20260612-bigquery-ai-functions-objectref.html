📊 BigQuery: AI 関数が ObjectRef を直接入力可能に

BigQuery GA AI Functions
2026-06-12

🎯 概要

BigQuery の AI 関数 (AI.GENERATE、AI.CLASSIFY、AI.IF、AI.SCORE など) が、ObjectRef 値を直接入力として受け付けるようになりました。これまで必要だった OBJ.GET_ACCESS_URL 関数による中間変換ステップが不要になり、マルチモーダルデータ分析のクエリが大幅に簡素化されます。

🤖 ObjectRef とは: Cloud Storage オブジェクトへの参照情報 (URI、バージョン、authorizer、メタデータ) を格納する STRUCT 型の値。BigQuery テーブルに非構造化データの参照を構造化データと共に保存する仕組みです。

🔄 Before / After 比較

❌ Before (以前の方式)

  • OBJ.GET_ACCESS_URL で署名付き URL に変換が必要
  • 署名付き URL は最大 6 時間で有効期限切れ
  • ネストした関数呼び出しでコード冗長化
  • URL 生成処理がクエリ実行オーバーヘッドに

✅ After (新しい方式)

  • ObjectRef 値を AI 関数に直接渡せる
  • 署名付き URL の管理が完全に不要
  • クエリの記述がシンプルで可読性向上
  • 中間ステップ省略で実行効率改善

⚡ 主要機能

🔗 ObjectRef 直接入力

AI 関数の STRUCT プロンプト内で ObjectRef 値または ARRAY<ObjectRef> を直接指定可能。BigQuery が内部的にオブジェクトアクセスを処理。

🔐 アクセス制御対応

Direct Access (ユーザー認証情報) と Delegated Access (Cloud Resource Connection 経由) の両方に対応。

🤖 全 AI 関数対応

AI.GENERATE、AI.CLASSIFY、AI.IF、AI.SCORE、AI.EMBED など全ての AI 関数で利用可能。

🔄 後方互換性

従来の OBJ.GET_ACCESS_URL を使用したクエリも引き続き動作。段階的な移行が可能。

💻 コードサンプル: 構文の比較

従来の構文と新しい構文を比較します。

SQL 
-- 以前の構文 (OBJ.GET_ACCESS_URL が必要)
SELECT AI.GENERATE(
  ("Describe this image:",
   OBJ.GET_ACCESS_URL(OBJ.MAKE_REF("gs://my-bucket/image.jpg", "us.connection1"), 'r')),
  connection_id => "us.connection2"
);
SQL 
-- 新しい構文 (ObjectRef を直接入力)
SELECT AI.GENERATE(
  ("Describe this image:",
   OBJ.MAKE_REF("gs://my-bucket/image.jpg", "us.connection1")),
  connection_id => "us.connection2"
);
SQL 
-- テーブルカラムの ObjectRef を直接使用
SELECT AI.GENERATE(
  ("Describe this image:", image_ref),
  connection_id => "us.connection2"
)
FROM my_dataset.products;

🎯 ユースケース

🛒 ユースケース 1: 商品画像の一括分類

シナリオ: EC サイトの商品テーブルに ObjectRef カラムとして保存されている商品画像を、カテゴリに自動分類

SQL 
SELECT
  product_id,
  product_name,
  AI.CLASSIFY(
    image_ref,
    ['Electronics', 'Clothing', 'Food', 'Furniture', 'Sports']
  ) AS category
FROM my_dataset.products;

→ 数千件の商品画像を簡潔なクエリで分類可能

📄 ユースケース 2: ドキュメント画像からの情報抽出

シナリオ: スキャンした請求書画像から構造化データ (金額、日付、取引先) を抽出

SQL 
SELECT
  invoice_id,
  AI.GENERATE(
    ("Extract the total amount, date, and vendor from this invoice:", invoice_image_ref),
    connection_id => "us.my_connection",
    output_schema => STRUCT()
  ) AS extracted_data
FROM my_dataset.invoices;

→ ドキュメント処理パイプラインの構築が簡素化

🛡️ ユースケース 3: マルチモーダルコンテンツのスコアリング

シナリオ: ユーザー投稿画像の品質やポリシー準拠度をスコアリングして、モデレーションに活用

SQL 
SELECT
  post_id,
  AI.SCORE(
    ("Rate how appropriate this image is for a family-friendly platform:", image_ref)
  ) AS appropriateness_score
FROM my_dataset.user_posts
ORDER BY appropriateness_score ASC
LIMIT 100;

→ コンテンツモデレーションの効率化と優先的レビューが可能

⚠️ 制限事項・注意点

制限事項:
  • ⚠1 つのプロジェクト・リージョンで使用できる Cloud Resource Connection は最大 20 個
  • ⚠ObjectRef 値から参照できるプロジェクトは、クエリ実行プロジェクト以外に最大 5 プロジェクト
  • ⚠動画オブジェクトは入力に最大 1 つまで
  • ⚠サポートされるファイル形式は Gemini API の mimeType パラメータに準拠
💡 考慮すべき点:
  • Direct Access の場合、クエリ実行プロジェクトと同じプロジェクトの Cloud Storage バケットのみアクセス可能
  • 従来の OBJ.GET_ACCESS_URL が有用なケース (外部システムへの署名付き URL 共有など) は引き続き存在
  • AI 関数の呼び出しごとに Gemini Enterprise Agent Platform の課金が発生する点は変更なし

📝 まとめ

今回の GA リリースにより、BigQuery でのマルチモーダル AI 分析が大幅に簡素化されます。Cloud Storage に保存された画像・動画・ドキュメントなどの非構造化データを、中間の URL 生成ステップなしに直接 AI 関数で処理できるようになりました。

移行方法: 既に ObjectRef カラムを持つテーブルを運用しているユーザーは、クエリから OBJ.GET_ACCESS_URL の呼び出しを削除するだけで、よりシンプルな構文に移行できます。
