📋 概要

GKE の全リリースチャネル (Rapid / Regular / Stable / Extended / No channel) でクラスタバージョンが更新された。 Rapid チャネルのデフォルトが Kubernetes 1.37 系 (1.37.1-gke.1552000) に引き上げられ、 Regular / Extended / No channel のデフォルトは 1.36.4-gke.1495002 に更新。 アルファクラスタ向けには 1.38.0-gke.2884000+preview が登場した。

セキュリティアップデート (2026-R44) として、累積的なセキュリティ修正を含む Container-Optimized OS イメージ (cos-121 / cos-125 / cos-133) を使用する新バージョンがリリース。 さらに、GKE Sandbox で Cloud Storage FUSE CSI ドライバを使用する Pod が Terminating のままスタックする不具合も修正された。 GKE クラスタを運用するすべてのプラットフォーム管理者・インフラエンジニアに影響する。

❌ Before (アップデート前の課題)

  • 直近の Container-Optimized OS セキュリティ修正が未適用
  • Rapid チャネルの新規クラスタのデフォルトは 1.36.4 系で、1.37 系は標準適用されず
  • Regular / Extended / No channel のデフォルトは旧パッチ (1.36.4-gke.1391002) のまま
  • GKE Sandbox + Cloud Storage FUSE CSI ドライバで Pod が Terminating 状態のままスタック

✅ After (アップデート後の改善)

  • Rapid のデフォルトが 1.37.1-gke.1552000 になり、新規クラスタに 1.37 系が標準適用
  • Regular / Extended / No channel のデフォルトが 1.36.4-gke.1495002 に更新
  • 各チャネルに 1.31〜1.37 系の新パッチ追加、自動アップグレードターゲットも更新
  • cos-121 / cos-125 / cos-133 の累積セキュリティ修正でノード OS の脆弱性リスクを低減
  • アルファ版 1.38.0+preview で次期マイナーバージョンの早期検証が可能に
  • Pod スタック問題は 1.37.1-gke.1552000 以降 + アノテーション追加で解消

GKE のリリースチャネルは、Rapid で導入されたバージョンが検証を経て Regular、Stable へと段階的に展開されるパイプラインとして機能する。 今回は Rapid チャネルのデフォルトが Kubernetes 1.37 系に引き上げられ、累積的なセキュリティ修正を含む新しい Container-Optimized OS イメージが各バージョンに組み込まれている。

⭐ 主要な変更点

1️⃣ Rapid チャネルのデフォルトが Kubernetes 1.37 系に更新

新規クラスタが 1.37.1-gke.1552000 で作成されるように。新パッチ 1.34.12-gke.1209000 / 1.35.8-gke.1975000 / 1.36.4-gke.2377000 / 1.37.1-gke.1697000 が追加され、1.36.4-gke.2202002 / 1.36.4-gke.2304000 は非推奨化。

2️⃣ アルファ版 1.38.0-gke.2884000+preview が利用可能に

Rapid チャネルのアルファクラスタで Kubernetes 1.38 系の早期検証が可能。旧アルファ版 1.38.0-gke.1002000+preview は提供終了。

3️⃣ Regular / Extended / No channel のデフォルトが 1.36.4-gke.1495002 に

新規クラスタに 1.36.4 系の修正済みパッチが標準適用。旧デフォルトの 1.36.4-gke.1391002 は Regular / Extended で提供終了。

4️⃣ Stable チャネルに 1.34.11 / 1.35.8 系の新パッチ追加

安定性重視の環境向けに 1.34.11-gke.1102000 / 1.35.8-gke.1439001 が利用可能に。1.34.9-gke.1655001 は非推奨化。

5️⃣ Container-Optimized OS のセキュリティ修正を累積適用

cos-121 (M121) / cos-125 (M125) / cos-133 (M133) のイメージを更新し、1.31.14 / 1.35.8 / 1.37.1 / 1.38.0 系の新バージョンにそれぞれ適用。

6️⃣ GKE Sandbox での Pod スタック問題を修正

Cloud Storage FUSE CSI ドライバ使用時に Pod が Terminating のままスタックする問題を 1.37.1-gke.1552000 以降で修正。dev.gvisor.fuse.abort-on-teardown: "true" アノテーションの追加が必要。

✅ 前提条件

  • クラスタに対する適切な IAM 権限 (container.admin ロールなど) を保持していること

⚖️ メリットと制約事項

💼 ビジネス面のメリット

✓セキュリティリスクの低減: 累積的なセキュリティ修正を含む COS イメージへの更新により、ノード OS の脆弱性露出時間を短縮
✓運用の安定性向上: GKE Sandbox + Cloud Storage FUSE CSI ドライバ環境の Pod スタック問題解消により、デプロイ・スケールイン時の運用トラブルを回避

🔧 技術面のメリット

✓1.37 系が Rapid チャネルの標準に: 新規クラスタで Kubernetes 1.37 の機能を標準利用でき、1.38 系アルファ版での早期検証も可能
✓複数チャネルでデフォルトバージョンを更新: Rapid (1.37.1-gke.1552000)、Regular / Extended / No channel (1.36.4-gke.1495002) の新規クラスタに修正済みパッチが標準適用
✓累積的なセキュリティ修正: COS イメージは前回リリース以降の修正をすべて含むため、途中のパッチをスキップしても最新のセキュリティ状態に到達可能

🚧 制限事項

✗ロールアウトは段階的なため、一部ゾーンでは新バージョンがまだ利用できない場合がある
✗コントロールプレーンのマイナーバージョンのスキップアップグレードは不可 (1 バージョンずつ順次アップグレード)
✗Rapid チャネルの最新バージョンは GKE SLA の対象外で、既知の回避策がない問題を含む可能性がある
✗アルファ版 1.38.0-gke.2884000+preview はアルファクラスタ専用で、本番ワークロードには使用不可
✗GKE Sandbox の不具合修正は、バージョンアップグレードに加えてアノテーションの明示的な追加が必要 (自動では適用されない)
⚠️ 考慮すべき点:
  • Rapid で 1.36.4-gke.2202002 / 1.36.4-gke.2304000 が非推奨化。対象クラスタは 90 日以内に後継パッチへ移行が必要
  • Stable で 1.34.9-gke.1655001 が非推奨化。1.34.11-gke.1102000 以降への移行計画を早期に策定すること
  • Extended では 1.31 / 1.32 / 1.33 系の複数の旧パッチが非推奨化。新パッチ (1.31.14-gke.2825000 / 1.32.13-gke.2567000 / 1.33.13-gke.1815000 以降) への移行が必要
  • Rapid の 1.35 系クラスタは 1.36.4-gke.2326000 への自動アップグレード対象。Kubernetes 1.36 の非推奨 API への対応状況を事前に確認すること
  • ノードのバージョンスキューポリシー (コントロールプレーンとノードの差は最大 2 マイナーバージョン) に注意

🎯 ユースケース

1️⃣ GKE Sandbox 環境での Pod スタック問題の解消

シナリオ: GKE Sandbox 上で Cloud Storage FUSE CSI ドライバを使用するワークロードを運用しており、Pod が Terminating のままスタックする事象が発生している。

Bashノードプールを修正済みバージョンへアップグレード
gcloud container clusters upgrade my-sandbox-cluster \
  --node-pool=sandbox-pool \
  --cluster-version=1.37.1-gke.1552000 \
  --location=asia-northeast1
YAMLDeployment にアノテーションを追加
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app
spec:
  template:
    metadata:
      annotations:
        dev.gvisor.fuse.abort-on-teardown: "true"

✨ 効果: Pod 終了時に FUSE 接続が適切に中断されるようになり、Terminating 状態でのスタックを回避できる。

2️⃣ セキュリティ修正の迅速な適用

シナリオ: セキュリティポリシーにより、ノード OS の脆弱性修正を速やかに適用する必要があるプロダクションクラスタを運用している。

BashCOS 更新済みバージョンへ手動アップグレード (Rapid の例)
gcloud container clusters upgrade my-prod-cluster \
  --node-pool=default-pool \
  --cluster-version=1.35.8-gke.1975000 \
  --location=asia-northeast1

✨ 効果: cos-125-19216-700-23 の累積セキュリティ修正が適用されたノードイメージに更新され、脆弱性の露出時間を最小化できる。

3️⃣ アルファクラスタでの Kubernetes 1.38 早期検証

シナリオ: 次期マイナーバージョン 1.38 の新機能と非推奨 API の影響を、本番環境への展開前に検証したい。

Bashアルファクラスタを 1.38 プレビュー版で作成
gcloud container clusters create test-138-alpha \
  --enable-kubernetes-alpha \
  --release-channel=rapid \
  --cluster-version=1.38.0-gke.2884000 \
  --location=us-central1

✨ 効果: 1.38 系が全クラスタに提供される前にワークロードの互換性を確認でき、将来のアップグレード計画を前倒しで策定できる。

📝 まとめ

GKE 2026-R44 アップデートにより、Rapid チャネルのデフォルトが Kubernetes 1.37 系 (1.37.1-gke.1552000) に、 Regular / Extended / No channel のデフォルトが 1.36.4-gke.1495002 に更新され、 各チャネルに 1.31〜1.37 系の新パッチとアルファクラスタ向けの 1.38.0-gke.2884000+preview が追加された。 あわせて累積的なセキュリティ修正を含む Container-Optimized OS イメージ (cos-121 / cos-125 / cos-133) が新バージョンに適用され、 GKE Sandbox で Cloud Storage FUSE CSI ドライバを使用する Pod が Terminating のままスタックする不具合も修正された。

💡 推奨アクション: クラスタ管理者は、非推奨化されたバージョンからの移行計画を早期に策定し、 GKE Sandbox 環境では 1.37.1-gke.1552000 以降へのアップグレードと dev.gvisor.fuse.abort-on-teardown アノテーションの追加を検討すること。
