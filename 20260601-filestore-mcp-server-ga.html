🗄️ Filestore: リモート MCP サーバー GA

Filestore GA MCP
2026-06-01

📋 概要

Google Cloud Filestore のリモート Model Context Protocol (MCP) サーバーが一般提供 (GA) となりました。LLM や AI アプリケーションから自然言語を使用して Filestore インスタンスの作成・管理が可能になります。

MCP は大規模言語モデルと AI アプリケーションが外部データソースやツールに接続するための標準化されたプロトコルです。Gemini CLI、ChatGPT、Claude などの AI アプリケーションから直接、高性能ファイルストレージのプロビジョニングと管理が実現します。

💡 ポイント: Filestore API を有効化すると MCP サーバーが自動的に利用可能になり、追加料金は発生しません。

🔄 Before / After

❌ Before

  • Console / gcloud CLI / REST API の直接操作が必要
  • AI エージェントからの管理にはカスタムインテグレーション開発が必要
  • 専用スクリプトや IaC ツールの知識が必須

✅ After

  • 自然言語でインスタンス作成・管理が可能
  • 標準 MCP プロトコルで AI アプリから直接操作
  • OAuth 2.0 + IAM による細粒度のアクセス制御
  • Model Armor によるセキュリティ保護 (オプション)

⚡ 主要機能

🌐 リモート MCP エンドポイント

グローバルエンドポイント https://file.googleapis.com/mcp で HTTP トランスポート + JSON-RPC 2.0 による標準化通信

🗂️ インスタンス管理

全インスタンスの一覧表示、特定インスタンスの詳細情報取得をサポート

📸 スナップショット管理

スナップショットの一覧・詳細取得・新規作成が可能。ポイントインタイムリカバリを実現

💾 バックアップ管理

バックアップの一覧・詳細取得・新規作成をサポート。データ保護を自動化

🔒 セキュリティ

OAuth 2.0 認証 + IAM 細粒度アクセス制御 + Model Armor + 集中化された監査ログ

🔐 認証・認可の設定

必要な IAM ロール

ロール 説明
roles/mcp.toolUser MCP ツールの呼び出し権限
roles/file.admin Filestore リソースへのフルアクセス

OAuth スコープ

スコープ URI 説明
https://www.googleapis.com/auth/cloud-filer Filestore リモート MCP サーバーへの認証

⚙️ 設定方法

前提条件

✓Google Cloud プロジェクトで Filestore API が有効化されていること
✓MCP サーバーが有効化されていること
✓適切な IAM ロール (roles/mcp.toolUser および roles/file.admin) が付与されていること

Step 1: MCP クライアントの設定

AI アプリケーションの MCP クライアント設定に以下を追加します。

JSON 
{
  "mcpServers": {
    "filestore": {
      "name": "Filestore MCP server",
      "url": "https://file.googleapis.com/mcp",
      "transport": "HTTP"
    }
  }
}

Step 2: ツール一覧の確認

Bash 
curl --location 'https://file.googleapis.com/mcp' \
  --header 'content-type: application/json' \
  --header 'accept: application/json, text/event-stream' \
  --data '{
    "method": "tools/list",
    "jsonrpc": "2.0",
    "id": 1
  }'

Step 3: 自然言語によるインスタンス管理

接続完了後、AI アプリケーションから自然言語でリクエストを送信できます。

例:

  • 「プロジェクト my-project の us-central1-a ゾーンに 1 TiB の Zonal インスタンスを作成してください」
  • 「全 Filestore インスタンスの状態とストレージティアを表形式で表示してください」
  • 「インスタンス my-instance のスナップショットを作成してください」

🎯 メリット

ビジネス面

📈 運用効率の向上

自然言語でインフラ管理。専門的な CLI/API 知識がなくてもストレージリソースを管理可能

🤖 AI ワークフロー統合

AI アプリケーションのワークフロー内で直接ストレージのプロビジョニングとデータ保護を実行

🚀 開発速度の加速

カスタムインテグレーション不要。標準プロトコルで即座に接続可能

技術面

📐 標準化プロトコル

MCP 標準に準拠し、全ての対応 AI アプリケーションから統一的にアクセス可能

🛡️ 細粒度セキュリティ

OAuth 2.0 + IAM で最小権限の原則に基づいたアクセス制御を実現

☁️ マネージドインフラ

Google Cloud 上で稼働。可用性やスケーラビリティを自前管理する必要なし

📝 監査ログ集中管理

MCP 経由の全操作が監査ログに記録され、コンプライアンス対応が容易

⚠️ 制限事項・注意点

制限事項:
  • スナップショットやバックアップの削除・復元・リストアは MCP 経由では実行不可 (意図しないデータ損失防止のため)
  • インスタンスの作成・削除など一部操作は MCP ツール未提供 (利用可能ツールは 8 種類に限定)
  • OAuth スコープとして https://www.googleapis.com/auth/cloud-filer が必要
💡 推奨事項:
  • AI エージェントには専用の ID を作成し、アクセスの制御と監視を実施
  • 過剰な API 呼び出しに注意 (全操作が監査ログに記録)
  • 本番環境では Model Armor によるセキュリティ保護の有効化を検討

💼 ユースケース

🧠 AI 開発プラットフォームからのストレージ自動プロビジョニング

機械学習パイプラインの一部として、トレーニングデータを格納するための高性能ファイルストレージを AI エージェントが自動的にプロビジョニング。インフラチームへの依頼や手動操作が不要になり、開発者が必要なタイミングでストレージを即座に確保可能。

🔄 定期的なデータ保護の自動化

AI エージェントが定期的に Filestore インスタンスの状態を確認し、重要なデータのスナップショットやバックアップを自動作成。人的介入なしにデータ保護ポリシーを遵守し、障害発生時の復旧ポイントを自動的に確保。

🌍 マルチクラウド AI ワークフローでのストレージ管理

異なる AI プラットフォーム (Claude、Gemini CLI など) から統一的に Filestore リソースを管理し、チーム全体でストレージインフラの状態を可視化。ツールに依存しない統一的なストレージ管理が可能。

📌 まとめ

Filestore リモート MCP サーバーの GA リリースにより、AI アプリケーションから標準化されたプロトコルを通じて高性能ファイルストレージを直接管理できるようになりました。これは Google Cloud が推進する「AI-ready インフラストラクチャ」戦略の一環であり、AI エージェントがインフラリソースを自律的に管理する時代の到来を象徴しています。

🤖 推奨アクション: Filestore を利用している組織は、既存の AI ワークフローへの MCP サーバー統合を検討し、インフラ管理の自動化と効率化を進めることを推奨します。
