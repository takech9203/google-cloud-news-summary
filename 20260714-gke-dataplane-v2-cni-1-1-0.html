GKE Dataplane V2 CNI v1.1.0 移行

Google Kubernetes Engine Breaking Change
2026-07-14
⚠️ 破壊的変更: GKE Dataplane V2 クラスタの CNI 設定ファイルが CNI バージョン 1.1.0 に更新されました。互換性のない下流 CNI プラグインを使用している場合、ノードが NotReady 状態になります。

📋 概要

GKE バージョン 1.35.1-gke.1516000 以降で、GKE Dataplane V2 クラスタの CNI 設定ファイルが CNI spec v1.1.0 に更新されました。これにより、すべての下流 CNI プラグインが CNI v1.1.0 と互換性を持つことが必須となります。

セルフマネージド Istio またはインクラスタ アンマネージド Cloud Service Mesh (CSM) を使用している場合、CSM CNI をバージョン 1.23 に手動アップグレードする必要があります。

🔄 Before / After 比較

❌ Before (v1.35.1-gke.1516000 未満)

  • CNI 設定ファイルは CNI v1.1.0 未満を使用
  • 下流 CNI プラグインは旧バージョンの CNI 仕様で動作
  • CSM CNI のバージョン互換性を意識する必要なし

✅ After (v1.35.1-gke.1516000 以降)

  • CNI 設定ファイルが CNI v1.1.0 を要求
  • 非互換の下流 CNI プラグインではノードが NodeNotReady に
  • CSM CNI 1.23 への手動アップグレードが必要

🔑 主要な変更点

📄
CNI 仕様バージョンの引き上げ

GKE Dataplane V2 クラスタの CNI 設定ファイルが CNI バージョン 1.1.0 を使用するように変更。対象は GKE バージョン 1.35.1-gke.1516000 以降。

🔗
下流 CNI プラグインの互換性要件

すべての下流 CNI プラグインが CNI バージョン 1.1.0 をサポートしている必要あり。非互換の場合はノードの初期化に失敗する。

☝️
Cloud Service Mesh CNI のアップグレード要件

インクラスタコントロールプレーンの CSM を利用している場合、CSM CNI をバージョン 1.23 にアップグレードする必要がある。CSM CNI 1.23 が CNI spec v1.1.0 に対応。

ロールアウト遅延時に影響の可能性 - Google 側のロールアウト完了を待つ、または一時的にダウングレード

✅ Dataplane V2 なし (レガシーデータプレーン)

影響なし - 対応不要

🛠️ 対応手順

💡 前提条件: GKE Dataplane V2 が有効で、セルフマネージド Istio またはインクラスタ アンマネージド CSM を使用し、GKE v1.35.1-gke.1516000 以降へのアップグレードを予定・実施済みのクラスタが対象です。

  1. 現在の GKE バージョンと CSM CNI バージョンの確認

    クラスタの GKE バージョンが対象範囲か確認し、CSM CNI のバージョンを特定します。

  2. CSM CNI を バージョン 1.23 にアップグレード

    GKE クラスタを 1.35.1-gke.1516000 以降にアップグレードする前に、CSM CNI のバージョンを 1.23 に更新することを推奨。

  3. 問題が発生した場合の緩和策

    ノードが NodeNotReady 状態の場合、GKE バージョンを対象バージョン未満にダウングレード、または CSM CNI を速やかに 1.23 にアップグレード。

Bash 
# クラスタの GKE バージョンを確認
gcloud container clusters describe CLUSTER_NAME \
  --location LOCATION \
  --format="value(currentMasterVersion)"

# CSM CNI DaemonSet のイメージバージョンを確認
kubectl get daemonset istio-cni-node -n kube-system \
  -o jsonpath='{.spec.template.spec.containers[0].image}'

# ノードの状態を確認
kubectl get nodes
kubectl describe node NODE_NAME | grep -A5 "Conditions"

⚠️ 制約事項・考慮点

❌ GKE v1.35.1-gke.1516000 以降へのアップグレードは、CSM CNI 1.23 への事前アップグレードなしには安全に行えない (該当構成の場合)
❌ Google マネージド Istio のロールアウト遅延により、一部クラスタで互換バージョン未適用の状態で影響を受ける可能性
⚠️ GKE リリースチャネル (Rapid, Regular, Stable) の自動アップグレードで予期せず影響を受ける可能性あり
⚠️ メンテナンスウィンドウの設定を確認し、事前に CSM CNI のアップグレードを完了させておくことが重要
⚠️ カスタム CNI プラグインを使用している場合、CNI spec v1.1.0 への対応状況を個別に確認する必要あり

🔗 関連サービス・機能

⚕️ Cloud Service Mesh (CSM)

Istio ベースのサービスメッシュ。CNI プラグインが Dataplane V2 と連携して動作する。

⚡ GKE Dataplane V2

Cilium ベースの eBPF データプレーン。anetd DaemonSet として各ノードで動作する。

🔌 Container Network Interface (CNI)

Kubernetes のネットワークプラグイン仕様。プラグインのチェイン呼び出しを定義する。

📝 まとめ

この変更は破壊的変更であり、GKE Dataplane V2 クラスタでセルフマネージド Istio またはアンマネージド Cloud Service Mesh を使用している場合、GKE 1.35.1-gke.1516000 以降へのアップグレード前に CSM CNI をバージョン 1.23 にアップグレードする必要があります。

対応を怠るとノードが NetworkPluginNotReady エラーで NotReady 状態となり、ワークロードのスケジューリングに影響が出ます。該当する構成を持つクラスタ管理者は、速やかに CSM CNI のバージョン確認とアップグレード計画の策定を行うことを強く推奨します。
