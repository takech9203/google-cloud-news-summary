🤖 Gemini Enterprise Agent Platform ✅ GA (一般提供)
📅 リリース日: 2026-11-20

⚡ Gemini 3.8 Flash の教師ありファインチューニングが GA

Supervised Fine-Tuning (SFT)・継続チューニング・チューニングチェックポイントが本番品質で利用可能に

📌 概要

Gemini Enterprise Agent Platform で、最新 Flash モデル gemini-3.8-flash に対する 教師ありファインチューニング (SFT)・ 継続チューニング・ チューニングチェックポイント が GA (一般提供) になりました。 ラベル付きデータセットで最新 Flash モデルをドメイン固有タスクに適応させる本番利用が可能です。

チューニングジョブは us・eu マルチリージョンエンドポイントで実行でき、 チューニング済みモデルの提供は us・eu に加えて global エンドポイントにも対応します。

❌ Before (アップデート前)

  • Gemini 3.8 Flash のチューニングは GA ではなく、ファインチューニングの本番利用には Gemini 3.5 Flash など旧世代モデルを選択する必要があった
  • 最新モデルの汎用性能とチューニングによるタスク特化を両立できなかった

✅ After (アップデート後)

  • Gemini 3.8 Flash を基盤に SFT を GA (本番品質) で実行可能
  • 継続チューニングでチューニング済みモデルやチェックポイントを基点に追加エポック・データで再チューニング可能
  • チェックポイントでエポックごとの進捗を保存し、最適なモデルを選択可能
  • チューニング済みモデルを global エンドポイントでも提供可能
🎯 対象ユーザー: 分類・要約・抽出型質問応答・チャットなど、明確に定義されたタスクでラベル付きデータを保有し、最新 Flash モデルの性能をタスク特化で引き出したい企業・開発者。

Cloud Storage 上の JSONL データセットを入力として us/eu マルチリージョンでチューニングジョブを実行し、 エポックごとのチェックポイントから最適なモデルを選択して us/eu/global エンドポイントで提供します。 チューニング済みモデルやチェックポイントは継続チューニングの基盤モデルとして再利用できます。

🚀 主要機能

1️⃣ 教師ありファインチューニング (SFT) の GA

→ラベル付きデータセットでモデルの重み (LoRA アダプタ) を調整し、予測とラベルの差を最小化
→分類、要約、抽出型質問応答、チャットなどのタスク性能改善に有効
→テキスト・画像・音声・動画・ドキュメントの各データタイプに対応

2️⃣ 継続チューニング (Continuous Tuning)

→チューニング済みモデルまたはチェックポイントをベースモデルとして、追加エポック・学習データでさらにチューニング (SFT → SFT)
→学習不足 (underfitting) の解消、新データによるモデル最新化、既存チューニング済みモデルのさらなるカスタマイズに活用
→Google Gen AI SDK でサポート (Agent Platform SDK for Python は非対応)

3️⃣ チューニングチェックポイント (Tuning Checkpoints)

→SFT ではエポックごとにチューニングの進捗を保存
→チェックポイント間の性能を比較し、最も性能の良いチェックポイントを選択可能
→Export last checkpoint only 設定で中間チェックポイントを無効化し、最終チェックポイントのみエクスポートすることも可能

4️⃣ マルチリージョン / グローバルエンドポイント対応

→チューニングジョブの実行: us・eu マルチリージョンエンドポイント
→チューニング済みモデルの提供: us・eu マルチリージョンおよび global エンドポイント

🧠 Thinking とチューニングの関係

🤖 ポイント: Gemini 3 以降のモデルでは、thinking level を MINIMAL に設定することで、チューニング済みタスクの性能向上とコスト削減が期待できます。SFT 中にモデルは学習データから学習し思考プロセスを省略するため、チューニング済みモデルは思考バジェットがほぼゼロでもタスクを効果的に実行できます。多段階推論能力そのものをチューニングしたい場合は、強化学習ファインチューニング (RLFT) の利用が案内されています。

🌍 リージョンとデータの扱い

→変換後のデータセットやチューニング済みモデルなどのユーザーデータは、チューニングジョブのリージョンに保存される
→チューニング中の計算は、アクセラレータ確保のため US または EU 内の他リージョンへ透過的にオフロードされることがある
→global リージョンは CMEK・Data Residency Zones (DRZ) に非対応。global モデルのチューニング済みアダプタは US リージョンに保存される (Cloud Storage に global バケットロケーションがないため)

ステップ 1: リージョンの指定 (Google Gen AI SDK)

Bash 環境変数でチューニングジョブのリージョンを指定 
export GOOGLE_CLOUD_PROJECT=PROJECT_ID
export GOOGLE_CLOUD_LOCATION=us   # または eu
export GOOGLE_GENAI_USE_ENTERPRISE=True

ステップ 2: チューニングジョブの作成 (REST / Gemini 3 以降)

Bash Gemini 3 以降のモデルのエンドポイント形式 
# Gemini 3 以降のモデルのエンドポイント形式
POST https://aiplatform.TUNING_JOB_REGION.rep.googleapis.com/v1/projects/PROJECT_ID/locations/TUNING_JOB_REGION/tuningJobs
⚠️ 注意: TUNING_JOB_REGION にジョブを実行するリージョン (us または eu) を指定します。Gemini 2.5 以前とはエンドポイントの URL 形式が異なる点に注意してください。

ステップ 3: 継続チューニング (チューニング済みモデルの再チューニング)

Python Google Gen AI SDK による継続チューニング 
from google import genai
from google.genai.types import (
    HttpOptions, TuningDataset, CreateTuningJobConfig,
)

client = genai.Client(http_options=HttpOptions(api_version="v1beta1"))

tuning_job = client.tunings.tune(
    base_model=tuned_model_name,  # チューニング済みモデルのリソース名
    training_dataset=TuningDataset(gcs_uri="gs://BUCKET/sft_train_data.jsonl"),
    config=CreateTuningJobConfig(
        tuned_model_display_name="continued tuning job",
        pre_tuned_model_checkpoint_id=checkpoint_id,  # 省略時はデフォルトチェックポイント
    ),
)

モデルリソース名は projects/{project}/locations/{location}/models/{modelId}@{version_id} 形式で指定します。 チェックポイント ID を省略した場合はデフォルトのチェックポイントが使用されます。

💡 メリット

💼 ビジネス面

✓最新 Flash モデルのタスク特化: 最も高性能な Flash モデルをドメイン固有タスクに適応させ、汎用モデルでは届かない精度を GA 品質で実現
✓チューニング資産の継続活用: 継続チューニングにより、過去のチューニング済みモデルを捨てずに新しいデータで更新でき、学習コストを抑制

🛠️ 技術面

✓チェックポイントによる最適モデル選択: エポックごとのチェックポイントを比較して過学習前の最適な時点を選べるため、試行錯誤が効率化
✓グローバル提供: チューニング済みモデルを global エンドポイントで提供でき、リージョンを跨ぐ推論構成に組み込みやすい
✓思考プロセスの省略による推論コスト削減: チューニング済みモデルは thinking level MINIMAL でもタスクを効果的に実行でき、推論コストを抑制

⚠️ デメリット・制約事項

🚧 制限事項

✗教師ありファインチューニングは Covered Service ではなく、SLA の SLO 対象外
✗チューニングジョブの実行は us・eu マルチリージョンエンドポイントのみ (単一リージョン指定は不可)
✗global リージョンは CMEK・DRZ に非対応。global モデルのチューニング済みアダプタは US リージョンに保存
✗Google Cloud コンソールからのジョブ作成は Gemini 2.5 以前のみ対応 (Gemini 3 以降は SDK / REST API を使用)
✗同時実行チューニングジョブ数にはグローバルクォータ (Global concurrent tuning jobs) が適用 (デフォルトで最低 1 ジョブ)

🤔 考慮すべき点

⚠️チューニング済みモデルへの推論リクエストで Controlled Generation (構造化出力の強制) を適用すると、モデル品質が低下する既知の問題がある。SFT 自体が構造化出力の生成をカスタマイズするため、チューニング済みモデルには Controlled Generation を適用しないことが推奨される
⚠️継続チューニングで CMEK を使用する場合、事前チューニング済みモデルのジョブと同じ CMEK を使用する必要がある
⚠️継続チューニングのベースにできるのは、2025 年 7 月 11 日以降にチューニングされた SFT ベースモデルのみ

🎯 ユースケース

📚 ユースケース 1: ドメイン特化タスクの精度向上

シナリオ: 金融・医療など、ベースモデルの学習データと大きく異なる専門用語・文書形式を扱う分類・要約・抽出型質問応答タスクで、プロンプトエンジニアリングだけでは目標精度に届かない。

効果: ラベル付きデータセットで Gemini 3.8 Flash をチューニングし、ドメイン固有のタスク性能を改善。チューニング済みモデルは思考プロセスを省略して動作するため、推論コストも抑制できる。

🔄 ユースケース 2: チューニング済みモデルの継続的な更新運用

シナリオ: 既にチューニング済みのモデルを本番運用しているが、新しいデータが継続的に蓄積されており、モデルを最新状態に保ちたい。

効果: 継続チューニングにより、ゼロから再チューニングせずにチューニング済みモデル (またはチェックポイント) へ追加データ・追加エポックを適用でき、モデルの鮮度維持と学習コスト削減を両立できる。

💰 料金

教師ありファインチューニングの料金は Gemini Enterprise Agent Platform の料金ページ (Model tuning) に記載されています。

→学習トークン数は「学習データセットのトークン数 × エポック数」で計算される
→チューニング後も、チューニング済みモデルへの推論 (予測リクエスト) 料金は別途発生。推論料金は Gemini の各 stable バージョンと同一

🔗 関連サービス・機能

🗄️ Cloud Storage

JSONL 形式の学習・検証データセットの保存先。チューニング済みアダプタの保存にも使用される。

📊 Gen AI evaluation service

チューニングジョブに評価設定 (evaluationConfig) を組み込み、チューニング完了後に自動評価を実行可能 (Preview、Gemini 2.5 系モデル対象)。

🧠 強化学習ファインチューニング (RLFT)

多段階推論能力をチューニングしたい場合の選択肢。SFT チェックポイントの上に RLFT を適用する継続チューニング (SFT → RLFT) も可能。

📦 Model Registry

チューニング済みモデルのバージョンとチェックポイントの管理・確認に使用。

📝 まとめ

最新の Gemini 3.8 Flash に対する教師ありファインチューニング・継続チューニング・チューニングチェックポイントが GA となり、最新 Flash モデルのタスク特化を本番品質で行えるようになりました。

既存のチューニング済みモデルを運用中のチームは、Gemini 3.8 Flash をベースにした再チューニングと、チェックポイント比較による最適モデル選択の導入を検討することを推奨します。

⚠️ 移行時の注意: Gemini 3 以降はジョブ作成がコンソール非対応 (SDK / REST のみ) で、エンドポイント URL 形式も変更されている点に注意してください。
