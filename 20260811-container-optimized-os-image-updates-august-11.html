2026 年 8 月 11 日リリースの新イメージ

cos-beta-133 / cos-129 LTS / cos-dev-138 / cos-121 LTS — セキュリティ修正とストレージ改善が中心
📅 リリース日: 2026-08-11

📌 概要

2026 年 8 月 11 日、Google Cloud はコンテナワークロード実行用 OS である Container-Optimized OS (COS) の新イメージを 4 つのチャネル (Beta / LTS x2 / Dev) で同時リリースしました。 今回の中心はセキュリティ修正 (CVE 対応) と ストレージ関連の安定性改善です。

google-guest-agent の CVE-2026-33186 の修正、nghttp2 1.69.0 へのアップグレード (CVE-2026-58055 対応)、Linux カーネルの 20 件を超える CVE 修正に加え、 cos-dkms 経由の Vast 4.5.8 NFS クライアントドライバサポートや bcache の I/O ストール防止パッチが含まれます。

🎯 対象ユーザー: Compute Engine や GKE のノード OS として COS を利用しているすべてのユーザー。 特に本番環境で cos-121-lts / cos-129-lts イメージファミリーを利用しているユーザー。

❌ Before (アップデート前の課題)

  • google-guest-agent に脆弱性 CVE-2026-33186 が存在
  • Linux カーネルに多数の未修正 CVE (CVE-2026-64227 ほか)
  • bcache の GC 実行中にスリープ間隔が長く I/O ストールが発生する可能性
  • nfttables-restore.service の影響で SSH 接続時間にリグレッション (遅延)
  • Vast の NFS クライアントドライバ 4.5.8 が COS で未サポート

✅ After (アップデート後の改善)

  • CVE-2026-33186 修正でゲストエージェント経由の攻撃リスクを低減
  • カーネル CVE (64227、64279、64286 ほか) と KCTF-8173f7e を修正
  • GC スリープ間隔短縮パッチで I/O ストールを防止
  • nfttables-restore.service マスクで SSH 接続時間が改善
  • cos-dkms 経由で Vast 4.5.8 NFS ドライバが利用可能に

🛠️ 設定方法

📋 前提条件

  • Compute Engine または GKE を使用するプロジェクト
  • イメージは cos-cloud プロジェクトから取得

ステップ 1: 新しいイメージの確認

Bash リリースされたイメージの確認 
gcloud compute images list --project=cos-cloud --no-standard-images | grep -E "19999-0-28|19506-299-116|20035-0-0|18867-528-58"

ステップ 2: 特定のイメージで VM を作成

Bash cos-129 LTS イメージで VM を作成 
gcloud compute instances create my-cos-vm \
  --image=cos-129-19506-299-116 \
  --image-project=cos-cloud \
  --zone=asia-northeast1-a
💡 推奨: 本番環境では、イメージファミリー API ではなく検証済みの特定イメージ名を指定することが推奨されています。

ステップ 3: GKE ノードプールの場合

GKE では COS イメージはノードの自動アップグレードにより GKE バージョンと連動して更新されます。 特定の COS ビルドを直接指定するのではなく、リリースチャネルの設定を確認してください。

⚖️ メリットと制約事項

👍 メリット

  • セキュリティリスクの低減: ゲストエージェントとカーネルの多数の CVE が修正され、コンプライアンス要件への対応が容易に
  • ダウンタイムの防止: bcache の I/O ストール防止により、ストレージ起因の性能劣化やサービス影響を回避
  • 運用性の改善: SSH 接続時間のリグレッションが解消され、デバッグや運用作業のレスポンスが改善
  • ストレージ選択肢の拡大: Vast NFS クライアントドライバサポートにより高性能 NFS ストレージと統合可能
  • 最新コンポーネント: node-problem-detector v0.8.25、Go 1.25.12 などが最新化

⚠️ 制限事項・考慮すべき点

  • Vast NFS クライアントドライバは cos-dkms 経由でのインストールが必要 (プリインストールされない)
  • Beta (COS 133) / Dev (COS 138) イメージは本番利用非推奨
  • 本番ロールアウト前に検証環境で新イメージの動作確認を行うことを推奨
  • LTS Refresh には中・低優先度の修正も含まれるため、ロールアウト時はリグレッションに注意
  • イメージファミリー API (getFromFamily) を本番インスタンス作成に使用すると、未検証イメージが自動適用されるリスク

💼 ユースケース

🛡️ ユースケース 1: 本番 GKE / GCE 環境のセキュリティパッチ適用

シナリオ: cos-121-lts または cos-129-lts を利用中の本番環境で、カーネルおよび google-guest-agent の CVE 修正を適用したい。

Bash 検証環境でテスト後、インスタンステンプレートを更新 
# 検証環境で新イメージをテスト後、インスタンステンプレートを更新
gcloud compute instance-templates create my-template-v2 \
  --image=cos-121-18867-528-58 \
  --image-project=cos-cloud \
  --machine-type=e2-standard-4

効果: CVE-2026-33186 やカーネル CVE 群が修正された状態で運用でき、脆弱性スキャンの指摘事項を解消できる。

💾 ユースケース 2: Vast NFS ストレージとの統合

シナリオ: AI/ML ワークロードなどで Vast Data の高性能 NFS ストレージを COS ノードからマウントしたい。

効果: cos-dkms 経由で Vast 4.5.8 NFS クライアントドライバをインストールでき、高スループットな NFS アクセスが COS 上で利用可能になる。

⚡ ユースケース 3: bcache 利用環境での I/O 安定化

シナリオ: ローカル SSD をキャッシュとして bcache を構成しているノードで、GC 実行中に I/O レイテンシのスパイクが発生していた。

効果: GC スリープ間隔短縮パッチにより I/O ストールが防止され、レイテンシが安定する。

💰 料金・利用可能リージョン

💵 料金: Container-Optimized OS 自体は無料で提供され、追加のライセンス費用はありません。 Compute Engine の VM インスタンスや GKE ノードの標準料金のみが適用されます。
  • Compute Engine 料金
  • GKE 料金
🌏 利用可能リージョン: COS イメージは cos-cloud プロジェクトからグローバルに提供され、 すべての Compute Engine リージョンで利用可能です。

🔗 関連サービス・機能

🖥️ Compute Engine

COS を VM のブートイメージとして使用。コンテナワークロードの直接実行に対応。

☸️ Google Kubernetes Engine (GKE)

COS はデフォルトのノードイメージ (cos_containerd)。ノード自動アップグレードで COS が更新される。

🧩 cos-dkms / cos-extensions

GPU ドライバや Vast NFS クライアントなどのサードパーティカーネルモジュールを COS にインストールする仕組み。

🩺 node-problem-detector

ノードの異常を検出して Kubernetes に報告するコンポーネント。今回 v0.8.25 に更新。

📝 まとめ

今回の COS リリースは、google-guest-agent とカーネルの多数の CVE 修正を含む セキュリティ中心のアップデートであり、LTS 系 (COS 121 / 129) を本番利用しているユーザーは 早期のロールアウトを検討すべきです。 bcache の I/O ストール防止や SSH 接続時間の改善など運用品質に直結する修正も含まれるため、 検証環境でのテストを経て計画的に適用することを推奨します。
