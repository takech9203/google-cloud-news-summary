🪣 Cloud Storage: HNS バケットでライフサイクル Delete が空フォルダを自動削除

Cloud Storage Hierarchical Namespace Breaking Change 2026/8/26 施行
2026-05-28

📋 概要

2026年8月26日以降、階層型名前空間 (HNS) が有効な Cloud Storage バケットにおいて、 Object Lifecycle Management の Delete アクションが、 ライフサイクルルールの全条件を満たす空フォルダを自動的に削除するようになります。

従来、HNS バケットではフォルダは明示的に DeleteFolder 操作を行わない限り削除されませんでした。 ライフサイクル管理の Delete アクションはオブジェクトのみを対象としており、空になったフォルダはそのまま残存していました。 今回の変更により、ライフサイクルルールの条件 (age, matchesPrefix, matchesSuffix 等) を満たす空フォルダも Delete アクションの対象となります。

⚠️ Breaking Change: この変更は既存の動作を変更します。HNS バケットを使用している全てのユーザーに影響する可能性があります。施行日 (2026年8月26日) までに既存のライフサイクルルールを精査してください。

🔄 Before / After 比較

❌ Before (現在の動作)

  • Delete アクションはオブジェクトのみを削除
  • 空フォルダは残存し続ける
  • 空フォルダの蓄積でリスト操作が劣化
  • 削除には別途スクリプトや手動操作が必要

✅ After (2026/8/26 以降)

  • Delete アクションがオブジェクト + 空フォルダを削除
  • 条件を満たす空フォルダは自動削除
  • リスト操作のパフォーマンスが維持
  • 追加スクリプトや手動運用が不要

⚡ 主要機能

🗑️ 空フォルダの自動ライフサイクル削除

  • ライフサイクルルールの全条件を満たす空フォルダが Delete アクションの対象に
  • 既存のライフサイクルルールがそのまま空フォルダにも適用
  • オブジェクトと同様に条件評価は非同期で実行

🔎 条件ベースの評価

  • age (作成からの経過日数) で評価
  • matchesPrefix / matchesSuffix でフィルタ
  • 全ての条件を満たした場合にのみ削除実行

🚀 パフォーマンス最適化

  • 空フォルダの蓄積を自動防止
  • リスト操作のパフォーマンスを維持
  • 大規模データパイプラインでの管理負荷を軽減

ライフサイクル条件の適用例

以下の例では、2026年8月26日以降、temp/ プレフィックスに一致し作成から30日以上経過した空フォルダも削除対象となります。

JSON 
{
  "lifecycle": {
    "rule": [
      {
        "action": {
          "type": "Delete"
        },
        "condition": {
          "age": 30,
          "matchesPrefix": ["temp/"]
        }
      }
    ]
  }
}

Step 1: 影響を受けるバケットの確認

Bash 
# HNS が有効なバケットを一覧表示
gcloud storage buckets list \
  --format="table(name,hierarchicalNamespace.enabled)" | grep True

Step 2: 現在のライフサイクルルールの確認

Bash 
# バケットのライフサイクル設定を確認
gcloud storage buckets describe gs://BUCKET_NAME \
  --format="json(lifecycle)"

Step 3: 必要に応じてルールの修正

Bash 
# ライフサイクル設定ファイルを更新して適用
gcloud storage buckets update gs://BUCKET_NAME \
  --lifecycle-file=lifecycle.json
💡 ヒント: 空フォルダを保持する必要がある場合は、matchesPrefix や matchesSuffix を活用して削除対象を限定するか、該当フォルダにダミーオブジェクト (プレースホルダーファイル) を配置することを検討してください。

⚠️ デメリット・制約事項

制限事項

✗ HNS バケットのみが対象 (フラットネームスペースのバケットは影響なし)
✗ フォルダ内にオブジェクトが1つでも存在する場合、そのフォルダは削除されない (空フォルダのみ対象)
✗ 非同期動作のため、条件を満たしてから実際の削除まで遅延が発生する可能性あり

考慮すべき点

⚠️ フォルダ構造に依存したシステムへの影響:
  • パーティション管理、メタデータ的なフォルダ利用がある場合は注意
  • マネージドフォルダが関連付けられている場合、フォルダ削除時に IAM ポリシーも削除される
  • 一度削除されたフォルダは復元できない (ロールバック不可)
  • 2026年8月26日までに開発環境での動作検証を強く推奨

💡 ユースケース

🚀 データパイプラインの一時フォルダ管理

シナリオ: ETL パイプラインが日次で staging/YYYY-MM-DD/ フォルダを作成し、処理完了後にオブジェクトを削除するが、空フォルダが残存し続ける

JSON 
{
  "lifecycle": {
    "rule": [
      {
        "action": { "type": "Delete" },
        "condition": {
          "age": 7,
          "matchesPrefix": ["staging/"]
        }
      }
    ]
  }
}

✨ 効果: 7日以上経過した staging/ 配下の空フォルダが自動クリーンアップされ、リスト操作のパフォーマンスが維持される

🤖 フォルダ構造を保持する必要があるケース (AI/ML ワークロード)

シナリオ: モデルのバージョン管理用にフォルダ構造 (models/v1/, models/v2/) を維持する必要があるが、古いモデルファイルは削除したい

🛠️ 対策: matchesPrefix を活用してモデルフォルダ以外にのみ Delete ルールを適用するか、各フォルダにプレースホルダーファイルを配置して空フォルダにならないよう対策する

本動作変更自体に追加料金は発生しません。ライフサイクル管理は Cloud Storage の標準機能として無料で利用できます。
