Priority PayGo の US/EU マルチリージョン対応 &
Agent Gateway の複数 Agent Registry サポート

リリース日: 2026-09-09
☁️ Gemini Enterprise Agent Platform Feature (提供中) Priority PayGo Agent Gateway データレジデンシー

📋 概要

2026 年 9 月 9 日、Gemini Enterprise Agent Platform に、エンタープライズにおけるエージェントワークロードの「リージョン戦略」を強化する 2 つのアップデートが発表されました。

1️⃣ Priority PayGo の US/EU マルチリージョンエンドポイント対応

Priority PayGo は、Provisioned Throughput のような事前コミットメントなしに、Standard PayGo よりも一貫したパフォーマンスを提供する従量課金の消費オプション。従来のグローバルエンドポイントに加えて、us / eu のマルチリージョンエンドポイントにもリクエストを送信できるようになり、機械学習処理を米国または EU の法域内に留める要件を持つワークロードでも利用可能になりました。

2️⃣ Agent Gateway の複数 Agent Registry インスタンス対応

エージェント・ツール・MCP サーバー間の通信をガバナンスする Agent Gateway に、最大 2 つの Agent Registry インスタンス (グローバル 1 + リージョン/マルチリージョン 1) を関連付け可能に。リージョンリソースの Agent Runtime エージェントと、グローバル/マルチリージョンリソースの Gemini Enterprise エージェントを単一ゲートウェイで統合ガバナンスできます。

❌ Before: アップデート前の課題

  • Priority PayGo はグローバルエンドポイントのみ。US / EU 法域内での ML 処理が必要なワークロードでは選択できなかった
  • Agent Gateway に関連付けられる Agent Registry は 1 インスタンスのみ。Agent Runtime (リージョン) と Gemini Enterprise (グローバル/マルチリージョン) のエージェントを単一ゲートウェイで扱いにくかった

✅ After: アップデート後の改善

  • us / eu マルチリージョンエンドポイント (aiplatform.us.rep.googleapis.com / aiplatform.eu.rep.googleapis.com) にも Priority PayGo リクエストを送信可能。法域内処理と一貫した性能を両立
  • グローバル 1 + リージョン/マルチリージョン 1 の計 2 つのレジストリを関連付け可能。異なるロケーション特性のエージェント群を統合ガバナンス
💡 関連情報: 同日には Agent Gateway の VPC Service Controls 対応も発表されています (別レポート参照)。組み合わせることで境界防御を強化できます。

1 つの Agent Gateway が最大 2 つの Agent Registry (グローバル + リージョン/マルチリージョン) を参照して宛先を解決し (URL が競合する場合はリージョン/マルチリージョンのエントリが優先)、Priority PayGo リクエストは従来のグローバルエンドポイントに加えて us / eu マルチリージョンエンドポイントにも送信できるようになりました。

⚡ 主要機能

🌍 Priority PayGo の US/EU マルチリージョンエンドポイント対応

  • Priority PayGo リクエストを global に加えて us および eu のマルチリージョンエンドポイントに送信可能
  • マルチリージョンエンドポイントは、サービスによる顧客データの機械学習処理を米国または EU という法域境界内に留めることを保証
  • REST の場合はホスト名を aiplatform.us.rep.googleapis.com または aiplatform.eu.rep.googleapis.com に、ロケーションを us / eu に置き換える
  • us-central1 などのシングルリージョンエンドポイントは Priority PayGo では引き続き非サポート

🔀 Priority PayGo の 2 つの利用モード (従来どおり)

  • スピルオーバーモード: Provisioned Throughput のクォータを優先消費し、超過分を Priority PayGo へ → X-Vertex-AI-LLM-Shared-Request-Type: priority ヘッダーを付与
  • Priority PayGo のみモード: X-Vertex-AI-LLM-Request-Type: shared と X-Vertex-AI-LLM-Shared-Request-Type: priority の両ヘッダーを付与
  • レスポンスの usageMetadata.trafficType に ON_DEMAND_PRIORITY が返り、Priority PayGo で処理されたことを確認できる

📚 Agent Gateway の複数 Agent Registry インスタンス対応

  • 1 つの Agent Gateway に最大 2 つの Agent Registry (グローバル 1 + リージョンまたはマルチリージョン 1) を関連付け可能
  • Agent Runtime のエージェントはリージョンリソース → デプロイリージョンに一致するリージョンレジストリに登録
  • Gemini Enterprise のエージェントはグローバル/マルチリージョンリソース → global、us、eu などのレジストリに登録
  • 宛先 URL の解決時、リージョン/マルチリージョンのエントリがグローバルより優先 (同一 URL のエントリが複数レジストリに存在する場合の競合解決)

⚙️ 設定方法

Priority PayGo をマルチリージョンエンドポイントで使用する (REST)

ホスト名とロケーションをマルチリージョンに置き換え、Priority PayGo のヘッダーを付与します。

Bash us マルチリージョンへの Priority PayGo リクエスト 
GOOGLE_CLOUD_PROJECT="PROJECT_ID"
GOOGLE_CLOUD_LOCATION="us"   # または "eu"
MODEL_ID="gemini-3.5-flash"
API_ENDPOINT="https://aiplatform.${GOOGLE_CLOUD_LOCATION}.rep.googleapis.com"

curl -X POST \
  -H "Authorization: Bearer $(gcloud auth print-access-token)" \
  -H "Content-Type: application/json; charset=utf-8" \
  -H "X-Vertex-AI-LLM-Shared-Request-Type: priority" \
  "${API_ENDPOINT}/v1/projects/${GOOGLE_CLOUD_PROJECT}/locations/${GOOGLE_CLOUD_LOCATION}/publishers/google/models/${MODEL_ID}:generateContent" \
  -d '{
    "contents": {
      "role": "user",
      "parts": { "text": "PROMPT_TEXT" }
    }
  }'

Python (Google Gen AI SDK) の場合

クライアント初期化時に location を us または eu に設定し、http_options で Priority PayGo ヘッダーを指定します。

Python Google Gen AI SDK での Priority PayGo 設定 
from google import genai
from google.genai.types import HttpOptions

client = genai.Client(
    vertexai=True,
    project="your_project_id",
    location="us",  # または "eu"
    http_options=HttpOptions(
        api_version="v1",
        headers={"X-Vertex-AI-LLM-Shared-Request-Type": "priority"},
    ),
)
💡 ヒント: Priority PayGo のみを使用する (Provisioned Throughput を消費しない) 場合は、X-Vertex-AI-LLM-Request-Type: shared ヘッダーを追加します。

⚖️ メリット・制約事項

✅ ビジネス面のメリット

✓データ処理所在地要件への対応: 米国または EU 内での ML 処理が求められる規制業種 (金融、公共、ヘルスケアなど) でも、事前コミットメント不要で一貫した性能の Priority PayGo を採用できる
✓ガバナンスの一元化: 異なるロケーション特性を持つエージェント資産を単一の Agent Gateway で統制でき、ガバナンス構成の重複を削減

✅ 技術面のメリット

✓柔軟な消費オプション選択: Provisioned Throughput のスピルオーバー先として、または単独の消費オプションとして、マルチリージョンでも利用可能
✓宛先解決の一貫性: リージョン/マルチリージョン優先という明確な競合解決ルールが定義されている

🚫 制限事項

✗Priority PayGo は us-central1 などのシングルリージョンエンドポイントを引き続き非サポート
✗マルチリージョンエンドポイントは Private Google Access 非サポート (プライベート接続には PSC エンドポイントが必要)
✗レジストリは最大 2 つで、構成は「グローバル 1 + リージョンまたはマルチリージョン 1」に限られる
✗クロスプロジェクトのエージェントは中央ガバナンスプロジェクトのレジストリに登録が必要

🤔 考慮すべき点

💰Priority PayGo は Standard PayGo より高いトークン単価。ワークロードの重要度と性能要件に応じた使い分けが必要
🔍Agent Gateway はホスト名を完全一致で照合。リージョン付きホスト名や mTLS ホスト名などのバリエーションもレジストリに登録しておく必要がある

🎯 ユースケース

💼 ユースケース 1: EU データ処理要件を持つ顧客向けバーチャルアシスタント

シナリオ: EU の顧客向けに提供するバーチャルアシスタントで、機械学習処理を EU 法域内に留める必要がある。トラフィックは変動が大きく、Provisioned Throughput の事前コミットメントは避けたい。

実装例: aiplatform.eu.rep.googleapis.com (locations/eu) に対して X-Vertex-AI-LLM-Shared-Request-Type: priority ヘッダー付きでリクエストを送信する。

効果: EU 法域内での処理を維持しながら、Standard PayGo より一貫したパフォーマンスをコミットメントなしで確保できる。

🏢 ユースケース 2: Gemini Enterprise と Agent Runtime の混在環境の統合ガバナンス

シナリオ: Gemini Enterprise 上のエージェント (グローバル/マルチリージョン) と、Agent Runtime にデプロイしたカスタムエージェント (リージョン) が混在しており、単一の Agent Gateway で通信を統制したい。

効果: グローバルレジストリとリージョン/マルチリージョンレジストリの 2 つを 1 つの Agent Gateway に関連付けることで、両方のエージェント群の宛先解決とアクセス制御を単一のゲートウェイで実現できる。

💰 料金・利用可能リージョン

💳 料金

Priority PayGo はトークン使用量ベースの従量課金で、Standard PayGo よりも高い単価が適用されます。具体的な料金は料金ページを参照してください。

🌏 利用可能リージョン

  • Priority PayGo: global エンドポイントおよび us / eu マルチリージョンエンドポイントでサポート。シングルリージョンエンドポイントは非サポート
  • Agent Registry: グローバル、マルチリージョン (us、eu など)、リージョンの各インスタンスが存在し、Agent Gateway にはグローバル 1 つ + リージョンまたはマルチリージョン 1 つを関連付け可能

🔗 関連サービス・機能

→Provisioned Throughput: 事前購入型のスループット保証オプション。Priority PayGo はそのクォータ超過分のスピルオーバー先としても利用できる
→Agent Registry: エージェント・MCP サーバー・エンドポイントを登録する管理リポジトリ。Agent Gateway の宛先解決とポリシー適用の基盤
→Identity-Aware Proxy (IAP) / IAM: Agent Gateway の宛先アクセス制御は iap.resources.egressViaIAP 権限を付与する IAM ポリシーで行う
→VPC Service Controls: 同日発表された Agent Gateway の VPC-SC 対応と組み合わせることで、境界防御を強化できる
→Private Service Connect: マルチリージョンエンドポイントへのプライベート接続に必要

📝 まとめ

今回の 2 つのアップデートにより、Priority PayGo は US/EU の法域内処理要件を持つワークロードでも利用可能になり、Agent Gateway はグローバルとリージョン/マルチリージョンの 2 つの Agent Registry を束ねた統合ガバナンスを実現できるようになりました。

データ所在地要件を持つ組織で Gemini モデルやエージェント基盤を運用している場合は、マルチリージョンエンドポイントへの Priority PayGo リクエストの切り替えと、Agent Gateway のレジストリ構成の見直しを検討することを推奨します。
