🔒 VPC Service Controls: Agent Identity & SPIFFE ID サポート

VPC Service Controls GA Security
2026-06-29

📋 概要

VPC Service Controls の Ingress/Egress ルールにおいて、Agent Identity および SPIFFE 形式のサードパーティ Workforce/Workload Identity のサポートが一般提供 (GA) となりました。

AI エージェントや外部 IdP のワークロードに対してもきめ細かいアクセス制御が可能になり、エンタープライズにおけるゼロトラストセキュリティが強化されます。

💡 ポイント: 2026年3月16日に Preview として提供開始、約3か月半の Preview 期間を経て GA に昇格。

🔄 Before / After 比較

❌ Before (従来)

  • AI エージェントは共有サービスアカウントでアクセス
  • SPIFFE 形式で外部 ID を指定不可
  • ANY_IDENTITY や ANY_SERVICE_ACCOUNT の広範な許可が必要
  • 最小権限の原則に反する運用

✅ After (新機能)

  • Agent Identity を principal:// 形式で個別指定
  • SPIFFE 形式で Workforce/Workload ID を指定可能
  • principalSet:// でグループ/属性ベースの一括制御
  • 最小権限の原則を徹底

VPC Service Controls のサービス境界に対して、Agent Identity および SPIFFE 形式の ID を Ingress/Egress ルールの identities フィールドに指定してアクセスを制御します。

⚡ 主要機能

🤖 Agent Identity のサポート

個別エージェント: principal://TRUST_DOMAIN/AGENT_UNIQUE_IDENTIFIER

属性ベース一括指定: principalSet://TRUST_DOMAIN/attribute.ATTR/VALUE

全エージェント指定: principalSet://TRUST_DOMAIN/*

Vertex AI Agent Engine、Gemini Enterprise などで対応

👤 SPIFFE Workforce Identity サポート

個別 ID: principal://POOL_ID.global.workforce.id.goog/SUBJECT

属性ベース: principalSet://POOL_ID.global.workforce.id.goog/attribute.ATTR/VALUE

全 ID: principalSet://POOL_ID.global.workforce.id.goog/*

全 ID: principalSet://POOL_ID.global.ORG_ID.workload.id.goog/*

🔧 設定方法

前提条件

✓VPC Service Controls のサービス境界が構成済み
✓Agent Identity: Vertex AI Agent Engine 等でエージェントがデプロイ済み
✓SPIFFE Workforce ID: Workforce Identity Pool が構成済み
✓SPIFFE Workload ID: Workload Identity Pool が構成済み

Step 1: Ingress ルールに Agent Identity を追加

YAML 
- ingressFrom:
    identities:
      - principal://agents.global.org-123456789012.system.id.goog/resources/aiplatform/projects/9876543210/locations/us-central1/reasoningEngines/my-agent
    sources:
      - accessLevel: "*"
  ingressTo:
    operations:
      - serviceName: bigquery.googleapis.com
        methodSelectors:
          - method: "*"
    resources:
      - projects/111222333

Step 2: Egress ルールに SPIFFE Workforce Identity を追加

YAML 
- egressFrom:
    identities:
      - principalSet://my-pool.global.workforce.id.goog/attribute.department/engineering
  egressTo:
    operations:
      - serviceName: storage.googleapis.com
        methodSelectors:
          - method: "*"
    resources:
      - projects/444555666

Step 3: サービス境界にポリシーを適用

Bash 
# Ingress ポリシーの更新
gcloud access-context-manager perimeters update PERIMETER_ID \
    --set-ingress-policies=ingress.yaml

# Egress ポリシーの更新
gcloud access-context-manager perimeters update PERIMETER_ID \
    --set-egress-policies=egress.yaml

✅ メリット

📈 ビジネス面

AI エージェントのセキュアな運用

エージェントごとに固有の ID を付与してアクセス制御。ガバナンス向上。

マルチクラウド統合管理

SPIFFE 標準に基づき、AWS/Azure/オンプレミスからのワークロードも統一管理。

コンプライアンス強化

個別エージェントの監査証跡が明確になり、規制要件への準拠を容易に実現。

🔧 技術面

最小権限の原則の徹底

個別エージェントや特定属性の ID グループにのみアクセスを許可。過度な権限付与を排除。

属性ベースアクセス制御 (ABAC)

principalSet:// と属性指定で、動的環境でも宣言的なポリシー管理が可能。

IAM v1 API との統合

既存の IAM プリンシパル識別子形式と整合性があり、学習コストが低い。

⚠️ デメリット・制約事項

制限事項:
  • Egress ルールで Identity Group 使用時、egressTo.resources にワイルドカード "*" は使用不可
  • Workload Identity を使用した Apache Airflow Web Interface (Cloud Composer) への操作は非対応
  • Workload Identity Federation for GKE はサポート対象外 (通常の Workload Identity Federation のみ対応)
💡 考慮すべき点:
  • Agent Identity 数の上限 3,000 個: 大規模環境では principalSet:// による属性ベースの指定を推奨
  • 属性数上限 6,000 に identities のエントリも含まれるため、既存ルールの属性数を考慮した設計が必要
  • Dry-run モードと Enforced モードそれぞれで属性制限が適用される

🎯 ユースケース

🤖 UC1: AI エージェントによるデータ分析パイプライン

シナリオ: Vertex AI Agent Engine の分析エージェントが、VPC SC で保護された BigQuery にアクセスして分析を実行

効果: 特定の分析エージェントのみが BigQuery のジョブ実行とクエリ結果取得を許可。他のエージェントや不正アクセスはブロック。

👤 UC2: 外部 IdP ユーザーのハイブリッドクラウドアクセス

シナリオ: Azure AD で管理される外部パートナー企業のエンジニアが、Workforce Identity Federation 経由でサービス境界内リソースにアクセス

効果: VPN 接続かつ特定チーム属性を持つ外部パートナーのみがストレージにアクセス可能。SPIFFE ベースの Trust Domain で統一管理。

🏢 UC3: マルチエージェント環境の一括制御

シナリオ: 組織内の全 AI エージェントに対して、Trust Domain 単位で特定サービスへのアクセスを制御

効果: principalSet://.../* で全エージェントに一括許可。新エージェントのデプロイ時にルール追加不要。

💰 料金

✅ 追加料金なし: VPC Service Controls の利用に追加料金は発生しません。Agent Identity および SPIFFE 形式の ID を Ingress/Egress ルールで使用する場合も、追加費用なしで利用できます。

※ 関連サービス (Workforce Identity Federation、Workload Identity Federation、Vertex AI Agent Engine など) には個別の料金体系が適用される場合があります。

🌐 利用可能リージョン

グローバル対応: VPC Service Controls はグローバルサービスであり、すべての Google Cloud リージョンで利用可能です。Ingress/Egress ルールでの Agent Identity および SPIFFE 形式 ID の指定も、全リージョンで対応しています。

📝 まとめ

VPC Service Controls における Agent Identity と SPIFFE 形式サードパーティ ID の GA は、AI エージェント時代のデータ境界セキュリティにおける重要なマイルストーンです。

従来の共有サービスアカウントベースの制御から、エージェントごと・Trust Domain ごとのきめ細かいアクセス制御への移行を可能にします。

🎯 推奨アクション: AI エージェントを本番環境で運用している組織は、既存の ANY_SERVICE_ACCOUNT 設定をレビューし、Agent Identity ベースの個別制御への移行を検討してください。
