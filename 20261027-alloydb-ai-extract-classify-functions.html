AlloyDB for PostgreSQL 🤖 AlloyDB AI Preview

🧠 AI 関数 ai.extract / ai.classify が登場

AI クエリエンジン関数のシグネチャ更新も同時実施 — SQL だけで非構造化テキストを構造化・分類
📅 リリース日: 2026-10-27

📌 概要

AlloyDB for PostgreSQL の AI クエリエンジンに、新しい AI 関数 ai.extract と ai.classify が Preview として追加されました。 ai.extract は非構造化テキストから指定スキーマに基づいて構造化データを抽出、 ai.classify はテキストを事前定義ラベルに分類する関数です。 外部の ETL パイプラインや外部サービス連携なしに、SQL クエリ内で直接非構造化データを処理できます。

あわせて、既存の AI 関数 (ai.analyze_sentiment、ai.summarize、ai.agg_summarize) の パラメータ名が prompt/prompts から input/inputs に統一され、 要約のフォーマット・長さ・トーンを指示できる additional_instructions パラメータが追加されました。

🎯 対象ユーザー: データベース内の問い合わせ記録、レビュー、議事録、契約書などの非構造化テキストを、 アプリケーション側コードや外部パイプラインなしで構造化・分類したいデータベースエンジニア / アプリケーション開発者。

❌ Before: アップデート前の課題

  • 構造化データの抽出には、DB 外部に ETL パイプラインや外部サービス (Vertex AI API 直接呼び出しなど) の構築が必要
  • 定義済みカテゴリへのテキスト分類も、同様に DB 外部での実装が必要
  • ai.summarize などで要約のフォーマット・長さ・トーンを指示する専用パラメータがなかった

✅ After: アップデート後の改善

  • ai.extract で JSON スキーマ / 自然言語指示に基づく構造化データ抽出が SQL 内で可能に
  • ai.classify でトピック分類・スパム検出・インテント認識などが SQL 内で可能に
  • additional_instructions で要約のフォーマット・長さ・トーンをガイド可能に
  • input/inputs への統一でパラメータ名の一貫性が向上

⚡ 主要機能

1️⃣ ai.extract: 構造化データ抽出関数 Preview

→非構造化テキストから、指定したスキーマに基づいて構造化データを抽出する組み込み関数
→output_schema には JSON スキーマ形式 (例: '{"contact_name": {"type": "string"}}') と自然言語によるテキスト指定の両方が利用可能。配列型フィールドの抽出にも対応
→スカラー版 (input)、配列ベースのバッチ版 (inputs)、カーソルベース版 (input_cursor) の 3 形態で、数千行規模のデータも効率的に処理可能

2️⃣ ai.classify: テキスト分類関数 Preview

→テキストを事前定義したクラス / ラベルに分類する組み込み関数
→categories にはラベルの配列、またはラベルと説明のペアの 2 次元配列を指定可能。オプションで examples (few-shot 例) と output_mode (デフォルト: single) を指定可能
→トピック分類、スパム検出、インテント認識などに対応し、スカラー版・配列版・カーソル版を提供

3️⃣ AI クエリエンジン関数のパラメータ名・シグネチャ更新

→ai.analyze_sentiment、ai.summarize、ai.agg_summarize のスカラー版・バッチ版で prompt/prompts を input/inputs にリネーム
→ai.summarize / ai.agg_summarize にオプションの additional_instructions を追加。要約のフォーマット・長さ・トーンを指示可能に
→ai.analyze_sentiment と ai.summarize のカーソルベース版では prompt パラメータを削除
→ai.agg_summarize は集約関数のため名前付き引数を非サポート。複数の位置引数シグネチャ (列のみ / 列 + 指示 / 列 + 指示 + モデル ID / 列 + モデル ID の VARCHAR キャスト) をサポート

4️⃣ スマートバッチング (AI 関数アクセラレーション) 対応

→google_ml_integration.enable_ai_function_acceleration フラグを on にすると、行単位のスカラー AI 関数呼び出しがバックグラウンドで自動的にバッチ化され、クエリ全体の実行時間を短縮

🛠️ 設定方法

📋 前提条件: AlloyDB クラスタが PostgreSQL 18 以降で稼働し、google_ml_integration 拡張のバージョンが 1.6.1 以上であること。

1拡張バージョンの確認とフラグの有効化

SQL フラグの有効化 (再起動不要) 
-- 拡張バージョンの確認
SELECT extversion FROM pg_extension WHERE extname = 'google_ml_integration';

-- 現在のセッションでフラグを有効化 (再起動不要)
SET google_ml_integration.enable_ai_query_engine = 'on';
SET google_ml_integration.enable_preview_ai_functions = 'on';

データベース単位で永続化する場合は ALTER DATABASE ... SET、インスタンス全体では gcloud alloydb instances update --database-flags を使用します。

2(推奨) スマートバッチングの有効化

SQL AI 関数アクセラレーション 
SET google_ml_integration.enable_ai_function_acceleration = 'on';

複数行に対するスカラー AI 関数呼び出しが自動でバッチ化され、実行時間が短縮されます。

3ai.extract / ai.classify の実行

SQL 構造化データの抽出とテキスト分類 
-- 構造化データの抽出
SELECT lead_id,
       ai.extract(
         input => raw_transcript,
         output_schema => '{"contact_name": {"type": "string"}, "company_name": {"type": "string"}, "job_title": {"type": "string"}}'
       ) AS extracted_info
FROM sales_leads
WHERE lead_status = 'new';

-- テキストの分類
SELECT id,
       ai.classify(
         input => review,
         categories => ARRAY['positive', 'neutral', 'negative']
       ) AS sentiment
FROM product_reviews
ORDER BY id;

🚧 制限事項

✗Preview 機能であり、Pre-GA Offerings Terms が適用される (サポートが限定される場合がある)
✗ai.extract / ai.classify は PostgreSQL 18 以降のみサポート

🤔 考慮すべき点

⚠️ 既存クエリへの影響: パラメータ名の変更 (prompt/prompts → input/inputs) およびカーソル版からの prompt 削除は、既存クエリで名前付き引数を使用している場合に修正が必要になる可能性があります。
→ai.agg_summarize は集約関数のため名前付き引数が使えず、モデル ID のみを指定する場合は 'MODEL_ID'::VARCHAR の明示的キャストが必要
→AI 関数の実行は Gemini モデルの呼び出しを伴うため、大量データ処理時はバッチサイズやコストへの影響を考慮する

🎯 ユースケース

📇 ユースケース 1: 営業コールの記録から CRM データを自動生成

シナリオ: 営業チームがフリーテキストで記録したコールメモから、担当者名・会社名・役職・ニーズを抽出して構造化したい。

SQL ai.extract による情報抽出 
SELECT ai.extract(
  input => 'Spoke with Alex R., Director of IT at Example Organization. They are looking to upgrade their cloud storage.',
  output_schema => '{"contact_name": {"type": "string"}, "job_title": {"type": "string"}, "company_name": {"type": "string"}, "need": {"type": "string"}}'
);
-- 出力: {"contact_name": "Alex R.", "job_title": "Director of IT", "company_name": "Example Organization", "need": "upgrade cloud storage"}

✨ 効果: 外部パイプラインなしで、SQL だけでフリーテキストを構造化 JSON に変換でき、CRM への取り込みを自動化できる。

⭐ ユースケース 2: 商品レビューのセンチメント分類

シナリオ: 蓄積された商品レビューを positive / neutral / negative に分類して、顧客満足度を集計したい。

SQL ai.classify のバッチ版による分類 
SELECT unnest(
  ai.classify(
    inputs => ARRAY(SELECT review FROM product_reviews ORDER BY id),
    categories => ARRAY[
      ARRAY['positive', 'Good sentiment'],
      ARRAY['neutral', 'Neither good nor bad sentiment'],
      ARRAY['negative', 'Bad sentiment']
    ],
    batch_size => 5
  )
) AS sentiment;

✨ 効果: ラベルに説明を添えた 2 次元配列で分類精度をガイドしつつ、バッチ処理で大量レビューを効率的に分類できる。

📝 ユースケース 3: 指示付き要約によるレポート整形

シナリオ: 映画レビューを映画ごとに集約し、長さを指定した要約を生成したい。

SQL ai.agg_summarize と additional_instructions 
SELECT ai.agg_summarize(review, 'Please summarize this within 10 words')
FROM movie_reviews
GROUP BY movie_id;

✨ 効果: 新しい additional_instructions により、要約の長さやトーンを SQL 内で直接コントロールできる。
