Contact Center as a Service (CCaaS) 正式リリース AI 機能

📞 Google Cloud CCaaS 5.2 リリース

留守番電話検出 (AMD) / メール解析データ API / 添付ファイル付きメール転送 / スマートディスポジション + 多数のバグ修正
リリース日: 2026-07-30

📋 概要

Google Cloud Contact Center as a Service (CCaaS、旧称 CCAI Platform) のバージョン 5.2 が正式リリースされました。 プログレッシブ アウトバウンド キャンペーン向けの留守番電話検出 (AMD)、メールの解析済みコンテンツを取得する 2 つの新しい読み取り専用 API、添付ファイル付きメール転送、 AI がディスポジション コードを自動提案するスマートディスポジションの 4 つの新機能に加え、 通話スタック・転送・レポート・チャット・CRM 連携に関わる多数のバグ修正が含まれています。

💡 ポイント: 本リリースは 2026-07-27 のプレリリースノートで事前告知されていた内容の正式リリースです。各インスタンスへの適用タイミングは選択しているデプロイスケジュールに依存します。正式リリースにともない各機能の公式ドキュメントが公開され、スマートディスポジションの前提条件 (Agent Assist の生成 AI セッション要約) や AMD のレポーティング仕様・制限事項が明らかになりました。

❌ Before (アップデート前の課題)

  • プログレッシブ キャンペーンで留守番電話に接続された通話もエージェントが手動で切断する必要があり時間を浪費
  • Apps API にメールの解析済みコンテンツ (送信者、件名、本文など) を取得するエンドポイントがなく、外部システムからのアクセスが困難
  • エージェントがメールアダプタから外部宛先にメールを転送する手段がなかった
  • ラップアップではディスポジション コードを手動で検索・選択する必要があり、後処理時間の増加と選択のばらつきの原因に

✅ After (アップデート後の改善)

  • AMD が通話音声を解析して留守番電話を自動終了・スキップし、エージェントは人間との会話に集中
  • 2 つの新 API でメールセッションのサマリーと解析済み全文コンテンツを外部システムから取得可能に
  • 「Forward」ボタンで添付ファイルを自動的に含めた外部宛先へのメール転送が可能に (送信前に添付削除も可)
  • AI が会話内容・キュー・種別に基づきディスポジション コードを自動提案、手作業削減とデータ一貫性向上

CCaaS 5.2 で追加された AMD とスマートディスポジションを組み合わせたプログレッシブ キャンペーンの通話フローです。 留守番電話を検出すると通話を自動終了して「Voicemail Detected」ラベルをメトリクスに記録し、 人間が応答した通話ではラップアップ時に AI がディスポジション コードを提案します。

🚀 主要機能

1️⃣ 📢 CCaaS 5.2 リリース (Announcement)

Google Cloud CCaaS のバージョン 5.2 が正式リリース。各インスタンスへのアップデート適用タイミングは、選択しているデプロイスケジュールに依存します。

2️⃣ 🎧 留守番電話検出 (AMD) for プログレッシブ キャンペーン

  • CCAI Platform がバックグラウンドで通話音声を解析し、応答したのが人間か留守番電話 (ボイスメール) かを判定
  • 留守番電話を検出した場合、通話は終了し、ダイヤラーは次の連絡先の発信に進む
  • 管理者向け: Settings > Campaigns > Dialer Modes の Progressive セクションに「Enable Answering Machine Detection」トグルを追加
  • UX: 留守番電話検出時にコールアダプタに緑色のバナーを表示
  • レポーティング: キャンペーン メトリクスに「Voicemail Detected」ラベル付きで記録

3️⃣ 🔌 メールセッション・メッセージ取得エンドポイント (Apps API)

  • メールの解析済みコンテンツ (送信者、宛先、件名、本文、添付ファイル メタデータ) を取得できる 2 つの読み取り専用エンドポイントを追加
  • /apps/api/v1/email/sessions/EMAIL_SUPPORT_ID: セッションのサマリーとメッセージ ID 一覧 (下書きは含まれない)
  • /apps/api/v1/email/messages/EMAIL_THREAD_ID: 単一メッセージの全文コンテンツ
  • 既存の Apps API と同様に Basic 認証を使用

4️⃣ 📤 添付ファイル付きメール転送

  • エージェントがメールアダプタから外部の宛先にメールを直接転送できるように
  • 元のメールのすべての添付ファイルが自動的に含まれる (送信前に削除も可能)
  • 元のメールは割り当てられたキューにステータス未変更のまま残るため既存フローに影響しない
  • UX: メールアダプタに新しい「Forward」ボタンを追加

5️⃣ 🤖 スマートディスポジション (Smart Disposition)

  • セッション終了時に AI がディスポジション コードを自動提案。手作業を減らしデータの一貫性を向上
  • 会話の内容・ルーティングされたキュー・インタラクション種別 (通話/チャット、インバウンド/アウトバウンド) に基づいて提案を生成
  • 管理者向け: Settings > Operation Management > Wrap-up 配下の 3 箇所 (inbound calls / outbound calls / chats) に「Smart Disposition」トグルを追加
  • エージェントは提案を確認し、承認するか、より適切なコードに変更して送信
  • グローバル設定に加えてキューレベルでも設定可能 (キューレベル設定が優先)

6️⃣ 🔧 多数のバグ修正 (Fixed)

  • 通話関連: 異常終了後に通話が仮想エージェント状態で固まる問題、ウォーム転送キャンセルで発信者が自動メニューをループする問題、OCD 有効キューへの転送の無限呼び出し音、早期切断・音声消失、Telnyx VoIP の無通知切断など
  • API・パフォーマンス関連: エージェント アクティビティ ログ API のタイムアウト、team / menu エンドポイントの性能遅延、Manager API の大規模データセット取得タイムアウトなど
  • レポート関連: Call History のカスケード グループ番号誤表示、Agent Activity ダッシュボードのタイムゾーン不整合、手動ラップアップの duration 水増しなど
  • チャット・SMS 関連: チャットがキューで固まる問題、SMS チャットの再ルーティング失敗、Web SDK の重複セッション作成など
  • メール関連: CC / BCC の機密情報がシステム ログに露出する問題、キュー間メール転送時の空白グレー画面を修正
  • 外部連携関連: Kustomer (通話が Call In Progress のまま残る)、ServiceNow (重複ケース作成)、Salesforce (誤った連絡先名表示) の各連携の不具合を修正
  • その他: Nexmo 経由 IVR での冒頭音声の聞き逃し、Dialogflow エージェントの誤エスカレーション、重複録音ファイル作成なども修正。通話品質診断の内部計測も改善

🔌 新しい Apps API エンドポイント

エンドポイントメソッド取得できる情報
/apps/api/v1/email/sessions/EMAIL_SUPPORT_ID GET メールセッションのサマリー情報 (ステータス、作成・更新日時、メールアカウント ID、メッセージ数) と、メタデータ付きメッセージ ID の一覧
/apps/api/v1/email/messages/EMAIL_THREAD_ID GET 単一メッセージの全文 (送信者、宛先、CC / BCC、件名、本文、Content-Type、添付ファイルのメタデータ)

セッション取得レスポンスの主なフィールド: email_support_id、status (unopened / active / paused / resolved / closed / reopened)、email_account_id、total_thread_numbers (下書きを除くメッセージ数)、email_threads 配列 (各要素に email_thread_id、RFC 5322 ヘッダー由来の message_id、received_at、direction)

メッセージ取得レスポンスの主なフィールド: from / from_name / to / cc / bcc / subject / body / content_type / attachment_count、および email_attachments 配列 (各要素に file_name、file_type、size_bytes、url。url フィールドは null を返す)

🔑 Apps API の基本仕様: ベース URL は https://{subdomain}.{domain}/apps/api/v1。Basic 認証 (サブドメインを username、API トークンを password として使用) が必要です。API クレデンシャルは Settings > Developer Settings > API Credentials で作成します。リクエストレートは顧客あたり 10 リクエスト/秒に制限されています。API レスポンスには将来新しい JSON キーが追加される可能性があるため、未知のキーを無視する防御的な実装が推奨されています。

💡 メリット

📈 ビジネス面

  • アウトバウンド キャンペーンの生産性向上: AMD により留守番電話対応の時間が不要になり、顧客との会話時間の比率が向上。「Voicemail Detected」ラベルで到達状況も定量的に把握
  • 後処理時間 (ACW) の短縮とデータ品質向上: AI 提案でラップアップ時間を削減しつつ、コード選択の一貫性が向上しレポーティング精度が向上
  • メール対応の柔軟性向上: 添付ファイル込みの転送がアダプタ内から直接行え、コピー&ペーストや別システムでの再送の手間が減少

🔧 技術面

  • 外部システム統合の強化: メールの全文や添付ファイル メタデータを外部のオーケストレーション、コンテンツベースのルーティング判断、分析基盤に取り込み可能
  • 既存フローへの影響が小さい設計: メール転送後も元のメールは元のキューにステータス未変更のまま残る
  • プラットフォーム安定性の向上: 通話スタック、転送ループ、API タイムアウト、CRM 連携の重複レコードなど運用に直結する広範な修正

⚠️ デメリット・制約事項

🚧 制限事項

  • AMD の検出性能はキャリアの状況や通話音声の影響を受ける。特にノイズの多い環境では留守番電話・ボイスメールの検出は保証されない (公式ドキュメントに明記)
  • AMD の対象はプログレッシブ アウトバウンド キャンペーン
  • メール取得エンドポイントは読み取り専用 (作成・更新は不可)。下書きは取得対象外、添付ファイルの url は null を返す (添付本体はダウンロード不可)
  • スマートディスポジションには Agent Assist の生成 AI セッション要約の構成が前提条件
  • Apps API のリクエストレートは顧客あたり 10 リクエスト/秒に制限

🤔 考慮すべき点

  • 5.2 の適用タイミングはデプロイスケジュールに依存するため、自組織のインスタンスへの適用時期を確認してから有効化・利用計画を立てる
  • スマートディスポジションは AI による「提案」。エージェントは提案の妥当性を必ず評価し、不適切な場合は適切なコードを選択する運用が公式に推奨。誤提案パターンは管理者にフィードバックする体制を整えるとよい
  • ディスポジション コードに Description を追加しておくと提案精度に有効なため、既存コード定義の見直しを検討
  • アウトバウンド キャンペーン運用では、Do Not Call (DNC) リスト照合や放棄呼率規制などのコンプライアンス要件に引き続き注意
  • メール転送で社外へ添付ファイルが送信可能になるため、情報漏えい防止の運用ルール整備を検討

🎯 ユースケース

📞 ユースケース 1: 督促・フォローアップ架電キャンペーンの効率化

シナリオ: 金融機関が支払いリマインドのプログレッシブ キャンペーンを実施しているが、架電の相当数が留守番電話につながり、エージェントが手動で切断する時間が積み重なって生産性を圧迫している。

実装例: Settings > Campaigns > Dialer Modes > Progressive で「Enable Answering Machine Detection」を有効化し、既存のプログレッシブ キャンペーンをそのまま実行する。

効果: 留守番電話への接続が自動で終了・スキップされ、エージェントは人間が応答した通話のみに対応。「Voicemail Detected」ラベルによりリストの到達品質 (留守番電話率) も可視化され、架電時間帯やリストの改善に活用できる。

🔌 ユースケース 2: メール対応データの外部ワークフロー・分析基盤への取り込み

シナリオ: サポート部門が、受信メールの内容に基づくルーティング判断を外部のオーケストレーション システムで行いたい。また、メールチャネルの問い合わせ内容を分析基盤に取り込み、傾向分析に活用したい。

Bash 実装例 
# セッション ID からメッセージ一覧を取得し、
# 各メッセージの全文を取得して外部システムに連携
curl -u "SUBDOMAIN:API_TOKEN" \
  "https://YOUR_CCAAS_HOST/apps/api/v1/email/sessions/EMAIL_SUPPORT_ID"

効果: 従来取得が難しかったメールの解析済みコンテンツ (件名、本文、送信者、添付ファイル メタデータ) をプログラムで取得でき、コンテンツアウェアなルーティングの自動化や、ETL パイプラインによる分析基盤への自動収集が可能になる。

📝 ユースケース 3: ラップアップ作業の標準化と短縮

シナリオ: 多数のディスポジション コードを階層化して運用しているコンタクトセンターで、エージェントによるコード選択のばらつきと後処理時間の長さが課題。Agent Assist の生成 AI セッション要約はすでに導入済み。

実装例: Settings > Operation Management > Wrap-up で対象セッション種別 (インバウンド / アウトバウンド / チャット) の Smart Disposition トグルを有効化。あわせて各ディスポジション コードに Description を追加して提案精度を高める。

効果: AI が会話内容・キュー・インタラクション種別に基づいてコードを提案し、エージェントは提案を確認・確定するだけでよくなる。コード選択の一貫性が向上し、レポーティング精度と後処理時間の両方が改善する。

🔗 関連サービス・機能

  • アウトバウンド キャンペーン (Preview / Predictive / Progressive): AMD が追加されたのはプログレッシブ モード。エージェントが手動発信する Preview、ダイヤル数を予測制御する Predictive を含む 3 つのダイヤルモードがある
  • Agent Assist (生成 AI セッション要約): スマートディスポジションの前提条件。通話・チャットの要約などのエージェント支援機能とあわせてラップアップ作業全体の効率化に寄与
  • Apps API / Manager API: CCaaS の外部統合用 API 群。今回のメール取得エンドポイントは Apps API に追加。本リリースでは Manager API の大規模データセット取得時のタイムアウトも修正
  • ディスポジション コードとリスト: ラップアップでセッション結果を分類する既存の仕組み。スマートディスポジションはこれを AI で拡張。コードの Description 追加が提案品質の観点で推奨
