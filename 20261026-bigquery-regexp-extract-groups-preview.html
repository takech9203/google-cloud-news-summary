🔍 BigQuery: REGEXP_EXTRACT_GROUPS 関数

BigQuery Preview GoogleSQL 文字列関数
📅 リリース日: 2026-10-26

📋 概要

BigQuery の GoogleSQL に新しい文字列関数 REGEXP_EXTRACT_GROUPS が追加されました (Preview)。 正規表現内の複数のキャプチャグループにマッチする部分文字列を一度にまとめて抽出し、 各グループに対応するフィールドを持つ STRUCT として返します。

ログ行や ID 文字列、日付文字列などの構造化されたテキストを 1 回の関数呼び出しで複数カラムに分解でき、 名前付きグループや型の自動キャストにも対応。 正規表現による文字列パースを多用するデータエンジニア・アナリストに有用なアップデートです。

❌ Before (アップデート前の課題)

  • REGEXP_EXTRACT は 1 グループのみ → 複数部分の抽出には同じ正規表現マッチングを複数回実行
  • REGEXP_EXTRACT_ALL は複数キャプチャグループを含むとエラー
  • 型変換には別途 CAST / SAFE_CAST の記述が必要

✅ After (アップデート後の改善)

  • 1 回の呼び出しで全キャプチャグループを STRUCT として取得
  • 名前付きグループ ((?<name>...)) がフィールド名になり、.* で個別カラムに展開可能
  • __TYPE サフィックス (例: __INT64) で指定型へ自動キャスト

⚡ 主要機能

1️⃣ 複数キャプチャグループの一括抽出

→REGEXP_EXTRACT_GROUPS(value, regexp) は、value の中で正規表現全体が最初にマッチした箇所から、各キャプチャグループに対応する部分文字列を STRUCT として返す
→STRUCT のフィールド順は、正規表現内のキャプチャグループの左から右の順序に対応
→正規表現は re2 構文で、少なくとも 1 つのキャプチャグループを含む必要がある

2️⃣ 名前付きグループと STRUCT のカラム展開

→名前付きグループ ((?<name>...) または (?P<name>...)、両者は等価) の名前がそのまま STRUCT のフィールド名になる
→名前のないグループは匿名フィールドとなり、STRUCT 内の 0 始まりの位置でアクセス可能
→SELECT リストで .* 演算子を使ってフィールドを個別のカラムに展開できる

3️⃣ __TYPE サフィックスによる自動キャスト

→グループ名末尾のダブルアンダースコア + 型名 (例: (?<val__INT64>...)) で、抽出文字列をその型に自動キャスト
→STRING (BYTES 版では BYTES) からキャスト可能な任意の型をサポート。型名は大文字小文字を区別せず、結果のフィールド名から __TYPE サフィックスは除去される
→キャスト失敗 (空文字列の数値・ブール型へのキャストを含む) はエラー。オプショナルグループが未マッチで NULL の場合、キャスト結果も NULL

4️⃣ NULL とオプショナルグループの扱い

→value が NULL の場合、または正規表現全体がまったくマッチしない場合は NULL を返す
→選択 (alternation) やオプショナルグループで特定グループが未マッチの場合、対応するフィールドのみ NULL (空文字列へのマッチとは区別される)

🚨 エラーになる条件

条件内容
無効な正規表現regexp が不正な場合
リテラル以外の指定regexp が文字列リテラルでない場合

💻 設定方法・使用例

SQL 関数のため事前設定は不要で、クエリ内でそのまま使用できます。

名前なしグループの抽出

SQL 匿名グループを STRUCT で取得 
SELECT REGEXP_EXTRACT_GROUPS('abc123xyz', r'([a-z]+)([0-9]+)([a-z]+)') AS result
-- result: {abc, 123, xyz}

名前付きグループの抽出とカラム展開

SQL .* 演算子で個別カラムに展開 
SELECT REGEXP_EXTRACT_GROUPS('PROD-WIDGET-1234', r'(?<env>\w+)-(?<product>\w+)-(?<id>\d+)').*
/*-------+-----------+------+
 | env   | product   | id   |
 +-------+-----------+------+
 | PROD  | WIDGET    | 1234 |
 +-------+-----------+------*/

自動キャスト (__TYPE サフィックス)

SQL INT64 への自動キャスト 
SELECT REGEXP_EXTRACT_GROUPS('2025-09-10',
  r'(?<year__INT64>\d{4})-(?<month__INT64>\d{2})-(?<day__INT64>\d{2})').*
/*--------+---------+-------+
 | year   | month   | day   |
 +--------+---------+-------+
 | 2025   | 9       | 10    |
 +--------+---------+-------*/

👍 メリット

💼 ビジネス面

✅クエリ開発の効率化: ログや ID 文字列のパース処理を 1 つの関数呼び出しに集約でき、クエリの記述量と保守コストを削減
✅可読性の向上: 名前付きグループがそのままカラム名になるため、抽出ロジックの意図がクエリから読み取りやすい

⚙️ 技術面

✅冗長な繰り返しの排除: 同一文字列への REGEXP_EXTRACT の複数回適用が不要になり、正規表現の定義を 1 箇所に集約
✅型変換の統合: __TYPE サフィックスにより抽出と型キャストを 1 ステップで実行、別途 CAST 不要
✅パイプ構文との親和性: |> EXTEND ... .* のようにパイプ構文と組み合わせて、抽出フィールドを後続の計算にそのまま利用可能

⚠️ デメリット・制約事項

🚧 制限事項

❌Preview 機能であり、Pre-GA Offerings Terms が適用される ("as is" 提供、サポートが限定される場合がある)
❌regexp は文字列リテラルである必要があり、カラム値や式を正規表現として渡すことはできない
❌同じグループ名の重複使用は不可 (大文字小文字を区別しない)
❌__TYPE キャストは失敗するとエラーになる (空文字列の数値型へのキャストを含む)。SAFE_CAST のような NULL フォールバックは、グループをオプショナル ((...)?) にするなどの工夫が必要

🤔 考慮すべき点

⚠️ NULL ハンドリングの違いに注意
  • 正規表現全体が未マッチ → STRUCT 全体が NULL
  • 一部グループのみ未マッチ → そのフィールドだけが NULL
  • オプショナルグループが空文字列にマッチした場合 (空文字列) と、まったくマッチしなかった場合 (NULL) では結果が異なる
💡 導入のヒント: Preview 段階のため、本番ワークロードへの組み込みは GA を待つか、影響範囲を限定して利用することが望ましい。

🎯 ユースケース

📦 ユースケース 1: 構造化された ID 文字列の分解

シナリオ: PROD-WIDGET-1234 のような「環境-製品-ID」形式の識別子カラムを、環境・製品・ID の 3 カラムに分解して分析したい。

SQL実装例
SELECT
  item_code,
  REGEXP_EXTRACT_GROUPS(item_code, r'(?<env>\w+)-(?<product>\w+)-(?<id__INT64>\d+)').*
FROM my_dataset.items

効果: 従来は REGEXP_EXTRACT を 3 回 + CAST を記述する必要があった処理が 1 つの関数呼び出しで完結し、クエリが簡潔になる。

⏱️ ユースケース 2: 時刻文字列のパースと計算 (パイプ構文)

シナリオ: 02:30:10 のような時刻文字列から時・分・秒を数値として取り出し、合計秒数を計算したい。

SQL実装例 (パイプ構文)
FROM UNNEST(['02:30:10', '01:02:03']) AS time_str
|> EXTEND REGEXP_EXTRACT_GROUPS(time_str,
     r'(?<h__INT64>\d{2}):(?<m__INT64>\d{2}):(?<s__INT64>\d{2})').*
|> SELECT time_str, h * 3600 + m * 60 + s AS total_seconds

効果: 自動キャストにより抽出直後から数値演算が可能で、パース・変換・計算を宣言的に記述できる。

📜 ユースケース 3: 複数フォーマットが混在するログのパース

シナリオ: config_id=123 と option_name=ABC のように異なる形式の行が混在するログから、形式ごとの値を抽出したい。

SQL実装例 (alternation)
SELECT t, REGEXP_EXTRACT_GROUPS(t, r'config_id=(?<id>\d+)|option_name=(?<name>\w+)') AS result
FROM logs

効果: 選択 (alternation) 内のすべての名前付きグループが STRUCT のフィールドになり、マッチした形式に対応するフィールドのみ値が入る (他は NULL) ため、1 つの正規表現で複数フォーマットを処理できる。

🔗 関連サービス・機能

→REGEXP_EXTRACT: 単一のキャプチャグループ (または正規表現全体) にマッチする部分文字列を返す既存関数。複数グループの抽出は本関数が補完する
→REGEXP_EXTRACT_ALL: マッチするすべての部分文字列を配列で返す既存関数。複数のキャプチャグループを含む正規表現はエラーになる
→GoogleSQL の STRUCT 型 / .* 演算子: 本関数の戻り値である STRUCT をカラムに展開する際に使用
→BigQuery パイプ構文: |> EXTEND と組み合わせて抽出フィールドを後続処理に利用できる
