🔒 Sensitive Data Protection:
カスタムメタデータラベル検出機能

Security Sensitive Data Protection Feature
2026-06-29

📋 概要

Sensitive Data Protection に、ファイルのメタデータラベルを検出するカスタム infoType 検出機能が追加されました。Google Drive ラベルや Microsoft 感度ラベル (Microsoft Purview Information Protection ラベル) など、既存のファイル分類システムで付与されたメタデータラベルを検査対象として認識できるようになります。

💡 ポイント: メタデータは対応ファイル形式から自動抽出されるか、アプリケーションから InspectContent リクエストで直接提供できます。既存の分類体系を DLP の検査・ポリシー適用に活用し、より包括的なデータガバナンスを実現します。

🔄 Before / After 比較

❌ Before (アップデート前)

  • ファイルの内容 (テキスト、画像) のみを検査対象
  • メタデータラベルを検出条件として利用不可
  • Microsoft 感度ラベルとの統合に別途カスタムワークフローが必要
  • 分類情報とコンテンツ検査を一元管理する手段がない

✅ After (アップデート後)

  • MetadataKeyValueExpression カスタム infoType で正規表現検出
  • DOCX/PDF/PPTX/XLSX から MSIP メタデータを自動抽出
  • クライアント提供メタデータも InspectContent で検査可能
  • Model Armor 連携でメタデータベースのサニタイズ実現

⚡ 主要機能

🏷️ MetadataKeyValueExpression カスタム infoType

key_regex と value_regex の正規表現でメタデータのキーと値をマッチング。Likelihood と SensitivityScore をカスタム設定可能。

📄 Microsoft Purview メタデータ自動検出

MSIP_Label_GUID_ATTRIBUTE 形式のメタデータを自動認識。対応属性: ActionId, ContentBits, Enabled, Method, Name, SetDate, SiteId

📤 クライアント提供メタデータスキャン

InspectContent リクエストの ContentMetadata フィールドにカスタムメタデータを提供可能。ファイル未埋め込みメタデータも検査対象に。

🛡️ Model Armor 連携

メタデータラベルに基づくドキュメントのサニタイズに対応。Gemini Enterprise など Model Armor を利用するサービスとの統合。

🔧 技術仕様

カスタム infoType 定義

項目 詳細
タイプ metadata_key_value_expression (MetadataKeyValueExpression)
key_regex メタデータキーを検索する正規表現
value_regex メタデータ値を検索する正規表現
デフォルト Likelihood VERY_LIKELY
デフォルト SensitivityScore HIGH

対応ファイル形式

ファイル形式 説明
DOCX Microsoft Word 文書
PDF PDF ドキュメント
PPTX Microsoft PowerPoint プレゼンテーション
XLSX Microsoft Excel スプレッドシート

💻 設定例

Microsoft 感度ラベルの検出

JSON 
{
  "inspect_config": {
    "custom_info_types": [
      {
        "info_type": {
          "name": "CUSTOM_MIP_HIGHLY_CONFIDENTIAL"
        },
        "likelihood": "VERY_LIKELY",
        "metadata_key_value_expression": {
          "key_regex": "MSIP_Label_12345678-9012-3456-7890-123456789012_Enabled",
          "value_regex": "true"
        }
      }
    ],
    "min_likelihood": "POSSIBLE"
  }
}

クライアント提供メタデータのスキャン

JSON 
{
  "inspect_config": {
    "custom_info_types": [
      {
        "info_type": {
          "name": "CUSTOM_MIP_CONFIDENTIAL_INTERNAL_USE"
        },
        "likelihood": "VERY_LIKELY",
        "metadata_key_value_expression": {
          "key_regex": "MSIP_Label_.*_Name",
          "value_regex": "Confidential|Internal Use"
        }
      }
    ]
  },
  "item": {
    "byte_item": {
      "type": "PDF",
      "data": "BASE64_ENCODED_PDF"
    },
    "content_metadata": {
      "properties": [
        {
          "key": "MSIP_Label_174b6716-c2ea-4041-b631-5633733fbe46_Name",
          "value": "Confidential"
        }
      ]
    }
  }
}

🔧 技術面

✓正規表現マッチング: 複数ラベル GUID を 1 つのルールでカバー
✓自動抽出: 対応ファイルから Microsoft Purview ラベルを自動検査
✓API 経由提供: ContentMetadata で未埋め込みメタデータも検査可能

⚠️ 制限事項・注意点

制限事項:
✗MetadataKeyValueExpression は Inspection Rule Sets (検査ルールセット) では使用不可
✗MetadataKeyValueExpression は De-identification Transformations (匿名化変換) では使用不可
✗対応ファイル形式は DOCX, PDF, PPTX, XLSX の 4 種類に限定
💡 考慮点:
  • Microsoft Purview ラベルの GUID はテナントごとに異なるため、正規表現パターンを環境に合わせて設定する必要がある
  • クライアント提供メタデータを利用する場合、アプリケーション側でメタデータの抽出・提供ロジックの実装が必要

🎯 ユースケース

📄 ユースケース 1: Microsoft 感度ラベル付きドキュメントの検出

シナリオ: Microsoft Purview で「Highly Confidential」ラベルを付与したドキュメントを、Cloud Storage の Discovery スキャンで自動検出し、Security Command Center にアラート送信。

効果: Cloud Storage 内の機密ドキュメントを自動識別し、データプロファイルの感度レベルに反映。Security Command Center でハイリスクリソースとして可視化。

🛡️ ユースケース 2: Model Armor によるメタデータベースのサニタイズ

シナリオ: Gemini Enterprise 環境で、「Internal Use Only」ラベル付きドキュメントが LLM プロンプトに含まれた場合にサニタイズ。

効果: 機密分類ドキュメントの内容が LLM に送信される前に、Model Armor がメタデータラベルに基づいて検出・サニタイズを実行し、情報漏洩リスクを低減。

🔍 ユースケース 3: マルチレイヤー分類の実現

シナリオ: 標準 infoType 検出 (クレジットカード番号、SSN) とメタデータラベル検出を組み合わせ、コンテンツとメタデータの両面からデータ分類。

効果: コンテンツに機密情報がなくても、メタデータラベルで「Confidential」と分類されたファイルを検出でき、網羅的なデータガバナンスを実現。

📌 まとめ

推奨アクション: Microsoft Purview を既に運用している組織は、まず Highly Confidential ラベルの検出ルールから導入し、Discovery スキャンでの活用を推奨します。

カスタムメタデータラベル検出機能により、既存のファイル分類システムを DLP 検出パイプラインに統合できます。コンテンツベースの検出とメタデータベースの検出を組み合わせたマルチレイヤーなデータガバナンスが可能になります。
