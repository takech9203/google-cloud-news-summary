🌊 Dataflow: ストリーミング高可用性
Streaming High Availability for Streaming Engine

📅 リリース日: 2026-10-21

📌 概要

Dataflow が Streaming Engine ジョブ向けのストリーミング高可用性 (Streaming High Availability) を Preview として提供開始。 サービスオプション requires_high_availability を有効にすると、バックエンド状態 (ステート) がリージョン内の複数ゾーンに複製され、 単一ゾーン障害からストリーミングジョブを保護します。

ゾーン障害が発生してもジョブはデータ損失なしで自動フェイルオーバーし、処理を継続。 ミッションクリティカルなストリーミングパイプライン (リアルタイム分析、CDC、イベント処理など) に特に有用なアップデートです。

❌ Before (アップデート前)

  • バックエンドリソースの一部を単一ゾーンで実行し、ゾーン障害時にデータ損失の影響を受ける可能性があった
  • ゾーン障害に備えるマネージドなステート複製の仕組みが存在しなかった

✅ After (アップデート後)

  • 状態が複数ゾーンに複製され、単一ゾーン障害でもジョブが停止しない
  • データをドロップせず自動フェイルオーバー、ユーザー対応は不要
  • job/high_availability_mode メトリクスでHA 状態とフェイルオーバーを監視可能

ストリーミング高可用性を有効にすると、バックエンド状態がリージョン内の複数ゾーンに複製されます。 プライマリのゾーンで障害が発生すると、セカンダリレプリカが新しいプライマリに自動昇格し、 別ゾーンに新たなセカンダリレプリカが作成されます。

⚡ 主要機能

🔁 1. クロスゾーンのステート複製

→Streaming Engine ジョブのバックエンド状態をリージョン内の複数ゾーンに複製
→ジョブがリージョンリソースとなり、単一ゾーン障害の影響を受けなくなる

🚀 2. 自動フェイルオーバー

→ゾーン障害時はデータをドロップすることなく自動フェイルオーバー、ユーザーの操作は不要
→フェイルオーバー中は、新プライマリへの切り替えと新セカンダリレプリカ確立の間、数秒〜数分程度スループットが低下する可能性あり

📊 3. 高可用性ステータスのモニタリング

→dataflow.googleapis.com/job/high_availability_mode メトリクス (ブール型ゲージ) で状態を監視
status ラベル意味
Highly Available複製済みで高可用
Establishing High Availabilityゾーン障害後などで新セカンダリレプリカを作成中
Disabled無効

🔧 技術仕様 — 要件と制限事項

項目詳細
Streaming Engine必須。Streaming Engine を使用するストリーミングパイプラインであること
ワーカー配置リージョナル配置が必須。特定のワーカーゾーン指定 (--workerZone、--worker_zone、--zone) を含むジョブは拒否される
設定タイミングジョブ作成時のみ有効化可能。実行中パイプラインのインプレース更新では有効化・無効化できない
ウォーターマークへの影響データが処理されかつクロスゾーン複製された後にウォーターマークが進むため、数秒程度の追加ラグが発生し得る
課金方式リソースベース課金 (resource-based billing) が常に適用され、データ処理量ベース課金は使用されない

🔌 ソースとシンクの可用性

⚠️ジョブをリージョンリソースとして構成しても、ソースとシンクが自動的にリージョナル/グローバルになるわけではない
✓Pub/Sub、BigQuery、Managed Service for Apache Kafka など多くの Google Cloud ソース/シンクは、デフォルトでリージョナルまたはグローバルの可用性を提供
⚠️セルフホスト Apache Kafka や Apache Iceberg などカスタム/自己管理のソース/シンクは、リージョン可用性を独自に構成・維持する必要がある

🛠️ 設定方法

✅ 前提条件

✓Streaming Engine を使用するストリーミングパイプラインであること
✓ワーカーがリージョナル配置であること (特定のワーカーゾーンを指定しない)

1️⃣ 新規ジョブ起動時にサービスオプションを指定

Bash パイプラインオプション 
# Java
--dataflowServiceOptions=requires_high_availability

# Python / Go
--dataflow_service_options=requires_high_availability

2️⃣ gcloud でテンプレート / Flex Template を実行する場合

Bash gcloud dataflow flex-template run 
gcloud dataflow flex-template run JOB_NAME \
  --project=PROJECT_ID \
  --template-file-gcs-location=TEMPLATE_LOCATION \
  --region=REGION \
  --enable-streaming-engine \
  --additional-experiments=requires_high_availability

Google Cloud コンソールからテンプレートを実行する場合は、「オプション パラメータ」の「Additional experiments」フィールドに requires_high_availability を入力します。REST API の場合は RuntimeEnvironment / FlexTemplateRuntimeEnvironment オブジェクトの additionalExperiments フィールドに指定します。

JSON REST API での指定例 
{
  "additionalExperiments": ["requires_high_availability"]
}
💡 既存ジョブへの適用: 自動 stop-and-replace 更新を実行するか、パイプラインを停止 (またはドレイン) してから --update フラグなしで新規ジョブを起動します。

🎯 メリット

💼 ビジネス面

✓ゾーン障害に対する事業継続性: 単一ゾーン障害でストリーミングジョブが停止せず、リアルタイムデータ処理の SLA 維持に寄与
✓運用負荷の軽減: フェイルオーバーは自動で行われ、障害時のユーザー対応が不要

⚙️ 技術面

✓データ損失なしの自動フェイルオーバー: ゾーン障害時もデータをドロップせずに処理を継続
✓可観測性: 専用メトリクスで HA 状態とフェイルオーバーイベントを Cloud Monitoring で監視可能

⚠️ デメリット・制約事項

🚫 制限事項

✗Streaming Engine を使用するストリーミングジョブのみ対応 (バッチジョブは対象外)
✗特定のワーカーゾーンを指定したジョブは拒否される (リージョナルワーカー配置が必須)
✗ジョブ作成時のみ有効化可能で、実行中パイプラインのインプレース更新では変更できない
✗Preview 機能のため、Pre-GA Offerings Terms が適用され、サポートが限定される場合がある
🤔 考慮すべき点
  • クロスゾーン複製を待ってからウォーターマークが進むため、数秒程度の追加ウォーターマークラグが発生し得る (超低レイテンシ要件のパイプラインでは影響を評価すること)
  • フェイルオーバー時には数秒〜数分程度のスループット低下が発生し得る
  • 常にリソースベース課金が適用されるため、データ処理量ベース課金を利用しているジョブは課金方式が変わる点に注意
  • ソース/シンクの可用性は別途確認が必要 (特にセルフマネージドなソース/シンク)

  • Preview 期間中: ストリーミング高可用性の利用に追加料金は発生しない
  • GA 以降: レプリケーションの使用量はプライマリ状態の使用量と同じレートで課金される予定。状態の使用量は Streaming Engine Compute Units の一部として計測される
  • ストリーミング高可用性ジョブは常にリソースベース課金を使用し、データ処理量ベース課金は使用されない
