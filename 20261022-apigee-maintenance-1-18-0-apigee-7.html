📌 概要

2026 年 10 月 22 日、Google は Apigee の更新版 1-18-0-apigee-7 をリリースしました。 Ingress Gateway のセキュリティ脆弱性パッチ (Bug ID 573663408) と Apigee インフラストラクチャのセキュリティ修正に加え、 生成 AI / LLM ゲートウェイ関連の修正が多数含まれるのが特徴です。 Semantic Governance Policies (SGP) の評価カバレッジ拡大、llmTokenQuota.* フロー変数の挙動修正、 圧縮 SSE レスポンスの EventFlow パススルー対応などが行われています。

❌ Before (アップデート前の課題)

  • Ingress Gateway に未パッチの脆弱性が存在
  • MP 起動直後の wait_time メトリクスに誤った値が混入
  • 生成 OpenAPI 仕様の servers[] がバックエンドのホスト名になっていた
  • OASValidation が有効なリクエストを間欠的に HTTP 400 で拒否
  • 圧縮 SSE レスポンスが EventFlow でボディ破損
  • SGP 拒否時に汎用メッセージのみで理由が不明
  • llmTokenQuota.* 変数が一致しないオペレーションからも設定
  • 一部の LLM リクエスト (配列形式メッセージ等) の評価をスキップ

✅ After (アップデート後の改善)

  • Ingress Gateway をアップグレードし脆弱性をパッチ (+ インフラ修正)
  • 起動ウォームアップ中は最初の 12 スクレイプでメトリクスをスキップ
  • servers[] が envgroup のホスト名に修正され、仕様をそのまま配布可能
  • strict パラメータ検証が正しく動作し誤拒否が解消
  • 圧縮 SSE は EventFlow をスキップしてパススルー
  • 拒否メッセージ未設定時は rationale (拒否理由) を表示
  • 変数は一致した LLM オペレーションのみから設定
  • スキップされていたリクエストも評価され、ガバナンスの抜け漏れが減少

🔒 セキュリティ修正

🚪 Ingress Gateway のアップグレード (Bug ID 573663408)

API トラフィックの入口となる Ingress Gateway をアップグレードし、セキュリティ脆弱性をパッチ。あわせて Apigee インフラストラクチャのセキュリティ修正も適用。

🤖 不具合修正: AI / LLM ゲートウェイ関連

🛡️ Semantic Governance の評価カバレッジ拡大 (Bug ID 567244615)

従来スキップしていた LLM リクエスト (例: メッセージコンテンツがパーツの配列である OpenAI リクエスト) を評価するように。最後のシステムメッセージだけでなくすべてのシステムメッセージを考慮。非ストリーミングの OpenAI / Ollama ツールコールで引数が有効な JSON でない場合は評価エラーに。

💬 SGP 拒否メッセージの改善 (Bug ID 549078690)

一致したポリシーに拒否メッセージが未設定の場合、汎用フォールバックではなく、ショートサーキットして rationale (拒否理由) を表示するように修正。

📋 verdict ログの sgpUserIntentMatchingMode を常時出力 (Bug ID 562964081)

ドライランのポリシーレコードを含め常に出力。sgpUserIntentMatching が未設定の場合も、評価に使用されたモード (CONSTRAINTS_AND_INTENT、またはツールコールに一致するポリシーがない場合は INTENT_ONLY) が記録される。

🎫 llmTokenQuota フロー変数の設定条件の修正 (Bug ID 492041991)

VerifyAPIKey / VerifyAccessToken はリクエストに一致した LLM オペレーションからのみ apiproduct.operation.llmTokenQuota.* を設定。一致していないオペレーションや、どのオペレーションにも一致しないリクエストには設定されなくなり、トークンクォータの誤適用を防止。

📡 圧縮 SSE レスポンスの EventFlow パススルー (Bug ID 572025634)

圧縮された text/event-stream ボディを持つレスポンスは EventFlow 処理をスキップしてそのままパススルー。従来は破損したボディが返されていた。

⚠️ 運用への影響: Semantic Governance の評価対象が増えるため、新たな拒否 (DENY) や judge モデルのトークン使用量の増加が発生し得ます。また llmTokenQuota.* を動的クォータ (countRef など) の参照元にしている場合、変数が設定されるケースが変わるため、プロキシの挙動確認を推奨します。

🔧 不具合修正: API プロキシランタイム関連

✅ OASValidation の間欠的 HTTP 400 を修正 (Bug ID 524115876)

strict パラメータ検証が有効なリクエストを間欠的に HTTP 400 で拒否する問題を修正。

📄 生成 OpenAPI 仕様の servers[] を修正 (Bug ID 573602919)

自動生成される OpenAPI 仕様の servers[] が、バックエンドターゲットではなく Apigee 環境グループ (envgroup) のホスト名を持つように修正。仕様をそのままクライアントに配布可能に。

📈 Message Processor 起動時のメトリクススキップ (Bug ID 568535165)

起動ウォームアップ中、最初の 12 回の Prometheus スクレイプで main_task_wait_time / nio_task_wait_time をスキップ。起動直後の不安定な値によるモニタリングのノイズや誤アラートを防止。

💡 その他の修正: JWS / JWT ポリシーの RFC 7797 (unencoded payload) 対応と検証強化、SanitizeModelResponse の SSE ストリームにおける双方向 gRPC 連続スキャン対応、SGP ドライランポリシーの評価・ログ記録、ext_proc の ImmediateResponse の Content-Type 保持、AppGroup アプリの OAuth レイテンシ改善など、多数の修正・改善が含まれます。詳細は 公式リリースノート を参照してください。

ステップ 2: 挙動変更の影響確認

🛡️ Semantic Governance を使用している場合

従来評価がスキップされていた LLM リクエスト (OpenAI の配列形式メッセージなど) が評価対象になるため、新たな拒否が発生していないか、judge モデルのトークン使用量が想定内かを semantic-governance-policy ログで確認する。

🎫 LLMTokenQuota で llmTokenQuota.* を参照している場合

変数が「一致した LLM オペレーションのみ」から設定されるようになったため、クォータの適用対象が意図どおりかを確認する。

📡 EventFlow 付きプロキシで圧縮 SSE レスポンスを扱う場合

圧縮された text/event-stream レスポンスは EventFlow の処理をスキップしてパススルーされるため、EventFlow 内のポリシー (DataCapture、LLMTokenQuota など) がそのレスポンスには実行されない点を考慮する。

考慮すべき点

⚠️ Semantic Governance の評価対象拡大: 意図した修正だが、これまで通過していたリクエストが新たに拒否される可能性と、judge モデルの使用量 (= コスト) が増える可能性がある。適用後はログとコストの監視強化を推奨。
⚠️ llmTokenQuota フロー変数の挙動変更: 一致しない LLM オペレーション由来の値に (意図せず) 依存していたプロキシでは、変数が未設定になるケースが生じる。該当するポリシー条件や countRef 参照の見直しが必要。
⚠️ 圧縮 SSE は EventFlow をスキップ: EventFlow 内でのトークン集計やデータ収集を確実に行いたい場合は、ターゲットとの間で圧縮を使わない構成も検討する。

シナリオ: API プロダクトの LLM オペレーションごとにトークンクォータを設定し、VerifyAPIKey の apiproduct.operation.llmTokenQuota.* フロー変数を LLMTokenQuota ポリシーから参照している。

🔗 関連サービス・機能

🛡️ Semantic Governance Policies (SGP)

AI エージェントのツールコールを自然言語制約で評価・統制する仕組み。本リリースで評価カバレッジと拒否メッセージ、verdict ログが改善。

🎫 LLMTokenQuota ポリシー

LLM レスポンスのトークン消費を数えて制限するポリシー。API プロダクトの LLM オペレーションと連動する動的クォータで apiproduct.operation.llmTokenQuota.* フロー変数を参照する。

📡 EventFlow (Server-Sent Events)

SSE ストリーミング応答をポリシーで加工するための特別なフロー。本リリースで圧縮 SSE レスポンスのパススルー挙動が修正。

✅ OASValidation ポリシー

OpenAPI 仕様に基づくリクエスト検証ポリシー。strict パラメータ検証の誤検知が修正。

📈 Cloud Monitoring / Prometheus メトリクス

Message Processor の main_task_wait_time / nio_task_wait_time メトリクスの起動時ノイズが解消。

📝 まとめ

1-18-0-apigee-7 は、Ingress Gateway の脆弱性パッチに加え、Semantic Governance・LLMTokenQuota・EventFlow といった LLM ゲートウェイ機能の修正が中心のリリースです。 ロールアウトは 10 月 22 日から 4 営業日以上かけて順次進むため、適用後は Semantic Governance の新たな拒否や judge モデル使用量、llmTokenQuota フロー変数に依存するプロキシの挙動を確認してください。 特に AI / エージェント向けの API を Apigee で統制しているチームは、評価対象拡大による影響のモニタリングを推奨します。
