🔒 Organization Policy カスタム制約が Private Services Access 接続で GA

Virtual Private Cloud (VPC) GA
2026-05-06

📋 概要

Organization Policy Service のカスタム制約が、Private Services Access (PSA) 接続に対して General Availability となりました。リソースタイプ servicenetworking.googleapis.com/Connection に対するカスタム制約を、本番環境で完全にサポートされた状態で使用できます。

Cloud SQL、Memorystore、AlloyDB などのマネージドサービスへのプライベート接続に対し、組織全体できめ細かいポリシー制御が可能になります。

💡 対象ユーザー: 大規模な組織でネットワークセキュリティとガバナンスを管理するクラウドアーキテクト、ネットワーク管理者、セキュリティチーム

🔄 Before / After

❌ Before (アップデート前)

  • PSA 接続の作成・変更に対して組織レベルでの細かい制御が困難
  • 特定 VPC のみでプライベート接続を許可するポリシーの一括適用が限定的
  • IP レンジ名に基づいた接続制限をプログラム的に強制する方法がなかった
  • Preview 段階で SLA 保証なし

✅ After (アップデート後)

  • GA で本番環境完全サポート、SLA 保証付き
  • CEL で VPC ネットワークや割り当てレンジ名に柔軟な条件定義
  • 組織 / フォルダ / プロジェクト各レベルで階層的ガバナンス
  • CREATE / UPDATE メソッド両方に制約適用可能

⚡ 主要機能

🌐 VPC ネットワークに基づく接続制限

特定の VPC ネットワークからのみプライベート接続を許可または拒否できます。resource.network フィールドを使用して条件を定義します。

例: 特定のネットワークでのプライベート接続作成を禁止

📛 割り当てレンジ名に基づく制限

resource.reservedPeeringRanges フィールドを使用して、使用可能な IP レンジ名を制御します。命名規則に基づいたレンジの許可・拒否が可能です。

例: legacy- プレフィックスで始まるレンジ名の使用を禁止

🔐 CREATE / UPDATE メソッドの制御

新規接続の作成時だけでなく、既存接続の変更時にもポリシーを適用できます。違反する変更はブロックされますが、既存の接続には遡及適用されません。

カスタム制約の構成例

YAML カスタム制約定義 
name: organizations/ORGANIZATION_ID/customConstraints/custom.servicenetworkingRestrictNetwork
resourceTypes:
  - servicenetworking.googleapis.com/Connection
methodTypes:
  - CREATE
  - UPDATE
condition: "resource.network == 'projects/PROJECT_ID/global/networks/VPC_NETWORK'"
actionType: DENY
displayName: Prevent private connections for a specific network.
description: Private connections can't be created for the specified VPC network.

Step 1: カスタム制約の YAML ファイルを作成

YAML restrict-psa-network.yaml 
name: organizations/ORGANIZATION_ID/customConstraints/custom.restrictPsaNetwork

  - servicenetworking.googleapis.com/Connection

  - CREATE
  - UPDATE

Step 2: カスタム制約を設定

💡 ユースケース

🏢 ユースケース 1: 本番環境ネットワークの保護

シナリオ: 大規模組織で、開発環境の VPC からのみプライベート接続を許可し、本番環境への意図しない接続変更を防止したい。

YAML 本番 VPC の PSA 変更をブロック 
name: organizations/123456789/customConstraints/custom.denyProdPsa
resourceTypes:
  - servicenetworking.googleapis.com/Connection
methodTypes:
  - CREATE
  - UPDATE
condition: "resource.network == 'projects/prod-project/global/networks/prod-vpc'"
actionType: DENY
displayName: Block PSA changes on production network
description: Prevents modifications to private service access connections on the production VPC network.

効果: 本番環境のプライベート接続が意図しない変更から保護され、可用性リスクを低減。

📛 ユースケース 2: IP レンジ命名規則の強制

シナリオ: 組織として IP レンジ名に特定の命名規則を適用し、レガシーな命名規則のレンジが使用されないようにしたい。

YAML レガシーレンジ名の使用を禁止 
name: organizations/123456789/customConstraints/custom.denyLegacyRanges
resourceTypes:
  - servicenetworking.googleapis.com/Connection
methodTypes:
  - CREATE
  - UPDATE
condition: "resource.reservedPeeringRanges.exists(range, range.startsWith('legacy-'))"
actionType: DENY
displayName: Deny legacy range names for PSA
description: Private connections cannot use allocated ranges with names starting with 'legacy-'.

効果: 命名規則の統一により、IP アドレス管理の可視性と運用効率が向上。

✅ メリット

ビジネス面

✓ コンプライアンス強化: 組織全体でプライベート接続を一元的に制御し、規制要件への対応が容易に
✓ ガバナンスの一元化: 組織レベルでのポリシー管理により運用コスト削減

技術面

✓ きめ細かい制御: CEL による柔軟な条件式で複数属性に基づいた制御が可能
✓ 階層的な適用: 継承と上書きにより例外処理も柔軟に対応
✓ GA の信頼性: SLA に裏付けられた本番環境での安定動作保証

⚠️ 制限事項・注意点

制限事項:
  • カスタム制約は既存の接続に対して遡及的には適用されない (新規作成・更新時のみ評価)
  • リソースタイプごとに最大 20 個のカスタム制約という上限がある
  • ポリシー適用後、enforcement 開始まで約 2 分の遅延がある
考慮すべき点:
  • PSA は VPC Network Peering を使用して実装されるため、ピアリングの制約 (非推移性など) も引き続き適用される
  • IPv6 アドレスレンジは Private Services Access ではサポートされていない
  • CEL で記述する条件式は複雑な場合テストが重要

💰 料金

Organization Policy Service のカスタム制約の使用自体に追加料金は発生しません。
Private Services Access の料金については VPC 料金ページ を参照してください。

📝 まとめ

Organization Policy Service のカスタム制約が Private Services Access 接続に対して GA となったことで、組織全体のプライベート接続ガバナンスが強化されました。特に大規模組織において、どの VPC ネットワークでプライベート接続を許可するか、どの IP レンジ名を使用可能とするかを CEL 条件で柔軟に制御できる点が大きな価値です。

既に Private Services Access を利用している組織は、セキュリティポスチャの強化策としてカスタム制約の導入を検討することを推奨します。
