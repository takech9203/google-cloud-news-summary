🔐 Cloud SQL: Data API での Secret Manager 認証サポート

Cloud SQL for MySQL Cloud SQL for PostgreSQL Feature
2026-07-20

📋 概要

Cloud SQL for MySQL および Cloud SQL for PostgreSQL の Data API (executeSql) において、Secret Manager を利用したパスワード認証がサポートされました。データベースパスワードを Secret Manager のリージョナルシークレットに保存し、API リクエスト時にシークレットバージョンのリソース名を渡すことで、安全にビルトインユーザーとして認証できます。

💡 ポイント: パスワードをコードや環境変数に直接埋め込む必要がなくなり、セキュリティ体制が大幅に強化されます。IAM 認証に加え、パスワードベース認証も Secret Manager と連携して安全に利用可能になりました。

⚡ 主要機能

🔑 Secret Manager によるパスワード認証

→--password-secret-version パラメータを使用
→リージョナルシークレットのリソース名を指定するだけ
→パスワードが平文で含まれない

🌍 リージョナルシークレット連携

→Cloud SQL と同じリージョンに配置が必要
→リージョナルエンドポイントで作成されたシークレットのみ
→グローバルエンドポイント作成のシークレットは非対応

🛡️ IAM 条件による細粒度制御

→特定シークレットへのアクセスのみ許可可能
→プロジェクト内の他シークレットへのアクセスを制限
→最小権限の原則を実現

🔄 複数認証方式のサポート

→IAM データベース認証 (ユーザー/SA/グループ)
→ビルトインユーザー + Secret Manager 認証 (今回)
→デフォルト root ユーザーは非対応 (MySQL)

🔧 技術仕様

API パラメータ

項目詳細
API エンドポイントPOST https://sqladmin.googleapis.com/sql/v1beta4/projects/{PROJECT_ID}/instances/{INSTANCE_NAME}/executeSql
gcloud コマンドgcloud sql instances execute-sql
パスワード指定--password-secret-version (gcloud) / リクエストボディ内フィールド (REST)
シークレットリソース名projects/{project}/locations/{location}/secrets/{secret}/versions/{version}
対応 SQL タイプDML, DDL, DQL
結果サイズ制限10 MB (超過時は partialResultMode で制御)

必要な IAM ロール

ロール説明
roles/cloudsql.adminCloud SQL Admin - フルアクセス
roles/cloudsql.instanceUserCloud SQL Instance User - SQL 実行権限
roles/cloudsql.studioUserCloud SQL Studio User - Studio 経由のアクセス
カスタムロールcloudsql.instances.executesql 権限を含む

REST API リクエストボディ

JSON 
{
  "database": "DATABASE_NAME",
  "sqlStatement": "SQL_STATEMENT",
  "user": "DATABASE_USER",
  "passwordSecretVersion": "projects/PROJECT_ID/locations/LOCATION/secrets/SECRET_ID/versions/VERSION",
  "partialResultMode": "FAIL_PARTIAL_RESULT"
}

📝 設定方法

前提条件

✓Cloud SQL インスタンスで Data API アクセスが有効化されていること
✓Secret Manager API が有効化されていること
✓データベースユーザーが作成済みであること (デフォルト root ユーザーは非対応)
✓適切な IAM ロールが付与されていること

Step 1: Data API を有効化

Bash 
# Data API アクセスを有効化
gcloud sql instances patch INSTANCE_NAME \
  --data-api-access=ALLOW_DATA_API

Step 2: データベースユーザーの作成

Bash 
# データベースユーザーを作成
gcloud sql users create DB_USER \
  --instance=INSTANCE_NAME \
  --password=INITIAL_PASSWORD

Step 3: Secret Manager にリージョナルシークレットを作成

Bash 
# リージョナルシークレットを作成
gcloud secrets create my-db-password \
  --location=REGION

# シークレットバージョンを追加 (パスワードを格納)
echo -n "INITIAL_PASSWORD" | gcloud secrets versions add my-db-password \
  --location=REGION \
  --data-file=-

Step 4: Secret Manager 認証で SQL 実行

Bash 
# Secret Manager 認証を使用して SQL ステートメントを実行
gcloud sql instances execute-sql INSTANCE_NAME \
  --database=my-database \
  --sql="SELECT * FROM users LIMIT 10;" \
  --user=DB_USER \
  --password-secret-version=projects/PROJECT_ID/locations/REGION/secrets/my-db-password/versions/latest

⚠️ デメリット・制約事項

制限事項:
✗リージョナルシークレットのみサポート (グローバルエンドポイントで作成されたシークレットは使用不可)
✗Cloud SQL インスタンスとシークレットは同じリージョンに配置が必要
✗MySQL のデフォルト root ユーザーでは Data API 認証は使用不可
✗Data API の結果サイズは 10 MB に制限
考慮すべき点:
→Secret Manager の API 呼び出し追加によるわずかなレイテンシ増加の可能性
→Secret Manager の利用料金が追加で発生 (アクセス回数に応じた課金)
→リージョナルシークレット作成にはリージョナルエンドポイント使用が必要
→Data API のリクエスト/レスポンス経路で中間ロケーションを経由する可能性

🎯 ユースケース

🚀 ユースケース 1: CI/CD パイプラインからのスキーマ管理

デプロイパイプラインで Cloud SQL インスタンスに対してスキーママイグレーションを実行。Cloud SQL Auth Proxy の設定なしに、安全にスキーマ変更を実行可能。

Bash 
# CI/CD パイプラインでの使用例
gcloud sql instances execute-sql production-instance \
  --database=app_db \
  --sql="@migration_001.sql" \
  --user=migration_user \
  --password-secret-version=projects/my-project/locations/us-central1/secrets/migration-password/versions/latest

🏢 ユースケース 2: マルチテナント環境でのデータベース管理

テナントごとに異なるデータベースユーザーとシークレットを管理。IAM 条件と組み合わせ、各テナント管理者が自テナントのシークレットのみにアクセスできる分離を実現。

Bash 
# テナントごとに異なるシークレットを使用
gcloud sql instances execute-sql shared-instance \
  --database=tenant_abc \
  --sql="SELECT count(*) FROM orders;" \
  --user=tenant_abc_admin \
  --password-secret-version=projects/my-project/locations/asia-northeast1/secrets/tenant-abc-password/versions/latest

🩺 ユースケース 3: 自動化されたデータベースヘルスチェック

Cloud Scheduler + Cloud Functions から定期的に Data API を呼び出し、ヘルスチェックやメトリクス収集を実行。長時間稼働のプロキシ接続維持が不要で、サーバーレス環境との相性が良い。

🌐 利用可能リージョン

Cloud SQL for MySQL と Cloud SQL for PostgreSQL が利用可能なすべてのリージョンで、Data API の Secret Manager 認証が利用可能です。

⚠️ 注意: Secret Manager のリージョナルシークレットは、Cloud SQL インスタンスと同じリージョンに作成する必要があります。

🔗 関連サービス

🗝️ Secret Manager

パスワードの安全な保管・管理・ローテーションを提供。リージョナルシークレット機能が本機能の基盤。

🔌 Cloud SQL Auth Proxy

クライアントからの接続を安全に仲介する従来のソリューション。Data API は Proxy 不要で SQL を実行可能。

IAM ユーザーやサービスアカウントでの認証方式。Secret Manager 認証はビルトインユーザー向けの代替手段。

🖥️ Cloud SQL Studio

ブラウザベースの SQL エディタ。Data API と同じ cloudsql.studioUser ロールを使用。
