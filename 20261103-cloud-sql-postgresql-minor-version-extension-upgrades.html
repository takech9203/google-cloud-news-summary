🐘 Cloud SQL for PostgreSQL Change (ロールアウト完了)

🔄 マイナーバージョンと拡張機能アップグレードのロールアウト完了

📅 リリース日: 2026-11-03

📝 概要

Cloud SQL for PostgreSQL の マイナーバージョン (14.24 / 15.19 / 16.15 / 17.11 / 18.6) と 8 つの拡張機能のアップグレードが完了しました。 新しいメンテナンスバージョンは [PostgreSQL version].R20261013.02_04 です。

特に PostgreSQL 18 系では 18.4 → 18.6 へ更新され、PostgreSQL bug #19616 のバックポート修正が含まれます。 サブトランザクションを持つアボート済みトランザクションがメモリ退避中にトランケートされた際に、論理デコーディングが不正な STREAM_ABORT メッセージを出力する問題が解消され、論理レプリケーションや CDC (Change Data Capture) の利用者にとって重要な修正です。

❌ Before (アップデート前の課題)

  • PostgreSQL 18.4 では、サブトランザクションを含むアボート済みトランザクションのメモリ退避時に、論理デコーディングが不正な STREAM_ABORT メッセージを出力する不具合 (bug #19616) があった
  • PostGIS は PG 13〜17 で 3.5.2、PG 18 で 3.6.0 と、メジャーバージョン間で拡張機能バージョンが分かれていた
  • pglogical も PG 17 以前 (2.4.5) と PG 18 (2.4.6) でバージョンが分かれ、各拡張機能のバグ修正・改善が未適用だった

✅ After (アップデート後の改善)

  • PostgreSQL 18.6 への更新で bug #19616 のバックポート修正が適用され、論理デコーディングの信頼性が向上
  • PostGIS が PG 13 以降で 3.6.4 に、pglogical が 2.4.8 に統一され、メジャーバージョン間の差異が解消
  • roaringbitmap が 0.5 → 1.2 へ大きく更新されるなど、各拡張機能の最新のバグ修正・機能改善を利用可能に

🛠️ 設定方法

📋 前提条件

✓Cloud SQL for PostgreSQL インスタンス (PostgreSQL 14〜18) を利用していること
✓メンテナンスバージョンの確認・更新には cloudsql.instances.update 権限が必要

ステップ 1: 現在のメンテナンスバージョンを確認する

Bash メンテナンスバージョンの確認 
gcloud sql instances describe INSTANCE_NAME \
  --format="value(maintenanceVersion)"

現在適用されているメンテナンスバージョンを確認します。R20261013.02_04 より古い場合、今後のメンテナンスで更新されます。

ステップ 2: (任意) セルフサービスメンテナンスで即時適用する

Bash セルフサービスメンテナンスの実行 
# 適用可能なメンテナンスバージョンを確認
gcloud sql instances describe INSTANCE_NAME \
  --format="value(availableMaintenanceVersions)"

# セルフサービスメンテナンスを実行
gcloud sql instances patch INSTANCE_NAME \
  --maintenance-version=POSTGRES_X_Y.R20261013.02_04

スケジュールされたメンテナンスを待たずに、任意のタイミングで最新のメンテナンスバージョンを適用できます。リードレプリカがある場合は、レプリカが先に更新されます。

ステップ 3: 拡張機能のカタログを手動で更新する

SQL 拡張機能カタログの更新 
-- インストール済み拡張機能のバージョンを確認
SELECT * FROM pg_extension;

-- 拡張機能を最新バージョンに更新 (例: PostGIS)
ALTER EXTENSION postgis UPDATE;
ALTER EXTENSION pglogical UPDATE;
⚠️ 重要: メンテナンス更新は拡張機能のバイナリを自動的にインストールしますが、データベースカタログは自動更新されません。 ALTER EXTENSION ... UPDATE を実行して、新しいバージョンを有効化する必要があります。

💡 メリット

💼 ビジネス面

✓データパイプラインの信頼性向上: 論理デコーディングの不具合修正により、CDC やレプリケーションを基盤とするデータ連携の安定性が高まる
✓運用負荷の軽減: マネージドサービスとしてマイナーバージョン・拡張機能の更新が自動的にロールアウトされ、パッチ適用作業が不要

🔬 技術面

✓論理デコーディングの修正 (bug #19616): PostgreSQL 18 で不正な STREAM_ABORT メッセージが出力される問題が解消され、サブスクライバー側での予期しない動作を防止
✓拡張機能バージョンの統一: PostGIS 3.6.4、pglogical 2.4.8 など、PostgreSQL メジャーバージョン間で拡張機能バージョンが揃い、バージョン差異による挙動の違いを考慮する必要が減少
✓roaringbitmap の大幅更新: 0.5 から 1.2 への更新により、大規模な整数集合の効率的な保存・集合演算に関する改善を利用可能

⚠️ デメリット・制約事項

🚧 制限事項

✗メンテナンス更新はインスタンスの再起動を伴うため、短時間のダウンタイムが発生する (Enterprise edition は平均 30 秒未満の接続断、Enterprise Plus edition はニアゼロダウンタイム)
✗拡張機能のデータベースカタログは自動更新されない。ALTER EXTENSION ... UPDATE の手動実行が必要
✗pgtt と roaringbitmap の新バージョンは PostgreSQL 12 以降、PostGIS 3.6.4 は PostgreSQL 13 以降が対象

🤔 考慮すべき点

💡 メンテナンスウィンドウの設定を推奨: ウィンドウを設定していない場合、更新は今後数週間以内の任意のタイミングで実行されます。業務影響を避けるにはメンテナンスウィンドウの設定を推奨します。
⚠️ PostGIS の挙動変更を確認: PostGIS のようなメジャー寄りの更新 (3.5.2 → 3.6.4) では、アプリケーションで利用している関数の挙動変更がないか事前にリリースノートを確認するとよいでしょう。
🚫 メンテナンスがスキップされるケース: エクスポートなどのインスタンス操作が実行中の場合やディスク使用率が 97% を超えている場合、メンテナンスはスキップされます。

🎯 ユースケース

📡 ユースケース 1: 論理レプリケーションを利用した CDC パイプラインの安定化

シナリオ: PostgreSQL 18 インスタンスで論理デコーディングを利用し、Datastream や pglogical で下流システムへデータを連携している。アボートされたトランザクションの処理で不正な STREAM_ABORT メッセージが問題となる可能性がある。

Bash セルフサービスメンテナンスで 18.6 を即時適用 
gcloud sql instances patch INSTANCE_NAME \
  --maintenance-version=POSTGRES_18_6.R20261013.02_04

効果: bug #19616 の修正により、ストリーミングレプリケーションプロトコル上の不正なメッセージが排除され、サブスクライバーやコネクタの予期しないエラーを防止できます。

🗺️ ユースケース 2: 地理空間ワークロードでの PostGIS 最新化

シナリオ: PostgreSQL 15 上で PostGIS 3.5.2 を利用して地理空間データを処理しており、3.6 系の修正・改善を取り込みたい。

効果: メンテナンス適用後に ALTER EXTENSION postgis UPDATE; を実行することで、PostgreSQL 13〜18 の全バージョンで PostGIS 3.6.4 に統一でき、環境間のバージョン差異を解消できます。
