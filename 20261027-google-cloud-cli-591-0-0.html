🔧 Google Cloud CLI 591.0.0 リリース

macOS 更新不具合の修正と多数の GA 昇格
⚠️ Breaking Change GA 一部 Beta
リリース日: 2026-10-27
🚨 最重要: macOS で gcloud CLI 590.0.0 / 590.0.1 を利用中の場合、gcloud components update が即時終了して更新できません。復旧には一度だけ gcloud components --flags-file=<(echo 'update:') の実行が必要です。

📋 概要

Google Cloud CLI バージョン 591.0.0 がリリースされた。最重要項目は Breaking Changes として告知された macOS 上の components update 不具合の修正である。590.0.0 / 590.0.1 では、macOS で gcloud components update を実行すると "WARNING: Known issue encountered updating Python modules" と出力した直後に処理が停止・即時終了し、最新リリースへの更新が一切できない状態になっていた。591.0.0 で問題自体は修正されたが、不具合は 590.x のインストール済み環境側に残存するため、該当ユーザーは一度だけワークアラウンドの実行が必要となる。

機能面では、Agent Registry の skills / publishers / findings コマンド群、Dataproc のフレキシブル構成フラグ、Network Security の WildFire 分析コマンド群と server-tls-policies の create/update など、多数のコマンド・フラグが GA に昇格。バンドル Python も 3.14.9 に更新された。

❌ Before (アップデート前の課題)

  • macOS の 590.0.0 / 590.0.1 では gcloud components update が "WARNING: Known issue encountered updating Python modules" を出力して即終了し、最新版へ更新不可能
  • Agent Registry の skills / skills revisions / publishers / findings は GA 前のトラックでのみ利用可能
  • Dataproc のフレキシブル構成フラグや WildFire 分析関連コマンド、server-tls-policies の create/update は GA 提供ではなく、本番利用に慎重な判断が必要
  • Bigtable テーブルのタイムスタンプ粒度を gcloud から指定する手段がなかった

✅ After (アップデート後の改善)

  • components update の macOS 不具合が修正され、590.x 環境も一度のワークアラウンド実行で復旧可能に
  • バンドル Python が 3.14.9 に更新
  • Agent Registry、Dataproc フレキシブル構成、Network Security (WildFire 分析 / server-tls-policies) など多数のコマンド・フラグが GA に昇格し本番利用が可能に
  • Bigtable の --timestamp-granularity、IAM の --discovery-uri / --actor-providers、GKE の --node-config-update-mode など新オプションを追加
🎯 対象ユーザー: gcloud CLI を利用するすべてのエンジニア。特に macOS で 590.0.0 / 590.0.1 を利用中のユーザーは即時の対応が必要。

🚨 Breaking Changes: macOS での components update 不具合の修正

⚠️ 問題の内容

  • macOS 上で gcloud components update を実行すると、"WARNING: Known issue encountered updating Python modules" と出力した直後に処理が停止・即時終了し、最新リリースへ更新できなかった
  • この不具合は 590.0.0 と 590.0.1 のリリースに含まれており、該当バージョンのインストール済み環境にはバグが残存する

🔧 ワークアラウンド (590.0.0 / 590.0.1 で止まっている場合のみ)

次のコマンドを一度だけ実行する。

Bash ワークアラウンドコマンド 
gcloud components --flags-file=<(echo 'update:')

📍 影響範囲

  • 589.0.0 以前、または 591.0.0 以降から更新するユーザーは影響を受けず、通常どおり gcloud components update を実行できる
  • ワークアラウンドが必要なのは、現在 590.0.0 または 590.0.1 で止まっているインストール環境のみ
  • 本件は Issue Tracker (issue 578071727) で追跡されている

📊 macOS 不具合の影響マトリクス

🚀 主要機能 (GA 昇格)

🤖 Agent Registry コマンド群の GA 昇格 GA

gcloud agent-registry skills、gcloud agent-registry skills revisions、gcloud agent-registry publishers、gcloud agent-registry findings の各コマンドグループが GA に昇格。

📊 Cloud Dataproc: フレキシブル構成フラグの GA 昇格 GA

  • clusters create / workflow-templates set-managed-cluster で --master-flexible-config、--worker-flexible-config、--secondary-worker-flexible-config が GA に昇格
  • clusters update でも --worker-flexible-config、--secondary-worker-flexible-config が GA に昇格

🛡️ Network Security: WildFire 分析と server-tls-policies の GA 昇格 GA

  • security-profiles wildfire-analysis の add-override / update-override / delete-override / add-inline-ml-exception / delete-inline-ml-exception が GA に昇格
  • firewall-endpoints create|update の WildFire 関連フラグが GA に昇格
  • firewall-endpoints wildfire-verdict-change-requests コマンドグループ (create / get / list) が GA に昇格
  • server-tls-policies create および update が GA に昇格

💻 Compute Engine: --identity-type フラグの昇格とサーキットブレーカー設定

  • compute instances create|update と instance-templates create の --identity-type フラグが beta / GA トラックに昇格
  • backend-services create|update にサーキットブレーカー関連フラグを追加 (--circuit-breakers-max-connections、--circuit-breakers-max-pending-requests、--circuit-breakers-max-requests、--circuit-breakers-max-requests-per-connection、--circuit-breakers-max-retries、update には --no-circuit-breakers)
  • beta compute instance-groups managed update-instances に --allowed-actions フラグ (restart-in-place を含む許可アクションを指定可能)、create / update には --update-policy-allowed-actions を追加 Beta

✨ その他の機能追加・変更

🐍 Google Cloud CLI 本体

バンドルされる Python を 3.14.9 に更新。

🗄️ Cloud Bigtable

bigtable instances tables create および bigtable tables create に --timestamp-granularity フラグを追加 (millis または micros)。マイクロ秒粒度は Enterprise Plus インスタンスのみサポート。

🔐 Cloud IAM (Workload Identity Federation)

  • workload-identity-pools providers create-oidc|update-oidc に --discovery-uri フラグを追加 (IdP がデフォルトの well-known パスを使用しない場合にカスタム OIDC ディスカバリ URI を指定)
  • 同コマンドに --actor-providers フラグを追加 (同一プール内のプロバイダーに対し、ID 委任用のアクタートークン発行を許可)

⚓ Kubernetes Engine

container node-pools update に --node-config-update-mode フラグを追加。ノードのライブ更新をトリガーでき、サポートされる値は LIVE_UPDATE_WITHOUT_DRAIN。

📁 Secure Source Manager Beta 昇格

beta source-manager branch-rules / hooks / issues / issues comments / pull-requests / pull-requests comments の各コマンドグループが beta に昇格。

🔑 Workspace Key Access 新規 Beta

beta workspace-key-access コマンドグループを追加。Workspace Key Access のエンドポイント、設定、オペレーションを管理。

🏗️ App Engine

beta app migrate-to-run が、表示する service.yaml 内の環境変数値をマスクするように変更。保存される service.yaml ファイルには元の値が保持される。

🔄 Database Migration

database-migration conversion-workspaces create|update に --ai-processing-location フラグを追加。Gemini 機能が変換ワークスペースのデータを処理するロケーションを設定でき、空の値を渡すと設定済みロケーションを削除できる。

⚙️ 技術仕様: 新フラグの主な仕様

フラグ / コマンドサービストラック内容
--timestamp-granularity (millis / micros) Cloud Bigtable - テーブルのタイムスタンプ粒度を指定。micros は Enterprise Plus のみ
--discovery-uri / --actor-providers Cloud IAM - Workload Identity Pool の OIDC プロバイダー構成を拡張
--node-config-update-mode (LIVE_UPDATE_WITHOUT_DRAIN) Kubernetes Engine - ノードをドレインせずにライブ更新
--allowed-actions (restart-in-place など) Compute Engine (MIG) beta update-instances で許可するアクションを指定
--ai-processing-location Database Migration - Gemini 機能のデータ処理ロケーションを指定

🎯 ユースケース

1️⃣ macOS 開発端末の一斉復旧

シナリオ: 社内の macOS 開発端末の多くが gcloud CLI 590.0.0 / 590.0.1 で止まっており、最新機能やセキュリティ更新を受け取れていない。

Bash 実装例 
# バージョン確認
gcloud version

# 590.0.0 / 590.0.1 の場合のみ一度だけ実行
gcloud components --flags-file=<(echo 'update:')

# 以降は通常どおり
gcloud components update

効果: 更新が止まっていた端末が 591.0.0 以降に復旧し、以降は通常の更新フローに戻れる。

2️⃣ GKE ノード設定のドレインなし更新

シナリオ: ノードプールの設定変更のたびにノードのドレインが発生し、ワークロードの再スケジュールによる影響が課題になっている。

Bash 実装例 
gcloud container node-pools update NODE_POOL_NAME \
  --cluster=CLUSTER_NAME \
  --node-config-update-mode=LIVE_UPDATE_WITHOUT_DRAIN

効果: ドレインを伴わないライブ更新をトリガーでき、ワークロードへの影響を抑えてノード設定を反映できる。

3️⃣ Workload Identity Federation でカスタム OIDC ディスカバリを利用

シナリオ: 社内 IdP がデフォルトの well-known パスで OIDC ディスカバリドキュメントを公開しておらず、Workload Identity Federation の構成ができなかった。

Bash 実装例 
gcloud iam workload-identity-pools providers update-oidc PROVIDER_ID \
  --workload-identity-pool=POOL_ID \
  --location=global \
  --discovery-uri=https://idp.example.com/custom/.well-known/openid-configuration

効果: 非標準パスの IdP でも Workload Identity Federation を構成できる。
