🤖 Proactive Generative Knowledge Assist V2

Agent Assist GA Gemini Enterprise for CX
2026-06-10

📋 概要

Agent Assist の Proactive Generative Knowledge Assist (PGKA) V2 が一般提供 (GA) として正式リリース。コンタクトセンターのヒューマンエージェントと顧客間の会話をリアルタイムで分析し、エージェントが必要とする情報を先回りして提案する AI 支援機能の最新バージョンです。

チャットと音声の両チャネルで利用可能。カスタマーサポートセンター、ヘルプデスク、テクニカルサポートなど、ナレッジベースを活用した顧客対応を行うすべての組織に適しています。

💡 V2 の 3 つの主要強化ポイント: リッチ検索コンテキスト、複数クエリ提案、トリガーイベントのきめ細やかな制御

🔄 Before / After 比較

❌ V1 の課題

  • 単一のクエリ提案のみ。複数トピックでも一つの検索候補のみ
  • 検索コンテキストの制御が限定的。クエリのみで検索精度が不十分
  • トリガーイベントが顧客メッセージ受信時のみに固定

✅ V2 の改善

  • キーバリューペアによるリッチ検索コンテキストで検索精度が大幅向上
  • 複数の関連クエリを同時提案。複数トピックに対応可能
  • CUSTOMER_MESSAGE / AGENT_MESSAGE / END_OF_UTTERANCE から選択可能

🏗️ アーキテクチャ図

PGKA V2 は会話をリアルタイムで監視し、設定されたトリガーイベントに基づいて検索クエリとコンテキストを自動生成します。

sequenceDiagram
    participant C as 顧客
    participant A as ヒューマンエージェント
    participant AA as Agent Assist (PGKA V2)
    participant DS as Data Store Agent (Dialogflow CX)
    participant KB as ナレッジベース

    C->>A: 問い合わせメッセージ
    A->>AA: AnalyzeContent API (会話コンテキスト送信)

    Note over AA: トリガーイベント判定

    AA->>AA: リッチ検索コンテキスト生成 (キーバリューペア抽出)
    AA->>AA: 複数クエリ候補生成

    AA->>DS: プライマリクエリ + 検索コンテキスト
    DS->>KB: ナレッジ検索
    KB-->>DS: 関連ドキュメント
    DS-->>AA: 回答 + ソース

    AA-->>A: クエリ提案 + 回答 (複数候補)
    A->>C: 回答提供

    Note over A,AA: エージェントは追加クエリを SearchKnowledge API に送信可能

プライマリクエリは自動的にナレッジベースに送信され、追加のクエリ候補はエージェントが必要に応じて手動で実行できます。

⚡ 主要機能

🔍 リッチ検索コンテキスト (Search Context)

会話の内容からキーバリューペアを自動抽出し、検索クエリに付加情報として追加。検索精度が向上し、より関連性の高いナレッジ記事が提案されます。

→ disable_query_search_context フィールドで有効/無効を制御可能
→ 無効化した場合、クエリのみでナレッジベース検索が実行される

📝 複数クエリ提案 (Multiple Suggested Queries)

会話中に議論される複数のトピックに対して、それぞれ関連する検索クエリを生成。

→ プライマリクエリは自動的にナレッジ検索に送信
→ 追加のクエリはエージェントが SearchKnowledge API で手動実行可能
→ enableQuerySuggestionWhenNoAnswer で回答なし時もクエリ候補を表示

🎯 トリガーイベントのカスタマイズ

suggestion_trigger_event フィールドで提案のトリガーを制御。ワークフローに合わせた柔軟な対応が可能です。

ランタイム会話処理 (Python)

Python 
from google.cloud import dialogflow_v2beta1 as dialogflow

def analyze_content(project_id, conversation_id, participant_id, text):
    client = dialogflow.ParticipantsClient()
    participant_path = client.participant_path(
        project_id, conversation_id, participant_id
    )
    text_input = {"text": text, "language_code": "ja"}
    response = client.analyze_content(
        participant=participant_path,
        text_input=text_input
    )

    for suggestion_result in response.human_agent_suggestion_results:
        if suggestion_result.suggest_knowledge_assist_response:
            knowledge_answer = suggestion_result.suggest_knowledge_assist_response
            print(f"Suggested Query: {knowledge_answer.suggested_query}")
            print(f"Answer: {knowledge_answer.suggested_query_answer}")

    return response

✅ メリット

📊 ビジネス面

✓ 顧客対応時間の短縮 - 情報検索時間削減で AHT 改善
✓ 顧客満足度の向上 - 正確で迅速な回答で CSAT スコア向上
✓ 育成コスト削減 - 新人でも適切な情報が自動提案

🔧 技術面

✓ 検索精度の向上 - リッチコンテキストによる意味的検索
✓ 柔軟なイベント駆動 - 3 種類のトリガーで様々なワークフローに対応
✓ 非同期処理対応 - クエリ提案のみの軽量モードが選択可能

⚠️ デメリット・制約事項

制限事項:
  • Dialogflow CX の Flow-based Data Store Agent または Playbook-based Data Store Agent の事前構築が必須
  • 大量のナレッジドキュメントがある場合はレイテンシに影響する可能性
  • 会話初期段階ではコンテキストが少なく精度が低い場合がある
💡 推奨事項:
  • ゴールデンセット (20-30 件) を作成して品質を事前評価
  • Data Store の信頼度レベルを Medium に設定すると提案数が増加 (関連性低い提案も含まれる可能性あり)
  • カスタムプロンプトやドキュメントメタデータの充実により検索精度を継続的に改善

💼 ユースケース

🖥️ テクニカルサポートセンター

シナリオ: 顧客がクラウドサービスの設定エラーについて問い合わせ。会話中に認証、ネットワーク、権限の複数トピックが議論される。

設定: CUSTOMER_MESSAGE + 検索コンテキスト有効 + enableQuerySuggestionWhenNoAnswer: true

効果: 複数クエリ提案により、認証設定、ネットワーク構成、IAM 権限それぞれについて関連ドキュメントが自動提案。問題の切り分けと解決を迅速に実施可能。

📞 音声対応コールセンター

シナリオ: 電話サポートで顧客が製品の使い方を質問。音声認識と連動して発話終了時に提案を生成。

設定: END_OF_UTTERANCE + 検索コンテキスト有効

効果: 顧客の発話が終わった瞬間に関連情報が提案。音声対応特有のリアルタイム性要件に対応し、保留時間を最小化。

🏦 金融機関のカスタマーサービス

シナリオ: 口座開設、ローン審査、投資商品について多岐にわたる問い合わせ。コンプライアンス情報を含む正確な回答を支援。

効果: リッチ検索コンテキストにより顧客属性や取引履歴を加味した検索が実行され、適用される規制やポリシーに関する正確なドキュメントが提案される。

📌 まとめ

PGKA V2 の一般提供開始により、コンタクトセンターのエージェントは会話コンテキストに基づいたより精度の高い情報提案を受けられるようになります。

既に Agent Assist を利用している組織は baseline_model_version を "2.0" に更新することで V2 の恩恵を受けることができます。新規導入を検討している組織にとっても本格的な AI 支援エージェント環境を構築する好機です。
