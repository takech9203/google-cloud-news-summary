EmailV2 v44.0 / SSH v24.0 / Google Threat Intelligence v25.0 / Salesforce v21.0
☁️ Google SecOps Marketplace (Response Integrations) GA (Generally Available) 📅 リリース日: 2026-11-20

📌 概要

2026 年 11 月 20 日、Google SecOps Marketplace (Response Integrations) の 4 つの統合に対して、 セキュリティ強化 (hardening) を主眼としたバージョンアップがリリースされました。 新機能の追加ではなく、SOAR プレイブックが外部データ (メール添付ファイル、アクションパラメータ、外部 URL、ケース番号) を扱う際の 攻撃経路を塞ぐ防御的な修正が中心です。

SOAR の統合はアラートに含まれる攻撃者由来のデータ (メール、URL、エンティティ値) をそのまま処理することが多く、 入力経由の攻撃 (パストラバーサル、コマンドインジェクション、SSRF、SOQL インジェクション) に対する堅牢性はプラットフォーム全体のセキュリティに直結します。

❌ アップデート前の課題

  • EmailV2: 添付ファイル名のディレクトリパス要素 (例: ../) が保存先パスに反映され得る構造で、保存先ディレクトリ外への書き込み (パストラバーサル) のリスク。1 つの添付ファイルの保存失敗がアクション全体の停止につながることも
  • SSH: パラメータ値 (IP アドレス、ユーザー名、プロセス名など) がシェルコマンドに渡される際の入力検証・エスケープが不十分で、コマンド注入のリスク
  • Google Threat Intelligence: Submit File の External URLs の検証が緩く、内部ネットワークやメタデータエンドポイントへの SSRF のリスク。タイムアウトやリダイレクト上限が未明示
  • Salesforce: Case Number が SOQL クエリに組み込まれる際のエスケープがなく、SOQL インジェクションのリスク

✅ アップデート後の改善

  • EmailV2 v44.0: ファイル名からパス要素を除去 (strip) してから保存し、パストラバーサルを防止。保存失敗はログに記録してスキップし、実行を継続
  • SSH v24.0: 入力検証とシェル引数エスケープを強化し、リモートホストへの不正な値の混入を防止
  • GTI v25.0: HTTP/HTTPS かつ公開ルーティング可能な IP に解決される URL のみ許可 (SSRF 対策)。60 秒タイムアウト + 最大 5 回リダイレクト制限、ダウンロード処理を認証情報から分離
  • Salesforce v21.0: Case Number を SOQL クエリ組み立て前にエスケープし、SOQL インジェクションを防止

⚙️ 技術仕様

🧩 影響を受けるアクションの役割 (公式ドキュメントより)

📧 EmailV2 - Download Email Attachments

指定したメールの添付ファイルを Google SecOps サーバー上の指定パス (Download Path) に保存する

📧 EmailV2 - Save Email Attachments To Case

メールの添付ファイルを現在のケースの Case Wall に保存する

📧 EmailV2 - Wait for Email from User

Send Email への返信を待機し、Fetch Response Attachments 有効時は返信の添付ファイルも取得する

🖥️ SSH - Block IP Address in iptables / Shutdown Machine / Terminate Process など

リモートサーバーに SSH 接続し、IP アドレスのブロック、マシンのシャットダウン、プロセスの終了などを実行する。Remote Server、Block IP Address、Process などのパラメータがコマンドに渡される

🛰️ Google Threat Intelligence - Submit File

ファイルを解析のために送信する。External URLs パラメータにはファイル取得元のパブリック URL をカンマ区切りで指定できる

☁️ Salesforce - Add Comment / Close Case / Get Case / Update Case

Case Number パラメータで対象ケースを指定し、コメント追加・クローズ・取得・更新を行う

✅ メリット

💼 ビジネス面

✓ SOAR プラットフォームの攻撃対象領域の縮小: フィッシング調査など攻撃者由来のデータを日常的に処理するプレイブックにおいて、統合経由でのサーバー侵害リスクが低減する
✓ 運用の継続性向上: EmailV2 で一部の添付ファイル保存に失敗してもアクションが停止せずログ記録のうえ継続されるため、プレイブックの失敗による対応遅延が減る

🔬 技術面

✓ 多層防御の強化: ファイル書き込み (パス除去)、シェル実行 (エスケープ)、外部通信 (URL/IP 検証・タイムアウト)、クエリ発行 (エスケープ) と、統合の出口ごとに入力サニタイズが実装された
✓ SSRF 対策の明確化: Submit File の外部 URL ダウンロードが公開 Web に限定され、内部ネットワークやクラウドメタデータへの到達が遮断される。認証情報の分離により資格情報の漏えい経路も塞がれる
✓ 挙動が仕様として明示: タイムアウト 60 秒・リダイレクト 5 回などの制限が明示され、プレイブック設計時に考慮できる

⚠️ デメリット・制約事項

⚠️ 考慮すべき点:
⚠ Google Threat Intelligence v25.0 では、内部ネットワーク上の URL や HTTP/HTTPS 以外の URL を External URLs に指定する運用は動作しなくなる。該当する使い方をしているプレイブックは、File Paths パラメータ (サーバー上のファイルパス指定) などへの切り替えが必要
⚠ 大きなファイルや応答の遅いサイトからのダウンロードは 60 秒のタイムアウトに達して失敗する可能性がある
⚠ EmailV2 ではファイル名のパス要素が除去されるため、添付ファイル名のディレクトリ構造に依存した後続処理がある場合は見直しが必要
⚠ 統合のアップデートで問題が発生した場合は、Content Hub のバージョンロールバック機能で旧バージョンへ復帰できる

🎯 ユースケース

📨 ユースケース 1: フィッシングメール調査プレイブックの安全性向上

シナリオ: EmailV2 の Download Email Attachments / Save Email Attachments To Case を使い、報告された不審メールの添付ファイルを自動で取得・解析している。攻撃者はファイル名に ../ を含む添付ファイルを送り付け、SOAR サーバー上の意図しない場所への書き込みを狙う可能性がある。

効果: v44.0 では添付ファイル名のパス要素が除去されるため、保存先は指定したダウンロードフォルダ内に限定される。また、保存に失敗した添付ファイルがあってもスキップして処理が続くため、大量添付メールの調査が途中で止まらない。

🛰️ ユースケース 2: Submit File の外部 URL 取得を安全に利用

シナリオ: 脅威インテリジェンス調査で、外部サイトにホストされている検体ファイルの URL を Google Threat Intelligence の Submit File (External URLs) に渡して解析している。細工された URL が内部 IP に解決されると SSRF の踏み台になるリスクがあった。

効果: v25.0 では HTTP/HTTPS かつ公開 IP に解決される URL のみダウンロードされるため、内部ネットワークへの到達が遮断される。タイムアウトとリダイレクト上限により、ダウンロードの長時間ハングやリダイレクトチェーンの悪用も防げる。

🧯 ユースケース 3: インシデント封じ込めアクション (SSH) の堅牢化

シナリオ: プレイブックから SSH 統合の Block IP Address in iptables や Terminate Process を実行し、アラートのエンティティ値 (IP アドレス、プロセス名) をそのままパラメータに渡して封じ込めを自動化している。

効果: v24.0 の入力検証とシェル引数エスケープにより、エンティティ値にシェルメタ文字が含まれていてもリモートホストで意図しないコマンドが実行されるリスクが低減する。

📝 まとめ

今回のアップデートは、SOAR 統合が攻撃者由来のデータを処理する際の代表的な攻撃経路 (パストラバーサル、コマンドインジェクション、SSRF、SOQL インジェクション) を塞ぐ セキュリティ強化パッケージです。

特にフィッシング調査や封じ込め自動化で EmailV2・SSH・Google Threat Intelligence・Salesforce 統合を利用している環境では、 Content Hub から新バージョンへの更新を早期に実施することを推奨します。 あわせて、内部 URL を External URLs に渡しているプレイブックなど、強化された検証により動作が変わるケースがないかの確認も行ってください。
