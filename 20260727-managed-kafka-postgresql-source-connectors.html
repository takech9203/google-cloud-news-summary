Managed Service for Apache Kafka Kafka Connect 提供開始 (Feature)

🐘 PostgreSQL Source コネクタ提供開始
Cloud SQL 版 / Generic 版で CDC をフルマネージド化

📅 リリース日: 2026-07-27

📌 概要

Managed Service for Apache Kafka の Kafka Connect で、Cloud SQL for PostgreSQL Source コネクタと Generic PostgreSQL Source コネクタの 2 種類が作成可能になりました。 いずれも Debezium PostgreSQL コネクタのインスタンスとして動作し、PostgreSQL の行レベル変更 (CDC: Change Data Capture) を読み取って Kafka トピックへ書き込みます。

データベースの変更をリアルタイムにイベントとして扱いたいデータエンジニアや、イベント駆動アーキテクチャを構築するアーキテクトにとって、 CDC パイプラインをフルマネージドで構築できる重要なアップデートです。

❌ Before (アップデート前)

  • PostgreSQL 用のマネージド Source コネクタがなく、Debezium を自前でホスト・運用する必要があった
  • Connect クラスタはカスタムコネクタプラグインのアップロード非対応のため、Debezium PostgreSQL コネクタをマネージド環境で使う手段がなかった

✅ After (アップデート後)

  • Cloud SQL 版: IAM データベース認証経由で Cloud SQL の行レベル変更をマネージドにストリーミング
  • Generic 版: セルフマネージド / オンプレミスなど任意の PostgreSQL からも CDC が可能
  • コンソールや gcloud managed-kafka connectors create で完結、Debezium ワーカーの運用が不要
  • 専用のトラブルシューティングドキュメントも提供

PostgreSQL の WAL (Write-Ahead Log) から Debezium PostgreSQL Source コネクタが行レベルの変更を読み取り、 テーブルごとに作成される Kafka トピックへ変更イベントを送信します。下流のコンシューマはトピックを購読して、 リアルタイム処理や他システムへの複製を行います。

⚡ 主要機能

1️⃣ Cloud SQL for PostgreSQL Source コネクタ

✓Cloud SQL for PostgreSQL の行レベル変更を読み取り、Kafka トピックへ書き込み
✓認証は IAM データベース認証 (Managed Kafka サービスアカウントを Cloud SQL の IAM ユーザーとして追加)
✓ネットワークはプライベート IP / Private Service Connect / パブリック IP の 3 方式に対応 (プライベート IP または PSC を推奨)

2️⃣ Generic PostgreSQL Source コネクタ

✓Cloud SQL 以外の PostgreSQL (セルフマネージド、オンプレミスなど) の行レベル変更を読み取り
✓パスワードは Secret Manager のシークレットで管理 (プレーンテキストは非サポート)
✓テーブルの複製・リストアなどのユースケースにも対応

3️⃣ 初期スナップショット + 継続的な変更キャプチャ

✓コネクタ初期化時にデータベースの初期スナップショットを作成
✓行を持つ全テーブルに対応する Kafka トピックを自動作成し、各行の変更イベントを対応するトピックへ送信
✓稼働中は継続的に変更イベントを送信

4️⃣ 柔軟なテーブルフィルタリング

✓デフォルトではデータベース内のすべての非システムテーブルをキャプチャ
✓schema.include.list / schema.exclude.list / table.include.list / table.exclude.list で対象を絞り込み可能

📝 設定ファイルの例 (Cloud SQL for PostgreSQL Source)

YAML Cloud SQL 版コネクタ設定 
connector.class: io.debezium.connector.postgresql.PostgresConnector
database.dbname: DATABASE_NAME
driver.cloudSqlInstance: PROJECT_ID:REGION:INSTANCE_NAME
driver.enableIamAuth: "true"
driver.ipTypes: IP_TYPES
driver.sslmode: disable
key.converter: org.apache.kafka.connect.json.JsonConverter
key.converter.schemas.enable: "false"
plugin.name: pgoutput
slot.name: SLOT_NAME
table.include.list: TABLE_LIST
topic.prefix: TOPIC_PREFIX
value.converter: org.apache.kafka.connect.json.JsonConverter
value.converter.schemas.enable: "true"

📝 設定ファイルの例 (Generic PostgreSQL Source)

YAML Generic 版コネクタ設定 (Secret Manager でパスワード管理) 
connector.class: io.debezium.connector.postgresql.PostgresConnector
database.dbname: DATABASE_NAME
database.hostname: HOSTNAME
database.user: DATABASE_USER
database.password: ${directory:/var/secrets:PROJECT_ID-SECRET_NAME-SECRET_VERSION}
key.converter: org.apache.kafka.connect.json.JsonConverter
key.converter.schemas.enable: "false"
plugin.name: pgoutput
topic.prefix: TOPIC_PREFIX
value.converter: org.apache.kafka.connect.json.JsonConverter
value.converter.schemas.enable: "true"

🛠️ 設定方法 (Cloud SQL for PostgreSQL Source の例)

📋 前提条件:
  • Managed Service for Apache Kafka クラスタと、それに関連付けられた Connect クラスタ
  • Cloud SQL 版: データベースを持つ Cloud SQL for PostgreSQL インスタンス
  • Generic 版: PostgreSQL データベースと、パスワードを保存した Secret Manager シークレット (Connect クラスタに設定)
1

論理デコーディングの有効化

Cloud SQL インスタンスのデータベースフラグ cloudsql.logical_decoding を On に設定します (設定によりデータベースが再起動します)。

2

CDC 対象テーブルのパブリケーション作成

SQL パブリケーション作成 
-- すべてのテーブルを対象にする場合
CREATE PUBLICATION dbz_publication FOR ALL TABLES;

-- 特定のテーブルのみ対象にする場合
CREATE PUBLICATION dbz_publication FOR TABLE "schema_name"."table_name";

デフォルトではコネクタはパブリケーション名 dbz_publication を使用します。

3

IAM データベースユーザーの作成と権限付与

Bash IAM サービスアカウントユーザーの作成 
gcloud sql users create service-PROJECT_NUMBER@gcp-sa-managedkafka.iam \
  --instance=INSTANCE_NAME \
  --type=cloud_iam_service_account

その後、cloudsqlsuperuser ロールを持つユーザーで接続し、以下を実行します。

SQL レプリケーション権限と SELECT 権限の付与 
ALTER USER "service-PROJECT_NUMBER@gcp-sa-managedkafka.iam" WITH REPLICATION;
GRANT SELECT ON ALL TABLES IN SCHEMA "SCHEMA_NAME" TO "service-PROJECT_NUMBER@gcp-sa-managedkafka.iam";
GRANT USAGE ON SCHEMA SCHEMA_NAME TO "service-PROJECT_NUMBER@gcp-sa-managedkafka.iam";
4

コネクタの作成

Bash gcloud によるコネクタ作成 
gcloud managed-kafka connectors create CONNECTOR_ID \
  --location=LOCATION \
  --connect-cluster=CONNECT_CLUSTER_ID \
  --config-file=CONFIG_FILE

コネクタは Connect クラスタと同じロケーションに作成する必要があります。作成後、初期スナップショットが実行され、テーブルごとのトピックへ変更イベントの送信が始まります。

💪 メリット

💼 ビジネス面

✓運用負荷の削減: Debezium ワーカーの構築・パッチ適用・スケーリングが不要になり、CDC パイプラインの運用コストを削減
✓リアルタイムデータ活用の加速: DB の変更を即座にイベント化し、リアルタイム分析やイベント駆動のビジネスプロセスを迅速に実現

⚙️ 技術面

✓標準技術 (Debezium) ベース: 既存の Debezium の知識・設定 (トピック命名規則、スナップショット動作など) をそのまま活用可能
✓セキュアな認証: Cloud SQL 版は IAM データベース認証、Generic 版は Secret Manager 管理で、認証情報を平文で書く必要なし
✓柔軟なネットワーク接続: プライベート IP / Private Service Connect / パブリック IP (Cloud NAT 経由) の 3 方式から選択可能

⚠️ デメリット・制約事項

🚫 制限事項

✗Generic 版でプレーンテキストパスワードは非サポート (database.password には Secret Manager のシークレットパスのみ指定可能)
✗Connect クラスタへのカスタムコネクタプラグインのアップロードは引き続き非サポート
✗コネクタは Connect クラスタと同じロケーションに作成する必要がある

🤔 考慮すべき点

⚠️レプリケーションスロットの管理: コネクタが一時停止・失敗・削除されてもスロットは自動削除されない。放置すると WAL ファイルが保持され続けてディスクを圧迫し、障害の原因になり得る。コネクタ削除時は手動でスロットを削除し、WAL ディスク使用量のアラート設定を推奨
⚠️同じデータベースに複数のコネクタインスタンスを作成する場合は、slot.name にそれぞれ一意の値を指定する
⚠️Cloud SQL 版の論理デコーディング有効化 (cloudsql.logical_decoding) はデータベースの再起動を伴う
⚠️トピックプレフィックスは Cloud SQL for PostgreSQL Source コネクタごとに一意の値を選択する

🎯 ユースケース

🛒 ユースケース 1: Cloud SQL の変更をリアルタイムに下流システムへ連携

シナリオ: EC サイトの注文テーブル (Cloud SQL for PostgreSQL) の INSERT/UPDATE/DELETE を、在庫管理や通知などの下流マイクロサービスにリアルタイムで伝搬したい。

YAML 注文テーブルのみを CDC 対象にする設定 (抜粋) 
table.include.list: '"public"."orders"'
topic.prefix: ec-orders
slot.name: ec_orders_slot

効果: アプリケーション側にイベント発行ロジックを追加することなく、データベースの変更を確実にイベント化でき、イベント駆動アーキテクチャを疎結合に実現できる。

🏢 ユースケース 2: オンプレミス PostgreSQL からのデータ複製・移行

シナリオ: オンプレミスで稼働する PostgreSQL のテーブルを、Generic PostgreSQL Source コネクタで Kafka 経由で他システムに複製し、段階的なクラウド移行や分析基盤へのデータ供給を行う。

効果: 初期スナップショット + 継続的な CDC により、ソースデータベースを止めずにデータを複製・同期でき、移行のダウンタイムを最小化できる。

💰 料金・利用可能リージョン

💵 料金

コネクタは Connect クラスタ上で稼働します。Managed Service for Apache Kafka はプロビジョニングしたリソース (vCPU、RAM、ローカルストレージ) と消費したリソース (永続ストレージ、データ転送) に対して課金されます。

💡 コスト最適化のヒント: Kafka クラスタと Connect クラスタを同一リージョンに配置すると、レイテンシとリージョン間ネットワーク転送コストを削減できます。 詳細は料金ページを参照してください。

🌏 利用可能リージョン

リリースノートおよびドキュメントにリージョン固有の記載はありません。コネクタは Connect クラスタと同じロケーションに作成する必要があります。 詳細は公式ドキュメントを参照してください。

📝 まとめ

Managed Service for Apache Kafka に PostgreSQL 向けの CDC Source コネクタ (Cloud SQL 版 / Generic 版) が追加され、 Debezium ベースの変更データキャプチャをフルマネージドで構築できるようになりました。

PostgreSQL を起点としたリアルタイムデータパイプラインやイベント駆動アーキテクチャを検討しているチームは、 まずドキュメントの手順に沿って論理デコーディングの有効化とコネクタ作成を試し、 レプリケーションスロットの監視 (WAL ディスク使用量アラート) の設定を忘れずに行うことを推奨します。
