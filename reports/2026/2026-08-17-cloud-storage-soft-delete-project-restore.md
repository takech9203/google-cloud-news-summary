# Cloud Storage: プロジェクト削除時のソフト削除バケット保持とプロジェクト復元対応

**リリース日**: 2026-08-17

**サービス**: Cloud Storage

**機能**: プロジェクト削除時のソフト削除有効バケットの保持・復元

**ステータス**: GA (Feature)

📊 [このアップデートのインフォグラフィックを見る](https://takech9203.github.io/google-cloud-news-summary/20260817-cloud-storage-soft-delete-project-restore.html)

## 概要

Google Cloud プロジェクトを削除した場合でも、ソフト削除 (Soft Delete) が有効なバケットが一定期間保持されるようになりました。保持期間内に削除済みプロジェクトを復元すると、バケットはプロジェクト削除時点の状態に復元されます。

これまで、ソフト削除はバケットやオブジェクトの誤削除・悪意ある削除からの保護機能として提供されていましたが、プロジェクト自体が削除された場合には、ソフト削除が有効であってもバケットやオブジェクトを復元できませんでした。今回のアップデートにより、プロジェクト削除という最も影響範囲の大きいオペレーションミスに対しても、Cloud Storage のデータ保護が拡張されます。

誤ってプロジェクトを削除してしまった場合のデータ損失リスクを大幅に軽減できるため、プロジェクトのライフサイクル管理を行う管理者や、データ保護要件の厳しいワークロードを運用するすべてのユーザーにとって重要なアップデートです。

**アップデート前の課題**

- プロジェクトを削除すると、バケットにソフト削除が有効であっても、ソフト削除によるバケット・オブジェクトの復元はできなかった
- プロジェクトの 30 日間の復元期間内にプロジェクトを復元しても、Cloud Storage などの一部サービスのリソースは早期に削除されるため、完全には復元できない可能性があった
- プロジェクト削除ミスに対する Cloud Storage データの保護手段が実質的に存在しなかった

**アップデート後の改善**

- プロジェクト削除後も、ソフト削除が有効なバケットは「ソフト削除の保持期間」と「プロジェクトの復元期間」のいずれか短い期間だけ保持されるようになった
- 保持期間内にプロジェクトを復元すると、削除時点でライブだったバケットはライブ状態で復元される
- プロジェクト削除時点でソフト削除状態だったバケットも、それぞれの保持期間が終了するまでソフト削除状態のまま維持される (個別に復元可能)

## サービスアップデートの詳細

### 主要機能

1. **プロジェクト削除時のバケット保持**
   - ソフト削除が有効なバケットは、プロジェクト削除後も「ソフト削除の保持期間」または「Google Cloud プロジェクトの復元期間」のいずれか短い期間だけ保持される
   - この期間が経過すると、バケットは完全に削除される

2. **プロジェクト復元時のバケット復元**
   - 保持期間内に削除済みプロジェクトを復元すると、プロジェクト削除時点でライブだったバケットはライブバケットとして復元される
   - プロジェクト削除時点でソフト削除状態だったバケットは、それぞれの保持期間が終了するまでソフト削除状態のまま維持される

3. **ソフト削除無効バケットとの動作差異**
   - ソフト削除が有効になっていないバケットは、プロジェクト削除時に即座に削除される可能性があり、復元できない場合がある
   - プロジェクト削除に対する保護を得るには、バケットのソフト削除ポリシーを有効に保つ必要がある

## 技術仕様

### 保持期間と復元の関係

| 項目 | 詳細 |
|------|------|
| バケットの保持期間 | ソフト削除の保持期間とプロジェクト復元期間のいずれか短い方 |
| プロジェクトの復元期間 | 30 日間 (`DELETE_REQUESTED` 状態) |
| ソフト削除の保持期間 | デフォルト 7 日間、7〜90 日間で設定可能 (0 で無効化) |
| ソフト削除のデフォルト | 対応するすべての新規バケットで自動的に有効 |
| 復元後のバケット状態 | プロジェクト削除時点の状態 (ライブ → ライブ、ソフト削除 → ソフト削除) |
| ソフト削除無効バケット | プロジェクト削除時に即時削除される可能性があり、復元不可の場合がある |

### 留意すべき既存のソフト削除仕様

| 項目 | 詳細 |
|------|------|
| ソフト削除中のリソース | 読み取り・変更・上書き不可。一覧表示と復元のみ可能 |
| バケット名の競合 | 同名のライブバケットが存在する場合、削除されるまで復元不可 |
| 非対応バケット | Rapid Bucket を使用するゾーンバケットはソフト削除非対応 |
| 復元後のストレージクラス | ソフト削除オブジェクトの復元後は Standard クラスに書き込まれる |

## 設定方法

この保護は、バケットのソフト削除ポリシーが有効であれば自動的に適用されます。追加の設定は不要ですが、保持期間の確認・変更は以下の手順で行えます。

### 手順

#### ステップ 1: バケットのソフト削除ポリシーを確認

```bash
gcloud storage buckets describe gs://BUCKET_NAME \
    --format="default(soft_delete_policy)"
```

現在のソフト削除保持期間を確認します。

#### ステップ 2: 保持期間の変更 (必要に応じて)

```bash
# 保持期間を 30 日に設定 (7〜90 日で指定可能)
gcloud storage buckets update gs://BUCKET_NAME --soft-delete-duration=30d
```

保持期間の変更は、変更後に削除されたリソースにのみ適用されます。

## メリット

### ビジネス面

- **データ損失リスクの低減**: プロジェクト削除という影響範囲の大きい操作ミスからも Cloud Storage データを保護でき、事業継続性が向上する
- **復旧オペレーションの簡素化**: プロジェクトを復元するだけでバケットが削除時点の状態に戻るため、バックアップからの再構築作業が不要になる

### 技術面

- **追加設定不要**: ソフト削除はデフォルトで有効なため、多くのバケットで自動的にこの保護が適用される
- **一貫した復元動作**: ライブバケットはライブ状態、ソフト削除中のバケットはソフト削除状態と、削除時点の状態が正確に維持される

## デメリット・制約事項

### 制限事項

- 保持期間は「ソフト削除の保持期間」と「プロジェクトの復元期間 (30 日)」の短い方であるため、デフォルトの 7 日間設定ではプロジェクト復元期間 (30 日) より早くバケットが完全削除される
- ソフト削除が無効なバケットは、プロジェクト削除時に即時削除される可能性があり、復元できない場合がある
- Rapid Bucket を使用するゾーンバケットはソフト削除に対応していない

### 考慮すべき点

- プロジェクト削除からの確実な復元を重視する場合、ソフト削除の保持期間を 30 日以上に設定することで、プロジェクト復元期間全体をカバーできる
- ソフト削除されたデータには保持期間中もストレージ料金が発生するため、保持期間の延長はコストとのトレードオフになる
- プロジェクト復元時、関連付けられていた Cloud Billing アカウントは自動的には再接続されないため、復元後に請求設定の確認が必要

## ユースケース

### ユースケース 1: プロジェクトの誤削除からのデータ復旧

**シナリオ**: 運用整理の一環で不要プロジェクトを削除したところ、本番データを含むバケットを持つプロジェクトを誤って削除してしまった。

**実装例**:
```bash
# 削除済みプロジェクトの状態を確認
gcloud projects describe PROJECT_ID
# lifecycleState: DELETE_REQUESTED であることを確認

# プロジェクトを復元
gcloud projects undelete PROJECT_ID
```

**効果**: 保持期間内であれば、プロジェクト復元によりソフト削除有効バケットが削除時点の状態で復元され、バックアップからの再構築なしにデータを回復できる。

### ユースケース 2: プロジェクトライフサイクル管理におけるデータ保護基準の策定

**シナリオ**: 組織内で多数のプロジェクトを管理しており、プロジェクト削除時のデータ保護基準を定めたい。

**効果**: 重要データを保持するバケットのソフト削除保持期間を 30 日以上に設定する運用ルールを定めることで、プロジェクト復元期間 (30 日) 全体にわたってバケットの復元可能性を確保できる。タグを使用して新規バケットのデフォルト保持期間を組織全体で統制することも可能。

## 料金

ソフト削除されたオブジェクトは、保持期間が終了して完全に削除されるまでストレージ料金が発生し続けます。プロジェクト削除後の保持期間中も同様にストレージが保持されます。

- Standard 以外のストレージクラスで最小保存期間の終了前にソフト削除されたオブジェクトには、早期削除料金が発生する
- 一時オブジェクトを大量に扱うバケットでは、ソフト削除によるコスト増が大きくなる可能性があるため、ソフト削除を無効化したバケットの利用が推奨される
- ソフト削除の有効化・無効化の判断には、コストと使用状況に基づく Soft Delete Recommender の活用が可能

詳細は [Cloud Storage の料金ページ](https://cloud.google.com/storage/pricing) を参照してください。

## 関連サービス・機能

- **Resource Manager (プロジェクトの削除と復元)**: プロジェクト削除後 30 日間の `DELETE_REQUESTED` 状態と `gcloud projects undelete` による復元機能が、今回のバケット復元の前提となる
- **オブジェクトのバージョニング**: 非現行バージョンのオブジェクトも削除時にソフト削除され、多層的なデータ保護を構成できる
- **Bucket Lock / Object Retention Lock**: 保持ポリシーによる削除防止に加え、ソフト削除が追加の保護レイヤーとして機能する
- **Soft Delete Recommender**: コストと使用状況に基づき、バケットごとのソフト削除の有効化・無効化を推奨する
- **タグ (Tags)**: 新規バケットのデフォルトのソフト削除保持期間 (7〜90 日または無効) を組織的に制御できる

## まとめ

プロジェクト削除というリカバリーが最も困難だった操作ミスに対して、Cloud Storage のソフト削除による保護が拡張された重要なアップデートです。ソフト削除はデフォルトで有効なため多くの環境で自動的に恩恵を受けられますが、デフォルトの保持期間は 7 日間であり、プロジェクト復元期間 (30 日) より短い点に注意が必要です。重要データを保持するバケットについては、コストとのバランスを考慮しつつ保持期間の延長を検討することを推奨します。
