# Google Cloud Contact Center as a Service (CCaaS): プレリリースノート 6.13

**リリース日**: 2026-09-16

**サービス**: Google Cloud Contact Center as a Service (CCaaS)

**機能**: 次期バージョン 6.13 プレリリースノート (修正予定の問題一覧)

**ステータス**: Announcement (プレリリースノート) / Fix

📊 [このアップデートのインフォグラフィックを見る](https://takech9203.github.io/google-cloud-news-summary/20260916-ccaas-6-13-prerelease.html)

## 概要

Google Cloud CCaaS の次期バージョン (6.13 になる見込み) のプレリリースノートが公開されました。プレリリースノートは、次期バージョンのリリース時に提供される予定の変更内容を事前に知らせるもので、コンタクトセンター管理者はリリース前に影響範囲を評価し、運用チームへの周知やテスト計画を準備できます。なお、公式リリースノートには「次期バージョンは 6.13 より大きい番号になる可能性がある」と明記されています。

今回のプレリリースノートは新機能の追加ではなく、既知の問題の修正 (Fixed) のみで構成されています。修正は約 36 件と多岐にわたり、通話ルーティング・キュー制御、レポーティング・データエクスポート、エージェントデスクトップ (アダプター)、Salesforce / Kustomer などの CRM 統合、Web SDK のアクセシビリティまで、CCaaS の広範な領域をカバーしています。

特に、エージェントが通話終了後も「通話中」扱いのままになり新規コールを受けられなくなる問題や、コールスパイク時にキャパシティ制限がバイパスされる問題、レポートから通話が欠落する問題など、コンタクトセンターの運用品質・レポート精度に直結する修正が多く含まれており、CCaaS を運用するすべての組織に関係するアップデートです。

**アップデート前の課題 (修正対象の既知の問題)**

- エンドユーザーの最初のメッセージ前に終了したチャットで、セッションメタデータとデータフィードファイルが外部ストレージに出力されなかった
- 通話終了後もエージェントがアクティブ (通話中) と誤認識され、Available への変更や新規コールの着信が妨げられることがあった
- 突発的なコールスパイク時にキャパシティ制限がバイパスされ、エージェントの可用性が必要最低水準を下回ることがあった
- All Call History や Voice Inbound (IVR) History などのレポートから、デフレクトされた通話やボイスメール前に切断された通話が欠落していた
- Salesforce の click-to-dial 発信が誤ったケースに関連付けられたり、既存アカウントではなく重複アカウントが作成されたりしていた

**アップデート後の改善 (6.13 で修正予定)**

- チャット・通話のセッションデータ、履歴レポート、Agent Activity Timeline の記録精度が改善される
- エージェント状態管理 (通話終了後のステータス、転送不応答時のアクティブ状態残留) が正しく動作するようになる
- キュー・ルーティングの信頼性 (キャパシティ制限、multicast フォールバック無効時のスタック、エージェント優先度オーバーライド) が向上する
- Salesforce / Kustomer 統合の発信者情報表示、ケース関連付け、OAuth Refresh Token Rotation 対応が改善される
- Web SDK のキーボードナビゲーション (WAI-ARIA) とスクリーンリーダー対応が改善される

## サービスアップデートの詳細

今回のプレリリースノートに含まれる修正を、カテゴリ別に整理します。

### 通話ルーティング・キュー制御の修正

1. **モバイルインバウンドコールの接続失敗**
   - エージェント側のレッグは正常に接続する一方、エンドユーザー側のレッグが `Unknown error` で失敗する問題を修正
2. **エージェント間転送での状態残留**
   - 受信側エージェントが応答しなかった場合に、通話終了後もそのエージェントが無期限に「通話中 (アクティブ)」として扱われる問題を修正
3. **通話終了後のエージェント状態の誤認識**
   - システムが通話終了後もエージェントを通話中と誤認識し、Available への変更を妨げたり、新規コールの着信をサイレントにブロックしたりする問題を修正
4. **コールスパイク時のキャパシティ制限バイパス**
   - 突発的なコール急増時にキャパシティ制限がバイパスされ、エージェント可用性が必要最低水準を下回る問題を修正
5. **ミスドオファーによるキュー内スタック**
   - オファーに応答されなかった通話がキュー内に永久にスタックし、他の対応可能なエージェントにルーティングされない問題を修正 (multicast フォールバック無効のキューで発生)
6. **エージェント優先度オーバーライドのルーティング不良**
   - エージェント優先度オーバーライド使用時に、最上位ランクのエージェントへ正しくルーティングされない問題を修正
7. **超過容量デフレクションの不発火**
   - エージェントがアウトバウンドコールをキューにウォーム転送した際に、over-capacity デフレクションがトリガーされない問題を修正
8. **SIP リダイレクト時のカスタムヘッダー欠落**
   - 直通インバウンドコールが超過容量キューにデフレクトされ、そのキューが SIP URI にリダイレクトする際、カスタム SIP ヘッダーが含まれない問題を修正
9. **キュー内アナウンス間隔の短縮**
   - インバウンド IVR コールで数分に設定したキュー内アナウンス間隔が、約 60 秒に誤って短縮される問題を修正
10. **通話終了処理の遅延によるタイムアウト**
    - 終了した通話の処理遅延がタイムアウトエラーを引き起こす問題を修正

### レポーティング・データエクスポートの修正

1. **セッションメタデータ・データフィードの欠落**
   - エンドユーザーの最初のメッセージ前に終了したチャットで、セッションメタデータとデータフィードファイルが外部ストレージから欠落する問題を修正
2. **履歴レポートからの通話欠落**
   - デフレクトされた通話が All Call History および Voice Inbound (IVR) History レポートから欠落する問題を修正
   - ボイスメールを残す前に発信者が切断した通話が All Call History および Voice Inbound History レポートから欠落する問題を修正
   - 接続前にキャンセルされた手動・カスケードアウトバウンドコールが、チームフィルター適用時の Call History レポートから欠落する問題を修正
3. **Agent Activity Timeline レポートの誤記録**
   - マイク障害により応答できなかった通話が「picked up」として誤って記録される問題を修正
   - 手動のログイン・ログアウトが該当エージェントではなく `System` に誤って帰属される問題を修正
4. **重複・矛盾したイベント記録**
   - エンドユーザーの離脱とエージェントのチャット終了がほぼ同時に発生した場合に、「chat finished」イベントが重複して報告される問題を修正
   - エスカレーションされた音声通話が「応答済み」と「放棄」の両方として誤って報告される問題を修正
5. **録音の音声欠落**
   - 通話の途中でバーチャルタスクアシスタントが実行された際に、エージェント音声の一部が録音から欠落する問題を修正

### エージェントデスクトップ・アダプターの修正

1. **ライブデータの消失**
   - エージェントデスクトップでライブコール・チャットのデータが失われる問題を修正
2. **Dismiss ボタンの 409 エラー**
   - エージェントがメッセージを送信した後も Dismiss ボタンが有効なまま残り、クリックすると 409 エラーになる問題を修正
3. **アダプターの表示不良・スタック**
   - エージェントが着信通知を受け取った直後にエンドユーザーが切断すると、エージェントアダプターが空白になり新規コールが届かなくなる問題を修正
   - 接続に失敗した通話がコールアダプター上で無音の「connecting」状態のままスタックする問題を修正
4. **ラップアップパネルのフリーズ**
   - ネットワーク再接続後、送信自体は完了しているにもかかわらずラップアップ (ディスポジション) パネルがフリーズする問題を修正
5. **言語・表示の不整合**
   - アウトバウンドコールのキュー一覧に古い情報が表示され、エージェントの選択言語と一致しないキューに通話が配置される可能性があった問題を修正
   - 通話転送メニューとボイスメール転送メニューが、エージェントの選択言語ではなく英語で表示される問題を修正
   - Agents > Filter Settings ページの上下矢印アイコンが不適切なスケールで描画される問題を修正

### CRM 統合 (Salesforce / Kustomer) の修正

1. **Kustomer: 発信者情報の非表示**
   - 直通インバウンドコールで、発信者情報がコールアダプターの Incoming call ページに表示されない問題を修正
2. **Salesforce: click-to-dial のケース関連付け不良**
   - click-to-dial のアウトバウンドコールが、発信元のケースではなく直近のオープンケースに誤って関連付けられる問題を修正
   - 同一電話番号に紐づく他のケースへ誤ってリンクされ、所有権が再割り当てされる問題を修正
3. **Salesforce: 重複アカウントの作成**
   - 着信コールが既存アカウントにリンクされず、重複した Salesforce アカウントが作成される問題を修正
4. **Salesforce: OAuth Refresh Token Rotation 環境での接続断**
   - OAuth Refresh Token Rotation を強制する組織で Salesforce CRM 接続がドロップする問題を修正

### その他 (メール・Agent Assist・Web SDK) の修正

1. **メールアカウントの再接続不能**
   - 一時的な認証失敗の後、メールアカウントが無期限に切断されたままになる問題を修正
2. **Agent Assist の誤検知アラート**
   - 通話中の長い無音により接続タイムアウトが発生し、誤検知のエラーアラートがトリガーされる問題を修正
3. **Web SDK のアクセシビリティ改善**
   - プレチャット・チャット画面のメニューが WAI-ARIA キーボードナビゲーション標準に準拠していなかった問題を修正
   - スクリーンリーダーがチャット画面の Text size オプションの目的を識別できなかった問題を修正

## メリット

### ビジネス面

- **レポート精度の向上**: 履歴レポートからの通話欠落や重複イベントが解消され、KPI 測定・要員計画・コンプライアンス報告の信頼性が向上する
- **顧客体験の改善**: キュー内スタックや接続失敗、キャパシティ制限バイパスの解消により、待ち時間や取りこぼしのリスクが減少する

### 技術面

- **エージェント状態管理の信頼性向上**: 通話終了後の状態残留やアダプターのスタックが解消され、エージェントの稼働率低下やサイレントな着信ブロックを防げる
- **CRM 統合の安定化**: Salesforce のケース関連付け・重複アカウント・OAuth Refresh Token Rotation 対応により、CRM データの整合性と接続の安定性が向上する
- **アクセシビリティ準拠**: Web SDK の WAI-ARIA 対応・スクリーンリーダー対応により、エンドユーザー向けチャットのアクセシビリティ要件への適合が進む

## デメリット・制約事項

### 考慮すべき点

- これはプレリリースノートであり、記載内容は正式リリース時に変更される可能性がある。また、次期バージョンの番号は 6.13 より大きくなる可能性があると明記されている
- 実際にインスタンスへ適用されるタイミングは、各組織が選択しているデプロイメントスケジュールに依存する
- 新機能の追加は含まれておらず、今回のプレリリースノートはすべて既知の問題の修正である

## 関連サービス・機能

- **Salesforce 統合**: click-to-dial のケース関連付け、重複アカウント作成、OAuth Refresh Token Rotation 対応など複数の修正が含まれる
- **Kustomer 統合**: 直通インバウンドコールでの発信者情報表示の修正が含まれる
- **Agent Assist**: 通話中の長い無音に起因する誤検知アラートの修正が含まれる
- **Web SDK**: エンドユーザー向けチャット画面のアクセシビリティ (WAI-ARIA、スクリーンリーダー) 修正が含まれる

## まとめ

Google Cloud CCaaS 次期バージョン (6.13 見込み) のプレリリースノートは、ルーティング、レポーティング、エージェントデスクトップ、CRM 統合にまたがる約 36 件の修正で構成されており、コンタクトセンターの運用品質とデータ精度に直結する内容です。CCaaS を運用する組織は、自社で影響を受けている既知の問題が含まれていないかを確認し、自社のデプロイメントスケジュールに沿った適用タイミングを把握しておくことを推奨します。特に Salesforce / Kustomer 統合やレポートの欠落に関する回避策を運用中の場合は、正式リリース後に不要になるかを検証してください。
