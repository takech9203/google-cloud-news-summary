SAP on Google Cloud Google Security Operations GA (一般提供) 自動脅威対応は Preview
📅 リリース日: 2026-10-30

🛡️ Google SecOps for SAP が一般提供 (GA) 開始

SAP テレメトリを Google SecOps に統合し、統一的な可視性・脅威検知・自動対応を実現

📌 概要

Google SecOps for SAP が GA となりました。ビジネスクリティカルな SAP のテレメトリ (インフラログ・アプリケーションログ) を Google Security Operations (Google SecOps) に統合し、SAP 環境に対する統一的な可視性、脅威検知、セキュリティ対応機能を提供します。 SAP 環境とセキュリティ運用の間に存在していた「可視性のギャップ」を解消し、SecOps アナリストが SAP 固有の脅威を IT 環境全体の脅威と並べて検知・調査・対応できます。

📥 ① SAP ログ取り込み GA

SAP RISE およびセルフマネージド SAP 環境 (Google Cloud / オンプレミス / 他クラウド) からのログ取り込み

🚨 ② SAP 固有の検知ルール GA

Google SecOps Detection Rules GitHub リポジトリで提供される SAP 固有の YARA-L 脅威検知ルール

🤖 ③ 自動脅威対応・封じ込め Preview

SAP RFC Gateway と SOAR プレイブックによる自動脅威対応・封じ込め機能

👥 対象ユーザー

SAP Basis 管理者 (ログ抽出構成)、SecOps チーム/アナリスト (脅威監視)、CISO・コンプライアンスチーム (ポスチャー監視・規制遵守)

🔄 Before / After

❌ アップデート前の課題

  • SAP の独自ログ形式を SIEM に取り込むにはカスタムのログパイプラインの構築・保守が必要
  • SAP 環境とそれ以外でセキュリティ監視がサイロ化。SAP 固有の脅威 (不正な構成変更、権限昇格、RFC の悪用など) の検知には深い SAP 専門知識が必要
  • SAP システム内の脅威封じ込め (ユーザーロックなど) は手動対応が中心で、SIEM/SOAR の自動化ワークフローから実行する標準手段がなかった

✅ アップデート後の改善

  • SAP RISE とセルフマネージド環境の両方に対応した標準のログ取り込みパスが GA。SAP 専用標準パーサーが生ログを UDM に自動正規化
  • Google のセキュリティ専門家がキュレーションした SAP 固有の YARA-L 検知ルールを GitHub (rules/community/sap) からインポートするだけで脅威を検知
  • SAP RFC Gateway (Cloud Run 上の HTTP-to-RFC ブリッジ) と SOAR プレイブックで、ユーザーロックやセッション強制終了を自動実行 (Preview)

💡 2 つのワークフロー: SAP 環境からインフラ・アプリケーションログを収集して Google SecOps に取り込む「インバウンドパイプライン」と、検知した脅威に対して SOAR プレイブックから SAP RFC Gateway 経由で封じ込めアクションを SAP システムに実行する「アウトバウンドパイプライン」で構成されます。

⚡ 主要機能

📥 1. SAP ログ取り込み GA

→SAP RISE 環境: インフラログは SAP LogServ がクラウドストレージ (Cloud Storage / Amazon S3 / Azure Blob Storage) に書き出し、Google SecOps がフィード経由で取得。アプリケーションログは Application Telemetry Collector が RFC プロトコルで抽出し、Bindplane サーバー経由で転送
→セルフマネージド環境: SAP ホストの Bindplane エージェントがインフラログを収集し、中央の Application Telemetry Collector がアプリケーションログを抽出。いずれも Bindplane サーバー経由で Google SecOps に転送
→SAP 専用標準パーサーが、複雑な SAP ログを構造化された UDM 形式に自動変換

🚨 2. SAP 固有の YARA-L 脅威検知ルール GA

→Google SecOps Detection Rules GitHub リポジトリの rules/community/sap ディレクトリで公式提供
→不正な構成変更・権限昇格・RFC 悪用などの脅威を検知
→データテーブル (SAP_ADMIN_USERS、production_systems、sensitive_abap_programs、sensitive_roles、sensitive_tables など) で自社の SAP ランドスケープに合わせたチューニングが可能
→ルールの運用状態 (Detecting / Alerting / Risk scoring) を個別に設定可能

🤖 3. 自動脅威対応・封じ込め Preview

→SAP RFC Gateway: Cloud Run 上で動作するコンテナ化された HTTP-to-RFC ブリッジ。SAP の RFC 機能を Google SecOps が安全に呼び出せる REST エンドポイントとして公開
→プレイブックがアラートの UDM フィールドから SAP ユーザー名やシステム ID を自動的に読み取るため、対応アクションごとのパラメータ手入力が不要
→Gemini によるケースサマリー生成 (脅威の説明、推奨調査手順、修復アクションの提案) も活用可能

📥 ステップ 1: ログ取り込みの構成

環境 (RISE / セルフマネージド) に応じたパスでログ収集を構成し、Google SecOps フィードまたは Bindplane 経由で取り込みます。取り込み確認は UDM 検索で行います。

UDM Search 取り込み確認クエリ 
metadata.log_type = "SAP_SECURITY_AUDIT"

🚨 ステップ 2: 検知ルールのインポートと有効化

GitHub の rules/community/sap から YARA-L ルールファイル (.yaral) をダウンロードし、Google SecOps の Detection > Rules and Detections > Rules Editor に貼り付けて保存します。インポートされたルールはデフォルトで無効のため、各ルールの運用状態 (Detecting / Alerting / Risk scoring) を設定し、データテーブルに自社環境の値を投入します。

🤖 ステップ 3: 自動対応の構成 (Preview、オプション)

SAP RFC Gateway を Cloud Run にデプロイし、リモートエージェントのサービスアカウントに Cloud Run 起動元 (roles/run.invoker) ロールを付与します。

Bash SAP RFC Gateway のデプロイ 
gcloud run deploy sap-rfc-gateway \
  --image=us-docker.pkg.dev/sap-core-eng-products/sap-rfc-gateway/google-cloud-sap-rfc-gateway:latest \
  --region=REGION \
  --service-account=SERVICE_ACCOUNT_EMAIL \
  --set-env-vars=GATEWAY_GCS_BUCKET=gs://BUCKET_NAME \
  --vpc-egress=all-traffic \
  --network=VPC_NETWORK_NAME \
  --subnet=VPC_SUBNET_NAME \
  --port=8080

その後、Google SecOps の Response > Integrations Setup で SAP ERP 統合インスタンスを作成し、Cloud Run サービス URL とリモートエージェントを指定します。

💡 メリット

💼 ビジネス面

✓エンタープライズ全体の統一的な可視性: オンプレミス、クラウド、SAP RISE 環境を含む IT インフラ全体の脅威を一元監視。CISO やコンプライアンスチームのポスチャー管理・規制対応を支援
✓ビジネスクリティカルデータの保護: Google の脅威インテリジェンスとキュレーション済み SAP 固有検知により、財務記録・顧客情報・知的財産を防御
✓運用効率の向上: カスタムログパイプラインの構築・保守が不要になり、既存の SecOps チームが SAP の深い専門知識なしで SAP 脅威にほぼリアルタイムで対応可能

⚙️ 技術面

✓標準パーサーによる UDM 正規化: SAP 固有のログ形式を意識せず、他のログソースと同じ UDM 検索・集計・検知の仕組みで扱える
✓マルチクラウド/ハイブリッド対応: Google Cloud 上の SAP だけでなく、オンプレミスや他クラウドのセルフマネージド SAP、SAP RISE (LogServ の Cloud Storage / S3 / Azure Blob 配信) にも対応
✓検知から封じ込めまでの自動化: YARA-L 検知 → アラート → ケース生成 → SOAR プレイブック → RFC Gateway 経由の緩和アクションを自動化。Gemini のケース要約で調査も加速

⚠️ デメリット・制約事項

🚧 制限事項
  • 自動脅威対応・封じ込め機能 (SAP RFC Gateway と SOAR プレイブック) は Preview であり、Pre-GA 利用規約が適用され、サポートが限定される場合がある
  • GitHub からインポートした YARA-L ルールはデフォルトで無効のため、各ルールの有効化とデータテーブルの投入 (本番システム ID、管理者ユーザー、機密 ABAP プログラムなど) が必要
  • カスタム YARA-L ルールを書く場合、SAP インスタンス情報と対象ユーザー名をアラートの UDM フィールドにマッピングしないと、プレイブックが緩和コマンドを正しい SAP インスタンスにルーティングできない
🤔 考慮すべき点
  • SAP RFC Gateway は SAP アプリケーションサーバーに直接接続できる VPC ネットワークが必要。SAP JCo ライブラリと SAP Crypto ライブラリ (SAP からの入手が必要) を Cloud Storage に配置する必要がある
  • Bindplane はサードパーティ製品であり、Bindplane 関連の問題はサードパーティベンダーのサポート対象となる
  • RISE 環境では SAP LogServ のプロビジョニング状況を SAP ECS 担当者と確認する必要があり、SAP 側 (LogServ 含む) の問題は SAP サポートの管轄となる

🔗 関連サービス・機能

→Google Security Operations (SecOps): 基盤となる SIEM/SOAR プラットフォーム。UDM 正規化、YARA-L 検知、ケース管理を提供
→Cloud Run: SAP RFC Gateway (HTTP-to-RFC ブリッジ) の実行基盤
→Secret Manager: SAP 接続の認証情報 (RFC ユーザー、SNC 証明書、PSE ファイル) の安全な管理
→Cloud Storage: SAP LogServ からのログ配信先、SAP JCo / Crypto ライブラリと gateway_config.json の格納先
→Gemini in Google SecOps: ケースサマリー生成、推奨調査手順の提示、自然言語による脅威ハンティングの高速化
→Bindplane (サードパーティ): SAP ホストからのログ収集・転送エージェント/サーバー

📝 まとめ

Google SecOps for SAP の GA により、これまでサイロ化しがちだった SAP 環境のセキュリティ監視を、カスタムパイプラインの構築なしに Google SecOps へ統合できるようになりました。 SAP RISE・セルフマネージドを問わず SAP を運用している組織は、まずログ取り込みと GitHub の YARA-L 検知ルールの導入から始め、 Preview の自動対応機能 (SAP RFC Gateway + SOAR プレイブック) は非本番環境で評価することを推奨します。
