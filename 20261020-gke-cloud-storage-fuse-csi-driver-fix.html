☁️ GKE: Cloud Storage FUSE CSI driver の
Pod 起動失敗問題が解決 🎉

Google Kubernetes Engine Cloud Storage FUSE CSI driver ✅ Fixed (解決済み)
📅 リリース日: 2026-10-20

📌 概要

2026 年 10 月 2 日に公表された、Cloud Storage FUSE CSI driver の DaemonSet Pod (gcsfusecsi-node) が特定のノードプール上で起動に失敗する既知の問題が 解決 (RESOLVED) されました。

元の問題は、コントロールプレーンが 1.36.3-gke.1244000 以降にアップグレードされた際、新しい DaemonSet がホストパス /proc/sys/fs/fuse をディレクトリとして要求するのに対し、古いカーネルで動作するノードプール (すべての ubuntu_containerd、および古い cos_containerd) ではこのパスがディレクトリとして存在せず、hostPath のタイプチェックが失敗して Pod がクラッシュするというものでした。Cloud Storage バケットをマウントする AI/ML やデータ処理のワークロードが影響を受けていました。

✅ ポイント: 今回の修正により、クラスタのコントロールプレーンを修正済みバージョンへアップグレードするだけで問題を解消できるようになりました。ノードプール側の変更は不要です。

❌ アップデート前の課題 (2026-10-02 時点)

  • バージョンスキューにより gcsfusecsi-node Pod が MountVolume.SetUp failed ... /proc/sys/fs/fuse is not a directory エラーで起動失敗
  • ubuntu_containerd 向け修正は「対応中」で、コントロールプレーンを 1.36.3-gke.1244000 より前へダウングレードする以外の回避策なし
  • cos_containerd はノードプール側を 1.34.6-gke.1154000 以降 / 1.35.3-gke.1389000 以降へアップグレードする必要あり
  • Cloud Storage FUSE CSI ボリュームのマウント失敗で、学習データ・モデルの読み込みに支障の可能性

✅ アップデート後の改善 (2026-10-20)

  • 問題が正式に 解決 (RESOLVED) とアナウンス
  • コントロールプレーンを 1.36.5-gke.1032000 以降 または 1.37.1-gke.1552000 以降 へアップグレードすれば、ubuntu_containerd および古い cos_containerd でも修正される
  • 1.36.4 系に留まる場合向けに 8 つの緩和パッチバージョンを提供
  • ダウングレードやアップグレード保留という暫定運用から脱却可能に

🔧 サービスアップデートの詳細

1️⃣ 問題の解決 (RESOLVED)

→2026 年 10 月 2 日に公表された Cloud Storage FUSE CSI driver の既知の問題が解決
→対象は ubuntu_containerd および古い cos_containerd ノードプールを持つクラスタ

2️⃣ 修正済みコントロールプレーンバージョン

1.36.5-gke.1032000 以降 1.37.1-gke.1552000 以降
✓コントロールプレーンのアップグレードのみで修正が適用され、ノードプール側の変更は不要

3️⃣ 1.36.4 系向けの緩和パッチ (8 バージョン)

1.36.4 系に留まりたいクラスタ向けに、以下の緩和パッチバージョンが提供されました。

1.36.4-gke.1247001 1.36.4-gke.1247002 1.36.4-gke.1391001 1.36.4-gke.1391003 1.36.4-gke.1495001 1.36.4-gke.1495003 1.36.4-gke.2046001 1.36.4-gke.2202002

🛠️ 設定方法 (修正の適用手順)

📋 前提条件

✓Cloud Storage FUSE CSI driver (GcsFuseCsiDriver アドオン) を有効にしたクラスタで、10 月 2 日公表の問題の影響を受けている (または受ける可能性がある) こと
✓クラスタのメンテナンスウィンドウ・アップグレードポリシーを確認済みであること
1現在のバージョンと影響状況を確認
Bash バージョン・OS イメージ・Pod 状態の確認 
# コントロールプレーンとノードプールのバージョン、OS イメージを確認
gcloud container clusters describe CLUSTER_NAME \
  --location=LOCATION \
  --format="value(currentMasterVersion)"

gcloud container node-pools list --cluster=CLUSTER_NAME --location=LOCATION \
  --format="table(name,version,config.imageType)"

# gcsfusecsi-node Pod の状態を確認
kubectl get pods -n kube-system -l k8s-app=gcs-fuse-csi-driver -o wide
💡 判定: コントロールプレーンが 1.36.3-gke.1244000 以降で、ubuntu_containerd または古い cos_containerd ノードプールが存在する場合は影響対象です。
2コントロールプレーンを修正済みバージョンへアップグレード
Bash コントロールプレーンのアップグレード 
# 利用可能なバージョンを確認
gcloud container get-server-config --location=LOCATION

# コントロールプレーンを修正済みバージョンへアップグレード
gcloud container clusters upgrade CLUSTER_NAME \
  --master \
  --cluster-version=1.36.5-gke.1032000 \
  --location=LOCATION

1.36.5-gke.1032000 以降、1.37.1-gke.1552000 以降、または 1.36.4 系の緩和パッチバージョンを指定します。

3修正の適用を確認
Bash Pod とマウント状態の確認 
# gcsfusecsi-node Pod がすべてのノードで Running になっていることを確認
kubectl get pods -n kube-system -l k8s-app=gcs-fuse-csi-driver -o wide

# Cloud Storage FUSE ボリュームを使用する Pod のマウント状態を確認
kubectl describe pod POD_NAME -n NAMESPACE

⚖️ メリットと考慮すべき点

💼 ビジネス面のメリット

✓暫定運用からの脱却: ubuntu_containerd 利用者はコントロールプレーンのダウングレードやアップグレード保留を解消し、通常のアップグレードサイクルに復帰できる
✓AI/ML ワークロードの安定稼働: Cloud Storage バケットをマウントする学習・推論ワークロードのマウント失敗リスクが解消される

🔩 技術面のメリット

✓ノードプール変更が不要: コントロールプレーンのアップグレードのみで修正が適用され、ノードプールの再作成やノードの再起動を伴う大規模な変更を回避できる
✓柔軟なバージョン選択: 1.36.5 以降 / 1.37.1 以降への移行に加え、1.36.4 系に留まるための緩和パッチも用意されており、クラスタのバージョン戦略に応じて選択できる

⚠️ 考慮すべき点 (制約事項)

!修正の適用にはコントロールプレーンのアップグレードが必要であり、メンテナンスウィンドウ内での計画的な実施が望ましい
!1.36.4 緩和パッチは特定の 8 バージョンに限定されるため、リリースチャンネルで利用可能か事前に確認する必要がある
!コントロールプレーンのダウングレードで回避していたクラスタは、アップグレード経路 (スキップ可能なバージョン) を確認してから修正済みバージョンへ移行する

🎯 ユースケース

🤖 ユースケース 1: Ubuntu ノードプールを使う AI/ML クラスタの正常化

シナリオ: ubuntu_containerd ノードプールで GPU ワークロードを実行しており、Cloud Storage FUSE で学習データをマウントしている。10 月 2 日の問題のためコントロールプレーンのアップグレードを保留していた。

Bash 実装例 
gcloud container clusters upgrade CLUSTER_NAME \
  --master \
  --cluster-version=1.37.1-gke.1552000 \
  --location=LOCATION

効果: アップグレード保留を解除し、ノードプールを変更することなく gcsfusecsi-node Pod の起動失敗を解消できる。

📌 ユースケース 2: 1.36.4 系を維持したいクラスタへの緩和パッチ適用

シナリオ: 社内の検証ポリシー上、マイナーバージョンを 1.36 に固定したまま問題だけを解消したい。

効果: 1.36.4-gke.1247001 などの緩和パッチバージョンを指定してアップグレードすることで、マイナーバージョンを維持しつつ修正を適用できる。

📝 まとめ

10 月 2 日に公表された Cloud Storage FUSE CSI driver の Pod 起動失敗問題が解決され、コントロールプレーンを 1.36.5-gke.1032000 以降、1.37.1-gke.1552000 以降、または 1.36.4 系の緩和パッチへアップグレードするだけで修正を適用できるようになりました。

本問題のためにアップグレードを保留またはダウングレードで回避していたクラスタ (特に ubuntu_containerd ノードプール利用クラスタ) は、修正済みバージョンへの計画的なアップグレードを実施してください。
