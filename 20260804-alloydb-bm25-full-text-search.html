AlloyDB for PostgreSQL Preview
📅 リリース日: 2026-08-04

🔍 BM25 インデックスによる全文検索

pg_textsearch 拡張機能で、確率的ランキングをマネージド PostgreSQL 内で直接実行

📝 概要

AlloyDB for PostgreSQL が、全文検索向けの Best Matching 25 (BM25) インデックスを Preview として提供開始しました。 新しい pg_textsearch 拡張機能を有効化するだけで、Elasticsearch などの専用検索エンジンで標準的に使われている 確率的ランキングアルゴリズムを SQL だけで利用できます。PostgreSQL 17 / 18 を実行する AlloyDB インスタンスでサポートされます。

🧮 BM25 が評価する 3 要素

📊
TF (単語頻度)
クエリ語の出現頻度を評価。k1 パラメータで飽和を制御
📉
IDF (逆文書頻度)
希少な単語ほど高く重み付けし、キーワードの重要度を反映
📏
文書長の正規化
長い文書が不当に有利/不利にならないよう b パラメータで調整

❌ Before: アップデート前の課題

  • 標準の全文検索は ts_rank / ts_rank_cd 依存で、TF-IDF ベースの確率的ランキング (頻度の飽和制御・文書長正規化) が使えなかった
  • 高性能全文検索向けの RUM 拡張は PostgreSQL 17 以前のみのサポートで、ランキング品質向上には追加の工夫が必要だった
  • BM25 相当の検索品質には Elasticsearch など外部検索基盤の構築・同期が必要で、運用コストとデータ整合性が課題だった

✅ After: アップデート後の改善

  • CREATE INDEX ... USING bm25 という SQL だけで BM25 インデックスを作成し、確率的ランキングによる全文検索が可能に
  • k1 (頻度の飽和) と b (文書長の正規化) をインデックス作成時に調整でき、コレクション特性に合わせたチューニングが可能に
  • <@> 演算子で関連度順検索を ORDER BY ... LIMIT で簡潔に記述
  • PostgreSQL 17 に加えて 18 でもサポートされ、最新バージョンの選択肢が拡充

⚡ 主要機能

🧩 1. pg_textsearch 拡張機能による BM25 インデックス

CREATE EXTENSION pg_textsearch で拡張機能を有効化し、USING bm25 構文でテキストカラムにインデックスを作成。 PostgreSQL 標準の全文検索 (GIN / GiST) では実現できなかった、TF-IDF ベースの確率的ランキングをデータベース内で直接実行できます。

🎯 2. <@> 演算子による関連度ランキング検索

content <@> '検索語' の形式で BM25 スコアを計算。スコアは負の値で返されます (PostgreSQL のインデックススキャンが昇順 (ASC) のみをサポートするための仕様)。より小さい (より負の) スコアほど関連度が高く、 ORDER BY ... ASC LIMIT N で上位 N 件を効率的に取得できます。

🎛️ 3. ランキングパラメータのチューニング

k1 (デフォルト 1.2): 単語頻度の飽和パラメータ。大きくすると、クエリ語が繰り返し出現するドキュメントのスコアが上がりやすくなる。
b (デフォルト 0.75): 文書長の正規化パラメータ。大きくすると、長いドキュメントへのペナルティが強くなる。
text_config (必須): 使用する PostgreSQL テキスト検索設定 (例: english)。

🛠️ 設定方法

📋 前提条件: PostgreSQL 17 または 18 を実行する AlloyDB インスタンス / alloydbsuperuser データベースロールを持つユーザー
1
pg_textsearch 拡張機能の有効化

psql などのクライアントで AlloyDB データベースに接続し、データベースごとに拡張機能を作成します。

SQL 拡張機能の有効化 
CREATE EXTENSION IF NOT EXISTS pg_textsearch;
2
BM25 インデックスの作成

WITH 句では text_config (必須) に加えて、k1 と b をオプションで指定できます。

SQL BM25 インデックスの作成 
-- サンプルテーブルの作成
CREATE TABLE documents (
  id SERIAL PRIMARY KEY,
  title TEXT NOT NULL,
  content TEXT NOT NULL
);

-- content カラムに BM25 インデックスを作成
CREATE INDEX idx_docs_bm25
ON documents
USING bm25 (content)
WITH (text_config = 'english');
3
BM25 スコアによる検索

<@> 演算子は負の BM25 スコアを返すため、昇順 (ASC) でソートすると関連度の高いドキュメントが先頭に来ます。

SQL 関連度順の全文検索 
SELECT title, content, content <@> 'database system' AS score
FROM documents
ORDER BY content <@> 'database system' ASC
LIMIT 5;
4
ランキングパラメータのチューニング (任意)
SQL k1 / b パラメータの調整 
-- 短いドキュメント向けに単語頻度を重視する設定例
CREATE INDEX idx_docs_bm25_tuned
ON documents
USING bm25 (content)
WITH (text_config = 'english', k1 = 1.5, b = 0.8);

💼 ビジネス面

✓ 検索基盤の統合によるコスト削減: 外部検索エンジン (Elasticsearch など) を別途構築・運用する必要がなくなり、インフラコストとデータ同期の運用負荷を削減
✓ 検索体験の向上: BM25 の確率的ランキングで検索結果の関連性が向上し、EC サイトやナレッジベースのユーザー体験改善に直結

⚙️ 技術面

✓ SQL ネイティブな実装: インデックス作成も検索も標準的な SQL 構文で完結し、既存の PostgreSQL アプリケーションに最小限の変更で導入可能
✓ データ整合性の維持: 検索インデックスがデータベース内にあるため、外部検索エンジンとの同期遅延や不整合が発生しない
✓ チューニング可能なランキング: k1 と b により、文書長のばらつきや単語の繰り返し傾向に合わせた最適化が可能
✓ ハイブリッド検索との親和性: AlloyDB の ScaNN ベクトル検索と組み合わせ、キーワード検索とセマンティック検索を融合したハイブリッド検索を単一データベースで構築可能

🤔 考慮すべき点

⚠️ 注意:
  • <@> 演算子が返すスコアは負の値 (PostgreSQL が昇順インデックススキャンのみをサポートするため)。アプリケーション側でスコアを表示する場合は符号の扱いに注意
  • 従来の RUM 拡張は PostgreSQL 17 以前のみのサポート。PostgreSQL 18 で高機能な全文検索を行う場合は BM25 インデックスが主な選択肢
  • k1 と b はインデックス作成時に指定するため、パラメータ変更にはインデックスの再作成が必要

🎯 ユースケース

🛒 ユースケース 1: EC サイトの商品検索の関連度改善

シナリオ: AlloyDB 上で商品カタログを管理する EC サイトで、商品説明文に対するキーワード検索の関連度を改善したい。 従来の ts_rank ベースの検索では、説明文の長い商品が不当に低くランクされたり、キーワードの重要度が反映されにくいという課題があった。

SQL 商品検索の実装例 
CREATE EXTENSION IF NOT EXISTS pg_textsearch;

CREATE INDEX idx_products_bm25
ON products
USING bm25 (description)
WITH (text_config = 'english', k1 = 1.5, b = 0.8);

SELECT name, description <@> 'wireless noise cancelling headphones' AS score
FROM products
ORDER BY description <@> 'wireless noise cancelling headphones' ASC
LIMIT 20;

効果: TF-IDF と文書長正規化に基づく関連度ランキングにより、検索エンジン専用製品に近い検索品質を外部システムなしで実現。

🤖 ユースケース 2: RAG アプリケーションのハイブリッド検索

シナリオ: AlloyDB AI のベクトル検索 (ScaNN インデックス) を使った RAG アプリケーションで、 セマンティック検索だけでは固有名詞や型番などの正確なキーワードマッチングが弱い。BM25 による全文検索を組み合わせて検索精度を高めたい。

📌 まとめ

AlloyDB の BM25 インデックスは、専用検索エンジンで標準的な確率的ランキングアルゴリズムをマネージド PostgreSQL 内で直接利用可能にする重要なアップデートです。 外部検索基盤なしで高品質な全文検索を実現でき、ScaNN ベクトル検索と組み合わせたハイブリッド検索により RAG アプリケーションの検索精度向上にも寄与します。 PostgreSQL 17 / 18 の AlloyDB インスタンスを利用中で検索機能を持つアプリケーションを運用している場合は、Preview 段階での評価を推奨します。
