📋 概要

Gemini Enterprise Agent Platform で、Google の Frontier Model である Gemini 4 Neon (gemini-4-neon) が一般提供 (GA) になりました。 高性能なコーディング・マルチステップ推論・マルチモーダル理解を低レイテンシで実現し、 エージェント型のエンタープライズワークフローに最適化されたモデルです。

Gemini 4 ファミリー共通の新しい API 規約 (統合 1,048,576 トークン制限、continuation_token による long decodes、4 段階の思考レベル、デフォルト有効の暗黙的キャッシュ) を踏襲し、 GenerateContent API / Interactions API / OpenAI 互換 Chat Completions API の 3 つの API サーフェスから利用できます。

❌ Before (アップデート前の課題)

  • 低レイテンシとフロンティア級推論 (特に XHIGH の深い推論) を両立するモデルの選択肢が限られ、エージェント型ワークフローではレイテンシと性能のトレードオフが課題
  • 先行の Gemini 4 Argon は非ストリーミング単一セグメント出力が 32,768 トークンに制限、思考レベルも 3 段階 (XHIGH 非対応)
  • Gemini 3 系では Office / OpenDocument ファイルを直接入力できず、PDF 変換などの前処理が必要

✅ After (アップデート後の改善)

  • GA モデルとして本番のエージェント型ワークロードに採用可能。Provisioned Throughput など SLA 含む消費オプションと組み合わせ可能
  • 単一セグメントで最大 65,536 出力トークン (ストリーミング / 非ストリーミング共通)、long decodes で最大 1,048,576 トークンまで出力拡張
  • 思考レベルに XHIGH が追加 (デフォルトは HIGH)
  • Office (.docx / .pptx / .xlsx) / OpenDocument (.odt / .odp / .ods) をインラインまたは gs:// から直接入力可能
⚠️ 注意: Gemini 4 Neon は Service Specific Terms の Section 34 が適用される Google Frontier Model であり、不正利用モニタリングの対象となります。 また、同日発表の Gemini Enterprise Web アプリ / モバイルアプリ / Workflow Builder 側の提供は別アップデートで、 本インフォグラフィックは Agent Platform (API) 側に焦点を当てています。

Gemini 4 Neon は 3 つの API サーフェス (GenerateContent / Interactions / OpenAI 互換) から利用でき、 暗黙的キャッシュ、各種ツール、グラウンディングオプション、Office / OpenDocument ファイル入力をサポートします。

🚀 主要機能

1️⃣ 統合 1,048,576 トークン制限と long decodes

  • 入力 + 出力を合算した統合 1,048,576 トークン制限 (出力には思考トークン・関数呼び出し・最終レスポンスを含む)
  • 単一フォアグラウンドセグメントはストリーミング / 非ストリーミングともに最大 65,536 出力トークン
  • long decodes (continuation_token) により Interactions API と GenerateContent API (v1beta1) で出力を最大 1,048,576 トークン (入力分を除く) まで拡張
  • Interactions API では非同期のサーバー管理バックグラウンド実行 (background=true) もサポート

2️⃣ 4 段階の思考レベル (LOW / MEDIUM / HIGH / XHIGH)

  • デフォルトは HIGH。深い推論ワークロード向けに XHIGH を提供
  • thinking_budget の指定や thinking_level="MINIMAL" は HTTP 400 バリデーションエラー (Gemini 3 からの移行時は要注意)

3️⃣ 暗黙的コンテキストキャッシュ (durable caching)

  • 共有プロンプトプレフィックスが 4,096 トークン以上で自動適用。durable caching がデフォルト有効
  • 明示的コンテキストキャッシュ (explicit caching) は非サポート
  • 2027-01-12 以降、Gemini 4 Hydrogen 以降で TTL 設定付きキャッシュ書き込み制御が導入され、書き込みはデフォルトで標準入力価格の 1.25 倍で課金 (保持期間が長いほど高コスト)

4️⃣ Office / OpenDocument ファイル入力

  • Microsoft Office (.docx / .dotx / .doc / .pptx / .ppt / .xlsx / .xls) と OpenDocument (.odt / .odp / .ods) をインラインまたは Cloud Storage (gs://) から入力可能
  • multimodal FunctionResponse パート内でのファイル入力にも対応

5️⃣ 幅広い API サーフェス・ツール・消費オプション

  • API: GenerateContent API / Interactions API / OpenAI 互換 Chat Completions API
  • ツール: Function Calling、Code Execution、Computer Use、URL Context、Agentic Video Understanding
  • グラウンディング: Google Search / Google Maps / Web Grounding for Enterprise / Parallel・Exa Web Search
  • 消費オプション: Standard PayGo (Usage Tiers)、Priority PayGo、Off-peak PayGo、バッチ推論、Provisioned Throughput

💻 リクエスト例 (GenerateContent + long decodes)

Python Google Gen AI SDK — long decodes + XHIGH 思考レベル 
from google import genai
from google.genai import types

client = genai.Client(enterprise=True, project="PROJECT_ID", location="global")

# Google Gen AI SDK は continuation_token を自動処理 (v1beta1 をデフォルト使用)
for chunk in client.models.generate_content_stream(
    model="gemini-4-neon",
    contents="大規模コードベースのリファクタリング計画を詳細に作成してください。",
    config=types.GenerateContentConfig(
        max_output_tokens=256000,  # 65,536 超で long decodes が有効
        thinking_config=types.ThinkingConfig(thinking_level="XHIGH"),
    ),
):
    print(chunk.text, end="")

🔧 技術面のメリット

✓長大な出力の生成: long decodes で 65,536 トークン超の網羅的なコード生成・長文ドキュメント生成・詳細な形式証明に対応
✓推論の深さを制御可能: LOW〜XHIGH の 4 段階でレイテンシ・コストと推論品質のバランスを明示的に制御

✓OpenAI 互換 API 対応: 既存の Chat Completions ベース実装から少ない変更で移行可能

⚠️ 制限事項

✗明示的キャッシュは非サポート。暗黙的キャッシュは共有プレフィックス 4,096 トークン以上の場合のみ適用
✗long decodes は v1beta1 API のみ対応 (既知の問題)。v1 では利用不可
✗提供ロケーションは global と us / eu マルチリージョンに限定

🤔 考慮すべき点

  • 出力トークンには思考トークンと関数呼び出しが含まれるため、HIGH / XHIGH では推論トークン分のヘッドルームを考慮したトークン予算設計が必要
  • 2027-01-12 以降、キャッシュ書き込みがデフォルトで標準入力価格の 1.25 倍で課金されるため、キャッシュ利用パターンとコストの再評価が必要
  • Google Frontier Model として不正利用モニタリング (Section 34) の対象。コンプライアンス要件を確認すること

💡 ユースケース

🧑‍💻 ユースケース 1: 長大な成果物を生成するコーディングエージェント

シナリオ: リポジトリ全体の解析結果をもとに、詳細な設計書や大規模なコード一式を一度のリクエストで生成したい。単一セグメントの 65,536 トークン制限では成果物が途中で途切れてしまう。

PythonInteractions API — バックグラウンド実行
interaction = client.interactions.create(
    model="gemini-4-neon",
    input="このリポジトリ全体のマイグレーション計画と変更コードを生成してください。",
    generation_config={
        "max_output_tokens": 500000,
        "thinking_level": "xhigh",
    },
    background=True,  # サーバー管理の非同期バックグラウンド実行
)

効果: SDK が continuation_token を自動処理し、最大 1,048,576 トークンまでの長大な出力を取得できる。background=true によりクライアントが接続を維持し続ける必要がなくなる。

📄 ユースケース 2: 社内 Office 文書を扱うエンタープライズエージェント

シナリオ: Cloud Storage に保存された .docx / .xlsx / .pptx などの社内文書を、変換処理なしでエージェントに読み込ませ、要約・分析・質問応答を行いたい。

効果: Office / OpenDocument ファイルを gs:// から直接入力できるため、PDF 変換などの前処理パイプラインが不要になり、multimodal FunctionResponse 経由でツール実行結果としてファイルを渡すエージェント設計も可能になる。

🗄️ ユースケース 3: 共通の長いシステムプロンプトを持つマルチテナントエージェント

シナリオ: 多数のユーザーが同一の長大なシステム指示とツール定義 (4,096 トークン以上) を共有するエージェントサービスで、入力トークンコストとレイテンシを抑えたい。

効果: 暗黙的キャッシュ + durable caching がデフォルト有効のため、静的なプロンプト部分を先頭に配置するだけで、追加実装なしにキャッシュヒットによるコスト削減と低レイテンシ化が期待できる。

💰 料金と利用可能リージョン

Gemini 4 Neon はトークンベースの従量課金で、Standard PayGo (Usage Tiers 対応)、Priority PayGo、Off-peak PayGo、 バッチ推論、Provisioned Throughput の各消費オプションが利用できます。固有の単価は公式料金ページを参照してください。

  • 暗黙的キャッシュの作成に使われる入力トークンは標準入力トークン価格で課金され、暗黙的キャッシュに個別のストレージ費用はかからない
📅 2027 年 1 月 12 日以降: Gemini 4 Hydrogen 以降のモデルで TTL 設定付きのキャッシュ書き込み制御が導入され、 キャッシュ書き込みはデフォルトで標準入力トークン価格の 1.25 倍で課金されます (保持期間が長いほど高コスト)。 キャッシュ戦略とコストの再評価を推奨します。
