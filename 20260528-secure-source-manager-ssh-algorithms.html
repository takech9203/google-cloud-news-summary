🔐 Secure Source Manager: Git-over-SSH レガシーアルゴリズムのサポート廃止

Secure Source Manager Breaking Change
2026-05-28

📋 概要

Google Cloud Secure Source Manager の Git-over-SSH サーバー構成において、セキュリティ強化と脆弱性 GHSA-3m6q-h5gj-7mrw への対応として、複数のレガシーおよび安全でない SSH アルゴリズムのサポートが削除されました。

SSH クライアントは接続時に curve25519-sha256 や aes256-gcm などのモダンなアルゴリズムを少なくとも1つサポートしている必要があります。OpenSSH 7.3 以降を使用している場合は通常影響を受けません。

⚠️ 重要: この変更は段階的な移行期間なく即座に適用されます。古い SSH クライアントを使用しているユーザーは即座に接続不能になる可能性があります。HTTPS 認証には影響しません。

🔄 Before / After 比較

❌ Before (変更前)

✗SHA-1 ベースの鍵交換がサポートされていた
✗CBC モード暗号 (aes128-cbc, 3des-cbc等) が使用可能
✗HMAC-SHA1, HMAC-MD5 などのレガシー MAC を許可
✗GHSA-3m6q-h5gj-7mrw の脆弱性リスクが存在
✗MITM 攻撃や暗号解読のリスク

✅ After (変更後)

✓モダンで安全なアルゴリズムのみ許可
✓AES-GCM, ChaCha20-Poly1305 (AEAD) を使用
✓HMAC-SHA2-256 系のみサポート
✓既知の脆弱性リスクを解消
✓業界標準のセキュリティ基準に準拠

🔑 主要な変更点

🔒 鍵交換アルゴリズムの制限

サポートされるアルゴリズムが 2種類に限定されました。

✓curve25519-sha256 - 楕円曲線 Diffie-Hellman (最推奨)
✓diffie-hellman-group14-sha256 - 2048-bit DH グループ 14 + SHA-256
✗diffie-hellman-group1-sha1, diffie-hellman-group14-sha1 - 廃止

🛡️ 暗号化方式 (Ciphers) の制限

ChaCha20-Poly1305 および AES-CTR/GCM モードのみサポート。

✓chacha20-poly1305@openssh.com
✓aes128-ctr / aes192-ctr / aes256-ctr
✓aes128-gcm@openssh.com / aes256-gcm@openssh.com
✗aes128-cbc, aes256-cbc, 3des-cbc - 廃止

📝 MAC アルゴリズムの制限

HMAC-SHA2-256 系 (ETM モードを含む) のみサポート。

✓hmac-sha2-256-etm@openssh.com - Encrypt-then-MAC
✓hmac-sha2-256
✗hmac-sha1, hmac-md5 - 廃止

✅ メリット

💼 ビジネス面

→コンプライアンス強化: NIST SP 800-131A や FedRAMP などのセキュリティ基準に準拠
→リスク低減: ソースコードの機密性が強化され、情報漏洩リスクが低減

🔬 技術面

→前方秘匿性 (Forward Secrecy): 過去の通信が将来的に解読されるリスクを排除
→認証付き暗号 (AEAD): AES-GCM / ChaCha20-Poly1305 でパディングオラクル攻撃を防止
→Encrypt-then-MAC: 暗号文の改ざん検知が暗号化解除前に行われ、堅牢なセキュリティを実現

⚠️ デメリット・制約事項

🚫 制限事項

✗OpenSSH 7.3 より古いバージョンでは SSH 経由の Git 操作が不可能に
✗レガシー組み込みシステムやカスタム SSH クライアントでは対応が困難な場合あり
✗CI/CD パイプラインで古い SSH クライアントを使用している場合、即座に失敗

💡 考慮すべき点

→即時適用: 段階的な移行期間なく即座に適用。事前の互換性確認が重要
→代替手段: SSH が使えない場合は HTTPS 認証への切り替えを検討
→鍵タイプとの違い: 今回はトランスポート層のアルゴリズム変更。RSA/ECDSA/Ed25519 鍵タイプとは別の問題

🔧 ユースケース 1: CI/CD パイプラインの互換性確認

シナリオ: GitHub Actions や Cloud Build から SSH 経由で Secure Source Manager のリポジトリにアクセスしている CI/CD パイプラインが突然失敗する。

Bash

効果: パイプライン障害の原因を迅速に特定し、SSH クライアントのアップデートまたは HTTPS への切り替えで復旧。

🏢 ユースケース 2: エンタープライズ環境での一括対応

シナリオ: 大規模開発チームで多数の開発者が Secure Source Manager を使用しており、一部の開発者が古い OS やカスタム SSH クライアントを使用している。

効果: IT 部門が全社的に SSH クライアントのバージョンを確認し、~/.ssh/config の標準テンプレートを配布することで、統一的な対応が可能。アップデートが困難な端末については HTTPS 認証への移行を案内。

🔍 ユースケース 3: セキュリティ監査への対応

シナリオ: 情報セキュリティ監査において、ソースコード管理システムの暗号化通信に使用されるアルゴリズムの安全性を証明する必要がある。

効果: Secure Source Manager が業界標準のモダンアルゴリズムのみをサポートしていることを示すことで、監査要件を容易に満たすことが可能。
