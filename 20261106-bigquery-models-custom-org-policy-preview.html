BigQuery Preview Organization Policy

🛡️ BigQuery モデルに対するカスタム組織ポリシーのサポート

📅 リリース日: 2026-11-06 ｜ カスタム制約 (custom constraints) によるモデル操作の許可・拒否

📌 概要

BigQuery のモデル (BigQuery ML リソース) に対して、Organization Policy Service の カスタム制約 (custom constraints) を使用して特定の操作を許可・拒否できるようになりました (Preview)。

カスタム組織ポリシーは組織・フォルダ・プロジェクトのいずれかのレベルで適用でき、 CEL (Common Expression Language) 条件でリソースのフィールド値を評価して、 CREATE / UPDATE 操作を ALLOW または DENY できます。 サポート対象リソースに bigquery.googleapis.com/Model が追加されました。

🎯 対象ユーザー: 組織全体で BigQuery ML モデルの命名規則や作成ルールを統制したい 組織ポリシー管理者やデータガバナンス担当者

❌ Before (アップデート前の課題)

  • カスタム制約のサポート対象にモデルが含まれず、モデルの作成・更新をカスタム組織ポリシーで統制できなかった
  • データセットやテーブルには命名規則などの制約を適用できる一方、モデルには同等のきめ細かなガバナンス手段がなかった

✅ After (アップデート後の改善)

  • bigquery.googleapis.com/Model を対象に CREATE / UPDATE を条件付きで許可・拒否できる
  • modelReference の projectId / datasetId / modelId を CEL 条件で評価し、命名規則の強制などが可能に
  • 組織・フォルダ・プロジェクトの各レベルで適用でき、配下のリソースに継承される

⚙️ 主要機能

1️⃣ モデルリソースへのカスタム制約の適用

✓サポート対象リソースに bigquery.googleapis.com/Model が追加
✓CREATE / UPDATE メソッドに対して制約を適用でき、条件に合致した操作を ALLOW または DENY できる

2️⃣ モデル参照フィールドによる条件定義

✓resource.modelReference.projectId / datasetId / modelId を CEL 条件で参照可能
✓例: resource.modelReference.modelId.contains('test') でモデル ID に特定文字列を含む操作を拒否

3️⃣ リソース階層でのきめ細かな適用

✓組織・フォルダ・プロジェクトの各レベルでポリシーを適用可能
✓デフォルトでポリシーは配下のリソースに継承される (継承動作は変更可能)

🔧 技術仕様

項目詳細
対象リソースbigquery.googleapis.com/Model
参照可能フィールドresource.modelReference.projectId / datasetId / modelId
対象メソッドCREATE、UPDATE
アクションALLOW / DENY
条件CEL 条件 (最大 1,000 文字)
制約数の上限多くのリソースタイプで最大 20 個のカスタム制約
適用レベル組織 / フォルダ / プロジェクト (配下に継承)
ステータスPreview (Pre-GA Offerings Terms が適用)

📝 カスタム制約の定義例 (公式ドキュメントの例)

YAML constraint.yaml — モデル ID に 'test' を含む操作を拒否 
name: organizations/ORGANIZATION_ID/customConstraints/custom.enforceModelId
resourceTypes:
- bigquery.googleapis.com/Model
methodTypes:
- CREATE
- UPDATE
condition: "resource.modelReference.modelId.contains('test')"
actionType: DENY
displayName: Reject models with names that contain 'model'.
description: Deny new models with names that contain 'model'.

🛠️ 設定方法

✅ 前提条件

✓組織 ID を確認しておく
✓組織リソースに対する Organization Policy Administrator (roles/orgpolicy.policyAdmin) ロールが付与されていること
✓BigQuery リソースの作成・管理には別途 BigQuery の権限が必要

1カスタム制約の YAML を作成し登録する

カスタム制約 (前述の YAML 例) を組織に登録し、組織ポリシーで利用可能にします。

Bash カスタム制約の登録 
# constraint.yaml を作成後、カスタム制約を登録
gcloud org-policies set-custom-constraint constraint.yaml

2カスタム制約を組織ポリシーとして適用する

登録した制約を組織・フォルダ・プロジェクトのいずれかに適用し、適用を有効化 (enforce: true) します。Google Cloud コンソールの「組織ポリシー」ページからも設定できます。

Bash 組織ポリシーの適用 
# policy.yaml の例:
# name: projects/PROJECT_ID/policies/custom.enforceModelId
# spec:
#   rules:
#   - enforce: true

gcloud org-policies set-policy policy.yaml

💡 メリット

💼 ビジネス面

✓ガバナンスの一元化: モデルを含む BigQuery リソース全体の操作ルールを組織レベルで集中管理でき、コンプライアンス要件への対応が容易になる
✓ポリシー違反の予防: 違反する操作はリクエスト時点で拒否されるため、事後的な検出・是正の運用負荷を削減できる

🔬 技術面

✓きめ細かな条件定義: CEL 条件により、モデル ID・データセット ID・プロジェクト ID に基づく柔軟な許可・拒否ルールを定義できる
✓階層的な適用と継承: 組織・フォルダ・プロジェクトの階層に沿ってポリシーが継承されるため、個別プロジェクトでの設定漏れを防げる

⚠️ デメリット・制約事項

🚧 制限事項
  • Preview のため、Pre-GA Offerings Terms が適用され、サポートが限定される場合がある
  • データセット以外のリソース (モデルを含む) に対するカスタム制約でアクセスが拒否された場合、BigQuery 監査ログに PolicyViolationInfo は公開されない (エラーメッセージには拒否した constraintId が含まれる)
  • 多くのリソースタイプで作成できるカスタム制約は最大 20 個まで
🤔 考慮すべき点
  • UPDATE メソッドで制約を適用すると、既に制約に違反している既存リソースへの変更は、違反を解消する変更でない限りブロックされる
  • ALLOW アクションは条件に合致する操作のみ許可し、それ以外をすべてブロックするため、条件設計に注意が必要

🎯 ユースケース

🚫 ユースケース 1: 本番環境でのテスト用モデル作成の禁止

シナリオ: 本番プロジェクトで、命名規則に反するテスト用モデル (モデル ID に test を含む) の作成・更新を防ぎたい。

YAML 実装例 
name: organizations/123456789/customConstraints/custom.enforceModelId
resourceTypes:
- bigquery.googleapis.com/Model
methodTypes:
- CREATE
- UPDATE
condition: "resource.modelReference.modelId.contains('test')"
actionType: DENY
displayName: Reject test models
description: Deny models whose model ID contains 'test'.
✅ 効果: 命名規則に違反するモデルの作成・更新がリクエスト時点で拒否され、本番環境の整合性を維持できる。

📁 ユースケース 2: モデル作成先データセットの統制

シナリオ: ML モデルを特定のデータセットにのみ作成させたい組織で、resource.modelReference.datasetId を条件にした ALLOW ポリシーを適用する。

✅ 効果: 承認済みデータセット以外へのモデル作成がブロックされ、モデル資産の配置を標準化できる。

🔗 関連サービス・機能

🛡️ Organization Policy Service
本機能の基盤。カスタム制約の定義・適用・継承を提供する
🤖 BigQuery ML
統制対象となるモデル (CREATE MODEL などで作成) を提供する機能
🔐 IAM
組織ポリシーの管理には roles/orgpolicy.policyAdmin が必要。IAM によるアクセス制御と組み合わせて多層的なガバナンスを実現
📜 Cloud Audit Logs (BigQuery 監査ログ)
ポリシー拒否時のログ連携先。ただしデータセット以外のリソースでは PolicyViolationInfo が公開されない制限がある

📝 まとめ

BigQuery のカスタム組織ポリシーがモデルリソースに拡張され、BigQuery ML モデルの作成・更新操作を 組織レベルで統制できるようになりました。

  • データガバナンスを強化したい組織は、まず dry-run を含むポリシー設計を検討
  • モデルの命名規則や作成先データセットの統制から段階的に適用することを推奨
  • Preview のため、本番適用時は Pre-GA の提供条件と監査ログの制限事項を確認
