📱 SMS 通知チャネル: テキストメッセージによるオプトアウト

「STOP」と返信するだけでアラート通知を停止 — コンソール不要のセルフサービス配信停止

📌 概要

Cloud Monitoring の SMS 通知チャネルで、受信者が SMS に 「STOP」(英語) / 「ARRET」(フランス語) と返信するだけでアラート通知を停止 (オプトアウト) できるようになりました。「HELP」「AIDE」「INFO」の返信でオプトアウト方法の案内も取得できます。

オプトアウトすると、Cloud Monitoring はその電話番号に関連付けられた すべての Google Cloud プロジェクトにまたがるすべての通知チャネル を無効化し、確認の SMS を送信します。英語・フランス語の 2 言語対応は、米国・カナダの SMS 規制へのコンプライアンス要件によるものです。

コンソールへのアクセス権を持たないオンコール担当者や、担当変更・退職で通知が不要になった受信者でも、自分自身で即座に通知を停止できます。本機能はプレビュー段階 (Pre-GA Offerings Terms 適用) です。

❌ Before: アップデート前の課題

  • SMS 通知の停止には、コンソールまたは Cloud Monitoring API での通知チャネルの編集・削除が必要だった
  • 受信者本人がプロジェクトへのアクセス権を持たない場合、管理者に依頼しない限り通知を止める手段がなかった
  • 電話番号が複数プロジェクトに登録されている場合、プロジェクトごとに個別対応が必要だった

✅ After: アップデート後の改善

  • SMS に「STOP」(英) / 「ARRET」(仏) と返信するだけでオプトアウトできる
  • 電話番号に紐づく全プロジェクトの通知チャネルを一括無効化し、確認 SMS が届く
  • 「HELP」「AIDE」「INFO」の返信でオプトアウト方法の案内を SMS で取得できる
  • 米国・カナダの SMS 関連規制へのコンプライアンス対応が容易になった

⚡ 主要機能

1️⃣ テキストメッセージによるオプトアウト

受信した SMS 通知への返信として STOP (英語) または ARRET (フランス語) を送信すると通知の受信を停止。その電話番号に関連付けられた通知チャネルを すべての Google Cloud プロジェクトにわたって 無効化し、完了後に確認の SMS メッセージを送信します。

2️⃣ オプトアウト方法の情報リクエスト

受信した SMS 通知への返信として HELP (英語)、AIDE / INFO (フランス語) を送信すると、オプトアウト方法に関する情報を取得できます。

3️⃣ オプトイン (通知の再開)

無効化されたチャネルは、Google Cloud コンソールまたは Cloud Monitoring API で編集して再度有効化することで通知を再開できます。API では notificationChannels.patch メソッド、gcloud CLI では gcloud beta monitoring channels update --enabled を使用します。

💡 メリット

💼 ビジネス面

✓コンプライアンス対応: 米国・カナダの SMS 規制で求められるオプトアウト手段 (STOP/ARRET) を標準機能として提供
✓問い合わせ対応の削減: 受信者が自分で通知を停止できるため、「通知を止めてほしい」という管理者への依頼が不要に

⚙️ 技術面

✓セルフサービスでの配信停止: プロジェクトへのアクセス権を持たない受信者でも SMS の返信だけで停止可能
✓プロジェクト横断での一括無効化: 電話番号に紐づく全プロジェクトのチャネルを一括無効化、個別対応が不要

⚠️ デメリット・制約事項

🚧 制限事項

✗プレビュー段階の機能であり、Pre-GA Offerings Terms が適用される (サポートが限定される可能性)
✗オプトアウト用のテキストメッセージは英語またはフランス語のみに対応 (米国・カナダの規制対応のため)
✗オプトアウトすると、電話番号に関連付けられた すべての Google Cloud プロジェクト の通知チャネルが無効化される (特定プロジェクトのみの停止はできない)

🤔 考慮すべき点

⚠️ 誤操作に注意: オンコール担当者が誤って「STOP」と返信すると、全プロジェクトのアラート通知が届かなくなります。運用チーム内での周知が必要です。
✗通知の再開には、無効化されたチャネルをコンソールまたは API で再度有効化する管理者側の操作が必要
✗公式ドキュメントでは、SMS は信頼性の高い通知チャネルではなく、一部リージョンでは利用できない可能性があるため、SMS のみに依存せずメールなど追加チャネルの設定が推奨されている

📞 ユースケース 1: 担当変更に伴う通知の即時停止

📜 ユースケース 2: 規制コンプライアンスを満たした SMS アラート運用

シナリオ 米国・カナダのユーザーに SMS でアラート通知を送信しており、SMS メッセージング規制で求められるオプトアウト手段の提供が必要。

効果 STOP/ARRET によるオプトアウトと HELP/AIDE/INFO による情報提供が標準機能として組み込まれているため、追加の実装なしで規制要件に対応した SMS 通知運用ができる。

🔗 関連サービス・機能

🔔 Cloud Monitoring 通知チャネル

SMS のほか、メール、Slack、PagerDuty、Google Cloud コンソール モバイルアプリ、Webhook、Pub/Sub などの通知チャネルを提供。ドキュメントでは SMS のみに依存せず複数チャネルの併用が推奨されています。

🔌 Cloud Monitoring API (notificationChannels)

notificationChannels.patch メソッドで通知チャネルの有効化・無効化をプログラムから制御可能。オプトアウトで無効化されたチャネルの再有効化に使用します。

📋 Cloud Logging (Logs Explorer)

通知チャネルのエラーログ (SMS クォータ超過の「Denied quota token」など) を確認できます。

📝 まとめ

SMS 通知チャネルの受信者が 「STOP」の返信だけでアラート通知をオプトアウト できるようになり、コンソールへのアクセス権を持たない受信者のセルフサービスでの配信停止と、米国・カナダの SMS 規制へのコンプライアンス対応が実現しました。

オプトアウトは電話番号に紐づく 全プロジェクトの通知チャネルを一括無効化 するため、SMS を通知手段として利用しているチームは、誤操作時の再有効化手順の整備と、メールなど代替チャネルの併用を検討することを推奨します。
