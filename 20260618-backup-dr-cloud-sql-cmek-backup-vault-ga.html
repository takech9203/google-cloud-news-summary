🔐 Cloud SQL CMEK Backup Vault サポート

Backup and DR Service GA
2026-06-18

📋 概要

顧客管理暗号鍵 (CMEK) で暗号化された Cloud SQL インスタンスの Backup Vault へのバックアップサポートが一般提供 (GA) となりました。 CMEK で保護されたデータベースのバックアップを、イミュータブル (不変) かつ インデリブル (削除不可) なストレージに保存し、強制保持期間を適用できます。

💡 ポイント: 金融機関、医療機関、政府機関など、厳格なデータ保護要件を持つ組織が、 バックアップデータに対しても CMEK 暗号化と Backup Vault の不変性を同時に実現可能に。

  • 本番ワークロードでの利用を公式サポート

⚡ 主要機能

🔑 ソースレベル CMEK 暗号化の継承

Cloud SQL バックアップは、ソースインスタンスの CMEK 鍵をそのまま使用して暗号化。鍵の一貫性が保たれ、鍵管理が簡素化されます。

🛡️ イミュータブル・インデリブルストレージ

Backup Vault に保存されたバックアップは変更不可 (イミュータブル)、強制保持期間中は削除不可 (インデリブル)。管理者でもデータ改ざん・早期削除が不可能。

⏱️ 強制保持期間 (Enforced Retention)

Backup Vault 単位で最小保持期間を設定可能 (最大 99 年)。バックアッププランの保持期間は Vault の最小保持期間以上が必要。

📅 スケジュール・オンデマンドバックアップ

時間単位、日次、週次、月次、年次のスケジュール設定。必要に応じてオンデマンドバックアップも作成可能。

鍵の無効化による影響

⚙️ 設定方法

前提条件

✓Backup and DR Service API が有効化されていること
✓Cloud Key Management Service API が有効化されていること
✓CMEK で暗号化された Cloud SQL インスタンスが存在すること
✓Backup Vault が作成済みであること
✓バックアッププランが作成済みであること

ステップ 1: Backup and DR サービスエージェントに CMEK 鍵へのアクセスを付与

Bash 
# Backup and DR サービスエージェントに CryptoKey Encrypter/Decrypter ロールを付与
gcloud kms keys add-iam-policy-binding KEY_NAME \
  --location=KMS_LOCATION \
  --keyring=KEY_RING \
  --member=serviceAccount:service-VAULT_PROJECT_NUMBER@gcp-sa-backupdr.iam.gserviceaccount.com \
  --role=roles/cloudkms.cryptoKeyEncrypterDecrypter \
  --project=KMS_PROJECT_ID

ステップ 2: Backup Vault サービスエージェントに Cloud SQL プロジェクトへのアクセスを付与

Google Cloud コンソールで以下のロールを付与:

→roles/backupdr.cloudSqlOperator (BackupDR Cloud SQL Operator)
→roles/iam.serviceAccountUser (Service Account User)

ステップ 3: バックアッププランを Cloud SQL インスタンスに適用

Google Cloud コンソールまたは gcloud CLI でバックアッププランを CMEK 暗号化された Cloud SQL インスタンスに適用します。

✅ メリット

ビジネス面

🏦コンプライアンス対応の強化 - PCI DSS、SOX、HIPAA で求められる暗号鍵の自社管理とバックアップの不変性を同時に実現
🛡️ランサムウェア対策 - イミュータブルなバックアップにより、攻撃者によるバックアップの暗号化や削除を防止
📋監査対応の簡素化 - 鍵管理とバックアップ保持ポリシーを一元管理し、監査証跡を容易に提供可能

技術面

🔗鍵管理の一貫性 - ソースインスタンスと同じ CMEK 鍵でバックアップを保護、鍵のライフサイクルを統一管理
🤖運用負荷の軽減 - スケジュールベースの自動バックアップと自動期限切れ削除で手動運用を最小化
🌐復元時の柔軟性 - クロスリージョン復元時に異なる KMS 鍵を指定可能

⚠️ デメリット・制約事項

⚠️ 重要な制限: CMEK 鍵を無効化または破棄すると、その鍵で暗号化されたバックアップデータに永続的にアクセスできなくなります。

制限事項

✗CMEK は Backup Vault 作成時にのみ設定可能 (既存 Vault への後付け不可)
✗Cloud KMS 鍵は Backup Vault と同じロケーションに配置する必要あり
✗CSEK (顧客提供暗号鍵) はサポートされない
✗AlloyDB、Filestore、VMware Engine では CMEK バックアップ非サポート
✗デフォルト Vault は Google 管理暗号化のため、CMEK 利用には新規 Vault 作成が必要

考慮すべき点

⚡両方のサービスエージェント (Backup and DR + Cloud SQL) に適切な IAM 権限が必要
⚡強制保持期間中はバックアップ削除不可のため、ストレージコストが継続的に発生

🌐 ディザスタリカバリ対応

シナリオ: マルチリージョン構成の Cloud SQL インスタンスで、DR 要件としてバックアップの改ざん防止と迅速な復元を実現。

効果: Backup Vault のイミュータビリティにより、DR シナリオにおいてバックアップの完全性が保証。復元時には別リージョンの KMS 鍵を指定してクロスリージョンリストアが可能。

💰 料金情報

Backup and DR Service は月額使用量ベースの課金。CMEK 使用に対する追加料金は発生しませんが、Cloud KMS の鍵使用料が別途課金されます。

項目 料金
CMEK バックアップ追加料金 なし (Backup and DR の通常料金に含まれる)
Cloud KMS 鍵使用料 Cloud KMS の料金体系に準拠
Backup Vault ストレージ 料金ページ参照

🌍 利用可能リージョン

Backup Vault は大部分の Google Cloud リージョンおよびマルチリージョンで利用可能。CMEK 鍵は Backup Vault と同じロケーションに配置する必要があります。
