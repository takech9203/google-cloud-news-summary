Priority PayGo GA / CodeMender v0.15.0 / DeepSeek-V4.1-Flash Public Preview
📅 リリース日: 2026-10-14

📝 概要 — 3 つのアップデートが同日発表

2026 年 10 月 14 日、Gemini Enterprise Agent Platform で 3 件のアップデートが発表されました。生成 AI の画像生成を本番運用するチーム、CI/CD で CodeMender を利用する開発チーム、オープンモデルの選択肢を広げたい AI 開発者が対象です。

🎨 ① Gemini Nano Banana 2.1 の Priority PayGo が GA

事前コミットメントなしで Standard PayGo より安定したパフォーマンスを得られる従量課金オプションが、画像生成モデル gemini-nano-banana-2.1 のグローバルエンドポイントで GA。ビジネスクリティカルな画像生成ワークロードに最適。

🛡️ ② CodeMender v0.15.0 リリース

セキュリティエージェント CodeMender の SARIF 2.1.0 レポーティングを強化し、GitHub Code Scanning との互換性を改善。cm stats --json にモデル呼び出しメトリクスを追加し、トークン使用量欠落のバグも修正。

🚀 ③ DeepSeek-V4.1-Flash が Public Preview (MaaS)

テキスト + 画像入力対応、最大 100 万トークンのコンテキストウィンドウを持つエージェント / コーディング向けモデルが、Model Garden のフルマネージドモデル (MaaS) として登場。インフラ管理不要。

🔄 Before / After

❌ アップデート前の課題

  • Nano Banana 2.1 の消費オプションは Standard PayGo と Provisioned Throughput のみ。事前コミットなしで安定性能を得る選択肢がなかった
  • CodeMender の SARIF 出力 (ルール記述子・重大度・アーティファクトの場所) が GitHub Code Scanning 統合に最適化されておらず、cm stats でモデル呼び出し回数も確認できなかった
  • エラー / キャンセル終了時に完了済みターンのトークン使用量がセッションログから欠落
  • DeepSeek MaaS に、マルチモーダル入力 + 1M コンテキストを兼ね備えたエージェント / コーディング向けモデルがなかった

✅ アップデート後の改善

  • リクエストヘッダーを付与するだけで Priority PayGo を利用でき、トラフィック変動の大きい画像生成でも安定した性能を確保
  • cm report の SARIF 2.1.0 出力が標準化ルール記述子・重大度プロパティ・リポジトリ相対パスに対応し、GitHub Code Scanning 互換性が向上
  • cm stats --json で合計 / セッション / ターン単位のモデル呼び出しを可視化。トークン欠落バグも修正
  • DeepSeek-V4.1-Flash をプロビジョニング不要の API として即利用。1M トークンでエージェント / コーディング処理が可能

Gemini Nano Banana 2.1 への Priority PayGo アクセス経路、Model Garden MaaS 経由の DeepSeek-V4.1-Flash 利用、CodeMender から GitHub Code Scanning への SARIF 連携という 3 つのアップデートの位置付けを示しています。

⭐ 主要機能の詳細

⚡ 1. Gemini Nano Banana 2.1 の Priority PayGo サポート (GA)

✓Provisioned Throughput の事前コミットなしで Standard PayGo より安定したパフォーマンスを提供する従量課金オプション (トークン単価は Standard PayGo より高め)
✓gemini-nano-banana-2.1 のグローバルエンドポイントで GA として利用可能
✓X-Vertex-AI-LLM-Shared-Request-Type: priority ヘッダーを付与するだけで利用でき、Provisioned Throughput クォータのスピルオーバー先としても構成可能
✓顧客向けバーチャルアシスタント、エージェント間連携ワークフローなどトラフィックが変動するビジネスクリティカルな用途に最適

🛡️ 2. CodeMender v0.15.0 アップデート

✓SARIF 2.1.0 レポーティング強化: cm report に標準化されたルール記述子、重大度プロパティ、リポジトリ相対のアーティファクトロケーションを導入し、GitHub Code Scanning との互換性を改善
✓モデル呼び出しメトリクス: cm stats --json で合計 / セッション単位 / ターン単位の呼び出し回数を取得可能に
✓バグ修正: エラー / キャンセル終了パスで完了済みターンのトークン使用量がセッションログから欠落する問題を修正

🚀 3. DeepSeek-V4.1-Flash の Public Preview 提供 (MaaS)

✓DeepSeek 製のマルチモーダル Mixture-of-Experts (MoE) モデル。テキストと画像の入力に対応し、エージェント処理とコーディングタスクが対象
✓コンテキストウィンドウは最大 1M (1,048,576) トークン。プリフィル時は 552B バックボーンのうちトークンあたり 8B のみアクティベートし、入力の多いエージェントワークロードでもコスト効率を維持
✓Model Garden からフルマネージドモデル (MaaS) として利用可能。インフラのプロビジョニング・管理は不要で、セルフデプロイも選択可能

📡 Priority PayGo のリクエスト例 (REST)

Bash Priority PayGo で generateContent を呼び出す 
curl -X POST \
  -H "Authorization: Bearer $(gcloud auth print-access-token)" \
  -H "Content-Type: application/json; charset=utf-8" \
  -H "X-Vertex-AI-LLM-Shared-Request-Type: priority" \
  "https://aiplatform.googleapis.com/v1/projects/PROJECT_ID/locations/global/publishers/google/models/gemini-nano-banana-2.1:generateContent" -d \
  $'{
    "contents": {
      "role": "user",
      "parts": { "text": "PROMPT_TEXT" }
    }
  }'
💡 ヒント: Provisioned Throughput を使わず Priority PayGo のみを使用する場合は、X-Vertex-AI-LLM-Request-Type: shared ヘッダーも併せて付与します。

🛡️ CodeMender の SARIF 出力 (CI/CD での利用例)

Bash diff スキャンと統計情報の取得 
# プルリクエストブランチを main と比較してスキャンし、SARIF を出力
cm find . --diff=origin/main --format=sarif --output=results.sarif \
  --fail-on=CRITICAL,HIGH

# モデル呼び出しメトリクスを含む統計情報を JSON で取得 (v0.15.0 で拡張)
cm stats --json

ステップ 1: Priority PayGo を Python SDK で利用する

Python クライアント初期化時に priority ヘッダーを設定 
from google import genai
from google.genai.types import HttpOptions

client = genai.Client(
    vertexai=True,
    project="your_project_id",
    location="global",
    http_options=HttpOptions(
        api_version="v1",
        headers={"X-Vertex-AI-LLM-Shared-Request-Type": "priority"},
    ),
)

クライアント初期化時にヘッダーを設定すれば、以降のリクエストはすべて Priority PayGo (Provisioned Throughput クォータがあればそちらを優先) で処理されます。

ステップ 2: DeepSeek-V4.1-Flash を MaaS として呼び出す

Model Garden の DeepSeek-V4.1-Flash モデルカードからモデルを有効化し、エンドポイント (deepseek-v4.1-flash-maas) に対して直接リクエストを送信します。MaaS のためインフラのプロビジョニングは不要で、レスポンスは SSE によるストリーミングにも対応しています。

💪 メリット

💼 ビジネス面

✓コミットメント不要の安定性能: Priority PayGo により、Provisioned Throughput の事前契約なしでビジネスクリティカルな画像生成ワークロードの安定稼働を実現
✓モデル選択肢の拡大: DeepSeek-V4.1-Flash の MaaS 提供により、サードパーティモデルをインフラコストや運用負荷なしで評価・採用できる

🔬 技術面

✓ヘッダーのみで切り替え可能: アプリケーションコードの大幅な変更なしに Priority PayGo を利用でき、Provisioned Throughput からのスピルオーバー構成も可能
✓CI/CD セキュリティ統合の強化: SARIF 2.1.0 出力改善で GitHub Code Scanning アノテーションの取り込み精度が向上し、cm stats --json でモデル利用状況の監視も可能に
✓長大コンテキストのエージェント処理: 1M トークンコンテキスト + MoE アーキテクチャ (プリフィル時 8B アクティブ) により、入力の多いエージェント / コーディングワークロードをコスト効率よく処理

⚠️ デメリット・制約事項

🚧 制限事項

✗Priority PayGo のトークン単価は Standard PayGo より高く設定されている
✗DeepSeek-V4.1-Flash は Public Preview で Pre-GA Offerings Terms が適用。Provisioned Throughput、バッチ推論、固定クォータは非対応 (消費オプションは Standard PayGo のみ)
✗DeepSeek-V4.1-Flash の入力はテキストと画像のみで、音声・動画には非対応
✗deepseek-v4.1-flash-maas エンドポイントの提供は「少なくとも 2026 年 11 月 28 日まで」とされ、Preview モデルの最低提供期間ポリシーに従う

🤔 考慮すべき点

⚠️Nano Banana 2.1 と DeepSeek-V4.1-Flash (MaaS) はいずれも global エンドポイントでの提供。リージョン固定のデータレジデンシー要件がある場合は注意
⚠️DeepSeek モデルは Google 製品ではなく、Service Specific Terms の「Separate Offerings」条項とモデルカード記載の個別規約が適用される
⚠️CodeMender の SARIF 出力形式が変わるため、既存の GitHub Code Scanning / Cloud Build 連携パイプラインでは v0.15.0 更新後の出力確認を推奨

🎯 ユースケース

🛒 ユースケース 1: 顧客向け画像生成サービスの安定運用

シナリオ: EC サイトで商品画像のバリエーション生成に Gemini Nano Banana 2.1 を使用。セール期間などトラフィックが大きく変動するため、Provisioned Throughput の固定契約はコスト効率が悪い。

Python Priority PayGo のみを使用するクライアント設定 
client = genai.Client(
    vertexai=True,
    project="your_project_id",
    location="global",
    http_options=HttpOptions(
        api_version="v1",
        headers={
            "X-Vertex-AI-LLM-Request-Type": "shared",
            "X-Vertex-AI-LLM-Shared-Request-Type": "priority",
        },
    ),
)

効果: 事前コミットなしで Standard PayGo より安定した性能を確保でき、トラフィック変動の大きい本番ワークロードでもユーザー体験を維持できる。

🧑‍💻 ユースケース 2: 大規模リポジトリに対するエージェント型コーディング支援

シナリオ: 大規模なモノレポのコード理解・リファクタリング支援に、長大なコンテキストを扱えるモデルが必要。マルチモーダル入力でアーキテクチャ図やスクリーンショットも併せて解釈させたい。

効果: DeepSeek-V4.1-Flash の 1M トークンコンテキストにより大量のソースコードを一度に投入でき、MaaS のためインフラ管理なしで Function calling や構造化出力を活用したエージェントを構築できる。

🔒 ユースケース 3: プルリクエストごとのセキュリティゲート

シナリオ: GitHub Actions で CodeMender の diff スキャンを実行し、結果を GitHub Code Scanning に取り込んで PR 上にアノテーション表示したい。

Bash PR ブランチの diff スキャン 
cm find . --diff="origin/$BASE_REF" --fail-on=CRITICAL,HIGH \
  --format=sarif --output=codemender.sarif

効果: v0.15.0 の SARIF 2.1.0 強化 (リポジトリ相対パス、標準化されたルール記述子) により、Code Scanning 上での指摘箇所の表示が正確になり、レビュー効率が向上する。
