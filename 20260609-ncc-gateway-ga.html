📋 概要

NCC Gateway は Network Connectivity Center (NCC) ハブに接続できるスポークタイプであり、クロスクラウドネットワークトラフィックに対してサードパーティの Security Service Edge (SSE) などのセキュリティ機能を有効化するリージョナルプロダクトです。

NCC Gateway を Secure Access Connect と組み合わせることで、リモートワーカーを Google Cloud、オンプレミス、または他のクラウドプロバイダー上のプライベートアプリケーション、および Palo Alto Networks Prisma Access のようなパブリックアプリケーションに安全に接続し、SASE アーキテクチャの実現を大幅に簡素化します。

⚡ 主要機能

🔒 シームレスな SSE 統合

Palo Alto Networks Prisma Access (GA) および Symantec Cloud SWG (Preview) との統合。透過的なトラフィックステアリングによりユーザー-アプリ間を保護。

🛡️ 高可用性 (99.9% SLA)

アクティブなデータプレーンプロービングによるヘルスモニタリング。BGP セッション自動シャットダウンと復旧。Cloud Monitoring メトリクスによるアラート設定。

🌍 リージョナルデプロイメント

最大 100 Gbps の処理容量。SSE プロバイダーへの物理的近接性に基づくリージョン選択。Google プライベートバックボーンを活用。

🔗 Secure Access Connect

グローバルリソース (Realm) とリージョナルリソース (Attachment) で構成。SSE サービスを NCC Gateway に接続してセキュアなインターネットアクセスを提供。

Step 1: NCC Hub の作成

Bash 
gcloud network-connectivity hubs create my-ncc-hub \
    --description="NCC Hub for Gateway deployment" \
    --preset-topology=HYBRID_INSPECTION

Step 2: NCC Gateway Spoke の作成

Bash 
gcloud network-connectivity spokes linked-ncc-gateways create my-gateway-spoke \
    --hub=my-ncc-hub \
    --location=us-east4 \
    --spoke-group=gateways \
    --processing-capacity=10G

Step 3: Secure Access Connect Realm の作成

Bash 
gcloud beta network-security secure-access-connect realms create my-realm \
    --provider=PALO_ALTO_NETWORKS

Step 4: Secure Access Connect Attachment の作成

Bash 
gcloud beta network-security secure-access-connect attachments create my-attachment \
    --realm=my-realm \
    --location=us-east4 \
    --ncc-gateway-spoke=my-gateway-spoke

Step 5: VLAN Attachment の追加

Bash 
gcloud compute interconnects attachments create my-vlan-attachment \
    --router=my-cloud-router \
    --interconnect=my-interconnect \
    --region=us-east4 \
    --bandwidth=10g

✅ メリット

💼 ビジネス面

  • 統合セキュリティ管理: 単一スタックで全トラフィックを保護、運用コスト削減
  • SASE アーキテクチャ実現: ゼロトラストモデルへの移行が容易
  • ベンダーロックイン軽減: 複数 SSE プロバイダーから選択可能

🔧 技術面

  • 低レイテンシ: Google プライベートバックボーンで SSE アクセスを最適化
  • 高可用性: 99.9% SLA + アクティブヘルスモニタリング
  • スケーラビリティ: リージョンあたり最大 100 Gbps

⚠️ 制約事項・注意点

制限事項:
  • ❌ Cloud Interconnect VLAN Attachment のみサポート (Cloud VPN / ルーターアプライアンスは非対応)
  • ❌ リージョンあたり 1 つの NCC Gateway Spoke のみ作成可能
  • ❌ Spoke 作成後の IP アドレス範囲変更は不可
  • ❌ 1 つの NCC Gateway に同時接続できる SSE サービスは 1 つのみ
  • ❌ VLAN Attachment の MTU は 1500 バイト固定
  • ❌ トラフィックバイパスのステアリングポリシーは未対応
💡 考慮すべき点:
  • 処理容量計算にはトラフィックフロー方向を考慮 (双方向で 2 倍の容量が必要)
  • 一部リージョン/パートナーでは 100 Gbps 未サポートの場合あり
  • Realm と Attachment は作成後に編集不可 (削除・再作成が必要)
  • Gateway Advertised Route 使用時はアクティブな SSE ゲートウェイが必要

🎯 ユースケース

1. リモートワーカーのセキュアなプライベートアプリケーションアクセス

シナリオ: グローバルに分散したリモートワーカーが Google Cloud 上のプライベートアプリに安全にアクセスする必要がある組織。従来 VPN 経由だったが、パフォーマンスとセキュリティに課題。

経路: ブランチ → Cloud Interconnect → NCC Gateway → Prisma Access (SSE) → NCC Gateway → VPC

効果: 統一セキュリティポリシー適用 + Google バックボーンによる低レイテンシアクセスで、VPN 比較でセキュリティとパフォーマンスが向上。

2. マルチクラウド環境でのセキュアなインターネットブレイクアウト

シナリオ: オンプレミスと Google Cloud の両方からインターネットアクセスが必要で、全トラフィックにセキュリティ検査を適用したい組織。

経路: オンプレミス/GCP → NCC Gateway → SSE (検査) → インターネット/SaaS

効果: 一元的な脅威検知、DLP、URL フィルタリングを実現。攻撃表面を最小化。

3. 既存 NCC デプロイメントへの段階的セキュリティ追加

シナリオ: 既に NCC の Star / Full Mesh トポロジーでハイブリッド接続を運用中の組織が、セキュリティレイヤーを追加したい場合。

効果: 既存トポロジーを維持したまま (Brownfield) NCC Gateway Spoke を追加し、段階的に SASE アーキテクチャへ移行可能。

📝 まとめ

NCC Gateway の GA リリースは、Google Cloud におけるクロスクラウドセキュリティの重要なマイルストーンです。サードパーティ SSE との統合により、組織は単一の管理ポイントで全ネットワークトラフィックにセキュリティポリシーを適用でき、SASE アーキテクチャへの移行が大幅に簡素化されます。

Cloud Interconnect を使用したハイブリッド接続環境で、セキュリティとパフォーマンスの両立を求める組織は、NCC Gateway の導入を検討することを推奨します。
