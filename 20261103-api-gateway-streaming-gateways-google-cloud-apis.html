🚪 API Gateway

ストリーミングゲートウェイから Google Cloud API の呼び出しが可能に
API Gateway ストリーミング機能: Public Preview 生成 AI / Gemini 対応
📅 リリース日: 2026-11-03

📝 概要

API Gateway のストリーミングゲートウェイが、aiplatform.googleapis.com などの Google Cloud API をバックエンドとして呼び出せるようになりました。effectiveStreamingMode が EFFECTIVE_STREAMING_MODE_ENABLED のゲートウェイは、ホスト名が .googleapis.com または .vertexai.goog で終わるバックエンドに対して、ゲートウェイのサービスアカウントのアクセストークンで認証します。それ以外のバックエンドには従来どおり ID トークンが送信されます。

Google Cloud API はアクセストークンを要求するため、これまでゲートウェイ経由での呼び出しは 401 エラーで失敗していました。今回のアップデートにより、Gemini モデル (Agent Platform) のストリーミングレスポンスを API Gateway 経由でクライアントに中継する構成が、トークン変換用の中間プロキシなしで実現できます。

❌ Before (アップデート前の課題)

  • Google Cloud API (例: aiplatform.googleapis.com、bigquery.googleapis.com) はアクセストークンを要求するが、API Gateway は ID トークンのみを送信していたため、直接呼び出しは 401 エラーで失敗
  • Vertex AI / Agent Platform の Gemini モデルを API Gateway の背後に置くには、ID トークンをアクセストークンに変換する中間プロキシ (Cloud Run など) を自前で用意する必要があった

✅ After (アップデート後の改善)

  • .googleapis.com / .vertexai.goog で終わるホストに対して、ゲートウェイのサービスアカウントのアクセストークンで自動的に認証
  • Gemini モデル (Agent Platform) のストリーミングレスポンスを、API Gateway 経由でそのままクライアントに配信可能に
  • その他のバックエンドは引き続き ID トークンを受け取るため、既存のバックエンド認証構成に影響なしで Google Cloud API バックエンドを追加できる
💡 既存ゲートウェイの切り替え: 既存のストリーミングゲートウェイは、API Gateway が次回ゲートウェイアップデートをロールアウトした時点でこの動作に切り替わります。すぐに切り替えたい場合は、ゲートウェイを新しい API config に更新することで即時に適用されます。

⚡ 主要機能

🔑 1. Google Cloud API バックエンドへのアクセストークン認証

→ホスト名が .googleapis.com または .vertexai.goog で終わるバックエンドに対して、ゲートウェイのサービスアカウントのアクセストークンで認証
→アクセストークンのスコープは https://www.googleapis.com/auth/cloud-platform のみ。別の OAuth スコープを要求する API メソッドは呼び出せない
→対象バックエンドでは jwt_audience (OpenAPI 2.0) / jwtAudience (OpenAPI 3.x) フィールドは効果を持たない

🤝 2. 既存バックエンドとの共存

→同一ゲートウェイ上のその他のバックエンド (Cloud Run、Cloud Run functions など) は引き続き ID トークンを受け取る
→disable_auth (OpenAPI 2.0) / disableAuth (OpenAPI 3.x) を設定したバックエンドにはトークンが送信されない

🔄 3. 既存ゲートウェイの切り替えタイミング

→アクセストークンをまだ送信していない既存のストリーミングゲートウェイは、次回ゲートウェイアップデートのロールアウト時点で新しい動作に切り替わる
→即時に切り替えるには、ゲートウェイを新しい API config に更新する

ステップ 1: ストリーミングを有効にしてゲートウェイを作成

Bash --enable-streaming でゲートウェイを作成 
gcloud api-gateway gateways create GATEWAY_ID \
  --api=API_ID \
  --api-config=CONFIG_ID \
  --location=GCP_REGION \
  --enable-streaming
💡 ヒント: ストリーミングはゲートウェイ作成時にのみ指定できます。明示的に無効化するフラグはなく、--enable-streaming を省略した場合は API config とプラットフォームのデフォルトからモードが解決されます。

ステップ 2: ストリーミングモードを確認

Bash effectiveStreamingMode を確認 
gcloud api-gateway gateways describe GATEWAY_ID \
  --location=GCP_REGION

出力に effectiveStreamingMode: EFFECTIVE_STREAMING_MODE_ENABLED が含まれていれば、ストリーミングが有効です。

ステップ 3: サービスアカウントに IAM ロールを付与

Bash 例: Agent Platform (aiplatform.googleapis.com) を呼び出す場合 
gcloud projects add-iam-policy-binding PROJECT_ID \
  --member="serviceAccount:SA_EMAIL_ADDRESS" \
  --role="roles/aiplatform.user"

ゲートウェイの API config に関連付けたサービスアカウントに、呼び出し先 API が要求するロールを付与します。

ステップ 4: 既存ゲートウェイを即時切り替える場合

Bash 新しい API config に更新して即時適用 
gcloud api-gateway gateways update GATEWAY_ID \
  --api=API_ID \
  --api-config=NEW_CONFIG_ID \
  --location=GCP_REGION

既存のストリーミングゲートウェイは次回のゲートウェイアップデートのロールアウトで自動的に切り替わりますが、新しい API config に更新することで即時に適用できます。

⚖️ メリットと制約事項

👍 メリット

💼 ビジネス面
  • 中間プロキシの排除によるコスト・運用負荷の削減: ID トークンをアクセストークンに変換するためだけの中間サービス (Cloud Run プロキシなど) が不要になり、構成がシンプルに
  • 生成 AI API の統一的な公開: API Gateway の認証・API キー管理・レート制御の仕組みを使って、Gemini モデルなどの Google Cloud API をクライアントに公開できる
🔧 技術面
  • 自動的なトークン種別の切り替え: ホスト名に基づいてアクセストークン / ID トークンが自動で使い分けられ、API config 側での特別なトークン設定が不要
  • ストリーミングとの組み合わせ: SSE や HTTP チャンク転送と組み合わせて、Gemini モデルのトークン単位のストリーミングレスポンスをそのまま配信できる
  • 最小権限の IAM 制御: 呼び出せる API はサービスアカウントへの IAM ロール付与で制御でき、権限管理を一元化できる

⚠️ 制限事項・考慮点

🚧 制限事項
  • アクセストークンのスコープは cloud-platform のみ。別の OAuth スコープを要求する API メソッドは呼び出せない
  • 非ストリーミングゲートウェイは Google Cloud API 呼び出し非対応 (401 エラーで失敗する場合がある)
  • ストリーミングモードは作成時に固定。既存ゲートウェイの変更不可 (対応にはゲートウェイの新規作成が必要)
  • ストリーミングゲートウェイは HTTP(S) Load Balancing / Serverless NEG と非互換。Public Preview 期間中はカスタムドメインも利用不可
  • Terraform でのストリーミング有効化は未対応 (将来のリリースで対応予定)
🤔 考慮すべき点
  • 既存のストリーミングゲートウェイは次回ロールアウト時に自動的に新しい認証動作へ切り替わる。タイミングを制御したい場合は新しい API config への更新で即時適用
  • 対象バックエンドでは jwt_audience / jwtAudience が効果を持たなくなるため、既存設定の動作変化に注意
  • サービスアカウントへの IAM ロールは、呼び出し先 API が要求する最小限のロールに絞る
  • ストリーミングの deadline はレスポンス全体に対する実時間の上限 (デフォルト 15 秒、最大 3,600 秒)。長いストリーミングレスポンスでは調整が必要

🎯 まとめ

ストリーミングゲートウェイが Google Cloud API をアクセストークンで直接呼び出せるようになったことで、Gemini モデルなどの生成 AI API を API Gateway の背後に置く構成が中間プロキシなしで実現できます。

✓既存のストリーミングゲートウェイは次回のゲートウェイアップデートで自動的に切り替わるため、jwt_audience を利用している構成では事前に影響を確認する
✓必要な IAM ロール (例: roles/aiplatform.user) をゲートウェイのサービスアカウントに事前に付与しておくことを推奨
