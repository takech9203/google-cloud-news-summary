リリース日: 2026-11-09 | Google Cloud Release Notes
Anthos Config Management Config Sync Change (セキュリティ・依存関係更新)

📝 概要

Config Sync 1.25.2 がリリースされ、セキュリティに関する 3 つの関連アップデートが実施されました。 Config Sync は GitOps スタイルで Kubernetes クラスタの構成を Git リポジトリ・OCI イメージ・Helm チャートなどの ソースオブトゥルースと同期させるサービスであり、クラスタ運用の中核を担うコンポーネントです。

新機能の追加はありませんが、Config Sync はクラスタ内で常時稼働し Git リポジトリや外部レジストリと通信するコンポーネントであるため、 脆弱性の解消は運用上重要です。プラットフォーム管理者・セキュリティ担当者は本バージョンへのアップグレードを検討することが推奨されます。

❌ Before (〜1.25.1)

  • 依存関係に複数の既知の CVE が含まれていた
  • git-sync v4.4.2 はベースイメージに既知の脆弱性を含んでいた (v4.4.3 でベースイメージの CVE 修正、v4.5.0 で Debian trixie + git 2.47.3 に更新)
  • OpenTelemetry 0.152.0 には、その後のリリース (〜0.159.0) で修正された脆弱性が残存

✅ After (1.25.2)

  • 依存関係の更新により、複数の CVE が解消
  • git-sync v4.5.0: 新ベースイメージ (Debian trixie) と git 2.47.3 により脆弱性修正を取り込み
  • OpenTelemetry 0.159.0: 0.153.0〜0.159.0 の脆弱性修正を取り込み

Config Sync の Reconciler Pod を構成するコンテナのうち、Git リポジトリとの通信を担う git-sync コンテナと、 メトリクス収集を担う otel-agent コンテナ (OpenTelemetry イメージ) がそれぞれ脆弱性修正版にアップグレードされました。

🔧 主要な変更点

1️⃣ 複数の CVE への対応 (依存関係の更新)

→Config Sync 本体の依存関係を更新し、複数の既知の脆弱性 (CVE) を解消
→Config Sync では定期的な CVE 対応が継続的に実施されており (1.25.1、1.25.0 などでも同様の対応あり)、今回もその一環

2️⃣ git-sync 依存関係のアップグレード (v4.4.2 → v4.5.0)

→git-sync は Git リポジトリから構成ファイルをローカルディレクトリに取得するコンテナで、spec.sourceType が git の場合に Reconciler Pod 内で稼働
→v4.5.0 ではベースイメージが Debian trixie に更新され、git 2.47.3 が同梱。途中の v4.4.3 ではベースイメージの CVE が解消
→詳細は git-sync releases を参照

3️⃣ OpenTelemetry イメージのアップグレード (0.152.0 → 0.159.0)

→OpenTelemetry イメージは otel-agent コンテナおよび otel-collector として、Config Sync コンポーネントのメトリクスを収集し Cloud Monitoring / Prometheus にエクスポート
→脆弱性修正の取り込みを目的としたアップグレードで、各リリースの変更内容は opentelemetry-collector-contrib の CHANGELOG で確認可能

🛠️ 設定方法 (アップグレード手順)

💡 前提条件:
✓GKE クラスタで Config Sync を利用していること
✓フリート経由で管理している場合は gcloud CLI、手動インストールの場合は kubectl が利用可能であること
1

現在のバージョンを確認

nomos status コマンドで、各クラスタの Config Sync バージョンと同期状態を確認します。

Bash バージョン確認 
nomos status
2

バージョン 1.25.2 へアップグレード

自動アップグレード (auto-upgrade) を有効にしている場合は、Google が管理するスケジュールで自動的に新バージョンが適用されます。 手動管理の場合は、Config Sync のアップグレード手順に従ってバージョンを 1.25.2 に更新します。

3

アップグレード後の動作確認

Reconciler Pod が正常に再作成され、同期ステータスが SYNCED であることを確認します。

Bash 動作確認 
nomos status
kubectl get pods -n config-management-system

💼 ビジネス面

✓セキュリティコンプライアンスの維持: 既知の CVE が解消されるため、脆弱性スキャンやコンプライアンス監査への対応が容易に
✓運用リスクの低減: クラスタ構成管理の中核コンポーネントの脆弱性を放置することによるリスクを低減

🔧 技術面

✓攻撃対象領域の縮小: Git リポジトリや外部レジストリと通信する git-sync、メトリクスを扱う OpenTelemetry コンポーネントの既知の脆弱性が解消
✓最新ベースイメージの採用: git-sync v4.5.0 は Debian trixie ベースとなり、新しいバージョンの git (2.47.3) を利用可能
✓アプリケーションレベルの非互換なし: git-sync v4.5.0 はベースイメージ更新が主体でアプリケーションコードの変更はなく、既存の同期動作への影響は最小限

⚠️ デメリット・制約事項

⚠️ 考慮すべき点:
→アップグレード時に Reconciler Pod が再作成されるため、ごく短時間の同期の中断が発生しうる (同期対象リソース自体は削除されない)
→OpenTelemetry イメージのアップグレードでは、過去のバージョン (1.23.1 / 1.23.3 など) で Breaking Change が発生した例があるため、カスタムメトリクス構成を利用している場合は CHANGELOG で 0.153.0〜0.159.0 の変更内容を確認することを推奨 (今回のリリースノートでは Breaking とは明記されていない)

🎯 ユースケース

🔍 ユースケース 1: 脆弱性スキャン指摘への対応

シナリオ: コンテナイメージの脆弱性スキャンで、クラスタ内の Config Sync 関連イメージ (git-sync、OpenTelemetry) に既知の CVE が検出されている。

効果: Config Sync 1.25.2 へのアップグレードにより、依存関係・git-sync・OpenTelemetry イメージの既知の脆弱性が解消され、スキャン指摘をクローズできる。

🔄 ユースケース 2: 自動アップグレードによる継続的なセキュリティ維持

シナリオ: 複数クラスタで Config Sync を運用しており、毎回の手動アップグレードの運用負荷が高い。

効果: Config Sync の自動アップグレードを有効にすることで、今回のようなセキュリティパッチリリースが自動的に適用され、継続的に安全なバージョンを維持できる。

🔗 関連サービス・機能

☸️ Google Kubernetes Engine (GKE)

Config Sync は標準の GKE で利用可能であり、GKE クラスタの構成管理を GitOps で実現する。

📈 Cloud Monitoring

otel-collector が Config Sync のメトリクスを Cloud Monitoring にエクスポートするため、今回の OpenTelemetry イメージ更新はこの監視パイプラインに関係する。

🛡️ Policy Controller

Config Sync と組み合わせて利用されることが多いポリシー管理サービス (リリースは Config Sync とは独立)。
