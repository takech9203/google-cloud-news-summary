🔒 Cloud Service Mesh: GCP-2026-035 セキュリティパッチ

Security Cloud Service Mesh Envoy Proxy
2026-06-08

📋 概要

Google Cloud は、Cloud Service Mesh のインクラスター版に対してセキュリティパッチをリリースした。 セキュリティ情報 GCP-2026-035 に記載された脆弱性を修正するもので、サポート対象の全バージョンライン (1.26.x、1.27.x、1.28.x) に対して提供されている。

今回のリリースは、2026年6月3日に発表されていた以前のロールアウトを置き換える形で提供されている。6月3日のパッチに含まれていた修正に加えて GCP-2026-035 の脆弱性修正も統合されているため、 6月3日のパッチを未適用の環境でも今回のバージョンに直接アップグレードすることで両方の修正を取得できる。

⚠️ 緊急対応推奨: セキュリティパッチのため、インクラスター Cloud Service Mesh を利用している全ての環境で速やかなアップグレードが推奨されます。

🔄 Before / After 比較

❌ アップデート前

  • GCP-2026-035 に記載されたセキュリティ脆弱性が存在
  • 6月3日のロールアウトでは GCP-2026-035 の修正が未含有
  • 旧バージョンの Envoy プロキシによるセキュリティリスク残存

✅ アップデート後

  • GCP-2026-035 の脆弱性が全サポートバージョンで修正
  • 6月3日のパッチも統合、1回のアップグレードで全修正適用可能
  • 最新の Envoy プロキシでセキュリティ保護が強化

⚡ 主要機能

🛡️ セキュリティ脆弱性 GCP-2026-035 の修正

インクラスター Cloud Service Mesh の全サポートバージョンに対する修正パッチ。セキュリティ情報の詳細は GCP-2026-035 セキュリティ速報に記載。

🔗 6月3日ロールアウトの統合

以前発表されていたロールアウトが停止され、今回のリリースに統合。未適用環境は今回のバージョンに直接アップグレード可能で、全ての修正を一度に適用できる。

🔧 Envoy プロキシの更新

各バージョンラインで Envoy が最新のセキュリティ修正版に更新。データプレーンのセキュリティが最新状態に維持される。

  • asmcli ツールが利用可能であること
  • クラスタへの管理者アクセス権限があること

Step 1: 現在のバージョンを確認

Bash 
# インストールされている Cloud Service Mesh のバージョンを確認
kubectl get pods -n istio-system -o jsonpath='{.items[*].spec.containers[*].image}' | tr ' ' '\n' | sort -u

Step 2: asmcli でアップグレードを実行

Bash 
# Cloud Service Mesh のアップグレード (例: 1.28.7-asm.4)
./asmcli install \
  --project_id PROJECT_ID \
  --cluster_name CLUSTER_NAME \
  --cluster_location CLUSTER_LOCATION \
  --output_dir OUTPUT_DIR \
  --enable_all

Step 3: ワークロードの再デプロイ

Bash 
# サイドカープロキシの更新のため、ワークロードをローリング再起動
kubectl rollout restart deployment -n YOUR_NAMESPACE
💡 ヒント: アップグレード後、サイドカープロキシは自動的に新しいバージョンに更新されます。ただし、StatefulSet や Job は手動での再起動が必要です。

セキュリティ面

✓ 脆弱性の解消: GCP-2026-035 に記載されたセキュリティリスクが排除される
✓ 統合パッチ: 6月3日のパッチ内容も含まれており、1回の作業で全ての修正を適用可能
✓ Envoy の最新化: データプレーンのセキュリティが最新状態に更新される

運用面

✓ 簡素化されたアップグレードパス: 停止されたロールアウトを気にせず、最新版に直接アップグレード可能
✓ 全バージョンラインのカバー: サポート対象の全バージョン (1.26、1.27、1.28) にパッチが提供されている

⚠️ デメリット・制約事項

制限事項

✗ インクラスター Cloud Service Mesh のみが対象 (マネージド版は自動更新)
✗ v1.25 以前はサポート終了のため、本パッチの対象外
✗ アップグレードにはワークロードの再起動が必要

考慮すべき点

  • セキュリティパッチのため、検証環境での確認後、速やかに本番環境への適用を推奨
  • マルチクラスタメッシュの場合、全クラスタで順次アップグレードが必要
  • StatefulSet や Job は自動更新されないため、手動での再起動を忘れずに実施
  • Envoy v1.36.8-dev および v1.35.12-dev は開発版タグが付いているが、Google がセキュリティ検証済みのビルドである

💡 ユースケース

🚨 ユースケース 1: 本番環境の緊急セキュリティ対応

シナリオ: インクラスター Cloud Service Mesh 1.28.5-asm.9 を運用している本番環境で、GCP-2026-035 のセキュリティ通知を受けた場合

効果: GCP-2026-035 の脆弱性が解消され、6月3日のパッチ内容も同時に適用される

Bash 
# 1. 現在のバージョン確認
kubectl get pods -n istio-system -l app=istiod -o jsonpath='{.items[0].metadata.labels.istio\.io/rev}'

# 2. 新しいコントロールプレーンのインストール
./asmcli install \
  --project_id my-project \
  --cluster_name my-cluster \
  --cluster_location us-central1 \
  --output_dir ./asm-output \
  --enable_all

# 3. カナリアアップグレードで段階的に移行
kubectl label namespace my-app istio.io/rev=asm-1287-4 --overwrite
kubectl rollout restart deployment -n my-app

🔄 ユースケース 2: 6月3日パッチ未適用環境の一括対応

シナリオ: 6月3日に発表されたロールアウトの適用を待っていた環境で、当該ロールアウトが停止された場合

効果: 今回のパッチ1つで6月3日分の修正と GCP-2026-035 の修正を同時に適用でき、作業が一本化される

📝 まとめ

Cloud Service Mesh のインクラスター版に対して、GCP-2026-035 セキュリティ脆弱性を修正する緊急パッチがリリースされた。 このパッチは6月3日に発表された以前のロールアウトも統合しており、全サポートバージョン (1.26.x、1.27.x、1.28.x) が対象となっている。 セキュリティパッチのため、インクラスター Cloud Service Mesh を運用している環境では速やかなアップグレードを推奨する。
