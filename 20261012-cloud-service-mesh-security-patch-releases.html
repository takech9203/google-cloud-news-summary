📋 概要

2026 年 10 月 12 日、in-cluster (クラスタ内コントロールプレーン) 型の Cloud Service Mesh について 4 つのバージョンが同時リリースされました。新マイナーバージョン 1.31.1-asm.16 は Istio 1.31.1 の機能を取り込み、Envoy v1.39.3 を使用します。あわせて 1.30.5-asm.8 / 1.29.8-asm.8 / 1.28.10-asm.49 のパッチが提供されました。

最大のポイントはセキュリティ対応です。1.30.5-asm.8 と 1.29.8-asm.8 は Security Bulletin GCP-2026-067 の脆弱性を解消し、全パッチバージョンで CVE-2026-84782 (High、スコア 8.2) を含む 15 件のプラットフォーム CVE が修正されています。対象コンポーネントはプロキシ (Envoy サイドカー)、コントロールプレーン (istiod)、CNI で、Distroless イメージは影響を受けません。

❌ Before (アップデート前の課題)

  • 1.30 / 1.29 系に Security Bulletin GCP-2026-067 記載の脆弱性が存在
  • プロキシ・コントロールプレーン・CNI に CVE-2026-84782 (High 8.2) など複数の CVE が未修正
  • Istio 1.31 系の機能を in-cluster Cloud Service Mesh で利用不可

✅ After (アップデート後の改善)

  • 1.30.5-asm.8 / 1.29.8-asm.8 で GCP-2026-067 の脆弱性を解消
  • 全 4 パッチバージョンで 15 件のプラットフォーム CVE を修正
  • 1.31.1-asm.16 で Istio 1.31.1 の機能 (サポート対象機能リスト準拠) が利用可能に
⚠️ 推奨アクション: in-cluster Cloud Service Mesh を自己管理で運用しているユーザー (特に Google Distributed Cloud (software only) 環境) は、セキュリティリスク低減のため各マイナーバージョンの最新パッチへの早期アップグレードが推奨されます。

ステップ 1: asmcli で新しいコントロールプレーンのリビジョンをインストール

Bash 
./asmcli install \
  --project_id PROJECT_ID \
  --cluster_name CLUSTER_NAME \
  --cluster_location CLUSTER_LOCATION \
  --fleet_id FLEET_PROJECT_ID \
  --output_dir DIR_PATH \
  --enable_all \
  --ca mesh_ca

カナリアアップグレードでは、既存のコントロールプレーンと並行して新しいリビジョンがインストールされます。それぞれのコントロールプレーンはリビジョンラベルで識別されます。

ステップ 2: ワークロードを新しいコントロールプレーンへ移行

Bash 
# 新しいリビジョンラベルを namespace に設定
kubectl label namespace NAMESPACE istio.io/rev=REVISION --overwrite

# ローリング再起動でサイドカーを再注入
kubectl rollout restart deployment -n NAMESPACE

ローリング再起動によりサイドカープロキシが再注入され、新しいコントロールプレーンに接続されます。動作確認後に全トラフィックを新コントロールプレーンへ移行するか、問題があれば旧コントロールプレーンへロールバックできます。

⚖️ メリットと制約事項

💼 ビジネス面のメリット

✓セキュリティリスクの低減: GCP-2026-067 の脆弱性と High 深刻度を含む 15 件の CVE が解消され、コンプライアンス要件への対応が容易に
✓サポート継続性の確保: 最新パッチへの追従により、n-2 マイナーバージョンというサポートポリシーの範囲内で安全に運用を継続可能

⚙️ 技術面のメリット

✓カナリアアップグレードによる安全な移行: 新旧コントロールプレーンを並行稼働させ、namespace 単位で段階的に移行・ロールバック可能
✓Istio 1.31.1 の機能を利用可能: 1.31.1-asm.16 により、サポート対象機能リストの範囲で最新の Istio 機能を in-cluster 環境で利用できる

🚧 制限事項

✗1.31.1-asm.16 では Istio 1.31 の一部機能 (zoneAwareLbSetting、External SDS プロバイダなど) が非サポート
✗CVE 修正は Distroless イメージには適用されない (影響を受けないため)
✗GKE on Google Cloud 上の ISTIOD コントロールプレーンを使った in-cluster Cloud Service Mesh は非推奨 (deprecated)。Google Distributed Cloud (software only) での利用が引き続きサポートされる

🤔 考慮すべき点

⚠️アップグレード時はサイドカーの再注入 (Pod のローリング再起動) が必要であり、ワークロードの再起動計画が必要
⚠️インストール時のカスタマイズがある場合、overlay ファイルを指定しないとデフォルト設定に戻ってしまう
⚠️1.28 系は最短 EOL (2026 年 10 月 19 日) が目前のため、1.28.10-asm.49 の適用は暫定対応とし、1.29 以降への移行を計画すべき

🎯 ユースケース

🚨 ユースケース 1: GCP-2026-067 への緊急対応

シナリオ: Google Distributed Cloud (software only) 上で in-cluster Cloud Service Mesh 1.30 系を運用しており、Security Bulletin GCP-2026-067 の脆弱性への対応が必要。

Bash 
# 現在のバージョンを確認
istioctl version

# カナリアアップグレードで 1.30.5-asm.8 を導入
./asmcli install --project_id PROJECT_ID --cluster_name CLUSTER_NAME \
  --cluster_location CLUSTER_LOCATION --fleet_id FLEET_PROJECT_ID \
  --output_dir ./asm-output --enable_all --ca mesh_ca

効果: マイナーバージョンを変えずにパッチ適用のみで脆弱性を解消でき、アプリケーションへの影響を最小化しながらセキュリティリスクを除去できる。

📅 ユースケース 2: 1.28 系からの計画的なバージョンアップ

シナリオ: 1.28 系を運用中だが EOL (最短 2026 年 10 月 19 日) が迫っており、サポート継続のためにバージョンアップが必要。

効果: まず 1.28.10-asm.49 で CVE を解消して時間を確保しつつ、カナリアアップグレードで 1.29 / 1.30 系へ段階的に移行することで、サポートポリシー (n-2 マイナーバージョン) の範囲内で安全に運用を継続できる。

🔗 関連サービス・機能

→GKE (Google Kubernetes Engine): Cloud Service Mesh が稼働する基盤。GKE on Google Cloud では managed Cloud Service Mesh への移行が推奨される
→Google Distributed Cloud (software only): in-cluster コントロールプレーンが引き続きサポートされる主要プラットフォーム
→GKE Enterprise / Fleet: asmcli によるインストールではクラスタの Fleet 登録と fleet workload identity を利用
→Cloud Service Mesh certificate authority (Mesh CA): mTLS 証明書を発行するマネージド CA。アップグレード時に --ca mesh_ca で指定
