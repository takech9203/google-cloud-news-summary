🛡️ Security Command Center
データレジデンシー設定変更 & Agent Platform シークレットスキャン

Security Command Center Preview 📅 リリース日: 2026-07-31
データレジデンシー Preview プログラム組織の設定変更対応 / Agent Platform Vulnerability Assessment によるプレーンテキストシークレット検出

📋 概要

2026 年 7 月 31 日、Security Command Center に 2 つの機能アップデートが発表されました。いずれもセキュリティ運用とコンプライアンスに関わる重要な強化です。

1️⃣ データレジデンシー設定の変更対応 (Preview プログラム組織)

データレジデンシー Preview プログラムに登録している組織が、データレジデンシーおよびデータ暗号化の設定を変更できるようになりました。既存の Preview 構成を GA 構成へ更新し、データロケーションの変更 (マルチリージョン構成 → 単一ロケーション) や、Google 管理鍵と Cloud KMS 鍵 (CMEK) の切り替えが可能です。2026 年 7 月 9 日の Standard / Premium ティア (GA 構成) 向け提供に続く拡張です。

2️⃣ Agent Platform Vulnerability Assessment のシークレットスキャン (Preview)

顧客がデプロイした Gemini Enterprise Agent Platform コンテナ内のプレーンテキストシークレット (認証情報、アクセストークン、API キーなど) を継続的・自動的にスキャンし、Security Command Center に Finding を生成。AI エージェントの本番運用におけるシークレット漏洩リスクを早期に発見できます。

❌ Before (アップデート前の課題)
  • Preview プログラム登録組織は、一度設定したデータレジデンシー / データ暗号化の構成を後から変更する手段がなかった
  • Preview 時代のマルチリージョン構成から GA のデータレジデンシー構成へ移行するパスが提供されていなかった
  • Agent Platform (旧 Agent Engine) のコンテナイメージに平文シークレットが含まれていても自動検出できず、手動レビュー頼み
✅ After (アップデート後の改善)
  • コンソールからデータレジデンシー設定 (有効化 / 無効化、ロケーション選択) とデータ暗号化設定 (Google 管理鍵 / Cloud KMS 鍵) を変更可能に
  • 初回の更新でマルチリージョン構成から選択した単一ロケーションへデータ移行し、GA 構成に統一できる
  • コンテナ内の平文シークレットを継続スキャンし、SECRETS_IN_AGENT_ENGINE カテゴリの重大度 CRITICAL の Finding を自動生成

🛠️ 設定方法

📌 前提条件

データレジデンシー / 暗号化設定の変更
✓Security Command Center が組織レベルで有効化 (Standard / Premium ティア)
✓roles/securitycenter.admin を組織に付与
✓CMEK 使用時は Cloud KMS 鍵を作成・準備 (ロケーション変更時は鍵の再選択が必要)
✓ロケーション識別子に依存するミュートルールや Pub/Sub 継続エクスポート設定を事前確認
✓一括エクスポートの実行中でないこと
Agent Platform Vulnerability Assessment
✓Security Command Center Premium または Enterprise (Deprecated) ティア
✓AI Protection の有効化 (新規の AI Protection 有効化では本スキャナーは自動有効)

ステップ 1: データレジデンシー / データ暗号化設定の変更

手順 Google Cloud コンソール 
1. Google Cloud コンソールで [設定] > [セットアップの詳細] に移動
2. Security Command Center を有効化した組織を選択
3. [データ レジデンシーと暗号化の管理] をクリック
4. データレジデンシーの有効化 / 無効化とデータロケーションを選択
5. 暗号化構成 (Google 管理鍵 or Cloud KMS 鍵) を選択
6. [移行を開始] をクリックし、組織 ID を入力して確定
💡 補足: 移行中は Security Command Center のページにアクセスできず、ステータスページが表示されます。完了後、新しいロケーションのコンソールへのリンクが表示されます。

ステップ 2: Agent Platform Vulnerability Assessment の有効化 (既存顧客)

手順 AI Protection の設定 
1. Google Cloud コンソールで AI Protection カードの [設定] > [設定を管理] に移動
   (組織レベルビューでのみ利用可能)
2. [Vulnerability Assessment for Agent Platform] セクションで [設定を管理] をクリック
3. 組織またはプロジェクトに対してサービスを有効化

ステップ 3: シークレット検出結果への対応

手順 修復ワークフロー 
1. Finding の詳細を調査し、シークレットの内容を確認
2. 露出した認証情報を失効 (revoke) またはローテーション
3. Dockerfile、ソースコード、設定ファイルから平文シークレットを削除
4. Secret Manager などのシークレット管理ソリューションへ移行
5. イメージを再ビルドして Agent Platform インスタンスを再デプロイ
   (再デプロイで再スキャンが実行され、解消済みなら Finding は INACTIVE に)

⚖️ メリットと制約事項

✅ ビジネス面のメリット
  • コンプライアンス対応の柔軟性: Preview で先行導入した組織も、規制要件の変化に合わせてデータロケーション (EU / KSA / US) や暗号鍵管理方式を後から変更可能
  • AI エージェントの安全な本番運用: コンテナに混入した認証情報や API キーを自動検出し、シークレット漏洩による情報流出リスクを低減
✅ 技術面のメリット
  • Preview 構成から GA 構成への移行パス: マルチリージョン構成のデータを選択した単一ロケーションへ自動統合・移行
  • CMEK 対応: Google 管理鍵から Cloud KMS 鍵への切り替えで、鍵のライフサイクルを自組織で管理
  • 修復サイクルの自動化: 再デプロイをトリガーに再スキャンが実行され、解消された Finding が自動的に INACTIVE になり修復状況の追跡が容易
⚠️ 制限事項
  • データ移行は週 1 回まで。複数回変更する場合は 1 週間以上間隔を空ける
  • プロジェクトレベルのみの有効化では設定変更を利用不可
  • Preview 組織の初回更新では、データ暗号化のみの変更は不可 (データレジデンシー構成の GA 化が必須)
  • 移行中は SCC 全体 (コンソール、API、Finding 生成、エクスポート) が一時停止 (4〜24 時間)
  • Agent Platform Vulnerability Assessment は Preview のため Pre-GA Offerings Terms が適用され、サポートが限定される場合がある
  • Agent Platform Vulnerability Assessment は Premium / Enterprise (Deprecated) ティアのみ
🤔 考慮すべき点
  • ロケーション変更後は Finding の name / canonicalName が変わるため、ミュートルール、検索クエリ、外部システム連携、スクリプトの更新が必要
  • 外部システムへのエクスポートでは、ロケーション識別子の更新により重複 Finding が発生
  • 移行中に notificationConfigs が v1 → v2 構造へ更新され、source_properties は v2 API 非サポートのため Pub/Sub / BigQuery エクスポート設定の見直しが必要な場合がある
  • 移行前日付のダッシュボード集計値が正しく表示されない場合や、リージョン間の重複 Finding は最新の eventTime のバージョンのみ移行される点に注意
  • ロケーション選択は組織ポリシー (gcp.resourceLocations 制約) と整合性を取る必要がある (SCC 側では検証されない)

🎯 ユースケース

💼 ユースケース 1: Preview プログラム組織の GA 構成への移行

シナリオ: EU 域内のデータ保管要件を持つ金融機関が、データレジデンシー Preview プログラムに早期登録して Security Command Center を運用してきた。GA 構成へ統一し、あわせて CMEK による鍵管理へ切り替えたい。

実装例 GA 構成への移行手順 
1. Cloud KMS で EU リージョンの鍵リング・鍵を作成
2. ミュートルールと Pub/Sub 継続エクスポートのロケーション識別子依存を棚卸し
3. コンソールから [データ レジデンシーと暗号化の管理] でロケーション eu + Cloud KMS 鍵を選択して移行開始
4. 移行完了後、エクスポート設定・ミュートルール・検索クエリを新ロケーションに合わせて更新
✅ 効果: マルチリージョン構成の Preview データが eu に統合され、CMEK による暗号鍵の自組織管理と EU データレジデンシー要件への準拠を両立できる。
🤖 ユースケース 2: AI エージェント開発でのシークレット混入検出

シナリオ: 開発チームが Gemini Enterprise Agent Platform にカスタムエージェントをデプロイしている。開発中に外部 API の API キーを誤ってソースコードにハードコードしたままコンテナイメージをビルド・デプロイしてしまった。

🔗 関連サービス・機能

🔐 Cloud Key Management Service (Cloud KMS)

🗝️ Secret Manager

検出された平文シークレットの修復先として推奨されるシークレット管理サービス。

🤖 AI Protection

Agent Platform Vulnerability Assessment を含む AI ワークロード保護機能群。AI セキュリティダッシュボードで検出結果を確認可能。

🚀 Gemini Enterprise Agent Platform

スキャン対象のエージェント実行基盤。Agent Platform Threat Detection や Model Armor とも連携。

📤 Pub/Sub / BigQuery エクスポート

Finding のエクスポート先。データロケーション変更時に設定の見直しが必要。
