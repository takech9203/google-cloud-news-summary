🔍 Google SecOps: SIEM Search の
Basic Mode 検索が GA

Google SecOps GA (General Availability) SIEM Search デフォルトモード
📅 リリース日: 2026-11-16

📋 概要

Google SecOps の SIEM Search ページにおける Basic Mode 検索オプションが 一般提供 (GA) になりました。生イベントの取得とフィールド集計にコンピュートリソースを集中させる 「ファストパス」実行パイプライン を採用し、タイムライン集計・プリバレンス (普及度) スコアリング・ 検出相関などの二次的なエンリッチメントをバイパスすることで、検索の待ち時間を大幅に短縮します。 GA に伴い、Basic Mode は SIEM Search の デフォルトモード になりました。

対象ユーザーは、大量のテレメトリ (AWS VPC Flow、ファイアウォール、プロキシ、Sysmon ログなど) を日常的に トリアージする SOC アナリスト や、仮説検証のためにクエリを素早く反復したい 脅威ハンター です。 クエリ構文とデータの忠実性は Advanced Mode と完全に同一のまま、インタラクティブな応答性だけを高められます。

❌ Before: アップデート前の課題

  • 検索のたびにプリバレンス計算、YARA-L 2.0 検出相関、タイムラインのバケット集計、Entity Context Graph (ECG) 解決が常に実行され、大量テレメトリ検索でレイテンシが増大
  • インジケータ (ドメイン、IP、ファイルハッシュなど) のプリバレンス計算だけで最大 20 秒の追加処理時間が発生
  • クエリ構文や正規表現のチューニングといった反復作業でも、毎回フルエンリッチメントの完了を待つ必要があった

✅ After: アップデート後の改善

  • ファストパス実行によりプリバレンス計算・検出エンリッチメント・タイムライン集計をバイパスし、マッチしたイベントを直接クライアントにストリーミング
  • UI は Results タブのみに絞られ、Events パネルと Event Viewer の画面スペースを最大化 (Aggregations パネルは利用可)
  • モードはローカルストレージ・URL パラメータ (&searchMode=FAST / ADVANCED)・検索履歴に記録され、URL 共有や再実行時に正しく引き継がれる

Basic Mode はプリバレンス計算・検出相関・タイムライン集計をバイパスして高速に結果を返し、 深掘りが必要になった時点で Advanced Mode に切り替えて同じクエリを再実行するワークフローを想定しています。

⚡ 主要機能

🚀 1. ファストパスのバックエンド実行
→プリバレンス計算のバイパス: ドメイン・IP アドレス・ファイルハッシュなどのインジケータに対する企業全体の履歴プリバレンス評価をスキップし、大量イベントストリームで最大 20 秒の処理時間を削減
→検出エンリッチメントの抑制: 検出相関の上限を 0 に設定し、イベント取得中のルールエンジンへの二次ルックアップを排除
→タイムライン集計のプルーニング: 細かいバケット化ヒストグラム計算をスキップし、マッチしたイベントを直接クライアントにストリーミング
🖥️ 2. 合理化されたインターフェース
→タブ表示の集約: Results タブのみを表示し、Alerts & Detections / Overview / Visualize タブを非表示にしてタブ切り替えのレイテンシを排除
→チャートウィジェットの非表示: Activity Over Time / Trend Over Time チャート、Prevalence タブ、Activity ヒートマップを自動非表示にし、Events パネルと Event Viewer の縦方向スペースを最大化
→フィールド集計の同等性: Aggregations パネルは引き続きアクティブで、値分布カウントの確認、Show only / Filter out フィルタの適用、結果の絞り込みが可能
🔗 3. モードの永続化と共有
→ブラウザ設定の永続化: 選択したモードはローカルストレージ (searchMode) に保存され、リフレッシュ・タブ・セッションをまたいで維持
→共有可能な URL 状態: アクティブなモードは URL クエリパラメータ (&searchMode=FAST または ADVANCED) に反映され、共有 URL のモードが受け取り側のブラウザ設定より優先
→検索履歴への記録: History ダイアログの各クエリに実行時のモードが記録され、履歴からの再実行時に当時のモードが自動復元

レイテンシプロファイル ⚡ 最小限の待ち時間 (インタラクティブなフィードバック) ⏱️ 標準的な待ち時間 (フルエンリッチメントを計算)

🎯 推奨される利用シナリオ

シナリオ 推奨モード 理由
初期の脅威ハンティング・仮説検証 ⚡ Basic Mode タイムラインヒストグラムを待たずに広い時間範囲でインジケータ仮説をテスト
大量テレメトリのトリアージ ⚡ Basic Mode AWS VPC Flow、ファイアウォール、プロキシ、Sysmon ログなどを最小レイテンシでクエリ
クエリ作成・フィルタチューニング ⚡ Basic Mode UDM 構文、正規表現、リファレンスリスト、データテーブルフィルタを反復調整
インシデントタイムラインの再構築 🔬 Advanced Mode イベント分布タイムラインとアクティビティヒートマップで時間的バーストを特定
インジケータの希少性・異常分析 🔬 Advanced Mode プリバレンススコアで観測アーティファクトが一般的か外れ値かを評価
検出の検証 🔬 Advanced Mode 特定イベントが YARA-L 2.0 アラートルールをトリガーしたかを確認

⚙️ 設定方法

✅ 前提条件

✓Google SecOps のライセンスとインスタンスが有効であること
✓ユーザーアカウントに Google SecOps Search の標準的な権限・ロールが割り当てられていること (データ RBAC 使用環境では、割り当てられたスコープに一致するデータのみ表示)

📝 手順

1
SIEM Search ページを開く
Google SecOps にログインし、ナビゲーションバーで Investigation > SIEM Search をクリックする
2
検索実行モードを選択する
クエリエディタで Basic Mode (デフォルト) または Advanced Mode を選択し、クエリを入力して Run Search をクリックする。選択したモードはブラウザのローカルストレージに保存され、以降の検索にも適用される
3
必要に応じて Advanced Mode に切り替える
Basic Mode の Results タブで疑わしいイベントを特定したら、Advanced Mode に切り替えて同じクエリを再実行し、タイムラインチャート、ヒートマップ、プリバレンススコア、相関検出を確認する

💡 メリット・デメリット

✅ ビジネス面のメリット
✓トリアージの高速化: 大量テレメトリへの検索待ち時間が最小化され、SOC アナリストの 1 件あたりの調査時間を短縮
✓チームコラボレーションの一貫性: 調査 URL にモードが埋め込まれ、共有相手も同じ表示状態で調査を引き継げる
✅ 技術面のメリット
✓クエリ・データの完全互換: クエリ構文とデータの忠実性は Advanced Mode と同一で、モード切り替えにクエリの書き換えは不要
✓最大 20 秒の処理時間削減: プリバレンス計算のバイパスだけで大量イベントストリームにおいて最大 20 秒を削減
✓画面スペースの最適化: チャートやタブの非表示により Events パネルと Event Viewer に集中した調査が可能
⚠️ 制限事項
✗Basic Mode ではプリバレンススコアリング、相関検出 (YARA-L 2.0)、Entity Context Graph、タイムラインチャートが利用不可 (必要な場合は Advanced Mode で再実行)
✗結果画面は Results タブのみで、Alerts & Detections / Overview / Visualize タブは表示されない
🤔 考慮すべき点
→モード設定はブラウザのローカルストレージ保存のため、別のブラウザや端末では再設定が必要
→共有 URL のモード指定は受け取り側のブラウザ設定より優先され、意図しないモードで開かれる場合がある
→時系列再構築や異常分析など、エンリッチメント情報が本質的に必要な調査では最初から Advanced Mode を使う方が効率的

🎯 ユースケース

📡 ユースケース 1: 大量テレメトリに対する初動トリアージ

シナリオ: SOC アナリストが、脅威インテリジェンスで共有された不審な IP アドレスについて、 過去 30 日間のファイアウォール・プロキシログを横断的に検索して影響範囲を素早く確認したい。

UDM Basic Mode (デフォルト) で UDM 検索を実行 
# Basic Mode (デフォルト) で UDM 検索を実行
target.ip = "203.0.113.10"

効果: タイムライン集計やプリバレンス計算を待たずにマッチしたイベントが直接ストリーミングされ、 広い時間範囲でも最小限の待ち時間でヒットの有無を確認できる。疑わしいイベントが見つかったら Advanced Mode に切り替えて深掘りする。

🛠️ ユースケース 2: 検出ルール作成前のクエリチューニング

シナリオ: 検出エンジニアが YARA-L ルール化する前に、UDM 構文・正規表現・リファレンスリストの 組み合わせを何度も試行してノイズを絞り込みたい。

効果: クエリの反復実行ごとのエンリッチメント待ちがなくなり、Aggregations パネルの値分布と Show only / Filter out フィルタを使って短いサイクルでフィルタ条件を調整できる。

🔗 関連サービス・機能

→UDM Search (SIEM Search): 本機能の対象となる検索基盤。UDM / RAW / JOIN / STATS など複数の検索タイプをサポート
→YARA-L 2.0 検出エンジン: Advanced Mode で相関検出として統合される検出ルール。Basic Mode ではルックアップがバイパスされる
→Entity Context Graph (ECG): Advanced Mode で解決されるエンティティコンテキスト。Basic Mode ではバイパスされる
→データ RBAC: 検索結果はユーザーロールに割り当てられたデータスコープに基づいてフィルタリングされる

📝 まとめ

Google SecOps の SIEM Search における Basic Mode が GA となり、 デフォルトの検索実行モードとして大量テレメトリの高速トリアージとクエリ反復を支えるようになりました。 日常の初動調査やクエリチューニングは Basic Mode で行い、タイムライン分析・プリバレンス評価・検出検証が 必要な場面でのみ Advanced Mode に切り替える、という使い分けを SOC の標準ワークフローに 組み込むことを推奨します。
