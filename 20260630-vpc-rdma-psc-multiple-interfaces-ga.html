🌐 Falcon VPC ネットワークで複数 PSC インターフェースをサポート

Virtual Private Cloud Networking GA
2026-06-30
RDMA + Private Service Connect

📋 概要

Google Cloud は、RDMA ネットワークプロファイルを使用する Falcon VPC ネットワークにおいて、 単一の Compute Engine インスタンスから複数の仮想 PSC インターフェースを使用した接続機能を General Availability (GA) としてリリースしました。

HPC (High Performance Computing) や AI/ML ワークロードで高帯域幅・低レイテンシの RDMA 通信を必要とするシナリオにおいて、 マネージドサービスプロデューサーが RDMA 対応コンシューマーネットワークに対してスケーラブルな接続を確立できるようになりました。

Before / After

❌ アップデート前

  • Falcon VPC では PSC が PSC_BLOCKED としてブロック
  • RDMA 対応ネットワークへの接続手段が限定的
  • 複数接続を確立する標準的な方法がなかった

✅ アップデート後

  • 複数 PSC インターフェース経由の RDMA 接続が GA
  • 単一 VM から複数コンシューマーネットワークに接続可能
  • PSC のセキュリティモデル + RDMA 高性能通信を両立

💡 ポイント: 各 PSC インターフェースは異なるネットワークアタッチメントに接続し、RDMA over Falcon transport プロトコルによる低レイテンシ通信を実現します。

⚡ 主要機能

🔗 複数 PSC インターフェースによる RDMA 接続

  • 単一 Compute Engine インスタンスから複数 PSC インターフェースで Falcon VPC に接続
  • 各 PSC インターフェースは異なるネットワークアタッチメント (異なるコンシューマー VPC) に接続
  • RDMA over Falcon transport プロトコルによる低レイテンシ通信

🦅 Falcon VPC ネットワークとの統合

  • IRDMA NIC タイプのみをサポート
  • ゾーン制約: RDMA ネットワークプロファイルと同じゾーン内に限定
  • 推奨 MTU: 8896 バイト (Falcon VPC のデフォルト)

🔐 PSC インターフェースの接続モデル

  • プロデューサー VPC からコンシューマー VPC への接続 (マネージドサービスエグレス)
  • 接続は双方向かつトランジティブ (他のワークロードへのアクセスも可能)
  • ネットワークアタッチメントによるアクセス制御 (手動/自動承認)

Falcon VPC ネットワークの仕様

🛠️ 設定方法

前提条件

✅Falcon VPC ネットワークが作成済み (ZONE-vpc-falcon プロファイル使用)
✅コンシューマー側でネットワークアタッチメントが作成済み
✅プロデューサープロジェクトがネットワークアタッチメントの承認リストに含まれている
✅H4D マシンシリーズが利用可能なゾーンである

Step 1: Falcon VPC ネットワークの作成 (コンシューマー側)

Bash Falcon VPC ネットワークとサブネットの作成 
# Falcon VPC ネットワークの作成
gcloud compute networks create rdma-falcon-network \
  --network-profile=ZONE-vpc-falcon \
  --subnet-mode custom

# サブネットの作成
gcloud compute networks subnets create rdma-falcon-subnet \
  --network=rdma-falcon-network \
  --region=REGION \
  --range=10.0.0.0/16

Step 2: ネットワークアタッチメントの作成 (コンシューマー側)

Bash ネットワークアタッチメントの作成 
# ネットワークアタッチメントの作成
gcloud compute network-attachments create consumer-attachment \
  --region=REGION \
  --subnets=rdma-falcon-subnet \
  --connection-preference=ACCEPT_MANUAL \
  --producer-accept-list=PRODUCER_PROJECT_ID

Step 3: 複数 PSC インターフェースを持つ VM の作成 (プロデューサー側)

Bash 複数 PSC インターフェースを持つ VM を作成 
# 複数の PSC インターフェースを持つ VM を作成
gcloud compute instances create producer-vm \
  --zone=ZONE \
  --machine-type=MACHINE_TYPE \
  --network-interface='subnet=producer-subnet,no-address' \
  --network-interface='network-attachment=projects/CONSUMER_PROJECT/regions/REGION/networkAttachments/consumer-attachment-1' \
  --network-interface='network-attachment=projects/CONSUMER_PROJECT/regions/REGION/networkAttachments/consumer-attachment-2'

Step 4: ルーティングの設定

💡 注意: VM 作成後、ゲスト OS 内でルーティングを手動設定し、PSC インターフェースを経由するトラフィックを適切にルーティングする必要があります。

✅ メリット

ビジネス面

🚀マネージドサービスの拡張性: サービスプロデューサーが RDMA 対応コンシューマーネットワークに対してスケーラブルな接続を提供可能
⚡HPC/AI ワークロードの加速: 高帯域幅・低レイテンシ通信により、分散処理の性能が向上
🔒セキュアな接続モデル: PSC のアクセス制御モデルにより、ネットワーク分離を維持しながら高性能通信を実現

技術面

🔥RDMA による高性能通信: カーネルバイパスによる低レイテンシ・高スループットのデータ転送
🔌マルチ NIC サポート: Falcon VPC ネットワークでは同一ネットワーク内の複数 NIC をサポート
🔀トランジティブ接続: PSC インターフェース経由でコンシューマーネットワークに接続された他のリソースにもアクセス可能

⚠️ デメリット・制約事項

制限事項

  • Falcon VPC ネットワークはゾーン制約あり (RDMA プロファイルと同一ゾーン内に限定)
  • nic0 を Falcon VPC ネットワークにアタッチ不可 (RDMA NIC は nic0 以外のみ)
  • VPC ピアリング、Cloud LB、Cloud NAT、Cloud VPN、Cloud Interconnect は利用不可
  • 外部 IP アドレス割り当て不可 (RDMA NIC はインターネットアクセスなし)
  • Cloud NGFW によるファイアウォールポリシー設定不可 (暗黙の許可ルール適用)

考慮すべき点

  • PSC インターフェース接続後、ゲスト OS でのルーティング設定が手動で必要
  • マルチテナント構成では、1 コンシューマーのアクションが他コンシューマーに影響する可能性あり
  • 各 PSC インターフェースは異なるネットワークアタッチメント (異なるコンシューマー VPC) に接続する必要あり

🎯 ユースケース

🤖 ユースケース 1: AI/ML 分散学習基盤

シナリオ: マネージドサービスプロバイダーが、複数のコンシューマー組織に対して AI モデルの分散学習サービスを提供。各コンシューマーは Falcon VPC 上に H4D インスタンスの GPU クラスタを保有し、プロデューサーのオーケストレーション VM が複数の PSC インターフェースで各コンシューマーの学習ノードと RDMA 通信。

効果: RDMA による低レイテンシ通信で、パラメータサーバーと学習ノード間のグラディエント同期が高速化され、分散学習スループットが大幅に向上。

🖥️ ユースケース 2: HPC クラスタのマネージドサービス

シナリオ: HPC サービスプロバイダーが、コンシューマーの Falcon VPC 内の計算ノードに対してジョブスケジューリングやデータ配信を実施。単一管理 VM から複数 PSC インターフェースで異なるコンシューマーの HPC クラスタに接続。

効果: PSC のセキュリティモデルを維持しながら、RDMA の高帯域幅を活用した効率的なデータ転送とジョブ管理が可能に。

🔗 関連サービス・機能

🖥️ Compute Engine (H4D シリーズ)

Falcon VPC でサポートされるマシンタイプ。IRDMA NIC による Cloud RDMA 通信が可能。

🤖 AI Hypercomputer

RDMA ネットワークプロファイルは AI ワークロード向けに設計され、AI Hypercomputer の一部として機能。

🔗 Private Service Connect

PSC インターフェースはプロデューサーからコンシューマーへの接続 (マネージドサービスエグレス) を提供。

☸️ GKE

H4D ノードプールで Falcon VPC への接続をサポートし、Pod レベルで RDMA 通信が可能。

🌐 Cloud RDMA (RoCE VPC)

A3 Ultra / A4 / A4X マシンタイプ向けの別の RDMA 実装 (MRDMA NIC 使用)。

📝 まとめ

今回の GA リリースにより、Falcon VPC ネットワーク (RDMA ネットワークプロファイル) を使用するコンシューマー環境に対して、プロデューサー側の単一 VM から複数の PSC インターフェースを介した RDMA 接続が本番環境で利用可能になりました。

推奨アクション: H4D マシンシリーズを使用した AI Hypercomputer 環境を構築している場合は、この機能の活用を検討してください。HPC や AI/ML ワークロードで高帯域幅・低レイテンシ通信を必要とするマネージドサービスプロバイダーは、PSC のセキュリティモデルを維持しながら RDMA の性能を活用できます。
