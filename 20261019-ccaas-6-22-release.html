📋 概要

Google Cloud CCaaS のバージョン 6.22 が正式リリースされました。 10 月 13 日のプレリリースノートで予告されていたとおり、2 つの新機能と45 件のバグ修正が提供開始されています。 各インスタンスへの適用タイミングは、契約時に選択したデプロイスケジュールに依存するため、管理者は自社インスタンスの更新時期を確認する必要があります。

❌ アップデート前の課題

  • スケジュールコールはインバウンド向けのみで、アウトバウンドキャンペーン通話中にコールバックをキャンペーン単位で予約・管理する仕組みがなかった
  • チャットトランスクリプトは 1 セッション = 1 統合ファイルで、転送・エスカレーション時に担当範囲を切り分けにくかった
  • 重複コールレコード、SIP 603 エラーによる着信拒否、録音の歪み、国際地域での IVR コールバック番号の誤りなど多数の既知の不具合が存在

✅ アップデート後の改善

  • キャンペーン通話中にコールバックを予約でき、ダイヤラーが選択されたタイムスロットに自動で再架電。スロット長・キャパシティ・予約可能期間・有効期限を設定可能
  • Transcript Separation で Per Segment を選択すると参加者セグメントごとに個別トランスクリプトを配信 (消費者には従来どおり統合版)
  • 音声・録音品質、チャット、レポーティング、CRM 連携、国際化、セキュリティにわたる 45 件の不具合を修正

⚡ 主要機能

💬 1. チャットのトランスクリプト分割 (Transcript Separation)

✓1 セッション 1 統合トランスクリプトではなく、参加者セグメントごとに個別ファイルを配信するよう構成できる
✓設定場所: Settings > Chat > Chat Transcript > Transcript Separation で Per Segment を選択
✓エージェント・仮想エージェント・スーパーバイザーごとに個別ファイルが生成され、転送・エスカレーション時の担当範囲の特定が容易に
✓消費者には設定にかかわらず常に全チャットの統合トランスクリプトが提供される
⚠デフォルトは無効。有効化には Google Cloud サポートへの連絡が必要

📅 2. キャンペーンベースのスケジュールコールバック

✓エージェントがアウトバウンドキャンペーン通話中にコールバックを予約できる
✓コールバックは個々のエージェントではなくキャンペーンに帰属し、ダイヤラーが消費者の選択したタイムスロットに自動で再架電
✓管理者はキャンペーンごとにスロット長・キャパシティ・予約可能期間・有効期限を設定可能
✓スーパーバイザーはキャンペーンリストから「予定 / 完了 / 期限切れ」のコールバックを追跡可能

🔧 3. 45 件のバグ修正 (テーマ別)

テーマ主な修正内容
📞 通話ルーティング・安定性 重複コールレコードの作成 (リアルタイムキューの待ち時間誤表示の原因)、DB 高レイテンシ時の SIP 603 エラーによる着信拒否、1 通話の 2 エージェント同時割り当て、クローズ済みキューへの転送、非表示の転送制限が有効なまま残る問題
🎙️ 録音・音声品質 複数回の保留による録音の歪み、ウォーム転送後も保留音が録音され続ける問題、拡張子のみの音声フォーマット検証による通話切断、アウトバウンド仮想エージェント音声の途中切断
💬 チャット・仮想エージェント 人間へのエスカレーションで最大 300 秒の割り当て遅延、チャットイベントからの会話 ID 欠落、無応答エンドユーザーへのチャット割り当て、バージイン時にスーパーバイザー名が非表示
📊 レポーティング・モニタリング 対応可能エージェント数の 0 誤表示 (スキルベースキュー)、通話・ラップアップ時間の重複レポート行、レポートエクスポートの未完了、デフレクション通話メタデータの Cloud Storage 未エクスポート
🔗 CRM・エージェント体験 Salesforce ルックアップ失敗時の重複レコード作成、キャンペーン通話中の CRM レコード自動表示不具合、必須ディスポジションの破棄、削除済みステータス起因のサインイン不可
🌍 国際化・地域対応 ノルウェー・デンマークなどの IVR コールバック番号への誤った +1 プレフィックス付与、セッションメタデータが設定言語ではなく英語で表示される問題
🔒 セキュリティ Kubernetes / Google Cloud サービスアカウントの過剰権限 (権限昇格リスク) の是正
♿ アクセシビリティ・UI 400% ズーム時のチャットウィジェットのテキストサイズメニューがスクロール不可、エージェントアダプター iframe 幅が狭い場合の表示崩れ
📚 ドキュメント Apps API / コールセッションメタデータスキーマの parentId・finishReason フィールド未定義、Manager API のエージェントアクティビティログで 17 個のチャットルーティング値が未記載

🛠️ 設定方法

📌 前提条件:
  • CCaaS (CCAI Platform) インスタンスがバージョン 6.22 に更新されていること (デプロイスケジュールを確認)
  • トランスクリプト分割の利用には Google Cloud サポートによるインスタンスでの有効化が必要
  • キャンペーンコールバックの利用にはアウトバウンドキャンペーン (キャンペーンマネージャー) の運用が前提
1
💬 トランスクリプト分割の有効化
  1. Google Cloud サポートに連絡し、インスタンスでの Transcript Separation 機能の有効化を依頼する
  2. CCAI Platform ポータルで Settings > Chat > Chat Transcript に移動する
  3. Transcript Separation で Per Segment を選択して保存する
2
📅 キャンペーンコールバックの設定
  1. CCAI Platform ポータルでキャンペーン設定を開く
  2. キャンペーンごとにスロット長、キャパシティ、予約可能期間、有効期限を設定する
  3. エージェントはキャンペーン通話中に消費者の希望時間帯でコールバックを予約する
  4. スーパーバイザーはキャンペーンリストから予定・完了・期限切れのコールバックを追跡する

💡 メリット

💼 ビジネス面

✓再架電の確実性と接続率の向上: コールバックがキャンペーンに帰属するため、予約したエージェントのシフトや離席に左右されず、消費者が選んだ時間帯に確実に再架電。商談機会の喪失防止と顧客体験の向上が期待できる
✓キャンペーン運用の可視性向上: 予定・完了・期限切れのコールバックを一覧で追跡でき、未消化コールバックの検知や改善サイクルの運用が容易に
✓品質管理・監査の効率化: 参加者別トランスクリプトにより、QA やコンプライアンス監査で各参加者の対応内容を正確に切り分けて評価できる

✓グローバル展開時の信頼性向上: ノルウェー・デンマークなどでの IVR コールバック番号の +1 プレフィックス誤付与が修正され、国際地域でのコールバック運用が正常化

⚠️ デメリット・制約事項

🚧 制限事項
  • トランスクリプト分割はデフォルトで無効。有効化には Google Cloud サポートへの連絡が必要 (セルフサービスで有効化できない)
  • バージョン 6.22 の適用時期はデプロイスケジュールに依存するため、リリース日時点で全インスタンスに反映されているわけではない
🤔 考慮すべき点
  • トランスクリプト分割を有効にすると配信されるファイル数が増加するため、後続のファイル処理・保管・分析フローへの影響を事前に確認する
  • キャンペーンコールバックのスロット長・キャパシティ・予約可能期間・有効期限はキャンペーンごとの設計が必要。既存のキャンペーン運用設計 (エージェント配置やダイヤリングモード) との整合を取る
  • プレリリースノート (10 月 13 日公開) を前提に準備していた場合も、正式リリースノートで修正一覧 (45 件) を改めて確認することを推奨

🎯 ユースケース

📞 ユースケース 1: アウトバウンドセールスキャンペーンでの再架電予約

シナリオ: 保険商品のアウトバウンドキャンペーンで、消費者が「明日の午後にかけ直してほしい」と希望した場合、エージェントが通話中にその時間帯のコールバックを予約する。

効果: コールバックはキャンペーンに帰属するため、翌日に当該エージェントが不在でもダイヤラーが指定スロットで自動的に再架電。スーパーバイザーは期限切れコールバックを監視し、未消化の再架電を検知してフォローできる。

🔍 ユースケース 2: エスカレーションを含むチャットの品質監査

シナリオ: 仮想エージェントで開始されたチャットが人間のエージェントにエスカレーションされ、さらにスーパーバイザーがバージインした会話について、各参加者の対応品質を監査する。

効果: Per Segment 設定により、仮想エージェント・エージェント・スーパーバイザーそれぞれのトランスクリプトファイルが個別に生成され、担当範囲を明確に切り分けて評価できる。消費者には従来どおり統合トランスクリプトが提供されるため、顧客体験は変わらない。

🔧 ユースケース 3: 既知の不具合に起因する運用課題の解消

シナリオ: リアルタイムキュービューの待ち時間が実態と乖離している、国際地域の IVR コールバックが失敗するなどの不具合に悩まされていたコンタクトセンターが、6.22 への更新で解消を図る。

効果: 重複コールレコードや IVR コールバック番号プレフィックスの修正などにより、回避策 (手動補正や個別サポート問い合わせ) が不要になり、運用負荷が低減する。

🔗 関連サービス・機能

📥 スケジュールコール (インバウンド)
営業時間外やキュー超過時に消費者がコールバックを予約できる既存機能。今回のキャンペーンベースのコールバックは、これをアウトバウンドキャンペーンの文脈に拡張するもの。
📤 アウトバウンドダイヤラー / キャンペーンマネージャー
Preview / Predictive / Progressive の各ダイヤリングモードを提供するキャンペーン管理基盤。スケジュールコールバックはこの基盤上で動作する。
💬 チャットトランスクリプト / CRM 連携
チャット終了後にトランスクリプトを Salesforce、Zendesk などの CRM や外部ストレージへ配信する既存機能。トランスクリプト分割はこの配信単位を参加者セグメントごとに変更する。
🪣 Cloud Storage
通話メタデータやトランスクリプトのエクスポート先。本リリースではデフレクションされた通話のメタデータがエクスポートされない不具合も修正された。

CCaaS 6.22 が正式リリースされ、プレリリースノートで予告されていたチャットトランスクリプトの参加者別分割とキャンペーンベースのスケジュールコールバックが利用可能になり、音声・チャット・レポーティング・セキュリティにわたる 45 件のバグ修正が適用されました。 インスタンスへの適用時期はデプロイスケジュールに依存するため、管理者はまず自社の更新タイミングを確認し、トランスクリプト分割を利用する場合は Google Cloud サポートへの有効化依頼、キャンペーンコールバックを利用する場合はスロット設計を進めることを推奨します。
