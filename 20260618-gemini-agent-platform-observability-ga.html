GA Agent Platform

📋 概要

Gemini Enterprise Agent Platform の Agent Observability が一般提供 (GA) となった。デプロイされた AI エージェントおよび MCP サーバーのパフォーマンス、動作、ヘルスに対する包括的な可視性を提供する。

🤖 主なポイント:
  • ADK エージェントの新規デプロイで OpenTelemetry トレーシングがデフォルト有効化
  • マルチモーダルペイロードのストレージが Cloud Storage (GCS) をデフォルトに変更
  • トレーススパンの DAG 表示による実行パスの視覚的検査が可能に

🔄 Before / After

❌ Before (Preview)

  • SLA 保証なし、本番利用に不安
  • トレーシング有効化に手動設定が必要
  • ペイロードは Cloud Logging に保存 (256KB 制限)
  • 実行パスの視覚化ツールが限定的

✅ After (GA)

  • SLA 保証で本番環境に正式対応
  • OpenTelemetry トレーシングがデフォルト有効
  • GCS がデフォルトで大容量データに対応
  • DAG 表示でステップバイステップ検査が可能

⚡ 主要機能

1. デフォルト有効トレーシング (Default-On Tracing)

→ Agent Runtime 上の新規 ADK エージェントで OpenTelemetry トレーシングが自動有効化
→ 環境変数 GOOGLE_CLOUD_AGENT_ENGINE_ENABLE_TELEMETRY='true' が自動設定
→ 追加コード・インフラ設定なしで即座にトレースデータ収集開始

2. GCS デフォルトストレージ (Storage Prioritization)

→ マルチモーダルペイロードの保存先が Cloud Storage に変更
→ Cloud Logging の 256KB エントリサイズ制限を解消
→ JSON Lines 形式で保存、BigQuery 外部テーブルとしてクエリ可能

3. 拡張トレーシング (Enhanced Tracing)

→ DAG (有向非巡回グラフ) 表示によるステップバイステップ実行検査
→ 3 ビュー構成: Session / Trace / Span
→ マルチターン会話分析、エンドツーエンドトレース、オペレーション単位検査

4. MCP サーバーモニタリング

→ リクエスト数、p95 リクエスト時間を監視
→ Cloud Trace による MCP ツール使用状況モニタリング
→ マルチエージェントトポロジビューで依存関係を可視化

5. マルチエージェントトポロジビュー

→ Agent Registry のすべてのエージェント/MCP サーバーのリアルタイム関係性表示
→ 依存関係マップによるボトルネック特定
→ インバウンド/アウトバウンド依存関係の個別表示

🛠️ 設定方法

💡 前提条件:
  • Google Cloud プロジェクトで課金が有効であること
  • API 有効化: Vertex AI, Cloud Storage, Telemetry, Cloud Logging, Cloud Trace
  • Cloud Storage バケットが作成済みであること
  • ADK フレームワーク v1.17.0 以上

ステップ 1: 既存エージェントのテレメトリ有効化

新規デプロイの場合は追加設定不要。既存エージェントの場合は以下を設定して再デプロイ:

Bash 
# 既存エージェント向け: テレメトリ有効化
export GOOGLE_CLOUD_AGENT_ENGINE_ENABLE_TELEMETRY='true'

ステップ 2: OpenTelemetry 環境変数の設定 (カスタマイズ時)

Bash 
# サービス名の設定
export OTEL_SERVICE_NAME='my-adk-agent'

# GenAI セマンティックコンベンション (最新版) の有効化
export OTEL_SEMCONV_STABILITY_OPT_IN='gen_ai_latest_experimental'

# メッセージコンテンツのキャプチャ設定
export OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT='EVENT_ONLY'

# スパンへの大容量属性付与を無効化 (PII 保護)
export ADK_CAPTURE_MESSAGE_CONTENT_IN_SPANS='false'

✅ メリット

ビジネス面

  • 運用コスト削減: デフォルト有効トレーシングでセットアップ工数ゼロ
  • SLA 保証: エンタープライズのプロダクション環境で安心して利用可能
  • 問題解決時間の短縮: DAG ベースのトレース可視化で根本原因を迅速に特定

技術面

  • ゼロコンフィグ可観測性: 追加コード・設定なしでトレーシング動作
  • OpenTelemetry 標準準拠: Jaeger, Grafana Tempo, Datadog 等の OTel 互換バックエンドと相互運用可能
  • スケーラブルなペイロード管理: GCS で Cloud Logging のサイズ制限を解消
  • BigQuery 連携: GCS データを外部テーブルとしてクエリ、AI.GENERATE 関数で高度な分析

⚠️ 制約事項・注意点

制限事項:
  • 既存デプロイ済みエージェントは Vertex AI SDK v1.126.1 以上へ更新 + 再デプロイが必要
  • OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT を true に設定すると最新セマンティックコンベンションとの互換性が失われる
考慮すべき点:
  • プロンプト/レスポンスデータの PII に注意し、GCS バケットの IAM ポリシーを適切に設定
  • Cloud Storage バケットの保持期間をログバケットと揃えることを推奨 (デフォルト 30 日)
  • テレメトリデータ送信によるネットワーク帯域とストレージコストへの影響を考慮

🎯 ユースケース

🔍 ユースケース 1: マルチエージェントシステムの障害診断

シナリオ: 複数エージェント + MCP サーバー構成のカスタマーサポートシステムで、特定リクエストのレスポンスタイムが急増

手順:

  1. トポロジビューで依存関係を確認し、問題パスを特定
  2. Traces タブで該当リクエストの DAG を表示し、レイテンシの大きいスパンを特定
  3. スパン属性から特定 MCP サーバーのツール呼び出しがボトルネックであることを発見
  4. Tools ダッシュボードで p95 レイテンシとエラー率のトレンドを確認

効果: 従来はログ手動追跡が必要だった障害診断が、DAG 表示により数分で完了

📈 ユースケース 2: エージェント品質の継続的モニタリング

シナリオ: デプロイ済みエージェントのハルシネーション率・応答品質を継続監視し、品質劣化を早期検出

効果: Evaluation ダッシュボードで品質メトリクスをリアルタイム監視し、閾値を下回った際にアラート設定でユーザー影響を最小化

📝 まとめ

Agent Observability の GA リリースにより、Gemini Enterprise Agent Platform 上のエージェントと MCP サーバーの運用監視が本番品質で利用可能になった。ADK エージェントへのデフォルト有効トレーシングと GCS ペイロードストレージにより、セットアップ工数を大幅に削減しながら包括的な可観測性を実現できる。

推奨アクション: エージェントを本番デプロイしている組織は、既存エージェントの SDK 更新 (v1.126.1+) と再デプロイを行い、本機能を活用した運用監視体制の構築を推奨する。
