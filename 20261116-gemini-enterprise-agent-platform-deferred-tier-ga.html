🤖 Gemini Enterprise Agent Platform GA (Generally Available)

⏳ Deferred ティア GA
自律エージェントスケジューリング & Interactions API 非同期モデル呼び出し

📅 リリース日: 2026-11-16

📝 概要

Gemini Enterprise Agent Platform の Deferred ティア が GA になりました。今回の発表は密接に関連する 2 つの GA を含みます。

1️⃣ 自律エージェントスケジューリング GA

従来の Gemini Deep Research Agent に加えて ADK エージェント (google-adk v2.10.0+) に対応。use_interactions_api=True のモデルに RunConfig(service_tier=ServiceTier.DEFERRED) を渡すだけで、レイテンシ許容型ワークロードをオフピーク時間帯にキューイングできます。

2️⃣ Interactions API 非同期モデル呼び出し GA

service_tier="deferred" により、カスタム / サードパーティエージェントがグローバルエンドポイント上の Gemini モデルを 非同期に呼び出し可能 になりました。

💡 ポイント: 割引は Agent Runtime / Cloud Run / GKE のいずれで実行するエージェントにも適用され、入力・出力・思考 (thinking) トークンすべてが対象。Standard PayGo へのフォールバックは発生しないため、割引なし料金で課金される心配がありません。大規模ドキュメント合成、脆弱性スキャン、オフライン評価などを 429 エラーを回避しながら低コストで実行できます。

🔄 Before / After

❌ アップデート前の課題

  • Deferred ティアはプレビュー段階で、許可リスト (allowlist) 登録が必要だった
  • 自律スケジューリングの対象は Gemini Deep Research Agent のみ。ADK カスタムエージェントは利用不可
  • 長時間実行のバックグラウンドエージェントを Standard ティアで実行すると 429 (リソース枯渇) エラー やレートリミットが発生しやすい
  • レイテンシ許容型ワークロードでも通常料金が課金され、コスト最適化の手段が限られていた

✅ アップデート後の改善

  • GA となり 許可リストなしで利用可能 (Cyber モデルを除く)
  • ADK エージェント (v2.10.0+) が RunConfig でオフピークスケジューリングに対応。1 つの定義でインタラクティブ / バッチを使い分け
  • service_tier="deferred" でカスタムエージェントの Gemini 呼び出しを 50% 割引で非同期実行
  • 重いワークロードをオフピークに逃がし、Standard ティアクォータを温存して 429 エラーを緩和

⚡ 主要機能

🗓️ 1. 自律エージェントスケジューリングの GA と ADK 対応

  • google-adk v2.10.0 以降で、use_interactions_api=True を設定した Gemini モデルに RunConfig(service_tier=ServiceTier.DEFERRED) を渡すだけで有効化
  • ティア設定は 実行 (run) 単位 のため、同一エージェント定義でインタラクティブ要求とバッチワークロードの両方に対応可能
  • ADK Runner がキュー投入・指数バックオフによるポーリング・結果取得までを内部処理。アプリ側は通常どおりイベントを消費するだけ
  • Agent Runtime、Cloud Run、GKE のいずれで実行しても 50% 割引が適用
  • Gemini Deep Research Agent のマネージド実行も引き続きサポート

🔁 2. Interactions API の非同期モデル呼び出し (Deferred ティア) GA

  • service_tier="deferred" + background=true + store=true で非同期の Gemini 呼び出しをキューイング
  • 24 時間以内の完了目標 (95%)、状態は 7 日間保持
  • previous_interaction_id によるマルチターン連鎖、requires_action (ツール呼び出し)、requires_continuation (長い生成の継続) に対応
  • Google Gen AI SDK (Python google-genai>=2.34.0 / Node.js @google/genai>=2.32.0) と REST で作成・ポーリング・ストリーミング・キャンセルをサポート
  • in_progress 後は stream=true で SSE ストリームにアタッチ可能。last_event_id で切断からの再接続も可能

💰 3. 50% 割引の料金体系 (フォールバックなし)

  • 入力・出力・思考トークンすべてが Standard PayGo 比 50% 割引
  • 契約割引や暗黙的コンテキストキャッシュのトークン割引と 重ねて適用
  • Standard PayGo へのスピルオーバー / ダウングレードは発生せず、割引なし料金で課金されることがない
  • キュー内でキャンセルしたターンは課金なし。24 時間以内に完了せず failed となった単一呼び出しターンも課金対象外

🔧 技術仕様

🚦 Interaction のステータス遷移

ステータス最終状態意味
queuedNo受理済みで容量待ち。バックオフ付きでポーリングする (この段階では stream=true 不可)
in_progressNo実行中。ポーリング継続、または stream=true で SSE ストリームにアタッチ可能
requires_actionYesモデルが function_call を出力して終了。ツールを実行し previous_interaction_id で新ターンを作成
requires_continuationYes長い生成が部分出力で停止。continuation_token 付きで再開
completedYes完了。output_text と usage を取得、または次ターンへ連鎖
incompleteYesmax_output_tokens 到達などで早期停止
failedYesランタイムエラー、または 24 時間の完了ウィンドウ超過
cancelledYesinteractions.cancel により停止

項目詳細

🐍 Python での Deferred 呼び出し例 (Interactions API)

Python Interactions API で Deferred 呼び出しを作成 
from google import genai

client = genai.Client(
    enterprise=True,
    project="PROJECT_ID",
    location="global",
)

interaction = client.interactions.create(
    model="gemini-4-argon",
    input="リポジトリ全体の脆弱性レポートを作成してください。",
    service_tier="deferred",  # 50% 割引の Deferred ティア
    background=True,          # 即時リターン (キューイング)
    store=True,               # 状態を 7 日間保持
)
print(interaction.id, interaction.status)  # => v1_..., queued

🛠️ 設定方法

📋 前提条件

✓課金が有効な Google Cloud プロジェクト
✓IAM ロール: roles/aiplatform.user (作成・ポーリング・キャンセル)、読み取り専用の監視は roles/aiplatform.viewer
✓SDK: Google Gen AI SDK (google-genai>=2.34.0 または @google/genai>=2.32.0)、ADK の場合は google-adk v2.10.0 以降
✓グローバルエンドポイント (locations/global) を使用すること

ステップ 1: ADK エージェントで Deferred スケジューリングを有効化

Python ADK: RunConfig で Deferred ティアを指定 
from google.adk.agents import LlmAgent, RunConfig
from google.adk.models import ServiceTier
from google.adk.models.google_llm import Gemini

root_agent = LlmAgent(
    name="batch_agent",
    model=Gemini(
        model="gemini-flash-latest",
        use_interactions_api=True,  # Deferred スケジューリングに必須
    ),
    instruction="入力ドキュメントを処理して要約を生成する。",
)

# この実行のすべてのモデル呼び出しにオフピーク容量をリクエスト
run_config = RunConfig(service_tier=ServiceTier.DEFERRED)
💡 ヒント: run_async() に run_config を渡すと、ADK がキュー投入と結果待機を内部で処理します。モデルに use_interactions_api=True がない場合、ティアは無視され警告ログ (has no effect for agent) が出力されるため、ログで適用を確認します。

ステップ 2: ポーリングで結果を取得 (Interactions API 直接利用時)

Python 指数バックオフによるポーリング 
import time

PENDING = {"queued", "in_progress"}
delay = 5.0
current = client.interactions.get(interaction.id)
while current.status in PENDING:
    time.sleep(delay)
    delay = min(delay * 2.0, 30.0)  # 指数バックオフ
    current = client.interactions.get(interaction.id)

print(current.status, current.output_text)

in_progress になった後は client.interactions.get(interaction_id, stream=True) で SSE ストリームにアタッチし、テキストデルタを逐次受信することもできます。

👍 メリット

💼 ビジネス面

✓推論コスト 50% 削減: レイテンシ許容型ワークロードのモデル推論料金が Standard PayGo の半額。契約割引やコンテキストキャッシュ割引とも併用可能。フォールバックがないため予算の予測可能性が高い
✓GA による本番利用の解禁: 許可リスト不要・Pre-GA 条項の制約なしで本番ワークロードに適用でき、FedRAMP High や VPC Service Controls などのガバナンス要件にも対応

⚙️ 技術面

✓429 エラーの緩和とクォータの有効活用: 重い非同期ワークロードをオフピークに逃がし、Standard ティアのクォータをリアルタイム本番トラフィック用に温存
✓実行単位のティア切り替え: ADK では RunConfig で指定するため、同一エージェント定義を変更せずにインタラクティブ / バッチの両モードで運用可能
✓マルチターンの非同期エージェントループ: previous_interaction_id 連鎖と requires_action によるツール呼び出しで、複雑なワークフロー全体を非同期かつ低コストで実行

⚠️ デメリット・制約事項

🚫 制限事項

✗グローバルエンドポイント専用。リージョナル / us / eu マルチリージョンでは HTTP 400 となり、データレジデンシー要件には対応しない
✗ストリーミングモードとの併用不可: ADK で ServiceTier.DEFERRED と StreamingMode.SSE を組み合わせると ValidationError (in_progress 後の SSE アタッチは可能)
✗store=false (ステートレスゼロデータ保持) と CMEK は未サポート。DoD IL5 / ITAR にも非対応
✗24 時間以内に完了しないターンは failed に遷移 (クレジット保証付きのレイテンシ SLA はない)
✗ADK はプロセス再起動をまたいだ実行再開 (in-flight interaction ID の永続化) をサポートしない

🤔 考慮すべき点

  • キュー待ち時間はバックエンド負荷に依存し上限がないため、ADK ではクライアント側デッドライン (asyncio.timeout()) の設定を推奨。ただし タイムアウトしてもバックエンドの実行はキャンセルされず課金は発生する
  • HTTP (adk api_server) 経由では接続がキュー待ちの間保持されるため、Cloud Run などのリクエストタイムアウトを引き上げるか、長時間待機するワークロードは Agent Runtime へのデプロイを推奨
  • ツールを呼び出すエージェントでは 各モデルターンが個別にキューイング されるため、合計レイテンシは全ターンのキュー待ち時間の合計になる
  • チェーンされたターンは暗黙的コンテキストキャッシュの対象だが、数時間のキュー待ちの間にキャッシュ済みプレフィックスが失効する可能性がある

🎯 ユースケース

🔒 1. コードベースの脆弱性スキャンと自動修正

シナリオ: セキュリティチームが毎晩、全リポジトリに対して脆弱性スキャンと修正提案を行う ADK エージェントを実行。リアルタイム応答は不要で、翌朝までに結果が揃えばよい。

Python 夜間バッチの実装例 
run_config = RunConfig(service_tier=ServiceTier.DEFERRED)
async for event in runner.run_async(
    user_id="security_bot",
    session_id=session.id,
    new_message=scan_request,
    run_config=run_config,
):
    process(event)

✅ 効果: モデル推論コストを 50% 削減しつつ、日中の対話型ワークロード用クォータを消費せずに大規模スキャンを完了。

📑 2. 金融・リーガル分野の大規模ドキュメント合成

シナリオ: 金融機関が日次・週次の株式市場リサーチや、M&A デューデリジェンスのための複数ドキュメント横断分析を Deep Research Agent / カスタムエージェントで実行。

✅ 効果: previous_interaction_id で分析ターンを連鎖させながら、半額の推論コストで数時間規模のリサーチパイプラインを安定実行。429 エラーによる途中失敗も減少。

🧪 3. 大規模なオフラインエージェント評価

シナリオ: エージェント開発チームが品質ベンチマークのため、数千件の評価ケースをマルチターンで実行。

✅ 効果: 評価ジョブをオフピーク容量に逃がすことで、本番環境のレートリミットに影響を与えず、評価コストを半減。

💰 料金

Deferred ティアのモデル呼び出しは、入力・出力・思考トークンすべてが Standard PayGo 比 50% 割引 で課金されます。

ルール内容
割引の重複適用契約割引、暗黙的コンテキストキャッシュのトークン割引とスタック (キャッシュ済みレートの上にさらに適用)
フォールバックなしStandard PayGo へのスピルオーバー / ダウングレードは発生せず、割引なし料金で課金されない
キャンセルqueued 中のキャンセルは課金なし。in_progress 中のキャンセルは開始済みのモデル呼び出しのみ課金
失敗24 時間ウィンドウ超過を含む failed の単一呼び出しターンは課金なし。マルチステップのツールループでは失敗前に完了した呼び出しのみ課金
チェーンprevious_interaction_id チェーンの各ターンは独立して課金

モデル別の単価は Agent Platform 料金ページ を参照してください。

🔗 関連サービス・機能

→Agent Development Kit (ADK): google-adk v2.10.0 以降で RunConfig(service_tier=ServiceTier.DEFERRED) によるオフピークスケジューリングに対応
→Gemini Deep Research Agent: 自律エージェントスケジューリングのマネージド実行対象。agent パラメータで Deferred ティア実行が可能
→Agent Runtime / Cloud Run / GKE: いずれのランタイムでも 50% 割引が適用。長時間のキュー待ちには HTTP 接続を保持しない Agent Runtime が推奨
→Batch API: 大規模・高スループットのオフライン一括推論向け。エージェント / ツール呼び出し型の非同期ワークロードには Deferred ティアが適する
→Flex PayGo: 同期型のレイテンシ許容ワークロード向けの 50% 割引オプション。Deferred ティアはそのクォータ (flex_requests_per_minute_per_project_per_base_model) を共有
→VPC Service Controls / Cloud Audit Logs / Access Transparency: Deferred ティアがサポートするガバナンス統制 (FedRAMP High 対応。CMEK・データレジデンシーは非対応)

🎉 まとめ

Deferred ティアの GA により、レイテンシ許容型のエージェントワークロードを 50% 割引・フォールバックなし の料金で本番運用できるようになりました。

  • ADK エージェント対応 (google-adk v2.10.0+) により、既存のエージェント定義を変更せず RunConfig の切り替えだけでコスト最適化が可能
  • 夜間バッチ、ドキュメント合成、オフライン評価などの非リアルタイムワークロードは、Standard ティアから Deferred ティアへの移行を検討することを推奨
