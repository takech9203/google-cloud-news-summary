🔍 Vertex AI Search: Weight Searchable Fields

Vertex AI Search Public Preview AI/ML

📋 概要

Vertex AI Search に検索可能フィールドの重み付け機能が Public Preview として追加されました。 スキーマ内の searchable フィールドに対して相対的な重要度 (weight) を 5 段階で指定でき、 検索結果のランキングにおいてどのフィールドがより重要であるかをシステムに伝えることが可能になりました。

🎯 ポイント: SearchableFieldImportance enum を使用して、フィールドごとに VERY_LOW ~ VERY_HIGH の 5 段階の重要度を宣言的に設定。スキーマレベルで恒久的な検索品質の改善が可能に。

重要度の 5 段階スケール

VERY_LOW
LOW
DEFAULT
HIGH
VERY_HIGH

🔄 Before / After 比較

❌ Before

-すべての searchable フィールドが同等の重みで検索ランキングに影響
-フィールドごとの重要度を区別できなかった
-検索精度向上にはクエリ時の boost や rankingExpression で対応が必要
-スキーマレベルでの検索品質制御が不可能

✅ After

+フィールドごとの検索重要度を 5 段階で指定可能
+タイトルや商品名など重要フィールドに高い重みを付与可能
+スキーマ設定だけで恒久的に検索品質を改善
+既存の rankingExpression との併用も可能

⚡ 主要機能

🎚️ SearchableFieldImportance

スキーマの各 searchable フィールドに対して 5 段階の重要度を enum で指定。未指定は DEFAULT_IMPORTANCE として動作。

📐 スキーマレベル永続設定

一度設定すればすべての検索クエリに自動適用。クエリごとの rankingExpression 指定が不要。コンソールまたは REST API から設定可能。

🔗 既存機能との互換性

Custom Ranking (rankingExpression) と併用可能。Boost、フィルタリング、ファセットなど他機能に影響しない。後から追加設定も可能。

🔧 技術仕様

SearchableFieldImportance enum

値 説明
SEARCHABLE_FIELD_IMPORTANCE_UNSPECIFIED 未設定。searchable フィールドの場合 DEFAULT_IMPORTANCE として動作
VERY_LOW_IMPORTANCE 検索に対して非常に小さいシグナルを提供
LOW_IMPORTANCE 検索に使用されるが、デフォルトより重要度が低い
DEFAULT_IMPORTANCE デフォルトの重要度。従来の動作と同等
HIGH_IMPORTANCE デフォルトフィールドより重要
VERY_HIGH_IMPORTANCE 検索において最も重要なフィールド

項目 詳細

🛠️ 設定方法

📋 前提条件:
  • Google Cloud プロジェクトで Vertex AI Search (AI Applications) が有効化済み
  • 構造化データ、非構造化データ (メタデータ付き)、またはウェブサイトデータのデータストアが作成済み
  • 対象フィールドが string 型であり、searchable に設定済み

ステップ 1: 現在のスキーマを確認

Bash 
curl -X GET \
  -H "Authorization: Bearer $(gcloud auth print-access-token)" \
  "https://discoveryengine.googleapis.com/v1alpha/projects/PROJECT_ID/locations/global/collections/default_collection/dataStores/DATA_STORE_ID/schemas/default_schema"

ステップ 2: スキーマを更新して重み付けを追加

Bash 
curl -X PATCH \
  -H "Authorization: Bearer $(gcloud auth print-access-token)" \
  -H "Content-Type: application/json" \
  "https://discoveryengine.googleapis.com/v1alpha/projects/PROJECT_ID/locations/global/collections/default_collection/dataStores/DATA_STORE_ID/schemas/default_schema" \
  -d '{
    "structSchema": {
      "$schema": "https://json-schema.org/draft/2020-12/schema",
      "type": "object",
      "properties": {
        "title": {
          "type": "string",
          "keyPropertyMapping": "title",
          "searchable": true,
          "searchableFieldImportance": "VERY_HIGH_IMPORTANCE"
        },
        "description": {
          "type": "string",
          "keyPropertyMapping": "description",
          "searchable": true,
          "searchableFieldImportance": "HIGH_IMPORTANCE"
        }
      }
    }
  }'

ステップ 3: 再インデックスの完了を確認

Bash 
curl -X GET \
  -H "Authorization: Bearer $(gcloud auth print-access-token)" \
  "https://discoveryengine.googleapis.com/v1alpha/projects/PROJECT_ID/locations/global/operations/OPERATION_ID"
⚠️ 注意: スキーマの更新はデータの再インデックスをトリガーします。大規模なデータストアでは数時間かかる場合があります。

✅ メリット

💼 ビジネス面

→検索精度の向上: 重要フィールドを優先しユーザーが求める結果を上位に表示
→運用コスト削減: クエリ時の rankingExpression 調整不要、スキーマ設定のみで恒久改善
→CX 改善: 関連性向上による離脱率低下・コンバージョン率向上

🔧 技術面

→宣言的な設定: スキーマに重要度を宣言するだけでランキングが自動考慮
→段階的な導入: 既存スキーマに後から追加可能、未設定は従来通り動作
→Custom Ranking 併用: フィールドレベル + クエリレベルで精密なランキング制御

⚠️ デメリット・制約事項

制限事項

!Public Preview のため SLA 対象外 - 本番環境での利用は推奨されない
!string 型のフィールドのみが対象 (数値型フィールドには設定不可)
!searchable フィールドの最大数は従来通り 50 フィールドまで
!スキーマ更新時にデータの再インデックスが発生 (大規模データでは数時間)
!API バージョンは v1alpha - GA 時に仕様変更の可能性あり

考慮すべき点

!重み付けの最適なバランスを見つけるにはテストと検証が必要
!過度に高い重要度を多くのフィールドに設定すると効果が薄れる可能性
!スキーマ更新中はサービスが一時的に遅延する可能性がある

💡 ユースケース

🛒 EC サイトの商品検索

シナリオ: 数百万点の商品を持つ EC サイトで、ユーザーが商品名で検索した際に正確な結果を上位に表示したい。

JSON 
{
  "product_name": { "searchableFieldImportance": "VERY_HIGH_IMPORTANCE" },
  "brand": { "searchableFieldImportance": "HIGH_IMPORTANCE" },
  "description": { "searchableFieldImportance": "DEFAULT_IMPORTANCE" },
  "review_text": { "searchableFieldImportance": "LOW_IMPORTANCE" }
}

効果: 商品名やブランド名に一致する商品が優先的に上位表示され、レビュー文中の偶発的なキーワードマッチによるノイズが軽減。

📚 社内ナレッジベース検索

シナリオ: 社内ドキュメントの検索で、タイトルや要約を重視し、本文中の付随的な言及よりも優先したい。

JSON 
{
  "document_title": { "searchableFieldImportance": "VERY_HIGH_IMPORTANCE" },
  "summary": { "searchableFieldImportance": "HIGH_IMPORTANCE" },
  "body_text": { "searchableFieldImportance": "DEFAULT_IMPORTANCE" },
  "metadata_comments": { "searchableFieldImportance": "VERY_LOW_IMPORTANCE" }
}

効果: タイトルや要約でマッチするドキュメントが優先的に返され、検索精度と業務効率が向上。

🎫 サポートチケット検索

シナリオ: カスタマーサポートのチケットシステムで、問題の概要や解決策を重視した検索を実現したい。

効果: issue_title や resolution_notes に高い重要度を設定し、internal_comments や log_data に低い重要度を設定することで、サポート担当者が関連チケットを素早く見つけられる。

💰 料金情報

🔗 関連サービス・機能

Custom Ranking クエリ時に rankingExpression を指定してランキングを制御。フィールド重み付けと併用で精密な制御が可能。
Boost/Bury 検索結果の特定条件に基づいてスコアを上下。フィールド重み付けはスキーマレベル、Boost はクエリレベルでの制御。
Natural Language Query Filters 自然言語クエリを自動的にフィルタと残余クエリに分解。重み付けとの組み合わせで構造化データの検索品質向上。
Key Property Mapping title、description、uri などのキープロパティにフィールドをマッピング。フィールド重要度と組み合わせて最適な検索体験を構築。

📝 まとめ

Vertex AI Search の検索可能フィールド重み付け機能は、スキーマレベルで検索ランキングにおけるフィールドの重要度を制御できる待望の機能です。 従来はすべての searchable フィールドが同等に扱われていましたが、本機能により「タイトルは最重要、説明は重要、補足情報は低重要度」といった直感的な設定が可能になりました。

📌 推奨アクション: 現在は Public Preview であるため本番利用は慎重に検討すべきですが、GA に向けて早期にテスト環境で重み付けの最適な設定を検証しておくことを推奨します。
