📋 概要

2026 年 9 月 29 日、gcloud CLI 587.0.0 がリリースされました。このリリースには 2 件の破壊的変更 が含まれています。

❌ 破壊的変更 1: Cloud Storage

gcloud storage buckets anywhere-caches pause コマンドが削除。停止は disable、復帰は resume に統一。

❌ 破壊的変更 2: Distributed Cloud Edge

非推奨だった gcloud edge-cloud container vpn-connections コマンド群 (create / list / describe / delete など) が削除。

ランタイム面では Python 3.15 サポート、バンドル Python (Linux / Windows) の grpcio 1.84.0 更新、setuptools の削除が行われました。機能面では AlloyDB IAM グループ認証、Cloud Dataplex dbt、Cloud Run スケーリングフラグ・エフェメラルディスクの GA 昇格、Cloud Run SSH 接続 (beta) など多数のアップデートが含まれます。

🔄 Before / After

🔴 Before (〜586.x) の課題

  • Anywhere Cache に pause と disable の 2 つの類似した停止系コマンドがあり使い分けが分かりにくい
  • Edge の vpn-connections コマンド群が非推奨のまま残り、廃止予定機能への依存が温存されやすい
  • AlloyDB IAM グループ認証は Preview 段階で本番利用にリスク。IAM ユーザーの個別管理は負荷が高い
  • Cloud Run のスケーリング調整フラグやエフェメラルディスクは GA 前トラックのみで本番適用がためらわれた
  • 実行中の Cloud Run インスタンスへ対話的にシェル接続する標準手段が CLI になかった

🟢 After (587.0.0〜) の改善

  • 停止操作は disable に整理、resume で復帰 (Paused / Disabled 両状態に対応)
  • 非推奨の Edge VPN コマンド群が削除され CLI サーフェスが整理された
  • AlloyDB は IAM グループ追加だけでメンバー全員が認証を継承 (GA で本番利用可能)
  • --scaling-cpu-target / --scaling-concurrency-target とエフェメラルディスクが GA 昇格、SLA のもとで利用可能
  • gcloud beta run services ssh / instances ssh で対話的シェル接続が可能に
  • Python 3.15 対応 + grpcio 1.84.0 で最新ランタイム環境の動作を保証

🚨 破壊的変更 (Breaking Changes) の詳細

1. gcloud storage buckets anywhere-caches pause の削除 削除済み

→ Anywhere Cache インスタンスを一時停止する pause コマンドが削除された

→ 587.0.0 以降のコマンド群は create / describe / disable / list / resume / update で構成

→ 停止には disable を使用。resume は Paused / Disabled いずれの状態からも RUNNING / CREATING 状態へ復帰可能

2. gcloud edge-cloud container vpn-connections コマンド群の削除 削除済み

→ 非推奨だった VPN 接続管理コマンド群 (create / list / describe / delete など) が削除された

→ Distributed Cloud connected クラスタと VPC ネットワーク間の VPN 接続を CLI で管理していたスクリプトは修正が必要

→ 既存の VPN 接続リソースの扱いは Distributed Cloud connected のドキュメントを参照

⚠️ 注意: どちらも 587.0.0 時点で削除済みのため、猶予期間なしで既存スクリプトが失敗します。CI/CD パイプラインで gcloud CLI を自動更新している場合は、事前に依存箇所を修正してください。

🐍 Google Cloud CLI 本体の変更

Python 3.15 サポート

gcloud CLI が Python 3.15 に対応。

バンドル Python の更新 (Linux / Windows)

→ grpcio を 1.84.0 にアップグレード

→ setuptools がバンドル Python から削除。バンドル Python 環境で setuptools に依存する処理がある場合は個別対応が必要

🚀 主要な GA 昇格・機能追加

🐘 AlloyDB GA

IAM グループユーザータイプ (--type=IAM_GROUP) が GA 昇格。IAM グループをクラスタに追加するとメンバー全員が認証を継承し、初回サインイン時にアカウントが自動作成される。

⚡ Cloud Run GA beta

→ --scaling-cpu-target / --scaling-concurrency-target が GA 昇格 (deploy / services update)。ただし --scaling-cpu-target の最大値が 0.95 → 0.90 に変更 (Cloud Run API と整合)

→ --add-volume の type=ephemeral-disk が GA 昇格 (deploy / jobs / worker-pools / services 系)

→ gcloud beta run services ssh / gcloud beta run instances ssh で対話的シェル接続が可能に

→ gcloud run instances deploy に --[no-]use-http2 フラグ追加

→ gcloud beta run deploy の --domain フラグでカスタム URL をサポート

📊 Cloud Dataplex GA

gcloud dataplex dbt が GA 昇格。

🔍 BigQuery

bq update --connection で AWS / Azure クロスクラウド接続の serviceDirectoryService を --service_directory_service='' でクリア可能に (空の場合、Cross-Cloud Interconnect ではなくパブリックインターネット経由でクエリ)。

🤖 AI Platform / Agent Registry

→ gcloud ai semantic-governance-policies create/update に --agent-response-denial-message フラグが追加。ポリシー拒否時のエンドユーザー向けカスタムメッセージを設定可能に

→ Agent Registry: bindings create の --source-identifier がオプションに変更

🧩 その他のアップデート

✓Cloud Dataproc: --multizone フラグ追加。リージョン内複数ゾーンにまたがるマルチゾーナルクラスタを作成可能に
✓Cloud Managed Lustre: lustre instances directory-policies コマンド群が GA 昇格。--target-version フラグも GA コマンドに追加
✓Compute Engine: スナップショット作成の --kms-key フラグが v1 (GA) に昇格、compute interconnects set-name が GA 昇格
✓Cloud Tasks: alpha|beta tasks batch-create 追加。JSON / YAML から複数タスクを一括作成。タスク単位のリトライフラグ (--max-attempts など) も追加
✓IAP: beta iap tcp に IAM ポリシー管理コマンド (get/set-iam-policy、add/remove-iam-policy-binding) 追加。Cloud Run トンネルリソースを含む IAP TCP リソースの IAM 管理が可能に
✓Network Security: network-security rate-limit-policies が beta に昇格
✓Cloud Build: builds submit / worker-pools create/update に --worker-release フラグ追加

🔧 設定方法 (移行手順)

💡 前提条件:
1.gcloud version で現在のバージョンを確認し、スクリプト・CI/CD パイプラインで anywhere-caches pause、edge-cloud container vpn-connections、Cloud Run の --scaling-cpu-target を使用している箇所を洗い出す
2.バンドル Python (Linux / Windows) 環境で setuptools に依存する処理がないか確認する
1
Anywhere Cache 停止処理の修正
Bash 
# 587.0.0 以降: pause は削除されたため disable を使用
gcloud storage buckets anywhere-caches disable my-bucket/my-cache-id

# 復帰は resume (Paused / Disabled 両状態から復帰可能)
gcloud storage buckets anywhere-caches resume my-bucket/my-cache-id

pause を使用していた運用スクリプトは disable に置き換えます。

2
Cloud Run スケーリングフラグの値を確認
Bash 
# GA 昇格後: 最大値は 0.90 (0.95 は指定不可)
gcloud run deploy my-service \
  --image=us-docker.pkg.dev/my-project/repo/app \
  --scaling-cpu-target=0.90 \
  --scaling-concurrency-target=80

--scaling-cpu-target に 0.90 を超える値を指定しているスクリプトは修正が必要です。

3
AlloyDB IAM グループユーザーの作成 (GA)
Bash 
# グループに必要なロールを付与したうえで、クラスタにグループユーザーを作成
gcloud alloydb users create my-group@example.com \
  --cluster=my-cluster \
  --region=asia-northeast1 \
  --type=IAM_GROUP

グループメンバーは個別追加不要で、初回サインイン時にアカウントが自動作成されます。

4
gcloud CLI の更新
Bash 
gcloud components update
gcloud version

✅ メリット

💼 ビジネス面

✓アクセス管理の効率化: AlloyDB の IAM グループ認証 GA により、データベースユーザーの入退社・異動対応がグループメンバーシップの管理だけで完結し、監査対応も簡素化される
✓本番適用の後押し: Cloud Run のスケーリング調整・エフェメラルディスクなどが GA となり、SLA のもとで本番ワークロードに適用できる

🔧 技術面

✓CLI サーフェスの整理: 重複していた Anywhere Cache の停止系コマンドと非推奨の Edge VPN コマンド群が削除され、コマンド体系が明確になった
✓最新ランタイム対応: Python 3.15 サポートと grpcio 1.84.0 への更新により、最新の OS / Python 環境での互換性が確保される
✓デバッグ性の向上: gcloud beta run services ssh により、実行中の Cloud Run インスタンスへ対話的に接続して障害調査ができる

⚠️ デメリット・制約事項

🚧 制限事項

✗anywhere-caches pause と edge-cloud container vpn-connections は 587.0.0 時点で削除済みのため、猶予期間なしで既存スクリプトが失敗する
✗Cloud Run の --scaling-cpu-target は 0.90 を超える値を受け付けなくなった (従来の最大値 0.95 を指定していた場合はエラー)
✗バンドル Python から setuptools が削除されたため、gcloud のバンドル Python 環境で setuptools を前提としたカスタム処理は動作しない
✗AlloyDB IAM グループ認証にはグループ数上限 (クラスタあたり 200)、グループ名 63 文字制限などの制約がある (詳細は公式ドキュメントを参照)

🤔 考慮すべき点

⚠️ CI/CD 自動更新に注意: gcloud CLI を自動更新している場合、587.0.0 への更新タイミングで削除コマンドに依存したジョブが突然失敗する可能性があるため、事前に依存箇所を修正すること。
⚠️ BigQuery クロスクラウド接続: --service_directory_service='' を指定すると、Cross-Cloud Interconnect ではなくパブリックインターネット経由のクエリになるため、ネットワーク要件 (セキュリティ・帯域) を確認したうえで使用すること。
⚠️ AlloyDB の移行: 既存の個別 IAM ユーザー (ALLOYDB_IAM_USER) はグループの権限を継承しないため、グループ認証へ移行する場合は個別ユーザーの削除と再サインインが必要。

🎯 ユースケース

1️⃣ Anywhere Cache 運用スクリプトの修正

シナリオ: 夜間バッチの前後で Anywhere Cache を pause / resume していた運用チームが、587.0.0 への更新でスクリプトが失敗するようになった。

Bash 
# 修正後: pause の代わりに disable を使用
gcloud storage buckets anywhere-caches disable analytics-bucket/asia-northeast1-b

# バッチ完了後に復帰
gcloud storage buckets anywhere-caches resume analytics-bucket/asia-northeast1-b

効果: 削除されたコマンドへの依存を解消し、disable / resume の 2 コマンドに運用を統一できる。

2️⃣ AlloyDB のユーザー管理をグループベースに移行

シナリオ: 数十名の分析チームメンバーを AlloyDB クラスタに個別登録していた組織が、IAM グループ認証の GA を機にグループベースの管理へ移行する。

Bash 
gcloud alloydb users create analytics-team@example.com \
  --cluster=prod-cluster --region=asia-northeast1 --type=IAM_GROUP
SQL 
-- グループ単位で DB 権限を付与
GRANT SELECT ON sales_data TO "analytics-team@example.com";

効果: メンバーの追加・削除は Google グループの管理だけで完結し、データベース側のユーザー管理作業が不要になる。

3️⃣ Cloud Run コンテナの対話的デバッグ

シナリオ: 本番相当環境の Cloud Run サービスで再現する不具合を、実行中のインスタンスに接続して調査したい。

Bash 
gcloud beta run services ssh my-service --region=asia-northeast1

効果: コンテナを再ビルドせずに実行中インスタンスの状態 (ファイル、環境変数、プロセス) を直接確認でき、調査時間を短縮できる。

💰 料金・🌏 利用可能リージョン

💰 料金

gcloud CLI 自体は無料で利用できます。本アップデートによる料金への直接の影響はありません。各コマンドで操作するサービス (Cloud Storage Anywhere Cache、AlloyDB、Cloud Run など) の料金は、それぞれのサービスの料金体系に従います。

→ Google Cloud の料金

🌏 利用可能リージョン

gcloud CLI はクライアントサイドツールのため、リージョンの制約はありません。バージョン 587.0.0 は 2026 年 9 月 29 日よりすべてのプラットフォーム (Linux、macOS、Windows) で利用可能です。
