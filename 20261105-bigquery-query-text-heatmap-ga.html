☁️ BigQuery GA ページ廃止

🔥 クエリテキストヒートマップの機能強化 (GA)
と Metadata curation ページの廃止

📅 リリース日: 2026-11-05

📌 概要

BigQuery の実行グラフにあるクエリテキストヒートマップに 2 つの機能強化が GA になりました。 ① ステージのステップから、ネストされた関数呼び出しやビュー参照などのコンテキスト参照の階層リストを表示・ナビゲートできる機能、 ② 永続・一時 UDF の SQL テキストをヒートマップ上に表示できる機能です。 ビューや UDF を多用する複雑なクエリでも、どの SQL コードがどのステージに対応し、どこにスロット時間が費やされているかをコンソール上で直接追跡できます。

また、同日のリリースノートで BigQuery の Metadata curation コンソールページの廃止も発表されました。今後は Knowledge Catalog (旧 Dataplex Universal Catalog) でディスカバリスキャン、データプロファイリング、データ品質などのガバナンスタスクを実行します。

❌ Before (アップデート前の課題)

  • ビューや UDF を含む複雑なクエリで、ステージのステップがどの SQL コード (特にネストされた参照先) に対応するかを階層的にたどる手段がなかった
  • 一時・永続 UDF の SQL 定義をヒートマップ上で確認できず、UDF 内部のロジックとステージの対応関係の把握が困難
  • メタデータキュレーション操作が専用ページに分かれ、Knowledge Catalog のガバナンス機能と導線が分散

✅ After (アップデート後の改善)

  • ステップからネストされた関数呼び出し・ビュー参照を含むコンテキスト参照の階層リストを開き、該当コード行に直接ジャンプ可能に (GA)
  • 永続・一時 UDF の SQL テキストがヒートマップに表示され、UDF を含むクエリのパフォーマンス分析が容易に (GA)
  • ディスカバリスキャン、データプロファイリング、データ品質などのガバナンスタスクが Knowledge Catalog に一本化

実行グラフの各ステージのステップが、メインクエリ・ビュー・UDF の SQL テキストにマッピングされ、コンテキスト参照の階層リストから該当コード行へ直接ナビゲートできる構成です。

⚡ 主要機能

🗂️ 1. コンテキスト参照の階層リスト GA

→ステージのステップ詳細で、クエリテキストにマッピングされたステップにコードアイコンが表示される
→マッピング先が単一ならクリックで直接該当コードへ移動。複数箇所や階層構造がある場合は、ネストされた関数呼び出しやビュー参照の階層リストを表示するダイアログが開く
→リストから参照先を選択すると、該当コード行がハイライトされ自動スクロールで表示される

🧩 2. 永続・一時 UDF の SQL テキスト表示 GA

→ヒートマップが永続 UDF と一時 UDF の SQL テキスト表示に対応
→ビューや永続ルーティンを使用するクエリでは、それらの名前と SQL テキストがマッピングとともに表示される
→マッピング部分にポインタを合わせると対応ステージとスロット時間をツールチップ表示、クリックで実行グラフ上の該当ステージを選択

🗑️ 3. Metadata curation コンソールページの廃止 変更

→BigQuery の Metadata curation コンソールページが削除された
→今後は Knowledge Catalog で Cloud Storage ディスカバリスキャンのスケジュール設定、データプロファイリング・データ品質の管理などを実行
→Knowledge Catalog は BigQuery、Cloud Storage、Pub/Sub、Spanner などの Google Cloud データソース全体を対象とした一元的なガバナンスソリューション

🔧 技術仕様

🔥 クエリテキストヒートマップの動作

項目詳細
表示場所Google Cloud コンソールの実行グラフタブの左パネル
ハイライトの基準マッピングされたステップを持つステージの合計スロット時間
対応する SQL テキストメインクエリ、参照されたビュー、SQL UDF (永続・一時)
ナビゲーションクエリテキスト → ステージ選択、ステップのコードアイコン → コード行ハイライト
複数マッピング1 つのクエリテキスト部分が複数ステージにマッピング可能 (ツールチップに各ステージとスロット時間を表示)

🔐 必要な IAM 権限

ビューやルーティンのマッピング表示に必要な権限です。リソースが削除された場合や権限がない場合、該当リソースのマッピングは表示されません。

対象リソース必要な権限
ビューbigquery.tables.get
ルーティン (UDF など)bigquery.routines.get

⚠️ ヒートマップ解釈上の注意

  • 色はステージ全体のスロット時間に基づく。BigQuery はステップ単位のスロット時間を計測しないため、マッピング部分の正確なスロット時間を表すものではない
  • 1 つのステージが複数の複雑な操作 (結合と集計など) を含む場合、特定のコード部分のスロット時間が過大に表示される可能性がある。ステージを構成する他のステップも併せて確認すること
  • 実行グラフが非常に複雑な場合、ペイロードサイズの制約によりサブステップが切り詰められることがある

🛠️ 設定方法

✅ 前提条件

✓Google Cloud コンソールで BigQuery を使用できること
✓ビュー・ルーティンのマッピング表示には、対象リソースへの bigquery.tables.get / bigquery.routines.get 権限があること

📋 手順

1
実行グラフを開く
  1. Google Cloud コンソールの BigQuery ページでクエリを実行する
  2. 完了したクエリの「実行の詳細 (Execution Details)」から「実行グラフ (Execution graph)」タブをクリックする
  3. 左パネルにクエリテキストヒートマップ、中央に実行グラフ、右パネルにクエリ / ステージ詳細が表示される
2
コンテキスト参照をナビゲートする
  1. 実行グラフでステージをクリックし、右パネルの「ステップ詳細」を確認する
  2. クエリテキストにマッピングされたステップのコードアイコンをクリックする
  3. マッピング先が複数または階層構造の場合、コンテキスト参照の階層リストのダイアログが開くので、参照先 (ネストされた関数呼び出しやビュー参照) を選択すると該当コード行がハイライトされる
3
Metadata curation の代替として Knowledge Catalog を使用する
  1. Google Cloud コンソールで Knowledge Catalog に移動する
  2. Cloud Storage ディスカバリスキャンのスケジュール設定、データプロファイリング / データ品質スキャンの作成・管理などのガバナンスタスクを Knowledge Catalog 上で実行する

💡 メリット

💼 ビジネス面

✓クエリ最適化の迅速化: スロット時間の大きいステージと対応する SQL コードを直接結び付けられるため、オンデマンド課金やスロット予約のコスト最適化につながるボトルネック特定が速くなる
✓ガバナンス導線の一元化: メタデータキュレーション関連のタスクが Knowledge Catalog に統合され、データガバナンス運用の窓口が明確になる

⚙️ 技術面

✓ネストされた参照の可視化: ビューの中のビューや UDF 内の関数呼び出しといった階層構造を、コンソール上でたどりながらデバッグできる
✓UDF を含むクエリの分析性向上: 永続・一時 UDF の SQL 定義がヒートマップに表示され、UDF 内部のロジックと実行ステージの対応を確認できる
✓双方向ナビゲーション: クエリテキストからステージ、ステージのステップからコード行へ、双方向に移動して分析できる

⚠️ デメリット・制約事項

🚧 制限事項

  • ヒートマップの色はステージ全体のスロット時間に基づくため、特定のコード部分単体の正確なスロット時間を表すものではない
  • 参照先のビューやルーティンが削除された場合、または bigquery.tables.get / bigquery.routines.get 権限を失った場合、そのリソースのマッピングは表示されない
  • ドライランやキャッシュから結果を返すクエリなど、実行リソースを使用しないジョブには実行グラフの診断情報が含まれない

🤔 考慮すべき点

  • Metadata curation ページを運用手順やドキュメントで参照しているチームは、Knowledge Catalog のページへの導線に更新する必要がある
  • 1 つのステージが複数の複雑な操作を含む場合はヒートマップの色が実態を過大に表す可能性があるため、ステップ詳細も併せて確認する

🎯 ユースケース

🔍 ユースケース 1: ビュー・UDF を多用する複雑なクエリのボトルネック特定

シナリオ: データマート層のビューを複数重ね、永続 UDF でビジネスロジックをカプセル化したクエリが遅く、どの部分が原因か特定したい。

手順 
1. クエリ実行後、「実行の詳細」→「実行グラフ」タブを開く
2. ヒートマップで濃い赤にハイライトされた SQL (ビューや UDF の定義を含む) を確認
3. スロット時間の大きいステージのステップ詳細からコードアイコンをクリックし、
   コンテキスト参照の階層リストで原因となるネストされた参照先に移動
✅ 効果: ビューや UDF の内部まで含めて、スロット時間を消費している SQL コードを特定でき、リライトやマテリアライズの判断が速くなる。

🔄 ユースケース 2: Metadata curation から Knowledge Catalog への運用移行

シナリオ: BigQuery の Metadata curation ページで Cloud Storage のディスカバリスキャンやデータ品質スキャンを管理していたチームが、ページ廃止に伴い運用を移行する。

✅ 効果: Knowledge Catalog 上でディスカバリスキャン、データプロファイリング、データ品質スキャンを一元管理でき、BigQuery 以外のデータソース (Cloud Storage、Pub/Sub、Spanner など) も含めたガバナンス運用に拡張できる。

🔗 関連サービス・機能

→BigQuery クエリプラン / 実行グラフ: クエリテキストヒートマップは実行グラフの一部であり、jobs.get API からもクエリプランと実行タイムライン情報を取得できる
→BigQuery ユーザー定義関数 (UDF): 今回ヒートマップでの SQL テキスト表示に対応した永続・一時 UDF。SQL 式や JavaScript でカスタムロジックをカプセル化する機能
→Knowledge Catalog (旧 Dataplex Universal Catalog): Metadata curation ページの代替。ディスカバリスキャン、データプロファイリング、データ品質、データリネージなどのガバナンス機能を提供

📝 まとめ

🔥 クエリテキストヒートマップの GA 強化により、ビューや UDF を含む複雑なクエリでも、スロット時間を消費する SQL コードをコンソール上で階層的にたどって特定できるようになりました。クエリ最適化の際は実行グラフとヒートマップを第一の分析手段として活用することを推奨します。

🗑️ また、Metadata curation ページは廃止されたため、該当機能を利用していたチームは Knowledge Catalog への運用移行を進めてください。
