📋 概要

GKE のカスタムステージによるロールアウトシーケンシングが一般提供 (GA) となりました。 Fleet (フリート) を基盤として、開発・テスト・ステージング・本番といった複数の環境にわたる GKE クラスタのアップグレード順序を、カスタム定義されたステージに基づいて段階的に制御できるようになります。

ラベルセレクターを使用してフリート内の特定クラスタサブセットをターゲットにすることで、カナリアデプロイメントのような高度なロールアウト戦略を実現します。

Before / After

❌ Before (アップデート前)

  • 環境横断でアップグレード順序を体系的に制御する手段が限定的
  • フリート内のクラスタサブセットを個別に制御できなかった
  • ロールアウトの一時停止・キャンセルといった細かい制御が不可
  • パッチ/マイナーバージョンを区別したロールアウト対象の選択が不可

✅ After (アップデート後)

  • ラベルセレクターでフリート内の特定クラスタサブセットをステージ定義
  • 特定バージョンへのロールアウトを手動で開始可能
  • 一時停止・再開・キャンセル・ステージ完了の操作が可能
  • アップグレードタイプ (パッチ/マイナー) を選択可能
  • RolloutSequence / Rollout API による可観測性向上

🛠 アーキテクチャ図

GKE が新バージョンをリリースすると、定義されたステージ順にクラスタがアップグレードされます。各ステージ間にはソークタイム (安定確認期間) が設定され、問題がないことを確認してから次のステージへ進みます。

📝 設定方法

💡 前提条件: GKE Autopilot/Standard クラスタが Fleet に登録済み、gkehub API 有効化済み、Fleet Editor IAM ロール付与済みであること。

Step 1: クラスタへのラベル付与 (オプション)

Bash カナリアクラスタのラベル設定 
gcloud container clusters update CLUSTER_NAME \
  --location=CLUSTER_LOCATION \
  --update-labels=canary=true

Step 2: ステージ設定ファイルの作成

YAML rollout-sequence.yaml 
# 開発環境 (ソークタイム 7 日)
- stage:
    fleet-projects:
      - projects/dev
    soak-duration: 604800s
# 本番カナリア (ソークタイム 7 日)
- stage:
    fleet-projects:
      - projects/prod
    soak-duration: 604800s
    label-selector: resource.labels.canary=='true'
# 本番全体 (ソークタイム 7 日)
- stage:
    fleet-projects:
      - projects/prod
    soak-duration: 604800s

Step 3: ロールアウトシーケンスの作成

Bash シーケンス作成コマンド 
gcloud container fleet rolloutsequences create ROLLOUT_SEQUENCE_NAME \
  --display-name="My Rollout Sequence" \
  --stage-config=rollout-sequence.yaml

Step 4: ロールアウトの管理

Bash ロールアウト管理コマンド 
# ロールアウトの一時停止
gcloud container fleet rollouts pause ROLLOUT_ID

# ロールアウトの再開
gcloud container fleet rollouts resume ROLLOUT_ID

# ロールアウトのキャンセル
gcloud container fleet rollouts cancel ROLLOUT_ID

# ステージの強制完了
gcloud container fleet rollouts force-complete-stage ROLLOUT_ID \
  --stage=STAGE_NUMBER

⚠️ 制約事項・注意点

⚠️ 制限事項
✗Google Cloud コンソール (UI) からの操作には非対応 (gcloud CLI のみ)
✗強制自動アップグレード (90 日間未アップグレード/サポート終了) は一時停止・キャンセル不可
✗1 ステージあたり最大 1 フリートのみ参照可能
✗全クラスタが同一リリースチャネル登録を推奨
💡 考慮すべき点
  • ロールアウトシーケンスの変更は進行中のロールアウトをキャンセルする可能性あり
  • クラスタのラベル更新は既存ラベルを上書きするため注意
  • ソークタイムの変更は現在および将来の全ロールアウトに影響

💡 ユースケース

🏢 ユースケース 1: エンタープライズの段階的本番デプロイ

シナリオ: 金融機関が複数リージョンにまたがる GKE クラスタを運用。新バージョンのアップグレードを開発 → ステージング → 本番カナリア → 本番全体の順で段階実施。

💻 Dev
3日 soak
→
🔧 Staging
7日 soak
→
🐦 Canary
3日 soak
→
🎯 Prod
全体展開

効果: 本番環境全体に影響する前に、カナリアクラスタで問題を早期発見。パッチアップグレード時にはソークタイムを短縮して迅速な適用も可能。

🔒 ユースケース 2: セキュリティパッチの迅速な適用

シナリオ: 重大な CVE が発見され、全クラスタに対して特定バージョンへの迅速なアップグレードが必要。ただし、段階的に適用してワークロードへの影響を確認しながら進めたい。

効果: 手動で特定バージョンのロールアウトを開始し、各ステージの完了を手動で進行させることで、安全性を保ちながら迅速にパッチを適用可能。問題発生時にはロールアウトを一時停止して調査できる。
