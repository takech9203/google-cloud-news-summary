Gemini Enterprise Gemini Notebook Enterprise ⚠️ Breaking Change

📓 Gemini Notebook Enterprise
Web アドレス変更 (Breaking Change)

URL パスへの go/ 追加 + ホスト名からの lm 削除 (2 段階の変更)
リリース日: 2026-11-06

📌 概要

Gemini Notebook Enterprise (旧 NotebookLM Enterprise) の Web アプリの URL が 2 段階で変更されます。 既存リンクは自動リダイレクトされるため一般ユーザーへの直接的な影響はありませんが、 URL パス単位の許可リスト (アローリスト) を運用する組織では対応が必須です。 対応しないと、ロールアウト後にユーザーが Web アプリへアクセスできなくなる可能性があります。

第 1 段階
URL パスに go/ を追加
notebooklm.cloud.google.com/us/
↓
notebooklm.cloud.google.com/go/us/

🗓️ global / us: 適用済み、eu: ロールアウト中、その他: 2026-11-09 開始

第 2 段階
ホスト名から lm を削除
notebooklm.cloud.google.com
↓
notebook.cloud.google.com

🗓️ 2026 年 11 月 16 日から開始

⚠️ 対応が必要な組織: ファイアウォール、プロキシ、セキュア Web ゲートウェイで 特定の URL パス単位の許可リストを運用している組織。主な対応対象者はネットワーク管理者・セキュリティ管理者です。 スタンドアロンの Gemini Notebook Enterprise と、Gemini Enterprise 内の Gemini Notebook (vertexaisearch.cloud.google.com/notebooklm/...) の両方が対象です。
❌ アップデート前の課題
  • Web アプリの URL パスは /{REGION}/ 形式 (例: notebooklm.cloud.google.com/us/) で、組織の許可リストはこのパスを前提に構成
  • ホスト名には旧製品名に由来する notebooklm が含まれていた (Google Identity 用: notebooklm.cloud.google.com、Workforce Identity Federation 用: notebooklm.cloud.google)
✅ アップデート後の改善
  • 既存リンクは新 URL へ自動リダイレクト。ブックマークや共有済みリンクはそのまま機能
  • Google 推奨のドメイン全体 (/*) 許可に従えば、将来のパス変更時に追加の許可リスト更新が不要
  • ホスト名が notebook.cloud.google.com / notebook.cloud.google に統一され、現在の製品名 (Gemini Notebook) に沿った体系に

🌍 パス単位で許可する場合のリージョン値

ドメイン全体 (/*) を許可しない場合は、/{REGION} と /go/{REGION} の 両方を許可する必要があります。REGION に入る値は以下のとおりです。

global us eu asia-northeast1 au ca de europe-west2 in kr sg
💡 例: notebooklm.cloud.google.com/us/ と notebooklm.cloud.google.com/go/us/ の両方を許可する。

🛠️ 設定方法

✅ 前提条件

✓組織でファイアウォール、プロキシ、またはセキュア Web ゲートウェイを使用し、Gemini Notebook へのアクセスを特定の URL パスで許可していること (該当しない場合、対応は不要)
✓ネットワーク機器・ゲートウェイの許可リストを変更できる管理権限

ステップ 1: 推奨される許可リストの追加 (ドメイン全体)

将来のパス変更時に追加更新が不要になるよう、Google はドメイン全体 (/*) の許可を推奨しています。

Text 推奨: ドメイン全体の許可リスト 
# 全組織共通
notebooklm.cloud.google.com/*
notebook.cloud.google.com/*

# Workforce Identity Federation を使用している場合は追加
notebooklm.cloud.google/*
notebook.cloud.google/*

# Gemini Enterprise 内の Gemini Notebook を使用している場合は追加
vertexaisearch.cloud.google.com/notebooklm/*

ステップ 2: パス単位で許可する場合 (ドメイン全体を許可できない場合)

/* を許可できない場合は、利用するロケーションごとに /{REGION} と /go/{REGION} の両方を許可します。

Text パス単位の許可リスト例 
# 例: us リージョンを利用している場合
notebooklm.cloud.google.com/us/
notebooklm.cloud.google.com/go/us/

ステップ 3: 暫定回避策 (許可リスト更新前にブロックが発生した場合)

許可リストの更新が間に合わずユーザーがブロックされた場合、ユーザー自身が URL から /go を削除し、 クエリパラメータ version=legacy を追加することで従来の URL にアクセスできます。

Text 暫定回避策の URL 例 
# 例
https://notebooklm.cloud.google.com/eu/?project=1234567&version=legacy
🚨 注意: この回避策は Google がレガシーバージョンを廃止した時点で機能しなくなります。 恒久対応として必ず許可リストを更新してください。

💡 メリット

📈 ビジネス面

🔗 ユーザー影響の最小化

既存リンクが自動リダイレクトされるため、エンドユーザーのブックマークや共有リンクの変更は不要。

⏳ 移行猶予の確保

段階的なロールアウト (リージョン別の日程、ホスト名変更は 11 月 16 日から) と version=legacy の暫定回避策により、管理者が計画的に対応できる。

⚙️ 技術面

🛡️ 将来のパス変更への耐性

推奨どおりドメイン全体 (/*) を許可すれば、今後のパス変更時に許可リストの再更新が不要になる。

🏷️ 製品名との整合性

ホスト名が notebook.cloud.google.com となり、NotebookLM Enterprise から Gemini Notebook Enterprise への製品名変更に沿った体系になる。

⚠️ デメリット・制約事項

🚫 制限事項

✗パス単位の許可リストを使用している組織は、更新しない限りロールアウト後にアクセスがブロックされる可能性がある
✗暫定回避策 (version=legacy) は恒久的なものではなく、レガシーバージョンの廃止時点で機能しなくなる
✗パス単位で許可を続ける場合、/{REGION} と /go/{REGION} の両方を 11 リージョン分管理する必要があり、運用負荷が増える

🤔 考慮すべき点

→ホスト名変更 (2026 年 11 月 16 日) までに、新ホスト名 notebook.cloud.google.com (および WIF 利用時は notebook.cloud.google) を許可リストへ追加しておく必要がある
→社内ポータルやドキュメントに旧 URL を記載している場合、リダイレクトされるものの、新 URL への更新を検討するとよい
→Private Service Connect 経由で Gemini Enterprise へアクセスしている環境では、DNS 設定やプロキシ/ファイアウォール設定に notebooklm.cloud.google.com などのドメインが含まれているため、あわせて確認するとよい

効果: notebooklm.cloud.google/* と notebook.cloud.google/* を許可リストに追加することで、2026 年 11 月 16 日のホスト名変更後も認証フローとアプリアクセスが継続する。
