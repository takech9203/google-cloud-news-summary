📋 概要

Gemini Enterprise において、エージェントと MCP サーバーのガバナンス管理を強化する複数の機能が GA および Public Preview としてリリースされた。Agent Registry を通じた A2A エージェントやカスタム MCP サーバーのカタログ管理、Agent Gateway による Egress ポリシーの適用、そしてエージェント ID (SPIFFE ID) の可視化が可能となり、エンタープライズ環境におけるエージェントの統制・管理が大幅に改善される。

加えて、Lovable データストアが Public Preview で利用可能になり、Airtable、Freshservice、Google Stitch、Zoho Desk、Zoho Projects への新しいアクション対応も追加された。

🎯 対象ユーザー: AI エージェントの導入が進む中で、セキュリティとガバナンスを確保しながらエージェント活用を拡大したい企業の IT 管理者、セキュリティ担当者、および業務効率化を推進するチーム。

🔄 Before / After 比較

❌ Before (アップデート前)

  • エージェントや MCP サーバーを一元的に管理・発見する仕組みがなかった
  • 外部サービスへの通信に対するきめ細かいアクセス制御が限定的
  • エージェントの SPIFFE ID を管理コンソールから確認する方法がなかった
  • Lovable や一部サードパーティサービスとの連携が未対応

✅ After (アップデート後)

  • Agent Registry からエージェント/MCP サーバーを検索・インポート可能
  • Agent Gateway の Egress ポリシーで Allow/Deny ルールを設定
  • 管理者がエージェント詳細ページから SPIFFE ID を確認可能
  • Lovable + 5 つの新コネクタがアクション対応

⚙️ 主要機能

1. Agent Registry からのエージェント・MCP サーバーのインポートとガバナンス GA

→A2A エージェント、エンドポイント、MCP サーバーを一元的に管理するカタログ
→Google 製・カスタム製の MCP サーバーを Registry から発見し、Gemini Enterprise アプリに追加可能
→A2A プロトコル対応エージェントも同様にインポート可能
→Agent Gateway による Egress ポリシーで、IAM 制御やセマンティックガバナンスポリシーを適用
→リージョン整合性の厳格な適用 (App / Gateway / Registry)

2. 新データストア・新アクション対応 Public Preview

→Lovable データストア: プロジェクトの検索・閲覧、自然言語によるアクション実行
→Lovable 対応アクション: コネクタ追加、プロジェクト Remix、ナレッジ設定、公開レベル設定
→新規コネクタ: Airtable、Freshservice、Google Stitch、Zoho Desk、Zoho Projects
→Google マネージド OAuth を使用 (OAuth アプリケーションの個別作成は不要)

3. エージェント ID の表示 GA

→管理者がエージェント詳細ページから SPIFFE ID を確認可能
→パブリッシャーが SPIFFE ID を未公開の場合は Agent Registry リソース ID がフォールバック表示

Agent Registry、Agent Gateway、Gemini Enterprise アプリの 3 コンポーネントはリージョン整合性が必須。

global us-central1 us-central1、us、または global

eu europe-west1 europe-west1 または eu

Agent Identity (SPIFFE ID) フォーマット

SPIFFE ID Format 
spiffe://<TRUST_DOMAIN>/resources/<SERVICE>/<RESOURCE_PATH>

Example:
spiffe://agents.global.org-123456789012.system.id.goog/resources/discoveryengine/projects/9876543210/locations/global/collections/default_collection/engines/my-agent

Gemini Enterprise の場合:

Gemini Enterprise SPIFFE ID 
principal://agents.global.org-{ORG_ID}.system.id.goog/resources/discoveryengine/projects/{PROJECT}/locations/global/collections/default_collection/engines/{AGENT}

⚠️ デメリット・制約事項

制限事項:
  • Agent Registry からのインポートは、同一リージョンの Agent Gateway に関連付けられた Registry からのみ可能
  • Gemini Enterprise エージェント間の直接通信や、エージェントとデータコネクタ間の直接通信は Agent Gateway のポリシー適用対象外
  • ガバナンスポリシーは Agent Gateway に関連付けられた単一の Registry 内のエージェント/MCP サーバーにのみ適用可能
  • Lovable データストアは global、us、eu ロケーションのみ対応
  • VPC Service Controls ペリメータを既存の Lovable データストアに適用する場合、データストアの再作成が必要
考慮すべき点:
  • Agent Gateway のセットアップが前提条件 (未導入環境では事前準備が必要)
  • リージョン整合性要件により、コンポーネントの分散配置は不可
  • 新データストアのコネクタは Public Preview のため、Pre-GA 利用条件が適用

💡 ユースケース

🏢 ユースケース 1: 全社的なエージェント統制

シナリオ: 大企業で複数チームが独自に AI エージェントや MCP サーバーを構築・利用。セキュリティチームはすべてのエージェントの利用状況を把握し、不正なデータアクセスを防止したい。

効果: Agent Registry でエージェント・MCP サーバーを一元カタログ化し、Agent Gateway の Egress ポリシーで許可リソースのみアクセス許可。SPIFFE ID による個別権限管理。

🔧 ユースケース 2: マルチツール業務自動化

シナリオ: プロジェクト管理チームが Lovable でプロトタイピング、Airtable でデータ管理、Zoho Projects でタスク管理。統一インターフェースから自然言語で操作したい。

効果: 「Lovable の新しいプロジェクトを Remix して」「Airtable のレコードを更新して」「Zoho Projects のタスクステータスを変更して」といった命令で複数ツールを横断操作。

📌 まとめ

本アップデートにより、Gemini Enterprise は Agent Registry・Agent Gateway・Agent Identity の 3 本柱でエージェントと MCP サーバーの統制を実現する本格的なエンタープライズガバナンス機能を GA として提供開始した。

AI エージェントの導入を検討している組織は、まず Agent Gateway のセットアップと Agent Registry の構築を行い、ガバナンスポリシーを定義した上でエージェント・MCP サーバーの段階的な展開を進めることが推奨される。
