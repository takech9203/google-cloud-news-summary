📋 概要

gcloud CLI バージョン 589.0.0 がリリースされました。最重要トピックは skaffold コンポーネントの非推奨化 (Breaking Change) です。 skaffold コンポーネントは 2027 年 1 月 15 日以降の Google Cloud CLI リリースから削除され、 すでに gcloud components install skaffold の実行が一部エラーを返すようになっています。 今後 Skaffold は Skaffold 公式のインストール手順 に従って個別にインストールする必要があります。2027 年 1 月 29 日には Skaffold の GitHub リポジトリがアーカイブされます (既存リリースは引き続き利用可能)。

💡 Cloud Deploy 利用者は影響なし: Cloud Deploy は Skaffold を内包しているため、Cloud Deploy のパイプライン実行自体に Skaffold の個別インストールは不要です。

基盤面では、バンドル Python 3.14.8 / OpenSSL 3.5.9 への更新、公式 PyPI ホイール由来の cryptography 46.0.7 への変更が行われ、 機能面では Cloud Alerting、Firestore change-streams、Apigee apis、Compute advice capacity などの GA 昇格、BigQuery の Azure Data Lake Storage URI 対応、 Cloud Storage 再開可能アップロードのサーバーサイドハッシュ検証デフォルト化など、幅広いアップデートが含まれます。

❌ アップデート前の課題

  • Skaffold は gcloud components install skaffold で配布され、CI/CD スクリプトや開発環境構築がこの配布経路に依存
  • Cloud Storage の cp / mv / rsync 再開可能アップロードで、サーバーサイドハッシュ検証がデフォルト無効
  • gcloud apigee apis import --from-template でテンプレートが feature を参照していると endpoints / targets が破棄される問題
  • gcloud monitoring alerts などが GA 未満のステージで、本番運用に制約
  • Cloud Composer のストレージエクスポートで --destination 外のオブジェクトが処理対象となり得た (パストラバーサルのリスク)

✅ アップデート後の改善

  • Skaffold のインストール経路が公式配布 (skaffold.dev) に一本化され、移行期限 (2027-01-15) とともに明確なマイグレーションパスを提示
  • Python 3.14.8 + OpenSSL 3.5.9 + 公式 PyPI ホイール由来の cryptography 46.0.7 でセキュリティ基盤を最新化
  • 再開可能アップロードのサーバーサイドハッシュ検証がデフォルト有効になり、データ整合性を強化
  • Cloud Alerting / Firestore change-streams / Apigee apis / Compute advice capacity の GA 昇格で本番利用が可能に
  • エクスポートコマンドが --destination 外のオブジェクトをスキップし、パストラバーサルを防止

🚨 Breaking Change: skaffold コンポーネントの非推奨化

📅 非推奨化と削除スケジュール

2026-10-13 (本日)
gcloud CLI 589.0.0 で skaffold コンポーネントが非推奨化。gcloud components install skaffold の一部がエラーを返すように
2027-01-15
この日以降の Google Cloud CLI リリースから skaffold コンポーネントが削除
2027-01-29
Skaffold の GitHub リポジトリがアーカイブ (既存リリースは引き続き利用可能)

✅ 必要なアクション

✓Skaffold 公式のインストール手順に従い、スタンドアロンでインストールする方式に移行する
✓CI/CD パイプライン、Dockerfile、開発環境セットアップスクリプト内の gcloud components install skaffold を洗い出して置き換える
✓Cloud Deploy は Skaffold を内包しているため、Cloud Deploy のレンダリング / デプロイ処理自体には影響しない

🔧 Google Cloud CLI 基盤の更新

🐍 バンドル Python の更新

→Linux / Windows および Alpine ベースの Docker イメージのバンドル Python を 3.14.8 に更新
→Python が TLS に使用する OpenSSL が 3.5.9 に更新
→cryptography 46.0.7 をカスタムビルドではなく公式 PyPI ホイールからインストールするよう変更

🐳 Alpine Docker イメージの変更

→:alpine および :VERSION-alpine イメージがバンドル Python を使用するようになり、システム python3 を含まなくなった
⚠️Alpine イメージ内でシステム python3 に依存している処理がある場合は注意が必要
項目詳細
バンドル Python3.14.8 (Linux / Windows / Alpine Docker イメージ)
OpenSSL3.5.9 (Python の TLS 用)
cryptography46.0.7 (公式 PyPI ホイールからインストール)
Alpine イメージバンドル Python を使用、システム python3 を同梱しない

ステップ 1: gcloud CLI を 589.0.0 に更新

gcloud components update
gcloud version

ステップ 2: skaffold コンポーネントへの依存箇所を確認

Bash 依存箇所の確認 
# インストール済みコンポーネントの確認
gcloud components list

# CI/CD スクリプトなどから依存箇所を検索する例
grep -r "components install skaffold" .

ステップ 3: Skaffold を公式手順でインストール

Bash Linux (x86_64) の例: skaffold.dev の公式手順に従う 
curl -Lo skaffold https://storage.googleapis.com/skaffold/releases/latest/skaffold-linux-amd64
chmod +x skaffold
sudo install skaffold /usr/local/bin/
skaffold version

Skaffold 公式のインストール手順 に従い、プラットフォームに応じた方法でスタンドアロンインストールします。CI/CD パイプラインの Dockerfile やセットアップスクリプトも同様に置き換えます。

⚖️ メリットと制約事項

💼 ビジネス面のメリット

✓移行計画が立てやすい: 削除期限 (2027 年 1 月 15 日) が明示されており、約 3 か月の猶予をもって CI/CD パイプラインの移行を計画できる
✓GA 昇格による本番利用の安心感: Cloud Alerting、Firestore change-streams、Apigee apis、Compute advice capacity などが GA となり、SLA を前提とした本番運用に組み込める

🔬 技術面のメリット

✓セキュリティ基盤の最新化: Python 3.14.8 + OpenSSL 3.5.9 + 公式 PyPI ホイール由来の cryptography により、サプライチェーンと TLS のセキュリティが向上
✓データ整合性の強化: Cloud Storage の再開可能アップロードでサーバーサイドハッシュ検証がデフォルト有効になり、アップロードデータの破損検知が標準化
✓パストラバーサル防止: Cloud Composer のエクスポートコマンドが --destination 外のオブジェクトをスキップするようになり、セキュリティが向上

⛔ 制限事項

✗gcloud components install skaffold はすでに一部でエラーを返すため、既存の自動化スクリプトが失敗する可能性がある
✗2027 年 1 月 15 日以降の gcloud CLI リリースでは skaffold コンポーネントが完全に削除される
✗Alpine ベースの Docker イメージはシステム python3 を含まなくなったため、イメージ内でシステム python3 を前提としていた処理は修正が必要

🤔 考慮すべき点

⚠️CI/CD パイプライン (Cloud Build、GitHub Actions など) の Skaffold インストール手順を期限前に移行すること
⚠️Skaffold の GitHub リポジトリは 2027 年 1 月 29 日にアーカイブされるため、長期的な CI/CD 戦略として Cloud Deploy のマネージドなレンダリング / デプロイ機能の活用も検討に値する
⚠️gcloud CLI のバージョン固定運用をしている場合も、セキュリティ更新 (Python / OpenSSL / cryptography) を考慮して更新計画を立てること

🎯 ユースケース

1. CI/CD パイプラインの Skaffold インストール移行

シナリオ: Cloud Build や GitHub Actions のパイプラインで gcloud components install skaffold を使って Skaffold をセットアップし、GKE へのデプロイを行っている。

YAML Cloud Build 設定の移行例 
# Before (非推奨 - 2027-01-15 以降は失敗する)
steps:
  - name: gcr.io/google.com/cloudsdktool/cloud-sdk
    entrypoint: bash
    args: ["-c", "gcloud components install skaffold && skaffold run"]

# After (公式配布からインストール)
steps:
  - name: gcr.io/google.com/cloudsdktool/cloud-sdk
    entrypoint: bash
    args:
      - -c
      - |
        curl -Lo /usr/local/bin/skaffold https://storage.googleapis.com/skaffold/releases/latest/skaffold-linux-amd64
        chmod +x /usr/local/bin/skaffold
        skaffold run

✨ 効果: 削除期限後もパイプラインが停止せず、Skaffold のバージョン管理を gcloud CLI のリリースサイクルから切り離して制御できる。

2. GA 昇格コマンドの本番運用への組み込み

シナリオ: これまで Beta ステージのため本番の運用自動化に組み込めなかった gcloud monitoring alerts や gcloud firestore change-streams を、GA 昇格を機に運用スクリプトへ正式採用する。

✨ 効果: GA コマンドとして安定したインターフェースで、アラート管理や Firestore の変更ストリーム管理を自動化できる。

💰 料金

✅ gcloud CLI (Cloud SDK) 自体は無料で利用できます。 今回のアップデートによる料金への直接的な影響はありません。 各コマンドが操作する対象サービス (AlloyDB、BigQuery、Compute Engine など) の利用料金は、それぞれのサービスの料金体系に従います。

🔗 関連サービス・機能

🚀 Cloud Deploy

Skaffold を内包しており、レンダリング (skaffold render) とデプロイ (skaffold apply) に使用。skaffold コンポーネント削除後も Cloud Deploy 自体の動作には個別インストール不要。

🏗️ Cloud Build

CI/CD パイプラインで Skaffold をインストールして使用している場合、インストール手順の移行が必要。

☸️ Google Kubernetes Engine (GKE)

Skaffold の主要なデプロイ先。今回のリリースでは Wiz Sensor 構成フラグも追加。

🔔 Cloud Monitoring

gcloud monitoring alerts の GA 昇格により、アラート管理の CLI 操作が正式サポートに。

📝 まとめ

gcloud CLI 589.0.0 の最重要ポイントは skaffold コンポーネントの非推奨化です。 2027 年 1 月 15 日以降のリリースで削除されるため、gcloud components install skaffold に依存する CI/CD パイプラインや開発環境は、期限前に Skaffold 公式のインストール手順への移行を完了させてください。 あわせて、Cloud Alerting や Firestore change-streams などの GA 昇格コマンドの本番採用、 Alpine Docker イメージのシステム python3 廃止の影響確認も推奨します。
