BigQuery Knowledge Catalog コンソール UI 変更

🗄️ BigQuery: Metadata curation ページ廃止
→ Knowledge Catalog へ一本化

📅 リリース日: 2026-11-05

📌 概要

BigQuery コンソールの Metadata curation (メタデータキュレーション) ページが削除された。 今後は Knowledge Catalog (旧 Dataplex Universal Catalog) を使用して、 Cloud Storage の検出スキャン (discovery scan) のスケジュール設定、データプロファイリングとデータ品質 (auto data quality) の管理、 および関連するデータガバナンスタスクを実行する。

💡 ポイント: 今回のアップデートは機能の廃止ではなく 管理画面の集約・移行。 検出スキャン・プロファイリング・品質スキャンの機能自体は Knowledge Catalog 側で引き続き提供される。 対象は BigQuery コンソールからこれらを運用していたデータエンジニア、データスチュワード、ガバナンス担当者。

❌ Before (アップデート前の課題)

  • ガバナンス関連の管理画面が BigQuery コンソール (Metadata curation ページ) と Knowledge Catalog の双方に分散
  • どちらのページを使うべきかが分かりにくい

✅ After (アップデート後の改善)

  • 検出スキャン・プロファイリング・品質管理が Knowledge Catalog に一本化され、管理場所が明確に
  • 「Data profiling & quality」ページでプロジェクト横断管理、テーブル単位は「Data quality」タブで直接管理
  • gcloud CLI (gcloud dataplex datascans ...) / クライアントライブラリ / REST API の自動化経路はそのまま利用可能

BigQuery コンソールの Metadata curation ページは削除され、Cloud Storage 検出スキャン、データプロファイリング、 データ品質スキャンの管理はすべて Knowledge Catalog のコンソールページに集約された。 検出スキャンは従来どおり Cloud Storage をスキャンして BigQuery に BigLake / 外部テーブルを作成・更新する。

⚙️ 主要機能 (移行先での管理内容)

🔍 1. Cloud Storage 検出スキャン (automatic discovery)

  • Knowledge Catalog から検出スキャンを作成し、スケジュール実行 (Repeat: 開始時刻・曜日・頻度を指定) またはオンデマンド実行を設定
  • 構造化・半構造化データ (Parquet、Avro、ORC、JSON、CSV) は BigLake 外部テーブル / 非 BigLake 外部テーブルとして、非構造化データ (画像、ドキュメント、音声/動画) は BigLake オブジェクトテーブルとして BigQuery に登録
  • スキャン実行時にバケットに対応する BigQuery データセットを自動作成 (データセット名はバケット名と同名。使用不可の文字はアンダースコアに置換)
  • BigLake テーブル作成には Google Cloud リソース接続 ID の指定が必要。未指定の場合は非 BigLake 外部テーブルを作成

📊 2. データプロファイリングの管理

  • Knowledge Catalog の「Data profiling & quality」ページから、データプロファイルスキャンの作成・実行・結果確認
  • プロファイル結果を Knowledge Catalog メタデータとして公開でき、カタログ上のテーブルエントリから参照可能

✅ 3. データ品質 (auto data quality) の管理

  • 「Data profiling & quality」ページから、品質スキャンの作成、Run now による即時実行、表示名・フィルタ・スケジュール・品質ルールの編集、権限管理、ジョブ履歴 (直近 300 ジョブまたは過去 1 年分) の確認
  • テーブル単位の管理も可能: Knowledge Catalog の検索ページでテーブルを開き「Data quality」タブから新規作成・実行・設定編集・履歴表示
  • 結果をカタログメタデータとして公開している場合、最新結果は BigQuery と Knowledge Catalog 双方のテーブルページの「Data quality」タブに表示

🔧 技術仕様

📋 タスク別の移行先

タスク 移行先 (Knowledge Catalog)
Cloud Storage 検出スキャンのスケジュール 検出スキャンの作成画面 (Repeat / On demand を設定)
データプロファイリングの管理 Data profiling & quality ページ
データ品質スキャンの管理 Data profiling & quality ページ、またはテーブルの Data quality タブ
品質スキャン結果の確認 スキャン詳細ページ (Overview / Jobs history)、テーブルの Data quality タブ

🖥️ コンソール以外のアクセス経路 (変更なし)

スキャンの管理は、コンソールに加えて以下の方法でも引き続き可能。

Bash gcloud CLI によるデータ品質スキャンの管理 
# データ品質スキャンの実行
gcloud dataplex datascans run DATASCAN --location=LOCATION

# 品質スキャンの履歴ジョブの一覧表示
gcloud dataplex datascans jobs list \
  --location=LOCATION --datascan=DATASCAN

# 品質スキャンジョブの結果確認
gcloud dataplex datascans jobs describe JOB \
  --location=LOCATION --datascan=DATASCAN --view=FULL

REST API (dataScans.get など) やクライアントライブラリ (C#、Go、Java、Ruby など) も Dataplex API として提供されている。

⚖️ メリット・制約事項

👍 ビジネス面のメリット

✓ガバナンス業務の一元化: データガバナンスタスクの管理場所が Knowledge Catalog に集約され、チームの運用手順やトレーニングをシンプルにできる
✓カタログ中心のガバナンスへの布石: 品質スコアカード、リネージ、データプロダクトなどを担う Knowledge Catalog 上で品質・プロファイル結果を活用する運用に自然につながる

🔧 技術面のメリット

✓API / CLI の互換性維持: スキャンの実体は Dataplex API の DataScan リソースであり、gcloud・REST・クライアントライブラリの自動化経路は影響を受けない
✓結果の参照性は維持: 結果をカタログメタデータとして公開していれば、従来どおり BigQuery コンソールのテーブルページの Data quality タブからも最新結果を参照可能

⚠️ 考慮すべき点

▲旧ページに慣れたユーザーは、新しいページ (Data profiling & quality ページなど) の操作導線を覚える必要がある
▲社内の運用手順書・ランブック・ブックマークに旧ページへの導線が残っている場合は更新が必要
▲既存の品質スキャンでコンソールページへの結果公開を設定している場合、今後の結果を Knowledge Catalog メタデータとして公開するにはスキャンを編集して公開設定を再度有効化する必要がある (カタログ公開には追加の権限が必要になる場合がある)

💰 料金

🔗 関連サービス・機能

📚 Knowledge Catalog (旧 Dataplex Universal Catalog)

今回の移行先。BigQuery メタデータの自動取り込み、セマンティック検索、データ品質スコアカード、データリネージ、データプロダクトなどガバナンス機能全般を提供。

🗄️ BigLake / BigQuery 外部テーブル

検出スキャンが作成・更新するテーブルタイプ。リソース接続 ID の有無とデータ形式に応じて BigLake 外部テーブル、非 BigLake 外部テーブル、BigLake オブジェクトテーブルが作成される。

🪣 Cloud Storage

検出スキャンの対象。構造化 (Parquet、Avro、ORC、JSON、CSV)・非構造化 (画像、ドキュメント、音声/動画) データをカタログ化できる。

🤖 Knowledge Studio (Preview)

2026-11-02 に発表された Knowledge Catalog の新機能群。自然言語によるデータ探索やエンリッチメントタスクを提供。今回の UI 集約と合わせて Knowledge Catalog がデータガバナンスとコンテキスト管理のハブになりつつある。

📝 まとめ

BigQuery コンソールの Metadata curation ページが削除され、Cloud Storage 検出スキャン、データプロファイリング、データ品質の管理は Knowledge Catalog に一本化された。 機能自体や API / gcloud による自動化経路は変わらないため影響は操作導線に限られるが、 該当ページを日常的に使用していたチームは、Knowledge Catalog の「Data profiling & quality」ページとテーブルの Data quality タブを使う運用への切り替えと、 社内手順書・ブックマークの更新を行うことを推奨する。
