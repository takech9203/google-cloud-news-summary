Container-Optimized OS GA (LTS リリース) Milestone 133 📅 リリース日: 2026-11-17

📋 概要

2026 年 11 月 17 日、Container-Optimized OS (COS) の LTS Milestone 133 系の新リリース cos-133-19999-44-250 が公開されました。Kernel COS-6.18.59、Docker v29.4.3、Containerd v2.4.1 で構成され、 サスペンド失敗の不具合修正、google-guest-agent への 2 つの拡張機能 (ManagedWorkloadIdentity / GuestTelemetry) のオプトインサポート追加、および 6 件の CVE 修正を含みます。

COS は GKE のノードイメージ (cos_containerd) や Compute Engine のコンテナワークロードで使用される、 コンテナ実行に最適化されたセキュリティ重視の OS です。GKE Autopilot クラスタは常にこのイメージを使用するため、 COS のセキュリティ修正は GKE 利用者全体に影響する重要なアップデートです。

❌ アップデート前の課題

  • インスタンスのサスペンド操作が UNSUPPORTED_OPERATION エラーで失敗する不具合があった
  • google-guest-agent が ManagedWorkloadIdentity / GuestTelemetry 拡張に未対応で、COS 上でオプトイン利用できなかった
  • oauthlib、auth-provider-gcp、sudo、google-osconfig-agent、node-problem-detector、rsync に既知の脆弱性 (CVE 6 件) が残存

✅ アップデート後の改善

  • サスペンド操作が UNSUPPORTED_OPERATION で失敗する問題が修正された
  • ManagedWorkloadIdentity 拡張と GuestTelemetry 拡張がオプトインで利用可能に
  • CVE-2026-118669 / 33814 / 35535 / 78663 / 42154 / 119741 の 6 件の脆弱性を修正

⚙️ 主要機能・修正内容

📦 1. コンポーネントバージョン (cos-133-19999-44-250)
✓Kernel: COS-6.18.59 (11/11 リリースの cos-133-19999-44-197 では COS-6.18.55)
✓Docker: v29.4.3、Containerd: v2.4.1 (前リリースから変更なし)
✓GPU ドライバ: リリースごとのドライバ一覧 (gpu_driver_versions.textproto) で公開
💤 2. サスペンド失敗の修正 (Fixed)
✓インスタンスのサスペンド操作が UNSUPPORTED_OPERATION エラーで失敗する問題を修正
✓Compute Engine のサスペンド/レジューム機能を COS インスタンスで利用するユーザーに影響する修正
🤖 3. google-guest-agent の拡張サポート追加 (Fixed)
✓ManagedWorkloadIdentity 拡張: Managed Workload Identity (SPIFFE 準拠の X.509 証明書による VM 間 mTLS 認証) に関連。証明書の自動プロビジョニング/ローテーションを担い、認証情報は /var/run/secrets/workload-spiffe-credentials に配置

✓いずれもオプトイン (明示的に有効化した場合のみ動作) として追加

✓OS 基盤パッケージ (sudo、rsync)、Python ライブラリ (oauthlib)、Google Cloud エージェント (auth-provider-gcp、google-osconfig-agent、node-problem-detector) を修正。詳細は下記の技術仕様を参照

🛠️ 設定方法

📌 前提条件

✓Container-Optimized OS を GKE ノードイメージまたは Compute Engine VM イメージとして使用していること
✓LTS Milestone 133 系 (cos-133) のイメージを利用していること

ステップ 1: 現在のイメージバージョンの確認

Bash バージョン確認 
# Compute Engine インスタンスの OS バージョン確認 (インスタンス内で実行)
cat /etc/os-release

# GKE ノードプールのノードイメージ確認
gcloud container node-pools describe NODE_POOL_NAME \
  --cluster=CLUSTER_NAME \
  --location=LOCATION \
  --format="value(config.imageType)"

ステップ 2: 新リリースの適用

Bash イメージ更新 / 自動更新の有効化 
# Compute Engine: 新しい COS イメージでインスタンスを再作成する場合
gcloud compute images list --project cos-cloud --filter="family:cos-133-lts"

# Compute Engine: 自動更新を有効化する場合 (Milestone 117 以降はデフォルト無効)
gcloud compute instances add-metadata INSTANCE_NAME \
  --metadata cos-update-strategy=update_enabled
💡 更新の仕組み: COS の自動更新はアクティブ/パッシブのルートパーティション方式で OS イメージ全体を更新します。更新はパッシブパーティションにインストールされ、再起動後に有効になります。GKE ノードでは COS の自動更新機能は無効化されており、GKE のノード自動アップグレード機能で更新されます。GKE パッチバージョンと COS ノードイメージの対応は マッピング JSON で公開されています。

✨ メリット

💼 ビジネス面

✓セキュリティリスクの低減: sudo や rsync といった基盤コンポーネントを含む 6 件の CVE が修正され、コンテナ実行基盤の脆弱性リスクが低減される
✓コンプライアンス対応: 定期的な脆弱性修正の適用により、脆弱性管理ポリシーやセキュリティ監査への対応が容易になる

🔧 技術面

✓サスペンド機能の信頼性向上: UNSUPPORTED_OPERATION で失敗していたサスペンド操作が修正され、コスト削減目的のインスタンスサスペンド運用が安定する
✓Managed Workload Identity への布石: guest-agent の ManagedWorkloadIdentity 拡張 (オプトイン) により、SPIFFE 準拠の X.509 証明書を用いた VM 間 mTLS 認証との統合パスが COS でも整備される
✓エージェントの脆弱性修正: node-problem-detector や google-osconfig-agent など、ノード運用に常駐するエージェントの依存ライブラリが更新される

⚠️ デメリット・制約事項

🚧 制限事項

●ManagedWorkloadIdentity / GuestTelemetry 拡張はオプトインであり、デフォルトでは有効化されない
●COS の自動更新は再起動するまで有効にならない (自動更新機能は強制再起動を行わない)
●UEFI Secure Boot が有効な COS VM および Arm ベースイメージではインプレース更新がサポートされない

🤔 考慮すべき点

●Milestone 117 以降、COS イメージの自動更新機能はデフォルトで無効のため、スタンドアロン利用時は cos-update-strategy メタデータの設定またはイメージの差し替えが必要
●GKE ノードは GKE のノード自動アップグレードで更新されるため、新リリースの反映タイミングは GKE のリリースチャネルに依存する
●カーネルが COS-6.18.55 から COS-6.18.59 に更新されているため、カーネルアップグレードに敏感な本番ワークロードでは事前検証を推奨

🎯 ユースケース

☸️ ユースケース 1: GKE ノードの脆弱性管理

シナリオ: セキュリティポリシーで既知 CVE の修正適用期限が定められている組織で、GKE ノード (cos_containerd) の脆弱性を解消したい。

Bash GKE ノードプールのアップグレード 
# GKE → COS イメージのマッピングを確認し、
# cos-133-19999-44-250 を含む GKE パッチバージョンへアップグレード
gcloud container clusters upgrade CLUSTER_NAME \
  --location=LOCATION \
  --node-pool=NODE_POOL_NAME \
  --cluster-version=GKE_PATCH_VERSION

効果: sudo、rsync、node-problem-detector などノード上のコンポーネントの CVE 6 件が解消され、脆弱性スキャンの指摘事項を低減できる。

💤 ユースケース 2: COS インスタンスのサスペンド運用

シナリオ: 開発環境の Compute Engine 上の COS インスタンスを夜間サスペンドしてコストを削減したいが、サスペンドが UNSUPPORTED_OPERATION で失敗していた。

効果: 本リリースの適用によりサスペンド失敗が修正され、サスペンド/レジュームを使った運用が可能になる。

🔗 関連サービス・機能

☸️ Google Kubernetes Engine (GKE)

COS は GKE のデフォルトノードイメージ (cos_containerd)。Autopilot クラスタは常にこのイメージを使用し、ノード自動アップグレードで新リリースが適用される。

🖥️ Compute Engine

コンテナ実行用 VM イメージとして COS を利用可能。サスペンド/レジューム機能や guest-agent (ゲスト環境) が本リリースの修正対象。

🔐 Managed Workload Identity

SPIFFE 準拠の X.509 証明書で VM 間 mTLS 認証を実現する機能。guest-agent が証明書の自動ローテーションを担う。本リリースで COS の guest-agent にオプトイン拡張が追加された。

🧩 OS Config (google-osconfig-agent)

VM のパッチ・構成管理エージェント。本リリースで CVE-2026-78663 が修正された。

📝 まとめ

cos-133-19999-44-250 は、サスペンド不具合の修正、guest-agent への ManagedWorkloadIdentity / GuestTelemetry 拡張のオプトイン追加、6 件の CVE 修正を含む LTS Milestone 133 の定期リリースです。GKE ノードや COS ベースの VM を運用している場合は、 ノード自動アップグレードやイメージ更新を通じて本リリースを適用し、脆弱性を解消することを推奨します。
