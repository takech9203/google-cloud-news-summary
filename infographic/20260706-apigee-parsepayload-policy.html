🔌 Apigee X: ParsePayload ポリシー

MCP ツールアクセス管理の新時代

2026-07-06
GA Apigee X

📋 概要

Apigee X に新しい ParsePayload ポリシーとペイロードオペレーションマッチング機能が追加されました。JSON-RPC ベースのプロトコル (特に Model Context Protocol: MCP) において、リクエストボディに埋め込まれたオペレーション情報を抽出し、ツール単位でのアクセス制御、クォータ管理、ルーティング、課金を実現します。

💡 ポイント: 従来の REST API では URL パスと HTTP メソッドでオペレーションを識別できましたが、MCP では単一エンドポイント (/mcp) で全てのツール呼び出しを処理するため、リクエストボディの解析が必要でした。ParsePayload ポリシーがこのギャップを埋めます。

Before / After 比較

❌ Before (従来)

  • MCP サーバーは単一エンドポイントで全ツール呼び出しを処理
  • URL パスベースのオペレーション識別が不可
  • ツール名抽出の仕組みが Apigee に存在しなかった
  • ツールごとのクォータ制限・アクセス制御が困難

✅ After (ParsePayload)

  • JSON-RPC リクエストからオペレーション名を自動抽出
  • API Product でツール単位のアクセス制御・クォータ設定
  • tools/list レスポンスの自動フィルタリング
  • 条件付きフローでツール別ロジックを実装可能

🏗️ アーキテクチャ図

ParsePayload ポリシーが JSON-RPC リクエストボディからオペレーション名を抽出し、後続の認証・クォータポリシーが API Product の設定に基づいてツール単位のアクセス制御を実行します。

⚡ 主要機能

📦 ParsePayload ポリシー

  • JSON-RPC 2.0 ペイロードからオペレーション情報を抽出
  • MCP プロトコルに対応し tools/call/{tool_name} 形式のオペレーション名を生成
  • フロー変数に抽出結果を格納
  • リクエスト PreFlow の先頭に配置

🎯 ペイロードオペレーションマッチング

  • API Product に payloadOperationGroup フィールドを追加
  • ツール単位で許可オペレーションとクォータを定義
  • 異なる API Product で階層型アクセスを実現
  • tools/list と tools/call/{tool_name} の両方を管理

🔒 自動ツールフィルタリング

  • tools/list レスポンスから未登録ツールを自動除外
  • 追加のフィルタリングポリシーは不要
  • ParsePayload + 認証ポリシーの組み合わせで自動動作

🔀 条件付きフローによるツール別ロジック

  • parsepayload.{policyName}.operation フロー変数を条件に使用
  • ツールごとに異なる SpikeArrest を適用可能
  • バックエンドルーティング、リクエスト変換に対応

🔧 技術仕様

ParsePayload ポリシー設定

要素説明値
<Source>解析対象メッセージrequest (デフォルト)
<PayloadType>ペイロード形式JSON-RPC-2.0
<Protocol>プロトコルMCP

抽出されるフロー変数

フロー変数説明値の例
parsepayload.{name}.operation導出されたオペレーション名tools/call/get_weather
parsepayload.{name}.json-rpc.request.methodJSON-RPC メソッドtools/call
parsepayload.{name}.json-rpc.request.idJSON-RPC リクエスト ID1
parsepayload.{name}.json-rpc.request.params.nameツール名get_weather
parsepayload.{name}.json-rpc.request.params.arguments.{arg}ツール引数引数値

ParsePayload ポリシー XML

XML 
<ParsePayload continueOnError="false" enabled="true" name="ParsePayload-MCP">
  <Source>request</Source>
  <PayloadType>JSON-RPC-2.0</PayloadType>
  <Protocol>MCP</Protocol>
</ParsePayload>

⚙️ 設定方法

⚠️ 前提条件: Apigee X 組織が構成済み / MCP サーバーへのルーティング用 API プロキシがデプロイ済み / Apigee 1-17-0-apigee-7 以降

ステップ 1: ParsePayload ポリシーの追加

API プロキシのリクエスト PreFlow に ParsePayload ポリシーを追加します。認証・クォータポリシーよりも前に配置する必要があります。

XML 
<ProxyEndpoint name="default">
  <PreFlow>
    <Request>
      <Step>
        <Name>ParsePayload-MCP</Name>
      </Step>
      <Step>
        <Name>VerifyAPIKey-1</Name>
      </Step>
      <Step>
        <Name>Quota-PerToolLimit</Name>
      </Step>
    </Request>
  </PreFlow>
  <HTTPProxyConnection>
    <BasePath>/mcp</BasePath>
  </HTTPProxyConnection>
  <RouteRule name="default">
    <TargetEndpoint>default</TargetEndpoint>
  </RouteRule>
</ProxyEndpoint>

ステップ 2: API Product の設定

payloadOperationGroup を使用して、ツール単位のオペレーションとクォータを定義します。

Bash 
curl -X POST \
  "https://apigee.googleapis.com/v1/organizations/ORG_NAME/apiproducts" \
  -H "Authorization: Bearer $(gcloud auth print-access-token)" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "mcp-tools-product",
    "displayName": "MCP Tools Product",
    "approvalType": "auto",
    "payloadOperationGroup": {
      "operationConfigs": [
        {
          "apiSource": "mcp-proxy",
          "operations": [
            { "operation": "tools/call/get_stock_price" },
            { "operation": "tools/call/get_company_news" }
          ],
          "quota": {
            "limit": "100",
            "interval": "1",
            "timeUnit": "minute"
          }
        },
        {
          "apiSource": "mcp-proxy",
          "operations": [
            { "operation": "tools/list" }
          ],
          "quota": {
            "limit": "300",
            "interval": "1",
            "timeUnit": "minute"
          }
        }
      ]
    }
  }'

ステップ 3: 認証ポリシー + クォータポリシー

XML 
<!-- API キー認証 -->
<VerifyAPIKey name="VerifyAPIKey-1">
  <DisplayName>Verify API Key</DisplayName>
  <APIKey ref="request.queryparam.apikey"/>
</VerifyAPIKey>

<!-- ツール別クォータ -->
<Quota name="Quota-PerToolLimit">
  <DisplayName>Per-Tool Quota</DisplayName>
  <UseQuotaConfigInAPIProduct stepName="VerifyAPIKey-1"/>
  <Distributed>true</Distributed>
</Quota>

✅ メリット

💼 ビジネス面

✓ MCP ツールの商用化: ツール単位の課金・クォータ管理により API プロダクトとして提供可能
✓ 階層型アクセス制御: Basic/Premium などの料金プランを構成可能
✓ ガバナンス強化: AI エージェントのツールアクセスを組織レベルで制御

🔧 技術面

✓ プロトコル非依存: 既存の Apigee ポリシーをそのまま適用可能
✓ 自動フィルタリング: カスタムポリシーなしで tools/list をフィルタ
✓ 柔軟な条件付きフロー: ツールごとに異なるルーティング・制限を実装
✓ 追加料金なし: 全 Apigee X 顧客が追加費用なしで利用可能

⚠️ 制限事項・注意点

✗ メッセージストリーミングとの併用は不可 (ParsePayload はストリーミング非対応)
✗ 対応する PayloadType は JSON-RPC-2.0 のみ
✗ 対応プロトコルは MCP のみ
✗ Extensible Policy に分類され、ライセンスによってはコスト影響の可能性あり
📌 考慮すべき点:
  • ParsePayload は必ず認証・クォータポリシーよりも前 (PreFlow 先頭) に配置すること
  • MCP システムメソッド (initialize, notifications/initialized, ping) はマッチングをバイパスするが、logging/setLevel は明示的な許可が必要
  • tools/list を API Product に含めない場合、クライアントはツール一覧を取得できない

🎯 ユースケース

🤖 ユースケース 1: AI エージェント向け階層型アクセス制御

企業が複数の AI エージェントに対して、役割に応じた MCP ツールへのアクセスを制御。一般エージェントには情報取得ツールのみ、管理者エージェントには全ツールへのアクセスを許可。

JSON 
{
  "name": "basic-agent-product",
  "payloadOperationGroup": {
    "operationConfigs": [{
      "apiSource": "mcp-proxy",
      "operations": [
        { "operation": "tools/call/get_stock_price" },
        { "operation": "tools/call/get_company_news" },
        { "operation": "tools/list" }
      ],
      "quota": { "limit": "100", "interval": "1", "timeUnit": "minute" }
    }]
  }
}
効果: tools/list 呼び出し時に許可されたツールのみが返されるため、未許可ツールの呼び出しを事前に防止。

💰 ユースケース 2: MCP ツールの従量課金サービス

SaaS プロバイダーが MCP サーバーを公開し、ツール呼び出しごとに異なるレート制限と課金を適用。高コストなツール (DB クエリ: 10回/分) と低コストなツール (キャッシュ読み取り: 1000回/分) で異なるクォータを設定。

JSON 
{
  "payloadOperationGroup": {
    "operationConfigs": [
      {
        "apiSource": "mcp-proxy",
        "operations": [{ "operation": "tools/call/query_database" }],
        "quota": { "limit": "10", "interval": "1", "timeUnit": "minute" }
      },
      {
        "apiSource": "mcp-proxy",
        "operations": [{ "operation": "tools/call/read_cache" }],
        "quota": { "limit": "1000", "interval": "1", "timeUnit": "minute" }
      }
    ]
  }
}

🏢 ユースケース 3: マルチテナント MCP プラットフォーム

プラットフォーム事業者がテナントごとに異なるツールセットと利用上限を提供する MCP プラットフォームを運用。テナントごとに異なる API Product を割り当て、単一の MCP サーバーで複数テナントのアクセス制御とクォータ管理を実現。Apigee のデベロッパーアプリ管理機能でテナントのオンボーディングとキー管理を効率化。
