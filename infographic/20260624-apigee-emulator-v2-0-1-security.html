📋 概要

Google Cloud は Apigee Emulator v2.0.1 をリリースした。これは v2.0.0 に対するセキュリティ専用のホットフィックスリリースであり、Netty ネットワーキングライブラリおよびGo 標準ライブラリのヘルスチェックバイナリに存在する計10件のセキュリティ脆弱性 (CVE) に対処している。

本リリースには機能変更、API 変更、設定変更は一切含まれておらず、v2.0.0 のドロップイン・リプレースメントとして位置づけられている。対象ユーザーは、VS Code の Cloud Code 拡張機能を使用して Apigee API プロキシのローカル開発・テストを行っている開発者全般である。

💡 ポイント: Apigee Emulator は 2026年5月22日の v2.0.0 以降、Apigee hybrid とは独立してバージョニング・リリースされるようになった。本リリースはその独立リリース体制のもとで迅速にセキュリティパッチを提供する初めてのケースとなる。

🔄 Before / After 比較

❌ Before (v2.0.0)

  • Netty 4.1.133.Final に7件の脆弱性が存在
  • Go 標準ライブラリ 1.25.10 に3件の脆弱性
  • netty-tcnative-boringssl-static 2.0.53.Final (旧TLS実装)
  • 推移的依存関係のバージョン不整合リスク

✅ After (v2.0.1)

  • Netty 4.1.135.Final で全7件のCVE修正済み
  • Go 1.25.11 で全3件のCVE修正済み
  • netty-tcnative-boringssl-static 2.0.77.Final (最新TLS)
  • netty-bom による一元バージョン管理導入

⚡ 主要機能

1. Netty 4.1.135.Final へのアップグレード

  • 4.1.133.Final から 4.1.135.Final へ更新
  • netty-handler (TLS/SSL ハンドシェイク処理) の3件の脆弱性を修正
  • netty-codec-http (HTTP/1.1 コーデック) の1件の脆弱性を修正
  • netty-codec-http2 (HTTP/2 コーデック) の3件の脆弱性を修正
  • netty-bom (Bill of Materials) を導入し、全推移的 netty-* アーティファクトのバージョンをピン留め

2. Cassandra ベースイメージのリフレッシュ

  • 組み込みヘルスチェックバイナリの Go 標準ライブラリを 1.25.10 から 1.25.11 へ更新
  • Go 標準ライブラリに関する3件の CVE を修正
  • ヘルスチェックバイナリは Cassandra コンテナの正常性確認に使用される

3. netty-tcnative-boringssl-static の更新

  • 2.0.53.Final から 2.0.77.Final へ更新
  • BoringSSL ベースの TLS ネイティブ実装を最新化
  • classifier variants (プラットフォーム固有バイナリ) を含む全バリアントが更新対象

ステップ 1: エミュレーターバージョンの更新

VS Code の Settings で apigee emulators を検索し、バージョン 2.0.1 を追加する。または settings.json に直接追記:

JSON VS Code settings.json 
{
  "cloudcode.apigee.emulators": ["2.0.1"]
}

ステップ 2: 新しいエミュレーターのインストール

Cloud Code の Apigee セクションで emulators フォルダを展開し、Apigee Emulator 2.0.1 のインストールアイコンをクリック。

ステップ 3: 既存コンテナの再作成

Bash 既存コンテナの停止・削除 
# 既存コンテナの停止・削除

# Cloud Code UI から新しいコンテナを追加
# emulators > Apigee Emulator 2.0.1 > "+" をクリック

⚠️ デメリット・制約事項

制限事項:
  • ローカル開発環境 (Apigee Emulator) のみが対象。Apigee X マネージドランタイムや hybrid ランタイムには影響しない
  • Docker 環境が必須 (コンテナとして動作するため)
  • VS Code + Cloud Code 拡張機能が前提環境
考慮すべき点:
  • 既存コンテナは手動で再作成が必要 (新イメージ使用のため)
  • カスタム Docker オプション (volumes、environment variables 等) は新コンテナ作成時に再設定が必要
  • エミュレーターイメージの取得には Google Artifact Registry へのアクセス権限が必要

🏦 ユースケース 1: セキュリティコンプライアンスが求められる開発チーム

シナリオ: 金融機関の API 開発チームが、社内セキュリティポリシーとして「既知の CVE を含むソフトウェアの使用禁止」を掲げている。Apigee Emulator を使ったローカル開発で脆弱性が検出された。

シナリオ: CI/CD パイプラインに Apigee Emulator を組み込み、コンテナイメージの脆弱性スキャン (Trivy、Snyk 等) を定期実行している。

効果: v2.0.1 への更新により、Netty および Go 標準ライブラリ関連の脆弱性アラートが解消され、セキュリティゲートを通過できるようになる。
