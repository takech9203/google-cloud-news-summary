📝 概要

2026 年 11 月 11 日、Google Cloud は Container-Optimized OS (COS) の 5 つのイメージリリースを公開。 開発チャネルの cos-dev-138-20309-0-0 と、LTS マイルストーンの cos-121-18867-652-49 / cos-125-19216-801-29 / cos-129-19506-625-25 / cos-133-19999-44-197 が対象の 107 項目にわたる大規模メンテナンスリリースである。

セキュリティ面では openssl、glibc、curl、expat、libpcre2 などの基盤ライブラリに加え、docker、containerd、cri-tools、cni-plugins、kubernetes、guest-agent、google-osconfig-agent といったコンテナランタイム・エージェント系コンポーネントの CVE が広範に修正された。 特に CVE-2026-84304 と CVE-2026-84445 は複数コンポーネント・複数マイルストーンにまたがる修正で、Go ベースのコンポーネント群に共通する脆弱性対応とみられる。

機能面では cos-dev-138 での 64k ページサイズの iRDMA サポート、PCI peer-to-peer DMA 有効化、A4X-Max イメージの RTC サポート、Lustre クライアントドライバ v2.16 対応 (cos-dev-138 / cos-121)、ext4 ジャーナル自動リサイズなどが追加。対象は GKE ノードや Compute Engine VM で COS を使用するすべてのユーザー。

❌ Before (アップデート前の課題)

  • openssl (CVE-2025-9230、CVE-2026-14456 など)、glibc (CVE-2026-4438、CVE-2026-6368)、curl (CVE-2026-18924 ほか 4 件) など基盤ライブラリに未修正の脆弱性
  • docker、containerd、cri-tools、cni-plugins、kubernetes、ゲストエージェント群に CVE-2026-84304、CVE-2026-84445、CVE-2026-116587 などが残存
  • COS で Lustre クライアントドライバ 2.16 系が利用不可
  • 64k ページサイズカーネルで iRDMA や PCI peer-to-peer DMA が未サポート
  • ステートフルパーティション拡張時に ext4 ジャーナルサイズが追従しない (cos-dev-138 で修正)

✅ After (アップデート後の改善)

  • 5 イメージにわたり基盤ライブラリとコンテナ関連コンポーネントの CVE を一括修正、脆弱性スキャン指摘が解消
  • cos-dev-138 / cos-121 で Lustre クライアントドライバ 2.16 (Managed Lustre 連携) が利用可能に
  • cos-dev-138 で 64k ページの iRDMA + PCI P2P DMA が有効化、HPC / AI 向け I/O 機能が拡充
  • cos-dev-138 で A4X-Max の RTC サポート、NVIDIA ドライバ v580.196.07 / v595.112.07 対応、fstrim.timer 定期実行を追加
  • cos-dev-138 で curl v8.22.0、openssh v10.6_p1、ca-certificates v20260816.3.131.1 など多数のパッケージを最新化

⚙️ 主な機能追加・変更

✓64k ページサイズの iRDMA サポート追加: 64k ページカーネルで Intel RDMA (iRDMA) が利用可能に
✓PCI peer-to-peer DMA の有効化 (64k カーネル): GPU とストレージ / NIC 間の直接データ転送を 64k ページカーネルでも利用可能に

✓Lustre クライアントドライバ v2.16.0_p60 のサポート: 並列ファイルシステム Lustre の新ドライバに対応
✓ext4 ジャーナルの自動リサイズ: ステートフルパーティション拡張時にジャーナルも適切にリサイズ
✓NVIDIA ドライバ v580.196.07 / v595.112.07 のサポート追加、cos-gpu-installer v2.7.12 (r615 以降のドライバ向け ucode ファームウェアをインストール)
✓fstrim.timer の定期実行を有効化: シンプロビジョニングストレージ上の未使用ブロックを定期的に回収
✓Linux カーネルを v6.18.60 に更新、openssh v10.6_p1、ca-certificates、nss v3.132、gnutls v3.8.13、e2fsprogs v1.47.4 など約 30 パッケージをアップグレード

🛠️ 設定方法

📌 前提条件

  • GKE ノードまたは Compute Engine VM で COS イメージ (cos-cloud プロジェクト) を使用していること
  • GKE の場合、ノード自動アップグレードが有効であれば本リリースは自動的に適用される

ステップ 1: 使用中の COS イメージバージョンの確認

Bash イメージバージョンの確認 
# Compute Engine VM のイメージを確認
gcloud compute instances describe INSTANCE_NAME \
  --zone=ZONE --format="value(disks[0].licenses)"

# COS インスタンス内からバージョンを確認
cat /etc/os-release

ステップ 2: 最新 LTS イメージへの更新 (Compute Engine)

Bash 最新 LTS イメージの確認と VM 再作成 
# 最新の COS 133 LTS イメージを確認
gcloud compute images describe-from-family cos-133-lts \
  --project=cos-cloud

# 新イメージで VM を再作成 (例)
gcloud compute instances create my-instance \
  --image-family=cos-133-lts \
  --image-project=cos-cloud \
  --zone=us-central1-a

ステップ 3: GKE ノードプールの更新

Bash ノードプールの手動アップグレード 
# ノードプールを手動でアップグレード (ノードイメージの更新)
gcloud container clusters upgrade CLUSTER_NAME \
  --node-pool=POOL_NAME \
  --zone=ZONE
💡 ヒント: GKE ではノード自動アップグレードにより新しい COS イメージが順次ロールアウトされるため、通常は手動操作は不要である。

✨ メリット

💼 ビジネス面

✓脆弱性スキャン指摘の一括解消: openssl、glibc、curl、docker、containerd など広範なコンポーネントの CVE が修正され、コンプライアンス要件 (脆弱性管理) への対応が容易になる
✓サポート継続中の全 LTS マイルストーンに同時展開: COS 121 / 125 / 129 / 133 のいずれを利用していても、マイルストーンを維持したままセキュリティ修正を受け取れる

⚙️ 技術面

✓コンテナランタイム・エージェント群の一斉修正: docker、containerd、cri-tools、cni-plugins、kubernetes、guest-agent、osconfig-agent、node-problem-detector と、ノードを構成するコンポーネント全体が更新される
✓Lustre 2.16 クライアント対応 (cos-dev-138 / cos-121): 並列ファイルシステムを使う HPC / AI ワークロードで新しい Lustre ドライバを利用可能
✓64k ページカーネルの機能拡充 (cos-dev-138): iRDMA と PCI peer-to-peer DMA のサポートにより、Arm / 大規模メモリ構成での高性能 I/O に対応
✓fstrim.timer の定期実行 (cos-dev-138): シンプロビジョニングされたストレージの未使用ブロックが自動回収され、ストレージ効率が向上

⚠️ デメリット・制約事項

🚧 制限事項

✗cos-dev-138 は開発チャネルのイメージであり、本番環境での使用は想定されていない。新機能 (64k iRDMA、PCI P2P DMA、RTC サポートなど) が LTS に到達する時期は未定
✗各 CVE の深刻度 (CVSS スコア) はリリースノートに記載されていないため、自組織への影響評価には NVD などでの個別確認が必要
✗COS 121 LTS のサポートは 2027 年 3 月に終了するため、中期的には COS 125 以降への移行計画が必要

🤔 考慮すべき点

⚠️ 注意:
  • GKE のノード自動アップグレードを無効化している場合、本リリースの CVE 修正は適用されない。手動でのノードプール更新が必要
  • Docker / Containerd のバージョンはマイルストーンごとに異なる (COS 121: Docker 27.5.1 / Containerd 2.0.10、COS 133: Docker 29.4.3 / Containerd 2.4.1)。ランタイムバージョンに依存するワークロードは移行時に検証が必要
  • 大量のパッケージ更新を含むメンテナンスリリースのため、重要ワークロードではカナリアノードプールなどでの段階的ロールアウトを推奨

🎯 ユースケース

1️⃣ セキュリティコンプライアンス対応 (GKE ノードの CVE 解消)

シナリオ: セキュリティチームの脆弱性スキャンで、GKE ノードの openssl (CVE-2025-9230)、glibc (CVE-2026-4438)、containerd (CVE-2026-84304) などが検出され、期限内の修正が求められている。

Bash ノード自動アップグレードの有効化 (未設定の場合) 
gcloud container node-pools update POOL_NAME \
  --cluster=CLUSTER_NAME \
  --zone=ZONE \
  --enable-autoupgrade

効果: 本リリースを含む最新 COS イメージがロールアウトされ、スキャンで検出された CVE が解消される。

2️⃣ Managed Lustre を使う HPC / AI ワークロード

シナリオ: COS 121 ベースのノードから Lustre ファイルシステムに接続する HPC クラスタで、Lustre 2.16 系クライアントが必要になった。

効果: cos-121-18867-652-49 で追加された lustre-client-drivers-2_16 パッケージにより、COS 121 LTS を維持したまま Lustre 2.16 クライアントドライバを利用できる。

💡 まとめ

今回のアップデートは、COS のサポート中の全 LTS マイルストーン (121 / 125 / 129 / 133) と開発チャネルにまたがる大規模なセキュリティ・メンテナンスリリースである。

  • openssl、glibc、curl といった基盤ライブラリから docker、containerd、kubernetes などのコンテナスタック、ゲストエージェント群まで広範な CVE を修正
  • GKE ではノード自動アップグレードの有効化を確認し、Compute Engine で COS を直接使用している場合は早期のイメージ更新を推奨
  • cos-dev-138 に入った 64k ページ iRDMA や PCI P2P DMA、Lustre 2.16 対応は、今後の LTS で HPC / AI ワークロード向け機能として展開が見込まれる変更として注目
