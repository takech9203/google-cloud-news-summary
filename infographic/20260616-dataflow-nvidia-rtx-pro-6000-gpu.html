⚡ Dataflow: NVIDIA RTX Pro 6000 GPU サポート

Dataflow GA GPU/ML
2026-06-16

📋 概要

Dataflow が NVIDIA RTX Pro 6000 GPU をサポート開始。NVIDIA Blackwell アーキテクチャを採用したプロフェッショナル向け GPU で、96 GB GDDR7 GPU メモリを搭載しています。Apache Beam パイプラインのアクセラレータタイプとして nvidia-rtx-pro-6000 を指定するだけで利用可能です。

🎯 ターゲット: Dataflow を使用して ML 推論パイプラインを構築しているデータエンジニア / ML エンジニア。特に L4 (24 GB) ではメモリ不足だが A100/H100 ほどの計算能力は不要なケースに最適。

🔄 Before / After

❌ Before (課題)

  • L4 (24 GB) では GPU メモリ不足で大規模モデル推論が困難
  • A100/H100 (40-80 GB) はコストが高すぎる
  • コストとパフォーマンスのバランスが取れた GPU 選択肢が限定的
  • 最新 Blackwell アーキテクチャを Dataflow で活用不可

✅ After (改善)

  • 96 GB GDDR7 メモリで L4 と A100 のギャップを埋める
  • 第5世代 Tensor コア (FP4) で推論速度向上
  • PCIe Gen 5 でデータ転送速度改善
  • 24,064 CUDA + 752 Tensor + 188 RT コアの豊富なリソース

📝 設定方法

💡 前提条件:
  • Dataflow Runner v2 を使用すること
  • GPU クォータが対象リージョンで確保されていること
  • カスタムコンテナイメージに必要な CUDA ライブラリがインストールされていること
  • ブートディスクサイズを 50 GB 以上に設定すること

Step 1: GPU クォータの確認

Bash 
# プロジェクトの GPU クォータを確認
gcloud compute regions describe us-central1 \
  --project=PROJECT_ID \
  --format="table(quotas.filter(metric='NVIDIA_RTX_PRO_6000_GPUS'))"

Step 2: カスタムコンテナイメージの準備

Dockerfile 
FROM apache/beam_python3.11_sdk:2.x.x

# CUDA ツールキットのインストール
RUN apt-get update && apt-get install -y --no-install-recommends \
    cuda-toolkit-12-2 \
    && rm -rf /var/lib/apt/lists/*

# ML フレームワークのインストール
RUN pip install torch torchvision transformers

# パイプラインコードのコピー
COPY pipeline/ /app/pipeline/
Bash 
# コンテナイメージのビルドとプッシュ
gcloud builds submit --tag REGION-docker.pkg.dev/PROJECT_ID/REPO/gpu-pipeline:latest

Step 3: Dataflow ジョブの実行

Bash 
python pipeline.py \
  --runner "DataflowRunner" \
  --project "PROJECT_ID" \
  --temp_location "gs://BUCKET/tmp" \
  --region "us-central1" \
  --worker_harness_container_image "REGION-docker.pkg.dev/PROJECT_ID/REPO/gpu-pipeline:latest" \
  --disk_size_gb 50 \
  --dataflow_service_options "worker_accelerator=type:nvidia-rtx-pro-6000;count:1;install-nvidia-driver" \
  --experiments "use_runner_v2"

Step 4: Dataflow Prime でのリソースヒント使用 (代替方法)

Python 
import apache_beam as beam

with beam.Pipeline() as p:
    (p
     | "Read" >> beam.io.ReadFromBigQuery(...)
     | "Inference" >> beam.ParDo(
         RunInference(model_handler)
       ).with_resource_hints(
         accelerator='type:nvidia-rtx-pro-6000;count:1;install-nvidia-driver'
       )
     | "Write" >> beam.io.WriteToBigQuery(...)
    )

Dataflow Prime を使用する場合は、パイプライン全体ではなく特定のステップにのみ GPU を割り当てることができます。

✅ メリット

ビジネス面

✓コスト最適化: A100/H100 比で低コスト。GPU メモリ容量あたりのコストパフォーマンスが向上
✓スケーラビリティ: Dataflow のオートスケーリングと組み合わせ、需要に応じた GPU リソース自動調整
✓Time-to-Market 短縮: 管理型サービスにより GPU インフラの構築・運用の手間を削減

技術面

✓大容量 GPU メモリ: 96 GB GDDR7 により大規模モデルのロードと推論が可能
✓最新アーキテクチャ: 第5世代 Tensor コアで推論スループット大幅向上
✓GPU P2P 通信: マルチ GPU 構成 (g4-standard-96+) で直接 GPU 間通信をサポート
✓柔軟なプロビジョニング: 標準および Flex-start プロビジョニングモデルに対応

⚠️ デメリット・制約事項

制限事項:
✗Dataflow Runner v2 が必須 (Runner v1 では GPU を使用できない)
✗GPU ドライバはカスタムコンテナではなく install-nvidia-driver オプションで自動インストール
✗Flex-start プロビジョニングはバッチパイプラインのみ対応 (ストリーミング非対応)
✗リージョンおよびゾーンの GPU 可用性に依存

考慮すべき点

→GPU コンテナイメージが大きいため、ブートディスクサイズを 50 GB 以上に設定
→GPU クォータは事前確保が必要 (新規プロジェクトはクォータ申請)
→GPU 利用時間に基づく課金 -- パイプライン実行時間とコストのバランスを考慮
→Apache Beam SDK バージョンとコンテナ内 Python バージョンの一致が必要

💡 ユースケース

🤖 ユースケース 1: 大規模言語モデル (LLM) によるバッチ推論

大量のカスタマーレビューデータに対して、70B パラメータクラスの LLM を使用して感情分析・要約・カテゴリ分類を一括実行。

Python 
import apache_beam as beam
from apache_beam.ml.inference.base import RunInference

class LLMModelHandler:
    def __init__(self):
        self.model_path = "gs://bucket/models/llm-70b"

    def load_model(self):
        # 96 GB GPU メモリに 70B モデルをロード
        from transformers import AutoModelForCausalLM
        return AutoModelForCausalLM.from_pretrained(
            self.model_path,
            device_map="auto",
            torch_dtype=torch.float16
        )

with beam.Pipeline(options=pipeline_options) as p:
    (p
     | "ReadReviews" >> beam.io.ReadFromBigQuery(
         query="SELECT review_text FROM reviews WHERE date = CURRENT_DATE()")
     | "RunLLMInference" >> RunInference(LLMModelHandler())
     | "WriteResults" >> beam.io.WriteToBigQuery("project:dataset.results")
    )
効果: 96 GB GPU メモリにより 70B パラメータモデルを完全にロードでき、CPU 推論と比較して 10-50 倍の処理速度向上が期待できる。

📷 ユースケース 2: リアルタイム画像・動画分析パイプライン

Pub/Sub 経由で流入する画像データに対して、物体検出・セグメンテーション・OCR などの複合的な Vision AI 処理をストリーミングで実行。

効果: 大容量 GPU メモリにより複数の Vision モデルを同時にロードし、マルチモデル推論パイプラインを単一 GPU 上で効率的に実行。レイテンシー低減とスループット向上を実現。

🔍 ユースケース 3: RAG (Retrieval-Augmented Generation) パイプライン

企業内ドキュメントに対して埋め込みベクトルを生成し、ベクトル検索と組み合わせた RAG パイプラインをバッチで実行。

効果: 大規模 Embedding モデルと生成モデルの両方を GPU メモリに保持しながら処理でき、ドキュメント処理スループットが大幅に向上。

💰 料金情報

GPU を使用する Dataflow ジョブの料金は、使用するリージョン、GPU 使用時間、および追加のコンピューティングリソースに基づいて計算されます。

料金構成要素

構成要素説明
GPU 時間RTX Pro 6000 GPU の使用時間に基づく課金
vCPU 時間ワーカー VM の vCPU 使用時間
メモリ時間ワーカー VM のメモリ使用量と時間
ディスクブートディスクおよび追加ディスクの使用量
ネットワークデータ転送量に基づく課金

コスト最適化のヒント

方法説明
Flex-start プロビジョニングバッチジョブで利用可能。プリエンプティブル料金の適用でコスト削減
Dataflow Prime リソースヒントGPU が必要なステップのみに GPU を割り当て、不要なステップでは CPU のみ使用
確約利用割引 (CUD)継続的な利用が見込まれる場合、1年/3年の確約で 20-40% 割引

🌍 利用可能リージョン

RTX Pro 6000 GPU の利用可能リージョンは Compute Engine の GPU リージョン・ゾーン可用性に準じます。参考として Cloud Run での対応リージョン:

🇺🇸 us-central1 (アイオワ)
🇳🇱 europe-west4 (オランダ)
🇸🇬 asia-southeast1 (シンガポール)
🇮🇳 asia-south2 (デリー)

Dataflow での正確なリージョン可用性は GPU regions and zones availability ドキュメントを参照してください。

📌 まとめ

Dataflow における NVIDIA RTX Pro 6000 GPU のサポートは、ML 推論パイプラインの選択肢を大幅に拡大する重要なアップデートです。

  • 96 GB GPU メモリ + Blackwell アーキテクチャで、L4 では対応できなかった大規模モデル推論をコスト効率よく実行
  • アクセラレータタイプを nvidia-rtx-pro-6000 に変更するだけで利用開始可能
  • Dataflow Prime のリソースヒントで特定ステップのみに GPU を割り当てることでさらにコスト最適化
