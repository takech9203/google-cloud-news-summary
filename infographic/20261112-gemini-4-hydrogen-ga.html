📝 概要

Gemini Enterprise Agent Platform で Gemini 4 Hydrogen (gemini-4-hydrogen) が 一般提供 (GA) になりました。日常的なコーディング、エージェントワークフロー、マルチモーダル分析、ツール利用における 速度と効率を重視して設計されたモデルで、短期リリース (廃止決定時は最低 45 日前に通知) として提供されます。

Gemini 4 Carbon / Argon と同様に、入力と出力を合わせた 1,048,576 トークンの統合ウィンドウと、 continuation_token による最大 1M トークンのロングデコードをサポート。思考レベルは LOW / MEDIUM / HIGH / XHIGH の 4 段階に拡張されました。 高速・低コストなワークホースとして Gemini 3.8 Flash を使うチームの移行先候補となります。

❌ Before (アップデート前の課題)

  • 速度・効率重視モデル (Gemini 3.8 Flash など) は出力が最大 65,536 トークンで頭打ち。統合 1M ウィンドウとロングデコードはフロンティアモデル (Argon / Carbon) 限定
  • 思考レベルは LOW / MEDIUM / HIGH の 3 段階のみで、より深い推論向けの上位レベルがなかった
  • 暗黙的キャッシュでは「何を・どれだけの期間キャッシュするか」をユーザーが制御できなかった
  • Office / OpenDocument ファイルを FunctionResponse パートで返すエージェントパターンが明示的に非サポート

✅ After (アップデート後の改善)

  • gemini-4-hydrogen が GA。速度重視ワークロードでも入出力合計 1,048,576 トークンの統合ウィンドウ + ロングデコード (最大 1M トークン出力)
  • 単一フォアグラウンドセグメントでストリーミング / 非ストリーミング共通 65,536 出力トークン (Carbon は非ストリーミング時 32,768)
  • XHIGH が追加され 4 段階の思考レベルに (デフォルト: HIGH)
  • 2027-01-12 以降、TTL 設定によるキャッシュ書き込み制御をサポート予定
  • Office / OpenDocument ファイルをインライン / gs:// / マルチモーダル FunctionResponse パートで入力可能
  • 関数呼び出し、コード実行、computer use、グラウンディング各種などエージェント向けツール群をフルサポート

アプリケーションは GenerateContent / Interactions / OpenAI 互換 API のいずれかで Gemini 4 Hydrogen を呼び出し、 暗黙的キャッシュ、エージェント向けツール群、ロングデコード (サーバー管理のバックグラウンド実行を含む) を活用して高速なエージェントワークフローを実行します。

⚙️ 主要機能

1️⃣ 統合 1M トークンウィンドウとロングデコード

  • 入力・思考・関数呼び出し・最終レスポンスが 1 つの 1,048,576 トークンウィンドウを共有
  • 単一フォアグラウンドセグメントはストリーミング / 非ストリーミングともに最大 65,536 出力トークン
  • Interactions API と GenerateContent API (v1beta1) の両方で continuation_token により最大 1,048,576 トークン (入力分を除く) まで出力を拡張
  • Interactions API では background=true による非同期のサーバー管理バックグラウンド実行に対応

2️⃣ 4 段階の思考レベル (LOW / MEDIUM / HIGH / XHIGH)

  • デフォルトは HIGH。深い推論ワークロード向けに XHIGH が利用可能
  • thinking_budget の指定や thinking_level="MINIMAL" は HTTP 400 のバリデーションエラー

3️⃣ 暗黙的コンテキストキャッシュ (durable caching 対応)

  • 4,096 トークン以上の共有プロンプトプレフィックスに durable caching 有効の自動キャッシュがデフォルト適用
  • 明示的コンテキストキャッシュは非サポート

4️⃣ キャッシュ書き込み制御と料金 (2027-01-12 開始)

  • Gemini 4 Hydrogen 以降のモデルで TTL 設定によるキャッシュ制御をサポート予定
  • 何をキャッシュするか・どれだけの期間有効にするかを TTL 設定で選択可能
  • キャッシュ書き込みはデフォルトで標準入力トークン価格の 1.25 倍で課金 (保持期間が長いほどコスト増)

5️⃣ Microsoft Office / OpenDocument ファイル入力

  • Office (.docx, .dotx, .doc, .pptx, .ppt, .xlsx, .xls) と OpenDocument (.odt, .odp, .ods) をインラインまたは Cloud Storage (gs://) から入力可能
  • マルチモーダル FunctionResponse パート内でのファイル入力にも対応し、ツール実行結果としてドキュメントを返すエージェントパターンを構築できる

6️⃣ 豊富な機能・消費オプション・エンドポイント

  • API: GenerateContent API、Interactions API、OpenAI 互換 Chat Completions API
  • ツール: 関数呼び出し、コード実行、computer use、URL コンテキスト、Grounding with Google Search、Google マップ、Enterprise Web Grounding、Parallel / Exa Web Search、Agentic video understanding
  • 消費オプション: Standard PayGo (Usage Tiers 付き)、Priority PayGo、Flex PayGo、バッチ推論、Provisioned Throughput (1 GSU あたり 685 トークン/秒)
  • エンドポイント: global および us / eu マルチリージョン

🔧 設定方法

✅ 前提条件

✓Google Cloud プロジェクトで Gemini Enterprise Agent Platform の API が有効化されていること
✓呼び出し元に適切な IAM 権限 (例: Vertex AI ユーザーロール) が付与されていること
✓短期リリースのライフサイクルポリシー (最低 45 日前の廃止予告) を理解し、モデル更新に追従できる運用体制があること

ステップ 1: モデル ID を指定してリクエストを送信

Bash curl での呼び出し例 
curl -X POST \
  -H "Authorization: Bearer $(gcloud auth print-access-token)" \
  -H "Content-Type: application/json" \
  "https://aiplatform.googleapis.com/v1/projects/PROJECT_ID/locations/global/publishers/google/models/gemini-4-hydrogen:generateContent" \
  -d '{
    "contents": [{
      "role": "user",
      "parts": [{"text": "このログから障害の原因を分析してください。"}]
    }],
    "generationConfig": {
      "thinkingConfig": {"thinkingLevel": "HIGH"}
    }
  }'

ステップ 2: Gemini 3.8 Flash からの移行調整

💡 移行チェックリスト (詳細は 開発者ガイド を参照)
✓モデル ID を gemini-4-hydrogen に変更する
✓thinking_budget を使用している場合は thinking_level (LOW / MEDIUM / HIGH / XHIGH) に置き換える (thinking_budget と MINIMAL は HTTP 400 エラー)
✓明示的コンテキストキャッシュを使用している場合は、暗黙的キャッシュ (デフォルト有効) に移行する
✓デフォルトの思考レベルが MEDIUM (3.8 Flash) から HIGH (Hydrogen) に変わるため、レイテンシとトークン消費を再評価する

ステップ 3: 64K トークンを超える出力にはロングデコードを使用

Python Interactions API によるバックグラウンド実行 
interaction = client.interactions.create(
    model="gemini-4-hydrogen",
    input="大規模なモジュールのリファクタリング案をコード全体とともに出力してください。",
    background=True,  # サーバー管理のバックグラウンド実行
    generation_config={
        "max_output_tokens": 262144,
        "thinking_level": "XHIGH",
    },
)

Interactions API の background=true を使うと、サーバー側で継続ループが実行され、65,536 トークンを超える出力を取得できます。 クライアント側で制御したい場合は continuation_token を使った継続ループも利用できます (GenerateContent API は v1beta1)。

💪 メリット

💼 ビジネス面

✓高頻度ワークロードのコスト効率: 速度と効率に最適化されたモデルを GA 品質で利用でき、日常的なコーディング支援やエージェント処理など呼び出し回数の多いワークロードに適する
✓柔軟な消費オプション: Standard / Priority / Flex PayGo、バッチ推論、Provisioned Throughput から、ワークロードの優先度とコスト要件に応じて選択できる
✓キャッシュコストの最適化 (将来): 2027-01-12 以降の TTL 設定付きキャッシュ制御により、キャッシュ戦略を自らコントロールできるようになる

🛠️ 技術面

✓速度重視でも 1M 統合ウィンドウ: フロンティアモデル (Argon / Carbon) と同じ統合 1M トークンウィンドウとロングデコードを効率重視モデルで利用できる
✓ストリーミング / 非ストリーミング共通の 64K 出力: 非ストリーミングでも 65,536 トークンまで単一セグメントで生成でき、クライアント実装の分岐を減らせる
✓4 段階の思考レベル: LOW から XHIGH まで、品質・レイテンシ・トークン消費のトレードオフをワークロード単位で細かく調整できる
✓エージェントツールのフルサポート: computer use、コード実行、各種グラウンディング、Agentic video understanding まで単一モデルでカバーできる

⚠️ デメリット・制約事項

🚧 制限事項

✗短期リリースのため、長期提供モデル (12 か月以上の提供保証) と異なり、後継モデル登場後に最低 45 日の予告期間で廃止される可能性がある
✗明示的コンテキストキャッシュは非サポート (暗黙的キャッシュのみ)
✗thinking_budget の指定や thinking_level="MINIMAL" は HTTP 400 バリデーションエラーになる
✗continuation_token によるロングデコードは GenerateContent API では v1beta1 での提供

🤔 考慮すべき点

⚠️ 運用上の注意
  • 短期リリースモデルを本番採用する場合は、廃止通知を監視し 45 日以内に移行できる体制 (評価パイプライン、モデル ID の設定外出しなど) を整えておく必要がある
  • デフォルトの思考レベルが HIGH のため、レイテンシ・コストが重要なワークロードでは LOW / MEDIUM への引き下げを評価すべき (思考トークンも出力トークンとして課金)
  • 2027-01-12 以降のキャッシュ書き込みはデフォルトで標準入力トークン価格の 1.25 倍で課金され、保持期間を延ばすほどコストが増えるため、TTL 設計がコストに直結する

🎯 ユースケース

1️⃣ 日常的なコーディングエージェント

シナリオ: CI パイプラインや IDE 連携のコーディングエージェントが、テスト失敗の調査、小〜中規模のリファクタリング、コードレビュー補助を高頻度で実行する。

Python 実装例 
response = client.models.generate_content(
    model="gemini-4-hydrogen",
    contents=[repo_context, "このテスト失敗の原因を特定し、修正を提案してください。"],
    config=GenerateContentConfig(
        thinking_config=ThinkingConfig(thinking_level="MEDIUM"),
    ),
)

効果: 速度・効率に最適化されたモデルにより、高頻度呼び出しでもレイテンシとコストを抑えつつ、1M 統合ウィンドウで大きなリポジトリコンテキストを扱える。

2️⃣ ツール利用を伴うマルチモーダル業務エージェント

シナリオ: 社内業務エージェントが、Cloud Storage 上の Office / OpenDocument ファイル (契約書、集計シート、提案資料) をツール実行結果 (FunctionResponse) として受け取り、Google 検索グラウンディングや URL コンテキストと組み合わせて分析・要約する。

効果: ファイル変換の前処理なしにドキュメントをエージェントループへ直接組み込め、グラウンディングにより根拠の明示された分析結果を高速に得られる。

3️⃣ 深い推論が必要なバッチ分析 (XHIGH + ロングデコード)

シナリオ: 夜間バッチで thinking_level="XHIGH" と background=true を使い、長大な分析レポートや大規模なコード生成を 64K トークン超の出力として生成する。

効果: サーバー管理のバックグラウンド実行により、クライアント側の継続処理なしで最大 1M トークン規模の出力を取得でき、深い推論と長い出力を要するジョブを自動化できる。

🔗 関連サービス・機能

⚡ Gemini 3.8 Flash (gemini-3.8-flash)

これまでの速度・効率重視ワークホースモデル。公式ドキュメントに Hydrogen への移行ガイダンスが用意されている。

🧠 Gemini 4 Argon / Carbon

同じ Gemini 4 世代のフロンティア推論モデル。深い推論・最難関タスクには Carbon、効率的なフロンティア推論には Argon、速度・効率最優先のタスクには Hydrogen という使い分けが可能。

🔄 Interactions API

background=true による非同期バックグラウンド実行と previous_interaction_id によるサーバー側の会話状態管理を提供。

📈 Provisioned Throughput

スループットを予約してオンデマンドより優先処理する消費オプション。Hydrogen は 1 GSU あたり 685 トークン/秒。

⚡ コンテキストキャッシュ

暗黙的キャッシュ (durable caching) による自動コスト削減に加え、2027 年 1 月 12 日から TTL 設定によるキャッシュ書き込み制御が利用可能になる予定。

📌 まとめ

速度と効率に最適化された Gemini 4 Hydrogen が GA となり、1M 統合トークンウィンドウ、 ロングデコード、4 段階の思考レベル (XHIGH 含む)、豊富なツールサポートを備えた ワークホースモデルが Gemini 4 世代に加わりました。Gemini 3.8 Flash で高頻度ワークロードを運用しているチームは、 開発者ガイドの移行手順に沿って評価を開始することを推奨します。

⚠️ 注意: 短期リリース (最低 45 日前の廃止予告) であるため、モデル更新に追従できる運用体制とのセットでの採用が前提となります。
