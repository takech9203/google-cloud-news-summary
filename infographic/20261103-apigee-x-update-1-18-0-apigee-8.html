📝 概要

2026 年 11 月 3 日、Google Cloud は Apigee のランタイム更新バージョン 1-18-0-apigee-8 をリリース。セキュリティ修正に加えて、OAuthV2 トークン有効期限の組織単位オーバーライド、MCP プロキシ認識の改善、LLMTokenQuota とセマンティックキャッシュの整合性修正、Apigee Connect の接続性改善を含む実用的なメンテナンスリリースである。

AI/LLM プロキシ関連の修正が多く、Apigee を AI ゲートウェイとして利用する組織や、HTTP フォワードプロキシ経由で制御プレーンに接続するネットワーク構成の組織にとって重要なアップデート。

❌ Before (アップデート前の課題)
  • OAuthV2 で <ExpiresIn> 省略時はインストールデフォルト (通常 30 日) が適用され、組織単位で変更できない
  • <ProxyOperationMode>MCP 宣言でも basepath によっては MCP プロキシとして認識されない
  • セマンティックキャッシュのヒットでも LLMTokenQuota がトークンを消費
  • Apigee Connect のサイレント切断の検出に約 2 時間、proxy-only クラスタで接続が長時間失われる

  • HTTP/2 キープアライブ ping で約 80 秒で検出、HTTPS_PROXY (認証情報付き) も尊重

🛡️ セキュリティ修正 (Bug ID: N/A)

Apigee インフラストラクチャに対するセキュリティ修正が適用された。個別の CVE 番号は公表されていない。あわせてインフラストラクチャおよびライブラリの更新も含まれる。

🔑 OAuthV2 デフォルトアクセストークン有効期限のオーバーライド (574037227)
  • 構成オーバーライドトークン oauth_default_access_token_expiry_time_in_millis が追加
  • デプロイメント契約 (deployment contract) 経由で組織 (per-org) 単位に設定
  • OAuthV2 ポリシーが <ExpiresIn> を省略した場合のデフォルト有効期限 (ミリ秒) をオーバーライド
  • 未設定の場合は従来通りの動作 (インストールデフォルト、通常 30 日) で変更なし
🤖 MCP プロキシ認識の改善 (573326336)
  • <ProxyOperationMode>MCP を宣言したプロキシが、basepath に関係なく MCP プロキシとして認識されるように
  • 以前は basepath によって MCP プロキシとして扱われないケースがあった
📊 LLMTokenQuota とセマンティックキャッシュの整合性 (576697209)
  • SemanticCacheLookup がキャッシュから応答を返した場合、LLMTokenQuota はトークンをカウントしない
  • キャッシュヒット応答には ai_llm_response_token_count も記録されない
  • 実際に LLM を呼び出していないリクエストがクォータを消費する問題が解消
🔌 Apigee Connect エージェントの接続性改善 (578314600)
  • 制御プレーン接続に HTTP/2 キープアライブ ping を使用
  • サイレントに切断された接続を約 80 秒で検出 (従来は約 2 時間)
  • HTTPS_PROXY 環境変数 (プロキシ認証情報を含む) を尊重し、proxy-only クラスタでも接続を確実に再確立

OAuthV2 の <ExpiresIn> とデフォルト有効期限の関係

OAuthV2 ポリシーの <ExpiresIn> 要素はアクセストークンの有効期限をミリ秒単位で指定する。省略した場合は「システムレベルで構成されたデフォルト値」が適用される。本リリースで、このシステムデフォルトを組織単位でオーバーライドする手段が提供された。

XML OAuthV2 ポリシーと ExpiresIn の関係 
<!-- ExpiresIn を明示的に指定する場合 (従来通り推奨) -->
<OAuthV2 name="GenerateAccessToken">
  <Operation>GenerateAccessToken</Operation>
  <ExpiresIn>3600000</ExpiresIn> <!-- 1 時間 (ミリ秒) -->
  <SupportedGrantTypes>
    <GrantType>client_credentials</GrantType>
  </SupportedGrantTypes>
</OAuthV2>

<!-- ExpiresIn を省略した場合:
     従来: インストールデフォルト (通常 30 日)
     今後: 組織に oauth_default_access_token_expiry_time_in_millis が
           設定されていればその値が適用される -->

⚙️ 技術面

✓運用の安定性向上: Apigee Connect の接続断検出が約 2 時間 → 約 80 秒に短縮され、制御プレーンとの接続性 (デプロイ、管理操作) のダウンタイムが大幅に減少
✓エンタープライズネットワークとの親和性: HTTPS_PROXY (認証付きプロキシを含む) を尊重し、フォワードプロキシ経由でのみ外部接続を許可する企業ネットワークでも Apigee Connect が確実に動作
✓MCP プロキシ設計の自由度向上: basepath の制約なしに <ProxyOperationMode>MCP 宣言だけで MCP 対応が可能。既存の URL 設計を崩さない

考慮すべき点

⚠️ 注意:
  • 既存の OAuthV2 ポリシーで <ExpiresIn> を明示指定している場合、本オーバーライドの影響は受けない (ポリシーの指定が優先)
  • 組織単位のデフォルト有効期限を変更すると、<ExpiresIn> を省略しているすべてのプロキシの新規発行トークンに影響するため、適用前に影響範囲の確認が必要
  • セマンティックキャッシュのヒット率が高い環境では、クォータ消費量・ai_llm_response_token_count のメトリクスが従来より減少する。レポートやアラートの基準値の見直しを推奨

🎯 ユースケース

1️⃣ 組織全体でのトークン有効期限ガバナンス

シナリオ: 多数の API プロキシを運用する組織で、一部のプロキシが <ExpiresIn> を指定し忘れており、30 日間有効なアクセストークンが発行されていた。セキュリティ監査で短縮を求められている。

効果: oauth_default_access_token_expiry_time_in_millis を組織単位で設定することで、個々のプロキシを修正せずにデフォルト有効期限を一括で短縮。<ExpiresIn> を明示しているプロキシの動作は変わらないため、段階的なガバナンス強化が可能。

2️⃣ セマンティックキャッシュ併用時の正確なトークンクォータ運用

シナリオ: Apigee を LLM ゲートウェイとして利用し、SemanticCacheLookup/SemanticCachePopulate でコスト削減しつつ、LLMTokenQuota でアプリごとのトークン消費量を制限。従来はキャッシュヒットでもクォータが消費され、キャッシュ導入のメリットがクォータに反映されなかった。

効果: キャッシュヒットした応答はクォータを消費しなくなり、実際の LLM 利用量に基づいた正確なクォータ制御が可能に。キャッシュヒット率の高いアプリはより多くのリクエストを処理できる。

3️⃣ フォワードプロキシ必須環境での Apigee Connect 安定運用

シナリオ: すべての外部通信を認証付き HTTP フォワードプロキシ経由に制限している企業で、Apigee Connect の制御プレーン接続がサイレントに切断されると最大 2 時間接続が失われ、プロキシのデプロイや管理操作が滞っていた。

効果: HTTP/2 キープアライブ ping により接続断を約 80 秒で検出し、HTTPS_PROXY (認証情報付き) を尊重して自動的に再接続。proxy-only クラスタでも制御プレーン接続が安定する。

🔗 関連サービス・機能

🔑 OAuthV2 ポリシー

アクセストークンの生成・検証を行う Apigee のコアポリシー。本リリースでデフォルト有効期限の組織単位オーバーライドが可能になった。

🤖 Apigee MCP (Model Context Protocol)

既存の Apigee API を MCP ツールとしてエージェント型アプリケーションに公開する機能。本リリースで MCP プロキシの認識が basepath 非依存になった。

🧠 SemanticCacheLookup / SemanticCachePopulate ポリシー

Vertex AI の Text Embeddings API と Vector Search を使い、意味的に類似したプロンプトへの応答をキャッシュから返すポリシー。

📊 LLMTokenQuota ポリシー

LLM 応答のトークン消費量をカウント・制限するポリシー。AI ワークロードのコスト管理に使用。

🔌 Apigee Connect

管理プレーン (制御プレーン) とランタイムプレーン間のセキュアな通信を担うコンポーネント。MART エンドポイントをインターネットに公開せずに接続できる。

🏢 Apigee hybrid

同日に v1.15.10 がリリースされ、同じ Apigee Connect の修正 (578314600) が含まれている。
