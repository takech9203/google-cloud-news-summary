📞 CCaaS バージョン 6.33 プレリリースノート
コンタクトセンター運用の信頼性を高める 14 件の不具合修正

リリース日: 2026-11-10
Contact Center as a Service (CCaaS) CCAI Platform プレリリース Fixed: 不具合修正

📝 概要

Google Cloud Contact Center as a Service (CCaaS) (旧称 Contact Center AI Platform / CCAI Platform) の次期バージョン 6.33 のプレリリースノートが公開されました。プレリリースノートは次バージョンで提供見込みの変更を事前告知するもので、適用タイミングは各インスタンスのデプロイメントスケジュールに依存します。

今回は新機能の追加ではなく、14 件の不具合修正 (Fixed) に特化したリリースです。インバウンドブロックリスト、Telnyx 経由コールのキュー滞留、コールバックの記録と FIFO 優先順位、エージェントデスクトップやポータルのパフォーマンスなど、運用の信頼性に直結する広範な領域をカバーします。

❌ Before: アップデート前の課題

  • ブロックリスト登録番号でも直通番号宛てはブロックされない
  • ハングアップ通知喪失で Telnyx コールがキューに無期限滞留
  • 放棄コールバックが「システム障害」として誤記録、キューグループ間移動で FIFO 優先順位が失われる
  • コールアダプタがハングアップ直後に誤再ダイヤル → 参加者ステータス失敗・ディスポジションパネル早期クローズ
  • 自動応答コールが同一エージェントへ無限再オファーループ、オーバーキャパシティデフレクション不発
  • スケジュール済みコールバックが最大猶予期限を超過して架電
  • ラップアップ終了時にチャットが残ると「次のステータス」が早期クリアされ Agent Monitoring に非表示
  • Manager API calls への期間無制限クエリがタイムアウト
  • 休日設定読み込み・通話終了時の非効率な DB 参照で大幅遅延

✅ After: 6.33 での改善見込み

  • 直通番号宛てもブロックリストが適用され、全着信経路で迷惑電話対策が機能
  • 通知喪失時も Telnyx コールが滞留せず、キュー統計と待ち時間の正確性を維持
  • 放棄コールバックを「エンドユーザー切断」として正しく記録、FIFO 優先順位も維持され公平な待ち行列処理を実現
  • 無限再オファーループが解消し、オーバーキャパシティデフレクションが設計どおり動作
  • スケジュール済みコールバックが期限内に実行され、顧客への約束時刻を遵守
  • 休日設定読み込み・通話終了・通話履歴取得のパフォーマンス改善でシステム安定性が向上
💡 ポイント: コンタクトセンターの管理者・スーパーバイザー・運用チームにとって、呼損やレポーティングの不正確さ、エージェント体験の低下につながっていた既知の問題が解消される、運用品質と KPI 計測の正確性の両面で重要なアップデートです。

🔧 主要な修正内容 (5 つの領域)

1️⃣ 📵 着信制御・テレフォニーの修正 (3 件)

  • インバウンドブロックリストの番号が直通番号 (ダイレクトライン) への着信でブロックされない問題を修正
  • 高負荷時にハングアップ通知が失われた場合に Telnyx コールがキューに無期限に滞留する問題を修正
  • コールアダプタがハングアップ直後に誤って再ダイヤルし、参加者ステータスの失敗と必須ディスポジションパネルの早期クローズを引き起こす問題を修正

2️⃣ 🔁 コールバック・キューイングの修正 (3 件)

  • キュー待機中に放棄されたコールバックコールが「システム障害」として誤記録される問題と、キューグループ間移動時に FIFO 優先順位が維持されない問題を修正
  • 自動応答コールが接続タイムアウト時に同一エージェントへ無限に再オファーされ、オーバーキャパシティデフレクションが発動しない問題を修正
  • スケジュール済みコールバックの再ダイヤルが最大猶予期限 (maximum deferral deadline) を超過して実行される問題を修正

3️⃣ 🧑‍💼 エージェント体験・ポータルの修正 (3 件)

  • 音声コールのラップアップ終了時にアクティブなチャットが残っていると、エージェントの「次のステータス」が早期クリアされ Agent Monitoring に表示されない問題を修正
  • ポータル言語がカナダフランス語 (fr_CA) の場合に Agents ページのログアウト確認ダイアログが英語で表示される問題を修正
  • Agents ビューのチームフィルタが古いデータレコードにより無関係なチームのエージェントを表示する問題を修正

4️⃣ 🤖 仮想エージェント・CRM 連携の修正 (2 件)

  • 転送ターンが会話終了を兼ねる場合に、仮想エージェント間のチャット転送が失敗する問題を修正
  • 仮想エージェントチャット中に {ACCOUNT_ID} プレースホルダが空文字列に解決され、CRM API リクエストが失敗する問題を修正

5️⃣ ⚡ API・パフォーマンスの修正 (3 件)

  • Manager API の calls エンドポイントに対する期間無制限の大規模クエリがタイムアウトする問題を修正 (このエンドポイントへのリクエストには期間指定が必須になる)
  • 休日設定の読み込みやエージェントデスクトップでの通話終了時の、非効率なデータベース参照による大幅な遅延を修正
  • エージェント通話履歴の取得による深刻なパフォーマンス遅延とシステム不安定性を修正

✅ メリット

💼 ビジネス面

  • 迷惑電話対策の一貫性: ブロックリストが直通番号を含むすべての着信経路で機能し、スパム・ハラスメント電話からエージェントを保護
  • 顧客との約束の遵守: スケジュール済みコールバックが期限内に実行され、「指定時刻に折り返す」約束が守られ CX が向上
  • KPI・レポーティングの正確性: 放棄コールバックが正しく「エンドユーザー切断」として記録され、放棄率やシステム障害率を正確に計測可能

⚙️ 技術面

  • キューの健全性向上: Telnyx コール滞留の解消により、キュー統計・推定待ち時間 (EWT) の信頼性が向上
  • オーバーキャパシティ制御の正常化: 無限再オファーループの解消で、過負荷時のデフレクション (コールバック提案や振り分け) が設計どおり発動
  • システム全体のパフォーマンス改善: 休日設定・通話終了・通話履歴取得の非効率な DB 参照が解消され、高負荷時の安定性が向上

⚠️ デメリット・制約事項

制限事項

▪プレリリースノートであり、正式リリース時に内容が変わる可能性がある (リリースノートにも「リリース時にはここに示すとおりになる見込み」と明記)
▪各インスタンスへの適用タイミングはデプロイメントスケジュールに依存するため、即時にはすべての環境で修正が有効にならない

考慮すべき点

🚨 破壊的変更の可能性: Manager API の calls エンドポイントは、タイムアウト対策として期間 (date range) の指定が必須になります。期間無制限のクエリを発行している既存のインテグレーションやスクリプトは、6.33 適用後に失敗する可能性があるため、事前に期間指定を追加しておくことを推奨します。
📈 KPI トレンドへの影響: 放棄コールバックの記録方法が変わる (システム障害 → エンドユーザー切断) ため、6.33 適用前後でレポート指標の傾向が変化する可能性があります。KPI のトレンド分析時には適用日を考慮してください。

🎯 ユースケース

📊 ユースケース 1: Manager API を利用したレポーティング基盤の事前対応

シナリオ: BI ツールやデータウェアハウスへ通話データを取り込むため、Manager API の calls エンドポイントを定期実行しているが、全期間を対象としたクエリを発行している。

HTTP calls エンドポイントへの期間指定の追加 
# 変更前 (6.33 適用後は失敗する可能性)
GET /manager/api/v1/calls

# 変更後 (期間を必ず指定する)
GET /manager/api/v1/calls?start_date=2026-11-01&end_date=2026-11-07

効果: 6.33 適用後もデータ取り込みが中断せず、クエリのタイムアウトも回避できる。

📵 ユースケース 2: 直通番号を運用するコンタクトセンターの迷惑電話対策

シナリオ: VIP 顧客向けにエージェント直通番号を提供しているが、ブロックリスト登録済みの番号から直通番号経由で着信してしまい、エージェントが対応を強いられていた。

効果: 6.33 適用後は直通番号への着信にもブロックリストが適用されるため、追加設定なしで全経路の迷惑電話対策が機能する。ブロックリストは CCAI Platform ポータルの Settings > Consumer Management > Phone Number Blocklist で管理する。

📈 ユースケース 3: コールバック放棄率の正確な計測

シナリオ: スーパーバイザーがコールバックの放棄率とシステム障害率をダッシュボードで監視しているが、放棄コールバックがシステム障害として計上され、障害率が実態より高く見えていた。

効果: 放棄コールバックが「エンドユーザー切断」として正しく分類され、システム障害の真の発生率を把握できる。FIFO 優先順位の維持により、キューグループ間を移動するコールバックの待ち時間の公平性も確保される。
