Managed Service for Apache Airflow ⚠️ Breaking Change (破壊的変更)

🐍 pip 23.2.1 → 26.2.2 アップグレード

カスタム PyPI パッケージのインストール動作が変わる破壊的変更
📅 リリース日: 2026-11-13

📌 概要

Managed Service for Apache Airflow (旧 Cloud Composer) の環境イメージに含まれる pip が 23.2.1 から 26.2.2 にアップグレードされました。 対象は Airflow 3.3.1 / 3.2.2 / 2.11.1 で、セキュリティ修正が含まれる一方、 カスタム PyPI パッケージのインストール動作が変わる破壊的変更です。

🕐 Before: pip 23.2.1 の課題

  • ❌ PEP 440 に厳密には準拠しない gcsfs>=0.8.* のような不正な指定子 (.* と >= の組み合わせ) が許容され、そのままインストールが通っていた
  • ❌ ソースパッケージ (.tar.gz) のビルドで分離環境が常時強制されず、環境内の既存ビルド依存関係に頼って動作するケースがあった
  • ❌ 旧バージョンの pip にはその後修正されたセキュリティ脆弱性が残っていた

🆕 After: pip 26.2.2 での改善

  • ✅ pip 26.2.2 のセキュリティ修正が取り込まれ、パッケージインストール基盤の安全性が向上
  • ✅ PEP 440 準拠が強制され、.* ワイルドカードは == と != でのみ使用可能に (例: gcsfs>=0.8 と記述)
  • ✅ ソースパッケージは常に分離環境でビルドされ、ビルドの再現性が向上
💡 セーフティネット: 環境のアップグレード中に PyPI パッケージのインストールが失敗した場合、 環境は現行バージョンとパッケージのまま稼働を継続します。ワークロード停止のリスクは抑えられています。

pip 26.2.2 へのアップグレード前後でのカスタム PyPI パッケージインストール動作の変化を示しています。 バージョン指定子の検証が厳格化され、ソースパッケージのビルドは常に分離環境で実行されます。

⚙️ 主な変更点

1️⃣ PEP 440 バージョン指定子の強制

pip 26.2.2 は PEP 440 への準拠を強制します。 .* ワイルドカードは == と != との組み合わせでのみサポートされます。

❌gcsfs>=0.8.* は不正な指定子となり失敗
✅gcsfs>=0.8 に書き換える

2️⃣ ソースパッケージの分離ビルド (Isolated source builds)

ソースパッケージ (.tar.gz) は常に分離環境でビルドされるようになりました。

→ プライベートリポジトリが唯一のインデックスの場合、setuptools や pyproject.toml の [build-system] requires に記載のビルド依存関係のプリコンパイル済み wheel (.whl) をリポジトリに含める必要あり
→ 代替策: パッケージを .whl 形式で公開する
→ 一時的な回避策: pip.conf でビルド分離を無効化 (ビルド依存関係が環境に既存の場合のみ有効)

3️⃣ レガシー pkg_resources ビルドの非互換

レガシー pkg_resources モジュールに依存する古いソースパッケージはビルドに失敗する可能性があります。

→ プリコンパイル済み .whl を提供する新しいパッケージバージョンを使用
→ 自社のプライベートパッケージは .whl としてビルド
→ ビルドスクリプトを pkg_resources を使わないように更新

4️⃣ セキュリティ修正

pip 26.2.2 にはセキュリティ修正が含まれており、依存関係インストール経路の脆弱性リスクが低減します。

🩹 回避策の設定例 (pip.conf)

ビルド分離を一時的に無効化する場合、環境バケットの /config/pip/ フォルダに配置する pip.conf に以下を追加します (ビルド依存関係が環境に既存の場合のみ有効)。

INI pip.conf (環境バケットの /config/pip/ に配置) 
[global]
no-build-isolation = false

📋 対応手順 (アップグレード前の確認)

✅ 前提条件: ① 環境更新操作をトリガーできるロール、および環境のサービスアカウントに更新操作に十分な権限があること。 ② カスタム PyPI パッケージの一覧を把握していること。
1

カスタム PyPI パッケージとバージョン指定子の確認

Bash カスタムパッケージ一覧の取得 
gcloud composer environments describe ENVIRONMENT_NAME \
  --location LOCATION \
  --format="value(config.softwareConfig.pypiPackages)"

>=0.8.* のような PEP 440 に準拠しない指定子 (.* を == / != 以外と組み合わせているもの) がないか確認します。

2

不正な指定子の修正

Bash PEP 440 準拠形式への更新 
gcloud composer environments update ENVIRONMENT_NAME \
  --location LOCATION \
  --update-pypi-package "gcsfs>=0.8"

gcsfs>=0.8.* のような指定子を gcsfs>=0.8 のような準拠形式に修正します。

3

プライベートリポジトリとソースパッケージの確認

✓プライベートリポジトリを唯一のインデックスとして使用している場合、setuptools などのビルド依存関係の .whl がリポジトリに含まれているか確認
✓自社パッケージはできるだけ .whl 形式で公開
✓pkg_resources に依存する古いソースパッケージは、新しいバージョンへの更新またはビルドスクリプトの修正を実施
4

環境のアップグレード

互換性を確認した上で、対象ビルド以降へのアップグレードを実施します。 インストールに失敗しても環境は現行構成で稼働を続けるため、失敗時はログを確認して 指定子やパッケージを修正の上で再実行します。

⚖️ メリット / 制約事項

👍 メリット

  • セキュリティリスクの低減: pip のセキュリティ修正が適用され、依存関係インストール経路の脆弱性リスクが減少
  • 安全なアップグレード設計: インストール失敗時も環境が現行構成で稼働を継続し、ワークロード停止リスクを抑制
  • 標準準拠の徹底: PEP 440 強制によりバージョン指定の曖昧さが排除され、将来の pip との互換性を確保
  • ビルドの再現性向上: 分離環境での常時ビルドにより、既存パッケージに依存しない再現性の高いビルドを保証

⚠️ 制約事項・考慮点

  • .* ワイルドカードは == と != でのみ使用可能 (例: >=0.8.* は不可)
  • プライベートリポジトリのみの構成では、ビルド依存関係 (setuptools 等) の .whl の用意が必要
  • pkg_resources 依存のレガシーソースパッケージはビルド失敗の可能性
  • no-build-isolation = false はあくまで一時的な回避策 (ビルド依存関係が環境に既存の場合のみ有効)
  • アップグレード前にカスタム PyPI パッケージの互換性確認を必ず実施
  • CI/CD で環境を再作成・更新しているチームは requirements 定義の棚卸しが必要

💼 ユースケース

📝 ユースケース 1: 不正なバージョン指定子を使っている環境のアップグレード準備

シナリオ: requirements.txt に gcsfs>=0.8.* のような指定子が含まれる環境を composer-3-airflow-2.11.1-build.25 以降にアップグレードしたい。

Text requirements の修正例 
# Before (pip 26.2.2 では不正)
gcsfs>=0.8.*

# After (PEP 440 準拠)
gcsfs>=0.8

効果: アップグレード時の PyPI パッケージインストール失敗を未然に防ぎ、スムーズに新ビルドへ移行できる。

🔒 ユースケース 2: プライベート PyPI リポジトリのみを使用する環境

シナリオ: VPC Service Controls 配下で、プライベートリポジトリを唯一のパッケージインデックスとして .tar.gz のソースパッケージを配布している。

効果: setuptools などのビルド依存関係の .whl をリポジトリに追加するか、 自社パッケージを .whl 形式で公開することで、分離ビルド環境下でもインストールが成功する。 移行期間中は pip.conf の no-build-isolation = false を一時的な回避策として使用できる。

🔗 関連サービス・機能

📦 Artifact Registry

PyPI パッケージの更新時に Managed Airflow が Docker イメージを生成・格納。プライベート Python リポジトリとしても利用でき、.whl パッケージの配布先となる。

🏗️ Cloud Build

カスタム PyPI パッケージをインストールしたイメージのビルドに使用 (デフォルト Cloud Build サービスアカウント、未設定時は環境のサービスアカウント)。

🛡️ VPC Service Controls

境界内の環境でプライベート PyPI リポジトリを使用する場合、追加の権限設定と接続構成が必要。

🎯 まとめ

Managed Airflow の pip が 26.2.2 に更新され、セキュリティが強化される一方、 PEP 440 準拠の強制・分離ビルドの常時適用・ レガシー pkg_resources ビルドの非互換という破壊的変更が発生します。 対象ビルドへアップグレードする前に、カスタム PyPI パッケージのバージョン指定子を棚卸しし、 プライベートリポジトリにはビルド依存関係の .whl を用意するか、 パッケージを .whl 形式へ移行することを推奨します。
