Document AI: Layout Parser
画像・テーブルアノテーション GA

Document AI GA
2026-05-27

📋 概要

Google Cloud Document AI の Layout Parser において、画像およびテーブルのアノテーション機能が General Availability (GA) としてリリースされました。

Layout Parser は Google の専用 OCR モデルと Gemini の生成 AI 機能を組み合わせた高度なドキュメント解析サービスです。ドキュメント内の画像やテーブルを識別し、記述的なテキストブロックとしてアノテーションできるようになりました。

🤖 RAG パイプラインでの活用: ドキュメント内の視覚的要素（チャート、図表、データテーブルなど）をテキスト化することで、検索や生成 AI アプリケーションからアクセス可能な情報として活用できます。

🔄 Before / After

❌ Before (プレビュー段階)

  • 本番ワークロードで SLA が保証されていなかった
  • ドキュメント内画像は OCR で認識されず情報欠落
  • テーブル構造がフラット化され検索精度が低下
  • 視覚情報の処理には別途仕組みの構築が必要

✅ After (GA リリース)

  • SLA 付き本番環境で安心して利用可能
  • 画像が自動識別され記述テキストとして生成
  • テーブルが構造化されデータ整合性を保持
  • 単一 API で画像・テーブル含むドキュメント全体を構造化

⚡ 主要機能

🖼️ 画像アノテーション (Image Annotation)

ドキュメント内の画像（図、チャート、写真など）を自動的に検出し、Gemini の生成 AI 機能を活用して画像の内容を詳細な記述テキストとして生成。例: 銀行レポート内の円グラフから各データポイントを抽出してテキスト化。

📊 テーブルアノテーション (Table Annotation)

複雑なテーブル構造（結合セル、複雑なヘッダーを含む）を正確に解析。テーブル内のデータを構造化されたテキスト情報として出力し、セルと列の正確なアライメントを維持してデータの整合性を保証。

📄 レイアウト認識チャンキング (Layout-aware Chunking)

アノテーション結果を含むセマンティックに一貫したチャンクを生成。祖先の見出しやテーブルヘッダーなどのコンテキスト情報を付与し、単独で取得されてもチャンクの意味が保持される設計。

🛠️ 設定方法

前提条件

✓Google Cloud プロジェクトが作成済みであること
✓Document AI API が有効化されていること
✓適切な IAM 権限（Document AI Editor 以上）が付与されていること

Step 1: Layout Parser プロセッサの作成

Bash 
gcloud alpha document-ai processors create \
  --display-name="layout-parser-with-annotations" \
  --type="LAYOUT_PARSER_PROCESSOR" \
  --location=us

Step 2: アノテーション機能の有効化

JSON 
{
  "processOptions": {
    "layoutConfig": {
      "chunkingConfig": {
        "chunkSize": 500,
        "includeAncestorHeadings": true
      },
      "returnImages": true,
      "returnTables": true
    }
  }
}

Step 3: ドキュメントの処理

Bash 
curl -X POST \
  -H "Authorization: Bearer $(gcloud auth print-access-token)" \
  -H "Content-Type: application/json" \
  "https://us-documentai.googleapis.com/v1/projects/PROJECT_ID/locations/us/processors/PROCESSOR_ID:process" \
  -d '{
    "rawDocument": {
      "mimeType": "application/pdf",
      "content": "BASE64_ENCODED_CONTENT"
    }
  }'

⚠️ デメリット・制約事項

制限事項:
  • オンライン処理は 20 MB / 15 ページ (PDF) に制限
  • バッチ処理でも PDF は最大 1 GB / 500 ページまで
  • 複数ページにまたがるテーブルは 2 つに分割される場合あり
  • ネストされたテーブル (DOCX, PPTX) はサポートされない
  • v1.6 系は Data Residency (DMZ) に非準拠
💡 考慮すべき点:
  • Gemini ベースのバージョン (v1.5 以降) は PDF ファイルのみで拡張機能が有効。非 PDF では v1.0 と同等の動作
  • アノテーション機能を有効にすると処理時間が増加する可能性あり
  • 画像アノテーションの品質は元画像の解像度や複雑さに依存

💼 ユースケース

🏦 金融レポートの自動解析と RAG

銀行や金融機関が四半期レポートや年次報告書（10-K ファイリングなど）を RAG パイプラインに取り込む際、チャートや財務テーブルの情報も検索可能にする。

効果: 円グラフやデータテーブルの内容がテキスト化され、「第3四半期の収益内訳は?」といった質問に対して、チャート内のデータに基づいた正確な回答が生成可能に。

Python 
from google.cloud import documentai_v1 as documentai

client = documentai.DocumentProcessorServiceClient()

request = documentai.ProcessRequest(
    name="projects/PROJECT/locations/us/processors/PROCESSOR_ID",
    raw_document=documentai.RawDocument(
        content=pdf_content,
        mime_type="application/pdf"
    ),
    process_options=documentai.ProcessOptions(
        layout_config=documentai.ProcessOptions.LayoutConfig(
            chunking_config=documentai.ProcessOptions.LayoutConfig.ChunkingConfig(
                chunk_size=500,
                include_ancestor_headings=True
            )
        )
    )
)

result = client.process_document(request=request)

# アノテーション付きチャンクを取得
for chunk in result.document.chunked_document.chunks:
