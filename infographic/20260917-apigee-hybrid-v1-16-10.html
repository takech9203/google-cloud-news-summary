📌 概要

2026 年 9 月 17 日、Apigee hybrid v1.16.10 がリリースされました。パッチリリースのため、Helm チャート経由のアップグレードでコンテナイメージも自動更新され、手動でのイメージ変更は通常不要です。

EventFlow (SSE) の 16 KB 超イベントの欠落・破損の修正、SAML / OAuthV2 / Script / SpikeArrest 各ポリシーのセキュリティ強化、WSFrameDecoder のメモリリーク修正など 13 件の修正に加え、Kubernetes 1.36 サポートと AI ポリシー (Model Armor / セマンティックキャッシュ) のフォワードプロキシ対応が追加されました。さらに 14 コンポーネントへの多数の CVE 対応が含まれます。

💡 こんな組織に重要: Apigee hybrid を GKE やマルチクラウド Kubernetes で運用するプラットフォームチーム、および AI ポリシーを厳格なネットワーク境界 (Egress 制御) 下で利用したい組織。

❌ アップデート前の課題

  • AI ポリシー (Model Armor / セマンティックキャッシュ) のアウトバウンド呼び出しがフォワードプロキシ非対応で、Egress をプロキシ統制する環境では利用困難
  • EventFlow (SSE) で 16 KB 超イベントが負荷下で欠落・切り詰め・破損し、LLM ストリーミングの信頼性に影響
  • v1.16 系は Kubernetes 1.36 未対応で、クラスタのバージョンアップに追随できず
  • ValidateSAMLAssertion (XSW)、OAuthV2 (トークンインジェクション、redirect_uri 検証)、Script (SSRF) に既知のセキュリティ課題
  • PodDisruptionBudget をカスタム値で構成できない

✅ アップデート後の改善

  • AI ポリシーのアウトバウンド呼び出しを HTTP フォワードプロキシ経由でルーティング可能に
  • EventFlow (SSE) の 16 KB 超イベントの 2 件の不具合を修正し、ストリーミングが安定
  • Kubernetes 1.36 を GKE / GDC Virtual / EKS / AKS / RKE2 でサポート
  • 各ポリシーのセキュリティ強化 + Netty スレッドセーフティ修正 + WSFrameDecoder メモリリーク修正 (503 スパイクの原因)
  • overrides.yaml で PodDisruptionBudget (minAvailable / maxUnavailable) をカスタム構成可能に
  • request.path.decode.encoded.separators で %2F / %5C のデコードをオプション有効化
  • 14 コンポーネントへの CVE 修正でセキュリティポスチャが向上

v1.16.10 では、環境にフォワードプロキシ (envs.httpProxy) を構成すると、Model Armor ポリシーとセマンティックキャッシュポリシーからのアウトバウンド呼び出し (Model Armor サニタイズ、Vertex AI 埋め込み、Vector Search の findNeighbors / upsertDatapoints) がポリシーレベルの追加設定なしでフォワードプロキシ経由にルーティングされます。

🚀 主要機能・修正内容

🤖 1. AI ポリシーのフォワードプロキシ対応 (Bug ID: 402250928)

→Model Armor ポリシー (SanitizeUserPrompt / SanitizeModelResponse) とセマンティックキャッシュポリシー (SemanticCacheLookup / SemanticCachePopulate) のアウトバウンド呼び出しを HTTP フォワードプロキシ経由でルーティング可能に
→envs.httpProxy を構成するとデフォルトでプロキシ経由に (ポリシーレベルの設定不要)。*.googleapis.com 配下でないエンドポイント (パブリックの Vector Search など) にも適用
→envs[].managementCallsSkipProxy: true でプロキシをスキップして直接 Egress (トレース・アナリティクスと同じ扱い)
→SemanticCacheLookup が PSC 経由のプライベート Vector Search エンドポイントを使う構成では、類似検索は直接 gRPC 接続となりプロキシを経由しない
→v1.17.0 (2026-09-14 リリース) で導入された同機能の v1.16 系へのバックポートに相当

☸️ 2. Kubernetes 1.36 サポート

→対応プラットフォーム: GKE、GDC Virtual for VMware (vSphere)、GDC Virtual for bare metal、Amazon EKS、Azure AKS、Rancher Kubernetes Engine (RKE2)

📡 3. EventFlow (Server-Sent Events) の修正

→556750755: http-adaptor データパス上で、負荷下において 16 KB 超イベントの後続イベントが欠落・切り詰められる問題を修正
→547712217: 16 KB 超の SSE レスポンスがソケット読み取りをまたいで切り詰め・破損する可能性がある問題を修正

🔒 4. ポリシーのセキュリティ強化・バグ修正

→ValidateSAMLAssertion: SAML XML Signature Wrapping (XSW) 脆弱性の修正 (519729209)、エンティティ・コメントインジェクションに対する検証改善 (472526232)
→OAuthV2: HTTP フォームパラメータ経由の不正なトークンインジェクション防止 (505645076)、implicit グラントの redirect_uri 検証改善 (503817773)
→Script ポリシー: リンクローカルアドレスへの SSRF をブロック (514384893)
→SpikeArrest: NullPointerException と 500 エラーを引き起こすエッジケースの修正 (480770263)

⚙️ 5. ランタイムの安定性向上

→Netty クライアント接続プールとチャネルライフサイクルのスレッドセーフティ問題を修正 (505543289)
→WSFrameDecoder のメモリリークを修正。503 レスポンス (no_healthy_upstream) のスパイクを引き起こす可能性があった (470375542)

🛠️ 6. 構成の柔軟性向上

→PodDisruptionBudget: overrides.yaml でコンポーネントごとにカスタム minAvailable / maxUnavailable を構成可能に (449228485)
→request.path.decode.encoded.separators: フロー選択前にパーセントエンコードされたパス区切り文字 (%2F、%5C) のデコードをオプションで有効化 (502268966)

ステップ 2: (任意) AI ポリシー用フォワードプロキシの構成

YAML overrides.yaml (環境単位のフォワードプロキシ設定) 
envs:

    httpProxy:
      host: proxy.example.com
      port: 3128

envs.httpProxy を構成すると、Model Armor ポリシーとセマンティックキャッシュポリシーのアウトバウンド呼び出しが追加設定なしでフォワードプロキシ経由になります。詳細は Configure a forward proxy を参照してください。

⚠️ デメリット・制約事項

🚧 制限事項

✗SemanticCacheLookup がプライベート Vector Search エンドポイント (PSC) を使う場合、類似検索呼び出しは直接 gRPC 接続となりフォワードプロキシを経由しない
✗envs[].managementCallsSkipProxy: true は AI ポリシー呼び出しも一括でプロキシをスキップする (AI ポリシーのみ個別制御する仕組みではない)
✗フォワードプロキシ設定 (httpProxy のみ) では Pub/Sub などの Google Cloud API への Apigee Runtime の外部呼び出しにプロキシ構成が適用されないため、*.googleapis.com の許可リスト登録が必要

🎯 ユースケース

🏦 ユースケース 1: Egress 統制環境での AI ゲートウェイ運用

シナリオ: 金融機関がオンプレミスの Kubernetes (GDC Virtual / RKE2) 上で Apigee hybrid を運用し、すべてのアウトバウンド通信を社内フォワードプロキシ経由に統制。LLM API へのアクセスに Model Armor によるプロンプトサニタイズを適用したい。

YAML overrides.yaml (実装例) 
envs:
  - name: prod
    httpProxy:
      host: corporate-proxy.internal
      port: 3128
      scheme: HTTP

効果: Model Armor のサニタイズ呼び出しや Vertex AI 埋め込み呼び出しが社内プロキシ経由となり、ネットワークセキュリティポリシーを維持したまま AI ポリシーを導入できる。

📡 ユースケース 2: LLM ストリーミング API の安定化

シナリオ: EventFlow (SSE) で LLM のストリーミングレスポンスを配信しているが、大きなチャンク (>16 KB) を含むレスポンスで欠落・破損が発生していた。

効果: v1.16.10 へのアップグレードにより、16 KB 超のイベントを含む SSE ストリームが負荷下でも安定して配信される。

🛡️ ユースケース 3: 脆弱性対応の一括適用

シナリオ: セキュリティチームのスキャンで apigee-fluent-bit や apigee-asm-ingress のコンテナイメージに多数の CVE が検出され、対応期限が設定されている。

効果: Helm チャートでのパッチアップグレードのみで 14 コンポーネントの CVE 修正が一括適用され、手動のイメージ差し替え作業が不要。

🔗 関連サービス・機能

🛡️ Model Armor

LLM のプロンプト・レスポンスをサニタイズするセキュリティサービス。Apigee の SanitizeUserPrompt / SanitizeModelResponse ポリシーから呼び出され、今回フォワードプロキシ経由のルーティングに対応。

🧠 Vertex AI (Embeddings / Vector Search)

セマンティックキャッシュポリシーが類似検索に利用。埋め込み生成と findNeighbors / upsertDatapoints 呼び出しもフォワードプロキシ対象。

☸️ GKE / GDC / Amazon EKS / Azure AKS / RKE2

Apigee hybrid のランタイムプラットフォーム。Kubernetes 1.36 が新たにサポート対象に。

☁️ Apigee X (マネージド版)

ランタイムを Google が管理する形態。hybrid はランタイムを自社の Kubernetes 上で運用する形態で、今回のようなランタイムのパッチ適用は利用者側の作業となる。
