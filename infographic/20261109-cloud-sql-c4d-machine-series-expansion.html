🗄️ Cloud SQL: C4D マシンシリーズが
Enterprise Plus で 9 リージョンに拡大

📅 リリース日: 2026-11-09
✅ 一般提供 (GA) Cloud SQL MySQL PostgreSQL SQL Server Enterprise Plus

📌 概要

Cloud SQL for MySQL / PostgreSQL / SQL Server の 3 エンジンすべてで、Enterprise Plus エディション向けに C4D マシンシリーズ が新たに 9 リージョン (東京・ロンドン・フランクフルトなど) で利用可能になりました。

C4D は 第 5 世代 AMD EPYC プロセッサ (Turin) と Google 独自のオフロード基盤 Titanium を搭載した x86 ベースのマシンシリーズです。ストレージには最新世代の Hyperdisk Balanced を使用し、IOPS とスループットをワークロードに合わせてカスタマイズできます。 東京 (asia-northeast1) を含む主要リージョンで選択できるようになった点で、日本のユーザーにとっても重要な拡大です。

❌ Before (アップデート前の課題)

  • 東京を含む 9 リージョンでは C4D を選択できず、N2 / C4 / C4A など他シリーズを使う必要があった
  • 第 5 世代 AMD EPYC (Turin) ベースの高性能シリーズを使うには別リージョンを選ぶ必要があり、データレジデンシーやレイテンシ要件と両立できなかった
  • N2 の上限 (最大 128 vCPU / 864 GB) などに制約されていた

✅ After (アップデート後の改善)

  • 東京 (asia-northeast1) を含む 9 リージョンで C4D マシンタイプ (db-perf-optimized-C4D-2 〜 192) を選択可能に
  • Hyperdisk Balanced により容量・プロビジョンド IOPS・スループットを個別にカスタマイズし、予測可能なストレージ性能を確保
  • 既存の N2 / 汎用シリーズからインプレースのマシンシリーズ変更で C4D へ移行可能 (SSD → Hyperdisk Balanced は最小限のダウンタイム)

C4D マシンシリーズは AMD EPYC Turin プロセッサと Titanium オフロード基盤の組み合わせで動作し、 ストレージには IOPS とスループットを個別に設定できる Hyperdisk Balanced を使用します。

⚡ 主要機能

1️⃣ 第 5 世代 AMD EPYC プロセッサ (Turin) + Titanium

→x86 ベースの最新世代 AMD プロセッサにより、要求の厳しいデータベースワークロードに一貫性のある予測可能な高パフォーマンスを提供
→Google 独自の Titanium がネットワークとストレージ I/O の処理をオフロードし、CPU リソースをデータベース処理に集中

2️⃣ Hyperdisk Balanced ストレージ

→Google Cloud の最新世代ネットワークブロックストレージを使用
→ストレージ容量、プロビジョンド IOPS、スループットをそれぞれカスタマイズ可能
→デフォルトの IOPS / スループット値と上限は、マシンタイプとストレージ容量に基づいて設定

3️⃣ 3 つのデータベースエンジンで同時提供

→MySQL / PostgreSQL / SQL Server の Enterprise Plus エディションすべてで利用可能
→2 vCPU から 192 vCPU まで 9 種類の事前定義マシンタイプを提供

🛠️ 設定方法

✅ 前提条件

✔Cloud SQL Enterprise Plus エディションを選択すること (C4D は Enterprise Plus 専用)
✔C4D がサポートされるリージョンを選択すること
✔データキャッシュは C4D では非対応のため、8 vCPU 以上のマシンタイプでは明示的に無効化すること (Enterprise Plus ではデータキャッシュがデフォルトで有効)

ステップ 1: C4D マシンタイプで Enterprise Plus インスタンスを作成

Bash 東京リージョンに PostgreSQL の C4D (8 vCPU) インスタンスを作成 
# 例: 東京リージョンに PostgreSQL の C4D (8 vCPU) インスタンスを作成
gcloud sql instances create my-c4d-instance \
  --database-version=POSTGRES_17 \
  --region=asia-northeast1 \
  --tier=db-perf-optimized-C4D-8 \
  --edition=ENTERPRISE_PLUS \
  --no-enable-data-cache

C4D ではデータキャッシュがサポートされないため、8 vCPU 以上のマシンタイプでは --no-enable-data-cache フラグを追加します。MySQL の場合は --database-version=MYSQL_8_4 など、SQL Server の場合は対応するバージョンを指定します。

ステップ 2: 既存インスタンスを C4D に変更 (インプレース変更)

Bash 既存 Enterprise Plus インスタンスのマシンタイプ変更 
# 既存の Enterprise Plus インスタンスのマシンタイプを C4D に変更
gcloud sql instances patch my-instance \
  --tier=db-perf-optimized-C4D-16 \
  --no-enable-data-cache

汎用マシンシリーズや N2 から C4D へ変更する場合、ストレージは SSD から Hyperdisk Balanced へ移行されます。 この移行は通常、最小限のダウンタイムで完了します。

👍 メリット

💼 ビジネス面

✔データレジデンシー要件との両立: 東京やヨーロッパ各リージョンなどデータ所在地の制約があるワークロードでも、最新の AMD ベース高性能マシンシリーズを選択できる
✔コミットメント割引によるコスト最適化: 1 年 / 3 年の確約利用割引 (CUD) を適用することで、オンデマンド比で大幅なコスト削減が可能

⚙️ 技術面

✔大規模スケールアップ: 最大 192 vCPU / 1,512 GB RAM まで単一インスタンスでスケールでき、N2 (最大 128 vCPU / 864 GB) を超える構成が可能
✔予測可能なストレージ性能: Hyperdisk Balanced によりプロビジョンド IOPS / スループットをワークロードに合わせて個別に設定可能
✔マシンシリーズの選択肢拡大: ワークロード特性に応じて N2 / C4 / C4A / C4D から最適な価格性能比のシリーズを選択できる

⚠️ デメリット・制約事項

🚫 制限事項

✖C4D は Enterprise Plus エディション専用であり、Enterprise エディションでは利用できない
✖データキャッシュ非対応 (ローカル SSD による読み取り高速化)。Enterprise Plus ではデータキャッシュがデフォルト有効のため、8 vCPU 以上の C4D を選択する場合は明示的な無効化 (--no-enable-data-cache) が必要
✖提供マシンタイプは事前定義タイプのみで、カスタム vCPU / メモリ構成は選択できない

🤔 考慮すべき点

  • データキャッシュによる読み取り性能向上 (最大 4 倍) に依存しているワークロードでは、C4 / C4A / N2 の方が適する場合がある
  • C4D から汎用 / N2 シリーズへ戻す場合、Hyperdisk Balanced から SSD へのストレージ移行で大きなダウンタイムが発生する可能性がある
  • Hyperdisk Balanced の IOPS / スループットはマシンタイプとストレージ容量によりデフォルト値と上限が決まるため、必要性能に応じた設計が必要

🎯 ユースケース

🇯🇵 ユースケース 1: 東京リージョンでの大規模基幹データベースのスケールアップ

シナリオ: 日本国内にデータを保持する要件がある EC サイトの基幹データベース (PostgreSQL) が、N2 の最大構成 (128 vCPU) に近づいており、さらなるスケールアップ余地が必要。

Bash 実装例 
gcloud sql instances patch ec-main-db \
  --tier=db-perf-optimized-C4D-192 \
  --no-enable-data-cache

効果: 東京リージョンのまま最大 192 vCPU / 1,512 GB RAM までスケールアップでき、シャーディングなどのアプリケーション側の分割対応を先送りできる。

🇩🇪 ユースケース 2: SQL Server の高負荷ワークロードの性能安定化

シナリオ: フランクフルトリージョンで稼働する SQL Server Enterprise インスタンスで、バッチ処理時の I/O 性能のばらつきが課題となっている。

効果: C4D + Hyperdisk Balanced へ移行し、プロビジョンド IOPS / スループットを明示的に設定することで、ピーク時にも予測可能なストレージ性能を確保できる。

💰 料金

C4D マシンタイプの料金は、vCPU 数とメモリ容量に基づく時間課金です。Hyperdisk Balanced のストレージ容量・ プロビジョンド IOPS・スループットは別途課金されます。1 年 / 3 年の確約利用割引 (CUD) が適用可能です。

🔗 関連サービス・機能

→Google Cloud Hyperdisk: C4D のストレージとして使用される最新世代のネットワークブロックストレージ。容量・IOPS・スループットを個別にプロビジョニング可能
→Compute Engine C4D マシンシリーズ: Cloud SQL の C4D は Compute Engine の C4D シリーズ (AMD EPYC Turin + Titanium) を基盤としている
→Cloud SQL Enterprise Plus エディション: 99.99% の可用性 SLA、1 秒未満の計画メンテナンスダウンタイム、高度な DR などを提供する上位エディション。C4D は本エディション専用

📝 まとめ

C4D マシンシリーズの提供リージョンが東京を含む 9 リージョンに拡大し、MySQL / PostgreSQL / SQL Server の Enterprise Plus インスタンスで 第 5 世代 AMD EPYC (Turin) + Titanium + Hyperdisk Balanced による高性能構成を選択できるようになりました。

データレジデンシー要件のあるワークロードや、N2 の構成上限 (128 vCPU) を超えるスケールアップが必要なデータベースでは、 C4D への移行を検討する価値があります。ただしデータキャッシュが非対応のため、読み取りキャッシュに依存する ワークロードでは既存シリーズとの性能比較を事前に行うことを推奨します。
