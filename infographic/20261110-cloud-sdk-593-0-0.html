📝 概要

2026 年 11 月 10 日、Google Cloud CLI (gcloud) の バージョン 593.0.0 がリリース。 2 件の破壊的変更 — ① App Lifecycle Manager --evaluation-spec フラグのスキーマ変更 (defaultTarget / target → defaultVariant / defaultAllocation / variantId / allocationId)、 ② Windows (x86 / x86_64) における バンドル版 Python の必須コンポーネント化 — を含む。

機能面でも App Lifecycle Manager コマンドグループの GA 昇格、Agent Identity の認可 IAM コマンド群 GA 化と Cross-App Access (XAA) 対応、Cloud Backup DR のリストア検証コマンド群 GA 化、GKE のクラスタ操作改善、 Cloud Run のアンビエントネットワーキング (Beta) など、幅広いサービスの更新が含まれる。

❌ Before (アップデート前の課題)

  • --evaluation-spec は非推奨の defaultTarget / target キーを使用し、API 側の命名と不整合
  • Windows ではバンドル版 Python が任意で、システム Python 依存で動作が不安定になるケースあり
  • Agent Identity 認可リソースの IAM ポリシー操作コマンドが GA 未提供
  • Backup DR のリストアテンプレート / 検証プラン関連コマンドが GA 未提供
  • GKE のノードプールなしクラスタで不適切な提案・分かりにくいエラー
  • Windows の gcloud storage rsync がソート順不具合で未変更ファイルを再コピー・削除
  • DMS 移行ジョブでスキーマ / テーブル単位のフィルタリングを CLI から指定不可

✅ After (593.0.0 での改善)

  • defaultVariant / defaultAllocation / variantId / allocationId の新スキーマに統一、コマンドグループも GA 昇格
  • Windows でバンドル版 Python が必須化され、components update / install が自動導入 → 環境差異問題を解消
  • Agent Identity の authorizations IAM コマンド 5 種が GA、XAA / Connector Reference 用フラグを追加
  • Backup DR の restore-templates / 検証プラン関連 4 コマンドグループが GA 昇格
  • GKE が明確なエラーと正しい表示 (NUM_NODES 列に 0) を返却
  • gcloud storage rsync (Windows) の再コピー / 誤削除を修正
  • DMS に --schemas-filter 等 4 フラグ追加でオブジェクト単位の移行制御が可能に

⚠️ 破壊的変更 (Breaking Changes)

🚩 1. App Lifecycle Manager: --evaluation-spec フラグのスキーマ変更
  • gcloud beta app-lifecycle-manager flags create / update の --evaluation-spec が、非推奨の defaultTarget / target キーに代わり defaultVariant、defaultAllocation、variantId、allocationId を使用
  • 既存のスクリプト / IaC で --evaluation-spec='{"defaultTarget": "..."}' を渡している場合は 新キー名への書き換えが必要
  • デフォルトバリアントの直接指定は defaultVariant、パーセンテージベースのアロケーション既定は defaultAllocation。rules 内のターゲット指定は variantId / allocationId に変更
🪟 2. Windows でバンドル版 Python が必須コンポーネントに
  • Windows (x86 / x86_64) でバンドル版 Python が 必須コンポーネント化
  • gcloud components update / install は未インストール時に 自動的にインストール
  • 従来の「Install Bundled Python」のチェックを外してシステム Python を使う構成は、593.0.0 への更新時にバンドル版 Python が導入される。ディスク使用量を厳密に管理する Windows CI ランナーのイメージ等では追加コンポーネントを考慮する必要あり

🚫 非推奨化

🐚 Cloud Shell: gcloud cloud-shell get-mount-command

非推奨化。将来のリリースで削除される予定。

📱 Device Run: sessions submit instrumentation の --apps フラグ

非推奨化。代わりに新設の --target-app (テスト対象アプリ)、--pre-target-apps / --post-target-apps (前後にインストールするアプリ) を使用する。

🎉 GA 昇格

🚩 App Lifecycle Manager

gcloud app-lifecycle-manager コマンドグループが GA に昇格。あわせて unit-kinds create / update に --application-template-component、--application-template-component-revision、--composite-ref-application-template、--composite-ref-revision フラグを追加 (Beta)。

🤖 Agent Identity

auth-providers authorizations の get-iam-policy / set-iam-policy / add-iam-policy-binding / remove-iam-policy-binding / test-iam-permissions が GA に昇格。

💾 Cloud Backup DR

restore-templates、restore-template-executions、restore-verification-plans、restore-verification-plan-associations の各コマンドグループが GA に昇格。リストア検証計画を CLI から本番運用可能に。

🖥️ Cloud Workstations

configs create / update の --disk-provisioned-iops と --disk-provisioned-throughput フラグが GA に昇格。

⚙️ Compute Engine

--svsm-config フラグ (instances create / bulk create / create-with-container / instance-templates create)、reservations update の --require-specific-reservation、url-maps invalidate-cdn-cache の --content-type / --http-status / --backend-service / --backend-bucket フラグが GA に昇格。

📊 Looker

instances create / update の --workforce-auth-enabled と --google-auth-enabled フラグが GA に昇格。

🌐 Network Connectivity

hubs create / update の --export-psc-published-services-and-regional-google-apis と --export-psc-global-google-apis フラグが GA に昇格。

✨ 主要な新機能・変更点 (サービス別)

🤖 Agent Identity: Cross-App Access (XAA) / Connector Reference 対応

auth-providers create / update に --xaa-auth-provider-id-token-input-jag、--xaa-auth-provider-client-secret-id、--xaa-auth-provider-client-assertion-jwt-id、--xaa-auth-provider-custom-issuer、--connector-reference-auth-provider など 10 個のフラグを追加。XAA と Connector Reference 認証プロバイダを CLI から構成可能に。

🏃 コンテナ / サーバーレス系
  • Cloud Run: gcloud beta run deploy / services update / multi-region-services update に --[no-]ambient-networking と --ambient-scope を追加。アンビエントネットワーキングの有効化とスコープ (リージョナル (既定) / グローバル) の選択が可能に (Beta)
  • Kubernetes Engine: clusters create / update に --default-compute-class を追加。デフォルト kubectl を 1.35.9 → 1.36.6 に更新し、kubectl 1.31 を削除 (同梱: 1.32.13 / 1.33.13 / 1.34.13 / 1.35.10 / 1.36.6 / 1.37.2)。ノードプールなしクラスタへの upgrade / resize / update --enable-autoscaling が明確なエラーを返し、NUM_NODES 列も 0 を表示。IPv6 専用クラスタで --no-enable-ip-alias が警告付きで無視されるよう修正
  • GKE Hub: rolloutsequences create / update に --auto-rollout-scope と --ignored-clusters-selector を追加。memberships register に --read-only フラグが追加され、非 GKE クラスタを READ_ONLY メンバーシップとして登録可能に
🗄️ データベース系
  • AlloyDB: --[no-]enable-psc-auto-dns と --[no-]enable-psc-auto-connection-policy を追加。PSC 自動接続の DNS / サービス接続ポリシーの自動作成を制御可能に
  • Cloud Spanner: gcloud alpha spanner databases wait-for-reencryption を追加。CMEK のバックグラウンド再暗号化完了を待機可能
  • Cloud Memorystore: --endpoints フラグに ipVersion キーを追加し、IPv6 の PSC 自動作成エンドポイントに対応
  • Database Migration: --schemas-filter / --tables-filter / --excluded-schemas-filter / --excluded-tables-filter を追加し、スキーマ / テーブル単位の移行対象の選択・除外に対応
  • Oracle Database: Exadata / Exascale VM クラスタの Workload Identity Connector を管理する enable-identity-connector / disable-identity-connector と --identity-connector-disabled フラグを追加
  • Cloud Bigtable: CVE-2026-81870 対応で go.opentelemetry.io/otel/sdk 1.45.0 でリビルド。cbt-emulator も go 1.26.9 でリビルド
📈 BigQuery
  • Python UDF の DDL 作成・置換時に bq query 出力へビルドステータスのガイダンスを追加。bq show --routine にもビルドステータス列を追加
  • bq mk / bq update の --reservation_assignment に --condition_expression / --condition_title / --condition_description を追加
  • 削除: 非推奨の --multi_region_auxiliary フラグを削除し、出力から multiRegionAuxiliary 列も削除 (使用スクリプトは修正が必要)
  • リージョナルエンドポイント (--api) 指定時のディスカバリドキュメント読み込み失敗・クラッシュを修正。同梱 PyYAML を Python 3 ライブラリ直接パッケージ化に変更
🔒 セキュリティ / IAM 系
  • Cloud IAM: workload-identity-pools create-cred-config に --actor-token-field-name / --actor-token-type を追加し、--credential-source-file と --credential-cert-path の併用に対応。証明書バインドされた OAuth 2.0 トークン交換とアクタートークン委任が可能に
  • Model Armor: templates create / update に --filter-version-selector / --filter-version-selector-alias を追加
  • Cloud KMS: kms locations list の既定出力に HSM_SINGLE_TENANT_AVAILABLE 列を追加
  • Secure Source Manager: repos create / update に --enable-vulnerability-scanning を追加
⚙️ 運用・その他
  • Audit Manager: audit-reports generate / audit-scopes generate / audit-schedules create に --parameter-overrides を追加
  • Cluster Director: clusters export / import を追加。--update-slurm-node-sets で startupScript / labels / bootDisk が無視される不具合を修正。MIG オーケストレーション設定フラグ群が Beta に昇格
  • Compute Engine: backend-services create の --service-lb-policy がリージョナルバックエンドサービスに対応。url-maps invalidate-cdn-cache の --host がワイルドカードホスト名 (*.example.com) に対応
  • Network Services: ExpressLink リソース管理の gcloud beta network-services express-links を追加
  • Network Management: connectivity-tests に --source-datastream-private-connection を追加
  • Service Health: アセット影響を一覧・参照する gcloud beta service-health impacts コマンドグループを追加
  • Cloud Storage: Windows の gcloud storage rsync で未変更ファイルが再コピー・削除される問題を修正
  • BigLake: beta biglake iceberg catalogs create / update に --snowflake-user-identity-federation-role を追加
  • Eventarc: イベントフィルタのないトリガーで triggers list が失敗する問題を修正
  • Config Connector: バージョン 1.160.0 に更新

🔧 設定方法

📌 前提条件

  • gcloud CLI がインストールされていること (gcloud components update で 593.0.0 に更新可能)
  • App Lifecycle Manager の機能フラグを利用している場合は、--evaluation-spec の JSON を新スキーマへ更新すること

ステップ 1: gcloud CLI を 593.0.0 に更新

Bash バージョン更新と確認 
gcloud components update
gcloud version

バージョンが Google Cloud SDK 593.0.0 になっていることを確認。Windows 環境ではこの更新時にバンドル版 Python が未インストールであれば自動的にインストールされる。

ステップ 2: App Lifecycle Manager のフラグ定義を新スキーマへ移行 (破壊的変更対応)

Bash evaluation-spec の新スキーマ移行 
# 旧: --evaluation-spec='{"defaultTarget": "Disabled"}'
# 新: defaultVariant を使用する
gcloud beta app-lifecycle-manager flags update my-feature-flag \
  --location=global \
  --evaluation-spec='{"defaultVariant": "Disabled"}'

# パーセンテージアロケーションを既定にする場合は defaultAllocation を使用する
gcloud beta app-lifecycle-manager flags update enhanced-search \
  --location=global \
  --evaluation-spec='{
    "allocations": [{
      "id": "percentage-rollout",
      "randomizedOn": "userID",
      "slots": [
        {"variant": "enabled", "weight": 10},
        {"variant": "disabled", "weight": 90}
      ]
    }],
    "defaultAllocation": "percentage-rollout"
  }'

CI/CD やスクリプトに埋め込まれた defaultTarget / target キーを検索し、新キーへ一括で書き換える。

ステップ 3: Database Migration のオブジェクトフィルタリング (新機能の例)

Bash スキーマ / テーブル単位の移行フィルタリング 
# 特定スキーマのみを移行対象にし、一部テーブルを除外する
gcloud database-migration migration-jobs create my-migration-job \
  --region=asia-northeast1 \
  --source=SOURCE_CONNECTION_PROFILE \
  --destination=DEST_CONNECTION_PROFILE \
  --type=CONTINUOUS \
  --schemas-filter=sales,inventory \
  --excluded-tables-filter=sales.audit_log

ステップ 4: 非 GKE クラスタの READ_ONLY フリート登録 (新機能の例)

Bash READ_ONLY メンバーシップ登録 
# クラスタへの変更や Connect Agent のインストールを行わずにフリートへ登録
gcloud container fleet memberships register my-external-cluster \
  --context=MY_KUBECONFIG_CONTEXT \
  --read-only

💡 メリット

💼 ビジネス面

✓リストア検証の本番運用: Backup DR のリストアテンプレート / 検証プラン関連コマンドの GA 昇格により、DR 訓練やリストア検証を CLI ベースで定常運用に組み込める
✓移行コストの削減: DMS のスキーマ / テーブル単位フィルタリングにより、必要なオブジェクトのみを移行対象にでき、移行時間とリスクを低減

⚙️ 技術面

✓Python 環境の安定化: Windows でバンドル版 Python が必須となり、システム Python のバージョン差異に起因する gcloud の動作問題が解消
✓フラグ評価スキーマの整合性: --evaluation-spec が API のリソースモデル (defaultVariant / defaultAllocation) と一致し、バリアントとアロケーションの参照が明確に
✓運用エラーの明確化: GKE のノードプールなしクラスタに対するコマンドが明確なエラーを返すようになり、ノードプール削除後の誤操作を早期検知
✓不具合修正: gcloud storage rsync (Windows) の再コピー / 誤削除、Eventarc トリガー一覧の失敗、BigQuery リージョナルエンドポイントのクラッシュなど運用影響のある問題を解消

⚠️ デメリット・制約事項

🔒 制限事項

⚠App Lifecycle Manager の flags コマンドは引き続き gcloud beta での提供 (コマンドグループ本体は GA 昇格)
⚠Cloud Run のアンビエントネットワーキングフラグは Beta コンポーネント (gcloud beta run) での提供
⚠gcloud alpha spanner databases wait-for-reencryption は Alpha 段階の提供

🤔 考慮すべき点

  • --evaluation-spec に旧キー (defaultTarget / target) を渡しているスクリプト・IaC は 593.0.0 で動作しなくなる可能性があるため、更新前に必ず書き換える
  • Windows の CI ランナーやゴールデンイメージでは、更新でバンドル版 Python が自動インストールされ ディスク使用量が増加する点に留意
  • BigQuery の --multi_region_auxiliary フラグや出力列 multiRegionAuxiliary をパースしているスクリプトは修正が必要
  • kubectl 1.31 を明示的に利用している場合は、gcloud 同梱版が削除されたため代替手段 (別途バイナリの取得など) を検討
  • gcloud cloud-shell get-mount-command と Device Run の --apps フラグは将来削除されるため、早めの移行が望ましい

🎯 ユースケース

1️⃣ App Lifecycle Manager フラグ定義の移行監査

シナリオ: 機能フラグの作成・更新を CI/CD パイプラインの gcloud beta app-lifecycle-manager flags コマンドで管理しており、旧スキーマの defaultTarget を利用している。

Bash 旧キー使用箇所の洗い出し 
# リポジトリ内の旧キー使用箇所を洗い出す
grep -rnE '"(defaultTarget|target)"\s*:' ci/ infra/ scripts/

# defaultTarget がバリアント ID を指す場合 → defaultVariant へ
# defaultTarget がアロケーション ID を指す場合 → defaultAllocation へ
# rules 内の target → variantId (または allocationId) へ書き換える

効果: 593.0.0 への更新に伴うフラグ管理パイプラインの破損を未然に防止できる。

2️⃣ Windows CI ランナーの 593.0.0 対応確認

シナリオ: Windows ベースのビルドエージェントで gcloud を利用しており、イメージサイズとインストールコンポーネントを厳密に管理している。

効果: バンドル版 Python の必須化により Python 環境の再現性が向上する一方、イメージサイズが増加するため、gcloud components update 後のイメージを事前検証してから展開することで、エージェントの安定稼働を維持できる。

3️⃣ Backup DR リストア検証の定常運用

シナリオ: 月次の DR 訓練で、バックアップからのリストアが正しく機能するかを検証したい。

Bash リストアテンプレートと検証プランの管理 (GA) 
gcloud backup-dr restore-templates list --location=asia-northeast1
gcloud backup-dr restore-verification-plans list --location=asia-northeast1

効果: GA 昇格によりリストア検証のワークフローをスクリプト化して定常運用に組み込め、復旧可能性の継続的な担保ができる。

💰 料金・🌏 利用可能リージョン

💰 料金: gcloud CLI (Cloud SDK) 自体は無料で利用できる。本リリースで追加された各フラグ・コマンドの利用料金は、対象となる各サービス (Cloud Run、GKE、AlloyDB、Backup DR、Database Migration など) の料金体系に従う。 → Google Cloud の料金
🌏 リージョン: gcloud CLI はクライアントツールのためリージョンの制約はない。各機能の利用可能リージョンは対象サービスのドキュメントを参照。

📌 まとめ

gcloud CLI 593.0.0 は、App Lifecycle Manager の --evaluation-spec スキーマ変更と Windows におけるバンドル版 Python の必須化という 2 つの破壊的変更を含むリリース。

  • ✅ まずは機能フラグ管理スクリプトの旧キー (defaultTarget / target) の棚卸しを
  • ✅ Windows CI 環境での更新検証を推奨
  • ✅ App Lifecycle Manager / Agent Identity / Backup DR リストア検証の GA 昇格や、DMS のオブジェクトフィルタリングなど、運用を強化する新機能の評価も価値がある
