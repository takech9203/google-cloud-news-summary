☸️ GKE 2026-R47 バージョンアップデート & セキュリティ更新

全リリースチャネルのデフォルトバージョン更新と Container-Optimized OS の累積セキュリティ修正
Google Kubernetes Engine GA (Generally Available) 📅 リリース日: 2026-11-10

📝 概要

GKE の全リリースチャネル (Rapid / Regular / Stable / Extended / No channel) で 2026-R47 バージョンアップデートが実施され、デフォルトバージョンの更新、新規バージョンの追加、 旧バージョンの非推奨化・削除、自動アップグレードターゲットの更新が行われました。 更新された Container-Optimized OS (COS) イメージは累積的で、 前回リリース以降のすべてのセキュリティ修正を取り込んでいます。

❌ Before (アップデート前の課題)

  • 以前のデフォルトバージョンには最新のセキュリティ修正やバグフィックスが未反映
  • COS イメージに既知の脆弱性への修正が反映されていないバージョンが残存
  • 自動アップグレードターゲットが旧バージョンを指し、クラスタが最新パッチを自動で受け取れない

✅ After (アップデート後の改善)

  • 各チャネルのデフォルトが最新パッチレベルに更新され、新規クラスタに即適用
  • 更新された COS イメージで前回リリース以降の累積セキュリティ修正を適用
  • 自動アップグレードターゲット更新で既存クラスタも順次アップグレード
  • Rapid チャネルで Alpha 1.38.0 が利用可能になり、次期バージョンの早期検証が可能

⚙️ 主要機能 (サービスアップデートの詳細)

⚡ 1. Rapid チャネルのバージョン更新

  • デフォルトバージョンが 1.37.1-gke.2097000 に更新
  • 新規利用可能: 1.34.12-gke.1698000 / 1.35.9-gke.1673000 / 1.36.5-gke.2262000 / 1.37.2-gke.1042000
  • 🧪 Alpha バージョン 1.38.0-gke.4814000+preview が GKE Alpha クラスタ向けに提供開始
  • 1.34.12-gke.1363000、1.35.8-gke.2308000、1.36.5-gke.1259000、1.37.1-gke.3020000 などが非推奨化 (90 日以内またはサポート終了時に削除)

⚖️ 2. Regular チャネルのバージョン更新

  • デフォルトバージョンが 1.36.4-gke.2377000 に更新
  • 1.34.12-gke.1153000、1.36.4-gke.2326000 が非推奨化、1.34.12-gke.1011000、1.36.4-gke.2046003 が削除
  • 自動アップグレードターゲット: 1.33 系クラスタは 1.34.12-gke.1209000 へのマイナーアップグレード対象

🛡️ 3. Stable チャネルのバージョン更新

  • デフォルトバージョンが 1.35.8-gke.1796000 に更新
  • 1.34.11 系、1.35.8-gke.1626001、1.36.4 系の複数パッチが非推奨化
  • 自動アップグレードターゲット: 1.33 → 1.34.12-gke.1011000、1.34 → 1.35.8-gke.1796000 のマイナーアップグレードが設定

🕐 4. Extended チャネルのバージョン更新

  • デフォルトバージョンが 1.36.4-gke.2377000 に更新
  • 新規利用可能: 1.32.13-gke.2788000 / 1.32.13-gke.3004000 / 1.33.13-gke.2074000 / 1.33.13-gke.2339000
  • 長期サポートが必要な環境向けに 1.32 系・1.33 系の最新パッチを継続提供
  • 自動アップグレードターゲット: 1.31 系クラスタは 1.32.13-gke.2701000 へのマイナーアップグレード対象

⚠️ 5. No channel (非推奨) のバージョン更新

  • デフォルトバージョンが 1.36.4-gke.2377000 に更新
  • 新規利用可能: 1.34.12-gke.1698000 / 1.35.9-gke.1673000 / 1.36.5-gke.2262000 / 1.37.2-gke.1042000
  • ノードバージョンとして 1.32.13-gke.3004000、1.33.13-gke.2339000 なども追加
  • No channel 構成自体は非推奨で 2027 年 6 月 14 日に削除予定。リリースチャネルへの移行が推奨される

🔒 6. セキュリティ更新 (Container-Optimized OS)

  • 更新された COS イメージを使用する新しい GKE バージョンを含む
  • イメージは累積的で、前回の GKE リリース以降のすべての COS セキュリティ修正を取り込む
  • 解決された個別の脆弱性は各 COS イメージの Security release notes で確認可能

🔧 設定方法

✅ 前提条件

✓Google Cloud プロジェクトで GKE API が有効化されていること
✓gcloud CLI がインストールされ、認証が完了していること
✓Kubernetes Engine Cluster Admin 以上の IAM 権限を持つこと

ステップ 1: 現在のクラスタバージョンとチャネルを確認

Bashクラスタ一覧の確認
gcloud container clusters list \
    --project PROJECT_ID \
    --format="table(name,location,currentMasterVersion,releaseChannel.channel)"

現在のクラスタが使用しているバージョンとリリースチャネルを確認します。

ステップ 2: 利用可能なバージョンを確認

Bashチャネル別バージョン一覧の表示
gcloud container get-server-config \
    --location LOCATION \
    --format="yaml(channels)"

ロールアウトは複数日かけて全ゾーンに展開されるため、リリースノート公開時点では一部のゾーンで新バージョンが未提供の場合があります。

ステップ 3: 手動でバージョンをアップグレードする場合

Bashコントロールプレーン → ノードプールの順にアップグレード
# コントロールプレーンのアップグレード
gcloud container clusters upgrade CLUSTER_NAME \
    --location LOCATION \
    --master \
    --cluster-version VERSION

# ノードプールのアップグレード
gcloud container clusters upgrade CLUSTER_NAME \
    --location LOCATION \
    --node-pool NODE_POOL_NAME \
    --cluster-version VERSION

手動アップグレードでは、コントロールプレーンを先にアップグレードし、その後ノードプールをアップグレードします。

ステップ 4: セキュリティパッチを早期適用したい場合 (accelerated patch auto-upgrades)

Bashaccelerated patch auto-upgrades の有効化
gcloud container clusters update CLUSTER_NAME \
    --location LOCATION \
    --patch-update accelerated

パッチバージョンが自動アップグレードターゲットに設定される前に、利用可能になった時点で自動アップグレードを受け取れます。セキュリティパッチを可能な限り早く適用したい場合に有効です。

💡 メリット

💼 ビジネス面

✓セキュリティリスクの低減: 累積的な COS セキュリティ修正を含む新バージョンにより、既知の脆弱性リスクが迅速に低減
✓運用負荷の軽減: リリースチャネル登録クラスタは自動アップグレードされ、手動でのバージョン管理作業が不要に
✓段階的なバージョン採用: チャネルごとの段階提供により、検証環境で先行評価し本番への影響を最小化

🔬 技術面

✓Kubernetes 1.38 の早期検証: Alpha バージョン 1.38.0-gke.4814000+preview で次期マイナーバージョンの新機能や API 変更を先行検証可能
✓幅広いバージョン選択肢: Extended チャネルで 1.32 系・1.33 系の最新パッチが追加され、長期サポートが必要なワークロードでもセキュリティ修正を受領
✓パッチバージョンの早期利用: 新パッチは自動アップグレードターゲット化の少なくとも 1 週間前に利用可能になり、手動または accelerated patch auto-upgrades で先行適用可能

⚠️ デメリット・制約事項

🚫 制限事項

✗Rapid チャネルのバージョンは GKE SLA の対象外であり、本番環境での使用は推奨されない
✗Alpha バージョン 1.38.0-gke.4814000+preview は GKE Alpha クラスタ専用で、通常のクラスタでは使用不可
✗ロールアウトはリリースノート公開時点で進行中であり、全 Google Cloud ゾーンへの展開完了まで複数日かかる場合がある
✗非推奨化されたバージョン (deprecated) は 90 日以内、またはサポート終了日のいずれか早い方で削除される

🤔 考慮すべき点

  • No channel 構成は 2027 年 6 月 14 日に削除予定。該当クラスタはリリースチャネルへの移行計画を策定すること
  • マイナーバージョンアップグレードには Kubernetes API の非推奨化・削除が含まれる場合があり、ワークロードの互換性確認が必要 (非推奨 API 使用中のクラスタは自動アップグレードが一時停止)
  • メンテナンスウィンドウとメンテナンス除外を適切に設定し、ビジネスクリティカルな時間帯の自動アップグレードを回避すること
  • 非推奨化されたバージョンを使用中のクラスタは、削除前に新しいパッチバージョンへのアップグレードを計画すること

🎯 ユースケース

🧪 ユースケース 1: Kubernetes 1.38 Alpha の先行検証

シナリオ: プラットフォームチームが次期 Kubernetes 1.38 の新機能や API 変更を事前に検証し、本番導入前に互換性課題を洗い出したい場合。Rapid チャネルの GKE Alpha クラスタで Alpha バージョンを使用します。

BashAlpha クラスタを 1.38.0 preview で作成
gcloud container clusters create alpha-test-cluster \
    --location us-central1 \
    --enable-kubernetes-alpha \
    --release-channel rapid \
    --cluster-version 1.38.0-gke.4814000+preview

効果: GKE で 1.38 系が一般提供される前に、アルファ機能ゲートを含む次期バージョンの挙動を検証でき、マイナーバージョンアップグレードに向けた準備期間を確保できます。

🔒 ユースケース 2: セキュリティパッチの迅速な適用

シナリオ: セキュリティ要件が厳しい環境で、COS のセキュリティ修正を含む新バージョン (例: 1.37.2-gke.1042000) を、自動アップグレードターゲットになる前に適用したい場合。

Bashaccelerated patch auto-upgrades を有効化
gcloud container clusters update prod-cluster \
    --location us-central1 \
    --patch-update accelerated

効果: パッチバージョンが利用可能になった時点で自動アップグレードが実行され、COS イメージの累積的なセキュリティ修正が通常よりも早く適用されます。

🕐 ユースケース 3: Extended チャネルによる長期バージョン保持とパッチ適用の両立

シナリオ: 規制要件によりマイナーバージョンアップグレードに社内監査プロセスが必要な環境で、1.32 系・1.33 系を長期維持しつつ、最新のセキュリティパッチ (1.32.13-gke.3004000 など) は適用したい場合。

効果: Extended チャネルのマイナーバージョン長期サポートを活用して監査プロセスに十分な時間を確保しながら、パッチレベルのセキュリティ修正は自動的に適用され、クラスタの安全性が維持されます。

🔗 関連サービス・機能

🚀 GKE リリースチャネル: クラスタのバージョン管理ポリシーを定義する機能。Rapid、Regular、Extended、Stable の 4 つのチャネルから選択可能
🖥️ Container-Optimized OS: GKE ノードのデフォルト OS イメージ。Google が管理するセキュリティ強化済みの OS で、今回のセキュリティ更新の対象
🗓️ GKE メンテナンスウィンドウと除外: 自動アップグレードの実行時間帯を制御する機能。ビジネスクリティカルな時間帯を避けてアップグレードをスケジュール可能
🔔 GKE クラスタ通知: バージョンの更新やアップグレードイベントに関する通知を Pub/Sub 経由で受信できる機能
🧪 GKE Alpha クラスタ: Kubernetes のアルファ機能ゲートと Alpha API を有効化した検証用クラスタ。Rapid チャネルの Alpha パッチバージョンを利用可能

📌 まとめ

2026-R47 バージョンアップデートにより、GKE の全リリースチャネルでデフォルトバージョンと自動アップグレードターゲットが更新され、 累積的な Container-Optimized OS のセキュリティ修正を含む新バージョンが提供されました。 Rapid チャネルでは 1.37.1 がデフォルトとなり、Alpha 1.38.0 preview による次期バージョンの先行検証も可能になりました。

自動アップグレードターゲットが更新されているため、メンテナンスウィンドウの設定を確認し、 特に 1.33 系以前を使用中のクラスタはマイナーバージョンアップグレードに備えたワークロードの互換性テストの実施を推奨します。 また、No channel 構成のクラスタは 2027 年 6 月の削除に向けてリリースチャネルへの移行を計画すべきです。
