📅 リリース日: 2026-11-23

🔀 Edge Microgateway 3.3.13 リリース

admin /stats エンドポイントのループバックバインド化 + コア処理のセキュリティ強化 + CVE 修正 + configure 不具合修正

📝 概要

Edge Microgateway は Apigee Edge と連携して動作する軽量 API ゲートウェイで、バックエンドの近くに配置して OAuth 認証やクォータなどの API 管理機能を提供します。 3.3.13 は、前回 3.3.12 (2026-11-04) に続くセキュリティ中心のメンテナンスリリースです。

⚠️ 破壊的変更: admin /stats エンドポイントのデフォルトバインドが 0.0.0.0 (全インターフェース) から 127.0.0.1 (ループバック) に変更。 リモートから /stats を参照していた環境は、アップグレード後に到達不能になります。

❌ Before (3.3.12 以前の課題)

  • admin /stats がデフォルトで 0.0.0.0 にバインドされ、認証なしのリモートアクセスのリスクがあった
  • 設定の TLS オプション処理、ローカルプロキシのシリアライゼーション、環境タグのエスケープに強化の余地 (570053366)
  • パス正規化、hop-by-hop ヘッダー、リクエストパターンキャッシュ、メトリクスヘッダー処理に強化の余地 (587833624)
  • tmp / rimraf の API 更新に起因して初回 edgemicro configure が失敗 (587349448)
  • npm 依存関係と Docker の Debian OS パッケージに既知の脆弱性が残存

✅ After (3.3.13 での改善)

  • /stats がデフォルトでループバック (127.0.0.1) のみにバインドされ、認証なしリモートアクセスを防止
  • 設定 TLS オプション処理・ローカルプロキシシリアライゼーション・環境タグエスケープを強化
  • パス正規化、hop-by-hop ヘッダーフィルタリング、キャッシュ境界設定、メトリクスヘッダー処理を強化
  • 初回 edgemicro configure / private configure が正常に完了
  • npm 依存更新 + node:24.22.3-trixie-slim への更新で計 4 件の CVE を修正

⚙️ 主要機能・変更点

🚨 1. 【破壊的変更】admin /stats エンドポイントのデフォルトバインドアドレス変更
  • 3.3.13 以降、/stats はデフォルトで 0.0.0.0 ではなく 127.0.0.1 (ループバック) にバインド
  • 目的は認証なしのリモートアクセスの防止
  • リモート監視システムから直接参照していた場合は、ローカル経由での取得への変更などの対応が必要
🔒 2. コア処理のセキュリティ強化
  • 設定の TLS オプション処理、ローカルプロキシのシリアライゼーション、環境タグのエスケープを強化 (Issue 570053366)
  • URL マッチングとターゲットルーティングにおけるリクエストパスの正規化 (canonicalization) を強化 (Issue 587833624)
  • hop-by-hop ヘッダーのフィルタリング、リクエストパターンキャッシュの境界設定 (bounded caching)、メトリクスヘッダー処理を強化 (Issue 587833624)
🛡️ 3. 脆弱性 (CVE) の修正
  • edgemicro パッケージ: npm 依存関係の更新により CVE-2026-118764、CVE-2026-118773 を修正
  • Docker イメージ: ベースイメージを node:24.22.3-trixie-slim に更新し、Debian OS パッケージの CVE-2026-27171、CVE-2026-85091 を修正
🔧 4. 初回 configure 失敗の不具合修正
  • tmp および rimraf パッケージの API 更新に起因し、初回の edgemicro configure / edgemicro private configure が edgemicro-auth のデプロイ中に失敗する問題を修正 (Issue 587349448)

🛠️ 設定方法 (アップグレード手順)

💡 前提条件:
✓npm インストールの場合、サポート対象の Node.js バージョン (22、24、26) で運用していること
✓リモートから admin /stats を参照している場合は、アップグレード前に影響範囲を確認しておくこと
1

npm インストールのアップグレード

Bash npm でのアップグレード 
npm install -g edgemicro@3.3.13

詳細手順は公式の「Upgrading Edge Microgateway」ドキュメントを参照してください。

2

Docker デプロイメントのアップグレード

Bash 3.3.13 の Docker イメージを取得 
# 3.3.13 の Docker イメージを取得
docker pull gcr.io/apigee-microgateway/edgemicro:3.3.13

3.3.13 の Docker イメージは node:24.22.3-trixie-slim ベースでビルドされ、Debian OS パッケージの CVE 修正を含みます。

3

/stats エンドポイントの参照経路の確認

アップグレード後、/stats はデフォルトでループバックのみにバインドされます。 リモートの監視システムから直接参照していた場合は、Edge Microgateway と同一ホスト (ローカル) 経由で統計情報を取得する構成に見直してください。

⚖️ メリット・デメリット

💼 ビジネス面のメリット

✓セキュリティリスクの低減: 認証なしリモートアクセスの経路がデフォルトで閉じられ、情報漏えいリスクとコンプライアンス指摘事項を削減
✓CVE 対応の一括適用: npm + Docker の計 4 件の CVE 修正を 1 回のアップグレードで適用

🔧 技術面のメリット

✓セキュアバイデフォルト: /stats のループバックバインドにより、追加設定なしで安全側の構成が標準に
✓コア処理の堅牢化: パス正規化や hop-by-hop ヘッダーフィルタリング強化により攻撃経路が狭まる
✓初期構築の信頼性向上: 初回 edgemicro configure の失敗が解消

⚠️ 制限事項・考慮点

✗3.3.13 以降、admin /stats はデフォルトではリモートホストから到達できない (ループバックのみ)
⚠️ 考慮点 1: リモート監視ツールや外形監視で /stats を直接参照している環境では、アップグレード後に統計取得が失敗。参照経路を棚卸しし、ローカル経由での取得に変更する対応を計画する。
⚠️ 考慮点 2: 3.3.12 の破壊的変更 (Node.js 20 サポート終了、Docker イメージからの npm / npx 削除) を未適用のまま 3.3.13 へ一気にアップグレードする場合は、それらの影響もあわせて確認する。

🎯 ユースケース

💡 ユースケース 1: セキュリティパッチの定期適用

シナリオ: npm インストールした Edge Microgateway 3.3.12 を運用しており、セキュリティチームから依存パッケージの CVE (CVE-2026-118764 / CVE-2026-118773) への対応を求められている。

Bash 実装例 
npm install -g edgemicro@3.3.13

効果: npm 依存関係の CVE 修正とコアリクエスト処理の強化が適用され、セキュリティ態勢を維持できる。

💡 ユースケース 2: /stats をリモート監視している環境の移行

シナリオ: Kubernetes 上で Edge Microgateway の Docker イメージを運用しており、別 Pod の監視エージェントが /stats エンドポイントをリモートから参照してメトリクスを収集している。

効果: 3.3.13 では /stats がループバックのみにバインドされるため、サイドカーコンテナなど同一ネットワーク名前空間内からの収集に変更することで、認証なしリモートアクセスを塞ぎつつメトリクス収集を継続できる。

✅ まとめ

Edge Microgateway 3.3.13 は、admin /stats エンドポイントのループバックバインドへの変更という破壊的変更を含むセキュリティ強化リリースです。 コアリクエスト処理の強化、4 件の CVE 修正、初回 configure 失敗の修正が含まれるため、すべての利用者にアップグレードが推奨されます。 適用前に /stats をリモートから参照する運用の有無を確認し、必要に応じてローカル経由のメトリクス収集へ構成を見直してから edgemicro@3.3.13 または Docker イメージ 3.3.13 へ移行してください。
