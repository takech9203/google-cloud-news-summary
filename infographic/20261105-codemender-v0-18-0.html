🛡️ CodeMender v0.18.0

検証セッションのガードレール強化と IAM 診断ガイダンス
📅 リリース日: 2026-11-05

📝 概要

AI コードセキュリティエージェント CodeMender の v0.18.0 がリリース。CodeMender はコードベースの脆弱性をスキャン (cm find)・検証 (cm verify)・修正 (cm fix) する自律型エージェントで、推論はクラウド、コマンド実行はローカルサンドボックスで行う「ローカルファースト」実行モデルを採用している。

v0.18.0 の目玉は、cm verify セッションに探索的ツールターン (tool-turn) の上限を設けるガードレールの追加。PoC (概念実証) エクスプロイトを生成・実行する検証セッションで、エージェントが無制限にコマンド実行ループを続けるリスクを抑制できる。さらに、サービスアカウント・CI/CD 環境向けに roles/aiplatform.agentsUser の IAM バインディングコマンドを具体的に提示する診断ガイダンスも追加された。

🎯 対象ユーザー: CodeMender でコードベースのセキュリティスキャン・脆弱性検証を行う開発チーム、CI/CD パイプラインに CodeMender を組み込んでいる DevSecOps チーム

❌ Before: アップデート前の課題

  • cm verify で探索的ツール実行に上限がなく、コマンド実行ループが無制限に継続するおそれ (実行時間・トークン消費の予測が困難)
  • CLI の更新プロンプトにリリースノートへの導線がなく、自分で DevSite を探す必要があった
  • IAM 権限不足時に必要なロールと付与コマンドを自力で特定する必要があった
  • 検証・再開セッション、シェル環境間の互換性、サインインフローに信頼性の課題

✅ After: アップデート後の改善

  • 探索的ツールターンの上限で無制限のコマンド実行ループを防止
  • 更新プロンプトに DevSite リリースノートへの直接リンクを表示、更新内容を即座に確認可能
  • セットアップ・エラーメッセージに roles/aiplatform.agentsUser の実行可能なバインディングコマンドを表示
  • エージェントセッションの信頼性、シェル互換性、サインインフロー、エラーレポートが改善

cm verify の検証セッションにおいて、エージェントの探索的なツール実行回数がガードレールでチェックされ、上限を超えるとセッションが停止される。また、権限エラー発生時には必要な IAM バインディングコマンドが CLI から直接提示される。

⚡ 主要機能

1️⃣ 検証ツールターンのガードレール

→cm verify セッションに探索的なツールターンの上限を追加
→PoC エクスプロイトの生成・検証中に無制限のコマンド実行ループに陥ることを防止
→実行時間とリソース消費の予測可能性が向上

2️⃣ 更新プロンプトでのリリースノートリンク

→新しい CLI バージョンへの更新を促す際、DevSite リリースノートへの直接リンクを表示
→更新前に変更内容 (新機能・破壊的変更・バグ修正) を確認可能に

3️⃣ エージェント IAM 診断ガイダンス

→セットアップおよびエラーメッセージに roles/aiplatform.agentsUser の IAM バインディングを付与する実行可能なコマンドを追加
→サービスアカウント環境・CI/CD 環境 (GitHub Actions、Cloud Build など) を対象とした具体的なガイダンス

4️⃣ バグ修正

✓エージェントセッション (検証・再開セッション含む) の信頼性を改善
✓シェル環境間の互換性を改善
✓対話的なアクティベーション時のサインインフローを改善
✓サービス一時停止時のエラーレポートを改善 (セキュリティ・安定性の改善を含む)

🛠️ 設定方法

📋 前提条件:
  • CodeMender へのアクセス権を持つ Google Cloud プロジェクト (限定された顧客向けの Public Preview)
  • CodeMender CLI のインストールと Application Default Credentials (ADC) の設定

ステップ 1: CLI を最新バージョンに更新

cm update

v0.18.0 以降、更新プロンプトには DevSite リリースノートへの直接リンクが表示されるため、更新前に変更内容を確認できる。

ステップ 2: 接続と権限のヘルスチェック

cm health --strict

資格情報 (exit code 10)、設定 (20)、ネットワーク到達性 (30)、プロジェクト IAM 権限 (40) のどのレイヤーで問題が発生しているかを切り分けられる。v0.18.0 では、権限不足時に roles/aiplatform.agentsUser のバインディングコマンドが実行可能な形で提示される。

ステップ 3: 検証セッションの実行

# cm report または cm find の出力から FINDING_ID を取得して実行
cm verify FINDING_ID

v0.18.0 では探索的ツールターンの上限がガードレールとして機能し、セッションが無制限に継続することはない。

🤔 考慮すべき点

⚠️cm verify はコマンド実行やファイル変更をホストシステム上で行う可能性があるため、サンドボックスを無効化 (--sandbox=false) する場合は隔離された VM やコンテナでの実行を推奨
⚠️ツールターン上限により、複雑な脆弱性の検証セッションが上限到達で終了する可能性に留意
⚠️CLI のバージョンアップは機能差分が大きい (v0.16.0〜v0.18.0 で cm health 追加やフラグ変更など) ため、リリースノートリンクで変更点を確認してから更新することが望ましい

🎯 ユースケース

📌 ユースケース 1: CI/CD パイプラインでの脆弱性検証の安定運用

シナリオ: GitHub Actions でプルリクエストごとに cm find --diff でスキャンし、検出された CRITICAL/HIGH の脆弱性を cm verify で検証するパイプラインを運用。従来は検証セッションが長時間化するリスクがあり、パイプラインのタイムアウト設計が難しかった。 

# パイプラインの preflight でヘルスチェック (権限エラーを早期検出)
cm health --strict --json

# PR の差分をスキャン
cm find . --diff=origin/main

# 検出された脆弱性を検証 (v0.18.0 ではツールターン上限により実行が有界)
cm verify FINDING_ID -y

効果: ツールターンのガードレールにより検証セッションの実行時間が有界となり、CI のタイムアウト設計とコスト見積もりが容易に。権限エラー時も具体的な roles/aiplatform.agentsUser バインディングコマンドが表示され、復旧が迅速になる。

📌 ユースケース 2: サービスアカウント環境での初期セットアップ

シナリオ: Workload Identity Federation を使った CI/CD 環境で CodeMender を新規セットアップする際、403 Forbidden エラーの原因特定に時間がかかっていた。

効果: v0.18.0 では CLI のセットアップ・エラーメッセージに実行可能な IAM バインディングコマンドが直接表示されるため、ドキュメントを往復することなく権限設定を完了できる。

CodeMender v0.18.0 は、cm verify のツールターン上限による実行ガードレールと、roles/aiplatform.agentsUser の IAM 診断ガイダンスにより、自律型セキュリティエージェントを CI/CD で安全かつ予測可能に運用するための重要な改善である。CodeMender を利用中のチームは cm update で最新 CLI に更新し、パイプラインの preflight に cm health --strict を組み込むことを推奨する。
