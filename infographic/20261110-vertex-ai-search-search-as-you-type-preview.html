🔍 Vertex AI Search (Agent Search) Public Preview

⌨️ Search-as-you-type (入力中検索)

カスタム検索アプリで、キーストロークごとにドキュメント検索結果をリアルタイム更新
📅 リリース日: 2026-11-10

📝 概要

Vertex AI Search (Agent Search) のカスタム検索アプリで、Search-as-you-type (入力中検索) が Public Preview になりました。スキーマのフィールド設定で有効化すると、ユーザーがクエリを入力し終える前に、 キーストロークごとにランク付けされたドキュメントの結果リストがリアルタイムで更新されます。

💡 最大のポイント — オートコンプリートとの違い: オートコンプリートは「クエリ文字列の候補」を提案するのに対し、Search-as-you-type は 「マッチするドキュメントそのもの」を返します。ユーザーはフルクエリを入力せずに目的のドキュメントへ到達できます。

❌ Before (アップデート前)

  • 入力中の支援はオートコンプリート (クエリ候補提案) のみで、クエリ確定まで実際の検索結果を確認できなかった
  • 「候補を選択 → 検索実行 → 結果確認」という複数ステップが必要だった
  • Google 検索や主要 EC サイトのようなインクリメンタル検索は、検索 API を連打する実装を自前で設計する必要があった

✅ After (アップデート後)

  • スキーマのフィールド設定だけで、キーストロークごとにランク付け済みドキュメントを返せるようになった
  • 入力途中で結果リストをブラウズし、フルクエリを入力せずに目的の結果を発見できる
  • クエリ候補のオートコンプリートとドキュメントを返す Search-as-you-type を目的に応じて使い分け可能に

⚡ 主要機能

⌨️ 1. キーストロークごとのドキュメント検索

→フルクエリの入力完了を待たずに、キーストロークごとにランク付けされたドキュメントのセットを更新して返却
→ユーザーは入力途中でも結果リストをブラウズし、クエリ確定前に目的の結果を発見できる

🗂️ 2. スキーマフィールド単位での有効化

→データストアのスキーマで、Search-as-you-type をサポートするフィールドを設定する方式
→既存のフィールド設定 (Searchable、Indexable、Retrievable、Completable など) と同様に、フィールド単位で検索挙動をコントロール

🔀 3. オートコンプリートとの明確な棲み分け

→オートコンプリート (Completable 設定): クエリ「文字列」の候補を提案
→Search-as-you-type: マッチする「ドキュメント」を返す
→両者は補完関係にあり、組み合わせて検索 UX を設計できる

🛠️ 設定方法

📋 前提条件

✓Vertex AI Search (Agent Search) のカスタム検索アプリとデータストアが作成済みであること
✓データストアにスキーマが定義されている (または自動検出されている) こと
1

フィールド設定の確認

Google Cloud コンソールの AI Applications からデータストアのスキーマを開き、対象フィールドの設定を確認します。スキーマは API からも取得できます。

Bash スキーマ定義の取得例 
# スキーマ定義の取得例
curl -X GET \
  -H "Authorization: Bearer $(gcloud auth print-access-token)" \
  "https://discoveryengine.googleapis.com/v1/projects/PROJECT_ID/locations/global/collections/default_collection/dataStores/DATA_STORE_ID/schemas/default_schema"
2

Search-as-you-type を有効化するフィールドの設定

公式ドキュメント「Configure field settings」の手順に従い、Search-as-you-type をサポートさせたいフィールドの設定を更新します。

💡 ヒント: 他のフィールド設定と同様、スキーマ更新後は再インデックスの完了を待ってから動作を確認してください。

🎯 メリット

💼 ビジネス面

✓検索体験の向上によるコンバージョン改善: フルクエリ入力なしで目的のドキュメント (商品、記事など) に到達でき、検索の離脱を減らし目的達成までの時間を短縮
✓自前実装コストの削減: インクリメンタル検索のような体験を、マネージドな検索エンジンのフィールド設定で実現

⚙️ 技術面

✓キーストロークごとのランキング済み結果: 単純な前方一致ではなく、Agent Search のランキングが適用されたドキュメントリストが返される
✓フィールド単位の制御: どのフィールドを対象にするかをスキーマ設定で選択でき、検索品質とインデックスサイズのバランスを調整可能

⚠️ デメリット・制約事項

🚧 制限事項

✗Public Preview 段階の機能であり、GA 前に仕様が変更される可能性がある
✗対象はカスタム検索アプリ (custom search apps) であり、スキーマのフィールド設定が前提となる

🤔 考慮すべき点

💰 クエリ課金への影響: キーストロークごとに検索結果が返される特性上、確定クエリのみを送信する場合と比べて検索リクエスト数が増加しうるため、クエリ課金 (従量課金または configurable pricing の QPM サブスクリプション) への影響を事前に見積もること。
🔄 再インデックスが必要: 他のフィールド設定 (Searchable、Prefix matchable など) と同様、設定変更後は再インデックスが必要。検証環境で挙動を確認してから本番適用することを推奨。

🔗 関連サービス・機能

💬 オートコンプリート (Configure autocomplete)

クエリ文字列の候補を提案する機能。Search-as-you-type はドキュメントを返す点で異なり、組み合わせて検索 UX を設計できる。

🗂️ フィールド設定 (Searchable / Indexable / Retrievable / Prefix matchable / Partially matchable)

Search-as-you-type と同じく、スキーマのフィールド単位で検索挙動を制御する設定群。

🎛️ サービングコントロール (Boost/Bury、Synonyms、Promote)

検索結果のランキングや表示を調整する機能で、Search-as-you-type の結果品質向上にも寄与する。
