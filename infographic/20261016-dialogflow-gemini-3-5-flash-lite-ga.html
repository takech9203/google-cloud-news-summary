💬 Dialogflow: gemini-3.5-flash-lite が一般提供 (GA) 開始

Dialogflow (Conversational Agents / Dialogflow CX) Gemini 3.5 Flash-Lite GA (一般提供)
📅 リリース日: 2026-10-16

📝 概要

Dialogflow (Conversational Agents / Dialogflow CX) で、Google の最新コスト効率モデル gemini-3.5-flash-lite が 一般提供 (GA) になりました。 プレイブック (Playbooks) とデータストアの要約モデルの選択肢として GA 掲載され、本番環境の会話型エージェントで SLA 対象外の Preview ではなく GA ステータスで最新 Flash-Lite 系モデルを利用できます。

Gemini 3.5 Flash-Lite は、シンプルなコーディングタスク、正確なドキュメント理解、低コスト・高速推論が求められる 軽量なエージェントワークフロー向けに最適化されており、思考レベル (thinking level) の調整で品質・速度・トークン出力のバランスを制御できます。

💡 あわせて確認: Gemini 3 以降のモデルは、従来のリージョン単位クォータとは異なる マルチリージョン / グローバル単位のクォータ体系 (Generative quotas) を使用します。 クォータ引き上げのリクエスト方法が変わる点に注意が必要です。

❌ アップデート前の課題

  • GA で利用できる最新の Flash-Lite 系モデルは gemini-3.1-flash-lite までで、最新世代の gemini-3.5-flash-lite を本番ワークロードの GA モデルとして選択できなかった
  • Gemini 3 以降のクォータは従来の ConversationalAgentLlmTokenConsumption (リージョン単位) と異なる体系で管理され、コンソールに該当クォータが表示されない場合の引き上げ申請方法がわかりにくかった

✅ アップデート後の改善

  • gemini-3.5-flash-lite が プレイブック・データストア要約などの選択肢として GA になり、本番環境で利用可能に
  • 最大 1,048,576 トークンのコンテキストと最大 65,536 トークンの出力を、低コスト・低レイテンシな会話ワークロードに適用可能に
  • Gemini 3 以降向けクォータの引き上げリクエスト手順 (gcloud コマンド) が公式ドキュメントで案内された

Dialogflow CX エージェントのプレイブックやデータストア要約で gemini-3.5-flash-lite を選択できるようになり、 トークン消費は Gemini 3 以降専用のマルチリージョン / グローバルクォータで管理されます。

⚙️ 主要機能

1️⃣ gemini-3.5-flash-lite の GA 提供

→プレイブックのモデルサポート表に GA として掲載 (gemini-2.5-flash、gemini-2.5-flash-lite、gemini-3.1-flash-lite と並ぶ選択肢)
→データストアの要約モデル (summarization model) の選択肢としても GA として掲載
→エージェントレベル (Agent settings → Generative AI → Playbook) またはリクエストレベル (DetectIntentRequest.query_params.llm_model_settings.model) でモデルを選択可能

2️⃣ コスト効率と速度に最適化されたモデル特性

→Flash-Lite 系列の最新モデルで、高スループットの分類・ルーティング・抽出タスクや軽量なエージェントワークフロー向け
→思考レベル (thinking level) を MINIMAL / LOW / MEDIUM / HIGH から選択可能。デフォルトは MINIMAL (速度・コスト効率を優先)
→Gemini 2.5 Flash や複雑度の低い Gemini 3 Flash ワークロードの移行先として位置付け

3️⃣ Gemini 3 以降のモデル向けクォータ体系

→生成系機能 (Generators、Generative fallback、Playbook、Data store) の LLM トークン消費はデフォルト 600,000 トークン/分
→米国内リージョンは multi_region=us、欧州リージョンは multi_region=eu の ConversationalAgentMultiRegionLLMTokenConsumption クォータ、その他 (global 含む) は ConversationalAgentGlobalLLMTokenConsumption クォータを使用
→コンソールにディメンション付きクォータが表示されない場合は gcloud beta quotas preferences create コマンドで引き上げをリクエスト可能

🛠️ 設定方法

📋 前提条件:
✓Dialogflow CX (Conversational Agents) のエージェントが作成済みであること
✓プレイブック、データストア、ジェネレーターなどの生成系機能を使用していること
1

モデルの選択

Conversational Agents コンソール で Agent settings → Generative AI → Playbook からモデル一覧の表示名で gemini-3.5-flash-lite を選択します。 API の場合は GenerativeSettings.llm_model_settings.model フィールドにモデル名を指定します。 データストアの要約モデルは、データストア設定の要約モデル選択で gemini-3.5-flash-lite を選択します。

2

クォータの確認・引き上げリクエスト (必要な場合)

Gemini 3 以降のモデル用のディメンション付きクォータがコンソールに表示されない場合は、以下の gcloud コマンドで引き上げをリクエストできます。

Bash クォータ引き上げリクエスト例 
PROJECT_ID=your-project
TARGET_TPM=1000000
MULTI_REGION=us
BASE_MODEL=gemini-3.5-flash-lite
USER_EMAIL=user@example.com
REASON="Reason for requesting higher multi-region token per minute limit"

gcloud beta quotas preferences create \
  --service=dialogflow.googleapis.com \
  --project="${PROJECT_ID}" \
  --billing-project="${PROJECT_ID}" \
  --quota-id=ConversationalAgentMultiRegionLLMTokensPerMinutePerBaseModel \
  --preferred-value=${TARGET_TPM} \
  --dimensions=multi_region=${MULTI_REGION},base_model=${BASE_MODEL} \
  --email="${USER_EMAIL}" \
  --justification="${REASON}"
3

トークン使用量のモニタリング

Cloud Monitoring の Metrics Explorer で「Conversational Agent LLM tokens quota usage」メトリクスを選択し、 location と base_model ディメンションで集計することで、リージョン・モデル別のトークン消費を可視化できます。

⚖️ メリットと制約事項

👍 メリット

💼 ビジネス面

  • 運用コストの最適化: Flash-Lite 系列はコスト効率重視のモデルラインで、大量の会話トラフィックを処理するコンタクトセンターやチャットボットの LLM コストを抑制
  • 本番利用の安心感: GA ステータスとなり、本番ワークロードでの採用判断がしやすい

🔧 技術面

  • 低レイテンシ: デフォルトの minimal thinking により、分類・ルーティング・抽出などの高スループットタスクで高速応答
  • 大規模コンテキスト: 1,048,576 トークンで長い会話履歴や大量の参照情報を処理
  • 柔軟な品質調整: 思考レベル (MINIMAL / LOW / MEDIUM / HIGH) でタスクの複雑さに応じた品質と速度のバランス調整

⚠️ 制限事項・考慮点

🚫 制限事項

  • temperature、top-K、top-P のカスタム値は非サポート (設定しても無視)
  • frequency penalty / presence penalty のカスタム値を設定するとエラー
  • モデルのチューニング (fine-tuning) は非サポート
  • 最後の入力ターンのロールが Model であるリクエストは非サポート

🤔 考慮すべき点

  • Gemini 3 以降はクォータ体系が Gemini 2.5 系と異なり、既存のクォータ引き上げ設定は引き継がれない
  • 複数ステップのツール呼び出しを行うエージェント用途では、minimal thinking のままだとツール実行が途中で終了する可能性があるため、thinking level を medium 以上に設定することを推奨
  • 既定パラメータ挙動が従来モデルと異なるため、既存エージェントの移行時は十分なテストが必要

🎯 ユースケース

🛒 ユースケース 1: 高トラフィックなカスタマーサポートボットのコスト最適化

シナリオ: EC サイトのカスタマーサポートで、FAQ 応答やデータストアに基づく回答の要約を行うエージェントを運用しており、月間数百万ターンの会話を処理している。

実装例: データストアの要約モデルを gemini-3.5-flash-lite に変更し、minimal thinking で高速・低コストに要約を生成する。

効果: 最新世代モデルの品質を維持しながら、低レイテンシでの応答とコスト効率の向上が期待できる。

🔀 ユースケース 2: 意図分類・ルーティング用プレイブックの高速化

シナリオ: 問い合わせ内容を分類して適切なフローやプレイブックへルーティングする前段処理を LLM で行っている。

効果: gemini-3.5-flash-lite は高スループットの分類・ルーティングタスクに適しており、minimal thinking により応答速度を優先した処理が可能。
