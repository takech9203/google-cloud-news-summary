Cloud Storage Preview 📅 リリース日: 2026-10-30

🪣 Storage Intelligence advisor にセキュリティ・コンプライアンス検出結果が登場

CMEK ポリシー違反・暗号化強制ルール違反のオブジェクトを自動検出し、一括再暗号化で是正

📌 概要

Storage Intelligence advisor に「セキュリティとコンプライアンス」カテゴリの検出結果 (Findings) が Preview として追加されました。 デフォルトの顧客管理暗号鍵 (CMEK) ポリシーに違反するオブジェクトや、バケットで強制されている暗号化ルールに違反するオブジェクトを含むバケットを自動的に特定し、該当オブジェクトを再暗号化して是正できます。

Storage Intelligence を有効化すると、advisor がバックグラウンドで自動的にセキュリティリスク評価を実行し、検出結果を 24 時間ごとに更新します。オブジェクトレベルの暗号化違反はバケット単位に集約されるため、アラート量を抑えつつダッシュボードで状況を把握できます。影響を受けるオブジェクトは BigQuery の Storage Insights データセットで特定し、Storage バッチオペレーションまたは gcloud CLI で再暗号化します。

❌ Before: アップデート前の課題

  • バケットにデフォルト Cloud KMS 鍵を設定しても、設定前の既存オブジェクトは再暗号化されず、GMEK / CSEK のまま残存
  • CMEK 違反オブジェクトの特定には、自前のメタデータ収集・分析基盤の構築が必要
  • プロジェクト・フォルダ・組織全体の暗号化コンプライアンスを一元的に把握する手段がなかった

✅ After: アップデート後の改善

  • Storage Intelligence を有効化するだけで暗号化メタデータが自動評価され、違反バケットが advisor ダッシュボードに表示
  • 2 種類の検出結果により、違反の種類に応じた是正手順が明確に
  • Storage Insights の参照 SQL クエリ + Storage バッチオペレーションで大規模な再暗号化を効率的に実行
💡 こんな人に: CMEK による暗号化を組織ポリシーやコンプライアンス要件として義務付けている企業のセキュリティ管理者・ストレージ管理者。暗号化コンプライアンスの継続的な監視と是正を大幅に効率化できます。

⚡ 主要機能

🔑 1. 「Objects violate default CMEK bucket policies」検出結果

デフォルトの Cloud KMS 鍵が設定されたバケット (encryption.defaultEncryptionType が CMEK) に、CMEK で暗号化されていないオブジェクト (GMEK や CSEK) が 1 つ以上含まれる場合に検出。

→例: デフォルト Cloud KMS 鍵の設定前にアップロードされたオブジェクト
→Storage Insights データセットで違反オブジェクトを特定し、バケットのデフォルト Cloud KMS 鍵で再暗号化して是正

🚫 2. 「Objects violate enforced encryption rules」検出結果

バケットの暗号化強制設定 (encryption enforcement configuration) で制限されている暗号化方式を使用するオブジェクトが含まれる場合に検出。

→例: GMEK や CSEK を制限する前にアップロードされた、それらの方式で暗号化されたオブジェクト
→許可された暗号化方式でオブジェクトを再暗号化して是正

🤖 3. 自動評価と検出結果の集約

✓プロジェクト・フォルダ・組織をまたいで、バケットレベル・オブジェクトレベルの暗号化メタデータを自動評価
✓初回ベースライン検出は有効化から 48 時間以内、以降 24 時間ごとに更新
✓オブジェクトレベルの違反はバケット単位に集約され、ダッシュボードのアラート量を抑制

🔍 4. 検出結果の詳細ビュー

✓コンソールの Storage Intelligence Advisor ページで、カテゴリ・最終更新時刻・共通要因・影響バケットを確認
✓バケット詳細パネルで、暗号化構成・影響オブジェクトの件数と割合・参照 SQL クエリを確認可能

🔀 再暗号化方式の選択

シナリオ推奨される対応
影響オブジェクトが GMEK (標準暗号化)BigQuery から CSV マニフェストをエクスポートし、Storage バッチオペレーションで一括再暗号化

🗄️ 違反オブジェクトの特定クエリ例 (BigQuery)

SQL 非 CMEK オブジェクトの特定 
SELECT bucket, name, encryptionType
FROM `DATASET_NAME.object_attributes_latest_snapshot_view`
WHERE bucket = 'BUCKET_NAME'
  AND encryptionType != 'CMEK'
  AND timeDeleted IS NULL
  AND softDeleteTime IS NULL;

1

Storage Intelligence を有効化する

Bashプロジェクトレベルでの有効化
gcloud storage intelligence-configs enable --project=PROJECT_ID

プロジェクトのほか、--sub-folder や --organization フラグでフォルダ・組織レベルでも構成できます。有効化から 48 時間以内に初回のベースライン検出結果が表示されます。

2

検出結果を確認する

Google Cloud コンソールの Storage Intelligence Advisor ページでリソースを選択し、「Top findings」セクションから対象の検出結果の「View details」をクリック。「Default CMEK buckets with non-CMEK encrypted objects」などのバケットテーブルで影響バケットを特定し、デフォルト KMS 鍵のリソース名を控えます。

3

違反オブジェクトのマニフェストをエクスポートする (GMEK の場合)

SQLCSV マニフェストのエクスポート
EXPORT DATA OPTIONS(
  uri='gs://DESTINATION_BUCKET/manifests/objects_violating_default_policies_*.csv',
  format='CSV', overwrite=true, header=true
) AS
SELECT bucket, name
FROM `DATASET_NAME.object_attributes_latest_snapshot_view`
WHERE bucket = 'BUCKET_NAME'
  AND encryptionType = 'GMEK'
  AND timeDeleted IS NULL
  AND softDeleteTime IS NULL;

BigQuery で EXPORT DATA クエリを実行し、再暗号化対象オブジェクトの CSV マニフェストを Cloud Storage に出力します。

4

Storage バッチオペレーションで再暗号化する

Bashバッチジョブによる一括再暗号化
gcloud storage batch-operations jobs create JOB_NAME \
  --bucket="BUCKET_NAME" \
  --manifest-location="gs://DESTINATION_BUCKET/manifests/objects_violating_default_policies_*.csv" \
  --rewrite-object="kms-key=DEFAULT_KMS_KEY"

オブジェクトを変更する前にジョブ構成を検証するには --dry-run フラグを付与します。CSEK オブジェクトは gcloud storage objects update に --decryption-keys と --encryption-key を指定して個別に再暗号化します。

👍 メリット

💼 ビジネス面

✓コンプライアンス監視の自動化: CMEK 義務化などの暗号化要件に対する違反を自動検出。カスタムのレポート基盤 (データ処理パイプラインや BigQuery スクリプトの自作・保守) なしで継続的な監査が可能に
✓一元的な可視性: プロジェクト・フォルダ・組織をまたいで Cloud Storage 環境全体の暗号化コンプライアンス状況を単一のインターフェースで把握

⚙️ 技術面

✓大規模な是正の効率化: BigQuery のマニフェストエクスポートと Storage バッチオペレーションの組み合わせで、大量の違反オブジェクトを一括再暗号化
✓ノイズの少ないアラート: オブジェクトレベルの違反がバケット単位に集約され、大量の違反があってもダッシュボードが煩雑にならない

⚠️ デメリット・制約事項

🚧 制限事項

✗Preview 段階の機能であり、Pre-GA Offerings Terms が適用される。サポートが限定される可能性がある
✗初回のベースライン検出まで最大 48 時間、以降の更新は 24 時間周期で、リアルタイム検出ではない
✗CSEK オブジェクトはバッチオペレーションで復号できないため、gcloud CLI で復号鍵を指定した個別対応が必要

🤔 考慮すべき点

⚠️ 検出結果がクリアされない条件に注意:
  • オブジェクトバージョニングが有効な場合、再書き込み後も非 CMEK の非現行バージョンが残るため、非現行バージョンを削除するかライフサイクルの Delete ルールを構成するまで検出結果はクリアされない
  • ソフト削除が有効な場合も、保持期間が終了するまで元の違反オブジェクトが残り、検出結果が継続する
→BigQuery でのクエリ実行とデータエクスポートには BigQuery の料金が発生する
→Storage Intelligence 自体が有料機能であり、管理対象データ量に応じたコストが発生する

🎯 ユースケース

🏦 ユースケース 1: CMEK 義務化環境での暗号化コンプライアンス監査

シナリオ: 金融機関が全社ポリシーとして Cloud Storage オブジェクトの CMEK 暗号化を義務付けているが、デフォルト KMS 鍵の設定前にアップロードされた既存オブジェクトが GMEK のまま残っていないか定期的に監査したい。

Bash組織レベルでの有効化
# 組織レベルで Storage Intelligence を有効化
gcloud storage intelligence-configs enable --organization=ORGANIZATION_ID

# 検出結果はコンソールの Storage Intelligence Advisor ページで確認
# 違反オブジェクトは Storage Insights データセット (BigQuery) で特定
✅ 効果: 組織全体の暗号化違反が 24 時間ごとに自動評価され、手動監査の工数を削減しながらコンプライアンス違反の見落としを防止できる。

🔄 ユースケース 2: 暗号化強制ルール導入後の既存オブジェクトの一括是正

シナリオ: バケットに GMEK / CSEK を制限する暗号化強制設定を導入したが、導入前にアップロードされた制限対象オブジェクトが大量に残っており、許可された暗号化方式へ効率的に移行したい。

✅ 効果: 「Objects violate enforced encryption rules」検出結果で影響バケットと参照 SQL クエリが提示され、Storage バッチオペレーションで大量オブジェクトを一括再暗号化できる。是正完了後は次回の 24 時間更新サイクルで検出結果が自動的にクリアされる。

💰 料金

Storage Intelligence の料金は、使用する機能と管理対象のデータ量に依存します。30 日間の無料トライアル (TRIAL エディション) も提供されており、トライアル終了後は自動的に STANDARD エディションに移行します。

💡 関連コストに注意: 違反オブジェクトの特定に使用する BigQuery のクエリ・エクスポート、再暗号化に使用する Storage バッチオペレーションや Cloud KMS にもそれぞれ料金が発生します。

詳細は Storage Intelligence の料金ページ を参照してください。
