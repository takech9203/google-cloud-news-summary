🔀 Apigee hybrid v1.16.14 リリース

Model Armor ポリシーの Function Calling 対応・バグ修正・セキュリティ修正
📅 リリース日: 2026-11-11
Apigee hybrid Model Armor パッチリリース CVE 修正あり

📋 概要

2026 年 11 月 11 日、Apigee hybrid v1.16.14 がリリースされました。パッチリリースのため、Helm チャートでのアップグレードによりコンテナイメージも自動更新されます。

最大の機能強化は、Model Armor と連携する SanitizeUserPrompt / SanitizeModelResponse ポリシーが LLM の Function Calling (ツール使用) フローに対応したことです。新しいオプション XML 要素 <FunctionResponseSource> と <FunctionCallSource> により、関数呼び出しのコンテンツを抽出して Model Armor でサニタイズできます。AI エージェントや LLM アプリケーションを Apigee hybrid 経由で保護する組織にとって、エージェンティックなワークフローのセキュリティ カバレッジが大きく向上します。

❌ アップデート前の課題

  • SanitizeUserPrompt の <UserPromptSource> は最後のコンテンツ エントリのテキストを抽出するため、Function Calling のターンでは抽出結果が空になり、外部 API やデータベース由来の信頼できない関数レスポンスが Model Armor のサニタイズ対象外だった
  • SanitizeModelResponse の <LLMResponseSource> は、モデルが関数呼び出しを返すターンでは空を返し、関数呼び出しの引数がサニタイズされなかった
  • Synchronizer の pollInterval 設定が apigee-env Helm チャートと Apigee オペレーターに無視されていた
  • 圧縮された text/event-stream レスポンスが EventFlow を持つプロキシを通過するとボディが破損していた
  • Model Armor ポリシーが HTTPClient.managementplane.skip.proxy 設定を尊重せず、フォワード プロキシをバイパスできなかった
  • 複数のコンテナ イメージに既知の脆弱性 (CVE) が存在していた

✅ アップデート後の改善

  • <FunctionResponseSource> (SanitizeUserPrompt) により、ユーザーターン内の関数/ツール レスポンス データを抽出してサニタイズ可能に (<UserPromptSource> が空の場合のフォールバック)
  • <FunctionCallSource> (SanitizeModelResponse) により、関数呼び出し引数を抽出してサニタイズ可能に (<LLMResponseSource> が空の場合のフォールバック)
  • デフォルト テンプレートは Gemini フォーマット対象で追加設定なしで動作 (OpenAI / Anthropic はカスタム JSONPath で対応)
  • SSE ストリームの連続スキャン (ContinuousScan) が双方向 gRPC ストリーミングに対応し、SSE JSON エンベロープとイベント フレーミングを保持
  • Apigee アナリティクスが Model Armor のテンプレート・判定 (verdict)・一致フィルタをリクエストごとにレポート
  • 6 つのコンテナ イメージの CVE が修正され、セキュリティ態勢が向上

LLM の Function Calling フローにおいて、新しい <FunctionResponseSource> と <FunctionCallSource> 要素がフォールバックとして機能し、関数レスポンスと関数呼び出し引数の両方を Model Armor でサニタイズする流れ

⚡ 主要機能

🛡️ 1. SanitizeUserPrompt / SanitizeModelResponse ポリシーの Function Calling 対応

→<FunctionResponseSource> (SanitizeUserPrompt): ユーザーターンから関数/ツール レスポンス データを抽出。Function Calling のターンで <UserPromptSource> が空を返す場合のフォールバック。関数レスポンスには外部 API やデータベース由来の信頼できないデータが含まれるためサニタイズが必要
→<FunctionCallSource> (SanitizeModelResponse): モデル レスポンスから関数呼び出し引数を抽出。<LLMResponseSource> が空を返す場合のフォールバック
→デフォルト テンプレートは Gemini フォーマット対象で追加設定不要。OpenAI / Anthropic フォーマットにはカスタム JSONPath テンプレートを設定

📝 ポリシー設定例

XML SanitizeUserPrompt ポリシー 
<SanitizeUserPrompt async="false" continueOnError="false" enabled="true" name="sanitize-prompt">
  <IgnoreUnresolvedVariables>true</IgnoreUnresolvedVariables>
  <ModelArmor>
    <TemplateName>projects/{project}/locations/{location}/templates/{template-name}</TemplateName>
  </ModelArmor>
  <UserPromptSource>{jsonPath('$.contents[-1].parts[-1].text',request.content)}</UserPromptSource>
  <FunctionResponseSource>{jsonPath('$.contents[-1].parts[-1].functionResponse.response',request.content)}</FunctionResponseSource>
</SanitizeUserPrompt>
XML SanitizeModelResponse ポリシー 
<SanitizeModelResponse async="false" continueOnError="false" enabled="true" name="sanitize-response">
  <IgnoreUnresolvedVariables>true</IgnoreUnresolvedVariables>
  <ModelArmor>
    <TemplateName>projects/{project}/locations/{location}/templates/{template-name}</TemplateName>
  </ModelArmor>
  <UserPromptSource>{jsonPath('$.contents[-1].parts[-1].text',request.content)}</UserPromptSource>
  <LLMResponseSource>{jsonPath('$.candidates[-1].content.parts',response.content)}</LLMResponseSource>
  <FunctionCallSource>{jsonPath('$.candidates[-1].content.parts[-1].functionCall.args',response.content)}</FunctionCallSource>
  <ContinuousScan>false</ContinuousScan>
</SanitizeModelResponse>

⚠️ デメリット・制約事項

🚧 制限事項

✗<FunctionResponseSource> / <FunctionCallSource> のデフォルト値は Gemini フォーマット対象。OpenAI / Anthropic フォーマットではカスタム JSONPath テンプレートの設定が必要
✗SanitizeUserPrompt / SanitizeModelResponse は Extensible ポリシーであり、Apigee のライセンスによってはコストや利用量への影響がある
✗Synchronizer の pollInterval は 60 秒未満を設定しても 60 秒に引き上げられる
✗ContinuousScan 使用時、Model Armor の Sensitive Data Protection (SDP) による匿名化 (redacted) テキストはクライアントに配信されない

🤔 考慮すべき点

⚠️ アップグレード時の注意:
  • パッチリリースのため、Helm チャートでのアップグレードによりコンテナ イメージが自動更新される。手動でイメージを管理している場合は注意
  • CVE 修正が含まれるため、セキュリティの観点から早期のアップグレードが推奨される
  • gRPC エラー挙動の変更: 不正フレームが UNAVAILABLE (14) から INTERNAL (13) に、ExternalCallout のサービス アカウント不存在が UNAVAILABLE (14) から UNAUTHENTICATED (16) に変更。gRPC ステータス コードに依存した監視・リトライ ロジックへの影響を確認すること
  • Model Armor コールアウトのフォワード プロキシ経由の挙動が変更されている (HTTPClient.managementplane.skip.proxy 設定時のバイパス) ため、プロキシ環境でのネットワーク経路を確認すること

🎯 ユースケース

🤖 ユースケース 1: AI エージェント ゲートウェイでのツール レスポンスの検査

シナリオ: Apigee hybrid を AI エージェントのゲートウェイとして使用し、エージェントが外部 API (検索、データベース照会など) をツールとして呼び出す構成。外部 API のレスポンスには信頼できないデータが含まれる可能性があり、間接的なプロンプト インジェクションのリスクがある。

XML 実装例 
<SanitizeUserPrompt name="SUP-agent-gateway">
  <ModelArmor>
    <TemplateName>projects/my-project/locations/us-west1/templates/agent-template</TemplateName>
  </ModelArmor>
  <!-- Gemini 形式の場合はデフォルトで Function Calling ターンをカバー -->
</SanitizeUserPrompt>

効果: エージェントのツール呼び出し結果が LLM に渡る前に Model Armor で検査され、ツール レスポンス経由の間接プロンプト インジェクションや悪意ある URL の混入を検出・ブロックできる。

🔐 ユースケース 2: 関数呼び出し引数の漏えい防止

シナリオ: LLM がテキストではなく関数呼び出し (functionCall) を返す場合に、その引数に機密データや不適切な内容が含まれないか検査したい。

効果: <FunctionCallSource> により、モデルが生成した関数呼び出し引数が実際のツール実行前に Model Armor でサニタイズされ、機密データの外部ツールへの流出や不正な引数によるツールの悪用を防止できる。

🩹 ユースケース 3: CVE 対応のためのパッチ適用

シナリオ: セキュリティ チームの脆弱性スキャンで apigee-asm-ingress や apigee-fluent-bit などのコンテナに CVE が検出されており、対応が求められている。

効果: Helm チャートで v1.16.14 にアップグレードするだけで、対象コンテナ イメージの CVE 修正が自動的に適用され、脆弱性スキャンの指摘に対応できる。

💰 料金

Apigee hybrid 自体のパッチ適用に追加料金は発生しません。SanitizeUserPrompt / SanitizeModelResponse ポリシーは Extensible ポリシーであり、Apigee のライセンス (サブスクリプションまたは従量課金) によってコストや利用量への影響が異なります。また、Model Armor の利用には Model Armor 側の料金が別途適用されます。

🌏 利用可能リージョン

Apigee hybrid はユーザー管理の Kubernetes クラスタ上で動作するため、ランタイムのリージョン制約はユーザー環境に依存します。Model Armor テンプレートはリージョン リソースであるため、利用可能なロケーションは Model Armor のドキュメントを参照してください。

🔗 関連サービス・機能

🛡️ Model Armor

LLM のリスク軽減のための AI セキュリティ サービス。SanitizeUserPrompt / SanitizeModelResponse ポリシーのバックエンドとして、プロンプト インジェクション検出、機密データ保護 (SDP)、悪意ある URI 検出などのフィルタを提供。

☁️ Apigee (SaaS 版)

同じ SanitizeUserPrompt / SanitizeModelResponse ポリシーが利用可能。hybrid はユーザー管理の Kubernetes 上でランタイムを運用する形態。

🕸️ Cloud Service Mesh (ASM)

Apigee hybrid のイングレス (apigee-asm-ingress) とコントロール プレーン (apigee-asm-istiod) として使用されており、今回の CVE 修正の対象。

🔍 Sensitive Data Protection (旧 Cloud DLP)

Model Armor テンプレートの SDP フィルタとして、機密データの検査・匿名化に使用される。

📊 Cloud Monitoring / Apigee Analytics

今回の修正により、Model Armor のテンプレート・判定・一致フィルタがアナリティクスでリクエストごとにレポートされる。

Apigee hybrid v1.16.14 は、Model Armor 連携ポリシーの LLM Function Calling 対応という AI セキュリティ上の重要な機能強化と、複数コンテナの CVE 修正を含むパッチリリースです。Apigee hybrid を AI ゲートウェイとして活用している、またはエージェンティックな AI ワークロードを保護したい組織は、早期のアップグレードを推奨します。gRPC エラー ステータスの挙動変更があるため、アップグレード前に監視・エラー ハンドリングへの影響を確認してください。
