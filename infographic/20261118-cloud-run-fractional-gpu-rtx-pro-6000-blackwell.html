⚡ Cloud Run Preview

🎮 NVIDIA RTX PRO 6000 Blackwell の
フラクショナル GPU (0.5 GPU) 対応

リリース日: 2026-11-18

📝 概要

Cloud Run のサービス・ジョブ・ワーカープールで、NVIDIA RTX PRO 6000 Blackwell GPU の フラクショナル GPU (0.5 GPU) を構成できるようになりました (Preview)。 従来は GPU 1 基全体 (96 GB VRAM) の割り当てが必須でしたが、0.5 GPU (48 GB VRAM) 単位での割り当てが可能になります。

フル GPU 性能を必要としない中小規模の LLM や画像生成モデルの推論に対して、Blackwell アーキテクチャの高性能を享受しながら GPU 割り当てを削減できる、コスト効率の高い選択肢です。CPU・メモリの最小構成もフル GPU の約半分 (10 CPU / 40 GiB 以上) に緩和されています。

❌ Before: アップデート前の課題

  • VRAM を 48 GB しか使わないワークロードでも GPU 1 基全体 (96 GB VRAM) の割り当てが必要
  • フル GPU 構成では最低 20 CPU / 80 GiB メモリが必須で、小規模推論にはリソースもコストも過剰
  • 稼働できる GPU インスタンス数が GPU 基数に制限され、小さなモデルを多数のサービスに分散配置しにくい

✅ After: アップデート後の改善

  • 0.5 GPU (48 GB VRAM) 単位で割り当て可能になり、推論をコスト効率よく実行できる
  • 10/12/14/16 CPU と 40 GiB 以上のメモリで構成でき、最小要件がフル GPU の約半分に
  • クォータが milliGPU 単位 (フル = 1,000 / 0.5 = 500) で管理され、同じクォータで最大 2 倍のインスタンスを稼働可能
  • サービス、ジョブ、ワーカープールのすべてで利用可能

1 基の物理 GPU を 0.5 GPU (48 GB VRAM) 単位に分割し、複数の Cloud Run インスタンスがそれぞれ独立したフラクションを利用できます。 これにより同じ GPU クォータでより多くのインスタンスを稼働できます。

⚙️ 主要機能

🧩 1. 0.5 GPU 単位のフラクショナル割り当て

✓--gpu 0.5 の指定で RTX PRO 6000 Blackwell の半分 (48 GB VRAM) をインスタンスに割り当て
✓フラクショナル GPU のタイプは GRID、ドライバーはフル GPU と同じ 580.x.x (CUDA 13.0)
✓サービス、ジョブ、ワーカープールのすべてで利用可能

🖥️ 2. CPU・メモリ最小要件の緩和

✓10、12、14、16 CPU のいずれかを選択可能 (フル GPU は最低 20 CPU)
✓メモリは最低 40 GiB、CPU あたり最大 4 GiB まで構成可能 (フル GPU は最低 80 GiB)

📊 3. milliGPU 単位のクォータ管理

✓nvidia-rtx-pro-6000 のクォータは milliGPU 単位 (フル GPU = 1,000 / 0.5 GPU = 500 milliGPU)
✓リージョン初回デプロイ時に 3,000 milliGPU (ゾーン冗長性オフ) を自動付与 → フル GPU 3 基またはフラクショナル GPU 6 基に相当

🛠️ 設定方法

前提条件

✓Cloud Run API が有効化されていること
✓Cloud Run デベロッパー (roles/run.developer) とサービスアカウントユーザー (roles/iam.serviceAccountUser) のロール
✓フラクショナル GPU 対応リージョン (us-central1 または europe-west4) にデプロイ
✓必要に応じて milliGPU クォータの引き上げをリクエスト

ステップ 1: フラクショナル GPU 付きサービスをデプロイ

Bash gcloud run deploy 
gcloud run deploy SERVICE \
  --image IMAGE_URL \
  --gpu 0.5 \
  --gpu-type nvidia-rtx-pro-6000 \
  --cpu 10 \
  --memory 40Gi \
  --no-cpu-throttling \
  --region us-central1
💡 ポイント: --gpu に 0.5 を指定するとフラクショナル GPU、1 を指定するとフル GPU が割り当てられます。CPU は 10/12/14/16 のいずれか、メモリは 40 GiB 以上 (CPU あたり最大 4 GiB) を指定します。

ステップ 2: 既存サービスの GPU 構成を更新

Bash gcloud run services update 
gcloud run services update SERVICE \
  --gpu 0.5 \
  --gpu-type nvidia-rtx-pro-6000 \
  --cpu 10 \
  --memory 40Gi \
  --no-gpu-zonal-redundancy

ゾーン冗長性をオフ (--no-gpu-zonal-redundancy) にすると GPU 秒あたりの単価が下がります。構成変更により新しいリビジョンが作成されます。

ステップ 3: GPU 設定の確認

Bash gcloud run services describe 
gcloud run services describe SERVICE

返された構成の GPU 設定 (nvidia.com/gpu と run.googleapis.com/accelerator) を確認します。

💡 メリット

💼 ビジネス面

✓GPU コストの削減: フル GPU を必要としない推論ワークロードで GPU 割り当てを半分にでき、CPU・メモリの最小構成も約半分になるため、インスタンスあたりの総コストを大幅に削減
✓スモールスタートの実現: 同じ自動付与クォータ (3,000 milliGPU) で最大 6 インスタンスまで稼働でき、小規模から GPU 推論サービスを開始しやすい

⚙️ 技術面

✓Blackwell アーキテクチャの活用: 割り当てを半分にしても最新 Blackwell 世代の性能・機能 (CUDA 13.0) をそのまま利用可能
✓フルマネージドな GPU 共有: ドライバーや分割設定の管理は不要で、--gpu 0.5 の指定だけで利用可能。スケールツーゼロやオンデマンド割り当てなど Cloud Run GPU の特性はそのまま
✓柔軟なリソース設計: 10〜16 CPU、40 GiB〜のメモリを VRAM 48 GB と組み合わせ、ワークロードに最適なサイズを選択可能

⚠️ デメリット・制約事項

制限事項

✗Preview 段階の機能であり、Pre-GA Offerings Terms が適用される (SLA やサポートが限定される可能性)
✗フラクショナル GPU は NVIDIA RTX PRO 6000 Blackwell のみ対応で、L4 GPU では利用不可
✗分割単位は 0.5 GPU (48 GB VRAM) のみ
✗対応リージョンは us-central1 (アイオワ) と europe-west4 (オランダ) の 2 リージョンのみ (フル GPU は asia-southeast1、asia-south2 でも利用可能)
✗CPU は 10/12/14/16 のいずれかに限定、メモリは CPU あたり最大 4 GiB までという上限がある

考慮すべき点

⚠VRAM が 48 GB に制限されるため、モデルサイズと KV キャッシュの合計が収まるか事前検証が必要
⚠フラクショナル GPU の既知の問題 (Known issues) がドキュメントに記載されているため、本番利用前に確認が必要
⚠ゾーン冗長性オフは低価格だがフェイルオーバーはベストエフォート。可用性要件とのバランスを検討する
⚠ワーカープールは GPU の自動スケーリングに非対応。プロセスが動いていなくてもインスタンス稼働中は GPU が課金される

🎯 ユースケース

🤖 ユースケース 1: 中規模 LLM のオンライン推論 API

シナリオ: 48 GB VRAM に収まる中規模のオープンモデル (量子化済みモデルなど) を Cloud Run サービスとして公開し、リクエスト量に応じてスケールさせたい。フル GPU ではコストが見合わない。

Bash vLLM サーバーのデプロイ例 
gcloud run deploy llm-inference \
  --image us-docker.pkg.dev/PROJECT/repo/vllm-server:latest \
  --gpu 0.5 \
  --gpu-type nvidia-rtx-pro-6000 \
  --cpu 10 \
  --memory 40Gi \
  --no-cpu-throttling \
  --no-gpu-zonal-redundancy \
  --region us-central1

効果: GPU・CPU・メモリの割り当てをフル GPU 構成の約半分に抑えながら、Blackwell 世代の推論性能とスケールツーゼロによるコスト最適化を両立。

🖼️ ユースケース 2: バッチ推論ジョブの並列実行

シナリオ: 画像のバッチ処理や埋め込み生成など、1 タスクあたり 48 GB VRAM で十分なバッチ推論を Cloud Run ジョブで並列実行したい。

効果: 自動付与される 3,000 milliGPU クォータ内でフラクショナル GPU インスタンスを最大 6 並列まで稼働でき、同じクォータのままスループットを従来の 2 倍に向上。

💰 料金

Cloud Run の GPU は、インスタンスのライフサイクル全体にわたり秒単位で課金されます。 ゾーン冗長性のオン/オフで GPU 秒あたりの単価が異なり、オフの方が低価格です。 フラクショナル GPU では CPU・メモリの最小構成がフル GPU の約半分となるため、インスタンスあたりの総コストを削減できます。

💡 試算例: フル GPU 構成 (1 GPU + 20 CPU + 80 GiB、ゾーン冗長性なし) を 1 時間稼働すると GPU 約 $1.31 + CPU 約 $1.30 + メモリ約 $0.58 = 約 $3.19。フラクショナル GPU の最小構成 (10 CPU + 40 GiB) では CPU・メモリ部分が約半分の約 $0.94 になります。フラクショナル GPU 自体の SKU 単価は Cloud Run 料金ページを参照してください。
