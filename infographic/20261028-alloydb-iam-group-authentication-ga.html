☁️ AlloyDB for PostgreSQL GA 一般提供

🔐 IAM グループ認証が一般提供 (GA)

グループ単位でデータベースユーザーを一元管理 — 個別登録は不要に

📅 リリース日: 2026-10-28
🏷️ IAM group authentication

📋 概要

AlloyDB for PostgreSQL において、IAM グループ認証が一般提供 (GA) となりました。 PostgreSQL 15 以降を実行する新規・既存クラスタで利用可能です。 IAM グループ (Cloud Identity グループなど) をクラスタに追加すると、グループのメンバーであるユーザーやサービスアカウントが 個別登録なしで認証でき、データベースのロールと権限をグループ単位で一元管理できます。

プライマリインスタンスとリードプールインスタンスの両方に対応し、リードプールへの直接初回サインインも可能。 Cloud SQL for PostgreSQL のバックアップから AlloyDB へ移行する際も、IAM ユーザー・グループ構成がマッピング・保持されます。

🎯 対象ユーザー: 多数の開発者やアプリケーションが AlloyDB にアクセスする環境で、データベースユーザー管理の運用負荷を削減したいデータベース管理者・セキュリティ管理者

❌ Before: 個別 IAM 認証の課題

✗IAM ユーザー・サービスアカウントを 1 件ずつクラスタに追加し、アカウントごとに権限を管理
✗入社・異動・退職のたびにクラスタレベルでユーザーの追加・削除が必要
✗PostgreSQL のロール・権限をユーザー単位で個別に更新

✅ After: グループ認証による改善

✓IAM グループを追加するだけで全メンバーが認証権限を継承、個別追加は不要
✓グループへのメンバー追加・削除だけでクラスタ横断の権限付与・剥奪が完結
✓プライマリ・リードプール・AlloyDB Studio に直接サインイン (初回もプライマリ経由不要)
✓Cloud SQL for PostgreSQL からの移行時にユーザー構成を保持

IAM グループをクラスタに 1 回登録するだけで、グループメンバー全員が個別の IAM 認証情報を使って プライマリインスタンス・リードプールインスタンス・AlloyDB Studio にサインインできます。 権限管理はグループ単位、監査ログは個人単位で記録されます。

⚡ 主要機能

👥 1. グループ単位のデータベースユーザー管理

→IAM グループをクラスタに追加すると、グループ内の全ユーザー・サービスアカウントが認証権限を継承
→グループへのメンバー追加で IAM ロールとデータベース権限を自動継承、削除で権限を剥奪
→新規・既存クラスタの両方で、手動のクラスタパッチなしに有効化可能

📖 2. リードプールインスタンスへの直接サインイン

→プライマリ・リードプール・AlloyDB Studio に直接サインイン可能
→初回サインインでもプライマリ経由なしでリードプールに直接接続できる
→初回サインイン時に AlloyDB がプリンシパル用のデータベースアカウントを自動作成

🔄 3. Cloud SQL for PostgreSQL からの移行時のユーザー構成保持

→Cloud SQL for PostgreSQL のバックアップからリストア・移行する際、個別 IAM ユーザーと IAM グループユーザーの構成をマッピングして保持

📝 4. 個人単位の監査証跡

→ロールと権限はグループレベルで割り当てるが、サインインは各自の IAM アカウントと認証情報で実施
→各ユーザー・サービスアカウントのサインインとデータベースアクティビティを監査ログに個別記録

🚀 設定方法

💡 前提条件: ① PostgreSQL 15 以降の AlloyDB クラスタ / ② IAM グループ (例: Cloud Identity グループ) が作成済み / ③ パスワード関連のデータベースフラグ (最小文字数などのポリシー) が緩和または無効化されていること

  1. 🚩 データベースフラグの有効化

    インスタンスで alloydb.iam_authentication と alloydb.iam_group_authentication の 2 つのフラグを on に設定します。

  2. 🛡️ IAM グループへのロール付与

    グループアカウントに roles/alloydb.databaseUser と roles/serviceusage.serviceUsageConsumer を割り当てます。

  3. ➕ グループをクラスタに追加

    Bash IAM グループの登録 (GROUP_EMAIL は完全なメールアドレスを指定) 
    gcloud alloydb users create GROUP_EMAIL \
  --cluster=CLUSTER \
  --region=REGION \
  --type=IAM_GROUP

  4. 🔑 グループへのデータベース権限付与

    SQL グループ名は特殊文字を含むためダブルクォートで囲む 
    GRANT SELECT ON TABLE_NAME TO "GROUP_NAME";

    psql から GRANT 文を実行し、個別ユーザーではなくグループに権限を付与します。

💡 メリット・制約事項

✅ ビジネス面のメリット
✓運用負荷の削減: メンバーの入れ替わりはグループメンバーシップ変更だけで対応、クラスタ側の操作は不要
✓ガバナンスの強化: IAM ポリシーによる一元管理と、個人単位の監査ログによる説明責任を両立
✅ 技術面のメリット
✓パスワードレス認証: 一時トークン使用でパスワード管理・ローテーションが不要
✓リードプールへの直接接続: 初回を含めプライマリ経由なしで接続可能
✓移行時の構成保持: Cloud SQL バックアップからの移行で IAM 構成を自動マッピング
✓自動アカウント作成: 初回サインイン時にデータベースアカウントを自動作成
⚠️ 制限事項
•PostgreSQL 15 (POSTGRES_15) 以降のみサポート
•SSL 接続のみ (非暗号化接続は拒否)
•インスタンスごとに 1 分あたりのサインインクォータあり (成功・失敗の両方がカウント、超過時は一時的に利用不可)
•クラスタあたり最大 200 グループ
•サービスアカウントの短縮プリンシパル (.gserviceaccount.com を除いた部分) は 63 文字以内
•グループ所属アカウントを個別 IAM ユーザー (ALLOYDB_IAM_USER) として重複追加不可。既存の個別ユーザーはグループから権限を継承しないため、移行には個別ユーザーの削除が必要
•マネージド接続プーリング・PgBouncer 接続は未サポート
•フェデレーテッド ID は未サポート
•パスワード関連フラグ (最小文字数・数字・最小長ポリシー) の緩和または無効化が必要
🤔 考慮すべき点
  • Cloud Identity グループのメンバーシップ変更の反映には約 15 分 + IAM 変更の伝播時間がかかる
  • グループからユーザーを削除しても、他のグループメンバーシップ経由でサインイン権限がある場合は新規セッションを作成できる (元のグループ由来のデータベース権限は失われる)
  • IAM で roles/alloydb.databaseUser を剥奪した場合や Cloud Identity でグループを削除した場合は、AlloyDB クラスタからも対応するグループユーザーを削除してアクセスを完全に除去する必要がある

🎯 ユースケース

👨‍💻 ユースケース 1: 開発チーム単位のデータベースアクセス管理

シナリオ: 数十名規模の開発チームが AlloyDB 上の分析用データベースに読み取りアクセス。メンバーの異動が頻繁で、個別ユーザー管理の負荷が高い。

Bash チームのグループをクラスタに追加 
# チームのグループをクラスタに追加
gcloud alloydb users create dev-team@example.com \
  --cluster=analytics-cluster \
  --region=asia-northeast1 \
  --type=IAM_GROUP
SQL グループに読み取り権限を付与 
-- グループに読み取り権限を付与
GRANT SELECT ON sales_data TO "dev-team@example.com";

効果: 異動時は Cloud Identity グループのメンバーシップを変更するだけで、AlloyDB 側の操作なしにアクセス権の付与・剥奪が完結。監査ログには個人単位の操作が記録される。

🔄 ユースケース 2: Cloud SQL for PostgreSQL から AlloyDB への移行

シナリオ: IAM 認証を利用している Cloud SQL for PostgreSQL 環境を、バックアップ経由で AlloyDB に移行する。

効果: 移行時に個別 IAM ユーザーと IAM グループユーザーの構成がマッピング・保持されるため、移行後にユーザーを再設定する手間が削減される。

👥 ユースケース 3: 既存の個別 IAM ユーザーのグループ認証への移行

シナリオ: すでに個別 IAM 認証で運用しているクラスタで、ユーザー管理をグループ単位に統合したい。

効果: ユーザーをグループに追加し、グループをクラスタに登録・ロール付与・権限付与した上で、既存の個別ユーザーをクラスタから削除する。次回サインイン時に AlloyDB がグループユーザーとしてアカウントを再作成する。
