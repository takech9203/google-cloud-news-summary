🛡️ CodeMender v0.16.0 アップデート

Deep スキャンのデフォルト化・cm health 事前ヘルスチェック・ファイル検出範囲の拡大
📅 リリース日: 2026-10-21

📝 概要

Gemini Enterprise Agent Platform 上の AI コードセキュリティエージェント CodeMender が v0.16.0 にアップデート。 CodeMender は、コードベースの脆弱性をスキャン (cm find)、検証 (cm verify)、修正 (cm fix) する自律型エージェントで、 推論は Google Cloud 側のホスト型エージェントが担い、コードの読み取り・ビルド・PoC (概念実証) エクスプロイトの実行はローカルの cm CLI サンドボックス内で行われる。

最大の変更点は、cm find のデフォルトがファイル単位の並行 Deep スキャンになったこと。 従来オプトインだった網羅的スキャンが標準となり、リポジトリ全体での脆弱性の検出率 (recall) が向上する。従来のクイックスキャンは --quick で引き続き利用可能。 また、新コマンド cm health により認証情報・構成・エンドポイント到達性・プロジェクト認可をスキャン前に検証でき、 C++ ヘッダーや拡張子なしスクリプトなどファイル検出範囲も大幅に拡大された。

❌ Before (アップデート前の課題)

  • Deep スキャンは --deep フラグの明示指定が必要 (デフォルトは単一セッション)
  • 認証情報・構成・到達性・認可の問題にスキャン実行まで気付けない (専用コマンドなし)
  • .hh / .hxx / .inl / .ipp、shebang 付き拡張子なしスクリプト、ネストされた build/・target/・obj/・bin/ 配下、spec/・locale/・i18n/ 配下がスキャン対象外
  • cm verify の書き込み先が .exploit/ に制限されず、ワークスペース復元時に問題が発生
  • 大きなファイルの読み取りや diff 生成に上限がなく、run_command のタイムアウトが短め
  • サンドボックスセッションが ~/.codemender/audit.log に書き込めない
  • マルチファイルスキャンの一部失敗をステータスから判別できない

✅ After (v0.16.0 での改善)

  • cm find がデフォルトで並行 Deep スキャンを実行し検出率が向上 (従来挙動は --quick)
  • cm stats がモード別 (--deep / --quick / --diff) に利用状況を集計
  • 新コマンド cm health (--json / --strict / --timeout) でスキャン前に環境を検証
  • C++ ヘッダー、shebang スクリプト、ビルドディレクトリ配下、spec/・locale/・i18n/ 配下もスキャン対象に
  • cm verify の書き込みを .exploit/ に制限、復元時は欠損アーティファクトをスキップ
  • 読み取り 256 KiB 上限 + ページネーション、diff 生成の制限、run_command タイムアウト 120 秒 / 300 秒に引き上げ
  • サンドボックスセッションも ~/.codemender/audit.log へ記録可能に
  • 一部失敗時は INCOMPLETE ステータスを報告

v0.16.0 では、cm health による事前ヘルスチェックを起点に、デフォルトで Deep スキャンとなった cm find、 書き込み先が制限された cm verify、モード別集計に対応した cm stats までのワークフロー全体が強化された。

⚡ 主要機能

1️⃣ Deep スキャンのデフォルト化 (cm find)

→cm find がデフォルトで、ファイル単位の並行 Deep スキャン (--deep) を実行。リポジトリ全体での脆弱性検出率 (recall) の向上が目的
→従来の単一セッションによるクイックスキャンは --quick フラグで選択可能
→cm stats がスキャン利用状況をモード別 (--deep / --quick / --diff) に集計表示

2️⃣ 事前ヘルスチェック (cm health) 🆕

→スキャン実行前に認証情報 (credentials)、構成 (configuration)、エンドポイント到達性 (endpoint reachability)、プロジェクト認可 (project authorization) を検証
→--json (機械可読出力)、--strict、--timeout に対応し、CI/CD パイプラインの前段チェックに組み込みやすい

3️⃣ ファイル検出範囲の拡大 (cm find)

→C++ ヘッダーの追加拡張子: .hh、.hxx、.inl、.ipp
→サポート言語 (python、node、ruby、php) の shebang を持つ、拡張子なしのスクリプト
→ネストされた build/、target/、obj/、bin/ ディレクトリ配下のソースコード
→spec/、locale/、i18n/ 配下のプロダクションコード

4️⃣ バグ修正

→cm verify のファイル書き込みをプロジェクトルート内の .exploit/ に制限。ワークスペース復元時は欠損・スコープ外のセッションアーティファクトをスキップ
→単一ターンのファイル読み取りを 256 KiB に制限 (ページネーションヒント付き)、大きなファイルでの unified diff 生成を制限、run_command のデフォルト/最大タイムアウトを 120 秒 / 300 秒に引き上げ
→サンドボックス化されたセッションが ~/.codemender/audit.log にツール呼び出しエントリを書き込めない問題を修正
→マルチファイルの --deep / --diff スキャンで 1 つ以上のファイルスキャンが失敗した場合、INCOMPLETE ステータスを報告

🚀 設定方法

📋 前提条件

✓Google Cloud プロジェクトのセットアップ (必要な API の有効化と IAM ロールの付与)
✓CodeMender CLI のダウンロード・インストールと Google Cloud 認証情報 (ADC) の構成
✓CodeMender は Public Preview のため、利用には対象顧客としてのアクセスが必要

ステップ 1: 事前ヘルスチェック (v0.16.0)

Bash cm health による事前検証 
# 認証情報・構成・エンドポイント到達性・プロジェクト認可を検証
cm health

# CI/CD 向け: JSON 出力 + 厳格モード + タイムアウト指定
cm health --json --strict --timeout=<SECONDS>

スキャン実行前に環境の問題を検出できるため、CI/CD パイプラインの前段チェックとして組み込める。

ステップ 2: スキャンの実行 (Deep がデフォルト)

Bash cm find のスキャンモード 
# v0.16.0 以降: デフォルトでファイル単位の並行 Deep スキャンを実行
cm find .

# 単一セッションのクイックスキャンを実行したい場合
cm find ./src --quick

# プルリクエストの差分スキャン (従来どおり)
cm find . --diff=origin/main

ステップ 3: 検証とモード別の利用状況確認

Bash cm verify / cm stats 
# Finding を検証 (ファイル書き込みは .exploit/ 内に制限される)
cm verify FINDING_ID

# スキャン利用状況をモード別 (--deep / --quick / --diff) に確認
cm stats

💡 メリット

💼 ビジネス面

✓検出カバレッジの底上げ: Deep スキャンがデフォルトになり、意識的にフラグを指定しなくても網羅的な監査が行われ、スキャン漏れによるリスクが減る。ファイル検出範囲の拡大により、これまで対象外だったコード (C++ ヘッダー、ビルドディレクトリ配下のソースなど) の脆弱性も捕捉できる
✓運用の信頼性向上: cm health により環境起因のスキャン失敗を事前に防止でき、INCOMPLETE ステータスにより「一部のファイルがスキャンできていない監査結果」を誤って完全な結果として扱うリスクを回避できる

⚙️ 技術面

✓CI/CD との統合性向上: cm health --json --strict をパイプラインの前段に置くことで、認証・構成の問題をスキャン実行前に fail-fast できる
✓検証のセキュリティ強化: cm verify の書き込み先がプロジェクトルート内の .exploit/ に制限され、PoC 実行時の副作用の範囲が明確になった
✓大規模リポジトリでの安定性: ファイル読み取りの 256 KiB 上限 (ページネーション付き) と diff 生成の制限、run_command タイムアウトの引き上げ (120s / 300s) により、大きなファイルを含むリポジトリでも安定して動作する
✓監査ログの完全性: サンドボックス化されたセッションでも ~/.codemender/audit.log へのツール呼び出し記録が確実に残るようになった

⚠️ デメリット・制約事項

🚫 制限事項

✗CodeMender は Preview (Pre-GA) であり、限定された顧客向けの提供。商用・本番目的での利用は不可で、テスト・評価目的に限定される
✗解析対象は、自身が所有または利用を許可されたコード、もしくは OSI 承認ライセンスで配布される OSS に限られる
✗Deep スキャンは標準 (クイック) スキャンや Diff スキャンに比べて実行時間が長く、トークン消費も多い。プルリクエストをブロックする同期チェックには不向き

🤔 考慮すべき点

⚠️デフォルト動作の変更に注意: v0.16.0 以降、cm find はデフォルトで Deep スキャンを実行するため、従来と同じコマンドでも実行時間とトークン消費 (コスト) が増加する可能性がある。これまでのクイックな挙動を維持したい場合は --quick を明示する必要がある
⚠️ビルドディレクトリ (build/、target/、obj/、bin/) 配下のソースや spec/ 配下のコードが新たにスキャン対象となったことで、Finding の件数やスキャン時間が増える可能性がある。スキャン対象を調整したい場合は config.yaml の scan 設定 (exclude_dirs など) を確認するとよい
⚠️Pre-GA 製品のため、重大なエラーが修正できない状況では使用せず、人間による監督のもとで利用することが求められる

🎯 ユースケース

1. CI/CD パイプラインでの事前ヘルスチェック

シナリオ: 夜間の定期 Deep スキャンジョブが、認証情報の期限切れやプロジェクト認可の不備で失敗し、翌朝まで気付かないことがあった。

Bash パイプライン前段チェック 
# パイプラインの前段で環境を検証し、問題があれば即座に失敗させる
cm health --json --strict --timeout=60 || exit 1

# 検証に合格したら Deep スキャン (v0.16.0 以降はデフォルト) を実行
cm find . --output=report.json --format=json
✅ 効果: 環境起因の失敗をスキャン開始前に検出でき、長時間のスキャンが無駄になることを防げる。--json 出力により失敗理由の機械的な解析も可能。

2. C++ プロジェクトの網羅的な定期監査

シナリオ: .hh / .hxx / .inl / .ipp 形式のヘッダーを多用する C++ リポジトリで、これらのファイルが従来のスキャン対象から漏れていた。

✅ 効果: v0.16.0 のファイル検出拡大により、これらの C++ ヘッダーやネストされたビルドディレクトリ配下のソースも自動的にスキャン対象となり、追加設定なしで監査カバレッジが向上する。一部のファイルスキャンが失敗した場合は INCOMPLETE ステータスで通知されるため、監査結果の完全性も確認できる。

3. 開発中のクイックチェックと定期監査の使い分け

シナリオ: 開発者がローカルで特定モジュールを素早く確認したい一方、チームとしては網羅的な定期監査も運用している。

Bash モードの使い分け 
# ローカルでの素早い確認は --quick で単一セッションスキャン
cm find ./src/auth --quick

# 定期監査はデフォルトの Deep スキャン
cm find .

# モード別の利用状況を把握してコストを管理
cm stats
✅ 効果: cm stats のモード別集計 (--deep / --quick / --diff) により、チーム内でどのモードがどれだけ使われているかを可視化し、トークン消費の傾向を把握できる。

📌 まとめ

CodeMender v0.16.0 は、cm find のデフォルトを並行 Deep スキャンに変更して検出率を底上げし、 cm health による事前ヘルスチェックと INCOMPLETE ステータスで運用の信頼性を高めるアップデートである。 既存ユーザーは、デフォルト動作の変更による実行時間・トークン消費の増加に留意しつつ、クイックチェックには --quick を明示し、 CI/CD パイプラインの前段に cm health --json --strict を組み込むことを推奨する。
