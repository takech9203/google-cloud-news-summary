リリース日: 2026-10-29 | 17 項目の一括アップデート

📝 概要

Looker (original) / Looker (Google Cloud core) に関する 17 項目のアップデートが一括発表されました。 中心は新しい Explore・マージクエリエクスペリエンスの GA 化 (デフォルトインターフェース化) です。 あわせて Gemini in Looker の Explore サマリー生成と Visualization Assistant が GA となり、 ブレットチャート・ヒストグラム・KPI (Single Value) チャート・テーブル行グルーピングなどの可視化機能も GA / 新規追加されました。

❌ Before (アップデート前の課題)

  • 新 Explore・マージクエリ UI は Preview 機能で、管理者による有効化が必要だった (Looker 26.6 以降)
  • Gemini の Explore サマリー / Visualization Assistant は Preview で Trusted Tester Features の有効化が必要、サポートも限定的
  • ブレットチャートやヒストグラムは標準チャートタイプになく、カスタム可視化で代替が必要
  • Looker CI はハブ & スポーク構成の下流プロジェクトを自動テストできず、上流変更による破壊を事前検知しにくい
  • ダッシュボードの関連タイルをまとめて移動・複製・削除する手段がなかった
  • インスタンスに展開された機能・変更をリアルタイムに確認できず、リリースノートの別途参照が必要
  • Looker (Google Cloud core) の Admin パネルにレガシー機能ページがなかった

✅ After (アップデート後の改善)

  • 新 Explore・マージクエリエクスペリエンスが GA、デフォルトインターフェースに
  • Gemini の Explore サマリー生成と Visualization Assistant が GA、本番利用可能に
  • ブレットチャート、ヒストグラム、KPI チャート、テーブル行グルーピングが標準機能に
  • Looker CI がハブの PR 作成・更新時に下流スポークを自動テストし、マージ前に破壊的変更を検出
  • Dashboard Tile Groups (Preview) で関連タイルを一括で移動・複製・削除 (LookML 管理にも対応)
  • Release Changelog (Preview) で機能・動作変更・バグ修正をリアルタイム確認
  • レガシー機能によりクラシック UI へのフォールバックをインスタンス単位・埋め込み単位で制御可能

今回のアップデートは「Explore 体験の刷新」を中核に、Gemini/AI 機能、可視化、管理・開発機能の 4 つのテーマで構成され、新 Explore UI 上で Gemini 支援機能が動作する関係になっています。

🔄 テーマ 1: Explore / マージクエリエクスペリエンスの刷新

✨ 新 Explore・マージクエリエクスペリエンス GA
  • 再設計された UI が GA となり、Explore および複数クエリのデータ結合におけるデフォルトインターフェースに
  • 直感的な操作で接続関係の発見やインサイト獲得を高速化することを目的に設計
  • Preview 期間中 (Looker 26.6 以降) は管理者による有効化が必要だったが、今後は標準の体験に
🔤 文字列フィルタの入力動作の改善
  • 「Done」クリックや入力フィールド外のクリックでは、未確定テキストからフィルタチップが作成されなくなった
  • フィルタチップの作成は Enter キー、カンマ (,) の入力、または値の貼り付けで行う
  • 意図しないフィルタ条件の追加を防ぐ改善
⏪ クラシック UI へのフォールバック用レガシー機能の追加
  • 「Use Legacy Explore and Merge Query Experience」(インスタンス全体) と「... for Embed」(埋め込み) の 2 つを追加
  • 管理者はクラシック UI でのデフォルト表示を構成でき、移行期間中の段階的な切り替えに活用可能

🤖 テーマ 2: Gemini / AI 機能の GA

📝 Gemini 支援による Explore サマリー生成 GA
  • LookML で description が未定義の Explore に対し、Gemini in Looker が目的やデータの種類を含むサマリーを自動生成
  • Configure パネル (新 UI) または Explore 名の横 (クラシック UI) の情報アイコンから閲覧可能
  • Preview 時に必要だった Trusted Tester Features の有効化は、GA 版では要件から除外
🎨 Visualization Assistant GA
  • 自然言語プロンプトから Highcharts JSON 形式のフォーマットオプションを生成し、可視化カスタマイズに適用
  • 縦棒・横棒・折れ線など Highcharts API を使用するほとんどの Cartesian チャートに対応
  • 生成された JSON は Chart Config エディタで手動編集も可能。複雑なカスタマイズの雛形作成に活用できる
🤖 ポイント: LookML や Highcharts JSON の知識がないビジネスユーザーでも、データ理解と可視化カスタマイズが容易になります (分析の民主化)。

📊 テーマ 3: 可視化の新機能・GA

🎯 ブレットチャート GA

単一の主要指標のパフォーマンスをバーで表し、目標値をターゲットラインで表示。「poor」「satisfactory」「good」などのしきい値を背景の網掛けレンジとして重ねられます。

📶 ヒストグラムチャート 新規追加

属性のデータ分布をグラフィカルに表現。区間 (ビン) を作成し、各ビンに含まれる値の件数をカウントして表示します。

🔢 KPI (Single Value) チャート GA

従来の Single Value チャートタイプを置き換える、KPI 表示に特化した単一値の可視化です。

🗂️ テーブル行グルーピングと Grouping メニュー GA

テーブルチャートのデータを階層的なグループで表示し、外観をカスタマイズできます。

🛠️ テーマ 4: 管理・開発機能の強化

🔁 Looker CI のハブ & スポークプロジェクト対応
  • 同一インスタンス上のハブプロジェクトからローカルプロジェクトインポートで取り込む構成で、下流スポークの自動テストが可能に
  • ハブプロジェクトで Pull Request が作成・更新されるたびにテストを実行
  • 上流 LookML の変更がマージされる前に、下流の Explore・コンテンツ・データテストの破壊的変更を検出

  • No Channel チャネル: Looker 26.22 の展開開始
  • Regular チャネル: Looker 26.18 のまま

🚨 テーマ 5: 破壊的変更・レガシー機能の削除

💥 Conversational Analytics System Activity ダッシュボードの要素名変更 Breaking change
  • Token usage タブの Feature 列 / Feature Name フィルタの値「Conversational Analytics API」が「Looker API」に名称変更 (Looker API の Conversational Analytics メソッドを指す)
  • 旧名称を参照するカスタムダッシュボードは破壊的変更となる可能性があり、修正が必要
  • ダッシュボードのレイアウトと機能自体に変更はない
🗑️ レガシー DB 接続ワークフローの削除 Change
  • 「Use Legacy Connections Page」レガシー機能とレガシーデータベース接続ワークフローが削除
  • すべてのデータベース接続は現行の接続ワークフローを使用
📢 2026 年 10 月 26 日からの自動有効化 Announcement

Looker 26.20 を実行する Looker (original) / Looker (Google Cloud core) インスタンスでは、2026 年 10 月 26 日以降、今回発表された機能群が自動的に有効化されます。

⚙️ 設定方法

前提条件

✓Looker (original) または Looker (Google Cloud core) インスタンスが対象バージョン (新 Explore エクスペリエンスは 26.6 以降、自動有効化は 26.20) を実行していること
✓Gemini 機能を使用する場合、Gemini in Looker がインスタンスで有効化されていること

ステップ 1: クラシック UI に戻す場合 (必要な場合のみ)

新 Explore エクスペリエンスをデフォルトにしたくない場合、管理者は Admin パネルの Legacy Features ページで以下を有効化します。

Text Legacy Features の設定 
Admin > General > Legacy Features
  - Use Legacy Explore and Merge Query Experience          (インスタンス全体)
  - Use Legacy Explore and Merge Query Experience for Embed (埋め込みコンテキスト)

ステップ 2: Gemini 機能の有効化と権限付与

Text Gemini in Looker の有効化と権限 
# Looker (original)
Admin > Platform > Gemini in Looker で機能を有効化

# Looker (Google Cloud core)
Google Cloud コンソールからインスタンスの Gemini in Looker を有効化

# 権限付与
- Explore サマリー: develop 権限 + Gemini ロール
- Visualization Assistant: gemini_in_looker + can_override_vis_config 権限

ステップ 3: Breaking change への対応確認

💥 対応: Conversational Analytics System Activity を参照するカスタムダッシュボードがある場合、Feature 列 / Feature Name フィルタの値「Conversational Analytics API」への参照を「Looker API」に更新します。

💪 メリット

💼 ビジネス面

✓分析の民主化: Gemini による Explore サマリーと Visualization Assistant の GA により、LookML や Highcharts JSON の知識がないビジネスユーザーでもデータ理解と可視化カスタマイズが容易に
✓KPI モニタリングの強化: ブレットチャートや KPI チャートの GA により、目標対比のパフォーマンス管理ダッシュボードを標準機能で構築可能
✓変更の可視性向上: Release Changelog により、インスタンスに展開された変更をユーザー自身が確認でき、問い合わせ対応コストを削減

🔧 技術面

✓LookML 開発の品質向上: CI のハブ & スポーク対応により、上流プロジェクトの変更が下流に与える影響をマージ前に自動検証
✓段階的な移行パス: レガシー機能によるクラシック UI へのフォールバックが用意されており、新 UI への移行を組織のペースで進められる
✓ダッシュボード管理の効率化: タイルグループの LookML サポートにより、ダッシュボード構成をコードとして管理可能

⚠️ デメリット・制約事項

制限事項

✗Dashboard Tile Groups と Release Changelog は Preview 段階であり、Pre-GA 提供条件が適用される
✗Dashboard Tile Groups は newspaper レイアウトのダッシュボードでのみ利用可能
✗Visualization Assistant は Highcharts API を使用する可視化タイプに限定
✗Looker (Google Cloud core) の Legacy features ページに表示されるレガシー機能は Looker (original) と異なる場合がある

考慮すべき点

  • Breaking change: 「Conversational Analytics API」→「Looker API」への名称変更により、旧名称を参照するカスタムダッシュボードは修正が必要
  • レガシー DB 接続ワークフローは削除済みのため、旧ワークフローを前提とした運用手順書は更新が必要
  • Looker 26.20 インスタンスでは 2026 年 10 月 26 日以降に機能が自動有効化されるため、エンドユーザーへの事前周知と教育を計画すべき
  • 文字列フィルタのチップ作成動作が変わるため、Enter / カンマ / 貼り付けでの確定を案内する必要がある

💡 ユースケース

📈 ユースケース 1: 営業 KPI ダッシュボードの刷新

シナリオ: 営業部門が四半期目標に対する達成状況をダッシュボードで管理したい。

Text 実装例 
1. KPI (Single Value) チャートで売上合計など主要指標を表示
2. ブレットチャートで目標値 (ターゲットライン) と達成度合い
   (poor / satisfactory / good の背景レンジ) を表現
3. 関連タイルを Dashboard Tile Groups (Preview) で「売上」「パイプライン」
   などのグループに整理

効果: 目標対比のパフォーマンスが一目で把握でき、ダッシュボードの視認性と保守性が向上。

🔁 ユースケース 2: ハブ & スポーク構成での LookML 品質ゲート

シナリオ: 共通ディメンション・メジャーをハブプロジェクトで管理し、部門ごとのスポークプロジェクトがローカルインポートで参照。ハブ側の変更で部門ダッシュボードが壊れる事故を防ぎたい。

効果: ハブの Pull Request 作成・更新時に Looker CI が下流スポークの Explore・コンテンツ・データテストを自動実行し、破壊的変更をマージ前に検出。

🚀 ユースケース 3: 新 Explore UI への段階的移行

シナリオ: 全社で新 Explore エクスペリエンスへ移行したいが、埋め込みダッシュボードを利用する外部顧客向けには当面クラシック UI を維持したい。

効果: 「Use Legacy Explore and Merge Query Experience for Embed」レガシー機能により、埋め込みコンテキストのみクラシック UI を維持しつつ、社内ユーザーは新 UI へ移行可能。
