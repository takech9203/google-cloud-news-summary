📋 概要

2026 年 11 月 5 日、Apigee hybrid v1.14.10 がリリースされました。 コンテナイメージは Helm チャートに統合されており、Helm チャートでのアップグレードによりイメージが自動更新されます (手動のイメージ変更は通常不要)。

特に重要なのは、HTTP フォワードプロキシ経由での egress を必須とするクラスタで apigee-connect-agent が HTTPS_PROXY を無視してコントロールプレーンへの tether を確立できなくなる問題 (Bug ID 578314600) の修正です。これは v1.14.9 などの以前のパッチで導入されたリグレッションで、該当環境ではマネジメントプレーン操作が失敗する深刻な影響がありました。

❌ アップデート前の課題

  • フォワードプロキシ必須クラスタで apigee-connect-agent が HTTPS_PROXY を無視して直接接続を試み、「no connections available from the Apigee connect agent(s)」エラーで管理操作が失敗 (既知の問題 578314600。v1.14.9 などが影響対象)
  • 侵害された emSign ルート証明書とクロス署名用 Comodo AAA Services ルートがトラストストアに残存
  • apigee-ingressgateway が内部ヘッダー x-envoy-decorator-operation を上流に転送
  • HTTP/2 フローで AssignMessage / HTTPModifier / RaiseFault (createNew="true") が :path / :authority 疑似ヘッダーを設定できず invalid-header エラー
  • OASValidation の strict 検証が高負荷時に正当なリクエストを断続的に HTTP 400 で拒否
  • Helm の podDisruptionBudget オーバーライドが Kubernetes API サーバーに破棄される
  • マルチ証明書トラストストアのトラストアンカー変更時に Message Processor の再起動が必要

✅ アップデート後の改善

  • apigee-connect-agent が HTTPS_PROXY (認証情報含む) を尊重し、HTTP/2 keepalive ping で接続維持。フォワードプロキシ必須環境でも tether 確立が可能に
  • 侵害された emSign ルートと Comodo AAA Services ルートを全コンテナのトラストストアから削除
  • apigee-redis が Valkey エンジン 8.1.10 に移行 (RESP2 プロトコルとバイナリ名は変更なし)
  • HTTP/2 フローのポリシーで :path / :authority 疑似ヘッダーを設定可能に
  • podDisruptionBudget オーバーライドが正しく適用
  • トラストアンカー変更時にアウトバウンド SSLContext が自動再構築され、MP 再起動が不要に
  • 18 コンポーネントで既知の CVE に対するセキュリティ修正を適用

🔍 既知の問題 578314600 の背景

⚠️ 影響バージョン: hybrid 1.14.9、1.15.8、1.15.9、1.16.11、1.16.12、1.17.1、1.17.2

overrides.yaml で httpProxy を設定すると apigee-connect-agent Pod に HTTPS_PROXY が設定されますが、 Bug 513032450 の修正で導入されたカスタム TCP keep-alive ダイヤラーが gRPC 組み込みの HTTP CONNECT プロキシ処理をバイパスし、 apigeeconnect.googleapis.com:443 へ直接接続を試みることが原因でした。 アウトバウンド通信がフォワードプロキシに制限されたクラスタでは接続がタイムアウトし、マネジメントプレーン操作が失敗します。

📝 まとめ

Apigee hybrid v1.14.10 は、フォワードプロキシ必須環境でのコントロールプレーン接続障害 (578314600) の修正と、 18 コンポーネントにわたる広範なセキュリティ修正を含む重要なパッチリリースです。

特に v1.14.9 で httpProxy を使用している環境では管理操作が失敗する深刻な影響があるため、早急なアップグレードを推奨します。 Helm チャートによるアップグレードでイメージが自動更新されるため、計画的なメンテナンスウィンドウでの適用を検討してください。
