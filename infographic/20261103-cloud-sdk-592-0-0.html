📋 概要

2026 年 11 月 3 日、Google Cloud CLI (gcloud) の バージョン 592.0.0 がリリースされた。 Datastore / Firestore エミュレータの Java 25 以上必須化 や、Debian ベース Docker イメージからの システム Python・C コンパイラの削除 といった 破壊的変更 (Breaking Changes) を含むため、 CI/CD パイプラインやローカル開発環境で gcloud の Docker イメージ・エミュレータを利用しているチームは特に注意が必要。

機能面では、Cloud Run の --public フラグ (Beta)、GKE の --enable-dataplane-v2 によるインプレース移行 (Preview)、 Cloud KMS の ECDH KEM アルゴリズム対応、Cloud SQL の PSC DNS 再調整コマンドなど幅広い更新があり、さらに Firebase Test Lab の非推奨化 (2027 年 9 月 30 日シャットダウン予定) という重要アナウンスも含まれる。

😣 Before (アップデート前の課題)

  • エミュレータの保守対象 Java バージョンが分散 (Java 21 で動作)
  • Docker イメージにシステム Python / gcc が同梱され、イメージ肥大化と脆弱性対応のオーバーヘッド
  • Cloud Run の公開は allUsers への IAM 付与が一般的で、ドメイン制限共有ポリシー下では煩雑
  • GKE Dataplane V2 への移行はクラスタ再作成とワークロード移設が必要
  • Datastream で --labels が暗黙的に無視される不具合
  • Cloud Shell への scp はパスワードレス認証に非対応

😊 After (592.0.0 での改善)

  • エミュレータ実行環境を Java 25 以上に統一、Java 依存はヘッドレス JRE に軽量化
  • 不要なシステム Python / gcc を削除し、常にバンドル版 Python で動作 (amd64 / arm64 共通)
  • gcloud beta run deploy --public で 1 フラグ公開 (Invoker IAM チェックと IAP を無効化)
  • --enable-dataplane-v2 で既存クラスタをインプレース移行開始 (Preview)
  • Datastream / Backup DR / Compute Engine の不具合を修正
  • Cloud Shell の scp / ssh が TCP トンネル経由のパスワードレス認証に対応

⚠️ 破壊的変更 (Breaking Changes)

☕ 1. Datastore / Firestore エミュレータ: Java 25 以上が必須に

  • gcloud beta emulators datastore start / gcloud emulators firestore start は Java 25 未満での実行サポートを削除
  • 対応策: Java 25 以上へアップグレード。Java 21 サポートが必要なら旧バージョンの gcloud CLI を使い続ける

🐳 2. Docker イメージ: システム Python と C コンパイラを削除

  • Debian ベースイメージから python3 / gcc を削除。gcloud / gsutil / bq は amd64・arm64 とも常に バンドル版 Python で動作
  • 削除パッケージ: :latest / :slim / :debian_component_based は python3, python3-dev, python3-pip, python3-crcmod, gcc。:emulators は python3, python3-crcmod。:stable は arm64 のみ python3-dev, python3-crcmod
  • ワークフローでシステム Python が必要なら apt-get install python3 をイメージに追加 (C 拡張のコンパイルには build-essential python3-dev も)
🚨 重要: CLOUDSDK_PYTHON=python3 (または CLOUDSDK_GSUTIL_PYTHON / CLOUDSDK_BQ_PYTHON) を設定していると、 PATH 上に python3 が存在しないため すべての gcloud / gsutil / bq 呼び出しが失敗する。該当環境変数は unset すること。

📦 3. Google Cloud CLI パッケージの Java 依存変更

  • google-cloud-cli-datastore-emulator、firestore-emulator、pubsub-emulator、app-engine-java、bqms の deb / rpm パッケージの Java 依存が フル JDK → ヘッドレス JRE (Java 25 優先) に変更
  • Datastore / Firestore エミュレータのパッケージは Java 25 以上が必須

🚫 非推奨化: Firebase Test Lab

⚠️ 移行計画が必要: gcloud firebase test コマンドグループが Deprecated となった。 Firebase Test Lab 自体が非推奨となり、2027 年 9 月 30 日に完全シャットダウン される予定。
→ テストワークフローを維持するには、Google Cloud の Developer Device Platform への移行が案内されている (移行ガイド / FAQ)

✨ 主要な新機能・変更点 (サービス別)

🏃 Cloud Run: --public フラグ Beta

  • gcloud beta run deploy / services update / multi-region-services update に追加
  • Invoker IAM チェックと IAP を無効化してサービスを公開。allUsers への IAM 付与が制限される ドメイン制限共有の組織ポリシー下でも推奨方式で公開可能

⎈ Kubernetes Engine: Dataplane V2 移行とネットワーキング強化

  • gcloud container clusters update --enable-dataplane-v2: 既存クラスタの GKE Dataplane V2 移行を開始 Preview (VPC ネイティブ、1.35.3-gke.1155000 以降などの要件あり)
  • gcloud container node-pools update --datapath-provider: ノードプール単位でデータパスプロバイダを更新 (移行の手動加速やロールバックに利用)
  • --enable-ambient-networking が clusters create / create-auto / clusters update で GA に昇格

🔐 Cloud KMS: ECDH 鍵カプセル化メカニズム

  • KEM アルゴリズム kem-ecdh-p256 と kem-ecdh-p384 をサポート

🗄️ Cloud SQL: PSC DNS ネットワーキングの再調整

  • gcloud sql instances reconcile-networking を追加。Private Service Connect (PSC) の DNS ネットワーキング設定をインスタンスに対して再調整可能に

🔥 Cloud Firestore エミュレータ v1.23.0

  • Datastore モードで merge join と複数不等式インデックス選択 (--require-indexes) をサポート
  • Firestore Pipelines API の add_window_fields ステージ (sum / average / count / minimum / maximum / first / last / array_agg / array_agg_distinct / rank) をサポート
  • 全データベースエディションで Enterprise データ型を許可。トランザクション競合検出などの不具合修正
  • 最小必須 Java バージョンが 25 に更新

📊 データベース・分析系の更新

  • AlloyDB: Auth Proxy インストール手順を v1.17.2 に更新。オートスケーラー関連フラグ群 (--enable-autoscaler ほか) が GA、--autoscaler-target-connections-count 追加
  • Cloud Bigtable: --automated-backup-keep-hot-duration で、指定期間ホット状態を維持してから標準バックアップに移行する自動バックアップを作成可能に
  • BigLake: Hive カタログの CMEK 対応 (--kms-key / --clear-kms-key)、Iceberg カタログの Workday OIDC 認証対応 (いずれも Beta)
  • Cloud Dataplex: datascans に --custom-instructions / --sql-dialect フラグを追加
  • Cloud Dataproc: DWS スケジュールクラスタ作成用の --scheduling-timeout / --requested-run-duration フラグを追加
  • Cloud Datastream: private-connections create の --labels 暗黙破棄の不具合を修正

🛡️ 運用・セキュリティ系の更新

  • Cloud Backup DR: applied-auto-protection-policies / auto-protection-bindings / auto-protection-policies / binding-matching-resources が GA。--location のデフォルト値 (-) が削除され必須化
  • BeyondCorp: --dispatch-info-output-type 追加。gcloud beta beyondcorp app / client-connector コマンドグループは削除
  • Network Security: SecurityProfile / SecurityProfileGroup の YAML スキーマが WildFire Analysis をサポート (Beta / GA)
  • Cloud Infrastructure Manager: 有償 Terraform バージョン (1.6.0 以降) 指定時に警告を表示
  • Cloud Workstations: クラスタ作成・更新に --direct-access-ports フラグ追加 (Beta)
  • Cloud Shell: scp が TCP トンネル経由のパスワードレス認証に対応、ssh はパスワードレス接続時に SSH 公開鍵アップロードをスキップ

🧩 その他のサービス更新

  • Agent Registry: skills create / update から --scanning-state を削除 (--scanning-policy を使用)
  • App Engine: Java SDK v5.2.0 に更新。gcloud beta app migrate-to-run に --from-image / --destination-repository を追加。app.yaml の vpc_access 対応で Standard 環境の Direct VPC egress が可能に
  • App Hub: applications create の --scope-type に MULTI_REGIONAL を追加
  • Artifact Registry: attachments download の添付ファイル名検証の問題を修正
  • Compute Engine: オペレーションエラーのトラブルシューティングリンク欠落を修正。--reservation-subblock が GA / Beta に昇格

🚧 制限事項

🎯 ユースケース

1️⃣ CI/CD パイプラインの 592.0.0 対応監査

シナリオ: gcloud Docker イメージ (google-cloud-cli:latest) を使う CI/CD パイプラインで、デプロイスクリプトがシステム Python に依存している。

Bash 影響箇所の確認と Dockerfile 修正 
# パイプライン内で影響箇所を確認
grep -rE 'CLOUDSDK_(PYTHON|GSUTIL_PYTHON|BQ_PYTHON)|python3 ' ci/

# 必要に応じて Dockerfile を修正
cat <<'EOF' >> Dockerfile
RUN apt-get update && apt-get install -y --no-install-recommends python3 \
    && rm -rf /var/lib/apt/lists/*
EOF

2️⃣ 既存 GKE クラスタの Dataplane V2 移行

シナリオ: Dataplane V1 で稼働中の本番 VPC ネイティブクラスタに Cilium ベースのネットワークポリシーと Dataplane V2 観測性を導入したいが、クラスタ再作成は避けたい。

効果: --enable-dataplane-v2 によるインプレース移行で、ワークロードを新クラスタへ移設することなく Dataplane V2 の機能を利用開始できる。メンテナンスウィンドウに従って段階的にノードプールがパッチされるため、ダウンタイムの計画も立てやすい。

3️⃣ Firebase Test Lab からの移行計画

シナリオ: モバイルアプリの CI で gcloud firebase test android run を利用しており、2027 年 9 月 30 日のシャットダウンまでに移行が必要。

効果: Developer Device Platform の移行ガイドに沿って早期に PoC を実施することで、テストワークフローの継続性を確保できる。
