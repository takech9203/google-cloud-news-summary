Oracle Database@Google Cloud GA (一般提供) 🔒 セキュリティ

🔗 Identity Connector の作成時オプション化と
作成後の有効化/無効化が GA に

Exadata VM Cluster / Exascale VM Cluster を Identity Connector なしで作成し、後からいつでも切り替え可能に
📅 リリース日: 2026-11-11

📝 概要

Oracle Database@Google Cloud において、Exadata VM Cluster および Exascale VM Cluster を Identity Connector なしで作成できるようになり、さらに クラスタ作成後に有効化・無効化できる機能が GA になりました。 操作は Google Cloud コンソール・gcloud CLI・API のいずれからも実行できます。

💡 Identity Connector とは: Oracle Database@Google Cloud のクラスタを Cloud KMS や顧客管理暗号鍵 (CMEK) などの Google Cloud サービスに接続するためのコンポーネント (Workload Identity Connector)。 CMEK を利用する場合は有効化が必須ですが、Oracle 管理キーのみで運用する場合は必ずしも必要ではありません。

🎯 対象ユーザー: Exadata Database Service (Exadata VM Cluster) または Exadata Database Service on Exascale Infrastructure (Exascale VM Cluster) を運用し、 CMEK の利用方針やセキュリティ要件に応じて Google Cloud サービスとの接続を制御したい組織

❌ Before (アップデート前)
  • クラスタ作成時に Identity Connector が常に自動プロビジョニングされ、CMEK を使わない場合でも省略できなかった
  • クラスタ作成後に有効/無効を切り替える手段がなかった
  • 作成時にセットアップが失敗した場合、再有効化するための標準化された手順がなかった
✅ After (アップデート後)
  • 作成時に自動プロビジョニングを無効化 (gcloud では --identity-connector-disabled) してクラスタを作成できる
  • 作成後にコンソール・gcloud・API のいずれからでも有効化/無効化できる
  • セットアップ失敗時も Operations タブでエラーを確認し、再度有効化を試行できる

Identity Connector はクラスタに紐づくサービス アカウント (Principal) を介して Cloud KMS (CMEK) などの Google Cloud サービスへの接続を担います。今回の GA により、この接続コンポーネントを クラスタ作成時に省略したり、作成後にいつでも有効化/無効化したりできるようになりました。

⚡ 主要機能

1️⃣ Identity Connector なしでのクラスタ作成
→従来はクラスタ作成時にデフォルトで自動作成されていた
→gcloud では --identity-connector-disabled フラグで自動プロビジョニングを無効化 (省略時または false の場合は従来どおり自動作成)
→Google Cloud CMEK を利用する予定がない場合、不要なコンポーネントの作成を省略できる
2️⃣ 作成後の Identity Connector 有効化
→Exadata VM Cluster: gcloud oracle-database cloud-vm-clusters enable-identity-connector
→Exascale VM Cluster: gcloud oracle-database exadb-vm-clusters enable-identity-connector
→コンソールではクラスタ詳細ページ「Identity Connector」セクションの「Manage」ダイアログのトグルで切り替え
→有効化には数分かかる場合があり、リージョンによってはさらに時間を要することがある
3️⃣ 作成後の Identity Connector 無効化
→Exadata VM Cluster: gcloud oracle-database cloud-vm-clusters disable-identity-connector
→Exascale VM Cluster: gcloud oracle-database exadb-vm-clusters disable-identity-connector
→無効化するとクラスタに関連付けられたサービス アカウント (Principal 含む) が削除される
→操作の進行状況はクラスタ詳細ページの「Operations」タブで確認できる

🛠️ 設定方法

✅ 前提条件

✓Oracle Database@Google Cloud API が有効化されており、対象の Exadata VM Cluster または Exascale VM Cluster が存在すること
✓enable/disable IdentityConnector の IAM 権限を含むロールが付与されていること
✓プロジェクトが VPC Service Controls の境界内にある場合、必要な egress ルールを追加していること (追加しないと Identity Connector は接続できない)

ステップ 1: Identity Connector を有効化する (gcloud)

Bash 作成後の有効化 
# Exadata VM Cluster の場合
gcloud oracle-database cloud-vm-clusters enable-identity-connector CLUSTER_ID \
  --project=PROJECT_ID \
  --location=REGION

# Exascale VM Cluster の場合
gcloud oracle-database exadb-vm-clusters enable-identity-connector CLUSTER_ID \
  --project=PROJECT_ID \
  --location=REGION

💻 コンソールの場合: クラスタ詳細ページの「Identity Connector」セクションで「Manage」をクリックし、 「Identity Connector enabled」トグルをオンにして保存します。

ステップ 2: Identity Connector を無効化する (gcloud / API)

Bash 作成後の無効化 
# Exadata VM Cluster の場合 (gcloud)
gcloud oracle-database cloud-vm-clusters disable-identity-connector CLUSTER_ID \
  --project=PROJECT_ID \
  --location=REGION

# Exascale VM Cluster の場合 (REST API)
curl -X POST \
  -H "Authorization: Bearer $(gcloud auth print-access-token)" \
  -H "Content-Type: application/json" \
  "https://oracledatabase.googleapis.com/v1/projects/PROJECT_ID/locations/REGION/exadbVmClusters/CLUSTER_ID:disableIdentityConnector" \
  -d '{}'
⚠️ 注意: 無効化の前に、クラスタ上のデータベースが CMEK を使用していないことを確認してください (CMEK 使用中は無効化できません)。

ステップ 3: 操作状況の確認

クラスタ詳細ページの「Operations」タブで、有効化/無効化オペレーションの状況とエラーの有無を確認します。 クラスタ作成時に Identity Connector のステータスが「Not enabled」になっている場合も、同タブでセットアップ エラーを確認してから再度有効化を試行します。

🌟 メリット

💼 ビジネス面

✓構成の柔軟性向上: CMEK を使う/使わないというセキュリティ方針の変更に対して、クラスタを再作成することなく Identity Connector の有効/無効で追従できる
✓最小権限の原則への準拠: CMEK を利用しない環境では Google Cloud サービスへの接続経路 (サービス アカウント) 自体を持たない構成を選択でき、監査やコンプライアンス要件に対応しやすい

⚙️ 技術面

✓マルチインターフェース対応: コンソール・gcloud CLI・REST API のすべてで同一操作が可能で、IaC や運用自動化に組み込みやすい
✓障害復旧手順の明確化: クラスタ作成時に Identity Connector のセットアップが失敗しても、クラスタ自体は作成され、後から有効化を再試行できる

⚠️ デメリット・制約事項

🚧 制限事項

✗クラスタ上のいずれかのデータベースが Google Cloud CMEK を使用している間は、Identity Connector を無効化できない。先に対象データベースを Oracle 管理キーに切り替える必要がある
✗無効化するとクラスタに関連付けられたサービス アカウント (Principal 含む) が削除される。再有効化すると新しいサービス アカウントが作成され、以前の IAM ロールと権限は引き継がれないため、新しい Principal に鍵へのアクセス権を再付与する必要がある

🤔 考慮すべき点

  • Google Cloud CMEK を利用する場合、Identity Connector の有効化は必須の前提条件
  • 有効化には数分以上かかる場合がある (リージョンによって所要時間が異なる)
  • VPC Service Controls の境界内にあるプロジェクトでは、必要な egress ルールを追加しないと Identity Connector は接続できない
  • クラスタ作成時にセットアップが失敗してもクラスタ作成自体は成功する場合があるため、作成後にステータスが「Not enabled」でないか確認するとよい

🎯 ユースケース

📦 ユースケース 1: CMEK 非利用環境での最小構成クラスタ作成

シナリオ: Oracle 管理キーのみで運用するポリシーの組織が、Google Cloud サービスへの接続コンポーネントを持たない Exascale VM Cluster を作成したい。

Bash Identity Connector なしでクラスタを作成 
gcloud oracle-database exadb-vm-clusters create my-cluster \
  --location=us-east4 \
  --identity-connector-disabled \
  ... # その他の必須フラグ

✅ 効果: 不要なサービス アカウントが作成されず、クラスタから Google Cloud サービスへの接続経路を持たない、シンプルかつ監査しやすい構成を実現できる。

🔑 ユースケース 2: 運用途中からの CMEK 導入

シナリオ: Identity Connector なしで作成・運用してきた Exadata VM Cluster で、セキュリティ要件の強化に伴い Google Cloud CMEK の利用が決定した。

🔗 関連サービス・機能

→Cloud KMS / CMEK: Identity Connector は、クラスタが Cloud KMS や CMEK に接続するための前提コンポーネント。CMEK を利用する場合は有効化が必須
→IAM: 有効化/無効化には専用の IAM 権限が必要。有効化時に作成される Principal への鍵アクセス権付与も IAM で管理
→VPC Service Controls: サービス境界内のプロジェクトでは、Identity Connector の接続に egress ルールの設定が必要
→Workload Identity Federation: Identity Connector は、サービス アカウント キーを使わずに外部ワークロードから Google Cloud リソースへアクセスする仕組みの一種 (Workload Identity Connector) として機能

✓CMEK の利用方針に応じて、接続コンポーネントの有無を柔軟に制御できる
✓運用チームは自社のセキュリティ要件に照らして Identity Connector の要否を見直し、無効化時のサービス アカウント削除と再有効化時の権限再付与の挙動を運用手順に反映することを推奨
