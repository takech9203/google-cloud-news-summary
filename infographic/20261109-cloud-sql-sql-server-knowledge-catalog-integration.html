📋 概要

2026 年 11 月 9 日以降に新規作成される Cloud SQL for SQL Server インスタンスは、メタデータとスキーマの更新を Knowledge Catalog (旧 Dataplex Universal Catalog) にニアリアルタイムで送信するようになりました。 統合は新規インスタンスでデフォルトで有効化されており、必要に応じていつでも設定の確認・変更が可能です。

Knowledge Catalog はメタデータの保存・管理・アクセスを一元化するプラットフォームで、データガバナンスと生成 AI の機能を統合した AI 駆動のコンテキストグラフを提供します。本統合により、インスタンス、データベース、テーブル、カラム、ビューの メタデータが自動的にカタログへ取り込まれ、データディスカバリー、分類、変更管理、スキーマ進化の追跡に活用できます。

データガバナンスを担うデータエンジニア、データスチュワード、SQL Server のメタデータを AI エージェントのグラウンディングに利用したいチームにとって、 カタログ鮮度の課題を解消する重要なアップデートです。

❌ Before: アップデート前の課題

  • メタデータの更新頻度は約 1 日 1 回 で、DDL・スキーマ変更の反映に最大 1 日程度のラグが発生
  • カタログ上のメタデータが古くなり得るため、ディスカバリーや AI グラウンディングで最新スキーマを参照できない場合があった
  • 新規インスタンスでも統合設定を意識する必要があり、有効化状況がインスタンスごとにばらつく可能性

✅ After: アップデート後の改善

  • 新規インスタンスではメタデータ・スキーマ更新をニアリアルタイム送信 (DDL / スキーマ変更は約 10 分以内に反映)
  • 統合がデフォルトで有効になり、追加設定なしでカタログ連携が開始
  • 統合状態はいつでも確認・変更 (有効化 / 無効化) でき、運用ポリシーに応じた柔軟な制御が可能

新規作成された Cloud SQL for SQL Server インスタンスのメタデータ・スキーマ変更がニアリアルタイムで Knowledge Catalog に送信され、 データ利用者や AI エージェントが常に最新のメタデータを検索・参照できる構成です。

⚡ 主要機能

1️⃣ ニアリアルタイムのメタデータ同期

→2026 年 11 月 9 日以降に作成された新規インスタンスで、メタデータ・スキーマ更新を Knowledge Catalog にニアリアルタイムで送信
→新しい DDL やスキーマ変更は約 10 分以内にカタログへ反映、インスタンス上の既存リソースは 24 時間以内に取り込み

2️⃣ 新規インスタンスでのデフォルト有効化

→Knowledge Catalog 統合は新規作成インスタンスでデフォルトで有効
→統合状態はいつでも確認・変更可能。gcloud sql instances patch、Google Cloud コンソール、REST API から制御できる

3️⃣ 自動収集されるメタデータ

→インスタンス、データベース、テーブル、カラム、ビューから自動収集: 名前、ロケーション (リージョン)、作成日・最終更新日、スキーマ (テーブル・ビュー)、説明、主キー・外部キー制約
→収集対象はプライマリインスタンスのみ (リードレプリカ・外部サーバーレプリカは対象外)

🛠️ 設定方法

✅ 前提条件

✓プロジェクトで Dataplex API を有効化していること
✓cloudsql.schemas.view 権限を含む IAM ロール (カスタムロールまたは事前定義ロール) が付与されていること

ステップ 1: 統合状態の確認・有効化

Bash 
# 既存インスタンスで Knowledge Catalog 統合を有効化する
gcloud sql instances patch INSTANCE_NAME \
  --enable-dataplex-integration
💡 ヒント: 2026 年 11 月 9 日以降の新規インスタンスではデフォルトで有効のため、追加操作は不要です。プロジェクト内の全インスタンスを一括で有効化するスクリプトも公式ドキュメントで案内されています。

ステップ 2: 統合の無効化 (必要な場合)

Bash 
# Knowledge Catalog 統合を無効化する
gcloud sql instances patch INSTANCE_NAME \
  --no-enable-dataplex-integration

ニアリアルタイム統合の無効化には最大 10 分かかります。REST API の場合は settings.enableDataplexIntegration を false に設定します。

🚧 制限事項

✗ニアリアルタイム更新は新しいネットワークアーキテクチャのインスタンスが対象。旧ネットワークアーキテクチャのインスタンスは 1 日 1 回の更新

🤔 考慮すべき点

⚠️cloudsql.schemas.view 権限はプロジェクトレベルで付与されるため、付与されたユーザーはプロジェクト内のすべての Cloud SQL インスタンスのメタデータを閲覧できる。権限設計に注意が必要
⚠️新規インスタンスでデフォルト有効となるため、メタデータをカタログに送信したくない場合は明示的に無効化する必要がある
⚠️ニアリアルタイム統合の無効化には最大 10 分かかる

🎯 ユースケース

📌 ユースケース 1: スキーマ変更のニアリアルタイム追跡によるデータガバナンス

シナリオ: 複数チームが共有する SQL Server データベースで頻繁にテーブル追加・カラム変更が行われており、データスチュワードが変更を迅速に把握してガバナンスポリシー (PII 分類など) を適用したい。

実装例:

Bash 
# Knowledge Catalog でメタデータエントリを検索
gcloud dataplex entries search "system=cloudsql" --project=PROJECT_ID

効果: DDL 変更が約 10 分以内にカタログへ反映されるため、新規テーブルの検出とアスペクト (例: pii:true) の付与をタイムリーに実施でき、ガバナンスの抜け漏れを防止できる。

🤖 ユースケース 2: AI エージェントのグラウンディングに最新スキーマを提供

シナリオ: text-to-SQL などの AI エージェントが Knowledge Catalog の MCP 統合経由でスキーマコンテキストを取得しており、古いスキーマ情報による SQL 生成エラーを防ぎたい。

効果: SQL Server のスキーマ変更がニアリアルタイムでカタログに反映されるため、AI エージェントは常に最新のテーブル定義・制約情報に基づいて正確なクエリを生成できる。
