🖥️ GPU 有効ジョブの最大 12 時間実行

長時間 GPU バッチ処理をサーバーレスで — LLM ファインチューニングもジョブ 1 本で
📅 リリース日: 2026-10-30

📝 概要

GPU を有効にした Cloud Run ジョブのタスクタイムアウトを最大 12 時間まで設定できる機能が Preview として登場しました。タスクタイムアウトはデフォルト 10 分、GPU なしタスクでは最大 168 時間 (7 日間) まで設定可能で、GPU タスクも今回の Preview により長時間実行に対応します。

LLM のファインチューニング、バッチ/オフライン推論、動画処理・レンダリングなど、 長時間の GPU 計算をサーバーレスかつフルマネージドな環境で実行できます。ドライバーの追加インストールは不要、 予約なしのオンデマンド利用で、GPU 付きインスタンスは約 5 秒で起動します。

🕐 アップデート前の課題

  • GPU 有効ジョブでは長時間のタスクタイムアウトを設定できず、LLM ファインチューニングや大規模バッチ推論のような数時間単位の GPU ワークロードを 1 タスクとして実行することが困難
  • 長時間の GPU バッチ処理には GKE や Compute Engine など、より運用負荷の高い環境を選択する必要があった

✅ アップデート後の改善

  • GPU 有効ジョブのタスクタイムアウトを最大 12 時間まで設定可能に (Preview)
  • ファインチューニング、バッチ/オフライン推論、動画処理などの長時間 GPU ワークロードをサーバーレスの Cloud Run ジョブで完結
  • チェックポイント + リトライ構成で、メンテナンス中断に耐性のある長時間 GPU ジョブを設計可能
⚠️ 重要: タスクタイムアウトは「試行 1 回あたりの最大実行時間」であり、中断なし実行の保証ではありません。 GPU タスクはライブマイグレーションされないため、数時間規模のタスクは少なくとも 1 回の中断 (メンテナンスによる終了) を想定し、 チェックポイントと再開を前提とした設計が公式に推奨されています。

GPU を有効にした Cloud Run ジョブのタスクタイムアウトが最大 12 時間に拡張され、Cloud Storage へのチェックポイント保存と リトライ設定を組み合わせることで、中断に耐性のある長時間 GPU バッチ処理をサーバーレスで実行できます。

🚀 主要機能

1️⃣ GPU タスクの最大 12 時間実行 (Preview)

→GPU を使用するタスクのタスクタイムアウトを最大 12 時間まで設定可能
→デフォルトは 10 分。GPU を使用しないタスクは最大 168 時間 (7 日間) まで設定可能
→タイムアウトはタスクの試行 1 回ごとに適用される (リトライ有効時は各試行に適用)

2️⃣ 中断を前提とした長時間実行の設計ガイド

→GPU タスクはライブマイグレーションされず、定期的なインフラメンテナンスで終了される
→終了の 10 秒前に SIGTERM が送信され、小さな状態の最終フラッシュに利用可能
→大きなモデルチェックポイントの書き込みには 10 秒では不十分 → 定期的なチェックポイント保存を主たる保護手段に
→公式チュートリアル「Design resilient long-running GPU jobs」でチェックポイント + 再開パターンを提供

3️⃣ リトライによる自動再開

→1 時間超のタイムアウトではデフォルトの 3 リトライを推奨 (0 リトライはメンテナンス時のサイレント失敗につながるため非推奨)
→合計実行時間の上限は「タイムアウト × (リトライ回数 + 1)」となる点に注意
→メンテナンス中断時はシステムログに INSTANCE_PREEMPTED が記録され、タスクは自動的に再起動

🛠️ 設定方法

📋 前提条件

✓Cloud Run API が有効化されていること
✓IAM ロール: Cloud Run デベロッパー (roles/run.developer) とサービス アカウント ユーザー (roles/iam.serviceAccountUser)
✓対象リージョンに十分な GPU クォータ (非ゾーン冗長) があること
✓並列実行する場合は parallelism をプロジェクトの GPU クォータ未満に設定すること

ステップ 1: GPU と長時間タイムアウトを有効にしたジョブをデプロイ

Bash GPU ジョブのデプロイ (12 時間タイムアウト + チェックポイント用ボリューム) 
gcloud run jobs deploy my-gpu-job \
  --image=IMAGE_URL \
  --region=REGION \
  --gpu=1 \
  --gpu-type=nvidia-l4 \
  --no-gpu-zonal-redundancy \
  --task-timeout=12h \
  --max-retries=3 \
  --add-volume=name=checkpoint-volume,type=cloud-storage,bucket=CHECKPOINT_BUCKET \
  --add-volume-mount=volume=checkpoint-volume,mount-path=/checkpoints
💡 ポイント: ジョブで GPU を使用するには --no-gpu-zonal-redundancy の指定が必須です。 --task-timeout=12h で GPU タスクの最大タイムアウトを設定し、Cloud Storage ボリュームマウントでチェックポイントを永続化します。 L4 GPU では最低 4 vCPU / 16 GiB メモリが必要です。

ステップ 2: ジョブを実行して監視

Bash ジョブの実行 
gcloud run jobs execute my-gpu-job --region=REGION

実行後は Logs Explorer でログを監視します。メンテナンスイベントが発生すると INSTANCE_PREEMPTED を理由とする システムログが記録され、リトライ設定に従ってタスクが自動的に再起動されます。アプリケーション側ではチェックポイントからの 再開処理を実装しておきます。

💡 メリット

💼 ビジネス面

✓インフラ運用コストの削減: 長時間 GPU バッチのために GKE クラスタや GPU VM を構築・運用する必要がなく、サーバーレスで完結
✓オンデマンド利用: 予約不要で GPU を利用でき、ジョブ実行中のみ課金されるため、散発的なバッチワークロードのコスト効率が高い

🔧 技術面

✓フルマネージドな GPU 環境: NVIDIA ドライバーがプリインストール済みで、GPU 付きインスタンスが約 5 秒で起動
✓長時間ワークロードへの対応: ファインチューニングや大規模バッチ推論など、従来はジョブに収まらなかった数時間単位の処理を 1 タスクとして実行可能
✓回復性のある設計パターン: SIGTERM ハンドリング、チェックポイント、リトライを組み合わせた公式のレジリエンス設計ガイドを提供

⚠️ デメリット・制約事項

🚧 制限事項

✗Preview 機能であり、Pre-GA Offerings Terms が適用される (サポートが限定的な場合がある)
✗GPU タスクの最大タイムアウトは 12 時間 (GPU なしタスクの 168 時間より短い)
✗ジョブの GPU は非ゾーン冗長のみサポート (フェイルオーバーはベストエフォート)
✗インスタンスあたり 1 GPU のみ。サイドカー使用時は GPU を 1 コンテナにのみアタッチ可能
✗利用可能リージョンが限定されている (下記「利用可能リージョン」参照)

🤔 考慮すべき点

→タスクタイムアウトは中断なし実行の保証ではない。GPU タスクはライブマイグレーションされないため、数時間のタスクは少なくとも 1 回の中断を想定して設計する必要がある
→SIGTERM 後の猶予は約 10 秒であり、大きなチェックポイントの書き込みには不十分。定期チェックポイントを主たる保護手段とする
→リトライ有効時の合計実行時間は「タイムアウト × (リトライ回数 + 1)」となり、GPU は各試行の全期間に課金されるため、コスト上限を見積もっておく
→並列実行 (parallelism) は GPU クォータ未満に設定しないとデプロイが失敗する

🎯 ユースケース

🧠 ユースケース 1: オープンモデルのファインチューニング

シナリオ: 社内データを使って Gemma などのオープンモデルを定期的にファインチューニングしたい。 処理には数時間かかるが、専用の GPU クラスタを常時運用したくない。

Bash ファインチューニングジョブのデプロイ例 
gcloud run jobs deploy finetune-job \
  --source=. \
  --region=us-central1 \
  --gpu=1 --gpu-type=nvidia-l4 --no-gpu-zonal-redundancy \
  --task-timeout=12h --max-retries=3 \
  --add-volume=name=ckpt,type=cloud-storage,bucket=my-checkpoints \
  --add-volume-mount=volume=ckpt,mount-path=/checkpoints

効果: GPU クラスタの常時運用なしに、チェックポイントからの再開に対応した数時間規模の ファインチューニングをサーバーレスで実行できる。

🎬 ユースケース 2: LLM による大規模バッチ推論・メディア処理

シナリオ: 蓄積したドキュメントやメディアファイルに対して、夜間に LLM によるバッチ推論や 動画のトランスコード/レンダリングをまとめて実行したい。

効果: Cloud Scheduler などと組み合わせて夜間に GPU ジョブを起動し、最大 12 時間のウィンドウで 大量データを処理できる。処理中のみ課金されるためコスト効率が高い。

💰 料金

ジョブの GPU は非ゾーン冗長 (non-zonal redundancy) 料金が適用されます。 GPU はインスタンスのライフサイクル全体 (各試行の全期間) に対して課金され、CPU・メモリの料金が別途かかります。 リトライ発生時は試行ごとに課金される点に注意してください。

🔗 関連サービス・機能

→Cloud Storage: チェックポイントの永続化先。ボリュームマウントでジョブのコンテナに直接マウント可能
→Cloud Logging: ジョブの実行ログや INSTANCE_PREEMPTED などのメンテナンスイベントの監視に使用
→Cloud Build / Artifact Registry: ジョブ用コンテナイメージのビルドと管理
→Cloud Scheduler: ジョブの定期実行 (夜間バッチなど) のトリガーに使用
→GKE (Autopilot/Standard): 12 時間を超える GPU ワークロードや複数 GPU が必要な場合の代替手段
