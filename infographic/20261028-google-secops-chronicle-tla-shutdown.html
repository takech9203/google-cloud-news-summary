🛡️ Google SecOps: レガシー Google 管理 BigQuery エクスポートデータセット (chronicle-tla) の最終シャットダウン

Google SecOps / SIEM Deprecated / Shutdown BigQuery エクスポート
📅 リリース日: 2026-10-28 | サービス: Google SecOps / Google SecOps SIEM
🚨 重要: 2026 年 10 月 28 日 より、chronicle-tla プロジェクト配下のレガシー Google 管理 BigQuery データセットへのエクスポートが恒久的に停止され、マネージドデータセットと API キーの廃止処理が開始されます。未対応の非 Enterprise+ 顧客は即時の対応が必要です。

📋 概要

Google SecOps は、2025 年 3 月 26 日の廃止 (deprecation) 発表に続き、chronicle-tla Google Cloud プロジェクトに関連付けられたレガシー Google 管理 BigQuery データセットおよび API キーの最終シャットダウンを完了します。影響を受けるのは、レガシーデータセットにプロビジョニングされたままの非 Enterprise+ 顧客のみです。BigQuery アクセスを維持するには、BYOBQ (Bring Your Own BigQuery) の構成、または Enterprise+ へのアップグレードが必要です。

❌ Before: アップデート前の課題

  • 非 Enterprise+ 顧客の一部は、廃止予定が告知済みのレガシー chronicle-tla データセットと API キーに依存したままエクスポートを継続
  • 2024 年 12 月 31 日の廃止開始以降の一時的な移行例外も、2025 年 9 月に期限切れ
  • Google 管理プロジェクト上のデータセットでは、IAM 権限を顧客が独立して管理できない

✅ After: 変更内容

  • 2026-10-28 よりレガシーデータセットへのエクスポートが恒久停止、データセットと API キーが廃止
  • 顧客管理プロジェクトへの BYOBQ 移行により、自組織の Google Cloud プロジェクト内で IAM 権限を独立管理
  • Enterprise+ へのアップグレードという選択肢も提供され、ティアに応じた明確なエクスポートモデルに整理

レガシーの chronicle-tla Google 管理データセットへのエクスポート (上) は 2026 年 10 月 28 日から恒久停止されるため、非 Enterprise+ 顧客は顧客管理 BigQuery プロジェクトへの BYOBQ エクスポート構成、または Enterprise+ へのアップグレード (下) への移行が必要です。

🎯 主要なポイント

🛑 変更内容: レガシーエクスポートの恒久停止

✖chronicle-tla プロジェクト配下のレガシー Google 管理 BigQuery データセットへのデータエクスポートが恒久的に停止
✖関連するマネージドデータセットおよび API キーが廃止
→廃止処理は 2026 年 10 月 28 日 に開始

👥 影響範囲: 非 Enterprise+ 顧客のみ

⚠対象: レガシー chronicle-tla データセットにプロビジョニングされたままの非 Enterprise+ 顧客 (2025 年 9 月に移行例外が期限切れとなったテナントを含む)
✓対象外: Enterprise+ 顧客、および顧客管理プロジェクトへの BYOBQ エクスポートを既に使用している顧客

🚀 必要なアクション

→顧客管理 BigQuery プロジェクトへのエクスポート (BYOBQ) を構成する
→または、アカウントチームに連絡して Enterprise+ へアップグレードする

🗄️ 移行先: BYOBQ (Bring Your Own BigQuery)

自組織が所有・管理する Google Cloud プロジェクトを Google SecOps インスタンスにリンクし、Unified Data Model (UDM) データをエクスポート。Google 管理側の設定に依存せず、IAM 権限を独立して管理できます。

1

エクスポート先の Google Cloud プロジェクトを作成・構成

Google SecOps 用に Google Cloud プロジェクトを構成します (公式ドキュメント「Configure a Google Cloud project for Google SecOps」参照)。

2

自己管理プロジェクトを Google SecOps インスタンスにリンク

Google SecOps と自己管理プロジェクト間の接続を確立します (公式ドキュメント「Link Google Security Operations to Google Cloud services」参照)。一度有効化すると Google 管理プロジェクトには戻せない点に注意。

3

BYOBQ を有効化

Google SecOps コンソールで SIEM Settings > Data Export を選択し、BYOBQ 機能を有効化・構成。データタイプごとに保持期間 (Retention Period) を設定でき、Unlimited も選択可能。

4

エクスポートの検証とアクセス権の付与

SQL エクスポート先テーブルの確認 
-- 自己管理プロジェクトの datalake データセットにテーブルが作成されたことを確認
SELECT table_name
FROM `PROJECT_ID.datalake.INFORMATION_SCHEMA.TABLES`;

データが datalake データセット配下のテーブルにエクスポートされていることを確認し、クエリを実行するユーザーに roles/bigquery.dataViewer、roles/bigquery.jobUser、roles/storage.objectViewer を付与します。

⚖️ メリットとデメリット・制約事項

✅ メリット (ビジネス面)
✓BigQuery アクセスの継続: 期限 (2026-10-28) 前に BYOBQ へ移行することで、ダッシュボードやアドホック分析など BigQuery ベースのワークフローを中断なく継続
✓選択肢の明確化: BYOBQ (自己管理・自己負担) と Enterprise+ (Advanced BigQuery Export) という、ティアに応じた明確なエクスポートモデルに整理
✅ メリット (技術面)
✓IAM の独立管理: 顧客管理プロジェクトでは、Google 管理側の設定に依存せず IAM 権限を独立して管理可能
✓BigQuery エコシステムの活用: アドホック SQL クエリや BigQuery と統合するサードパーティ BI ツールによる高度な分析が可能
⚠️ 制限事項
✖レガシー chronicle-tla データセットから自己管理プロジェクトへ既存データは移行されない (移行前後のデータは別プロジェクトに分かれる)
✖BYOBQ を有効化すると Google 管理プロジェクトには戻せない
✖BYOBQ は Enterprise Plus では利用不可 (Enterprise Plus は Advanced BigQuery Export を利用)
✖エクスポート用リソースは Google SecOps インスタンスと同一リージョンに作成される
🚨 考慮すべき点
!2026 年 10 月 28 日から廃止処理が開始されるため、未対応の非 Enterprise+ 顧客は即時の対応が必要
!BYOBQ では顧客プロジェクト側で BigQuery のストレージ・コンピューティングコストを負担
!レガシー API キーも廃止されるため、chronicle-tla 向け API キーに依存する自動化・連携処理は BYOBQ 前提の構成に見直しが必要
!有効化日をまたぐ期間のクエリは、両プロジェクトを結合する単一クエリか、プロジェクトごとの個別クエリで対応

💼 ユースケース

🚑 ユースケース 1: レガシーデータセット利用中の Standard / Enterprise 顧客の緊急移行

シナリオ: 非 Enterprise+ の SOC チームが、chronicle-tla の Google 管理データセットに対するスケジュールクエリで日次のセキュリティレポートを生成している。

Text 実装例 
1. エクスポート先の Google Cloud プロジェクトを作成し SecOps インスタンスにリンク
2. SIEM Settings > Data Export で BYOBQ を有効化
3. スケジュールクエリの参照先を自己管理プロジェクトの datalake データセットに変更
4. アナリストに bigquery.dataViewer / bigquery.jobUser を付与

効果: エクスポート停止によるレポート断絶を回避し、以後は自組織の IAM で権限を一元管理できる。

🏢 ユースケース 2: 大規模環境での Enterprise+ アップグレード

シナリオ: BigQuery のストレージ・コンピューティングコストの自己負担を避けたい、またはニアリアルタイムのデータ利用を求める大規模組織。

効果: アカウントチーム経由で Enterprise+ にアップグレードすることで本シャットダウンの影響対象外となる。Enterprise Plus 向けには、ストレージ・ストリーミングコストを Google SecOps 側が負担する Advanced BigQuery Export (Preview) が提供されている。

💰 料金

本アナウンス自体に新たな料金は発生しませんが、移行方式によってコスト負担が異なります。

移行先コスト負担
BYOBQ (顧客管理プロジェクト)顧客側で BigQuery のストレージおよびコンピューティング (クエリ) コストが発生し得る
Enterprise Plus (Advanced BigQuery Export)バックエンドのストレージ・ストリーミング挿入・DML コンピューティングコストは Google SecOps 側が負担。顧客は自ら実行するクエリの料金のみ支払う

詳細は BigQuery の料金ページ を参照してください。

🔗 関連サービス・機能

📊 BigQuery

エクスポート先のデータウェアハウス。BYOBQ では顧客管理プロジェクトの datalake データセットに UDM データが格納される。

🪣 Cloud Storage

エクスポートに伴い自己管理プロジェクト内に作成されるリソースの 1 つ。オブジェクトライフサイクルルールで保持管理が可能。

🔐 IAM

BYOBQ 移行後のデータアクセス制御 (bigquery.dataViewer、bigquery.jobUser、storage.objectViewer)。

⚡ Advanced BigQuery Export (Preview)

Enterprise Plus 顧客向けのフルマネージド・ストリーミングエクスポート。レガシーエクスポートのスキーマと互換のビューを提供。

📝 まとめ

2026 年 10 月 28 日より、chronicle-tla プロジェクト配下のレガシー Google 管理 BigQuery データセットと API キーの最終廃止処理が開始され、非 Enterprise+ 顧客のエクスポートは恒久的に停止されます。2025 年 3 月の廃止発表と 2025 年 9 月の移行例外期限を経た最終段階であり、該当する顧客は BigQuery アクセスを維持するために、顧客管理プロジェクトへの BYOBQ エクスポートの構成、またはアカウントチーム経由での Enterprise+ へのアップグレードを直ちに実施する必要があります。既存データはレガシーデータセットから移行されない点にも留意し、必要なデータの参照戦略を含めて移行計画を確定してください。
