🛡️ Cloud Service Mesh: セキュリティプロキシ更新

Cloud Service Mesh Security Update Rolling Out
2026-05-13

📋 概要

Managed Cloud Service Mesh において、新しいプロキシバージョン csm_mesh_proxy.20260423_RC03 が全てのリリースチャネル (Rapid, Regular, Stable) に対してロールアウトされています。セキュリティ関連の更新であるため、通常の段階的昇格プロセスではなく、全チャネルに同時展開されます。

❌ アップデート前

•以前のプロキシバージョンで Gateway API on GKE が動作
•セキュリティパッチが未適用のプロキシが稼働中
•既知の脆弱性が存在する状態

✅ アップデート後

•最新セキュリティ修正が適用される
•全チャネルで統一的にセキュリティ向上
•手動操作なしで自動更新 (マネージド有効時)

⭐ 主要機能

📦 プロキシバージョンの更新

→新バージョン: csm_mesh_proxy.20260423_RC03
→対象: Gateway API on GKE クラスタ
→全リリースチャネル (Rapid, Regular, Stable) に同時ロールアウト

⚙️ 自動ロールアウトメカニズム

→マネージドデータプレーン有効時: Pod 再起動で新プロキシが自動インジェクト
→Pod Disruption Budget (PDB) を尊重した段階的な更新
→GKE メンテナンスウィンドウを待たずに即時開始

📋 リリースチャネル連動

→Rapid: 最新版を最も早く取得
→Regular: Rapid で検証された安定版 (推奨)
→Stable: Regular で十分に検証された最も安定したバージョン

🛠️ ロールアウト中のユーザー対応

✅ マネージドデータプレーン有効時

特別な対応は不要。Google が自動的にプロキシを更新します。

✓PDB 設定があればサービス可用性を維持
✓メンテナンスウィンドウに関わらず更新開始
✓通常 2 週間以内に完了

⚠️ マネージドデータプレーン無効時

手動でのプロキシ更新が必要です。

→コントロールプレーンとプロキシのバージョンを確認
→コントロールプレーンが新しい場合、rollout restart を実行
Bash 
# コントロールプレーンとプロキシのバージョンを確認
# コントロールプレーンが新しい場合、以下のコマンドでプロキシを更新

kubectl rollout restart deployment -n NAMESPACE

Pod Disruption Budget の推奨設定

ロールアウト中のサービス可用性を確保するため、適切な PDB を設定することを推奨します。

YAML 
apiVersion: policy/v1
kind: PodDisruptionBudget
metadata:
  name: my-service-pdb
spec:
  minAvailable: "50%"
  selector:
    matchLabels:
      app: my-service

⚠️ 制約事項・注意点

自動更新の対象外

  • ✗インジェクトされていない Pod
  • ✗手動でインジェクトされた Pod
  • ✗Jobs
  • ✗StatefulSets
  • ✗DaemonSets
⚠️ 考慮すべき点:
  • ロールアウト中に Pod の再起動が発生するため、短時間の接続断が起こる可能性がある
  • PDB が適切に設定されていない場合、一時的にサービスの可用性が低下する可能性がある
  • セキュリティ更新は GKE メンテナンスウィンドウを無視して実行される
  • マネージドデータプレーンが無効な環境では、手動での対応が必要
