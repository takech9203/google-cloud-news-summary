📋 概要

2026 年 10 月 22 日、COS の最新 LTS マイルストーン cos-133-19999-44-159 (Kernel COS-6.18.55 / Docker v29.4.3 / Containerd v2.4.1) がリリースされました。 AMD CPUID faulting の KVM 仮想化サポートと ARM イメージへの nvidia-container-toolkit 追加という 2 つの新機能に加え、 curl・glibc・Go・Kubernetes・Docker・guest-agent など広範囲なコンポーネントの CVE が修正されています。

同日、サポート中の他マイルストーンにも LTS Refresh リリース (cos-125-19216-760-8 / cos-121-18867-652-7 / cos-129-19506-578-9) が提供されました。 LTS Refresh は約 3 か月ごとに中・低優先度のバグ修正とセキュリティ修正をまとめて提供する定期リリースで、 今回は全マイルストーン共通で cos-gpu-installer v2.7.11 と toolbox v20261020 への更新、多数の CVE 修正が適用されています。

💡 特筆ポイント: 全リリース共通で ca-certificates (v20260816.3.125) と nss (v3.131.1) のアップグレードにより、eMudhra 中間証明書侵害の影響を受けた証明書が削除されました。 GKE ノードや Compute Engine 上で COS を利用するすべてのユーザーにとって、信頼ストアの健全性を保つ重要なセキュリティ対応です。

❌ Before (アップデート前の課題)

  • curl の CVE-2026-80256、glibc の CVE-2026-5435、Go の CVE-2026-111943 など多数の未修正 CVE が存在
  • eMudhra 中間証明書侵害の影響を受けた証明書が信頼ストア (ca-certificates / nss) に残存
  • cos-133 の ARM イメージには nvidia-container-toolkit がなく、x86 イメージと構成差分があった
  • cos-133 の KVM 仮想化で AMD CPUID faulting が未サポート

✅ After (アップデート後の改善)

  • 各 LTS マイルストーン (133/129/125/121) で広範な CVE 修正が適用され、イメージ更新のみでリスク低減
  • eMudhra 侵害の影響を受けた証明書が削除され、信頼ストアが浄化
  • ARM イメージでも nvidia-container-toolkit が利用可能になり、ARM GPU ワークロード構成が容易に
  • AMD CPUID faulting の KVM サポートが追加され、ネスト仮想化で AMD CPU の機能を活用可能に

🛠️ 設定方法

✅ 前提条件

✓Google Cloud プロジェクトで Compute Engine API が有効であること
✓GKE の場合はノードイメージタイプに Container-Optimized OS (containerd) を使用していること

ステップ 1: 最新イメージの確認

Bash cos-cloud プロジェクトの最新イメージを一覧表示 
# cos-cloud プロジェクトの最新イメージを一覧表示
gcloud compute images list \
  --project cos-cloud \
  --filter="family~cos-133-lts OR family~cos-125-lts OR family~cos-121-lts OR family~cos-129-lts" \
  --sort-by=~creationTimestamp

各 LTS ファミリーで公開されている最新イメージ (今回のリリースバージョン) を確認します。

ステップ 2: 新イメージでの VM 作成 (Compute Engine)

Bash 特定イメージ名を指定して VM を作成 
# 検証した特定イメージ名を指定して VM を作成
# (本番環境では image-family ではなく特定イメージの指定を推奨)
gcloud compute instances create my-cos-instance \
  --image cos-133-19999-44-159 \
  --image-project cos-cloud \
  --zone asia-northeast1-a
💡 ヒント: 公式ドキュメントでは、本番環境では Image Family API に依存せず、 検証済みの特定イメージ名を指定することが推奨されています。

🚀 メリット

💼 ビジネス面

✓セキュリティコンプライアンスの維持: 多数の CVE 修正と eMudhra 侵害証明書の削除により、イメージ更新だけで脆弱性対応と信頼ストアの健全化を実現できる
✓更新リスクの管理: LTS Refresh は四半期ごとの計画的なリリースであるため、更新作業のスケジュールを立てやすい

🔧 技術面

✓広範な CVE 修正の一括適用: curl、glibc、Go、Kubernetes、Docker、ゲストエージェント群など OS 全域の脆弱性修正が 1 回のイメージ更新で適用される
✓ARM GPU 構成の簡素化: cos-133 の ARM イメージに nvidia-container-toolkit が標準搭載され、ARM 環境での GPU コンテナ構成の手間が減る
✓全サポート対象マイルストーンへの同時対応: 旧マイルストーン (121/125/129) を利用中でも、LTS Refresh により同等のセキュリティ修正を受けられる

⚠️ デメリット・制約事項

🚧 制限事項

✗Container-Optimized OS にはパッケージマネージャーがなく、個別パッケージの更新はできないため、修正の適用にはイメージ (ノード) の更新が必要
✗サポート終了が近いマイルストーン (COS 121 LTS は 2027 年 3 月終了) は、計画的な新マイルストーンへの移行が必要

🤔 考慮すべき点

⚠️公式ドキュメントによると、LTS Refresh リリースには中・低優先度の修正が含まれるため、リグレッションの可能性を考慮し、ロールアウト時には通常より慎重な検証が推奨される
⚠️cos-133 と旧マイルストーンでは Docker / Containerd のメジャーバージョンが異なる (v29.4.3 / v2.4.1 と v27.5.1 / v2.2.x 系) ため、マイルストーン間の移行時はランタイム互換性の確認が必要

🎯 ユースケース

☸️ ユースケース 1: GKE ノードのセキュリティパッチ適用

シナリオ: GKE クラスタのノードイメージに Container-Optimized OS を使用しており、curl や glibc などの CVE への対応と eMudhra 侵害証明書の削除を速やかに適用したい。

効果: ノードの自動アップグレード (node auto-upgrades) または手動アップグレードにより、今回の修正を含む COS イメージへ更新するだけで、OS 全域の CVE 修正と信頼ストアの浄化が完了する。

💪 ユースケース 2: ARM ベースの GPU ワークロード構築

シナリオ: Arm (Axion など) ベースのインスタンスで NVIDIA GPU を使ったコンテナワークロードを実行したい。

効果: cos-133 の ARM イメージに nvidia-container-toolkit が追加されたことで、GPU コンテナランタイム構成の手作業が減り、ARM 環境での GPU ワークロード立ち上げが容易になる。

🗓️ ユースケース 3: 旧 LTS マイルストーン利用環境の定期更新

シナリオ: 安定性重視で cos-121 や cos-125 を固定利用しており、四半期ごとのメンテナンスウィンドウでまとめてパッチを適用したい。

効果: LTS Refresh リリース (cos-121-18867-652-7、cos-125-19216-760-8) を計画的に適用することで、マイルストーンを変えずに Kubernetes を含む多数の CVE 修正を取り込める。

🔗 関連サービス・機能

☸️ Google Kubernetes Engine (GKE)

COS は GKE のデフォルトノード OS イメージであり、ノード自動アップグレードで今回の修正を展開できる。

🖥️ Compute Engine

cos-cloud プロジェクトのイメージファミリー経由で COS イメージを VM に利用できる。

🎮 cos-gpu-installer / nvidia-container-toolkit

GPU ドライバーのインストールと GPU コンテナ実行を支援するコンポーネント。今回それぞれ v2.7.11 への更新と ARM イメージへの追加が行われた。

🧰 toolbox

パッケージマネージャーを持たない COS 上でデバッグ・管理ツールを隔離コンテナとして実行するユーティリティ。v20261020 に更新された。

📝 まとめ

今回のリリースは、最新マイルストーン cos-133 への新機能追加 (AMD CPUID faulting の KVM サポート、 ARM イメージへの nvidia-container-toolkit 追加) に加え、サポート中の全 LTS マイルストーンに対する 広範な CVE 修正と eMudhra 侵害証明書の削除を含む、セキュリティ色の強いアップデートです。

COS を GKE ノードや Compute Engine で利用している場合は、各マイルストーンの最新イメージへの更新を計画することを推奨します。 特に LTS Refresh リリースは中・低優先度の修正を含むため、ステージング環境での検証を経てから本番へロールアウトしてください。
