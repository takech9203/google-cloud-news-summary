📋 概要

Google Cloud CCaaS (Contact Center as a Service) のバージョン 5.0 がリリースされました。エージェントのラップアップ業務を大幅に改善するDisposition Timing機能、チャットセッションの自動ルーティングを実現するAPI Direct Access Point (DAP) for Chat機能が新たに追加されています。

加えて、メール、通話、チャット、ボイスメールなど多岐にわたるチャネルで発生していた多数のバグが修正されています。

  • 完了済みセッションのディスポジション事後修正が可能
  • 外部 API レスポンスに基づくチャット自動ルーティング
  • 全チャネルの安定性が大幅に向上

🚀 主要機能

⏱️ 1. Disposition Timing (ディスポジションタイミング)

エージェントが手動でラップアップ状態に入った際、過去に完了したセッションにラップアップ時間、ディスポジションコード、ノートを紐付けることが可能になりました。

→過去セッションのリストから選択して紐付け
→完了済みセッションのディスポジションコード・ノートの修正 (15-30 分以内)
→CRM レコードの自動読み込み機能 (CRM 埋め込み型アダプター使用時)
→各ラップアップ期間は個別レコードとして追跡 (開始・終了時間記録)
→管理者向け: Settings > Operation Management > Wrap-up に新セクション追加

🔀 2. API Direct Access Point (DAP) for Chat

外部 API エンドポイントのレスポンスに基づいてチャットセッションを自動ルーティングする新機能です。

→2 つの DAP タイプ: API Response (直接応答) / Webhook Response (非同期応答)
→Web チャットとモバイルチャットの両方に対応
→新規チャットと再開チャットの両方で動作
→タイムアウト/マッチなし時は標準キューメニューにフォールバック
→優先順位: API response > General access point label > User segmentation
⚠️ 注意: デフォルトでは無効。有効化には Google Cloud Support への連絡が必要です。

制限事項

💡 ユースケース

🎧 ユースケース 1: マルチタスクエージェントのラップアップ管理

シナリオ: エージェントが複数チャットセッションを並行処理中。セッション A 完了後、セッション B 対応中にセッション A のディスポジションを記録する余裕がなかった。

1.管理者が「Select the call or chat session to attribute manual wrap-up to」を有効化
2.「Display the list of the last 5 calls and chats」を設定
3.エージェントがラップアップ状態に入ると過去 5 件のセッションリストが表示
4.セッション A を選択し、ディスポジションコードとノートを入力して Submit
効果: 複数セッションを効率処理しながら正確なディスポジション記録。レポーティング精度が向上。

🛒 ユースケース 2: CRM データに基づくチャット自動ルーティング

シナリオ: E コマース企業がチャットサポートを提供。顧客の注文ステータスに応じて適切な専門チームにルーティングしたい。

1.外部 API エンドポイント構築 (注文ステータスに応じたキー・バリューペアを返却)
2.API DAP for Chat を有効化し、エンドポイント URL を設定
3.各キューにマッチ条件を設定:
order_status: pending → 注文確認キュー
order_status: shipping → 配送問い合わせキュー
order_status: return → 返品対応キュー
効果: 顧客がチャット開始時に即座に適切な専門チームへ接続。待ち時間短縮と問題解決率向上。
