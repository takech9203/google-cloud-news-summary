Claude・OpenAI・Mistral・Llama・vLLM — どのモデルでも同じポリシーでツール呼び出しを統制

📋 概要

Gemini Enterprise Agent Platform の Semantic Governance Policy (SGP) が、 Gemini 以外のモデルプロバイダーを使用するエージェントのツール呼び出し評価に対応しました。 ポリシーエンジンが各プロバイダーのリクエスト/レスポンス形式を読み取るため、エージェントがどのモデルを使っていても 同じポリシー (自然言語制約 / NLC) をそのまま適用できます。

ツール呼び出しが拒否された場合、ポリシーエンジンはそのプロバイダーのレスポンス形式に合わせた拒否メッセージに置き換えます。 対象ユーザーは、複数のモデルプロバイダーを混在させてエージェントを運用するプラットフォーム管理者・セキュリティ管理者です。

❌ Before: アップデート前の課題

  • SGP のツール呼び出し評価は Gemini モデルの呼び出しが前提で、Claude、OpenAI、Mistral AI、Llama などの非 Google モデルを使うエージェントには同じポリシーを適用できなかった
  • 複数のモデルプロバイダーを使い分ける環境では、モデルごとにガバナンスの仕組みが分断されるリスクがあった

✅ After: アップデート後の改善

  • ポリシーエンジンが各プロバイダーの形式を解釈し、Anthropic / OpenAI / Mistral AI / OpenAI 互換 (Llama、vLLM 含む) のツール呼び出しも評価可能に
  • モデルを切り替え・混在させても同一の SGP (自然言語制約) をそのまま適用できる
  • 拒否時の応答も各プロバイダーのレスポンス形式で返され、エージェント側の実装変更が不要
  • 認可ポリシーの when 条件がクエリ文字列付きリクエストにもマッチ
💡 ポイント: これらのプロバイダーをガバナンス対象にするには、認可ポリシー (authorization policy) の when 条件を各プロバイダーのリクエストパスに一致するよう更新する必要があります。

Agent Gateway が認可ポリシーの when 条件で各モデルプロバイダーのリクエストパスを判定し、 マッチしたモデル推論トラフィックを SGP ポリシーエンジンに転送します。エンジンはプロバイダーごとの形式を解釈して 同一ポリシーで評価し、拒否時はそのプロバイダーのレスポンス形式で拒否メッセージを返します。

📝 認可ポリシーの when 条件 (全プロバイダー対応の例)

YAML authz-policy.yaml 
name: AUTHZ_POLICY_NAME
target:
  loadBalancingScheme: LOAD_BALANCING_SCHEME_UNSPECIFIED
  resources:
  - projects/PROJECT_ID/locations/LOCATION/agentGateways/AGENT_GATEWAY_NAME
httpRules:
- to:
    operations:
    - paths:
      - prefix: /
  when: "!request.headers['content-type'].startsWith('application/grpc') && (request.path.contains(':generateContent') || request.path.contains(':rawPredict') || request.path.contains('/v1/messages') || request.path.contains('/chat/completions'))"
action: CUSTOM
policyProfile: CONTENT_AUTHZ
customProvider:
  authzExtension:
    resources:
    - projects/PROJECT_ID/locations/LOCATION/authzExtensions/AUTHZ_EXTENSION_NAME
⚠️ 注意: この例はサポート対象の全モデルプロバイダーにマッチします。エージェントが使用しないプロバイダーのパスは削除できます。 条件を必要以上に広げると、MCP ツール呼び出しなど評価されないトラフィックにもレイテンシが加わるため避けてください。 また、gRPC トラフィックを除外する CEL 式を含めないと、ポリシーエンジンが gRPC 呼び出し (Cloud Resource Manager など) を傍受して エージェントの起動が失敗します。

🛠️ 設定方法

✅ 前提条件

  1. Agent Gateway が作成済みで、エージェントが Agent Gateway 経由でトラフィックをルーティングしている (identity_type=AGENT_IDENTITY と agent_gateway_config を指定してデプロイ済み)
  2. Semantic Governance Policy エンジンがプロビジョニング済みで、ネットワーク構成 (PSC エンドポイント、DNS レコード、VPC 接続) が完了している
  3. エージェントがサポート対象のモデルプロバイダーをストリーミングなしで呼び出している

⚠️ デメリット・制約事項

🚫 制限事項

✗ストリーミングされたモデルレスポンスは非サポート (:streamGenerateContent、:streamRawPredict、"stream": true を設定したリクエスト)。ストリーミングレスポンス内のツール呼び出しはブロックされない可能性があるため、エージェントはストリーミングなしでモデルを呼び出すよう構成する必要がある
✗新しいプロバイダーをガバナンス対象にするには、認可ポリシーの when 条件を手動で更新する必要がある
✗Semantic Governance Policy は Pre-GA (Preview) であり、「Pre-GA Offerings Terms」が適用される。また LLM を用いた確率的な評価のため、判定 (verdict) が常に正確とは限らない

🤔 考慮すべき点

  • when 条件は contains() を使用する (request.path にクエリ文字列が含まれるため、endsWith() ではクエリパラメータ付きリクエストを取りこぼす)
  • 使用しないプロバイダーのパスは条件から削除し、条件を必要以上に広げない (評価されないトラフィックにレイテンシが加わるため)
  • gRPC トラフィックを除外する CEL 式 (!request.headers['content-type'].startsWith('application/grpc')) を必ず含める

効果: モデルプロバイダーごとにポリシーを作り直すことなく、既存の自然言語制約が Claude 利用エージェントのツール呼び出しにも適用される。

📝 まとめ

Semantic Governance Policy が Anthropic、OpenAI、Mistral AI、Llama、vLLM などの非 Google モデルプロバイダーのツール呼び出し評価に対応し、 マルチモデル環境でも単一のポリシーセットでエージェントを統制できるようになりました。

非 Google モデルを使うエージェントを運用している場合は、認可ポリシーの when 条件に該当プロバイダーのリクエストパスを追加し、 ドライランモードで判定を確認してから本番適用することを推奨します。 ストリーミングレスポンスは評価対象外となるため、ガバナンス対象のエージェントはストリーミングなしの呼び出しに構成してください。
