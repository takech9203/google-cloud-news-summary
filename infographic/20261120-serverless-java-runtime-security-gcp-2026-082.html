📌 概要

2026 年 11 月 20 日、Google Cloud はサーバーレス系サービス (App Engine flexible / standard、Cloud Run、Cloud Run functions、Cloud Functions 1st gen) と Google Cloud Buildpacks 向けに、重要な Java ランタイムセキュリティアップデートをリリースしました。セキュリティ速報 GCP-2026-082 に記載された OpenJDK の Critical 脆弱性 CVE-2026-114938 への恒久対策です。

CVE-2026-114938 は、OpenJDK 17.0.6 以降に存在する RCE 脆弱性です。AVX-512 VBMI 対応の x86-64 プロセッサ上で、HotSpot の AVX-512 VBMI Base64 デコーダ intrinsic の整数アンダーフローにより、不正な Base64 入力 (Base64.getDecoder() / Base64.getUrlDecoder()) のデコード時にヒープ領域外書き込みが発生し、JVM プロセス内での任意コード実行につながる可能性があります。

⚠️ 重要: サービスごと・デプロイ形態ごとに必要なアクションが異なります。自動ベースイメージ更新が有効なワークロードはパッチが自動適用されますが、App Engine flexible、Cloud Run のジョブ / ワーカープール / カスタムコンテナ / 自動更新なしデプロイ、Buildpacks ビルドのアプリは再ビルド・再デプロイが必要です。

❌ Before (アップデート前の課題)

  • Java 17 以降のサーバーレスワークロードは CVE-2026-114938 の影響を受ける可能性があり、暫定緩和策として JDK_JAVA_OPTIONS="-XX:+IgnoreUnrecognizedVMOptions -XX:UseAVX=2" (AVX-512 無効化) の設定が必要だった
  • 暫定緩和フラグは AVX-512 命令を無効化するもので、恒久対策としてパッチ済み JDK への更新が待たれていた
  • マネージドランタイムの利用者は、自身でベースイメージの JVM にパッチを適用できなかった

✅ After (アップデート後の改善)

  • パッチ済み Java ランタイム (17.0.21.1+2 / 21.0.13.1+2 / 25.0.5.1+2) のベースイメージと Buildpacks パッケージのロールアウトが全対象サービスで完了
  • 自動ベースイメージ更新が有効なワークロードは、アクション不要でパッチ済みランタイムを受領
  • 再ビルド・再デプロイが必要なワークロードも、再デプロイだけで恒久対策が完了し、暫定的な JDK_JAVA_OPTIONS 緩和フラグを削除可能に

1️⃣ パッチ済み Java ランタイムベースイメージのロールアウト完了

→Java 17 (17.0.21.1+2)、Java 21 (21.0.13.1+2)、Java 25 (25.0.5.1+2) のランタイムベースイメージと Buildpacks パッケージが、Cloud Run、Cloud Run functions、Cloud Functions (1st gen)、App Engine、Google Cloud Buildpacks 全体でロールアウト完了
→CVE-2026-114938 (Critical / RCE) の恒久対策

2️⃣ 自動ベースイメージ更新によるゼロタッチ適用

→App Engine standard (java17 / java21 / java25)、自動ベースイメージ更新が有効な Cloud Run サービス (第 1・第 2 世代実行環境)、Cloud Run functions、自動更新が有効な Cloud Functions (1st gen) はパッチを自動的に受領

3️⃣ 再ビルド・再デプロイが必要なワークロードへの明確なガイダンス

→App Engine flexible (マネージド Java ランタイム)、Cloud Run ジョブ / ワーカープール、自動更新なしのソースデプロイは、再ビルド・再デプロイでパッチ済みランタイムを取得 (App Engine flexible では gcloud app deploy を実行し、旧バージョンを停止)

→パッチ済みランタイム稼働後、app.yaml / appengine-web.xml や環境変数に追加した暫定的な JDK_JAVA_OPTIONS="-XX:+IgnoreUnrecognizedVMOptions -XX:UseAVX=2" フラグを削除して再デプロイ

ステップ 1: 自動更新対象のワークロードを確認し、ウォームインスタンスを更新する

Bash ウォームインスタンスの即時更新 
# App Engine standard: 再デプロイでウォームインスタンスを即時更新
gcloud app deploy

# Cloud Run: 再デプロイ (リビジョン更新) でウォームインスタンスを即時更新
gcloud run deploy SERVICE --image APP_IMAGE --base-image java21

自動ベースイメージ更新が有効なワークロードはアクション不要ですが、再デプロイすることでウォームインスタンスを即座にパッチ済みランタイムへ入れ替えられます。Cloud Run では、サービスログの run.googleapis.com/base_image_versions ラベルで使用中のベースイメージバージョンを確認できます。

ステップ 2: 手動対応が必要なワークロードを再ビルド・再デプロイする

Bash 再ビルド・再デプロイ 
# App Engine flexible: 再ビルド・再デプロイし、旧バージョンを停止
gcloud app deploy
gcloud app versions stop OLD_VERSION

# Cloud Run ジョブ / ワーカープール / カスタムコンテナ:
# パッチ済み JDK / ベースイメージでイメージを再ビルドして再デプロイ
gcloud builds submit --tag REGION-docker.pkg.dev/PROJECT/REPO/IMAGE
gcloud run jobs update JOB --image REGION-docker.pkg.dev/PROJECT/REPO/IMAGE
💡 Buildpacks のヒント: GOOGLE_RUNTIME_VERSION を未設定にするか 21 / 21.0 のようなメジャー / マイナーバージョン指定にしておくことで、再ビルド時に最新のパッチ済みランタイムが自動選択されます。

ステップ 3: 暫定緩和フラグを削除する

Bash 暫定フラグの削除 
# Cloud Run: 環境変数から暫定フラグを削除
gcloud run services update SERVICE --remove-env-vars JDK_JAVA_OPTIONS

パッチ済みランタイムで稼働していることを確認したら、app.yaml / appengine-web.xml / 環境変数に追加した暫定的な JDK_JAVA_OPTIONS="-XX:+IgnoreUnrecognizedVMOptions -XX:UseAVX=2" を削除して再デプロイします。このフラグは AVX-512 を無効化するため、残したままにするとパッチ適用後も AVX-512 による最適化が利用されません。

👍 メリット

💼 ビジネス面

✓Critical 脆弱性への恒久対策: 認証不要の RCE という深刻なリスクに対し、暫定緩和 (AVX-512 無効化) ではなくパッチ済み JDK による恒久対策が完了する
✓運用負荷の最小化: 自動ベースイメージ更新を有効にしているワークロードは、再ビルドなしで保護される

🔧 技術面

✓自動ベースイメージ更新の価値の実証: Cloud Run / Cloud Run functions の自動ベースイメージ更新や App Engine standard のマネージドランタイムを使うことで、OS / ランタイムレベルのセキュリティパッチをゼロタッチで受けられる
✓移行期間のセーフガード: App Engine standard と Cloud Run 第 2 世代 (自動更新利用時) では、ウォームインスタンス入れ替え期間中も暫定 AVX-512 VBMI セーフガードが 2026 年 11 月 30 日まで維持され、保護の空白が生じない

⚠️ デメリット・制約事項

🚧 制限事項

✗自動ベースイメージ更新は Google Cloud Buildpacks ベースイメージのみ対応で、独自ベースイメージでは利用できない。カスタムコンテナは自身でパッチ済み JDK / ベースイメージへの再ビルドが必要
✗自動ベースイメージ更新では、Java のようなコンパイル言語のアプリケーションは再コンパイルされない。言語レベルの修正を完全に取り込むには再ビルドが必要な場合がある

🤔 考慮すべき点

⚠️自動適用の対象でも、ウォームインスタンスが残っている間は旧ランタイムで稼働し続けるため、即時の保護が必要な場合は再デプロイを実施する
⚠️App Engine standard / Cloud Run 第 2 世代の暫定 AVX-512 VBMI セーフガードは 2026 年 11 月 30 日までで終了するため、それまでにウォームインスタンスの入れ替え (再デプロイ) を完了させることが望ましい
⚠️Buildpacks で GOOGLE_RUNTIME_VERSION を 4 要素のパッチバージョン文字列に固定していると、再ビルドしてもパッチ済みランタイムを取得できない。メジャー / マイナーバージョン指定に変更する必要がある
⚠️暫定 JDK_JAVA_OPTIONS フラグの削除漏れは、AVX-512 最適化が無効のままとなるパフォーマンス面の機会損失につながる
⚠️GKE、Compute Engine、Distroless イメージなど自己管理の Java 17+ ワークロードは本アップデートの対象外であり、GCP-2026-082 のガイダンスに従って個別に対応する必要がある

🎯 ユースケース

📋 ユースケース 1: Cloud Run で Java サービスとジョブを混在運用している場合の棚卸し

シナリオ: 自動ベースイメージ更新を有効にした Cloud Run サービスと、カスタムコンテナベースの Cloud Run ジョブ / ワーカープールを運用している組織が、CVE-2026-114938 への対応状況を確認したい。

Bash 対応状況の確認と更新 
# サービスの自動ベースイメージ更新設定を確認
gcloud run services describe SERVICE --format="yaml(spec.template.metadata.annotations)"

# ジョブ / ワーカープールはパッチ済みベースイメージで再ビルド後に更新
gcloud run jobs update JOB --image REGION-docker.pkg.dev/PROJECT/REPO/IMAGE:patched

効果: 自動更新有効のサービスは確認のみで完了し、再ビルドが必要なジョブ / ワーカープール / カスタムコンテナに対応作業を集中できる。

📋 ユースケース 2: App Engine で standard と flexible を併用している場合の対応

シナリオ: App Engine standard (java21) と App Engine flexible (Java) の両方でアプリケーションを運用しており、それぞれに必要な対応を実施したい。

効果: standard はアクション不要 (即時更新したい場合のみ再デプロイ) である一方、flexible は gcloud app deploy での再デプロイと旧バージョンの停止が必須と切り分けられる。両環境とも、対応完了後に app.yaml / appengine-web.xml の暫定 JDK_JAVA_OPTIONS フラグを削除する。
