📌 概要

Google SecOps (旧 Chronicle) において、ケースに紐づくイベントを一覧取得する ListCaseEvents API エンドポイントが 2026 年 11 月 2 日付で非推奨 となりました。今後は代替として ListCaseEvidenceData API (projects.locations.instances.cases.caseEvidenceDatas.list) を使用する必要があります。

公式 Deprecations ページでは、非推奨日が 2026 年 9 月 30 日、シャットダウン日が 2026 年 11 月 2 日と記載されています。ListCaseEvents を利用した自動化スクリプト、 SOAR 連携、外部ツール統合を運用しているユーザーは、速やかに移行対応が必要です。

Google SecOps では、レガシー Backstory API / Ingestion API から Chronicle API (chronicle.googleapis.com) への移行や fetchavailablelogtypes エンドポイントの廃止など API 体系の刷新が段階的に進められており、今回の変更もその一環です。 ケース関連データへのアクセスは、Google Cloud のリソース階層に沿った新しい API に統一されていきます。

❌ Before (アップデート前の課題)

✗ケースのイベントデータ取得に旧来の ListCaseEvents エンドポイントが使用され、新しい Chronicle API 体系 (CaseEvidenceData リソース) と並存していた
✗旧エンドポイントに依存した統合・スクリプトは、API 刷新後のリソースモデル (evidenceType によるフィルタリングなど) を活用できなかった

✅ After (移行後の改善)

✓ケースの証跡データ (Case Evidence Data) 取得が ListCaseEvidenceData API に一本化され、Google Cloud 標準のリソース命名規則・IAM 権限モデルに準拠
✓AIP-160 準拠のフィルタ構文 (evidenceType = THREAT_HUNT など)、ページネーション (pageSize / pageToken)、ソート (orderBy) が利用可能

⚙️ 技術仕様 — ListCaseEvidenceData API (caseEvidenceDatas.list)

項目詳細
HTTP リクエストGET https://{endpoint}/v1alpha/{parent}/caseEvidenceDatas
パスパラメータ parentケースのリソース名。形式: projects/{project}/locations/{location}/instances/{instance}/cases/{caseId}
クエリパラメータ filterAIP-160 準拠のフィルタ文字列。evidenceType を含む必要がある (例: evidenceType = THREAT_HUNT)
クエリパラメータ pageSize返却件数の上限。デフォルト 1000、最大 1000 (超過分は 1000 に丸められる)
クエリパラメータ pageToken前回レスポンスの nextPageToken を指定して次ページを取得
クエリパラメータ orderByソート対象フィールド。デフォルトは caseEvidenceDataId 順
レスポンスcaseEvidenceDatas[]、nextPageToken、totalSize
OAuth スコープcloud-platform または chronicle
必要な IAM 権限chronicle.caseEvidenceDatas.get (parent リソースに対して)

✏️ ステップ 2: ListCaseEvidenceData API への書き換え

Bash ケースの証跡データを一覧取得する例 
# ケースの証跡データを一覧取得する例
curl -s \
  -H "Authorization: Bearer $(gcloud auth print-access-token)" \
  "https://chronicle.googleapis.com/v1alpha/projects/PROJECT_ID/locations/LOCATION/instances/INSTANCE_ID/cases/CASE_ID/caseEvidenceDatas?filter=evidenceType%20%3D%20THREAT_HUNT&pageSize=1000"

filter には evidenceType の指定が必須である点、レスポンスのスキーマが caseEvidenceDatas[] 形式に変わる点に注意して、レスポンス処理ロジックを更新します。

📄 ステップ 3: ページネーション処理の実装

totalSize が pageSize を超える場合は、レスポンスの nextPageToken を次のリクエストの pageToken に指定して全件を取得します。ページ送り時は、他のパラメータを最初のリクエストと一致させる必要があります。

⚠️ デメリット・制約事項

🔒 制限事項

⚠️ListCaseEvidenceData の filter には evidenceType の指定が必須
⚠️pageSize の最大値は 1000 (超過した値は 1000 に丸められる)

🚨公式 Deprecations ページではシャットダウン日が 2026 年 11 月 2 日と記載されており、ListCaseEvents に依存したワークフローは即時の移行対応が必要
