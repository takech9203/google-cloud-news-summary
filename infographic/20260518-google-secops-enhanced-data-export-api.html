🔐 Google SecOps: Enhanced Data Export API

GA Google SecOps Security API
2026-05-18

📋 概要

Google SecOps の Enhanced Data Export API が一般提供 (GA) となり、セキュリティデータの一括エクスポートに関する大幅な機能強化とセキュリティ改善が導入されました。この API は、Google Security Operations から顧客管理の Google Cloud Storage バケットへのセキュリティデータの一括エクスポートを実現し、従来のレガシー API と比較してより安全でスケーラブルなデータアーカイブを提供します。

今回の GA リリースでは、ゼロトラストセキュリティ (CMEK)、データ RBAC スコープ継承、高度なデータフィルタリング という 3 つの柱でエクスポート機能が強化されています。

⚠️ 重要: レガシー Data Export API は 2026年6月18日 にサンセット (廃止) 予定です。既存ユーザーは新しい v1 エンドポイントへの移行が必要です。

📝 設定手順

前提条件

✓Google SecOps インスタンスで Enhanced Data Export API が有効
✓IAM ロール Chronicle API Admin または Chronicle API Viewer が付与済み
✓エクスポート先 GCS バケットが SecOps テナントと同一リージョン
✓GCS バケットがパブリックアクセス禁止に設定済み
✓(CMEK) Cloud KMS に暗号鍵が作成され適切な権限が設定済み

Step 1: サービスアカウントの取得

Bash 
curl -X GET \
  -H "Authorization: Bearer $(gcloud auth print-access-token)" \
  "https://chronicle.us.rep.googleapis.com/v1/projects/MY_PROJECT/locations/us/instances/MY_INSTANCE/dataExports:fetchServiceAccountForDataExport"

Step 2: GCS バケットへの権限付与

Bash 
# サービスアカウントに Storage Object Admin ロールを付与
gcloud storage buckets add-iam-policy-binding gs://my-export-bucket \
  --member="serviceAccount:service-1234@gcp-sa-chronicle.iam.gserviceaccount.com" \
  --role="roles/storage.objectAdmin"

# サービスアカウントに Legacy Bucket Reader ロールを付与
gcloud storage buckets add-iam-policy-binding gs://my-export-bucket \
  --member="serviceAccount:service-1234@gcp-sa-chronicle.iam.gserviceaccount.com" \
  --role="roles/storage.legacyBucketReader"

Step 3: v1 エンドポイントへの移行

💡 ポイント: 既存のクライアントコードで v1alpha を v1 に置き換え、logType フィールドを includeLogTypes に変更してください。
Bash 
# 旧エンドポイント (廃止予定):
# https://chronicle.{region}.rep.googleapis.com/v1alpha/{parent}/dataExports

# 新エンドポイント (GA):
# https://chronicle.{region}.rep.googleapis.com/v1/{parent}/dataExports

Step 4: エクスポートジョブの作成

Bash 
curl -X POST \
  -H "Authorization: Bearer $(gcloud auth print-access-token)" \
  -H "Content-Type: application/json" \
  -d '{
    "startTime": "2026-05-01T00:00:00Z",
    "endTime": "2026-05-02T00:00:00Z",
    "gcsBucket": "projects/my-project/buckets/secops-export-bucket",
    "includeLogTypes": [
      "projects/my-project/locations/us/instances/my-instance/logTypes/GCP_DNS"
    ]
  }' \
  "https://chronicle.us.rep.googleapis.com/v1/projects/my-project/locations/us/instances/my-instance/dataExports"

⚠️ 制限事項・注意点

✗エクスポート対象は Raw Logs のみ (UDM ログ、UDM イベント、検出データは不可)
✗同時実行ジョブ数は最大 3 ジョブ / テナント
✗GCS バケットは SecOps テナントと 同一リージョン に配置必須
✗データは 非圧縮テキスト でエクスポート (ストレージコスト注意)
✗ビルトインスケジューラなし (定期実行は独自自動化が必要)
✗CMEK は Enterprise Plus パッケージ でのみ利用可能
✗既存レガシー API ジョブには新 API からアクセス不可
⚠️ 移行時の考慮点:
  • 移行期限: 2026/6/18 (約 1 か月の猶予、早期移行推奨)
  • 破壊的変更: logType → includeLogTypes へのフィールド名変更
  • ジョブ完了時間: 大容量ジョブは最大 18 時間 (リアルタイム用途には不向き)
  • ストレージクラス: Standard Storage のみ対応

💡 ユースケース

🏢 ユースケース 1: コンプライアンス対応の長期データ保持

シナリオ: 金融機関が SOX 準拠のため、セキュリティログを 7 年間保持。Google SecOps のデフォルト保持期間を超えるデータを、CMEK で暗号化した GCS バケットに定期エクスポート。

効果: CMEK + データ RBAC により、コンプライアンス監査要件を満たしながら長期保持を実現。

🌎 ユースケース 2: マルチテナント MSSP のデータ分離エクスポート

シナリオ: MSSP が複数顧客のセキュリティデータを管理し、顧客ごとにデータを分離してエクスポート。

効果: データ RBAC スコープ継承で各顧客担当者は自スコープ内のみエクスポート可能。ネームスペースとインジェストラベルで特定顧客データを正確に抽出。

🔍 ユースケース 3: インシデントレスポンスのフォレンジック分析

シナリオ: セキュリティインシデント発生時、特定の時間範囲とログタイプに限定したデータを迅速に抽出し、専用分析環境で詳細調査。

効果: 高度なフィルタリングで必要データのみを効率的にエクスポート。フォレンジック分析の迅速化とストレージコスト最適化を実現。

📋 まとめ

Google SecOps の Enhanced Data Export API が GA となり、ゼロトラストセキュリティ (CMEK)、データ RBAC 継承、高度なフィルタリングの 3 つの柱でセキュリティデータエクスポートが大幅に強化されました。

コンプライアンス要件の厳しい組織にとって、セキュリティデータの長期保持と主権管理の両立を実現する重要なマイルストーンです。レガシー API は 2026年6月18日 に廃止されるため、速やかに v1 エンドポイントへの移行を計画してください。
