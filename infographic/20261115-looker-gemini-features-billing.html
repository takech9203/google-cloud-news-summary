📝 概要

2027 年 2 月 1 日より、Looker の Gemini 支援機能 (Conversational Analytics をはじめとする GA 済みのエージェント型機能群) の使用量が、インスタンスに含まれる月間トークン割り当てを超過した場合、超過分に対する課金が開始されます。Preview 段階の機能 (例: LookML 生成アシスタント) は課金対象外です。

使用量は「データトークン」(LLM が処理するテキストとデータの基本単位) で計測され、入力トークンと出力トークンが個別にカウントされます。割り当て内の利用は追加費用なしで継続でき、超過しても機能は中断されず、超過分がオーバーレッジとして課金されます。

💡 請求先の紐付け: 課金は Google Cloud プロジェクトの請求先アカウントに紐付きます。Looker (Google Cloud core) はプロビジョニング時のプロジェクトが自動使用されますが、Looker (original) では管理者が課金用プロジェクトを事前にリンクする必要があります。

❌ アップデート前の課題

  • Gemini 支援機能の課金開始時期とモデルが確定しておらず、予算計画が立てにくかった
  • Looker (original) では課金先 Google Cloud プロジェクトのリンクが必須ではなかった
  • トークン消費量を意識した利用管理の仕組みが本格的に求められていなかった

✅ アップデート後の改善

  • 課金開始日・対象・計測単位が明確になり、コスト計画が可能に
  • 月間トークン割り当てはインスタンス単位でプールされ、ライセンス数・種別に応じて動的にスケール
  • 割り当て超過後も機能は中断されず、超過分のみオーバーレッジ課金で利用継続性を担保
  • System Activity ダッシュボードで課金開始前からトークン消費をモニタリング可能

Gemini 支援機能の利用はデータトークンとして計測され、インスタンス単位の月間プール割り当てを超えた分のみが、リンクされた Google Cloud プロジェクトの請求先アカウントに課金されます。

⚙️ 主要機能 (課金モデルの詳細)

1️⃣ 課金対象となる Gemini 支援機能

→Conversational Analytics が主要な課金対象 (Explore へのチャット、ダッシュボードデータエージェント、カスタム Explore データエージェント、埋め込みエージェント、Looker API 経由のリクエストを含む)
→その他の GA 済み Gemini 利用機能も対象: Visualization Assistant、Looker 式の生成支援、Advanced Analytics、Explore サマリー生成、スターター質問生成、セマンティック検索など
✓Preview 段階の機能 (例: LookML 生成) は課金対象外

2️⃣ データトークンによる使用量計測

→入力データトークン: 自然言語の質問・プロンプト、会話履歴とコンテキスト、LookML モデルスキーマのメタデータ (ビュー、ディメンション、メジャーの定義など)、エージェント指示などの関連コンテキスト
→出力データトークン: 自然言語の回答・要約・提案、生成される API 呼び出しや SQL / LookML クエリ、モデルの推論・オーケストレーションステップ、ビジュアライゼーションとチャートの仕様

3️⃣ 月間トークン割り当てとオーバーレッジ

→プール型割り当て: 月間トークンはインスタンス単位でプールされ、全アクティブユーザーで共有 (ユーザー個別の上限なし)
→ライセンス連動: 割り当て量はアクティブユーザーライセンスの数と種別 (標準内部ユーザー / 埋め込みユーザーなど) と、Looker エディションのベースライン割り当てに応じて動的にスケール
→毎月リセット: 請求サイクルの開始時にリセットされ、翌月への繰り越しなし
✓超過時も中断なし: 割り当て超過後も機能を使い続けられ、超過分のみが入力・出力別にオーバーレッジ課金

4️⃣ 請求先プロジェクトの紐付け

→Looker (Google Cloud core): プロビジョニング時にリンクされた Google Cloud プロジェクトと請求先アカウントが使用される (変更不可)
→Looker (original): 管理者が Admin パネルから課金用 Google Cloud プロジェクトをリンクする必要がある (課金開始前の設定を推奨)

✓モニタリング基盤の提供: System Activity ダッシュボードでエージェント別・ユーザー別・会話別の消費を可視化でき、課金開始前からトレンド分析と容量予測が可能
✓請求の一元化: Google Cloud プロジェクトの請求先アカウントに統合されるため、他の Google Cloud サービスと合わせたコスト管理 (予算アラートなど) ができる

🚫 制限事項

✗Looker (Google Cloud core) インスタンスでは、リンクされた Google Cloud プロジェクトを変更できない
✗月間トークン割り当ては翌月に繰り越されない
✗トークン使用量データの System Activity への反映には約 6 時間のレイテンシがある

🤔 考慮すべき点

⚠️ 注意: Looker (original) インスタンスでは、課金開始 (2027 年 2 月 1 日) までに請求先プロジェクトのリンクを完了しておかないと、ユーザーの利用に支障が出る可能性があります。
  • 埋め込み (Conversational Analytics Embed) や Looker API 経由の利用もトークン消費の対象となるため、顧客向け埋め込み分析を提供している場合は利用量の見積もりが特に重要
  • 具体的なユーザー種別ごとの月間トークン割り当て量、ベースライン割り当て、オーバーレッジ単価は Looker 料金ページで確認する必要がある
  • 現在 Preview の機能 (LookML 生成など) は無償だが、GA 昇格後は課金対象になり得る

🔗 関連サービス・機能

💬 Conversational Analytics

課金対象の中核となる機能。自然言語で Looker のデータに質問し、チャートやデータテーブルを取得できる。Explore チャット、ダッシュボードエージェント、埋め込み、API など全インターフェースがトークン消費の対象。

✨ Gemini Enterprise

Looker のデータエージェントを Gemini Enterprise に公開した場合の利用もトークン消費としてカウントされる。

🧾 Cloud Billing

課金は Google Cloud プロジェクトの請求先アカウントに紐付くため、予算・アラート設定によるコスト管理と組み合わせられる。

📈 Looker System Activity

Conversational Analytics ダッシュボードの Token usage タブで、入力・出力トークンの消費量と割り当て利用率をモニタリングできる。
