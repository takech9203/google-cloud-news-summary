📋 概要

Secure Source Manager のクレデンシャルスキャン機能に、インスタンスごとの日次レートクォータ (1 GB/日)が適用されるようになりました。 リポジトリへの push 時にコミット内容をスキャンし、SSH 秘密鍵、AWS/GCP クレデンシャル、OAuth シークレットなどの機密情報を検出する DLP 機能のリソース使用量が明確に制御されます。

💡 ポイント: このクォータは Rate クォータのため、同日内にインスタンスを削除して同一 ID で再作成してもクォータ使用量はリセットされません。翌日まで待つか、異なるインスタンス ID で再作成する必要があります。

⚡ 主要機能

📏 日次レートクォータの適用

インスタンスごとに1日あたりのスキャン対象コードサイズを制限。デフォルトは 1 GB/日/インスタンス。Cloud Quotas システムで管理・モニタリング可能。

🔄 クォータリセットの動作

日次リセットの Rate クォータ。インスタンス削除・再作成しても同日中はリセットされない。インスタンス ID に紐づいて追跡。

📈 クォータ引き上げの仕組み

Cloud Console の「クォータとシステム制限」ページからリクエスト可能。カスタマーケアへの連絡による引き上げにも対応。

🏢 サービス安定性の向上

💰 コスト予測可能性

明確なクォータ制限により、リソース使用量とコストの予測が容易に。

📋 コンプライアンス対応

スキャン実行状況をクォータとして可視化でき、セキュリティ監査に活用可能。

📊 リソース管理の明確化

Cloud Quotas システムとの統合により、使用量のモニタリングとアラート設定が可能。

📐 キャパシティプランニング

クォータ使用率に基づいた計画的なインスタンス追加やクォータ引き上げが可能。

🤖 自動化対応

Cloud Quotas API を通じたプログラマティックな管理が可能。

⚠️ デメリット・制約事項

制限事項:
  • デフォルト 1 GB/日/インスタンスは、大規模モノレポや多数リポジトリでは不足する可能性あり
  • 同日中のインスタンス削除・再作成ではクォータはリセットされない
  • クォータ超過時、DLP によるセキュリティ保護が一時的に無効になる可能性
注意すべき点:
  • CI/CD パイプラインで大量 push 発生時はクォータ消費の事前見積もりが必要
  • クォータ引き上げリクエストには審査期間が必要 (余裕を持った計画が重要)
  • 1コミットあたり 100 MB を超えないことが推奨
  • 同一インスタンス上の複数リポジトリはクォータを共有

💡 ユースケース

🏢 エンタープライズ開発チームのセキュリティ管理

シナリオ: 100名以上の開発者が複数リポジトリで日常的にコードを push する大規模組織。

対応: クォータ使用率 80% でアラート通知、100% で管理者にエスカレーション。必要に応じてクォータ引き上げリクエストを自動化。

🔧 マイクロサービスアーキテクチャでの運用

シナリオ: 多数の小規模リポジトリ (各数 MB) を持つマイクロサービス環境。各サービスが独立してデプロイ。

効果: 個々のリポジトリが小さいため、1 GB/日のクォータで十分にカバー可能。安定的なスキャン実行。

📦 モノレポ運用での大規模コード管理

シナリオ: 単一の大規模リポジトリ (数十 GB) にすべてのコードを集約するモノレポ方式。

効果: クォータ引き上げリクエストにより適切なクォータを確保。差分スキャンにより実際にスキャンされるのは変更されたコードのみ。
