Google Distributed Cloud (software only) for VMware GA Security Patch Release

☁️ GDC for VMware
1.34.1100-gke.125 リリース

信頼を失ったルート CA の排除とクラスタライフサイクル修正を含むパッチリリース
📅 リリース日: 2026-11-11
☸️ Kubernetes v1.34.12-gke.500

📋 概要

オンプレミスの VMware vSphere 環境上に GKE ベースの Kubernetes クラスタを構築・運用する GDC (software only) for VMware のパッチバージョン 1.34.1100-gke.125 がダウンロード可能になりました。 本バージョンは Kubernetes v1.34.12-gke.500 上で動作します。

今回の中心は 信頼を失った (distrusted) ルート CA への対応です。 eMudhra (emSign) および AAA Certificate Services のルート CA をシステムコンポーネント、コンテナベースイメージ、 ノード OS イメージ (COS / Ubuntu) から削除し、侵害された eMudhra の中間 CA を拒否するように更新されています。 あわせて COS milestone 121 へのアップグレード、Ubuntu 22.04 ベースイメージ更新 (USN-8944-1 対応)、 およびクラスタライフサイクル運用に関わる複数の不具合修正が含まれます。

🔄 Before / After

❌ アップデート前の課題
  • 信頼を失った eMudhra (emSign) / AAA Certificate Services のルート CA が信頼ストアに残り、侵害された中間 CA 経由の証明書が受け入れられるリスク
  • ユーザークラスタ削除後も k8s-health-check-reader-binding-<cluster-namespace> の ClusterRoleBinding が admin クラスタに孤立して残存
  • advanced ユーザークラスタで既存 MetalLB アドレスプールに IP を追加するとクラスタが UPDATING 状態でスタック
  • manual LB モードでも制御プレーン VIP がノードサブネット内にあることを誤って要求するプリフライトチェック
  • audit-proxy が恒久的エラーでも監査ログエクスポートを無限リトライし、過剰なトラフィックが発生
  • プリフライトヘルスチェックが admin クラスタの全 namespace をスキャンし、無関係なクラスタの古い reconciling リソースでアップグレードが失敗
✅ アップデート後の改善
  • システムコンポーネント / コンテナベースイメージ / COS 121 / Ubuntu 22.04 イメージから当該ルート CA を削除し、侵害された eMudhra 中間 CA を拒否
  • ヘルスチェック権限は namespace スコープの RoleBinding に変更され、レガシー ClusterRoleBinding は自動クリーンアップ
  • 既存 MetalLB アドレスプールへの IP 追加はバリデーションで拒否 (新規アドレスプール追加で対応する運用に変更)
  • manual LB モードでの誤った VIP サブネット検証を解消
  • audit-proxy は恒久的エラーで無限リトライせず、監査ログトラフィックを抑制
  • プリフライトヘルスチェックは対象クラスタの namespace のみをスキャンし、無関係なクラスタ起因の失敗を解消

本パッチリリースの構成要素と適用先を示した図です。ノード OS (COS / Ubuntu) とコンテナベースイメージの両方から 信頼を失ったルート CA が削除され、admin / user クラスタのライフサイクル運用に関わる不具合も修正されています。

⭐ 主要機能・修正内容

🔒 1. 信頼を失ったルート CA の削除 (Feature)
→システムコンポーネントとコンテナベースイメージを更新し、信頼を失った eMudhra (emSign) および AAA Certificate Services ルート CA を削除、侵害された eMudhra 中間 CA を拒否
→Container-Optimized OS (COS) を milestone 121 (cos-121-18867-652-7) にアップグレードし、同ルート CA を削除
→Ubuntu 22.04 ノード / 管理ワークステーションのベースイメージを ubuntu-gke-op-2204-1-33-v20261024 に更新し、eMudhra (emSign) ルート CA を削除 (Ubuntu セキュリティ通知 USN-8944-1 に対応)
🔁 2. クラスタライフサイクル関連の修正 (Fixed)
→ユーザークラスタ削除時に admin クラスタへ孤立した k8s-health-check-reader-binding-<cluster-namespace> ClusterRoleBinding が残る問題を修正。ヘルスチェック権限は namespace スコープの RoleBinding に変更され、レガシー ClusterRoleBinding は自動クリーンアップ
→advanced ユーザークラスタで既存 MetalLB アドレスプールへの IP 追加によりクラスタが UPDATING 状態でスタックする問題を修正 (更新はバリデーションで拒否し、新規アドレスプール追加で対応する方式に変更)
→Kubernetes プリフライトヘルスチェックが admin クラスタの全 namespace をスキャンし、無関係なクラスタの古い reconciling リソースでアップグレードが失敗する問題を修正
🛠️ 3. その他の修正 (Fixed)
→Vulnerability fixes に記載の脆弱性を修正
→制御プレーンロードバランサモードが manual の場合に、プリフライトチェックが制御プレーン VIP (loadBalancer.vips.controlPlaneVIP) を制御プレーンノードサブネット内に誤って要求する問題を修正
→audit-proxy が恒久的エラーに対して監査ログエクスポートを無限リトライし、過剰な監査ログトラフィックを生成する問題を修正

⚙️ 設定方法 (アップグレード手順)

✅ 前提条件

✓既存の GDC (software only) for VMware クラスタ (1.34 系へのアップグレードパスがあるバージョン) が稼働していること
✓サードパーティストレージベンダーを使用している場合、GDC Ready storage partners で本リリースの認定状況を確認すること

📥 ステップ 1: 新バージョンのダウンロードと管理ワークステーションの更新

Bash 
# バンドルのダウンロード先とアップグレード手順はドキュメントを参照
# https://cloud.google.com/kubernetes-engine/distributed-cloud/vmware/docs/how-to/upgrading

ダウンロードページから 1.34.1100-gke.125 を取得し、アップグレードガイドに従って管理ワークステーションを更新します。

🚀 ステップ 2: クラスタのアップグレード

Bash 
# 例: gkectl によるユーザークラスタのアップグレード
gkectl upgrade cluster \
  --kubeconfig ADMIN_CLUSTER_KUBECONFIG \
  --config USER_CLUSTER_CONFIG
💡 ヒント: リリース後約 7〜14 日で、GKE On-Prem API クライアント (Google Cloud コンソール、gcloud CLI、Terraform) からもこのバージョンが利用可能になります。

💪 メリット

💼 ビジネス面

✓サプライチェーンのセキュリティ強化: 信頼を失った CA がオンプレミスクラスタの信頼ストアから排除され、侵害された中間 CA を悪用した中間者攻撃などのリスクを低減できる
✓運用コストの削減: 孤立 RBAC リソースの自動クリーンアップやアップグレード失敗要因の解消により、クラスタライフサイクル運用時の手動対応が減少する

🧑‍💻 技術面

✓OS / イメージの一括更新: COS 121 と Ubuntu 22.04 の新イメージにより、ノード OS レイヤーの CVE 対応と CA 更新が同時に適用される
✓RBAC の最小権限化: ヘルスチェック権限がクラスタ全体の ClusterRoleBinding から namespace スコープの RoleBinding に変更され、権限境界が適切になった
✓アップグレードの信頼性向上: プリフライトチェックが対象クラスタの namespace のみを検証するようになり、環境内の他クラスタの状態に起因する誤検知が解消された

⚠️ デメリット・制約事項

🚧 制限事項

✗既存の MetalLB アドレスプールへの IP アドレス追加はバリデーションで拒否されるようになった。IP を追加したい場合は新しいアドレスプールを追加する必要がある (運用手順の変更が必要)
✗リリース直後は GKE On-Prem API クライアント (コンソール / gcloud / Terraform) からの利用に約 7〜14 日かかる

🤔 考慮すべき点

⚠️ 証明書チェーンの事前確認: eMudhra (emSign) または AAA Certificate Services 配下の証明書を社内サービスや外部連携で使用している場合、 本バージョン適用後に TLS 接続が失敗する可能性があります。事前に証明書チェーンを確認し、別の CA への移行を済ませておく必要があります。
⚠️ サードパーティストレージ: サードパーティストレージを使用している場合は、ストレージパートナーの本リリースに対する認定状況を事前に確認してください。

🎯 ユースケース

🏦 ユースケース 1: セキュリティコンプライアンス対応としての定期パッチ適用

シナリオ: 金融機関がオンプレミス VMware 環境で GDC クラスタを運用しており、社内規定で「信頼を失った CA の排除と月次の脆弱性パッチ適用」が義務付けられている。

効果: 1.34.1100-gke.125 へのアップグレードだけで、ノード OS (COS / Ubuntu)、システムコンポーネント、コンテナベースイメージの CA 更新と CVE 修正が一括適用され、個別対応が不要になる。

🗂️ ユースケース 2: マルチクラスタ環境でのアップグレード失敗の解消

シナリオ: 1 つの admin クラスタ配下で多数のユーザークラスタを運用しており、一部クラスタの古い reconciling リソースが原因で他クラスタのアップグレードがプリフライトチェックで失敗していた。

効果: プリフライトヘルスチェックが対象クラスタの namespace のみをスキャンするようになり、無関係なクラスタの状態に影響されずにアップグレードを進められる。また、クラスタ削除時の孤立 ClusterRoleBinding も自動クリーンアップされ、admin クラスタの RBAC リソースが整理される。

💰 料金・利用可能リージョン

💵 料金: GDC (software only) for VMware 自体の料金体系に変更はありません。詳細は Google Distributed Cloud の料金ページ を参照してください。
🌏 利用可能リージョン: オンプレミス (VMware vSphere 環境) で稼働するソフトウェアのため、リージョンの制約はありません。 ダウンロード提供は即時、GKE On-Prem API クライアント (コンソール / gcloud / Terraform) での利用はリリース後約 7〜14 日で可能になります。

📝 まとめ

✅ 早期適用を推奨: 本リリースは、信頼を失った eMudhra (emSign) / AAA Certificate Services ルート CA の排除というセキュリティ対応を中心に、 クラスタライフサイクル運用の信頼性を高める修正を多数含むパッチリリースです。 1.34 系を運用中の環境では、CA 排除と脆弱性修正の観点から早期の適用を推奨します。 適用前には、該当 CA 配下の証明書を利用している社内 / 外部サービスがないか、 および MetalLB アドレスプールの運用手順変更の影響を確認してください。
