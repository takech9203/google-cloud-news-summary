☁️ VMware solution on Google Cloud が一般提供 (GA)

リリース日: 2026-10-27
Google Cloud VMware Engine GA (一般提供) BYOL ベアメタル Compute Engine

📌 概要

VMware solution on Google Cloud が GA になりました。ユーザー自身の VPC ネットワーク内の専有ベアメタル Compute Engine インスタンス (z3-highmem-192-highlssd-metal) 上で、VMware Cloud Foundation (VCF) をデプロイ・構成・管理できる新しいモデルです。 ライセンスは BYOL (Bring Your Own License) モデルで、Broadcom から購入した VCF サブスクリプションを持ち込んで利用します。

ノード準備から VCF インストーラーアプライアンスのデプロイまでを Terraform と VMware solution toolkit で自動化でき、 Infrastructure as Code による再現性の高い VCF 環境構築が可能です。背景には Broadcom のライセンスモデル変更 (2025 年 10 月以降、VCF ライセンス込みノードの新規販売終了、BYOL への移行) があり、 VCF サブスクリプションを自社で保有する企業が Google Cloud 上で VMware 環境をより直接的にコントロールしたいケースに応えます。

💡 ポイント: 今後の VMware solution のリリースノートは、専用の VMware solution リリースノートページで公開されます。

❌ Before (アップデート前の課題)

  • Broadcom のライセンスモデル変更により、2025 年 10 月 15 日以降 VCF ライセンス込みの VMware Engine ノードは新規販売終了。BYOL 前提のデプロイモデルが必要に
  • 従来の VMware Engine プライベートクラウドは Google 管理インフラ上で動作し、ESXi ノードを自身のプロジェクト・VPC 内に直接配置する構成は選択不可
  • VPC 内の Google Cloud サービスとの接続にプライベートサービスアクセスなどの構成が関係し、ネットワーク設計に考慮が必要

✅ After (アップデート後の改善)

  • 専有ベアメタル ESXi ノードを削除保護・vSAN 用 Local SSD 付きで自身のプロジェクト内に直接プロビジョニング可能に
  • ノード準備、Secret Manager への認証情報保存、ネットワーキング、Cloud DNS 同期、vSAN 初期化、VCF インストーラーデプロイを Terraform + toolkit で自動化
  • vSAN フォールトドメイン対応のスプレッドプレースメントポリシーで、ノードを分離された可用性ドメインに分散し高可用性を確保
  • ESXi ノードと VLAN タグ付き Dynamic NIC を、プライベートサービスアクセスのピアリングなしで VPC サブネットに直接接続

Terraform と VMware solution toolkit がユーザーのプロジェクト内に専有ベアメタル ESXi ノードをプロビジョニングし、 Secret Manager・Cloud DNS と連携しながら vSAN と VCF インストーラーアプライアンスを自動構成します。 ノードはスプレッドプレースメントポリシーで複数の可用性ドメインに分散され、VPC サブネットに直接接続されます。

⚡ 主要機能

🖥️ 1. 専有ベアメタル ESXi ノードの直接プロビジョニング

z3-highmem-192-highlssd-metal ベアメタルインスタンスをユーザー自身のプロジェクト内に直接プロビジョニング。削除保護 (deletion protection) と、vSAN 用の Local SSD ストレージを備えます。

🛠️ 2. Terraform と VMware solution toolkit による自動化

ノード準備、Secret Manager への認証情報保存、vSwitch と Dynamic NIC のネットワーキング構成、Cloud DNS ゾーン・レコードの同期、vSAN ストレージの初期化、VCF インストーラーアプライアンスのデプロイまでを自動化します。

🛡️ 3. 可用性ドメインをまたいだ高可用性構成

スプレッドプレースメントポリシーでノードを分離されたアベイラビリティドメインに分散配置。配置は vSAN フォールトドメインと整合しており、ローカライズされた障害の影響を最小化します。

🌐 4. VPC サブネットへの直接接続

ESXi ノードと VLAN タグ付き Dynamic NIC を VPC サブネットに直接接続。プライベートサービスアクセスのピアリングが不要です。

📜 5. BYOL (Bring Your Own License) モデル

Broadcom から購入した VCF サブスクリプションを持ち込んで利用。VMware Engine の BYOL ライセンス管理 (2026 年 10 月 1 日 GA) では、Cloud Billing アカウントレベルでポータブル VCF ライセンスキーを登録・管理できます。

🔧 技術仕様

🖥️ ベアメタルノード (z3-highmem-192-highlssd-metal)

Compute Engine のストレージ最適化 Z3 ファミリーのベアメタルマシンタイプを使用します。

👍 メリット

💼 ビジネス面

  • BYOL によるライセンス投資の活用: Broadcom から購入済みの VCF サブスクリプションを Google Cloud 上でそのまま活用でき、ライセンスモデル変更後の移行パスが明確になる
  • 既存の VMware 運用資産の継続利用: VCF ベースの運用スキル・プロセスを維持しながら、Google Cloud のインフラとサービスを利用できる

⚙️ 技術面

  • Infrastructure as Code による再現性: Terraform と toolkit によりノード準備から VCF インストーラーデプロイまでを自動化でき、環境構築の再現性と効率が向上する
  • 自プロジェクト内での直接コントロール: ESXi ノードがユーザーのプロジェクト / VPC 内に存在するため、Secret Manager、Cloud DNS などと直接統合できる
  • シンプルなネットワーク構成: プライベートサービスアクセスのピアリングが不要で、VPC サブネットへ直接接続できる
  • 高可用性設計: スプレッドプレースメントポリシーと vSAN フォールトドメインの整合により、ハードウェア障害の影響範囲を限定できる

⚠️ デメリット・制約事項

考慮すべき点
▸BYOL モデルのため、VCF ライセンスは Broadcom (または認定リセラー) から別途購入する必要がある
▸従来のマネージド型 VMware Engine プライベートクラウドとは異なり、VCF のデプロイ・構成・管理はユーザー自身の責任範囲となる (運用体制の検討が必要)
▸使用できるノードタイプはリリースノート上では z3-highmem-192-highlssd-metal が示されており、要件に応じたサイジングは公式ドキュメントで確認が必要
▸どちらのモデルが適するかは「Compare VMware Engine models」ドキュメントで比較・検討することが推奨される

🎯 ユースケース

🏢 ユースケース 1: Broadcom ライセンスモデル変更後の VCF 環境新規構築

シナリオ: VCF サブスクリプションを Broadcom から直接購入している企業が、オンプレミス VMware 環境の拡張先・移行先として Google Cloud 上に新規 VCF 環境を構築する。

効果: 保有する VCF ライセンスを BYOL で活用しつつ、Terraform による自動化で VCF 環境を再現性高く構築できる。ノードは自社プロジェクト内にあるため、ガバナンスやネットワークポリシーを自社の VPC 設計に沿って適用できる。

🔌 ユースケース 2: VPC ネイティブな VMware ワークロードと Google Cloud サービスの統合

シナリオ: VMware 上のワークロードから Cloud DNS、Secret Manager などの Google Cloud サービスを密に利用したいが、プライベートサービスアクセスのピアリング設計を避けたい。

効果: ESXi ノードと Dynamic NIC が VPC サブネットに直接接続されるため、ピアリングを介さずシンプルなネットワーク構成で Google Cloud サービスと統合できる。

💰 料金

VMware solution は BYOL モデルのため、VCF ライセンス費用は Broadcom から購入するサブスクリプションに基づきます。 Google Cloud 側の費用は、専有ベアメタル Compute Engine インスタンス (z3-highmem-192-highlssd-metal) や 関連リソース (ネットワーク、Cloud DNS、Secret Manager など) の利用料金が発生します。

🧩 関連サービス・機能

  • Compute Engine (Z3 ベアメタルインスタンス): z3-highmem-192-highlssd-metal が ESXi ノードの基盤。Local SSD、Hyperdisk、最大 200 Gbps (Tier_1) のネットワーク帯域をサポート
  • スプレッドプレースメントポリシー: インスタンスを分離されたアベイラビリティドメイン (最大 8 つ) に分散し、局所的障害の影響を低減。vSAN フォールトドメインと整合させて利用
  • Secret Manager: VCF 環境の認証情報を安全に保存
  • Cloud DNS: VCF 環境の DNS ゾーンとレコードを同期
  • VMware Engine (プライベートクラウド): Google がインフラを管理する従来のマネージドモデル。要件に応じて VMware solution と使い分ける
  • VMware Engine BYOL ライセンス管理: Cloud Billing アカウントレベルでポータブル VCF ライセンスキーを登録・管理 (2026 年 10 月 1 日 GA)

✅ まとめ

VMware solution on Google Cloud の GA により、BYOL の VCF サブスクリプションを使って、 ユーザー自身の VPC 内の専有ベアメタル Compute Engine インスタンス上に VCF 環境を構築する選択肢が正式に利用可能になりました。 Broadcom のライセンスモデル変更後の VMware 環境戦略を検討している組織は、「Compare VMware Engine models」で 従来のマネージド型 VMware Engine との違いを確認し、自社の運用体制とライセンス状況に合ったモデルを選定することを推奨します。
