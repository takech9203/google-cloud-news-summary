🗄️ Bigtable Java Client 1.95.0 GA (ライブラリリリース) Bug Fixes

Bigtable Java クライアントライブラリ 1.95.0
Query 不変性とリトライ処理を修正

Release Notes 掲載日: 2026-11-09
ライブラリリリース日: 2026-11-02

📝 概要

Bigtable の Java クライアントライブラリ google-cloud-bigtable のバージョン 1.95.0 がリリースされました。新機能の追加ではなく、 10 件のバグ修正と 1 件のドキュメント改善を含むメンテナンスリリースです。

修正の中心は 2 つの領域です。1 つ目は Query オブジェクトの不変性 (イミュータビリティ) に関する修正で、 ポイントリードやページネーションの内部処理で Query をインプレースで変更してしまう問題が解消されました。 2 つ目はリトライ処理 (RetryingVRpc) の堅牢化で、残りデッドラインを考慮したリトライにより、 デッドライン超過後の無駄な試行が抑止されるようになりました。

❌ Before (アップデート前の課題)

  • createPointReadCallable や QueryPaginator の内部で Query がインプレース変更され、再利用時に意図しない挙動の可能性
  • RetryingVRpc.shouldRetry の isOk / getRejected 確認順序が不適切、クライアント起点リトライで残りデッドライン未確認
  • equals / hashCode / toString に reversed フラグが含まれず、逆順スキャンの有無だけが異なるクエリが等価判定され得た
  • pageSize より小さい limit が尊重されないケースがあった
  • RowSetUtil が空のスプリットポイントを受け付けていた
  • TestProxy の空 RowResult セマンティクスが不正確

✅ After (アップデート後の改善)

  • Query の不変性が保たれ、ポイントリードやページネーションで同一インスタンスを安全に再利用可能に
  • リトライ判定が堅牢化され、残りデッドラインを考慮したリトライで、デッドライン超過後の無駄な試行を抑止
  • reversed フラグが equals / hashCode / toString に含まれ、逆順スキャンクエリの比較・デバッグが正確に
  • limit が pageSize より小さい場合も正しく尊重
  • RowSetUtil が空のスプリットポイントを拒否、Javadoc も明確化
  • スキップされた大きな行が行数制限にカウントされることをドキュメントに明記

🔧 サービスアップデートの詳細

1️⃣ Query オブジェクトの不変性に関する修正

✓ createPointReadCallable で Query をインプレースで変更しないよう修正 (#14797)
✓ QueryPaginator で pageSize より小さいクエリの limit を尊重し、インプレース変更を回避 (#14821)
✓ Query の equals / hashCode / toString に reversed フラグを含めるよう修正 (#14799)

2️⃣ リトライ処理 (RetryingVRpc) の堅牢化

✓ RetryingVRpc.shouldRetry で isOk と getRejected を最初に確認するよう修正 (#14795)
✓ クライアント起点のリトライで残りデッドラインを確認するよう修正 (#14796)
✓ セッションダイバージョンを単一の共有ルールで解決するよう修正 (#14738)

3️⃣ その他の修正

✓ TestProxy における空の RowResult セマンティクスを修正 (#14810)
✓ RowBuilderShim で RowBuilder.startCell にセル値サイズを渡すよう修正 (#14800)
✓ RowSetUtil で空のスプリットポイントを拒否し、QueryPaginator の Javadoc を明確化 (#14811)
✓ ClientConfigurationManager からレガシーな PollingConfiguration 移行コードを削除 (#14822)

4️⃣ ドキュメント改善

✓ スキップされた大きな行 (large rows) が行数制限 (row limit) にカウントされることを明記 (#14801)

💡 補足: 同じ Release Notes エントリでは Java 1.96.0 (2026-11-05、session DirectAccess で非デフォルトサービスアカウントを許可する修正) も併記されています。アップデートの際は最新バージョンの利用を検討してください。

🔁 リトライ処理の背景

Cloud Client Libraries for Java のリトライは、RPC ごとに設定されたリトライ対象ステータスコードと RetrySettings (試行ごとのタイムアウト、全体のトータルタイムアウトなど) に基づいて動作します。 今回の修正により、クライアント起点のリトライで残りデッドラインが考慮されるようになり、 トータルタイムアウトを超過するリトライ試行が抑止される挙動が改善されています。 詳細は Java クライアントのリトライ設定ドキュメント を参照してください。

  </dependency>
</dependencies>

Google Cloud Libraries BOM を利用している場合は、BOM を最新化することで対応バージョンのクライアントが取り込まれます。 個別にバージョンを指定している場合は 1.95.0 以降 (可能であれば最新) を指定します。

ステップ 2: 依存関係の更新 (Gradle)

Groovy build.gradle 
implementation platform('com.google.cloud:libraries-bom:26.90.0')
implementation 'com.google.cloud:google-cloud-bigtable'

依存関係を更新した後、既存のテストスイートを実行し、クエリ再利用やリトライ周辺の挙動に問題がないことを確認します。

🔍 正確な等価判定とデバッグ

reversed フラグが equals / hashCode / toString に含まれることで、逆順スキャンクエリの比較・ログ出力が正確になる

📄 ページネーションの正確性

⚠️ デメリット・制約事項

⚠️ 考慮すべき点
  • バグ修正リリースのため新機能はなく、アップデートの効果は既存バグの解消に限られる
  • Query の equals / hashCode に reversed が含まれるようになったため、Query をハッシュキーや等価比較に利用しているコードでは挙動が変わる可能性がある
  • RowSetUtil が空のスプリットポイントを拒否するようになったため、従来空のスプリットポイントを渡していたコードはエラーになる可能性がある
  • 同じ Release Notes には 1.96.0 (2026-11-05) も掲載されており、アップデート時は最新バージョンの採用を検討するのが望ましい

🎯 ユースケース

📦 ユースケース 1: Query オブジェクトを再利用するバッチ読み取り処理

シナリオ: 複数のワーカーが同一の Query テンプレートを共有してポイントリードやページネーション読み取りを行うバッチ処理。 従来は内部でのインプレース変更により、再利用時に意図しない条件でクエリが実行されるリスクがあった。

Java Query テンプレートの安全な再利用 
Query baseQuery = Query.create(TableId.of("my-table")).limit(10);
// 1.95.0 以降、内部処理で baseQuery が変更されないため安全に再利用できる
ServerStream<Row> rows = dataClient.readRows(baseQuery);

効果: クエリテンプレートの再利用が安全になり、バッチ処理の正確性が向上する。

⏱️ ユースケース 2: 厳格なデッドラインを設定したオンラインサービス

シナリオ: レイテンシ SLO の厳しいオンラインサービスで、Bigtable 読み取りにトータルタイムアウトを設定している。 従来はクライアント起点のリトライで残りデッドラインが確認されず、デッドライン超過後にも試行が行われる可能性があった。

効果: 残りデッドラインを考慮したリトライにより、タイムアウト時の挙動が予測可能になり、無駄なバックエンド負荷を回避できる。
