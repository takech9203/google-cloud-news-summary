🖥️ GKE で C4D ベアメタルマシンタイプが GA

384 vCPU / 最大 3,072 GB メモリをハイパーバイザーなしで Kubernetes から利用
📅 リリース日: 2026-10-26

📌 概要

GKE において、C4D ベアメタルマシンタイプ (c4d-standard-384-metal / c4d-highcpu-384-metal / c4d-highmem-384-metal) が 一般提供 (GA) になりました。 バージョン 1.36 以降の Standard クラスタで C4D ベアメタルノードプールを作成できます。 さらに 1.37.0-gke.4713000 以降では、クラスタオートスケーラー、ノード自動プロビジョニング、 カスタム ComputeClass と組み合わせて利用でき、カスタム ComputeClass を使用する Autopilot クラスタでも利用可能です。

C4D は第 5 世代 AMD EPYC Turin プロセッサと Google 独自の Titanium オフロード基盤を搭載した汎用マシンシリーズです。 ベアメタルマシンタイプは専用ホストサーバー上でハイパーバイザーなしに直接実行され、 ライセンス要件・ネステッド仮想化・低レベルのハードウェアアクセスが必要なワークロードや、大規模なインメモリ処理に適しています。

❌ Before: アップデート前の課題

  • GKE では C4D の VM タイプは利用できたが、C4D ベアメタルは GA として利用不可
  • 先行の C3 / C4A ベアメタル (GKE 1.35.3-gke.1389000 以降) は 192 / 96 vCPU までで、大規模な単一ノード構成の選択肢が限定的
  • ベアメタルノードと自動スケーリング・自動プロビジョニングの組み合わせがシリーズごとに限定

✅ After: アップデート後の改善

  • Standard クラスタ (1.36 以降) で 384 vCPU / 最大 3,072 GB の C4D ベアメタルノードプールを作成可能
  • 1.37.0-gke.4713000 以降はクラスタオートスケーラー・ノード自動プロビジョニング・カスタム ComputeClass に対応
  • カスタム ComputeClass 経由で Autopilot クラスタでも利用可能
💡 注意: 1.37.0-gke.4713000 より前のバージョンでは、C4D ベアメタルノードプールは手動でスケールする必要があります。

GKE バージョンに応じた C4D ベアメタルノードのプロビジョニング経路。1.36 以降は Standard クラスタでの手動作成、 1.37.0-gke.4713000 以降はカスタム ComputeClass を介した自動プロビジョニング (Autopilot 含む) が可能。

⚡ 主要機能

1️⃣ C4D ベアメタルノードプールの GA

→c4d-standard-384-metal、c4d-highcpu-384-metal、c4d-highmem-384-metal の 3 つのマシンタイプが GKE で一般提供
→バージョン 1.36 以降の Standard クラスタでノードプールを作成可能
→ベアメタルインスタンスは専用ホストサーバーを必要とし、そのホスト上で実行される唯一のコンピュートインスタンスとなる

2️⃣ 自動スケーリング・自動プロビジョニング対応 (1.37.0-gke.4713000 以降)

→クラスタオートスケーラーおよびノード自動プロビジョニングで C4D ベアメタルノードを管理可能
→カスタム ComputeClass の machineType ルールで正確なマシンタイプを指定してプロビジョニング
→カスタム ComputeClass を使用する Autopilot クラスタでも利用可能
→これより前のバージョンでは、C4D ベアメタルノードプールは手動スケールが必要

3️⃣ 第 5 世代 AMD EPYC Turin + Titanium 基盤

→推定 SPECrate®2017_int_base ベンチマークで C3D 比 30% の性能向上
→最大 4.1 GHz のブースト周波数と改善された IPC により、MySQL で 55% 高い QPS、Memorystore for Redis で 35% 高いオペレーション性能 (C3D 比)
→Titanium によるネットワークオフロードで、標準ネットワーキング最大 100 Gbps、Tier_1 で最大 200 Gbps

🛠️ 設定方法

✅ 前提条件

✓GKE Standard クラスタの場合: バージョン 1.36 以降
✓自動スケーリング・ComputeClass・Autopilot で使用する場合: バージョン 1.37.0-gke.4713000 以降
✓C4D ベアメタルインスタンスが利用可能なリージョン・ゾーンであること

ステップ 1: Standard クラスタで C4D ベアメタルノードプールを作成する

Bash gcloud でノードプールを作成 
gcloud container node-pools create c4d-metal-pool \
    --cluster=CLUSTER_NAME \
    --location=LOCATION \
    --machine-type=c4d-standard-384-metal

--machine-type に C4D ベアメタルマシンタイプを指定してノードプールを作成します。 1.37.0-gke.4713000 より前のバージョンでは、このノードプールのスケールは手動で行う必要があります。

ステップ 2: カスタム ComputeClass で自動プロビジョニングする (1.37.0-gke.4713000 以降)

YAML カスタム ComputeClass 定義 
apiVersion: cloud.google.com/v1
kind: ComputeClass
metadata:
  name: c4d-metal-class
spec:
  priorities:
  - machineType: c4d-standard-384-metal
  nodePoolAutoCreation:
    enabled: true
⚠️ 重要: ベアメタルマシンタイプは正確なマシンタイプの指定が必要なため、 machineFamily フィールドではなく machineType フィールドで指定します。 machineFamily: c4d と指定しても、ベアメタルマシンタイプはプロビジョニングされません。 ワークロード側では nodeSelector で cloud.google.com/compute-class: c4d-metal-class を指定します。

👍 メリット

💼 ビジネス面

✓大規模ワークロードの集約: 384 vCPU / 最大 3,072 GB メモリの単一ノードにより、大規模なデータベースやインメモリ処理を少ないノード数で運用できる
✓コスト最適化の選択肢: C4D シリーズはリソースベースおよびフレキシブルな確約利用割引 (CUD) に対応しており、長期利用でのコスト削減が可能

⚙️ 技術面

✓ハイパーバイザーなしの直接実行: 専用ホストサーバー上で動作し、ハードウェアへの低レベルアクセスが必要なワークロードに対応できる
✓Kubernetes ネイティブな運用: 1.37.0-gke.4713000 以降ではクラスタオートスケーラー・ノード自動プロビジョニング・ComputeClass と統合され、ベアメタルノードも宣言的に管理できる
✓高いネットワーク性能: Titanium によるオフロードで最大 200 Gbps (Tier_1) のネットワーク帯域を利用できる

⚠️ デメリット・制約事項

🚫 制限事項

✗1.37.0-gke.4713000 より前のバージョンでは自動スケール不可で、手動スケールが必要
✗事前定義された Autopilot の Performance ComputeClass はベアメタルマシンタイプをサポートしない。カスタム ComputeClass で正確なマシンタイプの指定が必要
✗カスタム ComputeClass の machineFamily フィールド (例: c4d) ではベアメタルマシンタイプはプロビジョニングされない
✗Local SSD は利用不可 (Hyperdisk Balanced / Hyperdisk Extreme のみ)
✗Confidential VM (AMD SEV) はベアメタルインスタンスでは利用不可

🤔 考慮すべき点

→ベアメタルインスタンスは専用ホストサーバーを占有するため、小規模ワークロードには 384 vCPU の粒度が過剰になる場合がある。ノードあたりの集約率とコストのバランスを検討する
→C4D ベアメタルの利用可能リージョン・ゾーンは限定されるため、デプロイ先リージョンでの提供状況を事前に確認する

🎯 ユースケース

💾 ユースケース 1: 大規模インメモリデータベースの GKE 移行

シナリオ: 3 TB 近いメモリを必要とするインメモリデータベースやキャッシュ層を、Kubernetes 上で統一的に運用したい。

YAML 実装例: highmem ベアメタル用 ComputeClass 
apiVersion: cloud.google.com/v1
kind: ComputeClass
metadata:
  name: inmemory-db-class
spec:
  priorities:
  - machineType: c4d-highmem-384-metal
  nodePoolAutoCreation:
    enabled: true

効果: c4d-highmem-384-metal (384 vCPU / 3,072 GB メモリ) により、メモリ集約型ワークロードを単一ノードに収容しつつ、ComputeClass でノードのライフサイクルを自動管理できる。

🔐 ユースケース 2: ハイパーバイザーなしの実行が必要なワークロード

シナリオ: ライセンス要件やネステッド仮想化、低レベルのハードウェアアクセスなど、ハイパーバイザーを介さない実行環境が必要なワークロードを GKE で運用したい。

効果: 専用ホストサーバー上で直接実行されるベアメタルノードを GKE のノードプールとして管理でき、既存の Kubernetes 運用 (デプロイ、監視、アップグレード) に統合できる。

📝 まとめ

GKE で 384 vCPU / 最大 3,072 GB メモリの C4D ベアメタルマシンタイプが GA となり、 ハイパーバイザーなしの実行環境や大規模インメモリワークロードを Kubernetes 上で運用する選択肢が広がりました。 1.37.0-gke.4713000 以降ではカスタム ComputeClass・オートスケーラー・ノード自動プロビジョニングとの統合により、 ベアメタルノードも宣言的に管理できます。 該当ワークロードを持つ場合は、クラスタのバージョン要件と対象リージョンでの提供状況を確認のうえ、 カスタム ComputeClass での導入を検討してください。
