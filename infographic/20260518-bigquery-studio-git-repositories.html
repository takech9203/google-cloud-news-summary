フォルダベースのバージョン管理で開発ワークフローを革新

BigQuery Preview

🎯 概要

BigQuery Studio Git Repositories は、SQL スクリプトやノートブックをリモート Git リポジトリと直接統合して管理できる新機能です。Google Cloud コンソールを離れることなく、フォルダベースの直感的な操作で Git リポジトリの管理が可能になりました。

Developer Connect API を活用し、GitHub、GitLab、Bitbucket、Azure DevOps Services などの主要な Git プロバイダーとの接続をサポートします。従来のクラシックリポジトリで必要だったワークスペースの個別管理が不要になり、複数のリポジトリを同時にクローンして作業できます。

🔄 Before / After 比較

❌ Before (クラシックリポジトリ)

  • 各リポジトリ内にワークスペースを個別に作成・管理
  • バージョン管理に外部ツールとの切り替えが必要
  • フォルダベースのファイル操作ができない
  • ノートブックからリポジトリ内ファイルへのアクセスが困難

✅ After (Git Repositories)

  • ファイルブラウザ内で直接 Git リポジトリがフォルダとして表示
  • ワークスペース管理が不要、ブランチ直接切り替え
  • ノートブックから FUSE マウントで直接アクセス可能
  • OAuth ベースのシームレスな Git プロバイダー接続

⚡ 主要機能

📁

フォルダベースの Git 統合

左ペインにユーザールートフォルダ配下で Git リポジトリが直接表示。ファイルの作成、名前変更、移動、コピー、削除をドラッグ&ドロップで管理。

🌿

ブランチ管理

ローカル/リモートブランチの一覧表示、新規作成、切り替えが可能。CURRENT / DEFAULT ラベルで現在の状態を視覚的に確認。

💾

コミットとプッシュ

変更ファイルの差分表示 (View diff) による行単位の比較。コミットメッセージ入力とリモートブランチへのプッシュ。

🔗

ノートブック FUSE マウント

Git リポジトリをノートブックのランタイムにマウントし、標準的な Python import でリポジトリ内ファイルにアクセス可能。

🔐

Developer Connect 統合

OAuth ベースのアカウントコネクタによるセキュアな認証。既存コネクタの自動検出と再利用、HTTPS/SSH フォールバックもサポート。

ステップ 1: Git リポジトリの作成

  1. Google Cloud コンソールで BigQuery ページに移動
  2. 左ペインの Files をクリックしてファイルブラウザを開く
  3. ユーザールートノード横の View actions > Create > Git repository を選択
  4. リモート Git リポジトリの URL を入力
  5. Developer Connect アカウントコネクタを選択 (または新規作成)
  6. Connect をクリック

ステップ 2: ノートブックでの Git リポジトリマウント

Python 
from google_dataform_fuse_widget import FuseWidget
FuseWidget()

マウント後、リポジトリ内のファイルに対して標準的なファイルアクセスと Python import が可能になります。

💡 ユースケース

📊 データ分析チームの SQL スクリプト管理

複数メンバーで BigQuery の SQL スクリプトを開発する際に、変更履歴の管理とコードレビューのプロセスを確立。チーム共通の GitHub リポジトリを各メンバーが BigQuery Studio からクローンし、機能ブランチで開発後にプルリクエストで品質を担保。

🧪 ノートブックによるデータサイエンスワークフロー

BigQuery ノートブックでモデル開発を行い、前処理用 SQL スクリプトや共通ユーティリティを FUSE マウント経由で再利用。バージョン管理により実験の再現性も確保。

🚀 CI/CD パイプラインとの統合

BigQuery Studio で開発した SQL スクリプトがリモートリポジトリに同期されるため、GitHub Actions や GitLab CI でのテスト実行、本番環境へのデプロイ自動化が可能。GitOps によるデータパイプライン管理を実現。

⚠️ デメリット・制約事項

注意: Preview 段階であり、限定的なサポートのみ提供されます。本番環境での使用は慎重に検討してください。
✗リポジトリはユーザールートフォルダに制限され、他のユーザーとの共有は非サポート (プライベート用途)
✗Developer Connect アカウントコネクタの Git Proxy 使用は非サポート
✗大量のファイル、大きなファイルサイズ、深いコミット履歴を持つリポジトリはクローンがタイムアウトする可能性あり
✗BigQuery リポジトリ内で作成したアセットは BigQuery リポジトリからの直接スケジュール実行ができない
✗ファイルシステム操作は Dataform クォータを消費するため頻繁な操作はクォータ上限に達する可能性あり
✗マウント外での変更反映には最大 60 秒の遅延あり (CACHE_TTL_SECONDS の短縮はクォータ消費を増加)

💰 料金情報

✅ Git リポジトリの作成・更新・削除自体には課金されません。

ただし、以下の点に注意が必要です:

→ファイルシステム操作は Dataform クォータ を消費
→ノートブックの実行には通常の Colab Enterprise / BigQuery の料金が適用
→BigQuery のクエリ実行には通常の BigQuery 料金 (オンデマンドまたは定額) が適用

📝 まとめ

BigQuery Studio Git Repositories は、データチームが Google Cloud コンソール内で SQL スクリプトとノートブックのバージョン管理を完結できる重要なアップデートです。従来のクラシックリポジトリと比較してワークスペース管理が不要になり、フォルダベースの直感的な操作と Git ブランチの直接操作が可能になりました。

Preview 段階ではありますが、データ分析チームの開発生産性向上と CI/CD パイプラインとの統合を目指す組織にとって、早期評価を開始する価値がある機能です。
