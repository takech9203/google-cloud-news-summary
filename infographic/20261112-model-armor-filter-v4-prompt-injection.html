🛡️ Model Armor フィルタ v4 アップデート
プロンプトインジェクション / ジェイルブレイク検出強化

Latest エイリアス配下の v4 フィルタが更新され、間接プロンプトインジェクション (IPI)・ツール呼び出し・会話入力・ジェイルブレイクへの検出能力が向上

📌 概要

Model Armor のフィルタバージョン v4 (Latest エイリアス配下) に、更新されたプロンプトインジェクション / ジェイルブレイク検出フィルタが含まれるようになりました。 間接プロンプトインジェクション (IPI) やツール呼び出しに対する検出率 (recall) の向上、会話形式の入力に対する検出率向上と誤検知率の低減、ジェイルブレイク攻撃への検出率向上が実現されています。

Model Armor は、LLM のプロンプトとレスポンスに対してコンテンツの安全性・セキュリティ制御を適用する Google Cloud のサービスです。フィルタバージョン機能により、テンプレート単位でバージョン番号 (v3、v4 など) またはエイリアス (Latest、Stable) を指定でき、本番環境の安定性と最新の脅威検出モデルへのアクセスを両立できます。

💡 ポイント: エージェント型 AI の普及に伴い増加する「ツール呼び出しを悪用した間接プロンプトインジェクション」への検出強化が今回の目玉。Latest エイリアスを使用中のテンプレートは、設定変更なしで自動的に改善が適用されます。

😣 Before: アップデート前の課題

  • 外部データ (メール、ドキュメント、Web ページ) に埋め込まれた悪意ある指示による IPI やツール呼び出し標的攻撃は、直接攻撃に比べ検出が困難
  • マルチターン会話では、正当な対話の誤検知と攻撃の見逃しの両方が課題
  • 巧妙化するジェイルブレイク攻撃への検出率向上が必要

😊 After: アップデート後の改善

  • IPI / ツール呼び出しへの recall が向上し、エージェント型ワークロードの保護を強化
  • 会話形式入力でより低い誤検知率 × より高い検出率を実現し、UX を損なわずセキュリティ向上
  • ジェイルブレイク攻撃の検出率が向上

Model Armor はテンプレートで指定されたフィルタバージョンを使用してプロンプトとレスポンスをスクリーニングします。Latest エイリアスを使用するテンプレートは、今回更新された v4 のプロンプトインジェクション / ジェイルブレイク検出フィルタを自動的に利用します。

⚡ 主要機能

1️⃣ 間接プロンプトインジェクション (IPI) とツール呼び出しに対する検出率向上

  • 外部コンテンツに埋め込まれた悪意ある指示 (IPI) に対する recall が向上
  • AI エージェントのツール呼び出し (function calling) を標的とした攻撃の検出が強化され、エージェント型アーキテクチャの保護が向上

2️⃣ 会話形式入力の検出精度向上と誤検知低減

  • マルチターンの会話入力に対して、より高い検出率をより低い誤検知率で実現
  • チャットボットや対話型アプリケーションで、正当な対話をブロックするリスクを抑えつつセキュリティを強化

3️⃣ ジェイルブレイク攻撃への検出強化

  • モデルの安全制御を回避しようとするジェイルブレイク攻撃に対する recall が向上

📝 フィルタバージョンの指定方法

→フィルタバージョンはテンプレート単位で設定 (フィルタごとに異なるバージョンは指定不可)
→バージョン未指定のテンプレートは Stable がデフォルトで適用
→Latest / Stable エイリアス使用時は、参照先の更新で自動的に新バージョンを使用
→特定のバージョン番号 (v3、v4 など) を指定すると、エイリアスが更新されても固定された動作を維持

    }
  },
  "templateMetadata": {
    "filterVersionSelector": {

    }

🛠️ 設定方法

✅ 前提条件

✓Google Cloud プロジェクトで Model Armor API が有効化されていること
✓Model Armor テンプレートの作成・更新権限があること

ステップ 1: Latest エイリアスを使用するテンプレートを作成

Bash テンプレート作成 (Latest エイリアス指定) 
gcloud model-armor templates create TEMPLATE_ID \
  --project=PROJECT_ID \
  --location=LOCATION \
  --pi-and-jailbreak-filter-settings-enforcement=enabled \
  --filter-version-selector-alias=filter-version-alias-latest

Latest エイリアスを指定することで、今回更新された v4 フィルタが自動的に適用されます。

ステップ 2: 既存テンプレートのフィルタバージョンを更新

Bash 既存テンプレートの更新 
# エイリアスで指定する場合
gcloud model-armor templates update TEMPLATE_ID \
  --project=PROJECT_ID \
  --location=LOCATION \
  --filter-version-selector-alias=filter-version-alias-latest

# バージョン番号を固定する場合
gcloud model-armor templates update TEMPLATE_ID \
  --project=PROJECT_ID \
  --location=LOCATION \
  --filter-version-selector=v4

バージョン番号 (v4) を直接指定すると、エイリアスの参照先が変わっても固定された動作を維持できます。

💪 メリット

💼 ビジネス面

  • エージェント型 AI のリスク低減: ツール呼び出しや外部データ経由の IPI への検出強化で、AI エージェント導入時のセキュリティリスクを低減
  • UX とセキュリティの両立: 会話入力の誤検知率低減により、正当な利用をブロックせず保護を強化
  • 運用負荷なしの自動強化: Latest エイリアス使用なら設定変更・デプロイ作業なしで最新検出モデルの恩恵を享受

⚙️ 技術面

  • IPI / ツール呼び出しへの高い recall: RAG やエージェントが取り込む外部コンテンツに潜む攻撃ベクトルの検出率向上
  • バージョン管理による柔軟な運用: Latest で事前検証し、Stable 昇格後に本番適用する計画的ロールアウトが可能
  • マルチターン対応: 会話コンテキストを含む入力に対する検出精度が向上し、対話型アプリに最適な保護を実現

⚠️ デメリット・制約事項

🚧 制限事項

✗フィルタバージョンはテンプレート単位での設定であり、個々のフィルタごとに異なるバージョンは指定不可
✗Latest エイリアスは標準の SLO を提供するが、バージョン間で安定性 (フィルタ動作の一貫性) が変動する可能性
✗Legacy バージョンは新しい Stable リリース後 90 日で Retired となり利用不可 (v1 / v2 は 2026 年 12 月 17 日に廃止予定)
✗Google および Google Cloud MCP サーバーとの統合では、フィルタバージョンのオーバーライド不可

🤔 考慮すべき点

  • 本番環境でフィルタ動作の一貫性が必要な場合は、Latest ではなく Stable エイリアスまたは特定バージョンの固定を検討
  • 検出モデルの更新で判定結果が変わる可能性があるため、Latest 利用時は誤検知の監視体制 (モニタリングダッシュボードなど) を整備
  • 誤検知が発生した場合は、テンプレート固有の除外ルール (辞書・正規表現) で緩和可能

🎯 ユースケース

🤖 ユースケース 1: AI エージェントのツール呼び出し保護

シナリオ: 社内ドキュメントや外部 Web を参照しながらツール呼び出しを行う AI エージェントを運用。取り込んだコンテンツに埋め込まれた間接プロンプトインジェクションによる不正なツール実行を防止したい。

Bash エージェント保護テンプレートの作成例 
gcloud model-armor templates create agent-protection \
  --project=my-project \
  --location=us-central1 \
  --pi-and-jailbreak-filter-settings-enforcement=enabled \
  --filter-version-selector-alias=filter-version-alias-latest

✅ 効果: v4 の更新フィルタにより IPI とツール呼び出しを標的とした攻撃の検出率が向上し、エージェントの意図しない動作を未然に防止。

💬 ユースケース 2: カスタマーサポートチャットボットの誤検知低減

シナリオ: マルチターン対話のカスタマーサポートチャットボットで、正当な問い合わせが誤ってブロックされる誤検知が課題。

✅ 効果: 会話形式の入力に対して低い誤検知率で高い検出率を実現する v4 フィルタにより、ユーザー体験を損なわずジェイルブレイクやプロンプトインジェクションからボットを保護。

🚀 ユースケース 3: Latest での事前検証と Stable への計画的ロールアウト

シナリオ: 本番環境では Stable エイリアスを使用しつつ、ステージング環境で最新の検出能力を実トラフィックパターンに対して評価したい。

✅ 効果: ステージング用テンプレートに Latest エイリアスを設定することで、v4 の新しい検出動作を事前に検証でき、v4 が Stable に昇格した際の本番影響を予測可能に。
