📋 概要

Compute Engine の Managed Instance Group (MIG) において、Flex-start VM をキャパシティの空き状況に応じて段階的に作成する機能が GA になりました。

従来の MIG リサイズリクエストでは全容量が確保されるまで VM が作成されませんでしたが、本機能では利用可能なキャパシティに応じて一部の VM を先に作成し、残りは後からキャパシティが確保でき次第追加します。

Flex-start VM は Dynamic Workload Scheduler (DWS) を活用して GPU などの高需要リソースを割引価格で取得でき、モデルファインチューニング、バッチ推論、HPC シミュレーションなど、7 日以内で完了する短期ワークロードに最適です。

🔄 Before / After 比較

❌ アップデート前

  • 要求した全 VM のキャパシティが確保されるまで 1 台も VM が作成されなかった
  • GPU 等の高需要リソースでは全容量確保に長時間待機
  • 部分的なキャパシティが利用可能でもワークロードを開始できなかった
  • 全容量確保を待つ間、時間とコスト機会を損失

✅ アップデート後

  • キャパシティが利用可能になった分から段階的に VM を作成
  • 部分的なリソースでも早期にワークロードを開始可能
  • MIG が残りの VM をキャパシティ確保次第自動追加
  • 一括作成と段階的作成を用途に応じて選択可能

⚡ 主要機能

📦 段階的 VM プロビジョニング

MIG のターゲットサイズポリシーモード (Individual) で動作。キャパシティが利用可能になった分から VM を自動作成し、部分的なキャパシティでも即座にプロビジョニング開始。

💰 Flex-start 割引統合

DWS による割引価格でのリソース取得。A4/A3/A2/G4 で最大 53% 割引、H4D で 25% 割引。Preemptible クォータを消費。

🌍 リージョナル MIG 対応

ゾーナル/リージョナル MIG の両方に対応。ANY で複数ゾーン分散、ANY_SINGLE_ZONE で単一ゾーン内作成をサポート。

🎯 ワークロードポリシー配置制御

ベストエフォートでの密集配置でネットワークレイテンシを最小化。高スループットタイプのワークロードポリシーで AI/ML ワークロードに最適な配置を実現。

🛠️ 設定方法

💡 前提条件: 十分な Preemptible クォータ (GPU, vCPU, メモリ) の確保、Compute Instance Admin (v1) IAM ロールの付与が必要です。

ステップ 1: インスタンステンプレートの作成

Bash Flex-start テンプレート作成 
gcloud compute instance-templates create TEMPLATE_NAME \
    --machine-type=a2-highgpu-1g \
    --accelerator=type=nvidia-tesla-a100,count=1 \
    --provisioning-model=FLEX_START \
    --max-run-duration=604800s \
    --instance-termination-action=DELETE \
    --maintenance-policy=TERMINATE

ステップ 2: ゾーナル MIG の作成

Bash ゾーナル MIG 作成 (段階的プロビジョニング) 
gcloud compute instance-groups managed create MIG_NAME \
    --default-action-on-vm-failure=do-nothing \
    --size=SIZE \
    --template=TEMPLATE_NAME \
    --zone=ZONE

ステップ 3: リージョナル MIG の作成 (複数ゾーン分散)

Bash リージョナル MIG 作成 
gcloud compute instance-groups managed create MIG_NAME \
    --default-action-on-vm-failure=do-nothing \
    --size=SIZE \
    --template=TEMPLATE_NAME \
    --region=REGION \
    --target-distribution-shape=ANY

必要な IAM ロール

{
  "role": "roles/compute.instanceAdmin.v1",

✅ メリット

📊 ビジネス面

🚀ワークロード開始時間の短縮 - 全リソース確保を待たず部分キャパシティで作業開始、リードタイム短縮
💰コスト最適化 - 最大 53% GPU 割引 + 部分キャパシティ即時活用によるコスト効率向上
📈GPU 取得率向上 - 高需要リソースへのアクセス改善、プロジェクト遅延軽減

⚙️ 技術面

🤖自動キャパシティ管理 - MIG が残り VM を自動プロビジョニング、手動監視不要
🔗密集配置最適化 - DWS によるベストエフォート密集配置でノード間通信レイテンシ最小化
🔀柔軟なスケーリング - 段階的作成 (Individual) と一括作成 (Bulk) を用途に応じて選択

⚠️ 制限事項・注意点

制約事項
  • VM 修復 (自動修復) を無効化する必要がある
  • オートスケーラーとの併用不可
  • VM 終了アクションは DELETE のみ (MIG 内では STOP 不可)
  • キャナリーアップデート非対応
  • 対応マシンタイプが限定的 (GPU, TPU, H4D のみ)
  • A4X / A4X Max マシンタイプは非サポート
  • Compact 配置ポリシーは適用不可 (ワークロードポリシーを使用)
  • 予約 (Reservations) との併用不可
💡 考慮すべき点:
  • 部分キャパシティで作成された VM にも課金が発生 - 全 VM 必須のワークロードにはリサイズリクエスト方式が適切
  • VM は最大 7 日後に自動削除 - チェックポイント戦略が重要
  • Preemptible クォータ不足時はリクエスト保留 (クォータ確保まで VM 未作成)

🎯 ユースケース

🧠 GPU モデルファインチューニングの段階的実行

複数のモデルバリアントのファインチューニングを 8 台の A100 GPU VM で並列実行したいが、即座に 8 台分確保できない状況に最適。3 台確保できた時点で先にジョブを開始し、残りは順次追加。全容量待ちと比較して数時間のリードタイム短縮。

🔄 バッチ推論の柔軟なスケールアウト

大量の推論リクエストを処理するために Flex-start VM を使用し、利用可能なキャパシティに応じて段階的にスループットを拡大。全リソース確保を待つことなく SLA を満たす処理を早期に開始。GPU コスト最大 53% 割引。

🧮 HPC シミュレーションのリソース段階的確保

H4D マシンタイプを使用した HPC シミュレーションで、複数ノードを段階的に確保して並列計算を実行。H4D の 25% 割引を活用しつつ、部分ノードで予備的計算を開始し、全ノード揃い次第フル並列計算に移行。

💲 料金情報

Flex-start VM は Dynamic Workload Scheduler (DWS) 料金に基づいて課金されます。MIG の段階的プロビジョニング自体に追加料金はありません。

マシンシリーズ割引率割引対象
A4, A3, A2, G4最大 53%vCPU、メモリ、GPU
H4D25%vCPU、メモリ
  • 従量課金 (PAYG) 方式
  • VM が作成された時点から課金開始、削除時点で課金終了
  • 詳細は DWS 料金ページ を参照

🔗 関連サービス・機能

  • 📦 MIG リサイズリクエスト - 全 VM を一括作成。全容量確保まで待機し揃った時点で一斉プロビジョニング。部分課金を避けたい場合に最適。
  • 📦 MIG Bulk モード - ターゲットサイズポリシーを BULK に設定しインスタンスを一括作成。
  • ⚡ Dynamic Workload Scheduler (DWS) - Flex-start VM の基盤技術。キャパシティ認識型スケジューラーで GPU リソース取得率を向上。
  • ☸️ GKE Flex-start - GKE クラスター内で Flex-start VM をノードプールとして使用。
  • 🧠 Vertex AI DWS 統合 - サーバーレストレーニングジョブで Flex-start モードを使用。
  • 🎯 ワークロードポリシー - MIG 内の VM 配置を制御し AI/ML ワークロードに適した配置を実現。

📝 まとめ

MIG における Flex-start VM の段階的作成機能の GA により、GPU や TPU などの高需要リソースを部分的なキャパシティから利用開始できるようになりました。

従来のリサイズリクエスト (一括作成) と今回の段階的作成を使い分けることで、ワークロードの特性に応じた最適なリソース取得戦略を実現できます。ML モデルのファインチューニングやバッチ推論など、部分実行可能なワークロードを運用している場合は、まずインスタンステンプレートの作成と小規模な MIG での検証を推奨します。
