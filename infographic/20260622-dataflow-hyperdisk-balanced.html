💾 Dataflow: Hyperdisk Balanced ディスクのサポート

2026-06-22
Dataflow Hyperdisk Balanced Feature

📋 概要

Dataflow ワーカー VM で Hyperdisk Balanced ディスクが利用可能になりました。ディスクサイズとは独立して IOPS とスループットをプロビジョニングでき、パイプラインのワークロード要件に応じた最適なディスクパフォーマンスを設定できます。

最大 160,000 IOPS と 2,400 MiB/s のスループットを単一ボリュームでプロビジョニング可能。I/O 集約型のバッチ/ストリーミングパイプラインのパフォーマンスボトルネックを解消します。

160,000
最大 IOPS (単一ボリューム)
2,400
最大スループット (MiB/s)
64 TiB
最大ディスクサイズ

🔄 Before / After

❌ Before

  • ディスクタイプは pd-standard / pd-ssd に限定
  • IOPS とスループットはディスクサイズに比例
  • パフォーマンスを上げるにはディスクサイズの増加が必要
  • 不要なストレージコストが発生
  • I/O 集約型ワークロードではオーバープロビジョニングが不可避

✅ After

  • Hyperdisk Balanced でサイズと独立して IOPS/スループットを設定
  • ワークロードの I/O パターンに正確にマッチ
  • コスト最適化が可能
  • 最大 160,000 IOPS、2,400 MiB/s まで対応
  • サブミリ秒レイテンシを実現

⚡ 主要機能

💾 Hyperdisk Balanced ディスクタイプのサポート

ワーカー VM のディスクタイプとして hyperdisk-balanced を指定可能。Java では workerDiskType、Python では worker_disk_type、Go では disk_type パイプラインオプションを使用。

🔢 IOPS の独立プロビジョニング

ディスクサイズと無関係に IOPS を設定。設定範囲: 3,000 ~ 160,000 IOPS。未設定時のデフォルト: 3,000 IOPS。

📈 スループットの独立プロビジョニング

ディスクサイズと無関係にスループットを設定。設定範囲: 140 ~ 2,400 MiB/s (プロビジョニングされた IOPS に依存)。未設定時のデフォルト: 140 MiB/s。

💡 必須バージョン: Apache Beam SDK 2.74.0 以降が必要です。

📝 設定方法

前提条件

✓ Apache Beam SDK バージョン 2.74.0 以降がインストールされていること
✓ ワーカー VM のマシンタイプが Hyperdisk Balanced をサポートしていること

Java SDK での設定例

Java Dataflow Hyperdisk Balanced 設定 
PipelineOptions options = PipelineOptionsFactory.create();
options.as(DataflowPipelineOptions.class).setWorkerDiskType("hyperdisk-balanced");
options.as(DataflowPipelineOptions.class).setDiskProvisionedIOPS(10000L);
options.as(DataflowPipelineOptions.class).setDiskProvisionedThroughput(500L);
options.as(DataflowPipelineOptions.class).setDiskSizeGb(100);

Python SDK での設定例

Python Dataflow Hyperdisk Balanced 設定 
pipeline_options = PipelineOptions([
    '--worker_disk_type=compute.googleapis.com/projects/PROJECT_ID/zones/ZONE/diskTypes/hyperdisk-balanced',
    '--disk_provisioned_iops=10000',
    '--disk_provisioned_throughput_mibps=500',
    '--disk_size_gb=100',
])

Go SDK での設定例

Bash Go SDK パイプラインオプション 
--disk_type=compute.googleapis.com/projects/PROJECT_ID/zones/ZONE/diskTypes/hyperdisk-balanced
--disk_provisioned_iops=10000
--disk_provisioned_throughput_mibps=500
--disk_size_gb=100

🎯 ユースケース

📦 大規模バッチ ETL パイプライン

シナリオ: 数百 GB のデータを Cloud Storage から読み込み、変換して BigQuery に書き込むバッチパイプライン。Dataflow Shuffle を使用しないケースでは、シャッフルデータの I/O がボトルネックとなる。

Bash 実行コマンド例 
python -m my_pipeline \
  --runner=DataflowRunner \
  --worker_disk_type=compute.googleapis.com/projects/my-project/zones/us-central1-a/diskTypes/hyperdisk-balanced \
  --disk_provisioned_iops=50000 \
  --disk_provisioned_throughput_mibps=1000 \
  --disk_size_gb=200

効果: ディスク I/O スループットを 1,000 MiB/s にプロビジョニングし、シャッフルフェーズの処理時間を大幅に短縮。

🔄 ストリーミングパイプラインのステート管理

シナリオ: Streaming Engine を使用しないストリーミングジョブで、大量のステートデータをローカルディスクに保持する必要がある場合。

効果: 高い IOPS をプロビジョニングすることで、ステートの読み書きレイテンシを低減し、イベント処理のスループットを向上。

✅ メリット

ビジネス面

✓ コスト最適化: ディスクサイズを不必要に大きくせず、必要なパフォーマンスだけをプロビジョニングすることでストレージコストを削減
✓ パフォーマンス予測可能性: 固定されたプロビジョニング値によりパイプライン実行時間をより正確に見積もり可能

技術面

✓ 独立スケーリング: IOPS、スループット、容量をそれぞれ独立して制御可能
✓ 高パフォーマンス: 最大 160,000 IOPS、2,400 MiB/s で大規模 I/O 集約型パイプラインに対応
✓ サブミリ秒レイテンシ: Hyperdisk Balanced はサブミリ秒レイテンシを実現する設計

⚠️ 制約事項・注意点

制限事項
  • Apache Beam SDK 2.74.0 以降が必要 (それ以前のバージョンでは IOPS/スループットのプロビジョニングオプションは使用不可)
  • Dataflow で使用可能な Hyperdisk タイプは Hyperdisk Balanced のみ (Extreme、Throughput 等は対象外)
  • ワーカー VM のマシンタイプが Hyperdisk Balanced をサポートしている必要あり
  • プロビジョニングされたパフォーマンスは VM レベルのパフォーマンス上限を超えられない
考慮すべき点
  • Streaming Engine 使用時またはマシンタイプが N4 の場合は Persistent Disk を指定すべきではない
  • IOPS/スループットの変更は 4 時間に 1 回のみ可能 (Dataflow ジョブでは通常作成時に設定)
  • Hyperdisk はリソースベースの CUD やサステインド使用ディスカウントの対象外

💰 料金情報

Hyperdisk Balanced の料金は、プロビジョニングされた容量・IOPS・スループットに基づいて課金されます。ベースラインパフォーマンス (3,000 IOPS、140 MiB/s) は無料で含まれます。

料金単価 (us-central1)

項目 単価

IOPS (ベースライン超過分、1 IOPS あたり/月)$0.005
スループット (ベースライン超過分、1 MiB/s あたり/月)$0.040

ワーカー VM のリソースを自動最適化。特定の VM タイプ指定はサポート外

📌 まとめ

Dataflow で Hyperdisk Balanced ディスクが利用可能になったことで、I/O 集約型パイプラインのパフォーマンスをディスクサイズに依存せず最適化できるようになりました。特に Dataflow Shuffle や Streaming Engine を使用しないパイプラインにおいて、ディスク I/O がボトルネックとなるケースでの効果が大きく、Apache Beam SDK 2.74.0 以降にアップデートすることで活用可能です。
