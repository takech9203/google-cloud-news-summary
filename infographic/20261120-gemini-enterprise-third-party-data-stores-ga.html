📋 概要

Gemini Enterprise において、AirOps、Airtable、Asana、GitLab、Grafana、Hugging Face、Linear、Moody's、MSCI、PagerDuty、Sourcegraph、Stripe、Zapier など約 80 種類のサードパーティデータストアが一般提供 (GA) になりました。これらの外部アプリケーション・データソースを接続し、エンタープライズ検索やエージェントのグラウンディング (回答根拠) として本番環境で利用できます。

コネクタはサードパーティアプリケーションのデータをインジェスト (インデックス化)、またはフェデレーション方式で接続します。接続するとデータソースごとにデータストアが作成され、エンティティ (例: Jira Cloud の issue、attachment、comment) ごとにエンティティデータストアが関連付けられます。開発者ツールから金融・法務・旅行まで、コネクタエコシステムが大幅に拡充されました。

😣 アップデート前の課題

❌多くのデータソースが GA 前のステータスで、本番ワークロードでの採用判断が難しかった
❌社内ナレッジが多数の SaaS に分散し、横断的に参照できる対象が限られていた
❌業種特化型データ (金融マーケットデータ、法務ドキュメント管理など) をグラウンディングに組み込む公式な手段が限られていた

😊 アップデート後の改善

✅約 80 種類のデータストアが GA となり、本番環境で安心して利用可能に
✅開発・運用 (GitLab、Grafana、PagerDuty)、金融 (Moody's、MSCI、S&P Global)、法務 (iManage、Relativity) など業種特化データを公式コネクタで接続可能に
✅discoveryengine.managed.allowedDataSources 組織ポリシーで統制しつつエコシステム全体を活用可能に

3️⃣ データストアとエンティティデータストアの自動作成

→データソースを接続すると、Gemini Enterprise がデータストアを作成し、指定したエンティティごとにエンティティデータストアを関連付け
→エンティティタイプはデータソース固有 (例: Jira Cloud では issue、attachment、comment、worklog)
→非構造化データ (PDF、HTML、DOCX など) は非構造化データストア、構造化データは構造化データストアとして作成

4️⃣ 組織ポリシーによる統制

→各コネクタには discoveryengine.managed.allowedDataSources 組織ポリシー用の値が定義されており (例: GitLab は gitlab、Grafana は grafana)、管理者は組織で許可するデータソースを制御可能

🔧 技術仕様

🔀 接続方式: フェデレーションとインジェスト

方式内容特徴
データフェデレーション 指定したデータソースから直接情報を取得 インデックスにコピーしないためストレージ不要。ただしインデックス化されないため検索品質が低くなる場合がある
データインジェスト
(インデックス化)		 データを Gemini Enterprise のインデックスにコピー 検索品質の向上が期待できる。ただしストレージと同期時間を消費
💡 ポイント: コネクタが両方式をサポートする場合は、要件に応じて接続方式を選択できます。

🔒 セキュリティ関連の仕様

項目詳細
アクセス制御データストアに対するアクセス制御を設定 (Identity and permissions)
CMEK顧客管理の暗号鍵を使用する場合、サードパーティコネクタ向けにシングルリージョン鍵の登録が必要
静的 IP エグレスアウトバウンドトラフィックを固定 IP から発信するよう構成可能 (対応データストアのみ)。ソースシステム側での許可リスト登録に利用
データ保存リージョンインジェスト時に global、US、EU などの保存先リージョンを選択
フェデレーション時の注意クエリ文字列が有効化されたすべてのサードパーティ検索バックエンドに送信される。渡ったデータは当該システムの利用規約・プライバシーポリシーに従う

🛠️ 設定方法

📌 前提条件

✓Gemini Enterprise のセットアップが完了していること
✓サードパーティアプリケーションの管理者が、接続に必要な認証情報・スコープ・権限を確認し設定していること (必要な権限はデータソースごとに異なる)
✓データストアへのアクセス制御の設計 (Identity and permissions)
✓CMEK を使用する場合は、シングルリージョン鍵の登録

🚀 手順 (概要)

  1. 接続方式を決定: フェデレーションとインジェストのどちらでデータを接続するか選択
  2. 認証情報を確認: インジェストの場合、データ取り込みに使用するユーザー認証情報でリソースへのアクセスが制限されていないことを確認
  3. 同期頻度を決定: データの同期頻度を設計
  4. 静的 IP エグレスを構成 (必要に応じて): ソースシステム側で IP を許可リストに登録
  5. コネクタ別手順で接続: 各データソース固有のセットアップ手順 (公式ドキュメントのコネクタ別ページ) に従って接続

詳細は Connect a third-party data source および各コネクタのドキュメントを参照してください。

⚠️ デメリット・制約事項

🚧 制限事項

⚠️すべてのデータストアがアクション (操作実行) をサポートしているわけではなく、フェデレーテッド検索のみ・検索のみといった限定機能のデータストアもある
⚠️データソースごとにサポートされるエンティティタイプ・データ形式が異なる
⚠️インジェストはストレージを消費する (ストレージ・インデックス quota はエディションに応じてプールされる)

🤔 考慮すべき点

❗フェデレーテッド検索では、クエリ文字列 (検索リクエストや会話履歴の一部を含む可能性) がサードパーティ検索バックエンドに送信され、ユーザーの ID と紐付けられる可能性がある。渡ったデータは Google Cloud ではなく当該システムの利用規約・プライバシーポリシーの適用対象
❗PII を含むデータでオートコンプリートを使用する場合は PII 漏えい対策の検討が必要
❗サードパーティ側の認証情報・スコープの管理 (アプリケーション管理者による設定) が必要

効果: これらの金融データソースを GA コネクタで接続することで、Gemini Enterprise のアシスタントが信頼できる外部データに基づいて回答を生成でき、リサーチ業務を支援できる。
