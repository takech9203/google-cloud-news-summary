☕ Looker: OpenJDK 21 サポート

Looker GA Looker 26.8
2026-07-17

📄 概要

Looker 26.8 より、Looker の Java ランタイム要件が OpenJDK 21 にアップグレードされました。これは Looker のパフォーマンス、セキュリティ、および長期サポートを強化するための重要な基盤更新です。

Looker ホスト型インスタンスは既にアップグレード完了済み。カスタマーホスト型インスタンスを運用している組織は、手動でのアップグレードが必要です。

⚠️ 重要: java -jar コマンドで直接 Looker を実行している環境では、新しい JVM フラグ (--add-opens) の追加が必須です。

🔄 Before / After 比較

❌ Before (OpenJDK 11)

  • セキュリティパッチ提供が終了に近づいていた
  • 最新の暗号化アルゴリズムの恩恵を受けられず
  • Nashorn スクリプトエンジン非推奨化に伴うフラグが必要
  • 古いガベージコレクション実装

✅ After (OpenJDK 21)

  • LTS リリースによる長期セキュリティサポート
  • 最新 GC (ZGC, Shenandoah) で応答性向上
  • Nashorn フラグ不要、モジュールアクセス用フラグに移行
  • TLS 1.3 完全サポート

🔑 主要機能

① OpenJDK 21 への移行

→実行環境が OpenJDK 11 から OpenJDK 21 にアップグレード
→Java 21 は LTS (Long-Term Support) リリース
→JDK (JRE ではなく) の使用を推奨 -- トラブルシューティングツールが利用可能

② Looker ホスト型: 自動アップグレード

✓既に OpenJDK 21 にアップグレード済み
✓顧客側での追加作業は不要
✓サービス中断なしで移行が完了

③ カスタマーホスト型: 手動アップグレード

→管理者が手動でアップグレードを実施する必要あり
→java -jar 起動時は 3 つの --add-opens フラグが必須
→スタートアップスクリプト使用時はフラグが自動適用

必須 JVM フラグ (java -jar 起動時)

Java Platform Module System (JPMS) のアクセス制御を緩和し、Looker が必要とする内部 API へのリフレクションアクセスを許可するフラグです。

Bash 
java \
  --add-opens=java.base/sun.nio.ch=ALL-UNNAMED \
  --add-opens=java.base/java.io=ALL-UNNAMED \
  --add-opens=java.base/java.nio=ALL-UNNAMED \
  -jar looker.jar

📝 設定方法 (カスタマーホスト型)

💡 前提条件: Looker 26.8 以降、カスタマーホスト型インスタンスを運用、現在の環境のバックアップが取得済みであること。

Step 1: 現在の Java バージョンを確認

Bash 
java -version

Step 2: OpenJDK 21 のインストール

Bash (Ubuntu/Debian) 
sudo apt update
sudo apt install openjdk-21-jdk
Bash (RHEL/CentOS) 
sudo yum install java-21-openjdk-devel

Step 3: Java バージョンの切り替え

Bash 
sudo update-alternatives --config java
# OpenJDK 21 を選択

Step 4: Looker の再起動

スタートアップスクリプト使用時:

Bash 
cd /home/looker/looker
./looker restart

java -jar コマンド起動時:

Bash 
java \
  --add-opens=java.base/sun.nio.ch=ALL-UNNAMED \
  --add-opens=java.base/java.io=ALL-UNNAMED \
  --add-opens=java.base/java.nio=ALL-UNNAMED \
  -jar looker.jar start

Step 5: 動作確認

Bash 
# Looker のステータス確認
curl -s http://localhost:9999/alive

ブラウザから Looker UI にアクセスし、ダッシュボードやクエリが正常に動作することを確認してください。

✓コンプライアンス強化: 最新の暗号化アルゴリズムとセキュリティ機能により、規制要件への適合が容易
✓Looker ホスト型の利便性: 自動アップグレードにより運用負荷ゼロ

💻 技術面

✓パフォーマンス向上: 改善された JIT コンパイラとガベージコレクション
✓セキュリティ強化: 最新のセキュリティパッチと TLS 1.3 の完全サポート
✓モダンな Java 機能: Virtual Threads、Pattern Matching 等がプラットフォーム基盤に反映

⚠️ 制約事項・考慮点

制限事項

✗Oracle JDK はサポート対象外 (OpenJDK 21 のみ公式サポート)
✗OpenJDK 21 以外のバージョン (11, 17 等) はサポート対象外
✗java -jar 起動時は必ず 3 つの --add-opens フラグが必要

考慮すべき点

  • カスタマーホスト型では手動アップグレードが必要で、ダウンタイムが発生
  • 既存の JVM 起動スクリプトやシステムサービス設定の更新が必要な場合あり
  • Java 11 用の -Dnashorn.args=--optimistic-types=false フラグは不要になるため、起動オプションの見直しが必要
  • サードパーティの JDBC ドライバーとの互換性確認が推奨

💡 ユースケース

📌 ユースケース 1: スタートアップスクリプトを使用した環境

シナリオ: Ubuntu Linux 上でスタートアップスクリプトを使用して Looker を運用している企業が、OpenJDK 21 にアップグレードする場合。

Bash 
# 1. バックアップの作成
cd /home/looker/looker
./looker backup

# 2. Looker を停止
./looker stop

# 3. OpenJDK 21 をインストール
sudo apt install openjdk-21-jdk

# 4. Java バージョンを切り替え
sudo update-alternatives --config java

# 5. Looker を起動（スタートアップスクリプトがフラグを自動設定）
./looker start

効果: スタートアップスクリプトが --add-opens フラグを自動的に適用するため、最小限の変更でアップグレードが完了。

📌 ユースケース 2: systemd サービスとして運用 (java -jar)

シナリオ: systemd のサービスユニットファイルで java -jar を直接指定して Looker を起動している環境。

INI (systemd) 
# /etc/systemd/system/looker.service
[Unit]
Description=Looker Application
After=network.target

[Service]
Type=simple
User=looker
Group=looker
ExecStart=/usr/bin/java \
  --add-opens=java.base/sun.nio.ch=ALL-UNNAMED \
  --add-opens=java.base/java.io=ALL-UNNAMED \
  --add-opens=java.base/java.nio=ALL-UNNAMED \
  -Xmx4096m \
  -jar /home/looker/looker/looker.jar start
Restart=on-failure

[Install]
WantedBy=multi-user.target

効果: systemd サービス定義に JVM フラグを追加することで、再起動時にも自動的に正しい設定で Looker が起動。
