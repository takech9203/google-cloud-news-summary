📌 概要

2026 年 10 月 22 日、Google Cloud は PHP コア脆弱性 CVE-2026-109618 / CVE-2026-109619 (いずれも Critical、CVSS 9.2) への対応について、訂正版のセキュリティ注記を Release Notes に掲載しました。 対象は App Engine スタンダード環境 (PHP)、App Engine フレキシブル環境 (PHP)、Cloud Run、Cloud Run functions の 4 サービスで、4 件とも同一の文面です。

⚠️ 前日 10/21 の注記は公式に無効化: 各サービスの 10/21 の注記には「This note is incorrect; follow guidance in the entry for October 22, 2026. (この注記は正しくありません。2026 年 10 月 22 日のエントリのガイダンスに従ってください)」という訂正が付記されました。
📢 10/22 の訂正版ガイダンス: 「サポート対象の PHP 8.2 以降のすべてのバージョンにパッチが適用されています。更新された依存関係でリソースを再デプロイし、直ちに保護措置を講じてください。」 10/21 の注記にあった具体的なパッチバージョンの列挙 (8.5.12 / 8.4.27 / 8.3.36 / 8.2.35) や「自動的にパッチ適用済み」という自動適用の記述は、訂正版には含まれていません。

当サイトでは 10/21 の注記に基づくレポートを公開済みですが、その元となった注記が公式に「incorrect」とマークされたため、本レポート (10/22 の注記) が訂正後の最新ガイダンスとなります。

💡 主要なポイント

1️⃣ 4 サービスで同一の訂正版注記

App Engine スタンダード環境 PHP、App Engine フレキシブル環境 PHP、Cloud Run、Cloud Run functions に同一文面のセキュリティ注記が掲載されました。

"All supported versions of PHP 8.2 and later are patched. Take immediate protective action by redeploying your resources with updated dependencies."

2️⃣ 一律の即時アクション: 再デプロイ

訂正版では「自動適用済みのためアクション不要」という区分がなくなり、すべてのユーザーに更新された依存関係での再デプロイが指示されています。10/21 の注記に従って「対応不要」と判断していた場合も、改めて再デプロイを実施すべきです。

3️⃣ PHP 8.1 以前はパッチ対象外 (変更なし)

セキュリティブログの案内どおり、PHP 8.1 以前は EOL のため修正版が提供されません。該当バージョンの利用者は PHP 8.2 以降へアップグレードしたうえで再デプロイが必要です。

ステップ 1: App Engine (スタンダード / フレキシブル環境) — 再デプロイ

Bash 
# 依存関係を更新したうえでソースから再デプロイ
gcloud app deploy

フレキシブル環境でカスタムランタイムを利用している場合は、イメージ内の PHP 依存関係を更新してから再デプロイします。

ステップ 2: Cloud Run — 再デプロイ

Bash 
# ソースからサービスを再デプロイ (パッチ済みランタイムでビルドされる)
gcloud run deploy SERVICE --source .

ステップ 3: Cloud Run functions — 再デプロイ

Bash 
# 関数を再デプロイ
gcloud run deploy FUNCTION --source . --function FUNCTION_ENTRYPOINT

⚠️ デメリット・制約事項

🚧 制限事項

✗PHP 8.1 以前のランタイムには修正版が提供されない (EOL)。PHP 8.2 以降へのアップグレードが必須
✗再デプロイはユーザー自身が実施する必要があり、実施するまでワークロードは保護されない可能性がある
✗自前でビルドしたコンテナイメージ (GKE 上の PHP コンテナなどを含む) の再ビルド・再デプロイはユーザーの責任で行う必要がある

🤔 考慮すべき点

⚠️ 重要: 10/21 の注記に基づいて「対応不要」と判断した場合も、訂正版に従って再デプロイを実施すること。 App Engine スタンダード環境や自動ベースイメージ更新が有効な Cloud Run / Cloud Run functions も、訂正版では一律に再デプロイが指示されています。
→Cloud Armor のマネージドルール (File Upload / RFI カテゴリの有効化、巨大なリクエストボディのブロック) は緩和策として有効だが、パッチ適用 (再デプロイ) の代替にはならない
→影響範囲の確認には On-Demand Scanning API / Artifact Analysis によるイメージスキャンや Security Command Center の脅威検出が活用できる

効果: 各サービスを依存関係更新のうえ再デプロイすることで、すべてのサービスがパッチ済みランタイムに切り替わる。CI/CD パイプラインからの一括再実行でも対応できる。
