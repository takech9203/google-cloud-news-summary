Knowledge Catalog Preview (Gated)

🧠 Knowledge Studio 登場

メタデータカタログが AI エージェントを支える「アクティブなコンテキストエンジン」へ
📅 リリース日: 2026-11-02
☁️ Google Cloud リリースノート

📌 概要

Knowledge Catalog (旧 Dataplex Universal Catalog) に Knowledge Studio が Preview として登場。 メタデータを「受動的なカタログ」からアクティブなコンテキストエンジンへと変革し、 生成 AI アプリケーションの信頼性向上を実現する機能群です。

🕸️ コンテキストグラフ
自然言語でデータ探索
+
⚙️ エンリッチメントタスク
メタデータ自動生成
+
📦 コンテキストセット
ドメイン知識をパッケージ化
→
🤖 AI エージェント
MCP / API でグラウンディング

対象ユーザーはデータアーキテクト、ガバナンスリード、AI エンジニアなど。BigQuery の会話型分析や Gemini などの AI エージェントにおけるハルシネーション抑止を、ビジネスコンテキストによるグラウンディングで実現します。

❌ Before: 静的なカタログの限界

  • 静的なスキーマ・説明文の保管庫であり、テーブル間の結合条件、ビジネス指標の定義、用語集とストレージのマッピングといった深いセマンティック関係を提供できない
  • ビジネスルールやパイプラインの背景知識が Confluence や Jira に散在し、スキーマの進化に伴いカタログのドキュメントが陳腐化
  • AI エージェントへのスキーマ提供はプロンプトスタッフィングやハードコーディング頼みで、ハルシネーションとトークン消費が増大

✅ After: 常時稼働のコンテキストエンジン

  • 自然言語チャットとコンテキストグラフで、データアセットとビジネスセマンティクス (用語集、KPI 定義、データプロダクト) を同一キャンバス上で視覚的に探索
  • スキーマ、クエリログ、社内ドキュメント (SOP、Wiki) からメタデータ更新案を自動生成し、人間のレビューを経てカタログへ反映 (信頼度しきい値による自動公開も可能)
  • キュレーション済み知識をコンテキストセット化し、MCP / Knowledge Catalog API 経由で AI エージェントに動的提供。ハルシネーションとトークン消費を低減
⚠️ Gated Preview: コンテキストグラフの表示、コンテキストセットの作成、エンリッチメントワークフローの実行には組織単位での利用申請が必要です。

エンリッチメントタスクがスキーマ・クエリログ・企業内ナレッジからメタデータ提案を生成し、 データスチュワードのレビュー (または信頼度に基づく自動公開) を経てコンテキストセットに反映。 AI エージェントは MCP または Knowledge Catalog API 経由でこのキュレーション済みコンテキストを取得してグラウンディングされます。

🚀 主要機能

1️⃣ 自然言語探索とコンテキストグラフ (New chat)

→会話型チャット + インタラクティブなコンテキストグラフで、自然言語でのデータ検出・調査・セマンティッククエリ検証が可能
→データアセット (BigQuery テーブル/ビュー、レイクハウス) とビジネスセマンティクス (用語集、指標の計算式、データプロダクト) を同一キャンバスのノードとして統合
→エッジ (エントリリンク) として「スキーマ結合 (BigQuery ジョブの自動スキャン)」「定義 (カラムと用語集のマッピング)」「コンテキスト (ドキュメント紐付け)」「パッケージ (データプロダクト集約)」を可視化
→データリネージが「物理的な流れと変換」を追跡するのに対し、コンテキストグラフは「ビジネス上の意味と概念的な関係」をモデル化

2️⃣ エンリッチメントタスク (Enrichments)

→対象コンテキストセット、入力ソース、評価ベンチマークを定義する永続的な構成。オンデマンドまたは定期スケジュールで実行
→「シグナル・ドキュメント分析 → コンテキスト提案のドラフト → ベンチマークと最適化 → レビューポリシー適用」の 4 フェーズでキュレーション
→評価セット (Cloud Storage 上の JSONL: 自然言語質問とゴールデン SQL のペア) による回帰テストと信頼度スコアに基づく自動公開のしきい値制御
→自己学習 (Self-learning) で Gemini Enterprise の会話トレースや BigQuery のエージェント分析テーブルから知識ギャップを検出し継続更新

3️⃣ コンテキストセット (Context sets)

→セマンティック情報とデータアセット参照を格納する境界付きコンテナ。type="context-set" の特殊なエントリグループとして実装
→エージェントのカタログ全体検索を防ぐ密閉的 (hermetic) な実行境界を確立し、ハルシネーションとトークン消費を低減
→データプロダクトが「具体的なリソースとデータプレーンのアクセス制御」を管理するのに対し、コンテキストセットは「概念、クエリテンプレート、ドキュメントなどの会話的セマンティクス」をバンドル (データアクセス権は付与しない)

4️⃣ MCP / API によるエージェントのグラウンディング

→リモート MCP サーバー (https://dataplex.googleapis.com/mcp) または Knowledge Catalog API で、認定済みビジネスコンテキストとサンプルクエリを推論時に動的取得
→LookupContext API により、LLM プロンプトに直接注入可能なトークン量を考慮した YAML / JSON 形式の整形済みコンテキストを取得
→セマンティック検索による動的検出と、コンテキストセットのリソース URI を事前指定する決定論的グラウンディングの 2 つの消費パターンをサポート

ステップ 1: 外部ナレッジのリンクとエンリッチメントタスクの作成

Google Cloud コンソールの Knowledge Studio から、Google Drive や外部 Git リポジトリの読み取りを承認し、 コンテキストセット、対象リソース、ナレッジシグナル、評価戦略を定義してタスクを作成します。 評価セットは以下の形式の JSONL ファイルを Cloud Storage に配置します。

JSONL 評価セットの例 (自然言語質問 + ゴールデン SQL) 
{"display_name": "revenue-2026", "evaluation_request": {"prompt": {"text": "What is total revenue for customer C100 in 2026?"}, "golden_response": {"candidate": "golden", "text": "SELECT SUM(amount) FROM `project.dataset.orders` WHERE customer_id = 'C100' AND EXTRACT(YEAR FROM order_date) = 2026;"}}}
⚠️ 注意: Preview 期間中、エンリッチメントタスクの管理はコンソールのみで、公開 REST API や gcloud CLI コマンドは利用できません。

ステップ 2: AI 提案のレビューと承認

エンリッチメントランの実行後、Run Details ページで提案された説明文やエントリリンクの差分を確認し、承認してカタログへ反映します。 自動公開を有効化する場合は、信頼度スコアの下限 (例: 85%) と許容する品質低下幅 (例: -5%) をスライダーで設定します。

ステップ 3: MCP 経由でエージェントを接続

AI アプリケーション (ADK、LangChain、Claude、カスタムエージェントなど) から Knowledge Catalog リモート MCP サーバーに接続します。

Text リモート MCP サーバー接続情報 
Server URL  : https://dataplex.googleapis.com/mcp
Transport   : Streamable HTTP
認証        : OAuth 2.0 + IAM (Google Cloud 認証情報 / エージェント ID)
💡 ローカル開発: MCP Toolbox for Databases をローカルプロキシとして、VS Code や Cursor などの IDE から接続することもできます。

💼 ビジネス面のメリット

✓AI 回答の信頼性向上: 認定済みのビジネス用語定義、KPI 計算式、検証済み結合条件でグラウンディングし、会話型分析のハルシネーション (誤った結合キーや指標の取り違え) を抑止
✓メタデータ運用コストの削減: Confluence や Jira に散在する業務知識やクエリ履歴から更新案を自動生成し、カタログの陳腐化を防止
✓ガバナンスの能動化: Human-in-the-loop と信頼度ベースの自動公開を組み合わせ、品質を担保しながらスケール

🔧 技術面のメリット

✓トークン効率の向上: 密閉的な境界によりカタログ全体検索を防ぎ、プロンプトへの大量のスキーマ埋め込みが不要に
✓標準プロトコルでの統合: MCP (Streamable HTTP) と LookupContext API で ADK、LangChain、各種 IDE から統一的に取得
✓自己学習による継続的改善: 対話ログと評価ベンチマークに基づき品質が自動改善。下流アプリは再デプロイ不要

✗Gated Preview であり、利用には組織単位での申請と許可が必要
✗エンリッチメントタスクの管理はコンソールのみ (公開 REST API / gcloud CLI 非対応)
✗VPC Service Controls、CMEK、Assured Workloads は未サポート
✗エンリッチメントタスクとタスクランにはプロジェクト・リージョン単位のクォータが適用

🤔 考慮すべき点

→Pre-GA 機能のため「現状有姿 (as is)」で提供され、サポートが限定される可能性 (Pre-GA Offerings Terms が適用)
→自動公開を有効にする場合は評価セットの構成を強く推奨。評価ガードレールなしでは回帰を引き起こすメタデータが自動公開されるリスク
→コンテキストセットはデータアクセス権を付与しない。データプレーンのアクセス制御はデータプロダクトや IAM で別途設計が必要
→コンテキストグラフ (セマンティクス) とデータリネージ (物理的なデータフロー) は役割が異なり、用途に応じた使い分けが必要

🎯 ユースケース

📊 ユースケース 1: BigQuery 会話型分析のグラウンディング

シナリオ: ビジネスアナリストが「前四半期のリージョン別ネットリテンション率は?」と自然言語で質問。キュレーションされたセマンティクスがないと、モデルが結合キーをハルシネーションしたり、総予約額と純収益を取り違えたりする可能性がある。

効果: New chat インターフェースで売上ステージングテーブルと認定済みビジネス用語集の関係を検証。アクティブなコンテキストグラフが会話型分析をグラウンディングし、生成 SQL に検証済みの結合条件と標準 KPI 計算式が含まれるようになる。

📄 ユースケース 2: 社内 SOP からのメタデータエンリッチメント

シナリオ: BigQuery で多数のデータセットを管理する一方、重要なビジネスルールやパイプラインのリネージが Confluence Wiki や Jira チケットに存在し、スキーマの進化とともにカタログのドキュメントが陳腐化。

🤖 ユースケース 3: MCP によるカスタムエージェントへのコンテキスト提供

シナリオ: LangChain や ADK で顧客向けサポート/アドバイザリーエージェントを構築する AI 開発者が、認証情報のハードコーディングや大量のテーブル定義のプロンプト埋め込みなしに、最新のスキーマセマンティクスを必要としている。

効果: キュレーション済みメタデータと検証済み結合グラフをコンテキストセット (例: entryGroups/customer-360) に格納。エージェントは推論時に MCP エンドポイントまたは Catalog API 経由で、ユーザーの意図に関連する認定済みビジネスコンテキストとサンプルクエリを動的に取得できる。

💡 まとめ

Knowledge Studio は、メタデータカタログを AI エージェント時代の「アクティブなコンテキストエンジン」へと進化させる重要なアップデート。 エンタープライズにおける生成 AI のハルシネーション対策とメタデータ運用の自動化を同時に実現します。

BigQuery の会話型分析や ADK/LangChain ベースのエージェントを運用する組織は、Gated Preview への申請を検討し、 まずは Basic 構成のエンリッチメントタスクでメタデータ自動生成の品質を評価することを推奨。 本番適用時には VPC-SC / CMEK 未対応などの Preview 制約に留意が必要です。
