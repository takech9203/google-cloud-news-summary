⏰ Cloud Scheduler: 3 リージョンを追加

Milan (europe-west8) / Paris (europe-west9) / Dallas (us-south1) が利用可能に
Cloud Scheduler GA (一般提供) リージョン拡張
リリース日: 2026-07-29

📌 概要

Google Cloud は、フルマネージド cron ジョブサービス Cloud Scheduler を 新たに 3 つのリージョンで利用可能にしました。Cloud Scheduler のジョブは リージョナルリソース であり、作成時にリージョンを指定する必要があるため、 「どのリージョンで使えるか」はアーキテクチャ設計とコンプライアンス設計の両面で直接的な制約になります。

❌ Before (アップデート前の課題)

  • Milan / Paris / Dallas では Cloud Scheduler ジョブを作成できなかった
  • ターゲット (Cloud Run、Pub/Sub など) と別リージョンにスケジューラーを置く非対称構成が必要だった
  • Resource Locations 組織ポリシーで europe-west8 / west9 のみ許可の環境では、ポリシー例外が必要になるケースがあった
  • 該当ロケーションの App Engine アプリで、App Engine HTTP ターゲットのジョブを作成できなかった

✅ After (アップデート後の改善)

  • 3 リージョンで Cloud Scheduler ジョブを直接作成可能に
  • スケジューラーとターゲットを同一リージョンに揃え、レイテンシと障害面 (failure domain) の分散を削減
  • EU (イタリア・フランス) のデータレジデンシー要件下で EU 内に閉じた運用がしやすく
  • 提供リージョンが合計 30 に拡大 (Americas 10 / Europe 8 / Asia Pacific 9 / Middle East 3)

Cloud Scheduler のジョブはリージョナルリソースであり、HTTP/S・Pub/Sub ターゲットは任意のリージョンから呼び出せますが、 同一プロジェクトの App Engine HTTP ターゲットのみ「プロジェクトの App Engine リージョンと一致するリージョンでしかジョブを作成できない」 という制約があります。Resource Locations 組織ポリシーは Job リソースの作成・更新時に評価されます。

⚙️ サービスアップデートの詳細

🗺️ 1. リージョナルなジョブ配置の選択肢拡大

Job は特定リージョンに作成されるリソースで、作成時に --location (gcloud) / Region (コンソール) を指定します。 今回の追加により、ミラノ・パリ・ダラスをジョブの配置先として選択できるようになりました。

🇪🇺 2. EU データ境界 / データレジデンシーへの適合性

  • Resource Locations 組織ポリシー制約のサポート対象。制約は Job リソースの作成・更新時に適用 (既存リソースには非適用)
  • cloudscheduler.googleapis.com は Assured Workloads の EU Data Boundary 系コントロールパッケージの対象製品
  • europe-west8 / europe-west9 はいずれも Assured Workloads の EU 限定リージョン一覧に含まれる

🎯 3. ターゲットとのリージョン整合

  • HTTP/S エンドポイント・Pub/Sub トピックをターゲットとする場合、サポートされる全リージョンでジョブを作成可能
  • 同一プロジェクトの App Engine アプリをターゲットにする場合は、プロジェクトの App Engine リージョンでしかジョブを作成できない 制約が引き続き適用

🛠️ 設定方法

✅ 前提条件

✓Cloud Scheduler API (cloudscheduler.googleapis.com) が有効化されていること
✓ジョブ作成に必要な IAM ロール (例: roles/cloudscheduler.admin) が付与されていること
✓Pub/Sub ターゲットを使う場合は対象トピックが事前に作成されていること (roles/pubsub.editor など)
✓Resource Locations 組織ポリシーを運用している場合、対象リージョンが許可されていること

ステップ 1: 利用可能なロケーションを確認する

Bashロケーション一覧の確認
gcloud scheduler locations list

新しく追加された europe-west8、europe-west9、us-south1 が一覧に含まれることを確認します。

ステップ 2: 新リージョンにジョブを作成する (HTTP ターゲット)

Bashミラノに HTTP ターゲットのジョブを作成
gcloud scheduler jobs create http nightly-batch-milan \
  --location=europe-west8 \
  --schedule="0 2 * * *" \
  --time-zone="Europe/Rome" \
  --uri="https://batch-api.example.com/run" \
  --http-method=POST \
  --message-body='{"mode":"nightly"}' \
  --headers="Content-Type=application/json"
⚠️ タイムゾーン: --time-zone は tz database のタイムゾーン名を指定します。 夏時間の切り替えによりジョブが想定外のタイミングで実行される、または実行されない場合があるため注意してください。

ステップ 3: Pub/Sub ターゲットのジョブを作成する (パリ)

Bashパリに Pub/Sub ターゲットのジョブを作成
gcloud scheduler jobs create pubsub hourly-refresh-paris \
  --location=europe-west9 \
  --schedule="0 * * * *" \
  --time-zone="Europe/Paris" \
  --topic=cache-refresh-topic \
  --message-body="refresh"

Pub/Sub ターゲットの場合、Cloud Scheduler は Google APIs サービスアカウントとしてトピックにメッセージをパブリッシュします。

ステップ 4: 作成結果を確認する

Bashジョブの一覧・詳細確認
gcloud scheduler jobs list --location=europe-west9
gcloud scheduler jobs describe hourly-refresh-paris --location=europe-west9

💪 メリット

💼 ビジネス面

  • EU データレジデンシー要件への対応強化: イタリア・フランス国内リージョンでスケジューリング基盤を運用でき、EU 内のデータロケーション統制を取りやすい
  • 組織ポリシー例外の削減: EU 限定リージョンのみ許可の環境でも例外扱いせず導入しやすい
  • サステナビリティ: europe-west9 と us-south1 は Low CO2 リージョン

🔧 技術面

  • レイテンシ削減: ターゲットと同一リージョン配置でリージョン間ホップが不要に
  • 障害面の整合: スタックとスケジューラーを揃え、リージョン障害時の挙動を推論しやすい
  • App Engine 併用シナリオの解消: 該当ロケーションで App Engine HTTP ターゲットのジョブ作成が可能に
  • リージョナルなジョブ分散: リージョンごとに 5,000 ジョブのクォータを個別に利用可能

⚠️ デメリット・制約事項

🚧 制限事項

✗提供は 30 リージョンにとどまり、すべての Google Cloud リージョン (例: europe-west10、europe-west12) では利用不可
✗同一プロジェクトの App Engine ターゲットはプロジェクトの App Engine リージョンにのみ作成可能 (App Engine のリージョンは変更不可)
✗Resource Locations 制約は Job の作成・更新時にのみ適用され、既存リソースには遡って適用されない
✗HTTP ターゲットの実行時間上限は 30 分 (変更申請不可のシステム上限)
✗ジョブペイロードは合計 1 MB まで (約 1 KB のリクエストオーバーヘッドを含む)
✗at-least-once 配信のため、まれに複数回実行される可能性がある。ハンドラーは冪等でなければならない
✗HTTP ターゲットは公開アクセス可能なエンドポイントが必要 (Cloud Run などの内部呼び出しや VPC Service Controls 対応は別途の機能)

🤔 考慮すべき点

  • 既存ジョブの移設はマイグレーション作業: 既存ジョブは自動移動しない。新リージョンで作成し旧リージョンのジョブを削除する (重複実行を避けるため旧ジョブの一時停止を検討)
  • 課金は一時的に二重になり得る: 一時停止中のジョブも 1 ジョブとして課金対象。移行期間中は新旧両方が課金される
  • タイムゾーン設計: リージョンを EU に移してもタイムゾーンは --time-zone の設定に依存。別物として扱う
  • クォータはリージョン単位: ジョブ数クォータ (5,000) はリージョンごと、API リクエストクォータはプロジェクト単位で共有
  • 無料枠は請求先アカウント単位: リージョン分散でジョブ数が増えると、無料枠 (3 ジョブ) 超過分がそのまま課金される

💡 ユースケース

🇮🇹 1. EU データレジデンシー要件下でのバッチスケジューリング (イタリア)

イタリアの規制対象顧客データを扱うアプリを europe-west8 (Milan) に構築し、Resource Locations 組織ポリシーで EU 限定リージョンのみを許可。これまでは europe-west8 で Cloud Scheduler ジョブを作成できなかった。

BashEU リージョンに OIDC 認証付きジョブを作成
# 組織ポリシーで許可された EU リージョンにジョブを作成
gcloud scheduler jobs create http eu-nightly-reconciliation \
  --location=europe-west8 \
  --schedule="30 1 * * *" \
  --time-zone="Europe/Rome" \
  --uri="https://reconciliation-svc-xxxxx.europe-west8.run.app/execute" \
  --http-method=POST \
  --oidc-service-account-email=scheduler-invoker@PROJECT_ID.iam.gserviceaccount.com
✅ 効果: スケジューラー・ターゲットの両方を EU 内 (イタリア) に閉じて配置でき、組織ポリシーの例外設定が不要に。リージョン間ホップも解消。

🇫🇷 2. フランス国内サービスのキャッシュリフレッシュ (パリ)

フランス向け SaaS を europe-west9 (Paris) にデプロイ。10 分ごとのキャッシュ更新を Pub/Sub 経由でトリガーしたいが、 これまでは近隣リージョン (europe-west1 など) にスケジューラーを置く必要があり、リージョンが分離していた。

Bashパリに 10 分間隔の Pub/Sub ジョブを作成
gcloud scheduler jobs create pubsub fr-cache-refresh \
  --location=europe-west9 \
  --schedule="*/10 * * * *" \
  --time-zone="Europe/Paris" \
  --topic=cache-refresh \
  --message-body="refresh-all"
✅ 効果: パリリージョン内でスケジューリングと Pub/Sub 配信を完結。europe-west9 は Low CO2 リージョンでもあり、サステナビリティ目標にも合致。

🇺🇸 3. 米国中南部ワークロードのリージョン整合 (ダラス)

テキサス州近郊のユーザー向けに us-south1 (Dallas) へワークロードを配置しているが、Cloud Scheduler だけは us-central1 に置いており、リージョン障害時の影響範囲が 2 リージョンにまたがっていた。

✅ 効果: us-south1 にジョブを移設し、アプリケーションスタックとスケジューラーの障害面を単一リージョンに整合。us-south1 も Low CO2 リージョン。

💰 料金

Cloud Scheduler の料金は ジョブ (job) の数のみ に基づきます。 ジョブとは「定義された頻度で実行される 1 つのアクティビティ」であり、実行 (execution) 単位では課金されません。

ジョブ / 31 日 (1 日 $0.003)

月あたり無料 (請求先アカウント単位)
同一単価
新 3 リージョンでも料金差なし
  • 課金対象使用量は 日単位 で計算。例: ジョブを 1 件作成し 10 日後に削除 → $0.10 ÷ 31 × 10 = 約 $0.03
  • 一時停止 (paused) 中のジョブも 1 ジョブとしてカウントされ課金対象
  • 無料枠は プロジェクト単位ではなく請求先アカウント単位。例: 5 プロジェクト × 2 ジョブ (計 10 ジョブ) の場合、3 ジョブ無料 + 7 ジョブ課金

🌐 利用可能リージョン

今回の追加により、Cloud Scheduler は合計 30 リージョン (Americas 10 / Europe 8 / Asia Pacific 9 / Middle East 3) で利用可能になりました。

📈 継続的なリージョン拡張: 直近では 2026 年 4 月 17 日に europe-west4 (Eemshaven, Netherlands)、me-central1 (Doha, Qatar)、 me-central2 (Dammam, Saudi Arabia)、me-west1 (Tel Aviv, Israel) が追加されており、 Cloud Scheduler のリージョン拡張が継続的に進んでいます。

📝 まとめ

  • Cloud Scheduler が europe-west8 (Milan)、europe-west9 (Paris)、us-south1 (Dallas) に対応し、提供リージョンは 30 に拡大
  • ジョブはリージョナルリソースのため、イタリア・フランスの データレジデンシー要件 を満たす組織や Dallas にワークロードを持つ組織は、スケジューラーをターゲットと 同一リージョンへ寄せる設計 が可能に

  • 一時停止中のジョブも課金対象 ($0.10/ジョブ/31 日、請求先アカウントあたり月 3 ジョブ無料) である点に注意
