Knowledge Catalog Preview SQL Server PostgreSQL

🔍 概要

Google Cloud の Knowledge Catalog (旧 Dataplex Universal Catalog) に、SQL Server および PostgreSQL データソースからメタデータを自動インポートするプリビルトコネクタが Preview として追加されました。

BigQuery Data Transfer Service を活用し、外部データソースから技術メタデータ、運用メタデータ、ビジネスメタデータを自動抽出して Knowledge Catalog のエントリグループにインポートします。

💡 ポイント: Oracle、MySQL (2026年6月22日) と合わせて、4 大 RDBMS からのメタデータ統合が実現。エンタープライズ環境のデータガバナンス一元管理が大幅に容易になります。

Step 1: コネクタの作成

→Knowledge Catalog ページ → 「管理」→「コネクタ」→「接続を追加」
→コネクタリストから「SQL Server」または「PostgreSQL」を選択

Step 2: データソースの設定

→Network Attachment (必要に応じて)
→Host / Port / Database name / Username / Password
→TLS Mode / Trusted PEM Certificate (TLS 使用時)
→インポート対象のメタデータオブジェクトを選択

Step 3: 宛先の設定

→既存の Knowledge Catalog エントリグループを選択 or 新規作成
→エントリグループに対する権限を設定 (推奨)

Step 4: スケジュールの設定

→メタデータインポートジョブの実行頻度を設定
→「On-demand」選択で手動トリガー時のみ実行

Step 5: オプション設定

→通知: メールまたは Pub/Sub によるジョブ失敗通知
→暗号化: CMEK による一時データの暗号化

✅ メリット

ビジネス面

✓データガバナンスの統一: SQL Server や PostgreSQL に分散するメタデータを Knowledge Catalog で一元管理し、組織全体のデータ可視性を向上
✓コンプライアンス対応の簡素化: データ資産の所在とオーナーシップを自動的にカタログ化し、監査対応やデータリネージの追跡が容易に
✓データ民主化の促進: Knowledge Catalog のセマンティック検索を通じて、ビジネスユーザーがデータ資産を発見・理解しやすくなる

技術面

✓運用負荷の削減: カスタムコネクタ開発やパイプライン管理が不要に。コンソール操作のみでメタデータ同期を実現
✓自動同期による一貫性確保: スケジュールベースのフルオーバーライトにより、カタログとソースシステムの乖離を防止
✓パートナーエコシステム連携: Collibra、Atlan、Datahub などサードパーティガバナンスツールとの統合が可能

⚠️ デメリット・制約事項

⚠️ 制限事項:
  • Preview ステータスのため SLA 適用外 - 本番環境での使用には注意
  • 各実行時にフルオーバーライト (完全上書き) - 差分のみの更新 (インクリメンタル同期) には非対応
  • コネクタが管理するエントリグループ内のエントリのみが上書き対象 (手動追加したエントリには影響なし)

考慮すべき点

!Network Attachment によるプライベートネットワーク接続の設定が必要になる場合あり
!サービスエージェントに適切な権限付与が必要
!ジョブ実行履歴は 90 日間で自動削除
!CMEK は一時データの暗号化のみ (宛先エントリグループ内メタデータの暗号化には使用されない)
!Preview 期間中のサポートは dataplex-discuss@google.com へのメール連絡

🎯 ユースケース

🏢 ユースケース 1: ハイブリッドクラウド環境のメタデータ統合

シナリオ: オンプレミスの SQL Server と Cloud SQL for PostgreSQL の両方にデータを保持し、データ資産の全体像を把握したい場合

効果: 両データソースのメタデータを Knowledge Catalog に自動インポートし、オンプレミスとクラウドにまたがるデータ資産カタログを一元的に検索・閲覧可能に。データスチュワードの管理工数を削減。

🚚 ユースケース 2: データマイグレーション計画の策定

シナリオ: レガシーの SQL Server DB を Google Cloud に移行する計画があり、移行対象のテーブル・ビューの全体像を事前に把握する必要がある場合

効果: コネクタで SQL Server のメタデータを Knowledge Catalog にインポートし、テーブル定義やスキーマ構造を可視化。移行計画の精度向上とスコープ定義の明確化に貢献。

🤖 ユースケース 3: AI エージェントへのデータコンテキスト提供

シナリオ: AI エージェントがデータ分析タスクを実行する際に、利用可能なデータ資産とその意味を理解する必要がある場合

効果: Knowledge Catalog の lookupContext API と組み合わせ、SQL Server / PostgreSQL 上のデータ資産コンテキストを AI エージェントに提供。より適切なデータ利活用を実現。
