フォルダ・プロジェクトレベルでのイシュー表示

リリース日: 2026-10-19
🔒 Security Command Center Preview Issues Correlated Threats セキュリティグラフ

📌 概要

Security Command Center で、Correlated Threats ルールおよびセキュリティグラフルールによって作成されたイシュー (Issues) を、組織レベルだけでなくフォルダ・プロジェクトレベルで表示できるようになりました (Preview)。

イシューは Security Command Center が検出した最も重要なセキュリティリスクを集約する仕組みです。Google Cloud コンソールのスコープピッカーでフォルダやプロジェクトを選択すると、そのスコープ内のリソースを主リソースとするイシューのみを絞り込んで調査できます。さらに Issues ページでは、すべてのイシューをサービスタイプ・プロジェクト番号・フォルダ ID でフィルタリング可能になりました。

❌ Before (アップデート前の課題)

  • イシューは組織レベルでのみ表示・調査が必要で、フォルダ・プロジェクト所管チームが自分たちの範囲のイシューだけを確認できなかった
  • 組織レベルの閲覧権限を持たないプロジェクトチームは、自プロジェクトに影響するイシューを直接確認する手段が限られていた
  • 多数のプロジェクトを持つ組織では、担当範囲のイシュー特定に手動での確認が必要だった

✅ After (アップデート後の改善)

  • Correlated Threats・セキュリティグラフルールのイシューを組織・フォルダ・プロジェクトの各レベルで表示可能に
  • サービスタイプ、プロジェクト番号、フォルダ ID でのフィルタリングに対応
  • スコープ属性ルールにより、イシューが正しいフォルダ・プロジェクトに帰属
  • フォルダ・プロジェクトレベルの IAM ロールだけで自スコープのイシューを調査可能 (スコープ外リソースの詳細は権限がなければ非表示)

イシューの生成元 (Correlated Threats、セキュリティグラフルール、Risk Engine) と、リソース階層の各レベルでの表示可否を示しています。Correlated Threats とセキュリティグラフルールによるイシューは組織・フォルダ・プロジェクトの各レベルで表示できますが、Risk Engine による有害な組み合わせ・チョークポイントのイシューは引き続き組織レベルでのみ表示されます。

⚙️ 主要機能

1️⃣ フォルダ・プロジェクトレベルでのイシュー表示 (Scoped Issues)

→コンソールのスコープピッカーで組織・フォルダ・プロジェクトを選択し、そのスコープのイシューに絞り込み表示
→フォルダ選択時は、サブフォルダを含む配下リソースに影響するイシュー (Correlated Threats・セキュリティグラフルール起源) を表示
→Overview ページ (All Risk / AI Security ダッシュボード) と Issues ページの両方でスコープ選択に対応

2️⃣ Issues ページのフィルタリング強化

→すべてのイシューをサービスタイプ・プロジェクト番号・フォルダ ID でフィルタリング可能
→既存のフィルタ (アプリケーション、リソースタイプ、ドメインなど) と組み合わせて絞り込みできる

3️⃣ スコープ属性ルール (Scope Attribution Rules)

→各ルールがイシューの主リソース (primary resource) を特定し、主リソースが選択スコープ内にある場合にイシューが帰属
→セキュリティ条件が選択スコープ外のリソースにあっても、正しいスコープに帰属されるよう設計

4️⃣ スコープに応じたアクセス制御

→イシューと関連リソース情報の閲覧には、各レベルで必要な IAM ロールが必要
→スコープ外リソースの閲覧権限がない場合、イシューのカテゴリのみ表示され、リソース詳細は非表示 (セカンダリリソースも同様に秘匿)

🛠️ 設定方法

✅ 前提条件

✓Security Command Center が組織レベルで有効化されていること (イシューは組織レベル有効化時のみ生成される)
✓表示したいスコープ (組織・フォルダ・プロジェクト) に対する必要な IAM ロールを持っていること

📝 手順

1Issues ページでスコープを選択する

  • Google Cloud コンソールで Security Command Center の Issues ページに移動
  • コンソールのスコープピッカー (purview picker) で、組織・フォルダ・プロジェクトのいずれかを選択
  • 組織スコープ: すべての生成元のイシューが表示される
  • フォルダ / プロジェクトスコープ: 主リソースがそのスコープ内にある、セキュリティグラフルール・Correlated Threats 起源のイシューのみ表示される

2フィルタで絞り込む

  • アプリケーションで絞り込む場合は Application を選択し、Select app メニューからアプリケーションを選択
  • その他の属性 (サービスタイプ、プロジェクト番号、フォルダ ID、リソースタイプなど) は Add filter から条件を選択
  • 検出グループを展開して個々のイシューをクリックすると、概要、攻撃パス / エビデンス図、関連する検出結果、修復手順 (How to fix)、JSON データなどの詳細パネルが表示される

💡 メリット

💼 ビジネス面

✓責任範囲に応じたリスク管理: フォルダ・プロジェクト単位で部門やチームにセキュリティ運用を委譲している組織で、各チームが自分たちの責任範囲のイシューに集中できる
✓最小権限の原則との両立: 組織全体の閲覧権限を付与することなく、フォルダ・プロジェクトレベルの IAM ロールだけで担当範囲のイシュー調査が可能

⚙️ 技術面

✓スコープ属性の正確性: セキュリティ条件がスコープ外のリソースにあっても、主リソースに基づいてイシューが正しいフォルダ・プロジェクトに帰属される
✓フィルタリングの柔軟性: サービスタイプ・プロジェクト番号・フォルダ ID によるフィルタで、大規模環境でも目的のイシューへ素早く到達できる
✓権限に応じた情報開示: スコープ外リソースの詳細は権限がなければ自動的に秘匿され、情報漏洩リスクを抑えつつイシューのカテゴリは把握できる

⚠️ デメリット・制約事項

🚧 制限事項

•本機能は Preview であり、Pre-GA Offerings Terms が適用される (サポートが限定される可能性)
•イシューは Security Command Center が組織レベルで有効化されている場合のみ生成される (プロジェクトレベル有効化では利用不可)
•Risk Engine が作成する有害な組み合わせ (toxic combinations) およびチョークポイントのイシューは、引き続き組織レベルでのみ表示可能
•Correlated Threats のイシューは最初の脅威検出から 14 日間でアクティブ期間が終了し、この期間は変更できない

🤔 考慮すべき点

→フォルダ・プロジェクトレベルで表示されるのは、主リソースがそのスコープ内にあるイシューのみ。組織全体のリスク (有害な組み合わせ・チョークポイントを含む) の把握には組織レベルでの確認が引き続き必要
→スコープ外のセカンダリリソースの詳細確認には、該当プロジェクト・フォルダへの IAM 権限が別途必要
→Enterprise サービスティアは 2027 年 5 月 21 日に廃止され Premium ティアへ自動移行予定のため、ティア構成の確認を推奨

🎯 ユースケース

📦 ユースケース 1: プロジェクトチームによる自律的な脅威対応

シナリオ: 大規模組織で、各アプリケーションチームが自分たちのプロジェクトのセキュリティ対応に責任を持つ運用モデルを採用。従来はイシューが組織レベルでしか確認できず、中央セキュリティチームからの連絡を待って対応していた。

実装例 プロジェクトチームの運用フロー 
1. アプリケーションチームにプロジェクトレベルの必要な IAM ロールを付与
2. チームメンバーがコンソールのスコープピッカーで自プロジェクトを選択
3. Issues ページで自プロジェクトを主リソースとする Correlated Threats /
   セキュリティグラフルールのイシューを確認
4. How to fix タブの修復手順に沿って対応
✨ 効果: 中央チームを経由せずにプロジェクトチームが直接イシューを検知・対応でき、脅威への初動が高速化される。

📁 ユースケース 2: フォルダ単位での部門別リスクレビュー

シナリオ: 事業部ごとにフォルダを分けてリソースを管理している企業で、各事業部のセキュリティ担当者が月次でリスクレビューを実施する。

✨ 効果: スコープピッカーで事業部フォルダを選択するだけで、サブフォルダを含む配下リソースのイシューを一覧でき、サービスタイプやプロジェクト番号でのフィルタにより、レビュー対象の整理と優先順位付けが容易になる。

🔗 関連サービス・機能

🔗 Correlated Threats セキュリティグラフに対する事前定義クエリで関連する脅威検出結果を相関させ、イシューとして集約 (Preview)。MITRE ATT&CK にマッピングされた攻撃チェーンの可視化を提供
🕸️ セキュリティグラフ / 事前定義セキュリティグラフルール リソース・ID・アプリケーション・データをノード、リスク関係をエッジとして表現するグラフデータベース。パターン検出によりイシューを生成
⚠️ Risk Engine (有害な組み合わせ・チョークポイント) 複数のリスクが組み合わさって高価値リソースへの攻撃経路を形成するパターンを検出。これらのイシューは組織レベルでのみ表示可能
🚨 Event / Container / VM Threat Detection Correlated Threats が相関させる脅威検出結果の供給元となる脅威検出サービス群
📱 App Hub Issues ページ・Overview ページでアプリケーション単位のフィルタリングに利用可能
🔑 IAM スコープごとのイシュー閲覧に必要なロールを管理。権限のないリソースの詳細は自動的に秘匿される

📝 まとめ

Security Command Center のイシューを組織レベルだけでなくフォルダ・プロジェクトレベルで表示・フィルタリングできるようになり、分散型のセキュリティ運用モデルを採用する組織での活用範囲が大きく広がりました。

フォルダ・プロジェクト単位でセキュリティ責任を委譲している組織は、各チームへの適切な IAM ロール付与とあわせて本 Preview 機能の検証開始を推奨します。

⚠️ なお、有害な組み合わせ・チョークポイントの確認には引き続き組織レベルのビューが必要な点に留意してください。
