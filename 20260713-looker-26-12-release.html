📊 Looker 26.12 リリースチャネル展開開始

Looker (Google Cloud core) Deployment
2026-07-13

📋 概要

Looker (Google Cloud core) のリリースチャネルに最新バージョン Looker 26.12 の展開が開始されました。リリースチャネルは、インスタンスに新機能やアップデートが適用されるタイミングを細かく制御するための仕組みです。

Before (従来)

全インスタンスに一律のタイミングでアップデートが適用され、本番環境での事前検証が困難

After (リリースチャネル)

Rapid/Regular/No Channel を選択し、ステージングで先行検証してから本番適用が可能

💡 バージョン番号の読み方: X.Y.Z 形式で X=年の下2桁、Y=月次バージョン (1月=0、以降偶数で増加)、Z=パッチ。26.12 = 2026年7月、26.10 = 2026年6月に対応します。

🔄 リリースチャネル詳細

🚀 Rapid チャネル

  • 新機能や改善への最速アクセスを提供
  • 非本番環境、ステージング、テストインスタンスに推奨
  • 毎月新しい Looker バージョンを受け取り
  • セキュリティアップデートは利用可能になり次第適用
  • メンテナンスウィンドウ / 拒否期間の設定不可
  • SLA 対象外

✅ Regular チャネル

  • バランスの取れた安定性を提供 (月次アップデート)
  • 本番環境に推奨されるチャネル
  • Rapid チャネルの1ヶ月後にバージョンを受信
  • メンテナンスウィンドウ / 拒否期間の設定が可能
  • 標準 SLA の対象
  • ASP フラグによる緊急セキュリティパッチの即時適用が可能

📌 No Channel オプション

  • 従来の Looker (Google Cloud core) リリースプロセスを維持
  • リリースチャネルプレビュー期間中のデフォルト設定
  • 毎月新しいバージョンをバイナリおよびパッチロールアウトで受信
  • メンテナンスウィンドウ / 拒否期間の設定が可能
  • 標準 SLA の対象

⚙️ 設定方法

ステップ 1: リリースチャネルの確認

Bash 
gcloud looker instances describe INSTANCE_NAME \
  --region=REGION \
  --format config

このコマンドで RELEASE_CHANNEL フィールドと VERSION フィールドが返されます。

ステップ 2: リリースチャネルの変更

Google Cloud コンソールからインスタンスの設定を編集するか、gcloud CLI の --release-channel= フラグを使用してチャネルを変更できます。

ステップ 3: ASP の有効化 (Regular チャネルのみ)

Bash 
gcloud looker instances update INSTANCE_NAME \
  --region=REGION \
  --accelerated-security-patch-enabled

✅ メリット

💼 ビジネス面

  • リスク軽減: Rapid でテスト検証後、Regular で本番適用
  • 予測可能なアップデート管理: メンテナンスウィンドウでビジネス影響を最小化

🔧 技術面

  • セキュリティ強化: ASP フラグで重要パッチを即時適用
  • 段階的検証: 1ヶ月先行してバージョン検証、LookML 互換性確認

⚠️ デメリット・制約事項

制限事項:
  • リリースチャネル機能はプレビュー段階であり、「Pre-GA Offerings Terms」が適用
  • Rapid チャネルのバージョンは Looker (Google Cloud core) SLA の対象外
  • Rapid チャネルではメンテナンスウィンドウ / 拒否期間を設定不可
考慮すべき点:
  • Rapid から Regular への切り替え時、最大2ヶ月の遅延が発生する可能性
  • Regular への登録時、現在のバージョンから月次ケイデンスに揃えるまで一時的遅延が発生

🔐 ユースケース 2: セキュリティ重視の本番環境

シナリオ: 金融機関や医療機関など、セキュリティパッチの即時適用が求められるが、機能アップデートは安定性を重視したい場合

実装: Regular チャネル + ASP (Accelerated Security Patching) フラグを有効化

効果: 通常の機能アップデートは予測可能な月次ケイデンスで適用されつつ、重要なセキュリティ修正は利用可能になり次第即座に適用。
