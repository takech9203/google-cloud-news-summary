📋 概要

Apigee API hub が読み取り専用 API を Model Context Protocol (MCP) ツールとして公開する機能が Public Preview としてリリースされました。AI エージェントが標準的な MCP の tools/list および tools/call メソッドを使用して、API hub に登録されたリソースを自律的に探索できるようになります。

🤖 AI + API 管理の統合: AI エージェントが組織内の API カタログを自律的に探索し、必要な API を発見・理解するための標準インターフェースを提供。API ファーストと AI ファーストのアプローチを統合する基盤です。

⚡ 主要機能

📡 MCP ツール一覧の公開

apihub.googleapis.com MCP サーバーが 16 種類の読み取り専用ツールを提供。tools/list メソッドで利用可能な全ツールとスキーマを取得可能。JSON-RPC 2.0 プロトコルに準拠。

🔍 API リソースの検索・取得

search_resources でセマンティック検索、list_apis / get_api で API リソースの一覧取得・詳細取得が可能。

📄 スペックとデプロイメントの参照

list_specs / get_spec / get_spec_contents で API スペックを取得。list_deployments / get_deployment でデプロイメント情報を参照。

🔗 メタデータと依存関係の参照

list_attributes / get_attribute でカスタム属性を取得。list_dependencies / get_dependency で API 間の依存関係情報を参照。

⚙️ 設定方法

前提条件

✓Apigee API hub インスタンスがプロビジョニング済み
✓API hub がサポートリージョンにデプロイ済み
✓適切な IAM 権限が設定済み

Step 1: MCP ツール一覧の取得

Bash tools/list メソッド呼び出し 
curl --location 'https://apihub.REGION.rep.googleapis.com/mcp' \
  --header 'content-type: application/json' \
  --header 'accept: application/json, text/event-stream' \
  --header 'Authorization: Bearer $(gcloud auth print-access-token)' \
  --data '{
    "method": "tools/list",
    "jsonrpc": "2.0",
    "id": 1
  }'

Step 2: MCP ツールの呼び出し

Bash tools/call メソッド呼び出し (list_apis) 
curl --location 'https://apihub.us-east1.rep.googleapis.com/mcp' \
  --header 'content-type: application/json' \
  --header 'accept: application/json, text/event-stream' \
  --header 'Authorization: Bearer $(gcloud auth print-access-token)' \
  --data '{
    "method": "tools/call",
    "jsonrpc": "2.0",
    "id": 2,
    "params": {
      "name": "list_apis",
      "arguments": {
        "project": "YOUR_PROJECT_ID",
        "location": "us-east1"
      }
    }
  }'

✅ メリット

ビジネス面

📈API 資産の活用促進 - AI エージェントが API を自動発見し、既存 API の再利用率が向上。重複開発を防止。
🚀エージェント型 AI の迅速な構築 - 標準プロトコルによる API 発見で AI エージェントの開発期間を短縮。
🔒API ガバナンスの強化 - API hub 経由の一元管理で可視性とコントロールを維持。

技術面

🔧標準プロトコル準拠 - MCP 対応の任意の AI フレームワークやツールと互換性あり。
🛡️読み取り専用の安全性 - 意図しない変更リスクなくエージェントに API 探索権限を付与可能。
🔍セマンティック検索 - 自然言語クエリによる API 検索で、適切な API を効率的に発見。

⚠️ 制約事項・考慮点

制限事項
  • グローバルエンドポイント (apihub.googleapis.com) は MCP リクエストに非対応。リージョナルエンドポイントの使用が必須
  • 読み取り専用ツールのみ提供。API の作成・更新・削除は MCP 経由では不可
  • MCP 依存関係分析 (Dependency analysis) は現時点で MCP ツールに対して非対応
考慮すべき点
  • Public Preview 段階のため、GA までに仕様が変更される可能性あり
  • リージョナルエンドポイントのみサポートのため、マルチリージョン構成では各リージョンごとに管理が必要
  • AI エージェントからのアクセスに対して適切な認証・認可設計が必要

💡 ユースケース

🤖 AI エージェントによる API 自動発見と統合

社内の AI アシスタントが、ユーザーのリクエストに応じて適切な社内 API を自動的に発見し、仕様を理解してコード生成や API 呼び出しを実行。開発者が手動で API ドキュメントを検索する必要がなくなります。

📋 API カタログの自動監査とコンプライアンスチェック

AI エージェントが定期的に API hub の全 API を巡回し、スペックの整合性、バージョン管理状況、デプロイメントの健全性をチェック。ガバナンスチームの負荷を軽減し、ポリシー違反を早期発見。
