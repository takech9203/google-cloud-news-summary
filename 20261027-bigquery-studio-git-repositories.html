BigQuery GA (一般提供)

🗂️ BigQuery Studio Git リポジトリが GA に

SQL スクリプト・ノートブックをコンソール内でバージョン管理
📅 リリース日: 2026-10-27

📝 概要

BigQuery Studio Git リポジトリが一般提供 (GA) になりました。SQL スクリプトやノートブックなどのコードアセットを、BigQuery Studio のファイルブラウザ上で直接バージョン管理できます。リモート Git リポジトリのクローン、ブランチ管理、コミット・プッシュなどの Git 操作を、Google Cloud コンソールを離れることなく実行できます。

従来の BigQuery リポジトリ (classic repositories) と比較して、左ペインのユーザールートフォルダ配下での「フォルダベース」の操作体験が特徴です。GitHub、GitLab、Bitbucket、Azure DevOps などのリモート Git リポジトリと連携し、チーム標準の Git ワークフローに BigQuery 上の開発作業を組み込めます。

🎯 対象ユーザー: BigQuery 上で SQL スクリプトやノートブックを開発するデータアナリスト、データエンジニア、データサイエンティスト

❌ Before (アップデート前の課題)

  • コードアセットのリモート Git バージョン管理には Preview 段階の classic repositories (リポジトリ + ワークスペース構成) が必要だった
  • リポジトリとワークスペースという専用概念を介した操作で、ファイルブラウザ上でファイル・フォルダを直接操作する体験ではなかった
  • バージョン管理されたコードとノートブックのランタイムを直接連携させる仕組みが限られていた

✅ After (アップデート後の改善)

  • ユーザールートフォルダ配下にリモートリポジトリをクローンし、通常のファイル・ディレクトリとして直接操作できるフォルダベース統合が GA に
  • Source control パネルで差分表示・コミット・プッシュ・ブランチ操作・履歴表示・フェッチがコンソール内で完結
  • ノートブックから FuseWidget でリポジトリをマウントし、ファイルの読み書き・import が可能に
  • 大規模リポジトリ向けの shallow clone + 追加フェッチに対応

リモート Git リポジトリを BigQuery Studio のファイルブラウザ配下にクローンし、Source control パネルで Git 操作を行います。ノートブックからは FuseWidget によるマウントを通じて、同一リポジトリ内のファイルへ直接アクセスできます。

⚡ 主要機能

📁 1. フォルダベースの Git リポジトリ統合

→ ファイルブラウザのユーザールートノードから「Create > Git repository」でリモートリポジトリの URL を指定してクローンを作成
→ リポジトリ内のコードアセットを通常のファイルと同様に作成・リネーム・コピー・移動・ダウンロード・削除・アップロード可能
→ SQL クエリ、ノートブック、データキャンバス、データ準備、ファイル、サブディレクトリを新規作成できる

🔀 2. コンソール内での Git 操作 (Source control パネル)

→ 変更ファイルの行単位の差分表示 (Show diff)
→ コミットメッセージを入力してローカルブランチへコミットし、「Push to remote」でリモートへ同期
→ 新規ブランチのチェックアウト・既存ブランチへの切り替え (未コミットの変更がある場合は切り替え不可)
→ アクティブブランチのコミット履歴の表示と、リモートからのフェッチ

🔌 3. 接続方法の柔軟性

→ Developer Connect のアカウントコネクタを自動検出・新規作成可能
→ Developer Connect を使わない場合は HTTPS または SSH で接続可能
→ 対応プロバイダ: GitHub (SSH/HTTPS)、GitLab (SSH/HTTPS)、Bitbucket (SSH)、Azure DevOps Services (SSH)

⏬ 4. Shallow clone (浅いクローン)

→ Advanced options で Shallow clone を選択し、取得コミット数 (Depth) を指定可能
→ コミット履歴が深いリポジトリのクローン時間を短縮し、タイムアウトを回避
→ 後から「Fetch」で追加のコミットを段階的に取得できる

📓 5. ノートブックからのリポジトリマウント (FuseWidget)

→ ノートブック内で FuseWidget() を実行し、Git リポジトリを Colab ランタイムにマウント
→ カレントディレクトリと Python system path がリポジトリに合わせて更新され、標準の import 文でスクリプトを読み込める
→ Mount / Unmount / Connect / Disconnect / Repair 操作とステータスバー (Connected / Mounted / Stopped / Unhealthy) で状態管理

🛠️ 設定方法

✅ 前提条件

✓リモート Git リポジトリ (GitHub、GitLab、Bitbucket、Azure DevOps など) が利用可能であること
✓リモートがファイアウォール内にある場合は、Dataform の egress IP アドレス範囲をファイアウォールルールに追加していること
✓組織で dataform.restrictGitRemotes ポリシーを使用している場合は、対象リモートが許可リストに含まれていること

ステップ 1: Git リポジトリの作成 (クローン)

  1. Google Cloud コンソールで BigQuery ページに移動
  2. 左ペインで「Files」をクリックしてファイルブラウザを開く
  3. ユーザールートノードの横の「View actions > Create > Git repository」をクリック
  4. リモート Git リポジトリの URL を入力
  5. Developer Connect アカウントコネクタを選択・作成するか、「Use a different connection type」で HTTPS / SSH 接続を設定
  6. (任意) Advanced options で Shallow clone を選択し、Depth に取得コミット数を入力
  7. 「Connect」をクリック

💡 メリット

💼 ビジネス面

✓ガバナンスの向上: SQL スクリプトやノートブックの変更履歴が Git で管理され、分析資産の変更追跡・レビュー・ロールバックが既存の Git ワークフローの延長で実現できる
✓GA による本番利用: 一般提供となり、Pre-GA の制約なく利用できる

⚙️ 技術面

✓コンソール内で完結する Git 操作: クローン、差分確認、コミット、プッシュ、ブランチ操作、履歴参照をコンソールから離れずに実行でき、ローカル環境への git クローンや CLI 操作が不要
✓ノートブックとリポジトリの直接連携: FuseWidget のマウントにより、ノートブックからリポジトリ内のファイルを読み書きでき、標準の Python import でスクリプトを再利用できる
✓大規模リポジトリへの対応: shallow clone と追加フェッチにより、履歴の深いリポジトリでも実用的なクローン時間で利用を開始できる

⚠️ デメリット・制約事項

制限事項

▲ユーザールートフォルダのコンテキストに限定され、プライベート利用が前提 (他ユーザーとの共有は非推奨)
▲マウント内のファイルシステム操作は Dataform クォータを消費する
▲マウント内のノートブックファイルは 30 MB まで
▲未コミットの変更がある状態では、新規ブランチのチェックアウトやブランチ切り替えができない
▲ファイルのコピー・移動は同一 Git リポジトリ内に限定される

考慮すべき点

→マウント外での変更がマウントへ反映されるまで最大 60 秒のラグがある (CACHE_TTL_SECONDS で調整できるが、短くするほど Dataform クォータの消費が増える)
→ファイアウォール内のリモートリポジトリに接続する場合は、Dataform の egress IP 範囲の許可設定が必要
→組織ポリシー dataform.restrictGitRemotes を運用している場合、接続先リモートの事前許可が必要

Python スクラッチセルでマウントしてリポジトリ内モジュールを import 
# スクラッチセルで実行
from google_dataform_fuse_widget import FuseWidget
FuseWidget()

# マウント後、リポジトリ内のモジュールを標準の import で利用
import my_utils

効果: マウントによりカレントディレクトリと Python system path がリポジトリに合わせて設定されるため、パスベースのファイルアクセスと import がそのまま動作し、共通コードの再利用が容易になる。

💰 料金

BigQuery のリポジトリ機能では、リポジトリの作成・更新・削除に対する課金はありません。ただし、マウント内のファイルシステム操作は Dataform のクォータを消費します。BigQuery 自体の料金 (クエリ、ストレージなど) は通常どおり適用されます。

🗃️ BigQuery repositories (classic)

リポジトリ + ワークスペース構成の従来機能 (Preview)。BigQuery Studio Git リポジトリはこれに対するフォルダベースの統合を提供する。

✅ まとめ

BigQuery Studio Git リポジトリの GA により、SQL スクリプトやノートブックのバージョン管理を Google Cloud コンソール内で完結できるようになりました。リモート Git リポジトリとのフォルダベースの統合、Source control パネルでの Git 操作、ノートブックへのマウントにより、BigQuery 上の開発作業をチームの Git ワークフローへ自然に組み込めます。BigQuery 上でコードアセットを管理しているチームは、既存のリモートリポジトリを接続して評価を始めることを推奨します。
