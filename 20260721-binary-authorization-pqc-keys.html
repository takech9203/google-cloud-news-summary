🔐 Binary Authorization: PQC 鍵サポート

Security Binary Authorization Feature

📋 概要

Binary Authorization において、ポスト量子暗号 (Post-Quantum Cryptography: PQC) アルゴリズムを使用した鍵のサポートが追加されました。将来の量子コンピュータによる攻撃に対して長期的なセキュリティを確保しつつ、コンテナイメージのデプロイ検証を行うことが可能になります。

サポートされるアルゴリズムには ML-DSA-65 (Dilithium3) が含まれ、NIST が標準化した量子耐性アルゴリズムです。PQC 鍵は Cloud KMS で管理され、既存の Binary Authorization ワークフローにシームレスに統合できます。

💡 HNDL 攻撃への対策: 「Harvest Now, Decrypt Later」攻撃 --- 現在暗号化されたデータを収集し、将来量子コンピュータで復号する攻撃 --- に対する防御策として重要です。

🔄 Before / After 比較

❌ Before (アップデート前)

  • ECDSA や RSA などの古典的暗号アルゴリズムのみ使用可能
  • 将来の量子コンピュータによる署名偽造リスクに対する直接的防御手段なし
  • 量子耐性のある署名スキームへの移行準備ができなかった

✅ After (アップデート後)

  • ML-DSA-65 (Dilithium3) などの PQC 署名アルゴリズムで署名・検証が可能
  • Cloud KMS 統合により PQC 鍵の安全な生成・管理が容易
  • 古典・量子双方からの攻撃に耐性のある長期的セキュリティを実現

🛠️ 設定方法

前提条件: Binary Authorization の有効化、Cloud KMS API の有効化、適切な IAM 権限 (Cloud KMS 管理者、Binary Authorization 管理者)

Step 1: 環境変数の設定

Bash 
# プロジェクトと鍵の設定
KMS_KEY_PROJECT_ID=my-project-id
KMS_KEY_LOCATION=global
KMS_KEYRING_NAME=my-binauthz-pqc-keyring
KMS_KEY_NAME=my-pqc-attestor-key
KMS_KEY_VERSION=1
KMS_KEY_PURPOSE=asymmetric-signing
KMS_KEY_ALGORITHM=ml-dsa-65
KMS_PROTECTION_LEVEL=software

Step 2: キーリングと PQC 鍵の作成

Bash 
# キーリング作成
gcloud kms keyrings create ${KMS_KEYRING_NAME} \
    --location ${KMS_KEY_LOCATION}

# PQC 鍵の作成
gcloud kms keys create ${KMS_KEY_NAME} \
    --location ${KMS_KEY_LOCATION} \
    --keyring ${KMS_KEYRING_NAME} \
    --purpose ${KMS_KEY_PURPOSE} \
    --default-algorithm ${KMS_KEY_ALGORITHM} \
    --protection-level ${KMS_PROTECTION_LEVEL}

Step 3: Attestor の作成と公開鍵の登録

Bash 
# Attestor の作成
ATTESTOR_NAME=pqc-attestor
NOTE_ID=pqc-attestation-note

gcloud container binauthz attestors create ${ATTESTOR_NAME} \
    --attestation-authority-note=${NOTE_ID} \
    --attestation-authority-note-project=${KMS_KEY_PROJECT_ID}

# PQC 公開鍵を Attestor に追加
gcloud container binauthz attestors public-keys add \
    --attestor=${ATTESTOR_NAME} \
    --keyversion-project=${KMS_KEY_PROJECT_ID} \
    --keyversion-location=${KMS_KEY_LOCATION} \
    --keyversion-keyring=${KMS_KEYRING_NAME} \
    --keyversion-key=${KMS_KEY_NAME} \
    --keyversion=${KMS_KEY_VERSION}

⚠️ デメリット・制約事項

制限事項:
✗PQC 署名サイズが ECDSA (64 bytes) 比で大幅に大きい (ML-DSA-65: 3,309 bytes) --- ストレージ・帯域への影響あり
✗ハイブリッド署名 (PQC + 古典的署名の組み合わせ) は未サポート --- NIST 標準策定待ち
✗PQC アルゴリズムは比較的新しく、長期的な暗号解析による安全性評価が継続中
考慮すべき点:
⚠️既存 PKIX 鍵からの移行には Attestor の再作成または新規作成が必要
⚠️PQC 署名検証は計算コストが高い場合があり、大量デプロイ環境ではレイテンシ検証が必要
⚠️鍵・署名サイズが大きいため、Artifact Analysis のストレージコストに影響の可能性
