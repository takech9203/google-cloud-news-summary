🔒 Security Command Center:
データレジデンシー・暗号化設定の事後変更

Security Command Center GA Premium / Standard
2026-07-09

📋 概要

Security Command Center の Premium および Standard ティアにおいて、アクティベーション後にデータレジデンシーとデータ暗号化の構成を変更できるようになりました。これまではアクティベーション時にのみ設定可能であり、一度有効化すると変更不可能であった制約が緩和されています。

GDPR、データ主権規制、業界固有のコンプライアンス要件への対応が、再アクティベーションなしで柔軟に行えるようになります。

❌ Before (従来)

  • データレジデンシー設定はアクティベーション時のみ
  • CMEK 設定もアクティベーション後に変更不可
  • 変更には SCC を無効化して再アクティベーションが必要
  • データ主権ポリシーの変化に追随不可

✅ After (新機能)

  • アクティベーション後にデータレジデンシー設定を変更可能
  • 暗号化構成 (Google デフォルト / CMEK) も事後変更可能
  • サービス中断なしで柔軟に対応
  • 既存の Findings を維持しつつポリシー変更可能

⚡ 主要機能

🌍 データレジデンシー設定のポストアクティベーション変更

→アクティベーション後にデータの保存場所 (リージョン) を変更可能
→サポートロケーション: EU (欧州連合)、US (米国)、SA (サウジアラビア王国)
→Jurisdictional Google Cloud Console を使用して設定変更を実施

🔐 データ暗号化設定のポストアクティベーション変更

→Google デフォルト暗号化から CMEK (顧客管理暗号鍵) への切り替え、またはその逆が可能
→Cloud KMS キーの変更にも対応
→暗号化ポリシーの見直しを運用中に実施可能

🎯 対象ティア

→Premium ティア: サブスクリプションおよび従量課金の両方に対応
→Standard ティア: 無償ティアでも設定変更が利用可能
→組織レベルのアクティベーションが前提条件

前提条件

✓データレジデンシー変更の場合: Jurisdictional Console へのアクセス権限

ステップ 1: Jurisdictional Console へのアクセス

ロケーション Console URL
EU console.eu.cloud.google.com
US console.us.cloud.google.com
KSA console.sa.cloud.google.com

ステップ 2: CMEK キーの設定 (暗号化変更時)

Bash 
# キーリングの作成 (例: EU ロケーション)
gcloud kms keyrings create scc-keyring \
  --location europe \
  --project YOUR_KMS_PROJECT_ID

# 暗号化キーの作成
gcloud kms keys create scc-cmek-key \
  --keyring scc-keyring \
  --location europe \
  --purpose encryption \
  --project YOUR_KMS_PROJECT_ID

ステップ 3: サービスエージェントへの権限付与

Bash 
# SCC サービスエージェントに Cloud KMS CryptoKey Encrypter/Decrypter ロールを付与
gcloud kms keys add-iam-policy-binding scc-cmek-key \
  --keyring scc-keyring \
  --location europe \
  --member=serviceAccount:service-org-ORGANIZATION_NUMBER@security-center-api.iam.gserviceaccount.com \
  --role=roles/cloudkms.cryptoKeyEncrypterDecrypter

✅ メリット

ビジネス面

📊コンプライアンス対応の柔軟性: 規制変更やビジネス展開に伴うデータ主権要件の変化に、サービスの再構築なしで対応可能
🔄運用継続性の向上: SCC を停止・再アクティベーションする必要がなくなり、セキュリティ監視のギャップが発生しない
🌍マルチリージョン展開の促進: EU、US、KSA 間でのデータレジデンシー変更が容易になり、グローバル展開時のガバナンス調整が簡素化

技術面

🔑暗号化ライフサイクル管理の改善: CMEK キーの変更やローテーションに伴う暗号化方式の見直しが、運用中に実施可能
🏗️Infrastructure as Code との親和性: 設定変更が可能になったことで、Terraform 等による宣言的な構成管理に対応しやすくなる
📈セキュリティポスチャーの継続的改善: 暗号化強度の向上やリージョン変更を、既存の Findings データを維持しつつ段階的に実施可能

⚠️ デメリット・制約事項

⚠️ 制限事項:
  • データレジデンシー有効化で一部機能が利用不可 (KSA 環境での AI Protection、Compliance ページのスキャン数表示)
  • Security Command Center v2 API の使用が必須 (v1 API は使用不可)
  • CMEK キーを無効化・破棄した場合、SCC が動作停止しデータ損失の可能性あり (不可逆)
🚨 考慮すべき点:
  • データレジデンシー変更時、既存 Findings が新ロケーションに移行されるまで一時的に異なるリージョンに存在する可能性
  • CMEK キー変更後も、古いキーは 30 日間一部の機能で使用される場合がある
  • Enterprise ティアでは本変更の対象外となる可能性あり (別途確認が必要)

💡 ユースケース

🌐 ユースケース 1: EU 規制対応後の KSA 展開

シナリオ: EU のデータレジデンシー要件に対応するため EU リージョンで SCC を設定していた企業が、中東市場への展開に伴い KSA のデータ主権規制にも準拠する必要が生じた場合。

効果: SCC の再構築やデータ移行プロジェクトなしで、設定変更のみで新しいデータレジデンシー要件に対応。セキュリティ監視のダウンタイムゼロ。

🔑 ユースケース 2: Google デフォルト暗号化から CMEK への移行

シナリオ: コスト最適化のため Google デフォルト暗号化で運用していた組織が、監査要件の厳格化により CMEK の使用が必須となった場合。

効果: 既存の Findings やアラート設定を維持したまま、暗号化方式を CMEK に移行可能。Cloud KMS による鍵のライフサイクル管理、監査ログ、アクセス制御が追加。

🏢 ユースケース 3: M&A に伴うデータガバナンス統合

シナリオ: 企業買収により、買収先が異なるデータレジデンシー設定で SCC を運用していた場合。統合ガバナンスポリシーに合わせる必要がある。

効果: 買収先の SCC のデータレジデンシーおよび暗号化設定を統合ポリシーに合わせて変更可能。セキュリティ態勢の統合をスムーズに実施。

💰 料金情報

データレジデンシーおよび暗号化設定の変更自体には追加料金は発生しません。CMEK を使用する場合は Cloud KMS の料金が別途発生します。

項目 料金
Standard ティア 無料
Premium ティア (従量課金) リソース使用量に基づく課金
Premium ティア (サブスクリプション) 契約内容に基づく
Cloud KMS (CMEK 使用時) キーバージョンあたり $0.06/月 + 暗号化オペレーション料金

📝 まとめ

今回のアップデートにより、Security Command Center の Premium および Standard ティアにおいて、これまでアクティベーション時にのみ設定可能であったデータレジデンシーとデータ暗号化の構成を、運用開始後にも変更できるようになりました。

コンプライアンス要件の変化に柔軟に対応する必要がある組織にとって、セキュリティ運用の継続性を維持しつつガバナンスポリシーを適応させることを可能にする重要な改善です。

💡 推奨アクション: 既に Security Command Center を運用中でデータ主権要件の見直しを検討している組織は、公式ドキュメント「Modify data residency and encryption」を確認し、変更手順と制約事項を把握した上で計画的に実施してください。
