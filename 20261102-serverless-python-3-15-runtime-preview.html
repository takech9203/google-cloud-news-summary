🐍 Python 3.15 ランタイムが Preview で利用可能に

サーバーレス 4 サービスで同時提供開始 — コールドスタート改善に効く新機能を今すぐ検証
📅 リリース日: 2026-11-02

📝 概要

Google Cloud のサーバーレス プラットフォーム 4 サービス (App Engine スタンダード環境、App Engine フレキシブル環境、Cloud Run、Cloud Run functions) で、Python 3.15 ランタイムのサポートが Preview として同時に発表されました。Python 3.15 は 2026 年 10 月 9 日リリースの最新安定版で、リリースからわずか 1 か月弱でサーバーレス環境全体に展開されたことになります。

代表的な新機能は PEP 810 (明示的な遅延インポート) で、lazy import 構文によりモジュール読み込みを初回使用時まで遅延でき、コールドスタート時間の短縮に直結します。そのほか UTF-8 モードのデフォルト化、内包表記でのアンパック、frozendict / sentinel 組み込み型、ほぼゼロオーバーヘッドのサンプリング プロファイラ「Tachyon」などが追加されています。

😣 Before (アップデート前の課題)

  • マネージド ランタイムは Python 3.14 まで。3.15 の新機能・性能改善を利用できなかった
  • lazy import によるコールドスタート短縮や新プロファイラをマネージド ランタイムで検証する手段がなかった
  • Python 3.15 を試すにはカスタム コンテナ イメージを自前でビルド・運用する必要があった

😊 After (アップデート後の改善)

  • 4 つのサーバーレス サービスすべてで Python 3.15 を指定してデプロイ可能に (Preview)
  • カスタム イメージなしで、遅延インポート・UTF-8 デフォルト・改善されたエラーメッセージなどを評価可能に
  • GA に先立ち、既存アプリの 3.15 互換性テストをマネージド環境で開始できるように
👥 対象ユーザー: Python でサーバーレス アプリケーションや関数を開発しているすべての開発者。Preview 段階のため本番利用は非推奨ですが、互換性検証と新機能評価を早期に開始できます。

⚙️ 主要機能

1️⃣ 4 サービス同時の Python 3.15 対応 (Preview)

→App Engine スタンダード環境、App Engine フレキシブル環境、Cloud Run、Cloud Run functions の 4 サービスで同時に Preview 提供
→Google 管理のランタイム ベースイメージとして提供され、OS・言語レベルのセキュリティ パッチは Google が適用

2️⃣ Python 3.15 の主な新機能

🚀 PEP 810 - 明示的な遅延インポート

lazy import json と記述すると初回使用時まで読み込みを遅延。起動時間の短縮に有効で、サーバーレスのコールドスタート対策として特に有用

🔤 PEP 686 - UTF-8 モードがデフォルトに

encoding 未指定の I/O がロケールに依存せず UTF-8 になり、環境差異による文字化けバグを削減

📦 PEP 798 - 内包表記でのアンパック

[*L for L in lists] でのフラット化や {**d for d in dicts} での辞書マージが可能に

🧊 PEP 814 frozendict / PEP 661 sentinel

不変マッピングと一意なセンチネル値が組み込みで利用可能に

📊 PEP 799 - 新しい profiling パッケージ

統計的サンプリング プロファイラ「Tachyon」を搭載。実行中プロセスに PID でアタッチでき、フレームグラフ出力にも対応

💬 エラーメッセージの改善

AttributeError でネストした属性の提案や、他言語由来のメソッド名 (.push → .append など) の提案が追加

3️⃣ ランタイム ライフサイクルに沿った提供

→Preview 期間を経て GA に昇格するのが通例 (例: Python 3.11 は Preview 発表から約 2 か月で GA)
→GA 後はセキュリティ アップデート ポリシーに従いパッチが自動適用され、Python コミュニティのサポート終了に合わせて非推奨化・廃止が設定される

🛠️ 設定方法

✅ 前提条件:
  • Google Cloud プロジェクトと gcloud CLI (最新版) がセットアップ済みであること
  • Preview ランタイムの利用となるため、本番ワークロード以外での検証を推奨

ステップ 1: App Engine で Python 3.15 を指定する

YAML app.yaml (スタンダード環境) 
# app.yaml (スタンダード環境)
runtime: python315

スタンダード環境では app.yaml の runtime にバージョンを指定します (runtime: pythonVERSION 形式)。

ステップ 2: Cloud Run functions で Python 3.15 を指定する

Bash gcloud beta でデプロイ 
# Preview ランタイムのため gcloud beta を使用
gcloud beta run deploy my-function \
  --source . \
  --function my_entrypoint \
  --base-image python315

Cloud Run functions では --base-image フラグでランタイム ベースイメージを指定します。Preview 中のランタイムをデプロイする場合は beta コマンドの利用が案内されています。

ステップ 3: 互換性の確認

Bash ローカルでの事前確認 
# ローカルで Python 3.15 の互換性を事前確認
python3.15 -X dev -m pytest

デプロイ前にローカルで Python 3.15 を使ってテストを実行し、非推奨 API の削除 (ast、ctypes、pathlib などの一部 API) の影響がないか確認します。

⚖️ メリットとデメリット・制約事項

💼 ビジネス面のメリット
✓早期検証によるスムーズな移行: GA 前に互換性検証を始められるため、将来のランタイム アップグレードを計画的に進められ、非推奨化対応の駆け込み作業を回避できる
✓運用負荷の軽減: マネージド ランタイムとして提供されるため、Python 3.15 を試すためにカスタム イメージのビルド・パッチ適用体制を構築する必要がない
🔧 技術面のメリット
✓コールドスタートの短縮余地: PEP 810 の遅延インポートにより、起動時に不要なモジュール読み込みを先送りでき、サーバーレスで重要な起動時間を改善できる
✓本番プロファイリングの強化: 新しいサンプリング プロファイラ Tachyon はオーバーヘッドがほぼゼロで、パフォーマンス分析の選択肢が広がる
✓文字コード起因の不具合削減: UTF-8 がデフォルトになることで、ローカルと本番コンテナのロケール差異による不具合を防げる
🚧 制限事項
✗Preview 段階のため SLA の対象外であり、本番ワークロードでの利用は推奨されない
✗Python 3.15 の非推奨・廃止スケジュールはまだ公表されていない
✗Python 3.15 では profile モジュールの非推奨化や ast・ctypes・pathlib などの一部 API 削除があり、既存コードの修正が必要になる場合がある
⚠️ 考慮すべき点
  • 3.14 で導入されたインクリメンタル GC が 3.15 で世代別 GC に戻されるなど、メモリ挙動が変わる可能性があるため、メモリ使用量の回帰テストを推奨
  • 依存ライブラリ (特に C 拡張を含むもの) が Python 3.15 対応版を提供しているか事前確認が必要
  • App Engine フレキシブル環境・スタンダード環境・Cloud Run でランタイム指定方法が異なるため、各サービスのドキュメントに従うこと

🎯 ユースケース

💡 ユースケース 1: コールドスタートに敏感な API の起動時間改善検証

シナリオ: Cloud Run functions で提供している低頻度呼び出しの API で、コールドスタート時のレイテンシが課題になっている。

Python main.py (Python 3.15) — lazy import の実装例 
# main.py (Python 3.15)
lazy import pandas  # 初回使用時まで読み込みを遅延

import functions_framework

@functions_framework.http
def handler(request):
    if request.args.get("report"):
        df = pandas.DataFrame(...)  # ここで初めて pandas がロードされる
        ...
    return "ok"

効果: 重いライブラリの読み込みを実際に必要なリクエストまで遅延させ、大半のリクエストでのコールドスタート時間を短縮できる。

💡 ユースケース 2: GA 前の互換性検証パイプライン

シナリオ: App Engine スタンダード環境 (Python 3.13) で稼働中の社内アプリについて、将来のアップグレードに備えて Python 3.15 互換性を継続的に検証したい。
