Looker 26.22 機能アップデートまとめ

Google グループミラーリング / Sankey チャート GA / 公式 BigQuery JDBC ドライバー ほか
📅 リリース日: 2026-11-13
⏰ 2026-11-09 以降、26.22 インスタンスで自動有効化

📝 概要

2026 年 11 月 13 日、Looker 26.22 サイクルに関する複数のアップデートが発表されました。 2026 年 11 月 9 日以降、Looker 26.22 を実行する Looker (オリジナル) および Looker (Google Cloud コア) インスタンスでは、これらの機能が自動的に有効化されます。 アップデートは次の 3 つの領域にまたがります。

🔐 管理・認証

  • Looker (オリジナル) で Google グループミラーリング対応
  • Gemini 支援機能 (Conversational Analytics など) の超過利用分に課金開始

📈 可視化・レポーティング

  • 上限外の行/ピボット列を 「Other」カテゴリへ集約
  • ダウンロードにフィルタ・クエリ情報を付与
  • PDF ダウンロードの動作変更
  • Sankey チャートが GA

🔌 データベース接続

  • Google 公式 BigQuery JDBC ドライバーのオプトイン (Preview)
  • 将来レガシードライバーを置き換え予定

❌ Before: アップデート前の課題

  • Looker (オリジナル) の Google 認証ではグループメンバーシップに基づくロール・グループの自動割り当てができず、手動のユーザー・グループ管理が必要だった
  • Gemini 支援機能に対する課金の仕組みが未整備で、請求先プロジェクトの関連付けが必要になった
  • Limit Displayed Rows で上限外の行は単に非表示となり、「上位 N + その他」の表現ができなかった
  • ダウンロードファイルにフィルタ条件やクエリ実行情報が含まれず、ファイル単体では取得条件を確認できなかった
  • BigQuery 接続は Looker 独自のレガシードライバーのみで、Google 公式サポートのドライバーを選択できなかった
  • Sankey チャートは GA ではなかった

✅ After: アップデート後の改善

  • Google グループミラーリングでロール・グループを自動割り当て。Advanced Role Management と Looker API によるプログラマティック構成も可能に
  • Gemini in Looker 管理ページから請求先プロジェクトを関連付けて課金開始に備えられる
  • 「Group remaining rows/pivots into 'Other'」で上位 N + 「Other」集約表示。ラベルやカスタムカラーも指定可能
  • PNG はフィルタバナー、Excel はメタデータ・フィルタシートを付与。タブ付き PDF はフィルタ表示位置を選択可能
  • 公式 BigQuery JDBC ドライバー (Preview) にオプトイン可能
  • Sankey チャートが GA になり多段階パス分析に利用可能
💡 対象読者: Looker 管理者はグループ管理の自動化や課金プロジェクトの設定準備を、BI 開発者・利用者は新しい可視化・ダウンロードオプションの活用を検討してください。 同日発表の Looker (オリジナル) 2 要素認証 (2FA) デフォルト有効化 (Breaking Change) は別レポートで扱います。

Looker 26.22 では、Google グループとの認証連携、公式 BigQuery JDBC ドライバーによる接続、Gemini 支援機能の課金プロジェクト関連付けなど、Looker インスタンスを取り巻く複数の統合ポイントが強化されます。

🚀 主要機能 (7 つのアップデート)

1️⃣ Google グループミラーリング (Looker オリジナル)GA

  • Google グループのメンバーシップに基づき、Looker のロールとグループを自動割り当て
  • Google グループの変更はミラーリングされた Looker グループに自動伝播され、各ユーザーの次回ログイン時に検証
  • Advanced Role Management により、Google グループ構成と厳密に一致させるか、Looker 内での追加管理 (組み込みグループへの追加・直接のロール割り当て) を許可するかを制御可能
  • ミラーリング無効化時: ユーザーのいないミラーグループは即時削除、ユーザーが残るグループは「孤立 (orphaned)」としてマークされ 31 日間ログインがなければ削除
  • Looker API によるプログラマティックな構成にも対応

2️⃣ Gemini 支援機能の超過利用分への課金開始Change

  • 対象は Conversational Analytics をはじめとする GA 済みの Gemini エージェント機能群。プレビュー段階の機能は課金対象外
  • 使用量はデータトークンで計測 (入力: 質問、会話履歴、LookML スキーマメタデータなど / 出力: 自然言語応答、生成 SQL/LookML クエリ、可視化仕様など)
  • インスタンスに含まれる月間データトークン割り当てを超過した利用分が課金対象
  • Looker (オリジナル): 管理者が Gemini in Looker 管理ページから請求先プロジェクトを指定 / Looker (Google Cloud コア): プロビジョニング時のプロジェクトと請求先アカウントを使用
  • 公式ドキュメントでは課金開始日は 2027 年 2 月 1 日と記載

3️⃣ 可視化の「Other」カテゴリへのグループ化GA

  • Limit Displayed Rows / Limit Displayed Pivot Columns 使用時に、上限外の行/ピボット列を単一の「Other」カテゴリへ集約して表示
  • カテゴリラベルをカスタマイズ可能。円グラフや単一シリーズの縦棒・横棒・散布図ではカスタムカラーも指定可能
  • 行グループ化: テーブル、横棒、縦棒、折れ線、面、散布図、円、ドーナツマルチプル
  • ピボットグループ化: テーブル、横棒、縦棒、折れ線、面、散布図

4️⃣ ダウンロードへのフィルタ・クエリ情報の付与GA

  • PNG: 「Include filter context」でアクティブなフィルタと値を示すヘッダーバナーを画像上部に表示
  • Excel: 「Add query metadata sheet」でクエリ実行時間・タイムゾーンなどの「Metadata」シートと、適用フィルタの「Filters」シートを追加
  • ダッシュボード編集者は、タイルダウンロードの Excel メタデータオプションのデフォルトをダッシュボード設定で指定可能
  • タブ付きダッシュボードの PDF: 全フィルタを先頭に一括表示するか、各タブのアクティブフィルタをタブヘッダー下に表示するかを選択可能

5️⃣ 公式 Google BigQuery JDBC ドライバーへのオプトインPreview

  • Google がビルド・サポートする公式ドライバー。将来のリリースで現行の Looker レガシードライバーを置き換える予定
  • 既存の接続は管理者がオプトインしない限り現行ドライバーを継続使用。いつでも以前のドライバーに戻せる
  • プレビュー期間中の問題は cloud-looker-dialects@google.com に報告

6️⃣ PDF ダウンロード/配信の動作変更Change

  • 「Expand tables to show all rows」選択時、「Fit Page to Dashboard」オプションが選択不可になり、用紙サイズが A4 に設定、改ページがデフォルトで有効になる

7️⃣ Sankey チャートの一般提供 (GA)GA

  • カテゴリ、ステージ、状態間のデータのフローと分布を可視化。接続パスの幅がメジャー値に対応
  • カスタマージャーニー、Web サイトのナビゲーションフロー、システム間のリソース配分など多段階パスの分析に有用
  • Path 型 (2 つ以上のディメンション + 1 メジャー) と Edge list 型 (2 ディメンション + 1 メジャー) に対応し、クエリに基づき自動適用
  • クロスフィルタリング (Link crossfilter by: Both / Source / Target)、カスタムツールチップ、カラーコレクションなどのスタイルオプションに対応

🔧 設定方法

🔌 公式 BigQuery JDBC ドライバー (Preview) へのオプトイン

  1. Admin > Database > Connections で Connections 管理ページを開く
  2. 対象の BigQuery 接続の Edit ボタンをクリック
  3. 接続の Use latest stable driver トグルをオフにする
  4. Driver Version ドロップダウンメニューから BigQuery Official [Preview] ドライバーオプションのいずれかを選択
  5. Test で接続を確認し、Update Connection を選択

💳 Gemini 支援機能の請求先プロジェクトの指定 (Looker オリジナル)

  1. Admin パネルの Platform セクションで Gemini in Looker ページを開く
  2. Add project を選択
  3. 「Select a Google Cloud project」パネルで、有効な請求先アカウントにリンクされた Google Cloud プロジェクトのプロジェクト番号を入力
  4. パネルに表示されるサービスアカウント名を控える
  5. Google Cloud コンソールで該当プロジェクトを開き、そのサービスアカウントに Viewer IAM ロールを付与
  6. Looker のページに戻り、Validate and link を選択

👥 Google グループミラーリングの注意点

⚠️ 注意:
  • Advanced Role Management のすべてのオプションを有効にすると、Looker 管理者はミラーグループのメンバーシップを直接変更できなくなり、ロールは Google グループ経由でのみ割り当て可能になる
  • より制限の強い設定を有効にすると、Looker 内で直接構成されていたグループメンバーシップや割り当て済みロールが、ユーザーの次回サインイン時に失われる

💡 メリット

💼 ビジネス面

  • ID 管理の一元化: Google グループを唯一の情報源として Looker のグループ・ロールを管理でき、入退社や異動に伴う権限変更の運用負荷とヒューマンエラーを削減
  • ガバナンスとトレーサビリティの向上: ダウンロードファイルにフィルタ条件とクエリメタデータが含まれ、「いつ、どの条件で」取得されたデータかを受け手が確認でき、監査やレビューが容易に
  • 分析表現力の向上: Sankey チャートの GA と「Other」グループ化により、カスタマージャーニー分析や上位 N + その他のパレート的な可視化を標準機能で実現

🛠️ 技術面

  • Google 公式サポートのドライバー: BigQuery 接続を公式 JDBC ドライバーへ段階的に移行でき、将来の強制移行前にプレビューで検証可能
  • API によるガバナンス自動化: Google 認証設定が Looker API でプログラマティックに構成可能となり、IaC 的な管理や複数インスタンスへの一括適用が容易に
  • コストの可視化と管理: Gemini 支援機能の利用がデータトークンで計測され、請求先プロジェクトに紐づくため、Cloud Billing 側でコストを追跡可能

⚠️ デメリット・制約事項

🚧 制限事項

  • 「Other」カテゴリはクロスフィルタリング非対応で、非加算メジャー (個別カウント、パーセンタイルなど) を含むクエリでは利用不可。非テーブルチャートでは行とピボット列のグループ化を同時に有効化できない
  • Sankey チャートは最大 500 行までで、Edge list 型は循環パス (A > B > A) をレンダリング不可
  • 公式 BigQuery JDBC ドライバーはプレビュー段階であり、Pre-GA 提供条件が適用される
  • PNG フィルタバナーと Excel メタデータシートは PNG / Excel 形式のみで利用可能 (CSV、JSON などは対象外)

🤔 考慮すべき点

  • 自動有効化: 2026 年 11 月 9 日以降、26.22 インスタンスで自動有効化されるため、管理者は事前に動作変更 (特に PDF ダウンロードの挙動変更) の影響を確認しておくべき
  • Gemini 課金の準備: Looker (オリジナル) で Gemini 支援機能を利用中の場合、課金開始前に請求先プロジェクトの関連付けを済ませないと、利用の中断が生じる可能性がある。Looker (Google Cloud コア) ではプロビジョニング時のプロジェクトが使用され変更不可
  • グループミラーリングの切り替え影響: Advanced Role Management の制限的な設定を有効化すると、Looker 内で直接付与していたロールやグループメンバーシップが次回ログイン時に失われる
  • PDF 配信への影響: 既存の PDF 配信スケジュールで「Expand tables to show all rows」を使用している場合、用紙サイズが A4・改ページ有効に変わるため、出力レイアウトの確認が必要
  • JDBC ドライバーの検証: 公式ドライバーは将来レガシードライバーを置き換えるため、早めにプレビューで既存の LookML・ダッシュボードとの互換性を検証しておくことが望ましい

🎯 ユースケース

👥 ユースケース 1: Google グループによる Looker 権限管理の自動化

シナリオ: Google Workspace でチームごとの Google グループ (例: sales-analytics@example.com) を運用している企業が、Looker (オリジナル) のユーザー権限管理を手動で行っており、異動時の権限変更漏れが課題になっている。

手順 グループミラーリングの設定フロー 
1. Admin > Authentication > Google で Mirror Google Groups を有効化
2. Google グループ ID と Looker グループ名、割り当てるロールをマッピング
3. 必要に応じて Advanced Role Management で Looker 内での直接のロール付与を制限
4. 以降、Google グループのメンバー変更が次回ログイン時に Looker へ自動反映される

効果: 権限管理を Google グループに一元化し、手動運用によるミスと管理工数を削減できる。

🔀 ユースケース 2: Sankey チャートによるカスタマージャーニー分析

シナリオ: E コマースサイトで「流入元 → 訪問ページ → 購読状態」というユーザー行動のフローを可視化し、離脱ポイントを特定したい。

Explore で上記フィールドを選択し、可視化タイプに Sankey (Path 型) を指定する。

効果: 多段階パスの流量と分布が一目で把握でき、クロスフィルタリングと組み合わせてダッシュボード上でドリルダウン分析ができる。

📋 ユースケース 3: 監査要件を満たすレポート配布

シナリオ: 経営レポートを Excel でダウンロードして配布する際、「どのフィルタ条件で、いつ実行されたデータか」を明示する必要がある。

効果: 「Add query metadata sheet」を有効にすることで、Metadata シート (実行時間・タイムゾーン) と Filters シート (適用フィルタ) が自動付与され、配布後のファイル単体でデータの前提条件を確認できる。ダッシュボード設定でデフォルト有効にすれば、利用者の設定忘れも防げる。

💰 料金

今回のアップデートの大半は Looker の既存ライセンスの範囲で利用できますが、 Gemini 支援機能 (Conversational Analytics など) については、インスタンスに含まれる月間データトークン割り当てを超過した利用分への課金が開始されます (公式ドキュメントでは 2027 年 2 月 1 日開始と記載)。

  • 使用量はデータトークン (入力トークン + 出力トークン) で計測される
  • プレビュー段階の Gemini 支援機能は課金対象外
  • 課金は Google Cloud プロジェクトの請求先アカウントに紐づく。Looker (オリジナル) は管理者による請求先プロジェクトの指定が必要、Looker (Google Cloud コア) はプロビジョニング時のプロジェクトを使用

詳細なレートは Looker の料金ページを参照してください。
