📊 Apigee X: API Health & Availability ダッシュボードが Cloud Monitoring で一般提供 (GA)

Apigee X Cloud Monitoring GA (一般提供) 📅 リリース日: 2026-10-27

💡 概要

Apigee の API プロキシの健全性・パフォーマンス・可用性をリアルタイムに監視できる 「Apigee API Health & Availability ダッシュボード」が Cloud Monitoring で一般提供 (GA) になりました。 SRE の実践で重視されるゴールデンシグナル (トラフィック、エラー率、レイテンシ) を スコアカードとして一目で確認でき、API 運用チームが障害の検知と切り分けを迅速に行えるようになります。

🚦 Traffic
集計トラフィック (requests per second)
⚠️ Error Rate
5xx エラー率
⏱️ Latency
レイテンシ (p95)

スコアカードに加え、ステータスコード別のリクエストレート推移や、プロキシ単位の 5xx / 4xx エラー率チャートを提供。 project_id・location・proxy_name によるフィルタリングで、 特定リージョンや特定プロキシに絞り込んだトラブルシューティングが可能です。 主な対象は Apigee で API プログラムを運用するプラットフォームチーム・SRE・運用担当者です。

❌ Before: アップデート前の課題

  • Cloud Monitoring 上でゴールデンシグナルをまとめて確認するには、apigee.googleapis.com/proxy/request_count や proxy/response_count、proxy/latencies などのメトリクスでカスタムダッシュボードを自作する必要があった
  • 問題プロキシを特定する 5xx / 4xx エラー率のプロキシ別チャートを、PromQL / MQL クエリで個別に構築・保守する必要があった

✅ After: アップデート後の改善

  • 事前構築済みダッシュボードが GA となり、カスタム構築なしでゴールデンシグナルのスコアカードをすぐに利用可能
  • 「Request Rate by Status Code」でステータスコード別傾向を可視化、「5xx / 4xx Error Rate by Proxy」で問題プロキシを特定可能
  • project_id / location / proxy_name によるきめ細かなフィルタリングでトラブルシューティングが可能

🚀 主要機能

1️⃣ ゴールデンシグナルのスコアカード

✓集計された Traffic (requests per second)、Error Rate (5xx)、Latency (p95) をスコアカードとして表示
✓API 全体の健全性を一目で把握でき、異常の早期検知に役立つ

2️⃣ ステータスコードとエラーのトレンド可視化

✓「Request Rate by Status Code」チャートで、ステータスコード別のリクエストレートの推移を時系列で可視化
✓専用の「5xx Error Rate by Proxy」「4xx Error Rate by Proxy」チャートで、問題のある API プロキシを特定可能

3️⃣ きめ細かなフィルタリング

✓project_id、location、proxy_name でテレメトリをフィルタリング
✓特定のリージョンや特定のプロキシに絞り込んだトラブルシューティングが可能

💼 ビジネス面

✓MTTD (平均検知時間) の短縮: ゴールデンシグナルを一目で確認でき、顧客影響が出る前に API の異常に気づき対処しやすくなる
✓運用コストの削減: カスタムダッシュボードの構築・保守が不要になり、監視基盤の立ち上げ工数を削減

🔧 技術面

✓SRE プラクティスとの整合: Traffic / Error Rate / Latency というゴールデンシグナルベースの監視を標準で利用可能
✓Cloud Monitoring への統合: 他の Google Cloud リソースと同じ基盤・UI で監視でき、アラートポリシーなどと組み合わせやすい
✓プロキシ単位の切り分け: 5xx / 4xx Error Rate by Proxy チャートと proxy_name フィルタで問題のプロキシを素早く特定

⚠️ デメリット・制約事項

⚠️ 考慮すべき点
  • スコアカードのレイテンシは p95。p99 など他のパーセンタイルが必要な場合は、apigee.googleapis.com/proxy/latencies メトリクスを使ったカスタムチャートの作成を検討
  • フィルタ対象は project_id、location、proxy_name。それ以外の軸 (環境やメソッドなど) での深掘りが必要な場合は、Apigee の API Monitoring 画面 (Timeline / Investigate / Recent) や Metrics Explorer を併用

🎯 ユースケース

🚨 ユースケース 1: 障害発生時の迅速な切り分け

シナリオ: API 利用者からエラー増加の報告を受けた運用チームが、原因となっているプロキシとリージョンを特定したい。

実装例:

  1. Cloud Monitoring の Apigee API Health & Availability ダッシュボードを開く
  2. Error Rate (5xx) スコアカードと「5xx Error Rate by Proxy」チャートで異常なプロキシを特定
  3. location フィルタで特定リージョンに絞り込み、リージョン起因かプロキシ起因かを切り分け

効果: カスタムクエリを書かずに、問題のプロキシ・リージョンを短時間で特定でき、MTTD を短縮できる。

📅 ユースケース 2: ゴールデンシグナルベースの日常監視

シナリオ: SRE チームが複数の Apigee プロジェクトの API 健全性を日常的にレビューしたい。

効果: Traffic / Error Rate / Latency のスコアカードを定常確認することで、トラフィックの異常なスパイクや 5xx 増加、p95 レイテンシの悪化傾向を早期に把握できる。project_id フィルタでプロジェクトごとの状況も確認できる。

API プロキシのログと組み合わせることで、メトリクスで検知した異常の根本原因分析が可能。
