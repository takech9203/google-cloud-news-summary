Cloud Run への自動マイグレーション

App Engine Cloud Run Preview

📋 概要

App Engine flexible environment で動作している既存アプリケーションを Cloud Run にデプロイするための gcloud beta app migrate-to-run コマンドが Preview として利用可能になりました。

このコマンドは、App Engine の app.yaml 設定を Cloud Run の service.yaml に自動変換し、コンテナイメージのビルドとデプロイまでを一括で実行します。既存の App Engine アプリケーションの機能やトラフィックフローには影響を与えず、Cloud Run 上に独立したレプリカとして新しいサービスが作成されます。

💡 ポイント: Google Cloud は Cloud Run をサーバーレスコンテナプラットフォームの推奨選択肢として位置付けており、本コマンドは App Engine から Cloud Run への移行を自動化する重要なツールです。

⚡ 主要機能

📦 ローカル app.yaml からのデプロイ (推奨)

ローカルのソースコードと app.yaml を使用して Cloud Run にデプロイ。最新のコード変更を含むコンテナイメージが新規ビルドされます。

🐳 既存コンテナイメージからのデプロイ

App Engine 上で稼働中のバージョンのコンテナイメージを再利用。ソースコードへのアクセスが不要で、--from-image フラグで使用します。

🔍 互換性チェック (--dry-run)

デプロイを実行せずに互換性の問題を事前検出。非互換な設定がある場合は具体的な解決策を提示します。

📄 構成エクスポート (--export-only)

Cloud Run の service.yaml 設定ファイルのみを生成。デプロイ前に構成内容を確認・カスタマイズでき、CI/CD パイプラインへの組み込みに有用です。

🔧 コマンドフラグ

フラグ 説明
--appyaml=PATH app.yaml ファイルのパスを指定 (別ディレクトリにある場合)
--export-only=EXPORT_PATH service.yaml の出力先を指定 (デプロイなし)
--service=SERVICE App Engine サービス名を指定
--version=VERSION App Engine バージョン ID を指定
--from-image 既存のコンテナイメージを使用
--dry-run 互換性チェックのみ実行 (デプロイなし)

📝 設定手順

前提条件

✓App Engine アプリケーションがエラーなく動作していること
✓Cloud Run Admin API と Artifact Registry API が有効であること
✓gcloud CLI が最新バージョンに更新されていること
✓ローカル app.yaml からデプロイする場合はソースコードへのアクセスが必要

Step 1: プロジェクトとリージョンの設定

Bash 
gcloud auth login
gcloud config set project PROJECT_ID
gcloud config set run/region REGION
gcloud components update

Step 2: 互換性チェックの実行

Bash 
gcloud beta app migrate-to-run --dry-run

Step 3a: ローカル設定からのデプロイ

Bash 
# app.yaml があるディレクトリで実行
gcloud beta app migrate-to-run

Step 3b: 既存イメージからのデプロイ (代替)

Bash 
gcloud beta app migrate-to-run --service=SERVICE --version=VERSION --from-image

Step 4: (オプション) 構成のみエクスポート

Bash 
gcloud beta app migrate-to-run --export-only=./cloud-run-config/

⚖️ メリット / 制約事項

✅ メリット

  • 移行コスト削減: 手動変換作業が不要、工数を大幅削減
  • リスク最小化: 既存アプリに影響なし、独立テスト可能
  • Cloud Run 料金メリット: CUD 対応、スケールゼロ
  • 自動構成変換: スケーリング・リソース・環境変数を自動マッピング
  • 段階的移行: dry-run / export-only で段階的に検証
  • 高度な機能: GPU、サイドカーコンテナ、ボリュームマウント対応

⚠️ 制約事項

  • Preview 段階 (Pre-GA Offerings Terms 適用)
  • inbound_services: warmup は事前削除が必要
  • Cloud Run はデフォルトでプライベート (公開設定要)
  • URL 形式が appspot.com から run.app に変更
  • App Engine のファイアウォールルールは Cloud Armor に置換
  • スケーリング設定は負荷テストでの検証を推奨

💼 ユースケース

🔄 ユースケース 1: 既存 App Engine アプリの段階的な Cloud Run 移行

シナリオ: 複数のマイクロサービスを App Engine flexible environment で運用しているチームが、Cloud Run のコスト最適化や GPU 機能を活用するために段階的に移行したい。

Bash 
# 1. 互換性チェック
gcloud beta app migrate-to-run --dry-run

# 2. 構成確認 (デプロイなし)
gcloud beta app migrate-to-run --export-only=./migration-review/

# 3. テスト環境にデプロイ
gcloud beta app migrate-to-run

# 4. Cloud Run 上で動作確認後、トラフィックを段階的に切り替え

効果: 既存サービスに影響を与えずに移行を検証し、問題があればロールバック不要で App Engine 上のサービスに留まれます。

🚨 ユースケース 2: ソースコードなしでの緊急移行

シナリオ: レガシーアプリケーションでソースコードの管理状態が不明だが、App Engine 上で動作中のバージョンを Cloud Run に移行する必要がある。

Bash 
# 既存のコンテナイメージを直接 Cloud Run にデプロイ
gcloud beta app migrate-to-run --service=legacy-api --version=v1 --from-image

効果: ソースコードへのアクセスなしで、稼働中のアプリケーションを Cloud Run 上に複製できます。

⚙️ 非互換な機能

⚠️ 注意: 以下の設定が app.yaml に含まれている場合、移行前に対応が必要です。
非互換設定 解決策
inbound_services: warmup 削除する。Cloud Run はコンテナエントリーポイントでウォームアップを行う。startup probes や minimum instances で代替可能。

💰 料金

本コマンド自体の利用に追加料金は発生しません。Cloud Run へのデプロイ後は Cloud Run の料金体系が適用されます。

📊 リクエストベース課金

リクエスト処理中のみ CPU を割り当て。スケールゼロ対応でアイドル時はコストゼロ。

⏱️ インスタンスベース課金

App Engine に近い課金モデル (時間単位)。常時稼働が必要なワークロードに適しています。
