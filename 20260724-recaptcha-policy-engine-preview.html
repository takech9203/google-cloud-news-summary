📋 概要

Google Cloud Fraud Defense (旧 reCAPTCHA Enterprise) において、Policy Engine、Universal Keys、Challenge Policies が Preview として利用可能に。CEL ベースのカスタムルールによる精密な CAPTCHA 制御、スクリプトタグ 1 行での統合、AI 耐性 QR コードチャレンジを提供。

❌ Before (従来)

  • スコアしきい値ベースの単純なルールのみ
  • grecaptcha.enterprise.execute() を各アクションごとに手動呼び出し
  • ビジュアル/オーディオチャレンジは高度な AI ボットに突破されるリスク
  • 信頼できるボットの柔軟な許可手段なし

✅ After (改善後)

  • CEL ベースでスコア+IP+ASN+UA+ボット識別を組み合わせた精密制御
  • AutoExecute でスクリプトタグ追加のみで統合完了
  • AI 耐性 QR コードチャレンジでモバイル TEE 活用
  • verified_bots で信頼ボットを明示的に許可

⚡ 主要機能

🎯 Policy Engine

CEL (Common Expression Language) で記述されたカスタムルールに基づき、CAPTCHA チャレンジを決定論的にトリガー。ルールはグループ単位で管理し、first-match 方式で評価。

🔑 Universal Key

Policy Engine 内でのルール作成をサポートする新しいキータイプ。Console、gcloud CLI、REST API から作成可能。--universal フラグで作成。

⚙️ AutoExecute

Fetch API / XMLHttpRequest による非同期リクエストを自動インターセプトし、X-Recaptcha-Token ヘッダーとして自動付加。スクリプトタグの追加のみで統合完了。

📱 QR コードチャレンジ

モバイルデバイスの信頼された実行環境を活用した AI 耐性検証。Android (Play Services 25.41.30+)、iOS (iOS 16+ App Clips)対応。

📋 Challenge Policies

challenge_rule_groups でルールを定義。難易度レベルは USABILITY (易)、BALANCE (中/デフォルト)、SECURITY (難) の 3 段階。アクションワイルドカード (*) による全アクション一括適用も可能。

🔧 技術仕様

CEL 条件式で利用可能な変数

変数名 型 説明
score double Fraud Defense のボットスコア (0.0-1.0)
user_ip_address string リクエスト元の IP アドレス (IPv4/IPv6)
user_agent string リクエスト元のユーザーエージェント
user_asn int リクエスト元の ASN (AS プレフィックスなし)
verified_bots list(Bot) 検証済みボットのリスト

CEL 条件式で利用可能な関数

関数名 シグネチャ 説明
contains string.contains(string) -> bool 部分文字列の検索
startsWith string.startsWith(string) -> bool プレフィックス一致
endsWith string.endsWith(string) -> bool サフィックス一致
size size(string|list) -> int 文字列長/リストサイズ
has has(message.field) -> bool フィールドの存在確認
all list.all(x, predicate) -> bool 全要素が条件を満たすか
exists list.exists(x, predicate) -> bool 条件を満たす要素が存在するか

🛠️ 設定方法

Policy 設定 (YAML)

YAML Policy 設定例 
client_settings:
  allowedDomains:
    - example.com
  protected_endpoint_group:
    protected_endpoints:
      - path: "/login_api"
        action: login
      - path: "/register_api"
        action: register
      - path: "/cart_api/add/*"
        action: add_to_cart

challenge_rule_groups:
  - actions: ['login', 'signup']
    challenge_rules:
      - condition: 'score < 0.5'
        challenge:
          difficulty: BALANCE
      - condition: 'verified_bots.exists(e, e.name == "google-agent")'
        no_challenge: {}
  - actions: ['*']
    challenge_rules:
      - condition: 'score < 0.3'
        challenge:
          difficulty: SECURITY

セットアップ手順

  1. Universal Key の作成
    gcloud recaptcha keys create --universal --display-name="My Website Universal Key"
  2. フロントエンドへのスクリプト追加
    <script src="https://www.google.com/recaptcha/enterprise.js?render=KEY_ID"></script>
    AutoExecute 利用時はこのスクリプトタグの追加のみで統合完了。
  3. Policy 設定の適用
    gcloud alpha recaptcha policies update --key=KEY_ID --policy=policy.yaml
  4. バックエンドでのアセスメント作成
    Assessment API を呼び出し、トークンを検証してスコアと判定を取得。

ビジネス面のメリット

✓ CEL ベースの柔軟なルール定義: Infrastructure as Code との相性も良い
✓ AI 耐性の向上: QR コードチャレンジで高度なボット攻撃に対応

制限事項・注意点

! Preview ステータスのため、本番環境での SLA は保証されない (Pre-GA Offerings Terms 適用)
! QR コードチャレンジの利用には Fraud Defense チーム (fraud-defense@google.com) への事前申請が必要
! AutoExecute は Fetch API と XMLHttpRequest のみ対応 (ページロード時のリソース読み込みは対象外)
! Policy Engine は Premium ティアで 3 ルールまで、Enterprise で無制限
! ルール評価は first-match 方式のため、ルールの順序設計が重要

🎯 ユースケース

🛒 EC サイトのログイン保護

アカウント乗っ取り (ATO) 対策として、ログインにリスクベースのチャレンジを適用。社内 IP からはチャレンジなし、低スコアには高難易度チャレンジ。

YAML EC サイトログイン保護の設定例 
challenge_rule_groups:
  - actions: ['login']
    challenge_rules:
      - condition: 'user_ip_address.startsWith("10.0.")'
        no_challenge: {}
      - condition: 'score < 0.3'
        challenge:
          difficulty: SECURITY
      - condition: 'score < 0.7'
        challenge:
          difficulty: BALANCE

🤖 AI エージェント対応 Web サービス

正当な AI エージェント (AI ショッピングアシスタントなど) を許可しつつ、不正ボットによるスクレイピングや自動購入を防止。Agentic Web 時代の信頼性フレームワークを実現。

YAML AI エージェント対応の設定例 
challenge_rule_groups:
  - actions: ['*']
    challenge_rules:
      - condition: 'verified_bots.exists(e, e.name == "google-agent")'
        no_challenge: {}
      - condition: 'score < 0.5 && user_asn in [12345, 67890]'
        challenge:
          difficulty: SECURITY
      - condition: 'score < 0.5'
        challenge:
          difficulty: BALANCE

💳 高セキュリティ要件の決済ページ

QR コードチャレンジによる最高レベルのセキュリティを適用。モバイルデバイスの信頼された実行環境を使い、クリックファームや高度な AI ボットによるカーディング攻撃を防止。
