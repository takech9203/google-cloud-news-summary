BigQuery GA (一般提供) マルチクラウド

🔍 BigQuery クロスクラウド接続が GA

AWS・Azure・Salesforce Data 360 のデータを、すべての BigQuery リージョンからクエリ可能に
📅 リリース日: 2026-11-25

📌 概要

BigQuery のクロスクラウド接続 (Cross-cloud connections) が一般提供 (GA) になりました。 AWS (Amazon S3)、Microsoft Azure (Blob Storage)、Salesforce Data 360 のデータを、 すべての BigQuery リージョンからクエリできます。

従来の BigQuery Omni による標準接続は、リモートリージョンに軽量なコンピュートワーカーをデプロイし、データを移動せずにクエリする方式でした。 これに対しクロスクラウド接続は、他クラウドのデータを BigQuery 側に取り込んでクエリする方式を採ることで、 BigQuery AI、Gemini Enterprise Agent Platform、マテリアライズドビュー、UDF など、 標準接続では利用できなかった機能に直接アクセスできます。

💡 誰に重要? マルチクラウド環境でデータ分析基盤を運用している組織や、BigQuery Omni のリージョン制約・機能制約に課題を感じていた Solutions Architect、データエンジニアにとって重要なアップデートです。

😣 Before: アップデート前の課題

  • 標準接続は限られた BigQuery Omni リージョン (例: aws-us-east-1、azure-eastus2) に限定
  • Omni リージョンでは BigQuery ML・JavaScript UDF・DML などが利用不可。Blob Storage ではマテリアライズドビューも未サポート
  • Omni リージョンのクエリは別途スロット管理が必要で、既存の標準スロット予約と分離

😀 After: アップデート後の改善

  • すべての BigQuery リージョンで接続を作成し、AWS・Azure・Salesforce Data 360 のデータをクエリ可能
  • BigQuery AI・Gemini Enterprise Agent Platform・マテリアライズドビュー・UDF に直接アクセス可能
  • クエリは標準のスロット予約・コミットメントを消費。別個の容量管理が不要
  • クロスクラウドキャッシュ (オプトイン) で Egress コスト削減とクエリ高速化

AWS・Azure・Salesforce Data 360 のデータが、クロスクラウド接続を経由して任意の BigQuery リージョンに取り込まれ、標準スロットでクエリされるデータフローを示しています。キャッシュを有効化すると、取得済みファイルブロックはローカルリージョンから再利用されます。

⚡ 主要機能

🌐 1. すべての BigQuery リージョンからのクロスクラウドクエリ

✓接続を BigQuery Omni ロケーションではなく、標準の BigQuery ロケーション (例: us-east4、asia-northeast1) に作成
✓データに物理的に近いリージョンを選択することで、コストとパフォーマンスを最適化 (公式ドキュメントにリージョン推奨表あり)

🤖 2. 機能の一貫性 (Feature consistency)

✓他クラウドのデータを BigQuery に取り込むことで、BigQuery AI、Gemini Enterprise Agent Platform、マテリアライズドビュー、UDF など、標準接続 (BigQuery Omni) では利用できない機能に直接アクセス可能

💰 3. コスト効率 (Cost efficiency)

✓ワークロードは標準のスロット予約・コミットメントを消費するため、Omni リージョン用に別個のコンピュート容量を管理する必要がない

⚡ 4. インテリジェントキャッシュ (Intelligent caching)

✓接続で有効化すると、取得したファイルブロックが接続の Google Cloud リージョン内にローカルキャッシュされる
✓同じファイルブロックへの後続クエリはローカルキャッシュから読み取るため、クロスクラウド Egress コストの削減とクエリ高速化に寄与
✓容量・保持・エビクションは Google が自動管理し、追加料金なし
✓キャッシュ提供前に毎回リモートストレージとメタデータ・アクセス権限を検証するため、古いデータの読み取りや失効済み権限のバイパスは発生しない
✓デフォルトでは無効 (オプトイン)。同日に Lakehouse のクロスクラウドデータアクセス向けキャッシュも GA

ステップ 1: 接続の作成 (AWS の例)

Bash クロスクラウド接続の作成 (キャッシュ有効化) 
bq mk --connection \
  --connection_type='AWS' \
  --location=LOCATION \
  --project_id=PROJECT_ID \
  --properties='{"accessRole":{"iamRoleId":"arn:aws:iam::AWS_ACCOUNT_ID:role/ROLE_NAME"},"crossCloudCacheOptions":{"enabled":true}}' \
  CONNECTION_ID
💡 ポイント: LOCATION には BigQuery Omni ロケーションではなく、標準の BigQuery ロケーション (例: us-east4) を指定します。crossCloudCacheOptions.enabled でクロスクラウドキャッシュを有効化できます (デフォルトは false)。

ステップ 2: サービスアカウント情報の確認と信頼ポリシーの追加

Bash 接続のサービスアカウント情報を確認 
bq show --connection \
  --location=LOCATION \
  PROJECT_ID.LOCATION.CONNECTION_ID

表示されたサービスアカウント情報を使用して、AWS ロールに信頼ポリシーを追加します (Azure の場合はフェデレーション認証情報を追加)。

ステップ 3: 外部テーブルの作成とクエリ (Azure の例)

SQL 標準 BigQuery ロケーションに外部テーブルを作成 
CREATE SCHEMA `my-project.azure_raw_data` OPTIONS (location = 'us-east4');

CREATE EXTERNAL TABLE `my-project.azure_raw_data.sales_parquet`
WITH CONNECTION `us-east4.my-azure-connection`
OPTIONS (
  format = 'PARQUET',
  uris = ['azure://mystorageaccount.blob.core.windows.net/mycontainer/sales/year=2025/*']
);
💡 Salesforce Data 360 の場合: リンクされたデータセットを BigQuery Omni ロケーションではなく標準の BigQuery ロケーションに作成します。新しいデータセットへクエリを移行した後は、レガシーのリンク済みデータセットや BigQuery Omni マテリアライズドビューを削除できます。

✨ メリット

💼 ビジネス面

✓マルチクラウドデータの活用範囲拡大: Omni リージョンの制約を受けず、すべての BigQuery リージョンで AWS・Azure・Salesforce のデータを分析できる
✓コスト管理の簡素化: 標準のスロット予約・コミットメントに統合され、Omni 用の別容量管理が不要になる
✓Egress コストの削減: インテリジェントキャッシュにより、同一ファイルブロックへの繰り返しアクセスのクロスクラウド Egress を削減できる

⚙️ 技術面

✓BigQuery 機能のフル活用: BigQuery AI、マテリアライズドビュー、UDF など、Omni 標準接続では使えなかった機能をクロスクラウドデータに適用できる
✓キャッシュの整合性保証: キャッシュ提供前に毎回リモート側のメタデータと権限を検証するため、古いデータの読み取りや権限バイパスが発生しない
✓キャッシュ効果の可視化: BigQuery の JobStatistics2 の objectStorageStats (例: cacheBytesRead、objectStorageBytesRead) でキャッシュヒットと Egress 削減効果を確認できる

⚠️ デメリット・制約事項

🚧 制限事項

✗クロスクラウドキャッシュはデフォルトで無効のため、利用には接続作成時または更新時のオプトインが必要
✗キャッシュデータは Google のデフォルト暗号鍵で暗号化され、CMEK (顧客管理の暗号鍵) はクロスクラウドキャッシュでサポートされない。組織で constraints/gcp.restrictNonCmekServices を適用している場合、該当テーブルのキャッシュは自動的に無効化される (クエリ自体はリモート読み取りで実行される)

🤔 考慮すべき点

⚠️キャッシュを有効化すると、リモートファイルのキャッシュコピーがクエリ実行先の Google Cloud リージョンに一時保存されるため、データレジデンシー・コンプライアンス要件 (例: EU のデータを us-east4 からクエリする場合) の確認が必要
⚠️Egress 削減効果はクエリパターン、ソースファイルの変更頻度、キャッシュ保持状況に依存する
⚠️Apache Iceberg カタログを扱う場合や、BigQuery 以外のエンジン (Apache Spark など) からのクエリが必要な場合は、borderless Lakehouse のクロスクラウドデータアクセス機能の利用が推奨されている

🎯 ユースケース

🤖 ユースケース 1: AWS S3 上のデータレイクへの BigQuery AI 適用

シナリオ: Amazon S3 に蓄積された Parquet 形式の販売データに対して、BigQuery AI 関数やマテリアライズドビューを適用したいが、BigQuery Omni 標準接続では機能制約があり実現できなかった。

SQL 実装例 
CREATE EXTERNAL TABLE `my-project.aws_data.sales`
WITH CONNECTION `asia-northeast1.my-aws-connection`
OPTIONS (
  format = 'PARQUET',
  uris = ['s3://my-bucket/sales/*']
);

効果: データ移行パイプラインを構築することなく、BigQuery の AI 機能・マテリアライズドビュー・UDF をクロスクラウドデータに適用できる。

📊 ユースケース 2: Salesforce Data 360 データの任意リージョンでの分析

シナリオ: Salesforce Data 360 のデータを、既存の BigQuery データセットと同じ標準リージョンで統合分析したい。

効果: リンクされたデータセットを標準 BigQuery ロケーションに作成することで、既存データと同一リージョンで分析でき、レガシーのリンク済みデータセットや Omni マテリアライズドビューを整理できる。

📉 ユースケース 3: 繰り返し参照される BI ダッシュボードの Egress コスト削減

シナリオ: Azure Blob Storage 上の同じデータを BI ダッシュボードが繰り返しクエリしており、クロスクラウド Egress コストが嵩んでいる。

効果: 接続でインテリジェントキャッシュを有効化すると、2 回目以降のクエリはローカルキャッシュから読み取られ、Egress コスト削減とクエリ高速化が期待できる。

🌏 利用可能リージョン

✅ すべての BigQuery リージョンからクロスクラウド接続を利用できます (リリースノート記載)。

コストとパフォーマンスの最適化のため、ソースデータに物理的に近い BigQuery リージョンの選択が推奨されています (公式ドキュメントの Region recommendations を参照)。

🔗 関連サービス・機能

☁️ BigQuery Omni

従来の標準接続の実行基盤。リモートリージョンにコンピュートワーカーをデプロイし、データ移動なしでクエリする方式。クロスクラウド接続はその代替となる選択肢。

🧊 Borderless Lakehouse (クロスクラウドデータアクセス)

Apache Iceberg カタログ (AWS Glue、Databricks Unity Catalog、Snowflake Horizon Catalog など) や BigQuery 以外のエンジンが必要な場合の推奨機能。同日にクロスクラウドキャッシュも GA。

🌐 Cross-Cloud Interconnect

クロスクラウドのデータ転送をプライベートネットワーク経由にすることで、Egress コストの削減とレイテンシの安定化を実現するネットワークサービス。

📊 Salesforce Data 360

リンクされたデータセットを介して BigQuery からクエリできる Salesforce のデータ基盤。

🤖 Gemini Enterprise Agent Platform / BigQuery AI

クロスクラウド接続で取り込んだデータに直接適用できる AI 機能。

📝 まとめ

クロスクラウド接続の GA により、AWS・Azure・Salesforce Data 360 のデータを、Omni リージョンの制約なしにすべての BigQuery リージョンからクエリでき、 BigQuery AI やマテリアライズドビューなどのフル機能を適用できるようになりました。

マルチクラウド環境で BigQuery Omni を利用中の場合は、機能要件・リージョン要件・コスト (標準スロットへの統合、インテリジェントキャッシュによる Egress 削減) を比較し、 クロスクラウド接続への移行を検討することをおすすめします。
