Data Studio (Looker Studio) BigQuery Graph Feature

📊 BigQuery コネクタが BigQuery Graph への接続に対応

グラフのメジャーをメトリクスとしてレポートでそのまま活用
リリース日: 2026-10-22

💡 概要

Data Studio (Looker Studio) の BigQuery コネクタが BigQuery Graph への接続に対応しました。 データソース作成時にテーブルやビューと同様にグラフを直接選択できるほか、カスタム SQL クエリでグラフをクエリすることも可能です。 グラフに定義されたメジャー (measure) はメトリクスとして自動インポートされ、チャート・計算フィールド・クエリ結果変数・コントロールで利用できます。

BigQuery Graph は既存テーブルからノードとエッジを定義して関係性をモデリングする機能で、メジャーは結合により行が重複しても KEY 単位で正しく集計されることが保証されます。 データエンジニアがグラフ側で集計定義を一元管理し、レポート作成者はメトリクスとして使うだけでよくなるため、ダブルカウント防止とセマンティクスの一貫性確保に役立ちます。

❌ Before: アップデート前の課題

  • BigQuery コネクタの接続対象はテーブル・ビュー・カスタム SQL のみで、BigQuery Graph を直接選択できなかった
  • グラフに定義したメジャーを Data Studio のメトリクスとして利用する仕組みがなかった
  • 結合で行が重複するデータモデルでは、ダブルカウント対策をレポート作成者が個別に行う必要があった

✅ After: アップデート後の改善

  • テーブル・ビューと並んで BigQuery Graph を直接選択可能に (グラフはアイコンで区別表示)
  • Start Node (走査の起点) を指定でき、フラット化されたテーブルのスキーマを制御できる
  • グラフのメジャーがメトリクスとして自動インポートされ、チャート・計算フィールド等で利用可能
  • カスタム SQL クエリでもグラフに対するクエリを記述できる

BigQuery 上の既存テーブルから定義した BigQuery Graph に、BigQuery コネクタ経由 (直接選択またはカスタム SQL) で接続し、グラフのメジャーをメトリクスとして Data Studio のレポートで利用するデータフローです。

⚙️ 主要機能

🕸️ 1. BigQuery Graph への直接接続

✓データソース作成時の「Table / Graph」リストから、テーブル・ビューと同様にグラフを選択可能
✓データセット内のテーブルとグラフは異なるアイコンで表示され区別できる
✓「Start Node」リストから走査の起点ノードを選択可能。Start Node はフラット化されたテーブルのスキーマに影響し、グラフ定義によっては選択が必須

📐 2. グラフメジャーのメトリクス自動インポート

✓グラフに定義されたメジャーが、データソースのメトリクスとしてインポートされる
✓チャート、計算フィールド、クエリ結果変数、データソース横断のコントロールで利用可能
✗集計タイプは固定: BigQuery 側のグラフ定義で決まり、Data Studio 側では変更不可
✓編集可能なプロパティ: データ型と説明 (description) はデータソース側で編集可能

📝 3. カスタム SQL クエリによるグラフのクエリ

✓CUSTOM QUERY オプションで、BigQuery Graph に対するクエリを含む SQL を記述して接続できる
✓クエリ構文は Standard SQL (GoogleSQL) に準拠
✓BigQuery コンソールで動作確認したクエリをカスタムクエリエディタに貼り付ける方法が推奨

🧪 4. 公開データセットでの試用

✓公開データセット bigquery-public-data.thelook_ecommerce の graph で本機能を試用可能 (SHARED PROJECTS で課金プロジェクトを指定して接続)

🔬 技術仕様

📊 BigQuery Graph のメジャー (measure)

項目詳細
定義場所ノード/エッジテーブル定義の PROPERTIES 句内で MEASURE() キーワードを使用
対応集計関数SUM、AVG、COUNT、MIN、MAX、AGG (派生メジャー用)
DISTINCTAGG 以外の集計関数で DISTINCT キーワードをサポート
集計の粒度定義されたノード/エッジテーブルの KEY を基準に集計され、結合で行が重複しても正しく集計される
SQL からのアクセスGRAPH_EXPAND TVF でリレーショナル表現としてクエリし、メジャー列は AGG() 関数でラップして集計
エディション要件GQL クエリの実行には Enterprise / Enterprise Plus エディションの予約が必要。オンデマンド料金では GRAPH_EXPAND による SQL クエリを利用可能

💻 メジャー定義の例 (BigQuery 側)

SQL プロパティグラフでのメジャー定義 
CREATE OR REPLACE PROPERTY GRAPH university.SchoolGraph
  NODE TABLES (
    university.Department
      KEY(dept_id)
      PROPERTIES(dept_id, dept_name, budget,
        MEASURE(SUM(budget)) AS total_budget),
    ...
  )
  EDGE TABLES (...);

🔐 必要な IAM ロール

ロール用途
BigQuery データ閲覧者
roles/bigquery.dataViewer		テーブル・ビュー・グラフのデータとメタデータの読み取り
BigQuery ジョブユーザー
roles/bigquery.jobUser		課金プロジェクトでのクエリジョブの実行
💡 ヒント: 認証情報モードがオーナーの認証情報 (デフォルト) の場合、これらのロールが必要なのはデータソースのオーナーのみ。レポート閲覧者は自身の BigQuery アクセス権なしでチャートを閲覧できます。

🛠️ 設定方法

✅ 前提条件

✓Google Cloud 請求先アカウントに関連付けられたプロジェクトがあること
✓IAM ロール (BigQuery データ閲覧者、BigQuery ジョブユーザー) が付与されていること
✓接続対象の BigQuery Graph (CREATE PROPERTY GRAPH) が作成済みであること

🪜 手順 (グラフへの直接接続)

  1. データソースの作成 — Data Studio でデータソースを作成し、BigQuery コネクタを選択
  2. プロジェクト・データセット・グラフの選択 — プロジェクト (RECENT / MY / SHARED PROJECTS) とデータセットを選び、「Table / Graph」リストからグラフを選択。必要に応じて「Start Node」から起点ノードを選択
  3. レポートでメトリクスとして利用 — インポートされたメジャーをチャートや計算フィールドで利用

📝 手順 (カスタム SQL クエリでの接続)

CUSTOM QUERY オプションを選択し、BigQuery コンソールで検証済みのグラフクエリを貼り付けます。メジャーを SQL から扱う場合は GRAPH_EXPAND TVF と AGG() 関数を使用します。

SQL GRAPH_EXPAND でメジャーを集計するクエリ例 
SELECT
  College_college_name,
  AGG(Department_total_budget) AS college_budget
FROM GRAPH_EXPAND("university.SchoolGraph")
GROUP BY College_college_name;

🎯 メリット

💼 ビジネス面

✓セマンティクスの一元管理: 集計ロジックをグラフ定義に集約し、レポート作成者ごとの集計定義のばらつきを防止
✓集計ミスの防止: KEY 基準の集計により結合による行重複でもダブルカウントせず、数値の信頼性が向上
✓BI 民主化: 顧客・取引・サプライチェーンなどの関係性データを、無料の Looker Studio レポートで広く共有

⚙️ 技術面

✓ETL 不要: 中間テーブル展開パイプラインを作らなくても、コネクタがグラフをフラット化スキーマとして扱える
✓Start Node によるスキーマ制御: 走査起点の選択でレポート用途に合わせたフラット化スキーマを取得
✓カスタム SQL との併用: 直接接続と GRAPH_EXPAND などの柔軟なカスタムクエリを使い分け可能

⚠️ デメリット・制約事項

🚧 制限事項

✗グラフメジャーの集計タイプは BigQuery 側のグラフ定義で固定され、Data Studio 側では変更不可 (編集できるのはデータ型と説明のみ)
✗メジャー機能は、特定の BigQuery エディションで作成された予約では利用できない場合がある
✗GQL クエリの実行には Enterprise / Enterprise Plus エディションの予約が必要 (オンデマンドの場合は GRAPH_EXPAND による SQL クエリを使用)
✗GRAPH_EXPAND には入力制限がある (例: 多対多の中間テーブルをエッジテーブルとしてモデリングするとエッジが無視される)

🤔 考慮すべき点

⚠️ 注意: Data Studio 経由の BigQuery アクセスにはクエリ処理コストが発生し得るため、課金プロジェクトの設計 (データ参照プロジェクトと課金プロジェクトの分離など) を検討してください。公開データセット bigquery-public-data.thelook_ecommerce の graph で事前に動作確認してから本番データに適用するのがおすすめです。

💼 ユースケース

🛒 ユースケース 1: e コマースの顧客・注文分析レポート

シナリオ: 顧客・注文・商品の関係を BigQuery Graph でモデリングし、売上合計や注文数などのメジャーを定義。マーケティングチームが Looker Studio のダッシュボードで利用する。

  1. BigQuery で CREATE PROPERTY GRAPH により顧客-注文-商品のグラフを作成し、MEASURE(SUM(sale_price)) AS total_sales などのメジャーを定義
  2. Looker Studio の BigQuery コネクタでグラフを選択し、Start Node を指定
  3. インポートされた total_sales メトリクスをチャートに配置
✅ 効果: 結合による売上のダブルカウントを防ぎつつ、レポート作成者は集計ロジックを意識せずにメトリクスを利用できる。

🧪 ユースケース 2: 公開データセットでの機能検証

シナリオ: 本番導入前に、公開データセット bigquery-public-data.thelook_ecommerce の graph に接続して、グラフ接続とメジャーのインポート動作を検証する。

✅ 効果: 自社データのグラフ化に先立ち、コネクタの挙動 (Start Node 選択、メトリクスのインポート、固定集計) を低リスクで確認できる。

💰 料金

Looker Studio (Data Studio) 自体のこの機能に追加料金はありません。 ただし BigQuery は有料の分析プラットフォームであり、レポート経由で BigQuery データにアクセスするとクエリ処理コストが発生する場合があります。 また、GQL クエリの実行には Enterprise または Enterprise Plus エディションの予約が必要です。

詳細は BigQuery の料金ページ を参照してください。

🔗 関連サービス・機能

🕸️ BigQuery Graph — 既存テーブルからノードとエッジを定義して関係性をモデリング。GQL (ISO 標準のグラフクエリ言語) と SQL の両方で操作でき、本アップデートの接続対象。
📐 BigQuery グラフメジャー — ノード/エッジに定義する集計プロパティ。本アップデートで Data Studio のメトリクスとしてインポート可能に。
🌐 Spanner Graph — BigQuery Graph と同じグラフスキーマ・クエリ言語を共有。運用系グラフワークロードを Spanner、分析を BigQuery で実行する構成が可能。
📊 Looker (LookML) — sql_analytic_model_name パラメータで BigQuery Graph を LookML Explore の基盤に利用可能。ガバナンスされたセマンティックレイヤーが必要な場合の選択肢。
💬 BigQuery Conversational Analytics — グラフに対して自然言語で質問でき、エージェントがグラフ定義のメジャーを利用して回答品質を向上。

📝 まとめ

BigQuery Graph でモデリングした関係性データとメジャーを、Looker Studio のレポートでそのままメトリクスとして利用可能になり、 集計ロジックの一元管理とダブルカウント防止を BI レイヤーまで一貫して実現できます。

🚀 次のアクション: まずは公開データセット thelook_ecommerce の graph で接続とメジャーのインポートを試し、自社のグラフモデルへの適用を検討することを推奨します。
