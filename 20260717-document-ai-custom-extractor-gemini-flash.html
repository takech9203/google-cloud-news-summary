🔍 概要

Google Cloud Document AI の Custom Extractor に、最新の Gemini 3.5 Flash LLM を搭載した新しいプロセッサバージョン pretrained-foundation-model-v3.5-2026-05-26 が Preview として利用可能になりました。

ゼロショットおよびフューショット学習による高精度な情報抽出が可能で、請求書、契約書、身分証明書など多様なドキュメントからの自動データ抽出を実現します。

🤖 Gemini 3.5 Flash とは: Google の最新世代の高速 LLM。従来の Gemini 3 Flash (v1.6) からの世代交代により、抽出精度と処理速度の両面で改善が見込まれます。

🔧 設定方法

前提条件: Google Cloud プロジェクトで課金が有効、Document AI API が有効、IAM 権限 (roles/documentai.editor 以上) が付与されていること。

ステップ 1: Document AI API の有効化

Bash API 有効化 
gcloud services enable documentai.googleapis.com --project=PROJECT_ID

ステップ 2: Custom Extractor プロセッサの作成

Bash プロセッサ作成 (US リージョン) 
curl -X POST \
  -H "Authorization: Bearer $(gcloud auth print-access-token)" \
  -H "Content-Type: application/json" \
  -d '{
    "type": "CUSTOM_EXTRACTION_PROCESSOR",
    "displayName": "my-custom-extractor-v35"
  }' \
  "https://us-documentai.googleapis.com/v1/projects/PROJECT_ID/locations/us/processors"

ステップ 3: デフォルトバージョンの変更

Bash デフォルトバージョンを v3.5 に設定 
curl -X POST \
  -H "Authorization: Bearer $(gcloud auth print-access-token)" \
  -H "Content-Type: application/json" \
  -d '{
    "processorVersion": "projects/PROJECT_ID/locations/us/processors/PROCESSOR_ID/processorVersions/pretrained-foundation-model-v3.5-2026-05-26"
  }' \
  "https://us-documentai.googleapis.com/v1/projects/PROJECT_ID/locations/us/processors/PROCESSOR_ID:setDefaultProcessorVersion"

ステップ 4: ドキュメント処理リクエスト

Bash ドキュメント処理実行 
curl -X POST \
  -H "Authorization: Bearer $(gcloud auth print-access-token)" \
  -H "Content-Type: application/json" \
  -d '{
    "rawDocument": {
      "content": "BASE64_ENCODED_DOCUMENT",
      "mimeType": "application/pdf"
    }
  }' \
  "https://us-documentai.googleapis.com/v1/projects/PROJECT_ID/locations/us/processors/PROCESSOR_ID/processorVersions/pretrained-foundation-model-v3.5-2026-05-26:process"

⚠️ デメリット・制約事項

制限事項:
  • Preview (Release Candidate) ステータスのため、本番環境での利用にはリスクあり。SLA は適用されない
  • ファインチューニングは現時点で非対応。精度向上はフューショット学習に限られる
  • Confidence Score のサポートについて明示的な記載なし (v1.4, v1.5, v1.5 Pro のみ記載)
考慮すべき点:
  • Preview から GA 移行時にモデル挙動が変わる可能性
  • クォータはデフォルト 120 ページ/分が適用される可能性が高い
  • Data Residency (DMZ) 準拠の明確な記載がないため、厳格な要件がある場合は確認が必要
  • v1.5 (Stable) からの移行ではファインチューニング機能が失われる点に注意

💡 ユースケース

📑 ユースケース 1: 請求書からの自動データ抽出

経理部門が毎月大量の請求書を処理するシナリオ。フォーマットが統一されていない取引先からの請求書にも対応。ゼロショットでの抽出により、新規取引先のフォーマットにも即座に対応可能。

      {"name": "vendor_name", "baseTypes": ["string"], "description": "請求元の会社名"},

📋 ユースケース 2: 契約書の重要条項抽出

法務部門が大量の契約書レビューを実施。解約条件、責任制限、秘密保持期間などの重要条項を効率的に抽出。Gemini 3.5 Flash の高度な言語理解能力により、法的文書の複雑な表現からも的確に情報を抽出。3 段階ネスト機能で契約書の入れ子構造 (条項 > 項 > 号) にも対応。

🌐 ユースケース 3: 多言語ドキュメントの構造化

グローバル企業が各国の税務書類や証明書を一元管理。Gemini 3.5 Flash の多言語対応能力を活かし、英語・日本語・ドイツ語・フランス語など多言語のドキュメントを統一スキーマで処理可能。
