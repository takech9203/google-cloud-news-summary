📋 概要

GKE の Managed OpenTelemetry が、LangGraph ReAct エージェントおよびAgent Development Kit (ADK)フレームワークで構築された生成 AI エージェントからのマルチモーダルプロンプトとレスポンスの収集をサポートしました。

テキスト、画像、音声、動画、ドキュメントなど多様なメディアタイプのプロンプトとレスポンスを自動的にキャプチャし、Cloud Trace Explorer および BigQuery で可視化・分析できます。OpenTelemetry GenAI セマンティック規約 (v1.37.0 以降) に準拠し、アプリケーションコードの変更なしでデータ収集を開始できる点が大きな特長です。

🤖 ポイント: Instrumentation カスタムリソースの設定だけで、AI エージェントの入出力を全量記録。Cloud Storage に JSON Lines 形式で保存され、Trace Explorer と BigQuery で多角的に分析可能。

🔄 Before / After 比較

❌ Before (従来)

  • AI エージェントのプロンプト/レスポンスを体系的に収集する仕組みがない
  • マルチモーダルデータの記録には独自ロギング実装が必要
  • BigQuery 等の分析基盤との連携に複雑なパイプライン構築が必要

✅ After (新機能)

  • Instrumentation CR 設定のみでマルチモーダルデータを自動収集
  • Trace Explorer でチャット形式の可視化・レンダリング/ソース切替
  • BigQuery 連携で AI.GENERATE による会話要約や高度な分析が可能

🚀 設定方法

📝 前提条件:
  • GKE クラスタで Managed OpenTelemetry が有効化されていること
  • Cloud Storage バケットが作成済みであること
  • アプリケーション SA に storage.objects.create 権限が付与されていること

Step 1: Instrumentation カスタムリソースの作成

YAML 
apiVersion: telemetry.googleapis.com/v1alpha1
kind: Instrumentation
metadata:
  namespace: default
  name: prompts-responses
spec:
  selector: {}
  promptsResponses:
    uploadBasePath: gs://BUCKET_NAME

Step 2: ADK エージェントの追加設定

Bash 
# CLI 経由で ADK を実行する場合
adk web --otel_to_cloud

# FastAPI アプリケーションの場合
# get_fast_api_app(..., otel_to_cloud=True)

Step 3: ワークロードの再デプロイ

Bash 
# ワークロードを再起動して環境変数の注入を適用
kubectl rollout restart deployment/<YOUR_DEPLOYMENT> -n default

Step 4: Trace Explorer での確認

⚠️ デメリット・制約事項

制限事項:
  • Preview 段階のため SLA 対象外 - 本番環境での利用には注意が必要
  • 対応フレームワークは LangGraph ReAct エージェントと ADK に限定
  • fsspec のバージョン制約 (== 2025.10.0) があり全バージョン対応ではない
考慮すべき点:
  • マルチモーダルデータの Cloud Storage 保存によりストレージコスト増加の可能性
  • 大量プロンプト・レスポンスデータの保存はコスト面での検討が必要
  • Cloud Storage バケットのアクセス権限管理で機密データ漏洩防止が必要
  • BigQuery 分析には追加の API 有効化と IAM ロール設定が必要

💡 ユースケース

🎧 ユースケース 1: AI カスタマーサポートエージェントのモニタリング

シナリオ: GKE 上で稼働する ADK ベースのカスタマーサポートエージェントが、製品不具合写真等のマルチモーダルなやり取りを処理。サポート品質の継続的な改善のため全やり取りを記録・分析。

効果: 画像を含むユーザー問い合わせとエージェント回答を全量記録し、BigQuery で回答品質の傾向分析や AI.GENERATE による要約を実行、改善サイクルを確立。

YAML 
apiVersion: telemetry.googleapis.com/v1alpha1
kind: Instrumentation
metadata:
  namespace: support-agents
  name: support-prompts-collection
spec:
  selector:
    matchLabels:
      app: customer-support-agent
  promptsResponses:
    uploadBasePath: gs://support-agent-traces

🔬 ユースケース 2: LangGraph マルチモーダル RAG パイプラインのデバッグ

シナリオ: LangGraph で構築されたマルチモーダル RAG パイプラインがドキュメント画像から情報抽出して回答生成。特定入力画像に対する不正確な回答の原因調査。

効果: Trace Explorer で問題リクエストのスパンを特定し、入力画像とモデル出力を並べて確認、情報損失/誤解釈の発生ステップを迅速に特定。

📈 ユースケース 3: エージェント出力の自動品質評価

シナリオ: 複数の ADK エージェントが本番環境で稼働しており、出力品質を自動的に評価して品質低下を検知したい。

効果: BigQuery に蓄積されたデータに対し Vertex AI SDK を使用した自動評価 (センチメント分析、正確性チェック) を定期実行し、品質スコア低下をアラートとして検知。

📝 まとめ

GKE Managed OpenTelemetry のマルチモーダルプロンプト・レスポンス収集機能は、GKE 上で稼働する AI エージェントのオブザーバビリティを根本的に変革するアップデートです。LangGraph や ADK で構築されたエージェントの入出力を、コード変更なしで自動収集し、Trace Explorer での可視化や BigQuery での高度な分析を可能にします。

推奨アクション: AI エージェントを本番運用しているチームは、Preview 段階から検証を開始し、品質管理やデバッグのワークフローへの組み込みを検討することを推奨します。
