🧠 Knowledge Catalog: lookupContext

エージェント向けデータアセットコンテキスト取得

2026-06-04
Preview Knowledge Catalog

📋 概要

Google Cloud Knowledge Catalog に新しい lookupContext メソッドがプレビューとして追加されました。AI エージェントがエンタープライズデータの包括的なコンテキスト（スキーマ、説明、ビジネスアノテーション、データ品質インサイト、リレーションシップなど）を単一の API 呼び出しで取得し、LLM のグラウンディングに活用できます。

🤖 対象ユーザー: LangChain / Agent Development Kit (ADK) でカスタムエージェントを構築する AI 開発者、エンタープライズデータとの対話を必要とするエージェントビルダー、MCP 対応ツールを活用するデータプラットフォームチーム

Before / After

❌ Before

  • 複数の API 呼び出しでスキーマ、説明、品質情報を個別に収集
  • 取得メタデータを LLM 向けに手動変換・整形
  • リレーションシップやビジネスコンテキストの統一取得手段がない

✅ After

  • 単一 API で LLM 最適化済みコンテキストを取得

🏗️ アーキテクチャ図

AI エージェントが Knowledge Catalog の searchEntries で関連データアセットを発見し、lookupContext で LLM に最適化されたコンテキストを取得する一連のフローです。

sequenceDiagram
    participant Agent as AI エージェント
    participant KC as Knowledge Catalog
(CatalogService)
    participant DS as データソース
(BigQuery, Spanner 等)

    Agent->>KC: searchEntries(query)
    KC-->>Agent: 検索結果 (entry names)
    Agent->>KC: lookupContext(resources)
    KC->>DS: メタデータ収集
    DS-->>KC: スキーマ/品質/リネージ
    KC-->>Agent: LLM-ready コンテキスト (YAML/JSON/XML)
    Agent->>Agent: コンテキストで LLM をグラウンディング
    Agent-->>Agent: 正確なデータ操作を実行

⚡ 主要機能

📦 LLM-ready コンテキストの一括取得

  • 単一 API 呼び出しで最大 10 リソースのコンテキストを同時に取得
  • スキーマ、説明文、ビジネスアノテーション、データ品質インサイト、リレーションシップを包括的に含む
  • 出力フォーマット: YAML (デフォルト)、JSON、XML から選択可能

🎯 コンテキストバジェット制御

  • context_budget オプションで出力文字数を概算制御
  • LLM のトークン制限に合わせてインテリジェントに切り詰め
  • all_schema_fields オプションで全スキーマフィールド返却を強制可能

🛠️ 設定方法

📋 前提条件:
  • Google Cloud プロジェクトで Dataplex API が有効化されていること
  • 適切な IAM ロール (roles/dataplex.catalogViewer 以上) が付与されていること
  • 対象データアセットが Knowledge Catalog に登録済みであること

Step 1: gcloud CLI を使用したコンテキスト取得

Bash gcloud CLI でのコンテキスト取得 
gcloud alpha dataplex context lookup \
  --location=us-central1 \
  --project=my-project \
  --resources=projects/my-project/locations/us-central1/entryGroups/@bigquery/entries/bigquery.googleapis.com/projects/my-project/datasets/my_dataset/tables/my_table

Step 2: Python SDK を使用したエージェント統合

Python CatalogService クライアントによる lookupContext 
from google.cloud import dataplex_v1

# CatalogService クライアントの初期化
client = dataplex_v1.CatalogServiceClient(
    client_options={"api_endpoint": "dataplex.googleapis.com"}
)

# LookupContext リクエストの実行
parent_name = "projects/my-project/locations/us-central1"
lookup_request = {
    "name": parent_name,
    "resources": [
        "projects/my-project/locations/us-central1/entryGroups/@bigquery/entries/bigquery.googleapis.com/projects/my-project/datasets/sales/tables/orders"
    ]
}

response = client.lookup_context(request=lookup_request)

# LLM にコンテキストを提供
llm_context = response.context

Step 3: MCP 経由でのアクセス (Remote MCP Server)

Bash Remote MCP Server 経由の呼び出し 
curl --location 'https://dataplex.googleapis.com/mcp' \
  --header 'content-type: application/json' \
  --header 'accept: application/json, text/event-stream' \
  --header 'Authorization: Bearer $(gcloud auth print-access-token)' \
  --data '{
    "method": "tools/call",
    "params": {
      "name": "lookup_context",
      "arguments": {
        "projectId": "my-project",
        "location": "us-central1",
        "resources": [
          "projects/my-project/locations/us-central1/entryGroups/@bigquery/entries/bigquery.googleapis.com/projects/my-project/datasets/sales/tables/orders"
        ]
      }
    },
    "jsonrpc": "2.0",
    "id": 1
  }'

MCP 対応ツール (Gemini CLI, Claude Code, Cursor, VS Code 等) からも直接呼び出し可能です。

💡 ユースケース

🔍 ユースケース 1: SQL クエリ生成エージェント

データアナリストが自然言語で「国別のユーザー数を集計して」と依頼 → エージェントが適切なテーブルを特定し正確な SQL を生成

Python SQL クエリ生成エージェントの実装例 
# 1. セマンティック検索でテーブルを発見
search_response = client.search_entries(
    request={
        "name": parent_name,
        "query": "users country",
        "semantic_search": True,
    }
)

# 2. lookupContext で詳細コンテキストを取得
for result in search_response.results:
    context_response = client.lookup_context(
        request={
            "name": parent_name,
            "resources": [result.dataplex_entry.name]
        }
    )
    # 3. LLM にコンテキストを提供して SQL 生成
    sql = llm.generate(
        prompt=f"Context:\n{context_response.context}\n\nGenerate SQL to count users by country."
    )

効果: テーブル名、カラム名、データ型を正確に把握した SQL 生成によりハルシネーションを大幅に低減

🔧 ユースケース 2: データパイプライン構築支援エージェント

データエンジニアが「products テーブルのクリーニングパイプラインを作成して」と依頼 → テーブルのスキーマ、品質ルール、リネージを考慮したパイプラインコードを生成

効果: データ品質ルールやビジネスアノテーションを考慮した、ガバナンスに準拠したパイプラインの自動生成が可能

📊 メリットと制約事項

✅ ビジネス面のメリット

✓ エージェント開発の迅速化 - 複雑なロジック構築が不要
✓ データガバナンスの維持 - IAM ベースのアクセス制御
✓ 信頼性の向上 - ハルシネーション低減

⚡ 技術面のメリット

✓ 統一 API - REST / gcloud / MCP の 3 パターン対応
✓ 最適化フォーマット - LLM 直接消費可能、前処理不要
✓ バジェット制御 - トークン制限を考慮した切り詰め

⚠️ 制約事項・考慮点

⚠ Preview ステータス - GA 前に API 変更の可能性あり
⚠ 1 リクエストあたり最大 10 リソースに制限
⚠ context_budget は概算値 - 正確な文字数制御は非保証
⚠ エージェントのサービスアカウントに適切な権限設定が必要
⚠ コンテキストの鮮度はメタデータハーベスティング頻度に依存
⚠ Preview 段階のため本番ワークロードでの使用は SLA 観点で要検討

📝 まとめ

Knowledge Catalog の lookupContext メソッドは、AI エージェントがエンタープライズデータを正確に理解し活用するための重要な基盤機能です。単一の API 呼び出しで LLM に最適化されたコンテキストを取得できるため、エージェント開発の複雑さを大幅に軽減し、グラウンディングによる信頼性の高いデータ操作を実現します。

💡 推奨アクション: Preview 段階ですが、エージェント開発を進めているチームは早期に評価を開始し、データガバナンスとの統合パターンを検討することを推奨します。
