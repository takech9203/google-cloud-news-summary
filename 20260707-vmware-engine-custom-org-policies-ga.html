🛡️ VMware Engine: カスタム組織ポリシー制約が GA

Google Cloud VMware Engine GA
2026-07-07

📋 概要

Google Cloud VMware Engine において、カスタム組織ポリシー制約 (Custom Organization Policy Constraints) が一般提供 (GA) となりました。組織管理者は VMware Engine リソースに対して独自のセキュリティポリシーを定義・適用し、リソースの構成を細かく制御できるようになります。

Common Expression Language (CEL) を使用して独自の条件式を定義し、VMware Engine リソースの特定フィールドに対する制約を作成できます。これにより、組織全体でセキュリティ基準やコンプライアンス要件を一貫して適用することが可能になります。

💡 対象ユーザー: VMware Engine を利用する企業のクラウド管理者、セキュリティチーム、およびガバナンス担当者。特に、複数のプロジェクトやフォルダにまたがる VMware Engine 環境を運用し、統一的なポリシー管理が必要な組織。

⚡ 主要機能

📝 カスタム制約の作成

YAML ファイルまたは Cloud Console から独自の制約を定義可能。CEL による柔軟な条件式の記述をサポート。ALLOW / DENY の 2 種類のアクションタイプに対応。

🗂️ 8 種類のリソースタイプ

PrivateCloud、Cluster、ExternalAccessRule、ExternalAddress、NetworkPeering、NetworkPolicy、PrivateConnection、VmwareEngineNetwork に対応。

🔗 ポリシー継承と階層管理

組織・フォルダ・プロジェクトの各レベルでポリシーを適用。上位レベルで設定されたポリシーは下位に自動継承。継承ルールのカスタマイズも可能。

🧪 ドライランモード

ポリシーの影響を本番適用前に検証可能。Policy Simulator でテスト変更のシミュレーションが可能。安全なポリシー導入を実現。

📄 カスタム制約の定義例

以下は、プライベートクラウドの管理 CIDR 範囲を制限するカスタム制約の YAML 定義例です。

YAML 
name: organizations/ORGANIZATION_ID/customConstraints/custom.privateCloudManagementCidr
resourceTypes:
  - vmwareengine.googleapis.com/PrivateCloud
methodTypes:
  - CREATE
condition: "!resource.managementCidr.startsWith('192.168.0.0')"
actionType: DENY
displayName: Restrict private cloud management CIDR
description: Private clouds must have a management CIDR range starting with 192.168.0.0.

🚀 設定方法

前提条件

✓Google Cloud 組織が設定されていること
✓Organization Policy Administrator (roles/orgpolicy.policyAdmin) IAM ロールが付与されていること
✓組織 ID を確認済みであること

ステップ 1: カスタム制約の定義

Bash 
# constraint.yaml ファイルを作成
cat > constraint.yaml << 'EOF'
name: organizations/123456789/customConstraints/custom.privateCloudManagementCidr
resourceTypes:
  - vmwareengine.googleapis.com/PrivateCloud
methodTypes:
  - CREATE
condition: "!resource.managementCidr.startsWith('192.168.0.0')"
actionType: DENY
displayName: Restrict private cloud management CIDR
description: Private clouds must have a management CIDR range starting with 192.168.0.0.
EOF

ステップ 2: カスタム制約の登録

Bash 
# カスタム制約を組織に登録
gcloud org-policies set-custom-constraint constraint.yaml

ステップ 3: 組織ポリシーの作成と適用 (ドライラン)

Bash 
# policy.yaml ファイルを作成
cat > policy.yaml << 'EOF'
name: projects/PROJECT_ID/policies/custom.privateCloudManagementCidr
spec:
  rules:
    - enforce: true
dryRunSpec:
  rules:
    - enforce: true
EOF

# ドライランモードで先にテスト
gcloud org-policies set-policy policy.yaml --update-mask=dryRunSpec

ステップ 4: 本番ポリシーの適用

Bash 
# 本番ポリシーを適用
gcloud org-policies set-policy policy.yaml --update-mask=spec

ステップ 5: 制約の確認

Bash 
# 登録済みカスタム制約の一覧確認
gcloud org-policies list-custom-constraints --organization=ORGANIZATION_ID
⚠️ 注意: ポリシーの反映には最大 15 分かかります。ドライランで問題がないことを確認してから本番適用してください。

💼 ユースケース

🌐 ユースケース 1: 管理 CIDR 範囲の標準化

シナリオ: ネットワークチームが、すべての VMware Engine プライベートクラウドの管理 CIDR 範囲を特定のアドレス空間に限定し、オンプレミスネットワークとの競合を防止。

効果: すべてのプライベートクラウドが統一されたアドレス空間を使用し、ネットワーク設計の一貫性が保たれる。

🔒 ユースケース 2: 外部アクセスルールのセキュリティ強制

シナリオ: セキュリティチームが、外部アクセスルールで特定のプロトコル使用を制限し、不正なネットワークアクセスを防止。TCP/UDP のみを許可。

効果: 許可されたプロトコルのみが使用され、セキュリティ基準に準拠した通信制御が自動的に実施される。

⚙️ ユースケース 3: クラスタサイズの最小構成強制

シナリオ: 運用チームが、本番環境のクラスタが常に最低 3 ノードを確保し、可用性要件を満たすことを保証。

効果: すべてのクラスタが最低 3 ノード構成となり、高可用性の要件が組織全体で保証される。

⚠️ 制約事項・注意点

制限事項

!リソースタイプあたりのカスタム制約数は最大 20 個に制限
!ポリシーの反映に最大 15 分の遅延が発生する可能性
!CEL 条件式は最大 1,000 文字に制限
!UPDATE メソッドで制約適用した場合、既存の違反リソースの変更操作は違反解消の変更以外ブロック

考慮すべき点

!過度に厳格な制約は正当な運用作業をブロックする可能性 - ドライランモードでの事前検証が重要
!ポリシー階層の設計を慎重に行わないと、意図しない継承による問題が発生する可能性
!Organization Policy Administrator ロールの付与範囲を適切に管理する必要あり

💰 料金情報

✅ 追加料金なし: カスタム組織ポリシー制約の機能自体には追加料金は発生しません。Organization Policy Service は Google Cloud の無料のガバナンス機能として提供されています。ただし、VMware Engine リソース自体の利用料金は通常通り発生します。

🌍 利用可能リージョン

カスタム組織ポリシー制約は、Google Cloud VMware Engine が利用可能なすべてのリージョンで使用できます。組織ポリシーはグローバルサービスであり、リージョンに依存せずに適用されます。
