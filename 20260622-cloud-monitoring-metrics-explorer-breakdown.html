📊 Cloud Monitoring: Metrics Explorer
チャートのラベル別ブレイクダウン機能

Cloud Monitoring GA
2026-06-22

🔍 概要

Metrics Explorer にラベル別ブレイクダウン機能が追加されました。集約チャートでは隠れてしまうスパイク、ディップ、トレンドを、ラベルキーごとの個別タイルとして表示し、インシデントの根本原因を迅速に特定できます。

対象ユーザー: SRE、DevOps エンジニア、プラットフォームエンジニア

🔄 Before / After

❌ Before (従来)

  • 集約チャートで個別リソースのスパイクが隠蔽
  • 手動フィルタの追加で個別確認が必要
  • MTTR (平均修復時間) が長期化

✅ After (新機能)

  • ボタン一つでラベルキー別タイルグリッド表示
  • タイルから直接フィルタ適用でドリルダウン
  • 隠れた異常パターンを視覚的に即座把握

🏗️ アーキテクチャ図

Metrics Explorer のブレイクダウン機能は、集約チャートからラベルキー別タイル、さらにラベル値別の詳細タイルへとドリルダウンし、最終的にフィルタとして Metrics Explorer に反映するワークフローを提供します。

⚡ 主要機能

📐 ラベルキー別タイルグリッド表示

「Show breakdown」選択でスプリットスクリーンに切り替え。左に元のチャート、右にラベルキーごとのタイルコレクションを表示

🔎 ラベル値別ドリルダウン

タイル上の「Breakdown」ボタンで特定ラベルキーの各値を個別タイルに展開。スパイクやディップを即座に発見

🎯 インタラクティブなフィルタ適用

「Add Filter」選択でラベル値をクエリにフィルタ追加。フィルタの追加・削除はチャートに即座反映

💾 カスタムダッシュボード保存

ブレイクダウン分析中のチャートをカスタムダッシュボードに保存可能。適用フィルタは維持

🛠️ 設定方法

💡 前提条件: Cloud Monitoring が有効 / roles/monitoring.viewer 以上の IAM ロール / メトリックデータ収集済み
  1. Metrics Explorer を開く
    Google Cloud Console > Monitoring > Metrics Explorer に移動し、メトリックを選択してラインチャートを表示
  2. ブレイクダウンを表示
    ツールバーで「Show breakdown」を選択。スプリットスクリーンにラベルキーごとのタイルが表示
  3. ラベルキーを選択してドリルダウン
    タイル上の「Breakdown」ボタンで特定のラベルキー (例: zone) にドリルダウン
  4. フィルタを適用
    異常が見られるタイルの「Add Filter」を選択し、クエリにフィルタを追加
  5. 元の画面に戻る
    「Close breakdown」で Metrics Explorer に戻る (フィルタは維持)

✅ メリット

💼 ビジネス面

→MTTR の短縮: 根本原因を迅速に特定し障害復旧時間を短縮
→運用効率の向上: 手動フィルタ試行錯誤を削減しチーム生産性向上

🔧 技術面

→隠れた異常の可視化: 集約で隠蔽されたスパイクをラベル単位で確認
→インタラクティブ分析: タイルからフィルタを直接適用
→ノーコード分析: GUI 操作だけで多次元メトリック分析

⚠️ デメリット・制約事項

制限事項:
  • ラインチャートのみ対応 (ヒートマップ、積み上げ棒グラフなどは不可)
  • スプリットスクリーン表示自体のダッシュボード保存は不可
  • フィルタはブレイクダウン終了後も残るため注意が必要
考慮すべき点:
  • ラベルのカーディナリティが高い場合 (数百のラベル値)、タイル数が多くなり視認性が低下する可能性
  • ブレイクダウンは一時的な調査ツール。常時表示ダッシュボードにはフィルタ適用後のチャートを保存する運用が必要

🎯 ユースケース

🌏 ユースケース 1: リージョン別のレイテンシスパイク調査

シナリオ: Cloud Load Balancing のバックエンドレイテンシが全体平均で上昇しているアラートを受信。全リージョンの平均値を見てもどのリージョンが問題か不明。

→ zone ラベルでブレイクダウンし、asia-northeast1-a でのみレイテンシ急上昇を即座に発見。フィルタ適用で詳細分析に移行

💻 ユースケース 2: マシンタイプ別の CPU 使用率分析

シナリオ: GCE インスタンスの CPU 使用率が集約チャートでは安定して見えるが、特定マシンタイプで問題がないか確認したい。

→ machine_type ラベルでブレイクダウンし、e2-micro のみ CPU 100% 張り付きを発見。スケールアップ判断が可能に

🚨 ユースケース 3: サービス別のエラーレート特定

シナリオ: Cloud Run の全サービスのエラーレートが集約表示されているが、どのサービスに問題があるか切り分けたい。

→ service_name ラベルでブレイクダウンし、特定サービスのエラーレート急増を特定。ログ・トレースと連携した調査を開始

💰 料金

ブレイクダウン機能の利用: 無料

Metrics Explorer およびブレイクダウン機能自体の利用に追加料金は発生しません。Cloud Monitoring の料金はメトリックの取り込み量に基づいて課金されます。

メトリック種別 料金
Google Cloud システムメトリクス 無料
カスタムメトリクス / 外部メトリクス 取り込み量に応じた課金
