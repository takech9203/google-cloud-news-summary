CMEK によるディスクスナップショットリカバリ暗号化サポート

SAP on Google Cloud GA
2026-05-21

📋 概要

Google Cloud's Agent for SAP バージョン 3.14 が一般提供 (GA) となりました。本バージョンの最大の新機能は、ディスクスナップショットベースの SAP HANA リカバリ時に、顧客管理暗号化鍵 (CMEK) を使用してリカバリ先ディスクを暗号化する機能です。

Cloud KMS と統合された CMEK サポートにより、リカバリ時に作成される新しいディスクを自組織で管理する暗号化鍵で保護でき、鍵のライフサイクル管理 (ローテーション、無効化、削除) を完全にコントロールできるようになります。

💡 ポイント: 金融機関や医療機関など厳格なデータ暗号化ポリシーが求められる組織にとって重要なアップデートです。

🔄 Before / After 比較

❌ Before (v3.13 以前)

  • リカバリ先ディスクの暗号化は Google デフォルト暗号化または CSEK に限定
  • CMEK 必須環境ではリカバリ後に追加の暗号化鍵変更作業が必要
  • リカバリワークフロー全体で暗号化ポリシーの一貫適用が困難

✅ After (v3.14)

  • hanadiskrestore コマンドで CMEK を直接指定可能
  • バックアップからリカバリまで一貫した CMEK ベースの暗号化ポリシー
  • 規制産業でのコンプライアンス要件をリカバリ運用でも自動的に充足

🔧 技術仕様

CMEK 暗号化パラメータ

項目詳細
対象コマンドhanadiskrestore
暗号化方式Cloud KMS CMEK (AES-256)
鍵リソース形式projects/{PROJECT}/locations/{LOCATION}/keyRings/{KEY_RING}/cryptoKeys/{KEY}
対応ディスクタイプSSD Persistent Disk, Hyperdisk
サポートバージョンv3.14 以降
既存の暗号化オプションCSEK (-csek-key-file 引数、v3.2 以降)

Cloud KMS 鍵の要件

項目詳細
鍵の目的ENCRYPT_DECRYPT
鍵の保護レベルSOFTWARE または HSM
必要な IAM ロールroles/cloudkms.cryptoKeyEncrypterDecrypter
ロールの付与先Compute Engine サービスエージェント

必要な IAM 権限

JSON 
{
  "requiredPermissions": [

    "compute.instances.detachDisk",
    "cloudkms.cryptoKeyVersions.useToEncrypt",
    "cloudkms.cryptoKeyVersions.useToDecrypt"
  ]
}

🛠️ 設定方法

前提条件

✓Agent for SAP バージョン 3.14 がインストール済み
✓Cloud KMS に暗号化鍵 (CMEK) が作成済み
✓Compute Engine サービスエージェントに Cloud KMS 権限が付与済み
✓ディスクスナップショットベースのバックアップが取得済み

Step 1: Cloud KMS 鍵の作成

Bash 
# キーリングの作成
gcloud kms keyrings create sap-hana-keyring \
  --location=asia-northeast1

# 暗号化鍵の作成
gcloud kms keys create sap-hana-recovery-key \
  --location=asia-northeast1 \
  --keyring=sap-hana-keyring \
  --purpose=encryption
💡 推奨: SAP HANA が稼働するリージョンと同じロケーションに鍵を作成してください。

Step 2: サービスエージェントへの権限付与

Bash 
# Compute Engine サービスエージェントに Cloud KMS 暗号化/復号権限を付与
gcloud kms keys add-iam-policy-binding sap-hana-recovery-key \
  --location=asia-northeast1 \
  --keyring=sap-hana-keyring \
  --member="serviceAccount:service-PROJECT_NUMBER@compute-system.iam.gserviceaccount.com" \
  --role="roles/cloudkms.cryptoKeyEncrypterDecrypter"

Step 3: CMEK を指定したリカバリの実行

Bash 
# CMEK を指定してディスクスナップショットからリカバリを実行
sudo /usr/bin/google_cloud_sap_agent hanadiskrestore \
  -sid=HDB \
  -source-snapshot=hana-hdb-snapshot-20260521 \
  -new-disk-name=hana-data-recovered \
  -kms-key=projects/my-project/locations/asia-northeast1/keyRings/sap-hana-keyring/cryptoKeys/sap-hana-recovery-key

✅ メリット

ビジネス面

🏛️コンプライアンス対応の強化: FISC、HIPAA などの暗号化鍵自己管理要件をリカバリ運用でも自動的に充足
⚡運用効率の向上: リカバリ後の追加暗号化作業が不要、RTO (目標復旧時間) の短縮に貢献
📋監査対応の簡素化: Cloud KMS の監査ログで暗号化鍵の使用履歴を一元管理

技術面

🔗エンドツーエンドの暗号化一貫性: バックアップからリカバリまで CMEK による暗号化ポリシーを自動適用
🔄鍵ライフサイクル管理: Cloud KMS による鍵のローテーション、無効化、バージョン管理を活用
🔧統合ワークフロー: 既存の hanadiskrestore コマンドに引数追加するだけで利用可能

⚠️ 制約事項・注意点

⚠️ 制限事項:
  • CMEK 暗号化スナップショットからのリカバリでは、元の鍵または新しい CMEK を指定する必要あり
  • Cloud KMS の鍵が無効化・削除された場合、対象ディスクへのアクセス不可
  • IaC (Terraform 等) でデプロイされた SAP HANA では状態管理の競合が発生する可能性
  • スケールアウトのホスト自動フェイルオーバー構成ではディスクスナップショット機能自体が非サポート
💰 考慮すべきコスト:
  • Cloud KMS の鍵管理費用、暗号化/復号操作の API コール費用が追加で発生
  • 鍵ローテーション実施時は新規リカバリで最新の鍵バージョンが使用される
  • クロスリージョンリカバリ時はリカバリ先リージョンで利用可能な Cloud KMS 鍵を別途準備が必要

🎯 ユースケース

🏦 ユースケース 1: 金融機関における SAP HANA 災害復旧

金融機関が SAP S/4HANA を Google Cloud 上で運用し、FISC 安全対策基準に基づき保存データの暗号化鍵を自社管理。DR サイトへのリカバリ時にも同一の暗号化ポリシーを適用。

Bash 
# バックアップ取得 (プライマリサイト)
sudo /usr/bin/google_cloud_sap_agent hanadiskbackup \
  -sid=PRD \
  -hana-db-user=SYSTEM \
  -password-secret=sap-hana-password \
  -labels="env=production,backup-type=scheduled"

# リカバリ実行 (CMEK 暗号化指定)
sudo /usr/bin/google_cloud_sap_agent hanadiskrestore \
  -sid=PRD \
  -source-snapshot=hana-prd-snapshot-20260521 \
  -new-disk-name=hana-data-dr-recovery \
  -kms-key=projects/my-project/locations/asia-northeast1/keyRings/sap-prod-keyring/cryptoKeys/sap-hana-cmek
効果: DR リカバリ時にも自動的に CMEK 暗号化が適用され、FISC 安全対策基準への準拠を維持したまま迅速な復旧が可能

🏢 ユースケース 2: マルチテナント環境でのテナント分離

マネージドサービスプロバイダーが複数のテナント向けに SAP HANA を運用し、テナントごとに異なる暗号化鍵を使用してデータを分離管理。リカバリ時にもテナント固有の CMEK を適用。

効果: テナントごとの Cloud KMS 鍵を hanadiskrestore で指定することで、リカバリ後もテナント間のデータ分離が暗号化レベルで維持
