BigQuery 生成 AI 関数 GA (一般提供)

📊 BigQuery 生成 AI 関数が
gemini-4-hydrogen をサポート

リリース日: 2026-11-12

📝 概要

BigQuery の生成 AI 関数が gemini-4-hydrogen モデルをサポートしました (GA)。 AI.GENERATE や AI.GENERATE_TEXT などの生成 AI 関数から、SQL を離れることなく Gemini 4 世代の新モデルを呼び出し、テーブル内のテキスト・画像・音声・動画・PDF データに対して推論を実行できます。

🤖 Gemini 4 Hydrogen とは: 同日 (2026-11-12) に Gemini Enterprise Agent Platform で GA になったモデル。日常的なコーディング・エージェントワークフロー、マルチモーダル分析、ツール利用における速度と効率を重視した設計。深い推論特化の gemini-4-carbon に対し、大量行への適用が多い BigQuery のユースケースに適したスループット・コスト効率寄りの選択肢です。

🎯 主な対象ユーザー: SQL ベースで LLM をデータパイプラインに組み込むデータエンジニア・データアナリスト、BigQuery 上で大規模なテキスト処理 (要約・分類・抽出など) を行うチーム

❌ Before (アップデート前)

  • 生成 AI 関数で使える Gemini 4 世代は深い推論向けフロンティアモデル (gemini-4-carbon / argon) のみ
  • 速度・効率重視モデルは gemini-3.8-flash など Gemini 3 世代どまりで、Gemini 4 の品質を大量行にコスト効率よく適用できない
  • carbon / argon は思考トークンを多く消費し、数千〜数百万行への行単位適用ではトークン消費とレイテンシが課題

✅ After (アップデート後)

  • エンドポイントに gemini-4-hydrogen を指定でき、Gemini 4 世代の速度・効率重視モデルを SQL から直接利用可能 (GA)
  • 日常的な大量データ処理 (要約・分類・抽出) と深い推論タスクを、同じ生成 AI 関数インターフェースで使い分け可能
  • 暗黙的コンテキストキャッシュ (4,096 トークン以上の共有プレフィックス) がバッチ的な利用パターンで効きやすい

BigQuery テーブルのデータを生成 AI 関数経由で Gemini Enterprise Agent Platform のモデルに送信するデータフローです。今回のアップデートで、エンドポイントに速度・効率重視の gemini-4-hydrogen を指定できるようになりました。推論はすべて Agent Platform 側で実行され、結果は BigQuery に保存されます。

⚡ 主要機能

1️⃣ 生成 AI 関数での gemini-4-hydrogen サポート (GA)

✓AI.GENERATE 関数や、リモートモデル経由の AI.GENERATE_TEXT TVF などで gemini-4-hydrogen を指定可能
✓テキストに加え、ObjectRef / オブジェクトテーブル経由で画像・音声・動画・PDF などのマルチモーダルデータも分析対象
✓推論はすべて Agent Platform 側で実行され、結果は BigQuery に保存

2️⃣ Gemini 4 Hydrogen モデルの特徴 (Agent Platform 側で同日 GA)

✓日常的なコーディング・エージェントワークフロー、マルチモーダル分析、ツール利用における速度と効率を重視した設計
✓入出力合計 1,048,576 トークンの統一上限 (出力には思考・関数呼び出し・最終応答を含む)。単一フォアグラウンドセグメントで最大 65,536 出力トークン、long decode (continuation_token) で最大 1,048,576 トークン (入力分を除く) まで拡張可能
✓思考レベルは LOW / MEDIUM / HIGH / XHIGH の 4 段階 (デフォルトは HIGH、XHIGH は深い推論ワークロード向け)
✓暗黙的コンテキストキャッシュのみサポート (4,096 トークン以上、durable caching デフォルト有効)。明示的キャッシュは非サポート
✓Microsoft Office (.docx / .pptx / .xlsx など) と OpenDocument (.odt / .odp / .ods) ファイルの入力に対応
⚠短期リリース (short-term release) として提供され、最低 45 日前の廃止通知ポリシーの対象

3️⃣ モデルラインアップの拡充

gemini-4-hydrogen の追加により、BigQuery 生成 AI 関数の Gemini モデルは、タスク特性に応じて選べるラインアップになりました。

🚀 gemini-4-hydrogen (NEW)

  • 速度・効率重視の Gemini 4 世代モデル
  • 要約・分類・抽出などの日常的な大量データ処理に最適
  • 暗黙的キャッシュとの相性が良い

🧠 gemini-4-carbon / gemini-4-argon

  • 深い推論向けのフロンティアモデル
  • 法務文書分析など複雑なタスク向け
  • gemini-4-carbon は 2026-11-10 にサポート済み

このほか gemini-3.x flash 系も引き続き利用可能です。

BigQuery からの利用 (エンドポイント指定)

Agent Platform のモデルはマルチリージョンエンドポイントのみをサポートします。リージョンを省略した短縮名 (gemini-4-hydrogen) を指定した場合、クエリの実行リージョンに応じて us / eu / global エンドポイントが自動選択されます。特定のエンドポイントを使う場合は完全修飾名を指定します。

SQL リモートモデルの作成 (gemini-4-hydrogen を指定) 
-- リモートモデルの作成 (gemini-4-hydrogen を指定)
CREATE OR REPLACE MODEL `mydataset.gemini_hydrogen`
  REMOTE WITH CONNECTION `us.my_connection`
  OPTIONS (ENDPOINT = 'gemini-4-hydrogen');

🛠️ 設定方法

前提条件

✓BigQuery と Vertex AI (Gemini Enterprise Agent Platform) を利用できる Google Cloud プロジェクトがあること
✓Agent Platform への接続用の Cloud リソース接続 (connection) が作成済みで、接続のサービスアカウントに必要なロールが付与されていること
✓リモートモデルの作成権限 (bigquery.models.create など) があること

ステップ 1: リモートモデルを作成する

SQL ENDPOINT に gemini-4-hydrogen を指定 
CREATE OR REPLACE MODEL `mydataset.gemini_hydrogen`
  REMOTE WITH CONNECTION `us.my_connection`
  OPTIONS (ENDPOINT = 'gemini-4-hydrogen');

ステップ 2: 生成 AI 関数で推論を実行する

SQL AI.GENERATE_TEXT TVF による一括テキスト生成 
-- AI.GENERATE_TEXT TVF による一括テキスト生成
SELECT *
FROM AI.GENERATE_TEXT(
  MODEL `mydataset.gemini_hydrogen`,
  (
    SELECT CONCAT('次の製品レビューを 1 文で要約してください: ', review_text) AS prompt
    FROM `mydataset.product_reviews`
  ),
  STRUCT(TRUE AS flatten_json_output)
);
💡 ヒント: テーブルの各行に対して gemini-4-hydrogen による推論を実行し、結果を BigQuery の列として取得します。実行前に AI.COUNT_TOKENS 関数で入力トークン数を見積もることもできます。

👍 メリット

💼 ビジネス面

✓大量データへの LLM 適用コストの最適化: 速度・効率重視の Hydrogen により、要約・分類・抽出などの日常的なタスクを、フロンティア推論モデルよりも少ないトークン消費・低レイテンシで大量行に適用しやすい
✓データ移動不要の AI 活用: データを BigQuery から持ち出さずに最新の Gemini 4 世代モデルを利用でき、ガバナンスを維持したまま AI 活用を推進

⚙️ 技術面

✓ワークロードに応じたモデル使い分け: 同じ生成 AI 関数のまま、エンドポイント指定の変更だけで Hydrogen (速度・効率) と carbon / argon (深い推論) を切り替え可能
✓暗黙的キャッシュとの相性: 同一プロンプトプレフィックスを大量行に適用する BigQuery の典型パターンは、4,096 トークン以上の共有プレフィックスへの暗黙的キャッシュの恩恵を受けやすい
✓トークン・コストの可観測性: ジョブ情報で入力・出力・思考・キャッシュの各トークン数を確認でき、bigquery_job_id_prefix ラベルで Cloud Billing 上の Agent Platform 費用をジョブ単位で追跡可能

⚠️ デメリット・制約事項

🚫 制限事項

✗Gemini 4 Hydrogen は短期リリースであり、最低 45 日前の通知を経て廃止される可能性がある。長期運用するパイプラインではモデル ID の更新を前提とした設計が必要
✗Agent Platform のモデルはマルチリージョンエンドポイント (us / eu / global) のみをサポートし、リージョナルエンドポイントは利用不可
✗思考レベルは LOW / MEDIUM / HIGH / XHIGH のみで、thinking_budget や thinking_level="MINIMAL" は指定できない (HTTP 400 エラー)
✗VPC Service Controls の境界内では、委任アクセス (delegated access) を使う ObjectRef 値を AI 関数で処理できない (単一引数の OBJ.MAKE_REF(uri) による直接アクセスで回避)

🤔 考慮すべき点

⚠️デフォルトの思考レベルが HIGH のため、単純なタスクに大量適用する場合は思考トークンの消費に注意し、必要に応じて低い思考レベルを検討する
⚠️クォータ超過などによる行レベルエラーは該当行に NULL を返すため、結果の完全性が重要な場合はエラー処理 (マネージド AI 関数では max_error_ratio) を考慮する
⚠️2027-01-12 以降、Gemini 4 Hydrogen 以降のモデルでは TTL 設定付きキャッシュ制御が利用可能になり、キャッシュ書き込みはデフォルトで標準入力トークン価格の 1.25 倍で課金 (保持期間が長いほど高額) される点を将来のコスト設計で考慮する

🎯 ユースケース

📝 ユースケース 1: 製品レビューの大規模要約・分類

シナリオ: EC サイトの数百万件の製品レビューを、SQL パイプラインの中で要約し、トピック別に分類したい。

SQL AI.GENERATE によるレビュー要約 
SELECT
  review_id,
  AI.GENERATE(
    ('このレビューを 1 文で要約し、トピックを返してください: ', review_text),
    connection_id => 'us.my_connection',
    endpoint => 'gemini-4-hydrogen'
  ).result AS summary
FROM `mydataset.product_reviews`;

✅ 効果: 速度・効率重視の Hydrogen により、大量行への適用でもトークン消費とレイテンシを抑えながら Gemini 4 世代の品質で処理できる。共通のプロンプトプレフィックスには暗黙的キャッシュが効く。

🔀 ユースケース 2: タスク特性に応じたモデルの使い分け

シナリオ: 日常的なログ要約・エンティティ抽出は低コストで回し、法務文書の高度な分析など複雑なタスクのみ深い推論モデルを使いたい。

✅ 効果: リモートモデルの ENDPOINT を gemini-4-hydrogen と gemini-4-carbon で使い分けるだけで、同一の SQL インターフェースのままコストと品質のバランスを最適化できる。

💰 料金

生成 AI 関数は、クエリ実行に使用する BigQuery のコンピュートリソースへの課金に加えて、リモートモデルが Gemini Enterprise Agent Platform のモデルを呼び出すため、Agent Platform 側の料金 (gemini-4-hydrogen のトークン課金。思考トークンを含む) も発生します。

💡 ヒント: 実行前のトークン見積もりには AI.COUNT_TOKENS 関数を利用できます。

詳細は BigQuery ML の料金 および Gemini Enterprise Agent Platform の生成 AI 料金 を参照してください。

✅ まとめ

✓BigQuery の生成 AI 関数で Gemini 4 世代の速度・効率重視モデルが利用可能になり、大量データへの要約・分類・抽出といった日常的な LLM 処理をコスト効率よく SQL だけで実行できるようになった
