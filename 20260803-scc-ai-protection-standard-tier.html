🛡️ AI ワークロード向けセキュリティ・ガバナンス機能の拡充

Security Command Center / VPC Service Controls | リリース日: 2026-08-03
Security Command Center VPC Service Controls AI Protection (Standard ティア): 提供開始 Antigravity VPC-SC 統合: Preview

📌 概要

2026 年 8 月 3 日、Google Cloud は AI ワークロードのセキュリティとガバナンスに関する 2 つのアップデートを発表しました。 企業が生成 AI やエージェント型ワークロードを安全に導入・運用するための基盤を強化するものです。

1️⃣ SCC Standard ティアで AI Protection をサポート

追加料金なしの Standard ティアで AI Protection が利用可能に。プロジェクトレベル・組織レベルの両方のアクティベーションに対応し、 AI セキュリティダッシュボード、基本インベントリビュー (Gemini モデルを除く)、ベースラインのセキュリティ検出結果 (Security Essentials) にアクセスできます。

2️⃣ Google Antigravity in Gemini Enterprise の VPC Service Controls 統合 (Preview)

エージェント型開発ツール Google Antigravity の API (businessaicode.googleapis.com) を サービスペリメータで保護できるようになり、データ漏洩 (exfiltration) リスクを抑えながら境界内で通常どおり利用できます。

😰 Before: アップデート前の課題

  • AI Protection の主要機能は Premium / Enterprise ティアが前提で、無償の Standard ティアでは AI 資産のセキュリティ可視化手段が限定的
  • 組織全体での SCC 有効化権限を持たないチームは、担当プロジェクト単位で AI セキュリティダッシュボードを利用できなかった
  • Google Antigravity は VPC Service Controls の保護対象外で、統制の効いた環境ではエージェント型開発ツールの導入がコンプライアンス上の課題に

🎉 After: アップデート後の改善

  • Standard ティア (追加料金なし) でも AI Protection が利用可能になり、AI セキュリティダッシュボードと基本インベントリで AI 資産の全体像を把握
  • プロジェクトレベルのアクティベーションに対応し、組織管理者を介さずプロジェクト単位で AI セキュリティの可視化を開始可能
  • Antigravity の API をサービスペリメータで保護可能に (Preview)。既知の制限事項なしで境界内利用が可能

⚙️ 主要機能

🛡️ Standard ティアでの AI Protection サポート (SCC)
✓AI セキュリティダッシュボード: 「リスクの概要 > AI セキュリティ」から AI 関連リスクを一元的に確認
✓基本インベントリビュー: データソース、エンドポイント、エージェント、Agent Registry にカタログ登録された MCP サーバーなどの AI 資産を把握 (Gemini モデルは Premium / Enterprise のみ)
✓ベースラインのセキュリティ検出結果 (Security Essentials): AI 資産に対する基本的なセキュリティ検出結果を表示
✓プロジェクトレベル・組織レベルの両方のアクティベーションに対応
✗脅威検知 (Event Threat Detection / Agent Platform Threat Detection)、攻撃パスシミュレーション、CVE 脆弱性特定、高度なコンプライアンスフレームワークは Premium / Enterprise ティアまたは組織レベルのアクティベーションが必要
🔒 Google Antigravity in Gemini Enterprise の VPC Service Controls 統合 Preview
✓サービス名 businessaicode.googleapis.com をサービスペリメータの保護対象サービスとして構成可能
✓ペリメータ内で Antigravity を通常どおり利用でき、境界外からの API アクセスや境界外へのデータ持ち出しを制御
✓本統合には既知の制限事項なし (ドキュメント記載)
✗Preview 段階のため、本番環境での利用は完全にはサポートされない
💡 ポイント: 新規の SCC アクティベーションでは AI Protection がデフォルトで有効。 AI Protection 提供前に SCC を有効化していた場合は手動での有効化が必要です。

🛠️ 設定方法

✅ 前提条件

  • (AI Protection) Google Cloud プロジェクトが組織に関連付けられていること
  • (AI Protection) プロジェクトレベルの有効化には Security Admin (roles/iam.securityAdmin) および Security Center Admin (roles/securitycenter.admin) ロールが必要
  • (VPC Service Controls) Access Context Manager のアクセスポリシーが構成済みであること

ステップ 2: サービスペリメータへの Google Antigravity の追加

Bash 既存のサービスペリメータに Google Antigravity API を保護対象として追加 
# 既存のサービスペリメータに Google Antigravity API を保護対象として追加
gcloud access-context-manager perimeters update PERIMETER_NAME \
  --add-restricted-services=businessaicode.googleapis.com \
  --policy=POLICY_ID

ペリメータの構成後、境界内のプロジェクトからは Google Antigravity を通常どおり利用でき、境界外からのアクセスはブロックされます。

✨ メリット

💼 ビジネス面

  • AI セキュリティ導入の敷居を低減: 追加料金なしの Standard ティアで AI 資産の可視化を開始でき、AI ガバナンス整備の第一歩をコストゼロで踏み出せる
  • 規制業界でのエージェント型開発ツール採用: 金融・医療などデータ境界統制が必須の業界でも、VPC Service Controls の保護下で Antigravity を導入する道筋ができた
  • 法的・財務リスクの軽減: セキュリティ侵害や規制非準拠に伴うリスクを、AI 資産の早期可視化により低減

🔧 技術面

  • プロジェクト単位のスモールスタート: 組織全体の SCC 導入を待たずに、個別プロジェクトで AI セキュリティダッシュボードを利用可能
  • AI 資産の一元的な把握: データソース、エンドポイント、エージェント、MCP サーバーを含むインベントリを 1 つのダッシュボードで確認
  • 制限事項なしのペリメータ統合: Antigravity の VPC-SC 統合には既知の制限がなく、既存のペリメータ運用にそのまま組み込める

⚠️ デメリット・制約事項

🚧 制限事項

  • Standard ティアの基本インベントリビューには Gemini モデルが含まれない (Premium / Enterprise ティアが必要)
  • 脅威検知、攻撃パスシミュレーション、CVE 脆弱性特定、高度なコンプライアンスフレームワークは Premium / Enterprise ティアまたは組織レベルのアクティベーションが必要
  • VPC Service Controls の Antigravity 統合は Preview 段階であり、本番環境での利用は完全にはサポートされない
  • プロジェクトレベルのアクティベーションでは、ダッシュボードに表示されるデータは当該プロジェクトに限定される

🤔 考慮すべき点

  • AI Protection 提供前に SCC を有効化していた組織・プロジェクトでは、AI Protection の手動有効化が必要
  • MCP サーバーのインベントリ検出には、ホストする各プロジェクトで App Hub API の有効化が必要
  • Model Armor のテンプレートを構成していない場合、AI セキュリティダッシュボードの Model Armor ウィジェットにデータが表示されない
  • Enterprise ティアは 2027 年 5 月 21 日にシャットダウン予定のため、新規の高度な機能利用は Premium ティアを軸に検討するのが望ましい
