📊 Cloud Monitoring: カスタムダッシュボードでのトレースデータ表示

Cloud Monitoring Cloud Trace Public Preview
2026-06-05

🔍 概要

Cloud Monitoring のカスタムダッシュボードにトレースデータを直接表示できるようになりました。 メトリクス、ログ、トレースを統合した「ユニファイドトラブルシューティングビュー」を構築でき、 問題の根本原因をより迅速に特定できます。

対象ユーザー: 分散システムの運用チーム、SRE、アプリケーション開発者

Before (従来)

  • Trace Explorer ページに個別に遷移が必要
  • 複数画面を行き来する相関分析
  • 共有ダッシュボードにトレース情報を含められない

After (アップデート後)

  • 単一ダッシュボードでメトリクス・ログ・トレースを統合表示
  • 複数の可視化形式 (ヒートマップ、テーブル等) を選択可能
  • API でプログラマティックに構成・管理可能

⚡ 主要機能

📌 トレースウィジェットの追加

「Add widget」ダイアログの「Data」セクションから「Trace」を選択して追加。1ダッシュボードあたり最大100ウィジェット配置可能。

📊 複数の可視化形式
  • スパン期間ヒートマップ (デフォルト)
  • スパンレート (折れ線グラフ)
  • スパン期間パーセンタイル
  • テーブル形式 (グループ化/個別)
💾 Trace Explorer からの保存

Trace Explorer ページから直接ダッシュボードにウィジェットを保存可能。Visualizer、Span table、Grouped span table の3形式から選択。

🔎 スパンフィルタリング

スパン名、サービス名、ステータス、スパン種別、属性でフィルタリング。App Hub のサービス・ワークロードにも対応。

🔧 技術仕様

🛠️ 設定方法

前提条件

必要な IAM ロール:
  • roles/monitoring.editor - Monitoring 編集者
  • roles/cloudtrace.user - Cloud Trace ユーザー (トレースデータを閲覧する各プロジェクトに対して付与)

コンソールからウィジェットを追加

  1. Google Cloud コンソールで「Dashboards」ページに移動
  2. 既存のダッシュボードを選択、または「Create dashboard」をクリック
  3. ツールバーの「Add widget」をクリック
  4. 「Data」セクションで「Trace」を選択
  5. チャートビューを選択 (ヒートマップ、スパンレート、パーセンタイルなど)
  6. フィルタを追加してスパンの表示範囲を絞り込み
  7. 「Apply」をクリックして設定を保存

🎯 ユースケース

1. マイクロサービスのレイテンシ監視

複数のマイクロサービスで構成されるアプリケーションのレイテンシを統合的に監視。各サービスの応答時間、エラー率、スループットをメトリクスと併せて確認し、パフォーマンス劣化を即座に検出。

JSON Payment Service レイテンシ監視の実装例 
{
  "widget": {
    "title": "Payment Service Latency",
    "xyChart": {
      "dataSets": [{
        "plotType": "HEATMAP",
        "timeSeriesQuery": {
          "traceQuery": {
            "resourceContainer": "projects/my-project",
            "spanDataValue": "SPAN_DURATION",
            "spanFilters": {
              "services": ["payment-service"],
              "displayNames": ["/api/v1/payment"]
            }
          }
        }
      }]
    }
  }
}

2. インシデント対応用統合ダッシュボード

オンコールエンジニアがインシデント発生時に使用する統合ダッシュボードを構築。メトリクスの異常検知、関連ログ、影響を受けているトレースを一画面で確認し、対応時間を大幅に短縮。

3. AI/ML アプリケーションの推論レイテンシ追跡

Vertex AI を使用した推論パイプラインにおいて、各ステップ (前処理、推論、後処理) のスパンをダッシュボードで追跡し、ボトルネックを特定。エンドツーエンドのパフォーマンスを可視化。

✅ メリット

🏢 ビジネス面
  • MTTR の短縮: 統合ビューにより問題の根本原因特定を加速
  • チームコラボレーション向上: 共有ダッシュボードでチーム全体の状況認識を統一
🔬 技術面
  • 統合オブザーバビリティ: 3本柱を単一ダッシュボードで統合表示
  • API による自動化: プログラマティックにダッシュボードを構築・管理
  • 柔軟なフィルタリング: 多様な条件でデータをフィルタリング

⚠️ デメリット・制約事項

制限事項:
  • ダッシュボードレベルのフィルタはトレースウィジェットに適用されない
  • トレースウィジェットのクエリに変数 (Variable) を適用できない
  • パブリックプレビュー - サポートが限定される可能性 (Pre-GA Offerings Terms 適用)
  • 1ダッシュボードあたり最大100ウィジェットの制限
考慮すべき点:
  • トレースデータの閲覧にはプロジェクトごとに roles/cloudtrace.user ロールが必要
  • デフォルトのトレーススコープの設定が適切でない場合、期待するデータが表示されない可能性
  • スパンデータの保持期間は30日間

💰 料金情報

トレースウィジェットの表示自体に追加料金は発生しません。ただし、関連するサービスの利用料金が適用されます。

サービス料金無料枠
Cloud Trace スパン取り込み$0.20 / 100万スパン月 250万スパンまで無料
Cloud Monitoring API 読み取り$0.50 / 100万時系列返却月 100万時系列返却まで無料
Cloud Monitoring データ (カスタムメトリクス)$0.2580 / MiB月 150 MiB まで無料

🌍 利用可能リージョン

Cloud Monitoring のカスタムダッシュボード機能はグローバルサービスとして提供されており、全リージョンで利用可能です。トレースデータ自体は Observability Bucket に保存され、保存先のリージョンはプロジェクト設定に依存します。

🔗 関連サービス・機能

🔍 Cloud Trace Explorer

トレースデータの詳細な探索と分析を行う専用ページ。ダッシュボードウィジェットから直接遷移可能。

📱 Application Monitoring

App Hub 登録サービスのトレースデータを自動的にダッシュボードに表示する機能。

2026-06-02 に GA となったヒストグラムウィジェットと組み合わせて使用可能。

🌐 Trace DAG 可視化

2026-06-01 に発表されたスパン詳細ページでの有向非巡回グラフ (DAG) 表示機能。

📝 まとめ

Cloud Monitoring のカスタムダッシュボードでトレースデータを直接表示できるようになったことで、 メトリクス・ログ・トレースの3つのオブザーバビリティシグナルを統合した監視ビューの構築が可能になりました。 パブリックプレビュー段階ですが、統合ダッシュボードの構築を検討している運用チームは、 既存のダッシュボードにトレースウィジェットを追加して、トラブルシューティングワークフローの効率化を試すことを推奨します。
