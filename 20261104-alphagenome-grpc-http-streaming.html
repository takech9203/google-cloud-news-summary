🧬 AlphaGenome (alphagenome-004)
gRPC / 統合 HTTP ストリーミング対応

Google DeepMind のゲノム基盤モデルが、単一コンテナで gRPC と HTTP のバイナリストリーミングを統合サポート

📌 概要

Google DeepMind が開発したゲノム基盤モデル AlphaGenome の新サービングバージョン alphagenome-004 が、HTTP/2 gRPC ストリーミングと チャンク化バイナリ protobuf HTTP ストリーミングを統合サポート。 単一の統合コンテナが、共有エンドポイント向けの gRPC (PredictionService.StreamDirectRawPredict、ポート 8081) と、 専用エンドポイント向けの HTTP (streamRawPredict、ポート 8080) の両方を提供します。

DnaModelService の全 7 メソッドと 11 のゲノムモダリティ (遺伝子発現、クロマチンアクセシビリティ、ヒストン修飾、RNA スプライシング、3D クロマチンコンタクトマップなど) において、 1 MB (100 万塩基対) コンテキストのトラック予測レイテンシが削減されます。

❌ Before (alphagenome-003)

  • HTTP/1.1 ストリーミング (streamRawPredict、ポート 8080) のみに対応
  • JSON/base64 シリアライズのオーバーヘッドで 1 MB トラック予測のレイテンシが大きい
  • score_ism_variants のような高同時実行評価で HTTP ゲートウェイタイムアウトが発生
  • 共有エンドポイント経由の HTTP では 10 MB のレスポンスサイズ制限

✅ After (alphagenome-004)

  • gRPC で圧縮済みバイナリテンソルチャンクを直接送受信し、レイテンシ削減
  • 専用エンドポイントの proto_b64 チャンクで 10 MB 制限を回避
  • in silico 飽和変異導入 (ISM) がタイムアウトなしで完走
  • 統合 Python SDK でフォールド選択 (ALL_FOLDS、FOLD_0〜FOLD_3) に対応
  • alphagenome-003 は Model Garden に残り後方互換性を維持
🎯 対象ユーザー: ゲノム変異の機能的影響を大規模に解析するライフサイエンス研究機関・創薬企業・バイオインフォマティクスチーム。 特に高同時実行のマルチバリアント評価ワークロードで HTTP ゲートウェイタイムアウトを回避できる点が大きな改善です。
⚠️ 注意: AlphaGenome は研究用ツールであり、臨床診断用途には承認されていません。

統合 SDK を利用するクライアントは、共有エンドポイントでは gRPC (ポート 8081)、専用エンドポイントでは HTTP ストリーミング (ポート 8080) を通じて、 同一の alphagenome-004 コンテナが提供する DnaModelService メソッドを呼び出します。 どちらの経路でもバイナリ形式のストリーミングにより大きな予測結果を低レイテンシで受信できます。

⚡ 主要機能

📦 1. 統合サービングコンテナ (alphagenome-004)

単一コンテナで HTTP/2 gRPC ストリーミング (ポート 8081) と HTTP ストリーミング (ポート 8080) の両方を提供。DnaModelService の全 7 メソッドと 11 ゲノムモダリティをカバー。

🔌 2. gRPC ストリーミング (共有エンドポイント)

Model Garden で「Public (shared endpoint)」を選択し、dna_client_grpc.create_vertex_client で接続。 PredictionService.StreamDirectRawPredict により圧縮バイナリテンソルチャンクを JSON/base64 変換なしで直接ストリーミング。 1 MB トラック予測のレイテンシ削減とゲートウェイタイムアウト回避を実現。

🌐 3. HTTP ストリーミング (専用エンドポイント)

デフォルトの「Public (dedicated endpoint)」でデプロイし、dna_client_http.create_http_client で接続。 streamRawPredict によるチャンク化バイナリ protobuf (proto_b64) で、共有エンドポイントの 10 MB レスポンスサイズ制限を回避。

🧩 4. モデルフォールド選択

gRPC / HTTP 両クライアントで model_version パラメータによるフォールド選択に対応 (ALL_FOLDS がデフォルト、FOLD_0〜FOLD_3 を個別指定可能)。

🔄 5. 後方互換性

alphagenome-003 (HTTP/1.1 ストリーミングのみ) は Model Garden に残り、既存のレガシー HTTP デプロイメントを継続利用可能。

💡 メリット

💼 ビジネス面

✓大規模変異解析の時間短縮: in silico 飽和変異導入のようなマルチバリアント評価がタイムアウトなしで完走するため、創薬・機能ゲノミクス研究のイテレーションが高速化
✓移行リスクの低減: alphagenome-003 が後方互換のために維持されるため、既存ワークロードを止めずに段階的に alphagenome-004 へ移行可能

⚙️ 技術面

✓シリアライズオーバーヘッドの排除: gRPC では圧縮バイナリテンソルチャンクを直接ストリーミングし、JSON/base64 変換が不要なため 1 MB トラック予測のレイテンシが削減
✓レスポンスサイズ制限の回避: 専用エンドポイントの proto_b64 チャンクストリーミングにより、共有エンドポイントの 10 MB HTTP レスポンス制限を受けない
✓統一インターフェース: gRPC クライアント (GrpcDnaClient) と HTTP クライアント (HttpDnaClient) が同一の DnaModel インターフェースを実装しており、コード変更を最小限に経路を切り替え可能

⚠️ デメリット・制約事項

🚧 制限事項

✗AlphaGenome へのアクセスには許可リスト登録が必要 (GA with allowlist)。SDK wheel ファイルへのアクセスも制限されている
✗80 GB GPU メモリが必須で、対応マシンタイプは A100 80 GB / H100 / H100 Mega 系に限定 (a2-highgpu の 40 GB A100 は非対応)
✗研究用ツールであり、臨床診断用途には承認されていない

🤔 考慮すべき点

!gRPC (共有エンドポイント) と HTTP (専用エンドポイント) はデプロイ時のエンドポイントアクセス設定で決まるため、ワークロード特性に応じて事前に選択する必要がある
!入力 DNA 配列はサポートされるコンテキスト長 (最大 1 MB) にパディングする必要がある
!デプロイ前に対象リージョンの GPU サービングクォータの確認が必要

🎯 ユースケース

🧪 ユースケース 1: in silico 飽和変異導入 (ISM) による変異効果の網羅的スクリーニング

シナリオ: 創薬研究チームが、疾患関連遺伝子の制御領域における全一塩基置換の機能的影響を網羅的に評価したい。従来は多数の変異を並列評価すると HTTP ゲートウェイタイムアウトが発生していた。

✅ 効果: 高同時実行のマルチバリアント評価がタイムアウトなしで完走し、候補変異の優先順位付けが高速化する。

📈 ユースケース 2: 大規模トラック予測結果の低レイテンシ取得

シナリオ: バイオインフォマティクスパイプラインで、1 MB ゲノム区間の RNA-Seq・ATAC などのトラック予測を大量に取得する。JSON/base64 のオーバーヘッドと 10 MB レスポンス制限がボトルネックになっていた。

✅ 効果: gRPC のバイナリテンソルストリーミング、または専用エンドポイントの proto_b64 チャンクストリーミングにより、大きな予測結果を低レイテンシかつサイズ制限なしで受信できる。
