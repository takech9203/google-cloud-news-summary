🗄️ Oracle Database@Google Cloud
リモート MCP サーバーが GA

Oracle Database@Google Cloud GA (一般提供) 📅 リリース日: 2026-10-26

Database Connection 管理ツールと database_connection_executesql による SQL 実行機能が追加。AI エージェントから Oracle データベースを自然言語で一気通貫操作できるようになりました。

📌 概要

Oracle Database@Google Cloud のリモート MCP (Model Context Protocol) サーバーが GA になりました。MCP は、LLM や AI アプリケーションが外部データソースに接続する方法を標準化するプロトコルです。リモート MCP サーバーは Google Cloud のインフラ上で動作し、HTTP エンドポイント https://oracledatabase.googleapis.com/mcp を提供します。

Antigravity、ChatGPT、Claude、独自開発アプリケーションなどの AI プラットフォームから、Autonomous AI Database や Exadata のリソース管理 (プロビジョニング・一覧・詳細確認) に加え、データベース接続の作成と SQL 実行 (DML / DDL / DQL) までを AI エージェントのワークフローとして実行できます。Oracle Database@Google Cloud API を有効化すると MCP サーバーも有効になります。

❌ Before (アップデート前)

  • AI エージェントから操作するには gcloud CLI や API 呼び出しを個別に実装・仲介する必要があった
  • MCP 経由でデータベース内のデータに SQL を実行する標準的な手段がなかった
  • Database Connection の作成・管理を AI ワークフローに組み込むツールが未提供

✅ After (アップデート後)

  • リモート MCP サーバーが GA。本番利用を想定した標準エンドポイントでリソースを操作可能
  • Database Connection 管理ツールで ODB Network 上の DB への接続を自然言語プロンプトから作成
  • database_connection_executesql で DML / DDL / DQL を含むあらゆる SQL を AI エージェントから実行可能

🏗️ アーキテクチャ (シーケンス図)

LLM / AI アプリケーションは MCP クライアントとしてリモート MCP サーバーに接続し、Database Connection の作成を経て、database_connection_executesql ツールで Oracle Database に対する SQL を実行します。認証情報 (DB ユーザーのパスワード) は Secret Manager のシークレットとして参照されます。

⚡ 主要機能

🌐 リモート MCP サーバーの GA

  • グローバルエンドポイント https://oracledatabase.googleapis.com/mcp (Streamable HTTP トランスポート)
  • MCP バージョン 2026-07-28 のステートレスプロトコルに対応。initialize ハンドシェイクや Mcp-Session-Id が不要で各リクエストが自己記述的
  • Oracle Database@Google Cloud API 有効化で自動的に利用可能

🔗 Database Connection の作成・管理

  • ODB Network 上のデータベースに対する接続の作成・一覧取得・詳細取得に対応
  • DB ユーザーのパスワードは Secret Manager のシークレットとして指定 (生パスワードは非サポート)
  • 自然言語プロンプト (「シークレット ... を使って Connection を作成して」) で作成可能

📝 SQL 実行 (executesql)

  • database_connection_executesql ツールで DML / DDL / DQL を含むすべての SQL ステートメントを実行可能
  • 読み取り専用権限の DB ユーザーで接続を作成すれば、書き込み操作はデータベース側で拒否される (読み取り専用運用パターン)

🧰 リソース管理ツール群

  • ODB Network / ODB Subnet、Exadata Infrastructure、Exadata VM Cluster、Exascale VM Cluster / Storage Vault、Autonomous AI Database、DB System、Oracle GoldenGate (Deployment / Connection) の作成・一覧・取得
  • get_operation で長時間実行オペレーションをポーリング可能
  • ツール一覧は tools/list リクエスト (認証不要) または MCP リファレンスで確認

✅ メリット

💼 ビジネス面

🚀 開発の迅速化

自然言語プロンプトでデータベースのプロビジョニングからスキーマ作成、データ投入までを実行でき、Web アプリケーション開発などの初期セットアップを短縮できる。

📋 運用標準化の支援

プロジェクト内の Autonomous AI Database の構成を一覧・点検し、構成標準からの逸脱を AI エージェントにレポートさせる運用が可能。

⚙️ 技術面

🔌 標準プロトコルによる統合

MCP 標準に準拠しているため、Antigravity、ChatGPT、Claude、カスタムアプリケーションなど多様な AI プラットフォームから同一のエンドポイントで利用できる。

🔐 IAM によるきめ細かなアクセス制御

OAuth 2.0 + IAM による認証・認可で、エージェント専用 ID の分離やカスタムロールによる最小権限運用が可能。

🗝️ 安全な認証情報管理

DB パスワードは Secret Manager のシークレット参照のみをサポートし、生パスワードの受け渡しを排除。

👀 読み取り専用運用パターン

読み取り専用権限の DB ユーザーで接続を作成することで、LLM による意図しない書き込みをデータベース側で防止できる。

制限事項

✗create_autonomous_database / create_db_system ツールは Secret Manager に保存されたシークレットのみをサポートし、生パスワードは使用不可
✗database_connection_executesql のレスポンスが 10 MB を超える場合は切り捨てられる (metadata.status = PARTIAL、partialResult: true で通知)
✗30 秒を超えて実行されるクエリはタイムアウトする可能性がある
✗1 回の呼び出しで実行できる SQL ステートメントは 1 つのみ (autocommit)。複数ステートメントや複数呼び出しにまたがるトランザクションは非サポート
✗接続文字列でのホスト名指定は未サポート。データベースのプライベート IP を使用する必要がある

考慮すべき点

⚠️ SQL エラーの扱い: SQL エラーが発生しても呼び出し自体は成功として返ります。Oracle がステートメントを拒否した場合 (例: ORA-00942) は metadata.status = ERROR と metadata.message を確認する必要があります。
⚠️ シークレットの権限設計: Secret Manager は安全な保管手段ですが、secretmanager.versions.access 権限を持つユーザーや IAM ポリシーを変更できるユーザーはシークレットにアクセスし得るため、権限設計に注意が必要です。
💡 推奨: エージェント用には専用の ID を作成し、リソースアクセスを制御・監視することが推奨されています。

🧩 関連サービス・機能

🔐 Secret Manager

Database Connection やデータベース作成時の DB ユーザーパスワードをシークレットとして安全に管理。

👤 IAM

OAuth 2.0 と組み合わせた MCP ツール呼び出しの認証・認可。カスタムロールによる最小権限運用。

🛡️ Model Armor

プロジェクトのフロア設定により、MCP ツール呼び出しとレスポンスに対するセキュリティフィルタ (悪意ある URI 検出など) を適用可能。

📜 Cloud Audit Logs

Google Cloud リモート MCP サーバー共通の集中監査ログ。

🔌 Private Service Connect

ODB Network のサービス接続 (ネットワークアタッチメント) に使用。

🔄 Oracle GoldenGate

MCP ツール経由で Deployment / Connection の作成・管理が可能。

📝 まとめ

Oracle Database@Google Cloud のリモート MCP サーバーが GA となり、Database Connection 管理と database_connection_executesql による SQL 実行が加わったことで、AI エージェントから Oracle データベースのプロビジョニング・接続・データ操作までを一気通貫で自動化できるようになりました。

💡 始め方の推奨: AI 対応の開発ワークフローに Oracle Database@Google Cloud を組み込む場合は、まず tools/list でツールを確認し、最小権限のカスタムロールと読み取り専用接続の設計から始めることを推奨します。
