📝 概要

2026 年 11 月 12 日、Gemini Enterprise に関連する 4 つのアップデートが同日に発表されました。中心となるのは、最新モデル Gemini 4 Hydrogen が Gemini Enterprise の Web アプリ、モバイルアプリ、Workflow Builder、AI developer tools で一般提供 (GA) になったことです。global、us、eu のマルチリージョンでサポートされ、us と eu ではデータレジデンシー (at-rest DRZ) と ML 処理 (MLP) のコミットメントにも対応します。

あわせて、Gemini 3.8 Flash がカナダと日本の in-country リージョンで GA となり、国内でのデータ保存 (DRZ) と ML 処理 (MLP) に対応した状態で利用可能になりました。日本リージョン (asia-northeast1) でデータレジデンシー要件を持つ組織にとって重要なアップデートです。さらに、Gemini Notebook Enterprise の 「Gemini Notebook for business」への名称変更 (機能・API は変更なし) と、スキルのバージョン履歴の表示・復元機能も追加されました。

🎯 対象ユーザー: Gemini Enterprise を全社導入している管理者 / データレジデンシー要件を持つ規制業種 (特にカナダ・日本の組織) / スキルを作成・運用するユーザー / Antigravity などの AI developer tools を利用する開発者

❌ Before (アップデート前の課題)

  • Gemini 4 系モデル (Carbon、Argon) は in-country リージョンで利用できず、使用にはグローバルエンドポイントへのルーティングを警告ダイアログで承認する必要があった
  • カナダ・日本の in-country リージョンでは最新モデルが限られ、国内 DRZ / MLP を維持したまま新しい Flash 系モデルを使えなかった
  • スキル更新後に以前の内容を確認する手段がなく、誤った編集を過去の状態へ戻せなかった
  • 「Gemini Notebook Enterprise」は Workspace 側の「Gemini Notebook」との関係がわかりにくかった

✅ After (アップデート後の改善)

  • Gemini 4 Hydrogen が 4 つのサーフェスで GA となり、us / eu では DRZ と MLP を維持したまま最新モデルを利用可能に
  • Gemini 3.8 Flash がカナダ・日本の in-country リージョンで GA。国内 at-rest DRZ と MLP に対応し、該当リージョンの Web アプリではデフォルトで有効
  • スキルのオーナーがバージョン履歴を表示し、過去バージョンを読み取り専用で確認・最新として復元可能に
  • 製品名が「Gemini Notebook for business」に統一され位置付けが明確に (API は同一で移行作業不要)

Gemini 4 Hydrogen は 4 つのサーフェスすべてから利用でき、管理者がモデルトグルや Antigravity authorized models 設定で可用性を制御します。Gemini 3.8 Flash はカナダ・日本の in-country リージョンで国内データレジデンシーを維持したまま利用できます。

🚀 主要機能

1️⃣ ✨ Gemini 4 Hydrogen の一般提供 (GA)

→Web アプリ、モバイルアプリ、Workflow Builder、AI developer tools で利用可能
→ロケーション: global、us、eu マルチリージョン。us / eu では at-rest DRZ と MLP に対応
→Web / モバイルアプリではデフォルトで無効。管理者がモデルトグルで有効化する
→AI developer tools では「Antigravity authorized models」がデフォルト選択の場合、ライセンスユーザーに対してデフォルトで有効。カスタムモデルリスト指定時は管理者が手動で選択

2️⃣ 📓 Gemini Notebook Enterprise の名称変更 (→ Gemini Notebook for business)

→リブランドのみで、製品機能は従来と同一
→API は従来と同じエンドポイントを使用するため、既存インテグレーションへの影響なし
→キュレーションしたソース (ドキュメント、Web サイトなど) に基づく AI リサーチアシスタント。Gemini Enterprise (Standard / Plus) に含まれるほか、単体製品としても購入可能

3️⃣ ⚡ Gemini 3.8 Flash のカナダ・日本リージョン GA

→カナダ (northamerica-northeast1) と日本 (asia-northeast1) の in-country リージョンで GA
→国内での at-rest データレジデンシー (DRZ) と ML 処理 (MLP) をサポート
→カナダ・日本リージョンの Web アプリではデフォルトで有効。「Model availability」配下のトグルでアクセス管理

4️⃣ 🕘 スキルバージョンの表示と復元

→スキルのオーナーが Skills ページでバージョン履歴を表示できる
→過去バージョンの指示 (instructions) とファイルを読み取り専用モードで確認可能
→過去バージョンを最新バージョンとして復元できる

🌏 in-country リージョンに関する留意点

項目詳細
in-country リージョンの提供形態 GA (アローリスト制)。利用には Google アカウントチームへの連絡が必要
非対応モデルを有効化した場合 トラフィックはグローバルエンドポイントにルーティングされ、リージョナルなデータレジデンシーは適用されない (警告ダイアログの承認が必要)
組織ポリシーとの関係 リソースロケーション組織ポリシーで global が許可されていない場合、非対応モデルのトグルを有効化できない
スキルデータの保存場所 ユーザー作成スキルはアプリのロケーションの Gemini Enterprise ストレージに保存 (at-rest DRZ 対応、MLP は非対応)
💻 AI developer tools の対象: Antigravity アプリ、Antigravity CLI、Antigravity for IDEs、Android Studio が含まれます。データレジデンシーは選択したモデルのコミットメントに従います。

🔧 設定方法

✅ 前提条件

✓Gemini Enterprise アプリが作成済みであること
✓管理タスクには Gemini Enterprise Admin IAM ロール (roles/discoveryengine.agentspaceAdmin) が必要
✓in-country リージョン (カナダ・日本など) の利用にはアローリスト登録が必要 (Google アカウントチームに連絡)

🪜 手順

  1. Web アプリで Gemini 4 Hydrogen を有効化する
    Google Cloud コンソールで対象の Gemini Enterprise アプリを開き、モデル管理設定から Gemini 4 Hydrogen のトグルをオンにします。デフォルトでオフのため、管理者による明示的な有効化が必要です。
  2. AI developer tools のモデルを確認する
    「Antigravity authorized models」がデフォルト選択の場合、Gemini 4 Hydrogen はライセンスユーザーに対して自動的に有効になります。カスタムモデルリストを使用している組織では、AI developer tools 設定で管理者が手動で追加します。
  3. (カナダ・日本リージョン) Gemini 3.8 Flash のアクセスを管理する
    カナダ・日本リージョンの Web アプリでは Gemini 3.8 Flash がデフォルトで有効です。無効化したい場合は「Model availability」配下の Gemini 3.8 Flash トグルで制御します。
  4. スキルのバージョンを表示・復元する
    Web アプリの Skills ページで対象スキルのバージョン履歴を開き、過去バージョンの指示とファイルを読み取り専用で確認します。問題があれば過去バージョンを最新バージョンとして復元します。

💡 メリット

💼 ビジネス面

✓データレジデンシー要件と最新モデルの両立: 日本・カナダの規制業種 (金融、公共など) が国内 DRZ / MLP を維持したまま Gemini 3.8 Flash を利用可能に。従来はグローバルエンドポイントへのルーティングを許容する必要があった
✓全サーフェスで一貫したモデル体験: チャット (Web / モバイル)、エージェント構築 (Workflow Builder)、開発 (Antigravity 等) のすべてで同一の最新モデルを利用でき、組織全体の AI 活用レベルを底上げできる
✓スキル運用の安全性向上: バージョン復元により、スキルの編集ミスが業務プロセスへ影響するリスクを低減し、組織的なスキル共有を安心して進められる

🛠️ 技術面

✓Workflow Builder での最新モデル利用: Gemini Agent ノードで Gemini 4 Hydrogen を選択でき、エージェント / ワークフローの推論品質を向上できる (Workflow Builder は Gemini 3.0 以降のモデルをサポート)
✓API 互換性の維持: Gemini Notebook for business への名称変更では API エンドポイントが変わらないため、既存の自動化やインテグレーションの改修は不要
✓ガバナンスの一元管理: モデルトグル、Antigravity authorized models、組織ポリシー (リソースロケーション) を組み合わせて、モデル利用とデータ所在を一元的に統制できる

⚠️ デメリット・制約事項

🚧 制限事項

✗Gemini 4 Hydrogen の DRZ / MLP 対応は us / eu マルチリージョンのみで、in-country リージョン (カナダ、日本など) は対象外
✗Gemini 3.8 Flash の in-country GA は今回カナダと日本のみ (他の in-country リージョンは対象外)
✗in-country リージョンの利用自体がアローリスト制のため、事前の申請が必要
✗スキルバージョンの表示・復元を行えるのはスキルのオーナーのみ

🤔 考慮すべき点

  • Web / モバイルアプリでは Gemini 4 Hydrogen がデフォルトでオフのため、有効化しない限りユーザーは利用できない。モデル展開ポリシーを事前に決めておく
  • カナダ・日本リージョンでは Gemini 3.8 Flash がデフォルトでオンになるため、モデル利用を厳格に管理している組織はトグル設定を確認する
  • in-country リージョンで非対応モデル (Gemini 4 Hydrogen 含む) を有効化すると、トラフィックがグローバルエンドポイントにルーティングされ、データレジデンシーのコミットメントが適用されなくなる点に注意
  • ドキュメントや社内資料で「Gemini Notebook Enterprise」の名称を使用している場合は、「Gemini Notebook for business」への表記更新を計画する

🎯 ユースケース

🇯🇵 ユースケース 1: 日本国内のデータレジデンシー要件下での AI アシスタント展開

シナリオ: 日本の金融機関が、顧客データを国内に保持する要件 (国内 DRZ / MLP) を満たしながら、全社員に Gemini Enterprise を展開したい。

実装例: 日本 in-country リージョン (asia-northeast1) に Gemini Enterprise アプリをプロビジョニングし、デフォルトで有効な Gemini 3.8 Flash を標準モデルとして利用。リソースロケーション組織ポリシーで global を制限し、非対応モデルの有効化による意図しないグローバルルーティングを防止する。

効果: 国内でのデータ保存と ML 処理を維持したまま GA モデルを利用でき、規制要件とユーザー体験を両立できる。

🧩 ユースケース 2: Workflow Builder での高度なエージェント構築

シナリオ: 業務部門が Workflow Builder で構築している承認ワークフローの推論品質を向上させたい。

効果: Gemini Agent ノードのモデルとして GA となった Gemini 4 Hydrogen を選択することで、複雑な条件判断や文書要約を含むワークフローの精度を向上できる。GA モデルのため本番ワークフローにも安心して採用できる。

🔄 ユースケース 3: 組織共有スキルの安全な改善サイクル

シナリオ: ブランドボイスや契約レビューなどの共有スキルを継続的に改善しているが、改悪時に即座に切り戻したい。

効果: スキルオーナーがバージョン履歴から過去の指示・ファイルを確認し、問題があれば以前のバージョンを最新として復元できるため、スキルの改善サイクルを安全に高速化できる。
