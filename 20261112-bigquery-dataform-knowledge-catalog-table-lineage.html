📊 BigQuery / Dataform
Knowledge Catalog でのテーブルレベルのデータリネージ追跡が GA

BigQuery Dataform Knowledge Catalog GA (一般提供)
リリース日: 2026-11-12

📝 概要

BigQuery パイプラインと Dataform ワークフローで実行されるアクションのテーブルレベルのデータリネージを、 Knowledge Catalog (旧 Dataplex Universal Catalog) で追跡できる機能が一般提供 (GA) になりました。 Dataform がアクションの実行時に OpenLineage 形式のイベントを Data Lineage API に自動送信し、 「アクションが読み取るテーブル → Dataform プロセス → 書き込むテーブル」という流れがリネージグラフ上に可視化されます。

💡 重要ポイント: SQLX ファイルを一切変更することなくリネージが報告されます。 BigQuery Studio で作成したパイプラインと、Dataform リポジトリで管理する SQL ワークフローの両方をカバー。 データエンジニア、データガバナンス担当者、アナリティクスエンジニアの影響分析・原因調査・ガバナンス対応を大幅に効率化します。

😣 Before (アップデート前の課題)

  • Dataform / BigQuery パイプラインによる変換の流れがリネージグラフにプロセス情報として自動統合されず、SQLX コードの読解や手動のドキュメント管理が必要だった
  • テーブル変更時の下流影響調査 (影響分析) や、不正データの発生源をワークフロー実行まで遡る調査 (原因分析) が手作業だった
  • BigQuery、Dataflow、Managed Service for Apache Airflow / Apache Spark など他サービスのリネージと Dataform の変換処理を 1 つのグラフで俯瞰できなかった

😊 After (アップデート後の改善)

  • 各アクションが BIGQUERY_PIPELINES ソースタイプのプロセスとして自動登録され、実行 (run) 単位でテーブル間リネージを記録
  • BigQuery コンソールの「リネージ」タブから Dataform プロセスノードを選択し、アクション・リポジトリ・実行履歴の確認や Open in Dataform での直接ジャンプが可能に
  • BigQuery、Airflow、Spark、Dataflow と統合された End-to-End リネージグラフを閲覧可能に
  • リネージ報告が失敗してもワークフロー実行は失敗しない設計で安心して有効化できる

Dataform ワークフローまたは BigQuery パイプラインのアクション実行時に OpenLineage イベントが Data Lineage API へ送信され、 Knowledge Catalog のリネージグラフとして BigQuery コンソールから閲覧できます。

⚡ 主要機能

1️⃣ テーブルレベルリネージの自動報告 (SQLX 変更不要)

→アクション開始時に START、終了時に COMPLETE / FAIL / ABORT の OpenLineage イベントを Data Lineage API に送信
→各 Dataform アクションは BIGQUERY_PIPELINES ソースタイプの「プロセス」、各実行は「run」として Knowledge Catalog に登録
→リネージは BigQuery 処理ロケーションのリージョナルエンドポイントに書き込まれ、利用不可の場合はグローバルエンドポイントにフォールバック

2️⃣ リネージを報告するアクションタイプ

✓フル報告 (プロセス・run・テーブル間リンク): テーブル、ビュー、増分テーブル、マテリアライズドビュー、アサーション、プロパティグラフ、データ準備、hasOutput: true のオペレーション
→hasOutput: true でないオペレーション: プロセスと run のみ報告 (テーブル間リンクなし)
✗宣言 (declaration) は他アクションの入力としてのみ出現。ノートブックと SQL ユニットテストは報告対象外

3️⃣ 4 つの主要ユースケースへの対応

→影響分析: テーブル変更前に下流のすべてのアクションとテーブルを特定
→原因分析: 不正データを、それを書き込んだアクションとワークフロー実行まで遡って追跡
→ガバナンス: プロジェクトをまたぐデータフローと、データを移動したパイプラインを提示
→End-to-End リネージ: BigQuery、Managed Service for Apache Airflow / Apache Spark、Dataflow と 1 つのグラフで統合表示

4️⃣ フェイルセーフ設計

✓Data Lineage API の無効化、権限不足、クォータ超過が発生してもリネージ報告はスキップされるだけで、ワークフロー実行は影響を受けない
→報告結果は Cloud Logging の dataform.googleapis.com/lineage_emission ログ (outcome: SUCCEEDED / SKIPPED / FAILED) で監視可能

🔬 技術仕様

📐 データリネージ情報モデルへのマッピング

データリネージオブジェクト Dataform における対応
プロセス (Process) Dataform のアクション
実行 (Run) ワークフロー呼び出しにおけるアクションの 1 回の実行
リネージイベント その run における入力テーブルから出力テーブルへのリンク

⚙️ リネージ報告の有効化設定 (workflow_settings.yaml)

初期ロールアウト期間中はオプトイン方式です。リポジトリまたは BigQuery パイプライン単位で lineage.enabled プロパティを設定します。

YAML workflow_settings.yaml 
# workflow_settings.yaml
lineage:
  enabled: true

デフォルト有効化後にオプトアウトする場合は enabled: false を設定します。プロジェクト全体で停止する場合は Data Lineage API 自体を無効化します。

✅ 前提条件

→Dataform リポジトリがあるプロジェクトと、リネージを閲覧するプロジェクトの両方で Data Lineage API (datalineage.googleapis.com) を有効化
→ワークフローを実行する ID に Data Lineage Events Producer ロール (roles/datalineage.producer) を付与 (カスタムサービスアカウント使用時はそのアカウント、未設定時は Dataform サービスエージェント service-PROJECT_NUMBER@gcp-sa-dataform.iam.gserviceaccount.com に付与)
→閲覧側には Data Lineage Viewer (roles/datalineage.viewer)、BigQuery Metadata Viewer、Dataform Viewer などの閲覧権限を付与

ステップ 1: API 有効化とロール付与

Bash API 有効化と IAM 設定 
# Data Lineage API を有効化
gcloud services enable datalineage.googleapis.com --project=PROJECT_ID

# Dataform サービスエージェントに Producer ロールを付与
gcloud projects add-iam-policy-binding PROJECT_ID \
  --member="serviceAccount:service-PROJECT_NUMBER@gcp-sa-dataform.iam.gserviceaccount.com" \
  --role="roles/datalineage.producer"

ステップ 2: workflow_settings.yaml でリネージを有効化

YAML workflow_settings.yaml 
lineage:
  enabled: true

変更をリポジトリにコミット & プッシュすると、以降のワークフロー実行でリネージが報告されます。

ステップ 3: リネージの閲覧

1.Google Cloud コンソールで BigQuery ページに移動
2.Explorer ペインで Dataform アクションが生成したテーブルを選択
3.リネージ タブをクリック
4.Dataform プロセスノードを選択すると、アクション・リポジトリ・実行履歴を確認でき、「Open in Dataform」でリポジトリを直接開ける

(オプション) Dataform CLI からのリネージ報告

ローカルや CI からの実行でもリネージを報告できます。

Bash Dataform CLI 
dataform run --emit-lineage

--emit-lineage / --no-emit-lineage フラグは、その実行 1 回に限り lineage.enabled 設定をオーバーライドします。 CLI は Application Default Credentials を使用し、各出力テーブルのプロジェクトにリネージを記録します。

🎯 メリット

💼 ビジネス面

✓ガバナンス・監査対応の強化: プロジェクト横断のデータフローと「どのパイプラインがデータを動かしたか」を公式のリネージグラフで提示でき、規制対応やデータガバナンス監査の工数を削減
✓データ品質インシデントの早期解決: 不正データの発生源をアクションとワークフロー実行まで遡れるため、原因調査の時間を短縮

⚙️ 技術面

✓コード変更ゼロで導入可能: SQLX の修正不要。workflow_settings.yaml の 1 ブロック追加と IAM 設定だけで有効化
✓パイプラインへの非干渉: リネージ報告の失敗がワークフロー実行を失敗させないフェイルセーフ設計
✓統合リネージ: BigQuery、Dataflow、Managed Service for Apache Airflow / Apache Spark と同一グラフで End-to-End に追跡

⚠️ デメリット・制約事項

🚧 制限事項

✗テーブルレベルのみ: 列レベル (column-level) リネージは報告されない
✗宣言、ノートブック、SQL ユニットテストはリネージを報告しない。hasOutput: true でないオペレーションはプロセスと run のみでテーブル間リンクは作成されない
✗ユーザー認証情報 (Google アカウント) で実行されたワークフロー呼び出しはリネージを報告しない。必要な場合はカスタムサービスアカウントを使用
✗Data Lineage API の書き込みクォータ (標準ティアで約 1,000 アクション/分) の対象
✗個々の SQLX ファイルは Knowledge Catalog の個別エントリとしてはカタログ化されない (リポジトリ/ワークフローレベルのみ)

🤔 考慮すべき点

⚠️初期ロールアウト期間中はオプトイン (lineage.enabled: true の明示設定が必要)。将来デフォルト有効化された際にオプトアウトする場合は enabled: false を設定
⚠️Data Lineage API はプロジェクト単位で課金。Dataplex API を無効化しても課金は止まらず、停止するには Data Lineage API 自体の無効化が必要
⚠️リネージメタデータの保持期間は 30 日間で、その間はメタデータストレージ SKU の課金対象
⚠️開発用プロジェクトでは不要な処理コストを避けるため、必要なプロジェクトでのみ Data Lineage API を有効化することを推奨

💡 ユースケース

🔍 ユースケース 1: テーブル変更前の影響分析

シナリオ: 中核となるディメンションテーブルのスキーマ変更を計画しており、Dataform ワークフローおよび BigQuery パイプラインで構築された下流のテーブル・ダッシュボードへの影響を事前に把握したい。

Text 実装例 
1. BigQuery コンソールで対象テーブルを選択し「リネージ」タブを開く
2. 下流方向のグラフを展開し、依存するすべての Dataform プロセスと出力テーブルを列挙
3. 各プロセスノードから「Open in Dataform」でリポジトリを開き、修正が必要な SQLX を特定

効果: 変更による破壊的影響を事前に洗い出し、ダッシュボード停止などのインシデントを未然に防止できる。

🕵️ ユースケース 2: 不正データの原因分析 (ルートコーズ分析)

シナリオ: ダッシュボードに異常な集計値が表示された。どの変換処理・どの実行が不正データを書き込んだのかを特定したい。

効果: リネージグラフを上流に遡り、該当テーブルを書き込んだ Dataform アクションとワークフロー呼び出し (run) を特定。Cloud Logging の実行ログと突き合わせて、修正対象のコードと再実行範囲を迅速に確定できる。

🌐 ユースケース 3: マルチサービス環境での End-to-End ガバナンス

シナリオ: Dataflow でのストリーミング取り込み、Managed Service for Apache Airflow でのオーケストレーション、Dataform での変換が混在するデータ基盤で、組織横断のデータフローを 1 つのビューで説明する必要がある。

効果: Knowledge Catalog 上で各サービスのリネージが統合され、プロジェクトをまたぐデータの流れと担当パイプラインを単一のグラフで提示できる。

💰 料金

データリネージは Knowledge Catalog の Premium Processing SKU (Data Compute Unit: DCU 単位) で課金されます。 Dataform のリネージ取り込みでは、テーブル間リネージリンクを書き込むイベントのみが課金対象です。 リネージメタデータ (プロセス、run、イベント、リンク) の保存 (30 日間保持) はメタデータストレージ SKU で課金されます。 コンソールでのリネージ閲覧に BigQuery のクエリ/スキャン料金は発生しません。

🌍 利用可能リージョン

Dataform が利用可能なすべてのロケーションで Knowledge Catalog との連携を利用できます。 リネージはアクションの BigQuery 処理ロケーションのリージョナルエンドポイントに書き込まれます。 詳細は Dataform のロケーション を参照してください。

🔗 関連サービス・機能

→Knowledge Catalog (旧 Dataplex Universal Catalog): リネージグラフの保存・可視化基盤。Dataform リポジトリのメタデータも自動的にカタログ化される
→Data Lineage API: OpenLineage イベントの受け口。有効化・課金の単位となる API
→BigQuery パイプライン: Dataform を実行基盤とする BigQuery Studio のパイプライン機能。本アップデートの対象
→Dataflow / Managed Service for Apache Airflow / Managed Service for Apache Spark: それぞれ独自にリネージを報告し、Dataform のリネージと統合された End-to-End グラフを構成する
→Cloud Logging / Cloud Monitoring: lineage_emission ログによるリネージ報告状況の監視と、パイプライン失敗のアラート設定に使用
