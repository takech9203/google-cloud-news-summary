Config Controller: バージョンアップデート

Config Controller Change
2026-05-21

⚡ 概要

Config Controller に含まれる Config Connector v1.148.0-cc.3 と Config Sync v1.23.3 への自動アップグレードが実施されました。マネージドサービスとして Google が自動的にアップグレードを行うため、ユーザー側の作業は不要です。

今回のアップデートにより、新リソースサポート (ParameterManagerParameterVersion)、AI ツール統合 (MCP サーバー)、安定性向上 (SQLInstance 修正)、セキュリティ強化 (CVE 対応) が包括的に提供されます。

❌ Before (アップデート前)

  • Parameter Manager パラメータバージョンのリソース管理不可
  • SQLInstance で dataCacheConfig の不正な差分検出
  • Open Telemetry イメージに脆弱性
  • Helm バンドルが古くセキュリティ修正未適用

✅ After (アップデート後)

  • ParameterManagerParameterVersion リソースが利用可能
  • SQLInstance の差分検出バグ修正済み
  • Open Telemetry v0.133.0 で脆弱性修正
  • Helm v3.20.0 でセキュリティ強化

🌟 主要機能

Config Connector v1.148.0-cc.3 の新機能

🤖 MCP サーバー統合

kompanion ツールに Model Context Protocol サーバーが追加。AI IDE やアシスタントが Config Connector リソースと対話可能に。

📦 ParameterManagerParameterVersion

Parameter Manager パラメータバージョンの新規リソースサポート (Alpha, Direct Reconciler)。

🔗 MultiClusterLeaseSpec 改善

KRM オブジェクトの Syncer 統合をサポートし、サービス生成 ID を持つリソースの所有権管理が改善。

🔧 --skip-name-validation フラグ

統合テストやマルチマネージャーシナリオでの名前検証スキップが可能に。

Config Connector v1.148.0-cc.3 のバグ修正

✓SQLInstance: dataCacheConfig の不正な差分検出を修正
✓SQLInstance: nil 値と空オブジェクトの比較を修正し、不要なリコンサイルループを解消
✓TagKey/TagValue: ALREADY_EXISTS エラーの適切なハンドリング
✓BigQueryAnalyticsHubDataExchange: 構造化レポーティング差分の追加
✓CloudBuildTrigger: CRD の説明欠落を修正

Config Sync v1.23.3 の変更点

✓Open Telemetry イメージを v0.127.0 から v0.133.0 にアップグレード (脆弱性修正)
✓pkg.translator.prometheus.NormalizeName フィーチャーゲートが Stable に昇格
✓Helm バンドルバージョンを v3.18.6 から v3.20.0 にアップグレード (脆弱性修正)
✓複数の CVE に対応するための依存関係更新

🛠 設定方法

💡 重要: Config Controller はマネージドサービスのため、Google が自動的にアップグレードを実施します。ユーザー側での手動アップグレード操作は不要です。

バージョンの確認方法

Bash 
# Config Controller インスタンスのバージョンを確認
gcloud anthos config controller list --location=LOCATION
Bash 
# クラスター内の Config Connector バージョンを確認
kubectl get ns cnrm-system -o jsonpath='{.metadata.annotations.cnrm\.cloud\.google\.com/version}'
Bash 
# Config Sync のステータスを確認
kubectl get rootsync -n config-management-system

⚙ 技術面

✓マルチクラスター管理改善: Syncer 統合でリソース所有権管理向上
✓Helm 最新版対応: v3.20.0 で最新チャート機能と修正を利用可能

⚠️ 制限事項・注意点

✗Config Controller のアップグレードタイミングはユーザーが制御できない (Google による自動実施)
✗ParameterManagerParameterVersion は Alpha リリースのため、本番環境での使用は推奨されない
✗Open Telemetry アップグレードで NormalizeName が Stable に昇格 - メトリクス名の正規化動作が変更される可能性
🔎 考慮すべき点:
  • Open Telemetry v0.133.0 へのアップグレードでカスタムメトリクスソリューションへの影響を確認
  • Helm v3.20.0 のチェンジログで既存チャートとの互換性を検証
  • Config Connector の大幅バージョンジャンプ (v1.134.4 → v1.148.0) のためリリースノートを確認

🎯 ユースケース

📦 ユースケース 1: Parameter Manager による機密設定の宣言的管理

アプリケーションの設定パラメータをリージョナルに管理したい場合、Config Connector の ParameterManagerParameterVersion リソースを使用して Git リポジトリから宣言的に管理できます。Secret Manager と連携した Parameter Manager のリソースを GitOps ワークフローで管理でき、インフラのコード化が促進されます。

YAML 
apiVersion: parametermanager.cnrm.cloud.google.com/v1alpha1
kind: ParameterManagerParameterVersion
metadata:
  name: app-config-v1
  namespace: config-control
spec:
  parameterRef:
    name: my-app-config
  parameterVersionData:
    plainText: "database_host=10.0.0.1"

🤖 ユースケース 2: AI アシスタントによるインフラ管理

kompanion の MCP サーバー機能を使用して、AI IDE (Cursor, VS Code + Copilot 等) から Config Connector リソースの状態を確認し、トラブルシューティングを行います。インフラ管理の効率化と、問題発生時の迅速な原因特定が可能になります。

📝 まとめ

今回の Config Controller アップデートは、Config Connector v1.148.0-cc.3 と Config Sync v1.23.3 への更新により、以下を包括的に提供するものです。

✓新リソースサポート - ParameterManagerParameterVersion
✓AI ツール統合 - MCP サーバーによる AI IDE 連携
✓安定性向上 - SQLInstance 差分検出修正
✓セキュリティ強化 - CVE 対応・依存関係更新

マネージドサービスとして自動適用されるため、ユーザーは特別な対応なく最新の改善を享受できます。既存の Config Controller ユーザーは、リソースの動作に変更がないか確認し、新機能の活用を検討することを推奨します。
