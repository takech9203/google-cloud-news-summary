📋 概要

GKE の Rapid リリースチャネル において、2026-R21 バージョンアップデートが実施されました。 新しいクラスタ作成時のデフォルトバージョンが 1.35.5-gke.1000000 に更新され、 Kubernetes 1.33 から 1.36 までの最新パッチバージョンが追加されています。

❌ Before (アップデート前)

  • デフォルトバージョンに最新セキュリティ修正が未適用

  • 自動アップグレードパスが未更新

✅ After (アップデート後)

  • 古いバージョン削除で既知の問題を回避
  • 1.32 → 1.33 → 1.34 → 1.35 の自動アップグレードパス確立

⚡ 主要機能

🎯 デフォルトバージョンの更新

Rapid チャネルの新規クラスタ作成時のデフォルトバージョンが 1.35.5-gke.1000000 に更新されました。新規クラスタは自動的にこのバージョンで作成され、最新のセキュリティパッチと安定性改善が含まれます。

📦 新バージョンの追加

マイナーバージョン パッチバージョン 備考
Kubernetes 1.33 1.33.12-gke.1059000 延長サポート向け
Kubernetes 1.34 1.34.8-gke.1126000 安定版パッチ
Kubernetes 1.35 1.35.5-gke.1057000 現行推奨バージョン
Kubernetes 1.36 1.36.0-gke.2459000 最新マイナーバージョン

🔧 設定方法

💡 前提条件: Google Cloud プロジェクトで GKE API が有効であり、gcloud CLI がインストール済みで認証されていること。IAM 権限 container.clusters.update が必要です。

Step 1: 現在のクラスタバージョンを確認

Bash 
# クラスタの現在のバージョンを確認
gcloud container clusters describe CLUSTER_NAME \
  --location=LOCATION \
  --format="value(currentMasterVersion)"

Step 2: Rapid チャネルの利用可能バージョンを確認

Bash 
# Rapid チャネルの利用可能バージョンを一覧表示
gcloud container get-server-config \
  --flatten="channels" \
  --filter="channels.channel=RAPID" \
  --format="yaml(channels.channel,channels.validVersions)" \
  --location=LOCATION

Step 3: クラスタを手動でアップグレード (任意)

Bash 
# コントロールプレーンを特定のバージョンにアップグレード
gcloud container clusters upgrade CLUSTER_NAME \
  --location=LOCATION \
  --master \
  --cluster-version=1.35.5-gke.1057000

Step 4: ノードプールのアップグレード

Bash 
# ノードプールをアップグレード
gcloud container clusters upgrade CLUSTER_NAME \
  --location=LOCATION \
  --node-pool=NODE_POOL_NAME

🎯 ユースケース

🧪 ユースケース 1: プリプロダクション環境での Kubernetes 1.36 検証

開発チームが Kubernetes 1.36 の新機能 (新しい API やスケジューリング改善など) を本番導入前に検証したい場合

Bash 
# Rapid チャネルで 1.36 を使用するクラスタを作成
gcloud container clusters create test-cluster-136 \
  --location=us-central1 \
  --release-channel=rapid \
  --cluster-version=1.36.0-gke.2459000 \
  --num-nodes=3

効果: 本番環境に影響を与えることなく、最新の Kubernetes 機能と GKE パッチの動作を事前検証できる

🔒 ユースケース 2: セキュリティパッチの迅速な適用

セキュリティ要件の厳しい組織が、最新のセキュリティ修正を含むパッチバージョンへ迅速にアップグレードしたい場合

Bash 
# 既存クラスタを最新パッチへ手動アップグレード
gcloud container clusters upgrade my-cluster \
  --location=asia-northeast1 \
  --master \
  --cluster-version=1.35.5-gke.1057000

# accelerated patch auto-upgrades を有効化
gcloud container clusters update my-cluster \
  --location=asia-northeast1 \
  --accelerated-patch-auto-upgrades

効果: セキュリティ脆弱性の露出期間を最小化

📅 ユースケース 3: マイナーバージョン移行の計画

1.32 系クラスタを運用しているチームが、自動アップグレードに備えて 1.33 への移行テストを実施する場合

Bash 
# メンテナンスウィンドウを設定して計画的にアップグレード
gcloud container clusters update my-cluster \
  --location=asia-northeast1 \
  --maintenance-window-start=2026-06-01T02:00:00Z \
  --maintenance-window-end=2026-06-01T06:00:00Z \
  --maintenance-window-recurrence="FREQ=WEEKLY;BYDAY=SA"

効果: 計画されたメンテナンスウィンドウ内で自動アップグレードを実行させ、本番ワークロードへの影響を最小限に抑える

⚖️ メリット・デメリット

✅ メリット

ビジネス面
  • セキュリティリスクの低減
  • 運用コストの削減 (手動バージョン管理の負担軽減)
  • GKE SLA 対象範囲の確保
技術面
  • Kubernetes 1.36 の最新機能へのアクセス
  • 既知の問題があるバージョンの使用防止
  • 予測可能なバージョン移行の実現
  • コントロールプレーンとノード間のバージョン互換性維持

⚠️ デメリット・制約事項

制限事項
  • Rapid チャネルは GKE SLA の対象外
  • 削除バージョンへのダウングレード不可
  • 自動アップグレードは即座に適用されない場合あり
  • 本番環境ではなくプリプロダクション環境推奨
考慮すべき点
  • テスト不十分なバージョンへの移行リスク
  • 非推奨 API の互換性確認が必要
  • ノードプールアップグレード時の PodDisruptionBudget 確認
  • 1.36 は Regular/Stable への昇格に数か月必要

📝 まとめ

GKE 2026-R21 バージョンアップデートにより、Rapid チャネルのデフォルトバージョンが 1.35.5-gke.1000000 に更新され、 Kubernetes 1.33 から 1.36 までの最新パッチバージョンが利用可能になりました。 自動アップグレードターゲットが 1.32 から 1.35 へのパスで設定されているため、 Rapid チャネルに登録されたクラスタは段階的に新しいバージョンへ移行されます。

💡 推奨事項: Rapid チャネルを使用してプリプロダクション環境での検証を行い、Regular/Stable チャネルへの昇格前に互換性を確認することを推奨します。
