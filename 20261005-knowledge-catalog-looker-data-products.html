📦 データプロダクトが Looker アセットに対応

「データ + BI」を 1 つのプロダクトとして共有・ガバナンス
リリース日
2026-10-05

📋 概要

Knowledge Catalog (旧 Dataplex Universal Catalog) のデータプロダクト機能が Looker (Google Cloud core) アセットに対応し GA となりました。 ダッシュボード、Look、Explore、LookML プロジェクト・モデル・ビューをデータプロダクトとしてパッケージ化し、ガバナンスを適用した上で組織内に共有できます。

アクセス制御には Google グループミラーリング + IAM を組み合わせ、アクセスリクエストが承認されると Google グループへ自動追加され、ミラーリングされた Looker グループを通じてコンテンツへのアクセスが付与されます。 BigQuery などの「データ」と、その上の BI レイヤー (ダッシュボードやセマンティックモデル) を 1 つのデータプロダクトとして束ねて提供できる、データメッシュ運用に重要な機能強化です。

❌ Before: アップデート前の課題

  • データプロダクトに含められるのは BigQuery、Cloud Storage、Iceberg REST Catalog などのデータアセットが中心で、Looker の BI アセットはパッケージ化できなかった
  • Looker コンテンツへのアクセス付与は、承認ワークフローとは別に Looker 側で個別にユーザー・グループ管理が必要だった
  • データと可視化レイヤーを一体で発見・共有する仕組みがなく、消費者はデータとダッシュボードを別々に探す必要があった

✅ After: アップデート後の改善

  • ダッシュボード、ダッシュボードエレメント、Look、Explore、LookML プロジェクト・モデル・ビューをデータプロダクトのアセットとして登録可能に
  • Google グループミラーリングと IAM により、アクセス承認ワークフローで Looker コンテンツへのアクセスを一元管理
  • BigQuery テーブルと Looker ダッシュボードを同一プロダクトに含め、「データ + BI」をまとめて検索・共有・ガバナンス
  • GA となり本番環境での利用が正式サポート

データプロデューサーは BigQuery アセットと Looker アセットを 1 つのデータプロダクトにパッケージ化。コンシューマーのアクセスリクエストが承認されると、Google グループへの追加と Looker のグループミラーリングを通じて、データと BI コンテンツの両方へのアクセスが付与されます。

⚡ 主要機能

📊 1. Looker アセットのデータプロダクトへの登録

→ダッシュボード、ダッシュボードエレメント、Look、Explore、LookML プロジェクト / モデル / ビューをアセットとして追加可能
→BigQuery データセット / テーブル / ビュー / ルーティン / モデル、Cloud Storage バケット、Iceberg REST Catalog など既存アセットと同一のデータプロダクトに混在可能

👥 2. Google グループミラーリングによるアクセス制御

→アクセスグループに Google グループをマッピングし、Looker 側で Google OAuth 認証とミラーリンググループを有効化すると、メンバーシップが Looker グループに自動反映
→承認されたコンシューマーは、ミラーリングされた Looker グループを通じてコンテンツ (フォルダアクセスレベル、Looker ロール) にアクセス

🔄 3. 統合されたアクセスリクエスト・承認ワークフロー

→Knowledge Catalog の検索でプロダクトを発見し、コンソールまたは REST API (:requestAccess) からビジネス上の正当性 (justification) を添えてリクエスト
→オーナー承認後、グループ追加と権限プロビジョニングが自動実行され、ステータスはメール通知

1Looker (Google Cloud core) 側の準備

Looker インスタンスで Google OAuth とミラーリンググループを有効化し、ミラーリングされる Looker グループにフォルダアクセスレベルと Looker ロールを割り当てます。

Bash Knowledge Catalog 統合の確認 (デフォルトで有効) 
# Knowledge Catalog 統合が有効なことを確認 (デフォルトで有効)
gcloud looker instances describe INSTANCE_NAME --region=REGION

2データプロダクトの作成と Looker アセットの追加

「Knowledge Catalog > Data products」ページ、または REST API でデータプロダクトを作成し、Looker アセットを追加します。

Bash データアセットの追加 (REST API) 
curl -X POST \
  -H "Authorization: Bearer $(gcloud auth print-access-token)" \
  -H "Content-Type: application/json" \
  -d '{"resource": "RESOURCE_NAME"}' \
  "https://dataplex.googleapis.com/v1/projects/PROJECT_ID/locations/LOCATION/dataProducts/DATA_PRODUCT_ID/dataAssets?data_asset_id=DATA_ASSET_ID"

3アクセスグループの構成

「Access groups & permissions」タブでアクセスグループを作成し、識別子として Google グループのメールアドレスを設定します。Looker アセットについては、Looker インスタンス内でミラーリンググループに対する権限設定を手動で行います。

4コンシューマーによるアクセスリクエスト

Bash アクセスリクエストの送信 (REST API) 
curl -X POST \
  -H "Authorization: Bearer $(gcloud auth print-access-token)" \
  -H "Content-Type: application/json" \
  -d '{
    "parent": "projects/PROJECT_ID/locations/LOCATION/dataProducts/DATA_PRODUCT_ID",
    "change_request": {
      "justification": "JUSTIFICATION_TEXT",
      "data_product_access_request": {
        "parent": "projects/PROJECT_ID/locations/LOCATION/dataProducts/DATA_PRODUCT_ID",
        "access_group_id": "ACCESS_GROUP_ID"
      }
    }
  }' \
  "https://dataplex.googleapis.com/v1/projects/PROJECT_ID/locations/LOCATION/dataProducts/DATA_PRODUCT_ID:requestAccess"

データプロダクトオーナーが承認すると、コンシューマーは Google グループに追加され、Looker コンテンツへのアクセスが可能になります。

💼 ビジネス面

✓データとインサイトの一体提供: 生データだけでなくキュレーション済みダッシュボードやセマンティックモデルまでを 1 プロダクトとして提供でき、データ活用の立ち上がりが早くなる
✓ガバナンスの一元化: 承認ワークフロー、正当性の記録、アクセスの追跡がプロダクト単位に統合され、監査・コンプライアンス対応が容易に
✓データメッシュの実現: ドメインチームが「データ + BI」のプロダクトをセルフサービスで公開・共有可能に

⚙️ 技術面

✓アクセス制御の自動化: 承認時のグループ追加と Looker グループミラーリングにより、Looker 側のユーザー個別管理が不要に
✓IAM との統合: BigQuery アセットへの IAM ロール付与と Looker アセットへのアクセス付与を同じアクセスグループで扱える
✓GA 品質: 一般提供となり、SLA を含む本番環境での利用が正式サポート

⚠️ デメリット・制約事項

🚫 制限事項

✗サービスアカウント非対応: Google グループミラーリングは人間のユーザー ID のみサポートのため、Looker アセットを含むアクセスグループにサービスアカウントを含めることは不可
✗デフォルトロール非対応: アクセスグループレベルのデフォルト IAM ロールは Looker アセットには適用されず「Unsupported」と表示。Looker アセットごとに明示的な権限構成が必要
✗Looker 内の権限は手動同期: データプロダクト上のロール名はコンシューマー向け情報提供用プレースホルダーであり、実際のフォルダアクセスレベルや Looker ロールはプロデューサーが Looker インスタンス内で手動構成・維持
✗ロケーション制約: データプロダクトとアセットは同一の Google Cloud ロケーションに存在する必要がある

🤔 考慮すべき点

  • Looker メタデータのカタログ同期はバッチ処理 (約 4 時間ごとの同期、約 1 時間ごとの反映) のため、LookML の変更は即座に反映されない
  • アクセスグループは 1 プロダクトあたり最大 3 つのため、ロール設計 (例: Viewer / Analyst / Developer) を事前に整理する
  • データプロダクト API のレート制限・容量クォータは「Quotas for data products API requests」を確認する
