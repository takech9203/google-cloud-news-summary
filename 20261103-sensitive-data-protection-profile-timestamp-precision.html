🔒 Sensitive Data Protection Change (変更)

⏰ データプロファイルの
最終生成タイムスタンプの精度向上

📅 リリース日: 2026-11-03

📝 概要

Sensitive Data Protection のディスカバリ サービスが生成するデータプロファイルにおいて、 「最終生成タイムスタンプ (Last profile generated / profileLastGenerated)」の記録精度が向上しました。 このタイムスタンプは、実際にリソースのデータが読み取られた時刻に近い値として記録されるようになります。

データプロファイルは、BigQuery テーブル、Cloud SQL テーブル、Cloud Storage などのファイルストア、Vertex AI リソースに含まれる 機密データのセンシティビティとデータリスクを可視化するメタデータです。「最終生成タイムスタンプ」はプロファイルの鮮度を判断する基準であり、 データガバナンスやコンプライアンス監査において「この評価結果はいつ時点のデータに基づくものか」を示す重要な情報です。

❌ Before: アップデート前の課題

  • タイムスタンプが、実際にリソースのデータを読み取った時刻と乖離する場合があった
  • プロファイリングは読み取りから完了まで時間を要することがあり (リプロファイルは最大 24 時間)、「どの時点のデータ状態を反映した評価か」を正確に判断しにくかった
  • 鮮度を基準にデータ変更の反映有無を推定する運用では、評価時点の解釈に幅が生じていた

✅ After: アップデート後の改善

  • タイムスタンプがデータ読み取り時刻に近い精度で記録されるようになった
  • プロファイルが「いつ時点のデータ」を反映しているかをより正確に把握できる
  • 鮮度監視や監査証跡としての信頼性が向上
💡 ポイント: データプロファイルを BigQuery にエクスポートして鮮度を監視しているチームや、 Security Command Center と連携してリスク評価を行っている組織にとって、プロファイルの時点をより正確に解釈できるようになる改善です。

⚙️ 主要機能

1️⃣ 最終生成タイムスタンプの精度向上

データプロファイルの「Last profile generated (最終生成日時)」フィールドが、リソースデータの読み取り時刻に近い値で記録されます。プロファイルが反映しているデータの時点をより正確に解釈できます。

2️⃣ 対象となるタイムスタンプ フィールド

プロジェクト / テーブル / ファイルストアの各データプロファイルのメタデータに含まれる「最終生成日時」が対象です。Google Cloud コンソールのダッシュボード表示、API レスポンス、BigQuery エクスポートのいずれでも参照されるフィールドです。

3️⃣ 既存ワークフローへの影響なし

ユーザー側の設定変更は不要。既存のスキャン構成のまま、新しく生成・更新されるプロファイルに自動適用されます。プロファイリングの頻度や課金体系に変更はありません。

🔬 技術仕様

📋 データプロファイルの主なタイムスタンプ関連メタデータ

フィールド 説明
Profile first created プロファイルが最初に作成された日時
Last profile generated プロファイルが最後に生成された日時 (今回精度が向上 ⏰)
Latest update in BigQuery 対象テーブルが最後に変更された日時 (BigQuery テーブル プロファイルの場合)

🔄 プロファイリングの頻度 (参考)

設定 動作
初回スキャン スキャン構成作成後に実行
デフォルトのリプロファイル 30 日待機後、スキーマ・行・検査テンプレートの変更があれば再生成 (ディスカバリ タイプにより条件が異なる)
カスタム頻度 再生成しない / 毎日 / 毎週 / 毎月 から選択可能
💡 補足: リプロファイルの開始から完了までは最大 24 時間かかる場合があります。 今回の変更により、完了タイミングに左右されず、データ読み取り時点に近いタイムスタンプが記録されます。

🎯 メリット

💼 ビジネス面

✓ 監査・コンプライアンス対応の精度向上: 「この機密データ評価はいつ時点のデータに基づくか」を正確に示せるため、監査証跡としての信頼性が高まる
✓ データガバナンスの判断精度向上: プロファイルの鮮度を基準としたレビューや棚卸しにおいて、評価時点の解釈のずれを減らせる

🔧 技術面

✓ 鮮度監視の正確化: プロファイルを BigQuery にエクスポートして鮮度を SQL で監視している場合、読み取り時点に基づくより正確な分析が可能
✓ データ変更との突き合わせが容易に: テーブルの最終更新日時とプロファイルのタイムスタンプを比較し、変更が反映済みかを判断しやすい
✓ 設定変更不要: 既存のスキャン構成のまま自動的に適用される

⚠️ デメリット・制約事項

⚠️ 考慮すべき点:
  • タイムスタンプの解釈が「プロファイル生成完了時刻」から「データ読み取り時刻に近い値」に変わるため、このフィールドを厳密に利用している監視クエリやレポートがある場合は、変更後の値の意味を確認しておくことが望ましい
  • 過去に生成済みのプロファイルのタイムスタンプが遡って修正されるものではなく、今後生成・更新されるプロファイルに適用される

💡 ユースケース

📊 ユースケース 1: BigQuery エクスポートによるプロファイル鮮度の監視

シナリオ: データプロファイルを BigQuery データセットに保存し、機密データ評価の鮮度を定期的に監視している。

SQL 鮮度監視クエリの実装例 
-- 最終生成から 30 日以上経過したテーブル プロファイルを抽出
SELECT
  table_id,
  profile_last_generated,
  TIMESTAMP_DIFF(CURRENT_TIMESTAMP(), profile_last_generated, DAY) AS days_since_profiled
FROM
  `my-project.dlp_profiles.table_profiles`
WHERE
  TIMESTAMP_DIFF(CURRENT_TIMESTAMP(), profile_last_generated, DAY) > 30
ORDER BY
  days_since_profiled DESC;

✅ 効果: タイムスタンプがデータ読み取り時点に近くなったことで、「評価がどの時点のデータに基づくか」を正確に判定でき、鮮度アラートの精度が向上する。

🔄 ユースケース 2: データ変更とプロファイル反映状況の突き合わせ

シナリオ: 機密データを含む BigQuery テーブルに大規模なデータ投入を行った後、その変更が最新のデータプロファイルに反映されているかを確認したい。
