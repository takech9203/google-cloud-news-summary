Gemini 3.6/3.7 Flash 対応・--unrestricted フラグ・バグ修正
リリース日: 2026-08-27
Gemini Enterprise Agent PlatformCodeMender: Preview

📌 概要

CodeMender は Google DeepMind が開発したセキュリティ特化ハーネスを備えた 自律型 AI コードセキュリティエージェント。脆弱性の発見 (cm find)、 PoC エクスプロイト実行による悪用可能性の検証 (cm verify)、検証済みパッチの生成 (cm fix) を行う。

🔍 cm find
脆弱性を発見
→
🧪 cm verify
PoC で悪用可能性を検証
→
🩹 cm fix
検証済みパッチを生成

今回のリリースの 3 本柱:

1️⃣モデルサポート拡充: Gemini 3.6 Flash / 3.7 Flash を追加。gemini-3.7-flash が新デフォルト
2️⃣cm verify --unrestricted: 隔離環境でコマンドポリシー制限をバイパスしてエクスプロイト検証
3️⃣バグ修正: 長時間セッションの信頼性向上ほか複数の修正

❌ Before (アップデート前)

  • Gemini 3 ファミリーの最新 Flash モデル (3.6 / 3.7) が使えず、デフォルトは gemini-3.5-flash
  • cm verify で常にサンドボックスのコマンドポリシーが適用され、隔離環境での複雑なエクスプロイト検証に制約
  • 長時間セッションの信頼性、OS 間シェル解決、権限拒否メッセージ、相対パス起因の初期化失敗などの問題

✅ After (アップデート後)

  • Gemini 3.6 / 3.7 Flash が利用可能に。デフォルトは gemini-3.7-flash (Terminal-bench 2.1: 85.1%、DeepSWE: 63.7% と大幅向上)
  • --unrestricted でファイルシステム境界・OS レベルのコンテナ分離を一時的にバイパスして検証可能
  • 長時間セッションの信頼性向上、シェル解決の改善、エラーメッセージの明確化、初期化失敗の修正

CodeMender はローカルの CLI/デーモンとクラウド側のホスト型エージェントで構成され、 ソースコードリポジトリ全体はアップロードされない。 今回のアップデートで推論に使うモデルの選択肢が拡大し、cm verify にサンドボックス制限をバイパスする --unrestricted フラグが追加された。

⚙️ 主要機能

✨ 1. モデルサポート: Gemini 3.6 Flash / 3.7 Flash NEW

✓gemini-3.6-flash と gemini-3.7-flash をサポートし、gemini-3.7-flash が新デフォルトに
✓サポートモデルは 3.7 Flash / 3.6 Flash / 3.5 Flash / 3.1 Pro (Preview)。コスト・速度・深いコーディング性能のトレードオフで選択可能
✓Gemini 3.7 Flash は「エージェント向けワークホース」。3.6 Flash と同一価格帯でコード生成・ターミナル実行性能が大幅向上 (GA、2026-08-13 リリース)

🔓 2. 無制限検証: cm verify --unrestricted NEW

✓エクスプロイト検証時にコマンドポリシー制限をバイパスするフラグ
✓ファイルシステム境界と OS レベルのコンテナ分離を当該実行に限り無効化
⚠隔離環境 (使い捨て VM / コンテナ) での利用が前提。通常の開発環境ではデフォルトのサンドボックス維持を強く推奨

🔧 3. バグ修正

✓長時間セッションの信頼性向上
✓実行環境 (OS) をまたぐシェル解決の改善
✓権限拒否 (permission denied) エラーメッセージの明確化
✓相対パスに起因するサンドボックス初期化失敗の修正

CodeMender の構成要素

項目詳細
Agentコアのビジネスロジックと推論を実行するホスト型マルチエージェントシステム
Clientローカルマシン上の CLI 兼デーモン。プロセスレベルのサンドボックス内でビルド・テスト・脆弱性検証を実行
対応言語C/C++、Go、Java、Python、TypeScript/JavaScript、Rust、Ruby
対応フレームワークHTML/CSS、Django、Flask、React、Spring Boot、Express など
サポートモデルGemini 3.7 Flash (デフォルト 🆕)、Gemini 3.6 Flash 🆕、Gemini 3.5 Flash、Gemini 3.1 Pro (Preview)

データ保持セッションデータは最大 7 日間 (暗号化保存)、DeleteInteraction で即時削除可能。モデル学習には不使用

cm verify の主なフラグ

フラグ説明
-c / --contextエージェントへの追加コンテキスト・指示を渡す
--skip-exploit-verificationPoC エクスプロイトを実行せず静的検証のみ行う
--sandboxサンドボックスの有効/無効を明示的に制御 (例: --sandbox=false)
--unrestricted 🆕サンドボックス保護 (ファイルシステム境界、OS レベルのコンテナ分離) を当該実行に限りバイパス
-y / --yesツール実行と PoC エクスプロイト実行の確認プロンプトを自動承認 (CI/CD 向け)

🛠️ 設定方法

前提条件

→CodeMender CLI がインストール・構成済みであること (Install and configure the CLI)
→--unrestricted を使う場合は、隔離された VM またはコンテナ環境で CLI を実行すること (公式推奨)

ステップ 1: 脆弱性のスキャンと検証対象の特定

Bash スキャンとレポート確認 
# 対象ディレクトリをスキャン (10〜50 ファイル単位を推奨)
cm find ./src/auth/

# レポートから finding-id を確認
cm report

ステップ 2: 隔離環境で無制限検証を実行

Bash cm verify の実行パターン 
# デフォルト (サンドボックス内での検証)
cm verify FINDING_ID

# 隔離環境でコマンドポリシー制限をバイパスして検証 (新機能)
cm verify FINDING_ID --unrestricted

# CI/CD パイプラインでの自動承認と組み合わせる場合
cm verify FINDING_ID --unrestricted -y

ステップ 3: モデルの指定

Bash モデル指定 
# デフォルトは gemini-3.7-flash。コマンド実行時にモデルを指定可能
# 詳細: https://docs.cloud.google.com/gemini-enterprise-agent-platform/codemender#specifying-the-model

⚠️ 制約・考慮事項

🚧 制限事項
✗CodeMender は Preview 段階 (Pre-GA Offerings Terms が適用、サポート限定の場合あり)
✗Gemini 3.7 Flash では thinking_level="MINIMAL" が利用不可 (API バリデーションエラー)
🤔 考慮すべき点

→CodeMender はホスト上でコマンド実行・ファイル変更を行う可能性がある点に留意

🎯 ユースケース

🔁 ユースケース 1: CI/CD パイプラインでの自動脆弱性検証

シナリオ: 使い捨てコンテナで動く CI パイプラインに CodeMender の検証ステップを組み込み、静的スキャナの検出結果 (Wiz などからのインポートを含む) の悪用可能性を自動検証したい。サンドボックスのコマンドポリシーが特定のエクスプロイト PoC の実行を妨げていた。

Bash 使い捨てコンテナ内での自動検証 
# 使い捨てコンテナ内で、制限をバイパスしつつ自動承認で検証
cm verify FINDING_ID --unrestricted -y

効果: 隔離環境の CI 上で検証が完結し、悪用可能と確認された脆弱性のみを開発者にエスカレーション。誤検知のトリアージ工数を削減。

📈 ユースケース 2: デフォルトモデル更新による検証・修復品質の底上げ

シナリオ: これまで gemini-3.5-flash で CodeMender を運用していたチームが、追加コストを抑えつつ修復パッチの品質とターミナル操作の成功率を高めたい。

効果: デフォルトが gemini-3.7-flash となり、設定変更なしで最新モデルの性能 (Terminal-bench 2.1: 85.1%、DeepSWE: 63.7%) の恩恵を受けられる。深い推論が必要な複雑ケースのみ Gemini 3.1 Pro に切り替える運用も可能。
