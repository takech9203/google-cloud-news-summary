🗄️ Bigtable: Go クライアントで Data Boost 対応

2026-07-09 | Cloud Bigtable
Feature Cloud Bigtable Go Client Library Data Boost

📋 概要

Bigtable の Go クライアントライブラリ (cloud.google.com/go/bigtable) が Data Boost に対応。Go アプリケーションからサーバーレスコンピュートを使用した高スループットの読み取りジョブとクエリの実行が可能に。

Data Boost は、アプリケーショントラフィックを処理するクラスタのパフォーマンスに影響を与えることなく、Bigtable データに対して高スループットの読み取りジョブを実行できるサーバーレスコンピュートサービス。これまで Java クライアントライブラリのみの対応だったが、今回 Go 開発者も利用可能に。

❌ Before (アップデート前)

  • Go クライアントでは Data Boost が利用不可
  • 大規模分析で本番トラフィックに影響の恐れ
  • Data Boost 利用には Java への言語変更が必要

✅ After (アップデート後)

  • Go から直接 Data Boost アプリプロファイルを使用可能
  • 本番クラスタに負荷をかけず分析実行
  • 言語変更なしで高スループット読み取り機能を活用

⚡ 主要機能

1. Go クライアントからの Data Boost 読み取り

→cloud.google.com/go/bigtable パッケージで Data Boost アプリプロファイル経由の読み取りリクエスト送信
→ReadRows API を使用した高スループットスキャンに対応
→サーバーレスコンピュートでクラスタノードのキャパシティに影響なし

2. SQL クエリのサポート (Enterprise Plus)

→Enterprise Plus エディションでは Data Boost 経由で SQL クエリ実行可能
→ExecuteQuery および PrepareQuery API メソッドに対応

3. ワークロード分離

→分析トラフィックと本番アプリケーショントラフィックを完全に分離
→クラスタのノード数を分析ワークロードのために調整する必要なし

💻 実装例

Data Boost アプリプロファイルを指定してクライアントを作成し、高スループット読み取りを実行する例。

Go Data Boost アプリプロファイル接続設定 
package main

import (
    "context"
    "log"

    "cloud.google.com/go/bigtable"
)

func main() {
    ctx := context.Background()
    project := "my-project-id"
    instance := "my-instance-id"

    // Data Boost アプリプロファイルを指定してクライアントを作成
    clientConf := bigtable.ClientConfig{
        AppProfile: "data-boost-profile",
    }
    client, err := bigtable.NewClientWithConfig(ctx, project, instance, clientConf)
    if err != nil {
        log.Fatalf("Could not create client: %v", err)
    }
    defer client.Close()

    tbl := client.Open("my-table")

    // Data Boost を使用した高スループット読み取り
    err = tbl.ReadRows(ctx, bigtable.PrefixRange("row-prefix"),
        func(row bigtable.Row) bool {
            // 行の処理
            return true
        })
    if err != nil {
        log.Fatalf("Could not read rows: %v", err)
    }
}

🔧 設定方法

📋 前提条件: Bigtable インスタンスが Enterprise または Enterprise Plus エディション / Go 開発環境 / cloud.google.com/go/bigtable 最新バージョン

ステップ 1: Data Boost アプリプロファイルの作成

Bash gcloud CLI 
gcloud bigtable app-profiles create data-boost-profile \
    --instance=INSTANCE_ID \
    --data-boost \
    --data-boost-compute-billing-owner=HOST_PAYS \
    --route-to=CLUSTER_ID

ステップ 2: Go クライアントライブラリのインストール

Bash 
go get cloud.google.com/go/bigtable@latest

ステップ 3: アプリケーションコードの更新

bigtable.ClientConfig の AppProfile フィールドに Data Boost アプリプロファイル ID を指定してクライアントを作成。

Go 
clientConf := bigtable.ClientConfig{
    AppProfile: "data-boost-profile",
}
client, err := bigtable.NewClientWithConfig(ctx, project, instance, clientConf)

✅ メリット

ビジネス面

✓Go エコシステムの活用 - 既存のデータパイプラインやバッチ処理から言語変更なしに Data Boost を利用
✓コスト最適化 - サーバーレスで使用分だけ課金、常時ノードプロビジョニング不要
✓SLA への影響なし - 分析ワークロードが本番パフォーマンスに影響しない

技術面

✓ワークロード分離 - サーバーレスコンピュートで分析/本番を完全分離
✓スケーラビリティ - ノード数の事前プロビジョニング不要で大規模スキャン実行可能
✓シンプルな実装 - アプリプロファイル設定を追加するだけで利用開始可能

⚠️ 制約事項・注意点

制限事項:
  • 書き込み/削除リクエストには使用不可 (読み取り専用)
  • ポイントリード (単一行読み取り) にはコスト面で不向き
  • クラスタあたり 1,000 リード/秒を超えるトラフィック非対応
  • リバーススキャン非対応
  • マルチクラスタルーティング非対応
  • CMEK 暗号化インスタンスでは利用不可
  • 書き込み後 35 分以内のデータは読み取り保証なし

考慮すべき点

!レイテンシ重視のワークロードには不向き (スループット最適化設計)
!Data Boost は Bigtable SLA の対象外
!Enterprise / Enterprise Plus エディションが必要 (無料トライアル不可)

🎯 ユースケース

📦 ユースケース 1: Go ベースの ETL パイプライン

シナリオ: Go で構築されたバッチ処理システムが、定期的に Bigtable から大量データを読み取り Cloud Storage にエクスポート。本番パフォーマンスへの影響を排除したい。

Go ETL パイプライン例 
// Data Boost プロファイルで ETL 用クライアントを作成
clientConf := bigtable.ClientConfig{
    AppProfile: "etl-data-boost",
}
client, err := bigtable.NewClientWithConfig(ctx, project, instance, clientConf)
if err != nil {
    log.Fatal(err)
}

tbl := client.Open("events-table")

// 大規模スキャンを実行 (本番クラスタに影響なし)
err = tbl.ReadRows(ctx, bigtable.PrefixRange("2026-07"),
    func(row bigtable.Row) bool {
        // データの変換・エクスポート処理
        return true
    })

効果: 本番アプリの低レイテンシ読み書きを維持しつつ、大規模 ETL ジョブを並行実行可能

🤖 ユースケース 2: アドホック分析と ML 前処理

シナリオ: データサイエンスチームが Go で構築した ML パイプラインから、Bigtable に格納された時系列データを大量に読み取り、モデルのトレーニングデータを準備。

効果: 分析ジョブのためにクラスタのノード数を増やす必要がなく、サーバーレスコンピュートで必要なときだけリソースを使用してコストを最適化

💰 料金

Data Boost の料金はサーバーレス処理ユニット (SPU) に基づく従量課金制。

項目料金
Data Boost (SPU)$0.000845/SPU/時間
最小課金単位リクエストあたり 60 SPU 秒
最小レート10 SPU/秒
💡 ポイント:
  • 1,000 SPU はノード 1 台分のパフォーマンスに相当
  • プロビジョニング済みノードの課金とは別に計算
  • 使用した分だけ課金 (アイドル時のコストなし)
