☁️ Cloud Service Mesh 🛡️ Security Bulletin Critical CVE 対応

🛡️ セキュリティ速報 GCP-2026-069 対応
Cloud Service Mesh パッチリリース

ISTIO-SECURITY-2026-007 / GHSA-gcjh-h69q-9w9g に対応する修正版を全サポートブランチに提供
リリース日: 2026-10-19

📋 概要

Cloud Service Mesh (CSM) の in-cluster (クラスタ内コントロールプレーン) 向けに、セキュリティ速報 GCP-2026-069 (Istio のアドバイザリ ISTIO-SECURITY-2026-007 に対応) で公表された脆弱性を解消する新しいパッチバージョンがリリースされました。 対象は 1.28 系〜1.31 系の 4 つのサポートブランチで、それぞれ修正済み Envoy を同梱。最新の 1.31.1-asm.19 には GitHub Security Advisory GHSA-gcjh-h69q-9w9g の修正も含まれます。

マネージド CSM では各リリースチャンネル (rapid / regular / stable) に修正済みサイドカーが順次自動ロールアウトされ、 GKE の Gateway API 利用時のプロキシも csm_mesh_proxy.20261014_RC00 (Envoy 1.40 相当) に更新されます。 CVSS 9.8 のクリティカル CVE を複数含むため、in-cluster CSM を運用するすべてのチームに早急な対応が推奨されます。

❌ アップデート前の課題

  • in-cluster CSM の既存パッチバージョンに ISTIO-SECURITY-2026-007 の Envoy / Istio 脆弱性が未修正のまま残存
  • プロキシのベースイメージに CVSS 9.8 (Critical) を含む多数のプラットフォーム CVE が存在し、イメージスキャンで検出される状態
  • 修正版が存在せず、ユーザー側で脆弱性を緩和する恒久的な手段がなかった

✅ アップデート後の改善

  • 1.28 / 1.29 / 1.30 / 1.31 の各ブランチに修正済みパッチバージョンが提供され、アップグレードで脆弱性を解消可能に
  • マネージド CSM では修正済みサイドカー (1.21.6-asm.93 / 1.20.8-asm.143 / 1.19.10-asm.132) が自動ロールアウトされ、操作なしで保護
  • GKE Gateway API のプロキシも Envoy 1.40 ベースの修正版に更新

🛠️ 設定方法

📌 前提条件

✓in-cluster Cloud Service Mesh を使用している場合、現在のバージョンが 1.28〜1.31 のサポート対象ブランチであること
✓サポート終了 (EOL) バージョンを使用している場合、修正はバックポートされないため、まずサポート対象バージョンへのアップグレードが必要

ステップ 1: 現在の CSM / プロキシバージョンを確認

Bash バージョン確認 
# コントロールプレーン (istiod) のバージョン確認
kubectl get pods -n istio-system -l app=istiod \
  -o jsonpath='{.items[*].spec.containers[*].image}'

# サイドカープロキシのバージョン確認
kubectl get pods --all-namespaces \
  -o jsonpath='{range .items[*]}{.metadata.namespace}{"\t"}{.metadata.name}{"\t"}{.spec.containers[?(@.name=="istio-proxy")].image}{"\n"}{end}' | grep -v '^\s*$'

自クラスタが修正済みバージョンより古いパッチバージョンを使用していないかを確認します。

ステップ 2: in-cluster CSM を修正済みバージョンへアップグレード

Bash asmcli によるアップグレード例 (1.31.1-asm.19) 
# 例: asmcli を使用して 1.31.1-asm.19 へアップグレード
./asmcli install \
  --project_id PROJECT_ID \
  --cluster_name CLUSTER_NAME \
  --cluster_location CLUSTER_LOCATION \
  --fleet_id FLEET_ID \
  --enable_all

詳細は Cloud Service Mesh のアップグレードガイド を参照。 コントロールプレーンの更新後、ワークロードの再起動によりサイドカーを新バージョンへ入れ替えます。

ステップ 3: マネージド CSM の場合はロールアウト状況を確認

💡 ヒント: マネージド CSM では修正済みサイドカーが自動ロールアウトされるため、基本的にユーザー操作は不要です。ただし CVE 関連の高優先度更新は GKE メンテナンスウィンドウを待たずに適用される点に留意してください。

⚖️ メリットと制約事項

👍 メリット

ビジネス面
✓セキュリティリスクの低減: CVSS 9.8 のクリティカル CVE を含む多数の脆弱性が解消され、サービスメッシュ経由の攻撃リスクを低減
✓コンプライアンス対応: イメージスキャンで検出される既知 CVE が減少し、脆弱性管理ポリシーや監査への対応が容易に
技術面
✓全サポートブランチへの提供: 1.28〜1.31 の各ブランチに修正版があり、メジャーアップグレードなしのパッチ適用だけで対応可能
✓マネージド CSM の自動適用: コントロールプレーン・データプレーンともに Google が自動更新するため、運用負荷なく保護

⚠️ 制限事項・考慮すべき点

✗EOL ブランチには修正がバックポートされないため、古いバージョンの利用者はサポート対象バージョンへのアップグレードが必要
✗マネージドデータプレーンは手動注入 Pod、Job、StatefulSet、DaemonSet を自動更新しないため、該当ワークロードは手動での再起動が必要
→in-cluster CSM はユーザー自身でアップグレードしない限り脆弱なままとなるため、計画的かつ速やかな適用が必要
→CVE 関連のマネージドロールアウトは GKE メンテナンスウィンドウを考慮せず実施されるため、Pod の再起動 (eviction) がウィンドウ外に発生しうる。PodDisruptionBudget の適切な設定が重要
→サイドカーの入れ替えは Pod の再作成を伴うため、再起動に敏感なワークロードは事前に影響を確認する

🎯 ユースケース

🚑 ユースケース 1: in-cluster CSM クラスタの緊急パッチ適用

シナリオ: 本番 GKE クラスタで in-cluster Cloud Service Mesh 1.31 系を運用しており、セキュリティチームからクリティカル CVE (CVSS 9.8) への対応期限が設定されている。

Bash 緊急パッチ適用の実装例 
# 1. 現行バージョンの確認
kubectl get pods -n istio-system -l app=istiod -o jsonpath='{.items[0].spec.containers[0].image}'

# 2. 1.31.1-asm.19 へアップグレード後、ネームスペース単位でロールアウト再起動
kubectl rollout restart deployment -n production

効果: パッチバージョンの適用のみで ISTIO-SECURITY-2026-007 と GHSA-gcjh-h69q-9w9g、および多数のプラットフォーム CVE に対応でき、対応期限内に脆弱性を解消できる。

🔍 ユースケース 2: マネージド CSM 環境でのロールアウト影響確認

シナリオ: マネージド Cloud Service Mesh (regular チャンネル) を利用しており、自動ロールアウトによる Pod 再起動がサービスに影響しないか確認したい。

効果: PodDisruptionBudget を事前に整備しておくことで、サイドカー 1.20.8-asm.143 への自動更新時も可用性を維持したまま段階的に更新が完了する。ユーザーによるパッチ作業は不要。

💰 料金・利用可能リージョン

💵 料金

このセキュリティパッチ自体に追加料金は発生しません。Cloud Service Mesh の料金体系 (GKE Enterprise への含有、またはスタンドアロンの従量課金) は従来どおりです。 詳細は Cloud Service Mesh の料金ページ を参照してください。

🌍 利用可能リージョン

in-cluster パッチバージョンはすべての環境で利用可能です。マネージド Cloud Service Mesh のサイドカー更新は各リリースチャンネルに対して順次ロールアウトされます (ロールアウト完了まで時間差があります)。

🔗 関連サービス・機能

→GKE (Google Kubernetes Engine): CSM のホスト環境。マネージドデータプレーンの更新は GKE リリースチャンネル・メンテナンスウィンドウと連動する (ただし CVE ロールアウトはウィンドウを考慮しない)
→GKE Gateway API: GKE 上の Gateway API 利用時のプロキシも今回 csm_mesh_proxy.20261014_RC00 (Envoy 1.40) へ更新される
→Security Command Center / Artifact Analysis: コンテナイメージの脆弱性スキャンと組み合わせることで、修正対象 CVE の検出・適用状況の追跡が可能
→Istio / Envoy: CSM のベースとなる OSS。今回の修正は ISTIO-SECURITY-2026-007 に対応する

📝 まとめ

CVSS 9.8 のクリティカル CVE を複数含むセキュリティ速報 GCP-2026-069 への対応パッチであり、in-cluster Cloud Service Mesh を運用しているチームは速やかに修正済みバージョン (1.31.1-asm.19 / 1.30.5-asm.11 / 1.29.8-asm.11 / 1.28.10-asm.52) へのアップグレードを計画すべきです。 マネージド CSM は自動ロールアウトで保護されますが、CVE ロールアウトはメンテナンスウィンドウを考慮しないため、PodDisruptionBudget の整備を確認しておくことを推奨します。
