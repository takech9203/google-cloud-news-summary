📋 概要

Apigee の更新バージョン 1-17-0-apigee-8 がリリースされました。 Model Armor ポリシーのレスポンスパース処理における重要なバグ修正 (Bug ID: 514973778) が含まれています。

この修正により、Model Armor サービス側で将来的に新しいフィールドが追加された場合でも、 Apigee の SanitizeUserPrompt および SanitizeModelResponse ポリシーが 障害を起こすことなく動作を継続できるようになりました。

📌 ロールアウト情報: 2026年5月21日に開始。全ての Google Cloud ゾーンへの展開には4営業日以上かかる場合があります。ユーザー側での手動アップデート作業は不要です。

🔄 Before / After 比較

❌ 修正前の課題

  • Model Armor レスポンスに未知フィールドが含まれるとパース処理が失敗
  • ポリシーエラー (SanitizationResponseParsingFailed) が発生
  • Model Armor 側のアップデート毎に Apigee 側で対応が必要
  • 予期しないポリシー障害で API トラフィックが中断されるリスク

✅ 修正後の改善

  • 未知フィールドを無視して処理を継続する「グレースフルハンドリング」を実装
  • 将来のフィールド追加によるポリシー障害が発生しない
  • Apigee と Model Armor 間の前方互換性を確保
  • 運用安定性が大幅に向上

⚡ 主要機能

🔧 未知フィールドのグレースフルハンドリング

Model Armor レスポンス内の未知フィールドを検出した場合、エラーを発生させずに無視する処理を実装。JSON パース時に厳密なスキーマ検証からより柔軟な解析に変更。

🔗 前方互換性の確保

Model Armor サービスが新しいフィルター結果フィールドやメタデータを追加しても、既存の Apigee ポリシーが正常に動作。サービス間の独立したデプロイとバージョンアップが可能に。

🚫 ポリシー障害の防止

steps.sanitize.user.prompt.SanitizationResponseParsingFailed および steps.sanitize.model.response.SanitizationResponseParsingFailed エラーの発生を防止。

⚠️ デメリット・制約事項

制限事項:
  • ロールアウトには4営業日以上かかるため、即座に全ゾーンで修正が適用されるわけではない
  • ロールアウト完了まで、一部のインスタンスでは引き続き旧バージョンの動作となる
考慮すべき点:
  • 既に continueOnError="true" を設定してワークアラウンドしていた場合、修正適用後にポリシー設定の見直しを推奨
  • ロールアウト期間中は、異なるゾーン間で動作の不一致が生じる可能性がある

XML
