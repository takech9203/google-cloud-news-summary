🤖 Agent Designer エージェントを
Google Groups と共有

Gemini Enterprise GA
2026-06-09

📋 概要

Gemini Enterprise の Agent Designer で作成したエージェントを、Google Identity グループ (Google Groups) と共有できる機能が一般提供 (GA) となりました。

これにより、エンドユーザーは個別のメールアドレスだけでなく、組織内の Google Identity グループを指定してエージェントを共有できるようになります。管理者が「Enable End Users to share with Groups (Google Identity only)」設定を有効にすることで利用可能です。

🤖 Agent Designer とは: ノーコード・ローコードでカスタムエージェントを作成できるプラットフォーム。今回のグループ共有機能により、組織全体でのエージェント活用がより効率的になります。

🔄 Before / After 比較

❌ Before (アップデート前)

  • 個別のメールアドレスを1つずつ指定する必要があり、大人数への配布が煩雑
  • チームや部門単位の共有は管理者が手動で設定する必要があった
  • エンドユーザー側からグループへの共有ができなかった

✅ After (アップデート後)

  • エンドユーザーが直接 Google Identity グループを指定して共有可能
  • 部門やプロジェクトチーム単位での一括共有が容易に
  • 管理者承認フローとの組み合わせでセキュリティとスケーラビリティを両立

⚡ 主要機能

👥 Google Identity グループへのエージェント共有

  • Agent Gallery ページからエージェントの共有ダイアログでグループのメールアドレスを入力可能
  • Google Identity グループのみサポート (WIF グループは管理者のみ操作可能)
  • 共有リンクの生成も可能

🔐 管理者による共有制御

  • 「Enable End Users to share with Groups」トグルで機能の有効化/無効化
  • 管理者承認の要否を別途設定可能
  • 承認リクエストの確認・承認・拒否のワークフロー

📦 エージェントのライフサイクル管理

  • ドラフト状態のエージェントは共有不可 (作成完了後のみ)
  • エージェント所有者はいつでもアクセスリストから削除可能
  • 管理者もアクセスリストの追加・削除が随時可能

⚙️ 設定方法

📋 前提条件: Gemini Enterprise アプリが作成済み / Agent Designer が有効化済み / 管理者が「Enable End Users to share with Groups」設定を有効にしていること

ステップ 1: 管理者がグループ共有を有効化

  1. Google Cloud コンソールで Gemini Enterprise > Apps ページに移動
  2. アプリ名をクリックし、ナビゲーションメニューから Features を選択
  3. 「End user features」セクションで「Enable agent sharing」を有効化
  4. 「Enable End Users to share with Groups (Google Identity only)」を有効化

ステップ 2: エンドユーザーがエージェントを共有

  1. Gemini Enterprise ウェブアプリの Agent Gallery ページに移動
  2. 「Your Agents」セクションで共有したいエージェントを探す
  3. アクションメニュー (3点メニュー) から Share を選択
  4. 共有ダイアログで Google Identity グループのメールアドレスを入力し Done

ステップ 3: 管理者による承認 (設定されている場合)

  1. Google Cloud コンソールの Gemini Enterprise > Apps > Agents に移動
  2. 「User permissions」列に「Review share request」が表示されたエージェントを探す
  3. アクセスリストを確認し、Approve and enable または Deny を選択

⚠️ 制約事項・注意点

制限事項:
  • Google Identity グループのみサポート (WIF グループへのエンドユーザーからの共有は不可)
  • ドラフト状態のエージェントは共有できない
  • エージェント共有時、関連するすべてのデータソースとファイルへのアクセスも共有される (データの過剰公開リスク)
考慮すべき点:
  • 機密情報を含むナレッジファイルをアップロードしたエージェントを共有する場合、グループメンバー全員がアクセス可能になる
  • 管理者承認を無効化すると、エンドユーザーが意図せず広範囲に共有してしまうリスクがある
  • グループメンバーシップの変更がエージェントアクセスに即時反映されるため、グループ管理の適切な運用が重要

💡 ユースケース

🏢 ユースケース 1: 部門ナレッジエージェントの共有

シナリオ: 人事部の担当者が、社内規定や福利厚生に関するナレッジを搭載したエージェントを Agent Designer で作成し、人事部全員が所属する Google Group に共有する。

効果: 個別にメールアドレスを入力する必要がなく、新メンバーがグループに追加されると自動的にエージェントにアクセス可能になる。

👩‍💻 ユースケース 2: プロジェクトチームへの専用エージェント配布

シナリオ: 開発チームリーダーが、プロジェクト固有のドキュメントや API リファレンスを参照するエージェントを作成し、プロジェクトメンバーの Google Group に共有する。

効果: プロジェクトメンバーの入れ替わりにグループメンバーシップで自動的に対応でき、アクセス管理が簡素化される。

🏛️ ユースケース 3: 管理者承認付きの全社エージェント公開

シナリオ: 社内ツールの使い方を案内するエージェントを作成し、全社横断のグループに共有する。管理者承認を有効にして、公開前にコンテンツの適切性をレビュー。

効果: エンドユーザーの自律性を維持しながら、全社規模での共有に対しては管理者のガバナンスを確保。
