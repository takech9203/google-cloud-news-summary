🔀 Cloud Service Mesh: Envoy Lua Filter

Stable チャネルで Preview 利用可能に

2026-07-21
Cloud Service Mesh Preview

📋 概要

Cloud Service Mesh の Envoy Lua Filter が、Stable リリースチャネルにおいて Preview 機能として利用可能になりました。これまで Rapid チャネルのみで提供されていた本機能が、最も安定性を重視する Stable チャネルにまで展開されたことで、本番環境に近い安定したチャネルを利用するユーザーも Lua スクリプトによるデータプレーン拡張を評価・導入できるようになります。

Envoy Lua Filter は、EnvoyFilter API を通じて Envoy プロキシの HTTP フィルターチェーンに Lua スクリプトを挿入し、リクエストおよびレスポンスの処理をカスタマイズできます。Wasm フィルターのようなコンパイルやビルドパイプラインが不要で、インラインスクリプトとして直接記述できるため、迅速なプロトタイピングやシンプルなトラフィック操作に適しています。

🔄 Before / After 比較

❌ Before (アップデート前)

  • Lua Filter は Rapid チャネルでのみ Preview 提供
  • Stable チャネルの本番環境では利用不可
  • 評価のため Rapid チャネルへの移行が必要
  • 限定された拡張 (LocalRateLimit, GrpcWeb, Compressor) に依存

✅ After (アップデート後)

  • Stable チャネルでも Lua Filter が Preview で利用可能
  • 全チャネル (Rapid, Regular, Stable) で統一対応
  • 安定した環境でカスタムロジックをテスト可能
  • 段階的ロールアウト戦略に沿った検証が可能

🏗️ アーキテクチャ図

Envoy Lua Filter は HTTP フィルターチェーン内で動作し、Router フィルターの前に挿入されます。クライアントからのリクエストとアプリケーションからのレスポンスの両方を Lua スクリプトで処理できます。

⚡ 主要機能

📝 インライン Lua スクリプト実行

→default_source_code.inline_string で直接記述
→envoy_on_request() コールバックでリクエスト処理
→envoy_on_response() コールバックでレスポンス処理
→コンパイル不要、EnvoyFilter 適用のみでデプロイ

🔧 ヘッダー・メタデータ操作

→リクエスト/レスポンスヘッダーの読取・追加・変更・削除
→streamInfo() による動的メタデータ設定
→他フィルター (Apigee データキャプチャ等) との連携

🌐 全チャネル統一対応

→Rapid / Regular / Stable で利用可能
→GKE Stable チャネルに対応する CSM Stable チャネル
→段階的ロールアウト戦略に最適

⚙️ 設定方法

前提条件

✓Cloud Service Mesh がプロビジョニングされた GKE クラスタ (Stable チャネル)
✓TRAFFIC_DIRECTOR コントロールプレーン実装の使用
✓サイドカーインジェクションが有効な Namespace

ステップ 1: EnvoyFilter リソースの作成

YAML 
apiVersion: networking.istio.io/v1alpha3
kind: EnvoyFilter
metadata:
  name: custom-lua-filter
  namespace: my-namespace
spec:
  workloadSelector:
    labels:
      app: my-service
  configPatches:
  - applyTo: HTTP_FILTER
    match:
      context: SIDECAR_INBOUND
      listener:
        filterChain:
          filter:
            name: "envoy.filters.network.http_connection_manager"
            subFilter:
              name: "envoy.filters.http.router"
    patch:
      operation: INSERT_BEFORE
      value:
        name: envoy.filters.http.lua
        typed_config:
          "@type": type.googleapis.com/udpa.type.v1.TypedStruct
          type_url: type.googleapis.com/envoy.extensions.filters.http.lua.v3.Lua
          value:
            stat_prefix: my_lua_filter
            default_source_code:
              inline_string: |
                function envoy_on_request(request_handle)
                  request_handle:headers():add("x-custom-header", "processed")
                end
                function envoy_on_response(response_handle)
                  response_handle:headers():add("x-response-info", "filtered")
                end

ステップ 2: リソースの適用と確認

Bash 
# EnvoyFilter の適用
kubectl apply -f custom-lua-filter.yaml

# ステータスの確認
kubectl get envoyfilter -n my-namespace custom-lua-filter -o yaml

💼 ビジネス面

→迅速なプロトタイピング: コンパイル不要で開発サイクル短縮
→運用コスト削減: Wasm ビルドパイプライン不要

🔧 技術面

→柔軟なトラフィック操作: カスタムヘッダー/メタデータ設定
→全チャネル統一: 段階的ロールアウト可能
→軽量な拡張: インフラ変更最小限

⚠️ デメリット・制約事項

⚠️ Preview ステータス: 「Pre-GA Offerings Terms」が適用され、本番環境での利用は限定的サポートです。

制限事項

✗httpCall (外部 HTTP 呼び出し) がサポートされない
✗I/O、デバッグライブラリ、LuaJIT 拡張 (ffi/jit) が利用不可
✗個別 50KB / 合計 100KB / configPatches 最大 10 のサイズ制限

考慮すべき点

!複雑な Lua スクリプトはパフォーマンスに影響する可能性あり
!サポート範囲は設定のプロキシ伝播まで (スクリプト正確性は対象外)
!サポートされない機能使用時は EnvoyFilter がリジェクトされる

🎯 ユースケース

📌 ユースケース 1: カスタムリクエストヘッダーの付与

シナリオ: マイクロサービス間通信で、リクエスト元の識別や追跡のためにカスタムヘッダーを動的に付与したい。

Lua 
function envoy_on_request(request_handle)
  local path = request_handle:headers():get(":path")
  if string.match(path, "^/api/v2/") then
    request_handle:headers():add("x-api-version", "v2")
  end
end

効果: コード変更なしに、サービスメッシュ層でリクエストのバージョン識別やルーティング補助情報を付与できる。

📌 ユースケース 2: 動的メタデータ設定による監視連携

シナリオ: 特定のリクエストパターンに基づいてメタデータを設定し、下流のフィルターや監視システムと連携したい。

Lua 
function envoy_on_request(request_handle)
  local metadata = request_handle:streamInfo():dynamicMetadata()
  local user_agent = request_handle:headers():get("user-agent") or "unknown"
  metadata:set("envoy.filters.http.lua", "client_type", user_agent)
end

効果: リクエスト属性に基づいた動的メタデータを設定し、Envoy のアクセスログや外部監視システムでの分析に活用できる。
