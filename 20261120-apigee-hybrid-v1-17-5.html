🔒 Apigee hybrid v1.17.5 パッチリリース

☁️ Apigee hybrid 🛡️ Security Fix 📦 Patch Release
リリース日: 2026-11-20
apigee-hybrid-cassandra のセキュリティ修正

📋 概要

2026 年 11 月 20 日、Google Cloud は Apigee hybrid の更新バージョン v1.17.5 をリリースしました。 本リリースは、ランタイムデータストアを担う apigee-hybrid-cassandra コンテナイメージに対する セキュリティ修正 (Bug ID: N/A) に特化したパッチリリースです。

Cassandra は Apigee hybrid のランタイムプレーンで KMS (API キー・OAuth トークン)、KVM、クォータ、レスポンスキャッシュ などの 永続データを保持する中核コンポーネントです。機密性の高いデータを扱うため、v1.17 系を運用しているプラットフォームチーム・API 管理者は、 計画的なパッチ適用が推奨されます。

💡 ポイント: パッチリリースのコンテナイメージは Helm チャートに統合されています。 Helm チャートのアップグレードだけで修正済みイメージが自動適用され、手動でのイメージ変更は不要です。 v1.17.4 (11/18: Pod Topology Spread Constraints 対応、CVE-2026-114938 緩和) に続く短い間隔でのセキュリティパッチ提供です。
❌ Before (v1.17.4 以前)
  • apigee-hybrid-cassandra イメージに本リリースで修正対象となったセキュリティ上の問題が存在
  • イメージスキャンで脆弱性が検出されても、ユーザー側で個別にイメージを差し替える手段がなく、公式パッチを待つ必要があった
✅ After (v1.17.5)
  • Cassandra のセキュリティ修正が適用され、ランタイムデータストアのセキュリティ態勢が改善
  • Helm チャートのアップグレードのみで修正済みイメージが自動適用され、手動でのイメージ変更は不要

🛠️ 設定方法 (アップグレード手順)

✅ 前提条件

✓Apigee hybrid v1.17.x を Helm チャートで管理していること (新規インストールは The big picture から開始)
✓現行クラスタ構成を反映した overrides.yaml が利用できること
✓アップグレード前に Cassandra データベースと Helm チャートディレクトリのバックアップを取得していること (推奨)
1 v1.17.5 へのアップグレード
Bash Helm チャートのアップグレード 
# Helm チャートを v1.17.5 に更新し、各チャートを順にアップグレード
# (パッチリリースのためコンテナイメージはチャートに統合されており、自動的に更新される)
helm upgrade operator apigee-operator/ \
  --install \
  --namespace APIGEE_NAMESPACE \
  --atomic \
  -f overrides.yaml

operator、datastore (Cassandra)、telemetry、redis、ingress-manager、org、env、virtualhost の各チャートを 公式手順の順序でアップグレードします。

2 Cassandra Pod の更新確認
Bash Pod のステータスとイメージの確認 
# Cassandra Pod のステータスとイメージを確認
kubectl get pods -n APIGEE_NAMESPACE -l app=apigee-cassandra
kubectl get pods -n APIGEE_NAMESPACE -l app=apigee-cassandra \
  -o jsonpath='{.items[*].spec.containers[*].image}'

アップグレード後、Cassandra StatefulSet の Pod が正常 (Running/Ready) であること、 およびイメージが v1.17.5 のものに更新されていることを確認します。

💪 メリット

💼 ビジネス面
✓セキュリティリスクの低減: API キーや OAuth トークンなどの機微データを保持する Cassandra の修正により、データストア層のリスクが低減され、監査・コンプライアンス対応の負担が軽減
✓運用コストの抑制: Helm チャートのアップグレードのみで修正が適用されるため、個別のイメージ管理や手動差し替え作業が不要
⚙️ 技術面
✓適用の容易さ: コンテナイメージは Helm チャートに統合されており、通常のアップグレードフローだけで修正済みイメージが自動反映
✓脆弱性スキャン指摘への対応: イメージスキャンで apigee-hybrid-cassandra に指摘がある環境では、本パッチ適用により解消が期待できる

⚠️ デメリット・制約事項

⚠️ 考慮すべき点
  • 修正された脆弱性の個別の CVE 番号は公表されていない (Bug ID: N/A)。詳細が必要な場合は今後のドキュメント更新やサポート経由での確認が必要
  • Cassandra は StatefulSet のため、アップグレード時はローリング更新の進行と各 Pod の Ready 状態を確認しながら進めることが望ましい
  • アップグレード前には Cassandra データのバックアップ取得が推奨される
  • v1.17.4 (2026 年 11 月 18 日) の機能追加・修正を未適用の場合は、v1.17.5 への更新であわせて取り込まれるため、両リリースの変更内容を確認した上で検証・適用を計画する

🎯 ユースケース

🔍 ユースケース 1: 定期的な脆弱性対応としてのパッチ適用

シナリオ: セキュリティチームのコンテナイメージスキャンで Apigee hybrid の Cassandra イメージに脆弱性が検出され、SLA 内での修正が求められている。

効果: v1.17.5 への Helm チャートアップグレードのみで、apigee-hybrid-cassandra のセキュリティ修正済みイメージが自動適用され、スキャン指摘事項の解消が期待できる。

🏦 ユースケース 2: 機微データを扱う API 基盤のセキュリティ態勢維持

シナリオ: 金融・医療など規制産業の API 基盤として Apigee hybrid を運用しており、OAuth トークンや API キーを保持するデータストア層の脆弱性管理を厳格に行う必要がある。

効果: KMS・OAuth・KVM などの機微データを保持する Cassandra に対するセキュリティ修正を早期適用することで、データストア層のセキュリティ態勢を継続的に維持できる。
