🔨 Cloud Build: results フィールドによるアテステーション生成

Cloud Build GA Supply Chain Security
2026-05-15

📋 概要

Cloud Build のビルド構成ファイル (cloudbuild.yaml / cloudbuild.json) において、ビルドステップに results フィールド を設定できるようになりました。この機能により、ビルドステップ内でデータを保存し、ビルド完了後にそのデータをビルド結果内の アテステーション (証明書) として添付できます。

ソフトウェアサプライチェーンセキュリティの強化に直結する重要なアップデートです。ビルドプロセス中に収集した情報 (許可リスト、セキュリティスキャン結果、コンプライアンスチェック結果など) を、ビルド成果物に紐づけた検証可能なアテステーションとして記録できます。

🔄 Before / After 比較

❌ Before (アップデート前)

  • ビルドステップ内のデータをアテステーションとして直接添付する標準的な方法がなかった
  • 検証情報をビルド成果物と紐づけるには外部ツールや追加構成が必要
  • Binary Authorization との連携に別途ビルドステップや外部サービスの設定が必要

✅ After (アップデート後)

  • results フィールドを宣言するだけでアテステーション添付が可能
  • $RESULTS 環境変数でスクリプト内から簡単にデータ書き込み
  • ビルド完了時に自動的にアテステーションが生成・添付

🏗️ アーキテクチャ図

ビルド構成ファイルで results フィールドを定義し、ビルドステップのスクリプトから $RESULTS 環境変数に書き込むことで、ビルド完了時にアテステーションが自動生成されます。

⚡ 主要機能

📝 results フィールドの構成

→ビルドステップ内に results フィールドを定義
→キーバリューペア形式 (キーは文字列、値は JSON オブジェクト)
→ビルド完了後にアテステーションとして自動添付

💲 $RESULTS 環境変数

→スクリプト内で $RESULTS にデータを書き込み
→echo "key=value" >> $RESULTS 形式で追記
→同一ビルドステップ内で複数回の書き込みが可能

🏷️ アテステーションメタデータ

→attestationContent: アテステーションの名前
→attestationType: アテステーションのタイプ (URI 形式推奨)
→検証を予定している場合に必要なフィールド

📐 技術仕様

results フィールドの構造

項目 説明 必須
name 結果の名前。アテステーション内に表示され、ビルドステップ内で参照可能 必須
attestationContent アテステーションの名前。任意の値が設定可能 任意 (検証時に必要)
attestationType アテステーションのタイプ。任意の値が設定可能 任意 (検証時に必要)

💻 設定例

YAML 
steps:
  - name: "gcr.io/cloud-builders/docker"
    id: "build-step"
    args: ["build", "-t", "us-docker.pkg.dev/my-project/demo/helloworld-image", "."]
  - name: "ubuntu"
    id: "check-source-fetch-urls"
    results:
      - name: "allowlisted_prefixes"
        attestationContent: "remote_fetch_allow_list"
        attestationType: "https://cloudbuild.googleapis.com/attestations/build_content_restrictions"
    script: |
      #!/bin/bash
      prefixes="[\"github.com\", \"gitlab.com\"]"
      echo "allowlisted_prefixes=$prefixes" >> $RESULTS
      cat $RESULTS
images:
  - "us-docker.pkg.dev/my-project/demo/helloworld-image"
options:
  requested_verify_option: VERIFIED
  defaultLogsBucketBehavior: REGIONAL_USER_OWNED_BUCKET

ビルドの実行と結果確認

Bash 
# ビルドの送信
gcloud builds submit . --config=cloudbuild.yaml

# ビルド結果の確認 (アテステーションが含まれる)
gcloud builds describe BUILD_ID --format="json(results)"

✅ メリット

💼 ビジネス面

✓コンプライアンス強化: 検証内容を証明可能な形で記録、監査対応が容易に
✓サプライチェーンセキュリティ向上: アテステーション自動生成で不正デプロイリスクを低減

🛠️ 技術面

✓宣言的な構成: ビルド構成ファイル内で完結、外部ツール不要
✓Binary Authorization 統合: ポリシーベースの検証が可能
✓SLSA フレームワーク対応: Level 3 ビルドサポートと組み合わせ可能
✓柔軟なデータ形式: キーバリューペアとして任意の JSON を格納

⚠️ 制約事項・注意点

⚠️ 制限事項:
  • 保存データはキーバリューペア形式に限定 (キーは文字列、値は JSON オブジェクト)
  • $RESULTS 環境変数はスクリプトフィールドを使用するビルドステップでのみ利用可能
  • アテステーション検証には requested_verify_option: VERIFIED の設定が必要
💡 考慮すべき点:
  • Binary Authorization と連携する場合は別途ポリシー設定が必要
  • アテステーション内容の設計 (何を証明するか) は利用者側の責任
  • attestationContent と attestationType は検証予定時のみ必要

🎯 ユースケース

🔗 ユースケース 1: ソースフェッチ URL の制限検証

シナリオ: ビルドで使用されるソースコードリポジトリが許可リストに含まれるものだけであることを証明

YAML 
steps:
  - name: "ubuntu"
    id: "check-source-fetch-urls"
    results:
      - name: "allowlisted_prefixes"
        attestationContent: "remote_fetch_allow_list"
        attestationType: "https://cloudbuild.googleapis.com/attestations/build_content_restrictions"
    script: |
      #!/bin/bash
      prefixes="[\"github.com\", \"gitlab.com\"]"
      echo "allowlisted_prefixes=$prefixes" >> $RESULTS
✅ 効果: ビルド成果物に「承認されたソースのみから構築された」ことを証明するアテステーションが添付され、Binary Authorization で検証可能に

🔍 ユースケース 2: セキュリティスキャン結果の記録

シナリオ: コンテナイメージの脆弱性スキャンを実施し、結果をアテステーションとして記録

YAML 
steps:
  - name: "gcr.io/cloud-builders/docker"
    args: ["build", "-t", "us-docker.pkg.dev/my-project/repo/app:latest", "."]
  - name: "ubuntu"
    id: "vulnerability-scan-attestation"
    results:
      - name: "scan_results"
        attestationContent: "vulnerability_scan"
        attestationType: "https://example.com/attestations/vulnerability_scan"
    script: |
      #!/bin/bash
      scan_data='{"critical": 0, "high": 0, "scan_tool": "trivy", "scan_date": "'$(date -u +%Y-%m-%dT%H:%M:%SZ)'"}'
      echo "scan_results=$scan_data" >> $RESULTS
✅ 効果: デプロイ前に脆弱性スキャンが実施済みであることを証明、セキュリティポリシーの自動適用が可能に

📌 まとめ

Cloud Build の results フィールドは、ビルドプロセス中に収集したデータを検証可能なアテステーションとしてビルド結果に添付する機能です。Binary Authorization との組み合わせにより、「信頼されたビルドからのみデプロイを許可する」ポリシーの実装が、より宣言的かつ簡潔に実現可能になりました。
