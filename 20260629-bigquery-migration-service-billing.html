💳 BigQuery Migration Service
Cloud Billing アカウント必須化

BigQuery Change (適用済み)
2026-06-29

📋 概要

BigQuery Migration Service を利用するすべてのユーザーに対して、Cloud Billing アカウントの紐付けが必須となりました。 段階的に適用が進められ、現在はすべてのユーザーに適用済みです。

💡 重要ポイント: BigQuery Migration Service 自体の利用料金は引き続き無料です。課金アカウントの紐付けは必要ですが、サービス利用に対する直接的な課金は発生しません。

この変更は、Google Cloud のサービス利用ポリシーの統一化の一環であり、プロジェクト管理やリソース追跡の観点から課金アカウントの紐付けを標準要件とするものです。

全ユーザーに適用済み - すべてのプロジェクトで Cloud Billing アカウントの紐付けが必要

🔄 Before / After 比較

❌ 変更前

  • Cloud Billing アカウントなしで Migration Service を利用可能
  • リソース管理やプロジェクト追跡が困難
  • 正式な組織管理の枠組み外でサービスが利用される可能性

✅ 変更後

  • すべてのユーザーが Cloud Billing アカウントを紐付け
  • プロジェクトのガバナンスと管理が統一
  • 組織レベルでの利用状況の可視性が向上
  • 将来的な課金体系の変更にも柔軟に対応

🛠️ 設定方法

前提条件

✓ Google Cloud プロジェクトが作成済みであること
✓ Cloud Billing アカウントを所有、または Billing Account User ロールを持っていること
✓ BigQuery Migration Service API が有効化されていること

ステップ 1: Cloud Billing アカウントの確認

Bash 
# 利用可能な課金アカウントの一覧表示
gcloud billing accounts list

# プロジェクトに紐付けられた課金アカウントの確認
gcloud billing projects describe PROJECT_ID

ステップ 2: プロジェクトへの課金アカウント紐付け

Bash 
# プロジェクトに課金アカウントを紐付け
gcloud billing projects link PROJECT_ID \
  --billing-account=BILLING_ACCOUNT_ID

ステップ 3: BigQuery Migration Service API の有効化

Bash 
# BigQuery Migration API を有効化
gcloud services enable bigquerymigration.googleapis.com --project=PROJECT_ID

⚠️ 制約事項・注意点

⚠️ 注意: 2026年5月18日以降、Cloud Billing アカウントが紐付けられていないプロジェクトでは Migration Service を利用できません。

制限事項

✗ 課金アカウント未紐付けプロジェクトでは Migration Service 利用不可
✗ 組織ポリシーにより課金アカウント作成が制限されている場合、管理者の対応が必要
✗ Migration Service 自体は無料だが、関連するストレージ使用には料金が発生

考慮すべき点

→ 教育・研究目的で課金アカウントなしで利用していたユーザーは対応が必要
→ 無料トライアルアカウントでも課金アカウントのセットアップが求められる可能性がある
→ 既存の自動化スクリプトやパイプラインが課金アカウント未設定のプロジェクトを使用している場合、動作しなくなる可能性がある

🎯 ユースケース

📌 ユースケース 1: 既存ユーザーの対応

シナリオ: これまで課金アカウントなしで SQL 翻訳機能を利用していたチームが継続利用する必要がある

効果: サービスの継続利用が保証され、マイグレーションプロジェクトの中断を防止

Bash 
# 1. 既存プロジェクトの課金状態を確認
gcloud billing projects describe my-migration-project

# 2. 課金アカウントが未設定の場合、紐付けを実行
gcloud billing projects link my-migration-project \
  --billing-account=01ABCD-234EFG-567HIJ

# 3. Migration Service が引き続き利用可能か確認
gcloud services list --project=my-migration-project \
  --filter="name:bigquerymigration.googleapis.com"

📌 ユースケース 2: 新規マイグレーションプロジェクトの開始

シナリオ: オンプレミスの Teradata から BigQuery への移行を新規に開始する企業が、Migration Service を活用してアセスメントと SQL 翻訳を行いたい

効果: 課金アカウントのセットアップを最初に完了しておくことで、Migration Service だけでなく BigQuery Data Transfer Service やその他の関連サービスもスムーズに利用開始可能
