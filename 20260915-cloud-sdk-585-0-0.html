🛠️ gcloud CLI 585.0.0 リリース

Breaking Changes と複数サービスの新機能・GA 昇格
📅 リリース日: 2026-09-15

📌 概要

2026 年 9 月 15 日、Google Cloud CLI (gcloud) のバージョン 585.0.0 がリリースされました。 本リリースには 2 つの Breaking Changes が含まれています。 Cloud Storage Anywhere Cache の --admission-policy フラグにおける ADMIT_ON_SECOND_MISS の非推奨化と、 Certificate-Based Access (CBA) のレガシー --tls-offload フラグの削除 (レガシー C++ ECP TLS Offload Engine の非推奨化) です。 CBA リクエストは今後 ECP HTTP Proxy (ecp_http_proxy) のみを使用します。

加えて、App Topology の GA 昇格、API Gateway のレスポンスストリーミング対応 (--enable-streaming)、 Backup and DR の自動保護ポリシーコマンド群 (Alpha / Beta)、Memorystore トークン認証の GA 昇格、 Cloud CDN キャッシュ無効化の拡張マッチャー対応など、幅広い機能強化が含まれています。

🕐 Before: アップデート前の課題
  • --admission-policy=ADMIT_ON_SECOND_MISS を指定するスクリプトの将来的な動作継続が保証されない
  • CBA の TLS 処理がレガシー C++ ECP TLS Offload Engine と ECP HTTP Proxy の 2 系統併存で構成が複雑
  • API Gateway のストリーミング対応ゲートウェイ (SSE / WebSocket / gRPC 双方向) を CLI から作成できない
  • Backup and DR の自動保護ポリシーを gcloud から管理するコマンドが存在しない
  • Memorystore のトークン認証は GA 前のリリーストラックのみ
✅ After: アップデート後の改善
  • CBA の TLS 処理が ECP HTTP Proxy (ecp_http_proxy) に一本化され認証経路がシンプルに
  • gcloud api-gateway gateways create --enable-streaming でストリーミング対応ゲートウェイを作成可能
  • gcloud backup-dr auto-protection-policies など新コマンド群 (Alpha / Beta) で自動保護を CLI 管理
  • Memorystore の --authorization-mode=token-auth とトークン認証ユーザー管理コマンド群が GA
  • tmux 環境での ANSI エスケープシーケンス・カラー表示に対応

💡 ポイント: 585.0.0 以降、Certificate-Based Access (CBA) のリクエストはレガシー C++ ECP TLS Offload Engine を経由せず、すべて ECP HTTP Proxy 経由で mTLS 接続を行います。

🚨 Breaking Changes

🪣 1. Cloud Storage: Anywhere Cache の ADMIT_ON_SECOND_MISS 非推奨化 Deprecated
  • gcloud storage buckets anywhere-caches create / update の --admission-policy フラグで ADMIT_ON_SECOND_MISS が非推奨に
  • アドミッションポリシーは、キャッシュミス時にミスしたブロックをキャッシュに挿入するかを決定する設定 (従来は ADMIT_ON_FIRST_MISS と ADMIT_ON_SECOND_MISS の 2 択)
  • 既存スクリプトで指定している場合は ADMIT_ON_FIRST_MISS への移行を検討
🔐 2. gcloud CLI: レガシー --tls-offload フラグの削除 Removed
  • gcloud auth enterprise-certificate-config create から --tls-offload フラグを削除
  • レガシー C++ ECP TLS Offload Engine が非推奨となり、CBA リクエストは今後 ECP HTTP Proxy (ecp_http_proxy) のみを使用
  • certificate_config.json の libs.tls_offload に依存した構成は影響確認が必要
⚠️ 対応が必要な組織: gcloud CLI を CI/CD パイプラインや運用スクリプトで利用しているすべてのユーザー、特に Anywhere Cache の管理や企業証明書による CBA を利用している組織は、アップグレード前に影響範囲の確認を推奨します。

🚀 主要な新機能・GA 昇格

🗺️ App Topology GABeta

gcloud app-topology コマンド群が GA および Beta に昇格しました。

🌊 Cloud API Gateway: レスポンスストリーミング対応
  • gcloud api-gateway gateways create に --enable-streaming フラグを追加
  • Server-Sent Events (SSE)、HTTP チャンク転送、WebSocket、gRPC/HTTP2 双方向ストリーミングを提供するゲートウェイを作成可能
  • ⚠️ ストリーミングモードはゲートウェイの作成時のみ設定可能 (作成後の変更は不可)
💾 Cloud Backup DR: 自動保護コマンド群の追加 Alpha / Beta
  • gcloud backup-dr auto-protection-policies: 自動保護ポリシーの管理
  • gcloud backup-dr auto-protection-bindings: 自動保護バインディングの管理
  • gcloud backup-dr applied-auto-protection-policies: 適用済み自動保護ポリシーの確認
  • gcloud backup-dr binding-matching-resources: バインディングに一致するリソースの管理
🔑 Cloud Memorystore: トークン認証機能 GA
  • gcloud memorystore instances create/update の --authorization-mode=token-auth フラグが GA に昇格
  • create-token-auth-user、token-auth-users (create-auth-token / delete / describe / list)、token-auth-users auth-tokens (delete / describe / list) の各コマンド群が GA に昇格
  • gcloud memcache instances create の --tags フラグも GA に昇格
🖥️ Compute Engine: CDN キャッシュ無効化の拡張と image-views の GA 昇格
  • gcloud beta compute url-maps invalidate-cdn-cache に --content-type、--http-status、--backend-bucket、--backend-service フラグを追加 (拡張された無効化マッチャー対応)
  • --host フラグでワイルドカード (--host="*.example.com") マッチングに対応
  • gcloud compute image-views describe が GA に、image-views list が Beta / GA に昇格
  • コマンド引数でプロジェクト番号の使用が可能に。Interconnect Attachments のラベル更新不具合も修正

⚖️ メリットと制約事項

✅ メリット

💼 ビジネス面
  • セキュリティ構成の簡素化: CBA の TLS 処理経路が ECP HTTP Proxy に一本化され、企業証明書運用のトラブルシューティングコストが低減
  • バックアップ運用の自動化: Backup and DR の自動保護ポリシーを CLI で管理でき、保護対象リソースの追加漏れリスクを軽減
🔧 技術面
  • リアルタイム API の CLI 管理: SSE / WebSocket / gRPC 双方向ストリーミング対応ゲートウェイを IaC / スクリプトから作成可能
  • CDN 運用の柔軟性向上: コンテンツタイプ、HTTP ステータス、バックエンド単位、ワイルドカードホストでのキャッシュ無効化が可能
  • Memorystore の認証強化: トークン認証が GA となり、本番環境で安全に運用可能

⚠️ デメリット・制約事項

🚧 制限事項
  • API Gateway のストリーミングモードは作成時のみ設定可能 (既存ゲートウェイへの追加不可)
  • Backup DR の自動保護関連コマンド群は Alpha / Beta トラックで、GA 前に変更の可能性あり
  • ADMIT_ON_SECOND_MISS は非推奨であり、将来のバージョンで削除される可能性あり
🤔 考慮すべき点
  • --tls-offload を含む既存の CBA セットアップスクリプトは 585.0.0 以降エラーになるため、アップグレード前に修正が必要
  • CI/CD 環境でバージョンを固定していない場合、自動更新により Breaking Changes の影響を受ける可能性
  • kubectl のデフォルトが 1.35.8 に更新されるため、クラスタバージョンとのスキューポリシーを確認

🎯 ユースケース

🏢 ユースケース 1: CBA 利用組織での gcloud CLI アップグレード対応

シナリオ: 企業証明書による Certificate-Based Access (CBA) を全社の開発端末で利用しており、セットアップスクリプトで --tls-offload フラグを指定している。

Bash セットアップスクリプトの修正例 (Linux) 
# 修正前 (585.0.0 でエラーになる)
# gcloud auth enterprise-certificate-config create linux \
#   --label="Google Endpoint Verification" \
#   --module=/usr/lib/x86_64-linux-gnu/pkcs11/libcredentialkit_pkcs11.so.0 \
#   --slot=0x1234567 \
#   --tls-offload=/path/to/libtls_offload.so

# 修正後
gcloud auth enterprise-certificate-config create linux \
  --label="Google Endpoint Verification" \
  --module=/usr/lib/x86_64-linux-gnu/pkcs11/libcredentialkit_pkcs11.so.0 \
  --slot=0x1234567

効果: ECP HTTP Proxy 一本化により構成が簡素化され、アップグレード後もセットアップスクリプトが正常に動作する。
