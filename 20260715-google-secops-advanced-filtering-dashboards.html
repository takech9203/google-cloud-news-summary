🔍 Google SecOps: ダッシュボードの高度なフィルタリング機能

Google SecOps (SIEM) Preview
2026-07-15

📋 概要

Google SecOps (SIEM) のネイティブダッシュボードに、高度なフィルタリング機能 (Advanced Filtering) がプレビューとして追加されました。セキュリティアナリストはクエリ変数 (トークン)を使用して、動的な値、複雑な正規表現、またはブーリアンロジックを YARA-L クエリに実行時に注入できます。

従来の基本フィルターは特定のフィールドに紐づいていましたが、高度なフィルターはクエリ変数として動作します。単一のフィルター入力 ($token$) で、ダッシュボード内の複数チャートにまたがる複数フィールドを同時にフィルタリングすることが可能です。

💡 対象ユーザー: SOC (Security Operations Center) のアナリストやセキュリティエンジニア。日常的な脅威モニタリングやインシデント調査のワークフローを効率化します。

🔄 Before / After 比較

❌ Before (従来)

  • フィルターは特定フィールドに紐づき、柔軟性が不足
  • 動的な値や正規表現には手動でクエリを書き換えが必要
  • 複数値の OR 条件がダッシュボード上で不可
  • Scheduled Reports で動的フィルター条件の適用が困難

✅ After (新機能)

  • トークン変数で複数チャートを一括フィルタリング
  • YARA-L クエリ結果から動的にフィルター選択肢を生成
  • 正規表現や IN 句など柔軟なフォーマット対応
  • マルチセレクト + カスタムデリミタで複数値結合
  • デフォルト値設定で即座にデータ表示可能

⚡ 主要機能

🏷️ トークン変数の定義

ダッシュボードごとにユニークなトークン変数を定義可能。$token_name$ の形式でチャートクエリ内から参照し、文字列置換で動作します。変数名は英数字とアンダースコアのみ許可。

🔄 フィルター値の動的生成

YARA-L クエリの実行結果からフィルター選択肢を動的に生成 (Generate from Query)。手動入力による静的リストの定義も可能。Data RBAC に基づきユーザー権限範囲内の値のみ表示されます。

🔧 カスタマイズ可能なラッパー

プレフィックスとサフィックスでトークン値をラッピング。正規表現用に /^ と $/ で anchored regex を実現。IN 句やその他のクエリパターンにも対応します。

✅ マルチセレクト対応

単一トークンに対して複数値の選択を有効化。カスタムデリミタの設定 (例: | で正規表現の OR ロジック) とデフォルト値でダッシュボードの初期表示を最適化します。

クエリでのトークン使用例

YARA-L 
# ホスト名による完全一致フィルタリング
principal.hostname = $hostname$

# 正規表現によるIPアドレスフィルタリング
re.regex(target.ip, $ip_regex$)

# 正規表現デリミタ内でのトークン使用
principal.ip = /$ip_pattern$/

ステップ 1: 高度なフィルターの作成

1.Google SecOps コンソールでダッシュボードを開く
2.[Manage Filters] ダイアログを開く
3.[Add] をクリックし、Filter Type として [Advanced Filter] を選択
4.Filter Name (表示ラベル) と Token Variable (例: hostname) を入力

ステップ 2: フィルター値の設定

動的生成 (Generate from Query) の場合:

1.YARA-L クエリを入力し、Time Range を設定
2.[Run Search] をクリック
3.[Select Column] ドロップダウンから対象列を選択
4.[Preview Filter Dropdown] で値のプレビューを確認

手動入力 (Manual Entry) の場合:

1.Manual Entry フィールドに値を入力
2.[Add] をクリックして追加

ステップ 3: ラッパーとマルチセレクトの設定

1.必要に応じて Prefix と Suffix を設定
2.[Allow Selection of Multiple Options] を有効化し、Delimiter を指定 (例: |)
3.Default Value をドロップダウンから選択
4.[Done] をクリックして保存

ステップ 4: チャートクエリへのトークン挿入

YARA-L 
# チャートのクエリエディタで手動でトークンを挿入
events:
  $e.principal.hostname = $hostname$
  $e.metadata.event_type = "NETWORK_CONNECTION"

🎯 ユースケース

🌐 ユースケース 1: 動的な IP アドレスフィルタリング

シナリオ: SOC アナリストが、特定の不審な IP アドレスに関連するネットワークトラフィックを複数の視点 (接続先、送信元、横移動) でダッシュボード全体にわたって同時に調査したい場合。

YARA-L 
# トークン定義: suspicious_ip
# Prefix: /^  Suffix: $/
# Multi-Select: enabled, Delimiter: |

# Chart 1: 送信元としての活動
principal.ip = /$suspicious_ip$/

# Chart 2: 宛先としての活動
target.ip = /$suspicious_ip$/

# Chart 3: 正規表現マッチ
re.regex(principal.ip, $suspicious_ip$)

効果: 1つのフィルター操作でダッシュボード全体の全チャートが更新され、複数の不審 IP を OR 条件で同時調査可能。

🖥️ ユースケース 2: ユーザー行動分析のための動的ホストフィルタリング

シナリオ: セキュリティチームが特定のホスト群における認証失敗やアカウントロックアウトを監視し、内部脅威の可能性を調査する場合。

YARA-L 
# トークン定義: target_hosts
# Manual Entry: ["dc01.corp.local", "dc02.corp.local", "vpn-gw.corp.local"]
# Multi-Select: enabled, Delimiter: ,

# チャートクエリ
events:
  $e.principal.hostname = $target_hosts$
  $e.metadata.event_type = "USER_LOGIN"
  $e.security_result.action = "FAIL"

効果: 監視対象ホストをフィルターで柔軟に切り替えながら、認証失敗パターンをリアルタイムに可視化。

考慮すべき点

!トークン置換は純粋な文字列置換であり、最終クエリの構文的正しさはユーザーの責任
!未定義のトークンをクエリで使用した場合、リテラル文字列として扱われる (黄色の警告バナーが表示)
!トークン名の変更は既存クエリに影響するため、事前に影響範囲を確認すべき
!トークン変数名の変更時、既存チャートクエリを手動で更新する必要がある
